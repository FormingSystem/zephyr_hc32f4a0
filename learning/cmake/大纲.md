# CMake：把新增代码变成真实产物

第一次接触构建系统时，先按[主线 P006 原生 CMake](../P01_zephyr_make_project/P006_原生CMake与目标模型_Windows.md) → [P007 Zephyr 应用](../P01_zephyr_make_project/P007_Zephyr应用构建_Windows.md) → [P008 west 与 CMake 配合](../P01_zephyr_make_project/P008_west零基础与Zephyr构建_Windows.md)阅读；再用 [P009 输入发现](../P01_zephyr_make_project/P009_Zephyr的CMake输入与依赖发现_Windows.md)和 [P010 缓存排错](../P01_zephyr_make_project/P010_CMake缓存与构建排错_Windows.md)查接口。本目录的 P001/P002 保留为新增源码、库和模块的独立动手实验，编号不随主线移动。

读者已会写 C/C++，从构建目标、使用要求和模块发现开始补齐工具知识。

先围绕同一个小程序走通“21 → 42 → 43”，再增加限幅、故意漏掉实现，亲眼区分声明可见与链接完整。第二章把已理解的库关系带入 Zephyr，增加模块发现与软件开关，每次只多解决一个问题。

```mermaid
flowchart LR
    A["准备：确认主机工具"] --> B["P001：把函数接成可运行程序"]
    B --> C["P001：新增文件、排错、恢复"]
    C --> D["P002：接入 Zephyr 模块并比较开关"]
    B --> E["VS Code：停在函数中观察"]
    D --> F["板级 P003：实际运行模块场景"]
```

每章用固定步骤图标出当前位置，命令与解释就地配对。材料目录保存同一份带注释源码；编辑的是练习副本，生成物在独立构建目录。先完成主机程序，再按需要走向调试或 Zephyr 模块。

1. [把源文件和库加入构建](P001_把源文件和库加入构建.md)：主机编译、漏实现失败、恢复与新增文件练习。
2. [接入 Zephyr 模块](P002_接入Zephyr模块.md)：模块入口、软件开关、两种配置编译与调用条件；不提前引入 Twister。

前提：[实验准备](../P000_实验准备.md)。第一章无需 SDK；第二章需要[原生实验准备](../P000_实验准备.md)。正文内逐步实验，配套目录保存原件。完成第一章后即可进入 [VS Code 调试](../vscode/大纲.md)。
