# 第1章\_Zephyr从工程布局到构建

本专题在[学习主线](../README.md)中编号为 **P02**，目录为 `P02_zephyr_make_project`。需要先建立硬件基础的读者可阅读 [P01 计算机组成与 MCU 架构](../P01_computer_architecture/大纲.md)，其中以 STM32H743 解释处理器、总线、中断、汇编和芯片启动；本专题内的 P001、P002 等仍按章节独立编号。

先认识 Zephyr 能解决什么问题、是否适合自己的项目，再准备本机环境并取得源码。手中已有源码和配套材料后，对照实际文件认识工程，最后把一个明确应用编译成面向一个明确硬件目标的固件。贯穿任务是 hello_world + mps2/an386，成功后再换应用、加模块、接入 HC32。


需要接着以前的实验操作时，按使用处的章节链接回看准备步骤；确认所需产物后继续，无需重做整套环境。

正文中的“第几行”从所指代码块首行起算，注释和空行计入，阅读器自动折行不计。参数说明同时保留原样片段，配置说明给出文件与键，输出说明复用实际字段名；可先按这些名称定位，再读其作用。每篇末尾的命令索引按正文顺序提供可复制附件，执行前先阅读对应小节的环境和前提。

## 1.1\_先认识用途，再准备环境与源码

第一次接触 Zephyr，从 [P001 认识 Zephyr 与技术选型](P001_认识Zephyr与技术选型.md) 开始：理解实时操作系统、Zephyr 生态与选型条件。接着选择下面的一条 P002 环境路线；已经明确采用 Zephyr 的读者也从这里开始准备。

此时只需知道“下载 Zephyr 源码，准备能编译它的工具”。源码目录、硬件支持分层和构建输入的系统讲解放在 [P006 工程布局与构建全景](P006_工程布局与构建全景.md)：完成 P002—P005 后再读，能够边看文字边打开手中的文件，而不是提前记住一棵尚未下载的目录树。

本专题有 **Linux 与 Windows 两类环境路线**。Windows 再按 PowerShell、UCRT64 两种终端展开；WSL 中使用 Linux 工具时归入 Linux 路线。为衔接 Linux 内核，Linux 读者在首次构建后继续完成 [GNU Make 分支](P008_选择应用与硬件目标并构建.md#linux-make-build)，两类环境都学习 [Kconfig 菜单与 Kbuild 对照](P008_选择应用与硬件目标并构建.md#menuconfig-and-kbuild)。Ninja 是 Zephyr 的默认后端和 Windows 官方路线，不是所有工程的唯一选择；具体支持边界见 [Make/Ninja 环境选择](P008_选择应用与硬件目标并构建.md#build-backend-choice)。

| 环境 | 源码与主机准备 | Python 和 SDK |
| --- | --- | --- |
| Linux Bash / WSL Linux | [P002 Linux](P002_环境安装与源码准备_Linux.md) | 同章完成 Linux venv 与 SDK |
| Windows PowerShell | [P002 PowerShell](P002_环境安装与源码准备_PowerShell.md) | 同章完成 Windows venv；P004 安装 SDK |
| Windows UCRT64 Bash | [P002 UCRT64](P002_环境安装与源码准备_UCRT64.md) | P003 完成 Windows venv；P004 安装 Windows SDK |

三个环境各有 Git 获取和 ZIP 获取分支，在 P005 取得配套模块，在 P008 完成构建。没有 Git 历史不妨碍本地编译，有历史也不证明网络可用。公司内部 Git 与官方 GitHub 的来源区别在 P005 结合现有材料说明；材料齐全时不必重新获取。选择一条环境路线，不把两种 Windows 终端的命令混着执行。

west 随这条操作线逐步展开：环境章在安装和下载处解释当前需要的工具职责，P005 说明清单与 init/update 并完成依赖准备，P006 再对照已经取得的主仓和模块解释工作区布局。P007/P008 先看到 CMake 怎样构建，P009 再解释 west 的扩展与构建调用；不要求读者提前读后面的完整工具原理才能完成第一条命令。

示例源码根：UCRT64 为 `/g/zephyr_practice/zephyr-main`，PowerShell 为 `G:\zephyr_practice\zephyr-main`，Linux 为 `~/zephyrproject/zephyr`。它们是实验位置，文档仓库不是实验前提。旧材料目录 p003、p006 为稳定实验标识，不随章号迁移。
