# 第1章\_环境与依赖导航

尚未确定是否采用 Zephyr 时，先读 [P001 认识 Zephyr 与技术选型](P001_认识Zephyr与技术选型.md)，明确希望复用的能力与待验证条件。已经确定路线的读者可直接进入下面的工程与环境准备。

先选择本机环境，按对应 P002 取得源码，再按需要完成 P003—P005 的工具、SDK 和依赖准备。材料齐全后进入 [P006 工程布局与构建全景](P006_工程布局与构建全景.md)，对照实际目录认识应用与硬件支持；准备阶段不以读完工程分层为前提。

先按 **Linux 或 Windows** 选择主机工具与 SDK，再选终端。WSL Linux 与 UCRT64 Bash 虽然都能输入 Bash 命令，前者运行 Linux 工具，后者在本专题中调用 Windows 原生工具；venv、SDK 和构建缓存不交叉复用。

Linux 路线支持 Make 与 Ninja：完成准备后，在 [P008 Linux Make 实验](P008_选择应用与硬件目标并构建.md#linux-make-build)构建同一应用，观察生成规则与固件。Windows 路线沿 Zephyr 官方支持使用 Ninja；Make 本身仍有 Windows 移植，具体生成器与 Shell 的区别见 [P008 后端选择](P008_选择应用与硬件目标并构建.md#build-backend-choice)。两类环境最后在 [menuconfig 与 Linux 内核衔接](P008_选择应用与硬件目标并构建.md#menuconfig-and-kbuild)汇合，理解配置处理不依赖先打开菜单。

三条环境路线都在 [P005](P005_源码依赖与离线准备.md) 核对模块，再经 [P006](P006_工程布局与构建全景.md) 认识工程组成，到 [P008](P008_选择应用与硬件目标并构建.md) 选择本终端的构建命令并生成固件。编写自己的构建目标时可查阅 [P007 的 CMake 实验](P007_原生CMake与目标模型.md)。

只有源码 ZIP 时不必恢复 Git 历史，但要另备同修订模块。只能连接公司内部 Git 时，复用公司的依赖来源和清单；主源码改用内部地址不会自动改变全部模块地址。P005 先解释这些背景，再让读者选择已有的 Git 或归档操作；材料已经齐全就直接核验并进入构建。完全离线还要带齐主机包、Python wheel 与 SDK。第一次构建固定 hello_world + mps2/an386，成功后按[大纲](大纲.md)继续。

<a id="hal-origin"></a>

需要接入华大厂商库时，先完成已有目标构建，再读 [HC32 与外部源码模块接入](P014_HC32与外部源码模块接入.md)。它说明厂商来源、固定修订、HAL 与板/SoC 适配的分工。
