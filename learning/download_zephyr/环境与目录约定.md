# 第1章\_UCRT64\_环境与目录约定

本目录保留源码下载、Git、清单、SDK 和主机工具的完整讲解，操作统一使用 **Windows x64 + MSYS2 UCRT64 Bash + Windows Python 3.12**。UCRT64 提供 Bash 和常见 Unix 命令，主机仍然是 Windows；下载 SDK、Python wheel 时仍选 Windows 包。Linux 主机和 Linux 内核的对照内容保留用于理解差异。

## 1.1\_先确认终端与工具

从开始菜单打开 MSYS2 UCRT64。安装终端和国内换源的完整步骤见[准备 UCRT64 环境与下载 Zephyr](../P01_zephyr_make_project/P01_准备UCRT64环境与下载Zephyr.md)。

```bash
# 当前位置：任意目录；终端：MSYS2 UCRT64 Bash。
printf '%s\n' "$MSYSTEM" "$MINGW_PREFIX"
```

预期分别是 `UCRT64` 和 `/ucrt64`。进入某个目录不会切换终端类型。UCRT64 的默认搜索路径包含 `/ucrt64/bin` 和 `/usr/bin`，见 [MSYS2 环境说明](https://www.msys2.org/docs/environments/)。

已完成 MSYS2 系统更新后，可按需安装本教程涉及的工具：

```bash
# 当前位置：任意目录；终端：UCRT64。安装主机工具，不安装 ARM 交叉编译器。
pacman -S --needed git curl wget unzip \
    mingw-w64-ucrt-x86_64-cmake \
    mingw-w64-ucrt-x86_64-ninja \
    mingw-w64-ucrt-x86_64-dtc \
    mingw-w64-ucrt-x86_64-gperf \
    mingw-w64-ucrt-x86_64-7zip
```

其中 `7z` 用于 SDK 的 `.7z` 包；包名可在 [MSYS2 7-Zip 包页面](https://packages.msys2.org/packages/mingw-w64-ucrt-x86_64-7zip)核对。`find`、`grep`、`xargs`、`sha256sum` 使用 MSYS2 自带的 Unix 工具，避免误调用 Windows 同名程序。

Python 沿用本工程的 Windows 原生 Python 3.12；UCRT64 中可以调用 Windows Python Launcher `py`：

```bash
# 当前位置：任意目录；检查 Windows Python Launcher 和实际解释器。
type -a py
py -3.12 -c 'import sys; print(sys.version); print(sys.executable)'
type -a git cmake ninja dtc gperf 7z find grep sha256sum
```

若找不到 `py`，先安装带 Launcher 的 Windows Python 3.12，并让当前终端能找到它；不要为了解决命令缺失改用 `/usr/bin/python` 创建本教程环境。`type -a` 显示可能存在的多套工具；当前集成工程由 `scripts/project_env.py` 进一步选择项目工具，不必把现有安装全部替换。

## 1.2\_分清实验目录与当前集成工程

| 场景 | 源码与依赖在哪里 | 操作入口 |
| --- | --- | --- |
| 本目录的上游下载实验 | `~/zephyr-download-lab/zephyr/`，外部模块放在同级 `modules/` | 本目录各章的 ZIP、Git、west、CMake 示例 |
| 当前 HC32 集成工程 | 工程根已经包含 Zephyr、CMSIS_6、厂商 HAL 和板级代码 | 工程根的 `.venv`、`scripts/project_env.py` 和 `project-west.yml` |

两种布局说明不同组织方法。不要在当前工程内部再创建一个同名源码树，也不要把官方 ZIP 覆盖进现有工程。下载实验里的 `hal_hc32`、`your-company`、`module1`、`vX.Y.Z` 等是概念或待替换示例；`cmsis`、`cmsis_6` 的取舍取决于所选版本的真实清单。原文的 `v4.4.0` 用于说明固定版本，不代表当前工程基线；本工程版本以[锁定记录](../../dependencies.lock.json)为准。

需要亲自做 ZIP 下载实验时，单独创建目录：

```bash
# 当前位置：任意目录；仅创建一个新的独立下载实验目录。
# 若目录已存在，mkdir 会报错；先检查已有内容，不重复初始化或覆盖。
mkdir "$HOME/zephyr-download-lab" && cd "$HOME/zephyr-download-lab"
```

后续按需创建下载缓存：

```bash
# 当前位置：~/zephyr-download-lab。
mkdir -p downloads/source downloads/sdk downloads/python-wheels
```

P01 的 Mini Manifest 与 P03 的 ZIP 是可选路线，不要在同一目录把两套初始化命令顺序全部执行。示意中的 `app/`、`modules/`、SDK 要由对应步骤取得后才能构建；仅下载官方 Zephyr ZIP，不会得到本工程的 HC32 板级支持。

当前集成工程已有环境时，在**该工程根目录**使用：

```bash
# 当前位置：当前 HC32 集成工程根目录；不是上述独立实验目录。
source .venv/Scripts/activate
python scripts/project_env.py doctor
```

准备成功后再按[本工程环境说明](../../project-docs/environment.md)执行检查和构建；这里不重新初始化项目 west 工作区。

## 1.3\_Bash\_命令与路径写法

| 操作 | 本教程在 UCRT64 中的写法 |
| --- | --- |
| 多行命令 | 行尾 `\`，反斜杠后不再加空格 |
| 列目录，包含隐藏文件 | `ls -al` |
| 搜索命令位置 | `type -a python` |
| 搜索文本 | `grep -ni -- "hc32" ./west.yml` |
| 递归查文件 | `find . -type f`；管道传文件名时用 `-print0` 和 `xargs -0` |
| 文件摘要 | `sha256sum 文件名` |
| 移动文件或目录 | `mv -- 源 目标`，先核对目标是否存在 |
| 删除已搬空的目录 | `rmdir -- 目录`，非空会报错 |
| 设置环境变量 | `export 名称="值"`，对当前 shell 及随后启动的子进程生效 |
| 激活 Windows Python 环境 | `source .venv/Scripts/activate` |

`~/zephyr-download-lab` 中的 `~` 是 UCRT64 用户主目录，不是项目目录。Bash 命令中推荐使用 `"$HOME/zephyr-download-lab"`；双引号里的 `"~/..."` 不会展开 `~`。Windows 盘符路径可通过 `cygpath -u` 转成 Bash 路径，例如把自己从资源管理器复制的目录转换后再 `cd`。

Windows Python、CMake 和 SDK 读取的路径型环境变量使用 `cygpath -m` 转成盘符加正斜杠形式：

```bash
# 当前位置：~/zephyr-download-lab；对应源码和 SDK 目录应已准备好。
export ZEPHYR_BASE="$(cygpath -m "$PWD/zephyr")"
export ZEPHYR_SDK_INSTALL_DIR="$(cygpath -m "$PWD/zephyr-sdk-1.0.1")"
export ZEPHYR_TOOLCHAIN_VARIANT="zephyr"
```

路径需要引用以保护空格。`ZEPHYR_MODULES` 是 CMake 的分号列表，Bash 中应给整个 `-D` 参数加引号，否则分号会把它拆成两条 shell 命令；它和 Bash 中用冒号分隔的 `PATH` 不是一回事。路径转换规则见 [MSYS2 Filesystem Paths](https://www.msys2.org/docs/filesystem-paths/)。

Windows SDK 的 `setup.cmd` 仍是批处理文件。在 SDK 根目录中用 `MSYS2_ARG_CONV_EXCL='*' cmd.exe /d /c setup.cmd` 调用，保留 Windows SDK 的安装逻辑；无需切换到 PowerShell，也不能因为使用 Bash 就下载 Linux SDK。

## 1.4\_网络与虚拟环境

访问 GitHub 前按[代理配置](代理配置.md)核对 `10808` 混合端口。Git 配置只供 Git 使用；浏览器 ZIP 下载、curl 和 pip 分别检查代理入口。MSYS2 换源按主教程操作，包名前缀仍使用 UCRT64，不能将 Linux 的 `apt` 安装命令直接搬过来。

P06 创建虚拟环境时使用 `py -3.12 -m venv .venv`，之后在 Bash 中 `source .venv/Scripts/activate`。这仍然是 Windows 虚拟环境，包目录和可执行文件位于 `Lib/`、`Scripts/`；Linux 的 `.venv/bin/activate` 不适用于它。

源码、SDK 和缓存可按需搬运；复制来的旧 `.venv` 先移到别名位置，再在新位置创建全新的 `.venv`，从锁定依赖或匹配的 wheel 缓存恢复。Python 官方说明虚拟环境不应视为可直接复制的可移植目录，见 [venv 文档](https://docs.python.org/3/library/venv.html)。
