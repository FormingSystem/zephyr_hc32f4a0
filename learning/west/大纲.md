# west：从多仓库配套到团队工具扩展

应用和库各自能被 Git 正确取得，并不意味着它们选用了能够一起工作的版本。**west** 用清单记录这份配套关系，再调用 Git 把选定的代码放进工作区。它是工具名称，不是缩写；来自 Zephyr 生态，也能管理普通工程的多仓库组合。

如果当前任务是从已下载的 Zephyr 开始，先读[主线 P008：west 零基础与 Zephyr 构建](../P01_zephyr_make_project/P008_west零基础与Zephyr构建_Windows.md)：从安装位置、工作区和官方清单，讲到 Zephyr 扩展、`west build` 与直接 CMake 的配合。那条路线复用官方清单。本目录是之后可选择的多仓库进阶实验，P001—P005 仅在本专题内编号；这里创建的清单属于实验工作区，不覆盖 `zephyr-main/west.yml`。

面向已有嵌入式开发经验、没系统接触 west 的读者。你不必先安装 Zephyr SDK；实验用本地 Git 仓库模拟应用、共享库和可选文档。先核对[实验基线](../P000_实验准备.md)，不了解 Python 环境时先读 [venv 第一章](../python/venv/P001_创建并认识虚拟环境.md)。

| 顺序 | 为什么现在需要它 | 本章验收 |
| --- | --- | --- |
| [P001 建立第一个多仓库工作区](P001_建立第一个多仓库工作区.md) | 应用和库分别维护，却需要一起取得 | 完成 init/update，解释 YAML→schema→Project→命令，运行跨仓库程序 |
| [P002 管理版本与本地开发](P002_管理版本与本地开发.md) | “都下载好了”不等于配套版本正确 | 跟踪 update→Project.git→Git，切换版本、保存开发、冻结重建 |
| [P003 修改清单与配置](P003_修改清单与配置.md) | 项目增加后需要不同组合和本地设置 | 观察原始键与有效属性，解释默认值、配置、分组与导入的读取者 |
| [P004 编写自己的扩展命令](P004_编写自己的扩展命令.md) | 团队需要共享检查入口和自己的配置 | 从 inventory 入门，到 team-policy 字段与 repo-audit 的 Git 检查闭环 |

五章沿同一个加法程序推进：先取得能运行的组合，再改变版本并保存开发分支，随后允许个人选择额外文档，把人工判断写成扩展，最后验证另一位开发者需要取得的交付内容。正文中的下一步由上一步留下的问题引出，源码、配置、命令和恢复都在当章给出；[材料目录](labs/README.md)提供配套原件。

```mermaid
flowchart LR
    P1["P001<br/>认识工程并运行"] --> P2["P002<br/>选择与重建版本"] --> P3["P003<br/>选择项目和配置"] --> P4["P004<br/>把检查写成命令"] --> P5["P005<br/>交付可验证组合"]
```

这张图标出整个专题的顺序；进入章节后，使用对应的 1.1、1.2 等步骤图。每节会重现本章路线，把当前节点标成黄色，同时写出编号。命令块内直接注明执行位置，命令后就地解释，读到哪一步就操作哪一步。

跟做时把编辑器打开到原 workspace，终端也留在本章指定位置。遇到“改清单”，先保存对应文件，再执行后面的查询；源码发布、清单接受、下载到本地是不同动作，操作图会标出先后关系。遇到预先说明的失败，观察错误和退出码，再执行恢复，不能把失败那行直接跳过。

Python 示例从两数相加开始，逐步解释相邻仓库导入、命令参数、循环和报告输出。读扩展代码时先沿具体项目走一遍，再尝试增加 --count；读发布检查时先看一个项目怎样比较版本，再看整个集合是否齐全，不需要一次记住所有方法名。

按顺序阅读时保留原 `textbook-01/workspace`，每章交接如下。replay 和 textbook-missing 是旁边的对照工作区，实验完成后都回到原 workspace 继续。

| 读完章节 | 原工作区留给下一章的状态 |
| --- | --- |
| P001 | app、arithmetic 都已取得且为 v1.0，应用输出 5 |
| P002 | app v1.0、arithmetic v2.0；库检出回同步基线，开发备注仍保存在自己的分支 |
| P003 | 恢复三个项目的直接定义；guide 默认停用但可已克隆，实验过滤项已撤销 |
| P004 | inventory 保持登记，--count 与缺失检查可用；完成自定义策略实验后撤销 repo-audit 登记与 userdata，保留 Python 参考源码 |
| P005 | checklist 已接受 v2.0，交付检查通过；最后明确切换到真实工程的工具与清单 |

全部主线基于 west 1.5.0，具体命令用 `west <命令> -h` 核对；正文旁的官方文档供对照规则，不代替实验解释。证据和覆盖范围见[验证记录](../VALIDATION.md)。第五章最后回到 `G:\zephyr_practice\zephyr-main`，区分 ZIP 显式模块路线与已经初始化的 west 工作区。
