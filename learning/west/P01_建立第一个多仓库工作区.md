# 1. 建立第一个多仓库工作区

应用在一个 Git 仓库，公共库在另一个仓库。你分别 clone 了它们，编译却不通过：应用需要旧接口，库已经改成新接口。Git 很清楚每个仓库的历史，却没有自动替产品回答“这版应用配哪版库”。

**west** 解决的正是多个 Git 仓库怎样配套的问题。它读取一份 **清单（manifest）**，按照其中的来源、版本和位置，把项目组织成 **工作区（workspace）**。本章用一个加法程序建立最小工作区，不下载 Zephyr，也不需要开发板。分组、扩展和发布都留到对应章节，先让两份代码一起工作。

## 1.1 先安装工具，不把工具和源码混在一起

本章需要 UCRT64 Bash、Windows Python 3.12 和 Git。Python 环境的创建与激活沿用前面 venv 专题学过的方法。打开新终端，在本仓库根目录执行：

```bash
py -3.12 --version
git --version
py -3.12 -m venv build/learning-tools/west-textbook-tools
build/learning-tools/west-textbook-tools/Scripts/python.exe -m pip install west==1.5.0
source build/learning-tools/west-textbook-tools/Scripts/activate
python -c "import sys; print(sys.executable)"
west --version
export MSYS="${MSYS:+$MSYS }noglob"
```

解释器应来自 west-textbook-tools，west 应报告 v1.5.0。首次安装联网；后续源码都在本机。工具环境已存在时可以复用，先核对版本，不必重新创建。

最后一行保留已有 MSYS 选项并追加 noglob，只影响当前终端及其子进程。它避免 Windows Python 调用 MSYS Git 时再次展开含大括号的引用参数；本机已出现过因此导致的 not a valid SHA1。它不关闭 Bash 自己的通配符；使用原生 Git for Windows 时没有复现同一问题。

工具装好了，并不代表工作区已经建立。Python 环境保存 west 程序，稍后 .west 保存工作区配置，各仓库 .git 保存各自历史；这三类目录由不同工具管理。

## 1.2 取出两份小程序和它们的历史

教材需要几段已经存在的 Git 历史，便于练习选择版本。材料生成器只准备这些源仓库，不运行 west：

```bash
python learning/west/labs/seed_workspace.py --name textbook-01
cd build/learning-tools/west/textbook-01/workspace
pwd
```

同名目录存在时生成器拒绝覆盖，换 textbook-02 后，后续路径也使用这个名字。生成的结构如下；guide 和命令模板是后面章节的材料，本章不把它们加入清单：

```text
textbook-01/
  remotes/
    app/          应用源仓库，已有 v1.0
    arithmetic/   库源仓库，已有 v1.0、v2.0
    guide/        后续章节材料
  workspace/
    manifest/     维护配套声明的 Git 仓库
```

remotes 这个名字模拟代码托管端，实际上全在本机；workspace 是我们消费这些版本的地方。生成器的 Git 提交身份只作用于实验，不改用户全局配置。

第一版 arithmetic.py 的全部有效代码是：

```python
def add(a, b):
    return a + b
```

应用 main.py 是：

```python
import sys
from pathlib import Path

sys.path.insert(0, str(Path(__file__).resolve().parents[1] / "libs" / "arithmetic"))
from arithmetic import add

print(f"2 + 3 = {add(2, 3)}")
```

Path 根据应用文件位置找到工作区，再拼出 libs/arithmetic；sys.path.insert 将它放进 Python 的代码搜索路径。这个搜索路径由应用自己设置，west 不负责 Python 包安装。我们刻意直接调用相邻源码，避免把本章变成打包实验。

## 1.3 用一份清单说明怎样放到一起

当前位置始终是 textbook-01/workspace。用下面的完整内容替换 manifest/west.yml。cat 的文本块一直写到独占一行的 YAML；也可以在编辑器中粘贴同样内容：

```bash
cat > manifest/west.yml <<'YAML'
manifest:
  version: "1.2"
  projects:
    - name: app
      url: ../../remotes/app
      revision: v1.0
      path: app
    - name: arithmetic
      url: ../../../remotes/arithmetic
      revision: v1.0
      path: libs/arithmetic
  self:
    path: manifest
YAML
```

YAML 用空格缩进表达层次，列表项以 - 开头，不用 Tab。version 是清单格式要求，不是应用版本。projects 中每项描述一个受管 Git 仓库：

| 字段 | 本例含义 |
| --- | --- |
| name | west 选择项目的名字，例如 arithmetic |
| url | Git 到哪里获取历史 |
| revision | 要使用的标签、分支或完整提交标识 |
| path | 相对工作区根的消费目录 |

self 描述维护这份清单的仓库，本例放在 manifest。它本身不是普通的依赖条目。

最容易错的是两种相对路径。path 从工作区根开始；本例的本地 Git url 从消费仓库目录开始。arithmetic 将放到 workspace/libs/arithmetic，从那里向上三层才到 textbook-01，再进入 remotes/arithmetic。app 少一层，故 url 只有两个 ../。这不是相对 west.yml 的路径。

跨机器发布会使用大家可访问的托管地址；本地地址只为让本实验离线且不绑定作者盘符。

## 1.4 初始化只回答“清单在哪里”

独立目录中的原生命令是 `west init -l manifest`：-l 表示使用已有的本地清单仓库。当前教材位于一个可能已有外层 west 工作区的仓库内部，直接执行会被外层定位拦住，所以使用材料中的初始化辅助器：

```bash
python ../../../../../learning/west/labs/init_workspace.py -l manifest
west topdir
west config manifest.path
west manifest --path
cat .west/config
west manifest --validate
west list -f "{name}: {path} @ {revision} [{cloned}]"
```

五个 ../ 返回教材仓库根。辅助器在中立临时位置调用真正的 west init，再把初始化结果用于目标目录，不改外层 .west。它只处理实验嵌套条件，没有替你执行 update。没有外层工作区时可用原生命令，二者择一。

topdir 应指向 textbook-01/workspace；manifest.path 应为 manifest；manifest --path 应指向该目录下的 west.yml。validate 成功可以没有输出，它只检查声明。list 的 -f 指定显示格式，花括号字段由 west 填入。此时会列出 app/arithmetic，却显示未克隆。

这正是 init 与 clone 的区别：知道清单在哪里，并不表示全部源码已经拿到。如果 topdir 指向外层，先查当前目录和本地 .west/config，不要删除未知工作区来碰运气。

## 1.5 同步源码，再运行应用

现在才执行获取：

```bash
west update
west list -f "{name}: {path} @ {revision} [{cloned}]"
python app/main.py
git -C libs/arithmetic status --short --branch
```

update 读取清单，用 Git 取得所需对象并检出相应版本。工作区应出现 app 和 libs/arithmetic，list 显示已克隆，应用打印 `2 + 3 = 5`。

git -C 在指定仓库执行命令，不改变 Bash 的当前目录。--short --branch 用简洁格式显示分支与修改。看到 HEAD (no branch) 不必重建：这是 Git 的游离头状态，表示当前直接使用清单选定提交，没有检出自己的开发分支。下一章再练习开发分支与同步基线。

若 update 报地址或版本不存在，先查失败项目的 url/revision 及 remotes 中的源仓库；重复安装 west 不会修正 Git 地址。如果程序找不到 arithmetic，检查 libs/arithmetic 是否真的取得，而不是只看 list 有没有名字。

## 1.6 停下来时保存什么状态

本章结束的状态是：两个受管仓库已获取，应用输出 5，清单选择第一版。保留整个 textbook-01，因为 remotes 还要提供后续版本；不要把它当作仅含可删缓存的构建目录。

新开窗口时，从仓库根目录恢复工具与位置：

```bash
source build/learning-tools/west-textbook-tools/Scripts/activate
export MSYS="${MSYS:+$MSYS }noglob"
cd build/learning-tools/west/textbook-01/workspace
west topdir
python app/main.py
```

练习：能列出项目，是否说明它已下载？能运行应用，是否说明将来 update 会取最新版？第一问由 init 后的观察反驳；第二问还要看清单 revision，当前仍固定 v1.0。下一章就改变这条声明，观察文件究竟何时跟着变。
