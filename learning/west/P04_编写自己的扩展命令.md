# 4. 编写自己的扩展命令

目前已经能获取和配置仓库。团队想在测试之前检查“活动依赖是否都已经下载”：可以每个人手工查 list，也可以把共同规则写成程序，让缺少仓库时直接返回失败。

west 允许清单指定仓库中的 Python 程序，把项目操作接入自己的命令入口，这称为 **扩展命令（extension command）**。本章从配套材料中的 inventory 报告程序入手，先找到它怎样被注册，再沿一次调用读实现，最后增加一个选项并验证错误分支。只解释理解这段代码必需的 Python 写法，不要求先学习整套 Python 语法。

## 4.1 命令怎样从仓库进入帮助列表

当前位置：原 `textbook-01/workspace/`，默认只启用 app 与 arithmetic。**inventory** 是本实验自定义的命令名，表示项目清单报告；不是 west 内建命令。前三章没有启用它；现在编辑 manifest/west.yml 末尾的 self，使这一小节完整变为：

```yaml
  self:
    path: manifest
    west-commands: west-commands.yml
```

west-commands.yml 和 commands/inventory.py 已由材料生成器放入 manifest，本节才让 west 读取。保存后运行：

```bash
west help
west inventory -h
west inventory
west inventory --format json
west inventory --require-cloned
```

默认文字输出应列出两个项目及路径、revision、cloned 状态。**JSON（JavaScript Object Notation）** 是结构化数据格式，本命令用它提供适合程序读取的列表。输出中的 revision 是清单文本，cloned 表示本地 Git 仓库是否存在，均不等于应用已经构建成功或 HEAD 已与基线相同。

扩展发现链在本例中是：

```text
.west/config 定位 manifest/west.yml
  → self.west-commands 指向 west-commands.yml
  → 描述文件把 inventory 映射到 commands/inventory.py 中的 Inventory
  → west 创建类实例，解析参数，再执行命令方法
```

打开 manifest/west-commands.yml，实际登记内容是：

```yaml
west-commands:
  - file: commands/inventory.py
    commands:
      - name: inventory
        class: Inventory
        help: Show the active repositories in this workspace.
```

file 告诉 west 到提供扩展的仓库根目录下面找 commands/inventory.py，本例就是 manifest/commands/inventory.py。name 决定用户输入的子命令，class 决定加载文件后实例化哪个 Python 类，help 用于简短帮助。文件名、类名和命令名不必相同，但三者的映射必须正确；只新建 Python 文件而没有这条注册链，west 不会主动扫描并猜测它是命令。

官方对照：[Adding a West Extension](https://docs.zephyrproject.org/latest/develop/west/extensions.html#adding-a-west-extension)。在这个实验里，查看注册文件比重新安装 west 更能解释“为什么出现 inventory”。

## 4.2 一次调用怎样经过这份代码

下面是 manifest/commands/inventory.py 的完整实现。配套目录保留同一份原件；这次修改的是工作区副本。

```python
# SPDX-FileCopyrightText: Copyright The zephyr_hc32f4a0 Contributors
# SPDX-License-Identifier: Apache-2.0
"""只读的 west 扩展：列出活动项目，可供人或其他程序使用。"""

import json

from west.commands import WestCommand


class Inventory(WestCommand):
    """声明命令、接收参数，再读取 west 传入的清单。"""

    def __init__(self):
        super().__init__(
            "inventory",
            "Show active repositories",
            "List active projects; this command does not update repositories.",
        )

    def do_add_parser(self, parser_adder):
        parser = parser_adder.add_parser(self.name, description=self.description)
        parser.add_argument("--format", choices=("text", "json"), default="text")
        parser.add_argument("--require-cloned", action="store_true",
                            help="Fail if an active project has not been cloned")
        return parser

    def do_run(self, args, unknown_args):
        # 清单仓库由 init 定位，不计入这里的受管依赖项目。
        projects = [p for p in self.manifest.projects
                    if p.name != "manifest" and self.manifest.is_active(p)]
        rows = [{"name": p.name, "path": p.path, "revision": p.revision,
                 "cloned": p.is_cloned()} for p in projects]
        if args.require_cloned and any(not row["cloned"] for row in rows):
            self.die("An active project is missing; run west update first.")
        if args.format == "json":
            self.inf(json.dumps(rows, ensure_ascii=False, indent=2))
        else:
            for row in rows:
                self.inf(f"{row['name']}: {row['path']} @ {row['revision']} "
                         f"cloned={row['cloned']}")
```

WestCommand 是 west 提供的框架基类。可以借用 C++ 的“继承并实现回调”来理解控制方向：west 创建 Inventory，调用 do_add_parser 登记选项，再把解析结果交给 do_run。self 是当前对象，super() 调用基类初始化。构造方法只登记名称和帮助，不应该在查询帮助时就开始下载或修改项目。

parser.add_argument 建立参数规则。choices 限定 --format 的合法值，default 给出省略时的值；store_true 让 --require-cloned 出现时为真，否则为假，不需要再跟一个 true 字符串。连字符在属性名中变为下划线，所以业务代码读取 args.require_cloned。

do_run 中第一段列表推导可读成“遍历项目 p，只保留非 manifest 且活动的项目”。排除顶层清单仓库是这个命令的统计口径。is_active 判断配置选择，is_cloned 检查本地 Git 副本，两者各问一件事。第二段把每个项目整理为一行字典，revision 仍是清单声明，不是假装读取了实际 HEAD。

有缺失项目且用户要求严格检查时，self.die 报错并非零退出；否则 self.inf 输出报告。json.dumps 把同一组 rows 变成结构化 JSON 文本，indent=2 控制缩进。文字格式只是另一种显示，没有换一套项目选择规则。

这里没有隐藏的常驻服务。每次 west inventory 都重新读取并执行工作区中的代码，修改后下一次调用即可观察。也正因此，扩展具有当前用户进程的权限，应该像构建脚本一样审查。

## 4.3 修改一个输出选项

先保存一份 `cp manifest/commands/inventory.py ../inventory-before-count.py`。下面只改变刚完整读过的两个方法，其余保持原样。材料中的 solutions/inventory_count.py 提供最终文件对照，完成实验不需要跳过去复制。

我们希望快速取得活动项目数量。修改运行副本，在 `do_add_parser` 的 `return parser` 之前加入：

```python
        parser.add_argument("--count", action="store_true",
                            help="Print the number of active projects")
```

在 `do_run` 的缺失检查之后、原来的格式输出之前加入：

```python
        if args.count:
            self.inf(str(len(rows)))
            return
```

`--count` 是本次新设计的选项，计数只覆盖活动依赖，不含清单仓库。选择放在缺失检查之后，是为了保留 `--require-cloned` 的保证；如果提前 return，该保证会被绕过。这就是一个小修改也需要考虑的控制流不变量。

```bash
west inventory --count
west inventory --count --require-cloned
west inventory --format invalid
```

默认组配置下前两条应输出 `2`。最后一条是故意失败，参数解析器拒绝 invalid；Bash 用 `echo $?` 检查退出码，应非 0。该修改只改顶层清单仓库内的 Python 文件，下一次调用就生效，不需要重新安装 west，也不需要 update。

不要同时修改教材原件与实验副本来寻找“哪个会生效”；本次运行的是工作区内副本。要把改进纳入教材或产品，应另外审查并同步到权威源文件。

## 4.4 验证缺失与禁用两个失败分支

前面的 app 与 arithmetic 已经下载，无法再演示“严格检查拒绝缺失项目”。不必删除已有开发数据，可以创建另一个种子。下面从原 textbook-01/workspace 出发，先回仓库根目录，再进入新工作区；textbook-missing 必须尚不存在：

```bash
cd ../../../../..
python learning/west/labs/seed_workspace.py --name textbook-missing
cd build/learning-tools/west/textbook-missing/workspace
python ../../../../../learning/west/labs/init_workspace.py -l manifest
west inventory
west inventory --require-cloned
echo $?
west update
west inventory --require-cloned
cd ../../textbook-01/workspace
```

这里 init 后刻意不立即 update。普通报告应显示 cloned=False；严格检查应失败并提示先 update，退出码非零；补齐项目后同一条严格检查应成功。最后回到原 textbook-01/workspace。实验控制了唯一变量“项目是否已获取”，因而能验证检查逻辑。新工作区没有上一节 --count 的修改，因为生成器仍从教材原模板生成。若新增选项出现缩进错误，可用 `cp ../inventory-before-count.py manifest/commands/inventory.py` 恢复原工作区的文件，再按两处位置重改；不要重装 west。

回到原 workspace，观察开关：

```bash
west config --local commands.allow_extensions false
west inventory
west config --local commands.allow_extensions true
west inventory
west config --local -d commands.allow_extensions
```

禁用时自定义命令不可执行，但 `west config` 仍是内建命令，可重新启用；最后删除临时开关，恢复原有覆盖关系。若用户级本来禁用扩展，最后删除后仍会禁用，应遵循团队政策保留必要的本地明确配置。

执行扩展就是执行仓库提供的代码；它可以拥有当前进程的文件与网络权限。给团队加入扩展时像审查构建脚本一样审查代码与参数边界，不把描述 YAML 视为全部行为。正式扩展产生副作用时，还应明确输入、执行位置、失败返回和恢复方式。

## 4.5 为什么安装 west 后不一定有 build

`init`、`update`、`list`、`config` 等管理命令随 west 工具提供。Zephyr 的 `build`、`flash`、`debug` 则由它的仓库扩展提供。在本实验执行 `west build -h` 找不到命令是预期结果，不是安装损坏。

当回到真实项目时，先用 `west help` 看命令归属，再找清单声明和实现文件。若要统一团队的构建或报告入口，可以添加扩展；若只有一个简单脚本且不依赖工作区上下文，直接运行脚本也很合理。扩展不会替代底层编译器、调试服务器或构建系统。

清理修改前，使用 `git -C manifest diff` 检查 --count 和描述文件的变化。只有自己本节的练习修改且无需保留时，才将对应文件恢复；新实验目录可整体另行清理。下一章把这些模型组织成团队日常流程。
