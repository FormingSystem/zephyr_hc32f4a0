# 学习资料设计与维护约定

## 2026-10-04 实验与文档发布的职责

最终约定以 `project-docs/workspace-roles.md` 为准。Git 更新原则留待后续确定，本轮不实现脚本或迁移历史；驱动提交不属于已确定的自动同步范围。此边界属于维护记录，不放入面向读者的操作路线。

按用户说明修正：F 盘仓库用于文档推送与保留 HC32 移植对照，G 盘 `zephyr_practice/zephyr-main` 用于从零复现。读者路线为原生源码下载 → SDK 与模块 → MPS2 构建 → 工具实验 → 在同一源码树完成 HC32 移植后的板级练习。G 盘工程随实验逐步形成与 F 盘参考工程一致的目录、适配、工具和文档。正文不介绍文档仓库；环境与构建脚本必须先在实验中创建和讲解，再成为后续入口。两边源码版本、功能完成度和 Git 历史分别核对，不以目录相似代替一致性证明。版权署名及历史日志原样保留。

本轮以 `.local/learning-boundary-20261004/before/` 的未提交工作树为基线，按内容纠错模式修改；重点覆盖准备章、两期下载主线、SDK 参考、工具章节返回步骤与板级前提。主机练习源码与应用功能保留；Zephyr 模块材料改为显式读取实验源码和按原生清单下载的 CMSIS_6。旧验收结果不自动迁移为 G 盘新路线实测。

本目录记录个人学习笔记和配套演示资料的组织方式。正文、PPT 及讲解备注统一称受众为“读者”，以交流经验和说明操作为目的；以下历史记录中的教学方法说明和读者原话保留原意。

## 2026-09-28 从连贯叙述改为带着操作的教学

读者明确要求保姆式教学：此前修订虽然接上了段落，仍要求读者自行消化命令、Python 语法和场景变化。本轮重写 venv 四章、west 五章的操作讲解，保留当前主线、已有读者示例和稳定文件身份。备份位于忽略的 `.local/guided-teaching-20260928/`，不复用其他目录副本。

每次引入一段程序，先说清用途、输入、保存位置和预期结果，再给带中文注释的代码，沿一个实际输入解释执行顺序。shell 的任务是准备目录和启动程序，Python 才执行代码，分别标明；重复的已有语法只作提醒，避免每步重讲整门语言。提示用来消除真实的不确定性，例如无输出是否正常、红字是否预期、何时先停下来，不用空泛鼓励代替操作依据。

图随任务出现：venv 画解释器与包关系、构建安装路径、重建流程和诊断分支；west 画 init/update 操作、版本与开发分支、配置/导入读取、扩展调用和发布顺序。每张图之后用具体节点说明本次该走哪条路径，图不冒充可粘贴命令。Python 的重点讲解落在身份输出、greet 调用、unittest、Path 查找库、Inventory 回调与交付检查，正文和配套材料同步注释。

先完成 venv P01/P02 的读图、带注释代码、预期失败和恢复校准，再按相同解释深度推进其余章节。验收包括作者逐步试读、图语法及渲染、代码与材料一致性、操作顺序及独立实验回归；自动脚本通过不能宣称真实读者已经学会。没有新增远端发布授权，本轮内容完成后留在工作树供阅读。

## 2026-09-21 手把手实训补充设计

本轮选择内容补充模式。原章节解释机制，但读者需要跨章拼接命令，测试只在维护者脚本中出现，新增项目练习也缺完整输入。将两个 labs/README 改为可独立执行的实验手册，保留原章节作为深入解释；学习中心、大纲和项目入口直接链接手册。

| 实训 | 起点与贯穿对象 | 操作顺序 | 验收与错误模型 |
| --- | --- | --- | --- |
| venv | 会使用终端，不熟悉 Python 环境；一个依赖问候包的应用 | 复制源码与测试模板→创建 A/B→构建本地安装包→不同版本运行→应用测试→卸载恢复→冻结重建→修改源码与配置 | 依赖检查通过不等于业务测试通过；以两条 unittest 断言、包版本、导入位置分别证明 |
| west | 已有 Git 基础；本地应用、库、可选文档仓库 | 工具环境→生成本地源→初始化→同步→四项验收→修改版本→分组→新增仓库→扩展→冻结重建 | 清单合法不等于已同步；预期失败必须恢复后再继续；验收核对实际 HEAD、项目集合、应用行为 |

术语按执行需要进入：先解释解释器/环境/安装包，再引入 wheel 与测试断言；west 先区分工具、清单、工作区，再引入 revision、HEAD、分组及扩展。每步标明当前目录、粘贴命令、稳定输出、失败诊断和下一步前提。运行目录分别用 venv-practice 与 west/practice-01，避免与旧教程产物混淆；不改根 .venv 或工程父目录的 .west。

验收计划：在 UCRT64 Bash 中按手册命令从空目录执行，保留终端记录；特意验证未安装、错误包版本、缺少源码、清单未同步、扩展禁用等失败及恢复。维护者回归另行跑一遍，不能用它代替手册实跑。Windows 是本轮实测平台，其他平台只提供路径替换。工程源码、板级配置与硬件不在本轮修改范围。

本次在现有完整 Zephyr 工程中新增工具专题。`learning/` 保存项目环境需要补充的通用教学知识和实验；`project-docs/` 保存本项目实际采用的版本、配置、路径和流程。用户指定的两个原空目录补为项目接入说明并链接教程，不复制通用正文。已有 Zephyr 课程继续围绕本项目源码维护，其他未提交资料保持原样。本文件是作者工作蓝图，不是读者先修材料。

## 读者起点与成果

本轮（2026-10-01）采用内容补写与机制修复模式，保留五章文件身份、原实验及顺序。修改前快照保存在本机 `.local/west-mechanism-20261001/before-west`。增加的学习成果是：读者能从清单设计仓库组合，区分格式与行为，定位 Git 执行者，并为团队字段编写、注册、验证一个扩展命令。单纯照抄字段值不算完成。
