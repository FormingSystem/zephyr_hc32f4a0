# 从新增代码到板卡适配的教学蓝图

2026-09-21 修订模式：构建、编辑器调试与板级配置改为连续单元教材；每单元在正文完成实验并展示代码，labs 仅存材料原件，不再以跳转到综合实验实现“独立闭环”。
读者会写 C/C++，需要掌握工具如何把新增文件、模块、板卡选择和接线描述变成实际产物。

| 章节 | 当前问题与新增概念 | 实验与完成条件 |
| --- | --- | --- |
| CMake P01 | 新文件为何未参与构建；target、源码列表、头文件路径、库与子目录 | 主机程序增加换算函数；漏源文件导致链接失败，恢复后输出正确 |
| CMake P02 | 普通库与 Zephyr module 的接入区别；模块发现、CMake/Kconfig 入口 | 先验证开关与编译数据库，运行及 Twister 留到 Board P03，避免超纲 |
| VS Code P01 | 插件、任务、调试器和服务器分别做什么 | 同一主机程序由构建任务生成，GDB 断点/单步观察；HC32 提供待实板验证的附加配置 |
| Board P01 | 芯片与开发板不是一个选择项；板目标、SoC、软件配置、生成配置 | 列出板目标，以固定板构建；修改软件选项，观察最终 .config |
| Board P02 | PCB 接线变动应改哪层；DTS、binding、overlay、驱动支持边界 | 独立 overlay 将 LED 别名切到已核实的第二盏灯；核对合并设备树，不假定实板已运行 |
| Board P03 | 测试选择和模拟模型的边界；Twister 场景、构建/过滤/运行 | QEMU 场景打印成功标记，HC32 场景仅编译，报告明确区分 |

术语依赖：源文件/头文件 → 构建 target → 编译/链接 → CMake 缓存/选项 → 模块入口；
芯片/封装/PCB → board/SoC 选择 → Kconfig 软件能力 → 设备树节点/引用/binding → 驱动初始化 → 测试与调试。
错误模型：保存文件不等于参与编译；头文件可见不等于实现已链接；west 取源码不等于接入模块；
设备树能生成不等于驱动支持新引脚；QEMU 通过不等于 HC32 板卡通过；安装插件不等于安装工具链。

环境实施：创建根 .venv，安装项目依赖；共享源码/模块留在本仓库，SDK 外置且由私人配置定位。
west 采用受支持的父目录工作区拓扑，仓库内 project-west.yml 只登记自身扩展，受控源码快照不重复获取。
项目命令由 Python 包装器固定解释器和源码，VS Code 任务复用它；教学主线使用 Bash、相对路径。
验证分四层记录：文档与配置检查、主机编译/GDB、HC32 编译与 QEMU、真实 VS Code UI 和实板；未执行层不写通过。
