默认使用 UCRT64 Bash，保持 Linux 命令习惯。只有 Zephyr 官方明确采用 PowerShell 的 Windows 下载/安装步骤，以及 setup.cmd 等 Windows 专用脚本和其 Windows 管理操作，才切换到 PowerShell。普通下载、摘要校验、解压、版本检查、Python/venv 与 CMake 工程操作仍用 UCRT64，不能仅因调用 Windows 可执行程序就整段改成 PowerShell。Ubuntu 22.04 使用原生 Linux Bash。每段标明终端和目录，切换时重新进入目录，临时变量不互相继承。

## 0.1\_我们在哪个终端输入命令

当前位置：步骤 0.1，确认终端与 Python。

```mermaid

    S1["0.1<br/>确认终端与 Python"]
    S2["0.2<br/>识别路径与命令"]
    S3["0.3<br/>核对平台差异"]
    S4["0.4<br/>按需准备工程工具"]
    S5["0.5<br/>保存并恢复现场"]
    S1 --> S2 --> S3 --> S4 --> S5
    classDef current stroke:#a44700,stroke-width:3px
    class S1 current
```

主线使用 Windows 上的 MSYS2 UCRT64 终端，输入语言是 Bash。MSYS2 提供这套命令行与工具环境，UCRT64 是其中一种环境的名称，终端中的 MSYSTEM 环境变量记录当前选中了哪一种。终端使用 Bash，不意味着里面启动的 Python 一定是 Linux 程序。本书明确选择 Windows Python 3.12.10，避免把不同来源解释器的目录布局混在一起。

下面三种写法指向同一个 Windows 目录，但分别服务于不同场景：

| 写法 | 用在哪里 |
| --- | --- |
| `G:\zephyr_practice\zephyr-main` | Windows 资源管理器地址栏，正文标明为 Windows 路径 |
| `/g/zephyr_practice/zephyr-main` | UCRT64 Bash 的 `cd`、`mkdir`、`cp` 等命令 |
| `G:/zephyr_practice/zephyr-main` | `cygpath -m` 输出的 Windows 混合路径，传给 Windows 版 CMake 等程序 |

主线命令直接采用 `/g/...`。这不是 Linux 系统的挂载约定；Linux/WSL 不能照抄 `/g`、`cygpath`、`cmd.exe` 和 Windows Python 的 `Scripts/activate`。需要从资源管理器复制地址时，采用下面明确的备用输入方式；粘贴地址本体，不带“复制为路径”附加的首尾双引号：

变量提示：以下名称均为**教程自定义的临时 Bash 变量，不是 Zephyr 或 CMake 原生接口**。

- `SOURCE_INPUT`：定义见 0.1 我们在哪个终端输入命令；读者输入的 Windows 源码目录。
- `SOURCE_UCRT`：定义见 0.1 我们在哪个终端输入命令；转换后的 UCRT64 源码路径。

```bash
# 终端：Windows 的 UCRT64 Bash；备用方式，从资源管理器取得 Windows 路径。
read -r -p '粘贴 Windows 源码路径（如 G:\zephyr_practice\zephyr-main，不带引号）: ' SOURCE_INPUT
SOURCE_UCRT="$(cygpath -u "$SOURCE_INPUT")"
cd "$SOURCE_UCRT"
pwd
```

`read -r` 保留输入中的反斜杠；`cygpath -u` 把 Windows 路径转换成 UCRT64 路径，预期输出为 `/g/zephyr_practice/zephyr-main`。`SOURCE_INPUT` 和 `SOURCE_UCRT` 是这里自定的变量。直接写未引用的 `cd G:\...` 会让 Bash 将反斜杠解释为转义，因此不要把资源管理器地址直接贴进命令。

若输出意外变成 `/cygdrive/g/...`，运行 `type -a cygpath` 检查命中了哪个程序，并从 MSYS2 的 `ucrt64.exe` 重新打开终端。主线应使用 MSYS2 的 `/usr/bin/cygpath`；系统 PATH 中另一套 Cygwin 工具可能采用不同的盘符映射。

SDK 与源码并列存放：Windows 路径为 `G:\zephyr_practice\zephyr-sdk-1.0.1`，UCRT64 写作 `/g/zephyr_practice/zephyr-sdk-1.0.1`。SDK 下载包可放在 `G:\zephyr_practice\downloads`，解压和安装步骤见 SDK 章。

实验统一在 `G:\zephyr_practice\zephyr-main` 进行，它是直接包含 `VERSION`、`SDK_VERSION`、`west.yml` 的 Zephyr 源码根。尚未下载源码时，先完成[源码下载](P01_zephyr_make_project/P001_准备UCRT64环境与下载Zephyr_Windows.md)。打开 UCRT64 后明确进入这个位置：

```bash
# 当前位置：任意目录；终端：UCRT64 Bash。
cd /g/zephyr_practice/zephyr-main
pwd
ls VERSION SDK_VERSION west.yml
```

`pwd` 应显示 `/g/zephyr_practice/zephyr-main`。各章的“实验源码根目录”均指这里；源码以外的 SDK 安装位置由你选择。把随笔记提供的 `learning` 材料文件夹复制到这个目录下，保留各专题的 `labs` 和 `requirements-tools.txt`。它们是额外提供的实验材料，不是 Zephyr ZIP 自带的文件；只读正文和 PPT 时无需复制，运行引用 `learning/...` 的命令前才需要准备。已有同名目录时先比较内容，保留自己的练习修改。

```bash
# 当前位置：实验源码根目录；使用 UCRT64 Bash。
printf '%s\n' "$MSYSTEM"
```

打印 MSYS2 为当前终端设置的环境标识，应看到 UCRT64。这个检查是在辨认 shell 环境，不是在检查 Python 版本。

```bash
# 当前位置：实验源码根目录；使用 UCRT64 Bash。
py -3.12 --version
```

本段是安装了 Launcher 的发现方式。没有 `py` 时也可直接用安装目录里的 `python.exe`；定版安装和 PATH 设置统一见 [P002 的 Python 环境说明](P01_zephyr_make_project/环境与依赖导航.md)。`py` 成功不代表 `python` 已在 UCRT64 的 PATH 中。

py 是 Windows Python 启动器，-3.12 要求选择已安装的 3.12 系列。应显示 Python 3.12.10；找不到版本时先完成安装。

```bash
# 当前位置：实验源码根目录；使用 UCRT64 Bash。
py -3.12 -c "import sys; print(sys.executable); print(sys.platform)"
```

引号里的代码交给 Python：import sys 取得解释器自身的信息；sys.executable 是本次程序路径，sys.platform 在 Windows Python 中为 win32。print 把两项值显示出来，不会修改配置。

```bash
# 当前位置：实验源码根目录；使用 UCRT64 Bash。
test -d learning
echo $?
```

test -d 检查目录是否存在，本身不打印成功提示；紧随其后的 echo 显示它的退出码，0 表示找到了 learning。若为 1，先调整当前目录。

这些检查分别确认终端类型、解释器身份与工作目录。只要显示的是自己安装的 Python 路径、平台为 win32，目录检查为 0，就可以继续。路径输出以你的安装位置为准，不要求与作者相同。

-c 让选中的解释器执行后面一小段 Python；-m 则让它运行某个模块。后面使用 `python -m pip` 时，正是为了让选中的 Python 运行自己的安装器。若没有 py 或所需版本，先安装 Windows Python，再重新打开终端核对。

相对路径从当前目录开始计算，../ 回到父目录。每章会说明当前位置；不是看到一个代码块就默认仍在仓库根。Bash 使用正斜杠，路径有空格时加双引号。

命令块第一行的“当前位置”是给你看的注释，不会替你执行 cd。Bash 忽略 # 后的说明；图中的步骤也只是导航，不是可以粘贴执行的命令。后面介绍 CMake 时，还会遇到“工具按配置文件所在目录解释路径”的情况，我们会在第一次用到时指出，避免把所有相对路径都按终端位置计算。

```mermaid
flowchart LR
    A["learning 下的 labs<br/>随笔记提供的材料"] -->|"复制"| B["build/learning-tools 下的练习源码"]
    B -->|"由工具读取"| C["构建目录、环境、运行报告"]
    B -->|"保存你的练习修改"| D["下次继续的起点"]
```

复制材料后才编辑练习副本；构建目录是工具随后生成的结果。build/learning-tools 只是统一收纳位置，其中既有可重建的产物，也有你亲手写过的源码，不能因为上层目录名叫 build 就全部当作垃圾删除。

命令块按行执行。普通步骤失败时先看错误，不继续运行依赖它的下一步；正文明确标记的故意失败，则紧接 `echo $?` 查看退出码，再按恢复步骤继续。0 通常表示成功，非 0 的具体含义由程序定义，例如 rg 的 1 可以表示没有匹配，并不一定是工具损坏。

少量写文件命令采用：

```text
cat > 文件名 <<'结束标记'
文件内容
结束标记
```

这段是语法示意，不直接执行。真正实验会给出具体文件名和完整内容；> 会覆盖指定文件，结束标记必须独占一行。也可以在编辑器中写入相同内容。正文不会要求先学一套 shell 脚本语言才能完成工具实验。

学习资料原件放在 learning 的各主题 labs；环境、复制品、临时 Git 历史和产物放在 build/learning-tools。新实验目录已存在时换一个名字，保留旧练习，不用删除数据来制造“从零”的假象。

## 0.3\_Windows Python 与其他平台的路径差别

当前位置：步骤 0.3，核对平台差异。

```mermaid
flowchart LR
    S1["0.1<br/>确认终端与 Python"]
    S2["0.2<br/>识别路径与命令"]
    S3["0.3<br/>核对平台差异"]
    S4["0.4<br/>按需准备工程工具"]
    S5["0.5<br/>保存并恢复现场"]
    S1 --> S2 --> S3 --> S4 --> S5
    classDef current stroke:#a44700,stroke-width:3px
    class S3 current
```

已经辨认过终端和解释器，后面看见 Scripts 路径就不会奇怪：Windows Python 创建的环境入口位于 Scripts，即使启动它的是 Bash。Linux/macOS 的 Python 通常采用 bin。这是解释器的平台差异，并非激活失败：

| 操作 | 主线：UCRT64 + Windows Python | Linux/macOS Bash |
| --- | --- | --- |
| 基础解释器 | py -3.12 | 已核对版本的 python3 |
| 环境解释器 | a/Scripts/python.exe | a/bin/python |
| 激活 | source a/Scripts/activate | source a/bin/activate |
| 退出激活 | deactivate | deactivate |

Linux 发行版可能另行提供与 Python 对应的 venv 组件。不要仅凭终端外观判断路径；先看创建出来的实际布局。本次实测以 Windows 主线为准，其他平台是替换说明。

工具安装入口可查 [Python](https://www.python.org/downloads/)与 [MSYS2 环境说明](https://www.msys2.org/docs/environments/)。venv 的第一章只需要这里的 Python；不必为它提前安装 SDK、调试器或配置真实工程。

```mermaid
    classDef current stroke:#a44700,stroke-width:3px

```

前面的检查已经足够开始 venv；west 接着使用那里学到的环境与 pip。只有进入 Zephyr 模块和板级章节，才需要这一节的 SDK 和项目工具。主机 CMake 使用电脑上的 GCC，也不需要先配置这套交叉编译环境。

先按[SDK 与依赖安装](P01_zephyr_make_project/环境与依赖导航.md)准备 Windows 主机工具，在实验源码根建立 `.venv`，再按 [P004 的 CMSIS 下载步骤](P01_zephyr_make_project/P004_CMSIS与HAL选择下载_Windows.md#section-4-2)从源码 `west.yml` 取得 CMSIS_6。**软件开发工具包（Software Development Kit，SDK）** 提供交叉编译器；Python 运行构建脚本，CMake 与 Ninja 组织构建。后续工具实验不要求先完成 HC32 移植。芯片型号与 CMSIS/HAL 的选择依据见准备专题 P004 的 4.1—4.2：官方 AN386 示例不需要 HC32 HAL；所选 HC32F4A0PITB 实板在 P004 4.2.3 单独取得配套 HAL，当前原生 west.yml 没有 hal_xhsc。

为避免换终端后选中另一份源码，每次开始 Zephyr 构建练习时，在 UCRT64 中明确恢复这些设置：

下面的 `PWD` 是 Bash 保存当前位置的变量。`ZEPHYR_BASE` 指定源码根，`Zephyr_DIR` 指定 CMake 包入口；SDK 按 [P003 的默认发现方式](P01_zephyr_make_project/P003_SDK准备与编译器选型_Windows.md#section-3-2)准备；已注册且没有旧选择覆盖时，不再重复指定 SDK 根或 `ZEPHYR_TOOLCHAIN_VARIANT=zephyr`。`ZEPHYR_MODULES` 是 Zephyr 原生的模块目录列表，本例只放入已下载的 CMSIS_6。`EXTRA_ZEPHYR_MODULES` 与 `ZEPHYR_EXTRA_MODULES` 是额外模块设置，在这里清空，避免之前终端状态影响实验。

```bash
# Windows UCRT64；任意目录；P003 已准备并注册 SDK，P004 已核验工作区与 CMSIS_6。
# 仅供后续显式模块输入实验使用；普通官方应用按主线 P007 操作。
cd /g/zephyr_practice/zephyr-main
source .venv/Scripts/activate
export ZEPHYR_BASE="$(cygpath -m "$PWD")"
export Zephyr_DIR="$ZEPHYR_BASE/share/zephyr-package/cmake"
export ZEPHYR_MODULES="$(cygpath -m "$(west list cmsis_6 -f '{abspath}')")"
unset EXTRA_ZEPHYR_MODULES ZEPHYR_EXTRA_MODULES
python -c 'import sys; print(sys.executable)'
python -m pip check
cmake --version
ninja --version
test -f "$(cygpath -u "$ZEPHYR_MODULES")/zephyr/module.yml"
echo $?
```

`source` 只激活已经创建的环境；`export` 把源码和模块位置交给当前终端启动的程序。`ZEPHYR_MODULES` 是 Zephyr 原生输入，此处以一个模块路径为值。配套应用显式读取该环境输入；路径来自主线 P004 的 4.2.2 节模块下载步骤。最后输出 `0` 表示找到了模块声明文件。检查失败时返回对应准备步骤，不能用另一份源码目录补位。

这里复用主线 P004 已核对的 west 工作区与已下载的 CMSIS，不重复初始化或下载。主线 [P007 的官方应用](P01_zephyr_make_project/P007_Zephyr应用构建_Windows.md#section-7-2)由 Zephyr 在 CMake 配置时查询 west 并发现模块；本页的 ZEPHYR_MODULES 仅服务于后续专门讲显式输入的 CMake 配套应用，不是所有 Zephyr 应用都必须设置的前提。[主线 P008](P01_zephyr_make_project/P008_west零基础与Zephyr构建_Windows.md)先从 west 零基础讲到 Zephyr 扩展与 CMake 配合；[独立 west 专题](west/大纲.md)才另建小型 Git 实验深入讲清单，不在 zephyr-main 删除或替换官方 west.yml。主机 CMake 练习只使用 Windows GCC，不需要 SDK；Twister/QEMU 章节还需要安装测试依赖和模拟器。HC32 板级章节则要求在同一实验源码树完成相应移植，不能只修改 `BOARD` 字符串。

## 0.5\_如何停下来与重新开始

当前位置：步骤 0.5，保存并恢复现场。

```mermaid
    S4["0.4<br/>按需准备工程工具"]

    classDef current stroke:#a44700,stroke-width:3px
    class S5 current
```

工具准备好以后，通常不需要一口气做完所有实验。暂停前记下“做到哪一节、练习目录是什么、刚才是否还处于故意失败状态”。章节结尾会交代保留的状态；下次先打开同一份练习材料，进入章节指定目录，再按需要激活对应环境。
