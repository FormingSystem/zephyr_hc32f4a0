# VS Code：从构建到断点与单步

[搭建编译与单步调试环境](P001_搭建编译与单步调试环境.md)先用可运行的主机 C 程序区分任务、插件、GDB，再映射到 HC32 的 ARM GDB、pyOCD 和探针。

正文完整展示工作区配置和 GDB 命令，使用 CMake 起始原件，避免限幅练习改动影响 42→43 的观察。

```mermaid
flowchart LR
    A["构建原始主机程序"] --> B["读懂任务与 program 的对应"]
    B --> C["断点观察 42 → 43"]
    C --> D["用 GDB 命令复核"]
    D --> E["换到工程工作区"]
    E --> F["有硬件后再验实板链路"]
```

第一次阅读先完成主机路线。正文说明按钮触发的程序、暂停前后的变量和常见失败的检查顺序；实板部分再引入服务器与探针。主机 GDB 的结果不能代替 VS Code 图形操作或 HC32 实物验证，实际覆盖范围见[验收记录](../BUILD_BOARD_VALIDATION.md)。

前提：[CMake 主机实验](../cmake/P001_把源文件和库加入构建.md)。完成标准是命中断点、观察变量变化并能定位所调试的产物；实板步骤另行验收。
