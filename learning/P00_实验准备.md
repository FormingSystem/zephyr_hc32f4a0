# 0. 实验基线与命令约定

本系列面向已有 C/C++、嵌入式开发和基本命令行经验的读者。零基础指对 Python 环境隔离、包管理与 west 没有系统知识；不重讲编程语法。本章对齐终端、解释器和工作目录，之后直接进入工具实验。

## 0.1 在 UCRT64 Bash 中选择解释器

本机主线使用 MSYS2 的 UCRT64 终端，其中命令语言是 Bash。**终端使用 Bash，并不代表里面运行的 Python 一定来自 Linux。** UCRT64 自带的 Python、系统安装的 Windows Python，可能同时存在，版本与生成环境的布局也可能不同。

本教程选择已安装的 Windows Python 3.12，由启动器 `py -3.12` 明确选定。在仓库根目录执行：

```bash
printf '%s\n' "$MSYSTEM"
type -a python python3 py git
py --list
py -3.12 --version
py -3.12 -c "import sys; print(sys.executable); print(sys.platform)"
git --version
```

UCRT64 窗口的 MSYSTEM 应为 UCRT64；选中的 Python 在本次实验中报告 win32。输出的解释器位置由你自己的安装决定，不要照抄别人的磁盘路径。若没有 `py` 或 3.12，先安装对应 Python，或选择已确认的解释器并相应核对环境布局。不要看到 `python` 能运行就假定它等于 `py -3.12`。

**解释器（interpreter）** 是执行 Python 代码的程序。`-c` 执行紧随其后的短代码；`-m` 让选中的解释器运行指定模块。例如 `python -m pip` 将包安装器绑定到这份 Python，避免安装者和运行者来自不同环境。

基础工具入口：[Python 下载](https://www.python.org/downloads/)、[Git 安装](https://git-scm.com/book/en/v2/Getting-Started-Installing-Git)、[MSYS2 环境说明](https://www.msys2.org/docs/environments/)。首次安装工具可能联网，后续实验使用本地包与 Git 仓库。

本机 UCRT64 默认找到 MSYS2 Git。Windows Python 调用它时，MSYS 运行库可能再次展开 Git 的 `v1.0^{commit}` 等参数，导致 west update 报 `not a valid SHA1`。在当前教学终端执行：

```bash
export MSYS="${MSYS:+$MSYS }noglob"
```

这行保留已有 MSYS 选项并追加 noglob，关闭这层参数展开；Bash 自己的通配符功能不变。设置只属于当前终端及其子进程，不写机器配置。本机已复现该错误，并验证此设置恢复 update。使用 Git for Windows 的原生 Git 时未复现同一问题；Linux/macOS 无须这项 MSYS 设置。

## 0.2 相对路径与平台替换

“仓库根目录”指包含本仓库 README 与 learning 的目录。每组实验标明当前位置。命令采用相对路径；即使你的仓库换了盘符，保持目录关系仍可执行。Bash 用正斜杠，路径有空格时加双引号。

UCRT64 Bash 运行本教程所选 Windows Python 时，虚拟环境可执行文件在 `Scripts/`。Linux/macOS 读者按下表替换命令，其余实验步骤相同：

| 操作 | UCRT64 Bash + Windows Python（主线） | Linux/macOS Bash |
| --- | --- | --- |
| 基础解释器 | `py -3.12` | `python3`，先核对版本 |
| 环境解释器 | `环境目录/Scripts/python.exe` | `环境目录/bin/python` |
| 激活 | `source 环境目录/Scripts/activate` | `source 环境目录/bin/activate` |
| 退出 | `deactivate` | `deactivate` |

表中的“环境目录”是说明占位符；正文给出可直接执行的真实相对路径。Linux 的发行版可能单独提供 venv 组件，应安装与所选 Python 对应的包。本次没有把 UCRT64 自带 Python 3.14 作为基线；如果自行换解释器，先观察它生成的目录，再调整路径，不能机械套用 Linux 路径。

不用先学 shell 脚本：正文按行执行命令。少数括号块 `(...)` 在子 shell 中临时切换目录或配置，结束后不污染外层终端。失败后用 `echo $?` 观察退出码，先处理原因，再执行依赖步骤。

## 0.3 实验位置、网络与清理

教学源码在各主题 labs 中；环境、轮子包、临时 Git 仓库和运行证据统一生成到 `build/learning-tools/`，由仓库现有规则忽略。本项目实际配置记录在 [project-docs/](../project-docs/README.md)。

工具和构建后端准备好后，两个教学包与 west 源仓库都在本机，主要实验不联网、不下载 Zephyr，不需要开发板。为了让构建产物只进入 build，打包前先复制教学源码，再构建复制品。

清理前退出环境、离开目标目录并保存修改。只删除自己生成并核对过的实验目录。虚拟环境可按依赖说明重建；west 工作区包含开发源码和 Git 历史，不能把二者都当成无条件可删的缓存。
