# Python venv：从运行程序到可重建环境

**venv** 是 Python 自带的模块名称，用来建立一个拥有独立包安装位置的环境。它解决“项目 A 和项目 B 依赖冲突”，并不安装另一套操作系统。

先完成[终端准备](../../P00_实验准备.md)。本教程用两个同名、不同版本的小包贯穿全过程，不要求先懂 Zephyr 或打包工具。

| 顺序 | 本章解决的问题 | 亲手获得的证据 |
| --- | --- | --- |
| [P01 创建并认识虚拟环境](P01_创建并认识虚拟环境.md) | 什么程序在执行？激活改了什么？ | 解释器路径、环境前缀、激活前后对照 |
| [P02 安装包并验证版本隔离](P02_安装包并验证版本隔离.md) | 包装到了哪里？两个版本能否共存？ | 两个环境的问候语、版本号、安装位置 |
| [P03 配置依赖并重建环境](P03_配置依赖并重建环境.md) | 同事如何复现？怎样修改安装配置？ | 配置覆盖、依赖快照、离线重建 |
| [P04 排错与工程使用习惯](P04_排错与工程使用习惯.md) | 提示安装成功却导入失败怎么办？ | 诊断顺序、可编辑安装、选型与挑战 |

先动手再追原理：[完整实训](labs/README.md) 从复制应用与测试模板开始，逐步完成环境创建、打包、安装、错误版本测试、卸载恢复、离线重建、配置修改与可编辑安装。每步解释参数与状态，实训目录与章节目录分开，不需要先跑自动脚本。

已测版本和自动验收：[验证记录](../../VALIDATION.md)。按章节顺序阅读时，P01 创建的 A/B 环境由 P02 安装包，P03 增加重建环境；P04 的扩展练习另用独立环境。
