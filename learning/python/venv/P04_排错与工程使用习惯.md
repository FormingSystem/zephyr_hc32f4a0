# 4. 排错与工程使用习惯

前面已经完成创建、安装和重建。实际工作里仍会遇到“安装成功却导入失败”。**venv** 是创建虚拟环境的 Python 模块名；**pip** 是安装器名称。错误往往出在执行路径、包声明或导入位置，而不是需要再激活几遍。本章从可观察证据出发，最后练习一种适合改源码的安装方式。

## 4.1 用同一个解释器提问

当前位置：仓库根目录。A 已按 P02 安装 v1。以下 `PY` 表示 `build/learning-tools/venv/a/Scripts/python.exe`，执行前替换；Linux/macOS 换成同目录下 `bin/python`。

```text
PY -c "import sys; print(sys.executable); print(sys.prefix); print(sys.base_prefix)"
PY -m pip --version
PY -m pip show lab-greeting
PY -c "import lab_greeting; print(lab_greeting.__file__)"
PY -m pip check
```

先判断解释器身份，再判断 pip 安装位置，然后看实际导入文件，最后检查声明关系。这样每一步缩小一个范围：包根本没装进 A、装进 A 但名称错误、被其他文件遮蔽、或者依赖不兼容。

**导入路径（import path）** 是 Python 查找模块的一组目录，运行时保存在 `sys.path` 属性里。**PYTHONPATH** 是可额外加入搜索目录的环境变量；虚拟环境本身不保证清除它。项目当前目录或脚本目录也可能参与搜索，因此把自己的文件命名为 `json.py`、`pip.py`、`lab_greeting.py` 会产生意外遮蔽。

## 4.2 故意制造一次遮蔽

创建 `build/learning-tools/venv/shadow/`，在里面新建 `lab_greeting.py`，内容为 `print('local shadow module')`。仍使用已经装有 v1 的 A，以完整解释器路径从该目录执行：

UCRT64 Bash：

```bash
(cd build/learning-tools/venv/shadow && ../a/Scripts/python.exe -c "import lab_greeting; print(lab_greeting.__file__)")
(cd build/learning-tools/venv/shadow && ../a/Scripts/python.exe -c "from lab_greeting import greet")
```

第一条指向当前目录中的文件；第二条因为该文件没定义 `greet` 而失败。pip 显示安装正确与导入失败可以同时成立。把自己新建的遮蔽文件改名后重试，或离开该目录；不要先卸载所有依赖。清理时只删除本例 `shadow/`。

官方对照：[Python 模块搜索路径](https://docs.python.org/3.12/tutorial/modules.html#the-module-search-path)，带着“为什么当前目录优先”阅读。

## 4.3 把常见症状变成定位步骤

表中的 `python` 是解释器命令，`pip` 是安装器命令，`setuptools` 是构建后端工具名称，`ensurepip` 是 Python 随附的 pip 引导模块名称。先区分执行者、安装器和构建工具，才能把错误分派到正确的一层。

| 现象 | 优先检查 | 恢复动作与边界 |
| --- | --- | --- |
| 找不到 `python` 或 `pip` | 实际解释器路径是否存在 | 用完整路径，确认基础 Python 安装；不靠随机重装解决 |
| 安装成功却找不到模块 | `sys.executable` 与 `pip --version` 是否同环境 | 用运行程序的解释器执行 `-m pip`；再检查安装名和导入名 |
| 环境解释器提示基础路径失效 | 基础 Python 是否被卸载、环境是否被移动 | 按新解释器重建，不手改一串绝对路径 |
| 提示 `externally-managed-environment` | 是否正在修改发行版管理的系统 Python | 为项目建环境，再在环境中安装；无需破坏系统包管理 |
| 新环境没有 `setuptools` | Python 版本与项目构建需求 | 3.12 的该现象正常，按构建声明准备后端 |
| 没有 `ensurepip`/venv 组件 | 所选 Python 的来源 | 安装匹配发行版组件，或使用包含该模块的受支持发行版 |
| 提示没有匹配版本 | 包名、版本、索引、Python 版本和平台 | 查发布支持范围；旧包没有新 Python wheel 时可能需编译或换兼容版本 |
| 命令行正常，编辑器运行失败 | 编辑器选择的解释器 | 把项目解释器设为同一个环境路径，再用观察程序核对 |

编辑器的运行/调试配置可以选择自己的 Python 解释器，不一定沿用另一个终端的激活状态。这与嵌入式工程中终端和编辑器可能选中不同工具链类似；不要只看状态栏文字，用程序输出确认。

## 4.4 自己改包时使用可编辑安装

**可编辑安装（editable install）** 是让环境从开发目录读取项目代码的一种安装方式。常规安装把可分发结果装进环境，改源码后通常要重新安装；可编辑安装常用于边改边测，但修改元信息、入口命令或本地扩展后仍可能需要重新安装/构建。

当前位置：仓库根目录。复制 `labs/package_v1` 到 `build/learning-tools/venv/edit-src`，避免覆盖正式教材。UCRT64 Bash：

```bash
cp -R learning/python/venv/labs/package_v1 build/learning-tools/venv/edit-src
py -3.12 -m venv build/learning-tools/venv/dev
build/learning-tools/venv/dev/Scripts/python.exe -m pip install setuptools==80.9.0
build/learning-tools/venv/dev/Scripts/python.exe -m pip install --no-build-isolation -e ./build/learning-tools/venv/edit-src
build/learning-tools/venv/dev/Scripts/python.exe -c "import lab_greeting; print(lab_greeting.__file__); print(lab_greeting.greet())"
```

确保 `edit-src` 原先不存在，避免重复复制改变目录层次。`-e` 是 editable 的选项。修改复制品 `src/lab_greeting/__init__.py` 中的问候语，再启动一次命令；预期新进程输出变化，A 的已安装 wheel 不受影响。已经运行的长寿命 Python 进程可能缓存旧模块，不能据此推断源码未生效。

执行 Dev 的 `-m pip uninstall lab-greeting` 会解除该环境安装关系，不删除 `edit-src` 的源码。清理时保存自己的修改，再移除 dev 环境和复制品。[pip 本地项目安装](https://pip.pypa.io/en/stable/topics/local-project-installs/#editable-installs)给出可编辑模式与常规安装的行为边界。

## 4.5 常见工程约定与选择依据

一个独立项目通常对应一个环境，源码和环境分开；环境路径、Python 版本、依赖安装与测试入口写入项目文档。运行脚本和自动化优先明确指定解释器，交互终端则可以激活后使用短命令。升级先在新环境验证，再更新依赖记录和测试结果，保留回退组合。

**pipx** 是为独立 Python 命令行工具创建独立环境并暴露命令的工具名称，适合一个工具供多个项目使用；**uv** 是提供 Python 项目和包管理能力的工具名称；**Conda** 是能够管理 Python 及其他二进制依赖的环境工具名称。这些工具的工作范围不同：只需要理解包隔离且愿意管理依赖记录时，venv 加 pip 就能完成任务；需要统一锁定、解释器管理或复杂本地库时，再根据团队要求评估额外工具。这里是按职责作选择，没有要求项目迁移工具。

官方进一步阅读：[pipx 的工具隔离](https://pipx.pypa.io/stable/)、[uv 项目环境](https://docs.astral.sh/uv/concepts/projects/layout/)、[Conda 环境管理](https://docs.conda.io/projects/conda/en/stable/user-guide/tasks/manage-environments.html)。venv 自身不提供跨 Python 版本安装、完整依赖锁定或系统库隔离。

综合验收：另选一个项目目录，创建新环境，用本地需求文件安装 v1，输出解释器位置、包位置与问候语；重开终端且不激活，再用完整路径运行一次。若这四步都能解释，就已经掌握可迁移的模型，而不仅是记住 `activate`。
