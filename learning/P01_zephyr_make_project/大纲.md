# 第1章\_Zephyr从工程布局到构建

先认识 Zephyr 能解决什么问题、是否适合自己的项目，再弄清工程组成、准备环境，把一个明确应用编译成面向一个明确硬件目标的固件。贯穿任务是 hello_world + mps2/an386，成功后再换应用、加模块、接入 HC32。


正文中的“第几行”从所指代码块首行起算，注释和空行计入，阅读器自动折行不计。参数说明同时保留原样片段，配置说明给出文件与键，输出说明复用实际字段名；可先按这些名称定位，再读其作用。每篇末尾的命令索引按正文顺序提供可复制附件，执行前先阅读对应小节的环境和前提。

## 1.1\_先认识工程，再选环境

第一次接触 Zephyr，从 [P001 认识 Zephyr 与技术选型](P001_认识Zephyr与技术选型.md) 开始：用采集终端理解实时操作系统、系统组件与工程复用，再判断收益、成本和待验证条件。已经明确采用 Zephyr 的读者可以进入 P002。

[P002 工程布局与构建全景](P002_工程布局与构建全景.md) 接着把选型认识落到工程：先找到应用、主源码和输出目录，再读[架构、SoC 与开发板的职责](P002_工程布局与构建全景.md#hardware-layers)，区分硬件支持层与模块接入方式，最后把板目标对应到真实目录并认识构建输入。这两章均无需预先安装工具。

| 环境 | 源码与主机准备 | Python 和 SDK |
| --- | --- | --- |
| Linux Bash / WSL Linux | [P003 Linux](P003_环境安装与源码准备_Linux.md) | 同章完成 Linux venv 与 SDK |
| Windows PowerShell | [P003 PowerShell](P003_环境安装与源码准备_PowerShell.md) | 同章完成 Windows venv；P005 安装 SDK |
| Windows UCRT64 Bash | [P003 UCRT64](P003_环境安装与源码准备_UCRT64.md) | P004 完成 Windows venv；P005 安装 Windows SDK |

三个环境各有 Git 获取和 ZIP 获取分支，在 P006 取得配套模块，在 P008 完成构建。没有 Git 历史不妨碍本地编译，有历史也不证明网络可用。公司内部 Git 与官方 GitHub 的来源区别在 P006 结合现有材料说明；材料齐全时不必重新获取。选择一条环境路线，不把两种 Windows 终端的命令混着执行。

west 随这条操作线逐步展开：P002 认识它管理哪些目录，环境章区分“安装程序”和“取得源码”，P006 讲清清单与 init/update 并完成依赖准备。P007/P007 先看到 CMake 怎样构建，P009 再解释 west 如何读取同一工作区、加载 Zephyr 扩展并调用这个构建过程。P009 保留在首次构建之后，前面的操作背景在使用处说明，不要求读者来回翻章才能执行第一条命令。

示例源码根：UCRT64 为 `/g/zephyr_practice/zephyr-main`，PowerShell 为 `G:\zephyr_practice\zephyr-main`，Linux 为 `~/zephyrproject/zephyr`。它们是实验位置，文档仓库不是实验前提。旧材料目录 p003、p006 为稳定实验标识，不随章号迁移。
