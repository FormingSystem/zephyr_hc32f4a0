# 第14章\_M95P32缓冲页编程参数

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structflash__m95p32__ex__op__page__program__with__buffer__load__in.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：本页是闪存（Flash）应用程序接口（Application Programming Interface，API）参考。先读[Flash概述](../hardware/P012_Flash闪存.md)理解设备偏移，再按[本册大纲](大纲.md)区分应用接口、驱动后端（Driver Backend）、页布局（Page Layout）和扩展操作。原始标识符、类型与常量保持不变；重复的接口摘要与详细说明均保留。

`FLASH_M95P32_EX_OP_PAGE_PROGRAM_WITH_BUFFER_LOAD` 的输入参数。

```c
#include <zephyr/drivers/flash/m95p32_flash_api_extensions.h>
```

<a id="details"></a>

`FLASH_M95P32_EX_OP_PAGE_PROGRAM_WITH_BUFFER_LOAD` 的输入参数。编程前必须擦除目标存储阵列（Array）。驱动按 M95P32 的 512 字节页边界拆分数据，通过缓冲加载模式，将当前页的编程与下一页的数据加载重叠执行。

### `length`

```c
size_t flash_m95p32_ex_op_page_program_with_buffer_load_in::length
```

要编程的字节数。

> 译注——源码核对：当前M95P32实现先检查输入结构指针，接着在length为0时直接成功返回，之后才校验数据指针和范围。非零请求必须满足相应区域边界；零长度的快速返回不能证明偏移、数据缓冲区或目标配置有效。

<a id="ae089bd14b1b322f257aeb2d55ac9534f"></a>

### `offset`

```c
off_t flash_m95p32_ex_op_page_program_with_buffer_load_in::offset
```

M95P32 主存储阵列（Main Memory Array）中的偏移。

> 译注——源码核对：本字段的坐标由具体操作决定：读取标识区使用整个1024字节标识区的偏移；写入客户标识页虽然原文称“页中的偏移”，当前实现要求512～1023，即整个标识区坐标，不是从0开始的页内坐标；主阵列编程则使用主阵列自身的设备偏移。请按本页结构体名称与下方操作说明区分。

## 14.3\_源码定位与操作边界

本组是Zephyr官网的M95P32驱动扩展，包含[操作接口](P011_M95P32扩展操作接口.md)、三种输入结构、[头文件参考](P015_M95P32扩展头文件参考.md)与[源码浏览](P016_M95P32扩展头文件源码.md)。使用情境见已译[PGEEZ1官方示例](../shield_samples/P023_PGEEZ1扩展存储操作.md)。源码译注核对了[官方扩展头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/drivers/flash/m95p32_flash_api_extensions.h)与[MSPI NOR器件扩展实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/flash/flash_mspi_nor_quirks_m95p32.h)，摘要见[来源记录](../SOURCES.md)。这些文件未包含在本仓库当前源码中，故保留上游链接，不创建虚假的本地链接。

> 译注——输入与输出：调用flash_ex_op时，in传入对应结构体地址转换得到的uintptr_t。读取标识页时，out指向至少length字节的输出缓冲区；写入与缓冲页编程使用结构体的data输入，当前实现不使用out。上层还需启用CONFIG_FLASH_EX_OP_ENABLED并取得支持该操作的设备。

> 译注——缓冲编程边界：目标区域需要预先擦除。当前实现检查主阵列范围、512字节页大小和PGPR命令；范围或页大小错误返回-EINVAL，选定页编程命令不是PGPR时返回-ENOTSUP。每块长度还受packet_data_limit限制，逐块等待缓冲区空闲，最后等待写入完成。只有最后等待成功才尝试关闭缓冲模式，因此不能把出错返回理解为一定已恢复该模式。

本批仅翻译和核对官方源码，未构建、烧录、读写标识页或执行存储擦除；上游链接的main会滚动更新。
