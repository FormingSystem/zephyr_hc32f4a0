### `timespec_from_timeout()`

```c
void timespec_from_timeout ( k_timeout_t timeout, struct timespec * ts )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/timeutil.h>
```

将内核超时（Kernel Timeout）转换为timespec。

此函数把以Zephyr k_timeout_t对象表示的持续时间（Duration）转换为struct timespec对象。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` timeout` | 要转换的内核超时。 |
| `[out] ts` | 用于保存结果的timespec。 |

**说明（Note）**：若启用了断言且timeout不是相对超时，例如使用K_TIMEOUT_ABS_TICKS或类似接口生成的超时，此函数将触发断言。

<a id="gab6b84a5c3f4fd24ab8f568f0626a0149"></a>

### `timespec_to_timeout()`

```c
k_timeout_t timespec_to_timeout ( const struct timespec * req, struct timespec * rem )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/timeutil.h>
```

将timespec转换为内核超时。

此函数把以timespec对象表示的持续时间req转换为Zephyr k_timeout_t对象。

如果req表示负持续时间，或tv_sec和tv_nsec均为零，函数返回K_NO_WAIT。

如果req为可表示的最大timespec，即{max(time_t), 999999999}，函数返回K_FOREVER。

如果req超过可由tick表示的最大等效持续时间，则返回可表示的最大tick持续时间，即对req向下取整。

其余情况返回向上取整到tick边界的k_timeout_t。

如果rem非NULL，将其设置为转换余量，即请求持续时间与转换后持续时间的差，以timespec表示，大致如下例所示。

原始示例（Example）：

```c
rem = requested_duration - converted_duration
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` req` | 请求转换的timespec。 |
| `[out] rem` | 可选指针，用于保存转换余量的timespec。 |

**返回（Returns）**：对应的内核超时。

## 2.4\_源码定位与版本边界

本册提供[时间表示](P002_时间表示接口.md)、[时间同步](P003_时间同步接口.md)、[单位换算](P007_时间单位辅助接口.md)与[timespec工具](P008_timespec时间工具接口.md)。头文件相对定位：[timeutil.h](../../../include/zephyr/sys/timeutil.h)、[time_units.h](../../../include/zephyr/sys/time_units.h)，实现定位：[timeutil.c](../../../lib/utils/timeutil.c)。

配置与构建定位：[Kconfig](../../../lib/utils/Kconfig)、[CMakeLists.txt](../../../lib/utils/CMakeLists.txt)。本次[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/timeutil.h)、[单位换算头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/time_units.h)及[官方实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/timeutil.c)摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：阅读边界：时间表示（Time Representation）处理UTC日历字段与POSIX秒数，时间同步（Time Synchronization）映射两个计数时钟，单位换算（Unit Conversion）处理时长的单位与舍入，timespec工具处理秒／纳秒二元组。它们不自动校准RTC、选择时区或建立网络授时服务。

> 译注——源码核对：版本与定位：以下译注核对本次官方main源码，链接中的本仓库源码只是相对定位入口，不保证读者的本地版本与滚动更新的latest相同。官方原文、原始代码及法律注释保留；译注不修改接口契约。

> 译注——源码核对：timeutil_timegm64按tm_year+1900、tm_mon+1和日期字段计算UTC对应的POSIX秒数，不读取时区或夏令时，也不依赖tm_yday／tm_wday。实现没有空指针、日期字段合法性或任意越界字段规范化检查；64位结果也不是对无效输入的验证。

> 译注——源码核对：timeutil_timegm将64位结果转换为time_t，并把errno清零后执行范围检查；当前实现仅在time_t与int32_t同宽时检查有符号32位范围，越界返回-1并置ERANGE。合法的纪元前一秒也可能返回-1，须结合errno判断。

> 译注——源码核对：timespec_from_timeout接受相对超时（Relative Timeout）及永久等待哨兵；绝对期限（Absolute Deadline）不属于该接口的常规输入。普通节拍按向下换算分解为秒与纳秒；K_FOREVER映射到专用timespec值。

> 译注——源码核对：timespec_to_timeout把正时长向上对齐到节拍边界，并限制到可表达的最大节拍数。rem按“请求值减换算后时长”计算，向上舍入时可能为负，封顶时可能为正；它不是一律非负的余数。rem与req必须采用不同存储，当前实现会先写rem再读取req计算差值，重叠会破坏输入。

本次验证范围为文档与源码对照，未编译或执行时间同步、计时精度及实板实验。
