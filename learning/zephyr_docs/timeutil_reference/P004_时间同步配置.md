# 第4章\_时间同步配置

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structtimeutil__sync__config.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：先读[时间工具指南](../kernel/P037_时间工具.md)，再按[本册大纲](大纲.md)查时间表示、同步、单位换算及timespec接口。源码跟踪译注与官方原文分开标示。

同步两个时钟所需的不可变状态（Immutable State）。

```c
#include <zephyr/sys/timeutil.h>
```

<a id="details"></a>

同步两个时钟所需的不可变状态，保存两个时间尺度之间转换持续时间所需的值。注意：转换准确度及计算所得源间偏斜取决于这些频率的分辨率。当本地参考为Zephyr tick计数器时，具备微秒或纳秒分辨率的参考频率能提供更准确的跟踪。对于分辨率为1 Hz的RTC芯片等参考源，必须拉大采样时刻之间的间隔，才能检测相对时钟漂移。

## 4.2\_详细说明（Detailed Documentation）

<a id="a4c180ceb790108292c8c7a825792603f"></a>

### `local_Hz`

```c
uint32_t timeutil_sync_config::local_Hz
```

标称本地计数速率，以Hz表示。

假定此值不准确但相当稳定。对于晶体振荡器驱动的本地时钟，25 ppm误差很常见；RC振荡器通常有更大的误差。timeutil_sync设施可以计算本地与参考时钟之间的偏斜，并在时间尺度转换时应用修正。

该值必须为正。

<a id="a0ee43492ae85a6305a326046501a8ac7"></a>

### `ref_Hz`

```c
uint32_t timeutil_sync_config::ref_Hz
```

标称参考计数速率，以Hz表示。

假定此值精确，但可能随参考时钟源发生漂移。

该值必须为正。

## 4.3\_源码定位与版本边界

本册提供[时间表示](P002_时间表示接口.md)、[时间同步](P003_时间同步接口.md)、[单位换算](P007_时间单位辅助接口.md)与[timespec工具](P008_timespec时间工具接口.md)。头文件相对定位：[timeutil.h](../../../include/zephyr/sys/timeutil.h)、[time_units.h](../../../include/zephyr/sys/time_units.h)，实现定位：[timeutil.c](../../../lib/utils/timeutil.c)。

配置与构建定位：[Kconfig](../../../lib/utils/Kconfig)、[CMakeLists.txt](../../../lib/utils/CMakeLists.txt)。本次[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/timeutil.h)、[单位换算头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/time_units.h)及[官方实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/timeutil.c)摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：阅读边界：时间表示（Time Representation）处理UTC日历字段与POSIX秒数，时间同步（Time Synchronization）映射两个计数时钟，单位换算（Unit Conversion）处理时长的单位与舍入，timespec工具处理秒／纳秒二元组。它们不自动校准RTC、选择时区或建立网络授时服务。

> 译注——源码核对：版本与定位：以下译注核对本次官方main源码，链接中的本仓库源码只是相对定位入口，不保证读者的本地版本与滚动更新的latest相同。官方原文、原始代码及法律注释保留；译注不修改接口契约。

> 译注——源码核对：先将同步状态（Synchronization State）清零并设置cfg，使配置对象在使用期间有效。ref_Hz与local_Hz应为正；参考计数ref的0被用作未初始化哨兵，本地计数local允许为0。接口没有为所有配置指针和频率提供运行时有效性检查。

> 译注——源码核对：state_update安装首个有效基准时总把skew设为1.0f，与原说明中“仅当skew为0时设置”的措辞存在差异。后续采样只与base比较，不与已有latest比较；只要晚于base，也可能用比原latest更早的采样替换latest。更新采样不会自动估计或应用skew。

> 译注——源码核对：estimate_skew计算参考增量×本地标称频率÷本地增量÷参考标称频率，返回估计值而不修改状态。set_skew只检查skew>0；调用者还应保证有限值（Finite Value）及有效基准。它不验证新基准的ref非零或时间顺序。

> 译注——源码核对：CONFIG_TIMEUTIL_APPLY_SKEW决定换算是否应用校正：本地到参考方向乘skew，反方向除skew。返回值1仅表示存储的skew不等于1，即使关闭该配置也可能返回1，不能单凭返回值认定已应用校正。

> 译注——源码核对：换算使用有符号64位中间量，未覆盖所有差值、乘法和类型转换溢出。参考结果为负时返回-ERANGE且不写结果；反向结果类型为int64_t，允许负本地时间。调用者应约束计数跨度、频率与输出范围，不能按任意uint64_t全范围外推。

> 译注——源码核对：skew_to_ppb按(1-skew)×10^9转换，正误差表示本地时钟偏快。超出int32_t可表达范围时返回INT32_MIN；它没有完整处理NaN／无穷值的输入验证。float分辨率也限制校正精度，不能把ppb单位理解为达到1 ppb测量精度。

本次验证范围为文档与源码对照，未编译或执行时间同步、计时精度及实板实验。
