## 13.3\_详细说明（Detailed Documentation）

### `precision_pi_init()`

```c
void precision_pi_init ( struct precision_pi * pi, double kp, double ki )
```

```c
#include <zephyr/precision_timing/precision_pi.h>
```

初始化比例积分（PI）控制器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pi` | 控制器实例。 |
| `kp` | 比例增益（Proportional Gain）。 |
| `ki` | 积分增益（Integral Gain）。 |

void precision_pi_reset ( struct precision_pi * pi)

```c
#include <zephyr/precision_timing/precision_pi.h>
```

保留已配置的增益。

**参数（Parameters）**

## 13.4\_源码定位与版本边界

官方源码定位：[precision_pi.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/precision_timing/precision_pi.h)、[precision_pi.c](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/precision_timing/precision_pi.c)。摘要见[来源记录](../SOURCES.md)。本批对应的官方模块未出现在当前仓库源码中，故使用官方来源链接；译文内部导航均为相对链接。

> 译注——源码核对：以下源码跟踪译注依据来源记录中保存摘要的官方main文件，与官方正文分开。精确计时（Precision Timing，也译作精密计时）为协议提供通用部件，本身不负责选择主时钟、拒绝样本、锁定检测或失步恢复；本批核对不表示本仓库已集成该模块。

> 译注——源码核对：每个precision_pi实例独立保存kp、ki与integral。init写入两个增益并把integral清零；reset只清零积分项，保留增益。本次实现的更新顺序是先integral += ki × error，再返回kp × error + integral。

> 译注——源码核对：update没有采样间隔参数，不自动乘以经过时间，也不执行输出限幅、积分抗饱和（Anti-windup）、NaN检查或锁定状态判断。调用频率、误差符号、增益单位与有效范围须由上层控制策略确定，不能将它当成完整时钟同步伺服器（Clock Servo）。

> 译注——源码核对：Kconfig中的PTP／gPTP默认增益按千分之一表达，本次默认KP=700、KI=300，即0.7与0.3；直接调用precision_pi_init传入的是double增益，不应再把700与300原样传作相同物理意义。官方配置帮助以约1秒同步间隔说明默认值，更短间隔可能需要减小增益。

> 译注——源码核对：实例状态会在update/reset中修改；实现没有互斥或原子保护。多个调用上下文共享同一实例时，需要调用方安排同步；多个独立实例不共享积分状态。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
