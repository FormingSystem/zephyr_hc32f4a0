# 第1章\_数字信号处理接口

原文：[官方页面](https://docs.zephyrproject.org/latest/services/dsp/index.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 1.1\_数字信号处理（Digital Signal Processing，DSP）

DSP API 提供与体系结构无关的信号处理方式。原文说明，该 API 可在任何体系结构上工作，但未必经过优化。原页列出的状态如下。

| 体系结构（Architecture） | 状态（Status） |
| --- | --- |
| ARC | 已优化（Optimized） |
| ARM | 已优化（Optimized） |
| ARM64 | 已优化（Optimized） |
| MIPS | 未优化（Unoptimized） |
| POSIX | 未优化（Unoptimized） |
| RISCV | 未优化（Unoptimized） |
| RISCV64 | 未优化（Unoptimized） |
| SPARC | 未优化（Unoptimized） |
| X86 | 未优化（Unoptimized） |
| XTENSA | 未优化（Unoptimized） |

译注：表格按原文的分类名称保留；“可工作”与“已优化”是不同结论。具体算法性能还取决于所选后端、处理器能力、数据类型与构建配置，不能把表格当成当前硬件的性能测试。

## 1.2\_使用 zDSP（Using zDSP）

zDSP 提供多种后端（Backend），构建时为应用自动选择。默认情况下，包含 CMSIS 模块后，各体系结构都可使用 zDSP API；原文给出的配置为：

```ini
CONFIG_CMSIS_DSP=y
```

如果应用需要进一步定制，可以启用 [`CONFIG_DSP_BACKEND_CUSTOM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DSP_BACKEND_CUSTOM)。这意味着由应用负责提供 zDSP 库的实现。

译注——配置入口：当前 `subsys/dsp/Kconfig` 以 `CONFIG_DSP` 启用 zDSP 子系统，并通过 `DSP_BACKEND` 选择实现。启用 `CONFIG_CMSIS_DSP` 表示使用 CMSIS-DSP 模块，不能把它与 zDSP 子系统开关混为一谈。当前后端还包括 NXP PowerQuad、CMSIS 和 ARC MetaWare；自定义实现需由应用或模块加入 `zdsp` 构建目标，单独设置 CUSTOM 不会生成缺失的算法实现。

## 1.3\_针对体系结构优化（Optimizing for Your Architecture）

如果体系结构在上表中标为未优化，可以添加新的 zDSP 后端以改善支持。首先，在 `subsys/dsp/Kconfig` 中添加新的 Kconfig 选项、所需依赖，并为 `DSP_BACKEND` 选择项设置默认值（`default`）。

随后把实现放到 `subsys/dsp/<backend>/`，通过 `subsys/dsp/CMakeLists.txt` 接入。若需添加体系结构专用属性，应在 `subsys/dsp/Kconfig` 中定义相应选项，并据此更新 `include/zephyr/dsp/dsp.h` 中的 `DSP_DATA` 和 `DSP_STATIC_DATA`。

译注：上述路径均相对 Zephyr 源码根目录，`<backend>` 是新增后端目录名的占位符。数据属性可能决定地址生成单元或专用数据段的用法，应与实际工具链和存储布局一致。
