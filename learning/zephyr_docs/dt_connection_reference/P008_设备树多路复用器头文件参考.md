MUX设备树宏公共API头文件。

MUX子系统的纯设备树辅助宏：展开为预处理标记（Preprocessor Token），包括标识符、单元值、节点标识符，以及通过DEVICE_DT_GET取得的struct device指针。

生成struct mux_control或struct mux_state初始化器的辅助宏位于`<zephyr/drivers/mux.h>`，因为展开处需要这些结构体的完整定义。

## 8.2\_源码定位与版本边界

本册收录I/O通道、描述符映射、多路复用器及端口／端点宏。相对源码定位：[I/O通道](../../../include/zephyr/devicetree/io-channels.h)、[映射](../../../include/zephyr/devicetree/map.h)、[MUX](../../../include/zephyr/devicetree/mux.h)、[端口／端点](../../../include/zephyr/devicetree/port-endpoint.h)、[MUX驱动](../../../include/zephyr/drivers/mux.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：三种指针：DEV_GET系列取得控制器struct device指针，CONTROL_GET取得预先定义的struct mux_control地址，STATE_GET取得预先定义的struct mux_state地址。配置对象不包含同义的设备指针；应用须把匹配同一控制器的设备与配置配对传给mux_control_set或mux_state_apply，并自行检查设备就绪。GET不会自动创建对象或切换硬件通路。

> 译注——源码核对：先定义再取地址：SPEC_DEFINE_BY_IDX／BY_NAME在drivers/mux.h中生成static const存储，应在文件作用域对同一消费节点及索引只定义一次；随后GET引用生成的标识符。SPEC_DEFINE_ALL对mux-states每项调用定义宏，因此也需要完整结构定义所在的drivers/mux.h；不能在同一翻译单元再为相同条目重复定义。开发者自定义的entries数组形状由消费方决定。

> 译注——源码核对：寻址单元与状态：mux-controls的单元全部属于寻址信息；mux-states前N-1个单元属于寻址，最后一个单元按位置写入state，不强制名为state。只有一个单元时逻辑寻址长度为0；当前drivers/mux.h实际以{0}保留一个底层占位元素，因此源码注释中的“数组为空”应理解为len为0，并不代表零字节物理存储。状态描述符仍须至少有末尾状态单元。

> 译注——源码核对：原例注释：channel 5／channel 7分别为通道5／通道7；entry 0表示通道5、状态2，entry 1表示通道7、状态3。s0->control->cells[0] == 5与s0->state == 2分别说明寻址首单元和默认状态。&mux0／&mux1注释表示所引用控制器，C代码实际取得Zephyr设备对象地址，不是对DTS标签直接做C取地址。

> 译注——源码核对：名称与运行边界：mux-control-names和mux-state-names分别为两种属性条目提供名称，BY_NAME先换算条目索引再取对象。实例版本的inst指消费节点实例。带...和vendor,demux的片段是示意，不代表所需驱动、绑定和对象已存在；只有后续运行时调用才应用状态。

> 译注——源码核对：版本边界：本次四份设备树头文件、MUX驱动头文件、gen_defines.py和edtlib.py登记摘要；四份源码浏览页的非注释代码与对应头文件一致。滚动main与本仓库参照基线不自动视为同版本；本批未编译示例、构建固件、采样、配置MUX或执行硬件实验。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
