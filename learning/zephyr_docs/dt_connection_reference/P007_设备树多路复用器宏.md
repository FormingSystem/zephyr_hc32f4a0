### `MUX_CONTROL_DT_DEV_GET_BY_IDX`

```c
#define MUX_CONTROL_DT_DEV_GET_BY_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree/mux.h>
```

展开值（Value）：

```c
DEVICE_DT_GET(DT_PHANDLE_BY_IDX(node_id, mux_controls, idx))
```

取得mux-controls条目对应的多路复用器（Multiplexer，MUX）控制器设备指针。

等价于查找mux-controls索引idx处的句柄，再通过DEVICE_DT_GET()取得其struct device指针。将返回的设备用于mux_control_set()及相关函数。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
mux0: mux-controller@... { compatible = "vendor,demux"; ... };
mux1: mux-controller@... { compatible = "vendor,demux"; ... };

n: node {
        mux-controls = <&mux0 5>, <&mux1 9>;
};
```

用法示例：

原始示例（Example）：

```c
const struct device *d0 = MUX_CONTROL_DT_DEV_GET_BY_IDX(DT_NODELABEL(n), 0); // &mux0
const struct device *d1 = MUX_CONTROL_DT_DEV_GET_BY_IDX(DT_NODELABEL(n), 1); // &mux1
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 消费节点（Consumer）的设备树节点标识符。 |
| `idx` | mux-controls属性中的逻辑索引。 |

返回（Returns）：索引idx处MUX控制器的struct device指针。

另见（See Also）：DEVICE_DT_GET()。

### `MUX_CONTROL_DT_GET_BY_IDX`

```c
#define MUX_CONTROL_DT_GET_BY_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree/mux.h>
```

展开值（Value）：

```c
(&Z_MUX_CTRL_OBJ_NAME(node_id, idx))
```

取得由MUX_CONTROL_DT_SPEC_DEFINE_BY_IDX()定义的mux_control对象的指针。

负责分配底层存储的MUX_CONTROL_DT_SPEC_DEFINE_BY_IDX()宏位于`<zephyr/drivers/mux.h>`；此宏只返回该存储的地址。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
mux0: mux-controller@... {
        compatible = "vendor,demux";
        #mux-control-cells = <1>;
        ...
};

n: node {
        mux-controls = <&mux0 5>, <&mux0 7>;
};
```

用法示例：

原始示例（Example）：

```c
MUX_CONTROL_DT_SPEC_DEFINE_BY_IDX(DT_NODELABEL(n), 0);
MUX_CONTROL_DT_SPEC_DEFINE_BY_IDX(DT_NODELABEL(n), 1);

const struct mux_control *m0 =
        MUX_CONTROL_DT_GET_BY_IDX(DT_NODELABEL(n), 0);  // channel 5
const struct mux_control *m1 =
        MUX_CONTROL_DT_GET_BY_IDX(DT_NODELABEL(n), 1);  // channel 7
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 消费节点（Consumer）的设备树节点标识符。 |
| `idx` | mux-controls属性中的逻辑索引。 |

返回（Returns）：struct mux_control指针。

另见（See Also）：MUX_CONTROL_DT_SPEC_DEFINE_BY_IDX()。

> 译注——源码核对：先定义再取地址：SPEC_DEFINE_BY_IDX／BY_NAME在drivers/mux.h中生成static const存储，应在文件作用域对同一消费节点及索引只定义一次；随后GET引用生成的标识符。SPEC_DEFINE_ALL对mux-states每项调用定义宏，因此也需要完整结构定义所在的drivers/mux.h；不能在同一翻译单元再为相同条目重复定义。开发者自定义的entries数组形状由消费方决定。

### `MUX_STATE_DT_SPEC_DEFINE_ALL`

```c
#define MUX_STATE_DT_SPEC_DEFINE_ALL ( node_id)
```

```c
#include <zephyr/devicetree/mux.h>
```

展开值（Value）：

```c
DT_FOREACH_PROP_ELEM(node_id, mux_states, Z_MUX_STATE_DEFINE_FOR_EACH)
```

为节点mux-states属性中的每个条目定义一个mux_state对象。

这是比循环调用MUX_STATE_DT_SPEC_DEFINE_BY_IDX()更方便的形式。生成的mux_state存储由消费方定义的条目数组引用；消费方自行选择条目结构的形式。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
mux0: mux-controller@... { compatible = "vendor,demux"; ... };
mux1: mux-controller@... { compatible = "vendor,demux"; ... };

consumer: my-consumer {
        mux-states = <&mux0 5 2>, <&mux1 9 3>;
};
```

用法示例：

原始示例（Example）：

```c
struct my_mux_entry {
        const struct device *dev;
        const struct mux_state *state;
};

#define MY_ENTRY_INIT(node_id, prop, idx)                       \
        { .dev   = MUX_STATE_DT_DEV_GET_BY_IDX(node_id, idx),   \
          .state = MUX_STATE_DT_GET_BY_IDX(node_id, idx), },

MUX_STATE_DT_SPEC_DEFINE_ALL(DT_NODELABEL(consumer));
static const struct my_mux_entry entries[] = {
        DT_FOREACH_PROP_ELEM(DT_NODELABEL(consumer), mux_states,
                             MY_ENTRY_INIT)
};
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 消费节点（Consumer）的设备树节点标识符。 |

另见（See Also）：MUX_STATE_DT_SPEC_DEFINE_BY_IDX()。

本册收录I/O通道、描述符映射、多路复用器及端口／端点宏。相对源码定位：[I/O通道](../../../include/zephyr/devicetree/io-channels.h)、[映射](../../../include/zephyr/devicetree/map.h)、[MUX](../../../include/zephyr/devicetree/mux.h)、[端口／端点](../../../include/zephyr/devicetree/port-endpoint.h)、[MUX驱动](../../../include/zephyr/drivers/mux.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：三种指针：DEV_GET系列取得控制器struct device指针，CONTROL_GET取得预先定义的struct mux_control地址，STATE_GET取得预先定义的struct mux_state地址。配置对象不包含同义的设备指针；应用须把匹配同一控制器的设备与配置配对传给mux_control_set或mux_state_apply，并自行检查设备就绪。GET不会自动创建对象或切换硬件通路。

> 译注——源码核对：先定义再取地址：SPEC_DEFINE_BY_IDX／BY_NAME在drivers/mux.h中生成static const存储，应在文件作用域对同一消费节点及索引只定义一次；随后GET引用生成的标识符。SPEC_DEFINE_ALL对mux-states每项调用定义宏，因此也需要完整结构定义所在的drivers/mux.h；不能在同一翻译单元再为相同条目重复定义。开发者自定义的entries数组形状由消费方决定。

> 译注——源码核对：寻址单元与状态：mux-controls的单元全部属于寻址信息；mux-states前N-1个单元属于寻址，最后一个单元按位置写入state，不强制名为state。只有一个单元时逻辑寻址长度为0；当前drivers/mux.h实际以{0}保留一个底层占位元素，因此源码注释中的“数组为空”应理解为len为0，并不代表零字节物理存储。状态描述符仍须至少有末尾状态单元。

> 译注——源码核对：原例注释：channel 5／channel 7分别为通道5／通道7；entry 0表示通道5、状态2，entry 1表示通道7、状态3。s0->control->cells[0] == 5与s0->state == 2分别说明寻址首单元和默认状态。&mux0／&mux1注释表示所引用控制器，C代码实际取得Zephyr设备对象地址，不是对DTS标签直接做C取地址。

> 译注——源码核对：名称与运行边界：mux-control-names和mux-state-names分别为两种属性条目提供名称，BY_NAME先换算条目索引再取对象。实例版本的inst指消费节点实例。带...和vendor,demux的片段是示意，不代表所需驱动、绑定和对象已存在；只有后续运行时调用才应用状态。

> 译注——源码核对：版本边界：本次四份设备树头文件、MUX驱动头文件、gen_defines.py和edtlib.py登记摘要；四份源码浏览页的非注释代码与对应头文件一致。滚动main与本仓库参照基线不自动视为同版本；本批未编译示例、构建固件、采样、配置MUX或执行硬件实验。
