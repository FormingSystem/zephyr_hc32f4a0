## 4.2\_详细说明（Detailed Documentation）

### `DT_FOREACH_MAP_ENTRY`

```c
#define DT_FOREACH_MAP_ENTRY ( node_id, prop, fn )
```

```c
#include <zephyr/devicetree/map.h>
```

展开值（Value）：

```c
DT_CAT4(node_id, _P_, prop, _FOREACH_MAP_ENTRY)(fn)
```

对prop所定义映射中的每个条目调用fn。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `prop` | 映射属性名称，例如gpio_map。 |
| `fn` | 要调用的宏。 |

另见（See Also）：DT_FOREACH_PROP_ELEM。

### `DT_FOREACH_MAP_ENTRY_VARGS`

```c
#define DT_FOREACH_MAP_ENTRY_VARGS ( node_id, prop, fn, ... )
```

```c
#include <zephyr/devicetree/map.h>
```

展开值（Value）：

```c
DT_CAT4(node_id, _P_, prop, _FOREACH_MAP_ENTRY_VARGS)(fn, __VA_ARGS__)
```

对prop所定义映射中的每个条目调用fn，并插入分隔符。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `prop` | 映射属性名称，例如gpio_map。 |
| `fn` | 要调用的宏。 |
| `...` | 要传递给fn的可变数量参数（Variable Arguments）。 |

另见（See Also）：DT_FOREACH_PROP_ELEM_VARGS。

> 译注——源码核对：展开参数与分隔符：FOREACH_MAP_ENTRY调用fn(node_id, prop, entry_idx)，VARGS在其后追加实参；SEP将分隔符插在相邻展开之间，逗号写为(,)。原文把FOREACH_MAP_ENTRY_VARGS也描述为“带分隔符”，但该宏没有sep参数，实际只增加可变实参，需要分隔符应使用SEP_VARGS。

## 4.3\_源码定位与版本边界

本册收录I/O通道、描述符映射、多路复用器及端口／端点宏。相对源码定位：[I/O通道](../../../include/zephyr/devicetree/io-channels.h)、[映射](../../../include/zephyr/devicetree/map.h)、[MUX](../../../include/zephyr/devicetree/mux.h)、[端口／端点](../../../include/zephyr/devicetree/port-endpoint.h)、[MUX驱动](../../../include/zephyr/drivers/mux.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：两级索引：entry_idx选择整个映射条目，param_idx选择条目内部某一侧地址或描述符的单元。ADDRESS_LEN／SPECIFIER_LEN返回对应列表的元素数，不是映射条目数，也不自动把多单元地址拼成一个CPU指针。DT_MAP_LEN才统计条目总数；缺省PARAM版本选单元0，而DT_MAP_ENTRY_PARENT缺省版本选条目0。

> 译注——源码核对：父端不是树父节点：MAP_ENTRY_PARENT取得映射条目里phandle所引用的节点，不是DT_PARENT(node_id)。映射接口读取已解析的各字段，不会自行对外设写寄存器、选择中断路由或做运行时查表；读取前分别检查条目与所需单元存在，条目存在不保证每类地址／描述符均非空。

> 译注——源码核对：展开参数与分隔符：FOREACH_MAP_ENTRY调用fn(node_id, prop, entry_idx)，VARGS在其后追加实参；SEP将分隔符插在相邻展开之间，逗号写为(,)。原文把FOREACH_MAP_ENTRY_VARGS也描述为“带分隔符”，但该宏没有sep参数，实际只增加可变实参，需要分隔符应使用SEP_VARGS。

> 译注——源码核对：头文件示例范围：gpio-map的两项分别是子端0、1映射到父端2、3，以及子端4、5映射到父端6、7。SRC_AND_DST只取双方索引0的描述符单元，所以结果为{0,2}和{4,6}；它没有把映射中的所有单元都复制到数组。示例省略了控制器、绑定和单元数量上下文，不能直接当作完整DTS。

> 译注——源码核对：原简介的五类访问器：列表实际依次覆盖子端地址、子端描述符、父端地址、父端描述符和父端节点；随后的概括只列“子描述符、父描述符、父节点”，不能据此忽略地址单元。NODE_HAS_MAP等价于属性存在性检查，不验证任意属性是否具备完整映射元数据；有属性与有映射条目也要分开判断。

> 译注——源码核对：版本边界：本次四份设备树头文件、MUX驱动头文件、gen_defines.py和edtlib.py登记摘要；四份源码浏览页的非注释代码与对应头文件一致。滚动main与本仓库参照基线不自动视为同版本；本批未编译示例、构建固件、采样、配置MUX或执行硬件实验。
