## 2.3\_源码定位与版本边界

源码定位：[include/zephyr/logging/log_output_dict.h](../../../include/zephyr/logging/log_output_dict.h)、[subsys/logging/log_output_dict.c](../../../subsys/logging/log_output_dict.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。本地链接采用相对路径。

> 译注——源码核对：字典输出（Dictionary-based Output）发送二进制头部、cbprintf包以及可选十六进制数据，不能按普通UTF-8日志直接阅读。虽然原接口复用了“处理格式化字符串”的说明，源码实际直接输出这些二进制部分。

> 译注——源码核对：原始头字段说明把source描述为标识日志源的地址；当前实现实际写入log_source_id(source)的结果，空来源写0。地址描述与此版实现的差异独立保留，解码器应与固件的实际格式和构建数据匹配，不能按字段名直接把它解引用。

> 译注——源码核对：后端提供可用空间查询时，字典输出先估算整条头部、包和数据所需空间，再在锁内重新查询；空间不足会直接返回。没有可用空间查询时按普通输出路径处理，不能因此推断存在同样的整条消息容量保证。

> 译注——源码核对：头部使用位域（Bit-field）和__packed，source为uintptr_t，timestamp为log_timestamp_t。布局与指针宽度、时间戳配置及工具链ABI有关，不能仅依据字段名称假定固定跨平台字节布局。package_len与data_len分别描述cbprintf包和追加数据的字节数，不能把头部长度算入其中。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
