# 第16章\_X-NUCLEO-IKS02A1 扩展板：标准模式（Standard，Mode 1）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/shields/x_nucleo_iks02a1/standard/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/shields/x_nucleo_iks02a1/standard/README.rst/..)

<a id="overview"></a>

## 16.1 概述（Overview）

本示例用于测试配置为标准模式（Standard，Mode 1）的 X-NUCLEO-IKS02A1。该配置的更多说明见《[X-NUCLEO-IKS02A1：MEMS 惯性与环境多传感器扩展板](https://docs.zephyrproject.org/latest/boards/shields/x_nucleo_iks02a1/doc/index.html#x-nucleo-iks02a1)》。

本示例启用 X-NUCLEO-IKS02A1 扩展板上的全部传感器，然后周期性读取并显示以下传感器数据：

> 译注——本页范围：此程序演示 IIS2MDC、IIS2DLPC 与 ISM330DHCX 的运动和磁场数据。扩展板上的数字微机电系统（Micro-Electro-Mechanical Systems，MEMS）麦克风由独立示例负责，不能从“全部传感器”的表述推断本页还会采集音频。

- IIS2MDC：三轴磁场强度（3-Axis Magnetic Field Intensity）

- IIS2DLPC：三轴加速度（3-Axis Acceleration）

- ISM330DHCX：六轴加速度与角速度（6-Axis Acceleration and Angular Velocity）

<a id="requirements"></a>

## 16.2 硬件与配置要求（Requirements）

本示例通过 I2C 与叠接在 Arduino 接口开发板上的 X-NUCLEO-IKS02A1 通信。开发板必须为 Arduino 接口配置 I2C，包括引脚复用（Pin Muxing）与设备树（Devicetree）。可参考 [Nucleo F401RE](https://docs.zephyrproject.org/latest/boards/st/nucleo_f401re/doc/index.html#nucleo_f401re) 的开发板源码：

- `$ZEPHYR_BASE/boards/arm/nucleo_f401re/nucleo_f401re.dts`

- `$ZEPHYR_BASE/boards/arm/nucleo_f401re/pinmux.c`

> 译注——旧源码路径：上方两条是官方文档遗留位置。当前文件为 [nucleo_f401re.dts](../../../boards/st/nucleo_f401re/nucleo_f401re.dts) 与 [arduino_r3_connector.dtsi](../../../boards/st/nucleo_f401re/arduino_r3_connector.dtsi)；I2C1 的 PB8／PB9 通过设备树 pinctrl 配置，Arduino I2C 标签指向 I2C1，无需创建旧 pinmux.c。ZEPHYR_BASE 代表读者自己的源码根，不是作者机器固定地址。

原文指出，不能在已支持扩展板上某种传感器的开发板上运行本示例，例如 disco_l475_iot1，因为不支持同类传感器的多个实例。

> 译注——多实例说明的版本边界：不能把原文表述泛化为当前 Zephyr 传感器框架的统一限制。当前 DEVICE_DT_GET_ONE() 在多个匹配节点中返回任意一个设备，示例没有明确区分板载与扩展板实例；例如当前 LSM6DSO 驱动已按每个启用节点生成设备。移植时仍需核对驱动能力、总线地址与选定节点，避免程序读到另一颗同型号传感器。

<a id="building-and-running"></a>

## 16.4 构建与运行（Building and Running）

> 译注——执行前提：主机命令从读者自己的 Zephyr 源码根目录，用 UCRT64 Bash 或 Linux Bash 执行；先按[入门指南](../getting_started/大纲.md)准备模块、工具链和目标板。CMakeLists.txt 已选择 SHIELD=x_nucleo_iks02a1，所以原命令不必重复指定 --shield。先按本页链接核对扩展板硬件模式、供电和连接，再构建对应应用；设备不就绪时回查模式、总线、设备树与中断接线。下方是原文预期输出，本次未构建、烧录或实测。

本示例可在具有匹配 Arduino 接口并叠接 X-NUCLEO-IKS02A1 的开发板上运行。这里采用 [Nucleo F401RE](https://docs.zephyrproject.org/latest/boards/st/nucleo_f401re/doc/index.html#nucleo_f401re) 开发板。

```text
west build -b nucleo_f401re samples/shields/x_nucleo_iks02a1/standard/
```

<a id="sample-output"></a>

### 16.4.1 示例输出（Sample Output）

> 译注——读数单位：m/s^2 表示加速度，G 表示磁场高斯（Gauss），不是重力加速度单位 g；rad/s 表示角速度弧度每秒，温度用摄氏度、压力用 kPa。源码在一轮显示后休眠 2000 ms；传感器内部采样、触发更新和控制台刷新是不同节奏，日志数值不表示本次已完成标定或精度验收。

> ```text
> X-NUCLEO-IKS02A1 sensor Mode 1 dashboard
>
> IIS2DLPC: Accel (m/s^2): x: 0.000, y: 0.000, z: 9.342
> IIS2MDC: Magn (G): x: -0.120, y: -0.095, z: -0.338
> IIS2MDC: Temperature: 25.1 C
> ISM330DHCX: Accel (m/s^2): x: 0.182, y: -0.306, z: 9.753
> ISM330DHCX: Gyro (rad/s): x: 0.005, y: 0.001, z: -0.004
> 5:: iis2dlpc trig 809
> 5:: ism330dhcx acc trig 3332
> 5:: ism330dhcx gyr trig 1666
>
> <updated endlessly every 2 seconds>
> ```
