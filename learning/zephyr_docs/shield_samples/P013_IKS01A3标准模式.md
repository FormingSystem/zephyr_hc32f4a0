# 第13章\_X-NUCLEO-IKS01A3 扩展板：标准模式（Standard，Mode 1）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/shields/x_nucleo_iks01a3/standard/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/shields/x_nucleo_iks01a3/standard/README.rst/..)

<a id="overview"></a>

## 13.1 概述（Overview）

本示例用于测试配置为标准模式（Standard，Mode 1）的 X-NUCLEO-IKS01A3。该配置的更多说明见《[X-NUCLEO-IKS01A3：MEMS 惯性与环境多传感器扩展板](https://docs.zephyrproject.org/latest/boards/shields/x_nucleo_iks01a3/doc/index.html#x-nucleo-iks01a3)》。

本示例启用 X-NUCLEO-IKS01A3 扩展板上的全部传感器，然后周期性读取并显示以下传感器数据：

- HTS221：环境温度与相对湿度（Ambient Temperature and Relative Humidity）

- LPS22HH：环境温度与大气压力（Ambient Temperature and Atmospheric Pressure）

- LIS2MDL：三轴磁场强度（3-Axis Magnetic Field Intensity）

- LIS2DW12：三轴加速度（3-Axis Acceleration）

- LSM6DSO：六轴加速度与角速度（6-Axis Acceleration and Angular Velocity）

- STTS751：温度传感器（Temperature Sensor）

<a id="requirements"></a>

## 13.2 硬件与配置要求（Requirements）

本示例通过 I2C 与叠接在 Arduino 接口开发板上的 X-NUCLEO-IKS01A3 通信。开发板必须为 Arduino 接口配置 I2C，包括引脚复用（Pin Muxing）与设备树（Devicetree）。可参考 [Nucleo F401RE](https://docs.zephyrproject.org/latest/boards/st/nucleo_f401re/doc/index.html#nucleo_f401re) 的开发板源码：

- `$ZEPHYR_BASE/boards/arm/nucleo_f401re/nucleo_f401re.dts`

- `$ZEPHYR_BASE/boards/arm/nucleo_f401re/pinmux.c`

> 译注——旧源码路径：上方两条是官方文档遗留位置。当前文件为 [nucleo_f401re.dts](../../../boards/st/nucleo_f401re/nucleo_f401re.dts) 与 [arduino_r3_connector.dtsi](../../../boards/st/nucleo_f401re/arduino_r3_connector.dtsi)；I2C1 的 PB8／PB9 通过设备树 pinctrl 配置，Arduino I2C 标签指向 I2C1，无需创建旧 pinmux.c。ZEPHYR_BASE 代表读者自己的源码根，不是作者机器固定地址。

原文指出，不能在已支持扩展板上某种传感器的开发板上运行本示例，例如 disco_l475_iot1，因为不支持同类传感器的多个实例。

> 译注——多实例说明的版本边界：不能把原文表述泛化为当前 Zephyr 传感器框架的统一限制。当前 DEVICE_DT_GET_ONE() 在多个匹配节点中返回任意一个设备，示例没有明确区分板载与扩展板实例；例如当前 LSM6DSO 驱动已按每个启用节点生成设备。移植时仍需核对驱动能力、总线地址与选定节点，避免程序读到另一颗同型号传感器。

<a id="dil24-socket"></a>

## 13.4 DIL24 插座（DIL24 Socket）

除板载传感器外，还可在 DIL24 插座上安装其他兼容传感器。示例在传感器不存在时会跳过它。

> 译注——可选器件的边界：app.overlay 默认声明 LIS2DE12 节点，硬件缺席且设备初始化失败时，main.c 会跳过它；其他板载器件不就绪则直接退出。若连该节点也从设备树删除，DEVICE_DT_GET_ANY() 可返回 NULL，而当前失败分支仍访问 lis2de12->name，存在空指针风险。因此“跳过”不等于任意删除节点后程序仍安全运行。

本示例当前支持的 DIL24 传感器：

- LIS2DE12

<a id="building-and-running"></a>

## 13.5 构建与运行（Building and Running）

> 译注——执行前提：主机命令从读者自己的 Zephyr 源码根目录，用 UCRT64 Bash 或 Linux Bash 执行；先按[入门指南](../getting_started/大纲.md)准备模块、工具链和目标板。CMakeLists.txt 已选择 SHIELD=x_nucleo_iks01a3，所以原命令不必重复指定 --shield。先按本页链接核对扩展板硬件模式、供电和连接，再构建对应应用；设备不就绪时回查模式、总线、设备树与中断接线。下方是原文预期输出，本次未构建、烧录或实测。

本示例可在具有匹配 Arduino 接口并叠接 X-NUCLEO-IKS01A3 的开发板上运行。这里采用 [Nucleo F401RE](https://docs.zephyrproject.org/latest/boards/st/nucleo_f401re/doc/index.html#nucleo_f401re) 开发板。

```text
west build -b nucleo_f401re samples/shields/x_nucleo_iks01a3/standard/
```
