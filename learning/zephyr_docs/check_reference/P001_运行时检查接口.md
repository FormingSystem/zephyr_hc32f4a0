## 1.3\_详细说明（Detailed Documentation）

<a id="gac53803cb41bff9492f98fe0ac7ea1bc4"></a>

### `CHECKIF`

```c
#define CHECKIF ( expr)
```

```c
#include <zephyr/sys/check.h>
```

展开值（Value）：

```c
if (expr)
```

使用可配置检查控制错误处理代码的执行。

包装一个在检测到错误时求值为真的条件，以及该条件成立时要执行的语句或代码块。

原始示例（Example）：

```c
CHECKIF(dev == NULL) {
    return -EINVAL;
}
```

可通过Kconfig配置其行为：

- CONFIG_RUNTIME_ERROR_CHECKS为默认配置，展开为if (expr)。
- CONFIG_ASSERT_ON_ERRORS触发断言（Assertion），不运行受其控制的代码块。
- CONFIG_NO_RUNTIME_CHECKS在编译时省略检查。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `expr` | 错误条件表达式（Error Condition Expression）。 |

> 译注——源码核对：条件方向：CHECKIF(expr)把expr为真解释为错误，与断言通常要求条件为真才正常的写法相反。原例dev==NULL成立时，默认配置才进入返回-EINVAL的错误处理块；CHECKIF本身不生成固定错误码。 配置范围：Kconfig.zephyr中的choice在RUNTIME_ERROR_CHECKS、ASSERT_ON_ERRORS和NO_RUNTIME_CHECKS之间选择，默认采用运行时检查。该选择改变CHECKIF覆盖的检查，不会自动移除项目中所有普通if、其他断言或独立的错误处理。 断言分支：当前宏先执行__ASSERT_NO_MSG(!(expr))，随后接if(0)，因此原错误处理块不会运行。__ASSERT_NO_MSG本身还受断言配置控制；本次官方头文件使用DEFAULT模块断言等级，关闭时展开为空操作。选择ASSERT_ON_ERRORS不等于错误处理块仍会作为断言关闭后的后备路径。 副作用（Side Effect）：NO_RUNTIME_CHECKS分支不使用宏实参，断言禁用时ASSERT_ON_ERRORS分支也不求值expr。因此读数据、递增计数、释放资源等必须发生的操作应放在宏外，再把纯检查表达式传入，避免运行行为随配置改变。 编译与语法：if(0)让代码块不在运行时执行，不等于用预处理条件删除源码；代码仍须能够被解析和类型检查。ASSERT_ON_ERRORS分支含多条语句，外围if／else应使用花括号，避免只控制宏展开的第一条语句。
