# 第48章\_环境感知外设（ESP Peripheral）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/peripheral_esp/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/peripheral_esp/README.rst/..)

<a id="overview"></a>

## 48.1 概述（Overview）

本应用类似[基础外设（Peripheral）](P005_基础蓝牙外设.md#ble_peripheral)示例，但专门提供环境感知配置文件（Environmental Sensing Profile，ESP）的 GATT 服务。

> 译注——ESP 术语：此处 ESP 是 Environmental Sensing Profile（环境感知配置文件），不是 ESP32 芯片或 Espressif 平台名称；底层 GATT 服务通常称 Environmental Sensing Service（ESS）。

<a id="requirements"></a>

## 48.2 前提条件（Requirements）

- 主机上运行 BlueZ；或者

- 一块支持 Bluetooth LE 的开发板。

<a id="building-and-running"></a>

## 48.3 构建与运行（Building and Running）

> 译注——执行环境：以下官方命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行。先按[入门文档](../getting_started/大纲.md)准备工具链、west工作区、板定义与所需蓝牙控制器；`samples/...` 是官方已有目录，`<board>` 需替换为实际板目标。构建成功后才按板文档烧录，并通过本页描述的连接、服务发现、订阅或配网步骤观察结果；失败时分别回查构建配置、烧录器或对端角色与功能支持。构建输出由工具生成，中文目录不作为固件工作目录。本次仅核对文档，未执行这些操作。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/peripheral_esp
west flash
```

烧录后，使用蓝牙扫描应用，例如 nRF Connect，连接设备并订阅温度传感器特征，在温度变化时接收通知。服务还提供只读的湿度特征。

> 译注——硬件与回退数据：本次 Kconfig 可通过 `CONFIG_ESP_USE_HARDWARE_SENSOR` 启用真实传感器；main.c 依次选择 `ambient-temp0`、`dht0`、`die-temp0` 对应的启用别名。每次更新先生成演示值，只有采样和对应通道读取成功才覆盖温度或湿度，因此传感器失败或不支持湿度时仍可能保留模拟值。“只读湿度”指客户端无写权限，不表示该值永远不变。本地可从[示例Kconfig](../../../samples/bluetooth/peripheral_esp/Kconfig)和[main.c](../../../samples/bluetooth/peripheral_esp/src/main.c)追踪。
