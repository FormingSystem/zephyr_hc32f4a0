# 第30章\_定向广播（Direct Advertising）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/direct_adv/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/direct_adv/README.rst/..)

<a id="overview"></a>

## 30.1 概述（Overview）

本应用演示 Bluetooth LE 定向广播能力。若外设尚未与任何设备绑定（Bonding），则进行普通广播；一旦绑定，后续每次启动都会向已绑定的中心设备进行定向广播。示例还提供两个 Bluetooth LE 特征（Characteristic）：写入需要设备已绑定，读取则在连接后即可进行，无须绑定。

请注意，原文说明不允许向基于 iOS 的设备进行定向广播。面向 Apple 产品设计 Bluetooth LE 设备的更多信息，参见《Accessory Design Guidelines for Apple Devices》（Apple 设备配件设计指南）。

> 译注——平台限制：上句是官方示例页面保留的 Apple 兼容性说明，本次没有独立验证所有 iOS 版本的行为。下方“现代智能手机”是通用设备条件，不应据此忽略前述限制。绑定记录由示例配置的 Settings／NVS 保存；首次连接、配对和保存绑定是不同步骤，无法重连时应先检查对端隐私能力及已有绑定状态。

<a id="requirements"></a>

## 30.2 前提条件（Requirements）

- 一块支持 Bluetooth LE 的开发板。

- 第二个 Bluetooth LE 设备，作为启用隐私（Privacy）的中心设备，例如另一块 Zephyr 开发板或现代智能手机。

<a id="building-and-running"></a>

## 30.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/direct_adv
west flash
```

烧录后，设备开始广播。没有绑定记录时，进行非定向广播（Undirected advertising）；配对完成后，设备等待五秒并重启。后续启动时，它向已绑定的对端进行定向广播（Directed advertising）。
