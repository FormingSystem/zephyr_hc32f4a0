# 第36章\_周期广播连接过程：发起端（Periodic Advertising Connection Procedure / Initiator）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/periodic_adv_conn/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/periodic_adv_conn/README.rst/..)

<a id="overview"></a>

## 36.1 概述（Overview）

本简单应用演示 Bluetooth LE 周期广播连接过程的发起端。

开始带响应的周期广播（Periodic Advertising with Responses，PAwR）之前，本示例先按名称扫描响应端，通过普通连接与之连接并保存其地址，随后断开并启动 PAwR 广播。 相关链接：[周期广播连接过程：响应端（Periodic Advertising Connection Procedure / Responder）](P039_周期广播连接响应端.md#ble_periodic_adv_sync_conn)。

> 译注——地址来源：本次官方实现先通过普通 LE 连接获知响应端地址，再进行 PAwR 连接；响应内容中的设备名用于表明仍在活动，不是待解析的蓝牙地址。先启动响应端，并保持其与源码配置一致的身份地址，才能让此前保存的地址继续有效。

响应端回复子事件（Subevent）后，本示例使用之前保存的地址，而不是从响应数据中解析地址，通过周期广播连接过程与响应端连接。连接建立后，等待其断开，再在后续响应到来时重新连接。

<a id="requirements"></a>

## 36.2 前提条件（Requirements）

- 一块支持 Bluetooth LE 的开发板。

- 支持 PAwR 广播端（Advertiser）功能的控制器。

<a id="building-and-running"></a>

## 36.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/periodic_adv_conn
west flash
```

先在第二块开发板上运行周期广播连接过程响应端示例。本设备烧录后，扫描并连接响应端以获取其地址，然后断开并开始 PAwR 广播。响应端回复子事件后，发起端使用先前获知的地址与之连接。断开后，等待下一次响应以建立新连接。 相关链接：[周期广播连接过程：响应端（Periodic Advertising Connection Procedure / Responder）](P039_周期广播连接响应端.md#ble_periodic_adv_sync_conn)。

在第二块开发板上运行周期广播连接过程响应端示例，与本设备同步并响应。 相关链接：[周期广播连接过程：响应端（Periodic Advertising Connection Procedure / Responder）](P039_周期广播连接响应端.md#ble_periodic_adv_sync_conn)。
