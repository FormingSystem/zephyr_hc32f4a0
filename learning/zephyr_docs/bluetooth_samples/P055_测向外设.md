# 第55章\_测向外设（Direction Finding Peripheral）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/direction_finding_peripheral/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/direction_finding_peripheral/README.rst/..)

<a id="overview"></a>

## 55.1 概述（Overview）

> 译注——配对与天线：本页外设发送恒定音调扩展（CTE），与[测向中心设备](P054_测向中心设备.md)配对。AoD 的天线切换位于本发送端，AoA 的切换位于对端接收器；两种模式不能只改一个设备而忽略对端的支持与配置。

本简单应用演示连接模式下的 Bluetooth LE 测向 CTE 发送功能：响应已连接对端发来的请求，发送 CTE。

<a id="requirements"></a>

## 55.2 前提条件（Requirements）

- 基于 Nordic nRF SoC 且支持测向的开发板，例如 [nRF52833 DK](https://docs.zephyrproject.org/latest/boards/nordic/nrf52833dk/doc/index.html#nrf52833dk)、[nRF5340 DK](https://docs.zephyrproject.org/latest/boards/nordic/nrf5340dk/doc/index.html#nrf5340dk)。

- 用于到达角（Angle of Arrival，AoA）的天线矩阵，可选。

若不确定是否支持测向，请查阅所用 SoC 的产品规格。

<a id="building-and-running"></a>

## 55.3 构建与运行（Building and Running）

> 译注——执行环境：以下构建命令在读者自己的 Zephyr 源码根目录，用 UCRT64 Bash 或 Linux Bash 执行。先按[入门指南](../getting_started/大纲.md)准备工具链、west 工作区、板定义及控制器；`samples/...` 是官方已有目录，`<board>` 替换为实际目标。构建成功后按板文档烧录，分别核对对端角色、串口输出和本页预期结果；失败时先回查构建配置、烧录连接或角色与功能支持。本次仅翻译和核对来源，未执行构建、烧录或无线测试。

应用默认支持到达角（Angle of Arrival，AoA）和离开角（Angle of Departure，AoD）模式。

若只使用到达角模式，按以下方式构建，并根据开发板替换 `nrf52833dk/nrf52833`：

```text
west build -b nrf52833dk/nrf52833 samples/bluetooth/direction_finding_peripheral -- -DEXTRA_CONF_FILE=overlay-aoa.conf
west flash
```

在 nRF5340 DK 上运行应用时，网络核还必须运行蓝牙控制器应用，可使用 [HCI IPC](../intercore_reference/P189_蓝牙HCI的IPC示例.md#bluetooth_hci_ipc) 示例。要为该示例启用测向支持：

> 译注——文件来源与双核配置：上述源文件由官方示例提供；复制目标是读者为 HCI IPC 网络核应用创建或合并的配置，若目标已存在，应先比较内容，不能无条件覆盖。`.overlay` 配置设备树，`.conf` 配置 Kconfig，两者作用不同；应用核的 GPIO 分配和网络核的阵列控制必须与真实接线一致。AoA 接收／AoD 发送的天线要求随模式变化，示例阵列编号不能代替硬件核对。

- 将 [samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.overlay) 复制为新文件 `samples/bluetooth/hci_ipc/boards/nrf5340dk_nrf5340_cpunet.overlay`。

- 确保 [samples/bluetooth/direction_finding_peripheral/boards/nrf5340dk_nrf5340_cpuapp.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/direction_finding_peripheral/boards/nrf5340dk_nrf5340_cpuapp.overlay) 中分配给测向扩展的 GPIO，与新建的 `samples/bluetooth/hci_ipc/boards/nrf5340dk_nrf5340_cpunet.overlay` 一致。

- 将 [samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.conf](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.conf) 复制为新文件 `samples/bluetooth/hci_ipc/boards/nrf5340dk_nrf5340_cpunet.conf`。

<a id="antenna-matrix-configuration"></a>

## 55.4 天线矩阵配置（Antenna matrix configuration）

在 Nordic SoC 上启用 AoD 使用本例时，必须通过[设备树](../devicetree/P013_设备树文档入口.md#dt-guide)提供附加配置，以控制天线阵列。

[samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/direction_finding_peripheral/boards/nrf52833dk_nrf52833.overlay) 是设备树覆盖文件示例。为同一块板构建时可定制它；为其他板构建时，可在同目录创建对应板的覆盖文件。各属性说明见 [`nordic,nrf-radio`](../network_radio_frontend_binding_reference/P009_nordic_nrf-radio.md#std-dtcompatible-nordic-nrf-radio)；覆盖文件的设置与使用见“[设置设备树覆盖文件](../devicetree/P006_设备树操作指南.md#set-devicetree-overlays)”（Set devicetree overlays）。

注意，nRF5340 SoC 的天线矩阵配置属于网络核应用。以 [HCI IPC](../intercore_reference/P189_蓝牙HCI的IPC示例.md#bluetooth_hci_ipc) 作为网络核应用时，应将该配置存放在 `samples/bluetooth/hci_ipc/boards/nrf5340dk_nrf5340_cpunet.overlay`。
