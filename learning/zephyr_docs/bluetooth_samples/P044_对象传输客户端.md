# 第44章\_对象传输客户端中心设备（Central OTC）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/central_otc/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/central_otc/README.rst/..)

<a id="overview"></a>

## 44.1 概述（Overview）

本应用类似[基础中心设备（Central）](P006_基础蓝牙中心设备.md#ble_central)示例，但专门寻找对象传输服务（Object Transfer Service，OTS）的 GATT 服务。示例支持依次选择对象、读取元数据、写入数据、读取数据，以及计算所选对象的校验和（Checksum）。

<a id="requirements"></a>

## 44.2 前提条件（Requirements）

- 一块支持 Bluetooth LE 且带有四个按钮的开发板。

> 译注——四个按键的定义：官方 main.c 要求设备树别名 `sw0`、`sw1`、`sw2`、`sw3` 都指向启用的节点，否则直接报编译错误。网页中的 SW0～SW3 是按钮标记；有四个物理按钮并不自动满足别名、GPIO和中断配置。应先核对所用板，再按实际硬件补充覆盖文件。

<a id="building-and-running"></a>

## 44.3 构建与运行（Building and Running）

> 译注——执行环境：以下官方命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行。先按[入门文档](../getting_started/大纲.md)准备工具链、west工作区、板定义与所需蓝牙控制器；`samples/...` 是官方已有目录，`<board>` 需替换为实际板目标。构建成功后才按板文档烧录，并通过本页描述的连接、服务发现、订阅或配网步骤观察结果；失败时分别回查构建配置、烧录器或对端角色与功能支持。构建输出由工具生成，中文目录不作为固件工作目录。本次仅核对文档，未执行这些操作。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/central_otc
west flash
```

烧录后，示例扫描广播 OTS 的外设并连接。在第二块开发板上运行对象传输服务外设（Peripheral Object Transfer Service）示例作为对端。连接后，使用四个按钮操作对象： 相关链接：[对象传输服务外设（Peripheral Object Transfer Service，OTS）](P045_对象传输服务外设.md#ble_peripheral_ots)。

- 按钮 1（SW0）：第一次按下选择首个可用对象，后续每次按下前进到下一个对象。

- 按钮 2（SW1）：读取对象元数据（Metadata）。

- 按钮 3（SW2）：写入对象数据。

- 按钮 4（SW3）：读取对象数据。

> 译注——校验和触发：四个按钮分别对应选对象、读元数据、写数据和读数据，没有第五个独立“校验和按钮”。本次源码在写入时计算本地数据校验和，并在读回完成后调度工作项请求对象校验和，用回调打印比较结果。操作前应等待连接与服务发现完成，并确认已选中对象。
