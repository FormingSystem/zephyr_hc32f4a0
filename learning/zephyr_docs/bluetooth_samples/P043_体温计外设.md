# 第43章\_体温计外设（Health Thermometer / Peripheral）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/peripheral_ht/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/peripheral_ht/README.rst/..)

<a id="overview"></a>

## 43.1 概述（Overview）

本应用类似[基础外设（Peripheral）](P005_基础蓝牙外设.md#ble_peripheral)示例，但专门提供健康温度计（Health Thermometer，HT）GATT 服务。

若板上存在设备树别名节点 `dht0`，示例使用该传感器返回环境温度；在 Nordic nRF 设备上，使用内置 TEMP 外设返回芯片温度；在其他开发板上，生成模拟温度值。

> 译注——实现选择顺序：本次官方 [hts.c](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/bluetooth/peripheral_ht/src/hts.c)先检查 `CONFIG_TEMP_NRF5`，再检查 `dht0` 别名。二者同时存在时，不能仅按上文的叙述顺序判断优先级。实际选用的温度通道应结合构建配置和传感器就绪状态确认；本地可从[hts.c](../../../samples/bluetooth/peripheral_ht/src/hts.c)追踪。

<a id="requirements"></a>

## 43.2 前提条件（Requirements）

- 主机上运行 BlueZ；或者

- 一块支持 Bluetooth LE 的开发板。

<a id="building-and-running"></a>

## 43.3 构建与运行（Building and Running）

> 译注——执行环境：以下官方命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行。先按[入门文档](../getting_started/大纲.md)准备工具链、west工作区、板定义与所需蓝牙控制器；`samples/...` 是官方已有目录，`<board>` 需替换为实际板目标。构建成功后才按板文档烧录，并通过本页描述的连接、服务发现、订阅或配网步骤观察结果；失败时分别回查构建配置、烧录器或对端角色与功能支持。构建输出由工具生成，中文目录不作为固件工作目录。本次仅核对文档，未执行这些操作。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/peripheral_ht
west flash
```

烧录后，使用蓝牙扫描应用，例如 nRF Connect，连接设备并启用 Temperature Measurement 特征的指示，通过 HT 服务接收温度读数。

> 译注——指示与电量：这里应启用 Indication（指示），并非把 Notification（通知）与它混用。本次 main.c 每秒调用温度上报，同时递减并循环电池服务中的电量值；后者是模拟电量，不是对实际电池的采样。
