# 第32章\_加密广播（Encrypted Advertising）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/encrypted_advertising/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/encrypted_advertising/README.rst/..)

<a id="overview"></a>

## 32.1 概述（Overview）

本示例演示加密广播功能，包括：

> - 通过密钥材料特征（Key Material characteristic）交换会话密钥（Session key）和初始化向量（Initialization vector）。
>
> - 加密广播载荷（Advertising payload）。
>
> - 解密这些广播载荷。
>
> - 每次可解析私有地址（Resolvable Private Address，RPA）变化时，更新随机化字段（Randomizer）。

使用 [`bt_ead_encrypt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__ead.html#ga8bed2f85d63b3950fd3e19fe211a8f02) 和 [`bt_ead_decrypt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__ead.html#gaf4005550479008e5f32f5cf15200ea8e) 函数，必须启用 Kconfig 符号 [`CONFIG_BT_EAD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_EAD)。

本示例使用扩展广播，但加密广播本身并不强制要求扩展广播，也可以用于传统广播（Legacy advertising）。

> 译注——功能与示例配置：加密广播数据（Encrypted Advertising Data，EAD）与扩展广播是不同能力；本文演示程序仍按自身配置使用扩展广播。即使 EAD 可用于传统广播，也不能只因启用 `CONFIG_BT_EAD` 就认定当前控制器或整套示例满足全部条件。

<a id="requirements"></a>

## 32.2 前提条件（Requirements）

- 两块支持 Bluetooth LE 的开发板。

- 两块开发板均具备通过 GPIO 引脚连接的按钮，详情参见[按钮（Button）](../basic_samples/P003_按钮输入.md#button)示例。

<a id="building-and-running"></a>

## 32.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。两个应用应使用各自的构建目录；原文两段命令都使用默认目录，不应在未处理旧构建缓存的情况下直接切换应用。可按[west文档](../west/大纲.md)为两端分别指定构建目录，烧录时也选择相应目录和对应设备。

本示例包含两个应用，因此需要准备两个设备。在第一块开发板上构建并烧录外设应用，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/encrypted_advertising/peripheral
west flash
```

在第二块开发板上构建并烧录中心设备应用：

```text
west build -b <board> samples/bluetooth/encrypted_advertising/central
west flash
```

两个设备距离足够近时，应自动建立连接。

两块开发板连接后，会要求分别按下配置的按钮，以确认配对请求。两块板都需要一个映射到设备树别名 `sw0` 的按钮。若板级定义默认没有 `sw0`，应在构建前提供设备树覆盖文件（Devicetree overlay）。

> 译注——按键来源：两端官方 main.c 均使用 `DT_ALIAS(sw0)`，并对未定义该别名的板报编译错误。若需要 overlay，应由读者为实际板创建覆盖文件并指向真实按钮节点；不要照抄日志中的 gpio@50000000 或 pin 11。别名、GPIO 就绪、输入配置与中断配置均须成立，配对确认才有输入来源。
