# 第27章\_多实例广播（Multiple Broadcaster）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/broadcaster_multiple/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/broadcaster_multiple/README.rst/..)

<a id="overview"></a>

## 27.1 概述（Overview）

本简单应用演示低功耗蓝牙（Bluetooth Low Energy，Bluetooth LE）广播端使用多个广播集（Advertising set）的功能。

示例广播两个不可连接、不可扫描的广播集，分别使用不同的广播集标识符（SID）。修改项目配置文件中的 [`CONFIG_BT_EXT_ADV_MAX_ADV_SET`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_EXT_ADV_MAX_ADV_SET)，可增加广播集数量。

> 译注——广播集与容量：SID 是广播集标识，不是设备地址，也不是连接编号。本次官方 [broadcaster_multiple.c](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/bluetooth/broadcaster_multiple/src/broadcaster_multiple.c)按 `CONFIG_BT_EXT_ADV_MAX_ADV_SET` 创建广播集并设置 SID；厂商数据大小还扣除了 AD 格式和设备名等开销。调整 Host 侧配置不能自动突破实际控制器支持的广播集数或数据长度。

将本示例与 Bluetooth LE 控制器（Controller）一起构建时，可修改控制器的 [`CONFIG_BT_CTLR_ADV_DATA_LEN_MAX`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_CTLR_ADV_DATA_LEN_MAX)，使广播数据长度超过默认的 31 字节。示例会计算厂商数据（Manufacturer data）大小，以尽量利用受支持的广播数据（AD data）长度。

<a id="requirements"></a>

## 27.2 前提条件（Requirements）

- 一块支持 Bluetooth LE 扩展广播（Extended Advertising）的开发板。

<a id="building-and-running"></a>

## 27.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/broadcaster_multiple
west flash
```

可在另一块开发板上运行启用扩展扫描（Extended Scanning）的[观察者（Observer）](P003_蓝牙观察者.md#bluetooth_observer)示例，接收这些广播集的广播报告。

详情参见[蓝牙示例（Bluetooth samples）](https://docs.zephyrproject.org/latest/samples/bluetooth/bluetooth.html#bluetooth)。
