# 第33章\_扩展广播（Extended Advertising）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/extended_adv/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/extended_adv/README.rst/..)

<a id="overview"></a>

## 33.1 概述（Overview）

本示例通过以下内容演示扩展广播功能：

- 说明初始化扩展广播应用所需的步骤。

- 演示断开连接后如何有序重启该功能。

示例中，广播端创建一个可连接广播集，扫描端扫描到扩展广播后发起连接。连接建立后，广播端等待五秒再断开。断开后广播端立即重新广播，而扫描端等待五秒后才重新开始其流程。

为示范良好设计，本示例在独立线程中处理全部动作。虽然不是严格要求，仍强烈建议从其他上下文调度，例如使用工作项（Work item）；在 `recycled` 回调中直接重启广播端或扫描端，会使应用面临死锁（Deadlock）风险。

> 译注——回调与线程：本次官方两端 main.c 使用事件位和轮询信号通知应用线程，在线程循环中重启广播或扫描。`recycled` 表示连接对象已可复用，不是建议在该回调里直接完成全部重启操作；保留原文的死锁提醒。

<a id="requirements"></a>

## 33.2 前提条件（Requirements）

- 两块支持 Bluetooth LE 的开发板。

<a id="building-and-running"></a>

## 33.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。两个应用应使用各自的构建目录；原文两段命令都使用默认目录，不应在未处理旧构建缓存的情况下直接切换应用。可按[west文档](../west/大纲.md)为两端分别指定构建目录，烧录时也选择相应目录和对应设备。

本示例包含两个应用，因此需要准备两个设备。在第一块开发板上构建并烧录广播端应用，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/extended_adv/advertiser
west flash
```

在第二块开发板上构建并烧录扫描端应用：

```text
west build -b <board> samples/bluetooth/extended_adv/scanner
west flash
```

两个设备距离足够近时，应自动建立连接。
