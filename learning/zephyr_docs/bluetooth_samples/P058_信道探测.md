# 第58章\_信道探测（Channel Sounding，CS）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/channel_sounding/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/channel_sounding/README.rst/..)

<a id="overview"></a>

## 58.1 概述（Overview）

> 译注——示例范围：每设备约 512 字节、单天线路径、每过程单子事件是本例数据交换与算法的假设，不是所有信道探测实现的通用限制。RTT 与 PBR 输出的是距离估计，示例数值没有给出硬件精度保证；CS Test 覆盖随机化参数用于测试，不能将该测试行为当作常规 Connected CS 的安全配置。

这些示例演示如何使用蓝牙信道探测功能。

CS Test 示例演示 CS 测试命令，可覆盖某些信道探测参数的随机化过程、试验不同配置或评估射频介质（RF medium）。示例位于 [samples/bluetooth/channel_sounding/cs_test](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/channel_sounding/cs_test)。

Connected CS 示例演示在两个设备的连接上建立常规信道探测过程，位于 [samples/bluetooth/channel_sounding/connected_cs](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/channel_sounding/connected_cs)。

<a id="id1"></a>
<a id="id2"></a>

两者都包含基本距离估计算法。信道探测功能不强制规定具体测距算法；这些示例以参考资料 [1] 和 [2] 描述的数学表达为起点。 相关链接：[参考资料 1](#phase-and-amplitude)；[参考资料 2](#rtt-packets)。

通过信道探测估计距离需要两个设备的数据，因此示例通过 GATT 特征以简单方式交换探测结果。这使每次可处理的数据量约为每个设备 512 字节；假定只有一条天线路径，这足以利用少量往返时间（Round-Trip Timing，RTT）测量和约 35～40 个信道的基于相位的测距（Phase-Based Ranging，PBR）相位样本估计距离。

两个示例均重复执行信道探测过程，定期在控制台输出距离估计值；设计上假定每个过程只有一个子事件（Subevent）。

<a id="id3"></a>
<a id="id4"></a>

在两个已连接设备之间建立信道探测过程的步骤图，见参考资料 [3] 和 [4]。 相关链接：[参考资料 3](#cs-setup-phase)；[参考资料 4](#cs-start)。

<a id="requirements"></a>

## 58.2 前提条件（Requirements）

- 两块支持 Bluetooth LE 及信道探测的开发板，例如 [nRF54L15 DK](https://docs.zephyrproject.org/latest/boards/nordic/nrf54l15dk/doc/index.html#nrf54l15dk)。

- 支持信道探测功能的控制器。

<a id="building-and-running"></a>

## 58.3 构建与运行（Building and Running）

> 译注——两套配对与构建目录：Connected CS 的发起端／反射端构成一对，CS Test 的发起端／反射端构成另一对，以下四组命令不是依次烧录到同一设备。分别构建时可给 west build 添加 `-d build/cs-connected-initiator` 等不同相对输出目录，并在 west flash 中用相同 `-d` 指定该目录；目录由构建工具生成。已有目录先核对其应用、板与配置，避免误用前一个应用的缓存。

> 译注——执行环境：以下构建命令在读者自己的 Zephyr 源码根目录，用 UCRT64 Bash 或 Linux Bash 执行。先按[入门指南](../getting_started/大纲.md)准备工具链、west 工作区、板定义及控制器；`samples/...` 是官方已有目录，`<board>` 替换为实际目标。构建成功后按板文档烧录，分别核对对端角色、串口输出和本页预期结果；失败时先回查构建配置、烧录连接或角色与功能支持。本次仅翻译和核对来源，未执行构建、烧录或无线测试。

这些示例位于 Zephyr 源码树的 [samples/bluetooth/channel_sounding](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/bluetooth/channel_sounding) 目录。

每个示例包含两个应用，因此需要准备两个设备：一个烧录发起端（Initiator）应用，另一个烧录反射端（Reflector）应用。以下命令中的 `<board>` 应替换为目标开发板。

Connected CS：发起端（Initiator）：

```text
west build -b <board> samples/bluetooth/channel_sounding/connected_cs/initiator
west flash
```

Connected CS：反射端（Reflector）：

```text
west build -b <board> samples/bluetooth/channel_sounding/connected_cs/reflector
west flash
```

CS Test：发起端（Initiator）：

```text
west build -b <board> samples/bluetooth/channel_sounding/cs_test/initiator
west flash
```

CS Test：反射端（Reflector）：

```text
west build -b <board> samples/bluetooth/channel_sounding/cs_test/reflector
west flash
```

详情参见[蓝牙示例（Bluetooth samples）](https://docs.zephyrproject.org/latest/samples/bluetooth/bluetooth.html#bluetooth)。

两个设备距离足够近时，应每隔几秒重复进行距离估计。
