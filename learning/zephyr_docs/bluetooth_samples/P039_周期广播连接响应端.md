# 第39章\_周期广播连接过程：响应端（Periodic Advertising Connection Procedure / Responder）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/bluetooth/periodic_sync_conn/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/bluetooth/periodic_sync_conn/README.rst/..)

<a id="overview"></a>

## 39.1 概述（Overview）

本简单应用演示 Bluetooth LE 周期广播连接过程的响应端。

本示例启动为可连接广播端，使发起端先通过普通连接与其连接并获知地址。发起端断开后，示例扫描 PAwR 广播端，与之同步并响应子事件数据；响应中携带设备名仅用于证明仍在活动，因为发起端已经知道其地址。发起端通过周期广播连接过程连接后，本设备会断开并等待下一次连接。 相关链接：[周期广播连接过程：发起端（Periodic Advertising Connection Procedure / Initiator）](P036_周期广播连接发起端.md#ble_periodic_adv_conn)。

响应端使用身份地址（Identity address），使初次连接中获知的地址在后续 PAwR 连接时仍有效。

> 译注——地址稳定性依据：本次官方 prj.conf 设置 `CONFIG_BT_PRIVACY=n` 和 `CONFIG_BT_SCAN_WITH_IDENTITY=y`，用于保持初次获知的地址对后续 PAwR 连接有效。修改身份或隐私策略时，需要重新考虑发起端缓存地址的有效性，不能沿用旧地址假定连接仍可建立。

<a id="requirements"></a>

## 39.2 前提条件（Requirements）

- 一块支持 Bluetooth LE 的开发板。

- 支持 PAwR 扫描端（Scanner）功能的控制器。

<a id="building-and-running"></a>

## 39.3 构建与运行（Building and Running）

> 译注——构建位置与前提：以下是官方示例命令，在读者自己的 Zephyr 源码根目录中，使用 UCRT64 Bash 或 Linux Bash 执行；先完成[入门环境](../getting_started/大纲.md)，并确认所选板及控制器支持本文所需蓝牙能力。`samples/...` 是官方已有示例目录，`<board>` 是须替换的板目标占位符；构建输出由工具生成，不在本中文目录创建同名源码。先检查构建成功及板目标，再按板文档烧录并观察本文行为或日志；构建、烧录或通信失败时，分别回查工具链／板配置、烧录器和两端角色／控制器能力。本次未构建或运行示例。

按以下方式构建并烧录，将 `<board>` 替换为目标开发板：

```text
west build -b <board> samples/bluetooth/periodic_sync_conn
west flash
```

请先启动本示例。烧录后，设备进行可连接广播，供发起端连接并获知地址。发起端断开后，本设备扫描 PAwR 广播端，与之同步并响应子事件数据。发起端通过周期广播连接过程连接后，本设备断开并等待新连接。

在第二块开发板上运行周期广播连接过程发起端示例，先连接本设备，再启动 PAwR 广播，并在完成同步后连接本设备。 相关链接：[周期广播连接过程：发起端（Periodic Advertising Connection Procedure / Initiator）](P036_周期广播连接发起端.md#ble_periodic_adv_conn)。
