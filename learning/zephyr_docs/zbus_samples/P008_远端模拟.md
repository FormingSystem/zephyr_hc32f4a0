# 第8章\_远端模拟

原文：[Remote mock sample](https://docs.zephyrproject.org/latest/samples/subsys/zbus/remote_mock/README.html)。读取日期：2026-10-12，`latest`。

## 8.1\_概述

本应用演示主机脚本怎样通过**通用异步收发器（Universal Asynchronous Receiver/Transmitter，UART）**桥接，向嵌入式设备的 zbus 通道发布消息。设备把信息发给主机脚本；脚本需要模拟向某通道发布时再发回信息，并解码交换的数据，打印到**标准输出（Standard Output，stdout）**。

这种方式允许开发者用计算机上的任意编程语言编写测试，经通道直接与设备线程通信。因为可以控制和查看脚本收发内容，测试的可控性与可观测性也随之提高。

## 8.2\_构建并启动设备端

本项目向控制台输出，可在 native_sim 上构建并执行。

> 译注：下列 `native_sim` 命令面向准备好开发环境的 Linux 终端；Windows 读者需使用满足要求的 Linux 环境，不能直接把 Linux 设备节点交给 PowerShell。先按[入门指南](../getting_started/P002_入门指南.md)准备依赖，再核对 [native_sim 平台说明](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)。当前位置为实验用 Zephyr 源码根，west 的 `-b` 指定平台，`-t run` 启动已构建程序。不同示例应使用独立构建目录或清理旧缓存。

```sh
# From the root of the zephyr repository
west build -b native_sim samples/subsys/zbus/remote_mock
west build -t run
```

设备日志显示 Mock Proxy（模拟代理）接收主机请求，向通道发布测量启动事件，再把传感数据送回主机。discard loopback event 表示丢弃回环事件，避免把收到的同一请求再次回送。启动行 OS 表示**操作系统（Operating System，OS）**，START/FINISH 分别是开始/结束处理的日志标签。RX 是**接收（Receive，RX）**方向标签。这是官方示例输出：

```text
-- west build: running target run
[0/1] cd build/zephyr/zephyr.exe
uart_1 connected to pseudotty: /dev/pts/2
uart connected to pseudotty: /dev/pts/3
*** Booting Zephyr OS build zephyr-v3.1.0 ***
D: [Mock Proxy] Started.
D: [Mock Proxy RX] Started.
D: [Mock Proxy RX] Found sentence
D: Channel start_measurement claimed
D: Channel start_measurement finished
D: Publishing channel start_measurement
D: START processing channel start_measurement change
D: Channel start_measurement claimed
D: discard loopback event (channel start_measurement)
D: Channel start_measurement finished
D: FINISH processing channel start_measurement change

D: sending message to host (channel sensor_data)
D: Channel sensor_data finished
D: FINISH processing channel sensor_data change
D: sending sensor data err = 0

<repeats endlessly>
```

> 译注：原输出中的主机程序位置已改为相对路径 `build/zephyr/zephyr.exe`，其余日志保留。输出中的旧版本标识也只是原示例记录，并非本次使用的版本。若没有出现启动日志，先核对构建和运行目标。按 `Ctrl+C` 可结束运行。

## 8.3\_运行主机脚本

保持设备端运行，另开终端并同样进入 Zephyr 源码根，运行 `remote_mock.py` 脚本。需使用能导入串口库 pySerial 的 Python 环境，脚本随示例源码提供；原命令使用 `python3.8`，这是原例解释器名，不是要求为当前 Zephyr 降级 Python。实际使用兼容当前工程及脚本依赖的 Python 解释器。

```sh
python3.8 samples/subsys/zbus/remote_mock/remote_mock.py /dev/pts/2
```

因为设备运行于 native_sim，启动命令会打印**伪终端（Pseudoterminal）**端口。查找 `uart_1 connected to pseudotty` 对应的设备节点，例中是 `/dev/pts/2`，实际可能不同。实板应按板卡说明选择端口：Linux 通常类似 `/dev/tty...`，Windows 类似 `COM...`。这些是操作系统设备标识，不是仓库或个人文件路径。

脚本中 Proxy PUB（代理发布）启动测量，Proxy NOTIFY（代理通知）接收传感值；数值从 1 到 10 递增，并继续循环。

```text
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 1
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 2
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 3
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 4
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 5
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 6
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 7
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 8
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 9
Proxy PUB [start_measurement] -> start measurement
Proxy NOTIFY: [sensor_data] -> sensor value 10

<continues>
```

如果脚本打不开端口，核对当前进程打印的端口、访问权限和是否被其他终端占用；如果缺少 `serial` 模块，返回 Python 依赖准备。按 `Ctrl+C` 结束主机脚本。两端要同时运行才能完成交换。
