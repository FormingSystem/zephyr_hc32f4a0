# 第13章\_跨核代理

原文：[zbus Proxy agent - IPC](https://docs.zephyrproject.org/latest/samples/subsys/zbus/proxy_agent_ipc/README.html)。读取日期：2026-10-12，`latest`。

## 13.1\_跨执行域的请求与响应

本示例演示多核平台上的 zbus **代理通信（Proxy Agent Communication）**，使用**进程间通信（Inter-Process Communication，IPC）**后端，在不同处理器核之间转发消息。

它采用**请求—响应（Request–Response）**模式。应用处理器核作为请求方，向本地通道发布请求，从**影子通道（Shadow Channel）**接收响应；远端处理器核作为响应方，通过影子通道接收请求，再向本地通道发布响应。IPC 代理自动同步不同处理器执行域的通道数据。

每个执行域都定义自己的代理与通道：

- 宏 [`ZBUS_PROXY_AGENT_DEFINE`](../intercore_reference/P193_zbus代理接口.md) 定义代理。
- 宏 [`ZBUS_CHAN_DEFINE`](../intercore_reference/P213_zbus核心接口.md) 定义通道，宏 [`ZBUS_PROXY_ADD_CHAN`](../intercore_reference/P193_zbus代理接口.md) 将其加入代理。
- 宏 [`ZBUS_SHADOW_CHAN_DEFINE`](../intercore_reference/P193_zbus代理接口.md) 定义影子通道，自动镜像其他域的通道。
- 共享数据结构（例如结构体 `transfer_data`）在各域源码中分别定义，但必须保持布局兼容。

这样可以在跨核边界上保留总线的**发布/订阅（Publish/Subscribe）**结构。布局兼容要求通信双方对字段顺序、大小等有一致约定，并非只要结构体名称相同即可。

## 13.2\_构建与平台组合

本示例用 **多镜像系统构建（System Build，sysbuild）**组织多核程序，并从示例 `tests.yaml` 文件选取测试配置。原文给出的命令如下：

```sh
# From the root of the zephyr repository
west build -b nrf54h20dk/nrf54h20/cpuapp -T sample.zbus.proxy_agent_ipc.nrf54h20_cpuapp_cpurad .
```

> 译注：原命令注释说“从 Zephyr 根执行”，但最后的 `.` 把应用路径设成当前目录。所核对的 `scripts/west_commands/build.py` 中 `_resolve_test_item()` / `_parse_test_item()` 在所选应用目录寻找测试配置，并非自动搜索全仓。按该实现，若保留原命令，必须先进入 `samples/subsys/zbus/proxy_agent_ipc` 示例目录。若从 Zephyr 根执行，应把最后的 `.` 改成这个示例相对路径。测试条目含 `sysbuild: true`，因此此处由配置带入 sysbuild，不需要把原文误读成普通单镜像构建。

已完成[入门环境](../getting_started/P002_入门指南.md)、相应板工具链、依赖模块与多核板支持准备后，在开发终端操作。`-b` 选择板与核，`-T` 选择测试条目。若报找不到测试元数据，先核对工作目录和末尾应用路径；若报条目不存在，核对当前版本的 `tests.yaml`。构建成功应生成对应多核镜像，但仅构建并不会烧录或运行。

官方列出以下平台与核组合，核名是平台标识，不在此自行扩展为未经官方确认的缩写：

| 平台 | 核组合 |
| --- | --- |
| nRF54H20 | CPUAPP + CPURAD |
| nRF54L15 | CPUAPP + CPUFLPR |
| nRF54LM20 | CPUAPP + CPUFLPR |
| nRF5340 | CPUAPP + CPUNET |
| ESP32 | PROCPU + APPCPU |
| ESP32-S3 | PROCPU + APPCPU |

构建其他组合时，给 `-T <test_name>` 传入该版本 `tests.yaml` 中对应的测试条目。上表不表示这些目标都可在同一块板上执行。实际下载、复位和控制台连接需按所选板文档完成；原页没有提供一条通用的多板烧录命令。

## 13.3\_两端示例输出

输出中的 OS 是**操作系统（Operating System，OS）**，大写 ZBUS 仍指 zbus 消息总线。

应用处理器核先向通道对象 `request_channel` 发布值 1，再从响应通道对象 `response_channel` 收到值 2；下一次发布值 2，收到值 3：

```text
*** Booting Zephyr OS build v4.3.0-8932-g8ad7a29c8069 ***
main: ZBUS Proxy agent IPC Forwarder Sample Application
main: Requesting on channel request_channel, listening on channel response_channel
main: Published on channel request_channel. Test Value=1
main: Received message on channel response_channel. Test Value=2
main: Published on channel request_channel. Test Value=2
main: Received message on channel response_channel. Test Value=3
```

远端处理器核显示对应的接收和响应过程：收到 1 后回送 2，收到 2 后回送 3。

```text
*** Booting Zephyr OS build v4.3.0-8932-g8ad7a29c8069 ***
main: ZBUS Proxy agent IPC Forwarder Sample Application
main: Listening for requests on channel request_channel, responding on channel response_channel
main: Received message on channel request_channel. Test Value=1
main: Sending response: Test Value=2
main: Response published on channel response_channel
main: Received message on channel request_channel. Test Value=2
main: Sending response: Test Value=3
main: Response published on channel response_channel
```

两端值的对应关系说明请求已跨域传递并返回。若只有一端启动或只有发布日志，尚不能判定通信成功，应核对另一个核的镜像、IPC 后端及两端数据约定。原输出的版本字符串保留，本次没有构建镜像、运行处理器核或测试实际通信。
