# 第12章\_性能基准

原文：[Benchmarking](https://docs.zephyrproject.org/latest/samples/subsys/zbus/benchmark/README.html)。读取日期：2026-10-12，`latest`。

## 12.1\_测量目标与参数

本示例测量一个**生产者（Producer）**向若干**消费者（Consumer）**发送原文所称 256 **千字节（Kilobyte，KB）**数据的时间。后文输出给出精确大小为 262,144 字节，即 256 个 1,024 字节的数据单元。

> 译注：前提是已按[入门指南](../getting_started/P002_入门指南.md)准备 west、Zephyr 工作区、目标工具链及 QEMU 模拟器。在已激活开发环境的终端中操作，当前位置为实验用 Zephyr 源码根。以下是官方构建及启动命令；Windows 使用已配置的开发终端，Linux/macOS 使用对应终端。`-b` 选择模拟板目标，`-t run` 执行构建系统的运行目标。切换示例时应使用独立构建目录或按 [west 构建说明](../west/P007_构建烧录与调试.md)清理旧配置，避免复用其他应用的缓存。

本页模拟目标是 `qemu_cortex_m3`。示例专用 Kconfig 配置项决定每条消息大小、消费者数量和观察者类型；west 的 `--` 后将 CMake `-D` 参数传给配置阶段：

| Kconfig 配置项 | 用途与范围 |
| --- | --- |
| `CONFIG_BM_MESSAGE_SIZE` | 每条消息大小，2 到 4096 字节。 |
| `CONFIG_BM_ONE_TO` | 消费者数量，1 到 8。 |
| `CONFIG_BM_LISTENERS` | 设为 `y`，测量**监听器（Listener）**。 |
| `CONFIG_BM_SUBSCRIBERS` | 设为 `y`，测量普通**订阅者（Subscriber）**。 |
| `CONFIG_BM_MSG_SUBSCRIBERS` | 设为 `y`，测量**消息订阅者（Message Subscriber）**。 |

下面选择 512 字节消息、一位消费者和监听器模式：

```sh
# From the root of the zephyr repository
west build -b qemu_cortex_m3 samples/subsys/zbus/benchmark -- -DCONFIG_BM_MESSAGE_SIZE=512 -DCONFIG_BM_ONE_TO=1 -DCONFIG_BM_LISTENERS=y
west build -t run
```

## 12.2\_单次示例输出

结果类似下面的官方记录。Bytes sent/received（发送/接收字节数）用于核对数据量，Average data rate（平均数据率）和 Duration（耗时）给出本次配置的测量结果：

```text
*** Booting Zephyr OS build zephyr-vX.Y.Z ***
I: Benchmark 1 to 1 using LISTENERS to transmit with message size: 512 bytes
I: Bytes sent = 262144, received = 262144
I: Average data rate: 12.62MB/s
I: Duration: 0.019805908s

@19805
```

> 译注：末尾 `@19805` 是给脚本读取的数字标记，不是命令。所核对的 `samples/subsys/zbus/benchmark/src/benchmark.c` 先计算纳秒数，再将其除以 1000 打印到 `@` 后，因此这一整数是微秒。输出里的 MB/s 也沿用原例标签；该实现以每 1,048,576 字节计算一个单位，不能只凭标签按十进制百万字节解释。这里保留原值，不把模拟器结果推算成实板性能。

构建失败应先返回环境和目标检查；启动后没有报告时核对所选观察者、配置与控制台。模拟器中退出可先按 `Ctrl+A`，再按 `x`。

## 12.3\_批量执行基准

示例附带 [Robot Framework 测试框架](https://robotframework.org/)脚本 `benchmark_256KB.robot`，遍历输入组合完成整套基准，耗时较长。原文称结果文件为 `zbus_dyn_benchmark_256KB.csv`，位于项目根目录，采用**逗号分隔值（Comma-Separated Values，CSV）**格式。

原表用 LIS 表示 Listener（监听器）、SUB 表示 Subscriber（订阅者）、MSG_SUB 表示 Message Subscriber（消息订阅者）。六列如下。**随机存取存储器（Random Access Memory，RAM）**与**只读存储器（Read-Only Memory，ROM）**列表示构建报告的存储占用。

| 观察者类型 | 消费者数量 | 消息大小，字节 | Duration（耗时，原表标 ns） | RAM，字节 | ROM，字节 |
| --- | --- | --- | --- | --- | --- |
| LIS / SUB / MSG_SUB | 1、4、8 | 2、8、32、128、512 | 浮点数 | 整数 | 整数 |

LIS、SUB、MSG_SUB 分别是表格对监听器、普通订阅者和消息订阅者的简称。实际数据行使用 LISTENERS、SUBSCRIBERS、MSG_SUBSCRIBERS 三个字符串。

> 译注：所核对的 `benchmark_256KB.robot` 读取 `@` 后的数字并将三次结果取平均，没有再把微秒换算成纳秒，因此其 CSV 第四列与原表“ns”不一致，应按当前实现核对为微秒。脚本变量中的实际文件名还是小写 `zbus_dyn_benchmark_256kb.csv`；文件相对于执行脚本时的工作目录生成。大小写敏感系统不能把原文名字与脚本名字当成同一文件。

批量命令以 Nordic 板卡目标 `nrf52dk/nrf52832` 为例。运行前需准备 Robot Framework 及脚本声明的 SerialLibrary、CSVLibrary 等库、该板工具链和烧录器、可访问的串口。先进入实验源码下的 `samples/subsys/zbus/benchmark` 示例目录：脚本中的构建命令没有指定应用目录，因此依赖当前目录。本命令会多次构建并调用 `west flash` 烧录板卡，不是只生成一份文档报告。

```sh
robot --variable serial_port:/dev/ttyACM0 --variable board:nrf52dk/nrf52832 -d benchmark_out   benchmark_256KB.robot
```

命令中的 `--variable` 向脚本传入串口和板目标，`-d` 指定框架报告目录。`/dev/ttyACM0` 是 Linux 串口设备节点，须换成实际设备。译文将官方临时报告目录改成当前目录下的相对目录 `benchmark_out`；CSV 文件位置仍由脚本变量和工作目录决定。若出现串口、烧录或报告读取错误，先检查上述依赖，不要把未完成的数据当作完整测量。
