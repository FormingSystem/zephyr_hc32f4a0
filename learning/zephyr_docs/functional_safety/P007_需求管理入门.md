# 第7章\_需求管理入门（Getting started with Requirements Management）

原文：[官方页面](https://docs.zephyrproject.org/latest/safety/safety_requirements/getting_started/getting_started_with_requirements.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

Zephyr 使用 [StrictDoc](https://github.com/strictdoc-project/strictdoc) 管理需求。它是用于编写、组织和发布结构化需求的轻量工具。本节介绍如何设置和使用 reqmgmt 仓库提供的工具链。 相关链接：[`reqmgmt`](https://github.com/zephyrproject-rtos/reqmgmt)。

<a id="overview"></a>

## 7.1 概述（Overview）

`reqmgmt` 是 Zephyr 官方需求工作区，支持：

- 编写系统需求和软件需求。

- 将需求关联到验证产物。

- 生成可浏览的 HTML 文档。

- 运行用于编辑和评审的本地 Web 界面。

<a id="installation"></a>

## 7.2 安装（Installation）

StrictDoc 需要 Python 3.7 或更高版本。安装命令如下，某些环境可能需要用 pip3 替代 pip：

> 译注——执行前提与版本：以下为官方安装示例，应在读者选择的 Python 环境中使用 UCRT64 Bash 或 Linux Bash 执行。先确认 Python、pip 和 Git 可用，再选择适合的工具版本。原页写 Python 3.7 起；本次读取的[StrictDoc PyPI 元数据](https://pypi.org/pypi/strictdoc/json)中，0.30.2 的 `Requires-Python` 为 `>=3.10`，而[需求仓库 requirements.txt](https://raw.githubusercontent.com/zephyrproject-rtos/reqmgmt/main/requirements.txt)要求 `strictdoc>=0.16.2`。不能将旧网页的 Python 下限当作任意新版本的安装前提。本次未安装工具；安装失败时应先处理解释器与包版本兼容性，再继续。

```text
pip install strictdoc
```

克隆 Zephyr 需求仓库：

> 译注——仓库位置与复用：本段 `git clone` 在读者选择的工作区父目录执行，命令创建 `reqmgmt` 目录；如果已由 west 或此前操作取得仓库，直接进入已有仓库，不重复克隆。后续 `strictdoc export .`、`strictdoc server .` 的当前位置都是该需求仓库根目录，点号指该根目录，不指本中文翻译目录。

```text
git clone https://github.com/zephyrproject-rtos/reqmgmt
cd reqmgmt
```

<a id="usage"></a>

## 7.3 使用方法（Usage）

将需求导出为 HTML：

```text
strictdoc export .
```

这会在 `output/` 目录生成静态网站。

> 译注——产物与检查：`output/` 是导出命令生成的目录，不应预先当成原有源码。命令成功后检查输出提示和生成目录；失败时返回前面的工具版本、仓库位置和需求语法检查。

启动本地 Web 界面：

```text
strictdoc server .
```

应看到类似输出：

```text
Uvicorn running on http://127.0.0.1:5111 (Press CTRL+C to quit)
```

在本地浏览器中输入上面的地址，即可通过浏览器界面浏览和编辑需求。

> 译注——服务地址：`127.0.0.1` 是本机回环地址，不是作者的文件系统绝对路径。实际端口以启动输出为准。服务器运行后再在同一台机器的浏览器打开该地址；停止时按输出提示使用 Ctrl+C。

<a id="structure"></a>

## 7.4 目录结构（Structure）

仓库包含：

- `docs/`：按子系统组织的需求文档。

- `strictdoc.toml`：StrictDoc 配置文件。

> 译注——当前配置文件差异：原页列出 `strictdoc.toml`；本次核对的官方需求仓库使用[strictdoc_config.py](https://raw.githubusercontent.com/zephyrproject-rtos/reqmgmt/main/strictdoc_config.py)，通过 `create_config()` 返回 `ProjectConfig`。不要仅因原页列出 TOML 文件而另建配置；应以实际检出的仓库版本为准。

- `tasks.py`：用于构建和验证需求的自动化辅助脚本。

## 7.6 后续步骤（Next Steps）

- 浏览 `docs/`，查看需求文件示例。

- 通过 Web 界面创建或编辑自己的需求。

- 将需求链接到测试用例或源码模块，建立可追溯性。

`StrictDoc` 将系统目标与软件实现之间的关系形式化，帮助 Zephyr 为安全关键应用做好准备。
