# 第40章\_用户空间受保护内存示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/userspace/shared_mem/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

[在GitHub上浏览示例源码](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/userspace/shared_mem/README.rst/..)。

<a id="overview"></a>

## 40.1 概述（Overview）

本示例运行多个线程，为它们分配各自的内存域（Memory Domain）以及受保护的内存分区（Protected Partition）。应用把内存分区机制与一个模拟恩尼格玛式密码机（Enigma-like Machine）的示例算法结合使用；该密码机实现未经验证，不应用于任何实际安全用途。

<a id="requirements"></a>

## 40.2 要求（Requirements）

本示例依赖`app_memory`子系统，无法在不支持该子系统的开发板上运行。原文称已在`qemu_x86`、`frdm_k64`和`96b_carbon/stm32f401xe`上测试。

> 译注——开发板名称：这里保留原文中的`frdm_k64`拼写和测试表述，没有据此补造其他板的测试结果。选择目标时，应核对所用Zephyr版本中的板目标名称与用户空间支持情况。

<a id="building-and-running"></a>

## 40.3 构建与运行（Building and Running）

由于示例只是向控制台打印文本，这里仅介绍`qemu_x86`板：

> 译注——命令前提：先按所用Zephyr版本准备Python依赖、对应目标工具链和QEMU，并确认当前终端可以调用west。在UCRT64 Bash或Linux Bash中，以Zephyr源码根目录为当前目录执行；只有构建成功后才执行运行命令。若构建失败，先处理构建错误；若QEMU启动失败，检查该版本的模拟器和目标配置。下面的日志是官方示例输出，本文未执行构建或模拟运行。

```sh
west build -b qemu_x86 samples/userspace/shared_mem
west build -t run
```

启动后，控制台先显示多条启动消息，随后显示两组重复的消息。它们分别是恩尼格玛式密码机的输入和输出：第二条输入消息就是第一条消息的输出，再次处理后得到去掉空格的第一条消息。两条消息分别标记为`1`和`1’`。

按`CTRL+A`，再按`x`退出QEMU。

可以加入两个定义，分别改变转轮设置（Wheel Settings）和打印状态信息。取消`CMakeLists.txt`最后两行的注释，即可启用这两个定义。

> 译注——定义对应的实现：当前这两项为`ALTMSG`和`DBUG`。`ALTMSG`改变第一个转轮的初值，并选择与之对应的预置密文；`DBUG`启用加密过程的状态输出。以上用途可在`src/main.c`和`src/enc.c`中跟踪。

<a id="functionality"></a>

## 40.4 功能原理（Functionality）

明文线程（Plain Text Thread，PT线程）发送一条消息，休眠后再发送该消息的加密版本。发送时，PT线程检查一个标志；如果标志已清除，就把消息写入与加密线程（Encrypt Thread）共享的缓冲区，写完后设置该标志。

加密线程在标志被设置时，将公共缓冲区中的内容复制到自己的私有内存，然后清除标志。收到文本字符串后，它模拟恩尼格玛密码机，生成密文（Cypher Text，CT）。密文被复制到与第三个线程共享的内存分区。第三个线程将密文打印到控制台，并用`CYPHER TEXT`横幅标明内容。
