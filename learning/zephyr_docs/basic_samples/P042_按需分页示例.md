# 第42章\_按需分页示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/subsys/demand_paging/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

[在GitHub上浏览示例源码](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/subsys/demand_paging/README.rst/..)。

<a id="overview"></a>

## 42.1 概述（Overview）

本示例展示：当无法原地执行（Execute in Place，XIP），且固件大于可用随机存取存储器（Random Access Memory，RAM）时，如何使用按需分页（Demand Paging）。可以标记选定的代码，使其按需装入内存；当内存耗尽时，也可以自动将这些代码换出，以便执行更多代码。

<a id="requirements"></a>

## 42.2 要求（Requirements）

该演示要求受支持的硬件内存管理单元（Memory Management Unit，MMU），以及能够访问已编译Zephyr二进制文件的后备存储（Backing Store）实现。

为便于演示，它在QEMU ARM64目标上使用`ondemand_semihost`后备存储，并将RAM配置固定为较小容量。

> 译注——硬件条件：这里的MMU负责页映射和缺页处理，不等同于只提供区域访问保护的内存保护单元（Memory Protection Unit，MPU）。不能因为某个平台具备MPU，就推断该平台满足此示例的按需分页要求。

<a id="building-and-running"></a>

## 42.3 构建与运行（Building and Running）

可以按以下方式在QEMU中构建和执行本应用：

> 译注——命令前提：先按所用Zephyr版本准备Python依赖、对应目标工具链和QEMU，并确认当前终端可以调用west。在UCRT64 Bash或Linux Bash中，以Zephyr源码根目录为当前目录执行；只有构建成功后才执行运行命令。若构建失败，先处理构建错误；若QEMU启动失败，检查该版本的模拟器和目标配置。下面的日志是官方示例输出，本文未执行构建或模拟运行。

```sh
west build -b qemu_cortex_a53 samples/subsys/demand_paging
west build -t run
```

<a id="sample-output"></a>

### 42.3.1 示例输出（Sample Output）

```text
*** Booting Zephyr OS build v3.7.0-2108-g5975c3785356 ***
Calling huge body of code that doesn't fit in memory
free memory pages: from 37 to 0, 987 page faults
Calling it a second time
free memory pages: from 0 to 0, 987 page faults
Done.
```

按`CTRL+A`，再按`x`退出QEMU。

要观察底层按需分页子系统的实际工作过程，可以在配置文件中使用[`CONFIG_LOG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LOG)和[`CONFIG_KERNEL_LOG_LEVEL_DBG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_KERNEL_LOG_LEVEL_DBG)启用调试输出。

> 译注——缺页统计：当前源码用`__ondemand_func`标记一个很大的代码函数，两次调用它，并统计每次调用前后的空闲页数和缺页次数（Page Faults）。日志中的缺页属于触发装入页面的预期机制，不是应用崩溃的同义词；“空闲页为0”也不表示后续任意内存分配一定能够成功。原日志的系统版本及计数均按原样保留。
