## 39.1 概述（Overview）

设想一个“示例驱动”（Sample Driver）：它从某个未知来源接收数据，并产生携带该数据指针的中断。应用需要对数据进行处理，再把处理后的数据写回驱动。

本示例旨在展示：

- 多个逻辑应用，每个应用拥有自己的内存域（Memory Domain）。
- 创建`sys_heap`，并将其分配到一个内存分区（Memory Partition）。
- 使用`k_queue_alloc_append()`等需要配置线程资源池（Thread Resource Pool）的API。
- 管理内核对象（Kernel Object）和驱动的访问权限（Permission）。
- 如何定义应用专用的系统调用（Application-specific System Call）。
- 在中断服务程序（Interrupt Service Routine，ISR）和应用之间使用`k_msgq`进行进程间通信（Inter-process Communication，IPC），在应用之间使用`k_queue`进行IPC。
- 如何创建应用专用的系统调用。

在本例中，应用A（Application A）负责与驱动通信、缓冲传入数据，并在应用B（Application B）处理完成后将数据写回。

应用B只负责处理数据。假定这些数据不可信，甚至可能带有恶意内容，因此将应用B放入与其他部分隔离的沙箱（Sandbox），只通过两个队列发送和接收数据项。

控制循环如下：

1. 示例驱动发出中断，以固定大小的数据载荷（Payload）调用其关联的回调函数。
2. 应用A的回调函数在特权模式（Supervisor Mode）下，将数据载荷放入消息队列（Message Queue）。
3. 应用A的监视线程在用户模式（User Mode）下等待消息队列中的数据。唤醒后，将数据载荷复制到从共享内存池（Shared Memory Pool）分配的缓冲区中，再将该数据加入应用B监视的`k_queue`。
4. 应用B的处理线程等待队列中的新项，就地处理数据，然后将处理后的数据放入另一个队列，等待写回驱动。
5. 应用A的写回线程监视输出数据队列，取得包含处理结果的新项后，将数据写回驱动并释放缓冲区。

本示例还通过`magic_cookie()`函数展示应用自定义系统调用。

> 译注——共享数据与内核资源：共享载荷缓冲区来自`sys_heap`；`k_queue_alloc_append()`内部为队列节点分配内存时使用线程关联的资源池。当前实现分别配置这两类内存，不应将它们视为同一个池。内存域授予共享分区的访问权，内核对象权限控制对队列、消息队列和驱动的访问，两者需要分别配置。队列传递的是共享缓冲区指针，不能据此认为载荷自动复制到另一个应用的私有内存。

> 译注——系统调用名称：页面使用`magic_cookie()`，当前`app_syscall.h`及`app_syscall.c`中的实际名称是`magic_syscall(unsigned int *cookie)`。验证函数先把用户数据复制到局部变量，再交给实现处理，成功后才复制回用户地址，避免在检查和使用之间反复读取可能变化的用户数据。这是源码对照，未改写原文函数名。
