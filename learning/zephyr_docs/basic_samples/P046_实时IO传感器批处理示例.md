# 第46章\_实时IO传感器批处理示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/subsys/rtio/sensor_batch_processing/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

[在GitHub上浏览示例源码](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/subsys/rtio/sensor_batch_processing/README.rst/..)。

<a id="overview"></a>

## 46.1 概述（Overview）

本示例展示如何使用[实时输入／输出（Real Time I/O，RTIO）](../io_services/P001_实时输入输出.md#rtio)框架组织异步操作链（Asynchronous Operation Chain）。应用通过RTIO及其内存池API（Mempool API）从虚拟传感器（Virtual Sensor）获取数据，并在控制台显示。

<a id="requirements"></a>

## 46.2 要求（Requirements）

- 支持闪存（Flash）的开发板，或`native_sim`目标。

<a id="building-and-running"></a>

## 46.3 构建与运行（Building and Running）

本示例可以为大多数平台构建。以下原文命令为`native_sim`目标构建应用：

```sh
west build -b native_sim samples/subsys/rtio
west build -t run
```

> 译注——原命令的示例路径：官方页面写成`samples/subsys/rtio`，但实际应用的`CMakeLists.txt`位于`samples/subsys/rtio/sensor_batch_processing`。上方保留原命令；下方是据当前官方目录给出的更正。在具备`native_sim`构建依赖的Linux Bash环境中，以Zephyr源码根目录为当前目录执行；若构建失败，应先处理错误，不继续运行旧产物。

```sh
west build -b native_sim samples/subsys/rtio/sensor_batch_processing
west build -t run
```

运行时，控制台输出展示传感器数据请求的提交、数据消费及处理操作。

> 译注——批大小与完成等待：当前实现先准备8个提交队列项（Submission Queue Entry，SQE），每轮消费并处理4个样本。`rtio_submit(&ez_io, M)`的第二个参数是等待完成的数量（Wait Count），不是限制本次只提交几个SQE；不能把日志中的“Submitting 4 read requests”直接当作首轮只有4个请求入队的证明。

> 译注——内存归还顺序：应用取得完成队列项（Completion Queue Entry，CQE）对应的内存池缓冲区后，先释放CQE，再处理样本，最后归还样本缓冲区并准备新请求。释放CQE与释放数据缓冲区是两件事。虚拟传感器生成递增的测试字节，处理阶段通过休眠模拟耗时，不能将这份输出当成真实传感器采集或某种实际信号处理算法的实验结果。
