# 第13章\_不复制代码重定位示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/application_development/code_relocation_nocopy/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 13.1 概述（Overview）

这是一个使用自定义链接器脚本（Linker Script）重定位代码、数据或BSS段的简单示例。

与代码重定位示例不同，本示例将`ext_code.c`的内容放到另一个Flash段，代码直接从那里原位执行（Execute in Place，XIP），不需要复制或运行时搬移。其他代码，例如`main()`和Zephyr内核，仍保留在内部Flash中。

> 译注——NOCOPY的范围：当前[CMakeLists.txt](../../../samples/application_development/code_relocation_nocopy/CMakeLists.txt)将`ext_code.c`的代码通过`LOCATION EXTFLASH_TEXT NOCOPY`放入外部Flash，但同一文件的数据仍通过`LOCATION RAM_DATA`复制到RAM；`sram_code.c`则整体重定位到RAM。因此“不复制”针对指定代码段，不是整个应用完全没有复制过程。相关机制见[代码与数据重定位](../kernel/P050_代码与数据重定位.md)。

<a id="nrf5340-dk-platform-instructions"></a>

## 13.2 nRF5340 DK平台说明（nRF5340 DK platform instructions）

nRF5340 DK具有支持四线SPI（Quad SPI，QSPI）的64 Mb外部Flash，映射地址为`0x10000000`。

构建并烧录应用，包括外部存储器部分：

> 译注——操作前提：下列各板命令是相互独立的分支，在UCRT64 Bash或Linux Bash的Zephyr源码根目录执行；需要对应板的工具链、模块、烧录器和硬件已经准备好。先确认构建成功再执行`west flash`，失败时返回构建错误定位。这里的地址是目标芯片内存映射，不是主机文件路径；`Mb`表示兆比特，不能读成`MB`兆字节。

```sh
west build -b nrf5340dk/nrf5340/cpuapp samples/application_development/code_relocation_nocopy
west flash
```

<a id="stm32f769i-discovery-platform-instructions"></a>

## 13.3 STM32F769I-Discovery平台说明（STM32F769I-Discovery platform instructions）

`stm32f769i_disco`具有通过QSPI连接的64 MB外部Flash，映射地址为`0x90000000`。

```sh
west build -b stm32f769i_disco samples/application_development/code_relocation_nocopy
west flash
```

<a id="stm32-b-u585i-iot02a-discovery-kit-instructions"></a>

## 13.4 STM32 b\_u585i\_iot02a Discovery开发套件说明（STM32 b\_u585i\_iot02a Discovery kit instructions）

`b_u585i_iot02a`具有通过八线SPI（Octal SPI，OSPI）连接的64 MB外部Flash，映射地址为`0x70000000`。

```sh
west build -b b_u585i_iot02a samples/application_development/code_relocation_nocopy
west flash
```
