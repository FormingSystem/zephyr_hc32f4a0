<a id="overview"></a>

## 43.1 概述（Overview）

本示例实现一个由软件支撑的小型精密时钟（Precision Clock），并使用精确定时API（Precision-timing API）设置其绝对时间（Absolute Time）、应用相位校正（Phase Correction）和速率校正（Rate Correction）。速率校正由一个独立的比例积分控制器（Proportional-Integral Controller，PI控制器）计算。

<a id="building-and-running"></a>

## 43.2 构建与运行（Building and Running）

在`native_sim`上构建并运行本示例：

> 译注——命令前提：在已经准备Zephyr开发依赖和native_sim构建依赖的Linux Bash环境中，以Zephyr源码根目录为当前目录执行。构建成功后再运行，出现控制台输出表示进入示例；构建失败时先处理错误，避免运行旧产物。本文保留官方输出，未实际执行构建或模拟运行。

```sh
west build -b native_sim/native/64 samples/subsys/precision_timing
west build -t run
```

<a id="sample-output"></a>

### 43.2.1 示例输出（Sample Output）

```text
Precision clock: time 1000250000 ns, rate 16.25 ppm
```

> 译注——软件时钟的范围：当前实现把时间保存到结构体字段，先设为1000000000纳秒，再加250000纳秒，因此读回1000250000纳秒。PI控制器以0.5和0.15初始化，处理25.0这一输入后，示例将速率校正值转换为缩放后的百万分率（Scaled Parts Per Million，Scaled PPM）保存。该简化时钟的读操作只返回已保存的时间，速率调整也只保存数值；源码没有实现随真实时间自行递增的时钟或硬件频率校准闭环。不能把打印的16.25 ppm理解为已经测得并校正了硬件振荡器偏差。
