# 第30章\_哲学家就餐示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/philosophers/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 30.1 概述（Overview）

本示例实现哲学家就餐问题（Dining Philosophers Problem）的一种解法，这是经典的多线程同步问题。这个实现展示多个不同优先级的可抢占线程（Preemptible Thread）和协作式线程（Cooperative Thread），以及动态互斥锁和线程睡眠的使用。

哲学家总是先获取编号较小的叉子，顺序为`f1`再`f2`；用完后按相反顺序归还，先`f2`再`f1`。获得两把叉子时处于进餐（EATING）状态，否则处于思考（THINKING）状态。程序也显示过渡状态，例如想进餐但叉子不可用时的饥饿（STARVING），以及取得一把叉子、等待第二把时的持有一把叉子（HOLDING ONE FORK）。

每位哲学家会在进餐和思考状态间随机交替。

演示可以只运行协作式线程，也可以只运行可抢占线程。为此，在`prj.conf`中给`CONFIG_NUM_COOP_PRIORITIES`和`CONFIG_NUM_PREEMPT_PRIORITIES`设置以下值。

仅可抢占（preempt-only）：

```kconfig
CONFIG_NUM_PREEMPT_PRIORITIES=6
CONFIG_NUM_COOP_PRIORITIES=0
```

仅协作式（coop-only）：

```kconfig
CONFIG_NUM_PREEMPT_PRIORITIES=0
CONFIG_NUM_COOP_PRIORITIES=6
```

这两种情况下，哲学家线程的优先级分别为0至5，以及-7至-2。

> 译注——原配置与优先级范围：上述片段是写入应用`prj.conf`的配置，不是终端命令。当前`new_prio()`在仅协作式模式下返回`-phil-2`，六个线程确实需要-2至-7；但原文的`CONFIG_NUM_COOP_PRIORITIES=6`只提供-6至-1的范围，无法容纳-7。按这份实现至少需要7个协作式优先级，再核对主线程及其他配置；这里保留原片段并指出不一致，没有声称原配置已验证通过。

<a id="building-and-running"></a>

## 30.2 构建与运行（Building and Running）

项目向控制台输出，可以按以下方式在QEMU上构建并执行：

> 译注——命令环境：在UCRT64 Bash或Linux Bash的Zephyr源码根目录执行，先准备命令中QEMU目标的工具链、模块和模拟器。构建成功后再运行；失败时先检查对应目标与依赖，不把下面的原文输出当作本次执行记录。

```sh
west build -b qemu_x86 samples/philosophers
west build -t run
```

<a id="sample-output"></a>

### 30.2.1 示例输出（Sample Output）

```text
Philosopher 0 [P: 3]  HOLDING ONE FORK
Philosopher 1 [P: 2]  HOLDING ONE FORK
Philosopher 2 [P: 1]  EATING  [ 1900 ms ]
Philosopher 3 [P: 0]  THINKING [ 2500 ms ]
Philosopher 4 [C:-1]  THINKING [ 2200 ms ]
Philosopher 5 [C:-2]  THINKING [ 1700 ms ]
```

按`Ctrl+A`后再按`x`退出QEMU。

<a id="debug-threads"></a>

## 30.3 调试线程（Debug Threads）

哲学家示例默认启用[`CONFIG_DEBUG_THREAD_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DEBUG_THREAD_INFO)，因此OpenOCD和J-Link等工具可提供线程信息，供`info threads`检查。

> 译注——调试环境：在UCRT64 Bash或Linux Bash的Zephyr源码根目录，把`<board_name>`替换成实际板目标，先准备相应工具链、调试服务器及探针。构建成功后才运行`west debug`；`info threads`在进入GDB之后执行。原日志的源文件位置来自当时的调试信息，不要求读者复刻该目录。

```sh
west build -b <board_name> samples/philosophers
west debug
```
