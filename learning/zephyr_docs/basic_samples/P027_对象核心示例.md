# 第27章\_对象核心示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/kernel/object_cores/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 27.1 概述（Overview）

[对象核心（Object Cores）](../kernel/P048_内核对象核心.md#object-cores-api)是一项内核调试设施，工具可以借助它找到给定类型的内核对象，无论对象是静态定义还是运行时初始化，并读取该对象类型提供的统计信息。跟踪子系统中的对象跟踪（Object Tracking，[`CONFIG_TRACING_OBJECT_TRACKING`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_TRACING_OBJECT_TRACKING)）也由这套设施提供支持。

本示例逐项介绍这些能力：

- **对象清单（Object Inventory）**：每种类型有多少对象；有多少对象因位于栈存储中而被跳过登记，计为`skipped`；有多少因登记表已满而登记失败，计为`dropped`。只有`dropped`为0时，清单才完整；一旦出现丢弃，就有对象不会被任何遍历报告。某类型的内核代码若未链接到镜像，报告为`not present`。
- **静态与运行时对象（Static and Run-time Objects）**：用[`K_SEM_DEFINE`](../synchronization_reference/P008_信号量公共接口.md#ga018a8aa43e02e704deee7b6341502946)创建的信号量无需额外调用就会被报告；普通存储中的信号量则在[`k_sem_init()`](../synchronization_reference/P008_信号量公共接口.md#gadcd0e6cfba3392fb887222eafe4c1845)完成登记后才会被报告。
- **短暂对象（Transient Objects）**：函数内声明的信号量不会登记，因为它的存储生命周期随函数结束；信号量类型改为把它计入`skipped`。
- **线程（Threads）**：从创建线程起，到线程被中止为止，都能报告该线程。
- **释放的内存（Released Memory）**：嵌入堆分配结构中的互斥锁，在结构释放后不再报告。
- **显式取消登记（Explicit Unregistration）**：[`k_obj_core_unlink()`](../object_core_reference/P001_对象核心公共接口.md#ga7cb5b22d776880313c91a14583bb5d62)立即把对象从遍历结果中移除。
- **统计信息（Statistics）**：启用[`CONFIG_OBJ_CORE_STATS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_OBJ_CORE_STATS)后，可以通过统一的[`k_obj_core_stats_query()`](../object_core_reference/P002_对象核心统计接口.md#ga52afc700fb116acfaa4dd5e1ca49a782)接口读取各线程运行时统计、内存块池（Memory Slab）使用量及所有CPU消耗的周期数。

> 译注——“完整”的范围：原文同时说明栈上短暂对象会被有意跳过，`skipped`不会变成可遍历的对象列表。`dropped=0`表示没有因登记容量不足而遗漏对象，不能据此推断任意生命周期、任意存储位置的对象都出现在清单中。本仓库参照版本尚无这个示例，以下新行为应以所保存的官方源码为依据。

## 27.2 构建与运行（Building and Running）

可以按以下方式在QEMU上构建并执行：

> 译注——命令环境：在UCRT64 Bash或Linux Bash的Zephyr源码根目录执行，先准备命令中QEMU目标的工具链、模块和模拟器。构建成功后再运行；失败时先检查对应目标与依赖，不把下面的原文输出当作本次执行记录。

```sh
west build -b qemu_x86 samples/kernel/object_cores
west build -t run
```

要为另一块开发板构建，把上面的`qemu_x86`替换为该板名称。在[native_sim](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)上，线程使用主机栈，因此示例启用[`CONFIG_ARCH_POSIX_UPDATE_STACK_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ARCH_POSIX_UPDATE_STACK_INFO)，以便内核识别栈存储中的对象。

<a id="object-tracking"></a>

### 27.2.1 对象跟踪（Object tracking）

`tests.yaml`中的`sample.kernel.object_cores.tracking`配置使用[`CONFIG_TRACING`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_TRACING)和[`CONFIG_TRACING_OBJECT_TRACKING`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_TRACING_OBJECT_TRACKING)，代替`prj.conf`中的[`CONFIG_OBJ_CORE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_OBJ_CORE)来构建同一个程序：

```sh
west build -b qemu_x86 samples/kernel/object_cores -T sample.kernel.object_cores.tracking -t run
```

对象跟踪会选中对象核心框架，因此程序无需修改，输出第一行会注明框架是如何启用的。
