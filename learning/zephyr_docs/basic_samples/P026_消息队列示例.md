# 第26章\_消息队列示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/kernel/msg_queue/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 26.1 概述（Overview）

本示例展示Zephyr消息队列（Message Queue）的基本用法。生产者线程（Producer Thread）发送普通和紧急消息，由消费者线程（Consumer Thread）取出。

<a id="building-and-running"></a>

## 26.2 构建与运行（Building and Running）

可以按以下方式在QEMU上构建并执行：

> 译注——命令环境：在UCRT64 Bash或Linux Bash的Zephyr源码根目录执行，先准备命令中QEMU目标的工具链、模块和模拟器。构建成功后再运行；失败时先检查对应目标与依赖，不把下面的原文输出当作本次执行记录。

```sh
west build -b qemu_x86 samples/kernel/msg_queue
west build -t run
```

要为其他开发板目标构建，用相应目标替换上面的`qemu_x86`。

<a id="sample-output"></a>

### 26.2.1 示例输出（Sample Output）

每条普通消息放在队尾，按先进先出（First In, First Out，FIFO）顺序交付。每条“紧急”消息放在队首；只要后面没有新的紧急消息插入，它就会最先交付。

本示例中，生产者每发送两条普通消息，就发送一条紧急消息。注意，消息C最先被取出，因为它是最后作为紧急消息发送的那一条。

```text
[producer] sending: 0
[producer] sending: 1
[producer] sending: A (urgent)
[producer] sending: 2
[producer] sending: 3
[producer] sending: B (urgent)
[producer] sending: 4
[producer] sending: 5
[producer] sending: C (urgent)
[consumer] got sequence: CBA012345
```

按`Ctrl+A`后再按`x`退出QEMU。

> 译注——顺序的来源：当前实现使用`k_msgq_put()`追加普通消息，使用`k_msgq_put_front()`插入紧急消息，并在9条消息都已进入队列后才启动消费者。因此出现`CBA012345`；这不是消息队列自动识别某个“紧急”字段，也不意味着消费者始终在运行时仍会得到完全相同的累积顺序。
