# 第2章\_C语言编码风格

原文：[官方页面](https://docs.zephyrproject.org/latest/contribute/style/code.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 2.1\_适用范围与一致性

本页规则适用于新增或修改的代码；不要求为此清理与当前改动无关的旧代码。

如果规则没有明确规定，或允许多种写法，应采用既有代码的风格。优先与最接近的上下文保持一致：先看当前函数，再看当前文件，最后看所属子系统。

## 2.2\_C 语言及通用规则

总体遵循 [Linux 内核编码风格（Linux Kernel Coding Style）](https://kernel.org/doc/html/latest/process/coding-style.html)，但须遵守以下例外和补充：

- 使用制表符（tab）缩进，制表宽度为 8 个字符。
- 代码命名和变量命名采用[蛇形命名法（snake_case）](https://en.wikipedia.org/wiki/Snake_case)。
- 每行不超过 100 列；文档中的 URL 引用可以更长。
- `if`、`else`、`do`、`while`、`for` 和 `switch` 语句都使用花括号，即使语句体只有一行。
- 对齐声明后面的注释时使用空格，不使用制表符。
- 单行注释使用 C89 风格的 `/* */`，不使用 C99 风格的 `//`。
- Doxygen 注释使用 `/** */`。
- 避免使用以 `0b` 开头的二进制字面量（binary literal）。
- 避免在代码中使用非 ASCII 字符，除非能显著提高表达的清晰度；任何情况下都不要使用表情符号（emoji）。
- 代码注释中的名词采用其正确的大小写，例如写 `UART`，不写 `uart`；写 `CMake`，不写 `cmake`。


对应官方文档源码：[doc/contribute/style/code.rst](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/doc/contribute/style/code.rst)。

本仓库的[对应源码](../../../doc/contribute/style/code.rst)可用于跟踪，版本可能与网页不同；本批仅翻译和核对文档，没有执行固件构建、模拟运行或烧录。
