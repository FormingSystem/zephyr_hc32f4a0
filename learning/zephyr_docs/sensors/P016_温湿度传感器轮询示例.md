# 第16章\_温湿度传感器轮询示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/sensor/dht_polling/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 16.1 概述（Overview）

本示例演示数字温湿度传感器（Digital humidity and temperature sensor）的使用。

<a id="building-and-running"></a>

## 16.2 构建与运行（Building and Running）

> 译注——命令位置：以下主机构建命令从读者自己的Zephyr源码根目录执行，使用已完成官方入门配置的UCRT64 Bash或Linux Bash终端。代码中的`<board to use>`、`<your_board>`等是待替换占位符；设备树片段属于覆盖文件内容，不是Shell命令。构建成功只说明固件生成，烧录和传感器输出需要实际目标硬件及接线。出现设备未就绪或读取错误时，先核对别名、节点启用状态、驱动配置及总线连接。

示例支持最多10个温湿度传感器。每个传感器须设置`dhtN`别名，其中`N`从`0`到`9`。例如：

```devicetree
/ {
      aliases {
                      dht0 = &hs300x;
              };
      };
```

确认别名已加入设备树。有实际传感器时，还需要正确设置测试夹具（Fixture）。要通过Twister正确执行本示例，应在开发板的映射文件（Map file）中加入以下夹具设置：

```yaml
- fixture: fixture_i2c_hs300x
```

然后构建并运行：

```sh
west build -b <board to use> samples/sensor/dht_polling
west flash
```

> 译注——夹具与读取：Twister夹具描述测试环境具备的连接条件，不会自动创建传感器节点或代替接线。当前实现使用`sensor_read()`，随后分别解码`SENSOR_CHAN_AMBIENT_TEMP`和`SENSOR_CHAN_HUMIDITY`；`prj.conf`启用了`CONFIG_SENSOR_ASYNC_API`。多实例别名应从`dht0`连续编号：设备数组只收集存在的节点，而IO设备指针数组按0—9保留空位置，跳号会使两者的相同下标不再对应。

### 16.2.1 示例输出（Sample Output）

```text
hs300x@44: temp is 25.31 °C humidity is 30.39 %RH
hs300x@44: temp is 25.51 °C humidity is 30.44 %RH
hs300x@44: temp is 25.51 °C humidity is 30.37 %RH
hs300x@44: temp is 25.51 °C humidity is 30.39 %RH
hs300x@44: temp is 25.31 °C humidity is 30.37 %RH
hs300x@44: temp is 25.31 °C humidity is 30.35 %RH
hs300x@44: temp is 25.51 °C humidity is 30.37 %RH
hs300x@44: temp is 25.51 °C humidity is 30.37 %RH
hs300x@44: temp is 25.51 °C humidity is 30.39 %RH
hs300x@44: temp is 25.51 °C humidity is 30.44 %RH
hs300x@44: temp is 25.51 °C humidity is 30.53 %RH
```

`°C`表示摄氏温度，`%RH`表示相对湿度百分比（Relative humidity）。
