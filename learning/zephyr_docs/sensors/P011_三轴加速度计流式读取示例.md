# 第11章\_三轴加速度计流式读取示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/sensor/accel_stream/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 11.1 概述（Overview）

本示例演示三轴加速度计（3-Axis accelerometer）的使用。

<a id="building-and-running"></a>

## 11.2 构建与运行（Building and Running）

> 译注——命令位置：以下主机构建命令从读者自己的Zephyr源码根目录执行，使用已完成官方入门配置的UCRT64 Bash或Linux Bash终端。代码中的`<board to use>`、`<your_board>`等是待替换占位符；设备树片段属于覆盖文件内容，不是Shell命令。构建成功只说明固件生成，烧录和传感器输出需要实际目标硬件及接线。出现设备未就绪或读取错误时，先核对别名、节点启用状态、驱动配置及总线连接。

示例支持最多10个三轴加速度计。每个加速度计需要设置为`accelN`别名，其中`N`从`0`到`9`。例如：

```devicetree
/ {
      aliases {
                      accel0 = &lis2dh;
              };
      };
```

确认别名已经加入设备树后，构建并运行：

```sh
west build -b <board to use> samples/sensor/accel_stream
west flash
```

> 译注——流式读取的条件：当前实现受`CONFIG_SENSOR_ASYNC_API`控制。开启后通过`sensor_stream()`启动流，配置FIFO满（FIFO full）及FIFO水位（FIFO watermark）触发，消费RTIO完成队列并解码数据；未开启时使用获取／读取轮询路径。`prj.conf`本身没有直接启用该选项，下方输出保留原文，不能凭它判定流式路径已经运行。异步路径的`NUM_SENSORS`固定为1，增加别名还需检查IO设备、完成结果与各设备解码器的对应关系。
