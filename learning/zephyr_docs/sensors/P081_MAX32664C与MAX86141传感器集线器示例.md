# 第81章\_MAX32664C与MAX86141传感器集线器示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/sensor/max32664c/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

本示例通过轮询模式（Polling mode）取得MAX32664C与MAX86141的健康相关数据。

**原文要求：传感器集线器（Sensor hub）固件必须为30.13.31。**

<a id="overview"></a>

## 81.1 概述（Overview）

本示例用于在手腕处测量心率（Heart rate）及血氧饱和度（Blood oxygen saturation），由MAX32664C控制MAX86141传感器。

<a id="requirements"></a>

## 81.2 要求（Requirements）

示例在nRF54L15 DK上通过I2C30接口控制MAX32664传感器。

<a id="references"></a>

## 81.3 参考资料（References）

MAX32664C：[Analog Devices官方产品资料](https://www.analog.com/en/products/max32664.html)。

<a id="building-and-running"></a>

## 81.4 构建与运行（Building and Running）

> 译注——执行位置：主机构建命令从读者自己的Zephyr源码根目录执行；Windows使用UCRT64 Bash，Linux使用原生Bash，先按官方入门说明准备主机工具、模块与目标工具链。原生模拟目标还须满足相应主机环境要求；硬件分支需要目标板、设备树节点和接线。下方命令及日志来自官方文档，本次没有运行模拟器或硬件实验。

项目将传感器数据输出到控制台。目标板需要连接MAX32664C，并另将MAX86141连接到MAX32664C，为算法提供传感器数据。

```sh
# From the root of the zephyr repository
west build -b None samples/sensor/max32664c/
west flash
```

> 译注——原命令缺少目标：原页生成的`-b None`不是有效板名。当前官方测试定义使用`nrf54l15dk/nrf54l15/cpuapp`，随附覆盖文件设置I2C30、复位及MFIO信号，并通过`sensor`别名指向集线器。复现时应选择实际板目标及其连接配置。

<a id="sample-output"></a>

### 81.4.1 示例输出（Sample Output）

```text
[00:00:00.000,000] <inf> sensor: MAX32664C: Initializing...
[00:00:01.600,000] <inf> sensor: MAX32664C: Initialization complete.
[00:00:01.600,000] <inf> sensor: MAX32664C: HR: 75 bpm
[00:00:01.600,100] <inf> sensor: MAX32664C: HR Confidence: 98
[00:00:02.600,000] <inf> sensor: MAX32664C: HR: 76 bpm
[00:00:02.600,100] <inf> sensor: MAX32664C: HR Confidence: 97
[00:00:03.600,000] <inf> sensor: MAX32664C: HR: 74 bpm
[00:00:03.600,100] <inf> sensor: MAX32664C: HR Confidence: 98
```

> 译注——当前程序实际输出：当前主函数选择自动曝光控制（Automatic Exposure Control，AEC）算法运行模式和连续心率监测模式`MAX32664C_ALGO_MODE_CONT_HRM`，每轮休眠1秒，打印心率及其置信度。虽然概述介绍了血氧饱和度，当前这条主流程没有读取血氧通道；上方日志也只展示心率。日志版本与当前程序的初始化文字可能不同，不能据此声称已完成血氧测量。
