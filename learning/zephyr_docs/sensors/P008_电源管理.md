# 第8章\_电源管理

原文：[Power Management](https://docs.zephyrproject.org/latest/hardware/peripherals/sensor/power_management.html)。读取日期：2026-10-12，`latest`。

## 8.1\_通道电源状态与应用取舍

传感器的**电源管理（Power Management，PM）**常常并不简单，因为不同通道可能有不同电源状态。某些设备允许选择低噪声、低功耗，或挂起特定通道；这样可能明显省电，但会改变噪声或采样速度。极低功耗状态下，设备甚至会关闭数字逻辑并丢失内部状态。

因此传感器电源管理通常取决于具体应用。通道状态经常可通过[传感器属性](P003_属性配置.md)修改；整个设备的挂起与恢复，则需设备实现相应能力后，借助电源管理引用计数接口完成。

## 8.2\_运行时引用计数

对于整个设备的挂起和恢复，原文建议采用**设备运行时电源管理（Device Runtime Power Management）**。应用显式调用函数 [`pm_device_runtime_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__device__runtime.html#ga530d4be65757fb2276ab6f631953e045) 取得使用引用，以及函数 [`pm_device_runtime_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__device__runtime.html#ga98daba53a992fb6bd2c2b31cb445844f) 释放引用。

> 译注：这里的 get/put 是设备使用状态的引用操作，不是传感器数据读取函数。应用须检查返回值，并在使用完成后平衡成功取得的引用；具体驱动支持与启用方法见[设备运行时电源管理](https://docs.zephyrproject.org/latest/services/pm/device_runtime.html#pm-device-runtime)。

## 8.3\_流式读取的未来方向

原文提出，未来[读取与解码](P006_读取与解码.md)的流模式有可能自动管理设备电源，因为应用始终通过“在某事件发生时读取”的请求告知驱动其使用需求。

> 译注：这是原文讨论的可能发展方向，不能当成所有当前驱动已具备的自动省电保证。本次没有改变传感器电源状态或执行功耗测试。
