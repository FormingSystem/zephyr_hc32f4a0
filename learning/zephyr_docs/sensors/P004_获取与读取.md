# 第4章\_获取与读取

原文：[Fetch and Get](https://docs.zephyrproject.org/latest/hardware/peripherals/sensor/fetch_and_get.html)。读取日期：2026-10-12，`latest`。

## 4.1\_先获取，再读取缓存值

长期稳定使用的传感器**应用程序编程接口（Application Programming Interface，API）**包括以下函数：

- [`sensor_sample_fetch()`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#gaa75e25d93ee7cac0bf38399f3c006dff)：取得设备的样本。
- [`sensor_sample_fetch_chan()`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#gac16192826432438a15274cf28d66e8a6)：取得指定通道样本。
- [`sensor_channel_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#ga9e0e6c1408d32c52267984bae7cb268d)：从驱动已保存的数据中读取通道值。
- [`sensor_trigger_set()`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#ga7c72aca732e0641612d2f9437c2e41b7)：设置触发事件的回调。

**获取与读取（Fetch and Get）**是两步协作：获取函数阻塞调用它的线程，直到指定的 [`sensor_channel`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#gaaa1b502bc029b10d7b23b0a25ef4e934) 通道或全部通道数据被取得并存入驱动实例的私有数据区；之后逐通道调用读取函数，得到结构体 [`sensor_value`](https://docs.zephyrproject.org/latest/doxygen/html/structsensor__value.html) 表示的最近获取值。

**原文警告：**多个上下文如果没有锁机制，就并发调用这两步，行为未定义。大部分驱动不会在调用内部或两次调用之间替应用提供独占访问。

> 译注：如果另一个线程在两步之间再次获取，读取者可能拿到另一轮样本。需要同一轮数据时，应按驱动约定在应用侧保护整个获取—读取序列，而不只是分别保护某一次函数调用。

## 4.2\_在线程中轮询

软件线程可用这组接口进行**轮询（Polling）**。下面使用设备树别名 `magn0` 对应的磁力计。宏 `DT_ALIAS` 解析别名，宏 `DEVICE_DT_GET` 取得设备对象，函数 `device_is_ready()` 检查驱动是否就绪。

通道枚举 `SENSOR_CHAN_MAGN_X`、`SENSOR_CHAN_MAGN_Y`、`SENSOR_CHAN_MAGN_Z` 对应三个方向。函数 `sensor_value_to_double()` 把数值转换成双精度浮点数，用于格式化打印；函数 `k_sleep()` 配合超时宏 `K_MSEC(500)` 让线程休眠 500 毫秒。

```c
/*
 * Copyright (c) 2016 Intel Corporation
 *
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/kernel.h>
#include <zephyr/device.h>
#include <zephyr/drivers/sensor.h>
#include <zephyr/sys/printk.h>
#include <stdio.h>

int main(void)
{
	const struct device *const dev = DEVICE_DT_GET(DT_ALIAS(magn0));
	struct sensor_value value_x, value_y, value_z;
	int ret;

	if (!device_is_ready(dev)) {
		printk("sensor: device not ready.\n");
		return 0;
	}

	printk("Polling magnetometer data from %s.\n", dev->name);

	while (1) {
		ret = sensor_sample_fetch(dev);
		if (ret) {
			printk("sensor_sample_fetch failed ret %d\n", ret);
			return 0;
		}

		ret = sensor_channel_get(dev, SENSOR_CHAN_MAGN_X, &value_x);
		ret = sensor_channel_get(dev, SENSOR_CHAN_MAGN_Y, &value_y);
		ret = sensor_channel_get(dev, SENSOR_CHAN_MAGN_Z, &value_z);
		printf("( x y z ) = ( %f  %f  %f )\n",
		       sensor_value_to_double(&value_x),
		       sensor_value_to_double(&value_y),
		       sensor_value_to_double(&value_z));

		k_sleep(K_MSEC(500));
	}
	return 0;
}
```

> 译注：原例逐次覆盖 `ret` 而没有检查三次读取的错误。实际应用须在每次成功后才使用对应值，并确保所选 C 库与打印配置支持浮点格式。该片段演示线程轮询，不可搬到中断中执行阻塞获取。本次未构建或采集磁场数据。

## 4.3\_触发器及执行上下文

稳定接口中的**触发器（Trigger）**需要先启用具体设备的 Kconfig 选项。这类配置通常也选择触发处理的运行上下文。应用为所需事件调用 `sensor_trigger_set()`，注册签名符合函数类型 [`sensor_trigger_handler_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__sensor__interface.html#ga890c1fb6d6974aea22a2d08829a75902) 的回调。

**原文注意：**不能从**用户态（User Mode）**线程设置这类触发器，回调也不在用户态上下文运行。

驱动通常提供两种处理位置：[系统工作队列线程](../kernel/P007_工作队列线程.md)或专用线程。BMI160 驱动的 Kconfig 配置项是例子：[`CONFIG_BMI160_TRIGGER_NONE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BMI160_TRIGGER_NONE) 关闭触发器，[`CONFIG_BMI160_TRIGGER_GLOBAL_THREAD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BMI160_TRIGGER_GLOBAL_THREAD) 使用工作队列，[`CONFIG_BMI160_TRIGGER_OWN_THREAD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BMI160_TRIGGER_OWN_THREAD) 使用专用线程。

两种方式的取舍是：

- 专用线程有自己的栈，占用**随机存取存储器（Random Access Memory，RAM）**，这部分只供该处理线程使用。
- 专用线程通常可设置自己的优先级，便于相对其他线程安排触发处理。
- 专用线程不必等待系统工作队列前面其他耗时工作结束，减少这类**队头阻塞（Head-of-Line Blocking）**。

**原文注意：**无论选哪种方式，真实中断发生到回调执行之间都很可能有可变延迟；使用系统工作队列时，队列本身也是可变延迟来源。专用线程不意味着零延迟。

## 4.4\_轻敲计数回调

下面为设备树别名 `accel0` 指向的加速度计注册轻敲事件。结构体 `sensor_trigger` 保存触发配置，枚举 `SENSOR_TRIG_TAP` 表示轻敲，枚举 `SENSOR_CHAN_ACCEL_XYZ` 选择三轴加速度。示例把触发结构放在长期有效的状态对象中，用宏 `CONTAINER_OF` 从回调收到的成员地址找回外层计数状态。Kconfig 配置项 `CONFIG_ARCH` 仅供打印当前架构。

```c
/*
 * Copyright (c) 2024 Intel Corporation
 *
 * SPDX-License-Identifier: Apache-2.0
 */

#include <zephyr/drivers/sensor.h>


const struct device *const accel0 = DEVICE_DT_GET(DT_ALIAS(accel0));

static struct tap_count_state {
	struct sensor_trigger trig;
	uint32_t count;
} tap_count_state = {
	.trig = {
		.chan = SENSOR_CHAN_ACCEL_XYZ,
		.type = SENSOR_TRIG_TAP,
	},
	.count = 0,
};

void tap_handler(const struct device *dev, const struct sensor_trigger *trig)
{
	struct tap_count_state *state = CONTAINER_OF(trig, struct tap_count_state, trig);

	state->count++;

	printk("Tap! Total Taps: %u\n", state->count);
}

int main(void)
{
	int rc;

	printk("Tap Counter Example (%s)\n", CONFIG_ARCH);

	rc = sensor_trigger_set(accel0, &tap_count_state.trig, tap_handler);

	if (rc != 0) {
		printk("Failed to set trigger handler for taps, error %d\n", rc);
		return rc;
	}

	return rc;
}
```

> 译注：该例仍需设备就绪、轻敲功能和对应驱动触发配置支持。回调中的计数对象在此为静态对象；若其他线程也读写计数，需要另行同步。示例保留的版权和许可证注释属于原代码。本次没有注册或触发硬件事件。
