# 第78章\_流量计示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/sensor/flow_meter/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 78.1 概述（Overview）

本示例演示霍尔效应脉冲输出流量计（Hall-effect pulse-output flow meter）驱动的两种用法：

- 轮询累计体积`SENSOR_CHAN_VOLUME`和瞬时流量`SENSOR_CHAN_FLOW_RATE`，后者单位为升／分钟（L/min）。
- 使用`SENSOR_TRIG_THRESHOLD`和`SENSOR_ATTR_UPPER_THRESH`使能一次性体积阈值触发（One-shot volume threshold trigger），当目标体积流过后接收回调。

在`native_sim`上，示例通过`gpio_emul`生成合成脉冲，无需物理传感器；在真实开发板上，必须将霍尔流量计接到板级覆盖文件指定的GPIO。

<a id="building-and-running"></a>

## 78.2 构建与运行（Building and Running）

> 译注——执行位置：主机构建命令从读者自己的Zephyr源码根目录执行；Windows使用UCRT64 Bash，Linux使用原生Bash，先按官方入门说明准备主机工具、模块与目标工具链。原生模拟目标还须满足相应主机环境要求；硬件分支需要目标板、设备树节点和接线。下方命令及日志来自官方文档，本次没有运行模拟器或硬件实验。

在`native_sim`上模拟，无需硬件：

```sh
# From the root of the zephyr repository
west build -b native_sim samples/sensor/flow_meter
west build -t run
```

烧录到ESP32-C6 DevKit，流量计必须接到GPIO4：

```sh
# From the root of the zephyr repository
west build -b esp32c6_devkitc/esp32c6/hpcore samples/sensor/flow_meter
west flash
```

> 译注——阈值与结束条件：当前主程序先设置1 L阈值，再注册回调。阈值按设置时的累计脉冲数建立起点，表示此后新增的体积；触发一次后自动解除。示例收到阈值事件后打印最终累计体积并结束，不会重新使能阈值或无限测量。每次`sensor_sample_fetch()`会重置流量计算窗口，读取顺序和间隔会影响流量值。

<a id="porting-to-another-board"></a>

## 78.3 移植到其他开发板（Porting to Another Board）

在本示例目录下创建`boards/<board>.overlay`，定义名为`flow_meter_0`的节点，让`pulse-gpios`指向与传感器输出相连的GPIO，并将`pulses-per-liter`设为出厂校准值。未启用`CONFIG_GPIO_EMUL`的开发板会自动排除模拟脉冲生成代码。

> 译注——文件与单位：覆盖文件是读者为目标板准备的配置文件，`<board>`不是固定目录名。随附两份覆盖文件均采用450脉冲／升；该值须与真实流量计匹配。体积值按L表示，`sensor_value.val1`是整数升，`val2`是百万分之一升，例如`{1, 500000}`表示1.5 L。

<a id="sample-output"></a>

## 78.4 示例输出（Sample Output）

```text
Flow meter sample
1 L volume threshold armed

volume=0.100000 L  rate=150.000000 L/min
volume=0.200000 L  rate=10.909090 L/min
volume=0.300000 L  rate=10.909090 L/min
volume=0.400000 L  rate=10.909090 L/min
volume=0.500000 L  rate=10.909090 L/min
volume=0.600000 L  rate=10.909090 L/min
volume=0.700000 L  rate=10.909090 L/min
volume=0.800000 L  rate=10.909090 L/min
volume=0.900000 L  rate=10.909090 L/min
volume=1.000000 L  rate=10.909090 L/min

Volume threshold reached! Total volume: 1.000000 L
```

原文说明，第一次数值高于后续流量，是因为初始测量区间从驱动初始化开始，位于首批脉冲之前；该区间比稳定后的500 ms轮询周期短。

> 译注——模拟节拍：当前模拟分支每轮先生成45个脉冲，半周期555 µs，再休眠500 ms。因此完整循环约550 ms，尚未计入读取和输出开销；500 ms不是两次测量之间的全部时间。150 L/min是原日志的首轮结果，并非当前环境必然复现的固定数值。
