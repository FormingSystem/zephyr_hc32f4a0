# 第50章\_BME280温湿度与气压传感器示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/sensor/bme280/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 50.1 概述（Overview）

本示例说明如何使用Zephyr[传感器（Sensors）](P001_传感器驱动概览.md#sensor)API驱动访问[Bosch BME280](https://www.bosch-sensortec.com/products/environmental-sensors/humidity-sensors-bme280/)环境传感器（Environmental sensor）。

示例周期性地从系统中发现的第一个可用BME280设备读取温度（Temperature）、压力（Pressure）和湿度（Humidity）。传感器以轮询模式（Polling mode）访问，不使用中断触发。

> 译注——当前读取接口：原文的“第一个”不能理解为按总线地址扫描或轮流读取全部设备。当前源码通过`DEVICE_DT_GET_ANY(bosch_bme280)`选择一个已启用设备；使用`SENSOR_DT_READ_IODEV`、实时输入输出（Real-Time I/O，RTIO）上下文及`sensor_read()`取得编码数据，再通过解码器（Decoder）分别解出温度、压力和湿度，最后休眠1秒。`prj.conf`启用了`CONFIG_SENSOR_ASYNC_API`；周期发起读取与使用新的读取／解码接口可以同时成立，不应根据旧日志推断它仍只用Fetch/Get接口。

<a id="building-and-running"></a>

## 50.2 构建与运行（Building and Running）

> 译注——执行位置：主机构建命令从读者自己的Zephyr源码根目录执行，终端及工具链按官方入门说明准备。读取真实传感器还需要对应目标板、设备树节点和接线；下面的命令与日志来自官方文档，本次没有执行硬件实验。

示例支持通过I2C或SPI连接的BME280。配置通过[设备树（Devicetree）](../devicetree/P013_设备树文档入口.md#dt-guide)完成：设备树必须有已启用的节点，包含`compatible = "bosch,bme280";`。绑定信息见[bosch,bme280](https://docs.zephyrproject.org/latest/build/dts/api/compatibles/bosch,bme280.html#std-dtcompatible-bosch-bme280)，下面给出常见配置。

如果开发板没有内置传感器，先按[BME280数据手册](https://www.bosch-sensortec.com/media/boschsensortec/downloads/datasheets/bst-bme280-ds002.pdf)第38页的连接图接线。

<a id="boards-with-a-built-in-bme280"></a>

### 50.2.1 内置BME280的开发板（Boards with a built-in BME280）

开发板的默认设备树可能已经配置BME280节点。确认该节点具有`status = "okay";`，然后构建并运行：

```sh
# From the root of the zephyr repository
west build -b adafruit_feather_m0_basic_proto samples/sensor/bme280
west flash
```

<a id="bme280-via-arduino-spi-pins"></a>

### 50.2.2 通过Arduino SPI引脚连接BME280（BME280 via Arduino SPI pins）

如果传感器连接到Arduino排针上的SPI外设，使用以下命令构建和烧录：

```sh
# From the root of the zephyr repository
west build -b None samples/sensor/bme280 -- -DDTC_OVERLAY_FILE=arduino_spi.overlay
west flash
```

设备树覆盖文件[samples/sensor/bme280/arduino_spi.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/sensor/bme280/arduino_spi.overlay)适用于具有正确配置、引脚兼容Arduino的SPI外设的开发板。

> 译注——板名占位：上方`-b None`是原页面未填入具体板目标的结果，`None`不是可直接构建的目标。使用时应替换为实际板名，且该板必须提供覆盖文件引用的`arduino_spi`和`arduino_header`等节点。

<a id="bme280-via-arduino-i2c-pins"></a>

### 50.2.3 通过Arduino I2C引脚连接BME280（BME280 via Arduino I2C pins）

如果传感器连接到Arduino排针上的I2C外设，使用以下命令构建和烧录：

```sh
# From the root of the zephyr repository
west build -b None samples/sensor/bme280 -- -DDTC_OVERLAY_FILE=arduino_i2c.overlay
west flash
```

设备树覆盖文件[samples/sensor/bme280/arduino_i2c.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/sensor/bme280/arduino_i2c.overlay)适用于具有正确配置、引脚兼容Arduino的I2C外设的开发板。

> 译注——板名与地址：这里同样必须用实际板目标替换`None`。当前覆盖文件引用`arduino_i2c`并假设设备地址为`0x77`；应对照实际器件的地址选择接线，不能把示例地址当作所有模块的固定值。

<a id="bme280-via-raspberry-pi-pico"></a>

### 50.2.4 通过Raspberry Pi Pico连接BME280（BME280 via Raspberry Pi Pico）

[Raspberry Pi Pico](https://docs.zephyrproject.org/latest/boards/raspberrypi/rpi_pico/doc/index.html#rpi_pico)内置`spi0`设备默认分配到GPIO16—GPIO19。将传感器连接到这些信号后，构建和烧录：

```sh
# From the root of the zephyr repository
west build -b rpi_pico samples/sensor/bme280
west flash
```

另一种方式是使用可编程输入输出（Programmable I/O，PIO）实现SPI设备。设备树覆盖文件[samples/sensor/bme280/rpi_pico_spi_pio.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/sensor/bme280/rpi_pico_spi_pio.overlay)演示通过PIO SPI将传感器连接到可自行选择的GPIO引脚。构建和烧录：

```sh
# From the root of the zephyr repository
west build -b rpi_pico samples/sensor/bme280 -- -DDTC_OVERLAY_FILE=rpi_pico_spi_pio.overlay
west flash
```

注意：`sdi-gpios`、`sdo-gpios`和`clk-gpios`必须通过引脚控制（Pin control，pinctrl）分配给选定的PIO设备；`cs-gpios`不应这样分配。片选（Chip select）由SPI上下文控制，必须作为普通GPIO引脚工作，而不交给PIO控制。

> 译注——当前PIO覆盖文件：示例选择GPIO12作为输入、GPIO14作为时钟、GPIO15作为输出，GPIO13作为普通GPIO片选。它们是该覆盖文件的具体选择，其他SPI配置应按相应设备树核对引脚。

<a id="board-specific-overlays"></a>

### 50.2.5 板级覆盖文件（Board-specific overlays）

如果开发板设备树还没有BME280节点，可以在示例的`boards`目录中新建板级设备树覆盖文件来添加；已有覆盖文件可作为参考。

构建系统在选择相应开发板时默认使用这些文件，因此构建和运行时不需要再设置`DTC_OVERLAY_FILE`。

例如，为[Feather M0 Basic Proto](https://docs.zephyrproject.org/latest/boards/adafruit/feather_m0_basic_proto/doc/index.html#adafruit_feather_m0_basic_proto)构建时，可使用本示例提供的[samples/sensor/bme280/boards/adafruit_feather_m0_basic_proto.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/sensor/bme280/boards/adafruit_feather_m0_basic_proto.overlay)：

```sh
# From the root of the zephyr repository
west build -b adafruit_feather_m0_basic_proto samples/sensor/bme280
west flash
```

<a id="sample-output"></a>

### 50.2.6 示例输出（Sample Output）

示例向串口控制台（Serial console）输出数据，同时记录BME280设备驱动消息。连接串口控制台的方法见所用开发板的文档。

以下是默认应用设置下的输出示例，假设只有一个BME280连接到标准Arduino I2C引脚：

```text
[00:00:00.379,760] <dbg> BME280.bme280_init: initializing "BME280_SPI" on bus "SPI_3"
[00:00:00.379,821] <dbg> BME280.bme280_init: bad chip id 0xff
[00:00:00.379,821] <dbg> BME280.bme280_init: initializing "BME280_I2C" on bus "I2C_0"
[00:00:00.380,340] <dbg> BME280.bme280_init: ID OK
[00:00:00.385,559] <dbg> BME280.bme280_init: BME280_I2C OK
*** Booting Zephyr OS build zephyr-v2.4.0-2940-gbb732ada394f  ***
Found device BME280_I2C, getting sensor data
temp: 20.260000; press: 99.789019; humidity: 46.458984
temp: 20.260000; press: 99.789480; humidity: 46.424804
temp: 20.250000; press: 99.789246; humidity: 46.423828
```

以下同样采用默认应用设置，但假设有两个不同BME280，分别连接到标准Arduino I2C和SPI引脚：

```text
[00:00:00.377,777] <dbg> BME280.bme280_init: initializing "BME280_SPI" on bus "SPI_3"
[00:00:00.377,838] <dbg> BME280.bme280_init: ID OK
[00:00:00.379,608] <dbg> BME280.bme280_init: BME280_SPI OK
[00:00:00.379,638] <dbg> BME280.bme280_init: initializing "BME280_I2C" on bus "I2C_0"
[00:00:00.380,126] <dbg> BME280.bme280_init: ID OK
[00:00:00.385,345] <dbg> BME280.bme280_init: BME280_I2C OK
*** Booting Zephyr OS build zephyr-v2.4.0-2940-gbb732ada394f  ***
Found device BME280_I2C, getting sensor data
temp: 20.150000; press: 99.857675; humidity: 46.447265
temp: 20.150000; press: 99.859121; humidity: 46.458984
temp: 20.150000; press: 99.859234; humidity: 46.469726
```

两种情况下，驱动日志都包含`BME280_I2C OK`；没有连接SPI器件时，则不会出现`BME280_SPI OK`。

> 译注——旧日志边界：这两段日志属于原页给出的旧版本输出，保留其中未连接SPI器件时的芯片ID错误。当前示例只选取一个设备，并不会因为驱动初始化了两个设备，就自动交替输出两个传感器的全部数据。
