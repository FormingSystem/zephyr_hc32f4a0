### `K_OOPS`

```c
#define K_OOPS ( expr)
```

```c

```

展开值（Value）：

```c
do { \
```

此宏可用于触发内核 oops，从而终止调用线程。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `expr` | 待求值的表达式。表达式为 true 时触发 oops。 |

<a id="gacd20e09824dc9124f339f06b49ca6f39"></a>

### `K_SYSCALL_MEMORY`

```c
#define K_SYSCALL_MEMORY ( ptr, size, write )
```

```c
#include <zephyr/internal/syscall_handler.h>
```

展开值（Value）：

```c
K_SYSCALL_VERIFY_MSG(K_SYSCALL_MEMORY_SIZE_CHECK(ptr, size) \
                     && !Z_DETECT_POINTER_OVERFLOW(ptr, size) \
                     && (arch_buffer_validate((void *)(ptr), (size), (write)) \
                     == 0), \
                     "Memory region %p (size %zu) %s access denied", \
                     (void *)(ptr), (size_t)(size), \
                     (write) ? "write" : "read")
```

在运行时检查用户线程是否具有某内存区域的读和／或写权限。

检查指定内存区域在 CPU 处于用户模式时，是否可由当前运行线程读取和／或写入。防止用户空间让内核读取和／或修改该线程无权访问的内存，也防止传入解引用后会使内核崩溃或触发缺页异常（Page Fault）的无效指针。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `ptr` | 待检查的内存区域。 |
| `size` | 内存区域大小。 |
| `write` | 线程是否应能写入此内存，而不只是读取。 |

返回（Returns）：成功返回 false，失败返回 true。

说明（Note）：这是内部 API。除非正在扩展 Zephyr 源码树中的功能，否则不要使用。

<a id="gaac0e4ded775b724a809cdb9bf17803a8"></a>

### `K_SYSCALL_MEMORY_ARRAY`

```c
#define K_SYSCALL_MEMORY_ARRAY ( ptr, nmemb, size, write )
```

```c
#include <zephyr/internal/syscall_handler.h>
```

展开值（Value）：

```c
({ \
        size_t product; \
        K_SYSCALL_VERIFY_MSG(!size_mul_overflow((size_t)(nmemb), \
                                                (size_t)(size), \
                                                &product), \
                             "%zux%zu array is too large", \
                             (size_t)(nmemb), (size_t)(size)) ||  \
                K_SYSCALL_MEMORY(ptr, product, write); \
})
```

验证用户线程是否具有指定大小数组的读和／或写权限。

当内存区域以元素数量和每个元素的大小表示时使用，能够处理计算数组总范围时的溢出问题。其他情况参阅 `K_SYSCALL_MEMORY()`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `ptr` | 待检查的内存区域。 |
| `nmemb` | 数组中的元素数量。 |
| `size` | 每个数组元素的大小。 |
| `write` | 线程是否应能写入此内存，而不只是读取。 |

返回（Returns）：成功返回 false，失败返回 true。

说明（Note）：这是内部 API。除非正在扩展 Zephyr 源码树中的功能，否则不要使用。


声明属性：`inline`、`static`。

```c

```

检查内核对象是否通过动态方式分配。

动态分配的内核对象的生命周期由其权限位掩码（Permission Bitmask）决定：最后一个拥有权限的线程释放该权限或终止时，对象会立即释放，随后该内存可能被无关内核对象复用。内核自身保存的指针不计入该位掩码，因此不会延长对象生命周期。

| 名称／方向 | 说明 |

### `k_usermode_string_nlen()`

声明属性：`inline`、`static`。


## 1.4\_源码定位与版本边界

源码定位：[include/zephyr/internal/syscall_handler.h](../../../include/zephyr/internal/syscall_handler.h)、[kernel/userspace/userspace.c](../../../kernel/userspace/userspace.c)、[kernel/userspace/userspace_handler.c](../../../kernel/userspace/userspace_handler.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。存在于本仓库的源码使用相对链接；尚未纳入本仓库的上游文件仅链接官方来源，不创建同名占位源码。

> 译注——源码核对：本组系统调用处理接口属于内部API（Internal API），主要服务于Zephyr源码树内的验证函数（Verifier）。k_is_user_context判断CPU当前权限，k_is_in_user_syscall判断是否正在处理用户线程发起的系统调用；后者在特权处理代码中仍可为true，但在ISR中返回false。两者不能互换。

> 译注——源码核对：K_SYSCALL_VERIFY接受应为真的条件，却在条件失败时返回true。多数K_SYSCALL_*检查同样返回“是否失败”，K_OOPS则在传入表达式为true时触发错误。不要把检查结果当作“true即允许访问”。本页另有K_SYSCALL_MEMORY_SIZE_CHECK成功返回true，应按各自契约理解。

> 译注——源码核对：内存区域检查结合地址范围、指针溢出和架构访问权限；数组宏先用size_mul_overflow检查元素数量与大小之积，再检查得到的范围。宏参数可能被多次求值，应先保存带副作用表达式的结果。权限验证不会让用户缓冲区内容变为不可变，后续需要稳定内容时仍须复制并验证实际使用的数据。

> 译注——源码核对：K_SYSCALL_OBJ、OBJ_INIT和OBJ_NEVER_INIT分别要求已初始化、不检查初始化状态和未初始化。K_SYSCALL_OBJ_STATIC进一步拒绝动态对象；内核保存裸指针不会自动增加对象权限引用，最后一个拥有权限的线程退出或释放权限后，动态对象可能被回收。检查时有效不等于未来仍有效。

> 译注——源码核对：K_SYSCALL_DRIVER_OP直接访问设备的api及操作指针，不能单独替代设备对象类型与权限验证。K_SYSCALL_SPECIFIC_DRIVER先检查对象，再比较API结构地址；扩展驱动系统调用时需要保持相应校验顺序。

> 译注——源码核对：k_usermode_string_nlen可处理探测字符串引起的保护故障，但成功测长不等于用户线程拥有读权限。读取err后才能使用长度，并须另做权限检查；复制C字符串时还要包含终止字节并检查长度加一溢出。当前复制实现在复制后显式设置终止字符，以应对测长期间源字符串发生变化。

> 译注——源码核对：数据复制接口k_usermode_from_copy／to_copy当前实现失败返回正的EFAULT；k_usermode_string_copy还可能返回正的EINVAL。它们不是普遍采用的负errno约定。分配复制接口失败返回NULL，成功取得的资源池内存由调用者以后用k_free释放。

> 译注——源码核对：原文k_is_in_user_syscall的性能说明写为“调用系统调用时会跳过检查”，缺少调用来源限定。正文保留原意；本次相邻源码注释明确是监督模式调用直接进入实现，用户模式调用则经过生成的z_mrsh与z_vrfy路径。不要据原句取消用户参数校验。
