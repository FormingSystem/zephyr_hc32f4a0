## 3.2\_可见注释译文（Comments）

1. 版权与许可证：Copyright (c) 2017, Intel Corporation；SPDX-License-Identifier: Apache-2.0。原始法律声明保留。

2. 系统调用声明宏（System Call Declaration Macros）：这些宏在公共头文件中声明系统调用，生成的内联函数按编译上下文选择实现。仅内核代码或未启用CONFIG_USERSPACE时直接调用实现；仅用户代码时编组参数并提升权限；混合或未确定上下文时执行运行时检查。所有系统调用都需要遵循命名约定的验证函数和实现函数：以k_foo为例，z_vrfy_k_foo具有与被包装调用相同的类型签名，验证用户空间参数后调用实现；更多信息见相应类型定义的说明。z_impl_k_foo才是系统调用的实际实现。

3. 若系统调用函数必须陷入内核，则返回true；通常可在编译时决定。

4. _ASMLANGUAGE条件分支结束。

## 3.4\_源码跟踪译注

> 译注——z_syscall_trap根据CONFIG_USERSPACE、__ZEPHYR_SUPERVISOR__与__ZEPHYR_USER__选择直接调用或陷入内核（Trap）；混合上下文才调用架构权限检测。k_is_user_context仅报告当前权限，不会切换权限，也不会自动插入原文要求的内存屏障。

> 译注——用户调用路径的z_mrsh负责参数编组（Marshalling），z_vrfy负责验证，z_impl负责实际实现。监督模式直接进入实现时可能跳过验证函数，因此不能把只在z_vrfy中执行的检查视为所有内核内部调用都已完成的检查。

> 译注——头文件包含的syscall_list.h和具体系统调用包装由构建流程生成；不能因源文件中存在include就要求读者在源码树手写这些生成文件。本页只翻译官方参考与可见代码，不创建系统调用或更改权限配置。

头文件定位：[include/zephyr/syscall.h](../../../include/zephyr/syscall.h)，关联实现／接口：[kernel/userspace/userspace_handler.c](../../../kernel/userspace/userspace_handler.c)；[官方原始头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/syscall.h)与[官方关联文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/userspace/userspace_handler.c)的摘要见来源记录。去掉注释和展示空白后，本页代码与本次读取的原始头文件一致，不能推广到以后滚动更新的main或任意本地版本。
