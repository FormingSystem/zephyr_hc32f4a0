# 第5章\_引用最小堆公共接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__min__heap__ref__apis.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：先读[最小堆指南](../kernel/P055_最小堆.md)，再对照值堆与引用堆的公共API、结构和头文件。源码跟踪译注分别说明复制语义、句柄位置及容量限制。

引用式、基于句柄的最小堆（Reference / Handle-based Min-heap）实现。

<a id="details"></a>

引用式、基于句柄的最小堆实现。最小堆是基于二叉树的数据结构，最小元素始终位于根节点。与按值存储的最小堆不同，此变体存储指向调用者所拥有节点的指针，每个节点嵌入min_heap_handle。因此插入无需复制节点（Zero-copy），且可通过句柄以O(log n)时间移除指定节点，无需搜索。

### `MIN_HEAP_REF_FOREACH`

```c
#define MIN_HEAP_REF_FOREACH ( __heap, __handle )
```

```c
#include <zephyr/sys/min_heap_ref.h>
```

展开值（Value）：

```c
for (size_t __mh_i = 0;                                                        \
     (__mh_i < (__heap)->size) && ((__handle) = (__heap)->storage[__mh_i], true); \
     __mh_i++)
```

遍历最小堆中当前的每个元素。

按内部存储数组顺序，即广度优先遍历（Breadth-first Search，BFS）的层序访问所有元素。这不是排好序的顺序。

用法：

原始示例（Example）：

```c
struct min_heap_handle *h;
MIN_HEAP_REF_FOREACH(&heap, h) {
   struct data *t = CONTAINER_OF(h, struct data, handle);
}
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `__heap` | 指向最小堆的指针。 |
| `__handle` | min_heap_handle指针。 |

> 译注——源码核对：按内部数组的广度优先层序（BFS）访问，不能用来得到按比较器排列的序列，也不支持在遍历中任意修改堆。

<a id="ga3a1a84b467df02fd4cf0129d715fd3fd"></a>

### `MIN_HEAP_REF_FOREACH_CONTAINER`

```c
#define MIN_HEAP_REF_FOREACH_CONTAINER ( __heap, __cn, __field )
```

```c
#include <zephyr/sys/min_heap_ref.h>
```

展开值（Value）：

```c
for (size_t __mh_i = 0;                                                        \
     (__mh_i < (__heap)->size) &&                                              \
     ((__cn) = CONTAINER_OF((__heap)->storage[__mh_i], __typeof__(*(__cn)), __field), \
     true);                                                                    \
     __mh_i++)
```

遍历最小堆中的每个元素，并取得嵌入句柄的容器结构（Container Struct）。

用法：

原始示例（Example）：

```c
struct data *t;
MIN_HEAP_REF_FOREACH_CONTAINER(&heap, t, handle) {
   printk("key=%d\n", t->key);
}
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `__heap` | 指向最小堆的指针。 |
| `__cn` | 调用者声明的容器结构类型指针。 |
| `__field` | 容器中min_heap_handle成员的名称。 |

> 译注——源码核对：__cn必须是调用者声明的容器指针变量，宏通过其指向类型与__field成员反算容器地址；不是传入类型名称，也不进行运行时类型检查。

<a id="gaee8c80f86d707606a8dd294449779a03"></a>

### `min_heap_ref_push()`

```c
int min_heap_ref_push ( struct min_heap_ref * heap, struct min_heap_handle * handle )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/min_heap_ref.h>
```

向最小堆插入句柄。

向最小堆添加新句柄，并在必要时将其向上移动，以恢复堆顺序。若最小堆已达到容量上限，插入操作失败。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `heap` | 指向最小堆的指针。 |
| `handle` | 指向待插入句柄的指针。 |

**返回（Returns）**：成功时返回0；堆已满时返回-1。

> 译注——源码核对：要求heap、handle有效且handle->idx==0。正常满容量分支返回-1，与值堆的-ENOMEM不同；成功保存指针、设置从1开始的位置、增加size并向上调整。位置范围：idx是uint16_t，非零位置最多表示65535个在堆元素；capacity虽然是size_t，也不能绕过该限制。push先断言size<UINT16_MAX，再判断容量是否已满；达到65535后再次push可能先触发断言，不能笼统承诺所有满堆情况都返回-1。关闭断言也不会扩展索引范围。

```c
#include <zephyr/sys/min_heap_ref.h>
```

通过句柄从最小堆中移除指定元素。

句柄的idx字段以O(1)时间给出位置，无需线性扫描。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `heap` | 指向最小堆的指针。 |
| `handle` | 要移除元素的句柄；该元素当前必须位于堆中。 |

**返回（Returns）**：成功时返回true，否则返回false。

> 译注——源码核对：成员资格：remove只检查idx非零且不大于size，没有核对storage[idx-1]是否就是传入句柄，也没有记录所属堆。必须传入当前堆内的有效句柄；另一堆的句柄或手工伪造idx可能误删其他节点并破坏结构。成功移除后该句柄idx清0，节点本身不会被释放。

<a id="ga506c5f23a63e7f72af65fc4f8c7ca304"></a>

### `min_heap_ref_swap()`

```c
void min_heap_ref_swap ( struct min_heap_ref * heap, size_t a, size_t b )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/min_heap_ref.h>
```

交换堆存储中的两个元素，同时更新其idx字段。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `heap` | 指向最小堆的指针。 |
| `a` | 第一个元素的下标。 |
| `b` | 第二个元素的下标。 |

> 译注——源码核对：仅交换两个有效数组位置并同步句柄idx=a+1／b+1，不验证下标或修复整个堆的排序性质。此辅助操作需满足已有结构和生命周期前提。

## 5.7\_源码定位与版本边界

两种实现从[本册大纲](大纲.md)对应到公共API、结构及源码。相对定位：[值堆头文件](../../../include/zephyr/sys/min_heap.h)、[值堆实现](../../../lib/min_heap/min_heap.c)、[引用堆头文件](../../../include/zephyr/sys/min_heap_ref.h)。

配置依据：[库构建入口](../../../lib/CMakeLists.txt)、[最小堆构建规则](../../../lib/min_heap/CMakeLists.txt)与[Kconfig定义](../../../lib/min_heap/Kconfig)。本次说明依据[官方值堆实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/min_heap/min_heap.c)、[官方引用堆头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/min_heap_ref.h)及[官方构建入口](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/CMakeLists.txt)，摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：数据结构与顺序：这里的最小堆（Min-heap）用于排序和优先队列，不是动态内存分配器。比较器（Comparator）返回负数、零、正数表达小于、等于、大于；最高优先级对应比较关系下的最小元素。相等键的先入先出顺序不受保证，内部数组也不是全局排序结果。

> 译注——源码核对：同步与生命周期：两种实现均不自行加锁或等待，不发送通知。调用者应保护并发访问和对象生命周期；遍历期间修改堆可能改变数组位置及size，不能按原顺序继续访问或删除。直接修改影响比较结果的键也可能破坏堆性质。

> 译注——源码核对：接口边界：值堆复制elem_size字节，使用从0开始的当前数组下标删除；引用堆保存调用者对象的句柄指针，句柄idx从1开始，0表示未入堆。两者的容量、删除参数、返回值和所有权说明不能互换。

> 译注——源码核对：句柄与所有权：引用堆（Reference Min-heap）只保存min_heap_handle指针，节点始终由调用者拥有。新句柄应初始化idx=0，入堆后其地址必须保持稳定；同一句柄不能重复入堆或同时加入两个堆。需要多重成员资格时，应使用各自独立的句柄。

> 译注——源码核对：位置范围：idx是uint16_t，非零位置最多表示65535个在堆元素；capacity虽然是size_t，也不能绕过该限制。push先断言size<UINT16_MAX，再判断容量是否已满；达到65535后再次push可能先触发断言，不能笼统承诺所有满堆情况都返回-1。关闭断言也不会扩展索引范围。

> 译注——源码核对：成员资格：remove只检查idx非零且不大于size，没有核对storage[idx-1]是否就是传入句柄，也没有记录所属堆。必须传入当前堆内的有效句柄；另一堆的句柄或手工伪造idx可能误删其他节点并破坏结构。成功移除后该句柄idx清0，节点本身不会被释放。

> 译注——源码核对：初始化与构建：引用堆由min_heap_ref.h内联实现，官方指南说明不要求额外Kconfig配置。init断言heap、storage和cmp非空，但只重设堆字段和size，不遍历旧节点清除idx；不能把重置非空堆当成逐节点移除。

本次验证范围为文档与源码对照，未构建或运行最小堆及实板实验。
