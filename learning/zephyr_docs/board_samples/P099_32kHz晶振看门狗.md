# 第99章\_XTAL32K 看门狗定时器（XTAL32K Watchdog Timer，WDT）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/boards/espressif/xt_wdt/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/boards/espressif/xt_wdt/README.rst/..)

<a id="overview"></a>

## 99.1 概述（Overview）

本示例展示 XTAL32K 看门狗定时器（XT WDT）外设的用法。要正确运行，需要在开发板的 XTAL_32K_P 和 XTAL_32K_N 引脚之间连接外部晶体振荡器，原文将其频率写为 32.728 Hz。

> 译注——频率勘误：原文的 32.728 Hz 与同页日志 32768 Hz 不一致。本次 Zephyr 的 ESP32-C3／S2／S3 时钟绑定均将 XTAL32K 定义为 32768 Hz，即 32.768 kHz；不应按原文错写的数值选晶体。

应用会提示移除晶体，以模拟晶体故障并触发 XT WDT 中断。硬件内部会把 RTC SLOW 时钟源从 ESP32_RTC_SLOW_CLK_SRC_XTAL32K 切换为 ESP32_RTC_SLOW_CLK_SRC_RC_SLOW，原文给出的频率为 C3 和 S3 使用 136 kHz，S2 使用 9 kHz。

> 译注——S2 频率勘误：原文的 S2 9 kHz 与当前 esp32s2_clock.h 中 90000 Hz 不符。[Espressif 的 ESP32-S2 时钟树说明](https://docs.espressif.com/projects/esp-idf/en/stable/esp32s2/api-reference/peripherals/clk_tree.html)也将 RC_SLOW 描述为约 90 kHz。C3／S3 的本次绑定值为 136000 Hz；这些是该实现使用的频率值，不是本次测量结果。

<a id="supported-socs"></a>

## 99.2 支持的 SoC（Supported SoCs）

以下 SoC 支持 XT WDT 外设：

- ESP32-C3

- ESP32-S2

- ESP32-S3

<a id="building-and-running"></a>

## 99.3 构建与运行（Building and Running）

> 译注——执行前提：下面主机命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行；先按[入门指南](../getting_started/大纲.md)准备工具、模块、工具链与目标板。west flash 会下载固件；串口输出块是原文示例，提示符和日志不作为命令执行。本批未构建、烧录或运行硬件实验。

确保开发板已通过 USB 端口连接，且外部晶体已连接到 XTAL_32K_P 和 XTAL_32K_N 引脚。

> 译注——事件流程：app.overlay 选择 XTAL32K 为慢时钟源并启用 xt_wdt。驱动中断处理函数把 RTC SLOW 配置为 RC_SLOW，然后调用用户回调；回调释放信号量，主线程才从 K_FOREVER 等待中恢复并打印新时钟频率。这不是应用卡死时定时喂狗的例子；该驱动的 feed() 返回 -ENOSYS。

```text
west build -p -b esp32s3_devkitc/esp32s3/procpu samples/boards/espressif/xt_wdt
west flash
```

如果使用其他受支持的 Espressif 开发板，请将上述命令的参数替换为相应板名，例如 `esp32s2_devkitc`。

> 译注——失败判断：main.c 未检查 wdt_install_timeout()、wdt_setup() 和时钟查询的返回值。配置失败或晶振失效事件未发生时，程序可能一直等待，不能把最后一条提示当作完成验证。本次仅核对说明，没有执行移除晶体或任何硬件故障注入。
