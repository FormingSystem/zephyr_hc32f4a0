## 108.1 概述（Overview）

闪存加密用于加密 ESP32 片外闪存的内容。启用后，固件先以明文（Plaintext）烧录，再在首次启动时原地加密。因此，仅对闪存进行物理读取，不足以恢复其中的大部分内容。这是一项可在 MCUboot 构建过程中启用的硬件功能，在 MCUboot 原有功能之外提供额外的安全措施。

可使用以下闪存加密模式：

- 开发模式（Development Mode）

  > 建议仅在开发阶段使用，因为它不能防止对加密闪存内容的修改和读取。

- 发布模式（Release Mode）

  > 建议用于制造和生产，以防通过物理读取获取加密闪存内容。原文接着写道：“选择发布模式时……”

> 译注——原文完整性：发布模式段落在 When release mode is selected.. 处中断，没有后续条件或操作。这里明确保留这处缺文，不把其他版本的烧录步骤冒充原文续写；具体模式限制按本页链接的 Espressif／MCUboot 说明与实际芯片版本核对。

<a id="setup"></a>

## 108.3 准备工作（Setup）

仅靠本示例代码不足以启用闪存加密，因为它只展示加密和解密后的数据。需要预先配置 MCUboot 引导程序以启用该功能；运行前应先按照 [MCUboot 说明（MCUBoot Readme）](https://docs.mcuboot.com/readme-espressif)完成准备。

> 译注——引导程序前提：prj.conf 的 CONFIG_BOOTLOADER_MCUBOOT=y 让应用采用 MCUboot 相关布局，不等于本条 west build 已经创建并启用了闪存加密引导程序。MCUboot 官方移植说明把硬件闪存加密与其自身的加密镜像功能分开说明；不能把镜像传输加密等同于片外执行存储已加密。

警告（Warning）

启用闪存加密时，可以使用设备生成的密钥，该密钥保持未知且不可读；也可以使用主机生成的密钥，此时密钥所有者负责将其作为 .bin 文件私密且安全地保存。在设备上烧写电子熔丝（eFuse）启用闪存加密后，读写操作在运行时进行解密和加密。

> 译注——不可逆状态与接口：eFuse 相关配置可能在首次启动后不可回退，MCUboot 官方说明对此有明确提示。本示例没有烧写密钥或eFuse的操作代码；源码的常规 flash_read／flash_write 根据实际加密状态选择接口，而 esp_flash_read 原始读取仍能返回密文。因此原文“读写运行时加解密”不表示所有读取 API 都自动解密。

## 108.5 构建与运行（Building and Running）

> 译注——执行前提：主机命令在读者自己的 Zephyr 源码根目录，用 UCRT64 Bash 或 Linux Bash 执行；先按[入门指南](../getting_started/大纲.md)准备模块、工具链和目标板。网络示例须按本文准备对端、信道与路由器；加密示例须先满足引导程序前提。设备 Shell 命令与主机命令分别执行，日志仅为原文预期输出。本次未构建、烧录、配网、改写密钥或eFuse。

确保开发板已通过 USB 端口连接。

```text
west build -b esp32_devkitc/esp32/procpu samples/boards/espressif/flash_encryption
west flash
```

### 108.5.1 示例输出（Sample Output）

要查看本示例输出，可运行 `west espressif monitor`，或使用其他串口控制台程序，例如 minicom、putty、screen。本例使用 `west espressif monitor`，它会自动检测位于 `/dev/ttyUSB0` 的串口：

```text
$ west espressif monitor
```

示例将已知缓冲区写入 DTS 文件定义的存储区域，随后使用不解密的原始读取方式转储同一区域的 32 字节。此时读到的是加密内容；原文据此说明可防护对片外存储器的直接读取。最后通过适当的 spi_flash 调用再次读取，得到预期解密后的内容。

> 译注——写入范围与判据：本次 main.c 擦除 storage_partition 起点的 4096 字节，再写入 32 字节 0x00～0x1f；随后分别用 esp_flash_read 和 flash_read 转储。它没有检查这些操作的返回值，也没有自动比较解密结果，日志标签 Encrypted 本身不是加密已启用的证据；还需核对实际状态及读写结果。
