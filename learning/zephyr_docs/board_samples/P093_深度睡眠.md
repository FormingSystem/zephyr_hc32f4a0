# 第93章\_深度睡眠（Deep Sleep）

<a id="overview"></a>

## 93.1 概述（Overview）

ESP32 系列的深度睡眠（Deep sleep）是一种节电模式，会关闭 CPU、大部分 RAM，以及由 APB_CLK 提供时钟的数字外设的电源。

本示例展示如何设置唤醒源（Wake-up source）、触发深度睡眠，再利用预先配置的唤醒源让系统重新运行。

> 译注——恢复方式：这里最终调用 sys_poweroff()；唤醒后重新进入启动流程，不是在调用处继续执行。CONFIG_RETAINED_MEM 启用时，示例在保持内存（Retained memory）中保存标记和计数，用于跨深睡眠恢复；不能据此认为普通 RAM 都会保持。

本示例演示以下唤醒源：

1. `Timer`：实时时钟（Real-Time Clock，RTC）定时器，可编程为在预设时间后触发唤醒。本示例会每隔 20 秒触发一次唤醒。

2. `EXT1`：外部唤醒 1（External wake-up 1）关联多个 RTC GPIO。本示例使用 GPIO2 和 GPIO4，只要其中任意一个引脚为高电平（HIGH），就会触发唤醒。

3. `GPIO`：只有部分 Espressif 片上系统（System on Chip，SoC）支持。以 ESP32-C3 为例，GPIO0～5 可以用作唤醒源。

目标 SoC 会不断重复以下过程：启用 Timer 唤醒源，深度睡眠 CONFIG_EXAMPLE_WAKEUP_TIME_SEC 秒，然后唤醒。

> 译注——间隔差异：原文前面写 20 秒，输出却写 5s。本次上游 Kconfig 的 EXAMPLE_WAKEUP_TIME_SEC 默认值为 5，main.c 使用该值配置 RTC 定时器；应以实际构建配置为准。它是睡眠定时器间隔，不是包含启动、日志及一秒忙等在内的完整循环周期。

<a id="requirements"></a>

## 93.2 硬件与配置要求（Requirements）

如果仅使用 `Timer` 作为唤醒源，本示例应可在常见的 [ESP32-DevKitC](https://docs.zephyrproject.org/latest/boards/espressif/esp32_devkitc/doc/index.html#esp32_devkitc) 开发板上运行，无需额外硬件。

但是，启用 EXT1 时，必须为 GPIO2 和 GPIO4 配置下拉（Pull-down），避免引脚悬空。通常通过设备树（Devicetree）配置，例如使用 GPIO_PULL_DOWN。触发唤醒时，应将其中一个或两个引脚驱动为高电平。悬空引脚可能引起误唤醒。

`EXT1` 或 `GPIO` 唤醒使用的 GPIO 引脚及电气特性，例如引脚编号、上下拉配置和有效电平，都定义在示例的设备树覆盖文件（Devicetree overlay）中，可按测试需要修改。

> 译注——引脚前提：ESP32-DevKitC 覆盖文件为 GPIO2／4 设置 GPIO_PULL_DOWN、GPIO_ACTIVE_HIGH 和 GPIO_INT_WAKEUP，其他 SoC 使用各自覆盖文件。当前 main.c 即使使用定时器，也要求 wakeup-pins 别名存在；“无需额外硬件”不等于可以删除该设备树节点。

## 93.3 构建、烧录与运行（Building, Flashing and Running）

> 译注——执行前提：下面主机命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行；先按[入门指南](../getting_started/大纲.md)准备工具、模块、工具链与目标板。west flash 会下载固件；串口输出块是原文示例，提示符和日志不作为命令执行。本批未构建、烧录或运行硬件实验。

```text
west build -b esp32_devkitc/esp32/procpu samples/boards/espressif/deep_sleep
west flash
```
