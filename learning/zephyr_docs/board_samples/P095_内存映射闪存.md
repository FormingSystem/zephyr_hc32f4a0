# 第95章\_内存映射闪存（Memory-Mapped Flash）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/boards/espressif/flash_memory_mapped/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/boards/espressif/flash_memory_mapped/README.rst/..)

<a id="overview"></a>

## 95.1 概述（Overview）

ESP32 的内存硬件允许把闪存区域映射到指令地址空间和数据地址空间。这种映射只支持读取，不能通过向映射后的内存区域写入来修改闪存内容。

映射以 64 KB 页为单位进行。内存映射硬件可以将闪存映射到数据地址空间和指令地址空间。有关该硬件的更多细节与限制，请参阅技术参考手册（Technical Reference Manual）。更多信息见 [ESP32 闪存内存映射（ESP32 Flash Memory-Mapping）](https://docs.espressif.com/projects/esp-idf/en/latest/esp32/api-reference/peripherals/spi_flash/index.html#memory-mapping-api)。

> 译注——地址含义：Flash 分区偏移、映射后的 CPU 指针和主机文件路径是不同对象。这里的映射按 SPI_FLASH_MMAP_DATA 建立，结束时用 spi_flash_munmap() 解除；映射地址由当前布局决定，不应从示例日志复制为常量。

<a id="supported-socs"></a>

## 95.2 支持的 SoC（Supported SoCs）

所有 ESP32 SoC 都支持闪存内存映射功能。

<a id="building-and-running"></a>

## 95.3 构建与运行（Building and Running）

> 译注——执行前提：下面主机命令从读者自己的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行；先按[入门指南](../getting_started/大纲.md)准备工具、模块、工具链与目标板。west flash 会下载固件；串口输出块是原文示例，提示符和日志不作为命令执行。本批未构建、烧录或运行硬件实验。

确保开发板已经通过 USB 端口连接。

> 译注——板名差异：下方原文使用旧的 esp32s3_devkitc 名称；本次 tests.yaml 的对应目标为 esp32s3_devkitc/esp32s3/procpu。采用当前板模型时应使用完整目标，原始命令在此保留供对照。

```text
west build -b esp32s3_devkitc samples/boards/espressif/flash_memory_mapped
west flash
```

### 95.3.1 示例输出（Sample Output）

要查看本示例输出，可运行 `west espressif monitor`，或使用其他串口控制台程序，例如 minicom、putty、screen。本例使用 `west espressif monitor`，它会自动检测位于 `/dev/ttyUSB0` 的串口：

> 译注——输出与返回值：/dev/ttyUSB0 是原文的 Linux 设备节点示例，读者应选择实际串口。源码比较两种读取的前 32 字节并输出 matches／does not match；它没有检查映射、擦除、写入和读取函数的返回值，不能只凭十六进制日志宣称所有操作成功。

```text
$ west espressif monitor
```

示例代码擦除 DTS 文件定义的存储分区（Storage partition），并向其中写入一个 32 字节数据缓冲区。随后分别通过闪存 API 读取和内存映射指针打印该区域内容，两种读取应返回相同的值。特别注意，不允许通过内存映射指针写入。

> 译注——擦除范围：源码的 flash_erase() 使用整个 storage_partition 的大小，之后仅写入 32 字节的 0x00～0x1f 数据；不是只擦除这 32 字节。示例会改变该分区内容，映射本身只读不代表整个应用只读。
