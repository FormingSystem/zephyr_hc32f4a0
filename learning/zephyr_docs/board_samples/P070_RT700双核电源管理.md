# 第70章\_RT700 EVK 双核电源管理（RT700 EVK dual-core power management）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/boards/nxp/mimxrt700_evk/dual_core_pm/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/boards/nxp/mimxrt700_evk/dual_core_pm/README.rst/..)

<a id="overview"></a>

## 70.1 概述（Overview）

本示例为 MIMXRT700-EVK 构建两个 Zephyr 镜像：

- 主镜像运行在 CM33 CPU0，即计算核（Compute core），并通过既有的 `CONFIG_SECOND_CORE_MCUX` 开发板初始化路径启动 CM33 CPU1。

- 远端镜像运行在 CM33 CPU1，即感知核（Sense core）。

两个镜像都启用 Zephyr 系统电源管理，并注册 PM 通知器统计状态进入／退出事件。CPU0 负责协调测试：等待控制台输入 ENTER，随后执行一次完整测试矩阵并停止。每项测试中，CPU0 通过消息单元（Messaging Unit，MU）邮箱向 CPU1 发送模式。两核通过以下简短握手共同进入测量窗口：

1. CPU0 发送模式命令，CPU1 确认就绪。

2. CPU0 发送 `GO`，允许 CPU1 开始。

3. 每个内核各自执行配置秒数的测量窗口。

4. CPU1 报告其窗口已完成。

相邻测试之间留出 `CONFIG_SAMPLE_RT700_DUAL_CORE_PM_SETTLE_SECONDS` 指定的间隔，使电流曲线上出现分开的平台。最后一项完成后，CPU0 打印汇总行并保持空闲；按复位按钮可再次运行测试矩阵。

测试矩阵包含八种情况：

1. 两核均活动，作为基线（Baseline）。

2. CPU0 睡眠，CPU1 活动。

3. CPU0 活动，CPU1 睡眠。

4. 两核均睡眠。

5. CPU0 深度睡眠，CPU1 活动。

6. CPU0 活动，CPU1 深度睡眠。

7. 两核均深度睡眠。

8. CPU0 深度睡眠保持（Deep-sleep-retention，DSR），CPU1 深度睡眠。

启动时锁住较深的 PM 状态，使普通睡眠窗口保持在 `PM_STATE_RUNTIME_IDLE`。各深度窗口只在自身持续期间解锁所测试的状态：

- 睡眠窗口：`PM_STATE_RUNTIME_IDLE`。

- 深度睡眠窗口：`PM_STATE_SUSPEND_TO_IDLE`。

- DSR 窗口：`PM_STATE_STANDBY`。

深度睡眠保持是双电源域 FDSR 模式，只有 Compute 与 Sense 电源域都请求深度睡眠时才生效，因此第八项在 CPU0 进入 DSR 时，让 CPU1 停留在深度睡眠。

注意（Note）

第八项依赖控制台的设备电源管理。DSR 会关闭 VDD2_COMP，也使 LP_FLEXCOMM／LPUART 控制台掉电：封装层的 `PSELID[PERSEL]` 选择及整组 LPUART 寄存器均丢失，因此窗口之后的控制台写入可能在没有时钟的发送器上停住，或访问该模块时触发总线故障（Bus fault）。`CONFIG_PM_DEVICE_SYSTEM_MANAGED` 在窗口前后调用 `pm_suspend_devices()`／`pm_resume_devices()`；SoC 的 `peripheral-domain` 节点把 `PM_STATE_STANDBY` 作为真实的掉电重上电过程通知所有关联设备，使两个驱动重新执行 `PM_DEVICE_ACTION_TURN_ON`，从头恢复硬件。窗口开启时控制台出现的单个 NUL 字节是焊盘供电变化的现象，并非输出丢失。

示例不配置任何 PMC 寄存器掩码，两个镜像也不会代替另一内核维持共享资源。PMC 汇总两核都能表决的各项资源：只有两个电源域都同意，资源才会关闭；因此每核只请求保留自己使用的资源，并请求关闭其他资源。CPU1 启动时在开发板早期初始化钩子中提出自己的需求，包括 SENSE／COMN 主时钟、RAM 仲裁器时钟、VDDN_COM 以及代码和数据分区，使 CPU0 在第五至第七项深度睡眠时，CPU1 仍可运行。应用仅通过 MU 协调；上述 `pm_policy` 锁只选择窗口测试的状态，不会因为 CPU1 正在运行就阻止 CPU0 进入深度睡眠。

CPU0 和 CPU1 分别输出到各自调试 UART。串口输出只能粗略确认两核启动成功且 PM 进入／退出回调已触发；应在稳定的低功耗窗口中测量板电流。

<a id="building-and-running"></a>

## 70.2 构建与运行（Building and Running）

> 译注——执行前提：west 命令从读者的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行；先按[入门指南](../getting_started/大纲.md)准备工具链、模块及对应板。构建产物由工具生成，下载与启动按具体板文档核对。本次未执行构建、烧录或硬件测量。

使用 sysbuild 一起构建 CPU0 和 CPU1 镜像：

> 译注——双镜像依赖：本次 sysbuild.cmake 添加 remote 应用，并将 CPU1 生成的 zephyr_image_info.h 所在目录传给 CPU0 的 CONFIG_SECOND_CORE_MCUX_REMOTE_DIR，配置和下载顺序也建立依赖。应保留 --sysbuild；只构建 CPU0 不能替代这条完整路径。

```text
west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 --sysbuild samples/boards/nxp/mimxrt700_evk/dual_core_pm
west flash
```

复位后，CPU0 列出测试项并等待 ENTER；这是示例唯一需要的控制台输入。测量设备就绪后按一次回车，第一至第八项会连续运行，无需后续交互。CPU0 控制台输出如下：

```text
RT700 dual-core PM sample: CPU0 started on mimxrt700_evk/mimxrt798s/cm33_cpu0

RT700 dual-core PM cases:
  1: active baseline
  2: CPU0 sleep, CPU1 active
  3: CPU0 active, CPU1 sleep
  4: CPU0 and CPU1 sleep
  5: CPU0 deep sleep, CPU1 active
  6: CPU0 active, CPU1 deep sleep
  7: CPU0 and CPU1 deep sleep
  8: CPU0 deep sleep retention, CPU1 deep sleep

Press ENTER to run all 8 cases once:

CPU0: run: 8 cases, window=2 s, settle=2 s

CPU0: case 1: active baseline
CPU0: local=active remote=active window=2 seconds
CPU0: entering active window
CPU0: local active window complete
CPU0 PM counts: runtime-idle=2/2 suspend-to-idle=0/0 standby=0/0

... cases 2 to 8 ...

CPU0: run complete: 8 cases
```

CPU1 在自己的控制台报告对应活动：

> 译注——计数与握手边界：state_entry_count／state_exit_count 从启动后累计增加，当前源码没有在每项前清零，比较单项应看前后差值。CPU0 等待 MU 回复时没有超时；若远端未启动，程序可能停在等待处。打印 unexpected 回复后也不会自动中止测试，所以 run complete 不是全部握手和功耗目标均通过的严格断言。

```text
RT700 dual-core PM sample: CPU1 started on mimxrt700_evk/mimxrt798s/cm33_cpu1
CPU1: waiting for CPU0 PM test commands
CPU1: prepared for active window
CPU1: entering active window
CPU1: active window complete
```

注意（Note）

两项测试之间，CPU1 通过 `k_yield()` 轮询 MU 邮箱，不进入睡眠，以免等待过程增加 PM 状态进入次数，便于阅读每项计数。因此，稳定间隔不是 CPU1 的有效低功耗测量窗口，应在控制台 `entering`／`complete` 标出的窗口内测量。

<a id="measurement-notes"></a>

## 70.3 测量说明（Measurement Notes）

通过 EVK 的 JP21 测量 RT700 SoC 电流。移除默认的 JP21 跳线，串联电流表或功耗分析仪。JP21 测量 RT700 SoC 电源轨，不能分别隔离 CPU0 和 CPU1。要观察每核的贡献，应比较活动基线、单核睡眠、单核深度睡眠以及协调睡眠／深度睡眠／DSR 窗口。

> 译注——测量对象：两个内核共享的 SoC 电源轨不能直接拆成独立内核电流，串口、唤醒和共享资源也影响读数。只比较同一接线和测量条件下的稳定窗口；两个核心的串口 PM 计数只是软件事件证据。

默认测量窗口为两秒，之后是两秒稳定间隔；两者均可在构建时修改。sysbuild 将窗口长度传给两个镜像，将稳定间隔传给 CPU0：

> 译注——参数层级：原文使用 SB_CONFIG_* 指定系统构建层配置，sysbuild 将窗口映射到两个镜像各自的 CONFIG_*，稳定间隔只传 CPU0。等待间隔中 CPU1 轮询邮箱，因此它不是两核都休眠的参考值。

```text
west build -p always --sysbuild \
  -b mimxrt700_evk/mimxrt798s/cm33_cpu0 \
  samples/boards/nxp/mimxrt700_evk/dual_core_pm \
   -- -DSB_CONFIG_SAMPLE_RT700_DUAL_CORE_PM_SLEEP_SECONDS=30 \
   -DSB_CONFIG_SAMPLE_RT700_DUAL_CORE_PM_SETTLE_SECONDS=5
```

> 译注——源码入口：本仓库尚无对应文件，上游入口：[src/main.c](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/boards/nxp/mimxrt700_evk/dual_core_pm/src/main.c)；[prj.conf](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/boards/nxp/mimxrt700_evk/dual_core_pm/prj.conf)；[remote/src/main.c](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/boards/nxp/mimxrt700_evk/dual_core_pm/remote/src/main.c)；[sysbuild.cmake](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/samples/boards/nxp/mimxrt700_evk/dual_core_pm/sysbuild.cmake)。
