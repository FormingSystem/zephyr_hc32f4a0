# 第71章\_RT700 系统关闭（RT700 System Off）

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/boards/nxp/mimxrt700_evk/system_off/README.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

[在 GitHub 浏览源码（Browse source code on GitHub）](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/boards/nxp/mimxrt700_evk/system_off/README.rst/..)

<a id="overview"></a>

## 71.1 概述（Overview）

本示例展示在 i.MX RT700 上使用 `sys_poweroff()`，流程如下：

- 等待控制台输入 ENTER，确保电流测量就绪后再开始。

- 选择常开 IRTC 唤醒定时器作为唤醒源。

- 设置唤醒定时器，在 `CONFIG_SAMPLE_RT700_SYSTEM_OFF_WAKEUP_SECONDS` 秒后触发，默认三秒。

- 调用 `sys_poweroff()` 关闭芯片。

- 重复上述过程三次，并记录已完成的循环次数。

默认情况下，`sys_poweroff()` 进入深度掉电（Deep Power Down，DPD），除了 RTC／VDD1V8_AON 常开电源岛之外，整颗芯片掉电。IRTC 唤醒定时器事件通过 SLEEPCON WAKEUPEN 的 RTC 线路路由，闹钟到期时芯片执行上电复位（Power-on reset）冷启动，应用重新开始。

只有冷启动会停在输入提示处。DPD 唤醒是同一镜像的全新启动，如果再次要求输入，就会打断无人值守循环，因此剩余循环连续执行。

> 译注——首次输入与复位：这里“只有冷启动”指计数为零的初次运行；DPD 唤醒在硬件上也经历冷启动，但代码识别 DEEPPDF 与保留计数后跳过提示，直到完成三轮。计数无效或被清零时会重新要求输入。

<a id="counting-the-power-off-cycles"></a>

## 71.2 统计关闭循环次数（Counting the power-off cycles）

DPD 唤醒是冷启动，SRAM 无法保留循环计数。唯一保留状态的是 VDD1V8_AON 常开电源岛，因此示例借用两个 IRTC 闹钟寄存器保存计数；采用唤醒定时器时，这两个寄存器未被使用。`RTC0->GPR` 看似更合适，但它属于启动 ROM，用来保存 Flash 状态上下文。

> 译注——寄存器使用：本次源码用 ALM_YEARMON 的有效字段保存标记，用 ALM_HOURMIN 的字段保存计数，并处理写保护；它依赖日历闹钟寄存器在本例未被使用。添加日历闹钟功能时不能继续假定这些字段空闲，也不能占用 ROM 使用的 GPR。

`PMC0->FLAGS[DEEPPDF]` 用于区分 DPD 唤醒与其他启动，因此断电重上电或调试器复位会从零重新计数，而不会沿用旧值。

<a id="selecting-the-power-off-mode"></a>

## 71.3 选择关闭模式（Selecting the power-off mode）

`sys_poweroff()` 进入由 SoC Kconfig 选项组选择的模式：

- `CONFIG_SOC_IMXRT7XX_POWEROFF_DPD` 为默认选项，对应深度掉电。

- `CONFIG_SOC_IMXRT7XX_POWEROFF_FDPD` 对应完全深度掉电（Full Deep Power Down）；连 VDD1V8_PMC 也关闭，因此唤醒依赖常开 RTC 路径。

两种模式都不保持 SRAM，唤醒始终是冷启动。

<a id="measurement-notes"></a>

## 71.4 测量说明（Measurement Notes）

通过 EVK 的 JP21 测量 RT700 SoC 电流。移除默认 JP21 跳线，串联电流表或功耗分析仪。JP21 承载整个 SoC 电源轨，适合测量关闭模式：DPD 与 FDPD 关闭其后的所有电源域，因此读数体现常开电源岛的剩余功耗，而非某一个内核的数值。

先准备好仪表，再按 ENTER。每个关闭窗口持续 `CONFIG_SAMPLE_RT700_SYSTEM_OFF_WAKEUP_SECONDS` 秒，并由控制台的 `Powering off` 与下一次启动横幅标出；因此三段窗口呈现为三个独立平台，之间是电流高得多的启动和重新配置过程。

窗口长度和 ENTER 提示均可在构建时修改：

> 译注——时间与次数：CONFIG_SAMPLE_RT700_SYSTEM_OFF_WAKEUP_SECONDS 改变每次关闭时长，CONFIG_SAMPLE_RT700_SYSTEM_OFF_WAIT_FOR_ENTER 控制首次提示；当前 WAKEUP_CYCLES 固定为三次，修改等待秒数不会改变循环次数。Done, staying awake 表示三轮完成后保持运行。

```text
west build -p always -b mimxrt700_evk/mimxrt798s/cm33_cpu0 \
  samples/boards/nxp/mimxrt700_evk/system_off \
  -- -DCONFIG_SAMPLE_RT700_SYSTEM_OFF_WAKEUP_SECONDS=30 \
  -DCONFIG_SAMPLE_RT700_SYSTEM_OFF_WAIT_FOR_ENTER=n
```

比较两种模式时，对每个 `CONFIG_SOC_IMXRT7XX_POWEROFF_*` 选项分别构建，并测量相同窗口。FDPD 在设计上是更深的模式，但它让电压参考保持高功耗状态，以便 VDD1V8 上升时唤醒芯片；只有设置 `POWERCFG[FDPDBGLP]`，SoC 才消除这部分开销，而驱动在每次进入时都会设置该位。

<a id="requirements"></a>

## 71.5 前提条件（Requirements）

本应用使用 MIMXRT700-EVK。

<a id="building-flashing-and-running"></a>

## 71.6 构建、烧录与运行（Building, Flashing and Running）

> 译注——执行前提：west 命令从读者的 Zephyr 源码根目录，在 UCRT64 Bash 或 Linux Bash 中执行；先按[入门指南](../getting_started/大纲.md)准备工具链、模块及对应板。构建产物由工具生成，下载与启动按具体板文档核对。本次未执行构建、烧录或硬件测量。

```text
west build -b mimxrt700_evk/mimxrt798s/cm33_cpu0 samples/boards/nxp/mimxrt700_evk/system_off
west flash
```

运行步骤（Running）：

1. 打开 UART 终端。

2. 将设备断电后重新上电。

3. 出现提示时按 ENTER。

4. 设备设置唤醒闹钟并关闭，进入深度掉电。

5. 三秒后，RTC 唤醒使应用从冷启动重新运行。

6. 三次循环后，应用保持唤醒。
