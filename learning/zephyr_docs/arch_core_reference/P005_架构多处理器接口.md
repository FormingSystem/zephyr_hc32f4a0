### `arch_cpu_start()`

```c
void arch_cpu_start ( int cpu_num, k_thread_stack_t * stack, int sz, arch_cpustart_t fn, void * arg )
```

```c
#include <zephyr/arch/arch_interface.h>
```

在具备多处理器能力（Multiprocessor，MP）的系统上启动指定编号的 CPU。

启动并初始化指定 CPU。启动时主线程运行在 CPU 0，其他处理器依次编号。此函数返回时，可以确定该 CPU 已开始运行，并将进入提供的函数。该 CPU 的中断已经初始化但处于禁用状态，可使用提供的键调用 `irq_unlock()` 来使能中断。

在 SMP 模式下，通常由内核初始化调用此函数，不应把它用作用户 API。但它在此公开声明，以支持特殊应用：让 Zephyr 在一个核心运行，而将其他核心用于专门处理。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `cpu_num` | CPU 的整数编号。 |
| `stack` | 供此 CPU 使用的栈内存。 |
| `sz` | 栈缓冲区大小，单位为字节。 |
| `fn` | 要在该 CPU 上开始运行的函数。 |
| `arg` | 传给 `fn` 的无类型参数。 |

<a id="gad628c89816128546501e3c26eaaf9dea"></a>

### `arch_proc_id()`

```c
uint32_t arch_proc_id ( void )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

处理器硬件 ID（Hardware ID）。

大多数多处理器架构都有与当前 CPU 关联的底层唯一 ID，可在内核上下文中快速高效地取得。CPU 编号保证唯一，但具体数值由平台定义，尤其不保证与 Zephyr 自身连续编号的 CPU ID 一致，虽然某些平台上两者确实相同。

说明（Note）：此 API 存在固有竞态；返回值被使用之前，系统可能抢占当前线程并将其迁移到另一个 CPU。安全使用需要确定不可能迁移，例如处于中断上下文、持有自旋锁（Spinlock），或因 `k_cpu_mask` 状态而无法迁移。

返回（Returns）：当前执行 CPU 的唯一 ID。

## 5.4\_源码定位与版本边界

源码定位：[include/zephyr/arch/arch_interface.h](../../../include/zephyr/arch/arch_interface.h)、[kernel/smp/smp.c](../../../kernel/smp/smp.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库内源码采用相对链接，架构实现举例不表示全部架构都具有相同硬件能力，也不表示已在目标板执行验证。

> 译注——源码核对：arch_cpu_start用于启动另一个CPU的架构入口，不是创建普通应用线程。当前kernel/smp/smp.c传入该CPU的中断栈和smp_init_top入口，并通过ready_flag等待启动就绪；线程创建与CPU启动不能互换。

> 译注——源码核对：CPU编号、CPU数量、调度亲和性（Affinity）与线程迁移是不同概念。取得当前CPU相关信息后若允许线程迁移，不能假定后续代码仍在原CPU运行；跨核中断和启动握手也不能用本地中断锁替代。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
