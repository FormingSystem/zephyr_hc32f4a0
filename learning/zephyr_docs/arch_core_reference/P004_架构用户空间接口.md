## 4.2\_详细说明（Detailed Documentation）

### `arch_buffer_validate()`

```c
int arch_buffer_validate ( const void * addr, size_t size, int write )
```

```c
#include <zephyr/arch/arch_interface.h>
```

检查内存区域权限。

给定内存区域，返回当前内存管理硬件配置是否允许用户线程读写该区域。系统调用用它验证用户空间传入的缓冲区。

说明：若整个缓冲区并非用户可访问，此函数保证不会返回验证成功。

若整个缓冲区的用户访问权限由单个已使能的内存管理区域实施，此函数保证正确验证该缓冲区权限。

在某些架构上，若缓冲区跨越多个已使能的内存管理区域，即使全部区域都允许用户访问，验证也始终失败。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `addr` | 缓冲区起始地址。 |
| `size` | 缓冲区大小。 |
| `write` | 非零时，额外检查区域是否可写；否则只检查是否可读。 |

**警告（Warning）**：警告（Warning）：大小为零的缓冲区，其行为未定义。

返回（Returns）：权限不匹配时返回非零值。

### `arch_cohere_stacks()`

```c
void arch_cohere_stacks ( struct k_thread * old_thread, void * old_switch_handle, struct k_thread * new_thread )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

在上下文切换前确保缓存一致性（Cache Coherence）。

`CONFIG_KERNEL_COHERENCE` 为 true 时必须提供。在缓存不一致的多处理器架构上，为提高性能，线程栈默认使用缓存，因此上下文切换时必须适当写回。规则如下：

- 旧栈中包含有效数据的区域（通常是当前栈指针与栈内存顶部之间的字节）必须写回底层存储，使随后运行同一线程的新 CPU 看到正确数据。必须在给线程结构的 `switch_handle` 字段赋值之前完成；该赋值表示上下文切换完成。
- 新栈中将被读取的数据区域（通常与保存时的有效区域相同）应在数据缓存中失效，且不得写回！这是因为自本 CPU 挂起该线程后，其他 CPU 可能运行或重新初始化了它，此时缓存中的数据已经过时。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `old_thread` | 允许在其他 CPU 运行之前需要写回的旧线程。 |
| `old_switch_handle` | 要保存到 `old_thread` 的切换句柄；缓存写回之前该句柄无效，因此此时尚未保存。在 `z_swap()` 内部此参数为 `NULL`，因为 `arch_switch()` 尚未保存它。 |
| `new_thread` | 在本 CPU 运行之前，需要使其栈缓存失效的新线程。 |

说明（Note）：内核在中断退出并选定新线程时调用此函数，也会在进入 `arch_switch()` 执行代码驱动的上下文切换前立即调用。后一种情况下，此函数返回后到切换完成前，很可能仍会向 `old_thread` 的栈写入数据。许多架构仅在此简单写回并不足够，可能需要与 `arch_switch()` 实现协同。

### `arch_syscall_invoke0()`

```c
uintptr_t arch_syscall_invoke0 ( uintptr_t call_id)
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

发起不带参数的系统调用。

出于安全原因，从监督模式返回用户模式时，除返回值外不得保留其他通用寄存器状态。

从用户模式提升至监督模式时，要求所有参数保存在寄存器中。

系统调用在独立的内核栈上处理。从分发表调用系统调用参数编组函数（Marshaller）时，应使能中断；处理系统调用期间可以发生线程抢占。

调用 ID 不可信，必须检查边界，因为它将用作系统调用分发表的索引，而表中保存着指向具体系统调用代码的函数指针。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `call_id` | 系统调用 ID。 |

返回（Returns）：系统调用的返回值；无返回值的系统调用在此返回 0。

### `arch_user_mode_enter()`

```c
FUNC_NORETURN void arch_user_mode_enter ( k_thread_entry_t user_entry, void * p1, void * p2, void * p3 )
```

```c
#include <zephyr/arch/arch_interface.h>
```

从监督模式（Supervisor Mode）单向切换到用户模式。

此函数的实现必须完成以下操作：

- 将线程栈指针重设为合适的初始值。这是单向操作，不需要保留先前上下文。
- 建立 CPU 在提升权限时使用的内核栈区域。
- 将 CPU 置于该架构相应的用户模式。
- 在用户模式下，将所有给定参数传给 `arch_new_thread()` 并转移执行到它。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `user_entry` | 作为用户线程开始执行的入口点。 |
| `p1` | 用户线程的第一个参数。 |
| `p2` | 用户线程的第二个参数。 |
| `p3` | 用户线程的第三个参数。 |

### `arch_user_string_nlen()`

```c
size_t arch_user_string_nlen ( const char * s, size_t maxsize, int * err )
```

```c
#include <zephyr/arch/arch_interface.h>
```

安全取得可能无效的字符串长度。

返回（Returns）：不包含结尾空字节的字符串长度，最大为 `maxsize`。

<a id="ga48be2412ba65ec550ded63e2f1a0470f"></a>

### `arch_virt_region_align()`

```c
size_t arch_virt_region_align ( uintptr_t phys, size_t size )
```

```c
#include <zephyr/arch/arch_interface.h>
```

取得可优化 MMU 页表布局的最佳虚拟区域对齐。

某些 MMU 硬件要求区域按中间层块的边界对齐，以减少页表用量。此调用返回最佳虚拟地址对齐，使后续 MMU 映射调用能够采用这项优化。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[in] phys` | 待映射区域的物理地址，须按 `CONFIG_MMU_PAGE_SIZE` 对齐。 |
| `[in] size` | 待映射区域大小，须按 `CONFIG_MMU_PAGE_SIZE` 对齐。 |

返回（Returns）：此区域虚拟地址应采用的对齐。
