### `ARCH_DATA_PAGE_ACCESSED`

```c
#define ARCH_DATA_PAGE_ACCESSED
```

```c
#include <kernel_arch_interface.h>
```

表示自上次清除此值以来，数据页曾被访问的位（Accessed Bit）。

若 `ARCH_DATA_PAGE_LOADED` 未置位，则此位未定义。

```c
#define ARCH_DATA_PAGE_DIRTY
```

```c
#include <kernel_arch_interface.h>
```

表示数据页若被逐出，则需要换出的位。

数据页自上次换出以来被修改，或此前从未换出时置位。不确定时可安全地将此位置位。

若 `ARCH_DATA_PAGE_LOADED` 未置位，则此位未定义。

### `arch_mem_map()`

```c
int arch_mem_map ( void * virt, uintptr_t phys, size_t size, uint32_t flags )
```

```c
#include <kernel_arch_interface.h>
```

将物理内存映射到虚拟地址空间（Virtual Address Space）。

这是将页面映射到地址空间的底层接口。传入未对齐的地址或大小时，行为未定义；接口假定它们按 `CONFIG_MMU_PAGE_SIZE` 对齐。

核心内核负责全部虚拟地址空间管理；调用此函数时，映射位置已经完全确定。若页表在该虚拟内存区域已有映射，这些映射会被覆盖。

目标架构若支持多种页面大小，目前只使用最小页大小。

此操作不会访问内存区域本身。

此 API 必须能够安全地从 ISR 或异常处理函数调用。假定对它的调用已串行化；所有调用都来自负责虚拟内存管理的 `kernel/mm.c`。

架构应为 `CONFIG_KERNEL_VM_BASE` 和 `CONFIG_KERNEL_VM_SIZE` 定义的整个地址空间预分配页表；此操作不得需要为分页结构分配任何内存。

参数验证应通过断言（Assertions）完成。

此 API 属于仍在开发中的基础设施，可能发生变化。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `virt` | 按页对齐、待建立映射的目标虚拟地址。 |
| `phys` | 按页对齐、待建立映射的源物理地址。 |
| `size` | 映射内存区域的大小，单位为字节，须按页对齐。 |
| `flags` | 缓存、访问与控制标志，参阅 `K_MAP_*` 宏。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时。 |
| `-EINVAL` | 参数无效时。 |
| `-ENOTSUP` | 目标架构不支持 `flags` 请求的缓存与属性组合时。 |
| `-ENOMEM` | 无法更新底层页表时。 |
| `-errno` | 架构专有实现可以针对其他失败模式返回其他负错误码。 |

<a id="ga3c446aea862e37d479a809582322b3ae"></a>

### `arch_mem_page_in()`

```c
void arch_mem_page_in ( void * addr, uintptr_t phys )
```

```c
#include <kernel_arch_interface.h>
```

为换入的数据页更新所有页表。

此函数执行以下操作：

- 将指定虚拟数据页地址映射到给定物理页框，使后续内存访问按预期工作；访问与缓存属性保持不变。
- 清除“已访问”与“脏”状态的记账信息。

使用多个页表时，必须更新全部页表。调用此函数时中断已锁定。

对已经换入的数据页调用此函数，行为未定义。

此 API 属于仍在开发中的基础设施，可能发生变化。

<a id="ga4c13ffab5b5a5f8c93971c4d3b51bd8f"></a>

### `arch_mem_page_out()`

```c
void arch_mem_page_out ( void * addr, uintptr_t location )
```

```c
#include <kernel_arch_interface.h>
```

为换出的数据页更新所有页表（Page Tables）。

此函数执行以下操作：

- 将虚拟数据页设置为：访问时触发一种能与访问权限违规或未映射页面区分的故障。
- 保存给定位置值，使缺页异常处理函数能够为该数据页取回它。
- 此处不规定位置值的语义，但保证它按页对齐；它可以为 0。

使用多个页表时，必须更新全部页表。调用此函数时中断已锁定。

对已经换出的数据页调用此函数，行为未定义。

此 API 属于仍在开发中的基础设施，可能发生变化。

### `arch_mem_scratch()`

```c
void arch_mem_scratch ( uintptr_t phys)
```

```c
#include <kernel_arch_interface.h>
```

为临时映射更新当前页表。

把物理页框地址映射到特殊虚拟地址 `K_MEM_SCRATCH_PAGE`，授予监督模式读写权限，使函数返回后调用上下文能够通过该地址读写页框内容。

只需在当前页表集合建立此映射，因为它只在短时间内由调用者独占使用。调用此函数时中断已锁定。

此 API 属于仍在开发中的基础设施，可能发生变化。

<a id="gad78289a6d8810c30c7fa3052bcac9c23"></a>

### `arch_mem_unmap()`

```c
int arch_mem_unmap ( void * addr, size_t size )
```

```c
#include <kernel_arch_interface.h>
```

移除指定虚拟地址范围的映射。

这是从地址空间解除页面映射的底层接口。完成后，相关页表项将更新为该内存范围从未映射过的状态，无须保留之前的上下文。必须更新全部活动页表中的映射。

传入未对齐的地址或大小时，行为未定义；接口假定它们按 `CONFIG_MMU_PAGE_SIZE` 对齐。

传入尚未映射的地址范围时，行为未定义。

此函数不得需要为分页结构分配内存，也不必释放分页结构。所有条目均解除映射后形成的空页表可以保留。

实现必须按需使地址转换后备缓冲器（Translation Lookaside Buffer，TLB）失效。

此 API 属于仍在开发中的基础设施，可能发生变化。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `addr` | 按页对齐、待解除映射的虚拟基址。 |
| `size` | 按页对齐的区域大小。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时。 |
| `-EINVAL` | 参数无效时。 |
| `-errno` | 架构专有实现可以针对其他失败模式返回其他负错误码。 |

<a id="gab32a4bb6b3d44c126d63a473caf28b70"></a>

### `arch_page_info_get()`

```c
uintptr_t arch_page_info_get ( void * addr, uintptr_t * location, bool clear_accessed )
```

```c
#include <kernel_arch_interface.h>
```

从页表取得页面特征。

架构负责维护数据页的“已访问”（Accessed）与“脏”（Dirty）状态，以支持标记式逐出算法。可由硬件直接支持，也可通过修改保护策略，在读写时触发异常来模拟。无论采用哪种方式，架构都必须维护这些信息。

对于给定虚拟地址，若页面已映射且未换出，则报告系统中所有活动页表相关条目的已访问与脏状态按逻辑或合并后的结果。

若 `clear_accessed` 为 true，将清除 `ARCH_DATA_PAGE_ACCESSED` 标志；函数报告清除前的状态。使用多个页表时，会清除全部页表中的已访问状态。

调用时中断已锁定，确保基于所报告信息作决策时，这些信息不会过时。

返回值可能包含其他置位的位，调用者必须忽略它们。

对未标记为 `ARCH_DATA_PAGE_LOADED` 的数据页清除已访问状态，行为未定义。

返回值中的 `ARCH_DATA_PAGE_DIRTY` 和 `ARCH_DATA_PAGE_ACCESSED` 仅在 `ARCH_DATA_PAGE_LOADED` 置位时有效，否则忽略。

返回值中的 `ARCH_DATA_PAGE_NOT_MAPPED` 仅在 `ARCH_DATA_PAGE_LOADED` 未置位时有效，否则忽略。

除非另有说明，虚拟数据页在所有页表中具有相同映射。对不符合此规则的数据页（例如临时页 Scratch Page）调用此函数，行为未定义。

此 API 属于仍在开发中的基础设施，可能发生变化。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` addr` | 要在页表中查找的虚拟地址。 |
| `[out] location` | 若非 `NULL`，则根据 `ARCH_DATA_PAGE_LOADED` 状态更新为物理页框地址或后备存储位置。若为 `ARCH_DATA_PAGE_NOT_MAPPED`，则不修改此输出。 |
| ` clear_accessed` | 是否清除 `ARCH_DATA_PAGE_ACCESSED` 状态。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `Value` | 设置相应 `ARCH_DATA_PAGE_*` 位，反映数据页配置。 |

<a id="ga74b3ce1173b91a8f82c25ef89f9fbbc0"></a>

### `arch_page_location_get()`

```c
enum arch_page_location arch_page_location_get ( void * addr, uintptr_t * location )
```

```c
#include <kernel_arch_interface.h>
```

取得指定地址处页面的位置信息。

只需查询当前页表集合；若使用多个页表，所报告信息应在它们之间一致，因此无须遍历全部页表。这可能允许采用某些优化，例如 x86 的反向页表映射。

调用时中断已锁定，确保基于所报告信息作决策时，这些信息不会过时。

除非另有说明，虚拟数据页在所有页表中具有相同映射。对不符合此规则的数据页（例如临时页）调用此函数，行为未定义。只需检查当前安装的页表并返回其中的信息。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` addr` | 发生缺页异常（Page Fault）的虚拟数据页地址。 |
| `[out] location` | 若为 `ARCH_PAGE_LOCATION_PAGED_OUT`，则是用于取回数据页的后备存储位置值；若为 `ARCH_PAGE_LOCATION_PAGED_IN`，则是页面所映射的物理地址。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `ARCH_PAGE_LOCATION_PAGED_OUT` | 页面已被逐出到后备存储。 |
| `ARCH_PAGE_LOCATION_PAGED_IN` | 数据页驻留在内存中。 |
| `ARCH_PAGE_LOCATION_BAD` | 页面未映射，或发生了其他无效访问。 |

### `arch_page_phys_get()`

```c
int arch_page_phys_get ( void * virt, uintptr_t * phys )
```

```c
#include <zephyr/arch/arch_interface.h>
```

取得虚拟地址所映射的物理地址。

查询依据调用者当前活动的页表。只有在调用者上下文中有效的映射才能可靠报告；不属于该上下文的映射（例如非当前内存域中的内存，或临时页等按上下文区分的数据页）可能被报告为未映射，或解析为不同地址。对这些地址调用此函数，行为未定义。

从实现角度，只需检查当前安装的页表，无须遍历系统中其他页表：通过此 API 合法查询的对象，在所有这些页表中的映射都相同。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` virt` | 按页对齐的虚拟地址。 |
| `[out] phys` | 映射到的物理地址；若只检查虚拟地址是否已映射，可以为 `NULL`。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 找到有效映射时。 |
| `-EFAULT` | 虚拟地址未映射时。 |

<a id="ga229fa5699ad47951235af494f3d2a06a"></a>

### `arch_reserved_pages_update()`

```c
void arch_reserved_pages_update ( void )
```

```c
#include <kernel_arch_interface.h>
```

使用保留页信息更新页框数据库（Page Frame Database）。

系统 RAM 中的某些页框可能无法使用，例如类 PC 系统第一个兆字节内的保留区域。

实现应将 `k_mem_page_frames` 中相关条目标记为 `K_PAGE_FRAME_RESERVED`。此函数在系统早期初始化期间调用，调用时持有 `mm_lock`。

## 3.5\_源码定位与版本边界

源码定位：[include/zephyr/arch/arch_interface.h](../../../include/zephyr/arch/arch_interface.h)、[kernel/mmu.c](../../../kernel/mmu.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库内源码采用相对链接，架构实现举例不表示全部架构都具有相同硬件能力，也不表示已在目标板执行验证。

> 译注——源码核对：内存映射（Memory Mapping）建立虚拟地址与物理地址及权限之间的关系，不等于分配存储或复制数据。地址、大小、页对齐、锁定上下文和允许的标志应按具体函数约束满足，不能把任意字节范围直接当作可用页映射。

> 译注——源码核对：页位置（Page Location）与页信息标志的输出有效条件不同。只有函数说明允许时，才能使用输出的物理地址或后备存储位置；未映射、已换出和已装入不是可互换的状态。页表状态刷新与数据缓存写回也是不同操作。

> 译注——源码核对：原文仍出现kernel/mm.c；本次官方main中的通用内存管理实现位于kernel/mmu.c。当前初始化在建立空闲页帧列表之前调用arch_reserved_pages_update标记架构保留页，使其不会被当作可分配页帧。

> 译注——源码核对：当前通用换页路径使用z_mm_lock，并在允许中断的配置下结合SMP互斥锁或调度锁。原文要求的中断锁定是接口调用条件，不能由此推导关闭本地中断已经完成所有跨CPU同步。

> 译注——源码核对：本组MMU（Memory Management Unit，内存管理单元）和请求分页（Demand Paging）接口不能直接等同于Cortex-M的MPU（Memory Protection Unit，内存保护单元）内存域功能。具体实现由架构和构建配置决定。
