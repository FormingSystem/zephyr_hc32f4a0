## 6.2\_详细说明（Detailed Documentation）

<a id="ga4d0297717c23a3cc5df434549e26924d"></a>

### `arch_cpu_atomic_idle()`

```c
void arch_cpu_atomic_idle ( unsigned int key)
```

```c
#include <zephyr/arch/arch_interface.h>
```

原子地重新使能中断并进入低功耗模式（Low-power Mode）。

`arch_cpu_atomic_idle()` 的要求如下：

- 使能中断与进入低功耗模式必须是原子操作：处理器进入低功耗模式之前，不得存在中断已使能的时间窗口。关于不满足此要求时出现的竞态，可参阅 `k_lifo_get()` 中的注释。
- 从低功耗模式唤醒后，必须按输入参数 `key` 恢复中断锁定状态。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `key` | 先前调用 `arch_irq_lock()` 返回的锁定键。 |

另见（See Also）：`k_cpu_atomic_idle()`。

<a id="ga6ce051203e6cc091d0fb42a15f662a48"></a>

### `arch_cpu_idle()`

```c
void arch_cpu_idle ( void )
```

```c
#include <zephyr/arch/arch_interface.h>
```

节能空闲例程（Power-saving Idle Routine）。

内核空闲循环会调用此函数；内核中 `z_pm_save_idle` 的某些实现也可能在 `_pm_save_flag` 非零时调用它。

未实现电源管理指令的架构可以立即返回；否则应执行节能指令，等待中断。

说明（Note）：预期在使 CPU 退出节能模式的中断已经处理后才返回，但这不是严格要求。

另见（See Also）：`k_cpu_idle()`。

<a id="gadc25c1301f4fa3496361d0750c09cf4f"></a>

### `arch_pm_state_set_finish()`

```c
void arch_pm_state_set_finish ( unsigned int key)
```

```c
#include <zephyr/arch/arch_interface.h>
```

离开系统电源管理状态后恢复中断状态。

此钩子将 `arch_pm_state_set_prepare()` 准备的中断状态恢复为 PM 核心期望的锁定状态。原始空闲线程的中断键仍由空闲路径持有，在 PM 恢复记账完成后才恢复。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `key` | `arch_pm_state_set_prepare()` 返回的架构专有键。 |

<a id="gab5e5f1690ef60723890b3d0b40b126d7"></a>

### `arch_pm_state_set_prepare()`

```c
unsigned int arch_pm_state_set_prepare ( void )
```

```c
#include <zephyr/arch/arch_interface.h>
```

进入系统电源管理状态（PM State）前准备中断状态。

此钩子由 SoC PM 实现调用；这些实现会在系统 PM 恢复期间保持 IRQ 分派被阻止。调用时中断已锁定，应紧挨着低功耗指令之前调用。架构可借此允许挂起的唤醒事件使 CPU 退出低功耗指令，同时不让普通中断处理函数在 PM 恢复记账之前运行。

尽管名称如此，它并不是 `pm_state_set()` 边界钩子。SoC 代码应把调用紧贴低功耗指令（通常是 WFI）前后安排，以尽量缩短严格屏蔽中断的时间窗口。

返回（Returns）：要传给 `arch_pm_state_set_finish()` 的架构专有键。

## 6.3\_源码定位与版本边界

源码定位：[include/zephyr/arch/arch_interface.h](../../../include/zephyr/arch/arch_interface.h)、[arch/arm/core/cortex_m/cpu_idle.c](../../../arch/arm/core/cortex_m/cpu_idle.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库内源码采用相对链接，架构实现举例不表示全部架构都具有相同硬件能力，也不表示已在目标板执行验证。

> 译注——源码核对：CPU空闲（Idle）入口与系统电源策略选择的深度低功耗状态不是同一个层次。当前Cortex-M实现使用WFI／WFE并配合SEVONPEND、屏障和中断掩码；是否能进入某个SoC低功耗状态、唤醒源与唤醒延迟仍取决于目标实现。

> 译注——源码核对：arch_cpu_atomic_idle接收的中断锁定键（Interrupt Lock Key）具有状态恢复语义，不能替换成任意常量。Cortex-M主线实现临时组合PRIMASK与BASEPRI，在睡眠前后按要求恢复状态，不能把该过程简化为无条件开中断。

> 译注——源码核对：当前特定CONFIG_PM条件下的准备／结束钩子保存并恢复BASEPRI，配合PRIMASK控制处理程序进入时机；它们服务于电源管理核心已持有的锁定上下文。原文中的历史辅助符号和调用示例按原样保留，不代表当前源码仍逐字使用相同内部名称。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
