## 14.2\_详细说明（Detailed Documentation）

<a id="ga582ebea3e0d18285840bf277c5382da6"></a>

### `CBPRINTF_PACKAGE_CONVERT_KEEP_RO_STR`

```c
#define CBPRINTF_PACKAGE_CONVERT_KEEP_RO_STR BIT(2)
```

```c
#include <zephyr/sys/cbprintf.h>
```

在包中保留只读位置索引。

设置后，复制时保留包中的只读字符串指针；否则丢弃它们。

> 译注——源码核对：KEEP_RO_STR保留的是只读字符串位置索引，不是把字符串内容追加进去。对已有只读索引，当前实现先判断KEEP_RO_STR，再判断RO_STR；同时设置时会保留这些索引。需要完全自包含时，fsc包装器采用RO_STR和RW_STR，不设置KEEP_RO_STR。

<a id="ga370563f835488868020effcd48b23b90"></a>

### `CBPRINTF_PACKAGE_CONVERT_PTR_CHECK`

```c
#define CBPRINTF_PACKAGE_CONVERT_PTR_CHECK BIT(3)
```

```c
#include <zephyr/sys/cbprintf.h>
```

检查格式字符串中用于%p的参数是否被当成%s打包。

静态打包只根据格式字符串所用参数的类型进行，不检查字符串内的格式说明符。因此，若将(unsigned) char指针用于%p，会将其视为字符串位置，转换时可能尝试把字符串追加到包内。这可能导致错误行为：较轻时包变大，严重时可能触发内存故障（Memory Fault）或安全违规（Security Violation）。

设置此标志后，会检查格式字符串，识别实际上用于%p的字符串候选指针，避免从意外位置追加字符串。同时生成日志警告，提示将此类参数转换为void *。建议采用这种转换，因为某些配置下格式字符串不可访问，无法检查，也就无法识别这种情况。

> 译注——源码核对：PTR_CHECK原说明按传入标志描述启用检查；本次实现实际在CONFIG_CBPRINTF_CONVERT_CHECK_PTR启用且cb非NULL时调用is_ptr，条件中没有检查PTR_CHECK位。因此计算长度与实际复制可能走不同的指针识别路径。用于%p的字符指针应按官方建议转换为void *，不要只依赖该标志。

<a id="ga9802b700abd5d3cd7cef0e0cbcceb3e7"></a>

### `CBPRINTF_PACKAGE_CONVERT_RO_STR`

```c
#define CBPRINTF_PACKAGE_CONVERT_RO_STR BIT(0)
```

```c
#include <zephyr/sys/cbprintf.h>
```

将源包中的只读字符串追加到目标包。

若包以CBPRINTF_PACKAGE_ADD_RO_STR_POS或CBPRINTF_PACKAGE_ADD_RW_STR_POS创建，其中会包含可在包内找到字符串地址的索引数组。设置此标志后，只读字符串复制到目标包；也会检查标记为可读写的字符串地址，若判定实际只读，同样予以复制。

<a id="ga983c65ed8afb356a29fa2736f9de7b39"></a>

### `CBPRINTF_PACKAGE_CONVERT_RW_STR`

```c
#define CBPRINTF_PACKAGE_CONVERT_RW_STR BIT(1)
```

```c
#include <zephyr/sys/cbprintf.h>
```

将源包中的可读写字符串追加到目标包。

若包以CBPRINTF_PACKAGE_ADD_RW_STR_POS创建，其中会包含可在包内找到字符串地址的索引数组。设置此标志后，检查可读写字符串列表，并把未被判定为只读的字符串复制到目标包。若未设置CBPRINTF_PACKAGE_CONVERT_RO_STR，其余字符串位置视为指向只读存储区，并在设置CBPRINTF_PACKAGE_CONVERT_KEEP_RO_STR时复制到包中。

本册提供[公共API](P001_回调格式化输出接口.md)、[创建标志](P013_格式化包创建标志.md)、[转换标志](P014_格式化包转换标志.md)以及四份头文件的参考与源码。相对定位：[cbprintf.h](../../../include/zephyr/sys/cbprintf.h)、[参数标签](../../../include/zephyr/sys/cbprintf_enums.h)、[内部工具](../../../include/zephyr/sys/cbprintf_internal.h)、[C++工具](../../../include/zephyr/sys/cbprintf_cxx.h)。

实现与配置：[包装器](../../../lib/os/cbprintf.c)、[打包实现](../../../lib/os/cbprintf_packaged.c)、[完整格式化器](../../../lib/os/cbprintf_complete.c)、[Nano格式化器](../../../lib/os/cbprintf_nano.c)、[Kconfig](../../../lib/os/Kconfig.cbprintf)、[构建规则](../../../lib/os/CMakeLists.txt)。本次[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/cbprintf.h)与[官方打包实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/os/cbprintf_packaged.c)等文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：职责：cbprintf通过回调逐字符输出；package接口捕获格式字符串和参数，稍后再格式化。打包不等于已经得到文本，打包函数返回包字节数，输出函数返回字符数。两者的缓冲区大小、错误路径与生命周期不能混用。

> 译注——源码核对：版本：本册核对本次官方main头文件与实现，原文和代码保持原样，差异另列译注。仓库内的相对源码链接用于定位，不保证任意本地版本与滚动更新的latest一致。

> 译注——源码核对：原convert接口的strl说明借用了packaged这一名称，但该函数没有此参数。当前实现以cb是否为NULL区分长度计算与实际输出；package_copy包装器才以目标packaged是否为NULL选择回调。

> 译注——源码核对：KEEP_RO_STR保留的是只读字符串位置索引，不是把字符串内容追加进去。对已有只读索引，当前实现先判断KEEP_RO_STR，再判断RO_STR；同时设置时会保留这些索引。需要完全自包含时，fsc包装器采用RO_STR和RW_STR，不设置KEEP_RO_STR。

> 译注——源码核对：PTR_CHECK原说明按传入标志描述启用检查；本次实现实际在CONFIG_CBPRINTF_CONVERT_CHECK_PTR启用且cb非NULL时调用is_ptr，条件中没有检查PTR_CHECK位。因此计算长度与实际复制可能走不同的指针识别路径。用于%p的字符指针应按官方建议转换为void *，不要只依赖该标志。

> 译注——源码核对：错误传播差异：没有字符串需要追加时，当前快速路径忽略数据回调的返回值，并返回输入长度；结束时的cb(NULL,0,ctx)返回值也被忽略。package_copy的复制回调可能返回-ENOSPC，但快速路径不传递它，因此不能只看正返回值认定数据已复制。先计算并提供充足空间；一般转换路径只检查回调负值，不会自动重试短写。

> 译注——源码核对：fsc接口文档列出输入NULL的-EINVAL，但包装器最终进入仅以断言检查输入非空的convert；启用带标签参数时cbpprintf也可能在下层NULL检查前读取包头。不要把这些返回说明当作任意空指针输入都受保护的保证。错误发生前可能已输出部分数据或修改目标，没有事务性回滚。
