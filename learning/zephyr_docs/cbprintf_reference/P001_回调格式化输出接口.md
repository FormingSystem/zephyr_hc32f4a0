## 1.5\_详细说明（Detailed Documentation）

### `CBPRINTF_MUST_RUNTIME_PACKAGE`

```c
#define CBPRINTF_MUST_RUNTIME_PACKAGE ( flags, ... )
```

```c
#include <zephyr/sys/cbprintf.h>
```

展开值（Value）：

```c
Z_CBPRINTF_MUST_RUNTIME_PACKAGE(flags, __VA_ARGS__)
```

判断字符串是否必须在运行时打包（Runtime Packaging）。

如果能在编译时确定包大小，就可以采用静态打包。通常，当没有可能因被视为临时字符串（Transient String）而复制到包体中的字符串参数时，包大小即可在编译时确定。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `...` | 字符串及其参数。 |
| `flags` | 选项标志，参见包创建标志（Package Flags）。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `1` | 字符串必须在运行时打包时。 |
| `0` | 字符串可以静态打包时。 |

**说明（Note）**：默认将所有char指针视为指向临时字符串。使用CBPRINTF_PACKAGE_CONST_CHAR_RO可将这一范围缩小到非const指针。

### `CBPRINTF_STATIC_PACKAGE`

```c
#define CBPRINTF_STATIC_PACKAGE ( packaged, inlen, outlen, align_offset, flags, ... )
```

```c
#include <zephyr/sys/cbprintf.h>
```

展开值（Value）：

```c
Z_CBPRINTF_STATIC_PACKAGE(packaged, inlen, outlen, \
                          align_offset, flags, __VA_ARGS__)
```

静态打包（Static Packaging）字符串。

根据格式字符串构建字符串包，假定格式字符串位于只读存储器（Read-only Memory）。

如果不支持_Generic，则执行运行时打包。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `packaged` | 指向可存储打包数据的位置。传入空指针可跳过存储但仍计算所需总空间。数据可重定位（Relocatable），即可以移动到另一块连续存储区；地址必须按最长参数的大小对齐，建议使用CBPRINTF_PACKAGE_ALIGNMENT。 |
| `inlen` | packaged处可用的字节数。packaged为NULL时忽略此值。 |
| `outlen` | 用于接收完整存储打包信息所需字节数的变量；输入缓冲区太小时置为-ENOSPC。 |
| `align_offset` | 输入缓冲区的对齐偏移，以字节为单位。偏移0表示按CBPRINTF_PACKAGE_ALIGNMENT对齐。Xtensa要求packaged按CBPRINTF_PACKAGE_ALIGNMENT对齐，因此偏移必须为其整数倍或0。 |
| `flags` | 选项标志，参见包创建标志（Package Flags）。 |
| `...` | 格式字符串及参数；格式字符串必须为常量。 |

> 译注——源码核对：当前静态宏检测到可读写字符串参数而未设置ADD_RW_STR_POS时，outlen置-EINVAL。其参数存储先检查起始偏移小于容量，再写完整参数；尾部位置数组也在最终总容量检查之前写入。因此不要故意用不足容量的缓冲区试探长度：先以NULL查询，再按相同对齐提供足量空间。-ENOSPC不是当前实现所有写入均受边界保护的证明。

### `cbprintf()`

```c
int cbprintf ( cbprintf_cb out, void * ctx, const char * format, ... )
```

```c
#include <zephyr/sys/cbprintf.h>
```

通过回调提供类似*printf的输出。

此函数本质上类似printf()，但通过提供的out函数逐字符输出。因此可格式化任意长度的文本，而无需为完整输出分配临时缓冲区。

识别C99的所有格式说明符（Format Specifiers），在相应功能启用时支持其中大部分。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `out` | 用于输出每个生成字符的函数。 |
| `ctx` | 调用out时提供的上下文。 |
| `format` | 标准ISO C格式字符串，包含普通字符与转换说明（Conversion Specifications）。 |
| `...` | 与format中的转换说明对应的参数。 |

**说明（Note）**：选择CONFIG_CBPRINTF_NANO后，此函数的功能会显著缩减。

**返回（Returns）**：已打印的字符数，或调用out得到的负错误值。

### `cbprintf_fsc_package()`

```c
int cbprintf_fsc_package ( void * in_packaged, size_t in_len, void * packaged, size_t len )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/cbprintf.h>
```

将包转换为完全自包含包（Fully Self-contained，FSC）。

字符串默认按地址保存，因此包可能并不自包含。把临时字符串，即非只读字符串，追加到包后，可形成部分自包含包；仅当还能访问只读字符串时，才能解码这种包。

完全自包含包包含包中使用的全部字符串。以CBPRINTF_PACKAGE_ADD_RO_STR_POS标志创建的包可转换为FSC包：其中包含定位只读字符串并将其复制到包体所需的信息。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `in_packaged` | 指向使用CBPRINTF_PACKAGE_ADD_RO_STR_POS创建的原始包。 |
| `in_len` | in_packaged的长度。 |
| `packaged` | 指向写入输入包之完全自包含版本的位置；传入空指针可只计算所需空间。 |
| `len` | packaged处可用的字节数；packaged为空时不使用。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 成功存入packaged的字节数，不超过len；packaged为空时为计算出的长度。 |
| `-ENOSPC` | packaged非空，且存储所需空间超过len时。 |
| `-EINVAL` | in_packaged为空时。 |

> 译注——源码核对：fsc接口文档列出输入NULL的-EINVAL，但包装器最终进入仅以断言检查输入非空的convert；启用带标签参数时cbpprintf也可能在下层NULL检查前读取包头。不要把这些返回说明当作任意空指针输入都受保护的保证。错误发生前可能已输出部分数据或修改目标，没有事务性回滚。

### `cbprintf_package_convert()`

```c
int cbprintf_package_convert ( void * in_packaged, size_t in_len, cbprintf_convert_cb cb, void * ctx, uint32_t flags, uint16_t * strl, size_t strl_len )
```

```c
#include <zephyr/sys/cbprintf.h>
```

转换格式化包（Package）。

转换可包括把包中使用的字符串追加到包体。若输入包使用CBPRINTF_PACKAGE_ADD_RO_STR_POS或CBPRINTF_PACKAGE_ADD_RW_STR_POS创建，其中会包含字符串在包内的位置资料，可据此在转换期间复制字符串。

cb会分段接收输出包；转换结束时，cb还会收到一次缓冲区为空的调用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| ` in_packaged` | 输入包。 |
| ` in_len` | 输入包长度；若为0，则从in_packaged中取得包长度。 |
| ` cb` | 分段接收转换后包的回调；为空时只计算输出包长度。 |
| ` ctx` | 传给cb的上下文。 |
| ` flags` | 标志，参见包转换标志（Package Convert Flags）。 |
| `[in,out] strl` | packaged为空时，指向用于保存前strl_len个字符串长度的数组；packaged非空时，数组包含这些字符串的长度。这样可以只在packaged为空的长度计算阶段测量一次字符串长度，以优化复制。 |
| ` strl_len` | strl数组的元素数。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 输出包大小。 |
| `-ENOSPC` | packaged非空，且存储所需空间超过len时。 |

> 译注——源码核对：原convert接口的strl说明借用了packaged这一名称，但该函数没有此参数。当前实现以cb是否为NULL区分长度计算与实际输出；package_copy包装器才以目标packaged是否为NULL选择回调。 错误传播差异：没有字符串需要追加时，当前快速路径忽略数据回调的返回值，并返回输入长度；结束时的cb(NULL,0,ctx)返回值也被忽略。package_copy的复制回调可能返回-ENOSPC，但快速路径不传递它，因此不能只看正返回值认定数据已复制。先计算并提供充足空间；一般转换路径只检查回调负值，不会自动重试短写。

> 译注——源码核对：生命周期（Lifetime）：默认保留只读字符串地址，追加需要保存的临时字符串；ADD_RW_STR_POS改为记录位置后，相关字符串仍须有效，直到完成转换或输出。const只表示类型限定，CONST_CHAR_RO及FIRST_RO_STR_CNT是调用者作出的只读／有效性承诺，不会延长局部数组、可释放缓冲区或映射区域的寿命。

> 译注——源码核对：可移植性：完全自包含（Fully Self-contained）只解决字符串内容依赖。包仍包含本机参数表示、指针大小、ABI布局及平台对齐，不能直接作为跨架构、跨固件版本或不可信网络数据的通用序列化格式。复制后须保持原来的对齐关系。

> 译注——源码核对：输出会修改包内指针，使已追加字符串的参数地址指向当前位置，因此包需要可写存储。不要把同一包无同步交给多个输出调用，也不能因“非破坏”措辞就把包放入只读区域。原始只读字符串在被追加之前仍须可访问。

> 译注——源码核对：长度查询：cbprintf_package与cbvprintf_package最终进入同一运行时实现。packaged为NULL时len表示假想对齐偏移，并非总被忽略；原cbvprintf_package参数说明称忽略len，当前源码与此有差异。查询和实际写入须采用一致的对齐、配置、格式及参数，并保持字符串内容稳定。

> 译注——源码核对：容量边界：描述符len是参数区连同包头的32位字数，不含尾部位置资料与字符串，不能直接当作总字节数。运行时实现限制参数区不超过8位字数，并使用16项字符串位置数组；转换路径对只读索引数加两倍可读写索引数施加32项限制。不能据逐字符输出可不预分配完整文本，推断打包没有大小上限。

> 译注——源码核对：输入前提：转换和输出按包头及内部索引读取参数，in_len=0时还会扫描已有字符串；这些接口没有完整的不可信包边界校验。传入有效、完整、来源可信的包，源与目标存储不要重叠。长度缓存strl采用uint16_t，包含字符串结尾空字节，使用时也须保证长度可表达且内容未变。

> 译注——源码核对：原convert接口的strl说明借用了packaged这一名称，但该函数没有此参数。当前实现以cb是否为NULL区分长度计算与实际输出；package_copy包装器才以目标packaged是否为NULL选择回调。

> 译注——源码核对：KEEP_RO_STR保留的是只读字符串位置索引，不是把字符串内容追加进去。对已有只读索引，当前实现先判断KEEP_RO_STR，再判断RO_STR；同时设置时会保留这些索引。需要完全自包含时，fsc包装器采用RO_STR和RW_STR，不设置KEEP_RO_STR。

> 译注——源码核对：PTR_CHECK原说明按传入标志描述启用检查；本次实现实际在CONFIG_CBPRINTF_CONVERT_CHECK_PTR启用且cb非NULL时调用is_ptr，条件中没有检查PTR_CHECK位。因此计算长度与实际复制可能走不同的指针识别路径。用于%p的字符指针应按官方建议转换为void *，不要只依赖该标志。

> 译注——源码核对：错误传播差异：没有字符串需要追加时，当前快速路径忽略数据回调的返回值，并返回输入长度；结束时的cb(NULL,0,ctx)返回值也被忽略。package_copy的复制回调可能返回-ENOSPC，但快速路径不传递它，因此不能只看正返回值认定数据已复制。先计算并提供充足空间；一般转换路径只检查回调负值，不会自动重试短写。

> 译注——源码核对：fsc接口文档列出输入NULL的-EINVAL，但包装器最终进入仅以断言检查输入非空的convert；启用带标签参数时cbpprintf也可能在下层NULL检查前读取包头。不要把这些返回说明当作任意空指针输入都受保护的保证。错误发生前可能已输出部分数据或修改目标，没有事务性回滚。

> 译注——源码核对：静态打包（Static Packaging）按类型推导布局，不代表写包动作在编译时完成。当前宏在运行时把实参值写入调用者提供的内存；C使用_Generic，C++使用重载和模板。字符指针用于%p时应转为void *，避免被识别为字符串候选。

> 译注——源码核对：当前静态宏检测到可读写字符串参数而未设置ADD_RW_STR_POS时，outlen置-EINVAL。其参数存储先检查起始偏移小于容量，再写完整参数；尾部位置数组也在最终总容量检查之前写入。因此不要故意用不足容量的缓冲区试探长度：先以NULL查询，再按相同对齐提供足量空间。-ENOSPC不是当前实现所有写入均受边界保护的证明。

> 译注——源码核对：FIRST_RO_STR_CNT使用3位计数，调用者应保持n在0至7内；宏本身不先屏蔽任意大的n。格式字符串隐含为只读，不计入这里的n。long double、各架构栈对齐与创建标志存储均受配置影响，不能固定假设所有包头只有一个指针宽度。

> 译注——源码核对：带标签参数（Tagged Arguments）要求相应配置和匹配的类型标签／值序列，普通va_list不能直接按带标签列表解释。内部枚举、Z_宏及C++辅助模板用于实现公共接口，不能据源码浏览页的可见性认定它们是稳定的独立应用API。

> 译注——源码核对：配置边界：完整与Nano格式化器由构建选择，整数宽度、浮点、%a和%n另受配置控制。当前头文件中的cbvprintf本身不受CONFIG_CBPRINTF_LIBC_SUBSTS包围，原说明的“仅此配置可用”不能推广为当前实现事实；该配置控制带cb后缀的libc兼容入口。

> 译注——源码核对：Picolibc路径不同：启用Picolibc时，带cb后缀的兼容入口在头文件中映射到标准stdio函数，构建规则不加入普通cbprintf.c包装器。不能把所有配置都描述成必然绕开libc格式化器。

> 译注——源码核对：snprintfcb／vsnprintfcb返回本应生成的字符数，不含结尾空字节；目标过小时，实际保留字符更少。先确认返回值非负，再与size比较判断截断。size为0可用于长度查询，size非0时目标须有效；逐字符回调仍须承担设备阻塞、同步及错误处理。
