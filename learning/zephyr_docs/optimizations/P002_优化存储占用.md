# 第2章\_优化存储占用

原文：[Optimizing for Footprint](https://docs.zephyrproject.org/latest/develop/optimizations/footprint.html)。读取日期：2026-10-12，`latest`。

Zephyr 面向多种平台和应用，通用默认配置可能预留了当前应用并不需要的空间。优化**存储占用（Footprint）**时，可以先检查系统栈和外设，再考虑调试及内存保护功能的取舍。

## 2.1\_检查系统栈大小

各系统线程的**栈（Stack）**大小默认设置得较宽裕，以支持尽可能多的平台和使用场景。优化应从检查所有栈大小开始，再根据应用需要调整。

原文列出的配置与默认大小如下，单位为字节：

| 配置项 | 对象与原文默认值 |
| --- | --- |
| [`CONFIG_ISR_STACK_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ISR_STACK_SIZE) | **中断服务程序（Interrupt Service Routine，ISR）**使用的栈，默认 2048。 |
| [`CONFIG_MAIN_STACK_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MAIN_STACK_SIZE) | 主线程栈，默认 1024。 |
| [`CONFIG_IDLE_STACK_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_IDLE_STACK_SIZE) | **空闲线程（Idle Thread）**栈，原文列为默认 320。 |
| [`CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SYSTEM_WORKQUEUE_STACK_SIZE) | **系统工作队列（System Workqueue）**线程栈，默认 1024。该线程执行提交给系统工作队列的工作项。 |
| [`CONFIG_PRIVILEGED_STACK_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_PRIVILEGED_STACK_SIZE) | **特权栈（Privileged Stack）**，默认 1024，依赖**用户空间（Userspace）**功能。 |

> 译注：这些是原文概括的默认数值，不是所有板、架构和配置的最终值。仓库 `kernel/Kconfig` 中的空闲栈默认值就有多个条件分支，无条件后备值为 256；架构还可能另外覆盖。以当前构建生成的 `build/zephyr/.config` 为准。特权栈是在用户线程栈之外、用于系统调用等特权执行的区域；不能将其与主线程栈混为同一项。减小数值后仍需验证最深调用路径和相应运行场景，静态改小不代表已经验证可用。

## 2.2\_关闭未使用的外设支持

某些外设默认启用，可以在应用配置中关闭未使用的功能。例如 `CONFIG_GPIO` 控制**通用输入输出（General-Purpose Input/Output，GPIO）**支持，`CONFIG_SPI` 控制**串行外设接口（Serial Peripheral Interface，SPI）**支持：

```kconfig
CONFIG_GPIO=n
CONFIG_SPI=n
```

> 译注：这是应用配置文件（例如 `prj.conf`）的内容，不是终端命令。确认应用及其依赖不需要这些接口后再选择性关闭；重新配置构建时若出现依赖错误，应返回检查被关闭功能的使用者。

## 2.3\_调试与信息输出选项

以下选项为运行中的应用提供信息输出、调试和错误处理能力：

| 配置项 | 作用与取舍 |
| --- | --- |
| [`CONFIG_BOOT_BANNER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BOOT_BANNER) | 控制启动横幅，默认启用；关闭可节省少量字节。 |
| [`CONFIG_DEBUG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DEBUG) | 可在调试构建中启用。 |

## 2.4\_内存保护功能的取舍

根据应用和平台需求，可以关闭**内存保护单元（Memory Protection Unit，MPU）**或**内存管理单元（Memory Management Unit，MMU）**支持，节省部分内存并改善性能。但是必须考虑后果：高级栈检查及相关支持也会失去。

> 译注：原文是在说明可选取舍，并非对所有应用推荐关闭保护。MPU 用于按区域实施访问保护，MMU 可提供地址映射和保护；平台能否关闭及依赖影响，应按当前架构配置判断。
