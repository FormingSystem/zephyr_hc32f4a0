# 第6章\_术语表

原文：[Glossary of Terms](https://docs.zephyrproject.org/latest/glossary.html)。译文基线：2026-10-12 的 `latest` 页面。本页保留全部词条及英文检索顺序；它是一份参考表，不要求先通读并记忆后再操作。

## 6.1\_API：应用程序接口

**应用程序编程接口（Application Programming Interface，API；原词条写作 Application Program Interface）** 是为构建应用软件而定义的一组例程与协议。

## 6.2\_application：应用

由用户提供、被 Zephyr 构建系统用于为指定开发板配置生成应用镜像的一组文件。它可以包含应用专用代码、内核配置设置，以及至少一个 `CMakeLists.txt` 文件。应用的内核配置指导构建系统生成定制内核，以有效利用开发板资源。

如果应用不依赖特定开发板独有的能力，有时可以为多种开发板配置构建，甚至可以跨处理器架构。

## 6.3\_application image：应用镜像

加载到目标开发板并在其上执行的二进制文件。每个应用镜像既包含应用代码，也包含支持该应用所需的 Zephyr 内核代码；两者被编译、链接为一个完整二进制文件。

镜像加载到开发板后，会接管系统、完成初始化，并作为系统唯一的应用运行。原文接着说明：应用代码与内核代码在同一共享地址空间中，以特权代码运行。

> 译注：上一句是该术语页保留的整体镜像描述，不应扩大解释为“Zephyr 所有应用线程只能以特权模式运行”。介绍页已提及用户空间和内存保护；需要用户模式隔离时应查[用户模式文档](https://docs.zephyrproject.org/latest/kernel/usermode/index.html)，并以具体架构和配置为准。

## 6.4\_architecture：架构

**指令集架构（Instruction Set Architecture，ISA）**及其编程模型。

## 6.5\_board：开发板

具有已定义设备与能力、能够加载并执行应用镜像的目标系统。它既可以是实际硬件，也可以是运行在 QEMU 下的模拟系统。一块开发板可以包含一个或多个 **片上系统（System on Chip，SoC）**。Zephyr 内核支持[多种开发板](https://docs.zephyrproject.org/latest/boards/index.html)。

## 6.6\_board configuration：开发板配置

用于指定内核如何使用开发板设备的一组内核配置选项。Zephyr 构建系统为每块受支持开发板定义一个或多个配置；应用可按需要覆盖构建系统指定的内核设置。

## 6.7\_board name：开发板名称

供人阅读的开发板名称，用来唯一且清楚地标识某个系统，但不包含构建其 Zephyr 镜像可能还需要的附加信息。详情见[开发板术语](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html#board-terminology)。

## 6.8\_board qualifiers：开发板限定符

跟在开发板名称以及可选修订版本之后、用正斜杠 `/` 分隔的一组附加标记。它们共同构成完整的开发板目标。目前接受的限定符包括 SoC、处理器簇和变体。详情见[开发板术语](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html#board-terminology)。

## 6.9\_board revision：开发板修订版本

用于标识硬件系统特定修订的可选版本字符串。当硬件只发生小幅变化时，可避免重复创建整套开发板文件。详情见[多修订版本支持](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html#multiple-board-revisions)和[为指定修订版本构建](https://docs.zephyrproject.org/latest/develop/application/index.html#building-for-a-board-revision)。

<a id="term-board-target"></a>

## 6.10\_board target：开发板目标

可传给 Zephyr 构建工具、用于为某个硬件系统编译并链接镜像的完整字符串。它唯一确定开发板名称、修订版本和限定符的组合。详情见[开发板术语](https://docs.zephyrproject.org/latest/hardware/porting/board_porting.html#board-terminology)。

## 6.11\_CPU cluster：处理器簇

由一个或多个处理器核组成的一组处理单元。它们在同一地址空间内、以**对称多处理（Symmetric Multiprocessing，SMP）**配置执行同一镜像。只有相同架构的处理器核才能组成同一处理器簇。一个 SoC 可以同时容纳多个处理器簇，每个簇又可有一个或多个核。

## 6.12\_CPU core：处理器核

具有自己的程序计数器、顺序执行程序指令的单个处理单元。处理器核属于某个处理器簇，后者可以包含一个或多个核。

## 6.13\_device runtime power management：设备运行时电源管理

设备运行时**电源管理（Power Management，PM）**指设备独立于系统电源状态进行节能的能力。设备跟踪自身的使用情况，并自动挂起或恢复。通过 Kconfig 选项 `CONFIG_PM_DEVICE_RUNTIME` 启用此功能。

## 6.14\_idle thread：空闲线程

没有其他线程处于就绪状态时运行的系统线程。

## 6.15\_IDT：中断描述符表

中断描述符表（Interrupt Descriptor Table，IDT）是 x86 架构用于实现中断向量表的数据结构，用来确定对中断和异常的正确响应。

## 6.16\_internal API：内部接口

Zephyr 源码树中用于内部目的的函数、结构或宏。内部接口用于“扩展”Zephyr，只应在特定软件组件之间使用。通常这些组件位于源码树内，但也存在树外组件，例如新增的树外架构或驱动。应用不能超出自身适用范围调用内部接口；接口被调用或实现的上下文有明确规定。

例如，前缀为 `arch_` 的函数供 Zephyr 内核调用架构相关代码。内部接口大体保持稳定，但稳定性保证弱于公共接口。

## 6.17\_ISR：中断服务例程

**中断服务例程（Interrupt Service Routine，ISR）**，也称中断处理程序，是一个由硬件中断或软件中断指令触发执行的回调函数。它处理需要中断当前处理器执行流程的高优先级情况。

## 6.18\_kernel：内核

由 Zephyr 提供、用于实现 Zephyr 内核的一组文件，包括核心服务、设备驱动、网络协议栈等。

## 6.19\_power domain：电源域

在一次操作中统一供电或断电的一组设备。Zephyr 使用 `device` 表示电源域。

## 6.20\_power gating：电源门控

通过关闭集成电路中当前不用的区域来降低功耗。

## 6.21\_private API：私有接口

在 Zephyr 源码树中定义、仅供其所属软件组件内部使用的函数、结构或宏。私有接口可能随时变化，组件外部代码不得使用。

<a id="term-public-API"></a>

## 6.22\_public API：公共接口

定义在 `include/zephyr` 目录中、且没有明确标记为私有的函数、结构或宏。公共接口面向源码树内外的所有软件组件。

修改公共接口必须遵循 [API 生命周期](https://docs.zephyrproject.org/latest/develop/api/api_lifecycle.html)规定，因此它们提供随时间维持稳定的保证。

## 6.23\_SoC：片上系统

片上系统（System on a Chip，SoC）是一种集成电路，至少包含一个处理器簇，而该簇至少具有一个处理器核，同时还包含外设和存储器。

## 6.24\_SoC family：SoC家族

由一个或多个 SoC，或一个或多个 SoC 系列构成；它们具有足够多的共性，因此被认为彼此相关，并归入同一族名。

## 6.25\_SoC series：SoC系列

一组具有相似特征和功能的不同 SoC，厂商通常将它们以共同系列名称命名和推广。

## 6.26\_software component：软件组件

Zephyr 源码中自包含、模块化且可替换的部分。驱动、子系统和应用都是软件组件的例子。

## 6.27\_subsystem：子系统

操作系统中逻辑上相对独立、处理特定功能或提供特定服务的部分。

## 6.28\_system power state：系统电源状态

描述整个系统功耗的状态，使用 `pm_state` 表示。

## 6.29\_variant：变体

在开发板限定符中，变体表示某个 SoC 与处理器簇组合下的一种构建类型或配置。常见用途包括：在支持可信执行环境的平台上区分安全和非安全构建，或者选择构建使用的 **随机存取存储器（Random Access Memory，RAM）** 类型。

## 6.30\_west

为 Zephyr 项目开发的多仓库元工具。详细说明见 [West](https://docs.zephyrproject.org/latest/develop/west/index.html)。

## 6.31\_west installation：旧称

west 0.7 以前用于指代 west 工作区的术语，现已废弃。

## 6.32\_west manifest：west清单

通常名为 `west.yml` 的 YAML 文件，描述构成 west 工作区的各项目，即 Git 仓库，以及附加元数据。一般介绍见 [Basics](https://docs.zephyrproject.org/latest/develop/west/basics.html)，详细说明见 [West Manifests](https://docs.zephyrproject.org/latest/develop/west/manifest.html)。

## 6.33\_west manifest repository：west清单仓库

west 工作区中包含清单文件的 Git 仓库。其位置由 `manifest.path` 配置项给出。详情见 [Basics](https://docs.zephyrproject.org/latest/develop/west/basics.html)。

## 6.34\_west project：west项目

west 清单中的每个项目条目，用来描述一个 Git 仓库。使用相应清单仓库工作时，这些仓库由 west 克隆和管理。

west 项目与 Zephyr 模块不是同一个概念，尽管很多项目同时也是模块。详情见 [Projects](https://docs.zephyrproject.org/latest/develop/west/manifest.html#west-manifests-projects)。

## 6.35\_west workspace：west工作区

系统上的一个目录，其中包含 `.west` 子目录和清单仓库。用 `west init` 创建工作区时，会把 Zephyr 源码及其 west 项目源码克隆到系统中。详情见 [Basics](https://docs.zephyrproject.org/latest/develop/west/basics.html)。

> 译注：这里沿用术语页的整体描述；实际命令分工在入门指南中更明确：`west init` 初始化并取得清单仓库，`west update` 再取得清单列出的项目。

## 6.36\_XIP：就地执行

就地执行（eXecute In Place，XIP）指直接从长期存储器执行程序，而不是先复制到 RAM。这样可以把可写内存留给动态数据，而不用于存放静态程序代码。

## 6.37\_zephyr module：Zephyr模块

包含 `zephyr/module.yml` 文件的 Git 仓库。Zephyr 构建系统使用该文件，将模块的源码和配置文件整合到常规构建中。Zephyr 模块可以是 west 项目，但并非必须如此。详情见 [Modules](https://docs.zephyrproject.org/latest/develop/modules.html)。
