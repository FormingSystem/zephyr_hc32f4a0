# 第3章\_入门之后

原文：[Beyond the Getting Started Guide](https://docs.zephyrproject.org/latest/develop/beyond-GSG.html)。译文基线：2026-10-12 的 `latest` 页面。

[入门指南](P002_入门指南.md)给出在 Linux、macOS 或 Windows 上建立 Zephyr 开发环境的直接路线。本文进一步讨论开发环境的配置问题及替代方案。

> 译注：本章承接官方 `zephyrproject` 示例，默认已经取得源码、工具并激活虚拟环境。下面的更新、别名和模拟运行是不同用途的分支，不应连续粘贴执行。

<a id="python-and-pip"></a>

## 3.1\_Python与pip

Zephyr 广泛使用 Python 3 及其包管理器 pip：安装和运行编译、执行应用所需的脚本，建立与维护开发环境，以及生成项目文档。

根据操作系统不同，安装新包时可能需要给 `pip3` 添加 `--user`。各处安装说明会注明是否需要。详情见 Python Packaging User Guide 的[安装软件包](https://packaging.python.org/en/latest/tutorials/installing-packages/)，其中也解释了用户级安装。

- **Linux**：确保 `~/.local/bin` 位于 `PATH` 前部，否则找不到通过 `--user` 安装的程序。原文说明，使用 `--user` 可避免 pip 与系统包管理器之间的冲突，并称它是基于 Debian 的发行版上的默认方式。
- **macOS**：原文称 Homebrew 禁用了 `--user`，并链接到 Homebrew 的 Python 说明。
- **Windows**：如果必须使用此选项，参照上面的 Python 软件包安装说明。

所有系统中，pip 的 `-U` 选项会安装软件包，或者在已有包但有新版本时进行升级。如果确实需要最新版，使用该选项是合适的做法。具体版本约束应检查 Zephyr 的 [scripts/requirements.txt](https://github.com/zephyrproject-rtos/zephyr/blob/main/scripts/requirements.txt)。

> 译注：本段保留补充页的原文表述。Homebrew 原链接现已重定向，旧锚点不再存在；当前[Python 环境说明](https://docs.brew.sh/Language-Runtimes-and-Packages#python)要求把项目依赖装入虚拟环境，其基础 Python 环境按 PEP 668 标记为受外部管理。前章主线已经使用虚拟环境，不要向其机械添加 `--user`。发行版的系统 Python 管理策略可能使旧的用户级安装做法不再适用，应以当前发行版规则和前章虚拟环境路线为准。

## 3.3\_安装工具链

Zephyr 二进制程序通过由交叉编译器及相关工具组成的工具链编译、链接。这套工具不同于为主机操作系统开发原生软件时使用的编译器和工具。

可以安装 [Zephyr SDK](https://docs.zephyrproject.org/latest/develop/toolchains/zephyr_sdk.html)，获得各受支持架构的工具链；也可以安装芯片厂商或特定开发板推荐的[其他工具链](https://docs.zephyrproject.org/latest/develop/toolchains/index.html)，具体查对应开发板文档。

设置 `ZEPHYR_TOOLCHAIN_VARIANT` 等环境变量及所选工具链要求的附加变量，可指定构建系统使用哪种工具链。

## 3.4\_更新Zephyr SDK工具链

更新 **软件开发工具包（Software Development Kit，SDK）** 时，先检查是否已设置环境变量 `ZEPHYR_TOOLCHAIN_VARIANT` 或 `ZEPHYR_SDK_INSTALL_DIR`。

- **均未设置**：默认选择最新的兼容 SDK，无须修改这些变量。
- **已设置 `ZEPHYR_TOOLCHAIN_VARIANT`**：构建时选择对应工具链。Zephyr SDK 的值为 `zephyr`；如果当前值不是 `zephyr`，要选用 Zephyr SDK，就应取消该变量或将其改为 `zephyr`。
- **已设置 `ZEPHYR_SDK_INSTALL_DIR`**：该值覆盖 SDK 默认搜索位置。若 SDK 安装在[推荐位置](https://docs.zephyrproject.org/latest/develop/toolchains/zephyr_sdk.html)，可取消该变量；否则将其设为实际安装位置。

更多说明见[重要环境变量](https://docs.zephyrproject.org/latest/develop/env_vars.html)。

## 3.5\_克隆与更新Zephyr仓库

Zephyr 源码维护在 [GitHub zephyr 仓库](https://github.com/zephyrproject-rtos/zephyr)中，外部模块位于 [Zephyr GitHub 组织](https://github.com/zephyrproject-rtos)。存在这些依赖，因此使用 Zephyr 开发的 west 获取和管理主仓库及模块源码比较方便。基础概念见 [west Basics](https://docs.zephyrproject.org/latest/develop/west/basics.html)。

开发工具安装好之后，使用 west 创建、初始化工作区并下载主仓库和外部模块。这里使用 `zephyrproject`，也可另选名字，但整个路径都不能含空格。

以下是新建工作区的独立分支，在打算容纳该工作区的父目录执行：

```text
west init zephyrproject
cd zephyrproject
west update
```

`west update` 获取模块，并使 `zephyrproject` 内的模块与本地 Zephyr 仓库所要求的代码版本保持一致。

> 原文警告：每当 `zephyr/west.yml` 改变，都必须运行 `west update`。例如在 Zephyr 仓库中拉取更新、切换分支或执行 `git bisect` 后，清单可能改变。

> 译注：已经完成前章的读者跳过上面的初始化命令；它说明另一种起步写法，不是要求再次初始化。

### 3.5.1\_保持Zephyr更新

先使用 Git 获取 Zephyr 源码的最新变化，再运行 `west update`，并检查新增或更新的 Python 依赖。

Linux/macOS，在虚拟环境已激活的终端中执行：

```bash
# 将 zephyrproject 替换为当初传给 west init 的路径
cd zephyrproject/zephyr
git pull
west update
west packages pip --install
```

Windows 命令提示符：

```bat
:: 将 zephyrproject 替换为当初传给 west init 的路径
cd zephyrproject\zephyr
git pull
west update
cmd /c scripts\utils\west-packages-pip-install.cmd
```

Windows PowerShell：

```powershell
# 将 zephyrproject 替换为当初传给 west init 的路径
cd zephyrproject\zephyr
git pull
west update
python -m pip install @((west packages pip) -split ' ')
```

> 译注：若 Git 报告冲突或本地修改问题，先处理该问题，再继续工作区更新。

## 3.6\_导出CMake包与开发板别名

如果尚未在入门指南中完成，可以把 [Zephyr CMake 包](https://docs.zephyrproject.org/latest/build/zephyr_cmake_package.html)导出到 CMake 用户包注册表。对应命令见前章的“导出 Zephyr 的 CMake 包”。

同时使用多个开发板的开发者，可能觉得完整目标名过长，希望为常用目标设置别名。可以创建包含下列内容的 CMake 文件：

```cmake
# foo_BOARD_ALIAS=bar 会把 BOARD=foo 替换为 BOARD=bar，
# 并在 CMake 缓存中设置 BOARD_ALIAS=foo。
set(pca10028_BOARD_ALIAS nrf51dk/nrf51822)
set(pca10056_BOARD_ALIAS nrf52840dk/nrf52840)
set(k64f_BOARD_ALIAS frdm_k64f)
set(sltb004a_BOARD_ALIAS efr32mg_sltb004a)
```

用 `ZEPHYR_BOARD_ALIASES` 指定此文件的位置后，即可在指定开发板的地方使用 `pca10028` 等别名，例如 `cmake -DBOARD=pca10028`。

> 译注：原文的另一个例子写作 `west -b pca10028`，缺少构建子命令。实际构建应使用 `west build -b pca10028 <应用路径>`。此处明确说明修正，没有把这一缺漏照搬成可执行命令。别名文件由使用者自行创建，并不是 Zephyr 下载后自带的文件。

## 3.7\_构建应用并烧录到开发板

在受支持的主机系统上，可以构建、烧录并在实际硬件上运行应用。根据操作系统不同，也可通过 QEMU 模拟运行，或者通过 `native_sim` 作为主机原生应用运行。详情见[构建应用](https://docs.zephyrproject.org/latest/develop/application/index.html#building-an-application)。

### 3.7.1\_构建Blinky

Zephyr 应用针对特定硬件构建，该硬件被称为“开发板”（board）。这里使用 Phytec `reel_board`；如果使用其他开发板，替换构建目标。在工作区内运行 `west boards`，或查看[开发板列表](https://docs.zephyrproject.org/latest/boards/index.html)，可找到受支持的目标。

先进入官方示例的 Zephyr 仓库，再构建：

```text
cd zephyrproject/zephyr
west build -b reel_board samples/basic/blinky
```

主要构建产物位于 `build/zephyr`。其中 `build/zephyr/zephyr.elf` 是 **可执行与可链接格式（Executable and Linkable Format，ELF）** 格式的 Blinky 应用二进制；根据开发板配置，还可能生成其他格式的二进制、反汇编文件和映射文件。

`samples` 目录中的其他应用见[示例与演示](https://docs.zephyrproject.org/latest/samples/index.html)。

> 原文说明：如果想为另一块开发板或另一个应用复用已有构建目录，应给 `west build` 添加 `-p=auto`，清除之前构建的设置和产物。

### 3.7.2\_烧录运行

大多数受支持的实体开发板可以通过 `west flash` 烧录，但可能需要安装、配置专用工具。详情见[运行应用](https://docs.zephyrproject.org/latest/develop/application/index.html#run-an-application)及相应开发板文档。

<a id="udev-rules"></a>

## 3.8\_配置udev规则

烧录需要直接访问开发板硬件的权限，通常在安装烧录工具时配置。在 Linux 上，如果 `west flash` 失败，可能需要定义 udev 规则来赋予访问权限。

udev 是 Linux 内核的设备管理器，其守护进程处理设备添加或移除引发的用户空间事件。添加规则文件，可以允许非 root 用户访问某些 **通用串行总线（Universal Serial Bus，USB）** 设备。

OpenOCD（On-Chip Debugger）项目提供的规则文件涵盖多数 Zephyr 支持的 Arm 开发板。可以从 SourceForge 下载，或者使用已安装 SDK 中的副本；二选一。

**下载规则文件：** 在 Linux 终端的可写目录中执行：

```bash
wget -O 60-openocd.rules https://sf.net/p/openocd/code/ci/master/tree/contrib/60-openocd.rules?format=raw
sudo cp 60-openocd.rules /etc/udev/rules.d
```

**使用 SDK 副本：** 原文以设置好的 SDK 根变量及 x86-64 Linux SDK 布局为例：

```bash
sudo cp ${ZEPHYR_SDK_INSTALL_DIR}/sysroots/x86_64-pokysdk-linux/usr/share/openocd/contrib/60-openocd.rules /etc/udev/rules.d
```

选择其中一种方式后，要求 udev 重新加载规则：

```bash
sudo udevadm control --reload
```

拔下再接上开发板的 USB 连接，之后应能访问开发板并烧录。必要时继续查开发板说明。

> 译注：复制 SDK 副本前先确认变量非空、文件实际存在。前文允许 SDK 自动发现，因此读者的环境不一定已经设置这个变量；也不能把这里的 x86-64 路径直接套到其他主机架构。

## 3.9\_在QEMU中运行

可以使用 QEMU 在主机上模拟运行面向 x86 或 Arm Cortex-M3 的 Zephyr 应用。Zephyr SDK 包含 QEMU。

如果手动安装 QEMU，确保系统 `PATH` 能找到它。`QEMU_BIN_PATH` 可作为可选覆盖项，指定 Twister 使用的 QEMU 可执行文件位置；设置后，Twister 会验证路径是否存在。未设置时，Twister 使用 SDK 或其他 QEMU 发现机制。

例如，采用 x86 模拟开发板配置 `qemu_x86` 构建并运行 Hello World。在 Zephyr 源码根目录执行：

```text
west build -b qemu_x86 samples/hello_world
west build -t run
```

退出 QEMU 时，先按 Ctrl+A，再按 X。目标改为 `qemu_cortex_m3` 时，可构建面向模拟 Arm Cortex-M3 的示例。

> 译注：前面若已经在默认 `build` 目录构建过 Blinky，应按 3.7 节的规则处理旧构建目录，避免把不同开发板配置混在一起。

## 3.10\_在Linux上原生运行示例

一些示例可以在 Linux 上编译成主机程序，详情见 [native_sim](../native_reference/P004_Native_Simulator本机模拟器.md)。在 64 位主机系统上，需要安装 32 位 C 库，或者改为针对 `native_sim/native/64` 构建。

先在 Zephyr 源码根目录为 `native_sim` 构建 Hello World：

```bash
west build -b native_sim samples/hello_world
```

随后运行应用，以下两种方式任选一种：

```bash
west build -t run
# 或者直接运行生成的 zephyr.exe：
./build/zephyr/zephyr.exe
```

按 Ctrl+C 退出。运行 `./build/zephyr/zephyr.exe --help` 可列出选项；还可以用 gdb、valgrind 等标准工具分析这个可执行文件。

> 译注：这里的 `zephyr.exe` 是 Linux 主机程序，不能凭 `.exe` 后缀把这组命令当作 Windows 运行方法。

## 3.11\_原文脚注

**关于 pip：** pip 是 Python 软件包安装器。`install` 首先尝试复用计算机上已经安装的包及其依赖；不能满足时，就从互联网的 Python Package Index（PyPI）下载。Zephyr 的 `requirements.txt` 所要求的版本可能与系统其他需求冲突，因此可以为 Zephyr 开发建立虚拟环境。

**关于 board：** 这个名称在某些场景下并不完全符合字面含义。目标通常是独立硬件板上的微处理器，但也可以是在 QEMU 中模拟其他架构的目标，或者用 POSIX 接口实现 Zephyr 驱动接口的主机原生程序，甚至是同一芯片上不同架构处理器核分别运行的 Zephyr 二进制。Zephyr 把这些硬件配置都称为 board。
