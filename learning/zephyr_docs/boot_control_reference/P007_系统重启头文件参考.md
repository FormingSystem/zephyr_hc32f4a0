### `sys_reboot()`

```c
FUNC_NORETURN void sys_reboot ( int type)
```

重启系统（Reboot the System）。

按 `type` 指定的方式重启系统。并非所有架构或平台都支持各种重启类型（`SYS_REBOOT_COLD`、`SYS_REBOOT_WARM`）。

成功时，此例程不会返回。

## 7.4\_源码定位与版本边界

相对源码定位：[include/zephyr/sys/reboot.h](../../../include/zephyr/sys/reboot.h)、[lib/os/reboot.c](../../../lib/os/reboot.c)、[lib/os/Kconfig](../../../lib/os/Kconfig)、[arch/arm/core/cortex_m/scb.c](../../../arch/arm/core/cortex_m/scb.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位采用相对链接；本地版本如有差异，应核对来源摘要与实际实现，不把文档核对视为固件升级或重启实测。

> 译注——源码核对：SYS_REBOOT_WARM与SYS_REBOOT_COLD表达请求的重启类型，实际支持取决于平台。本次Cortex-M的弱定义sys_arch_reboot忽略type并调用NVIC_SystemReset，不能据两个常量推断所有硬件都有不同的冷／热复位实现；SoC可以覆盖弱定义。

> 译注——源码核对：通用sys_reboot先按配置处理覆盖率数据，锁定普通中断及配置允许的零延迟中断，按配置关闭缓存与系统定时器，再调用sys_arch_reboot。如果底层意外返回，则打印错误并持续进入CPU空闲循环；接口没有可供调用者处理的失败返回码。

> 译注——源码核对：原页仍引用subsys/os/Kconfig，此处按原文保留。本次官方源码的REBOOT选项位于lib/os/Kconfig；它使能sys_reboot，并可能引入安全重启所需子系统。接口说明不保证掉电复位、存储自动提交或完整应用级关机。
