## 8.4\_源码跟踪译注

> 译注——SYS_REBOOT_WARM与SYS_REBOOT_COLD表达请求的重启类型，实际支持取决于平台。本次Cortex-M的弱定义sys_arch_reboot忽略type并调用NVIC_SystemReset，不能据两个常量推断所有硬件都有不同的冷／热复位实现；SoC可以覆盖弱定义。

> 译注——通用sys_reboot先按配置处理覆盖率数据，锁定普通中断及配置允许的零延迟中断，按配置关闭缓存与系统定时器，再调用sys_arch_reboot。如果底层意外返回，则打印错误并持续进入CPU空闲循环；接口没有可供调用者处理的失败返回码。

> 译注——原页仍引用subsys/os/Kconfig，此处按原文保留。本次官方源码的REBOOT选项位于lib/os/Kconfig；它使能sys_reboot，并可能引入安全重启所需子系统。接口说明不保证掉电复位、存储自动提交或完整应用级关机。

头文件相对定位：[include/zephyr/sys/reboot.h](../../../include/zephyr/sys/reboot.h)，关联实现／接口：[lib/os/reboot.c](../../../lib/os/reboot.c)；[官方原始头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/reboot.h)与[官方关联文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/os/reboot.c)的摘要见来源记录。去掉注释和展示空白后，本页代码与本次读取的原始头文件一致，不能推广到以后滚动更新的main或任意本地版本。
