## 2.2\_详细说明（Detailed Documentation）

<a id="gaecc27edfc80a72c2a0e0b1fcd746aabb"></a>

### `DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX`

```c
#define DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT4(node_id, _DMA_RANGES_IDX_, idx, _VAL_CHILD_BUS_ADDRESS)
```

获取 `dma-ranges` 属性在指定索引处的子总线地址。

当节点是 PCI Express（PCIe）总线时，子总线地址具有一个用于存放标志的额外单元（Cell）；因此，会从子总线地址中去除该单元。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
parent {
        #address-cells = <2>;

        pcie0: pcie@0 {
                compatible = "pcie-controller";
                reg = <0 0 1>;
                #address-cells = <3>;
                #size-cells = <2>;

                dma-ranges = <0x1000000 0 0 0 0x3eff0000 0 0x10000>,
                             <0x2000000 0 0x10000000 0 0x10000000 0 0x2eff0000>,
                             <0x3000000 0x80 0 0x80 0 0x80 0>;
        };

        other: other@1 {
                reg = <0 1 1>;

                dma-ranges = <0x0 0x0 0x0 0x3eff0000 0x10000>,
                             <0x0 0x10000000 0x0 0x10000000 0x2eff0000>;
        };
};
```

用法示例：

原始示例（Example）：

```c
DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(pcie0), 0) // 0x0
DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(pcie0), 1) // 0x0
DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(pcie0), 2) // 0x8000000000

DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(other), 0) // 0x0
DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(other), 1) // 0x10000000
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | `dma-ranges` 数组中的逻辑索引（Logical Index）。 |

返回（Returns）：索引 `idx` 处 DMA 地址范围的子总线地址字段。

> 译注——源码核对：DMA原例注释：DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(DT_NODELABEL(pcie0), 1)原注释为0x0，但第二个条目去除标志0x2000000后，子地址两个单元是0和0x10000000，合并结果应为0x10000000。原示例保留，并据生成器掩码逻辑指出差异；这不是硬件运行结果。

<a id="ga7dac1689c6f3129d6c82bba250b93813"></a>

### `DT_DMA_RANGES_HAS_IDX`

```c
#define DT_DMA_RANGES_HAS_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
IS_ENABLED(DT_CAT4(node_id, _DMA_RANGES_IDX_, idx, _EXISTS))
```

判断 `idx` 是否为有效的 DMA 地址范围块索引。

若返回 1，则 `DT_DMA_RANGES_CHILD_BUS_ADDRESS_BY_IDX(node_id, idx)`、`DT_DMA_RANGES_PARENT_BUS_ADDRESS_BY_IDX(node_id, idx)` 或 `DT_DMA_RANGES_LENGTH_BY_IDX(node_id, idx)` 有效。若返回 0，则不能使用索引 `idx` 调用这些宏，否则会出错。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
parent {
        #address-cells = <2>;

        pcie0: pcie@0 {
                compatible = "pcie-controller";
                reg = <0 0 1>;
                #address-cells = <3>;
                #size-cells = <2>;

                dma-ranges = <0x1000000 0 0 0 0x3eff0000 0 0x10000>,
                             <0x2000000 0 0x10000000 0 0x10000000 0 0x2eff0000>,
                             <0x3000000 0x80 0 0x80 0 0x80 0>;
        };

        other: other@1 {
                reg = <0 1 1>;

                dma-ranges = <0x0 0x0 0x0 0x3eff0000 0x10000>,
                             <0x0 0x10000000 0x0 0x10000000 0x2eff0000>;
        };
};
```

用法示例：

原始示例（Example）：

```c
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(pcie0), 0) // 1
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(pcie0), 1) // 1
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(pcie0), 2) // 1
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(pcie0), 3) // 0

DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(other), 0) // 1
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(other), 1) // 1
DT_DMA_RANGES_HAS_IDX(DT_NODELABEL(other), 2) // 0
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | `dma-ranges` 数组中的逻辑索引（Logical Index）。 |

返回（Returns）：若 `idx` 是有效的 `dma-ranges` 块索引则为 1，否则为 0。

```dts
                reg = <0 1 1>;

                dma-ranges = <0x0 0x0 0x0 0x3eff0000 0x10000>,
```

### `DT_NUM_DMA_RANGES`

```c
#define DT_NUM_DMA_RANGES ( node_id)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _NUM_DMA_RANGES)
```

获取 `dma-ranges` 属性中的 DMA 地址范围块数量。

请使用此宏，而不是 `DT_PROP_LEN(node_id, dma_ranges)`。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
parent {
        #address-cells = <2>;

        pcie0: pcie@0 {
                compatible = "pcie-controller";
                reg = <0 0 1>;
                #address-cells = <3>;
                #size-cells = <2>;

                dma-ranges = <0x1000000 0 0 0 0x3eff0000 0 0x10000>,
                             <0x2000000 0 0x10000000 0 0x10000000 0 0x2eff0000>,
                             <0x3000000 0x80 0 0x80 0 0x80 0>;
        };
```

## 2.3\_源码定位与版本边界

本册收录reg、ranges与dma-ranges属性宏。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：属性与方向：ranges描述子总线地址到父总线地址的映射条目；dma-ranges描述直接内存访问（Direct Memory Access，DMA）相关的总线地址映射。宏只是提取构建时字段，不配置DMA控制器、输入／输出内存管理单元（Input/Output Memory Management Unit，IOMMU）或缓存一致性，也不分配DMA缓冲区。父总线地址是这一层的字段，不能一概称为已递归转换后的CPU物理地址。

> 译注——源码核对：单元与索引：子地址单元数取本节点#address-cells，父地址单元数取父节点#address-cells，长度单元数取本节点#size-cells。一个索引对应完整的子地址／父地址／长度三元组，而不是单个32位单元。PCIe识别依据绑定产生的node.buses包含pcie，不依据节点名称；其首个子地址单元拆为标志，其余单元组成数值地址。

> 译注——源码核对：缺省与空属性：本次解析器将未写入或空值的ranges／dma-ranges都解析为空条目列表，生成数量0及空遍历；因此只看NUM宏无法区分属性缺省和显式空值。解析器_translate对ranges缺省与空值的递归处理不同，不能由“数量为0”推出相同的地址转换语义。

> 译注——源码核对：字段存在边界：HAS_IDX检查条目_EXISTS，不检查每个字段。若相应#address-cells或#size-cells为0，解析器可将字段置为None，生成器就不生成该字段值；索引存在并非所有地址／长度宏均可使用的充分条件。PCIe标志应另用HAS_CHILD_BUS_FLAGS_AT_IDX检查；这是原文一般有效性表述需要结合数据布局理解的边界。

> 译注——源码核对：遍历展开：FOREACH_RANGE和FOREACH_DMA_RANGE按属性条目顺序传入node_id与idx，不自行插入逗号或分号；例中的长度辅助宏自带逗号，所以结果保留尾随逗号。它们生成编译期代码，不是运行时迭代设备的函数。

> 译注——源码核对：片段前提：原例省略了一些父级或子级单元数设置。比如NUM_RANGES片段中reg与ranges的布局仍需各自匹配外部父节点设置，不能只凭片段中的数值把它认作独立可编译DTS。原例含PCIe是用于解释通用字段编码，不表示本仓库的芯片具有PCIe硬件。

> 译注——源码核对：版本边界：依据本次官方网页及另行取得的devicetree.h、gen_defines.py和edtlib.py核对。滚动main与本仓库参照源码不自动视为同一提交；相对源码链接用于定位，读取摘要见来源记录。本批未编译DTS／C示例或执行寄存器、DMA、PCIe及实板操作。

本次验证范围为文档与源码对照，未编译DTS／C示例或执行寄存器、DMA、PCIe及实板操作。
