## 1.2\_详细说明（Detailed Documentation）

<a id="gae43b5601701f53e1cf637fa985dca613"></a>

### `DT_FOREACH_REG`

```c
#define DT_FOREACH_REG ( node_id, fn )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _FOREACH_REG)(fn)
```

对 `node_id` 的 `reg` 属性中的每个条目调用 `fn`。

宏 `fn` 接收两个参数：`node_id` 是具有 `reg` 属性的节点标识符（Node Identifier），`idx` 是 `reg` 数组的索引。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
n: node@0 {
        #address-cells = <0x2>;
        #size-cells = <0x2>;
        reg = <0x0 0x0 0x0 0x1000>,
              <0x0 0x1000 0x0 0x1000>,
              <0x0 0x2000 0x0 0x1000>;
};
```

用法示例：

原始示例（Example）：

```c
#define REG_ADDR(node_id, idx) DT_REG_ADDR_BY_IDX(node_id, idx),
#define REG_SIZE(node_id, idx) DT_REG_SIZE_BY_IDX(node_id, idx),

const uint64_t reg_addrs[] = {
        DT_FOREACH_REG(DT_NODELABEL(n), REG_ADDR)
};
const uint64_t reg_sizes[] = {
        DT_FOREACH_REG(DT_NODELABEL(n), REG_SIZE)
};
```

展开结果如下：

原始示例（Example）：

```c
const uint64_t reg_addrs[] = {
    0x0, 0x1000, 0x2000,
};
const uint64_t reg_sizes[] = {
    0x1000, 0x1000, 0x1000,
};
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `fn` | 要调用的宏。 |

> 译注——源码核对：原设备树示例的上下文：reg编码由父节点的#address-cells与#size-cells决定。示例把两个属性写在n节点内部，它们控制n的子节点，不能独立决定n自身reg的四单元布局。原片段照录；要按注释得到三个条目，外围父节点还需有相应的2／2设置，不能把省略父级的片段当作已验证完整DTS。

**参数（Parameters）**

### `DT_REG_ADDR_BY_IDX_RAW`

```c
#define DT_REG_ADDR_BY_IDX_RAW ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT4(node_id, _REG_IDX_, idx, _VAL_ADDRESS)
```

获取索引 `idx` 处寄存器块不带类型后缀的原始基地址（Raw Base Address）。

获取索引 `idx` 处寄存器块的基地址，不附加任何类型后缀（Type Suffix）。它可用于索引其他设备树属性；在实际代码中赋值时应使用不带 `_RAW` 的宏。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | 要获取地址的寄存器块索引。 |

返回（Returns）：第 `idx` 个寄存器块的地址。

> 译注——源码核对：RAW的含义：这里表示不添加C整数字面量类型后缀，不表示绕过设备树地址转换。edtlib._init_regs在保存地址前调用_translate；生成器write_regs读取该解析结果，RAW和普通版本都使用同一个_VAL_ADDRESS。它们不会建立内存管理单元（Memory Management Unit，MMU）映射，也不会读取硬件或完成设备就绪检查。

| --- | --- |

返回（Returns）：节点的寄存器块地址。

### `DT_REG_HAS_IDX`

```c
#define DT_REG_HAS_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
IS_ENABLED(DT_CAT4(node_id, _REG_IDX_, idx, _EXISTS))
```

判断 `idx` 是否为有效的寄存器块索引。

若返回 1，则 `DT_REG_ADDR_BY_IDX(node_id, idx)` 或 `DT_REG_SIZE_BY_IDX(node_id, idx)` 有效。若返回 0，则不能使用索引 `idx` 调用这些宏，否则会出错。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | 要检查的索引。 |

返回（Returns）：若 `idx` 是有效的寄存器块索引则为 1，否则为 0。

> 译注——源码核对：存在检查的边界：生成器对每个reg条目生成_EXISTS，但仅在地址／大小字段非None时生成相应_VAL_ADDRESS／_VAL_SIZE。例如父节点#size-cells为0时，可有有效条目而没有SIZE宏；不能将原文HAS_IDX的有效性说明扩展成所有字段均存在的保证。按名称的_EXISTS在有地址且有名称时生成，SIZE_BY_NAME_OR仅判断这个名称标志，不能补救已命名但缺少大小字段的情况。

## 1.3\_源码定位与版本边界

本册收录reg、ranges与dma-ranges属性宏。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：对象与数量：reg描述资源地址和大小，未必是CPU可以直接解引用的内存映射寄存器，也可能是总线上的设备地址。DT_NUM_REGS计数完整地址／大小条目，不是32位单元数量，也不是字节长度；DT_REG_SIZE取得单个块的大小。无_BY_IDX版本选索引0，文中“唯一”不表示宏会验证只有一个条目。

> 译注——源码核对：类型后缀：普通版本经DT_U32_C使用UINT32_C，U64版本经DT_U64_C使用UINT64_C；这不是运行时强制转换，也不能用宏名推断地址一定小于4 GiB。在链接器或汇编上下文中两种包装均不添加C后缀。目标对象的类型和地址空间仍由使用者选择。

> 译注——源码核对：名称与回退：name对应reg-names中的名称，按小写加下划线的预处理标记使用，不传带引号的运行时字符串。_OR分支使用COND_CODE_1进行预处理期选择；它不是硬件访问失败后的回退，也不创建缺失资源。

> 译注——源码核对：遍历与分隔符：fn是宏名，先接收node_id和从0开始的条目索引，VARGS再追加调用者参数。普通遍历由fn自行提供逗号或分号；REG_SEP生成器使用join，只在相邻展开之间插入分隔符，末尾不自动追加。分隔符写成(,)或(;)。不要把其他遍历宏的尾随规则直接套到本组。

> 译注——源码核对：版本边界：依据本次官方网页及另行取得的devicetree.h、gen_defines.py和edtlib.py核对。滚动main与本仓库参照源码不自动视为同一提交；相对源码链接用于定位，读取摘要见来源记录。本批未编译DTS／C示例或执行寄存器、DMA、PCIe及实板操作。

本次验证范围为文档与源码对照，未编译DTS／C示例或执行寄存器、DMA、PCIe及实板操作。
