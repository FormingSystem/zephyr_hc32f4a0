# 第5章\_其他交叉编译器

原文：[Other Cross Compilers](https://docs.zephyrproject.org/latest/develop/toolchains/other_x_compilers.html)。读取日期：2026-10-12，`latest`。

这一工具链变体借用了 Linux 内核构建系统通过 `CROSS_COMPILE` 环境变量配置 GNU 交叉工具链的机制。

“其他交叉编译器”可以是 Linux 发行版打包的工具链、自行编译的工具链或从网络取得的工具链。不同于[工具链列表](P001_工具链入口.md)明确列出的工具链，Zephyr 构建系统可能没有对它们做过测试，也不提供正式支持；但这种工具链接入机制本身受支持。

## 5.1\_安装工具链

安装同时适合主机和目标系统的交叉编译器。例如，在基于 Debian 的系统安装 `gcc-arm-none-eabi`，或在 Fedora/Red Hat 安装 `arm-none-eabi-newlib`。在相应 Linux 终端中二选一：

```bash
# Debian 或 Ubuntu：
sudo apt-get install gcc-arm-none-eabi
# Fedora 或 Red Hat：
sudo dnf install arm-none-eabi-newlib
```

## 5.2\_设置变量并核对

按[环境变量](P003_环境变量.md)的方法设置：

- `ZEPHYR_TOOLCHAIN_VARIANT` 为 `cross-compile`。
- `CROSS_COMPILE` 为工具链所有二进制文件共有的路径前缀，即可执行文件目录、目标三元组及末尾连字符的组合。

以下会话展示如何检查，路径应以实际安装为准：

```text
# Linux、macOS：
$ echo $ZEPHYR_TOOLCHAIN_VARIANT
cross-compile
$ echo $CROSS_COMPILE
/usr/bin/arm-none-eabi-
```

也可以把 `CROSS_COMPILE` 设置为 CMake 变量。

## 5.3\_路径前缀的含义

使用这一方式时，所有工具链程序必须位于同一目录，并具有共同的文件名前缀。`CROSS_COMPILE` 等于“目录路径 + 文件名前缀”。

上面的 Debian 示例把 `arm-none-eabi-gcc`、`arm-none-eabi-ld` 等安装到 `/usr/bin/`，因此公共前缀是 `/usr/bin/arm-none-eabi-`，包括末尾的 `-`。

如果变量 `TOOLCHAIN_BIN` 指向工具链的 `bin` 目录，程序文件名基于目标三元组 `myarch-none-elf`，则路径前缀为 `${TOOLCHAIN_BIN}/myarch-none-elf-`。

> 译注：本例用路径变量代替原文写死的安装位置。应先根据实际工具链安装结果设置 `TOOLCHAIN_BIN`，再由所用 shell 展开；该名称不是 Zephyr 自动提供的变量。

> 译注：这个值既不是只含目录的路径，也不是完整的 `gcc` 文件名。构建系统在其后追加具体工具名称；漏掉末尾连字符或追加了 `gcc`，都会使后续程序名拼接错误。工具链是否具备目标所需的库与架构选项，仍需实际构建核验。
