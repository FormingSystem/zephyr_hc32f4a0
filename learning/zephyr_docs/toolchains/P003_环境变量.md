# 第3章\_环境变量

原文：[Environment Variables](https://docs.zephyrproject.org/latest/develop/env_vars.html)。读取日期：2026-10-12，`latest`。

Zephyr 文档中的多个页面要求设置特定环境变量，本页说明如何设置。示例中的 `MY_VARIABLE` 是演示用的变量名，`foo` 是演示值。

## 3.1\_设置变量

可以只为当前终端设置，也可以写入持久配置供后续会话使用；下面按保存范围和操作系统列出方法。

### 3.1.1\_方式一：仅在当前终端中生效

要把 `MY_VARIABLE` 设为 `foo`，并仅在当前终端窗口的生命周期内生效，可使用以下命令。

Linux/macOS：

```bash
# 当前 shell；与工作目录无关。
export MY_VARIABLE=foo
```

Windows 命令提示符：

```bat
:: 当前 cmd.exe 窗口；与工作目录无关。
set MY_VARIABLE=foo
```

这种方式最适合试验。关闭终端、换到其他终端窗口或标签页、重启计算机等，都会使这里设置的值不再可用。需要持续使用时，建议采用方式二或三。

> 译注：Windows 的 `set` 是 cmd.exe 语法，不是 PowerShell 的环境变量赋值语法。此处忠实保留原文终端分支，不应把命令直接粘贴到另一种 shell。

### 3.1.2\_方式二：在所有新终端中生效

**Linux/macOS：** 在用户主目录中的 shell 启动脚本加入：

```bash
export MY_VARIABLE=foo
```

对于 Bash，Linux 上通常是 `~/.bashrc`，macOS 上通常是 `~/.bash_profile`。修改启动脚本不会影响已经运行的 shell；打开新的终端窗口以取得新设置。

**Windows：** 可使用 cmd.exe 的 `setx` 程序，或第三方 RapidEE 图形工具。

使用 `setx` 时，在 cmd.exe 中执行后关闭窗口：

```bat
:: Windows cmd.exe；保存给之后新开的窗口使用。
setx MY_VARIABLE foo
```

之后新开的 cmd.exe 窗口中，`MY_VARIABLE` 将为 `foo`。

RapidEE 是免费的图形化环境变量编辑器。原文给出通过 Chocolatey 安装的方法，在管理员命令提示符执行：

```bat
:: 需要已有 Chocolatey；管理员 cmd.exe。
choco install rapidee
```

之后可以在终端运行 `rapidee` 打开程序并设置变量。应使用“User”用户环境变量区域，否则需以管理员身份运行 RapidEE。退出前，单击左上方保存按钮保存修改；之后新开的终端窗口会获得这些设置。

> 译注：RapidEE 是官方页面列出的可选工具，不是 Zephyr 构建的必需依赖；有了可用的设置方式，无须为了翻译中的备选步骤再安装一套工具。

### 3.1.3\_方式三：使用zephyrrc文件

若希望保留设置，但不希望它自动出现在所有终端中，可使用这种方式，在使用 Zephyr 时再加载。

**Linux/macOS：** Zephyr 尽可能遵循 XDG Base Directory Specification，按以下次序查找 `zephyrrc`：

1. `$XDG_CONFIG_HOME/zephyr/zephyrrc`。
2. `$HOME/.config/zephyr/zephyrrc`。
3. `$HOME/.zephyrrc`。

在选定位置自行创建文件，并加入：

```bash
# zephyrrc 文件内容，不是要求同时创建三个文件。
export MY_VARIABLE=foo
```

要把设置加载到当前终端，在 Zephyr 主仓库根目录运行 `source zephyr-env.sh`。脚本会加载上述列表中首先找到的 `zephyrrc`，并执行其他环境准备。关闭窗口等操作后，当前环境中的值会丢失；再次运行同一命令即可重新加载。

**Windows：** 使用记事本等文本编辑器，在 `%userprofile%\zephyrrc.cmd` 文件中加入：

```bat
set MY_VARIABLE=foo
```

随后打开 cmd.exe，进入 Zephyr 主仓库，运行 `zephyr-env.cmd`。该脚本会执行 `%userprofile%\zephyrrc.cmd`。关闭窗口后，再次运行 `zephyr-env.cmd` 才会重新加载这些设置。

这些脚本会把 `ZEPHYR_BASE` 设为 Zephyr 仓库位置，将 `scripts` 等 Zephyr 特定目录加入 `PATH`，并加载前述 `zephyrrc`。需要这些设置时即可使用。

## 3.2\_Zephyr环境脚本

仓库中的 `zephyr-env.sh` 面向 macOS/Linux，`zephyr-env.cmd` 面向 Windows；它们将 Zephyr 特定设置加载到当前终端。在 Zephyr 源码根目录执行对应命令：

```bash
# Linux/macOS shell；当前目录是所选 Zephyr 源码根目录。
source zephyr-env.sh
```

```bat
:: Windows cmd.exe；当前目录是所选 Zephyr 源码根目录。
zephyr-env.cmd
```

脚本的作用是：

- 将 `ZEPHYR_BASE` 设为 Zephyr 仓库所在位置。
- 将 Zephyr 的 `scripts` 等目录加入 `PATH`。
- 加载上一节说明的 `zephyrrc` 设置。

需要其中任一设置时都可以使用脚本。

> 译注：环境脚本加载不等于创建 Python 虚拟环境，也不等于安装 **软件开发工具包（Software Development Kit，SDK）**。修改 `zephyrrc` 后若要改变当前窗口，须重新加载；若设置已经进入 CMake 构建缓存，还应按构建文档处理缓存。它们属于不同的状态保存位置。

## 3.3\_重要环境变量

部分[重要构建系统变量](https://docs.zephyrproject.org/latest/develop/application/index.html#important-build-system-variables)也可通过环境设置。下面列出其中一些重要项，并非完整列表。

| 变量 | 原文说明或深入入口 |
| --- | --- |
| `BOARD` | 见重要构建系统变量 |
| `CONF_FILE` | 见重要构建系统变量 |
| `SHIELD` | 见[扩展板](https://docs.zephyrproject.org/latest/hardware/porting/shields.html) |
| `ZEPHYR_BASE` | 见重要构建系统变量 |
| `EXTRA_ZEPHYR_MODULES` | 见重要构建系统变量 |
| `ZEPHYR_MODULES` | 见重要构建系统变量 |
| `ZEPHYR_BOARD_ALIASES` | 见[开发板别名](../getting_started/P003_入门之后.md) |

选择构建工具链时，还涉及：

| 变量 | 含义 |
| --- | --- |
| `ZEPHYR_SDK_INSTALL_DIR` | SDK 安装路径 |
| <a id="envvar-ZEPHYR_TOOLCHAIN_VARIANT"></a>`ZEPHYR_TOOLCHAIN_VARIANT` | 要使用的工具链名称 |
| `{TOOLCHAIN}_TOOLCHAIN_PATH` | 所选工具链的路径；例如变体为 `host/llvm` 时使用 `LLVM_TOOLCHAIN_PATH`，注意变量名中的大写形式 |

更新 SDK 工具链时，可能需要调整这些变量，见[入门之后](../getting_started/P003_入门之后.md)。

<a id="envvar-PATH"></a>

模拟器或开发板还可能依赖额外程序。构建系统会尝试自动查找，但也可能依赖附加的 CMake 变量或环境变量；具体查模拟器和开发板文档。在这些情况下，`PATH` 也可能有用：它是类 Unix 和 Microsoft Windows 系统中用于指定可执行程序搜索目录集合的环境变量。
