## 1.4\_详细说明（Detailed Documentation）

<a id="ga14c9c3bb09cec4c297a22f1ec751ceff"></a>

### `syscon_get_base()`

```c
int syscon_get_base ( const struct device * dev, uintptr_t * addr )
```

```c
#include <zephyr/drivers/syscon.h>
```

获取Syscon基地址（Base Address）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 要获取其基地址的设备。 |
| `addr` | 用于写入基地址的位置。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 已向addr写入基地址。 |
| `-ENOSYS` | 未实现该API或函数。 |

> 译注——源码核对：基地址与版本：get_base返回通用驱动映射后的内存映射输入／输出（Memory-Mapped I/O，MMIO）基地址，不应无条件当作物理地址或任意用户线程可直接访问的指针。头文件的update_bits包装器直接转换dev->api，其余包装器通过DEVICE_API_GET获取操作表；这不构成接受任意设备指针的保证。完整保留本次源码，非注释内容与官方syscon.h一致，相对源码位置用于跟踪，不假定本地基线与滚动main始终相同。

### `syscon_get_size()`

```c
int syscon_get_size ( const struct device * dev, size_t * size )
```

```c
#include <zephyr/drivers/syscon.h>
```

获取Syscon寄存器的大小，单位为字节。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 要获取其寄存器大小的设备。 |
| `size` | 用于写入大小的指针。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-ENOSYS` | 未实现该API或函数。 |

> 译注——源码核对：区域与访问宽度：原文get_size摘要写“寄存器的大小”，后端说明明确为寄存器区域（Register Region）的大小；通用驱动返回设备树reg给出的区域字节数，不是单个寄存器的宽度。reg是区域内偏移量；通用驱动按base_address+reg访问，单位为字节，不是寄存器序号。reg-io-width单独决定访问宽度，未设置时为4字节，源码支持1、2、4字节。

### `syscon_read_reg()`

```c
int syscon_read_reg ( const struct device * dev, uint32_t reg, uint32_t * val )
```

```c
#include <zephyr/drivers/syscon.h>
```

读取Syscon寄存器。

此函数读取Syscon区域内的指定寄存器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 要从中读取的设备。 |
| `reg` | 寄存器偏移量（Register Offset）。 |
| `val` | 返回从Syscon寄存器读出的值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-ENOSYS` | 未实现该API或函数。 |

> 译注——源码核对：参数与边界：应用须传入有效的Syscon设备及有效输出指针，成功后再使用addr、size或val。头文件包装器没有检查设备就绪，也没有通用偏移边界校验。通用驱动的读取函数检查val非空，其他输出指针仍须由调用者保证；通用偏移辅助函数检查reg按宽度对齐且reg小于区域大小，不检查reg+宽度的完整访问范围。因此设备树应保证区域布局和宽度有效，不能把该检查理解为所有不合理映射都能被拒绝。

<a id="ga453503af7f04d6106db93e54e9072a6c"></a>

### `syscon_update_bits()`

```c
int syscon_update_bits ( const struct device * dev, uint32_t reg, uint32_t mask, uint32_t val )
```

```c
#include <zephyr/drivers/syscon.h>
```

原子地更新Syscon寄存器中的位（Atomically Update Bits）。

在驱动内部锁（Internal Lock）保护下对寄存器执行读—修改—写（Read-Modify-Write）。先清除mask选中的位，再用val中对应的位替换。等价于：

原始示例（Example）：

```c
syscon_read_reg(dev, reg, &tmp);
tmp = (tmp & ~mask) | (val & mask);
syscon_write_reg(dev, reg, tmp);
```

但相对于同一设备上的其他Syscon操作，整个过程以原子方式执行。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | Syscon设备。 |
| `reg` | 寄存器偏移量（Register Offset）。 |
| `mask` | 待修改位的位掩码（Bitmask）。 |
| `val` | mask选中位的新值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-ENOSYS` | 未实现该API或函数。 |

> 译注——源码核对：原子性范围：syscon_update_bits的官方契约是相对于同一设备其他Syscon操作保持原子性。包装器不自行加锁，而是调用update_bits回调；通用驱动让read、write与update_bits共用设备自旋锁（Spinlock），后者在同一次持锁期间完成读取、掩码计算和写入。原文三行代码只说明等价计算，应用分别调用read和write会在两次调用间释放锁，不能据此获得同样的原子性。
>
> 译注——源码核对：掩码与寄存器语义：计算为(tmp & ~mask) | (val & mask)，val中mask以外的位被忽略，mask内的位从val取值。这个读—修改—写算法适用于相应硬件允许的寄存器；读清零、写一清零（Write One to Clear，W1C）或其他带访问副作用的寄存器必须按硬件语义处理。通用驱动即使mask为0仍会执行读和写，不等于一定没有硬件副作用。驱动锁也不阻止DMA、硬件自身或绕过驱动锁的直接寄存器访问。

## 1.5\_源码定位与版本边界

本册依次提供公共API、驱动后端、操作结构、头文件参考与源码。相对源码定位：[syscon.h](../../../include/zephyr/drivers/syscon.h)、[通用驱动](../../../drivers/syscon/syscon.c)、[偏移校验](../../../drivers/syscon/syscon_common.h)和[设备树绑定](../../../dts/bindings/syscon/syscon.yaml)。本次官方原始文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：配置前提：reg-io-width必须与硬件实际寄存器访问宽度一致。当前绑定只声明它为整数，驱动却在宽度分支前以reg % reg_width检查对齐；若配置为0，会在进入返回-EINVAL的宽度分支前产生除零问题。因此不要用非法宽度作为可安全尝试的探测方式。1／2字节写入会使用相应窄访问，调用者应使值和掩码适合硬件宽度，不能期待驱动自动报告所有高位丢失。

> 译注——源码核对：可选操作与错误：当前结构五个回调全部标为OPT。各包装器在API表或对应回调为空时返回-ENOSYS，否则原样传递驱动返回值；不支持update_bits时不会自动退回分开的read／write。返回表列出的0和-ENOSYS不是所有具体驱动错误的穷举，例如通用驱动还可返回-EINVAL。输出错误码并不表示这些包装器已经设置标准C的errno。
