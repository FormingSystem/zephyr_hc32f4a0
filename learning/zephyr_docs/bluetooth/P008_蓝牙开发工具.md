# 第8章\_蓝牙开发工具

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/bluetooth/bluetooth-tools.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

本页介绍辅助蓝牙协议栈及应用开发的工具，用于简化调试和交互、加快开发。

<a id="mobile-applications"></a>
<a id="bluetooth-mobile-apps"></a>

## 8.1\_移动端应用（Mobile applications）

借助已有移动应用与运行Zephyr的硬件交互，通常可以在不编写额外代码、不增加额外硬件的情况下测试功能。原文推荐以下应用。

| 平台 | 应用 |
| --- | --- |
| Android | [nRF Connect for Android](https://play.google.com/store/apps/details?id=no.nordicsemi.android.mcp&hl=en)、[nRF Mesh for Android](https://play.google.com/store/apps/details?id=no.nordicsemi.android.nrfmeshprovisioner&hl=en)、[LightBlue for Android](https://play.google.com/store/apps/details?id=com.punchthrough.lightblueexplorer&hl=en_US) |
| iOS | [nRF Connect for iOS](https://itunes.apple.com/us/app/nrf-connect/id1054362403)、[nRF Mesh for iOS](https://itunes.apple.com/us/app/nrf-mesh/id1380726771)、[LightBlue for iOS](https://itunes.apple.com/us/app/lightblue-explorer/id557428110) |

## 8.2\_配合Zephyr使用BlueZ（Using BlueZ with Zephyr）

Linux蓝牙协议栈BlueZ附带实用工具，可用于调试Zephyr的主机（Host）和控制器（Controller），并与它们交互。原文要求使用较新的Linux内核与BlueZ，并列出以下版本：Linux Kernel 4.10+、BlueZ 4.45+。

Linux发行版可能没有默认打包全部BlueZ工具。如果需要从源码更新或取得完整工具，可按下面步骤构建。在GNU/Linux终端进入自行选择的源码存放父目录后，克隆命令会创建 `bluez` 子目录；后续命令在该目录执行。

```bash
git clone git://git.kernel.org/pub/scm/bluetooth/bluez.git
cd bluez
./bootstrap-configure --disable-android --disable-midi
make
```

随后可在 `tools/` 找到 `btattach`、`btmgt`和 `btproxy`，在 `monitor/` 找到 `btmon`。

> 译注——名称与版本：上述版本下限和命令按Zephyr原页保留，不代表对所有新版本的构建依赖承诺。原文的 `btmgt` 是拼写错误；[BlueZ构建文件](https://raw.githubusercontent.com/bluez/bluez/master/Makefile.tools)中的程序名为 `tools/btmgmt`，本页后面的管理示例也使用该名称。此处的目录从BlueZ源码根解析，不能与Zephyr源码根混淆。

要使用较新的蓝牙功能，需要启用BlueZ实验特性。编辑系统服务文件 `/lib/systemd/system/bluetooth.service`，确保守护进程启动行带有 `-E`：

```ini
ExecStart=/usr/libexec/bluetooth/bluetoothd -E
```

最后，在GNU/Linux终端重新加载服务配置并重启服务：

```bash
sudo systemctl daemon-reload
sudo systemctl restart bluetooth
```

> 译注：`ExecStart`是服务文件配置，不是终端命令。这里的系统服务路径和后文的Unix套接字路径来自官方操作示例，与读者把仓库克隆在哪个磁盘无关；实际发行版的服务文件位置应按其安装布局确认。本次翻译没有修改服务或安装BlueZ。

## 8.3\_在QEMU或native_sim中运行（Running on QEMU or native_sim）

蓝牙应用可以运行于[QEMU模拟器](../application/P001_应用开发.md#application-run-qemu)或 [`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)。两种方式都需要把宿主操作系统Linux的蓝牙控制器导出供模拟端使用，所需工具见[BlueZ设置](#using-bluez-with-zephyr)。

<a id="using-the-host-system-bluetooth-controller"></a>

### 8.3.1\_使用宿主系统蓝牙控制器（Using the Host System Bluetooth Controller）

宿主系统控制器按以下方式接入：

- 对QEMU，通过Unix套接字连接第二条串口。参数为 `-serial unix:/tmp/bt-server-bredr`；应用启用蓝牙支持时，会通过 `QEMU_EXTRA_FLAGS` 自动传给QEMU。
- 对 [`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)，通过传给可执行程序的 `--bt-dev=hci0` 参数，连接其 [蓝牙用户通道驱动（BT User Channel Driver）](../native_reference/P004_Native_Simulator本机模拟器.md#nsim-bt-host-cont)。

在宿主侧，BlueZ通过用户通道（User Channel）导出控制器，供QEMU或[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)使用。

> 原文说明：只有QEMU需要运行 `btproxy`；[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)自行处理Unix套接字代理。

使用QEMU时，先确保控制器处于关闭（down）状态，再从BlueZ源码根调用 `btproxy` 打开监听套接字。下面第一行为命令，第二行为预期输出。

```console
sudo tools/btproxy -u -i 0
Listening on /tmp/bt-server-bredr
```

`-i 0`中的索引应按要代理的控制器替换。若运行QEMU时出现 `Received unknown host packet type 0x00`，表示收到未知主机数据包类型0x00，应在 `btproxy` 命令中加入 `-z`，忽略启动时传送的空字节。

硬件连接并准备好后，从 `samples/bluetooth` 选择示例，切换到Zephyr源码根构建和运行。`<sample>`是待替换的示例目录名。

运行QEMU蓝牙应用：

```bash
west build -b qemu_x86 samples/bluetooth/<sample>
west build -t run
```

此时QEMU第二条串口连接到 `bt-server-bredr` Unix套接字，应用由此访问控制器。

使用 [`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim) 时先构建：

```bash
west build -b native_sim samples/bluetooth/<sample>
```

然后运行；`$`是原文终端提示符，不属于命令。

```console
$ sudo ./build/zephyr/zephyr.exe --bt-dev=hci0
```

<a id="using-a-zephyr-based-bluetooth-controller"></a>

### 8.3.2\_使用基于Zephyr的控制器（Using a Zephyr-based Bluetooth Controller）

根据现有硬件，构建基于Zephyr的单模蓝牙控制器时可选两种传输：

- UART：使用 [HCI UART](../bluetooth_samples/P016_HCI_UART传输.md#bluetooth_hci_uart) 示例，按[在QEMU或native_sim中使用控制器](../bluetooth_samples/P016_HCI_UART传输.md#bluetooth-hci-uart-qemu-posix)的说明操作。
- USB：使用 [HCI USB](../usb/P190_蓝牙HCIUSB控制器示例.md#bluetooth_hci_usb) 示例，之后把它作为上一节的宿主系统蓝牙控制器使用。

<a id="hci-tracing"></a>
<a id="bluetooth-hci-tracing"></a>

### 8.3.3\_HCI跟踪（HCI Tracing）

Host运行在电脑上、连接外部Controller时，查看双方完整交互日志非常有用。该日志采用[主机控制器接口（Host Controller Interface，HCI）](P003_蓝牙协议栈架构.md#bluetooth-hci)格式，可以用BlueZ中的 `btmon` 查看：

```console
$ btmon
```

输出示例如下：

```text
= New Index: 00:00:00:00:00:00 (Primary,Virtual,Control)                     0.274200
= Open Index: 00:00:00:00:00:00                                              0.274500
< HCI Command: Reset (0x03|0x0003) plen 0                                 #1 0.274600
> HCI Event: Command Complete (0x0e) plen 4                               #2 0.274700
      Reset (0x03|0x0003) ncmd 1
      Status: Success (0x00)
< HCI Command: Read Local Supported Features (0x04|0x0003) plen 0         #3 0.274800
> HCI Event: Command Complete (0x0e) plen 12                              #4 0.274900
      Read Local Supported Features (0x04|0x0003) ncmd 1
      Status: Success (0x00)
      Features: 0x00 0x00 0x00 0x00 0x60 0x00 0x00 0x00
         BR/EDR Not Supported
         LE Supported (Controller)
```

> 译注——日志对照：New Index／Open Index为新建／打开控制器索引；Primary、Virtual、Control分别表示主要、虚拟和控制类型。HCI Command／HCI Event分别为HCI命令／事件，Reset为复位，Command Complete为命令完成，Read Local Supported Features为读取本地支持特性；Status: Success表示成功。`plen`为参数长度，`ncmd`为可用命令包数，Features为特性位；BR/EDR Not Supported表示不支持经典蓝牙，LE Supported (Controller)表示支持LE控制器功能。原样保留的时间戳、包序号和十六进制值属于示例输出，不是本次运行记录。

<a id="embedded-hci-tracing"></a>
<a id="bluetooth-embedded-hci-tracing"></a>

#### 8.3.3.1\_嵌入式HCI跟踪（Embedded HCI tracing）

Host和Controller运行在实际芯片上时，默认控制台只有普通日志，无法直接访问两者间HCI流量。蓝牙提供一种特殊日志模式，把控制台改为二进制协议，将普通日志和HCI流量交错传输。

构建应用前，在配置中启用以下选项：

```kconfig
CONFIG_BT_DEBUG_MONITOR_UART=y
CONFIG_UART_CONSOLE=n
```

[`CONFIG_BT_DEBUG_MONITOR_UART`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_DEBUG_MONITOR_UART)启用该格式；关闭 [`CONFIG_UART_CONSOLE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_UART_CONSOLE) 后，该UART不再用于系统控制台，例如 `printk` 和[启动横幅（boot banner）](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BOOT_BANNER)。

如果开发板的监视UART驱动支持中断API，还可设置 [`CONFIG_BT_DEBUG_MONITOR_UART_INTERRUPT_DRIVEN`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_DEBUG_MONITOR_UART_INTERRUPT_DRIVEN)：它对完整监视记录排队，在UART中断处理程序中发送，避免逐字节发送时阻塞。缓冲区容纳不下的记录会被丢弃，并在下一条监视记录中报告；大小可通过 [`CONFIG_BT_DEBUG_MONITOR_UART_BUFFER_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_DEBUG_MONITOR_UART_BUFFER_SIZE) 调整。

要解码控制台UART输出的二进制协议，在Linux主机上使用BlueZ的 `btmon`；把 `<console TTY>` 替换为实际串口设备。

```console
$ btmon --tty <console TTY> --tty-speed 115200
```

如果没有UART，或仍希望保留非二进制日志，可改设 [`CONFIG_BT_DEBUG_MONITOR_RTT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_DEBUG_MONITOR_RTT)，使用SEGGER实时传输（Real Time Transfer，RTT）。例如连接序列号为683578642的nRF52840DK：

```console
$ btmon --jlink nRF52840_xxAA,683578642
```

> 译注：`nRF52840_xxAA`与`683578642`是原文的目标器件和探针序列号示例，应按实际设备替换，不是本仓库目标板的固定参数。

## 8.4\_虚拟控制器与native_sim（Running on a Virtual Controller and native_sim）

可以用虚拟控制器替代物理蓝牙控制器，通过支持HCI H4协议的HCI TCP服务器连接。与物理方案相比，它允许在没有实际蓝牙控制器的情况下，测试运行于原生目标板的Zephyr应用。

主要用途是不依赖蓝牙硬件的连接测试，从而自动执行Zephyr与外部应用——例如蓝牙网关或移动应用——之间的集成测试。

原文使用Google实验性Python模块 [Bumble](https://github.com/google/bumble) 演示：它可以创建基于TCP的虚拟蓝牙控制器，并连接Zephyr Host。安装方式见 [Bumble入门指南](https://google.github.io/bumble/getting_started.html)。

> 原文说明：如果Zephyr应用需要HCI LE Set extended命令，应安装Bumble的 `controller-extended-advertising` 分支。

> 译注：以上分支要求按原页保留，属于该示例的版本背景；本页没有证明这一分支名称对任意Bumble发行版本都仍适用，不能把历史分支名当作通用安装条件。

<a id="android-emulator"></a>

### 8.4.1\_Android模拟器（Android Emulator）

可把Zephyr蓝牙应用连接到Android模拟器来测试虚拟控制器。原文步骤如下。

1. 构建Zephyr应用并关闭HCI ACL流控，即 `CONFIG_BT_HCI_ACL_FLOW_CONTROL=n`，因为原文所述Android虚拟控制器当时不支持该功能。ACL为异步无连接链路（Asynchronous Connection-Less），此配置的方向见[应用开发页](P006_蓝牙应用开发.md#host-on-linux-with-an-external-controller)译注。
2. 安装Android Emulator 33.1.4.0或更新版本；原文认为最简单的方法是安装最新 [Android Studio Preview](https://developer.android.com/studio/preview)。
3. 使用 [Android设备管理器](https://developer.android.com/studio/run/managing-avds)创建Android虚拟设备（Android Virtual Device，AVD），SDK API级别至少为34。
4. 在终端启动模拟器。原文命令为 `emulator avd YOUR_AVD -packet-streamer-endpoint default`。
5. 使用Bumble的 `hci-bridge` 在Zephyr应用与Android虚拟控制器之间建立蓝牙桥接：`bumble-hci-bridge tcp-server:_:1234 android-netsim`。原文称这会在本机IP `127.0.0.1`、端口1234创建TCP桥接服务器。
6. 运行Zephyr应用并连接该服务器：`./zephyr.exe --bt-dev=127.0.0.1:1234`。

> 译注——启动参数修正：[Android官方命令行文档](https://developer.android.com/studio/run/emulator-commandline)规定虚拟设备选项是 `-avd`，原页命令漏了连字符。对应修正为 `emulator -avd YOUR_AVD -packet-streamer-endpoint default`，其中 `YOUR_AVD`替换为实际虚拟设备名。本次只核对参数文档，没有启动模拟器。

> 译注——监听地址修正：[Bumble的TCP服务器实现](https://raw.githubusercontent.com/google/bumble/main/bumble/transport/tcp_server.py)把 `_`映射为`host=None`，表示通配监听，不保证仅监听`127.0.0.1`。如果只需原文描述的本机回环连接，应明确写为 `bumble-hci-bridge tcp-server:127.0.0.1:1234 android-netsim`。第6步原命令以可执行文件所在目录为当前位置；若仍在Zephyr源码根，则使用 `./build/zephyr/zephyr.exe --bt-dev=127.0.0.1:1234`。这些路径均由实际构建目录相对解析。

完成上述步骤后，Zephyr应用通过Bumble桥接的虚拟控制器向Android模拟器提供蓝牙功能。可在AVD蓝牙设置中扫描Zephyr设备来确认通信；可选[心率监视器外设](../bluetooth_samples/P007_心率服务外设.md#ble_peripheral_hr)或 [设备信息服务（Device Information Service，DIS）外设](../bluetooth_samples/P025_设备信息服务外设.md#ble_peripheral_dis)示例。

## 8.5\_将Zephyr控制器用于BlueZ（Using Zephyr-based Controllers with BlueZ）

若希望用BlueZ Host测试Zephyr Controller，需要先准备[BlueZ工具](#using-bluez-with-zephyr)。从BlueZ源码根启动管理工具，然后在其交互提示符中操作：

```console
sudo tools/btmgmt --index 0
[hci0]# auto-power
[hci0]# find -l
```

`--index 0`应按实际控制器索引替换；`auto-power`用于自动上电，`find -l`执行LE发现。`[hci0]#`为工具提示符，不能当作Shell命令前缀。`btmgmt`的更多说明可查看其手册页。

> 译注：本页保留官方构建、服务修改和调试命令及原始输出；本批只翻译和核对，没有安装BlueZ／Bumble、修改系统服务、运行模拟器或连接蓝牙设备。

对应官方文档源码：[doc/services/connectivity/bluetooth/bluetooth-tools.rst](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/doc/services/connectivity/bluetooth/bluetooth-tools.rst)。

> 译注——源码跟踪：本仓库的[对应源码](../../../doc/services/connectivity/bluetooth/bluetooth-tools.rst)可用于跟踪，版本可能与网页不同；本批仅翻译和核对文档，没有执行固件构建、模拟运行或烧录。
