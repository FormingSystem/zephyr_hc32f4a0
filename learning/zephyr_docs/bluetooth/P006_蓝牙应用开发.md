# 第6章\_蓝牙应用开发

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/bluetooth/bluetooth-dev.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

蓝牙应用使用[应用开发（Application Development）](../application/P001_应用开发.md#application)中介绍的通用基础设施与方法。本页补充只与蓝牙有关的内容。

<a id="thread-safety"></a>

## 6.1\_线程安全（Thread safety）

除 API 函数文档另有说明外，蓝牙 API 的设计目标是线程安全（Thread-safe）。确保所有调用都满足这一目标的工作仍在进行；本段正式声明的是总体目标。欢迎提交有助于实现这一目标的缺陷报告和拉取请求（Pull Request，PR）。

<a id="hardware-setup"></a>
<a id="bluetooth-hw-setup"></a>

## 6.2\_硬件设置（Hardware setup）

构建和调试 Zephyr 蓝牙应用时，可根据现有硬件、需求和开发方式选择设置。主要有三类：嵌入式平台、使用外部控制器的QEMU或[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)主机，以及通过BabbleSim模拟的nRF5x。

<a id="embedded"></a>
<a id="bluetooth-hw-setup-embedded"></a>

### 6.2.1\_嵌入式平台（Embedded）

此方案让全部软件直接运行在应用的目标嵌入式平台上，支持全部[部署配置](P003_蓝牙协议栈架构.md#bluetooth-configs)与[构建类型](P003_蓝牙协议栈架构.md#bluetooth-build-types)。如果采用双芯片方案，或者SoC多个核运行不同构建类型，例如一核运行主机（Host）、另一核运行控制器（Controller），可能需要分别构建多次Zephyr。

按[入门指南](../getting_started/P002_入门指南.md#getting-started)选择支持蓝牙的开发板；双芯片方案可能需要多块板，然后[运行应用](../application/P001_应用开发.md#application-run-board)。即使Host和Controller之间没有物理传输，也能取得两者之间的[主机控制器接口（Host Controller Interface，HCI）](P003_蓝牙协议栈架构.md#bluetooth-hci)流量，方法见[嵌入式HCI跟踪](P008_蓝牙开发工具.md#bluetooth-embedded-hci-tracing)。

<a id="host-on-linux-with-an-external-controller"></a>
<a id="bluetooth-hw-setup-external-ll"></a>

### 6.2.2\_Linux主机与外部控制器（Host on Linux with an external Controller）

> 原文说明：目前仅适用于GNU/Linux。

此方案采用[双芯片配置](P003_蓝牙协议栈架构.md#bluetooth-configs)：[仅主机](P003_蓝牙协议栈架构.md#bluetooth-build-types)应用运行在QEMU模拟器或Zephyr的[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)原生移植上；Controller可选商用控制器、Zephyr[仅控制器](P003_蓝牙协议栈架构.md#bluetooth-build-types)构建，或[虚拟控制器](P008_蓝牙开发工具.md#bluetooth-virtual-posix)。

> 原文警告：某些外部控制器不能接受Zephyr默认设置的流控参数，例如Qualcomm；或者不能从Controller向Host传送任何数据，例如Realtek。若启动示例时出现如下消息，或Controller→Host没有数据，需要调整流控设置。查看日志前，应先在应用的 `prj.conf` 启用 [`CONFIG_LOG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LOG)。

```text
<wrn> bt_hci_core: opcode 0x0c33 status 0x12
```

原文要求在 `prj.conf` 设置 `CONFIG_BT_HCI_ACL_FLOW_CONTROL=n`。

> 译注——流控方向：原文两处把这里称作“Host to Controller flow control”；但[官方Kconfig定义](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/subsys/bluetooth/Kconfig)明确表示该选项控制 **Controller→Host** 的异步无连接链路（Asynchronous Connection-Less，ACL）缓冲流控。本仓库的[对应Kconfig](../../../subsys/bluetooth/Kconfig)也作此定义。保留原配置值，方向按配置实际含义理解；此处是特定控制器兼容性处理，不应当作所有蓝牙应用的默认设置。

<a id="qemu"></a>
<a id="bluetooth-hw-setup-qemu-host"></a>

#### 6.2.2.1\_QEMU

Zephyr Host可以在[QEMU模拟器](../application/P001_应用开发.md#application-run-qemu)中运行，与外部物理蓝牙控制器交互。完整构建和运行方法见[在QEMU或native_sim中运行](P008_蓝牙开发工具.md#bluetooth-qemu-native)。

<a id="native-sim"></a>
<a id="bluetooth-hw-setup-native-sim-host"></a>

#### 6.2.2.2\_native_sim

> 原文说明：目前仅适用于GNU/Linux。

[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)把Zephyr应用、Zephyr内核以及最少量的硬件模拟一起构建成原生Linux可执行程序。它是普通Linux程序，可以用常见方式调试和插桩，并与外部物理或虚拟控制器通信。物理控制器设置见[QEMU／native_sim运行方法](P008_蓝牙开发工具.md#bluetooth-qemu-native)；虚拟控制器设置见[虚拟控制器与native_sim](P008_蓝牙开发工具.md#bluetooth-virtual-posix)。

<a id="simulated-nrf5x-with-babblesim"></a>
<a id="bluetooth-hw-setup-bsim"></a>

### 6.2.3\_使用BabbleSim模拟nRF5x（Simulated nRF5x with BabbleSim）

> 原文说明：目前仅适用于GNU/Linux。

[`nrf52_bsim`](../bsim_reference/P002_NRF52模拟开发板.md#nrf52-bsim)与[`nrf5340bsim`](../bsim_reference/P003_NRF5340模拟开发板.md#nrf5340bsim)是模拟目标板，模拟开发、测试低功耗蓝牙（Bluetooth Low Energy，LE）应用所需的nRF52／53 SoC外设。这些目标使用：

- [BabbleSim](https://babblesim.github.io/)模拟nRF5x调制解调器与射频环境。
- POSIX体系结构与原生模拟器模拟处理器，并在主机上原生运行。
- [nRF5x硬件模型](https://github.com/BabbleSim/ext_NRF_hw_models/)。

与[`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim)一样，构建结果是普通Linux可执行程序。单设备或多设备模拟的运行方式见[相应开发板文档](../bsim_reference/P002_NRF52模拟开发板.md#nrf52bsim-build-and-run)。

[`nrf52_bsim`](../bsim_reference/P002_NRF52模拟开发板.md#nrf52-bsim)通常采用[合并构建](P003_蓝牙协议栈架构.md#bluetooth-build-types)；也可以在一个模拟设备中用[HCI UART](../bluetooth_samples/P016_HCI_UART传输.md#bluetooth_hci_uart)示例构建Controller，在另一个模拟设备中使用H4驱动而非集成控制器来构建Host。

[`nrf5340bsim`](../bsim_reference/P003_NRF5340模拟开发板.md#nrf5340bsim)可以让Controller与Host都运行在网络核，也可以只让Controller运行于网络核，Host和应用运行于应用核，通过核间通信（Inter-Process Communication，IPC）承载HCI。

<a id="initialization"></a>

## 6.3\_初始化（Initialization）

通过 [`bt_enable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__gap.html#gac45d16bfe21c3c38e834c293e5ebc42b) 初始化蓝牙子系统。调用者必须检查返回码，确认是否成功。如果传入函数指针，则异步初始化，完成后通过给定函数通知。

<a id="bluetooth-application-example"></a>

## 6.4\_蓝牙应用示例（Bluetooth Application Example）

下面是一个简单的蓝牙信标（Beacon）应用。它初始化蓝牙子系统并启用不可连接广播，实际充当LE广播者（Broadcaster）。代码按原文完整保留。

```c

/*
 * Set Advertisement data. Based on the Eddystone specification:
 * https://github.com/google/eddystone/blob/master/protocol-specification.md
 * https://github.com/google/eddystone/tree/master/eddystone-url
 */
static const struct bt_data ad[] = {
	BT_DATA_BYTES(BT_DATA_FLAGS, BT_LE_AD_NO_BREDR),
	BT_DATA_BYTES(BT_DATA_UUID16_ALL, 0xaa, 0xfe),
	BT_DATA_BYTES(BT_DATA_SVC_DATA16,
		      0xaa, 0xfe, /* Eddystone UUID */
		      0x10, /* Eddystone-URL frame type */
		      0x00, /* Calibrated Tx power at 0m */
		      0x00, /* URL Scheme Prefix http://www. */
		      'z', 'e', 'p', 'h', 'y', 'r',
		      'p', 'r', 'o', 'j', 'e', 'c', 't',
		      0x08) /* .org */
};

/* Set Scan Response data */
static const struct bt_data sd[] = {
	BT_DATA(BT_DATA_NAME_COMPLETE, DEVICE_NAME, DEVICE_NAME_LEN),
};

static void bt_ready(int err)
{
	bt_addr_le_t addr = {0};
	size_t count = 1;

	if (err) {
		printk("Bluetooth init failed (err %d)\n", err);
		return;
	}

	printk("Bluetooth initialized\n");

	/* Start advertising */
	err = bt_le_adv_start(BT_LE_ADV_NCONN_IDENTITY, ad, ARRAY_SIZE(ad),
			      sd, ARRAY_SIZE(sd));
	if (err) {
		printk("Advertising failed to start (err %d)\n", err);
		return;
	}


	/* For connectable advertising you would use
	 * bt_le_oob_get_local().  For non-connectable non-identity
	 * advertising an non-resolvable private address is used;
	 * there is no API to retrieve that.
	 */

	bt_id_get(&addr, &count);

	printk("Beacon started, advertising as %s\n", bt_addr_le_str(&addr));
}

int main(void)
{
	int err;

	printk("Starting Beacon Demo\n");

	/* Initialize the Bluetooth Subsystem */
	err = bt_enable(bt_ready);
	if (err) {
		printk("Bluetooth init failed (err %d)\n", err);
	}
	return 0;
}
```

该示例的关键API是初始化蓝牙的 [`bt_enable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__gap.html#gac45d16bfe21c3c38e834c293e5ebc42b)，以及按指定广播数据与扫描响应数据组合启动广播的 [`bt_le_adv_start()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bt__gap.html#gad2e3caef88d52d720e8e4d21df767b02)。

> 译注——代码注释和输出：`ad`按Eddystone规范设置广播数据，包含Eddystone UUID、Eddystone-URL帧类型、0米校准发送功率、`http://www.`前缀与`.org`后缀，对应`zephyrproject.org`；`sd`设置扫描响应数据，包含完整设备名。`Starting Beacon Demo`表示开始信标演示，`Bluetooth initialized`表示初始化完成，`Bluetooth init failed`及`Advertising failed to start`分别表示初始化或启动广播失败，括号中给出错误码；`Beacon started, advertising as`表示已启动信标并输出广播地址。

> 译注——地址注释：可连接广播可使用 `bt_le_oob_get_local()`；不可连接且不使用身份地址的广播采用不可解析私有地址（Non-resolvable Private Address，NRPA），原注释说明没有获取该地址的API。本例使用 `BT_LE_ADV_NCONN_IDENTITY`，通过 `bt_id_get()` 取得身份地址并打印。以上是原代码说明，未把其他广播类型的地址获取方式混入本例；完整构建环境及 `DEVICE_NAME` 等定义应参考实际示例工程。
