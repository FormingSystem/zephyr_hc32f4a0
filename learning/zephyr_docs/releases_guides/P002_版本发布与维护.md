# 第2章\_版本发布（Releases）

原文：[官方页面](https://docs.zephyrproject.org/latest/releases/index.html)。读取日期：2026-10-16；来源摘要见[来源记录](../SOURCES.md)。

Zephyr以源代码及构建脚本形式分发，不提供统一的二进制镜像。使用Zephyr元工具West获取特定版本代码，所有带标签发行版的完整历史可在[GitHub仓库](https://github.com/zephyrproject-rtos/zephyr)查看。（[West，Zephyr元工具（Meta-tool）](../west/P014_west官方总入口.md#west)；[获取代码](../getting_started/P002_入门指南.md#get-the-code)）

当前及历史版本技术文档位于[https://docs.zephyrproject.org/](https://docs.zephyrproject.org/)，可通过版本选择器选择所需版本。

<a id="end-of-life-releases"></a>

### 停止维护的版本（End-of-life Releases）

停止维护的版本不再维护，也不再接收安全修复；这些版本的发行说明及迁移指南可在此查阅。（[此处](P001_停止维护的版本.md#eol-releases)）

<a id="release-life-cycle-and-maintenance"></a>

<a id="zephyr-release-cycle"></a>

## 版本生命周期与维护（Release Life Cycle and Maintenance）

<a id="major-and-maintenance-releases"></a>

### 主版本与维护版本（Major and Maintenance Releases）

Zephyr每6个月发布一个主版本，目标时间为每年4月及10月。此节奏提供定期且经过充分测试的版本，避免更新过于频繁给用户造成负担，并避开不同地区的主要节假日。

当主版本分支积累足够多的重要修复后，会不定期发布维护版本，即补丁版本（Point Release）。每个补丁版本发布前均经过完整质量保证QA周期。

<a id="long-term-support-and-maintenance"></a>

### 长期支持与维护（Long Term Support and Maintenance）

稳定版支持持续2个发布周期，约1年；Zephyr项目会对其中某些版本提供更长支持，这些版本称为长期支持版LTS。

Zephyr每2.5～3年发布一个长期支持版LTS，独立于主线建立分支并维护，维护期约为发布后5年。（[长期支持（Long Term Support，LTS）](../project_governance/P008_发布流程.md#release-process-lts)）

这样可为项目用户提供更稳定的基础，并留出更多时间升级到下一个LTS。

<a id="transitioning-to-the-new-release-cadence"></a>

### 过渡到新的发布节奏

新的发布节奏从2026年开始过渡。Zephyr 4.4计划于2026年4月发布，此后每6个月发布一次。

<a id="security-fixes"></a>

### 安全修复（Security Fixes）

Zephyr中修复的每个安全问题都会回移或提交到以下版本：


- 当前受支持的长期支持版LTS。
- 最近的两个版本。

更多信息见[安全漏洞报告（Security Vulnerability Reporting）](../security/P007_安全漏洞报告.md#reporting)。

<a id="release-documentation"></a>

## 发行文档（Release Documentation）

每个发行版本包含两份配套文档：


- 发行说明（Release Notes）概述该发布周期内整个项目的变更。
- 迁移指南（Migration Guide）描述应用从上一个主版本迁移到下一个主版本时，需要用户采取措施的变更。

<a id="release-notes"></a>

### 发布说明（Release Notes）

发行说明列出版本开发周期内项目各领域的变化。要求用户修改应用才能支持新版本的变化也可在发行说明中提及，但具体修改内容应详细写在该版本的迁移指南中。

发布周期结束后仍允许更新发行说明，但仅限于文体、排版错误修正，以及从维护版本分支向上合并说明，其唯一目的在于使最新文档与项目变更保持一致。

<a id="migration-guides"></a>

### 迁移指南（Migration Guides）

Zephyr为所有主版本提供迁移指南，帮助用户从上一版本过渡。

如上节所述，为保持应用现有行为而要求用户采取行动，例如修改源码或配置文件的代码变化，都属于迁移指南内容，包括：


- 破坏兼容性的API变更。
- 弃用项（Deprecations）
- 影响用户的设备树或Kconfig变更，例如默认值变化、重命名等。
- 产生影响的全源码树变更，例如改变头文件包含路径或默认使用另一种C标准库。
- 其他可能影响已有应用编译或运行时行为的变化。

迁移指南每一项都必须简要解释变更，并引用引入该变更的拉取请求（Pull Request），让用户了解背景。

## 译注

支持状态、发布日期及发布节奏来自本页快照；阅读其他版本时请同时核对对应版本文档。
