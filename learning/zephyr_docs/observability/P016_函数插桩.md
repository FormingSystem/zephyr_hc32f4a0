# 第16章\_函数插桩

原文：[Instrumentation](https://docs.zephyrproject.org/latest/services/instrumentation/index.html)。读取日期：2026-10-13，`latest`。

## 16.1\_概述与选择

**插桩（Instrumentation）**子系统为 Zephyr 应用提供由编译器管理的运行时系统插桩能力。开发者只需很少的手工插桩工作，即可跟踪函数调用、观察上下文切换（Context Switch）和分析应用性能。

跟踪子系统提供能理解**实时操作系统（Real-Time Operating System，RTOS）**事件的结构化**应用程序编程接口（Application Programming Interface，API）**。插桩子系统则在更低层使用编译器插桩钩子，几乎可以捕获任意函数的进入和退出，无须在代码中手动添加跟踪调用。

| 需求 | 适合的子系统 |
| --- | --- |
| 跟踪线程切换、信号量操作等RTOS事件，并尽量降低开销 | 跟踪（Tracing） |
| 详细查看函数级执行、理解代码流程或定位性能瓶颈，且不手动加跟踪点 | 插桩（Instrumentation） |

自动函数插桩依赖编译器支持。启用后，编译器会在应用中每个函数的入口和出口插入特殊处理函数调用，但显式标记为 `__no_instrumentation__` 的函数除外。目前只支持 **GNU编译器集合（GNU Compiler Collection，GCC）**的 `-finstrument-functions` 选项。

子系统在**随机存取存储器（Random Access Memory，RAM）**初始化后自动初始化，并通过触发函数（Trigger）和停止函数（Stopper）控制记录区间。两者默认均为 `main()`，可通过 Kconfig 配置；默认记录从进入 `main()` 到其返回的整个执行过程。

数据存放在 RAM 中，可通过提供简单命令的**通用异步收发器（Universal Asynchronous Receiver/Transmitter，UART）**后端从主机访问。`scripts/instrumentation/zaru.py` 脚本提供较高层的命令行界面，便于取得适合进一步分析的数据，例如交给 Perfetto 查看器。

## 16.2\_调用图模式

两种工作模式可以分别启用，也可以同时启用。

**调用图模式（Callgraph Mode）**由 [`CONFIG_INSTRUMENTATION_MODE_CALLGRAPH`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_MODE_CALLGRAPH) 启用，将函数进入/退出事件、时间戳（Timestamp）和上下文信息记录到内存缓冲区，可重建完整函数调用图、观察线程上下文切换，并分析执行流程和时间关系。

跟踪缓冲区默认采用**环形缓冲区（Ring Buffer）**，新条目覆盖旧条目；也可采用写满即停止的固定缓冲区（Fixed Buffer）。大小通过 [`CONFIG_INSTRUMENTATION_MODE_CALLGRAPH_TRACE_BUFFER_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_MODE_CALLGRAPH_TRACE_BUFFER_SIZE) 配置。

## 16.3\_统计模式

**统计模式（Statistical Mode）**由 [`CONFIG_INSTRUMENTATION_MODE_STATISTICAL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_MODE_STATISTICAL) 启用。它对触发点和停止点之间执行的每个不同函数累积计时统计，提供逐函数总执行时间，帮助识别性能瓶颈。最多跟踪 [`CONFIG_INSTRUMENTATION_MODE_STATISTICAL_MAX_NUM_FUNC`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_MODE_STATISTICAL_MAX_NUM_FUNC) 个不同函数。

以下官方示例显示耗时最多的 10 个函数：

```console
$ ./scripts/instrumentation/zaru.py profile -n 10

9.45% 0000061d main
6.00% 0000049d k_msleep
5.98% 00000469 k_sleep
5.95% 0000aea1 k_sleep_ticks
5.93% 0000ad6d z_impl_k_sleep_ticks
5.66% 00000431 k_sem_take
5.65% 00007e65 z_impl_k_sem_take
5.51% 0000ac29 z_pend_curr
2.83% 000063ed sys_clock_isr
2.67% 0000d361 sys_clock_announce
```

## 16.4\_配置与保留内存

启用插桩及对应模式：

```ini
CONFIG_INSTRUMENTATION=y
CONFIG_INSTRUMENTATION_MODE_CALLGRAPH=y    # For tracing
CONFIG_INSTRUMENTATION_MODE_STATISTICAL=y  # For profiling
```

插桩子系统通过 UART 控制台与目标设备通信。原文要求 `zephyr_console` 所选节点指向希望使用的 UART 控制器。

[保留内存（Retained Memory）](https://docs.zephyrproject.org/latest/services/storage/retention/index.html#retention-api)可让触发/停止函数地址在重启后继续保留。这是可选功能，通过 [`CONFIG_INSTRUMENTATION_DYNAMIC_TRIGGER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_DYNAMIC_TRIGGER) 启用。启用后，设备树（Devicetree）必须指定保留内存区域。以下示例从主静态随机存取存储器（Static Random Access Memory，SRAM）中划出保留区域；宏 `DT_SIZE_K` 按 1024 字节为单位表达大小：

```dts
/ {
    sram@2003FC00 {
        compatible = "zephyr,memory-region", "mmio-sram";
        reg = <0x2003FC00 DT_SIZE_K(1)>;
        zephyr,memory-region = "RetainedMem";

        retainedmem {
            compatible = "zephyr,retained-ram";
            status = "okay";

            instrumentation_triggers: retention@0 {
                compatible = "zephyr,retention";
                status = "okay";
                reg = <0x0 0x10>;
            };
        };
    };
};

/* Adjust main SRAM to exclude retained region */
&sram0 {
    reg = <0x20000000 DT_SIZE_K(255)>;
};
```

完整配置见[插桩示例](P019_函数插桩示例.md)。其他选项包括缓冲区大小、触发函数以及函数/文件排除列表，参见[以 `CONFIG_INSTRUMENTATION_*` 开头的 Kconfig 选项](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_INSTRUMENTATION_*)。

## 16.5\_zaru.py用法

位于 `scripts/instrumentation/zaru.py` 的命令行工具 `zaru.py` 用于控制插桩，并通过 UART 从目标提取数据。支持以下命令：

| 命令 | 用途 |
| --- | --- |
| `status` | 检查目标是否支持调用图跟踪模式、统计分析模式，以及动态触发/停止函数配置 |
| `trace` | 捕获并显示函数调用跟踪 |
| `profile` | 捕获并显示函数性能分析数据 |
| `reboot` | 重启目标设备 |

运行 `zaru.py <command> --help` 可查看各命令帮助。默认连接设备 `/dev/ttyACM0`，可通过 `--serial` 指定其他串口：

```shell
$ ./scripts/instrumentation/zaru.py --serial /dev/ttyACM1 status
```

`--build-dir` 指定 Zephyr 构建目录，用于定位符号解析所需的**可执行与可链接格式（Executable and Linkable Format，ELF）**文件。未提供时，脚本会尝试自动查找。详细用法同样参见插桩示例。

## 16.6\_限制与注意事项

| 方面 | 限制或影响 |
| --- | --- |
| 编译器支持 | 需要支持 `-finstrument-functions` 的GCC，不支持其他编译器 |
| 栈大小 | 每次函数调用都会增加插桩开销和栈占用，通常需要增大线程栈，以容纳处理函数与嵌套调用 |
| 执行开销 | 所有函数调用都会承担插桩开销；额外调用增大代码体积，并影响性能 |
| 初始化时机 | RAM初始化之前的代码，例如早期启动函数，在子系统初始化前执行，因此不会被捕获 |

要减少开销，可用触发/停止函数只记录关注的代码区间，并通过 [`CONFIG_INSTRUMENTATION_EXCLUDE_FUNCTION_LIST`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_EXCLUDE_FUNCTION_LIST) 和 [`CONFIG_INSTRUMENTATION_EXCLUDE_FILE_LIST`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_EXCLUDE_FILE_LIST) 排除对性能敏感的函数或文件。
