# 第13章\_周期延迟测量工具

原文：[Zyclictest](https://docs.zephyrproject.org/latest/services/debugging/zyclictest.html)。读取日期：2026-10-13，`latest`。

## 13.1\_测量原理与前提

Zyclictest 模块用于估计实时线程的**最坏情况延迟（Worst-case Latency）**。它可测量硬件中断发生到执行**中断服务例程（Interrupt Service Routine，ISR）**，再到 Zephyr 线程运行的时间。模块及其名称受 Linux 的 `cyclictest` 程序启发，因此称为 Zephyr cyclictest。

它使用定时器中断作为中断源，因为该中断的预定发生时刻是已知的。ISR 读取当前时间，计算它与定时器中断预定时间之差。另外，一个线程也与定时器同步，并测量当前时间与定时器预定时间的差值。两组测量时间存入数组，作为测量结束时打印的直方图（Histogram）的数据源。该过程按指定间隔循环执行。

要了解优先级为 `<p>` 的任务延迟，需要让实际应用运行起来。在其运行期间启动 Zyclictest，并让测试线程的优先级数值至少比被测应用线程小 1。例如，被关注线程的优先级为 `-10` 时，Zyclictest 应使用 `-11` 或更小的数值，也就是更高的优先级。

另一个重要参数是测量间隔。间隔不应小于测得的最坏情况延迟，建议至少为预期或已测最坏情况延迟的两倍。如果结束时报告溢出（Overflow），说明在直方图覆盖的范围内无法确定最坏情况延迟。

为取得有意义的输出，建议将 [`CONFIG_SYS_CLOCK_TICKS_PER_SEC`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SYS_CLOCK_TICKS_PER_SEC) 设为至少 `1000000`，即达到 1 微秒或更细的分辨率；还需要启用无周期节拍内核（Tickless Kernel），即 [`CONFIG_TICKLESS_KERNEL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_TICKLESS_KERNEL)。

## 13.2\_运行模式与配置

默认采用**自由运行模式（Free-running Mode）**，不限定循环次数，停止时打印已获得的结果。

**循环模式（Loop Mode）**通过 `start -l <loops>` 指定循环次数。达到次数后，命令行界面（Shell）显示测试结束消息；也可用 `zyclictest stop -c` 提前取消。

设置 [`CONFIG_ZYCLICTEST_SHELL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ZYCLICTEST_SHELL)，启用 Shell 命令。

## 13.3\_命令用法

启动命令为 `zyclictest start [options]`：

| 选项 | 含义 |
| --- | --- |
| `-i <interval>` | 测量间隔，单位为微秒 |
| `-l <loops>` | 按指定循环次数运行 |
| `-p <prio>` | 设置测试线程优先级 |

停止命令为 `zyclictest stop [options]`：

| 选项 | 含义 |
| --- | --- |
| `-c` | 提前取消循环模式 |
| `-q` | 安静模式（Quiet Mode），仅打印摘要，不打印直方图数据 |

## 13.4\_示例与结果解释

本例测量一个被中断唤醒、优先级为 `-10` 的协作式任务（Cooperative Task）。预期延迟小于 200 μs，采用自由运行模式。

先以 400 μs 间隔启动测试线程，即预期最坏情况延迟的两倍；测试优先级为 `-11`，高于应用线程：

```shell
zyclictest start -i 400 -p -11
```

执行需要测试的应用活动，然后停止测量：

```shell
zyclictest stop
```

官方示例输出如下。`IRQ` 是中断请求（Interrupt Request），`Thread` 表示线程，`Count` 为循环次数，`Max-Latency` 为最大延迟，`Errors` 为错误数，`Overflow` 为溢出数：

```console
Count: 547329
                   IRQ  Thread
Max-Latency:        21      27
Errors:              0       0
Overflow:            0       0
Histogram:
[...]
 23                  0  547306
 24                  0       2
 25                  0       5
 26                  0       5
 27                  0       2
 28                  0       0
[...]
```

本次示例没有错误，也没有溢出，因此测量结果可用。测试执行了 547329 次循环；观测到的最坏中断延迟为 21 μs，最坏线程延迟为 27 μs。
