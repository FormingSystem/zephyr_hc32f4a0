# 第8章\_格式化输出

原文：[Formatted Output](https://docs.zephyrproject.org/latest/services/formatted_output.html)。读取日期：2026-10-12，`latest`。

应用和 Zephyr 自身都需要把值**格式化（Formatting）**为可读内容。标准 C99 的 `*printf()` 系列可以输出到流设备或内存缓冲区，但嵌入式设备未必接受流式输出，也未必有足够内存保存完整格式化结果。

Zephyr 过去为 `printk()` 和内部 minimal libc 提供了彼此独立的内部接口；日志、追踪、shell 和其他应用按构建选项使用它们或标准 libc。

公开的 `cbprintf()` **应用程序编程接口（Application Programming Interface，API）** 通过回调逐字符输出，转换 C99 格式串与参数，替代原有内部函数，并支持几乎全部 C99 格式规范。已有 `s*printf()` 用法可以转为 `snprintfcb()`，避免另行引入 libc 的格式化实现。

## 8.1\_功能与内存配置

以下 Kconfig 项控制启用的功能集合，以便权衡能力和内存占用：

- `CONFIG_CBPRINTF_FULL_INTEGRAL` 或 `CONFIG_CBPRINTF_REDUCED_INTEGRAL`。
- `CONFIG_CBPRINTF_FP_SUPPORT`。
- `CONFIG_CBPRINTF_FP_A_SUPPORT`。
- `CONFIG_CBPRINTF_FP_ALWAYS_A`。
- `CONFIG_CBPRINTF_N_SPECIFIER`。

`CONFIG_CBPRINTF_LIBC_SUBSTS` 提供行为类似标准 libc 的函数，但使用选定的 cbprintf 格式化器，避免从 libc 再引入一套。`CONFIG_CBPRINTF_NANO` 则恢复到此前 `printk()` 使用的极小、功能有限的格式化器。

> 译注——源码跟踪：当前Picolibc配置把带cb后缀的兼容入口映射到标准stdio；普通配置才采用cbprintf.c中的包装器。不能把所有构建都描述成绕开libc。相关配置与版本边界见[公共接口](../cbprintf_reference/P001_回调格式化输出接口.md)。

## 8.2\_Cbprintf打包

`printf` 系列通常在调用时同步格式化，但有些场景适合延后处理。这时需要捕获格式串和参数，形成一个包；包还可以包含格式串自身或 `%s` 参数字符串的副本。

包的主要部分类似 `va_list` 栈帧，因此可以交给标准格式化函数处理。由于数据按 `va_list` 布局读取，必须严格对齐；填充会影响包大小。复制包时，应复制到与原位置具有相同对齐条件的内存块。

### 8.2.1\_三种包

| 类型 | 内容与使用条件 |
| --- | --- |
| 自包含（Self-contained） | 将非只读字符串附加到包中；只要仍可访问只读字符串原位置，就能格式化。可另外记录包内只读字符串指针的位置，以便转换为完全自包含包 |
| 完全自包含（Fully self-contained） | 所有字符串都附加到包中，不依赖外部数据即可格式化 |
| 临时包（Transient） | 只保存参数，并记录非只读字符串指针在包中的位置；可选记录只读字符串位置。使用时非只读字符串必须仍然有效、只读字符串必须可访问。也可转换为自包含包；若带有只读字符串位置信息，还可转成完全自包含包 |

### 8.2.2\_运行时与静态打包

运行时打包使用 `cbprintf_package()` 或 `cbvprintf_package()`，扫描格式串，根据转换说明构建包。

静态打包由预处理器在编译期识别参数类型，再通过简单赋值写入指定内存。原文称其速度可超过运行时方式十五倍，但存在关键限制：参数为字符指针时，无法区分 `%p` 与 `%s`，所有 `char` 或 `unsigned char` 指针都会按字符串处理，并尝试附加内容。

从临时包转换为自包含包时，使用 `CBPRINTF_PACKAGE_CONVERT_PTR_CHECK` 标志可正确处理这种情况，但需要访问格式串，未必总能做到。因此建议给 `%p` 的字符指针先转换为 `void *`。带该标志调用 `cbprintf_package_convert()` 时，如果发现 `%p` 使用字符指针，会生成日志警告。

> 译注：这里的“静态”指编译期类型分析，不表示包必须放在静态存储区。十五倍是原文描述，不是针对当前 HC32 配置的测量结果。

打包行为还受 `CONFIG_CBPRINTF_PACKAGE_LONGDOUBLE` 和 `CONFIG_CBPRINTF_STATIC_PACKAGE_CHECK_ALIGNMENT` 控制。

## 8.3\_包转换

包可以转换为包含更多信息的类型，例如从临时包变为自包含包。若创建时使用 `CBPRINTF_PACKAGE_ADD_RO_STR_POS`，还可以转成完全自包含包。

`cbprintf_package_copy()` 可计算新包所需空间，并执行复制与转换。

## 8.4\_包格式

包含有与平台相关的填充。头部记录不含附加字符串的包大小、附加字符串数量等；随后是带对齐填充、类似 `va_list` 栈帧的参数。再后面可以记录尚未附加的字符指针参数位置信息，以便后续转换时追加字符串；最后是可选的附加字符串区。

每个附加字符串前有一个字节头，指出对应地址参数在包中的位置。打包时将该参数地址设为 null，格式化前再更新为当前包内字符串地址。包复制后地址会变化，因此必须在紧接格式化之前更新。

原文布局的全部部分如下：

| 区域 | 顺序与内容 |
| --- | --- |
| 头部，总体大小为 `sizeof(void *)` | 一字节：包含头部及 `fmt` 的参数列表大小，以三十二位字为单位；一字节：附加字符串数；一字节：只读字符串参数位置数；一字节：临时字符串参数位置数；然后按平台填充到 `sizeof(void *)` |
| 参数 | `fmt` 指针，若格式串附加在包内则为 null；可选对齐填充；参数0；可选对齐填充；参数1；依此继续 |
| 字符串位置信息，可选 | 包内只读字符串指针所在字的索引；临时字符串使用的“参数索引、参数位置索引”对 |
| 附加字符串，可选 | 一字节：相关参数位置在包内的索引；随后为以 null 终止的字符串；重复该结构 |

> 译注：原文在此把转换函数拼为 `cbprinf_package_convert()`，是拼写错误，正确名称为 `cbprintf_package_convert()`。不同包类型对外部字符串的依赖不同，不能仅凭“已打包”就认定外部缓冲区可立即释放。

> 译注——源码跟踪：上表是官方指南的布局说明。当前启用创建标志存储后，包头还可能包含pkg_flags及架构填充，不应固定按一个指针宽度解析。完全自包含解决字符串依赖，不代表包可直接跨架构传输；格式化会修补包内字符串指针，存储区必须可写。详见[包描述符](../cbprintf_reference/P002_格式化包描述符.md)与[包头源码](../cbprintf_reference/P006_回调格式化输出头文件源码.md)。

## 8.5\_限制与建议

> 原文警告：同时启用 `CONFIG_MINIMAL_LIBC` 和 `CONFIG_CBPRINTF_NANO` 时，`printf`、`snprintf` 等标准 C 函数的格式化能力受限，包括不支持 `%n`、大多数格式标志、精度控制和浮点。

所有用于 `%p` 的字符指针都建议转换成其他指针类型，例如 `void *`。格式串无法访问时，只能静态打包，所有检测到的字符串都会被附加；若误把 `%p` 的字符指针识别为 `%s`，就可能从非预期地址复制，造成内存故障或安全越界。

> 译注——源码跟踪：当前转换代码的%p检查条件使用CONFIG_CBPRINTF_CONVERT_CHECK_PTR及回调是否存在，没有检查PTR_CHECK标志位；原文规则与源码差异见[转换标志](../cbprintf_reference/P014_格式化包转换标志.md)。静态打包及复制均应先按相同对齐计算长度并提供足量空间，当前静态宏最终容量检查前已有写入，转换快速路径还可能忽略复制回调错误，不能用小缓冲区或正返回值单独判断成功。详见[接口逐项译注](../cbprintf_reference/P001_回调格式化输出接口.md)。
