# 第18章\_性能采样工具

原文：[Perf](https://docs.zephyrproject.org/latest/services/profiling/perf.html)。读取日期：2026-10-13，`latest`。

## 18.1\_工作原理

**Perf** 是基于**栈跟踪（Stack Tracing）**的性能分析工具，以很小的代码开销提供轻量性能分析（Profiling）。

命令行界面（Shell）中的 `perf record` 命令启动一个使用 Perf 跟踪函数的定时器。定时器由中断驱动，因此跟踪函数在中断期间调用。Zephyr 核心在调用中断处理函数之前，会将返回地址（Return Address）和帧指针（Frame Pointer）保存到中断栈、`callee_saved` 结构或架构特定的异常帧中。Perf 使用这些返回地址和帧指针生成栈跟踪。

在 Cortex-M 上，Perf 封装 SysTick 处理函数，以便在常规定时器**中断服务例程（Interrupt Service Routine，ISR）**使用处理程序栈之前，采样被中断的线程模式（Thread Mode）的**进程栈指针（Process Stack Pointer，PSP）**帧。后端先验证该帧，再将其交给 Arm 栈遍历器（Stack Walker）。

Cortex-M 后端不适用于可信执行（Trusted Execution）的非安全（Non-secure）映像，因为非安全固件不能访问安全（Secure）异常帧。

`scripts/profiling/stackcollapse.py` 脚本可以利用**可执行与可链接格式（Executable and Linkable Format，ELF）**文件中的符号，将栈跟踪内的返回地址转换为函数名，并输出为[火焰图工具 FlameGraph](https://github.com/brendangregg/FlameGraph/) 所需的格式。

## 18.2\_配置

| 配置项 | 作用 |
| --- | --- |
| [`CONFIG_PROFILING_PERF`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_PROFILING_PERF) | 启用模块，并向Shell加入 `perf` 命令 |
| [`CONFIG_PROFILING_PERF_BUFFER_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_PROFILING_PERF_BUFFER_SIZE) | 设置打印之前保存采样数据的Perf缓冲区大小 |

架构后端可能还需要其他**栈展开（Stack Unwinding）**支持。Cortex-M 后端要求 SysTick、线程栈信息、额外异常信息、Arm 栈遍历支持，并要求采用单处理器（Uniprocessor）配置。
