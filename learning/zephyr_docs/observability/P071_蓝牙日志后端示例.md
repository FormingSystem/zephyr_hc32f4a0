# 第71章\_蓝牙日志后端示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/subsys/logging/ble_backend/README.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 71.1\_概述

本示例展示如何配置和使用蓝牙日志后端（Bluetooth Logging Backend）。它沿用 nRF Connect SDK 的 Nordic UART 服务（Nordic UART Service，NUS）通用唯一标识符（Universally Unique Identifier，UUID），以便兼容已有的 UART 风格蓝牙调试应用。

后端通知（Notification）缓冲区的大小取决于 [`CONFIG_BT_L2CAP_TX_MTU`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BT_L2CAP_TX_MTU) 配置的最大传输单元（Maximum Transmission Unit，MTU）。要提高蓝牙日志吞吐量，原文提示相应调整此配置。

> 译注：该服务通过蓝牙传送 UART 风格数据，不表示无线链路本身是实体 UART。当前后端缓冲区按配置 MTU 减去 ATT 通知开销确定，而单次通知还受 `bt_gatt_get_mtu()` 返回的连接实际 MTU 限制。因此只改本端编译配置，不保证对端协商结果或吞吐量同步提高。

## 71.2\_要求与运行

需要支持低功耗蓝牙（Bluetooth Low Energy，Bluetooth LE）的开发板。

可用 nRF Toolbox，或其他能建立蓝牙连接并识别 NUS UUID 服务的类似应用测试。本页原文没有给出具体 `west build`／烧录命令。

译注：当前示例先启用蓝牙并广播日志服务，随后每秒生成一条运行时间日志。后端的客户端特征配置（Client Characteristic Configuration，CCC）回调在客户端订阅通知时启用后端，取消订阅时停用；仅完成连接还不足以开始接收日志。源码只使用发送特征，接收特征的存在是为了兼容要求双特征的应用，不能据此认定已实现双向串口命令通道。
