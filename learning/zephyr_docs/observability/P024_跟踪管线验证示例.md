# 第24章\_跟踪管线验证示例

原文：[Tracing a sensor pipeline](https://docs.zephyrproject.org/latest/samples/subsys/tracing/pipeline/README.html)。读取日期：2026-10-13，`latest`。

## 24.1\_传感器数据管线

本示例是一个小型但有代表性的实时应用，模拟嵌入式产品中常见的**数据管线（Data Pipeline）**，并使用大多数内核同步原语（Synchronization Primitive）。将捕获的跟踪交给控制台查看器 `scripts/tracing/trace_viewer.py`，即可清楚看到调度、阻塞和资源争用。

各阶段按调度优先级从高到低排列如下：

| 线程 | 优先级 | 角色 |
| --- | --- | --- |
| `aggregator`，聚合线程 | 3，最高 | 读取传感器消息队列，更新由互斥锁保护的聚合数据；每隔若干读数向消费者发布一帧，并向共享“总线”写入摘要 |
| `consumer0`、`consumer1`，消费者 | 6 | 在条件变量上等待新帧，随后执行一段中央处理器（Central Processing Unit，CPU）密集型计算 |
| `sensor_temp`、`sensor_press`、`sensor_imu`，传感器生产者 | 8 | 三个周期不同的生产者，将读数推入消息队列后睡眠 |
| `storage`，存储线程 | 9，最低 | 周期性获取共享总线并持有一段时间，模拟缓慢的存储刷新 |

示例使用的原语和同步方式如下：

| 原语 | 用途 |
| --- | --- |
| 消息队列（Message Queue）[`k_msgq`](../msgstack_reference/P002_内核消息队列结构.md) | 传感器向聚合线程交付读数 |
| 互斥锁（Mutex）[`k_mutex`](../synchronization_reference/P007_内核互斥量结构.md) | 保护共享聚合数据，默认也保护总线 |
| 条件变量（Condition Variable）[`k_condvar`](../synchronization_reference/P011_内核条件变量结构.md) | 帧就绪时，聚合线程唤醒消费者 |
| 信号量（Semaphore）[`k_sem`](../synchronization_reference/P009_内核信号量结构.md) | 可选的总线锁，用于演示优先级反转 |
| 可延迟工作（Delayable Work）[`k_work_delayable`](https://docs.zephyrproject.org/latest/doxygen/html/structk__work__delayable.html) | 在系统工作队列上周期性执行后台刷新 |
| 定时器（Timer）[`k_timer`](https://docs.zephyrproject.org/latest/doxygen/html/structk__timer.html) | 从系统时钟中断服务例程（Interrupt Service Routine，ISR）触发心跳 |

多个线程优先级使抢占（Preemption）和上下文切换（Context Switch）清晰可见。应用使用 [`sys_trace_named_event()`](../network_thread_trace_reference/P004_命名事件跟踪接口.md#ga205bc648bdf0152f8652f04f15cf48af) 标记各阶段，例如传感器采样 `sensor_sample`、帧发布 `frame_publish`、开始消费 `consume_begin`、开始存储 `store_begin` 和总线写入 `bus_write`，便于在跟踪中定位。

## 24.2\_构建与运行

默认配置与基础跟踪示例类似，采用**通用跟踪格式（Common Trace Format，CTF）**和**半主机（Semihosting）**后端，可直接生成跟踪文件：

```shell
west build -b mps2/an385 samples/subsys/tracing/pipeline
west build -t run
```

构建目录中生成 `tracing.bin`，用查看器打开。命令中的 `ZEPHYR_BASE` 是指向 Zephyr 源码根目录的环境变量：

```shell
$ZEPHYR_BASE/scripts/tracing/trace_viewer.py build/tracing.bin
```

在 `native_sim` 原生模拟目标上，使用**可移植操作系统接口（Portable Operating System Interface，POSIX）**后端覆盖配置。原文称它将数据写到构建目录中的 `channel0_0`：

```shell
west build -b native_sim samples/subsys/tracing/pipeline -- -DEXTRA_CONF_FILE=prj_native_ctf.conf
```

```shell
./build/zephyr/zephyr.exe &
$ZEPHYR_BASE/scripts/tracing/trace_viewer.py build/channel0_0
```

> 译注：这里的输出位置与官方当前后端实现存在差异。[POSIX后端](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/tracing/tracing_backend_posix.c)默认文件名是相对路径 `channel0_0`，[底层实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/tracing/tracing_backend_posix_bottom.c)直接用 `fopen` 打开该路径。因此，按上方命令从仓库根目录运行时，默认输出应在当前工作目录，查看器却指向 `build/channel0_0`。原命令保留；实际使用时，应让查看器读取真正的输出文件，或运行程序时显式传入 `-trace-file=build/channel0_0` 使两者一致。

## 24.3\_阅读跟踪

查看器按线程状态给泳道着色，从中可观察管线节奏：

- 传感器大部分时间睡眠（`░`），每个周期短暂运行（`█`）以提交读数。
- 聚合线程阻塞在消息队列上（`▒`，原因为 `msgq`），读数到达后立即唤醒。由于优先级最高，它会抢占当时运行的线程。
- 消费者阻塞在条件变量上（`▒`，原因为 `condvar`），直到发布新帧，随后集中执行CPU密集型工作。
- 指标面板汇总当前可见窗口的CPU忙碌百分比、上下文切换与事件速率，以及逐线程利用率条。

选择泳道后，可看到光标所在时刻线程阻塞的准确原因：它正在等待哪个信号量、互斥锁、消息队列或条件变量。这样就能将笼统的“系统感觉迟缓”定位为“聚合线程阻塞在总线上”。

## 24.4\_发现优先级反转

最低优先级的 `storage` 与最高优先级的 `aggregator` 共享“总线”。构建时可选择保护它的原语：

- 默认 Kconfig 选项 `CONFIG_SAMPLE_BUS_MUTEX` 使用互斥锁。高优先级聚合线程等待它时，Zephyr 的**优先级继承（Priority Inheritance）**临时提升低优先级存储线程，使其尽快完成并释放总线。跟踪中可看到 `storage` 在这段时间提升到优先级3，对应事件为 `thread_sched_priority_set`。
- `CONFIG_SAMPLE_BUS_SEM` 改用普通信号量，不支持优先级继承。此时，存储线程持有总线期间，中等优先级消费者可以运行，最高优先级聚合线程只能等待，这就是典型的**优先级反转（Priority Inversion）**。

构建会发生反转的变体并采集跟踪：

```shell
west build -b mps2/an385 samples/subsys/tracing/pipeline -- -DCONFIG_SAMPLE_BUS_SEM=y
west build -t run
```

放大聚合线程标记为 `blocked on sem`（阻塞于信号量）的区间，可看到最高优先级线程阻塞（`▒`），中等优先级消费者运行（`█`），最低优先级存储线程持有总线。下图为原文字符时间线，其中 `p9`、`p6`、`p3` 表示优先级，`▓` 为就绪等待，`░` 为睡眠：

