# 第23章\_基础跟踪示例

原文：[Tracing](https://docs.zephyrproject.org/latest/samples/subsys/tracing/basic/README.html)。读取日期：2026-10-13，`latest`。

## 23.1\_概述

本示例演示[跟踪（Tracing）子系统](P015_跟踪子系统.md)，驱动有代表性的一组内核功能。无论构建时选择哪种跟踪格式和后端，都能生成丰富、连续的事件流，供主机采集和可视化。

- 两个线程，一个静态、一个动态，通过一对信号量（Semaphore）同步，轮流打印“Hello World”。示例运行期间持续产生线程切换、睡眠和信号量给出/获取事件。
- 启动时，一次性负载使用互斥锁（Mutex）、系统工作队列（System Work Queue）和内核定时器（Kernel Timer），使这些对象的生命周期事件也出现在跟踪中。
- 代码中使用 [`sys_trace_named_event()`](../network_thread_trace_reference/P004_命名事件跟踪接口.md#ga205bc648bdf0152f8652f04f15cf48af) 发出应用自定义事件，内容是短名称和两个 32 位参数。命名事件（Named Event）是应用代码为跟踪添加注释的主要方式。
- 可选的通用输入输出（General-Purpose Input/Output，GPIO）场景位于 `samples/subsys/tracing/basic/src/gpio_main.c`，通过调用 GPIO 应用程序编程接口（Application Programming Interface，API）触发相关跟踪钩子（Hook）。

## 23.2\_格式与后端

跟踪配置分为两个独立方面：**格式（Format）**决定事件如何编码，**后端（Backend）**决定编码后的字节如何离开设备。

原文将默认 `samples/subsys/tracing/basic/prj.conf` 描述为完整、可用的基线：启用**通用跟踪格式（Common Trace Format，CTF）**及**随机存取存储器（Random Access Memory，RAM）**后端，不需要传输接口或设备树设置，因此可在任意开发板上构建和运行；不加额外选项也能产生跟踪。

> 译注：官方同一页后面的终端查看器章节又称默认使用半主机（Semihosting）后端。2026-10-13 核对[官方主分支的实际配置](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/subsys/tracing/basic/prj.conf)，其中启用了 `CONFIG_TRACING_BACKEND_SEMIHOST=y` 和 `CONFIG_SEMIHOST=y`，但文件注释仍称默认RAM。下面保留原文各分支及命令；默认后端应以读者实际源码配置为准，不能据前述RAM说明认定当前基线可在任意板上运行。

要使用传输接口流式输出，或改用其他格式，通过 `EXTRA_CONF_FILE` 将一个 `prj_*.conf` 覆盖配置叠加到基线上。每份覆盖配置只包含与基线不同的选项，因此可与基线及开发板配置组合而不重复。

表中 UART 指通用异步收发器（Universal Asynchronous Receiver/Transmitter），USB 指通用串行总线（Universal Serial Bus），POSIX 指可移植操作系统接口（Portable Operating System Interface），RTT 指 SEGGER 实时传输（Real Time Transfer）。USB CDC ACM 是通信设备类的抽象控制模型（Communications Device Class / Abstract Control Model）通道。

| 配置 | 格式 | 后端 | 说明 |
| --- | --- | --- | --- |
| `prj.conf`，原文默认项 | CTF | RAM | 二进制CTF在RAM中缓冲，由调试器导出；默认项差异见上述译注 |
| `prj_uart.conf` | `test` | UART | 通过专用UART输出人可读字符串 |
| `prj_uart_ctf.conf` | CTF | UART | 通过专用UART输出二进制CTF流 |
| `prj_usb_ctf.conf` | CTF | USB | 通过USB CDC ACM通道输出二进制CTF流 |
| `prj_native_ctf.conf` | CTF | POSIX | 由 `native_sim` 将二进制CTF写入文件 |
| `prj_user.conf` | `user` | 不适用 | 应用提供回调，见 `src/tracing_user.c` |
| `prj_gpio.conf` | `user` | 不适用 | 面向GPIO钩子的用户回调 |
| `prj_percepio.conf` | Percepio | 模块 | Percepio Tracealyzer记录器，需要 `percepio` 模块 |
| `rtt-tracing` 配置片段 | SystemView | RTT | 经RTT使用SEGGER SystemView |

采集和解码还可能需要主机工具，下文按场景说明。

## 23.3\_RAM配置用法

原文给出的无额外选项基线构建命令如下，当前默认后端差异见上一节译注：

```shell
west build -b qemu_x86 samples/subsys/tracing/basic
```

对于 RAM 后端，CTF 流保存在 `ram_tracing` 数组中。运行一段时间后，在调试器中暂停目标并导出缓冲区。例如，在 **GNU调试器（GNU Debugger，GDB）**中：

```gdb
dump binary memory channel0_0 &ram_tracing &ram_tracing+sizeof(ram_tracing)
```

> 译注：上方命令按原文保留。`&ram_tracing` 若在GDB中保持数组指针类型，其加法按数组大小缩放，不能直接把末地址表达式当成按字节相加。实际导出前应核对地址范围，必要时将起址转成字节指针后再加 `sizeof(ram_tracing)`，避免超出缓冲区。

大小由 Kconfig 选项 [`CONFIG_RAM_TRACING_BUFFER_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RAM_TRACING_BUFFER_SIZE) 控制。导出的文件是 CTF 流，解码方法见本章后面的 CTF 解码部分。

## 23.4\_UART后端

构建 UART 跟踪映像：

```shell
west build -b mps2/an521 samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_uart.conf
```

若需要二进制 CTF 流，则使用：

```shell
west build -b mps2/an521 samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_uart_ctf.conf
```

> 注意：可能需要在设备树 `chosen` 节点设置 `zephyr,tracing-uart` 属性。示例见 `samples/subsys/tracing/basic/boards/mps2_an521_cpu0.overlay`。

应用运行一段时间后，检查跟踪输出文件，即从跟踪 UART 收到的字节。CTF 流按本章后文解码。

## 23.5\_USB后端

构建 USB 跟踪映像：

```shell
west build -b reel_board samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_usb_ctf.conf
```

等待串口控制台稳定出现类似输出：

```console
thread_a: Hello World from reel_board!
thread_b: Hello World from reel_board!
thread_a: Hello World from reel_board!
thread_b: Hello World from reel_board!
```

连接开发板 USB 端口与主机，在主机上运行 `scripts/tracing/trace_capture_usb.py`：

```shell
sudo python3 trace_capture_usb.py -v 0x2FE3 -p 0x0001 -o channel0_0
```

USB 的供应商标识符（Vendor ID，VID）和产品标识符（Product ID，PID）可以配置，应相应调整命令参数。采集得到的 `channel0_0` 是 CTF 流。

## 23.6\_POSIX后端

构建 POSIX 跟踪映像：

```shell
west build -b native_sim samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_native_ctf.conf
```

运行程序，将 CTF 流写入当前工作目录的 `channel0_0` 文件：

```shell
./build/zephyr/zephyr.exe
```

数秒后用 `Ctrl-C` 停止，再按后文解码。

## 23.7\_用户回调与其他工具

`user` 格式实际不使用后端，而由内核调用应用直接实现的 `sys_trace_*_user` 弱符号回调（Weak Callback）。本例线程、中断服务例程（Interrupt Service Routine，ISR）、睡眠和 GPIO 钩子实现见 `samples/subsys/tracing/basic/src/tracing_user.c`。构建命令为：

```shell
west build -b qemu_x86 samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_user.conf
```

事件发生时，回调直接向控制台打印，例如：

```console
sys_trace_thread_switched_in_user: 0x...
sys_trace_k_thread_sleep_enter_user: thread=0x... timeout=... ticks
```

### SEGGER SystemView RTT

用 [SystemView RTT跟踪配置片段](../snippets/P014_SystemView_RTT跟踪配置片段.md#snippet-rtt-tracing)构建：

```shell
west build -b frdm_k64f -S rtt-tracing samples/subsys/tracing/basic
```

目标运行期间，在主机的 SEGGER SystemView 中打开跟踪。

### Percepio Tracealyzer

工作区需要包含 `percepio` 模块。构建命令如下，随后在 Percepio Tracealyzer 打开生成的记录：

```shell
west build -b frdm_k64f samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_percepio.conf
```

### GPIO跟踪

使用 `user` 格式和 GPIO 钩子构建：

```shell
west build -b native_sim samples/subsys/tracing/basic -- -DEXTRA_CONF_FILE=prj_gpio.conf -DEXTRA_DTC_OVERLAY_FILE=gpio.overlay
```

执行 GPIO API 时，相应回调向控制台打印。

## 23.8\_解码CTF

UART、USB、POSIX 和 RAM 等 CTF 后端输出二进制流，格式遵循 `subsys/tracing/ctf/tsdl/metadata` 中的元数据。把捕获流和元数据文件放在一起，使用理解 CTF 的工具，例如 `babeltrace2` 打开：

```shell
mkdir ctf
cp channel0_0 ctf/
cp $ZEPHYR_BASE/subsys/tracing/ctf/tsdl/metadata ctf/
babeltrace2 ctf/
```

也可在 Trace Compass 中打开同一 `ctf` 目录，显示图形时间线。

## 23.9\_终端跟踪查看器

不安装其他工具也能快速查看：`scripts/tracing/trace_viewer.py` 以类似 SEGGER SystemView 或 Trace Compass 的方式在控制台绘制跟踪。它从同一份 `metadata` 读取字段布局，自行解码紧凑排列的 CTF 记录，因此只需要 Python 3。

原文在此使用默认半主机后端，运行后在构建目录生成 `tracing.bin`：

```shell
west build -p -b mps2/an385 samples/subsys/tracing/basic -t run
$ZEPHYR_BASE/scripts/tracing/trace_viewer.py build/tracing.bin
```

交互视图主要是甘特图（Gantt Chart）式时间线，每个线程有一条泳道，另有空闲和 ISR 泳道。颜色按线程状态而非线程身份区分：

| 状态 | 符号与颜色 |
| --- | --- |
| 运行（Running） | `█`，绿色 |
| 就绪/被抢占，等待中央处理器（Central Processing Unit，CPU） | `▓`，黄色 |
| 阻塞在内核对象上（Blocked） | `▒`，红色 |
| 等待超时的睡眠（Sleeping） | `░`，青色 |
| 挂起（Suspended） | `—` |

从就绪到运行的转变就是上下文切换。高优先级线程阻塞而低优先级线程运行，是优先级反转（Priority Inversion）的典型形态。泳道阻塞时，信息条会解释播放位置所选泳道的原因，例如 `blocked on sem 0x2000012c` 表示等待该信号量，`blocked on mutex 0x...` 表示等待互斥锁。

下方指标面板汇总可见时间窗口：CPU忙碌程度、上下文切换速率、事件速率，以及各线程运行、就绪、阻塞和睡眠时间占比的堆叠利用率条。平移或缩放时自动更新，可用 `m` 显隐。

可移动的播放指针（Playhead）选定跟踪时刻，图下信息条显示图例、正在运行的线程及所选泳道状态和原因。按键如下：

| 按键 | 操作 |
| --- | --- |
| 方向键 | 移动播放指针或选择泳道 |
| `,`、`.` | 平移 |
| `+`、`-` | 缩放 |
| `a` | 适配整段跟踪 |
| `m` | 显隐指标面板 |
| `i` | 显隐信息条 |
| 空格 | 回放；指针按实时推进，图表跟随滚动 |
| `[`、`]` | 调整回放速度 |
| `v` | 切换到原始CTF日志视图；可滚动查看所有解码事件，并突出最接近播放指针的事件 |
| `q` | 退出 |

## 23.10\_跟随运行中的数据

用 `-f` 或 `--follow` 观察应用运行期间持续增长的文件。查看器增量解码，并让图表跟随最新事件；任何平移或缩放都会退出跟随。随时按 `End` 或 `f` 可跳到最新状态并重新同步，甘特图和日志视图均支持。

这很适合半主机后端：应用在 QEMU 中运行时持续写入 `tracing.bin`。

```shell
west build -t run &
$ZEPHYR_BASE/scripts/tracing/trace_viewer.py -f build/tracing.bin
```

查看器会等待文件和首批事件出现，因此可在启动应用前或后运行。传入 `--text` 可得到静态、非交互的美国信息交换标准代码（American Standard Code for Information Interchange，ASCII）时间线，便于管道传递或重定向；`--metadata <path>` 可指定元数据文件。
