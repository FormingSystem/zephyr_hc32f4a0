# 第60章\_核心转储架构接口

原文：[group__arch-coredump](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html)。读取日期：2026-10-13，`latest`。

## 60.1\_头文件与架构信息

这些接口实现**核心转储（Core Dump）**的架构特定处理。

```c
#include <kernel_arch_interface.h>
```

```c
void arch_coredump_info_dump(const struct arch_esf *esf);
uint16_t arch_coredump_tgt_code_get(void);
uintptr_t arch_coredump_stack_ptr_get(const struct k_thread *thread);
void arch_coredump_priv_stack_dump(struct k_thread *thread);
```

| 函数 | 行为与参数 |
| --- | --- |
| [`arch_coredump_info_dump()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#gae997cb3dc249bec6d5166145f37d9292) | 转储架构特定信息；`esf` 为架构特定的异常栈帧（Exception Stack Frame） |
| [`arch_coredump_tgt_code_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#ga1d9b0c011a03434272ff9bec120f273d) | 返回架构指定的目标代码（Target Code） |
| [`arch_coredump_stack_ptr_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#gad53d55d1e9bf8c15137e204bc05d2732) | 返回所给线程的栈指针（Stack Pointer） |
| [`arch_coredump_priv_stack_dump()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#ga31bcb446604666c8f4d05ccfcbc00441) | 转储架构特定的特权栈（Privileged Stack）；`thread` 指向线程对象 |

## 60.2\_冻结其他处理器

```c
void arch_coredump_freeze_other_cpus(void);
void arch_coredump_thaw_other_cpus(void);
```

[`arch_coredump_freeze_other_cpus()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#ga54e37d442ec14ee803a70bad2b3fe9a1) 冻结其他所有在线**中央处理器（Central Processing Unit，CPU）**并捕获它们的现场寄存器状态（Live Register State）。它向除调用方之外的每个CPU发送架构特定的**处理器间中断（Inter-Processor Interrupt，IPI）**，并以有限超时等待各CPU报告已捕获快照。

对于未及时响应的CPU，例如尚未启动或正在屏蔽中断的CPU，直接跳过；**此操作绝不能无限期阻塞**。后续必须配对调用 [`arch_coredump_thaw_other_cpus()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#ga62d5f5996b36634ce38bf0544ca50bc2)，恢复被冻结的CPU。**不能由多个CPU同时调用冻结函数。**

[`arch_coredump_thaw_other_cpus()`](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-coredump.html#ga62d5f5996b36634ce38bf0544ca50bc2) 释放所有通过上述冻结函数停止的CPU。

## 60.3\_输出处理器快照

```c
void arch_coredump_cpu_snapshot_dump(unsigned int cpu);
```

输出为参数 `cpu` 指定的CPU索引捕获的现场寄存器快照（Register Snapshot）。索引范围为 `0..CONFIG_MP_MAX_NUM_CPUS-1`，其中Kconfig选项 `CONFIG_MP_MAX_NUM_CPUS` 设置最大CPU数量。

如果该CPU没有成功冻结，例如它是调用方自身、从未启动或冻结超时，则此调用不执行任何操作。**只能在冻结函数调用之后、恢复函数调用之前调用。**
