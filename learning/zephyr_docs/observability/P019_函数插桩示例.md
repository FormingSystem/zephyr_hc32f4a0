# 第19章\_函数插桩示例

原文：[Instrumentation](https://docs.zephyrproject.org/latest/samples/subsys/instrumentation/README.html)。读取日期：2026-10-13，`latest`。

## 19.1\_概述与要求

本示例展示[函数插桩（Instrumentation）子系统](P016_函数插桩.md)的跟踪（Tracing）与性能分析（Profiling）功能。两个线程以乒乓方式轮流执行消耗一定中央处理器（Central Processing Unit，CPU）周期的循环。

运行需要 Linux 主机和通用异步收发器（Universal Asynchronous Receiver/Transmitter，UART）控制台。

## 19.2\_构建与运行

按以下方式构建并烧写，将 `mps2/an385` 替换为自己的开发板目标：

```shell
west build -b mps2/an385 samples/subsys/instrumentation
west flash
```

也可以在 QEMU 模拟器中运行：

```shell
west build -b mps2/an385 samples/subsys/instrumentation -- '-DQEMU_SOCKET=y'
west build -t run
```

烧写完成或 QEMU 开始运行后，可使用插桩命令行界面（Command-Line Interface，CLI）工具 `scripts/instrumentation/zaru.py` 收集、查看跟踪和性能信息。

> 注意：动态触发配置需要 `retained_mem` 保留内存驱动，因此必须为目标板添加适当的设备树覆盖文件（Devicetree Overlay）。示例见 `samples/subsys/instrumentation/boards/mps2_an385.overlay`。若采用构建期配置，使用 Kconfig 选项 [`CONFIG_INSTRUMENTATION_TRIGGER_FUNCTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_TRIGGER_FUNCTION) 和 [`CONFIG_INSTRUMENTATION_STOPPER_FUNCTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_INSTRUMENTATION_STOPPER_FUNCTION)。

## 19.3\_采集跟踪和性能数据

把开发板 UART 连接到主机，在主机上运行脚本。先载入 `zephyr-env.sh`，设置 `ZEPHYR_BASE` 环境变量，并将脚本加入命令搜索路径环境变量 `PATH`：

```shell
. zephyr-env.sh
```

检查插桩状态：

```shell
zaru.py status
```

设置跟踪/性能分析触发点。本例选择 `get_sem_and_exec_function` 函数，以便观察上下文切换（Context Switch）：

```shell
zaru.py trace -v -c get_sem_and_exec_function
```

重启目标，使该位置的跟踪/性能分析生效：

```shell
zaru.py reboot
```

等待约 2 秒，让 `main` 与 `thread_A` 两个线程完成两轮乒乓交互，然后读取跟踪：

```shell
zaru.py trace -v
```

读取性能分析结果：

```shell
zaru.py profile -v -n 10
```

也可以导出跟踪供 Perfetto 查看。此前的 `zaru.py trace` 已导出并清空缓冲区，因此需要再次重启：

```shell
zaru.py reboot
zaru.py trace -v --export-tef --output perfetto_zephyr.json
```

随后访问 [Perfetto](https://perfetto.dev)，打开跟踪查看器（Trace Viewer），加载 `perfetto_zephyr.json`。
