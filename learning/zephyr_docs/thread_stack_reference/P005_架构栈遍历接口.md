# 第5章\_架构栈遍历接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__arch-stackwalk.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：从[本册大纲](大纲.md)进入线程栈、架构线程和栈遍历接口参考，再通过接口链接进入完整说明。源码跟踪译注与官方原文分开标示。

架构专有栈遍历 API（Architecture-specific Stack Walk APIs）。

<a id="details"></a>

架构专有栈遍历 API。若要为某架构添加支持，应实现 `arch_stack_walk()`，并在该架构顶层 Kconfig 中创建用户不可配置、默认值为 y 的 `ARCH_HAS_STACKWALK` 选项，同时设置所有相关依赖。

## 5.3\_详细说明（Detailed Documentation）

<a id="gaec9949df614728aa6d677f9f1fafd844"></a>

### `stack_trace_callback_fn`

```c
typedef bool(* stack_trace_callback_fn) (void *cookie, unsigned long addr)
```

```c
#include <zephyr/arch/arch_interface.h>
```

`stack_trace_callback_fn`：`arch_stack_walk` 的回调函数（Callback）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `cookie` | 调用者提供的指针，由 `arch_stack_walk` 原样传回。 |
| `addr` | 要处理的栈条目地址。 |

返回（Returns）：条目已处理或已跳过时返回 true；没有剩余存储空间时返回 false。

<a id="ga7129c254277cfa162cd9c5778a7662c2"></a>

### `arch_stack_walk()`

```c
void arch_stack_walk ( stack_trace_callback_fn callback_fn, void * cookie, const struct k_thread * thread, const struct arch_esf * esf )
```

```c
#include <zephyr/arch/arch_interface.h>
```

遍历栈的架构专有函数。

| thread | esf | 行为 |
| --- | --- | --- |
| thread | NULL | 从指定线程取得栈回溯（Stack Trace），线程可以为 `_current`。 |
| thread | esf | 从异常栈帧（Exception Stack Frame，ESF）开始回溯。 |

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `callback_fn` | 架构代码为每个条目调用的回调函数。 |
| `cookie` | 调用者提供的指针，将传给 `callback_fn`。 |
| `thread` | 指向 `k_thread` 结构的指针，可以为 `NULL`。 |
| `esf` | 指向 `arch_esf` 结构的指针，可以为 `NULL`。 |

## 5.4\_源码定位与版本边界

源码定位：[include/zephyr/arch/arch_interface.h](../../../include/zephyr/arch/arch_interface.h)、[arch/arm/core/stacktrace.c](../../../arch/arm/core/stacktrace.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位使用相对链接；代码对照不代表已验证具体开发板的栈保护、线程切换或回溯能力。

> 译注——源码核对：栈遍历（Stack Walk）接口将地址逐条交给回调；回调返回true表示继续，返回false允许停止收集，cookie由调用者提供。接口本身没有承诺把全部调用栈一次性存入某个固定格式数组。

> 译注——源码核对：官方页面的参数组合表在HTML中显示为连续文本，此译文按原始两行关系恢复为表格：thread与NULL从线程回溯，thread与esf从异常帧回溯。没有增加原表未给出的组合保证。

> 译注——源码核对：本次ARM实现将thread为空替换为_current，再从线程或异常帧初始化回溯状态，按CONFIG_ARCH_STACKWALK_MAX_FRAMES限制帧数；回调拒绝或无法展开下一帧时停止。结果可能是部分回溯，不保证覆盖全部逻辑调用，也不能凭本页证明跨CPU运行中线程的栈已获得一致快照。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
