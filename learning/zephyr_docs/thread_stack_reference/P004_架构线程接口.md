### `ARCH_KERNEL_STACK_RESERVED`

```c
#define ARCH_KERNEL_STACK_RESERVED
```

```c
#include <zephyr/arch/arch_interface.h>
```

仅内核栈（Kernel-only Stack）的 MPU 保护区大小。

如果使用 MPU 栈保护来捕获栈溢出，则指定内核栈对象中的保留空间大小。若保护区大小取决于上下文，此处应设为最小保护区大小，其余空间在需要时另行划出。

可选定义，默认值为 0。

另见（See Also）：`K_KERNEL_STACK_RESERVED`。

### `ARCH_THREAD_STACK_OBJ_ALIGN`

```c

```


<a id="gace8831316d471ccfb06eeddb6d69d817"></a>

### `ARCH_THREAD_STACK_RESERVED`

```c
#define ARCH_THREAD_STACK_RESERVED
```

```c
#include <zephyr/arch/arch_interface.h>
```

每个线程栈对象起始处的保留空间。

在线程栈对象最低地址处，为架构或平台数据（例如 MPU 栈保护区域）保留的字节数。此空间不能用作线程栈缓冲区，也不计入用户请求的栈大小。

可选定义，默认值为 0。

另见（See Also）：`K_THREAD_STACK_RESERVED`。

<a id="gab76d60bd06e5c5a0f995c6b11bf97fd8"></a>

### `ARCH_THREAD_STACK_SIZE_ADJUST`

```c
#define ARCH_THREAD_STACK_SIZE_ADJUST ( size)
```

```c
#include <zephyr/arch/arch_interface.h>
```

将栈缓冲区大小向上取整，以满足对齐约束。

将请求的栈缓冲区大小调整为其底层缓冲区的真实大小；该缓冲区指可用于线程栈上下文和线程局部存储（Thread-local Storage，TLS）的区域。

此处传入的大小不包含为平台数据保留的存储空间。

返回值等于给定大小（若已正确对齐），或向上取整以满足对齐约束。这里执行的计算必须具有幂等性（Idempotence）。

可选定义。未定义时，栈缓冲区大小按以下方式之一处理：

- 若启用了用户模式，且架构的 MPU 要求此类对齐，则向上取整到下一个二的幂。
- 向上取整到 `ARCH_STACK_PTR_ALIGN` 的倍数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `size` | 请求的栈缓冲区大小。 |

返回（Returns）：调整后的栈对象大小。

另见（See Also）：`Z_THREAD_STACK_SIZE_ADJUST`。

### `arch_ipi_lazy_coprocessors_save()`

```c
void arch_ipi_lazy_coprocessors_save ( void )
```

```c
#include <kernel_arch_interface.h>
```

在处理器间中断（Inter-processor Interrupt，IPI）中保存协处理器状态。

此函数由 IPI 处理函数调用，用于跨 CPU 的延迟上下文切换（Lazy Context Switch）。它先保存相关协处理器上下文，再通知等待中的 CPU 保存已经完成。

### `arch_new_thread()`

```c
void arch_new_thread ( struct k_thread * thread, k_thread_stack_t * stack, char * stack_ptr, k_thread_entry_t entry, void * p1, void * p2, void * p3 )
```

```c
#include <kernel_arch_interface.h>
```

处理建立新线程时架构专有的逻辑。

必须设置好栈和架构专有线程状态，使之后切换到该线程能够成功，并以请求的线程及参数进入 `z_thread_entry`。

在此函数实现的某个位置，必须使用线程栈对象内可用栈缓冲区的真实边界调用 `z_setup_new_thread()`。

提供的栈指针保证满足 CPU 和 ABI 的对齐要求。栈指针与栈缓冲区边界之间可能保留了一些空间，用于初始栈指针随机化（Randomization）和线程局部存储。

调用此函数时，`thread->base` 中的字段已经初始化。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 指向尚未初始化的 `struct k_thread` 的指针。 |
| `stack` | 指向栈对象的指针。 |
| `stack_ptr` | 已对齐的初始栈指针。 |
| `entry` | 线程入口函数（Thread Entry Function）。 |
| `p1` | 入口点的第一个参数。 |
| `p2` | 入口点的第二个参数。 |
| `p3` | 入口点的第三个参数。 |

### `arch_swap()`

```c
int arch_swap ( unsigned int key)
```

```c
#include <kernel_arch_interface.h>
```

以协作方式切换上下文。

调用时必须已锁定中断，并提供对应的锁定键（Key）。这是旧式上下文切换方法，与对称多处理（SMP）不兼容。建议新的架构移植（无论 SMP 还是单处理器 UP）改为实现 `arch_switch()`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `key` | 中断锁定键。 |

返回（Returns）：若线程从等待某个内核对象的阻塞状态被唤醒，则返回该阻塞操作的结果。

<a id="gab411d82ce5b60f062171f5a19e33e025"></a>

### `arch_switch()`

```c
void arch_switch ( void * switch_to, void ** switched_from )
```

声明属性：`inline`、`static`。

```c
#include <kernel_arch_interface.h>
```

协作式上下文切换原语（Cooperative Context Switch Primitive）。

`arch_switch()` 应切换到第一个参数传入的新上下文，并把指向当前上下文的指针保存到第二个参数指定的地址。

切换句柄（Switch Handle）的实际类型与解释由架构规定。它与 `arch_new_thread()` 为新建线程保存在 `switch_handle` 字段中的数据结构相同，也作为 `interrupted` 参数传给内核的 `z_get_next_switch_handle()`。

注意：在 SMP 系统中，内核将通过第二个指针进行的存储操作作为同步点，以判断线程上下文已完整保存，让另一个 CPU 知道何时可以安全切换。该存储操作必须发生在所有相关状态保存之后，并包含必要的内存屏障或缓存管理代码，以确保其他 CPU 正确看到结果。

`arch_switch()` 最简单的实现通常是把状态压入线程栈，并使用得到的栈指针作为切换句柄。某些架构也可使用指向线程结构内部的指针作为切换句柄。这些实现可以假定第二个参数是 `struct thread_base` 中 `switch_handle` 字段的地址，再用偏移量找到线程结构的其他部分。例如，`arch_switch()` 的 C 伪代码（Pseudocode）可能如下：

```c
void arch_switch(void *switch_to, void **switched_from)
{
    struct k_thread *new = switch_to;
    struct k_thread *old = CONTAINER_OF(switched_from, struct k_thread,
                                      switch_handle);

    // save old context...
    *switched_from = old;
    // restore new context...
}
```

> 译注——原始伪代码注释：`save old context` 表示保存旧上下文，`restore new context` 表示恢复新上下文。省略部分属于原文伪代码，并非完整可编译实现。

注意，内核按上述方式管理 `switch_handle` 字段以实现同步。因此，架构代码不得假定该字段在其他时刻具有某个特定值；尤其不得从第二个参数所指地址读取该字段。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `switch_to` | 将要切入线程的切换句柄。 |
| `switched_from` | 指向将要切出线程的切换句柄存储位置的指针；必须更新此位置。 |

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位使用相对链接；代码对照不代表已验证具体开发板的栈保护、线程切换或回溯能力。

> 译注——源码核对：架构栈接口规定栈指针、对象基址和大小调整的不同约束。应用通常使用K_THREAD_STACK_*或K_KERNEL_STACK_*包装，架构移植者则提供ARCH_*定义；不能把某个MPU要求的二的幂规则推广到所有平台。

> 译注——源码核对：原文ARCH_THREAD_STACK_SIZE_ADJUST说明传入值不含平台保留区；当前公共头文件的Z_THREAD_STACK_SIZE_ADJUST在存在架构钩子时实际传入size加K_THREAD_STACK_RESERVED。正文保留原文，译注明确这一源码边界；实现或修改架构钩子时必须沿实际调用链核对，避免重复加保留量。

> 译注——源码核对：原文arch_new_thread说明要求在其内部调用z_setup_new_thread。当前内核实现的调用方向则是z_setup_new_thread先完成公共栈设置，再调用arch_new_thread；本次Cortex-M实现不反向调用z_setup_new_thread。原文照译，移植时应核对当前调用链，不能照旧文字制造递归初始化。

> 译注——源码核对：arch_switch的第二个参数是保存切出线程句柄的位置。在SMP系统中，这次存储是上下文保存完成的发布点，必须晚于全部状态保存并满足所需内存可见性；它不是可任意读取旧句柄的双向参数。原文伪代码只展示约定，没有包含完整寄存器保存或屏障实现。

> 译注——源码核对：旧式arch_swap要求中断已锁定并传入正确键，原文明确它不兼容SMP。协作式切换原语（Cooperative Switch Primitive）描述调用机制，不表示目标线程必然采用协作式调度优先级。

> 译注——源码核对：本次Cortex-M在CONFIG_FPU与CONFIG_FPU_SHARING下，arch_float_disable只接受当前线程且不能从ISR调用，否则返回-EINVAL；arch_float_enable返回-ENOTSUP。公共契约存在不代表所有架构都实现双向启用／禁用，也不能把x86寄存器选项套到ARM。
