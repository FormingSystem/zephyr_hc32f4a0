### `K_THREAD_STACK_RESERVED`

```c
#define K_THREAD_STACK_RESERVED ((size_t)0U)
```

指示为栈对象额外保留了多少内存。

任意栈声明都可能包含用于保护区、监督模式栈或平台专用数据的额外内存；此宏指示为这些用途保留的空间大小。

此值只计入栈对象中永久保留的内存，不计入从线程栈缓冲区中“借用”的内存。

保留内存位于栈对象起始处。其大小必须经过适当安排，使紧随其后的栈缓冲区正确对齐。

<a id="a14296483e6ba0ef950a4b0e719b388e6"></a>

### `K_THREAD_STACK_BUFFER()`

```c
char * K_THREAD_STACK_BUFFER ( k_thread_stack_t * sym)
```

声明属性：`inline`、`static`。

取得指向实际栈缓冲区的指针。

取得指向栈对象非保留区域的指针。不保证这是线程可写区域的起点，因为它不计入为 MPU 栈溢出保护而从缓冲区划出的内存。

请谨慎使用。栈缓冲区的真实边界可从关联线程的 `stack_info` 成员取得。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `sym` | 已定义的栈符号名称。 |

返回（Returns）：缓冲区本身，类型为 `char *`。

## 2.4\_源码定位与版本边界

源码定位：[include/zephyr/kernel/thread_stack.h](../../../include/zephyr/kernel/thread_stack.h)、[kernel/thread.c](../../../kernel/thread.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位使用相对链接；代码对照不代表已验证具体开发板的栈保护、线程切换或回溯能力。

> 译注——源码核对：栈对象（Stack Object）、可用栈缓冲区（Stack Buffer）和初始栈指针（Stack Pointer）是不同概念。sizeof得到整个对象大小，K_*_STACK_SIZEOF按宏定义扣除固定保留区，K_*_STACK_BUFFER返回非固定保留区的起点；后者仍可能包含架构随后划出的保护区域。实际线程边界应结合stack_info及其delta理解。

> 译注——源码核对：K_KERNEL_STACK_*只面向监督模式线程或专用中断／异常栈，不能用它承载用户线程。未启用CONFIG_USERSPACE时，K_THREAD_STACK_*在本次头文件中映射到内核栈宏；这只是当前配置下的展开关系，不意味着开启用户模式后两类栈仍可互换。

> 译注——源码核对：数组宏额外把每个成员长度向上对齐，保证后续成员也满足栈对象基址约束。声明应与实际定义采用相同元素数量和请求大小，不应以普通char数组替代不透明的k_thread_stack_t对象，再自行猜测MPU或ABI对齐。

> 译注——源码核对：本次内核线程创建路径先计算栈布局，按配置填充初值、设置栈哨兵（Stack Sentinel）、预留线程局部存储与随机化空间，并设置stack_info。noinit段避免启动时一般清零，不代表线程创建期间不会初始化栈，也不保证栈中旧数据仍可使用。

> 译注——源码核对：Cortex-M在用户可用栈或浮点上下文需要额外MPU保护时，可能从缓冲区划出保护空间并调整stack_info.start／size。这类按上下文借用的空间不全计入K_THREAD_STACK_RESERVED，因此不能仅用对象起点加固定保留量得到最终可写边界。

> 译注——源码核对：启用CONFIG_HW_SHADOW_STACK时，头文件还生成硬件影子栈（Hardware Shadow Stack）及映射信息；它服务于所支持架构的控制流保护，不等于普通线程栈或MPU溢出保护区。源码中可见的内部映射结构不因此成为应用稳定接口。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
