# 第4章\_烧录与调试主机工具

原文：[Flash & Debug Host Tools](https://docs.zephyrproject.org/latest/develop/flash_debug/host-tools.html)。读取日期：2026-10-12，`latest`。

本指南介绍开发电脑上用于**烧录（Flashing）**和**调试（Debugging）** Zephyr 应用的软件。west 的 `flash`、`debug`、`debugserver`、`attach` 命令集成了这些工具，前提是板级硬件支持，并由开发板目录中的 `board.cmake` 正确声明。命令用法见 [west构建、烧录与调试](../west/P007_构建烧录与调试.md)。

> 译注：**运行器（Runner）**是 west 与具体主机工具之间的适配层，不是工具本身。**GNU调试器（GNU Debugger，GDB）**客户端提供调试交互，服务器连接目标或探针；不同 runner 支持的命令和连接次序并不完全相同。本章只是翻译安装与使用说明，没有执行下载、安装、固件更新或烧录。

## 4.1\_Black_Magic_Probe

**Black Magic Probe（BMP，开源调试探针产品名）**将 GDB 服务器集成在探针固件中，因此无需另装对应的主机 GDB 服务器程序。使用方法与支持目标见[调试探针](P003_调试探针.md)。

## 4.2\_SAM启动助手

**SAM启动助手（SAM Boot Assistant，SAM-BA）**可从 **通用串行总线（Universal Serial Bus，USB）**或**通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）**主机进行**在系统编程（In-System Programming，ISP）**，无需额外编程接口。

Zephyr 允许通过 west 开发和烧录支持 SAM-BA 的板，支持有或没有 **只读存储器引导加载器（ROM Bootloader）**的设备，以及 Arduino、Adafruit 扩展。原文说明完整支持从 Zephyr **软件开发工具包（Software Development Kit，SDK）**0.12.0 引入。

典型命令：

```sh
west flash [ -r bossac ] [ -p /dev/ttyX ] [ --erase ]
```

> 原文注意：bossac 默认只擦除包含应用镜像的闪存页；使用 `--erase` 则擦除目标的整片闪存。

> 译注：方括号表示可选参数，不是直接输入的语法。`/dev/ttyX` 是操作系统串行设备节点示意，需换成实际端口。这里保留必要的设备节点语义，不代表文件应保存到该位置。

### 4.2.1\_三种引导加载器配置

**设备自带 ROM Bootloader：**不需特殊配置，构建后执行 `west flash`。

**设备没有 ROM Bootloader：**

1. 定义容纳引导加载器与应用的闪存分区，见 [Flash分区映射](../storage/P001_Flash分区映射.md)。
2. 在开发板 `.defconfig` 中设置 `CONFIG_USE_DT_CODE_PARTITION=y`，使构建系统使用这些分区放置代码；也可在 `prj.conf` 或其他 Kconfig 片段中设置。
3. 构建并将 SAM-BA 引导加载器烧入设备。

**设备使用兼容的 SAM-BA Bootloader：**

1. 定义引导加载器与应用分区。
2. 在板 `.defconfig` 中设置 `CONFIG_BOOTLOADER_BOSSA=y`，它自动选中 `CONFIG_USE_DT_CODE_PARTITION`。再根据所用兼容模式，设置 `CONFIG_BOOTLOADER_BOSSA_ARDUINO`、`CONFIG_BOOTLOADER_BOSSA_ADAFRUIT_UF2` 或 `CONFIG_BOOTLOADER_BOSSA_LEGACY`。也可在应用配置片段中设置。
3. 构建并烧入 SAM-BA 引导加载器。

> 原文注意：`CONFIG_BOOTLOADER_BOSSA_LEGACY` 应作为最后选择，先尝试“没有 ROM Bootloader”的配置方式。

### 4.2.2\_典型闪存布局

引导加载器驻留闪存时，必须提供设备树分区。设备自带 ROM Bootloader，但应用使用存储等非代码分区时，也必须定义分区；此时省略引导分区，并让以 `code_partition` 为节点标签的代码分区从偏移 0 开始。各分区大小必须避免重叠。

下例注释中的 **闪存循环缓冲区（Flash Circular Buffer，FCB）**、**非易失性存储（Non-Volatile Storage，NVS）**和 LittleFS 文件系统可使用存储分区；它们是存储服务，不是引导加载器。没有 ROM Bootloader 的典型布局：

```devicetree
/ {
        chosen {
                zephyr,code-partition = &code_partition;
        };
};

&flash0 {
        partitions {
                compatible = "fixed-partitions";
                #address-cells = <1>;
                #size-cells = <1>;

                boot_partition: partition@0 {
                        label = "sam-ba";
                        reg = <0x00000000 0x2000>;
                        read-only;
                };

                code_partition: partition@2000 {
                        label = "code";
                        reg = <0x2000 0x3a000>;
                        read-only;
                };

                /*
                * The final 16 KiB is reserved for the application.
                * Storage partition will be used by FCB/LittleFS/NVS
                * if enabled.
                */
                storage_partition: partition@3c000 {
                        label = "storage";
                        reg = <0x0003c000 0x00004000>;
                };
        };
};
```

自带 ROM Bootloader 且包含存储分区的典型布局：

```devicetree
/ {
        chosen {
                zephyr,code-partition = &code_partition;
        };
};

&flash0 {
        partitions {
                compatible = "fixed-partitions";
                #address-cells = <1>;
                #size-cells = <1>;

                code_partition: partition@0 {
                        label = "code";
                        reg = <0x0 0xF0000>;
                        read-only;
                };

                /*
                * The final 64 KiB is reserved for the application.
                * Storage partition will be used by FCB/LittleFS/NVS
                * if enabled.
                */
                storage_partition: partition@F0000 {
                        label = "storage";
                        reg = <0x000F0000 0x00100000>;
                };
        };
};
```

> 译注：第二段原例注释说“最后 64 KiB”，但 `storage_partition` 的 `reg` 第二项写成 `0x00100000`，即 1 MiB，而不是 64 KiB；它是长度，不是结束地址。若确为从 `0xF0000` 开始的 64 KiB 分区，长度应为 `0x10000`，仍须根据芯片实际容量核对。第一例为 8 KiB 引导区、232 KiB 代码区、16 KiB 存储区。上述布局都不是本项目板的分区定义。

### 4.2.3\_启用SAM-BA运行器

`board.cmake` 应包含 `include(${ZEPHYR_BASE}/boards/common/bossac.board.cmake)`。开发板可以包含多个 runner 声明，默认 `west flash` 选择第一个，其余通过参数选择，例如 `west flash -r bossac`。

更多实现见[开发板与扩展板文档](https://docs.zephyrproject.org/latest/boards/index.html#boards)，原文列出的参考板有：

- [SAM4E Xplained Pro](https://docs.zephyrproject.org/latest/boards/atmel/sam/sam4e_xpro/doc/index.html#sam4e_xpro)：ROM Bootloader。
- [Feather M0 Basic Proto](https://docs.zephyrproject.org/latest/boards/adafruit/feather_m0_basic_proto/doc/index.html#adafruit_feather_m0_basic_proto)：Adafruit UF2 Bootloader。
- [Arduino Nano 33 IOT](https://docs.zephyrproject.org/latest/boards/arduino/nano_33_iot/doc/index.html#arduino_nano_33_iot)：Arduino Bootloader。
- [Arduino Nano 33 BLE (Sense)](https://docs.zephyrproject.org/latest/boards/arduino/nano_33_ble/doc/index.html#arduino_nano_33_ble)：Arduino 旧版 Bootloader。

### 4.2.4\_Windows原生BOSSAC支持（实验性）

原文说明 Zephyr SDK 的 bossac 当前只支持 Linux 和 macOS。Windows 可使用 [BOSSA官方发布](https://github.com/shumatech/BOSSA/releases)中的 bossac，安装后将可执行文件所在目录加入 `PATH`；也可通过 `--bossac` 指定程序。下例 Windows 命令提示符使用环境变量 `BOSSAC_EXE`；先将其值设为本机 bossac 可执行文件的位置：

```bat
west flash -r bossac --bossac="%BOSSAC_EXE%" --bossac-port="COMx"
```

> 译注：本命令将原文固定盘符改为 `BOSSAC_EXE` 环境变量。先将该变量设为自己实际安装的可执行文件，再把 `COMx` 换成设备端口。变量是本页为路径可移植性引入的名称，不是 west 自动设置的配置。

原文注意：此方式目前不支持 **适用于Linux的Windows子系统（Windows Subsystem for Linux，WSL）**。

## 4.3\_NXP_LinkServer

LinkServer 用于启动和管理 NXP 探针的 GDB 服务器，同时提供命令行闪存编程。它可与 [MCUXpresso for Visual Studio Code](https://www.nxp.com/design/software/development-software/mcuxpresso-software-and-tools-/mcuxpresso-for-visual-studio-code:MCUXPRESSO-VSC)、基于 GNU 工具的自定义配置，以及无图形界面的持续集成/测试系统配合。支持 MCU-Link、LPC-Link2、基于 LPC11U35 和 OpenSDA 的独立或板载探针。

> 译注：原文 MCUXpresso Installer 的 `latest` 链接返回 404，下面改为已核对可访问的官方 26.07 文档入口。

NXP 建议用 [MCUXpresso Installer](https://mcuxpresso.nxp.com/mcux-vscode/26.07/html/MCUXpresso-Installer.html) 安装，同时获得 MCU-Link、LPCScrypt 等配套工具。原文列出的兼容探针为 LPC-Link2 CMSIS-DAP、MCU-Link CMSIS-DAP、OpenSDA DAPLink。

> 译注：**CMSIS-DAP**是 Arm 的 **Cortex微控制器软件接口标准（Cortex Microcontroller Software Interface Standard，CMSIS）**中的**调试访问端口（Debug Access Port，DAP）**方案。具体固件分支见[探针文档](P003_调试探针.md)。

与 west 配合时，将实际 LinkServer 安装目录加入 `PATH`。原文按三种系统分别给出默认目录；此处用安装目录占位说明替代固定机器路径。

Linux：

```text
<Linux上的LinkServer安装目录>
```

macOS：

```text
<macOS上的LinkServer安装目录>
```

Windows：

```text
<Windows上的LinkServer安装目录>
```

> 译注：三行都是目录说明，不是命令。按安装结果选择包含 LinkServer 程序的目录；保留系统分支，不要求采用某个盘符、用户名或版本目录。

支持的 west 命令为 `flash`、`debug`、`debugserver`、`attach`。可以列出探针：

```sh
LinkServer probes
```

同时连接多个探针时，用 runner 的 `--probe` 参数指定索引，例如：

```sh
west flash --runner=linkserver --probe=3
```

用 `--override` 覆盖设备专用设置，可重复传入，格式由 LinkServer 定义，例如：

```sh
west flash --runner=linkserver --override /device/memory/5/flash-driver=MIMXRT500_SFDP_MXIC_OSPI_S.cfx
```

> 译注：`/device/memory/5/flash-driver` 是 LinkServer 配置对象的字段路径，不是本机文件系统绝对路径；示例驱动文件对应特定目标。

LinkServer 不会在复位处理器处自动设置隐式断点。如果想从应用起点单步，需手动在 `main` 或复位处理函数处设置断点。可用 `--gdb-init` 将该断点或其他命令追加到 `west debug`、`west attach` 启动的 GDB 客户端：

```sh
west debug --runner=linkserver --gdb-init 'b main'
```

## 4.4\_J-Link主机工具

SEGGER 为 Linux、macOS、Windows 提供：

| 工具 | 用途 |
| --- | --- |
| J-Link GDB Server | GDB 远程调试 |
| J-Link Commander | 命令行控制与闪存编程 |
| RTT Viewer | **实时传输（Real Time Transfer，RTT）**终端输入输出 |
| SystemView | 实时事件可视化与记录 |

兼容探针包括 LPC-Link2 J-Link、OpenSDA J-Link、MCU-Link J-Link、外部 J-Link，以及采用适配固件的 ST-LINK/V2-1。先检查 [J-Link支持设备](https://www.segger.com/downloads/supported-devices.php)是否包含目标 **片上系统（System on Chip，SoC）**。

> 译注：原文下载页的章节锚点已无法定位，链接改为同一官方下载页面，可按软件包名称查找。

下载并安装 [J-Link Software and Documentation Pack](https://www.segger.com/downloads/jlink/)，取得 GDB Server、Commander 和 USB 驱动。RTT Viewer 与 SystemView 可以独立下载，但不是必要组件。

原文说明 J-Link GDB Server 尚不支持 Zephyr **实时操作系统感知（Real-Time Operating System Awareness，RTOS Awareness）**。

> 译注：此处按读取页面保留工具能力描述。RTOS 感知指识别 Zephyr 线程等内核对象，不等于普通断点调试；具体工具版本及插件支持须另行核对，不能据旧页面概括全部版本。

### 4.4.1\_追加GDB命令

`jlink` runner 接受 `--gdb-init`，向 `west debug` 和 `west attach` 启动的 GDB 客户端追加命令。可重复指定，按给定顺序执行，位置在 runner 自己发送的全部命令之后、目标恢复运行之前。因此不能用它改变 runner 自身的连接、加载与复位次序；`west flash`、`west reset`、`west rtt`、`west debugserver` 不受影响。

例如，在本次会话启用 J-Link **半主机（Semihosting）**功能：

```sh
west debug -r jlink --gdb-init 'monitor semihosting enable' \
  --gdb-init 'monitor semihosting basedir .'
```

可在板的 `board.cmake` 中将命令作为默认参数：

```cmake
board_runner_args(jlink "--gdb-init=monitor semihosting enable")
```

> 译注：半主机让目标程序经调试器使用主机输入输出；`basedir .` 使用当前目录作为相应文件访问基准。原文 CMake 片段只展示第一条启用命令，若还需要第二条，应另行加入。

`--gdb-init` 只传到 GDB 客户端。J-Link GDB Server 自身参数用 `--tool-opt`，烧录时交给 J-Link Commander 的命令用 `--pre-script-cmd`。`linkserver`、`openocd`、`intel_cyclonev` runner 也接受 `--gdb-init`，但适用命令与插入位置由各 runner 决定。

## 4.5\_OpenOCD主机工具

**开放片上调试器（Open On-Chip Debugger，OpenOCD）**是社区开源项目，提供大量 SoC 的 GDB 远程调试与闪存编程。Zephyr SDK 包含一个加入 Zephyr RTOS 感知支持的分支；其他获取方式见 [Getting OpenOCD](https://openocd.org/pages/getting-openocd.html)。

原文列出的兼容探针为 OpenSDA DAPLink、外部 J-Link、ST-LINK/V2-1。检查 [OpenOCD目标配置](https://github.com/zephyrproject-rtos/openocd/tree/latest/tcl/target)是否包含芯片。

Linux 可从 [Zephyr SDK](https://github.com/zephyrproject-rtos/sdk-ng/releases)取得。原文 Windows 安装步骤为：

1. 下载 [Windows OpenOCD](https://gnutoolchains.com/arm-eabi/openocd/)。
2. 将 `bin` 和 `share` 放到同一 OpenOCD 安装根目录。
3. 将该根目录下的 `bin` 子目录加入 `PATH`。

> 译注：上述第二、三步将原文固定盘符改为按实际安装根目录定位；`bin` 与 `share` 的相对关系保留。

## 4.6\_pyOCD主机工具

pyOCD 是 Arm 提供的开源 Python 调试工具，为 Arm Cortex-M SoC 提供 GDB 远程调试和闪存编程。它通过 **Python软件包索引（Python Package Index，PyPI）**分发，在完成[获取Zephyr并安装Python依赖](../getting_started/P002_入门指南.md)步骤时安装，并支持 Zephyr RTOS 感知。

原文列出的兼容探针为 LPC-Link2 CMSIS-DAP、MCU-Link CMSIS-DAP、OpenSDA DAPLink、ST-LINK/V2-1。检查 [pyOCD内置目标](https://github.com/pyocd/pyOCD/tree/main/pyocd/target/builtin)中是否包含芯片。

> 译注：探针兼容与芯片支持是两个条件；使用目标支持包或项目钩子的配置还需按具体芯片说明处理，不能仅因 USB 探针被发现就认定可安全擦写目标。

## 4.7\_Lauterbach_TRACE32

[Lauterbach TRACE32](https://www.lauterbach.com/) 是微处理器开发工具、调试器及实时跟踪器产品系列，支持多种核心架构上的 **JTAG（Joint Test Action Group，联合测试行动小组；此处指调试接口标准）**、**串行线调试（Serial Wire Debug，SWD）**、NEXUS、ETM，涵盖 Arm Cortex-A/R/M、RISC-V、Xtensa 等。Zephyr 可通过 west 使用它开发和编程。

> 译注：**嵌入式跟踪宏单元（Embedded Trace Macrocell，ETM）**用于输出处理器执行跟踪；NEXUS 是调试与跟踪接口标准系列名称。它们不等同于一般串口日志。

runner 包装 TRACE32 软件，让板针对不同命令执行自己的 **PRACTICE脚本（Practice Script，TRACE32脚本语言）**，也可接收 CMake 提供的附加参数。每个命令实际执行什么，由板级脚本决定。

### 4.7.1\_安装与运行

从 [TRACE32下载站](https://www.lauterbach.com/download_trace32.html)取得软件，需要注册；按[安装指南](https://www2.lauterbach.com/pdf/installation.pdf)安装。

将 `T32_DIR` 环境变量设为 TRACE32 系统目录，再执行 `west flash` 或 `west debug`。`debug` 打开 **图形用户界面（Graphical User Interface，GUI）**，`flash` 隐藏界面，在后台操作。

默认使用 TRACE32 系统目录中的 `config.t32`。用 `--config CONFIG` 选择其他配置，例如：

```sh
west flash --config myconfig.t32
```

通过 `west flash --context -r t32` 查看更多选项。启用 Zephyr RTOS 感知的方法见 [TRACE32 Zephyr OS Awareness手册](https://www2.lauterbach.com/pdf/rtos_zephyr.pdf)。

## 4.8\_NXP_S32探针主机工具

NXP S32 Debug Probe 与 [S32 Design Studio for S32 Platform](https://www.nxp.com/design/software/development-software/s32-design-studio-ide/s32-design-studio-for-s32-platform:S32DS-S32PLATFORM) 配合。注册并下载后，按[安装指南](https://www.nxp.com/webapp/Download?colCode=S32DSIG)安装工具及 USB 驱动。NXP S32 GDB Server 的 Zephyr RTOS 感知支持取决于目标设备，需查对应发布说明。

支持 `debug`、`debugserver` 和 `attach`。

### 4.8.1\_基本使用

将 S32 Design Studio 安装目录加入 `PATH`，或每次通过 `--s32ds-path` 传入。下例将原文固定安装路径替换为事先设置的 `S32DS_DIR` 环境变量。

Linux shell：

```sh
west debug --s32ds-path="$S32DS_DIR"
```

Windows cmd.exe：

```bat
west debug --s32ds-path="%S32DS_DIR%"
```

> 译注：两个系统使用不同的变量展开语法。`S32DS_DIR` 是本例自定变量，必须先按安装结果设置，不可空值执行。

主机通过 USB 连接多个 S32 探针时，runner 会在命令行提示选择。也可用 `--dev-id=<connection-string>` 指定连接串，格式见 [S32探针用户手册](https://www.nxp.com/docs/en/user-guide/S32DBGUG.pdf)。例如序列标识为 `00:04:9f:00:ca:fe`：

```sh
west debug --dev-id='s32dbg:00:04:9f:00:ca:fe'
```

`--tool-opt` 可传递附加参数：执行 `debug`、`attach` 时只交给 GDB 客户端，执行 `debugserver` 时交给服务器。例如将应用加载到 **静态随机存取存储器（Static Random-Access Memory，SRAM）**后退出调试会话：

```sh
west debug --tool-opt='--batch'
```

要求 S32 Design Studio 3.6.0 或更新版本，以及 S32DebugProbe OS 固件 1.1.0 或更新版本。更新探针固件按用户手册的 **Reprogramming S32 Debug Probe Firmware Images（重新编程探针固件镜像）**章节执行。

## 4.9\_probe-rs

probe-rs 是使用 Rust 编写的开源嵌入式工具集，直接支持 CMSIS-DAP、ST-Link、SEGGER J-Link、FTDI 和 ESP32 内置 USB-JTAG 等探针或接口。

安装见 [probe-rs Installation](https://probe.rs/docs/getting-started/installation/)，芯片支持见 [Supported Devices](https://probe.rs/targets/)。

## 4.10\_Renesas_Flash_Programmer

Renesas 官方的 [Renesas Flash Programmer（RFP，瑞萨闪存编程工具）](https://www.renesas.com/en/software-tool/renesas-flash-programmer-programming-gui)用于采用标准启动固件的 Renesas 板，提供 GUI 和 **命令行界面（Command-Line Interface，CLI）**。

板配置 `rfp` runner 后，可通过 RFP CLI 烧录 Zephyr，支持 west `flash`。若下载的 `rfp-cli` 不在 `PATH` 中，可显式指定：

```sh
west flash --rfp-cli ~/Downloads/RFP_CLI_Linux_V31800_x64/linux-x64/rfp-cli
```

> 译注：这是相对于用户主目录的原下载布局示例，应换成实际文件位置，不能把文件包中的版本号当成当前必须安装的版本。

## 4.11\_STM32CubeCLT

[STM32CubeCLT](https://www.st.com/en/development-tools/stm32cubeclt.html) 是 ST 官方面向 Linux、macOS、Windows 的一体化工具集，可在第三方开发环境中使用 ST 工具。它包含 **ST-LINK GDB Server**，通过板载或外部 ST-LINK 调试 STM32。

兼容 ST-LINK/V2-1，以及独立的 [ST-LINK-V2](https://www.st.com/en/development-tools/st-link-v2.html)、[ST-LINK-V3](https://www.st.com/en/development-tools/stlink-v3set.html)、[STLINK-V3PWR](https://www.st.com/en/development-tools/stlink-v3pwr.html)。原文建议从 ST 网站安装 STM32CubeCLT 取得服务器，获取下载链接需有效邮箱。

可通过 `west attach`、`west debug`、`west debugserver` 调试，例如：

```sh
west debug --runner stlink_gdbserver
```

原文注意：同一安装包中的 STM32CubeProgrammer 可用于烧录，但应选择它专用的 runner，而非 `stlink_gdbserver`：

```sh
west flash --runner stm32cubeprogrammer
```

## 4.12\_STM32CubeProgrammer

[STM32CubeProgrammer（STM32CubeProg）](https://www.st.com/en/development-tools/stm32cubeprog.html) 是 ST 官方的 STM32 编程工具，支持 Linux、macOS、Windows。它可通过 JTAG/SWD 调试接口，以及 UART、USB DFU、I2C、SPI、CAN 引导加载器接口读写并验证设备内存。

> 译注：**设备固件升级（Device Firmware Upgrade，DFU）**是这里的 USB 升级协议；**控制器局域网（Controller Area Network，CAN）**是另一种通信总线。不同芯片 Bootloader 支持的接口并不相同。

该工具支持内部闪存、**随机存取存储器（Random-Access Memory，RAM）**、**一次性可编程存储器（One-Time Programmable Memory，OTP）**及外部存储器，提供选项编程和上传、内容验证、脚本自动编程，并提供 GUI 与 CLI 版本。

兼容 ST-LINK/V2-1、外部 J-Link，以及 ST-LINK-V2/V3/V3PWR。可从 ST 网站下载，原文说明需有效邮箱；也可通过 STM32CubeCLT 安装。系统安装了 STM32CubeIDE 时，也已包含 STM32CubeProg。

原文将 STM32CubeProgrammer 描述为 Zephyr 支持的全部活动 STM32 板的默认烧录 runner。显式调用：

```sh
west flash --runner stm32cubeprogrammer
```

高级 GUI/CLI 用法见[用户手册](https://www.st.com/resource/en/user_manual/um2237-stm32cubeprogrammer-software-description-stmicroelectronics.pdf)。具体板的默认 runner 仍以所用版本的板级配置为准。

## 4.13\_AMD_XSDB

AMD XSDB（原页展开为 **Xilinx Software Command-line Tool for Debug，Xilinx软件调试命令行工具**）用于编程和调试许多 AMD 自适应 SoC 与 **现场可编程门阵列（Field-Programmable Gate Array，FPGA）**平台。

它不包含在 Zephyr SDK 中，须安装 [AMD Vitis](https://www.amd.com/en/products/software/adaptive-socs-and-fpgas/vitis.html) 或对应 AMD 工具链，并让 `xsdb` 位于 `PATH` 中。

使用 `xsdb` runner 的板通常在板定义旁提供 `support/xsdb.cfg`。所需启动产物，如 **可编程器件镜像（Programmable Device Image，PDI）**、**配置位流（Bitstream）**、**第一阶段引导加载器（First Stage Bootloader，FSBL）**等，须查该板文档。

支持 `flash`、`debug` 和 `debugserver`。对这个 runner，后两者都启动同一种 XSDB 原生交互会话，经板的 `xsdb.cfg` 加载应用，并停留在 XSDB 提示符；不同于 GDB runner 的 `debugserver`，它不是仅启动供 IDE 连接的远程服务。

```sh
west flash --runner xsdb

west debug --runner xsdb

west debugserver --runner xsdb
```

> 原文注意：这与 J-Link、STM32CubeCLT 等专有工具的依赖方式相同：Zephyr 通过 runner 集成，取得工具链及对应许可由用户负责。

## 4.14\_UF2上传器

`uf2` runner 支持通过 **USB烧录格式（USB Flashing Format，UF2）**为部分板烧录。该格式面向通过 USB 大容量存储设备拖放编程的场景。

目标须进入特殊引导加载器模式，在主机上表现为存储设备；然后将 `.uf2` 应用文件复制到挂载卷即可上传。

```sh
west flash --runner uf2
```

未自动识别 UF2 卷时，可通过 `--device` 手动指定挂载点。格式与工具见 [USB Flashing Format](https://github.com/microsoft/uf2)。

## 4.15\_Realtek替代编程工具rtkprog

rtkprog 是 Realtek Bee 系列 SoC 通过 UART 烧录协议的开源实现。

```sh
west flash --runner rtkprog
```

## 4.16\_Realtek_Bee编程工具MPCli

Realtek 官方 **Flash Programmer（MPCli，工具名称）**支持 Linux、macOS、Windows，通过 UART 进行 ISP，无需外部编程硬件。多数官方 Bee 评估板内置 UART-USB 转换器，可直接用于编程和日志。

下载 [MPCli](https://docs.realmcu.com/tools/mpcli_tool/en/latest/mpcli/text_en/README.html) 压缩包，解压并选择匹配操作系统的版本，将 `mpcli` 所在目录加入 `PATH`。开始前须将板置于下载模式，见 [Realtek开发板文档](https://docs.zephyrproject.org/latest/boards/realtek/index.html)。

```sh
west flash [--runner mpcli] --port /dev/ttyX
```

## 4.17\_IAR_EW与C-Spy

IAR 提供 **Embedded Workbench（EW，嵌入式开发工作台）**与 CSpyBat，用于调试和烧录。名为 `iar` 的运行器要求 **IAR Embedded Workbench for Arm（EWARM）**10.10 或更新版本。
