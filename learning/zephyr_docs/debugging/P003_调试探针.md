# 第3章\_调试探针

原文：[Debug Probes](https://docs.zephyrproject.org/latest/develop/flash_debug/probes.html)。读取日期：2026-10-12，`latest`。

**调试探针（Debug Probe）**是用于控制另一块板上 Zephyr 应用执行的专用硬件。通常可读写寄存器和内存，配合主机上的 **GNU调试器（GNU Debugger，GDB）**进行断点调试；还可能支持其他调试软件及[执行跟踪（Execution Tracing）](https://docs.zephyrproject.org/latest/services/tracing/index.html#tracing)等高级功能。相关软件见[烧录与调试主机工具](P004_烧录与调试主机工具.md)。

探针通常通过 **通用串行总线（Universal Serial Bus，USB）**连接主机，也可通过 **互联网协议网络（Internet Protocol Network，IP Network）**或其他方式访问。探针与目标通常使用 **JTAG（Joint Test Action Group，联合测试行动小组；此处指其调试接口标准）**或**串行线调试（Serial Wire Debug，SWD）**连接。探针可以是独立外设，也可以是目标板上的集成电路。

许多 Zephyr 开发板包含第二颗**微控制器（Microcontroller Unit，MCU）**，作为板载探针、USB 转串口适配器，有时还提供拖放式烧录功能，因而无需另购外部探针，也可选择多种主机工具。

不同厂商有自己的板载探针实现。NXP 可能使用 OpenSDA、LPC-Link2 或 MCU-Link，取决于运行探针固件的 MCU；ST 使用 ST-LINK。同一探针 MCU 可支持一种或多种固件，分别连接相应主机工具。例如，OpenSDA MCU 可装载 DAPLink 固件以连接 pyOCD/OpenOCD，也可装载 J-Link 固件以连接 J-Link 工具。

> 译注：OpenSDA、DAPLink、MCU-Link、LPC-Link2、J-Link、ST-LINK、pyOCD 均是产品或项目名称，不是可以任意互换的协议名。**开放片上调试器（Open On-Chip Debugger，OpenOCD）**是主机软件。芯片、探针硬件、探针固件和主机工具是不同层次，兼容性需按具体组合判断。

## 3.1\_探针与主机工具兼容表

| 外部 J-Link | ✓ | ✓ | — | — | — | — |
| LPC-Link2 CMSIS-DAP | — | — | — | — | ✓ | — |

> 译注：**CMSIS-DAP**是 Arm **Cortex微控制器软件接口标准（Cortex Microcontroller Software Interface Standard，CMSIS）**中的**调试访问端口（Debug Access Port，DAP）**接口方案。该表是原文概览，留空不能当作普遍不兼容的结论；同套主机工具文档还列出 pyOCD 对 LPC-Link2/MCU-Link CMSIS-DAP 的支持。固件类型、目标芯片和软件版本仍须核对。

部分板没有板载探针，需要外部探针。有板载探针的板也常提供 SWD/JTAG 接口，以便绕过板载探针的限制，例如高级调试器或高速跟踪能力不足。使用外部探针时，可能需要调整跳线，避免板载探针干扰。

## 3.2\_NXP板载探针的识别

NXP 板载探针是评估板上的第二颗 MCU，可按其**片上系统（System on Chip，SoC）**型号判断类型：

| 调试MCU | 探针 |
| --- | --- |
| LPC55S69 | MCU-Link |
| LPC4322 | LPC-Link2 |
| MK20 | OpenSDA |

例如 [FRDM-K64F](https://docs.zephyrproject.org/latest/boards/nxp/frdm_k64f/doc/index.html#frdm_k64f) 使用 MK20 调试 MCU，所以是 OpenSDA。

## 3.3\_MCU-Link板载探针

MCU-Link 使用 LPC55S69，支持默认的 CMSIS-DAP 固件和 J-Link 固件。使用 MCU-Link 主机工具为其编程，这些工具随 LinkServer 安装；NXP 建议使用 [MCUXpresso Installer](https://www.nxp.com/lgfiles/updates/mcuxpresso/MCUXpressoInstaller.exe) 安装 LinkServer。

### 3.3.1\_MCU-Link_CMSIS-DAP固件

默认 CMSIS-DAP 固件可与兼容工具链配合，包括 IAR EWARM、Keil MDK、NXP MCUXpresso IDE 及 MCUXpresso 的 VS Code 扩展。除调试外，视 MCU-Link 型号和实现，还可能提供：

- **串行线输出（Serial Wire Output，SWO）**跟踪端点，供 MCUXpresso 获取跟踪数据，详见其 IDE 文档。
- 与目标相连的**虚拟串口（Virtual COM Port，VCOM）**或 **通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）**桥接。
- USB 到 UART、**串行外设接口（Serial Peripheral Interface，SPI）**或**集成电路间总线（Inter-Integrated Circuit，I2C）**桥接。
- 目标 MCU 的能量测量。

本节原文列出的兼容主机工具为 LinkServer。安装好 MCU-Link 工具后，按以下步骤写入 CMSIS-DAP 固件：

1. 确认主机已有 MCU-Link 实用程序，可通过 LinkServer 安装取得。
2. 装上 **设备固件升级（Device Firmware Upgrade，DFU）**跳线，再连接板上 USB 调试端口，使探针 MCU 进入 DFU 启动模式。该跳线也可能称为 **在系统编程（In-System Programming，ISP）**跳线，连接 LPC55S69 的 `PIO0_5`。
3. 运行 MCU-Link 安装目录 `scripts` 下的 `program_CMSIS` 脚本。
4. 拔掉 DFU 跳线，对开发板断电再上电。

### 3.3.2\_MCU-Link_J-Link固件

该固件提供 J-Link 兼容调试接口和 USB 转串口，配合 J-Link 主机工具。默认未安装，需要更新：

1. 确认已通过 LinkServer 安装 MCU-Link 实用程序。
2. 装上接到 LPC55S69 `PIO0_5` 的 DFU/ISP 跳线，再连接 USB 调试口，进入探针 MCU 的 DFU 模式。
3. 运行 MCU-Link 安装目录 `scripts` 下的 `program_JLINK`。
4. 拔掉跳线，断电再上电。

## 3.4\_LPC-Link2板载探针

LPC-Link2 使用 LPC4322，支持 CMSIS-DAP、J-Link 和默认的 DAPLink 固件。使用随 LinkServer 安装的 LPCScrypt 主机工具编程，NXP 同样建议通过 MCUXpresso Installer 安装。

### 3.4.1\_LPC-Link2_CMSIS-DAP固件

CMSIS-DAP 支持 IAR EWARM、Keil MDK、MCUXpresso IDE 和 MCUXpresso VS Code 扩展等兼容工具。除调试外，LPC-Link2 还提供 SWO 跟踪端点、连接目标的 VCOM/UART 桥接，以及用于 I2C/SPI 外设通信的 LPCSIO 桥接。

> 译注：LPCSIO 是 NXP 桥接接口的名称，指探针提供的外设通信通道；SWO 输出跟踪数据，UART/VCOM 输出串行数据，不能当成同一接口。

本节原文列出的兼容主机工具为 LinkServer。更新 CMSIS-DAP 固件：

1. 确认主机已安装 LPCScrypt，可通过 LinkServer 取得。
2. 装上连接 LPC4322 `P2_6` 的 DFU 跳线，再连接 USB 调试端口，使探针进入 DFU 启动模式。
3. 运行 LPCScrypt 安装目录 `scripts` 下的 `program_CMSIS`。
4. 拔掉 DFU 跳线，断电再上电。

<a id="lpclink2-jlink-onboard-debug-probe"></a>

### 3.4.2\_LPC-Link2_J-Link固件

> 原文注意：某些板刷入 J-Link 探针固件后，USB 调试端口不再为板供电，必须改用其他供电方式。

该固件提供 J-Link 兼容调试接口及 USB 转串口，配合 J-Link 主机工具。更新前先在 [Firmware for LPCXpresso](https://www.segger.com/products/debug-probes/j-link/models/other-j-links/lpcxpresso-on-board/) 确认固件支持目标板，再进行：

1. 确认已安装 LPCScrypt。
2. 装上连接 LPC4322 `P2_6` 的 DFU 跳线，再连接 USB 调试口。
3. 运行 LPCScrypt 安装目录 `scripts` 下的 `program_JLINK`。
4. 拔掉跳线，断电再上电。

### 3.4.3\_LPC-Link2_DAPLink固件

原文说明，DAPLink 是基于 LPC-Link2 的板出厂预装固件，但不是推荐固件，建议按前述步骤更新为 CMSIS-DAP。DAPLink 编程详情见 [NXP AN13206](https://www.nxp.com/docs/en/application-note/AN13206.pdf)。

## 3.5\_OpenSDA板载探针

OpenSDA 基于 NXP MK20，支持拖放编程，以及默认的 DAPLink 和 J-Link 调试固件。

### 3.5.1\_OpenSDA_DAPLink固件

兼容 pyOCD、OpenOCD 和 LinkServer。向 OpenSDA MCU 写入 DAPLink OpenSDA 固件即可实现该探针，NXP 提供[按开发板区分的固件](https://www.nxp.com/opensda)。写固件前应先安装对应主机工具。

1. 按住复位按钮并给板上电，使 OpenSDA MCU 进入**引导加载器模式（Bootloader Mode）**。这里指探针 MCU，不是运行 Zephyr 的目标 MCU。
2. 上电后松开复位按钮，主机会枚举名为 `BOOTLOADER` 或 `MAINTENANCE` 的 USB 大容量存储设备。若名为 `BOOTLOADER`，先按 [DAPLink Bootloader Update](https://os.mbed.com/blog/entry/DAPLink-bootloader-update/) 更新引导加载器。
3. 把 OpenSDA 固件二进制复制到该存储设备。
4. 不按复位按钮，重新断电再上电。应枚举三个 USB 设备：**通信设备类（Communications Device Class，CDC）**串口、**人机接口设备类（Human Interface Device，HID）**调试端口，以及拖放烧录所用的大容量存储设备。

### 3.5.2\_OpenSDA_J-Link固件

> 译注：原文两个下载链接的章节锚点已无法定位，以下保留同一官方下载页，按 Generic Firmwares（通用固件）和 Board-Specific Firmwares（板专用固件）名称查找。

兼容 J-Link 主机工具。SEGGER 提供 [OpenSDA 通用固件](https://www.segger.com/downloads/jlink/)和[板专用固件](https://www.segger.com/downloads/jlink/)，有专用版本时通常优先使用它。i.MX RT 板需要专用固件支持外部闪存，通用固件兼容全部 Kinetis 板。

先安装调试主机工具，再进行：

1. 按住复位按钮，将 USB 接入板的调试口，使 OpenSDA MCU 进入引导加载器模式；不要与目标 MCU 启动模式混淆。
2. 松开按钮，等待 `BOOTLOADER` 或 `MAINTENANCE` 存储设备出现。若名为 `BOOTLOADER`，先按上述 DAPLink 文档更新引导加载器。
3. 将相应 OpenSDA 固件二进制复制到该存储设备。
4. 不按按钮，断电再上电。应枚举 CDC 串口与厂商专用调试端口两个 USB 设备。

## 3.6\_外部J-Link探针

[SEGGER J-Link](https://www.segger.com/products/debug-probes/j-link/) 是一个外部探针产品系列，包括 J-Link EDU、PLUS、ULTRA+、PRO，支持多种架构与厂商的大量目标设备。

兼容 J-Link 主机工具和 OpenOCD。原文要求在更新探针固件前安装对应主机工具。

## 3.7\_ST-LINK_V2-1板载探针

ST-LINK/V2-1 是串行与调试适配器，在电脑等 USB 主机和嵌入式目标间建立桥接，用一根 USB 线提供调试、烧录和串行通信。原文将其描述为集成于全部 Nucleo 和 Discovery 板。

> 译注：“全部”是原文的概括，不能覆盖不同年代、不同型号的所有 ST 板；实际探针可能是其他 ST-LINK 版本，应以板卡资料为准。

兼容 OpenOCD、J-Link、STM32CubeCLT；部分 STM32 板也兼容 pyOCD。OpenOCD 可直接使用它，而使用 J-Link 需要更新探针固件。SEGGER 提供使 ST-LINK/V2-1 兼容 J-LinkOB 的固件，获得相应 J-Link 烧录、调试及 GDB Server 功能。升级及恢复说明见 [SEGGER over ST-Link](https://www.segger.com/products/debug-probes/j-link/models/other-j-links/st-link-on-board/)。

### 3.7.1\_用OpenOCD烧录与调试

原文说明 OpenOCD 为默认工具，示例命令为：

```sh
# From the root of the zephyr repository
west build -b None samples/hello_world
west flash
```

```sh
# From the root of the zephyr repository
west build -b None samples/hello_world
west debug
```

> 译注：页面生成的 `-b None` 不是有效板名，应替换为实际板目标。默认 runner（west 调用的工具适配器）由板级 `board.cmake` 决定；同套主机工具文档对当前 STM32 板又提到 STM32CubeProgrammer，不能把此处默认值当成全版本保证。

<a id="using-segger-j-link"></a>

### 3.7.2\_用SEGGER_J-Link烧录与调试

探针已刷入 SEGGER 固件，且主机已安装 J-Link GDB Server 后，可用 CMake 参数 `-DBOARD_FLASH_RUNNER=jlink` 更改默认烧录 runner；或在应用 `CMakeLists.txt` 中加入：

```cmake
set(BOARD_FLASH_RUNNER jlink)
```

使用 west 时，也可通过 `--runner` 或 `-r` 指定：

```sh
west flash --runner jlink
```

连接调试器并打开调试控制台：

```sh
west debug --runner jlink
```

更多选项见 [west构建、烧录与调试](../west/P007_构建烧录与调试.md)。

如果应用使用 **SEGGER实时传输（Real Time Transfer，RTT）**控制台，可通过 Telnet 打开：

```text
$ telnet localhost 19021
Trying ::1...
Trying 127.0.0.1...
Connected to localhost.
Escape character is '^]'.
SEGGER J-Link V6.30f - Real time terminal output
J-Link STLink V21 compiled Jun 26 2017 10:35:16 V1.0, SN=773895351
Process: JLinkGDBServerCLExe
Zephyr Shell, Zephyr version: 1.12.99
Type 'help' for a list of available commands
shell>
```

> 译注：以上是原文历史输出，包含 J-Link 6.30f 和 Zephyr 1.12.99，并非本次运行结果。Telnet 是远程终端协议；`localhost:19021` 指向当前电脑上的服务。RTT 本身通过探针交换数据，不是板上额外提供网络接口。

没有 RTT 输出时，可能需要关闭示例或应用默认启用的冲突控制台，例如在 `menuconfig` 中关闭 `UART_CONSOLE`。

### 3.7.3\_更新或恢复ST-Link固件

可以通过 [STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) 更新 ST-Link 固件。这在遇到烧录问题时通常有用，例如使用 Twister 的设备测试功能时。

安装后，原文给出的命令为：

```sh
s java -jar ~/STMicroelectronics/STM32Cube/STM32CubeProgrammer/Drivers/FirmwareUpgrade/STLinkUpgrade.jar -sn <board_uid>
```

`board_uid` 可通过 Twister 的 `generate-hardware-map` 选项取得，详见 [Twister测试运行器](https://docs.zephyrproject.org/latest/develop/twister/index.html#twister-script)。

> 译注：原命令开头的 `s java` 存在明显疑点，通常应直接调用 `java -jar`；本文保留原文便于核对。JAR 路径也是原安装布局，应从实际工具目录定位。更新的是探针固件，不是 Zephyr 应用镜像；本翻译过程没有执行它。

### 3.7.4\_OpenOCD弃用旧HLA接口

OpenOCD 于 2024 年 1 月[弃用旧ST-Link HLA接口](https://sourceforge.net/p/openocd/code/ci/34ec5536c0ba3315bc5a841244bbf70141ccfbb4)，转向通用 DAP 接口。**高层适配器（High-Level Adapter，HLA）**是旧接口方案；ST-Link 固件从 2015 年的 `v2j24` 起支持这里的 DAP 方式。

使用 `v0.12.0` 发布标签之后的较新 OpenOCD，而 ST-Link 固件早于 `v2j24` 时，可能出现通信问题，应更新 ST-Link 固件。无法更新时，可以在适用的 OpenOCD 配置中把：

```tcl
source [find interface/stlink-dap.cfg]
transport select dapdirect_swd
```

换为：

```tcl
source [find interface/stlink-hla.cfg]
transport select hla_swd
```

> 译注：Tcl 是 OpenOCD 配置脚本使用的语言名称。`dapdirect_swd` 与 `hla_swd` 是不同传输选择，不应只改配置文件名而漏改传输。

## 3.8\_NXP_S32探针

[NXP S32 Debug Probe](https://www.nxp.com/design/software/automotive-software-and-tools/s32-debug-probe:S32-DP) 通过标准调试端口连接 NXP S32 目标系统，主机侧可使用 USB 或远程以太网。

它设计为与 NXP **S32 Design Studio（S32DS）**及 NXP 汽车 MCU/处理器配合。更新探针固件之前，按[主机工具说明](P004_烧录与调试主机工具.md)安装相应软件。

## 3.9\_Black_Magic探针

[Black Magic Probe（BMP）](https://black-magic.org/index.html) 是与 Black Magic Debug 固件配合的开源调试硬件。固件内置 GDB 服务器，因此可从 GDB 直接连接目标，无需另起主机 GDB 服务器程序。

部分 STM32F103 板可运行该固件，见[支持的硬件](https://black-magic.org/index.html#other-hardware-supported-by-black-magic-debug)。
