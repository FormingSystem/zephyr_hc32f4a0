# 第8章\_管理回调

原文：[MCUmgr Callbacks](https://docs.zephyrproject.org/latest/services/device_mgmt/mcumgr_callbacks.html)。读取日期：2026-10-12，`latest`。

## 8.1\_事件通知与操作控制

MCUmgr 的**回调与通知（Callback and Notification）**系统允许应用及模块订阅关心的事件、执行处理，或向调用方返回状态以控制操作是否继续。

例如文件系统管理组 `fs_mgmt` 的**访问钩子（Access Hook）**允许检查请求路径，决定允许或拒绝，也可以改写路径，实现透明文件重定向。

## 8.2\_启用与注册

Kconfig 配置项 [`CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS) 编入注册与通知基础设施，但不会默认开启所有事件。还须启用所需事件的配置，见后文事件表。

回调函数使用类型 [`mgmt_cb`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gae61f705224a859776ee5161dfda5ed7d)，将函数和事件放入结构体 [`mgmt_callback`](https://docs.zephyrproject.org/latest/doxygen/html/structmgmt__callback.html)，再调用函数 [`mgmt_callback_register()`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gaaf698627904995930784c96fb48a1d7b) 注册。多个处理器按注册顺序调用。下面注册命令完成事件 [`MGMT_EVT_OP_CMD_DONE`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gga590788274b4508c6203685d9e9252184adb820d1a8cdea6c74a5a39f096deab12)；它还要求启用 [`CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS)。

回调参数 `event` 表示事件，`prev_status` 是此前处理器的状态；`rc` 与 `group` 用于传回错误，`abort_more` 可终止后续回调；`data` 与 `data_size` 给出本次事件数据及长度。枚举 `mgmt_cb_return` 是回调返回类别，`MGMT_CB_OK` 表示接受：

```c
#include <zephyr/kernel.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>

struct mgmt_callback my_callback;

enum mgmt_cb_return my_function(uint32_t event, enum mgmt_cb_return prev_status,
                                int32_t *rc, uint16_t *group, bool *abort_more,
                                void *data, size_t data_size)
{
    if (event == MGMT_EVT_OP_CMD_DONE) {
        /* This is the event we registered for */
    }

    /* Return OK status code to continue with acceptance to underlying handler */
    return MGMT_CB_OK;
}

int main()
{
    my_callback.callback = my_function;
    my_callback.event_id = MGMT_EVT_OP_CMD_DONE;
    mgmt_callback_register(&my_callback);
}
```

这个事件在管理命令处理并生成输出后发生。**译注：**全局回调对象在注册期间持续存在；多个独立示例各自包含 `main()`，不能全部原样拼进一个应用。

## 8.3\_事件组合的限制

同一个函数可以由多个回调对象共用，同一个事件也可以注册多个函数。某组的 `MGMT_EVT_OP_*_ALL` 表示整组通知，[`MGMT_EVT_OP_ALL`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#ggaab6470007be89e5aab88838456f9561aaf9e289ad5f7e0fd8bec581f67951813a) 表示所有通知。

一次注册中只能合并同一组的事件。例如五个镜像组事件可以合并，但再订阅操作系统组事件时须另行注册，因为组编号是递增数值，组内事件才是**位掩码（Bitmask）**。

下面把命令接收事件 `MGMT_EVT_OP_CMD_RECV`、状态事件 `MGMT_EVT_OP_CMD_STATUS` 与完成事件合并，这是允许的：

```c
my_callback.callback = my_function;
my_callback.event_id = (MGMT_EVT_OP_CMD_RECV |
                        MGMT_EVT_OP_CMD_STATUS |
                        MGMT_EVT_OP_CMD_DONE);
mgmt_callback_register(&my_callback);
```

下面将镜像组的升级开始事件 `MGMT_EVT_OP_IMG_MGMT_DFU_STARTED` 和操作系统组的复位事件 `MGMT_EVT_OP_OS_MGMT_RESET` 混合，**原文明确禁止**，会产生未定义行为：

```c
my_callback.callback = my_function;
my_callback.event_id = (MGMT_EVT_OP_IMG_MGMT_DFU_STARTED |
                        MGMT_EVT_OP_OS_MGMT_RESET);
mgmt_callback_register(&my_callback);
```

## 8.5\_允许、拒绝与两类错误

某些回调必须返回是否允许操作，例如文件访问钩子。第一个返回非成功状态的处理器，其错误会被送回管理客户端，后续返回成功也不会撤销这个错误。

下面示例只在前序处理器没有失败时检查请求。结构体 [`fs_mgmt_file_access`](https://docs.zephyrproject.org/latest/doxygen/html/structfs__mgmt__file__access.html) 保存访问类型和文件名；枚举 `FS_MGMT_FILE_ACCESS_WRITE` 表示写入。它拒绝一切写入并停止后续回调，对指定文件的读取则返回“不存在”错误，但允许其他回调继续得到此前失败状态：

这里 `MGMT_ERR_EACCESSDENIED` 表示拒绝访问，`MGMT_ERR_ENOENT` 表示不存在；`MGMT_CB_ERROR_RC` 是通知框架的通用错误返回类别，具体错误码通过 `*rc` 传出。

```c
#include <zephyr/kernel.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>
#include <string.h>

struct mgmt_callback my_callback;

enum mgmt_cb_return my_function(uint32_t event, enum mgmt_cb_return prev_status,
                                int32_t *rc, uint16_t *group, bool *abort_more,
                                void *data, size_t data_size)
{
    /* Only run this handler if a previous handler has not failed */
    if (event == MGMT_EVT_OP_FS_MGMT_FILE_ACCESS && prev_status == MGMT_CB_OK) {
        struct fs_mgmt_file_access *fs_data = (struct fs_mgmt_file_access *)data;

        /* Check if this is an upload and deny access if it is, otherwise check
         * the path and deny if is matches a name
         */
        if (fs_data->access == FS_MGMT_FILE_ACCESS_WRITE) {
            /* Return an access denied error code to the client and abort calling
             * further handlers
             */
            *abort_more = true;
            *rc = MGMT_ERR_EACCESSDENIED;

            return MGMT_CB_ERROR_RC;
        } else if (strcmp(fs_data->filename, "/lfs1/false_deny.txt") == 0) {
            /* Return a no entry error code to the client, call additional handlers
             * (which will have failed set to true)
             */
            *rc = MGMT_ERR_ENOENT;

            return MGMT_CB_ERROR_RC;
        }
    }

    /* Return OK status code to continue with acceptance to underlying handler */
    return MGMT_CB_OK;
}

int main()
{
    my_callback.callback = my_function;
    my_callback.event_id = MGMT_EVT_OP_FS_MGMT_FILE_ACCESS;
    mgmt_callback_register(&my_callback);
}
```

此回调在收到文件读写命令后、实际访问检查阶段调用，需启用 `CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK`。原例的 `/lfs1/false_deny.txt` 是目标设备文件系统中的挂载路径，不是开发主机或文档仓库的绝对地址；保留它是为了表达具体的访问匹配语义。

可以返回两类错误：

- 通用**简单管理协议（Simple Management Protocol，SMP）**错误：把枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5) 的错误码写到 `*rc`，返回回调类别 [`MGMT_CB_ERROR_RC`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gga1ba636c0efb7a91630ed9743e6fd4d6ca6ca7c4ba7dc1c300489da4a935b7d990)。
- 第2版组错误：把组编号写到 `*group`，组内错误码写到 `*rc`，返回 [`MGMT_CB_ERROR_ERR`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gga1ba636c0efb7a91630ed9743e6fd4d6cad88f720a1d62658c346e8bebfb81d66d)。

> 译注：[`MGMT_ERR_EACCESSDENIED`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5aa43ccd2b916bcf346b202a8e0e5e4bde) 等协议错误码与 `MGMT_CB_ERROR_RC` 等回调类别属于不同枚举。不能只从回调直接返回一个协议错误值代替设置输出参数；也不要混淆 `abort_more`（停止后续通知）和最终允许/拒绝状态。

## 8.6\_在命令中发送通知

处理器调用函数 [`mgmt_callback_notify()`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gaf9308502f8137f7fb80667941cdd46ca)，传入事件编号及可选数据结构。处理回调可修改该数据；不需要数据时，可令数据指针为 `NULL`、长度为0。

下面定义自定义事件组、两个事件和测试数据结构。宏 `MGMT_EVT_GRP_USER_CUSTOM_START` 提供用户事件组起点，宏 `MGMT_DEF_EVT_OP_ID` 与 `MGMT_DEF_EVT_OP_ALL` 构造具体或整组事件标识。示例给通知传入值8，允许继续时在 **简洁二进制对象表示（Concise Binary Object Representation，CBOR）**响应中写入 `output_value = 1234`；返回组错误时通过函数 `smp_add_cmd_err()` 编码。

示例中 `MGMT_EVT_GRP_USER_ONE` 为自定义事件组，`MGMT_EVT_OP_USER_ONE_FIRST` 与 `MGMT_EVT_OP_USER_ONE_SECOND` 为事件，`MGMT_EVT_OP_USER_ONE_ALL` 表示整组；这些是应用自行定义的名称。`MGMT_ERR_EMSGSIZE` 表示编码空间不足等大小错误，`MGMT_ERR_EOK` 表示处理成功。

```c
#include <zephyr/kernel.h>
#include <zcbor_common.h>
#include <zcbor_encode.h>
#include <zephyr/mgmt/mcumgr/smp/smp.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>

#define MGMT_EVT_GRP_USER_ONE MGMT_EVT_GRP_USER_CUSTOM_START

enum user_one_group_events {
    /** Callback on first post, data is test_struct. */
    MGMT_EVT_OP_USER_ONE_FIRST  = MGMT_DEF_EVT_OP_ID(MGMT_EVT_GRP_USER_ONE, 0),

    /** Callback on second post, data is test_struct. */
    MGMT_EVT_OP_USER_ONE_SECOND = MGMT_DEF_EVT_OP_ID(MGMT_EVT_GRP_USER_ONE, 1),

    /** Used to enable all user_one events. */
    MGMT_EVT_OP_USER_ONE_ALL    = MGMT_DEF_EVT_OP_ALL(MGMT_EVT_GRP_USER_ONE),
};

struct test_struct {
    uint8_t some_value;
};

static int test_command(struct mgmt_ctxt *ctxt)
{
    int rc;
    int err_rc;
    uint16_t err_group;
    zcbor_state_t *zse = ctxt->cnbe->zs;
    bool ok;
    struct test_struct test_data = {
        .some_value = 8,
    };

    rc = mgmt_callback_notify(MGMT_EVT_OP_USER_ONE_FIRST, &test_data,
                              sizeof(test_data), &err_rc, &err_group);

    if (rc != MGMT_CB_OK) {
        /* A handler returned a failure code */
        if (rc == MGMT_CB_ERROR_RC) {
            /* The failure code is the RC value */
            return err_rc;
        }

        /* The failure is a group and ID error value */
        ok = smp_add_cmd_err(zse, err_group, (uint16_t)err_rc);
        goto end;
    }

    /* All handlers returned success codes */
    ok = zcbor_tstr_put_lit(zse, "output_value") &&
         zcbor_int32_put(zse, 1234);

end:
    rc = (ok ? MGMT_ERR_EOK : MGMT_ERR_EMSGSIZE);

    return rc;
}
```

若完全不需要读取通知返回状态，原文说可将函数调用结果强转为 `void`。

> 译注：这是旧接口片段。所核对的当前命令上下文使用 `struct smp_streamer` 与 `ctxt->writer->zs`，本例仍用 `struct mgmt_ctxt` 和 `ctxt->cnbe->zs`，应按实际版本改写。忽略函数返回值也不意味着可省略必需错误输出参数：本地 `mgmt_callback_notify()` 会写入 `err_rc` 和 `err_group`，仍须提供有效地址；只有事件数据本身明确允许空指针。

## 8.7\_迁移旧回调接口

Zephyr 3.2或更早回调系统的代码需要迁移到 `mgmt_callback_register()`。除替换注册方式外，还须启用基础通知配置及对应事件选项。

| 旧注册入口 | 新事件与数据 | 必需事件配置 |
| --- | --- | --- |
| `mgmt_evt` | 同名命令接收/状态/完成事件；数据为 [`mgmt_evt_op_cmd_arg`](https://docs.zephyrproject.org/latest/doxygen/html/structmgmt__evt__op__cmd__arg.html)。 | `CONFIG_MCUMGR_SMP_COMMAND_STATUS_HOOKS` |
| `fs_mgmt_register_evt_cb` | `MGMT_EVT_OP_FS_MGMT_FILE_ACCESS`；数据为 `fs_mgmt_file_access`。 | `CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK` |
| `img_mgmt_register_callbacks` | 旧 `dfu_started_cb`、`dfu_stopped_cb`、`dfu_pending_cb`、`dfu_confirmed_cb` 依次对应 DFU_STARTED、DFU_STOPPED、DFU_PENDING、DFU_CONFIRMED 完整事件符号，见上表。这些状态通知不返回操作许可。 | `CONFIG_MCUMGR_GRP_IMG_STATUS_HOOKS` |
| `img_mgmt_set_upload_cb` | `MGMT_EVT_OP_IMG_MGMT_DFU_CHUNK`；数据为 [`img_mgmt_upload_check`](https://docs.zephyrproject.org/latest/doxygen/html/structimg__mgmt__upload__check.html)。 | `CONFIG_MCUMGR_GRP_IMG_UPLOAD_CHECK_HOOK` |
| `os_mgmt_register_reset_evt_cb` | `MGMT_EVT_OP_OS_MGMT_RESET`。 | `CONFIG_MCUMGR_GRP_OS_RESET_HOOK` |

旧文件访问、镜像上传检查和复位回调曾用 `true`/`false` 表示允许/拒绝。原文迁移说明要求改为管理结果码：[`MGMT_ERR_EOK`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a4201fc6fbffd1ca9ae99a2e90a40896f) 表示允许，其他错误表示拒绝并返回给客户端；拒绝访问可用 `MGMT_ERR_EACCESSDENIED`。

> 译注：迁移说明这里概括的是最终管理结果。实际新 `mgmt_cb` 函数仍必须采用第8.5节的返回类别与输出参数协议，而不是直接返回任意 `MGMT_ERR_*` 数值。原代码和说明之间的这一层区别需要保留。

完整**应用程序编程接口（Application Programming Interface，API）**见[Callbacks参考](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html)。本次未注册设备回调、执行文件访问或触发复位。
