# 第14章\_设置管理组

原文：[Settings (Config) Management Group](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_groups/smp_group_3.html)。读取日期：2026-10-12，`latest`。

本章使用**简单管理协议（Simple Management Protocol，SMP）**；载荷采用**简洁二进制对象表示（Concise Binary Object Representation，CBOR）**。下列原文结构记号不是可以直接发送的 **JavaScript对象表示法（JavaScript Object Notation，JSON）**文本：`str` 为字符串，`uint` 为无符号整数，`int` 为整数，`bool` 为布尔值，`bstr` / `byte str` 为字节串，`opt` 表示可选。头字段 `OP` 为操作码，`Group ID` 为组标识，`Command ID` 为命令标识；0/1分别为读请求/响应，2/3分别为写请求/响应。

各命令的第2版组错误以 `err.group` 给出枚举 [`mcumgr_group_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ga81f98b9a0c3810f7d607b783f8e259b5) 所属组、以 `err.rc` 给出非零组内错误码。第1版错误及第2版的通用SMP错误以顶层 `rc` 给出枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5) 的非零错误码；成功时不必携带这些错误字段。后面保留每个命令的原始结构，通用编码规则见[SMP协议规范](P009_SMP协议规范.md)。

## 14.1\_设置管理命令

**设置（Settings）**管理在原MCUmgr仓库中称为**配置管理器（Configuration Manager）**。管理组编号3，定义以下命令：

| 命令编号 | 用途 |
| --- | --- |
| 0 | 读/写设置（Read/Write Setting）。 |
| 1 | 删除设置（Delete Setting）。 |
| 2 | 提交设置（Commit Settings）。 |
| 3 | 加载/保存设置（Load/Save Settings）。 |

Zephyr增加了原始上游不支持的命令与功能，但原客户端的读写功能应仍可工作。

## 14.2\_读取设置

请求头 `OP=0, Group ID=3, Command ID=0`：

```text
{
    (str)"name"         : (str)
    (str,opt)"max_size" : (uint)
}
```

`name` 是要获取的设置名称字符串；可选 `max_size` 是允许返回的数据最大大小。

响应头 `OP=1, Group ID=3, Command ID=0`：

```text
{
    (str)"val"          : (bstr)
    (str,opt)"max_size" : (uint)
}
```

`val` 是返回数据的二进制字节串，无法由该字段说明内部数据类型，客户端必须事先知道其解释方式。当设备支持的最大数据大小小于请求上限时，响应带 `max_size`，给出设备上限。原文把它对应到Kconfig配置项 `CONFIG_MCUMGR_GRP_SETTINGS_NAME_LEN`。

> 译注：本地实现分别使用 `CONFIG_MCUMGR_GRP_SETTINGS_NAME_LEN` 限制名称，使用 `CONFIG_MCUMGR_GRP_SETTINGS_VALUE_LEN` 限制值缓冲区，并以后一项生成响应 `max_size`。原页这里的名称长度符号与实现不符，不能据此调整错误的配置项。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 14.3\_写入设置

此命令更新或设置设备上的条目。请求头 `OP=2, Group ID=3, Command ID=0`：

```text
{
    (str)"name"    : (str)
    (str)"val"     : (bstr)
}
```

`name` 为设置名称，`val` 为待设置的二进制值。响应头 `OP=3, Group ID=3, Command ID=0`，成功载荷为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 14.4\_删除设置

请求头 `OP=2, Group ID=3, Command ID=1`，`name` 指定要删除的设置：

```text
{
    (str)"name"   : (str)
}
```

响应头 `OP=3, Group ID=3, Command ID=1`，成功载荷为空CBOR映射。

失败响应（第2版组错误）：

```text

        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：


字段的出现条件与本章开头相同。

## 14.5\_提交设置

提交命令应用设备上已经设置但尚未生效的全部设置。请求头 `OP=2, Group ID=3, Command ID=2`，载荷为空CBOR映射；响应头 `OP=3, Group ID=3, Command ID=2`，成功载荷也为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 14.6\_加载设置

加载与保存命令在设备的**持久存储（Persistent Storage）**和运行时设置之间读写已序列化条目。加载请求头 `OP=0, Group ID=3, Command ID=3`，载荷为空CBOR映射；响应头 `OP=1, Group ID=3, Command ID=3`，成功载荷也为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 14.7\_保存设置

保存请求头 `OP=2, Group ID=3, Command ID=3`：

```text
{
    (str,opt)"name" : (str)
}
```

可选 `name` 是要保存的设置子树；启用Kconfig配置项 [`CONFIG_SETTINGS_SAVE_SINGLE_SUBTREE_WITHOUT_MODIFICATION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SETTINGS_SAVE_SINGLE_SUBTREE_WITHOUT_MODIFICATION) 时也可指定单项名称。不提供名称则保存全部设置。

响应头 `OP=3, Group ID=3, Command ID=3`，成功载荷为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 14.8\_设置访问回调

**访问回调（Access Callback）**让应用或模块知道设置管理命令何时被使用，并可阻止访问，例如接入安全机制。Kconfig配置项 [`CONFIG_MCUMGR_GRP_SETTINGS_ACCESS_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_SETTINGS_ACCESS_HOOK) 启用此功能，注册事件 [`MGMT_EVT_OP_SETTINGS_MGMT_ACCESS`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api__settings__mgmt.html#gga1711bc9f45a8114a6b0c89db4a40e3dea65c675aa2e807d9977a5ff13a97c75a0)，回调数据类型为 [`settings_mgmt_access`](https://docs.zephyrproject.org/latest/doxygen/html/structsettings__mgmt__access.html)。注册与返回状态规则见[管理回调](P008_管理回调.md)。
