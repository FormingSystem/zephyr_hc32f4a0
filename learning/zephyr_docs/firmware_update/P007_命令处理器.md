# 第7章\_命令处理器

原文：[MCUmgr handlers](https://docs.zephyrproject.org/latest/services/device_mgmt/mcumgr_handlers.html)。读取日期：2026-10-12，`latest`。

## 7.1\_组与命令处理器

MCUmgr 用**组处理器（Group Handler）**组织某个管理领域的功能。每个组由16位标识值寻址，枚举 [`mcumgr_group_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ga81f98b9a0c3810f7d607b783f8e259b5) 给出 Zephyr 中的组及编号。**简单管理协议（Simple Management Protocol，SMP）**的头部带有组编号和8位命令编号，前者选择组，后者选择组内函数。每个唯一组编号只能注册一个组；报文结构见[SMP协议规范](P009_SMP协议规范.md)。

## 7.2\_目录组织

应用或外部模块都可以添加处理器，不要求代码位于上游 Zephyr 树内。通常先创建下列目录结构，其中 `<dir>` 和 `<grp_name>` 为需要替换的相对目录与组名占位符：

```text
<dir>/grp/<grp_name>_mgmt/
├── CMakeLists.txt
├── Kconfig
├── include
├──── <grp_name>_mgmt.h
├──── <grp_name>_mgmt_callbacks.h
├── src
└──── <grp_name>_mgmt.c
```

上游处理器头文件放在 `zephyr/include/zephyr/mgmt/mcumgr/grp/<grp_name>_mgmt`，以便应用全局包含。这里前缀 `zephyr/` 是上游工作区中的源码目录，外部应用应按自己的头文件搜索路径组织。

## 7.3\_命令和错误定义头文件

`<grp_name>_mgmt.h` 提供处理器与应用共同使用的定义，例如命令编号。下面用示例宏 `MGMT_GROUP_ID_EXAMPLE` 指定自定义组，使用枚举 `example_mgmt_err_code_t` 定义组错误：

常量 [`MGMT_GROUP_ID_PERUSER`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gga81f98b9a0c3810f7d607b783f8e259b5af2504389290c7b2a3537f4ebfb730726) 是用户自定义组起点，示例将自己的组编号设为该值。不同组必须分配不同编号，可像上游一样通过一个中央索引头统一管理。

命令常量 `EXAMPLE_MGMT_ID_TEST` 和 `EXAMPLE_MGMT_ID_OTHER` 分别标识测试与其他操作；错误常量 `EXAMPLE_MGMT_ERR_OK`、`EXAMPLE_MGMT_ERR_UNKNOWN`、`EXAMPLE_MGMT_ERR_NOT_WANTED` 和 `EXAMPLE_MGMT_ERR_REJECTED_BY_HOOK` 依次表示成功、未知错误、不接受当前值与被钩子拒绝。

```c
/*
 * Copyright (c) 2023 Nordic Semiconductor ASA
 *
 * SPDX-License-Identifier: Apache-2.0
 */
#ifndef H_EXAMPLE_MGMT_
#define H_EXAMPLE_MGMT_

#ifdef __cplusplus
extern "C" {
#endif

/**
 * Group ID for example management group.
 */
#define MGMT_GROUP_ID_EXAMPLE  MGMT_GROUP_ID_PERUSER

/**
 * Command IDs for example management group.
 */
#define EXAMPLE_MGMT_ID_TEST   0
#define EXAMPLE_MGMT_ID_OTHER  1

/**
 * Command result codes for example management group.
 */
enum example_mgmt_err_code_t {
	/** No error, this is implied if there is no ret value in the response */
	EXAMPLE_MGMT_ERR_OK = 0,

	/** Unknown error occurred. */
	EXAMPLE_MGMT_ERR_UNKNOWN,

	/** The provided value is not wanted at this time. */
	EXAMPLE_MGMT_ERR_NOT_WANTED,

	/** The provided value was rejected by a hook. */
	EXAMPLE_MGMT_ERR_REJECTED_BY_HOOK,
};

#ifdef __cplusplus
}
#endif

#endif
```

示例定义两个命令：test（测试）编号0，other（其他操作）编号1。SMP第2版为每个组定义独立错误码；旧第1版使用公共枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5)。组错误应始终包含值0的成功码和值1的未知错误码，本例还定义值2的“不接受当前值”，以及值3的“被钩子拒绝”。

## 7.4\_事件回调头文件

`<grp_name>_mgmt_callbacks.h` 提供事件及其数据结构，供处理器和应用共享。下面为 other 命令定义一个可注册的事件，使应用或模块可在执行时介入，返回错误并阻止后续动作。

宏 [`MGMT_EVT_GRP_USER_CUSTOM_START`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api.html#gga40ecf8933112abe76d7fedb3dcc7cdbea66361c0b52e996d2feb0a7c84532594d) 是用户自定义事件组起点；宏 `MGMT_DEF_EVT_OP_ID` 组合事件组与组内事件位置，宏 `MGMT_DEF_EVT_OP_ALL` 表示该组全部事件。结构体 `example_mgmt_other_data` 向回调传递用户数值：

示例宏 `MGMT_EVT_GRP_EXAMPLE` 是事件组，`MGMT_EVT_OP_EXAMPLE_OTHER` 标识具体事件，`MGMT_EVT_OP_EXAMPLE_MGMT_ALL` 标识该组全部事件。

```c
/*
 * Copyright (c) 2023 Nordic Semiconductor ASA
 *
 * SPDX-License-Identifier: Apache-2.0
 */
#ifndef H_MCUMGR_EXAMPLE_MGMT_CALLBACKS_
#define H_MCUMGR_EXAMPLE_MGMT_CALLBACKS_
#include <stdint.h>
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>

#ifdef __cplusplus
extern "C" {
#endif

/* This is the event ID for the example group */
#define MGMT_EVT_GRP_EXAMPLE MGMT_EVT_GRP_USER_CUSTOM_START

/* MGMT event opcodes for example management group */
enum example_mgmt_group_events {
	/* Callback when the other command is received, data is example_mgmt_other_data */
	MGMT_EVT_OP_EXAMPLE_OTHER = MGMT_DEF_EVT_OP_ID(MGMT_EVT_GRP_EXAMPLE, 0),

	/* Used to enable all smp_group events */
	MGMT_EVT_OP_EXAMPLE_MGMT_ALL  = MGMT_DEF_EVT_OP_ALL(MGMT_EVT_GRP_EXAMPLE),
};

/* Structure provided in the #MGMT_EVT_OP_EXAMPLE_OTHER notification callback */
struct example_mgmt_other_data {
	/* Contains the user supplied value */
	uint32_t user_value;
};

#ifdef __cplusplus
}
#endif

#endif
```

事件组编号同样须唯一，可用统一索引头分配。**译注：**管理命令组编号和通知事件组编号属于不同的编号体系，不能只因两者都叫 group 就相互替用。

## 7.5\_处理命令与注册组

`<grp_name>_mgmt.c` 接收命令、生成响应并把组注册到 MCUmgr。原文把最后一步写成“注册传输”，但下面实际注册的是管理组，底层传输是另外的对象。

原例使用 zcbor 库处理 **简洁二进制对象表示（Concise Binary Object Representation，CBOR）**数据。结构体 `smp_streamer` 提供读写上下文；类型 `zcbor_state_t` 表示编解码状态。宏 `ZCBOR_MAP_DECODE_KEY_DECODER` 描述字段与解码函数，函数 `zcbor_map_decode_bulk()` 批量解析，函数 `zcbor_map_decode_bulk_key_found()` 检查必填字段是否出现。

两个处理函数的行为如下：

- test 接受读取请求，必须带无符号字段 `uint_key` 和非空字符串字段 `string_key`；数值大于50时产生组错误，否则响应 `return_int = 4691`。
- other 接受写请求，`user_value` 为可选字段，缺省0。启用对应钩子后先通知应用；应用可拒绝操作，否则返回字符串字段 `return_string`，内容为原例占位文本。

函数 `smp_add_cmd_err()` 将组错误编码进响应；通用错误常量 `MGMT_ERR_EINVAL` 表示参数无效，`MGMT_ERR_EOK` 表示处理成功，`MGMT_ERR_EMSGSIZE` 表示响应编码容量不足等导致的大小错误。宏 `LOG_MODULE_REGISTER` 注册日志模块，宏 `LOG_DBG` 输出调试日志，宏 `ARRAY_SIZE` 取得数组元素数量。

启用 Kconfig 配置项 `CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS` 后可使用通知系统，示例配置项 `CONFIG_MCUMGR_GRP_EXAMPLE_OTHER_HOOK` 决定是否启用 other 钩子。宏 `MCUMGR_HANDLER_DEFINE` 注册初始化入口，初始化函数调用 `mgmt_register_group()` 注册组。示例日志级别由 `CONFIG_MCUMGR_GRP_EXAMPLE_LOG_LEVEL` 控制；回调类别 `MGMT_CB_OK` 表示接受，`MGMT_CB_ERROR_RC` 表示通过输出参数返回通用错误。兼容开关 `CONFIG_MCUMGR_SMP_SUPPORT_ORIGINAL_PROTOCOL` 启用旧版错误转换，其中 `MGMT_ERR_ENOENT` 表示不存在，`MGMT_ERR_EBADSTATE` 表示状态不正确，`MGMT_ERR_EUNKNOWN` 表示未知错误。完整原例为：

```c
/*
 * Copyright (c) 2023 Nordic Semiconductor ASA
 *
 * SPDX-License-Identifier: Apache-2.0
 */
#include <zephyr/kernel.h>
#include <zephyr/mgmt/mcumgr/mgmt/mgmt.h>
#include <zephyr/mgmt/mcumgr/smp/smp.h>
#include <zephyr/mgmt/mcumgr/mgmt/handlers.h>
/* The below should be updated with the real name of the file */
#include <example_mgmt.h>
#include <zephyr/logging/log.h>
#include <assert.h>
#include <limits.h>
#include <string.h>
#include <stdio.h>
#include <zcbor_common.h>
#include <zcbor_decode.h>
#include <zcbor_encode.h>
#include <mgmt/mcumgr/util/zcbor_bulk.h>

#if defined(CONFIG_MCUMGR_MGMT_NOTIFICATION_HOOKS)
#include <zephyr/mgmt/mcumgr/mgmt/callbacks.h>
#if defined(CONFIG_MCUMGR_GRP_EXAMPLE_OTHER_HOOK)
/* The below should be updated with the real name of the file */
#include <example_mgmt_callbacks.h>
#endif
#endif

LOG_MODULE_REGISTER(mcumgr_example_grp, CONFIG_MCUMGR_GRP_EXAMPLE_LOG_LEVEL);
/* Example function with "read" command support, requires both parameters are supplied */
static int example_mgmt_test(struct smp_streamer *ctxt)
{
	uint32_t uint_value = 0;
	zcbor_state_t *zse = ctxt->writer->zs;
	zcbor_state_t *zsd = ctxt->reader->zs;
	bool ok;
	struct zcbor_string string_value = { 0 };
	size_t decoded;
	struct zcbor_map_decode_key_val example_test_decode[] = {
		ZCBOR_MAP_DECODE_KEY_DECODER("uint_key", zcbor_uint32_decode, &uint_value),
		ZCBOR_MAP_DECODE_KEY_DECODER("string_key", zcbor_tstr_decode, &string_value),
	};

	LOG_DBG("Example test function called");

	ok = zcbor_map_decode_bulk(zsd, example_test_decode, ARRAY_SIZE(example_test_decode),
				   &decoded) == 0;
	/* Check that both parameters were supplied and that the value of "string_key" is not
	 * empty
	 */
	if (!ok || string_value.len == 0 || !zcbor_map_decode_bulk_key_found(
			   example_test_decode, ARRAY_SIZE(example_test_decode), "uint_key")) {
		return MGMT_ERR_EINVAL;
	}

	/* If the value of "uint_key" is over 50, return an error of "not wanted" */
	if (uint_value > 50) {
		ok = smp_add_cmd_err(zse, MGMT_GROUP_ID_EXAMPLE, EXAMPLE_MGMT_ERR_NOT_WANTED);
		goto end;
	}

	/* Otherwise, return an integer value of 4691 */
	ok = zcbor_tstr_put_lit(zse, "return_int") &&
	     zcbor_int32_put(zse, 4691);

end:
	/* If "ok" is false, then there was an error processing the output cbor message, which
	 * likely indicates a lack of available memory
	 */
	return (ok ? MGMT_ERR_EOK : MGMT_ERR_EMSGSIZE);
}

/* Example function with "write" command support */
static int example_mgmt_other(struct smp_streamer *ctxt)
{
	uint32_t user_value = 0;
	zcbor_state_t *zse = ctxt->writer->zs;
	zcbor_state_t *zsd = ctxt->reader->zs;
	bool ok;
	size_t decoded;
	struct zcbor_map_decode_key_val example_other_decode[] = {
		ZCBOR_MAP_DECODE_KEY_DECODER("user_value", zcbor_uint32_decode, &user_value),
	};

#if defined(CONFIG_MCUMGR_GRP_EXAMPLE_OTHER_HOOK)
	struct example_mgmt_other_data other_data;
	enum mgmt_cb_return status;
	int32_t err_rc;
	uint16_t err_group;
#endif

	LOG_DBG("Example other function called");

	ok = zcbor_map_decode_bulk(zsd, example_other_decode, ARRAY_SIZE(example_other_decode),
				   &decoded) == 0;

	/* The supplied value is optional, therefore do not return an error if it was not
	 * provided
	 */
	if (!ok) {
		return MGMT_ERR_EINVAL;
	}

#if defined(CONFIG_MCUMGR_GRP_EXAMPLE_OTHER_HOOK)
	/* Send request to application to check what to do */
	other_data.user_value = user_value;
	status = mgmt_callback_notify(MGMT_EVT_OP_EXAMPLE_OTHER, &other_data, sizeof(other_data),
				      &err_rc, &err_group);
	if (status != MGMT_CB_OK) {
		/* If a callback returned an RC error, exit out, if it returned a group error
		 * code, add the error code to the response and return to the calling function to
		 * have it sent back to the client
		 */
		if (status == MGMT_CB_ERROR_RC) {
			return err_rc;
		}

		ok = smp_add_cmd_err(zse, err_group, (uint16_t)err_rc);
		goto end;
	}
#endif
	/* Return some dummy data to the client */
	ok = zcbor_tstr_put_lit(zse, "return_string") &&
	     zcbor_tstr_put_lit(zse, "some dummy data!");

#if defined(CONFIG_MCUMGR_GRP_EXAMPLE_OTHER_HOOK)
end:
#endif
	/* If "ok" is false, then there was an error processing the output cbor message, which
	 * likely indicates a lack of available memory
	 */
	return (ok ? MGMT_ERR_EOK : MGMT_ERR_EMSGSIZE);
}

#ifdef CONFIG_MCUMGR_SMP_SUPPORT_ORIGINAL_PROTOCOL
/* This is a lookup function that converts from SMP version 2 group error codes to legacy
 * MCUmgr error codes, it is only included if support for the original protocol is enabled.
 * Note that in SMP version 2, MCUmgr error codes can still be returned, but are to be used
 * only for general SMP/MCUmgr errors. The success/OK error code is not used in translation
 * functions as it is automatically handled by the base SMP code.
 */
static int example_mgmt_translate_error_code(uint16_t err)
{
	int rc;

	switch (err) {
	case EXAMPLE_MGMT_ERR_NOT_WANTED:
		rc = MGMT_ERR_ENOENT;
		break;

	case EXAMPLE_MGMT_ERR_REJECTED_BY_HOOK:
		rc = MGMT_ERR_EBADSTATE;
		break;

	case EXAMPLE_MGMT_ERR_UNKNOWN:
	default:
		rc = MGMT_ERR_EUNKNOWN;
	}

	return rc;
}
#endif

static const struct mgmt_handler example_mgmt_handlers[] = {
	[EXAMPLE_MGMT_ID_TEST] = {
		.mh_read = example_mgmt_test,
		.mh_write = NULL,
	},
	[EXAMPLE_MGMT_ID_OTHER] = {
		.mh_read = NULL,
		.mh_write = example_mgmt_other,
	},
};

static struct mgmt_group example_mgmt_group = {
	.mg_handlers = example_mgmt_handlers,
	.mg_handlers_count = ARRAY_SIZE(example_mgmt_handlers),
	.mg_group_id = MGMT_GROUP_ID_EXAMPLE,
#ifdef CONFIG_MCUMGR_SMP_SUPPORT_ORIGINAL_PROTOCOL
	.mg_translate_error = example_mgmt_translate_error_code,
#endif
};

static void example_mgmt_register_group(void)
{
	/* This function is called during system init before main() is invoked, if the
	 * handler needs to set anything up before it can be used, it should do it here.
	 * This register the group so that clients can call the function handlers.
	 */
	mgmt_register_group(&example_mgmt_group);
}

MCUMGR_HANDLER_DEFINE(example_mgmt, example_mgmt_register_group);
```

若启用配置项 `CONFIG_MCUMGR_SMP_SUPPORT_ORIGINAL_PROTOCOL`，错误转换函数会把第2版组错误映射为旧版通用错误；成功码由基础SMP代码处理，不放入该转换函数。第2版仍可返回通用错误，但应用于SMP/MCUmgr自身的问题。

> 译注：当组错误已成功编码到响应中时，处理函数返回 `MGMT_ERR_EOK` 表示“响应构造成功”，不表示客户端请求的业务操作成功。客户端仍应检查协议错误字段。`example_mgmt.h` 等示例文件须实际建立并加入搜索路径，示例专用Kconfig符号也不是启用任意上游固件后就自动存在。

应用引用自定义事件时，必须同时包含 Zephyr 基础回调头和自定义回调头；基础头只包含树内处理器的事件头，不会自动发现树外组。通知机制详见[管理回调](P008_管理回调.md)。

## 7.6\_Kconfig选项

Kconfig 文件让使用者启用或调整组功能。原例以 `MCUMGR_GRP_EXAMPLE_` 为公共前缀，功能相关选项尽量共用前缀后的词干。选项 `MCUMGR_GRP_EXAMPLE_APP` 控制应用级示例，`MCUMGR_GRP_EXAMPLE_OTHER_HOOK` 依赖通知系统，日志模板生成对应的日志级别设置。`MCUMGR` 启用管理子系统，`MCUMGR_SMP_CBOR_MIN_DECODING_LEVEL_2` 要求至少两层CBOR解码深度，`MCUMGR_MGMT_NOTIFICATION_HOOKS` 提供通知基础设施；这些Kconfig名称在生成配置头中带 `CONFIG_` 前缀：

```kconfig
# Copyright Nordic Semiconductor ASA 2023. All rights reserved.
# SPDX-License-Identifier: Apache-2.0
# The Kconfig file is dedicated to example management group of
# of MCUmgr subsystem and provides Kconfig options to configure
# group commands behaviour and other aspects.
#
# Options defined in this file should be prefixed:
#  MCUMGR_GRP_EXAMPLE_ -- general group options;
#
# When adding Kconfig options, that control the same feature,
# try to group them together by the same stem after prefix.
if MCUMGR

menuconfig MCUMGR_GRP_EXAMPLE_APP
	bool "MCUmgr handlers for example management (app)"
	select MCUMGR_SMP_CBOR_MIN_DECODING_LEVEL_2
	default y
	help
	  Enables MCUmgr handlers for example management. This demonstrates the
	  file at application-level.

if MCUMGR_GRP_EXAMPLE_APP
config MCUMGR_GRP_EXAMPLE_OTHER_HOOK
	bool "Other hook"
	depends on MCUMGR_MGMT_NOTIFICATION_HOOKS
	help
	  Allows applications to receive callback when the "other" example
	  management function is called

module = MCUMGR_GRP_EXAMPLE
module-str = mcumgr_grp_example
source "subsys/logging/Kconfig.template.log_config"

endif

endif

source "Kconfig.zephyr"
```

> 译注：这一段包含应用顶层所用的 `source "Kconfig.zephyr"`。如果把组文件再嵌入另一个已经包含它的顶层 Kconfig，就应按实际层级组织，避免重复包含。后文模块版本的符号与本段应用版本也不完全相同，须使用相应版本的定义。

## 7.7\_CMake编译入口

`CMakeLists.txt` 决定哪些源文件参与编译、增加哪些包含目录，以及配置条件。模块方式使用示例配置项 `CONFIG_MCUMGR_GRP_EXAMPLE_MODULE`；CMake函数 `zephyr_library()` 定义模块库，`zephyr_library_sources()` 添加源文件，`zephyr_include_directories()` 添加头文件目录：

```cmake
# Copyright (c) 2023 Nordic Semiconductor ASA
# SPDX-License-Identifier: Apache-2.0

if(CONFIG_MCUMGR_GRP_EXAMPLE_MODULE)
  zephyr_library()
  # The below should be updated with the real name of the file
  zephyr_library_sources(src/example_mgmt.c)
  zephyr_include_directories(include)
endif()
```

应用方式则把文件通过 CMake 命令 `target_sources()` 加入应用目标 `app`：

```cmake
if(CONFIG_MCUMGR_GRP_EXAMPLE_APP)
  target_sources(app PRIVATE example_as_module/src/example_mgmt.c)
  zephyr_include_directories(example_as_module/include)
endif()
```

> 译注：模块分支的 `_MODULE` 选项与前面Kconfig的 `_APP` 选项不是同一个符号；要采用相应示例的完整配套配置。`example_as_module/` 是原应用示例目录，不能假定读者项目中已经存在。

## 7.8\_由应用引入

应用的 CMake 文件加入如下子目录：

```cmake
add_subdirectory(mcumgr/grp/<grp_name>)
```

应用目录中的 Kconfig 文件（不存在则创建）通过 `rsource` 相对当前文件引入组配置，再加载 Zephyr 顶层配置：

```kconfig
rsource "mcumgr/grp/<grp_name>/Kconfig"

# Include Zephyr's Kconfig
source "Kconfig.zephyr"
```

> 译注：前面目录树用了 `<grp_name>_mgmt`，这里的占位路径写成 `<grp_name>`。替换占位符时应统一成真实目录，不应保留不匹配路径。该文件怎样接入构建，以应用和模块章节所示的完整层级为准；不重复添加已经存在的顶层包含。

## 7.9\_由外部模块引入

[Zephyr模块](../modules/P001_模块与外部项目.md)可让多个应用共用处理器，避免每个应用复制源码。模块根下的 `zephyr/module.yml` 用 **YAML配置格式（YAML Ain’t Markup Language，YAML）**描述构建入口：

```yaml
build:
  kconfig: Kconfig
  cmake: .
```

其中 `build.kconfig` 选择模块根的 Kconfig，`build.cmake` 中的 `.` 表示模块根。根 CMake 文件再加入组目录：

```cmake
add_subdirectory(mcumgr/grp/<grp_name>)
```

根 Kconfig 文件引入组配置：

```kconfig
rsource "mcumgr/grp/<grp_name>/Kconfig"
```

模块必须先按[模块发现与接入说明](../modules/P001_模块与外部项目.md)被工程识别，不能只复制一个 `module.yml` 就假定已经加载。完整演示位于官方 [`tests/subsys/mgmt/mcumgr/handler_demo/`](https://github.com/zephyrproject-rtos/zephyr/blob/main/tests/subsys/mgmt/mcumgr/handler_demo/)，同时包含应用级和模块级配置，可作为自定义处理器的起点。本次未创建固件处理器、构建或执行管理命令。
