# 第2章\_设备固件升级

原文：[Device Firmware Upgrade](https://docs.zephyrproject.org/latest/services/device_mgmt/dfu.html)。读取日期：2026-10-12，`latest`。

## 2.1\_固件升级子系统的边界

**设备固件升级（Device Firmware Upgrade，DFU）**子系统提供在运行时更新 Zephyr 应用镜像所需的框架，目前由两个模块构成：

- [`subsys/dfu/boot/`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/dfu/boot/)：与**引导加载程序（Bootloader）**连接的接口代码。
- [`subsys/dfu/img_util/`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/dfu/img_util/)：镜像管理代码。

DFU 负责镜像管理，不负责把镜像发到目标设备所需的传输或管理协议。相关协议与框架见[设备管理](P001_设备管理概览.md)。

<a id="flash-img-api"></a>

## 2.2\_Flash镜像写入接口

**闪存镜像（Flash Image）**接口在[流式Flash写入](../storage/P004_流式Flash写入.md)之上提供抽象，让应用更方便地将固件数据块写入闪存。完整的**应用程序编程接口（Application Programming Interface，API）**见 [Flash image API](https://docs.zephyrproject.org/latest/doxygen/html/group__flash__img__api.html)。

<a id="mcuboot-api"></a>

## 2.3\_MCUboot镜像控制

MCUboot 接口用于取得应用镜像版本和引导状态，还可选择下一次启动使用的应用镜像及启动类型。完整函数说明见 [MCUboot镜像控制接口](../boot_control_reference/P001_MCUboot镜像控制接口.md)。

<a id="mcuboot"></a>

## 2.4\_与MCUboot配合

Zephyr 直接兼容开源、跨**实时操作系统（Real-Time Operating System，RTOS）**的 [MCUboot](https://mcuboot.com/) 引导加载程序，了解它要求的镜像格式，并为以它引导的应用提供 DFU 支持。原文源码入口为 [MCUboot GitHub项目](https://github.com/runtimeco/mcuboot)。

使用时需要完成以下事项：

1. 定义 MCUboot 所需闪存分区，参阅 [Flash分区映射](../storage/P001_Flash分区映射.md)。
2. 把应用所在分区选为设备树代码分区。下面用节点标签 `slot0_partition` 作为主槽，属性 `zephyr,code-partition` 指向它：

```dts
/ {
   chosen {
      zephyr,code-partition = &slot0_partition;
   };
};
```

3. 在应用 `.conf` 文件启用 Kconfig 配置项 [`CONFIG_BOOTLOADER_MCUBOOT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_BOOTLOADER_MCUBOOT)，使 Zephyr 按兼容 MCUboot 的方式构建。
4. 另行构建并将 MCUboot 本体烧录到设备。
5. 避免**整片擦除（Mass Erase）**破坏引导程序，并把 Zephyr 应用写到正确偏移。原文用“紧接引导程序之后”概括这一位置。

> 译注：实际偏移来自板卡分区布局、镜像头和对齐要求，不能把这句概括换算成任意板都通用的地址。设备树中的 `/` 是根节点语法，不是文件系统绝对路径。启用兼容配置不等于已经下载引导程序、完成签名或具备安全升级流程。

更详细步骤见 [MCUboot与Zephyr配合说明](https://docs.mcuboot.com/readme-zephyr)。本次只翻译文档，没有调整分区、擦除、烧录或重启设备。
