# 第12章\_镜像管理组

原文：[Application/software image management group](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_groups/smp_group_1.html)。读取日期：2026-10-12，`latest`。

本章使用**简单管理协议（Simple Management Protocol，SMP）**；载荷采用**简洁二进制对象表示（Concise Binary Object Representation，CBOR）**。下列原文结构记号不是可以直接发送的 **JavaScript对象表示法（JavaScript Object Notation，JSON）**文本：`str` 为字符串，`uint` 为无符号整数，`int` 为整数，`bool` 为布尔值，`bstr` / `byte str` 为字节串，`opt` 表示可选。头字段 `OP` 为操作码，`Group ID` 为组标识，`Command ID` 为命令标识；0/1分别为读请求/响应，2/3分别为写请求/响应。

各命令的第2版组错误以 `err.group` 给出枚举 [`mcumgr_group_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ga81f98b9a0c3810f7d607b783f8e259b5) 所属组、以 `err.rc` 给出非零组内错误码。第1版错误及第2版的通用SMP错误以顶层 `rc` 给出枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5) 的非零错误码；成功时不必携带这些错误字段。后面保留每个命令的原始结构，通用编码规则见[SMP协议规范](P009_SMP协议规范.md)。

## 12.1\_命令与镜像槽

应用/软件镜像管理组编号1，定义下列命令：

| 命令编号 | 用途 |
| --- | --- |
| 0 | 镜像状态（State of Images）。 |
| 1 | 镜像上传（Image Upload）。 |
| 2 | File，文件命令；保留，Zephyr不支持。 |
| 3 | Corelist，内核转储列表；保留，Zephyr不支持。 |
| 4 | Coreload，内核转储加载；保留，Zephyr不支持。 |
| 5 | 镜像擦除（Image Erase）。 |
| 6 | 槽信息（Slot Info）。 |

**镜像（Image）**与**槽（Slot）**沿用MCUboot术语。一个可升级应用对应一对槽：应用通常从**主槽（Primary Slot）**运行，更新上传到**次槽（Secondary Slot）**，MCUboot在启动时负责交换。具体行为仍取决于引导模式。

Zephyr的**设备树源码（Devicetree Source，DTS）**用 `slot0_partition` / `slot1_partition` 等标签标识 `fixed-partitions` 或 `zephyr,mapped-partition`，但这些分区名称又叫 `image-0` / `image-1`，容易与逻辑镜像编号混淆。原页写明“当前至多支持两个镜像”，并给出以下映射：

| 原表镜像序号 | 槽标签 | 槽名称 |
| --- | --- | --- |
| 1 | `slot0_partition`、`slot1_partition` | `image-0`、`image-1` |
| 2 | `slot2_partition`、`slot3_partition` | `image-2`、`image-3` |

> 译注：此表的1、2是原文排列序号；协议中的默认 `image` 值为0，不能把表的显示序号直接当作协议参数。支持数量和槽分配应按实际固件配置核对；本表不表示任意Zephyr版本与引导后端的固定上限。

## 12.2\_读取镜像状态

请求头 `OP=0, Group ID=1, Command ID=0`，发送空CBOR映射；响应头 `OP=1, Group ID=1, Command ID=0`。只列出可识别的有效镜像，无效镜像直接跳过。

只有单镜像时可省略 `image`，多镜像时必须提供它以标识归属。成功响应为：

```text
{
    (str)"images" : [
        {
            (str,opt)"image"        : (uint)
            (str)"slot"             : (uint)
            (str)"version"          : (str)
            (str,opt*)"hash"        : (byte str)
            (str,opt)"bootable"     : (bool)
            (str,opt)"pending"      : (bool)
            (str,opt)"confirmed"    : (bool)
            (str,opt)"active"       : (bool)
            (str,opt)"permanent"    : (bool)
        }
        ...
    ]
    (str,opt)"splitStatus" : (int)
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
    (str,opt)"rsn"  : (str)
}
```

字段的出现条件与本章开头相同。 可选字符串 `rsn` 进一步说明失败原因，尤其适用于未知错误常量 [`MGMT_ERR_EUNKNOWN`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a68adbc4d77eaae550973b5169d1c14be)。

| 字段 | 含义与出现条件 |
| --- | --- |
| `image` | 半可选的逻辑镜像编号；单镜像可省略，多镜像必需。 |
| `slot` | 该镜像内部的槽号：主槽0、次槽1；次槽用于双区设备固件升级（Device Firmware Upgrade，DFU）。 |
| `version` | 由imgtool设置的镜像版本字符串。 |
| `hash` | 镜像头与主体的 **256位安全散列算法（Secure Hash Algorithm 256-bit，SHA-256）**摘要。来自MCUboot **类型—长度—值（Type-Length-Value，TLV）**区域中的签名验证摘要，不等于整个文件的摘要。仅在MCUboot串口恢复且只有一对槽时，可通过关闭Kconfig配置项 `CONFIG_BOOT_SERIAL_IMG_GRP_HASH` 省略；应用内MCUmgr必须支持发送该摘要。 |
| `bootable` | 已设可启动标志时为真；为假可省略。 |
| `pending` | 已安排下次交换时为真；为假可省略。 |
| `confirmed` | 已确认时为真；为假可省略。 |
| `active` | 当前运行的应用为真；为假可省略。 |
| `permanent` | 下次启动后将保持在主槽时为真；为假可省略。 |
| `splitStatus` | 拆分镜像的加载程序与应用部分是否兼容；Zephyr未使用。 |

摘要类型标识为 `IMAGE_TLV_SHA256`。进一步参阅MCUboot的[镜像槽说明](https://docs.mcuboot.com/design.html#image-slots)和[镜像格式](https://docs.mcuboot.com/design.html#image-format)。

## 12.3\_设置镜像状态

请求头 `OP=2, Group ID=1, Command ID=0`，载荷为：

```text
{
    (str,opt)"hash"     : (byte str)
    (str)"confirm"      : (bool)
}
```

`confirm` 为假或未提供时，把 `hash` 对应镜像安排为测试镜像，不标为永久；原文说明硬复位后会恢复先前应用至主槽。`confirm` 为真时可省略 `hash`，此时默认确认当前运行应用。响应结构与读取镜像状态相同；写操作响应使用 `OP=3`，组和命令编号不变。

> 译注：回退依赖引导加载程序的交换/回退模式与确认流程，不能把上述行为套用到无回退的覆盖模式。结构示意把 `confirm` 标成非可选，而文字也说明了省略时的行为，两者在此一并保留。

## 12.4\_分块上传镜像

每个数据块发送一次请求，直到完整镜像上传结束。请求头 `OP=2, Group ID=1, Command ID=1`：

```text
{
    (str,opt)"image"    : (uint)
    (str,opt)"len"      : (uint)
    (str)"off"          : (uint)
    (str,opt)"sha"      : (byte str)
    (str)"data"         : (byte str)
    (str,opt)"upgrade"  : (bool)
}
```

| 字段 | 含义与条件 |
| --- | --- |
| `image` | 可选逻辑镜像编号，默认0；只应在 `off=0` 时发送。 |
| `len` | 镜像总长度；其他块可省略，但 `off=0` 时必须提供。 |
| `off` | 本请求携带的数据块在镜像中的偏移。 |
| `sha` | **整个上传镜像文件**的完整SHA-256摘要，用于会话识别、续传与上传验证；只应在 `off=0` 时发送。没有摘要时必须省略，对应续传和验证能力也不可用。 |
| `data` | 写入指定偏移的镜像字节。其自身包含长度信息，因此没有独立块长度字段。 |
| `upgrade` | 可选标志，要求只接受升级；新版本不高于现有版本时拒绝。默认比较主版本、次版本、修订号 `x.y.z`；Kconfig配置项 [`CONFIG_MCUMGR_GRP_IMG_VERSION_CMP_USE_BUILD_NUMBER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_IMG_VERSION_CMP_USE_BUILD_NUMBER) 还启用构建号比较。只应在 `off=0` 时发送。 |

MCUmgr用 `sha` 标记正在进行的会话。收到 `off=0` 请求后，若摘要与保存的会话匹配，就返回客户端应继续上传的偏移。若数据以流方式提供等原因使摘要不可用，不应伪造摘要；对应验证和续传功能不可用。

**原文注意：**其他传输或MCUmgr之外启动了上传、设备重启、报文丢失等情况，都可能导致服务器返回 `off=0`。客户端此时必须重新发送最初首包里的所有必需和可选字段，重建上传状态；漏发这些字段会导致无法继续。

## 12.5\_上传响应

响应头 `OP=3, Group ID=1, Command ID=1`，成功载荷为：

```text
{
    (str,opt)"off"    : (uint)
    (str,opt)"match"  : (bool)
}
```

原文把 `off` 描述为“最后成功写入字节的偏移”；它用来指示继续上传的位置。可选 `match` 表示上传内容是否匹配给定SHA-256摘要，仅启用Kconfig配置项 [`CONFIG_IMG_ENABLE_IMAGE_CHECK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_IMG_ENABLE_IMAGE_CHECK) 时在最后响应中发送。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
    (str,opt)"rsn"  : (str)
}
```

字段的出现条件与本章开头相同。 可选字符串 `rsn` 进一步说明失败原因，尤其适用于未知错误常量 [`MGMT_ERR_EUNKNOWN`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a68adbc4d77eaae550973b5169d1c14be)。

只有成功处理请求的响应才带 `off`。原文还指出 `rc` 为负时可能不带该字段。

> 译注：客户端应使用服务器给出的续传偏移，不要自行把它当作末字节索引再加一；错误判断也不能仅依赖 `rc<0`，SMP通用错误和组错误的非零值都必须检查。

## 12.6\_擦除镜像

命令擦除目标槽。它是**同步命令（Synchronous Command）**，完成前不会给请求方响应，可能耗时较长。

请求头 `OP=2, Group ID=1, Command ID=5`：

```text
{
    (str,opt)"slot"     : (uint)
}
```

`slot` 可省略，默认1。响应头 `OP=3, Group ID=1, Command ID=5`，成功发送空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
    (str,opt)"rsn"  : (str)
}
```

字段的出现条件与本章开头相同。 可选字符串 `rsn` 进一步说明失败原因，尤其适用于未知错误常量 [`MGMT_ERR_EUNKNOWN`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a68adbc4d77eaae550973b5169d1c14be)。

设备可能返回状态不允许错误常量 [`MGMT_ERR_EBADSTATE`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a4385d9d027ea3ddd10ae9467ed8ca787)，表示次镜像已被标记为下次启动使用，不能擦除。

## 12.7\_查询槽信息

Kconfig配置项 [`CONFIG_MCUMGR_GRP_IMG_SLOT_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_IMG_SLOT_INFO) 启用查询可用槽的功能。请求头 `OP=0, Group ID=1, Command ID=6`，载荷为空CBOR映射；响应头 `OP=1, Group ID=1, Command ID=6`：

```text
{
    (str)"images" : [
        {
            (str)"image"                        : (uint)
            (str)"slots" : [
                {
                    (str)"slot"                 : (uint)
                    (str)"size"                 : (uint)
                    (str,opt)"upload_image_id"  : (uint)
                }
                ...
            ]
            (str,opt)"max_image_size"           : (uint)
        }
        ...
    ]
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

| 字段 | 含义与条件 |
| --- | --- |
| `image` | 正在枚举的镜像编号。 |
| `slot` | 该镜像内部槽号0或1，**不是物理槽序号**。 |
| `size` | 槽大小。 |
| `upload_image_id` | 外部工具可用于向此槽上传的镜像标识；仅启用Kconfig配置项 [`CONFIG_MCUMGR_GRP_IMG_DIRECT_UPLOAD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_IMG_DIRECT_UPLOAD) 后出现。 |
| `max_image_size` | 此逻辑镜像允许上传的最大应用大小；仅启用Kconfig配置项 [`CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_SYSBUILD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_SYSBUILD) 或 [`CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_BOOTLOADER_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_IMG_TOO_LARGE_BOOTLOADER_INFO) 后出现。 |
