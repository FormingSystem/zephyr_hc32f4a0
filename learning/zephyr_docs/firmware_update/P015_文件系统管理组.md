# 第15章\_文件系统管理组

原文：[File system management](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_groups/smp_group_8.html)。读取日期：2026-10-12，`latest`。

本章使用**简单管理协议（Simple Management Protocol，SMP）**；载荷采用**简洁二进制对象表示（Concise Binary Object Representation，CBOR）**。下列原文结构记号不是可以直接发送的 **JavaScript对象表示法（JavaScript Object Notation，JSON）**文本：`str` 为字符串，`uint` 为无符号整数，`int` 为整数，`bool` 为布尔值，`bstr` / `byte str` 为字节串，`opt` 表示可选。头字段 `OP` 为操作码，`Group ID` 为组标识，`Command ID` 为命令标识；0/1分别为读请求/响应，2/3分别为写请求/响应。

各命令的第2版组错误以 `err.group` 给出枚举 [`mcumgr_group_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ga81f98b9a0c3810f7d607b783f8e259b5) 所属组、以 `err.rc` 给出非零组内错误码。第1版错误及第2版的通用SMP错误以顶层 `rc` 给出枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5) 的非零错误码；成功时不必携带这些错误字段。后面保留每个命令的原始结构，通用编码规则见[SMP协议规范](P009_SMP协议规范.md)。

## 15.1\_文件系统管理与访问控制

**文件系统（File System）**管理组编号8，用于向设备上传文件或从设备下载文件：

| 命令编号 | 用途 |
| --- | --- |
| 0 | 文件下载/上传。 |
| 1 | 文件状态。 |
| 2 | 文件散列/校验和（Hash/Checksum）。 |
| 3 | 支持的文件散列/校验和类型。 |
| 4 | 关闭文件。 |

默认无条件允许文件上传和下载。启用Kconfig配置项 [`CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_FS_FILE_ACCESS_HOOK) 后，应用可注册事件 [`MGMT_EVT_OP_FS_MGMT_FILE_ACCESS`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__callback__api__fs__mgmt.html#gga324223c20cbefe3400272e2789082c79a0475953c86b97afa8e4ed30da3f736d3)，允许或拒绝某个文件的读写，也可改写客户端给出的路径；见[管理回调](P008_管理回调.md)。

本章协议中的 `name` 是**目标设备文件系统的绝对路径**，不是文档仓库或开发主机位置。此处保留协议要求，译文中的资源链接仍使用相对路径。

## 15.2\_文件下载

下载命令读取设备指定路径中已有文件的内容。客户端必须跟踪已下载数据和文件内位置，持续修改偏移并请求后续块，直到获得整个文件；MCUmgr也会缓存这些状态。请求不携带块大小，该大小由设备应用确定。

只要没有达到空闲超时、其他传输也未使用文件管理上传/下载，连续请求之间可以保持文件句柄打开。但MCUmgr不独占文件：两次请求之间文件可能改变，甚至被移除。

请求头 `OP=0, Group ID=8, Command ID=0`：

```text
{
    (str)"off" :  (uint)
    (str)"name" : (str)
}
```

字段 `off` 为开始下载的偏移，`name` 为目标文件路径。响应头 `OP=1, Group ID=8, Command ID=0`：

```text
{
    (str)"off"      : (uint)
    (str)"data"     : (byte str)
    (str,opt)"len"  : (uint)
}
```

`off` 指本响应对应的文件偏移；字段 `data` 是读取的CBOR字节串，其编码自带长度，只在成功状态出现。字段 `len` 是文件长度，`off=0` 时必须给出，其他块可省略。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

**译注：**原文把数据存在条件写成“`rc` 为0”；成功响应也可能省略 `rc`，应结合SMP的成功/错误规则判断。

## 15.3\_文件上传

命令向指定位置上传文件；已有文件会被覆盖，不存在时创建。协议支持**无状态上传（Stateless Upload）**，每个请求携带不同数据块，由客户端跟踪进度。

连续请求可能保持句柄打开，条件与下载相同：没有空闲超时、未被其他传输的文件操作占用；文件不由MCUmgr独占，也可能在请求之间被修改或删除。原文此段有重复句，这里合并相同说明。

**原文注意：**Zephyr实现称为“半无状态”，能保存单个上传上下文，包含上传进行中的布尔标志、最近成功偏移和总长度。默认访问及可选访问钩子的规则同下载。

请求头 `OP=2, Group ID=8, Command ID=0`：

```text
{
    (str)"off"      : (uint)
    (str)"data"     : (str)
    (str)"name"     : (str)
    (str,opt)"len"  : (uint)
}
```

| 字段 | 含义 |
| --- | --- |
| `off` | 开始或继续上传的文件偏移。 |
| `data` | 写入文件的数据块，其CBOR编码自带长度。 |
| `name` | 目标设备文件路径。 |
| `len` | 文件总长度，`off=0` 时必需，其他块可省略。 |

> 译注：原结构将 `data` 标为 `str`；本地实现实际用函数 `zcbor_bstr_decode` 解码字节串，二进制文件数据不应因此转为文本字符串。

响应头 `OP=3, Group ID=8, Command ID=0`，成功载荷为：

```text
{
    (str)"off"      : (uint)
}
```

原文将 `off` 描述为最后成功写入数据的偏移。**译注：**本地实现累加已写数据长度后返回该位置，用于后续块的偏移，不需要自行再加一。

原文在上传错误位置没有显示代码框，但列明与本章开头相同的 `err.group`、非零 `err.rc` 及通用 `rc` 字段和出现条件；第2版组错误与通用错误仍须分别处理。

## 15.4\_文件状态

查询指定路径上已有文件的状态。请求头 `OP=0, Group ID=8, Command ID=1`，字段 `name` 为文件路径：

```text
{
    (str)"name" : (str)
}
```

响应头 `OP=1, Group ID=8, Command ID=1`。成功时 `len` 给出文件长度，单位为字节：

```text
{
    (str)"len"      : (uint)
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 15.5\_计算文件散列或校验和

命令在设备上对指定文件计算散列或校验和。需要内核堆分配工作缓冲区，并需要较大的栈缓冲区生成结果。

Kconfig配置项 [`CONFIG_MCUMGR_GRP_FS_CHECKSUM_HASH`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_FS_CHECKSUM_HASH) 启用基础功能；[`CONFIG_MCUMGR_GRP_FS_CHECKSUM_IEEE_CRC32`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_FS_CHECKSUM_IEEE_CRC32) 选择 **IEEE标准32位循环冗余校验（Cyclic Redundancy Check，CRC32）**，[`CONFIG_MCUMGR_GRP_FS_HASH_SHA256`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_FS_HASH_SHA256) 选择 **256位安全散列算法（Secure Hash Algorithm 256-bit，SHA-256）**。IEEE为**电气与电子工程师协会（Institute of Electrical and Electronics Engineers）**。

请求头 `OP=0, Group ID=8, Command ID=2`：

```text
{
    (str)"name"     : (str)
    (str,opt)"type" : (str)
    (str,opt)"off"  : (uint)
    (str,opt)"len"  : (uint)
}
```

| 字段 | 含义与默认值 |
| --- | --- |
| `name` | 目标文件路径。 |
| `type` | 算法字符串；省略则用默认算法。 |
| `off` | 开始计算的偏移；可选，默认0。 |
| `len` | 最多读取多少数据参与计算；可选，原文默认完整文件大小。 |

协议的算法名称字符串为 `crc32` 与 `sha256`，与上述两个可选实现对应。

| 算法名 | 算法 | 返回字节串 | 结果大小 |
| --- | --- | --- | --- |
| `crc32` | IEEE CRC32校验和。 | 否，为数值。 | 4字节。 |
| `sha256` | SHA-256散列。 | 是。 | 32字节。 |

若启用了 `crc32`，默认使用它；否则默认使用 `sha256`。

响应头 `OP=1, Group ID=8, Command ID=2`：

```text
{
    (str)"type"     : (str)
    (str,opt)"off"  : (uint)
    (str)"len"      : (uint)
    (str)"output"   : (uint or bstr)
}
```

`type` 是实际使用的算法；`off` 为计算起点，仅非零时出现；`len` 为实际参与计算的数据字节数；`output` 为结果，类型依算法为整数或字节串。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 15.6\_列出支持的算法

Kconfig配置项 [`CONFIG_MCUMGR_GRP_FS_CHECKSUM_HASH_SUPPORTED_CMD`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_FS_CHECKSUM_HASH_SUPPORTED_CMD) 启用此查询。请求头 `OP=0, Group ID=8, Command ID=3`，载荷为空CBOR映射；响应头 `OP=1, Group ID=8, Command ID=3`：

```text
{
    (str)"types" : {
        (str)<hash_checksum_name> : {
            (str)"format"       : (uint)
            (str)"size"         : (uint)
        }
        ...
    }
}
```

映射键 `<hash_checksum_name>` 是算法名称；`format=0` 表示数值结果，`format=1` 表示字节数组；`size` 是结果大小，单位为字节。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 15.7\_关闭文件

关闭由文件管理实现 `fs_mgmt` 上传/下载请求保持的文件句柄，适用于传输停滞或未完成的情况。请求头 `OP=2, Group ID=8, Command ID=4`，载荷为空CBOR映射；响应头 `OP=3, Group ID=8, Command ID=4`，成功载荷也为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。
