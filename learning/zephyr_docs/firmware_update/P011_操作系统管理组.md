# 第11章\_操作系统管理组

原文：[Default/OS Management Group](https://docs.zephyrproject.org/latest/services/device_mgmt/smp_groups/smp_group_0.html)。读取日期：2026-10-12，`latest`。

本章使用**简单管理协议（Simple Management Protocol，SMP）**；载荷采用**简洁二进制对象表示（Concise Binary Object Representation，CBOR）**。下列原文结构记号不是可以直接发送的 **JavaScript对象表示法（JavaScript Object Notation，JSON）**文本：`str` 为字符串，`uint` 为无符号整数，`int` 为整数，`bool` 为布尔值，`bstr` / `byte str` 为字节串，`opt` 表示可选。头字段 `OP` 为操作码，`Group ID` 为组标识，`Command ID` 为命令标识；0/1分别为读请求/响应，2/3分别为写请求/响应。

各命令的第2版组错误以 `err.group` 给出枚举 [`mcumgr_group_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ga81f98b9a0c3810f7d607b783f8e259b5) 所属组、以 `err.rc` 给出非零组内错误码。第1版错误及第2版的通用SMP错误以顶层 `rc` 给出枚举 [`mcumgr_err_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#gac5d8757a7ca945c77f405764b85ad5c5) 的非零错误码；成功时不必携带这些错误字段。后面保留每个命令的原始结构，通用编码规则见[SMP协议规范](P009_SMP协议规范.md)。

## 11.1\_默认与操作系统管理命令

**操作系统（Operating System，OS）**管理组编号0，定义下列命令：

| 命令编号 | 用途 |
| --- | --- |
| 0 | 回显（Echo）。 |
| 1 | 控制台/终端回显控制；Zephyr未实现。 |
| 2 | 任务统计（Task Statistics）。 |
| 3 | 内存池统计（Memory Pool Statistics）。 |
| 4 | 日期时间字符串（Date-time String）。 |
| 5 | 系统复位（System Reset）。 |
| 6 | MCUmgr参数。 |
| 7 | 操作系统/应用信息。 |
| 8 | 引导加载程序信息（Bootloader Information）。 |

## 11.2\_回显

此命令原样返回收到的字符串。请求头为 `OP=0或2, Group ID=0, Command ID=0`；请求字段 `d` 是需要回显的字符串：

```text
{
    (str)"d" : (str)
}
```

读请求的响应头为 `OP=1, Group ID=0, Command ID=0`，写请求的响应头为 `OP=3, Group ID=0, Command ID=0`。成功字段 `r` 是回显字符串：

```text
{
    (str)"r"        : (str)
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.3\_任务统计

命令返回系统任务统计。请求头 `OP=0, Group ID=0, Command ID=2`，载荷为空CBOR映射。响应头 `OP=1, Group ID=0, Command ID=2`，成功载荷为：

```text
{
    (str)"tasks" : {
        (str)<task_name> : {
            (str)"prio"         : (uint)
            (str)"tid"          : (uint)
            (str)"state"        : (uint)
            (str)"stkuse"       : (uint)
            (str)"stksiz"       : (uint)
            (str)"cswcnt"       : (uint)
            (str)"runtime"      : (uint)
            (str)"last_checkin" : (uint)
            (str)"next_checkin" : (uint)
        }
        ...
    }
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

| 字段 | 含义 |
| --- | --- |
| `<task_name>` | 标识任务的字符串，作为该任务统计映射的键。 |
| `prio` | 任务优先级。 |
| `tid` | 数值任务标识。 |
| `state` | 数值任务状态。 |
| `stkuse` | 任务/线程的栈使用量。 |
| `stksiz` | 任务/线程的栈大小。 |
| `cswcnt` | 任务/线程的上下文切换次数。 |
| `runtime` | 以**时钟节拍（Tick）**为单位的运行时间。 |
| `last_checkin` | Zephyr将其设为0。 |
| `next_checkin` | Zephyr将其设为0。 |

**原文注意：**`stkuse` 与 `stksiz` 的单位依系统而定，Zephyr使用4字节字的数量；不能直接当作字节数读取。

## 11.4\_内存池统计

命令获取运行中系统的活动内存池信息。请求头 `OP=0, Group ID=0, Command ID=3`，载荷为空CBOR映射；响应头 `OP=1, Group ID=0, Command ID=3`。成功结构：

```text
{
    (str)"mpools" : {
        (str)<pool_name> : {
            (str)"blksiz"   : (int)
            (str)"nblks"    : (int)
            (str)"nfree"    : (int)
            (str)"min'      : (int)
        }
        ...
    }
}
```

> 译注：原结构中的 `"min'` 引号不配对，下面按字段名 `min` 解释；结构为协议示意，原样保留便于对照。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

| 字段 | 含义 |
| --- | --- |
| `<pool_name>` | 内存池名称，作为池统计映射的键。 |
| `blksiz` | 池中块大小；Zephyr中始终为1。Kconfig配置项 [`CONFIG_MCUMGR_GRP_OS_MPSTAT_ONLY_SUPPORTED_STATS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_OS_MPSTAT_ONLY_SUPPORTED_STATS) 可使响应省略该字段。 |
| `nblks` | 池中的块数。 |
| `nfree` | 空闲块数。 |
| `min` | 运行期间达到的最低空闲块数。 |

## 11.5\_读取日期时间

日期时间命令读取或设置设备时间，两者均使用格式 `yyyy-MM-dd'T'HH:mm:ss.SSSSSSZZZZZ`。

读取请求头 `OP=0, Group ID=0, Command ID=4`，载荷为空CBOR映射；响应头 `OP=1, Group ID=0, Command ID=4`。成功时字符串字段 `datetime` 使用上述格式：

```text
{
    (str)"datetime" : (str)
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.6\_设置日期时间

设置请求头 `OP=2, Group ID=0, Command ID=4`；字段 `datetime` 使用同一日期时间格式：

```text
{
    (str)"datetime" : (str)
}
```

**译注：**原文在请求一节把此结构称为“response”，这里按所在小节说明其用途。

响应头 `OP=3, Group ID=0, Command ID=4`，成功载荷为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.7\_系统复位

设备应先发送接受命令的响应，再执行复位，让SMP客户端能够收到确认。默认在所有条件下接受复位；若启用Kconfig配置项 [`CONFIG_MCUMGR_GRP_OS_RESET_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_OS_RESET_HOOK) 并由应用注册回调，则可在重启前清理状态，也可直接拒绝请求并返回错误，见[管理回调](P008_管理回调.md)。

请求头 `OP=2, Group ID=0, Command ID=5`。通常发送空CBOR映射；如果上次复位尝试的 `rc` 为忙错误常量 [`MGMT_ERR_EBUSY`](https://docs.zephyrproject.org/latest/doxygen/html/group__mcumgr__mgmt__api.html#ggac5d8757a7ca945c77f405764b85ad5c5a7a0a4726f516645ac8b19efb25f79be1)，可用以下映射请求强制复位：

```text
{
    (opt)"force"       : (int)
    (opt)"boot_mode"   : (uint)
}
```

`force` 大于0表示强制复位，值为0时可省略。`boot_mode` 选择镜像或应用的启动模式，要求启用Kconfig配置项 [`CONFIG_MCUMGR_GRP_OS_RESET_BOOT_MODE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_OS_RESET_BOOT_MODE)。

响应头 `OP=3, Group ID=0, Command ID=5`，成功载荷为空CBOR映射。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.8\_MCUmgr参数

请求库参数的头部为 `OP=0, Group ID=0, Command ID=6`，载荷为空CBOR映射。响应头 `OP=1, Group ID=0, Command ID=6`，成功载荷为：

```text
{
    (str)"buf_size"     : (uint)
    (str)"buf_count"    : (uint)
}
```

字段 `buf_size` 是单个SMP缓冲区大小，包含SMP头与CBOR载荷；字段 `buf_count` 为支持的SMP缓冲区数量。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.9\_操作系统与应用信息

功能类似Linux的 `uname` 命令，可返回内核名称、版本、构建日期时间、处理器类型以及应用定义的信息。Kconfig配置项 [`CONFIG_MCUMGR_GRP_OS_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_OS_INFO) 启用该功能。

请求头 `OP=0, Group ID=0, Command ID=7`，载荷为：

```text
{
    (str,opt)"format"      : (str)
}
```

可选字符串 `format` 选择返回字段。字段按其自然索引升序追加，**不是按请求字符串中字符的排列顺序**；省略时使用 `s`。

| 格式字符 | 字段 |
| --- | --- |
| `s` | 内核名称（Kernel Name）。 |
| `n` | 节点名称（Node Name）。 |
| `r` | 内核发行版本（Kernel Release）。 |
| `v` | 内核版本（Kernel Version）。 |
| `b` | 构建日期时间；需要Kconfig配置项 [`CONFIG_MCUMGR_GRP_OS_INFO_BUILD_DATE_TIME`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MCUMGR_GRP_OS_INFO_BUILD_DATE_TIME)。 |
| `m` | 机器（Machine）。 |
| `p` | 处理器（Processor）。 |
| `i` | 硬件平台（Hardware Platform）。 |
| `o` | 操作系统（Operating System）。 |
| `a` | 上述全部字段的简写。 |

响应头 `OP=1, Group ID=0, Command ID=7`。成功字段 `output` 包含请求参数的文本：

```text
{
    (str)"output"       : (str)
}
```

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.10\_引导加载程序信息

此命令查询设备的引导加载程序及其参数。请求头 `OP=0, Group ID=0, Command ID=8`：

```text
{
    (str,opt)"query"  : (str)
}
```

可选字符串 `query` 表示参数查询，格式不受协议额外限制，由引导加载程序后端解释。不提供查询时返回引导加载程序名称。

响应头 `OP=1, Group ID=0, Command ID=8`。未提供 `query` 时，字符串 `bootloader` 标识名称：

```text
{
    (str)"bootloader"      : (str)
}
```

提供 `query` 时，响应结构由查询和后端决定：

```text
{
    (str,opt)<response>   : ()
    ...
}
```

可选 `<response>` 是查询答案，可以有多个参数或嵌套映射；还可附加带值的关键字说明参数特征。若查询没有答案，可省略该字段，预期使用第2版组错误常量 `OS_MGMT_ERR_QUERY_YIELDS_NO_ANSWER`。

失败响应（第2版组错误）：

```text
{
    (str)"err" : {
        (str)"group"    : (uint)
        (str)"rc"       : (uint)
    }
}
```

第1版错误或第2版通用SMP错误：

```text
{
    (str)"rc"       : (int)
}
```

字段的出现条件与本章开头相同。

## 11.11\_MCUboot查询

若应用使用MCUboot，空请求的响应如下：

```text
{
    (str)"bootloader"      : (str)"MCUboot"
}
```

当前支持通过查询字符串 `mode` 查询运行模式：

```text
{
    (str)"query"           : (str)"mode"
}
```

响应为：

```text
{
    (str)"mode"                     : (int)
    (str,opt)"no-downgrade"         : (bool)
}
```

| `mode` 值 | 含义 |
| --- | --- |
| -1 | 未知MCUboot模式。 |
| 0 | 单应用模式。 |
| 1 | 使用暂存分区（Scratch Partition）交换。 |
| 2 | 覆盖模式（Overwrite），仅升级。 |
| 3 | 不使用暂存分区交换。 |
| 4 | **直接原地执行（Direct Execute In Place，DirectXIP）**，不支持回退。 |
| 5 | DirectXIP，支持回退。 |
| 6 | **随机存取存储器（Random Access Memory，RAM）**加载模式。 |

`no-downgrade` 为真时始终发送，表示MCUboot启用了防降级：若上传镜像的版本低于当前应用，MCUboot不会用它升级。在此配置下，MCUmgr也可能拒绝较低版本镜像。
