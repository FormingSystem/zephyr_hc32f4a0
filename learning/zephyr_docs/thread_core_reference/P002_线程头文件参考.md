## 2.4\_源码定位与版本边界

源码定位：[include/zephyr/kernel/thread.h](../../../include/zephyr/kernel/thread.h)、[kernel/thread.c](../../../kernel/thread.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位采用相对链接；接口条件、结构布局与特定配置的实现应分别阅读，本次未运行线程调度或多核实板测试。

> 译注——源码核对：k_thread是内核维护的线程对象，不是应用可随意写入的调度配置结构。字段是否存在由Kconfig决定，架构专有arch字段必须位于末尾，不应假定不同架构或配置下具有相同二进制布局。

> 译注——源码核对：_thread_base把优先级与调度锁计数放在相邻字段中用于快速判断可抢占性。源注释中的0x0080阈值解释的是这种内部布局，不能当作公共优先级或直接修改线程状态的接口。

> 译注——源码核对：stack_info.start表示线程可写栈区域起点，size包括线程数据预留和随机栈指针调整留下的范围；delta扣除TLS及随机偏移占用，start+size-delta才对应初始栈指针。启用内存映射栈时，stack_obj字段按原文保存物理地址，不应直接当作普通虚拟数据指针使用。

> 译注——源码核对：futex_pointer仅在线程等待Futex时具有对应语义，其他时候可能保留旧值；join_queue、halt_queue与next_thread等是内核队列关系，不应由应用自行改写。

> 译注——源码核对：CPU统计中的execution_cycles包含非空闲与空闲周期，线程统计中的execution_cycles等于total_cycles；单个线程的idle_cycles始终为0。源码中的统计字段注释按CPU与线程各自边界保留，不能将所有周期字段混作同一个时间量。

> 译注——源码核对：条件启用的互斥锁优先级继承字段记录所持互斥锁、等待中的互斥锁及原优先级，属于内核维护状态。原文中止接口对资源和优先级继承清理的要求仍然适用，不能通过清空结构成员代替正常释放。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
