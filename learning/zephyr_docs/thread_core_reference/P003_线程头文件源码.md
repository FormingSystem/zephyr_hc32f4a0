## 3.4\_源码跟踪译注

> 译注——k_thread是内核维护的线程对象，不是应用可随意写入的调度配置结构。字段是否存在由Kconfig决定，架构专有arch字段必须位于末尾，不应假定不同架构或配置下具有相同二进制布局。

> 译注——_thread_base把优先级与调度锁计数放在相邻字段中用于快速判断可抢占性。源注释中的0x0080阈值解释的是这种内部布局，不能当作公共优先级或直接修改线程状态的接口。

> 译注——stack_info.start表示线程可写栈区域起点，size包括线程数据预留和随机栈指针调整留下的范围；delta扣除TLS及随机偏移占用，start+size-delta才对应初始栈指针。启用内存映射栈时，stack_obj字段按原文保存物理地址，不应直接当作普通虚拟数据指针使用。

> 译注——futex_pointer仅在线程等待Futex时具有对应语义，其他时候可能保留旧值；join_queue、halt_queue与next_thread等是内核队列关系，不应由应用自行改写。

> 译注——CPU统计中的execution_cycles包含非空闲与空闲周期，线程统计中的execution_cycles等于total_cycles；单个线程的idle_cycles始终为0。源码中的统计字段注释按CPU与线程各自边界保留，不能将所有周期字段混作同一个时间量。

> 译注——条件启用的互斥锁优先级继承字段记录所持互斥锁、等待中的互斥锁及原优先级，属于内核维护状态。原文中止接口对资源和优先级继承清理的要求仍然适用，不能通过清空结构成员代替正常释放。

> 译注——CPU过滤遍历当前按thread->base.cpu比较；该字段表示线程当前或最近一次执行的CPU。因此原文“在指定CPU上运行”的措辞不能理解为只返回此刻正占用该CPU的线程，也不是按允许运行的CPU掩码过滤。

> 译注——普通遍历持有监视器自旋锁调用回调；unlocked版本只在访问链表节点时持锁，回调期间解锁。解锁并不延长线程对象生命周期，必须按原文避免遍历期间中止后复用对象内存；普通回调也不应在持锁环境中阻塞或重入需要同一锁的线程管理操作。
