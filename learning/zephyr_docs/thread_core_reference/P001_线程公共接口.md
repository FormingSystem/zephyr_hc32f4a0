**警告（Warning）**：警告（Warning）：根据架构不同，栈大小 `stack_size` 可能必须为 `CONFIG_MMU_PAGE_SIZE` 的整数倍（使用 MMU 时），或为 2 的幂（使用 MPU 时）。

### `k_reschedule()`


### `k_sched_lock()`

```c
void k_sched_lock ( void )
```

```c
#include <zephyr/kernel.h>
```

锁定调度器。

此函数指示调度器把当前线程视为协作式线程，从而防止其他线程抢占它。如果当前线程随后执行了使自身变为非就绪状态的操作，仍会按正常方式切换出去；当它再次成为当前线程时，不可抢占状态仍然保持。

可以递归调用此函数。

得益于实现方式，非用户空间线程的调度锁操作极快，只需对线程结构中的一个字节执行递增或递减。

说明（Note）：该机制临时将线程提升到协作式优先级，能够以较低成本与同一 CPU 上的其他可抢占或协作式线程同步，但不能阻止其他类型的抢占或异步行为。`CONFIG_SMP=y` 时，它不会阻止其他 CPU 上的线程运行；也不会阻止中断或 MetaIRQ 优先级线程抢占当前线程。总体而言，这是一个历史 API，不太适合现代应用，应谨慎使用。

### `k_sched_time_slice_set()`

```c
void k_sched_time_slice_set ( int32_t slice, int prio )
```

```c
#include <zephyr/kernel.h>
```

设置时间片（Time Slice）周期及适用范围。

此函数指定调度器如何对可抢占线程执行时间片轮转（Time Slicing）。

使能时间片时，`slice` 必须非零。调度器保证一个线程连续运行不超过指定时间上限，然后让同优先级的其他线程获得执行机会。优先级高于 `prio` 的线程不受此限制，可以持续执行而不会因时间片用尽被抢占。

时间片只限制线程连续执行的最长时间。调度器选中一个线程后，并不保证它至少运行多长时间才会调度相同或更高优先级的线程。

如果当前线程是该优先级下唯一符合执行条件的线程，此函数没有实际影响；时间片到期后会立即重新调度同一线程。

禁用时间片时，将 `slice` 和 `prio` 都设为 0。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `slice` | 最大时间片长度，单位为毫秒。 |
| `prio` | 允许参与时间片轮转的最高线程优先级等级。 |

### `k_thread_absolute_deadline_set()`

```c
void k_thread_absolute_deadline_set ( k_tid_t thread, int deadline )
```

```c
#include <zephyr/kernel.h>
```

为调度器设置绝对截止到期时间（Absolute Deadline）。

将截止到期时刻设置为与 `k_cycle_get_32()` 相同单位的时间戳。启用截止时间调度（Deadline Scheduling）时，调度器在相同静态优先级的线程之间选择最先到期者；静态优先级不同的线程仍按各自静态优先级调度。

`k_thread_deadline_set` 相对于调用过程中隐式取得的“当前时刻”设置截止时间；此函数设置绝对时间戳，该值由调用前显式取得的“当前时刻”计算而来，因此调用者可以使用共同的时间基准为多个线程设置截止时间。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 要设置截止时间的线程。 |
| `deadline` | 以周期（Cycle）为单位的时间戳。 |

说明（Note）：截止时间在内部用 32 位无符号整数保存。调度队列中“第一个”与“最后一个”截止时间相差的周期数必须小于 2^31，即可表示为有符号非负值，否则线程的截止时间调度顺序可能错误。即使给定时间戳已经过去，内核仍按截止时间从早到晚排序。虽然接口名称带有“截止时间”，调度器并不保证线程一定在该时限内获得调度，也不接收 Linux `sched_setattr()` 中 runtime、period 等用来验证调度可行性的额外信息。这类能力可以建立在本接口之上，而此调用本身只为优先级选择逻辑提供输入。

**注意（Attention）**：注意（Attention）：仅在启用 Kconfig 选项 `CONFIG_SCHED_DEADLINE` 时可用。

### `k_thread_create()`

```c
k_tid_t k_thread_create ( struct k_thread * new_thread, k_thread_stack_t * stack, size_t stack_size, k_thread_entry_t entry, void * p1, void * p2, void * p3, int prio, uint32_t options, k_timeout_t delay )
```

```c
#include <zephyr/kernel.h>
```

创建线程。

此函数初始化一个线程，然后安排其执行。

新线程可以立即执行，也可以延迟启动。如果没有指定延迟，内核调度器可能抢占当前线程，使新线程开始执行。

线程选项与架构有关，可以包含 `K_ESSENTIAL`、`K_FP_REGS` 和 `K_SSE_REGS`。可以用 `|` 运算符组合多个选项；原文将其称为逻辑或（Logical OR）。

为了保持可移植性，传给此函数的栈对象可以使用以下任一宏静态分配：

- `K_THREAD_STACK_DEFINE()`：用于可能支持用户线程或监督模式线程的栈。
- `K_KERNEL_STACK_DEFINE()`：用于只支持监督模式线程的栈；启用 `CONFIG_USERSPACE` 时，这类栈占用的内存更少。

也可以用 `k_thread_stack_alloc` 动态分配栈。

`stack_size` 参数受到限制，必须采用以下值之一：

- 传给 `K_THREAD_STACK_DEFINE()` 或 `K_KERNEL_STACK_DEFINE()` 的原始大小值。
- 栈由 `K_THREAD_STACK_DEFINE()` 定义时，使用 `K_THREAD_STACK_SIZEOF(stack)` 的返回值。
- 栈由 `K_KERNEL_STACK_DEFINE()` 定义时，使用 `K_KERNEL_STACK_SIZEOF(stack)` 的返回值。

使用其他值或 `sizeof(stack)` 可能产生未定义行为。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `new_thread` | 指向尚未初始化的 `struct k_thread`。 |
| `stack` | 指向栈空间的指针。 |
| `stack_size` | 栈大小，单位为字节。 |
| `entry` | 线程入口函数。 |
| `p1` | 入口函数的第一个参数。 |
| `p2` | 入口函数的第二个参数。 |
| `p3` | 入口函数的第三个参数。 |
| `prio` | 线程优先级。 |
| `options` | 线程选项。 |
| `delay` | 调度延迟；不延迟时使用 `K_NO_WAIT`。 |

返回（Returns）：新线程的标识符。

### `k_thread_deadline_set()`

```c
void k_thread_deadline_set ( k_tid_t thread, int deadline )
```

```c
#include <zephyr/kernel.h>
```

为调度器设置相对截止到期时间（Relative Deadline）。

将截止到期时间设置为相对于当前时刻的时间差，单位与 `k_cycle_get_32()` 相同。启用截止时间调度时，调度器在静态优先级相同的线程之间选择最先到期者；静态优先级不同的线程仍按各自静态优先级调度。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 要设置截止时间的线程。 |
| `deadline` | 以周期为单位的时间差。 |

说明（Note）：截止时间在内部用 32 位无符号整数保存。调度队列中“第一个”与“最后一个”截止时间相差的周期数必须小于 2^31，即可表示为有符号非负值，否则线程的截止时间调度顺序可能错误。虽然接口名称带有“截止时间”，调度器并不保证线程一定在该时限内获得调度，也不接收 Linux `sched_setattr()` 中 runtime、period 等用来验证调度可行性的额外信息。这类能力可以建立在本接口之上，而此调用本身只为优先级选择逻辑提供输入。为保持调度器的模数比较约束，相对截止时间会被静默限制在 `[0, INT32_MAX / 2]` 范围内，原文将此量级写为 2^30 个周期；负值向上限制为 0。

**注意（Attention）**：注意（Attention）：仅在启用 Kconfig 选项 `CONFIG_SCHED_DEADLINE` 时可用。

> 译注——源码核对：截止时间只参与相同静态优先级线程间的排序，不是保证完成期限的实时预算。当前相对实现把deadline限制到0至INT32_MAX/2，再加上当前周期计数；严格上限为1073741823，不是精确的2^30。原文写法保留并说明这个一周期差异。 当前用户模式校验器在进入相对截止时间实现之前要求deadline>0，因此不能把实现层“负数限制为0”的行为当作用户模式允许传入负数或零的承诺。绝对截止时间更新在调度锁内对已入队线程执行出队、修改和重新入队，避免破坏队列排序。

阻止内核调度器将 `thread` 选为当前线程，但该线程的其他内部操作仍照常进行，例如仍可把它正在等待的内核对象交给它。挂起不会影响线程正在等待的任何超时，例如 `k_sem_take()` 或 `k_sleep()` 的超时。因此，即使等待超时在挂起期间到期，线程仍保持挂起，直到调用 `k_thread_resume()`。

目标线程正在另一个 CPU 上执行时，调用者会阻塞，直到目标线程停止执行，即被挂起或中止。如果调用者处于中断上下文，则会自旋等待另一个 CPU 上的目标线程停止。

如果线程已经挂起，此函数不产生作用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 要挂起的线程标识符。 |

<a id="ga563928f292a4134acd4142029b60e631"></a>

### `k_thread_time_slice_set()`

```c
void k_thread_time_slice_set ( struct k_thread * th, int32_t slice_ticks, k_thread_timeslice_fn_t expired, void * data )
```

```c
#include <zephyr/kernel.h>
```

设置线程时间片。

与 `k_sched_time_slice_set` 类似，但在 `CONFIG_TIMESLICE_PER_THREAD=y` 时为指定线程设置时间片。非零的线程专属时间片优先于全局设置。

这类线程的时间片到期时，会先调用所配置的回调，再将线程从运行队列移除并重新加入。回调在中断上下文执行，且可以保证指定线程已被当前 ISR 抢占。回调可以修改该线程后续执行的优先级或时间片，也可以挂起线程等。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `th` | 有效且已初始化的线程。 |
| `slice_ticks` | 最大时间片，单位为时钟节拍。 |
| `expired` | 时间片到期时调用的回调函数。 |
| `data` | 传给到期处理函数的参数。 |

说明（Note）：与旧 API 不同，这里的时间片以时钟节拍为单位，而不是毫秒。内核一直使用时钟节拍作为内部单位，并非所有平台都能在两者之间进行整数换算。线程设置了非零的专属时间片后，总会参与时间片轮转，即使其优先级高于 `k_sched_time_slice_set()` 设置的适用优先级上限。时间片到期通知必须在线程仍是“当前线程”时发生，因此早于该节拍上已登记的其他超时处理。这会带来一个容易混淆的结果：节拍时间，例如 `k_uptime_get()`，尚未反映刚刚到期的这些节拍。需要在该回调中作精细计时决策的应用，应使用周期 API，或 `k_thread_runtime_stats_get()` 等派生接口。

## 1.6\_源码定位与版本边界

源码定位：[include/zephyr/kernel.h](../../../include/zephyr/kernel.h)、[kernel/thread.c](../../../kernel/thread.c)、[kernel/sched.c](../../../kernel/sched.c)、[kernel/deadline.c](../../../kernel/deadline.c)、[kernel/smp/cpu_mask.c](../../../kernel/smp/cpu_mask.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位采用相对链接；接口条件、结构布局与特定配置的实现应分别阅读，本次未运行线程调度或多核实板测试。

> 译注——源码核对：线程创建需要线程对象、栈对象、入口和调度参数。栈对象大小、可用栈大小与初始栈指针不是同一数值；k_thread_create只接受原文列出的栈大小来源，不能把sizeof(stack)当作通用替代。K_KERNEL_STACK_DEFINE定义的栈不能用于降权进入用户模式。

> 译注——源码核对：线程中止（Abort）、线程结束等待（Join）、挂起（Suspend）、睡眠（Sleep）与唤醒（Wakeup）具有不同语义。中止不会替调用者释放互斥锁或内存等资源，挂起不会冻结等待超时，k_wakeup只对睡眠状态起作用。不能用状态名称近似推导清理或恢复行为。

> 译注——源码核对：原文把选项组合符号|称为logical OR；C语言中这里实际是按位或（Bitwise OR），逻辑或是||。代码和原始符号保持不变，组合线程标志时应使用|。

> 译注——源码核对：调度锁（Scheduler Lock）不屏蔽中断，也不是跨CPU互斥锁。当前线程如果主动阻塞，仍会切换出去；MetaIRQ和SMP的限制按原文保留，不能把锁定调度器当作任意共享内存操作的完整同步。

> 译注——源码核对：全局时间片接口使用毫秒，线程专属时间片接口使用时钟节拍。后者的到期回调在ISR上下文执行，先于同一节拍的其他超时记账；不能直接套用线程上下文的阻塞操作或把k_uptime_get当作已完成更新的精细计时依据。

> 译注——源码核对：截止时间只参与相同静态优先级线程间的排序，不是保证完成期限的实时预算。当前相对实现把deadline限制到0至INT32_MAX/2，再加上当前周期计数；严格上限为1073741823，不是精确的2^30。原文写法保留并说明这个一周期差异。

> 译注——源码核对：当前用户模式校验器在进入相对截止时间实现之前要求deadline>0，因此不能把实现层“负数限制为0”的行为当作用户模式允许传入负数或零的承诺。绝对截止时间更新在调度锁内对已入队线程执行出队、修改和重新入队，避免破坏队列排序。

> 译注——源码核对：CPU掩码修改要求目标线程当前不可运行。当前k_thread_cpu_pin用一次cpu_mask_mod调用设置所选位并清除其他位，不是要求应用先调用清空接口再调用使能接口；后者在PIN_ONLY下会产生不允许的中间空掩码。

> 译注——源码核对：CPU过滤遍历当前按thread->base.cpu比较；该字段表示线程当前或最近一次执行的CPU。因此原文“在指定CPU上运行”的措辞不能理解为只返回此刻正占用该CPU的线程，也不是按允许运行的CPU掩码过滤。

> 译注——源码核对：普通遍历持有监视器自旋锁调用回调；unlocked版本只在访问链表节点时持锁，回调期间解锁。解锁并不延长线程对象生命周期，必须按原文避免遍历期间中止后复用对象内存；普通回调也不应在持锁环境中阻塞或重入需要同一锁的线程管理操作。

> 译注——源码核对：动态栈从池或堆取得，释放与线程中止是独立操作。当前禁用动态栈的实现使分配返回NULL、释放返回-ENOSYS；启用时仍需要处理-EBUSY等返回值。用户模式动态堆栈还依赖动态内核对象支持，不能把普通malloc缓冲区当作可互换的用户栈对象。

> 译注——源码核对：k_thread_user_mode_enter在当前通用实现中设置K_USER并清除essential标志，然后在支持用户空间时检查栈能力、重置相应本地数据与TLS，再进入架构降权入口。原文“保留线程选项”并不意味着K_ESSENTIAL保持不变。未启用CONFIG_USERSPACE的分支直接调用入口，源码明确不重置栈，不能把它当作真实降权隔离。

> 译注——源码核对：线程名称直接取得接口返回内部名称指针，复制接口则写调用者缓冲区。当前监督模式复制实现使用strncpy，缓冲区太小时不保证末尾有空字符；原文中部分错误条件注明仅适用于用户模式，不能推广为所有调用路径统一拒绝小缓冲区。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
