## 1.5\_详细说明（Detailed Documentation）

<a id="gafac28874aaad3bcec72c693186e988cb"></a>

### `ATOMIC_BITMAP_SIZE`

```c
#define ATOMIC_BITMAP_SIZE ( num_bits)
```

```c
#include <zephyr/sys/atomic.h>
```

展开值（Value）：

```c
(ROUND_UP(num_bits, ATOMIC_BITS) / ATOMIC_BITS)
```

此宏计算表示包含 num_bits 位的位图（Bitmap）所需的原子变量数量。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `num_bits` | 位数。 |

> 译注——源码核对：结果是atomic_t元素的数量，不是位数或字节数。ATOMIC_BITS由sizeof(atomic_val_t)与BITS_PER_BYTE计算；按字宽向上取整后，数组可能包含超过请求位数的存储空间。

<a id="ga249c575db9764486197709b327f7370e"></a>

### `ATOMIC_DEFINE`

```c
#define ATOMIC_DEFINE ( name, num_bits )
```

```c
#include <zephyr/sys/atomic.h>
```

展开值（Value）：

```c
atomic_t name[ATOMIC_BITMAP_SIZE(num_bits)]
```

定义原子变量数组。

此宏定义一个原子变量数组，包含至少 num_bits 个位。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 原子变量数组的名称。 |
| `num_bits` | 所需位数。 |

**说明（Note）**：如果在文件作用域（File Scope）使用，数组中的位初始化为零；如果在函数内部使用，则这些位不进行初始化。

> 译注——源码核对：宏仅声明数组，没有添加初始化器。原文的函数内未初始化说明针对通常的自动局部数组；若声明具有静态存储期（Static Storage Duration），即使位于函数内也适用C的零初始化规则。调用方仍须管理逻辑位数和有效索引，不能将分配后的填充位自动视为业务标志。

<a id="gacad6866fa4c844026cd9f8c3fb60ecd7"></a>

### `atomic_ptr_t`

```c
typedef void* atomic_ptr_t
```

```c
#include <zephyr/sys/atomic_types.h>
```

原子指针变量（Atomic Pointer Variable）。

此类型的原子变量保存一个指针值；线程（Thread）和中断服务程序（Interrupt Service Routine，ISR）可通过原子指针 API，以不可分割的方式读取和修改该值。

> 译注——源码核对：本次类型实际是void *的typedef。原子性针对指针值的访问，不会自动保护被指向对象的所有字段或管理对象的释放；须另行处理对象生命周期与使用协议。

### `atomic_t`

```c
typedef long atomic_t
```

```c
#include <zephyr/sys/atomic_types.h>
```

原子整数变量（Atomic Integer Variable）。

线程（Thread）和中断服务程序（Interrupt Service Routine，ISR）可通过原子 API，以不可分割的方式读取和修改此类型的原子变量。在32位机器上它是32位变量，在64位机器上则是64位变量。

> 译注——源码核对：本次类型实际是long的typedef，不是C语言_Atomic限定类型。不可分割访问和内存顺序由对应API及所选后端实现；仅将普通共享对象改名为atomic_t不使任意直接读写都变成原子操作。

> 译注——源码核对：与test_and_set_bit／test_and_clear_bit不同，此函数返回“是否改变”。val为true时，原位为0才返回true；val为false时，原位为1才返回true。不要将其返回值直接当作原位值。

### `atomic_test_bit()`

```c

```

声明属性：`inline`、`static`。

以原子方式读取一个值，然后测试 target 中编号为 bit 的位是否置位。target 可以是单个原子变量，也可以是原子变量数组。

## 1.6\_源码定位与版本边界

公共入口位于[sys/atomic.h](../../../include/zephyr/sys/atomic.h)，类型与后端通过该文件选入；本次核对[官方公共头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/atomic.h)、[C实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/os/atomic_c.c)与[配置定义](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/os/Kconfig.atomics)，摘要见[来源记录](../SOURCES.md)。仓库源码、滚动更新的main和latest网页不能自动视为同一版本。

> 译注——同步与边界：公共API约定在适用情况下提供完整／顺序一致的内存屏障。单次操作的原子性不会使多个调用组成一个不可分割事务，也不会同时原子修改位图的全部元素。当前C后端有禁止SMP的编译断言，具体行为见[C源码跟踪](P009_通用C原子操作接口源码.md)。

本批完成文档与源码核对，未构建或运行并发、内存顺序及实板实验。
