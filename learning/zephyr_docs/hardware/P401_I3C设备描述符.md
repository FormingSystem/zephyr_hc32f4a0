# 第401章\_I3C设备描述符

原文：[structi3c__device__desc](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html)。读取日期：2026-10-13，`latest`。

## 401.1\_用途与初始化要求

`struct i3c_device_desc` 描述一个**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）目标设备（Target Device）**。头文件为 `zephyr/drivers/i3c.h`。

此结构实例传给 I3C 控制器设备接口。原文以 `i3c_device_register()` 为例，表示告知控制器某个目标设备；以 `i3c_transfers()` 为例，表示启动控制器与目标设备之间的数据传输。

> 译注：原文此处的传输函数名为复数 `i3c_transfers()`；当前[传输接口页面](P394_I3C传输接口.md)定义的是 `i3c_transfer()`。上段保留原举例名称，不应直接把它当作可编译函数调用。

实现目标设备行为的模块，在把对象引用传给控制器接口之前，必须初始化 [`bus`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#aaa1a96e29bf98028ad6ee4c1aae79809)、[`pid`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a153ff108d8cf523d60aad3534d06f88e) 和 [`static_addr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a078901f1dc853dabf6503407d78735c0)。目标没有静态地址时，[`static_addr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a078901f1dc853dabf6503407d78735c0) 可以为 0。内部字段 [`node`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a965edbd5d74c06773e190a14d4f6e3cd) 不应由调用者手动初始化或修改。

## 401.2\_设备归属与基础标识

**预置标识（Provisioned ID，PID）**识别设备。**总线特征寄存器（Bus Characteristic Register，BCR）**描述总线相关特征；**设备特征寄存器（Device Characteristic Register，DCR）**描述设备类型。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `node` | [`sys_snode_t`](../slist_reference/P001_单向链表公共接口.md#ga69bf43aad81e3ee2d55250c59b857493) | 内部单向链表节点；不手动初始化或修改。 |
| [`bus`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#aaa1a96e29bf98028ad6ee4c1aae79809) | `const struct device *` | 此目标附接的 I3C 总线。 |
| [`dev`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#af0466893f56f9aebdaa7677a9a0076ed) | `const struct device *` | I3C 设备的驱动实例。 |
| [`pid`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a153ff108d8cf523d60aad3534d06f88e) | [`uint64_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a2095b9bffea4b2656950c6c0419edbf1) | 设备预置标识。 |
| [`bcr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#ae1cff0a31d9cc5d7b18206556f8e0b21) | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | BCR，参见 [`I3C_BCR`](P425_I3C公共接口参考.md) 定义组。 |
| [`dcr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#aee6342edbc47c478aa39b8330fab0d9c) | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | DCR；具体数值的设备类型含义需查官方说明。 |

## 401.3\_静态地址、动态地址与初始偏好

**静态地址（Static Address）**是设备预先具备的地址；**动态地址（Dynamic Address）**用于总线通信，通过**动态地址分配（Dynamic Address Assignment，DAA）**等过程设置。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| [`static_addr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a078901f1dc853dabf6503407d78735c0) | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | 此目标的静态地址；仅使用动态地址时为 0。 |
| [`init_dynamic_addr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a0477ac021d81431a34f55fa1c9f04bb5) | `const uint8_t` | 希望在地址分配时取得的初始动态地址；无偏好时为 0。 |
| [`dynamic_addr`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a4e4c9614871e5ea4aa08b1560ecc40d0) | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | 当前用于通信的动态地址；尚未分配时为 0。 |

`init_dynamic_addr` 由**设备树（Devicetree）**属性 `assigned-address` 指定，用来表示在 `SETDASA` 与 `ENTDAA` 分配地址时的期望值。

控制器驱动应在以下过程设置 `dynamic_addr`。这些名称都是**通用命令码（Common Command Code，CCC）**：

- `ENTDAA`：执行动态地址分配。
- `RSTDAA`：复位动态地址分配。
- `SETAASA`：把所有地址设为静态地址。
- `SETNEWDA`：设置新的动态地址。
- `SETDASA`：由静态地址设置动态地址。

当 `static_addr` 为 0 时，设备必须先通过 `ENTDAA` 得到动态地址，才能与控制器通信。此时不能通过 `SETAASA` 或 `SETDASA` 设置其动态地址，因为这两种方式都要求目标使用其静态地址作为动态地址。

## 401.4\_设备标志

[`flags`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a5cc5f0ffdd173478275a6b5f651d86a3) 的类型为 `const uint8_t`，保存设备标志（Device Flags）：

| 位 | 含义 |
| --- | --- |
| 0 | 若设备支持 `SETAASA`，用于优化总线初始化。 |
| 1 | 表示此设备是否为 I3C 1.0 设备。 |

## 401.5\_速度与长度

[`data_speed`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#ada4abe9b2486917684f3a961687e80ba) 嵌套结构保存最大数据速度，原文标注为 `GETMXDS` CCC。**读取周转时间（Read Turnaround Time）**是其中以微秒为单位记录的时间参数。

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `data_speed.maxrd` | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | 最大读取速度。 |
| `data_speed.maxwr` | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | 最大写入速度。 |
| `data_speed.max_read_turnaround` | [`uint32_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a0a8582351ac627ee8bde2973c825e47f) | 最大读取周转时间，单位为微秒。 |

[`data_length`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#afc6133bb816889751c74306de604ccfe) 嵌套结构保存最大数据长度。原页面也把该组标为 `GETMXDS` CCC，这里保留这一原文标注。

> 译注：[读取长度命令载荷](P415_I3C最大读取长度命令数据.md)对应 SETMRL/GETMRL，[写入长度命令载荷](P416_I3C最大写入长度命令数据.md)对应 SETMWL/GETMWL。因此不能把本字段组重复的 GETMXDS 标注理解为全部长度字段都由该命令返回。

**带内中断（In-Band Interrupt，IBI）**可以附带载荷（Payload）：

| 字段 | 类型 | 含义 |
| --- | --- | --- |
| `data_length.mrl` | [`uint16_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a5debae8b2a1ec20a6694c0c443ee399e) | 最大读取长度（Maximum Read Length，MRL）。 |
| `data_length.mwl` | [`uint16_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a5debae8b2a1ec20a6694c0c443ee399e) | 最大写入长度（Maximum Write Length，MWL）。 |
| `data_length.max_ibi` | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | 最大 IBI 载荷大小，仅在 BCR 第 2 位为 1 时有效。 |

## 401.6\_高数据速率能力

[`getcaps`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#ab059b569119a1311304451ee1f720de0) 嵌套结构描述目标的高级能力与特性。其中 [`gethdrcap`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#ae01bc68ac8154238d85bbf44dc06dfb7) 与 [`getcap1`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a062f86dec32de3b9e899b096df47d828) 位于匿名联合体（Anonymous Union），共用存储，且都关联 `I3C_CCC_GETCAPS1_*` 定义。

**高数据速率（High Data Rate，HDR）**包括双倍数据速率（Double Data Rate，DDR）、纯总线三元符号（Ternary Symbol Pure-bus，TSP）、包含传统设备总线的三元符号（Ternary Symbol Legacy-inclusive-bus，TSL），以及大块传输（Bulk Transport，BT）模式。

| 字段 | 类型 | 位含义 |
| --- | --- | --- |
| `getcaps.gethdrcap` | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | I3C 1.0 HDR 能力：位 0 为 DDR，位 1 为 TSP，位 2 为 TSL，位 7:3 保留。 |
| `getcaps.getcap1` | [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d) | I3C 1.1 及以后版本 GETCAPS1：位 0 为 DDR，位 1 为 TSP，位 2 为 TSL，位 3 为 BT，位 7:4 保留。 |

## 401.7\_GETCAPS2与GETCAPS4

**循环冗余校验（Cyclic Redundancy Check，CRC）**用于错误检测。`getcaps.getcap2` 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，对应 GETCAPS2 和 `I3C_CCC_GETCAPS2_*`：

| 位 | 含义 |
| --- | --- |
| 3:0 | I3C 1.x 规范版本。 |
| 5:4 | 组地址能力（Group Address Capabilities）。 |
| 6 | HDR-DDR 写入中止（Write Abort）。 |
| 7 | HDR-DDR 中止 CRC（Abort CRC）。 |

`getcaps.getcap4` 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，对应 GETCAPS4；位 7:0 全部保留。

## 401.8\_GETCAPS3

`getcaps.getcap3` 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，对应 GETCAPS3 和 `I3C_CCC_GETCAPS3_*`。**多通道（Multi-Lane，ML）**和**设备间传输（Device-to-Device Transfer，D2DXFER）**是其中描述的传输能力；**定义字节（Defining Byte）**与**强制数据字节（Mandatory Data Byte，MDB）**是命令或中断中的特定字节。

| 位 | 含义 |
| --- | --- |
| 0 | 支持 ML 数据传输。 |
| 1 | 支持 D2DXFER。 |
| 2 | 具备 D2DXFER IBI 能力。 |
| 3 | 在 `GETCAPS` 中支持定义字节。 |
| 4 | 在 `GETSTATUS` 中支持定义字节。 |
| 5 | 支持 HDR-BT CRC-32。 |
| 6 | 支持用 IBI MDB 发送待读取通知（Pending Read Notification）。 |
| 7 | 保留。 |

## 401.9\_控制器能力与移交延迟

字段 [`crhdly1`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a3fc3b3f1cf396eaf164612e7b667b37a) 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，保存**控制器移交延迟参数（Controller Handoff Delay Parameters）**。嵌套结构 [`crcaps`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#af21d5045678651c6d0ccb4319d187686) 描述控制器功能能力（Controller Feature Capabilities）。

`crcaps.crcaps1` 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，表示 CRCAPS1：

| 位 | 含义 |
| --- | --- |
| 0 | 支持热加入（Hot Join）。 |
| 1 | 支持组管理（Group Management）。 |
| 2 | 支持多通道（Multi-Lane）。 |
| 7:3 | 保留。 |

`crcaps.crcaps2` 的类型为 [`uint8_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a3cb4a16b0e8d6af0af86d4fd6ba5fd9d)，表示 CRCAPS2：

| 位 | 含义 |
| --- | --- |
| 0 | 支持带内中断。 |
| 1 | 控制权交回（Controller Pass-Back）。 |
| 2 | 具备深度睡眠（Deep Sleep）能力。 |
| 3 | 延迟控制权移交（Delayed Controller Handoff）。 |
| 7:4 | 保留。 |

## 401.10\_带内中断回调

字段 [`ibi_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html#a1f9eda89e2e28971e39aace38ddbb265) 的类型为 [`i3c_target_ibi_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga814cf622b240808216ce4e87802e965c)，保存 IBI 回调（Callback），仅在设置 Kconfig 配置项 [`CONFIG_I3C_USE_IBI`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_USE_IBI) 时可用。回调签名、载荷及返回值见[带内中断接口](P396_I3C带内中断接口.md)。
