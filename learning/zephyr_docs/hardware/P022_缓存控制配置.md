# 第22章\_缓存控制配置

原文：[Cache Control Configuration](https://docs.zephyrproject.org/latest/hardware/cache/config.html)。读取日期：2026-10-12，`latest`。

本页概述 Zephyr **缓存（Cache）**接口及相关 Kconfig 选项。各选项分别描述硬件能力、Zephyr 是否使用缓存，以及是否提供标准接口。

## 22.1\_能力与使用开关

`CONFIG_CPU_HAS_DCACHE` / `CONFIG_CPU_HAS_ICACHE` 是隐藏选项。**中央处理器（Central Processing Unit，CPU）** 实际支持数据或指令缓存时，由 **片上系统（System on Chip，SoC）** 或平台层选择；缓存控制器可以在核内，也可以是由独立驱动管理的外部控制器。它们描述硬件存在的能力，无论 Zephyr 是否计划支持或使用，都应如实设置。

`CONFIG_DCACHE` / `CONFIG_ICACHE` 表示 Zephyr 对相应缓存的支持已经存在并工作。缓存控制相关代码路径应依据这些符号条件启用；符号打开时，视为缓存已启用并正在使用。

关闭这两个选项不保证硬件缓存已关闭，因为硬件默认状态可能仍启用缓存。它们也不说明对用户暴露了何种接口，例如平台可以启用 `CONFIG_DCACHE`，却只在平台代码中调用硬件抽象层（HAL）函数管理缓存。

## 22.2\_标准接口与不缓存区域

`CONFIG_CACHE_MANAGEMENT` 表示通过标准缓存接口暴露操作。启用时，预期相应缓存函数已经由架构代码或外部缓存控制器驱动实现。

`CONFIG_MEM_ATTR` 允许通过[内存区域属性](https://docs.zephyrproject.org/latest/services/mem_mgmt/index.html)指定固定区域，在内核初始化后禁用该区域缓存。

`CONFIG_NOCACHE_MEMORY` 允许用 `__nocache` 标记全局变量；链接器把这些变量放进特殊不缓存区域，再由 **内存保护单元（Memory Protection Unit，MPU）** 驱动设置区域属性。

## 22.3\_实现位置

`CACHE_TYPE` 下的 `CONFIG_ARCH_CACHE` 与 `CONFIG_EXTERNAL_CACHE` 互斥：前者由架构代码实现缓存接口；后者由外部缓存控制器驱动实现，驱动按常规放在 `drivers/cache/` 目录。

## 22.4\_接口参考

完整函数参考见[缓存接口](../cache_reference/P001_公共缓存接口.md)。实际使用方法见[缓存基础](P021_缓存基础.md)。
