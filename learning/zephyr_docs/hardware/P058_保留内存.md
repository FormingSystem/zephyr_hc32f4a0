# 第58章\_保留内存

原文：[Retained Memory](https://docs.zephyrproject.org/latest/hardware/peripherals/retained_mem.html)。读取日期：2026-10-13，`latest`。

## 58.1\_保留内存与掉电边界

**保留内存（Retained Memory）**驱动的 **应用程序编程接口（Application Programming Interface，API）**用于读写在设备保持供电时保留内容的内存区域。原文特别指出：**在低功耗模式下，数据可能丢失**。

“保留”描述的是特定供电条件下的内容保持，不能直接等同于永久保存或任何低功耗状态都不丢失。使用前需结合实际内存区域与所进入的电源状态。

## 58.2\_相关配置

原页列出的Kconfig配置项如下；Kconfig是Zephyr的配置系统。

| 配置项 | 用途 |
| --- | --- |
| [`CONFIG_RETAINED_MEM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM) | 启用保留内存驱动支持。 |
| [`CONFIG_RETAINED_MEM_INIT_PRIORITY`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM_INIT_PRIORITY) | 保留内存驱动初始化优先级。 |
| [`CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE) | 强制关闭所有保留内存驱动的互斥保护。 |

## 58.3\_互斥保护与中断调用

当应用编译时启用了多线程支持，保留内存驱动默认启用 **互斥量（Mutex）**保护。不同线程因此可以安全调用这些函数，避免与其他线程的并发调用冲突；但这也意味着这些函数**不能在中断服务程序（Interrupt Service Routine，ISR）中使用**。

启用 [`CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE) 可以全局禁用所有保留内存驱动的互斥保护。此时，确保各次函数调用彼此不冲突的责任转移给使用者；不能把关闭互斥理解为驱动自动解决了并发访问问题。

完整接口见[保留内存参考](P630_保留内存接口.md)。
