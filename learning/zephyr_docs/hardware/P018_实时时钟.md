# 第18章\_实时时钟

原文：[Real-Time Clock (RTC)](https://docs.zephyrproject.org/latest/hardware/peripherals/rtc.html)。读取日期：2026-10-12，`latest`。

**实时时钟（Real-Time Clock，RTC）**是以分解的日历时间跟踪时刻的低功耗设备。这里的分解时间是年、月、日、时、分、秒等字段，而不是单一连续计数。

## 18.1\_概念与设备树

原文术语区分如下：实时时钟以分解时间计时；实时计数器（Real-Time Counter）是可用于跟踪时间的低功耗计数器；RTC 在本页专指实时时钟。两者有时名称或缩写相同，但不能混淆。

RTC 通常针对低能耗优化，在系统低功耗状态下仍持续运行。通常带一个或多个闹钟，在指定时刻触发，常用于唤醒系统。

RTC 绑定必须包含 `rtc-device.yaml`；它进一步包含 `base.yaml`，并规定必需的 `alarms-count` 属性：

```yaml
include: rtc-device.yaml
```

## 18.2\_驱动设计

驱动初始化需要保持时间连续性，并处理外部中断与时钟输出。

### 18.2.1\_初始化

原文规定系统不主动关闭 RTC 电源。初始化时驱动应预期设备处于两种状态之一：已供电、已配置且正在运行；或已供电、未配置且停止。

驱动应确保配置正确，同时保留已有时间、闹钟和运行状态。调用 `rtc_set_time()` 设置时间后，RTC 开始运行。闹钟待处理状态由 `rtc_alarm_is_pending()`，或通过 `rtc_alarm_set_callback()` 注册后触发的闹钟回调清除。

### 18.2.2\_通过GPIO连接的中断

RTC 的中断输出脚已连接时，驱动必须在初始化期间配置并启用它们。主机可以启停自身 **通用输入输出（General-Purpose Input/Output，GPIO）** 中断，但 RTC 一侧的中断输出必须保持启用。

这使内部与外部连接 RTC 的行为一致，也支持通过 GPIO 对已启用的闹钟、更新时间等事件进行系统唤醒。

原文明确要求：中断输出未连接的 RTC 不得通过周期轮询来伪装成中断已连接；此时 `rtc_alarm_set_callback()` 与 `rtc_update_set_callback()` 应返回 `-ENOTSUP`。

### 18.2.3\_时钟输出

设备支持时钟输出时，通过设备树指定配置，驱动在初始化阶段应用它。

## 18.3\_配置与接口

相关配置为 `CONFIG_RTC`、`CONFIG_RTC_ALARM`、`CONFIG_RTC_UPDATE`、`CONFIG_RTC_CALIBRATION`。参考分为 [RTC 接口](https://docs.zephyrproject.org/latest/doxygen/html/group__rtc__interface.html)和 [Fake RTC](P497_RTC伪设备接口.md)。

[RTC 示例](https://docs.zephyrproject.org/latest/samples/drivers/rtc/README.html)展示设置和读取日期时间。

## 18.4\_驱动测试套件

RTC 测试套件设计为可跨开发板移植，通过设备树别名 `rtc` 选择被测设备。测试设置/读取时间、时间正确递增、硬件支持时有回调和无回调两种闹钟方式，以及硬件支持时的校准。

校准测试会尝试一组值并打印，使用者必须人工比较设置值与读回值，确认有效。默认只启用必需的设置与读取时间测试；闹钟、更新事件回调、校准属于可选项，要分别启用 `CONFIG_RTC_ALARM`、`CONFIG_RTC_UPDATE`、`CONFIG_RTC_CALIBRATION`。

原例使用 `native_sim`。其他目标需把开发板名替换为实际板名。默认配置构建命令：

```shell
# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api
```

用 menuconfig 启用额外 RTC 功能：

```shell
# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api
west build -t menuconfig
```

更新配置后重新构建：

```shell
# From the root of the zephyr repository
west build -b native_sim tests/drivers/rtc/rtc_api
```

测试实际开发板时，烧录并运行测试应用，结果输出到控制台。原文提醒：使用真实硬件时，每项测试可能需要长达 30 秒。

> 译注：这些是官方测试步骤，不是本次已执行记录；`native_sim` 是本机仿真目标，不等同于需要向 HC32 烧录的固件。运行目标应与实际构建选择保持一致。

## 18.5\_仿真RTC设备

仿真 RTC 完整实现接口，但有三项限制：时间不跨应用初始化保存；闹钟不跨应用初始化保存；时间可能逐渐漂移。

每次应用初始化都重置 RTC 时间和闹钟。在通过 `rtc_set_time()` 设置之前，`rtc_get_time()` 返回 `-ENODATA`；设置后按普通 RTC 方式工作，直到应用再次复位。

仿真驱动对应兼容字符串 [`zephyr,rtc-emul`](https://docs.zephyrproject.org/latest/build/dts/api/bindings/rtc/zephyr%2Crtc-emul.html)，原文说明选择 `CONFIG_RTC` 时可纳入该驱动。

> 译注：创建可用设备实例仍需要目标设备树与驱动配置匹配；仅打开 RTC 总开关不代表任意开发板自动生成仿真设备节点。

## 18.6\_Zephyr中的RTC历史

在独立 RTC 接口出现之前，Zephyr 通过[计数器接口](P017_计数器.md)支持 RTC，驱动在 Unix 时间戳与硬件内部的分解时间之间转换。

这种方式的缺点是硬件计数器接口不能设置指定计数，因此各 RTC 需要设备专用的设时接口；有时不必要地转换 Unix 时间和日历时间；还缺少输入时钟校准、更新回调等常见能力。
