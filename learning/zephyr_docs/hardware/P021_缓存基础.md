# 第21章\_缓存基础

原文：[Caching Basics](https://docs.zephyrproject.org/latest/hardware/cache/guide.html)。读取日期：2026-10-12，`latest`。

本章介绍**缓存一致性（Cache Coherency）**，以及何时必须显式管理缓存。配置项见[缓存控制配置](P022_缓存控制配置.md)，完整接口见[缓存参考](../cache_reference/P001_公共缓存接口.md)。本章主要讨论数据缓存；支持缓存的系统通常也有指令缓存。

原文前提是已启用架构相关的**内存保护单元（Memory Protection Unit，MPU）**支持，具体约束应查看架构文档。

虽然 **对称多处理（Symmetric Multiprocessing，SMP）** 核间共享也涉及一致性，Zephyr 通常负责使各核一致地观察内核内存。多数应用直接使用缓存接口，是为了与 **直接内存访问（Direct Memory Access，DMA）** 控制器或运行另一操作系统镜像的外部 **中央处理器（Central Processing Unit，CPU）** 交互。多核内核一致性配置为 `CONFIG_KERNEL_COHERENCE`。

## 21.1\_为何需要缓存管理

处理器核与其他总线主设备共享内存时，必须考虑一致性。缓存通常紧贴各 CPU 核，以获得较高性能；DMA 直接搬运内存数据后，CPU 缓存可能仍保存旧内容，表现得像数据损坏。若 DMA 已传输但处理器看不到预期数据，缓存一致性就是可能原因之一。

保证一致性有几条路径：全局关闭缓存最简单，但失去缓存性能收益；只禁用部分区域的缓存可以折中，例如 **串行外设接口（Serial Peripheral Interface，SPI）** DMA 缓冲区；也可以在运行时对区域做缓存写回或失效。

## 21.2\_全局关闭数据缓存

全局关闭通常显著影响性能，但可用于调试。要求启用 `CONFIG_DCACHE`，让 Zephyr 控制数据缓存，并启用 `CONFIG_CACHE_MANAGEMENT` 提供缓存接口。

通过 `sys_cache_data_disable()` 全局关闭数据缓存。

## 21.3\_指定不缓存区域

只禁用部分内存的缓存，是不缓存区域性能不关键时的折中方案。如果应用有许多彼此无关、且小于缓存行的缓冲区，这种方式也很合适。

要求启用 `CONFIG_DCACHE`、处理设备树内存属性的 `CONFIG_MEM_ATTR`，再按[内存属性](https://docs.zephyrproject.org/latest/services/mem_mgmt/index.html)标注设备树。

MPU 驱动在内核初始化时按这些属性配置区域。还需让链接器把缓冲区放进该区域，例如通过 `Z_GENERIC_SECTION`：

```c
/* SRAM4 marked as uncached in device tree */
uint8_t buffer[BUF_SIZE] Z_GENERIC_SECTION("SRAM4");
```

采用独立缓存规则的区域通常占用一个 MPU 区域。某些架构的区域数有限，还要留给[用户模式](../kernel/P043_MPU用户空间实现.md)、[栈保护](../kernel/P042_MPU栈对象.md)和[内存域](../kernel/P041_内存保护与内存域.md)。

## 21.4\_按变量自动放置到不缓存区域

Zephyr 可以自动定义不缓存链接区域，并通过 `__nocache` 把变量放进去，启动时由 MPU 驱动标为不缓存。它比手工定义区域简单，但位置控制较少，链接器可以把区域放在 **随机存取存储器（Random Access Memory，RAM）** 中合适的地方。

要求启用 `CONFIG_DCACHE` 与 `CONFIG_NOCACHE_MEMORY`。在缓冲区定义后添加属性：

```c
uint8_t buffer[BUF_SIZE] __nocache;
```

即使区域由 Zephyr 自动建立，它仍占用独立 MPU 区域，前述数量限制依然适用。

## 21.5\_运行时缓存控制

原文认为运行时控制是性能最好但最复杂的方式。主要操作是写回（flush）和失效（invalidate），最小操作单位为缓存行。数据缓存行常见大小为 16～128 字节，参见 `CONFIG_DCACHE_LINE_SIZE`。

缓存行大小通常由硬件固定，不能由应用任意选择；Zephyr 需要知道它以正确管理缓存。缓冲区小于缓存行时，可能更适合放入不缓存区，因为同一缓存行中的无关脏数据可能在失效时丢失。

写回把指定区域内已修改缓存行写入共享内存。CPU 填充完缓冲区、其他总线主设备读取之前，应完成对应写回。

部分架构支持直写（write-through）缓存，CPU 写入会传播到共享内存；这解决 CPU 写入方向的一致性问题，但增加主存流量，可能降低性能。

失效把指定缓存行标记为无效，使 CPU 下次读取时重新从主存取得。外设写完缓冲区、CPU 读取之前，应使相关数据缓存失效。

同一缓冲区同时用于 DMA 读写等情况时，可以先写回再失效，以保证 CPU 下一次访问重新获取数据。要求启用 `CONFIG_DCACHE` 与 `CONFIG_CACHE_MANAGEMENT`，对应接口分别为 `sys_cache_data_flush_range()`、`sys_cache_data_invd_range()`、`sys_cache_data_flush_and_invd_range()`。

> 译注：这些操作必须与传输方向、完成时刻和缓冲区所有权配合。外设已经写入后，不能把 CPU 中过时的脏缓存再写回覆盖新数据；一次“写回并失效”也不能替代 DMA 完成同步。

## 21.6\_对齐

按 `sys_cache_data_invd_range()` 等接口要求，缓冲区应对齐到缓存行边界，可用 `__aligned`：

```c
uint8_t buffer[BUF_SIZE] __aligned(CONFIG_DCACHE_LINE_SIZE);
```

> 译注：只对齐起始地址仍不保证尾部独占缓存行。若进行整行失效，大小和相邻对象布局也需要考虑，避免同一行中的其他数据受影响。
