# 第114章\_核心转储设备

原文：[Coredump Device](https://docs.zephyrproject.org/latest/hardware/peripherals/coredump.html)。读取日期：2026-10-13，`latest`。

## 114.1\_两类核心转储伪设备

**核心转储设备（Coredump Device）**是一种 **伪设备驱动（Pseudo-Device Driver）**，具有两种类型。

内存复制类型 `COREDUMP_TYPE_MEMCPY` 通过 **设备树绑定（Devicetree Binding）**提供要纳入每次转储的内存地址与大小。驱动还提供 **应用程序编程接口（Application Programming Interface，API）**，用于在运行时添加、移除转储内存区域。

回调类型 `COREDUMP_TYPE_CALLBACK` 要求 `memory-regions` 数组恰好包含一个条目。原文把该条目描述为“大小为0及期望大小”，随后说明驱动静态分配期望大小的内存，并提供注册 **回调函数（Callback Function）**的API；发生转储时，回调负责填充这段内存。

> 译注：原句把零值位置也称为“size”，存在歧义。对照本仓库当前[驱动实现](../../../drivers/coredump/coredump_impl.c)中的 `CREATE_COREDUMP_DEVICE` 宏，数组必须有两个单元，依次为地址和大小；第一个单元的**地址必须为0**，第二个单元用于分配缓冲区。也就是“地址0、期望大小”，不是要求分配大小为0。此处为本仓库实现核对，使用其他版本时应复查其绑定和驱动。

## 114.2\_配置与接口

相关Kconfig配置项为 [`CONFIG_COREDUMP_DEVICE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_COREDUMP_DEVICE)；Kconfig是Zephyr配置系统。完整声明见[核心转储伪设备API](https://docs.zephyrproject.org/latest/doxygen/html/group__coredump__device__interface.html)。
