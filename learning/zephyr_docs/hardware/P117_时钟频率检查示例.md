# 第117章\_时钟频率检查示例

原文：[Clock Monitor Frequency Check](https://docs.zephyrproject.org/latest/samples/drivers/clock_monitor/check_freq/README.html)。读取日期：2026-10-13，`latest`。

## 117.1\_连续检查频率窗口

本示例使用 **时钟监视器（Clock Monitor）**的 **应用程序编程接口（Application Programming Interface，API）**，在窗口模式枚举 [`CLOCK_MONITOR_MODE_WINDOW`](../timer_reference/P098_时钟监控公共接口.md) 下持续比较时钟与可编程阈值。每次越过阈值都通过 **回调函数（Callback Function）**报告，日志指出时钟过快或过慢；主循环只周期性打印 **心跳（Heartbeat）**消息。概览见[时钟监视器](P102_时钟监视器.md)。

示例的Kconfig配置项 `CONFIG_SAMPLE_EXPECTED_HZ` 设置窗口中心频率，`CONFIG_SAMPLE_TOLERANCE_PPM` 设置容差，`CONFIG_SAMPLE_WINDOW_NS` 设置刷新间隔。Kconfig是Zephyr配置系统；Hz为赫兹，ppm为 **百万分率（Parts Per Million）**，ns为纳秒。预期频率保持0时，通过[时钟控制API](P007_时钟控制.md)取得时钟实际频率作为中心。

## 117.2\_所需设备与覆盖文件

开发板必须通过 **设备树别名（Devicetree Alias）** `clock-monitor` 暴露一个时钟监视器。基于NXP **频率测量（Frequency Measurement，FREQME）**外设的开发板还需要共享 **设备树覆盖文件（Devicetree Overlay）** [clock_monitor.overlay](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/drivers/clock_monitor/clock_monitor.overlay)，它位于源码中的 `samples/drivers/clock_monitor/`。

## 117.3\_构建与运行

以下原命令在Zephyr源码目录中使用west工作区工具构建、烧录FRDM-MCXE31B目标。FRDM为NXP开发板系列标识，构建目标字符串应原样保留。

```sh
west build -b frdm_mcxe31b samples/drivers/clock_monitor/check_freq
west flash
```

使用FREQME外设的板卡需要添加共享覆盖文件。原例以FRDM-MCXN236为目标；`EXTRA_DTC_OVERLAY_FILE` 构建变量传入附加设备树覆盖文件：

```sh
west build -b frdm_mcxn236 samples/drivers/clock_monitor/check_freq -- -DEXTRA_DTC_OVERLAY_FILE="../clock_monitor.overlay"
west flash
```

## 117.4\_原始输出及含义

日志首先打印预期频率配置、正负50000 ppm容差与1000000 ns窗口，然后每5秒打印一次心跳。这里 `expected ~0 Hz` 是原示例输出，不表示真实时钟频率必为0；前文已说明0配置值触发实际频率查询。

```text
[00:00:00.000,000] <inf> sample: clock check running (expected ~0 Hz, tolerance +/-50000 ppm, window 1000000 ns)
[00:00:05.000,000] <inf> sample: heartbeat: clock check running
[00:00:10.000,000] <inf> sample: heartbeat: clock check running
```

时钟漂移到窗口之外或停止时，由回调打印异常。例如，下列原日志表示被监视时钟低于下限，或已丢失：

```text
[00:00:12.345,000] <err> sample: [cmu-fc@2bc000] monitored clock below lower threshold (or lost)
```
