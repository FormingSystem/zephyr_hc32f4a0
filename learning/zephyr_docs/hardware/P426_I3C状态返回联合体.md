# 第426章\_I3C状态返回联合体

原文：[unioni3c__ccc__getstatus](https://docs.zephyrproject.org/latest/doxygen/html/unioni3c__ccc__getstatus.html)。读取日期：2026-10-13，`latest`。

## 426.1\_GETSTATUS返回格式

`union i3c_ccc_getstatus` 是**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）通用命令码（Common Command Code，CCC）** `GETSTATUS` 的载荷（Payload），用于**获取设备状态（Get Device Status）**。头文件为 `zephyr/drivers/i3c/ccc.h`。

联合体包含格式 1（Format 1）的 [`fmt1`](https://docs.zephyrproject.org/latest/doxygen/html/unioni3c__ccc__getstatus.html#adbc4805456634d5602ab74c2cde4d903) 结构，以及格式 2（Format 2）的 [`fmt2`](https://docs.zephyrproject.org/latest/doxygen/html/unioni3c__ccc__getstatus.html#ac3a7629c6d213beff8ab38863a366b11) 联合体。按原字段表整理如下：

```c
union i3c_ccc_getstatus {
    struct {
        uint16_t status;
    } fmt1;
    union {
        uint16_t tgtstat;
        uint16_t precr;
        uint16_t raw_u16;
    } fmt2;
};
```

## 426.2\_格式1设备状态

字段 `fmt1.status` 为 16 位设备状态（Device Status）：

| 位 | 含义 |
| --- | --- |
| 15:8 | 保留。 |
| 7:6 | 活动模式（Activity Mode）。 |
| 5 | 协议错误（Protocol Error）。 |
| 4 | 保留。 |
| 3:0 | 挂起中断数量（Number of Pending Interrupts）。 |

对于驱动及辅助函数，目标返回的原始数据采用**大端字节序（Big-endian）**，必须先转换为**中央处理器（Central Processing Unit，CPU）**的字节序，再交给调用者。

## 426.3\_格式2定义字节

**定义字节（Defining Byte）**选择本次状态数据的具体格式。原文中的 `TGTSTAT`、`PRECR` 是格式名称。

- `fmt2.tgtstat`：定义字节 `0x00`，格式名 `TGTSTAT`；字段含义参见 `fmt1.status`。
- `fmt2.precr`：定义字节 `0x91`，格式名 `PRECR`，位定义见下表。
- `fmt2.raw_u16`：原页仅列出 [`uint16_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a5debae8b2a1ec20a6694c0c443ee399e) 声明，没有附加语义说明。

| PRECR位 | 含义 |
| --- | --- |
| 15:8 | 厂商保留（Vendor Reserved）。 |
| 7:2 | 保留。 |
| 1 | 控制权移交延迟的否定应答（Negative Acknowledgement，NACK）。 |
| 0 | 检测到深度睡眠（Deep Sleep Detected）。 |

`fmt2.precr` 的原始数据同样采用大端字节序；驱动及辅助函数必须在返回调用者之前完成 CPU 字节序转换。
