# 第822章\_数模转换器接口

原文：[group__dac__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html)。读取日期：2026-10-13，`latest`。

数模转换器（Digital-to-Analog Converter，DAC）接口自Zephyr 2.3提供，本接口文档标注版本为1.1.0。公共头文件为 `zephyr/drivers/dac.h`，它包含DAC驱动应用程序接口（Application Programming Interface，API）。

```c
#include <zephyr/drivers/dac.h>
```

相关类型包括[通道配置结构](P825_DAC通道配置结构.md) [`dac_channel_cfg`](https://docs.zephyrproject.org/latest/doxygen/html/structdac__channel__cfg.html) 与[设备树规格结构](P826_DAC设备树规格结构.md) [`dac_dt_spec`](https://docs.zephyrproject.org/latest/doxygen/html/structdac__dt__spec.html)。驱动开发参见[驱动实现接口](P823_DAC驱动实现接口.md)，器件专用功能参见[驱动扩展入口](P824_DAC驱动扩展入口.md)。以下保留原页全部宏、函数、参数、返回值与代码示例；原注释存在矛盾的地方另附译注。

## 822.1\_广播通道与设备树通道配置

```c
#define DAC_CHANNEL_BROADCAST 0xFF
```

[`DAC_CHANNEL_BROADCAST`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gabeb2cf325aec36624a013ee91a377b35) 为支持广播（Broadcast）的DAC提供广播通道标识。**此标识仅用于 [`dac_write_value()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga437a6f6b2402cf2e2a2a689429663b4e)**。

`DAC_CHANNEL_CFG_DT(node_id)` 从设备树（Devicetree）节点读取通道配置，返回 `struct dac_channel_cfg` 的静态初始化器（Static Initializer）。参数 `node_id` 是设备树节点标识符（Node Identifier）。宏展开为：

```c
        { \
        .channel_id       = DT_REG_ADDR(node_id),                      \
        .resolution       = DT_PROP_OR(node_id, zephyr_resolution, 0), \
        .buffered         = DT_PROP(node_id, zephyr_buffered),         \
        .internal         = DT_PROP(node_id, zephyr_internal),         \
}
```

原始设备树源码（Devicetree Source，DTS）示例：

```dts
&dac {
   #address-cells = <1>;
   #size-cells = <0>;

   channel@0 {
       reg = <0>;
       zephyr,resolution = <12>;
   };

   channel@1 {
       reg = <1>;
       zephyr,resolution = <12>;
       zephyr,buffered;
   };
};
```

原始C用法与初始化结果：

```c
static const struct dac_channel_cfg ch0_cfg_dt =
    DAC_CHANNEL_CFG_DT(DT_CHILD(DT_NODELABEL(dac), channel_0));
static const struct dac_channel_cfg ch1_cfg_dt =
    DAC_CHANNEL_CFG_DT(DT_CHILD(DT_NODELABEL(dac), channel_1));

// Initializes 'ch0_cfg_dt' to:
// {
//     .channel_id = 0,
//     .resolution = 12,
// }
// and 'ch1_cfg_dt' to:
// {
//     .channel_id = 1,
//     .resolution = 12,
//     .buffered = true,
// }
```

例中的通道0、1分辨率（Resolution）均为12位，通道1启用输出缓冲（Buffered Output）。代码中的英文注释保留原文，便于逐项对照字段。

## 822.2\_默认通道与按索引读取

`DAC_DT_SPEC_GET(node_id)` 等价于 `DAC_DT_SPEC_GET_BY_IDX(node_id, 0)`，返回 `struct dac_dt_spec` 的静态初始化器。参数 `node_id` 是设备树节点标识符，具体行为参见本节按索引读取宏。

```c
DAC_DT_SPEC_GET_BY_IDX(node_id, 0)
```

`DAC_DT_SPEC_GET_BY_IDX(node_id, idx)` 从节点及通道索引（Channel Index）取得DAC输入输出通道（I/O Channel）信息，返回 `struct dac_dt_spec` 的静态初始化器。节点必须定义 `io-channels` 属性。参数 `node_id` 是设备树节点标识符，`idx` 为通道在属性中的索引。

```c
DAC_DT_SPEC_STRUCT(DT_IO_CHANNELS_CTLR_BY_IDX(node_id, idx), \
                   COND_CODE_1(DT_PHA_HAS_CELL_AT_IDX(node_id, io_channels, idx, output), \
                               (DT_IO_CHANNELS_OUTPUT_BY_IDX(node_id, idx)), \
                               (0)))
```

原始设备树片段：

```dts
/ {
    zephyr,user {
        io-channels = <&dac0 1>, <&dac0 3>;
    };
};

&dac0 {
   #address-cells = <1>;
   #size-cells = <0>;

   channel@3 {
       reg = <3>;

       zephyr,resolution = <12>;
   };
};
```

原始C用法与初始化结果：

```c
static const struct dac_dt_spec dac_chan0 =
    DAC_DT_SPEC_GET_BY_IDX(DT_PATH(zephyr_user), 0);
static const struct dac_dt_spec dac_chan1 =
    DAC_DT_SPEC_GET_BY_IDX(DT_PATH(zephyr_user), 1);

// Initializes 'dac_chan0' to:
// {
//     .dev = DEVICE_DT_GET(DT_NODELABEL(dac0)),
//     .channel_id = 1,
// }
// and 'dac_chan1' to:
// {
//     .dev = DEVICE_DT_GET(DT_NODELABEL(dac0)),
//     .channel_id = 3,
//     .channel_cfg_dt_node_exists = true,
//     .channel_cfg = {
//         .channel_id = 3,
//         .resolution = 12
//     },
// }
```

这里索引0指向硬件通道1，索引1指向硬件通道3；索引与硬件通道编号（Channel ID）并不相同。示例只为通道3定义了配置子节点，因此只有相应的 `dac_chan1` 初始化结果含有效的通道配置及 `channel_cfg_dt_node_exists = true`。

## 822.3\_按索引读取的回退值

`DAC_DT_SPEC_GET_BY_IDX_OR(node_id, idx, default_value)` 与 [`DAC_DT_SPEC_GET_BY_IDX()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga23c61ff062c1745349b5ef5e8eee5454) 相似，但支持默认回退值（Fallback Value）。

| 参数 | 含义 |
| --- | --- |
| `node_id` | 设备树节点标识符 |
| `idx` | 通道索引 |
| `default_value` | 无法取得所需项时展开得到的回退值 |

返回值为该属性对应的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`。宏实际通过 [`DT_PROP_HAS_IDX`](../dt_property_reference/P001_设备树属性读取宏.md#ga479dfc704087eea7e7c5af42ae98576c) 检查指定索引，展开式如下。实例形式参见 [`DAC_DT_SPEC_INST_GET_BY_IDX_OR()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga01636bb214c44daae7a06e3fd42a7378)。

```c
COND_CODE_1(DT_PROP_HAS_IDX(node_id, io_channels, idx), \
            (DAC_DT_SPEC_GET_BY_IDX(node_id, idx)), (default_value))
```

## 822.4\_按名称读取

`DAC_DT_SPEC_GET_BY_NAME(node_id, name)` 根据节点与通道名称（Channel Name）获取DAC的 `io-channel` 信息，返回 `struct dac_dt_spec` 的静态初始化器。节点必须定义 `io-channels` 属性。`node_id` 为设备树节点标识符，`name` 为通道名称。

```c
DAC_DT_SPEC_STRUCT(DT_IO_CHANNELS_CTLR_BY_NAME(node_id, name), \
                   DT_IO_CHANNELS_OUTPUT_BY_NAME(node_id, name))
```

原始设备树片段同时提供通道引用与名称：

```dts
/ {
    zephyr,user {
        io-channels = <&dac0 1>, <&dac0 3>;
        io-channel-names = "A0", "A1";
    };
};

&dac0 {
   #address-cells = <1>;
   #size-cells = <0>;

   channel@3 {
       reg = <3>;
       zephyr,resolution = <12>;
   };
};
```

原始C用法及结果：

```c
static const struct dac_dt_spec dac_chan0 =
    DAC_DT_SPEC_GET_BY_NAME(DT_PATH(zephyr_user), a0);
static const struct dac_dt_spec dac_chan1 =
    DAC_DT_SPEC_GET_BY_NAME(DT_PATH(zephyr_user), a1);

// Initializes 'dac_chan0' to:
// {
//     .dev = DEVICE_DT_GET(DT_NODELABEL(dac0)),
//     .channel_id = 1,
// }
// and 'dac_chan1' to:
// {
//     .dev = DEVICE_DT_GET(DT_NODELABEL(dac0)),
//     .channel_id = 3,
//     .channel_cfg_dt_node_exists = true,
//     .channel_cfg = {
//         .channel_id = 3,
//         .resolution = 12,
//     },
// }
```

示例中设备树字符串为 `"A0"`、`"A1"`，宏调用使用标识符 `a0`、`a1`。配置结果与前面的索引示例一致：硬件通道1没有配置子节点，通道3配置为12位。

## 822.5\_按名称与默认通道读取的回退值

`DAC_DT_SPEC_GET_BY_NAME_OR(node_id, name, default_value)` 与 [`DAC_DT_SPEC_GET_BY_NAME()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga220c6d61ae537cefd98a0d912d0e62ab) 相似，但支持默认回退值。

| 参数 | 含义 |
| --- | --- |
| `node_id` | 设备树节点标识符 |
| `name` | 通道名称 |
| `default_value` | 展开使用的回退值 |

返回该属性的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`。宏实际检查指定名称，实例形式见 [`DAC_DT_SPEC_INST_GET_BY_NAME_OR()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga09baadf4436c502b23c34cb6c6a85ba0)。

```c
COND_CODE_1(DT_PROP_HAS_NAME(node_id, io_channels, name), \
            (DAC_DT_SPEC_GET_BY_NAME(node_id, name)), (default_value))
```

`DAC_DT_SPEC_GET_OR(node_id, default_value)` 等价于 `DAC_DT_SPEC_GET_BY_IDX_OR(node_id, 0, default_value)`。参数 `node_id` 为设备树节点标识符，`default_value` 为回退值。返回该属性的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`。完整行为参见按索引读取的回退宏。

```c
DAC_DT_SPEC_GET_BY_IDX_OR(node_id, 0, default_value)
```

## 822.6\_驱动实例读取宏

这些宏从 `DT_DRV_COMPAT` 所对应的设备树实例（Devicetree Instance）读取通道信息。各宏中的 `inst` 均表示该兼容字符串对应的实例编号；`idx` 是通道索引，`name` 是通道名称，`default_value` 是回退时展开的值。实例编号不是硬件通道编号。

`DAC_DT_SPEC_INST_GET(inst)` 等价于 `DAC_DT_SPEC_INST_GET_BY_IDX(inst, 0)`，返回 `struct dac_dt_spec` 的静态初始化器，行为参见 [`DAC_DT_SPEC_GET()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gaea739243d370edbcd2f9611a4bdf69b9)。

```c
DAC_DT_SPEC_GET(DT_DRV_INST(inst))
```

`DAC_DT_SPEC_INST_GET_BY_IDX(inst, idx)` 从指定实例按索引读取DAC通道信息，返回 `struct dac_dt_spec` 的静态初始化器，行为参见 [`DAC_DT_SPEC_GET_BY_IDX()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga23c61ff062c1745349b5ef5e8eee5454)。

```c
DAC_DT_SPEC_GET_BY_IDX(DT_DRV_INST(inst), idx)
```

`DAC_DT_SPEC_INST_GET_BY_IDX_OR(inst, idx, default_value)` 与上一宏相似，增加回退值。返回该属性的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`，行为参见 [`DAC_DT_SPEC_GET_BY_IDX_OR()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga0ca5cf0282575457b7d28de0a5851c80)。

```c
DAC_DT_SPEC_GET_BY_IDX_OR(DT_DRV_INST(inst), idx, default_value)
```

`DAC_DT_SPEC_INST_GET_BY_NAME(inst, name)` 从指定实例按名称读取DAC通道信息，返回 `struct dac_dt_spec` 的静态初始化器，行为参见 [`DAC_DT_SPEC_GET_BY_NAME()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga220c6d61ae537cefd98a0d912d0e62ab)。

```c
DAC_DT_SPEC_GET_BY_NAME(DT_DRV_INST(inst), name)
```

`DAC_DT_SPEC_INST_GET_BY_NAME_OR(inst, name, default_value)` 与上一宏相似，增加回退值。返回该属性的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`，行为参见 [`DAC_DT_SPEC_GET_BY_NAME_OR()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga07f89cc0df2630b44bcd01a99d60fd03)。

```c
DAC_DT_SPEC_GET_BY_NAME_OR(DT_DRV_INST(inst), name, default_value)
```

`DAC_DT_SPEC_INST_GET_OR(inst, default_value)` 为指定实例的索引0提供默认回退值。返回该属性的 `struct dac_dt_spec` 静态初始化器；节点或属性不存在时返回 `default_value`，行为参见 [`DAC_DT_SPEC_GET_OR()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gaa8e67bb9affd8a1016cf1aed6a36813b)。

```c
DAC_DT_SPEC_GET_OR(DT_DRV_INST(inst), default_value)
```

**译注：原文将最后一个宏的等价形式写成 `DAC_DT_SPEC_INST_GET_BY_IDX_OR(inst, 0, default)`；实际参数名是 `default_value`。**上面的原始展开式使用正确的参数名，可与官方头文件核对。

## 822.7\_物理电压转换函数类型

```c
typedef int (*dac_x_to_raw_fn)(uint32_t ref_mv, uint8_t resolution,
                             uint32_t *valp);
```

此函数指针类型（Function Pointer Type）定义从指定输入单位转换到DAC原始码值（Raw DAC Value）的操作，即将物理电压（Physical Voltage）换算为原始输出值。

| 参数 | 含义 |
| --- | --- |
| `ref_mv` | 本次换算所用的参考电压（Reference Voltage），单位固定为毫伏（Millivolt，mV） |
| `resolution` | 输出绝对值所占的位数 |
| `valp` | 输入时指向物理电压值；转换成功后保存相应原始输出值；转换失败时原存储值保持不变 |

转换成功返回0。输入电压使用毫伏还是微伏，由具体转换函数决定；即使输入是微伏，`ref_mv` 仍以毫伏计。

## 822.8\_配置通道

```c
int dac_channel_setup(const struct device *dev,
                      const struct dac_channel_cfg *channel_cfg);
```

配置DAC通道。**每个通道在被选中执行写请求之前，都必须先调用本函数完成配置。**`dev` 指向驱动实例的设备结构，`channel_cfg` 为通道配置。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-EINVAL` | 传入的某个参数值无效 |
| `-ENOTSUP` | 不支持所请求的分辨率 |

```c
static inline int dac_channel_setup_dt(const struct dac_dt_spec *spec);
```

[`dac_channel_setup_dt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gadde628b52a3579003f63b2480ac9254b) 使用 `struct dac_dt_spec` 配置通道，`spec` 为来自设备树的DAC规格。返回 [`dac_channel_setup()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gab8be77003ba8fd7225c0808f95602a56) 的结果；设备树信息无效时返回 `-ENOTSUP`。调用和返回约定参见上面的直接配置函数。

## 822.9\_设备就绪检查

```c
static inline bool dac_is_ready_dt(const struct dac_dt_spec *spec);
```

验证DAC设备是否就绪（Ready）。`spec` 为来自设备树的DAC规格；设备可用时返回 `true`，否则返回 `false`。

**译注：当前官方头文件的实现还检查 `spec->channel_cfg_dt_node_exists`。**只有配置节点存在且 `device_is_ready(spec->dev)` 为真时才返回真，不能只依据设备指针存在便认定该规格可用。

## 822.10\_微伏转换为原始码值

```c
static inline int dac_microvolts_to_raw(uint32_t ref_mv, uint8_t resolution,
                                       uint32_t *valp);
```

将微伏（Microvolt，µV）值转换为DAC原始码值。参数与返回约定见 [`dac_x_to_raw_fn`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga227ead59c9e4ea4b43b69b2bdd5af6c9)：`ref_mv` 为毫伏参考电压，`resolution` 为位数，`valp` 输入微伏值并在成功时改写为原始码值，失败时保持原值；成功返回0。

```c
static inline int dac_microvolts_to_raw_dt(const struct dac_dt_spec *spec,
                                          uint32_t *valp);
```

利用 `struct dac_dt_spec` 中的信息进行微伏到原始码值的转换。输入参数 `spec` 是设备树DAC规格，`valp` 是输入／输出参数。返回 [`dac_microvolts_to_raw()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gacea77754e7d0ae6e244f14b7ab05e086) 的结果；设备树信息无效时返回 `-ENOTSUP`，参见上述转换函数。

**原文参数说明与译注：**原文把 `valp` 描述为“输入原始测量值，成功后得到相应微伏值；失败时保持原值”。这与函数名称、功能摘要及实现的转换方向相反。官方实现调用 `dac_x_to_raw_dt_chan(dac_microvolts_to_raw, spec, valp)`，实际应输入微伏值，成功后得到DAC原始码值。这里保留原说明的含义并明确指出矛盾，避免按反方向调用。

## 822.11\_毫伏转换为原始码值

```c
static inline int dac_millivolts_to_raw(uint32_t ref_mv, uint8_t resolution,
                                       uint32_t *valp);
```

将毫伏值转换为DAC原始码值。参数与返回约定见 [`dac_x_to_raw_fn`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga227ead59c9e4ea4b43b69b2bdd5af6c9)：`ref_mv` 为毫伏参考电压，`resolution` 为位数，`valp` 输入毫伏值并在成功时改写为原始码值，失败时保持原值；成功返回0。

```c
static inline int dac_millivolts_to_raw_dt(const struct dac_dt_spec *spec,
                                          uint32_t *valp);
```

利用 `struct dac_dt_spec` 中的信息进行毫伏到原始码值的转换。输入参数 `spec` 为设备树DAC规格，`valp` 为输入／输出参数。返回 [`dac_millivolts_to_raw()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#gaa266992a47b299804d37d713229eef42) 的结果；设备树信息无效时返回 `-ENOTSUP`，参见上述转换函数。

**原文参数说明与译注：**原文把 `valp` 描述为“输入原始测量值，成功后得到相应毫伏值；失败时保持原值”。同样与函数名称、摘要及实现方向相反。官方实现调用 `dac_x_to_raw_dt_chan(dac_millivolts_to_raw, spec, valp)`，实际输入为毫伏值，成功后的输出为DAC原始码值。

## 822.12\_写入单个输出值

```c
int dac_write_value(const struct device *dev, uint8_t channel, uint32_t value);
```

向DAC通道写入单个值。

| 参数 | 含义 |
| --- | --- |
| `dev` | 指向驱动实例设备结构的指针 |
| `channel` | 要使用的通道编号；支持广播的设备可在此使用 `DAC_CHANNEL_BROADCAST` |
| `value` | 要写入DAC输出寄存器（Output Register）的数据 |

成功返回0；参数值无效时返回 `-EINVAL`。

```c
static inline int dac_write_value_dt(const struct dac_dt_spec *spec,
                                     uint32_t value);
```

根据 `struct dac_dt_spec` 向DAC通道写入单个值。`spec` 为设备树DAC规格，`value` 为要写入DAC输出寄存器的数据。返回 [`dac_write_value()`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga437a6f6b2402cf2e2a2a689429663b4e) 的结果；设备树信息无效时返回 `-ENOTSUP`。配置与直接写入的要求仍适用。

## 822.13\_按设备树规格调用转换函数

```c
static inline int dac_x_to_raw_dt_chan(dac_x_to_raw_fn conv_func,
                                       const struct dac_dt_spec *spec,
                                       uint32_t *valp);
```

原文功能摘要为“将原始DAC值转换为任意输出单位”，参数说明如下：

| 参数及方向 | 原文含义 |
| --- | --- |
| `conv_func`，输入 | 转换为最终输出单位的函数 |
| `spec`，输入 | 来自设备树的DAC规格 |
| `valp`，输入／输出 | 输入时指向物理电压值，转换成功后保存对应原始输出值；转换失败则保持原存储值不变 |

原文返回值说明写为“来自 [`dac_x_to_raw_dt_chan`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga450f0f61564dfc503872a96e6eaac604) 的值；设备树信息无效时为 `-ENOTSUP`”，并要求参见 [`dac_x_to_raw_fn`](https://docs.zephyrproject.org/latest/doxygen/html/group__dac__interface.html#ga227ead59c9e4ea4b43b69b2bdd5af6c9)。

**译注：该摘要与 `valp`、函数指针类型的说明方向不一致，返回值文字还引用了自身。**当前官方实现先检查通道配置节点是否存在；不存在时返回 `-ENOTSUP`，否则执行并返回 `conv_func(spec->vref_mv, spec->channel_cfg.resolution, valp)` 的结果。因此，该包装函数提供设备树中的参考电压和分辨率，由 `conv_func` 将物理电压换算为原始码值，而不是反向换算。
