# 第305章\_I2C公共接口

原文：[group__i2c__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html)。读取日期：2026-10-13，`latest`。

## 305.1\_范围与术语

本页定义集成电路间总线（Inter-Integrated Circuit，I²C）控制器接口，自Zephyr 1.0提供，接口版本为1.0.0；声明来自 `zephyr/drivers/i2c.h`。

控制器（Controller）发起总线事务，目标设备（Target）响应其地址。下文起始条件（START）、停止条件（STOP）、重复起始条件（RESTART）保持总线术语；确认（Acknowledgement，ACK）与不确认（Negative Acknowledgement，NACK）描述接收方的响应。

相关分组包括[I²C驱动后端](P311_I2C驱动后端.md)、[I²C EEPROM目标设备](P313_I2CEEPROM目标接口.md)及[I²C模拟接口](P314_I2C模拟后端.md)。其中EEPROM为电可擦可编程只读存储器（Electrically Erasable Programmable Read-Only Memory）。

结构 [`i2c_dt_spec`](P306_I2C设备树描述.md) 保存完整设备树（Devicetree）I²C信息，[`i2c_msg`](P307_I2C消息结构.md) 表示一条消息，[`i2c_target_callbacks`](P308_I2C目标回调表.md) 保存目标设备应实现的回调，[`i2c_target_config`](P309_I2C目标配置.md) 描述支持目标接口的设备，[`i2c_device_state`](P310_I2C设备状态.md) 为设备状态提供I²C类别专用扩展。

## 305.3\_设备定义宏

<a id="ga47b9d476cc85d6f5b8081c73dd87064f"></a>

宏 `I2C_DEVICE_DT_DEFINE(node_id, init_fn, pm, data, config, level, prio, api, ...)` 与带去初始化版本类似，但不提供 `deinit_fn`：

```c
I2C_DEVICE_DT_DEINIT_DEFINE(node_id, init_fn, NULL, pm, data,   \
                            config, level, prio, api,           \
                            __VA_ARGS__)
```

<a id="ga831cf78c11ebfceb65315995504cb7fb"></a>

宏 `I2C_DEVICE_DT_DEINIT_DEFINE(node_id, init_fn, deinit_fn, pm, data, config, level, prio, api, ...)` 类似 [`DEVICE_DT_DEINIT_DEFINE()`](../device_reference/P001_设备模型公共接口.md#gaa53f7267950569df898b0e5362e6f583)，附加I²C专用处理。它定义实现I²C接口的设备，并根据统计配置 [`CONFIG_I2C_STATS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I2C_STATS) 的需要生成自定义设备状态容器和初始化函数封装。

```c
Z_I2C_DEVICE_STATE_DEFINE(Z_DEVICE_DT_DEV_ID(node_id));         \
Z_I2C_INIT_FN(Z_DEVICE_DT_DEV_ID(node_id), init_fn)             \
Z_DEVICE_DEFINE(node_id, Z_DEVICE_DT_DEV_ID(node_id),           \
                DEVICE_DT_NAME(node_id),                        \
                &UTIL_CAT(Z_DEVICE_DT_DEV_ID(node_id), _init),  \
                deinit_fn, Z_DEVICE_DT_FLAGS(node_id), pm, data,\
                config, level, prio, api,                       \
                &(Z_DEVICE_STATE_NAME(Z_DEVICE_DT_DEV_ID(node_id)).devstate), \
                __VA_ARGS__)
```

| 参数 | 含义 |
| --- | --- |
| `node_id` | 设备树节点标识符 |
| `init_fn` | 驱动初始化函数名，可为 `NULL` |
| `deinit_fn` | 驱动去初始化函数名，可为 `NULL` |
| `pm` | 电源管理（Power Management，PM）设备资源引用；不使用时为 `NULL` |
| `data` | 设备私有数据指针 |
| `config` | 驱动实例配置结构的地址 |
| `level` | 初始化级别，详见 [`SYS_INIT()`](../device_reference/P005_系统初始化接口.md#gaf507cc0613add8113c41896bd631254f) |
| `prio` | 所选级别内的初始化优先级，详见 [`SYS_INIT()`](../device_reference/P005_系统初始化接口.md#gaf507cc0613add8113c41896bd631254f) |
| `api` | 驱动接口函数结构的初始指针，可为 `NULL` |

<a id="gabfd94bccb99bd1a958cd8d7902b2072a"></a>

宏 `I2C_DEVICE_DT_INST_DEFINE(inst, ...)` 是匹配驱动兼容标识 `DT_DRV_COMPAT` 的实例版本；`inst` 由 `DT_DRV_INST(inst)` 换成节点标识符，其余参数传给非实例版本：

```c
I2C_DEVICE_DT_DEFINE(DT_DRV_INST(inst), __VA_ARGS__)
```

<a id="ga9c7a8248802760a2f9509e76377fb38a"></a>

宏 `I2C_DEVICE_DT_INST_DEINIT_DEFINE(inst, ...)` 是带去初始化参数的对应实例版本：

```c
I2C_DEVICE_DT_DEINIT_DEFINE(DT_DRV_INST(inst), __VA_ARGS__)
```

> 译注：原展开中的 `Z_I2C_*`、`Z_DEVICE_*` 是设备状态、初始化与设备对象生成的内部宏；[`UTIL_CAT`](../util_reference/P006_内部宏工具头文件参考.md#a7e7766e792d1638bfbbc9d0f328d3d0d) 拼接标识，[`DEVICE_DT_NAME`](../device_reference/P001_设备模型公共接口.md#gad864d7a50ee45285dacd68be1e5a49ce) 取得设备名。这里保留原展开，不将内部名称另作公共接口。

## 305.4\_实时输入输出设备定义

<a id="gac6e54447306bdf8cc085cb8169097465"></a>

实时输入/输出（Real-Time Input/Output，RTIO）用输入输出设备对象（I/O Device，iodev）表示提交目标。宏 `I2C_DT_INST_IODEV_DEFINE(name, inst)` 为总线上的设备树实例定义对象，`name` 是符号名，`inst` 是实例编号：

```c
I2C_DT_IODEV_DEFINE(name, DT_DRV_INST(inst))
```

<a id="ga304d3b906b5222a9b704f5b35641143d"></a>

宏 `I2C_DT_IODEV_DEFINE(name, node_id)` 为总线上指定设备树节点定义对象，`node_id` 是节点标识符。对象不必全局共享，但共享可节约少量内存。展开中的 `RTIO_IODEV_DEFINE` 定义对象，`i2c_iodev_api` 是I²C所用RTIO操作表。

```c
const struct i2c_dt_spec _i2c_dt_spec_##name =                          \
        I2C_DT_SPEC_GET(node_id);                                       \
RTIO_IODEV_DEFINE(name, &i2c_iodev_api, (void *)&_i2c_dt_spec_##name)
```

## 305.5\_设备树描述初始化

<a id="gabb3ae5225cea677f3f3b36e4477ed045"></a>

宏 `I2C_DT_SPEC_GET(node_id)` 从设备树读取总线和地址，展开为 [`i2c_dt_spec`](P306_I2C设备树描述.md) 静态初始化器（Static Initializer），`node_id` 是对应I²C设备节点。它根据节点位于I²C还是改进型集成电路间总线（Improved Inter-Integrated Circuit，I3C）上选择分支：

```c
{                                                               \
        COND_CODE_1(DT_ON_BUS(node_id, i3c),                    \
                    (I2C_DT_SPEC_GET_ON_I3C(node_id)),          \
                    (I2C_DT_SPEC_GET_ON_I2C(node_id)))          \
}
```

<a id="gafa81ab3407e8a1da368b729b31471af8"></a>

宏 `I2C_DT_SPEC_GET_ON_I2C(node_id)` 为I²C总线设备生成相应初始化内容：

```c
.bus = DEVICE_DT_GET(DT_BUS(node_id)),                          \
.addr = DT_REG_ADDR(node_id)
```

<a id="ga6479e2c8f807fc8c92646a87d1dcca84"></a>

宏 `I2C_DT_SPEC_GET_ON_I3C(node_id)` 为I3C总线上的I²C设备生成相应初始化内容：

```c
.bus = DEVICE_DT_GET(DT_BUS(node_id)),                          \
.addr = DT_PROP_BY_IDX(node_id, reg, 0)
```

<a id="ga2197cbc5122f0d8b2e0788113bcb5963"></a>

宏 `I2C_DT_SPEC_INST_GET(inst)` 为设备树实例提供同样的初始化器，等价于：

```c
I2C_DT_SPEC_GET(DT_DRV_INST(inst))
```

> 译注：原展开的 [`DT_ON_BUS`](../dt_node_reference/P001_设备树总线查询宏.md#gabe5eea44ff838c11dc5b75f9ec2a9317) 检查总线类型，`COND_CODE_1` 选择分支，[`DT_BUS`](../dt_node_reference/P001_设备树总线查询宏.md#ga1082d31ac2dafdf9e085d4c23f2169dc) 取得总线节点，[`DEVICE_DT_GET`](../device_reference/P001_设备模型公共接口.md#ga9a65996ce21f43acb7db061e23b48ec7) 取得设备，[`DT_REG_ADDR`](../dt_reg_reference/P001_设备树寄存器属性宏.md#gac6d8279c32351ced4c0ac7f32270974e) 读取寄存器地址，[`DT_PROP_BY_IDX`](../dt_property_reference/P001_设备树属性读取宏.md#ga52ad691ea4cae633ca702020e939d461) 按索引读取属性。

## 305.6\_显式总线与地址的输入输出设备

<a id="ga451d0877ad5f4c2e9601dc2db8644924"></a>

宏 `I2C_IODEV_DEFINE(name, _bus, _addr)` 为给定总线和目标地址定义iodev。`name` 为符号名，`_bus` 是I²C总线节点标识符，`_addr` 是目标地址。它同样不要求全局共享，共享可节约少量内存。`I2C_CAT2` 为标识拼接宏。

```c
const struct i2c_dt_spec I2C_CAT2(_i2c_dt_spec_, name) = {     \
        .bus = DEVICE_DT_GET(_bus),                                     \
        .addr = _addr,                                                  \
};                                                                      \
RTIO_IODEV_DEFINE(name, &i2c_iodev_api, (void *)&I2C_CAT2(_i2c_dt_spec_, name))
```

## 305.7\_速度编码与提取

<a id="ga0eda328bb70285895d09154f9a828040"></a>

宏 `I2C_SPEED_GET(cfg)` 从32位配置字 `cfg` 提取速度编码。展开中的 `I2C_SPEED_MASK` 是速度字段掩码，`I2C_SPEED_SHIFT` 是字段位移：

```c
(((cfg) & I2C_SPEED_MASK) \
>> I2C_SPEED_SHIFT)
```

<a id="ga6d64fdac5a2d9008e7856e670b3c4305"></a>

宏 `I2C_SPEED_SET(speed)` 将某个 `I2C_SPEED_*` 常量编码为配置字中的速度字段：

```c
(((speed) << I2C_SPEED_SHIFT) \
& I2C_SPEED_MASK)
```

## 305.9\_异步与目标设备回调

以下目标回调的 `config` 均指向本次寻址所对应设备的配置结构。原文中的“控制器调用”指驱动控制器对目标设备回调的分发。

<a id="ga590293ec0d90d3fb0d8cbfee097798fc"></a>

回调类型 [`i2c_callback_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga590293ec0d90d3fb0d8cbfee097798fc)：

```c
typedef void(* i2c_callback_t) (const struct device *dev, int result, void *data);
```

异步传输请求的完成回调。`dev` 是通知完成或出错的I²C设备，`result` 为结果：`0` 成功、负错误码失败；`data` 是请求者提供并传入回调的数据。

<a id="gaa7951f4de2a2c0a8d424781d0c35e447"></a>

回调类型 [`i2c_target_buf_read_requested_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#gaa7951f4de2a2c0a8d424781d0c35e447)：

```c
typedef int(* i2c_target_buf_read_requested_cb_t) (struct i2c_target_config *config, uint8_t **ptr, uint32_t *len);
```

开始读取设备时使用缓冲区的回调：总线准备好向该设备地址的读操作提供更多缓冲区数据时调用。`ptr` 指向保存返回数据缓冲区地址的位置，`len` 指向保存传输长度的位置；它们给出的缓冲区内容与长度将被传输。提供数据后返回 `0`，失败返回负错误码。成功后控制器继续响应后续读取，出错后忽略总线操作直到新的START。

<a id="gac8f543b0ef4bb853a4f6659d827022bc"></a>

回调类型 [`i2c_target_buf_write_received_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#gac8f543b0ef4bb853a4f6659d827022bc)：

```c
typedef void(* i2c_target_buf_write_received_cb_t) (struct i2c_target_config *config, uint8_t *ptr, uint32_t len);
```

写设备完成时调用。控制器在持续写操作中完成从源缓冲区向目标缓冲区接收数据后调用此回调。`ptr` 指向含有待传输数据的缓冲区，`len` 为数据长度；没有返回值。

<a id="ga36f28e4b6958cd065296bfd2663c223e"></a>

回调类型 [`i2c_target_error_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga36f28e4b6958cd065296bfd2663c223e)：

```c
typedef void(* i2c_target_error_cb_t) (struct i2c_target_config *config, enum i2c_error_reason error_code);
```

作为目标时检测到I²C错误的回调。在发往本设备的事务中发生总线错误、仲裁丢失或其他严重错误时调用；`error_code` 标识错误类型。没有返回值。

<a id="ga4cb0ae2cf41fc2105d1baa5e496e5dae"></a>

回调类型 [`i2c_target_read_processed_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga4cb0ae2cf41fc2105d1baa5e496e5dae)：

```c
typedef int(* i2c_target_read_processed_cb_t) (struct i2c_target_config *config, uint8_t *val);
```

继续读取设备时调用：总线准备好从该设备地址提供下一字节时，通过 `val` 所指位置返回下一字节，它将被发送。已提供数据返回 `0`，失败返回负错误码；成功则继续响应后续读取，失败则忽略总线操作直到新的START。

<a id="ga244264ecdbd51210728ee92dcbebbc87"></a>

回调类型 [`i2c_target_read_requested_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga244264ecdbd51210728ee92dcbebbc87)：

```c
typedef int(* i2c_target_read_requested_cb_t) (struct i2c_target_config *config, uint8_t *val);
```

开始读取设备时调用：总线完成针对本设备地址的读START后，通过 `val` 所指位置返回第一个数据字节，它将被发送。可以继续请求数据时返回 `0`，失败返回负错误码；成功后继续响应读取，失败后忽略总线操作直到新的START。

<a id="ga3c898d0bef364461a3502037cf3d40b0"></a>

回调类型 [`i2c_target_stop_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga3c898d0bef364461a3502037cf3d40b0)：

```c
typedef int(* i2c_target_stop_cb_t) (struct i2c_target_config *config);
```

在针对某个设备的START之后观察到STOP时调用。函数返回后控制器进入准备响应新START的状态，返回值被忽略。

> 译注：原页详细段落又写成“总线准备好提供更多读取数据时调用”，与本回调的STOP标题及简述不符。此处保留这一疑点，不将其混同于持续读取回调。

<a id="ga619db7eea1c4400adcbea5dddf5cf2c5"></a>

回调类型 [`i2c_target_write_received_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga619db7eea1c4400adcbea5dddf5cf2c5)：

```c
typedef int(* i2c_target_write_received_cb_t) (struct i2c_target_config *config, uint8_t val);
```

继续写入设备时，在控制器完成接收一个字节后调用，`val` 为收到的字节。可以接收更多数据时返回 `0`，失败返回负错误码。成功使控制器对**下一收到的字节**发ACK，出错使其发NACK。

<a id="ga4cd9be521a6c7d088f15b88400624e4e"></a>

回调类型 [`i2c_target_write_requested_cb_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga4cd9be521a6c7d088f15b88400624e4e)：

```c
typedef int(* i2c_target_write_requested_cb_t) (struct i2c_target_config *config);
```

开始写入设备时，在总线完成针对本设备地址的写START后调用。接受写入返回 `0`，失败返回负错误码。成功使控制器对下一收到的字节发ACK，失败使其发NACK。

## 305.10\_函数参数与结果约定

以下控制器传输函数的 `dev` 指向配置为控制器模式的I²C驱动实例；目标注册接口会另行注明目标模式。`spec` 为设备树I²C描述；`addr`、`dev_addr` 是总线上的目标地址；`start_addr` 是内部起始地址，`reg_addr` 是内部寄存器地址。数组和缓冲区长度均按各参数说明计数，字节数不等于消息条数。

错误码 `-EIO` 表示一般输入/输出（Input/Output，I/O）错误；其他返回条件在各函数旁列出。RTIO提交队列条目（Submission Queue Entry，SQE）用于描述待提交请求。

## 305.43\_i2c_transfer

<a id="ga2958e6fe92ffb17851052d5c9a5c058e"></a>

函数 [`i2c_transfer()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga2958e6fe92ffb17851052d5c9a5c058e) 的声明为：

```c
int i2c_transfer(const struct device * dev, struct i2c_msg * msgs, uint8_t num_msgs, uint16_t addr);
```

以控制器模式同步向另一个I²C设备执行通用传输；简单读写可用 [`i2c_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga935d1fdcbf9a40c9a673aa8977048ee7)、[`i2c_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#ga2cc5f49493dce89e128ccbfa9d6149a0)。`msgs` 是消息数组，**不得为NULL**；`num_msgs` 可为0，此时不传输。`addr` 为目标地址。成功返回 `0`，失败返回 `-EIO`。

并非所有驱动都支持全部分散/聚集事务（Scatter/Gather Transaction）。例如连续多个写缓冲区，有的驱动会合成一次事务，有的会逐片段发起独立写事务，两者行为不同；多消息限制还应参见 [`i2c_msg`](P307_I2C消息结构.md)。

分散/聚集事务的**最后一条消息隐含STOP**，即使未显式设置也一样，以便为下一次可能来自其他调用上下文的事务保持总线状态。

<a id="gab2a84398805e2be7662e9ae9cd4f9299"></a>

函数 [`i2c_xfer_stats()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i2c__interface.html#gab2a84398805e2be7662e9ae9cd4f9299) 的声明为：

```c
static inline void i2c_xfer_stats(const struct device * dev, struct i2c_msg * msgs, uint8_t num_msgs);
```

更新I²C传输统计。`dev` 为需要更新统计的I²C设备，`msgs` 为 [`i2c_msg`](P307_I2C消息结构.md) 数组，`num_msgs` 为数组中消息条数。没有返回值。
