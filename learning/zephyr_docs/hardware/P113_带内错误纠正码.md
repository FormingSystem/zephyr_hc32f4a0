# 第113章\_带内错误纠正码

原文：[In Band Error Correction Code (IBECC)](https://docs.zephyrproject.org/latest/hardware/peripherals/edac/ibecc.html)。读取日期：2026-10-13，`latest`。

## 113.1\_带内纠错与存储开销

**带内错误纠正码（In-Band Error Correction Code，IBECC）**最初出现在Intel Elkhart Lake **片上系统（System on Chip，SoC）**及后续开发板的集成内存控制器中。

IBECC通过检测和纠正错误提高可靠性，可覆盖整个物理内存空间或特定区域。对于不支持 **带外错误纠正码（Out-of-Band Error Correction Code，ECC）**的存储技术，IBECC尤其有用。

IBECC增加相当于内存容量1/32的存储开销。这部分内存不可访问，用于存放ECC **伴随式数据（Syndrome Data）**。IBECC把一次读写事务拆成两个独立事务：一个访问实际数据，另一个访问包含ECC值的 **缓存行（Cache Line）**。

调试功能 **错误注入（Error Injection）**可帮助调试和验证IBECC。ECC错误在写入路径注入，并在读取路径产生ECC错误。

## 113.2\_启动阶段选择运行模式

**引导加载程序（Bootloader）**可通过模式字段 `OPERATION_MODE` 选择以下三种运行模式：

| 模式字段值 | 保护策略 |
| --- | --- |
| `0x0` | 按地址范围决定是否保护请求。 |
| `0x1` | 所有请求都不受保护，并忽略范围检查。 |
| `0x2` | 保护所有请求，并忽略范围检查。 |

IBECC运行模式通过 **基本输入输出系统（Basic Input/Output System，BIOS）**或引导加载程序配置。模式0还有内存区域等额外BIOS配置项。

原文强调：错误注入能力具有较高安全风险，**不应在生产环境启用**；只在测试中启用。

## 113.3\_错误记录与上层策略

IBECC记录 **错误地址（Error Address）**、**错误伴随式（Error Syndrome）**和 **错误类型（Error Type）**。错误类型分为：

- **可纠正错误（Correctable Error，CE）**：IBECC模块已检测并纠正错误。
- **不可纠正错误（Uncorrectable Error，UE）**：IBECC模块已检测到错误，但未自动纠正。

驱动向上层应用提供错误类型，由应用实施所需的内存错误处理策略。驱动自身不使用错误伴随式，但会将它提供给上层应用。

## 113.4\_不可屏蔽中断中的同步限制

使用 **不可屏蔽中断（Non-Maskable Interrupt，NMI）**时必须特别谨慎。即使本地 **中央处理器（Central Processing Unit，CPU）**已关闭中断，NMI仍可能随时到达，因此不能靠普通锁阻止NMI打断受保护代码。

Zephyr的 **进程间通信（Inter-Process Communication，IPC）**机制普遍使用本地 **中断请求（Interrupt Request，IRQ）**锁定作为上层同步原语的基础。因而，不能仅凭普通锁“保护”一个对象，就把它与NMI处理程序共享；这种保护对NMI不起作用。

原文指出：Zephyr **应用程序编程接口（Application Programming Interface，API）**中，能够针对NMI实现同步的工具是 **原子操作层（Atomic Layer）**。这一限制同样适用于NMI处理程序调用的 **回调函数（Callback Function）**。

## 113.5\_配置项

相关Kconfig配置项为 [`CONFIG_EDAC_IBECC`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_EDAC_IBECC)；Kconfig是Zephyr配置系统。
