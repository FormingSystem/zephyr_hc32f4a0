# 第84章\_I2S回声示例

原文：[I2S echo](https://docs.zephyrproject.org/latest/samples/drivers/i2s/echo/README.html)。读取日期：2026-10-13，`latest`。

## 84.1\_用延迟信号产生回声

本示例演示 **芯片间声音总线（Inter-IC Sound，I2S）**驱动的简单音频流处理：配置并启动 **接收（Receive，RX）**和 **发送（Transmit，TX）**两条流，把原信号与缓冲后的延迟信号混合，产生简单的 **回声效果（Echo Effect）**。

## 84.2\_编解码器和设备树

示例使用WM8731 **音频编解码器（Audio Codec）**，例如Audio Codec Shield上就有该器件；原文说明也可以适配其他编解码器。若收发共用一个I2S设备，定义设备树节点标签 `i2s_rxtx`；若收发使用不同I2S设备，分别定义 `i2s_rx`、`i2s_tx`。

官方报告使用Audio Codec Shield在nRF52840 DK（`nrf52840dk/nrf52840`）和nRF5340 DK（`nrf5340dk/nrf5340/cpuapp`）测试，并提供两块板的 **覆盖文件（Overlay）**。还为MAX32690EVKIT（`max32690evkit/max32690/m4`）提供使用板载MAX9867编解码器的配置。

原文扩展资料为[Audio Codec Shield](http://wiki.openmusiclabs.com/wiki/AudioCodecShield)和[WM8731产品说明](https://www.cirrus.com/products/wm8731/)。这些器件名称和板名保留原样，不代表可以忽略实际引脚、时钟与驱动差异。

## 84.3\_Nordic板分支

官方源码位于 `samples/drivers/i2s/echo`。先准备Zephyr环境、对应工具链、烧录工具和实际音频接线；从实验Zephyr源码根目录，在Ubuntu Bash或已准备好的UCRT64 Bash中执行：

```shell
west build -b nrf52840dk/nrf52840 samples/drivers/i2s/echo
west flash
```

构建成功后烧录。在Nordic板上，按Button 1切换回声效果，按Button 2停止音频流。构建或设备初始化失败时应返回板目标、覆盖文件和驱动配置检查，而不是先排查回声算法。

## 84.4\_MAX32690EVKIT分支

将JP9和JP10跳线设为2—3位置，音源连接到 `LINE_IN` 线路输入插孔，耳机连接到 `HD_PHONE` 耳机插孔。准备该板对应工具后，在实验Zephyr源码根目录执行另一组构建、烧录命令：

```shell
west build -b max32690evkit/max32690/m4 samples/drivers/i2s/echo
west flash
```

切换板时应使用独立构建目录，或按构建章节清理旧目标配置。运行后按SW2切换回声效果；**此板不提供流停止／重新启动控制**，不能照搬Nordic板的Button 2操作。

相关 **应用程序编程接口（Application Programming Interface，API）**见[I2S参考](https://docs.zephyrproject.org/latest/doxygen/html/group__i2s__interface.html)。本次没有设置跳线、播放音频、烧录或验证任一板的按键行为。
