# 第74章\_脉冲输入输出

原文：[Pulse IO](https://docs.zephyrproject.org/latest/hardware/peripherals/pulse_io.html)。读取日期：2026-10-13，`latest`。

## 74.1\_脉冲边沿硬件的统一接口

**脉冲输入／输出（Pulse Input/Output，Pulse IO）**子系统提供与厂商无关的 **应用程序编程接口（Application Programming Interface，API）**，面向在单根 **通用输入／输出（General-Purpose Input/Output，GPIO）**线上生成、捕获带时间信息的数字边沿的硬件。

多个 **微控制器（Microcontroller Unit，MCU）**系列以不同名称提供这种专用外设。Pulse IO统一这类硬件，使可寻址 **发光二极管（Light-Emitting Diode，LED）**灯带、红外收发、步进电机脉冲生成、频率／占空比测量及单线类协议等客户端驱动，只需适配一次，即可运行在提供后端的 **片上系统（System on Chip，SoC）**上。

相关Kconfig配置项为 [`CONFIG_PULSE_IO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_PULSE_IO)；Kconfig是Zephyr配置系统。

## 74.2\_两种提交模式

通道在配置时固定为一种 **提交模式（Submission Mode）**，所选模式必须属于后端报告的能力。

`PULSE_IO_MODE_SYMBOL` 是 **符号模式（Symbol Mode）**。应用提交 [`pulse_symbol`](https://docs.zephyrproject.org/latest/doxygen/html/structpulse__symbol.html) 数组，每个元素明确携带一个电平与持续时间，时间单位为所配置分辨率下的tick。连续符号可具有任意、互不相关的持续时间，适合一条数据流中边沿长度变化的协议，例如红外遥控、单线协议和步进电机加速过程。

`PULSE_IO_MODE_CELL` 是 **周期单元模式（Cell Mode）**。应用提交 [`pulse_cell`](https://docs.zephyrproject.org/latest/doxygen/html/structpulse__cell.html) 数组，每个单元具有相同周期，周期在通道配置时设置一次；单元携带该周期内的电平或占空比。它适合只有每周期电平／占空比变化的周期流，例如可寻址LED的比特波形或可变占空比 **脉宽调制（Pulse Width Modulation，PWM）**。在这些场景下，cell比symbol节约内存。

后端通过 [`pulse_io_caps`](https://docs.zephyrproject.org/latest/doxygen/html/structpulse__io__caps.html) 能力结构报告支持的模式。请求不支持的模式时，[`pulse_io_channel_configure()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#gaa3a5b31cb44647823aa60af4416e6d3f) 返回 `-ENOTSUP`，表示不支持。

## 74.3\_配置、传输与字节编解码

客户端在探测阶段调用 [`pulse_io_get_capabilities()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga3d92ae937058d0675dd56b009aa1138f)，决定采用的模式和功能集；随后通过 [`pulse_io_channel_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga0a0eb57e852853da9c3ba1e262991091) 预留通道，并在任何传输前调用 [`pulse_io_channel_configure()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#gaa3a5b31cb44647823aa60af4416e6d3f) 配置通道。

阻塞传输使用 [`pulse_io_transmit_sync()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga3e03e72bb73c8949c222d48f28c03612) 和 [`pulse_io_receive_sync()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga1d122c085430f9d4408564b76dee0944)；异步与流式传输使用下一节的RTIO路径。

字节到符号的辅助函数 [`pulse_io_encode_bytes()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#gaca42826a8404d4e5e1eacefc5f17debf) 及其逆向函数 [`pulse_io_decode_bytes()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga05add5c7dc934ad84ddafbfe4c08d2a6)，按每一位的模板在协议字节流与脉冲符号之间转换。编码模板决定如何将比特表示为电平和持续时间，不能把协议字节缓冲区直接视为已编码的符号数组。

## 74.4\_可选的实时I/O集成

后端可以选择与 **实时输入／输出（Real Time I/O，RTIO）**集成，提供 `iodev` 设备提交路径，以及通过 [`pulse_io_get_encoder()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#gaf925af6fa08b119550e51024c5ebc408) 和 [`pulse_io_get_decoder()`](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html#ga382adc1d7095dba8dd087c47c551436c) 获得的编码器、解码器 **函数表（Vtable）**。RTIO框架说明见[官方入口](https://docs.zephyrproject.org/latest/services/rtio/index.html#rtio)。

客户端先把载荷编码到符号缓冲区，通过RTIO队列提交，再解码捕获到的响应。由此可获得排队与链式传输、流式接收，以及RTIO框架提供的用户空间路径。

RTIO操作是可选的。未实现它们的后端把相应驱动API成员设为 `NULL`，相应访问函数返回 `-ENOSYS`，表示功能未实现。这与上一节选择了不受支持模式时的 `-ENOTSUP` 属于不同条件。

## 74.5\_接口与示例

完整声明见[Pulse IO接口参考](https://docs.zephyrproject.org/latest/doxygen/html/group__pulse__io__interface.html)。[pulse_io字节传输示例](../driver_samples/P041_脉冲IO字节传输示例.md#pulse_io_byte_transfer)演示借助编解码辅助函数，通过Pulse IO控制器传输字节。本页未执行脉冲输出、信号捕获或外设配置。
