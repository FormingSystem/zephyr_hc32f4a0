# 第90章\_伪比较器接口

原文：[group__comparator__fake](https://docs.zephyrproject.org/latest/doxygen/html/group__comparator__fake.html)。读取日期：2026-10-13，`latest`。

## 90.1\_测试用伪比较器

本驱动是 **比较器（Comparator）** **应用程序编程接口（Application Programming Interface，API）**的 **伪函数框架（Fake Function Framework，FFF）**实现，用于测试。通过Kconfig配置项 [`CONFIG_COMPARATOR_FAKE_COMP`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_COMPARATOR_FAKE_COMP) 启用，并从设备树 `zephyr,fake-comp` 节点实例化；Kconfig是Zephyr配置系统。官方头文件为 `zephyr/drivers/comparator/fake_comp.h`。

每个伪函数都对应一个控制结构，名称是在函数名后加 `_fake`。测试用它设置返回值、安装自定义伪函数、检查调用次数及捕获参数。这些控制结构未在原页中独立列出，细节见[通过FFF模拟（Mocking via FFF）](https://docs.zephyrproject.org/latest/develop/test/ztest.html#mocking-fff)。

## 90.2\_返回值与每用例重置

只报告状态的伪函数可以使用 `return_val` 设置返回值；带输出参数的伪函数必须用 `custom_fake` 驱动输出，因为 `return_val` 不会修改输出参数。这是原页对FFF使用方式的说明，不能把返回成功等同于已模拟全部设备行为。

启用Kconfig配置项 [`CONFIG_ZTEST`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ZTEST) 时，Zephyr测试框架ztest的规则会在每个测试用例之前重置全部伪函数。自定义测试状态不应依赖上一个用例遗留的数据。

## 90.3\_取得输出的测试片段

下面是官方测试片段，仅清理网页代码展示中的行末空格：通过设备树节点标签 `fake_comp` 取得伪设备，让输出查询返回1，再验证公共接口结果、调用次数和设备参数。[`DEVICE_DT_GET()`](../device_reference/P001_设备模型公共接口.md#ga9a65996ce21f43acb7db061e23b48ec7) 取得设备引用，[`DT_NODELABEL()`](../dt_identity_reference/P001_设备树节点标识宏.md#gab7d23294a6bf7fd44a98b48ec47d8a79) 由标签取得节点标识，[`zassert_equal()`](P503_ZTest断言宏.md) 断言两值相等。

```c
const struct device *dev = DEVICE_DT_GET(DT_NODELABEL(fake_comp));

comp_fake_comp_get_output_fake.return_val = 1;

zassert_equal(1, comparator_get_output(dev));
zassert_equal(1, comp_fake_comp_get_output_fake.call_count);
zassert_equal(dev, comp_fake_comp_get_output_fake.arg0_val);
```

控制结构 `comp_fake_comp_get_output_fake` 的 `return_val` 设置返回值，`call_count` 记录调用次数，`arg0_val` 记录第一个参数。这里的1是测试预设的高输出状态，不是对实际比较器引脚测量的结果。
