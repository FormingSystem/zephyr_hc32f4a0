# 第394章\_I3C传输接口

原文：[group__i3c__transfer__api](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html)。读取日期：2026-10-13，`latest`。

## 394.1\_接口与配置前提

本页提供**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）**传输接口。控制器通过 `struct i3c_device_desc` 描述的**目标设备（Target Device）**发起传输，消息由[结构体 [`i3c_msg`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__msg.html)](P395_I3C传输消息.md)描述。包含头文件 `zephyr/drivers/i3c.h`。

本页全部函数都要求启用 Kconfig 配置项 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。异步回调传输函数 [`i3c_transfer_cb()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga354eb19c5134f1a4df291005d0f6622a) 还要求启用 Kconfig 配置项 [`CONFIG_I3C_CALLBACK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CALLBACK)。

## 394.2\_消息标志

消息可以指定读写方向、**停止条件（Stop Condition，STOP）**与**重复起始条件（Repeated Start Condition，RESTART）**。**高数据速率（High Data Rate，HDR）**标志选择高速传输；**否定应答（Negative Acknowledgement，NACK）**表示目标未确认传输。

| 宏 | 值 | 含义 |
| --- | --- | --- |
| [`I3C_MSG_WRITE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga72f9fb65d218521ad006febf3dd6851b) | `(0U << 0U)` | 向 I3C 总线写消息。 |
| [`I3C_MSG_READ`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga6ba89782a8646f96dc1f9fa3b9cd2058) | `BIT(0)` | 从 I3C 总线读消息。 |
| [`I3C_MSG_STOP`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga0d4ae269a53af945837d158f638d8b5c) | `BIT(1)` | 在此消息之后发送 STOP。 |
| [`I3C_MSG_RESTART`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gad9ff03f4fdcb117b90c17d667a49c295) | `BIT(2)` | 对此消息重新开始 I3C 事务。 |
| [`I3C_MSG_HDR`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gad827935caf8503aeaedd1aceb53d4e38) | `BIT(3)` | 使用 HDR 模式传输。 |
| [`I3C_MSG_NBCH`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga4147e7cdf8155d2ef7c4dc7c08e16b6a) | `BIT(4)` | 跳过 I3C 广播头，仅用于私有传输（Private Transfer）。 |
| [`I3C_MSG_NOACK_EXPECTED`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga735a347b1d0f431ab0c3a90f509fcbe1) | `BIT(5)` | 预期目标设备将返回 NACK。 |

`I3C_MSG_RESTART` 的支持依赖驱动。不是所有驱动都具备或需要显式支持；部分驱动要求在写后读或读后写时，为后一个消息设置此标志。有些驱动利用该标志把相邻片段合并成一个事务，有些驱动不会这样处理。

## 394.4\_公共参数与返回值

本页数据传输函数的 `target` 参数均为 I3C 目标设备描述符。除输出消息的 [`i3c_dump_msgs()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga61098371d2492a3f35c0fa779a88b348) 外，各函数均列出以下结果；同步通用传输还有一个额外返回值，见下一节。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功。 |
| `-EBUSY` | 总线忙。 |
| `-EIO` | 通用输入/输出（Input/Output，I/O）错误。 |

## 394.5\_同步通用传输

```c
int i3c_transfer(struct i3c_device_desc *target,
                  struct i3c_msg *msgs, uint8_t num_msgs);
```

<a id="ga067c0f1e3c9abb6ef34ce48cb7e45cb8"></a>

[`i3c_transfer()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga067c0f1e3c9abb6ef34ce48cb7e45cb8) 提供同步数据传输的通用接口。简单读取或写入可直接使用 [`i3c_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaba39bd08ab50c5737ba617f4d27c3541)、[`i3c_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaa3b61aa9813ccb0df80562b0829d95dd)。

`msgs` 是待传输消息的数组，不能为 `NULL`。`num_msgs` 是消息数量，可以为 0，此时不发生传输。

并非所有驱动都支持全部**分散/聚集（Scatter/Gather）**事务。例如，把多个连续 [`i3c_msg`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__msg.html) 缓冲区都配置为 [`I3C_MSG_WRITE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga72f9fb65d218521ad006febf3dd6851b) 的聚集写操作，可能被某些驱动打包为单个事务，也可能被其他驱动拆成各片段独立的写事务；二者行为不同。多消息总线事务的限制见[传输消息结构](P395_I3C传输消息.md)。

除公共返回值外，当消息设置了 `I3C_MSG_NOACK_EXPECTED`，且目标对传输返回 NACK 时，返回 `-ENODATA`。

## 394.6\_异步回调传输

```c
int i3c_transfer_cb(struct i3c_device_desc *target,
                     struct i3c_msg *msgs, uint8_t num_msgs,
                     i3c_callback_t cb, void *userdata);
```

`i3c_transfer_cb()` 提供从控制器到目标设备的异步传输（Asynchronous Transfer），并使用**完成回调（Completion Callback）**。`msgs` 不能为 `NULL`；消息数量 `num_msgs` 可以为 0，此时不发生传输。

`cb` 是完成回调函数指针，`userdata` 是传给回调的用户数据。该函数还要求启用 `CONFIG_I3C_CALLBACK`。

同步接口中有关分散/聚集事务的驱动限制同样适用于此函数：连续写片段可能被合并为一次事务，也可能分开处理，不能假定行为一致。原页面列出的返回值为 0、`-EBUSY` 和 `-EIO`。

## 394.7\_简单同步读写

```c
static inline int i3c_write(struct i3c_device_desc *target,
                            const uint8_t *buf, uint32_t num_bytes);
static inline int i3c_read(struct i3c_device_desc *target,
                           uint8_t *buf, uint32_t num_bytes);
```

[`i3c_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaa3b61aa9813ccb0df80562b0829d95dd) 同步向目标设备写入指定数量的数据。`buf` 指向数据来源内存，`num_bytes` 为待写字节数。

[`i3c_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaba39bd08ab50c5737ba617f4d27c3541) 同步从目标设备读出指定数量的数据。`buf` 指向保存读取结果的内存，`num_bytes` 为待读字节数。两者均使用本页公共返回值。

## 394.8\_组合写后读

```c
static inline int i3c_write_read(struct i3c_device_desc *target,
                                 const void *write_buf, size_t num_write,
                                 void *read_buf, size_t num_read);
```

[`i3c_write_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga3da2e99b667eab4fd92f5c0e1b57a8ea) 通过一次组合写后读总线事务（Write-then-read Bus Transaction），支持“这是我要的内容”“现在把它给我”的成对操作。

`write_buf` 指向待写数据，`num_write` 为待写字节数；`read_buf` 指向读取结果的存储区，`num_read` 为待读字节数。返回值使用公共约定。

## 394.9\_从内部地址连续读写

```c
static inline int i3c_burst_read(struct i3c_device_desc *target,
                                 uint8_t start_addr, uint8_t *buf,
                                 uint32_t num_bytes);
static inline int i3c_burst_write(struct i3c_device_desc *target,
                                  uint8_t start_addr, const uint8_t *buf,
                                  uint32_t num_bytes);
```

两个函数均同步完成操作，`start_addr` 是目标设备内部地址，`num_bytes` 是传输字节数，返回值遵循公共约定。

[`i3c_burst_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga3e4d985a784618efad67f8550f715115) 从指定内部地址读取多个字节，`buf` 用于存放读出数据；这种调用也可以由 [`i3c_write_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga3da2e99b667eab4fd92f5c0e1b57a8ea) 替代。

[`i3c_burst_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaee773f95fcaf6cb88ced47f5c512c78c) 从指定内部地址写入多个字节，`buf` 提供待写数据。不是所有 I3C 设备都支持此接口合成的组合写操作。要提高可移植性，可把内部地址和数据组合到一个缓冲区，再调用 `i3c_write()`。

## 394.10\_读取与写入单字节寄存器

```c
static inline int i3c_reg_read_byte(struct i3c_device_desc *target,
                                    uint8_t reg_addr, uint8_t *value);
static inline int i3c_reg_write_byte(struct i3c_device_desc *target,
                                     uint8_t reg_addr, uint8_t value);
```

[`i3c_reg_read_byte()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga87c1f23c94d37dfbaa22e4679fb8130a) 同步读取目标设备的一个 8 位内部寄存器。`reg_addr` 是寄存器地址，`value` 指向保存读取值的位置。

[`i3c_reg_write_byte()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#gaf7033eb93fd3779ffa98eb83e5a1a1b1) 同步写入一个 8 位内部寄存器。`reg_addr` 是寄存器地址，`value` 是待写入的值。此函数在内部把寄存器地址和值合并为单次总线事务。

两者均返回公共约定的结果。

## 394.11\_按位更新单字节寄存器

```c
static inline int i3c_reg_update_byte(struct i3c_device_desc *target,
                                      uint8_t reg_addr, uint8_t mask,
                                      uint8_t value);
```

[`i3c_reg_update_byte()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__transfer__api.html#ga4e0488ff21cbe99b206c115017473ed9) 同步更新目标设备一个 8 位内部寄存器中的一组位。`reg_addr` 指定寄存器地址，`mask` 是更新位掩码（Bit Mask），`value` 是更新用的值。

如果计算出的新寄存器值与读取值相同，此函数不会发起写操作。返回值遵循公共约定。

## 394.12\_输出消息内容

```c
void i3c_dump_msgs(const char *name, const struct i3c_msg *msgs,
                   uint8_t num_msgs, struct i3c_device_desc *target);
```

`i3c_dump_msgs()` 输出一组 I3C 消息。写消息以 `W`（Write）标识，并以十六进制显示数据。

| 参数 | 含义 |
| --- | --- |
| `name` | 此次输出的名称，显示在顶部。 |
| `msgs` | 待输出的消息数组。 |
| `num_msgs` | 待输出的消息数量。 |
| `target` | I3C 目标设备描述符。 |

以下是名称为 `testing` 时的官方日志示例；`D:` 是日志前缀，`addr` 是地址，`len` 是长度，`contents` 标识后续数据内容：

```text
D: I3C msg: testing, addr=56
D:    W len=01:
D: contents:
D: 06                      |.
D:    W len=0e:
D: contents:
D: 00 01 02 03 04 05 06 07 |........
D: 08 09 0a 0b 0c 0d       |......
```
