# 第389章\_I3C目标设备回调表

原文：[structi3c__target__callbacks](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html)。读取日期：2026-10-13，`latest`。

## 389.1\_总线事件与回调

`struct i3c_target_callbacks` 定义**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）目标设备（Target Device）**收到总线事件时的**回调函数（Callback Function）**。包含头文件 `zephyr/drivers/i3c/target_device.h`。

所有回调的 `config` 参数均指向当前操作所寻址设备的配置结构 `struct i3c_target_config`。

以下**起始条件（Start Condition）**与**停止条件（Stop Condition）**指总线事务的开始与结束信号；**确认应答（Acknowledgement，ACK）**表示接受，**否定应答（Negative Acknowledgement，NACK）**表示拒绝。回调中的控制器指调用这些函数的控制器驱动。

## 389.2\_逐字节写入

```c
int (*write_requested_cb)(struct i3c_target_config *config);
int (*write_received_cb)(struct i3c_target_config *config, uint8_t val);
```

[`write_requested_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#ad9e51587a8f86f08d065071d28241ee2) 在开始向设备写入时调用：总线完成一个面向该设备地址的写操作起始条件后，控制器调用它。返回 0 表示接受写入，负数表示错误。成功返回使控制器对下一个收到的字节作 ACK 应答；错误返回使其对下一个字节作 NACK 应答。

[`write_received_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#a7288f143d19ad306616e25e68ffedc03) 在向设备持续写入时调用：控制器在当前写操作中接收完一个字节后调用它。`val` 是控制器收到的字节。返回 0 表示还能接受更多数据，负数表示错误；成功/错误同样分别使控制器对下一个收到的字节作 ACK/NACK 应答。

## 389.3\_逐字节读取

```c
int (*read_requested_cb)(struct i3c_target_config *config, uint8_t *val);
int (*read_processed_cb)(struct i3c_target_config *config, uint8_t *val);
```

[`read_requested_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#ac72e0bab1eeff6995983f90f6d934749) 在开始从设备读取时调用：总线完成一个面向该设备地址的读操作起始条件后，控制器调用它。`val` 指向用于写出首个数据字节的存储位置；通过它写出的值将被发送。返回 0 表示可以继续请求数据，负数表示错误。

[`read_processed_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#ae53661cfa98a3b58a9702fef28234c30) 在从设备继续读取时调用：总线已经可以为当前地址的读操作提供更多数据时，控制器调用它。`val` 指向用于写出下一个数据字节的存储位置。返回 0 表示已提供数据，负数表示错误。

两个回调均遵循同一后续处理规则：成功返回使控制器继续响应读操作；错误返回使控制器忽略总线操作，直到收到新的起始条件。

## 389.4\_按缓冲区写入

以下缓冲区回调仅在启用 Kconfig 配置项 [`CONFIG_I3C_TARGET_BUFFER_MODE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_TARGET_BUFFER_MODE) 时可用。

```c
void (*buf_write_received_cb)(struct i3c_target_config *config,
                              uint8_t *ptr, uint32_t len);
```

[`buf_write_received_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#abaf52fa6a2189b9e03728a4ae38e66e8) 在写入设备的操作完成时调用。控制器在当前设备写操作中完成从源缓冲区向目标缓冲区的数据接收后，调用此函数。

`ptr` 指向包含传输数据的缓冲区，`len` 为传输数据长度。回调没有返回值。

## 389.5\_按缓冲区读取

```c
int (*buf_read_requested_cb)(struct i3c_target_config *config,
                             uint8_t **ptr, uint32_t *len,
                             uint8_t *hdr_mode);
```

[`buf_read_requested_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#a9b7ae83ecc4671ea509b4b6f9d01f614) 在开始从设备读取时调用：总线准备好通过缓冲区为设备地址的读操作提供更多数据时，控制器调用它。此回调也仅在启用 Kconfig 配置项 [`CONFIG_I3C_TARGET_BUFFER_MODE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_TARGET_BUFFER_MODE) 时可用。

| 参数 | 含义 |
| --- | --- |
| `config` | 当前寻址设备的配置结构。 |
| `ptr` | 指向存储位置的指针，回调用该位置写出读请求的数据缓冲区地址。 |
| `len` | 指向存储位置的指针，回调用该位置写出待读取的数据长度。 |
| `hdr_mode` | 高数据速率（High Data Rate，HDR）模式。 |

原文称返回在 `**ptr` 与 `*len` 中的值将被发送。成功返回使控制器继续响应读操作；错误返回使控制器忽略总线操作，直到收到新的起始条件。提供数据后返回 0，否则返回负数错误码。

> 译注：根据参数表，`ptr` 的用途是写出缓冲区地址，即回调通过 `*ptr` 提供地址，`*len` 提供长度。原文的 `**ptr` 指向数据字节，不应据此把双重指针参数误当成只返回一个字节。

## 389.6\_停止事件

```c
int (*stop_cb)(struct i3c_target_config *config);
```

[`stop_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#a15a1bacdd10c0d6803fbd24f1a1a3323) 的概要规定：在出现过面向某设备的起始条件之后，观察到停止条件时调用此函数。返回后，控制器应进入准备响应新起始条件的状态。返回值被忽略。

> 译注：原详细说明还写道“总线准备好为设备地址的读操作提供更多数据时，控制器调用此函数”，这与该字段的停止条件概要不一致，且重复了读取回调的表述。这里保留这一差异；不能据此把停止回调理解成提供下一字节的读取回调。

## 389.7\_控制权移交事件

```c
int (*controller_handoff_cb)(struct i3c_target_config *config);
```

当前活动控制器把控制权移交（Controller Handoff）给此目标设备时，调用 [`controller_handoff_cb`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__target__callbacks.html#a1e92d1a9bd94b0ef3930bc692764721f)。这种移交既可能由目标设备请求，也可能由活动控制器主动选择一个具备控制器能力的目标设备。返回值被忽略。
