# 第396章\_I3C带内中断接口

原文：[group__i3c__ibi](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html)。读取日期：2026-10-13，`latest`。

## 396.1\_带内事件与相关类型

**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）**支持**带内中断（In-Band Interrupt，IBI）**，通过总线传递中断请求。本页涉及[请求结构](P397_I3C带内中断请求.md) `struct i3c_ibi`、[载荷结构](P398_I3C带内中断载荷.md) `struct i3c_ibi_payload` 和[排队工作项](P399_I3C带内中断工作项.md) `struct i3c_ibi_work`。

**目标设备（Target Device）**可能请求中断、申请成为控制器，或请求**热加入（Hot Join，HJ）**。原枚举定义如下：

```c
enum i3c_ibi_type {
    I3C_IBI_TARGET_INTR,
    I3C_IBI_CONTROLLER_ROLE_REQUEST,
    I3C_IBI_HOTJOIN,
    I3C_IBI_TYPE_MAX = I3C_IBI_HOTJOIN,
    I3C_IBI_WORKQUEUE_CB
};
```

| 枚举项 | 含义 |
| --- | --- |
| [`I3C_IBI_TARGET_INTR`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ggaf4be72fc9c862d996d860c0b7fbc862ba368e8ad08a003ebf197add6d73ffd43d) | 目标中断。 |
| [`I3C_IBI_CONTROLLER_ROLE_REQUEST`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ggaf4be72fc9c862d996d860c0b7fbc862ba00235d326559f945d54638b0c0558815) | 控制器角色请求（Controller Role Request，CRR）。 |
| [`I3C_IBI_HOTJOIN`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ggaf4be72fc9c862d996d860c0b7fbc862ba493d3b1e9669434c3d62f16aa3d6f92f) | 热加入请求。 |
| [`I3C_IBI_TYPE_MAX`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ggaf4be72fc9c862d996d860c0b7fbc862baab12781f76c743cec6b72ffa7d8c27ee) | 原定义等于 `I3C_IBI_HOTJOIN`。 |
| [`I3C_IBI_WORKQUEUE_CB`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ggaf4be72fc9c862d996d860c0b7fbc862ba39d8f6a9b69d092eabf9ca9726deec8c) | 不是真正的 IBI 类型，仅供 IBI 工作队列执行通用回调使用。 |

枚举、回调与排队接口的头文件为 `zephyr/drivers/i3c/ibi.h`；下文静态内联函数的头文件为 `zephyr/drivers/i3c.h`。

## 396.2\_载荷宏与接收回调

原生成页面列出 Kconfig 配置宏：

```c
#define CONFIG_I3C_IBI_MAX_PAYLOAD_SIZE 0
```

> 译注：这里保留原 API 页面展示的值。它是配置宏，不能把此页面的 0 当成所有构建都只能使用零长度载荷的限制。

**载荷（Payload）**是随中断携带的数据。控制器收到目标设备的 IBI 时调用以下回调：

```c
typedef int (*i3c_target_ibi_cb_t)(struct i3c_device_desc *target,
                                  struct i3c_ibi_payload *payload);
```

`target` 是对应目标设备的描述结构；`payload` 是 IBI 的载荷，没有载荷时为 `NULL`。返回 0 表示接受中断，负数表示错误。

成功返回使控制器对下一个收到的字节作**确认应答（Acknowledgement，ACK）**；错误返回使其作**否定应答（Negative Acknowledgement，NACK）**。

## 396.3\_控制器应答策略

本节函数要求同时启用 Kconfig 配置项 [`CONFIG_I3C_USE_IBI`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_USE_IBI) 与 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。

```c
static inline int i3c_ibi_hj_response(const struct device *dev, bool ack);
static inline int i3c_ibi_crr_response(struct i3c_device_desc *target,
                                      bool ack);
```

[`i3c_ibi_hj_response()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#gac8c77e43fc7c06701437e799739507ee) 告知控制器是否对 IBI 热加入请求作确认应答。`dev` 指向控制器设备驱动实例。

[`i3c_ibi_crr_response()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga2546ae3b345b9271a3962c40ce38f73e) 告知控制器是否对指定目标的 IBI 控制器角色请求作确认应答。`target` 指向目标设备描述符。

两个函数的 `ack` 为 `true` 时选择 ACK，为 `false` 时选择 NACK。成功返回 0；通用输入/输出（Input/Output，I/O）错误返回 `-EIO`。

## 396.4\_发起IBI

```c
static inline int i3c_ibi_raise(const struct device *dev,
                               struct i3c_ibi *request);
```

[`i3c_ibi_raise()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga516c656231efd07429402c37643eca66) 向当前活动控制器发起 IBI。`dev` 是控制器设备驱动实例指针，`request` 指向 IBI 请求结构。

要求同时启用 Kconfig 配置项 [`CONFIG_I3C_USE_IBI`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_USE_IBI) 和 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。成功返回 0；通用输入/输出错误返回 `-EIO`。

## 396.5\_启用与禁用目标IBI

```c
static inline int i3c_ibi_enable(struct i3c_device_desc *target);
static inline int i3c_ibi_disable(struct i3c_device_desc *target);
```

两个函数均要求同时启用 Kconfig 配置项 [`CONFIG_I3C_USE_IBI`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_USE_IBI) 与 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。`target` 为目标设备描述符。

[`i3c_ibi_enable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga7625ef0313ded1f638a6eb44395b02c0) 启用已请求 IBI 的目标设备的 IBI。成功返回 0；通用输入/输出错误返回 `-EIO`；如果控制器使用 IBI 表而该表已无空闲项，返回 `-ENOMEM`。

[`i3c_ibi_disable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga037e156404324262694b4a5403821adc) 禁用已请求 IBI 的目标设备的 IBI。成功返回 0；通用输入/输出错误返回 `-EIO`；若此前没有为该目标启用 IBI，返回 `-ENODEV`。

## 396.6\_能力查询

```c
static inline int i3c_ibi_has_payload(struct i3c_device_desc *target);
static inline int i3c_device_is_ibi_capable(struct i3c_device_desc *target);
static inline int i3c_device_is_controller_capable(
    struct i3c_device_desc *target);
```

这三个函数读取设备描述符中的**总线特征寄存器（Bus Characteristics Register，BCR）**值，因此调用前必须已从设备取得 BCR 并设置 [`i3c_device_desc::bcr`](P401_I3C设备描述符.md)。

| 函数 | 返回真时表示 |
| --- | --- |
| [`i3c_ibi_has_payload()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga1a23e2ca2afb7cf371f523dcbcd7724f) | 目标设备的 IBI 带有载荷。 |
| [`i3c_device_is_ibi_capable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga6c09d19ab1c7c19db4d085a30066345e) | 目标设备具备 IBI 能力。 |
| [`i3c_device_is_controller_capable()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga537c1e2dafe3df1a5758e535beb323ea) | 目标设备具备控制器能力。 |

否则返回假。原声明的返回类型为 `int`，本页保持原类型。

## 396.7\_IBI工作队列公共结果

**工作队列（Workqueue）**用于把事件排队，留待后续处理。下面五个入队函数均使用 IBI 工作队列；其返回值约定相同：成功入队返回 0；没有可用内部节点来存储 IBI 工作项时返回 `-ENOMEM`；其他结果参见内核函数 [`k_work_submit_to_queue()`](https://docs.zephyrproject.org/latest/doxygen/html/group__workqueue__apis.html#ga5353e76f73db070614f50d06d292d05c)。

## 396.8\_通用工作项入队

```c
int i3c_ibi_work_enqueue(struct i3c_ibi_work *ibi_work);
```

[`i3c_ibi_work_enqueue()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#gaafc2fdf9f2402691c3ebe11d06106840) 把 `ibi_work` 指向的 IBI 工作项排入队列。函数将该结构复制到内部结构；没有足够空间完成复制时返回 `-ENOMEM`。返回值遵循上一节的公共约定。

## 396.9\_目标中断入队

```c
int i3c_ibi_work_enqueue_target_irq(struct i3c_device_desc *target,
                                   uint8_t *payload, size_t payload_len);
```

[`i3c_ibi_work_enqueue_target_irq()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga7fbf838ea07516849dc1296d48af65d1) 排入目标中断 IBI。`target` 是目标设备描述符指针，`payload` 指向 IBI 载荷字节数组，`payload_len` 为该数组长度。返回值遵循公共约定。

## 396.10\_控制器角色请求与热加入入队

```c
int i3c_ibi_work_enqueue_controller_request(struct i3c_device_desc *target);
int i3c_ibi_work_enqueue_hotjoin(const struct device *dev);
```

[`i3c_ibi_work_enqueue_controller_request()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#gad643c7f0512e1e6dcddbe5821e70fc0d) 排入控制权请求 IBI，`target` 指向目标设备描述符。

[`i3c_ibi_work_enqueue_hotjoin()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#gab135cb893efd50c7db16c1734b6a0bab) 排入热加入 IBI，`dev` 指向控制器设备驱动实例。两个函数的返回值均遵循公共约定。

## 396.11\_通用回调入队

```c
int i3c_ibi_work_enqueue_cb(const struct device *dev,
                           k_work_handler_t work_cb);
```

[`i3c_ibi_work_enqueue_cb()`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__ibi.html#ga4c6f4516e55d0ab6c539fb800d7ec45a) 将通用回调排入 IBI 工作队列，留待后续处理。`dev` 是控制器设备驱动实例指针，`work_cb` 是回调函数。返回值遵循公共约定。
