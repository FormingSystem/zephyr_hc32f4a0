# 第13章\_I2C总线

原文：[Inter-Integrated Circuit (I2C) Bus](https://docs.zephyrproject.org/latest/hardware/peripherals/i2c.html)。读取日期：2026-10-12，`latest`。

Zephyr **集成电路间总线（Inter-Integrated Circuit，I2C）** 接口采用 [NXP I2C 总线规范 Rev 7.0](https://www.nxp.com/docs/en/user-guide/UM10204.pdf) 的术语；这版规范于 2021-10-01 发布时修改了先前术语。

I2C（Inter-Integrated Circuit，读作“eye squared see”）是常见的双信号共享外设总线。许多 **片上系统（System on Chip，SoC）** 提供相应控制器。总线上有两种角色：控制器（controller）发起事务并控制时钟；目标（target）响应事务命令。SoC 的 I2C 外设一般支持控制器角色，一部分也支持目标角色，Zephyr 为两者分别提供接口。

## 13.1\_控制器与目标接口

控制器接口用于外设控制总线，特别是起始、停止条件和时钟。这是最常见方式，用于访问传感器、串行存储器等 I2C 设备。原文说明树内全部 I2C 外设驱动都支持它，接口已稳定。

目标接口用于响应其他控制器发起的事务。例如 Zephyr 应用充当受主处理器控制的换能器设备。树内仅少量驱动支持；原文将其标为实验性，因为它不能覆盖全部支持控制器模式的硬件能力。

## 13.2\_配置与传输超时

相关配置为 `CONFIG_I2C`、`CONFIG_I2C_TRANSFER_TIMEOUT_MS`。子系统提供两种互补机制，控制驱动等待传输完成多久后返回 `-ETIMEDOUT`。

### 13.2.1\_应用级默认值

驱动通过选择 `I2C_TRANSFER_TIMEOUT_SUPPORTED` 声明支持统一超时后，`CONFIG_I2C_TRANSFER_TIMEOUT_MS` 设置其默认毫秒超时。值为 0 表示永远等待，即 `K_FOREVER`。

不允许无限超时的驱动，例如直接把超时写入硬件寄存器的实现，会使用 `BUILD_ASSERT_INVALID_I2C_TRANSFER_TIMEOUT` 在构建时要求非零值。

### 13.2.2\_逐控制器设备树覆盖

设备树绑定 `dts/bindings/i2c/i2c-controller.yaml` 定义 `zephyr,transfer-timeout-ms` 属性，允许控制器覆盖应用默认值；属性缺省时回退到 Kconfig 默认值。开发板 overlay 示例：

```dts
&i2c1 {
    /* Fast sensor bus - fail quickly on a hung device */
    zephyr,transfer-timeout-ms = <50>;
};

&i2c2 {
    /* EEPROM bus - allow for long internal write cycles */
    zephyr,transfer-timeout-ms = <2000>;
};
```

支持逐实例超时的驱动使用 `I2C_DT_INST_TRANSFER_TIMEOUT`，或取得原始整数的 `I2C_DT_INST_TRANSFER_TIMEOUT_MS`。解析顺序是先取控制器节点设备树属性，再取 `CONFIG_I2C_TRANSFER_TIMEOUT_MS`；最终解析值为 0 时表示 `K_FOREVER`。

> 译注：这是所读取最新文档的能力，必须由驱动主动支持。不能只加入设备树属性，就假定旧版或本地 HC32 驱动自动获得该行为。示例中的 EEPROM 写周期说明也不保证延长总线传输超时就能替代设备协议所需的写完成等待或应答轮询。
