# 第116章\_多路复用器

原文：[Multiplexer (MUX)](https://docs.zephyrproject.org/latest/hardware/peripherals/mux.html)。读取日期：2026-10-13，`latest`。

## 116.1\_通过统一接口选择信号通路

**多路复用器（Multiplexer，MUX）**子系统为硬件信号多路复用器提供统一 **应用程序编程接口（Application Programming Interface，API）**。使用该功能的 **消费者驱动（Consumer Driver）**通过标准 **设备树（Devicetree）**属性 `mux-controls` 或 `mux-states` 引用MUX控制器，就能把输入信号路由至输出，而无需依赖厂商特定的 **硬件抽象层（Hardware Abstraction Layer，HAL）**。

这两个属性都属于 **节点句柄数组（Phandle Array）**，但面向不同使用方式：

- `mux-controls`：消费者引用控制器，在运行时调用状态设置函数 [`mux_control_set()`](https://docs.zephyrproject.org/latest/doxygen/html/group__mux__interface.html#ga69b883de5e7c90f797d5a07063089bbc) 提供状态，即选择哪个输入或写入哪种输出模式。适合正常运行期间需要改变路由的场景。
- `mux-states`：消费者在设备树中同时给出控制器与固定状态，描述符最后一个单元就是状态值。运行时调用固定状态应用函数 [`mux_state_apply()`](https://docs.zephyrproject.org/latest/doxygen/html/group__mux__interface.html#gad1b56b4430fca99f03bdf2b0ad6725c5) 即可应用该固定状态。适合集成阶段已确定路由、初始化后不再改变的场景。

## 116.2\_控制器侧绑定

每个MUX控制器绑定都包含 `dts/bindings/mux/` 下的 `mux-controller.yaml`，并声明两个单元数量属性。此处路径均从Zephyr源码根目录起算。

| 属性 | 含义 |
| --- | --- |
| `#mux-control-cells` | `mux-controls` 描述符的单元数；这些单元只用于寻址控制器内所需的控制线路。 |
| `#mux-state-cells` | `mux-states` 描述符的单元数，等于 `#mux-control-cells + 1`。最后一个单元携带状态值，框架在编译时将它提取到 `mux_state::state` 字段。 |

后端可以按硬件含义命名寻址单元，例如 `channel`（通道）、`output`（输出）、`index`（索引）、`device/input`（设备／输入）；最后的状态单元也可按硬件含义命名，例如 `state`（状态）、`input`（输入）、`connection`（连接）或 `source`（信号源）。

## 116.3\_消费者侧绑定

消费者绑定包含 `mux-consumer.yaml`，可设置以下属性：

| 属性 | 内容 |
| --- | --- |
| `mux-controls` | “节点句柄＋寻址单元”的元组列表。 |
| `mux-control-names` | 与 `mux-controls` 条目对应的可选名称。 |
| `mux-states` | “节点句柄＋寻址单元＋末尾状态单元”的元组列表。 |
| `mux-state-names` | 与 `mux-states` 条目对应的可选名称。 |

## 116.4\_配置与接口

相关Kconfig配置项为 [`CONFIG_MUX`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MUX)；Kconfig是Zephyr配置系统。完整声明见[MUX接口](https://docs.zephyrproject.org/latest/doxygen/html/group__mux__interface.html)。
