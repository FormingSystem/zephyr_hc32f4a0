# 第59章\_内存控制器

原文：[Memory Controller (MEMC)](https://docs.zephyrproject.org/latest/hardware/peripherals/memc.html)。读取日期：2026-10-13，`latest`。

## 59.1\_访问外部存储器的两种方式

**内存控制器（Memory Controller，MEMC）**的 **应用程序编程接口（Application Programming Interface，API）**为访问外部存储器提供通用入口，例如 **伪静态随机存取存储器（Pseudo-Static Random Access Memory，PSRAM）**与 **或非型闪存（NOR Flash）**。接口支持两种访问方式。

**内存映射访问（Memory-Mapped Access）**中，控制器将设备暴露为 **中央处理器（Central Processing Unit，CPU）**可直接访问的地址窗口。驱动可实现 [`memc_driver_api.get_mem_base`](https://docs.zephyrproject.org/latest/doxygen/html/structmemc__driver__api.html#a9c6376bec867625f3569ccf2bf379a7b)，报告映射基地址，使 [`memc_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga7b766a76f3bffe8b89eafb93c4f16cae) 与 [`memc_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga8c08116a54ccb2765822ba20ba77ed39) 自动使用内存复制函数 `memcpy()` 完成访问。

另一种情况是硬件已经透明地映射内存，驱动完全不提供运行时API；上层直接使用平台特定基地址访问设备。是否存在硬件映射与是否提供运行时API不是同一件事。

**总线事务（Bus Transaction）**方式在每次传输时发出明确的总线命令，例如通过 **多位串行外设接口（Multi-bit Serial Peripheral Interface，MSPI）**。当控制器没有内存映射窗口时，驱动实现 [`memc_driver_api.read`](https://docs.zephyrproject.org/latest/doxygen/html/structmemc__driver__api.html#af5091fa43e0227b5038a6f7eae649e72) 和 [`memc_driver_api.write`](https://docs.zephyrproject.org/latest/doxygen/html/structmemc__driver__api.html#af64136ddf8e8f569eaf7882e28a5f8c8) 来完成访问。

[`memc_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga7b766a76f3bffe8b89eafb93c4f16cae) 与 [`memc_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga8c08116a54ccb2765822ba20ba77ed39) 会优先选择可用的内存映射路径，否则回退到总线事务。可选的设备信息查询接口包括 [`memc_get_size()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga02bca9fd387ac26841394a73d51dbe7e)，返回设备容量，以及 [`memc_read_id()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#gaf797d9df098f75ce12e69223f759364b)，返回设备标识字节。

## 59.2\_仅执行初始化的旧驱动

已有的MEMC驱动可能在调用 `DEVICE_DT_INST_DEFINE` 时把API指针设为 `NULL`。这些 **仅初始化驱动（Init-Only Driver）**不受新接口影响；调用者应先用 [`DEVICE_API_IS`](../device_reference/P007_设备模型头文件参考.md#a48c6030c2e7d1d05ace7c708dda11949) 判断设备是否实现了MEMC接口，再调用对应函数。

以下是原文的C代码片段。它属于已取得设备和缓冲区的调用位置，`MEMC_BASE` 表示平台特定的映射基地址，不能不加核对地复制为其他板的地址。

```c
if (DEVICE_API_IS(memc, dev)) {
   memc_read(dev, offset, buf, sizeof(buf));
} else {
   /* Legacy init-only driver - device is memory-mapped.
    * Access via platform-specific base address.
    */
   memcpy(buf, (const uint8_t *)MEMC_BASE + offset, sizeof(buf));
}
```

分支为真时通过 [`memc_read()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga7b766a76f3bffe8b89eafb93c4f16cae) 读取；否则按代码注释所述，将旧驱动对应的设备视为内存映射设备，直接从平台基地址加偏移读取。`dev`、`offset` 和 `buf` 由调用者上下文提供，原页不是包含全部声明的独立应用。

对未实现MEMC API的设备调用 `memc_read()` 或 [`memc_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html#ga8c08116a54ccb2765822ba20ba77ed39)，会返回 `-ENOTSUP`，表示不支持该操作。这不同于设备不存在，也不同于已有映射数据读写失败。

## 59.3\_配置与接口参考

相关Kconfig配置项为 [`CONFIG_MEMC`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MEMC)（MEMC支持）和 [`CONFIG_MEMC_INIT_PRIORITY`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MEMC_INIT_PRIORITY)（初始化优先级）。Kconfig是Zephyr配置系统；具体函数、操作结构和类型见[MEMC接口参考](https://docs.zephyrproject.org/latest/doxygen/html/group__memc__interface.html)。
