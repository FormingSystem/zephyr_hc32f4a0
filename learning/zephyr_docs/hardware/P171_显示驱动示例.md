# 第171章\_显示驱动示例

原文：[Display](https://docs.zephyrproject.org/latest/samples/drivers/display/README.html)。读取日期：2026-10-13，`latest`。

## 171.1\_概述（Overview）

本示例通过[显示设备](P130_显示设备.md)的 **应用程序编程接口（Application Programming Interface，API）**在屏幕上绘制基本形状。

对大多数显示控制器，绘制内容为矩形。矩形的颜色和位置用于检查 **液晶显示屏（Liquid Crystal Display，LCD）**的方向，以及 **红绿蓝（Red, Green, Blue，RGB）**位顺序是否正确。从左上角开始按顺时针方向依次绘制红、绿、蓝、灰四个矩形，其中灰色从黑变到白。

提示：如果灰色在某些时刻明显偏绿或偏红，或者四角颜色次序不符合上述顺序，LCD 可能发生了字节序交换（Endian Swap）。

## 171.2\_彩色显示与官方动画（RGB）

320×240 分辨率下的典型输出是：左上红色、右上绿色、右下蓝色；左下角从黑到白变化。在真实硬件上，矩形大小随分辨率缩放。

## 171.3\_只能整行绘制的显示器（Alignment Width）

对于每次只能绘制完整一行的显示器，见能力标志 [`SCREEN_INFO_X_ALIGNMENT_WIDTH`](P214_显示公共接口.md)，例如采用 `sharp,ls0xx` 驱动的设备，上述矩形会替换为覆盖整个屏幕宽度的条带。

此时只会看到绿色和灰色两条色带：左上与右上的绘制都占满整行，所以在顶部重叠；右下与左下也在底部重叠。最终顶部为绿色，底部为不断变化的灰色。

## 171.4\_灰度显示（Grayscale）

使用多位亮度格式（Multi-bit Luminance Format）的显示器，例如像素格式 [`PIXEL_FORMAT_L_8`](P214_显示公共接口.md)，每个角显示不同灰度，左下角仍从黑色逐渐变化到白色。其他多位单色格式也有类似表现：各角具有不同灰度。

## 171.5\_每像素一位（1 bpp）

对每像素只有一位（Bits Per Pixel，bpp）的显示器，底部矩形或条带的灰度变化表现为黑白闪烁。其他角保持与当前像素格式背景相匹配的固定颜色。

原图注说明：三个角保持背景颜色；对 `MONO01` 为黑色，对黑屏上的 `MONO10` 为白色；左下角不断切换。

## 171.6\_电子纸（E-paper）

查询显示控制器能力时，可检查 `display_capabilities.screen_info` 中是否设置了 [`SCREEN_INFO_EPD`](P214_显示公共接口.md) 位，以判断其是否为 **电子纸显示器（Electronic Paper Display，EPD）**。

为了适应电子墨水技术通常较低的刷新率，这类显示器左下角的颜色变化会比普通 LCD 慢得多。

## 171.7\_构建与运行（Building and Running）

这是一个通用示例，应适用于 Zephyr 支持的各种显示器。下面以 nRF52840 DK 开发板配合 Adafruit 2.8 英寸 **薄膜晶体管（Thin-Film Transistor，TFT）**触摸屏扩展板（Shield）v2 为例。

译注：在已配置 Zephyr 开发环境的终端中，从 Zephyr 源码根目录执行以下官方命令；示例源码由官方仓库提供，west 生成构建产物。

```bash
west build -b nrf52840dk/nrf52840 --shield adafruit_2_8_tft_touch_v2 samples/drivers/display
```

无需实际硬件的测试也可以使用 [`native_sim`](../native_reference/P004_Native_Simulator本机模拟器.md#native_sim) 主机原生仿真目标。在同一源码根目录中执行：

```bash
west build -b native_sim samples/drivers/display
```
