# 第221章\_显示颜色抖动接口

原文：[group__display__color__dither](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html)。读取日期：2026-10-13，`latest`。

## 221.1\_用途与接入位置

本页提供显示驱动使用的 **颜色抖动（Color Dithering）**辅助接口，声明来自官方头文件 `zephyr/drivers/display/color_dither.h`。它让原生写入路径只接受 4 位索引色（4-bit Indexed Color，I4）的驱动，也能接收配置启用的红、绿、蓝（Red, Green, Blue，RGB）输入格式。

辅助接口在驱动原生写入代码运行前，使用驱动的 **调色板（Color Palette）**，把每次 RGB 写入缓冲区转换为打包的像素格式枚举常量 [`PIXEL_FORMAT_I_4`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__interface.html#ggac346bc56771052a8fe919c3ec23d7c9cacaed33ee4be17042d45cf238ac49df6a)。配置系统 Kconfig 的 [`CONFIG_DISPLAY_COLOR_DITHER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DISPLAY_COLOR_DITHER) 控制此辅助功能。

接入位置如下：

1. 在驱动运行数据中加入 [`display_color_dither_state`](https://docs.zephyrproject.org/latest/doxygen/html/structdisplay__color__dither__state.html) 状态结构成员，保存每个实例的状态。
2. 用宏 [`DISPLAY_COLOR_DITHER_DEFINE`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gaa5614d4a4e791b87d1a925964c3a862d) 与 [`DISPLAY_COLOR_DITHER_INIT`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gab7a067eae6c3fde92740be190c11d62e) 定义并初始化底层存储。
3. 在驱动函数表 `display_driver_api` 的 `write()` 操作开头调用函数 [`display_color_dither_prepare()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gab765e6926c9f1f1f693c5016bce04efc)。
4. 在 `get_capabilities()` 操作填好显示能力后调用函数 [`display_color_dither_patch_caps()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gaad0ed338c68320c61543c2986e3f7a0a)。
5. 在 `set_pixel_format()` 操作中调用函数 [`display_color_dither_set_input_format()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#ga38578e4fd14280d9e623172b2bfabd15)。

> 译注：原文称“四处”，但实际列出五项；这里完整保留五项。

## 221.2\_原始集成示例

示例中的 `foo_data`、`foo_write`、`foo_get_capabilities`、`foo_set_pixel_format` 和 `FOO_DEFINE` 是演示驱动的结构、函数及实例定义宏名称；`scratch` 是临时描述符。设备树实例定义宏 `DEVICE_DT_INST_DEFINE` 用于定义驱动设备，省略号表示待补的驱动代码或参数。

```c
#include <zephyr/drivers/display/color_dither.h>

struct foo_data {
        struct display_color_dither_state color_dither;
        // ... other fields for driver state ...
};

static int foo_write(const struct device *dev,
                     const uint16_t x, const uint16_t y,
                     const struct display_buffer_descriptor *desc,
                     const void *buf)
{
        struct display_buffer_descriptor scratch;
        struct foo_data *data = dev->data;
        int ret = display_color_dither_prepare(dev, &data->color_dither, &desc, &buf,
                                               &scratch);

        if (ret < 0) {
                return ret;
        }
        // ...existing I_4-only body, unchanged...
}

static void foo_get_capabilities(const struct device *dev, struct display_capabilities *caps)
{
        struct foo_data *data = dev->data;

        // ... existing population of caps (advertising I_4, plus maybe other formats) ...
        display_color_dither_patch_caps(&data->color_dither, caps);
}

static int foo_set_pixel_format(const struct device *dev,
                                enum display_pixel_format pf)
{
        struct foo_data *data = dev->data;

        // Let the color dithering helper know which input format to expect.
        return display_color_dither_set_input_format(&data->color_dither, pf);
}

// In the driver instance definition, define backing storage before data:
#define FOO_DEFINE(inst)                                                               \
        DISPLAY_COLOR_DITHER_DEFINE(inst);                                             \
        static struct foo_data foo_data_##inst = {                                     \
                .color_dither = DISPLAY_COLOR_DITHER_INIT(inst),                       \
        };                                                                             \
        DEVICE_DT_INST_DEFINE(inst, ...);
```

禁用 [`CONFIG_DISPLAY_COLOR_DITHER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DISPLAY_COLOR_DITHER) 时，底层存储宏为空；[`display_color_dither_set_input_format()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#ga38578e4fd14280d9e623172b2bfabd15) 只接受原生 [`PIXEL_FORMAT_I_4`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__interface.html#ggac346bc56771052a8fe919c3ec23d7c9cacaed33ee4be17042d45cf238ac49df6a)，其余内联辅助接口保持驱动行为不变。

## 221.3\_底层存储定义与初始化宏

宏 `DISPLAY_COLOR_DITHER_DEFINE(inst)` 为一个显示驱动实例定义底层存储。每个可使用辅助功能的实例调用一次，为转换缓冲区及可选的 **误差扩散（Error Diffusion）**行分配空间。缓冲区尺寸来自该实例设备树（Devicetree，DT）的 `width`、`height` 属性；`inst` 是 DT 实例索引。

下面原展开式中的 [`DT_INST_PROP`](../dt_instance_reference/P001_设备树驱动实例宏.md#ga9dce2e631b2a94804e8f2bcc76c6eff8) 是读取实例属性的宏，`COLOR_DITHER_I4_BYTES` 计算 I4 存储字节数，`COLOR_DITHER_ERRDIFF_DEFINE` 定义误差扩散所需存储，`color_dither_buf_##inst` 是由实例索引拼接的转换缓冲区名称。

```c
static uint8_t color_dither_buf_##inst[COLOR_DITHER_I4_BYTES(DT_INST_PROP(inst, width),    \
                                                             DT_INST_PROP(inst, height))]; \
COLOR_DITHER_ERRDIFF_DEFINE(inst, DT_INST_PROP(inst, width))
```

原页对这个宏的有效实现注明：仅在启用 [`CONFIG_DISPLAY_COLOR_DITHER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DISPLAY_COLOR_DITHER) 时可用；禁用时为空宏的行为见前述总说明。

宏 `DISPLAY_COLOR_DITHER_INIT(inst)` 初始化同一实例驱动数据中的颜色抖动状态成员，必须在 [`DISPLAY_COLOR_DITHER_DEFINE`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gaa5614d4a4e791b87d1a925964c3a862d) 已定义该实例存储后，用于驱动数据初始化器（Initializer）。禁用配置时展开为空初始化器，状态成员大小为零，因此可以无条件使用。

原展开式中 `input_format` 为输入格式，`converted_buf`、`converted_buf_size` 对应转换缓冲区及其大小，`err_rows`、`err_row_len` 对应误差扩散行；`COLOR_DITHER_DEFAULT_FMT`、`COLOR_DITHER_ERRDIFF_R0`、`COLOR_DITHER_ERRDIFF_R1`、`COLOR_DITHER_ERRDIFF_R2` 和 `COLOR_DITHER_ERRDIFF_LEN` 是内部初始化辅助宏。驱动应通过接口使用状态，不直接访问这些字段。

```c
{                                                                                          \
        .input_format = COLOR_DITHER_DEFAULT_FMT,                                          \
        .converted_buf = color_dither_buf_##inst,                                          \
        .converted_buf_size = sizeof(color_dither_buf_##inst),                             \
        .err_rows =                                                                        \
                {                                                                          \
                        COLOR_DITHER_ERRDIFF_R0(inst),                                     \
                        COLOR_DITHER_ERRDIFF_R1(inst),                                     \
                        COLOR_DITHER_ERRDIFF_R2(inst),                                     \
                },                                                                         \
        .err_row_len = COLOR_DITHER_ERRDIFF_LEN(DT_INST_PROP(inst, width)),                \
}
```

## 221.4\_准备写入缓冲区

函数 [`display_color_dither_prepare()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gab765e6926c9f1f1f693c5016bce04efc) 为原生 I4 写入路径准备缓冲区，应在驱动 `write()` 操作开头调用。

```c
int display_color_dither_prepare(const struct device *dev,
    struct display_color_dither_state *state,
    const struct display_buffer_descriptor **desc, const void **buf,
    struct display_buffer_descriptor *scratch);
```

`state->input_format` 为 RGB 输入格式时，函数将 `buf` 转换为打包的 I4，并更新 `desc`、`buf` 使其指向转换后的数据。输入格式已经是 I4，或状态没有转换缓冲区时，输入保持不变。

| 参数 | 含义 |
| --- | --- |
| `dev` | 显示设备，用于读取驱动调色板。 |
| [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) | 嵌入驱动数据的颜色抖动状态。 |
| `desc` | 写入回调的描述符指针的地址。 |
| `buf` | 写入回调的缓冲区指针的地址。 |
| `scratch` | 调用者拥有的临时描述符存储。 |

返回 0 表示可以继续写入；`-EINVAL` 表示输入描述符不适用于所选格式（Invalid Descriptor）；`-ENOMEM` 表示转换缓冲区太小（Insufficient Memory）；`-ENOTSUP` 表示所选格式或调色板无法转换（Not Supported）。

## 221.5\_补充显示能力

函数 [`display_color_dither_patch_caps()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#gaad0ed338c68320c61543c2986e3f7a0a) 向显示能力加入辅助功能管理的 RGB 格式：

```c
void display_color_dither_patch_caps(struct display_color_dither_state *state,
                                     struct display_capabilities *caps);
```

在驱动 `get_capabilities()` 操作末尾、原生能力与调色板已填好后调用。[`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是嵌入驱动数据的状态，`caps` 指向待补充的显示能力。

函数将 Kconfig 启用的 RGB 格式加入能力结构字段 `supported_pixel_formats`。辅助功能正在转换时，字段 `current_pixel_format` 也报告辅助功能管理的输入格式。函数无返回值。

## 221.6\_选择输入格式

函数 [`display_color_dither_set_input_format()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#ga38578e4fd14280d9e623172b2bfabd15) 从驱动 `set_pixel_format()` 操作中调用：

```c
int display_color_dither_set_input_format(struct display_color_dither_state *state,
                                          enum display_pixel_format pf);
```

[`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是嵌入驱动数据的状态；`pf` 是调用者请求的格式。选择 [`PIXEL_FORMAT_I_4`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__interface.html#ggac346bc56771052a8fe919c3ec23d7c9cacaed33ee4be17042d45cf238ac49df6a) 使用原生 I4 路径，不经辅助转换；选择已配置的 RGB 格式，则在原生写入前转为打包 I4。

返回 0 表示成功，包括无需转换的原生 I4。返回 `-ENOTSUP` 表示辅助功能禁用、状态没有转换缓冲区，或 `pf` 不支持 RGB 到 I4 转换；前文明确的原生 I4 成功情况仍适用。

## 221.7\_查询是否正在转换

函数 [`display_color_dither_is_active()`](https://docs.zephyrproject.org/latest/doxygen/html/group__display__color__dither.html#ga79ff5454e68af2c1bb5eedf25904dca2) 报告辅助功能是否正在把输入转换为原生 I4：

```c
bool display_color_dither_is_active(const struct display_color_dither_state *state,
                                    enum display_pixel_format current_pixel_format);
```

[`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是嵌入驱动数据的状态；`current_pixel_format` 是驱动当前向调用者报告的格式。返回 [`true`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a41f9c5fb8b08eb5dc3edce4dcb37fee7) 表示辅助功能正在将该格式转换为 I4；返回 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727) 表示使用原生 I4 写入路径，没有辅助转换。

原页在这四个函数的有效实现处均注明需要启用 [`CONFIG_DISPLAY_COLOR_DITHER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_DISPLAY_COLOR_DITHER)；禁用时的内联辅助行为已在集成说明中保留。

相关类型见[颜色抖动状态](P222_显示颜色抖动状态.md)、[显示能力](P216_显示能力结构.md)、[缓冲区描述符](P215_显示缓冲区描述符.md)和[显示驱动函数表](P220_显示驱动函数表.md)。
