# 第70章\_I3C总线

原文：[Improved Inter-Integrated Circuit (I3C) Bus](https://docs.zephyrproject.org/latest/hardware/peripherals/i3c.html)。读取日期：2026-10-13，`latest`。

## 70.1\_总线角色与动态地址

**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）**是一种使用两根信号线的共享外设接口总线。设备可以承担两种角色：**控制器（Controller）**发起事务并控制时钟；**目标设备（Target）**响应事务命令。原页说明当前 **应用程序编程接口（Application Programming Interface，API）**以[I3C规范1.1.1版](https://www.mipi.org/specifications/i3c-sensor-specification)为基础。

当I3C控制器控制总线，尤其是起始条件、停止条件和时钟时，使用控制器API。这是与传感器等I3C目标设备交互的常见方式。

有些I3C设备上电时没有地址，因此控制器还要执行 **动态地址分配（Dynamic Address Assignment，DAA）**。为追踪设备状态，控制器需要独立的数据结构。例如，构建时可为I3C和传统 **集成电路间总线（Inter-Integrated Circuit，I2C）**设备分别创建描述符数组。

[`I3C_DEVICE_ARRAY_DT_INST`](P424_I3C设备树宏.md) 与 [`I3C_I2C_DEVICE_ARRAY_DT_INST`](P424_I3C设备树宏.md) 是辅助宏，依据I3C控制器下的设备树节点创建相应设备描述符数组；`inst` 表示所处理的设备树实例。原例为：

```c
static struct i3c_device_desc i3c_device_array[] = I3C_DEVICE_ARRAY_DT_INST(inst);
static struct i3c_i2c_device_desc i2c_device_array[] = I3C_I2C_DEVICE_ARRAY_DT_INST(inst);
```

其中 [`i3c_device_desc`](P401_I3C设备描述符.md) 与 `i3c_i2c_device_desc` 分别是I3C、I2C设备描述符类型。

## 70.2\_控制器与硬件初始化

在设备驱动初始化函数中，原文给出如下通用流程。

首先初始化I3C控制器驱动实例的数据结构。可以用 [`DEVICE_DT_INST_DEFINE`](../device_reference/P001_设备模型公共接口.md#gada5ba4aca9e0662ccebb2232c7256419) 等设备定义宏，并把初始化函数传给宏。辅助结构 [`i3c_addr_slots`](P384_I3C地址槽结构.md) 与 [`i3c_dev_list`](P403_I3C已知设备列表.md) 用于地址分配、设备列表管理；采用这些结构时，通过 [`i3c_addr_slots_init()`](P383_I3C地址槽管理.md) 完成相关初始化，后续也可配合其他辅助函数使用。

如果控制器驱动需要，初始化设备描述符。然后初始化硬件，包括设置引脚复用和方向、配置控制器时钟、给硬件上电，以及配置硬件参数，例如 **串行时钟线（Serial Clock Line，SCL）**频率。

## 70.3\_总线初始化和公共命令

不需要特殊总线初始化处理的控制器可使用通用辅助函数 [`i3c_bus_init()`](P425_I3C公共接口参考.md)。下面按原文顺序说明其流程中的 **公共命令码（Common Command Code，CCC）**与设备信息。

1. 执行 `RSTDAA`，即 **重置动态地址分配（Reset Dynamic Address Assignment）**。设备可能已经拥有地址，而控制器状态记录中还没有这些信息，例如刚上电时；重置后重新分配能使双方状态对应。
2. 执行 `DISEC`，即 **禁用事件（Disable Events）**，禁止设备事件。
3. 如有需要，执行 `SETDASA`，即 **由静态地址设置动态地址（Set Dynamic Address from Static Address）**。原文同时指出，不能假设所有已连接设备都支持 `SETAASA` 这种把静态地址用作动态地址的命令；应单独读取 **总线特性寄存器（Bus Characteristics Register，BCR）**与 **设备特性寄存器（Device Characteristics Register，DCR）**，填入目标设备描述符。
4. 如果仍有设备没有地址，执行 `ENTDAA`，即 **进入动态地址分配（Enter Dynamic Address Assignment）**。具体匹配规则见下一节；如果所有设备都不需要DAA，可以跳过。
5. 可选但强烈推荐：执行 `GETMRL`、`GETMWL` 查询 **最大读取长度（Maximum Read Length，MRL）**、**最大写入长度（Maximum Write Length，MWL）**；执行 `GETMXDS` 查询 **最大数据速度（Maximum Data Speed）**，包括最大读写速度和最大读取周转时间。[`i3c_bus_init()`](P425_I3C公共接口参考.md) 会获取BCR、DCR、MRL、MWL等基本信息。
6. 执行 `ENEC`，即 **启用事件（Enable Events）**。[`i3c_bus_init()`](P425_I3C公共接口参考.md) 只重新启用 **热加入（Hot-Join）**事件；目标设备的带内中断事件要在启用该设备带内中断时才打开。

这里将命令用途与英文名称一起保留，实际操作仍由控制器驱动完成；读取能力信息与使能中断不是同一个动作。

## 70.4\_动态地址分配中的描述符匹配

等待地址的设备会返回 **预置标识符（Provisioned ID，PID）**、BCR和DCR。控制器将收到的PID与已登记的I3C设备列表比较。

如果匹配，分配一个地址：尚未执行SETDASA时可以使用已声明的静态地址，或者使用一个空闲地址；同时在设备描述符中设置BCR与DCR。

如果不匹配，如何处理取决于策略：可以分配空闲地址，也可以停止分配过程并报错。**I3C API要求设备描述符存在，没有描述符的设备无法通过该API访问。** 因此“总线上设备得到地址”并不自动等于“应用已有可用于API的描述符”。

## 70.5\_带内中断

如果目标设备能产生 **带内中断（In-Band Interrupt，IBI）**，控制器必须知道该设备的中断能力和配置。

[`i3c_ibi_enable()`](P396_I3C带内中断接口.md) 启用目标设备的IBI。部分控制器硬件有IBI槽位，需要将目标设备信息编入槽位，以识别来自该设备的IBI。槽位数量通常有限，所以使能可能失败。驱动实现还应发送ENEC命令，启用目标设备的中断。

[`i3c_ibi_disable()`](P396_I3C带内中断接口.md) 禁用目标设备的IBI。如果控制器使用IBI槽位，应从槽位删除该设备描述；驱动还应发送DISEC命令，禁用目标设备中断。仅修改一侧的软件记录不足以替代两端配置。

## 70.6\_设备树控制器与子设备

下面是官方 **设备树源文件（Devicetree Source，DTS）**片段：定义一个I3C控制器，并挂接一个I3C设备和一个I2C设备。`vendor`、地址、时钟及引脚配置属于示例占位内容，实际值要来自目标硬件。

```devicetree
i3c0: i3c@10000 {
        compatible = "vendor,i3c";

        #address-cells = <0x3>;
        #size-cells = <0x0>;

        reg = <0x10000 0x1000>;
        interrupts = <0x1F 0x0>;

        pinctrl-0 = <&pinmux-i3c>;
        pinctrl-names = "default";

        i2c-scl-hz = <400000>;

        i3c-scl-hz = <12000000>;

        status = "okay";

        i3c-dev0: i3c-dev0@420000ABCD12345678 {
                compatible = "vendor,i3c-dev";

                reg = <0x42 0xABCD 0x12345678>;

                status = "okay";
        };

        i2c-dev0: i2c-dev0@380000000000000050 {
                compatible = "vendor-i2c-dev";

                reg = <0x38 0x0 0x50>;

                status = "okay";
        };
};
```

> 译注：原片段中的 `pinmux-i3c`、`i3c-dev0`、`i2c-dev0` 被用于标签或标签引用，而设备树标签标识符不允许连字符。正式工程应使用合法标签名，并同步修改引用；节点名称与标签的语法并不相同。此处原样保留官方片段以供对照，没有将其视为已经编译通过的板级文件。

## 70.7\_I3C设备的reg属性

I3C设备的 `reg` 属性包含三个元素：

| 元素 | 含义与要求 |
| --- | --- |
| 第一个 | 设备静态地址。不使用静态地址时可以为0，地址将在DAA期间分配；非0且未设置 `assigned-address` 属性时，它就是执行SETDASA后的设备地址。 |
| 第二个 | 48位PID的高16位，其中制造商标识左移1位放入；按完整PID的零起始位编号，制造商标识占第33—47位。该元素必须非0。 |
| 第三个 | PID低32位，其中包括左移16位的部件标识（PID第16—31位）和左移12位的实例标识（PID第12—15位）。 |

第二个元素为0会使辅助宏把节点识别为传统I2C设备，并创建I2C描述符。因此，即使使用SETDASA寻址、其他地方没有用到PID，也必须填写PID。

节点的 **单元地址（Unit Address）**，即 `@` 后面的部分，必须完整匹配 `reg`：将三个元素分别当作32位整数，拼接成96位整数。这是正确生成设备树宏的要求，不能只填第一个元素。

## 70.8\_I2C设备的reg属性与LVR

设备驱动已支持在I3C总线下工作时，I2C节点可直接定义为I3C控制器子节点；只支持I2C控制器的驱动，则应使用后文所述的虚拟I2C控制器。

直接描述I2C设备时，`reg` 同样有三个元素。第一个必须是有效静态地址，因为I2C设备不支持动态地址分配；第二个始终为0，供辅助宏识别I2C节点；第三个是 **传统设备虚拟寄存器（Legacy Virtual Register，LVR）**。

LVR的位31—8未使用；位7—5保存I2C设备索引：

| 索引 | 原文描述的设备能力 |
| --- | --- |
| 0 | 具有50 ns尖峰滤波器，不受SCL高频信号影响。 |
| 1 | 没有50 ns尖峰滤波器，但可以承受SCL上的高频信号。 |
| 2 | 没有50 ns尖峰滤波器，且不能承受SCL上的高频信号。 |

> 译注：原文在索引0和2的句子中写作“I3C device”，但该表位于I2C设备的LVR说明下，并明确称为I2C设备索引。上表保留其滤波和频率能力含义，指出这一名称不一致，不将其解释为另一套I3C索引。

位4是I2C模式标志：0表示 **快速模式增强版（Fast-mode Plus，FM+）**，1表示 **快速模式（Fast-mode，FM）**。与I3C设备一样，单元地址必须匹配三个32位 `reg` 元素拼接的96位值。

## 70.9\_设备驱动取得描述符

I3C控制器API的所有传输函数都要求使用 `i3c_device_desc` 描述符。它保存动态地址、BCR、DCR、MRL、MWL等运行时信息。

I3C设备驱动应通过 [`i3c_device_find()`](P425_I3C公共接口参考.md) 向控制器取得描述符指针。该函数使用 [`i3c_device_id`](P400_I3C设备匹配标识.md) 类型的标识参数进行匹配；返回的指针用于后续控制器API调用。

## 70.10\_I3C总线下的I2C驱动

I3C向后兼容I2C。如果I3C控制器驱动也实现I2C API，现有I2C设备驱动可以不作修改，仍调用I2C接口。代价是I3C控制器使用设备描述符，每次I2C API调用都要根据I2C地址查找对应描述符，增加一些处理开销。

也可以扩展设备驱动，使用I3C控制器API原生支持的I2C设备操作：在设备初始化时调用 `i3c_i2c_device_find()` 获取描述符指针，后续调用复用它。无论采用哪种方式，原文都要求相关I2C节点按I3C标准声明。

原文还说明，虚拟I2C控制器驱动可让I3C总线上的I2C设备驱动保持不变，并称需要在设备树中加入中间节点；随后的示例如下：

```devicetree
i3c0: i3c@10000 {
        <... I3C controller related properties ...>
        <... Nodes of I3C devices, if any ...>

        i2c-dev0: i2c-dev0@420000000000000050 {
                compatible = "vendor-i2c-dev";

                reg = <0x42 0x0 0x50>;

                status = "okay";
        };
};
```

> 译注：这段原例含 `<...>` 占位行，而且仍直接把I2C节点放在I3C控制器下，没有实际展示文字所说的中间节点。因此不能把它当成完整可编译的虚拟控制器配置；正式配置需查所用适配驱动的绑定、控制器支持与节点层级。标签连字符问题也与前一片段相同。
