# 第428章\_I3C能力返回联合体

原文：[unioni3c__ccc__getcaps](https://docs.zephyrproject.org/latest/doxygen/html/unioni3c__ccc__getcaps.html)。读取日期：2026-10-13，`latest`。

## 428.1\_GETCAPS与版本

`union i3c_ccc_getcaps` 是**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）通用命令码（Common Command Code，CCC）** `GETCAPS` 的载荷（Payload），用于**获取可选功能能力（Get Optional Feature Capabilities）**。头文件为 `zephyr/drivers/i3c/ccc.h`。

仅支持 GETCAPS 格式 1 和格式 2。I3C 1.0 中该命令称为 `GETHDRCAP`，只返回一个字节，对应 GETCAPS1 字节。

以下按原字段表保留嵌套联合体：

```c
union i3c_ccc_getcaps {
    union {
        uint8_t gethdrcap;
        uint8_t getcaps[4];
    } fmt1;
    union {
        uint8_t tgtcaps[4];
        uint32_t testpat;
        uint8_t crcaps[2];
        uint8_t vtcaps[2];
    } fmt2;
};
```

## 428.2\_I3C1.0高数据速率能力

**高数据速率（High Data Rate，HDR）**包括双倍数据速率（Double Data Rate，DDR）、纯总线三元符号（Ternary Symbol Pure-bus，TSP）、包含传统设备总线的三元符号（Ternary Symbol Legacy-inclusive-bus，TSL）及大块传输（Bulk Transport，BT）。

I3C 1.0 使用 `fmt1.gethdrcap`：位 0 表示 HDR-DDR，位 1 表示 HDR-TSP，位 2 表示 HDR-TSL，位 7:3 保留。

## 428.3\_GETCAPS1与GETCAPS2

I3C 1.1 及以后的设备能力由 `fmt1.getcaps[4]` 返回，共四个字节。第 1 字节 GETCAPS1：位 0 为 HDR-DDR，位 1 为 HDR-TSP，位 2 为 HDR-TSL，位 3 为 HDR-BT，位 7:4 保留。

第 2 字节 GETCAPS2 使用**循环冗余校验（Cyclic Redundancy Check，CRC）**相关能力标志：

| 位 | 含义 |
| --- | --- |
| 3:0 | I3C 1.x 规范版本。 |
| 5:4 | 组地址能力（Group Address Capabilities）。 |
| 6 | HDR-DDR 写入中止（Write Abort）。 |
| 7 | HDR-DDR 中止 CRC（Abort CRC）。 |

## 428.4\_GETCAPS3与GETCAPS4

第 3 字节 GETCAPS3 描述**多通道（Multi-Lane，ML）**、**设备间传输（Device-to-Device Transfer，D2DXFER）**和**带内中断（In-Band Interrupt，IBI）**能力。**定义字节（Defining Byte）**选择命令格式；**强制数据字节（Mandatory Data Byte，MDB）**是 IBI 的特定数据字节。

| 位 | 含义 |
| --- | --- |
| 0 | 支持 ML 数据传输。 |
| 1 | 支持 D2DXFER。 |
| 2 | 具备 D2DXFER IBI 能力。 |
| 3 | GETCAPS 支持定义字节。 |
| 4 | GETSTATUS 支持定义字节。 |
| 5 | 支持 HDR-BT CRC-32。 |
| 6 | 支持用 IBI MDB 发送待读取通知（Pending Read Notification）。 |
| 7 | 保留。 |

第 4 字节 GETCAPS4 的位 7:0 全部保留。

## 428.5\_格式2的目标能力与测试模式

格式 2 的成员由定义字节选择：

| 字段 | 类型 | 选择值及含义 |
| --- | --- | --- |
| `fmt2.tgtcaps` | `uint8_t [4]` | `0x00`：TGTCAPS，内容参见 `fmt1.getcaps`。 |
| `fmt2.testpat` | [`uint32_t`](https://docs.zephyrproject.org/latest/doxygen/html/stdint_8h.html#a0a8582351ac627ee8bde2973c825e47f) | `0x5A`：TESTPAT 测试模式（Test Pattern）。 |
| `fmt2.crcaps` | `uint8_t [2]` | `0x91`：CRCAPS 控制器能力数据。 |
| `fmt2.vtcaps` | `uint8_t [2]` | `0x93`：VTCAPS 虚拟目标能力数据。 |

[`testpat`](https://docs.zephyrproject.org/latest/doxygen/html/unioni3c__ccc__getcaps.html#afd68057c626bb954cee2b6b46350ebae) 应始终为按**大端字节序（Big-endian）**表示的 `0xA55AA55A`。

## 428.6\_CRCAPS控制器能力

`fmt2.crcaps[2]` 的第 1 字节为 CRCAPS1：

| 位 | 含义 |
| --- | --- |
| 0 | 支持热加入（Hot Join）。 |
| 1 | 支持组管理（Group Management）。 |
| 2 | 支持多通道。 |

第 2 字节为 CRCAPS2：

| 位 | 含义 |
| --- | --- |
| 0 | 支持带内中断。 |
| 1 | 控制权交回（Controller Pass-Back）。 |
| 2 | 具备深度睡眠（Deep Sleep）能力。 |
| 3 | 延迟控制权移交（Delayed Controller Handoff）。 |

## 428.7\_VTCAPS虚拟目标能力

`fmt2.vtcaps[2]` 描述**虚拟目标（Virtual Target）**能力。第 1 字节为 VTCAPS1：

| 位 | 含义 |
| --- | --- |
| 2:0 | 虚拟目标类型（Virtual Target Type）。 |
| 4 | 副作用（Side Effects）。 |
| 5 | 共享外设检测（Shared Peripheral Detect）。 |

第 2 字节为 VTCAPS2：

| 位 | 含义 |
| --- | --- |
| 1:0 | 中断请求（Interrupt Requests）。 |
| 2 | 地址重映射（Address Remapping）。 |
| 4:3 | 总线上下文与条件（Bus Context and Conditions）。 |

原字段页未说明这两类能力中未列出的位，此处不补造位定义。
