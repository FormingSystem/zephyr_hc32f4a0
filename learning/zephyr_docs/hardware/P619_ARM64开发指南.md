# 第619章\_ARM64开发指南

原文：[ARM64 Developer Guide](https://docs.zephyrproject.org/latest/hardware/arch/arm64.html)。读取日期：2026-10-13，`latest`。

## 619.1\_带超时的等待

Arm 的**带超时等待（Wait with Timeout，WFxT）**扩展提供带超时事件等待指令 `WFET` 和带超时中断等待指令 `WFIT`；它们以绝对虚拟计数器值作为超时参数。Zephyr 在运行时检查 `ID_AA64ISAR2_EL1` 的 `WFxT` 字段以检测此扩展。Arm64 架构代码可调用 `include/zephyr/arch/arm64/lib_helpers.h` 中声明的 `is_wfxt_implemented()` 查询支持情况。

当 Arm **架构定时器（Architectural Timer）**提供 [`arch_busy_wait()`](../timing_reference/P009_架构计数周期接口.md#gaffc9f3013d53e72c25243ce4f972549f) 实现，且具备 WFxT 时，Arm64 的 [`k_busy_wait()`](../thread_core_reference/P001_线程公共接口.md#ga550b642e071480323e589866abb99c22) 路径使用 `WFET`：由 `CNTVCT_EL0` 计算截止计数值，然后反复执行 `WFET`，直到计数器达到该值。之所以需要循环，是因为允许 `WFET` 在超时之前返回。不具备 WFxT 的处理器则轮询计数器。实现见 `drivers/timer/arm_arch_timer.c`。

默认的 Arm64 [`arch_cpu_idle()`](../arch_core_reference/P006_架构电源管理接口.md#ga6ce051203e6cc091d0fb42a15f662a48) 仍使用**等待中断（Wait for Interrupt，WFI）**指令。采用 Arm 架构定时器时，内核的下次超时被写入系统定时器，并由其中断唤醒处理器。在保留该中断的同时将 `WFI` 换成 `WFIT`，并不能省去定时器编程或中断处理。若要避免中断，需要复杂修改内核超时记账、重新调度及**对称多处理（Symmetric Multiprocessing，SMP）**系统的截止时刻协调；原文认为这会增加明显的风险与维护成本，且尚无已证明的收益。

## 619.2\_根据设备树建立MMU区域映射

ARM64 平台可在编译时根据**设备树（Devicetree）**自动填充**内存管理单元（Memory Management Unit，MMU）**页表。凡具有 `compatible = "zephyr,memory-region"` 且同时携带 `zephyr,memory-attr` 属性的节点，都会由架构启动代码转换为静态 `arm_mmu_region` 条目，无需为每个**片上系统（System on Chip，SoC）**修改 `mmu_regions.c`。

仅接受**普通内存（Normal Memory）**类型。**设备内存（Device Memory）**，即外设的**内存映射输入/输出（Memory-Mapped Input/Output，MMIO）**，必须通过 `DEVICE_MMIO` **应用编程接口（Application Programming Interface，API）**映射，参见[设备驱动模型（Device Driver Model）](P003_设备驱动模型.md)。

属性宏定义于 `include/zephyr/dt-bindings/memory-attr/memory-attr-arm64.h`，由通用的 `DT_MEM_CACHEABLE` 标志与架构专用子属性组合而成。**写回（Write-back，WB）**和**直写（Write-through，WT）**是两种不同的缓存写策略。

| 设备树宏 | 属性含义与组合 |
| --- | --- |
| `DT_MEM_ARM64_MMU_NORMAL` | 普通、写回、可缓存：`DT_MEM_CACHEABLE \| ATTR_ARM64_CACHE_WB` |
| `DT_MEM_ARM64_MMU_NORMAL_NC` | 普通、不可缓存（Non-cacheable，NC）：`0` |
| `DT_MEM_ARM64_MMU_NORMAL_WT` | 普通、直写、可缓存：`DT_MEM_CACHEABLE` |

## 619.3\_设备树覆盖文件示例

以下**覆盖文件（Overlay）**示例定义可缓存的共享内存池 `SHM0`，以及不可缓存的**直接内存访问（Direct Memory Access，DMA）**缓冲区 `DMA_BUF`。节点地址、长度及原始注释保持原样。

```dts
#include <zephyr/dt-bindings/memory-attr/memory-attr.h>
#include <zephyr/dt-bindings/memory-attr/memory-attr-arm64.h>

/ {
    soc {
        /* Cacheable shared memory pool */
        shm0: memory@42000000 {
            compatible = "zephyr,memory-region";
            reg = <0x0 0x42000000 0x0 0x1000>;
            zephyr,memory-region = "SHM0";
            zephyr,memory-attr = <DT_MEM_ARM64_MMU_NORMAL>;
        };

        /* Non-cacheable DMA buffer */
        dma_buf: memory@43000000 {
            compatible = "zephyr,memory-region";
            reg = <0x0 0x43000000 0x0 0x1000>;
            zephyr,memory-region = "DMA_BUF";
            zephyr,memory-attr = <DT_MEM_ARM64_MMU_NORMAL_NC>;
        };
    };
};
```

每个区域均以 `MT_P_RW_U_NA | MT_DEFAULT_SECURE_STATE`，结合由 `zephyr,memory-attr` 推导出的内存类型进行映射。

## 619.4\_转换表容量与属性组合

落在不同 2 MB 边界的每个映射区域，都需要额外的**三级页表（Level 3 Page Table）**。若新增区域后启动无输出地挂起，应在开发板或测试配置中增大 [`CONFIG_MAX_XLAT_TABLES`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MAX_XLAT_TABLES)：

```kconfig
CONFIG_MAX_XLAT_TABLES=16
```

所有非设备内存的属性组合都有效：通用位 `DT_MEM_CACHEABLE` 决定是否可缓存；可缓存时，架构专用子位 `ATTR_ARM64_CACHE_WB` 决定采用写回还是直写。
