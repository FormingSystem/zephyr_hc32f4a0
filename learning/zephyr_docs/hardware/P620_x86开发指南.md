# 第620章\_x86开发指南

原文：[x86 Developer Guide](https://docs.zephyrproject.org/latest/hardware/arch/x86.html)。读取日期：2026-10-13，`latest`。

## 620.1\_启动时的虚拟内存

本页说明面向 x86 平台开发时的部分架构事项。

在启动的很早阶段，页表已被加载，因此严格来说内核运行于**虚拟地址空间（Virtual Address Space）**。默认情况下，物理内存与虚拟内存采用**恒等映射（Identity Mapping）**，看起来就像直接在物理地址空间执行。

**设备树（Devicetree）**中的 [`DT_CHOSEN_SRAM_ADDR`](../dt_overview_reference/P005_选定SRAM区域宏.md#gad2693f2710d28709b0f129d5b791a29e) 与 [`DT_CHOSEN_SRAM_SIZE`](../dt_overview_reference/P005_选定SRAM区域宏.md#ga0a148f7de43111280b85a3ce4afaddea) 界定物理地址空间；[`CONFIG_KERNEL_VM_BASE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_KERNEL_VM_BASE) 与 [`CONFIG_KERNEL_VM_SIZE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_KERNEL_VM_SIZE) 界定虚拟地址空间。这里 SRAM 指**静态随机存取存储器（Static Random-Access Memory）**，VM 指**虚拟内存（Virtual Memory）**。[`CONFIG_SRAM_OFFSET`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SRAM_OFFSET) 控制 Zephyr 内核在内存中的放置位置，对应的虚拟地址偏移配置为 [`CONFIG_KERNEL_VM_OFFSET`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_KERNEL_VM_OFFSET)。

## 620.2\_分离物理与虚拟地址空间

32 位 x86 可以使用彼此分离的物理与虚拟地址空间。代码和数据链接至虚拟地址空间，但仍加载到物理内存中。不过，在执行 `arch/x86/core/ia32/crt0.S` 内的启动入口 `vm_enter` 之前，启动代码与数据必须已位于物理内存，并能通过物理地址访问。`vm_enter` 之后，代码通过虚拟地址执行，数据也可用虚拟地址引用。

之所以能完成这一转换，是因为页表生成脚本 `arch/x86/gen_mmu.py` 除了建立虚拟地址到物理内存的映射，还在**页目录（Page Directory，PD）**层级恒等映射物理地址。启动流程稍后在内存管理初始化函数 `z_x86_mmu_init()` 中清除页目录层级的恒等映射条目，从而撤销这组物理内存映射。

撤销操作是**用户空间隔离（Userspace Isolation）**所必需的，否则用户空间可通过物理地址访问受限内存。恒等映射建立在页目录层级，因此无需额外的页表空间，但仍可能需要为额外页目录表分配空间。

虚拟地址空间的放置有以下限制：

1. **物理与虚拟地址空间必须互不重叠。** 清理页目录时会移除条目；若两者重叠，将同时清除虚拟地址所需的条目。
2. 启用 `CONFIG_X86_PAE=y`，即**物理地址扩展（Physical Address Extension，PAE）**时，每个地址空间必须位于各自独立的 1 GB 区域，因为每个**页目录指针（Page Directory Pointer，PDP）**条目覆盖 1 GB。假设 `CONFIG_SRAM_OFFSET` 和 `CONFIG_KERNEL_VM_OFFSET` 均为 `0x0`，`DT_CHOSEN_SRAM_ADDR == 0x00000000` 配合 `CONFIG_KERNEL_VM_BASE = 0x40000000` 有效；配合 `CONFIG_KERNEL_VM_BASE = 0x20000000` 则无效。
3. 禁用 `CONFIG_X86_PAE=n` 时，每个地址空间必须位于各自独立的 4 MB 区域，因为每个 PD 条目覆盖 4 MB。
4. `DT_CHOSEN_SRAM_ADDR` 与 `CONFIG_KERNEL_VM_BASE` 都必须对齐到目标区域的起始地址。

## 620.3\_构建时增加内存映射

页表生成脚本 `arch/x86/gen_mmu.py` 使用第一次链接产生的内核映像，生成代码执行和数据访问所需的多级页表。可以额外传入命令行参数建立更多映射，用于静态映射，或启动极早阶段的设备**内存映射输入/输出（Memory-Mapped Input/Output，MMIO）**访问。

在开发板配置文件中填充名为 `X86_EXTRA_GEN_MMU_ARGUMENTS` 的 CMake 列表，即可向该脚本传递附加参数。官方示例如下：

```cmake
set(X86_EXTRA_GEN_MMU_ARGUMENTS
    --map 0xA0000000,0x2000
    --map 0x80000000,0x400000,LWUX,0xB0000000)
```

`--map` 的参数格式为 `<physical address>,<size>[,<flags:LUWX>[,<virtual address>]]`。原格式中的占位项含义为：

| 参数项 | 是否必需 | 含义 |
| --- | --- | --- |
| `<physical address>` | 必需 | 映射的物理地址 |
| `<size>` | 必需 | 待映射区域的大小 |
| `<flags>` | 可选 | 映射标志，见下表 |
| `<virtual address>` | 可选 | 映射的虚拟地址 |

| 标志 | 含义 |
| --- | --- |
| `L` | 页目录层级的大页（Large Page） |
| `U` | 允许用户空间访问（Userspace Access） |
| `W` | 可读写（Read/Write） |
| `X` | 允许执行（Execution） |
| `D` | 禁用缓存（Cache Disabled） |

默认采用 4 KB 小页，仅允许监管级访问、只读且禁止执行。译注：原文格式提示列出 `LUWX`，标志解释另包含 `D`；这里保留这一差异。

增加映射需要增大预分配页表的存储空间，包括内核页表及每个内存域的页表。使用 [`CONFIG_X86_EXTRA_PAGE_TABLE_PAGES`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_X86_EXTRA_PAGE_TABLE_PAGES) 指定额外预留的页数；若预留空间与实际所需空间并不恰好一致，`gen_mmu.py` 会输出消息，给出该 Kconfig 配置应设的值。
