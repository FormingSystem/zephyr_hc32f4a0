## 425.1\_接口范围与类型

本页为**改进的集成电路间总线（Improved Inter-Integrated Circuit，I3C）**控制器提供公共**应用程序编程接口（Application Programming Interface，API）**。接口自 Zephyr 3.2 提供，版本为 0.8.0；主头文件为 `zephyr/drivers/i3c.h`。

相关接口分别见[地址管理](P383_I3C地址槽管理.md)、[通用命令码](P429_I3C通用命令码参考.md)、[设备树宏](P424_I3C设备树宏.md)、[HDR DDR](P385_I3C高数据速率双沿模式.md)、[带内中断](P396_I3C带内中断接口.md)、[目标设备](P386_I3C目标设备接口.md)及[传输接口](P394_I3C传输接口.md)。

## 425.2\_BCR寄存器与位宏

**总线特征寄存器（Bus Characteristic Register，BCR）**可通过**通用命令码（Common Command Code，CCC）** `GETBCR` 取得。**带内中断（In-Band Interrupt，IBI）**可以携带**强制数据字节（Mandatory Data Byte，MDB）**。

| 位 | 宏 | 值与含义 |
| --- | --- | --- |
| 0 | [`I3C_BCR_MAX_DATA_SPEED_LIMIT`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga91ebe41a421dc05ae7f1de1ce2dd314f) | `BIT(0)`；0 无速度限制，1 表示限制需通过 `GETMXDS` 取得。 |
| 1 | [`I3C_BCR_IBI_REQUEST_CAPABLE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga0c09de8a18ea1586e37d35e073ae641f) | `BIT(1)`；0 不具备 IBI 请求能力，1 具备。 |
| 2 | [`I3C_BCR_IBI_PAYLOAD_HAS_DATA_BYTE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#gae119c230097cb8e1eab9fc45cafde838) | `BIT(2)`；0 表示接受 IBI 后没有数据字节，1 表示后跟一个 MDB，之后还可能有其他数据字节。 |
| 3 | [`I3C_BCR_OFFLINE_CAPABLE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga7b9fea89457022d8012ac25133bf63db) | `BIT(3)`；0 总会响应 I3C 命令，1 不保证总会响应。 |
| 4 | [`I3C_BCR_VIRTUAL_TARGET`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga69dc4a5004da568684a3c72046bba870) | `BIT(4)`；0 不是虚拟目标（Virtual Target），1 是虚拟目标。 |
| 5 | [`I3C_BCR_ADV_CAPABILITIES`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga07018705794753d0d0d65131f011e097) | `BIT(5)`；0 不支持可选高级能力，1 支持，可通过 `GETCAPS` 查询。 |
| 7:6 | [`I3C_BCR_DEVICE_ROLE_MASK`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga25721c9963040c84b7f5bbb48bb87b44) | `GENMASK(7U, 6U)`，设备角色位掩码。 |

角色值宏 [`I3C_BCR_DEVICE_ROLE_I3C_TARGET`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga867b4b12b23c803b86b57dcc86b9e604) 为 `0U`，表示 I3C 目标；[`I3C_BCR_DEVICE_ROLE_I3C_CONTROLLER_CAPABLE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga0e64c8aa6717b96bcf9dad6c9ec7f852) 为 `1U`，表示具备控制器能力。角色值 2 和 3 保留。

`I3C_BCR_DEVICE_ROLE(bcr)` 从参数 `bcr` 提取角色值，原展开如下。[`FIELD_GET`](https://docs.zephyrproject.org/latest/doxygen/html/silabs-pinctrl-siwx91x_8h.html#aa49a456f06f7bdbedfcf3517e461947e) 按位掩码提取字段，`BIT(n)` 表示第 n 位，`GENMASK(h,l)` 表示从高位 h 到低位 l 的掩码。

```c
FIELD_GET(I3C_BCR_DEVICE_ROLE_MASK, (bcr))
```

## 425.3\_遍历总线设备

以下四个宏均要求启用 Kconfig 配置项 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。`bus` 是 I3C 总线设备指针，`desc` 是设备描述符指针，每次循环被更新为当前设备。带 `_SAFE` 的版本使用额外设备描述符指针 `desc_s` 作为安全遍历临时变量。

`I3C_BUS_FOR_EACH_I2CDEV(bus, desc)` 遍历总线上的全部 I2C 设备：

```c
SYS_SLIST_FOR_EACH_CONTAINER(                                                              \
        &((struct i3c_driver_data *)(bus->data))->attached_dev.devices.i2c, desc, node)
```

`I3C_BUS_FOR_EACH_I2CDEV_SAFE(bus, desc, desc_s)` 安全遍历全部 I2C 设备：

```c
SYS_SLIST_FOR_EACH_CONTAINER_SAFE(                                                         \
        &((struct i3c_driver_data *)(bus->data))->attached_dev.devices.i2c, desc, desc_s,  \
        node)
```

`I3C_BUS_FOR_EACH_I3CDEV(bus, desc)` 遍历全部 I3C 设备：

```c
SYS_SLIST_FOR_EACH_CONTAINER(                                                              \
        &((struct i3c_driver_data *)(bus->data))->attached_dev.devices.i3c, desc, node)
```

`I3C_BUS_FOR_EACH_I3CDEV_SAFE(bus, desc, desc_s)` 安全遍历全部 I3C 设备：

```c
SYS_SLIST_FOR_EACH_CONTAINER_SAFE(                                                         \
        &((struct i3c_driver_data *)(bus->data))->attached_dev.devices.i3c, desc, desc_s,  \
        node)
```

这些展开使用内核单向链表（Singly Linked List）遍历宏及驱动的已附接设备列表。

## 425.4\_匹配标识初始化器

宏 `I3C_DEVICE_ID(pid)` 使用**预置标识（Provisioned ID，PID）**参数 `pid`，生成 `struct i3c_device_id` 的静态初始化器（Static Initializer）。

```c
{                                                               \
        .pid = pid                                              \
}
```

## 425.5\_定义RTIO设备

**实时输入/输出（Real-Time Input/Output，RTIO）**使用输入/输出设备（I/O Device，IODev）来提交请求。下列两个宏仅在启用 Kconfig 配置项 [`CONFIG_I3C_RTIO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_RTIO) 时可用。

`I3C_DT_INST_IODEV_DEFINE(name, inst)` 为设备树（Devicetree）实例定义 IODev。`name` 是定义的符号名，`inst` 是设备树实例编号；等价于 `I3C_DT_IODEV_DEFINE(name, DT_DRV_INST(inst))`：

```c
I3C_DT_IODEV_DEFINE(name, DT_DRV_INST(inst))
```

`I3C_DT_IODEV_DEFINE(name, node_id)` 为总线上给定的设备树节点定义 IODev。`node_id` 是节点标识符，`name` 是符号名。这些对象不必全局共享，不过共享可以节省少量内存。

```c
const struct i3c_iodev_data _i3c_iodev_data_##name = {                  \
        .bus = DEVICE_DT_GET(DT_BUS(node_id)),                          \
        .dev_id = I3C_DEVICE_ID_DT(node_id),                            \
};                                                                      \
RTIO_IODEV_DEFINE(name, &i3c_iodev_api, (void *)&_i3c_iodev_data_##name)
```

## 425.6\_LVR设备索引

**传统虚拟寄存器（Legacy Virtual Register，LVR）**描述 I3C 总线上的 I2C 设备。其第 7:5 位表示设备索引。**串行时钟线（Serial Clock Line，SCL）**上的 50 纳秒尖峰滤波器（Spike Filter）决定相应高速时钟兼容能力。

| 宏 | 值 | 含义 |
| --- | --- | --- |
| [`I3C_LVR_I2C_DEV_IDX_0`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga4319835ddb6b5984b21f5a5a2f14ae75) | `0` | 有 50 ns 尖峰滤波器，不受 SCL 高频信号影响。 |
| [`I3C_LVR_I2C_DEV_IDX_1`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga02a21af4c679a81b8290beea30c8ef40) | `1` | 无 50 ns 尖峰滤波器，但可以在 SCL 高频信号下工作。 |
| [`I3C_LVR_I2C_DEV_IDX_2`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga5950bb8ceea5fcd3ceb38c7da0d9dd68) | `2` | 无 50 ns 尖峰滤波器，且不能在 SCL 高频信号下工作。 |
| [`I3C_LVR_I2C_DEV_IDX_MASK`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga50fa249b36b91d56e49004548a1c7520) | `GENMASK(7U, 5U)` | I2C 设备索引位掩码。 |

宏 `I3C_LVR_I2C_DEV_IDX(lvr)` 从参数 `lvr` 提取设备索引：

```c
FIELD_GET(I3C_LVR_I2C_DEV_IDX_MASK, (lvr))
```

## 425.7\_LVR速度模式与开漏时序

LVR 第 4 位表示 I2C 速度模式；第 3:0 位保留。**快速模式（Fast Mode，FM）**与**增强快速模式（Fast Mode Plus，FM+）**的值如下：

| 宏 | 值 | 含义 |
| --- | --- | --- |
| [`I3C_LVR_I2C_FM_PLUS_MODE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga9bf868ac6ae38e3f8ab6e5e1378bfb75) | `0` | FM+ 模式。 |
| [`I3C_LVR_I2C_FM_MODE`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga053945f5f67ee3c681de2c9362e69c39) | `1` | FM 模式。 |
| [`I3C_LVR_I2C_MODE_MASK`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#gaf073cc9ea1a68c57663c36de12554876) | `BIT(4)` | 模式指示位掩码。 |

宏 `I3C_LVR_I2C_MODE(lvr)` 从参数 `lvr` 读取模式值：

```c
FIELD_GET(I3C_LVR_I2C_MODE_MASK, (lvr))
```

以下宏给出标准 I3C **单数据速率（Single Data Rate，SDR）**与 I2C FM 速度相关的**开漏（Open Drain，OD）**时序最大/最小值，单位为纳秒：

| 宏 | 值 |
| --- | --- |
| [`I3C_OD_TLOW_MIN_NS`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#gadd026a36545d50ea3c043d0ebcfde95b) | `200` |
| [`I3C_OD_MIXED_BUS_THIGH_MAX_NS`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga7478181801369cb7ed7a7124fa9c4240) | `41` |
| [`I3C_OD_FIRST_BC_THIGH_MIN_NS`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ga41fc93e0aba6bc1cf3540ca89e860a2b) | `200` |

> 译注：按宏名称，三者分别表示开漏低电平最短时间、混合总线开漏高电平最长时间、首个广播开漏高电平最短时间；原宏条目没有额外解释后两项。

| [`I3C_DATA_RATE_MAX`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ggae9d98642c6f249ee0e6ea0dc491b5073a4b8e5152ac9e2a54fad142cc47b13725) | 等于 `I3C_DATA_RATE_HDR_BT`。 |
| [`I3C_DATA_RATE_INVALID`](https://docs.zephyrproject.org/latest/doxygen/html/group__i3c__interface.html#ggae9d98642c6f249ee0e6ea0dc491b5073a511dd2b924d1d423adbaa841b941748a) | 无效速率枚举项。 |

异步请求完成或出错时，调用以下**回调（Callback）**：

```c
typedef void (*i3c_callback_t)(const struct device *dev, int result, void *data);
```

`dev` 是通知完成或错误的 I3C 设备；`result` 为结果，0 表示成功，失败为负错误码 `-errno`；`data` 是请求者提供并传递给回调的数据。

以下各函数的配置条件、参数及返回值分别列出。原声明中静态内联（Static Inline）属性继续保留。

## 425.10\_按标识查询已知设备

```c
struct i3c_device_desc * i3c_dev_list_find (const struct i3c_dev_list *dev_list, const struct i3c_device_id *id);
```

要求启用 Kconfig 配置项 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。

在 `dev_list` 指向的设备列表中，查找与 `id` 指向的 I3C 设备标识结构匹配的目标描述符。找到返回描述符指针，未找到返回 `NULL`。

## 425.11\_按动态地址查询I3C设备

```c
struct i3c_device_desc * i3c_dev_list_i3c_addr_find (const struct device *dev, uint8_t addr);
```

要求启用 Kconfig 配置项 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。

## 425.14\_动态地址分配的地址选择

```c
int i3c_dev_list_daa_addr_helper (const struct device *dev, uint64_t pid, bool must_match, bool assigned_okay, struct i3c_device_desc **target, uint8_t *addr);
```

要求启用 Kconfig 配置项 [`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)。

在 `ENTDAA` **动态地址分配（Dynamic Address Assignment，DAA）**过程中寻找可用地址。`dev` 是控制器驱动实例，`pid` 是待分配设备的预置标识。

按 PID 搜索设备列表。如果匹配描述符给出首选地址，即设备树的 `assigned-address` / 字段 `init_dynamic_addr`，且地址仍可用，就返回它；否则返回另一个空闲地址。

- `must_match = true`：PID 必须匹配设备列表中的设备。
- `must_match = false`：允许返回任意地址，适合设备树没有描述全部设备的情况；否则这些设备会因无法分配地址而阻止 DAA 继续。
- `assigned_okay = true`：允许返回已经分配给该设备的 `dynamic_addr`；若尚未分配，行为与 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727) 相同。可用于设备从挂起恢复后热加入（Hot Join）时重新获得原地址。
- `assigned_okay = false`：设备不能已经有地址，即其 `dynamic_addr` 不能为非零；主要用于首次 DAA。

输出参数 `target` 保存与输入 PID 匹配的设备描述符指针，`addr` 保存要分配的地址。

成功返回 0；`must_match` 为真但无设备匹配时返回 `-ENODEV`；匹配设备已经有地址或函数实参无效时返回 `-EINVAL`。

## 425.55\_移交控制权

按 I3C 1.1.1 规范第 5.1.7.1 节执行控制权移交（Controller Handoff）。`target` 指向目标描述符；`requested` 为 `true` 表示由目标请求移交，`false` 表示当前活动控制器主动把控制权交给次级控制器。成功返回 0，通用 I/O 错误返回 `-EIO`，目标不能接受移交返回 `-EBUSY`。

## 425.56\_接收控制权后的处理回调


要求启用 Kconfig 配置项 [`CONFIG_I3C_USE_IBI`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_USE_IBI)、[`CONFIG_I3C_CONTROLLER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_CONTROLLER)、[`CONFIG_I3C_TARGET`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_I3C_TARGET)。

当控制权移交给本设备时调用。`work` 指向工作项（Work Item）。函数读取此前收到的 `DEFTGTS`，通过 `GETPID` 读取全部设备 PID 并与已知 PID 匹配。无法匹配时，尝试从内存块池（Memory Slab）取得 [`i3c_device_desc`](https://docs.zephyrproject.org/latest/doxygen/html/structi3c__device__desc.html)，然后获取设备的标准 I3C 信息。
