### `RESET_DT_SPEC_GET_BY_IDX`

```c
#define RESET_DT_SPEC_GET_BY_IDX ( node_id, idx )
```

```c
#include <zephyr/drivers/reset.h>
```

展开值（Value）：

```c
{                                                                       \
        .dev = DEVICE_DT_GET(DT_RESET_CTLR_BY_IDX(node_id, idx)),       \
        .id = DT_RESET_ID_BY_IDX(node_id, idx)                          \
}
```

reset_dt_spec的静态初始化器（Static Initializer）。

给定设备树节点标识符、指定复位控制器的属性以及索引，返回reset_dt_spec结构的静态初始化器。

设备树片段示例：

原始示例（Example）：

```dts
 n: node {
    resets = <&reset 10>;
 }
```

使用示例：

原始示例（Example）：

```c
 const struct reset_dt_spec spec = RESET_DT_SPEC_GET_BY_IDX(DT_NODELABEL(n), 0);
 // Initializes 'spec' to:
 // {
 //         .dev = DEVICE_DT_GET(DT_NODELABEL(reset)),
 //         .id = 10
 // }
```

仍须检查reset字段是否就绪，例如使用device_is_ready()。除非该节点存在、具有指定属性，并且该属性如上所示指定了复位控制器的复位线ID，否则使用此宏就是错误的。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 设备树节点标识符（Devicetree Node Identifier）。 |
| `idx` | resets中的逻辑索引（Logical Index）。 |

返回（Returns）：该属性对应的struct reset_dt_spec静态初始化器。

> 译注——源码核对：描述结构：reset_dt_spec实际只有dev和id两个成员。原文RESET_DT_SPEC_GET_BY_IDX说明中写检查reset字段，属于字段名不一致；应检查spec.dev所指控制器设备是否就绪。静态初始化器只产生结构内容，不执行复位、不初始化控制器。四个_dt函数仅将spec->dev和spec->id转交普通接口，不另外验证spec或设备。

### `RESET_DT_SPEC_GET_BY_IDX_OR`

```c
#define RESET_DT_SPEC_GET_BY_IDX_OR ( node_id, idx, default_value )
```

```c
#include <zephyr/drivers/reset.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_NODE_HAS_PROP(node_id, resets),                  \
            (RESET_DT_SPEC_GET_BY_IDX(node_id, idx)),           \
            (default_value))
```

类似RESET_DT_SPEC_GET_BY_IDX()，但可回退到默认值（Default Value）。

如果设备树节点标识符node_id指向的节点具有resets属性，则展开为RESET_DT_SPEC_GET_BY_IDX(node_id, idx)。此时不会展开default_value参数。

否则展开为default_value。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 设备树节点标识符（Devicetree Node Identifier）。 |
| `idx` | resets属性中的逻辑索引。 |
| `default_value` | 要展开为的回退值（Fallback Value）。 |

返回（Returns）：该属性对应的struct reset_dt_spec静态初始化器；如果节点或属性不存在，则返回default_value。

> 译注——源码核对：回退条件差异：普通节点RESET_DT_SPEC_GET_BY_IDX_OR只检查节点是否有resets属性，不检查idx是否存在；属性存在但索引越界时仍会展开取值宏，不能期待自动使用default_value。实例RESET_DT_SPEC_INST_GET_BY_IDX_OR使用DT_PROP_HAS_IDX，检查指定索引。这一差别按本次源码说明，不把两类_OR都概括为相同的索引保护。

## 1.7\_源码定位与版本边界

本册包括公共接口、驱动后端、设备树描述结构、操作结构、驱动头文件参考与源码，以及设备树宏组和头文件参考与源码。相对源码定位：[驱动接口reset.h](../../../include/zephyr/drivers/reset.h)和[设备树辅助reset.h](../../../include/zephyr/devicetree/reset.h)。本次官方原始文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：操作语义：使复位生效（Assert）是让目标进入复位状态，释放复位（Deassert）是退出该状态，不等于固定写1或写0；具体极性和寄存器语义由驱动／硬件决定。toggle的契约是assert再deassert，不是单纯翻转当前逻辑值，也不意味着重启整个系统。

> 译注——源码核对：版本范围：本册覆盖公共接口、驱动后端、描述和操作结构，以及两份头文件和设备树宏组；公共页链接到的各厂商复位编码仍按各自页面进度计，不因入口已译而标成全部完成。保留源码、示例和法律声明，去掉注释和展示空白后两份源码与本次官方头文件一致。本地源码采用相对链接，不假定滚动main与任意本地基线相同。
