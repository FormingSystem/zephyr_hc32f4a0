## 1.3\_详细说明（Detailed Documentation）

<a id="ga50d995ef13e80eb36cfc8556e39056d0"></a>

### `ITERABLE_SECTION_RAM`

```c
#define ITERABLE_SECTION_RAM ( struct_type, subalign )
```

```c
#include <zephyr/linker/iterable_sections.h>
```

展开值（Value）：

```c
SECTION_DATA_PROLOGUE(struct_type##_area, ,) \
{ \
        Z_LINK_ITERABLE(struct_type); \
} GROUP_DATA_LINK_IN(RAMABLE_REGION, ROMABLE_REGION)
```

定义可读写的可遍历输出段。

定义一个输出段，建立由等大小数据结构组成的可遍历区域，与STRUCT_SECTION_ITERABLE()配合使用。输入段（Input Section）按ld的SORT_BY_NAME规则按名称排序。

本宏用于运行时需要修改的可读写数据。

即使符号没有被直接引用，此宏也会将它们保留在映像中。当代码通过遍历段间接引用符号时，应使用此形式。

> 译注——源码核对：当前实现通过Z_LINK_ITERABLE使用KEEP与SORT_BY_NAME，按名称排序并保留匹配的输入段。RAM形式表示数据可在运行时修改，不表示集合可动态增删。六个公共ROM／RAM宏虽有subalign形参，本次宏体均没有使用该参数；不能仅凭传入某个值就断言已设置输入子段对齐，应核对实际布局及所用版本。

### `ITERABLE_SECTION_RAM_GC_ALLOWED`

```c
#define ITERABLE_SECTION_RAM_GC_ALLOWED ( struct_type, subalign )
```

```c
#include <zephyr/linker/iterable_sections.h>
```

展开值（Value）：

```c
SECTION_DATA_PROLOGUE(struct_type##_area, ,) \
{ \
        Z_LINK_ITERABLE_GC_ALLOWED(struct_type); \
} GROUP_DATA_LINK_IN(RAMABLE_REGION, ROMABLE_REGION)
```

定义允许链接器垃圾回收的可读写可遍历输出段。

定义一个输出段，建立由等大小数据结构组成的可遍历区域，与STRUCT_SECTION_ITERABLE()配合使用。输入段（Input Section）按ld的SORT_BY_NAME规则按名称排序。

本宏用于运行时需要修改的可读写数据。

段内符号允许被链接器垃圾回收。

> 译注——源码核对：当前辅助展开省去KEEP，因此允许链接器清理未使用的输入段；是否实际移除还取决于链接配置及引用关系。这里的垃圾回收发生在链接阶段，不是运行时释放堆对象。subalign在本次宏体中未使用。

### `ITERABLE_SECTION_RAM_NUMERIC`

```c
#define ITERABLE_SECTION_RAM_NUMERIC ( struct_type, subalign )
```

```c
#include <zephyr/linker/iterable_sections.h>
```

展开值（Value）：

```c
SECTION_PROLOGUE(struct_type##_area, EMPTY,) \
{ \
        Z_LINK_ITERABLE_NUMERIC(struct_type); \
} GROUP_DATA_LINK_IN(RAMABLE_REGION, ROMABLE_REGION)
```

定义按数字排序的可读写可遍历输出段。

ITERABLE_SECTION_RAM()的这个版本按数字排列条目，即SECNAME10位于SECNAME2之后。最多处理两位数字，范围为0～99。

**参阅（See Also）**：另请参阅ITERABLE_SECTION_RAM()。

> 译注——源码核对：原文称最多两位数字，当前Z_LINK_ITERABLE_NUMERIC实际依次使用`._<struct_type>.static.*_?_*`至`._<struct_type>.static.*_?????_*`所对应的一至五个字符匹配长度，具体原始模式见链接器源码。这是按名称模式分组后排序，问号匹配字符，不是通用数值解析器；应使用符合约定的数字后缀和下划线，不能把任意字符串、负数或补零数字都视为自动正确排序。RAM描述中的SECNAME10／SECNAME2也未体现当前下划线模式。subalign在本次宏体中未使用。

为可遍历段起始符号提供extern声明的辅助宏，典型调用为TYPE_SECTION_START_EXTERN(struct foobar, foobar)。这使宏能够处理不同类型，以及类型名称与段名称不同的情况。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[in] type` | 段中元素的数据类型。 |
| `[in] secname` | 输出段名称。 |

## 1.4\_源码定位与版本边界

C侧辅助宏位于[sys/iterable_sections.h](../../../include/zephyr/sys/iterable_sections.h)，链接脚本侧定义位于[linker/iterable_sections.h](../../../include/zephyr/linker/iterable_sections.h)。本次核对[官方C侧头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/iterable_sections.h)与[官方链接器头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/linker/iterable_sections.h)，摘要见[来源记录](../SOURCES.md)；本地源码、滚动更新的main和latest网页不能自动视为同一版本。

> 译注——排序和对齐的版本边界：原文数字排序说明保留两位数限制，但当前源码有一至五字符模式；这不是无限范围的数值排序器。当前六个公共输出段宏接收subalign却未使用它，另有内部Z_LINK_ITERABLE_ALIGNED显式执行ALIGN。对象声明侧的Z_DECL_ALIGN、输出地址对齐和输入子段布局是不同环节，不能相互替代。

本批只做官方文档翻译与源码核对，没有编译或链接测试固件，也未执行运行时注册／遍历实验。
