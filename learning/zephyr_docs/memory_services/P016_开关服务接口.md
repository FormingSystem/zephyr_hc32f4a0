# 第16章\_开关服务接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__resource__mgmt__onoff__apis.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 16.1\_概述

开关服务接口（On-Off Service APIs）用于管理共享资源的二值状态和多个客户端的使用请求。原文所属主题为资源管理（Resource Management）。

```c
#include <zephyr/sys/onoff.h>
```

## 16.3\_ONOFF\_CLIENT\_EXTENSION\_POS

<a id="gad61d053ae4e9ee12efe8d37372a16c63"></a>
<a id="r_gad61d053ae4e9ee12efe8d37372a16c63"></a>

```c
#define ONOFF_CLIENT_EXTENSION_POS SYS_NOTIFY_EXTENSION_POS
```

```c
#include <zephyr/sys/onoff.h>
```

标识 [`sys_notify`](P014_异步通知结构.md) 标志中可供外层服务使用的位区域。

原文所称 `queued_operation` 结构体内包含的 [`sys_notify`](P014_异步通知结构.md)，其 `flags` 字段从此位置开始及更高位置的位，可供 [`onoff_client`](P019_开关客户端结构.md) 结构体的扩展使用。

这些位供外层服务实现记录客户端专用信息，并须遵守 [`sys_notify`](P014_异步通知结构.md) API 规定的其他使用条件。

> 译注：原文仍使用 queued_operation 名称；本页及头文件中的实际客户端类型是 onoff_client，其 notify 成员类型为 sys_notify。该名称按原文保留，不应据此假定还需另一种公开结构体。

## 16.6\_ONOFF\_STATE\_MASK

<a id="ga0e06eafdf5021ce970027f20fc001acc"></a>
<a id="r_ga0e06eafdf5021ce970027f20fc001acc"></a>

```c
#define ONOFF_STATE_MASK
```

```c
#include <zephyr/sys/onoff.h>
```

用于提取服务状态位的掩码（Mask）。

先用此掩码提取某个值，再检查 [`ONOFF_FLAG_ERROR`](#ga9ae0c3528254b10f5e1a9743aea234dd)，以判断状态机是否存在尚未清除的错误；也可与 [`ONOFF_STATE_ON`](#ga7cd0fba52afba2e337ab7c830d3058d7)、[`ONOFF_STATE_OFF`](#gab9e5380dce026a5dfea770f999400484)、[`ONOFF_STATE_TO_ON`](#gac4a0d8a7b501adb011aa1c4c4da3f2a3)、[`ONOFF_STATE_TO_OFF`](#ga235a04122763f1a2cbb849c56df65d26) 或 [`ONOFF_STATE_RESETTING`](#gacc0438b5c81c639e0035ada5caec940b) 比较。

展开值（Value）：

```c
(ONOFF_FLAG_ERROR   \
| ONOFF_FLAG_ONOFF \
| ONOFF_FLAG_TRANSITION)
```

## 16.13\_onoff\_client\_callback

<a id="ga41b94526182c5772d7adebb1d1745068"></a>
<a id="r_ga41b94526182c5772d7adebb1d1745068"></a>

```c
typedef void(* onoff_client_callback) (struct onoff_manager *mgr, struct onoff_client *cli, uint32_t state, int res)
```

```c
#include <zephyr/sys/onoff.h>
```

用于通知开关服务客户端操作完成的函数签名（Function Signature）。

这些函数可能在任何上下文中调用，包括内核初始化前（Pre-kernel）、中断服务例程（Interrupt Service Routine，ISR）、协作式线程（Cooperative Thread）或可抢占线程（Preemptible Thread）。兼容的函数必须满足可在中断中调用（isr-ok）的要求，而且不能休眠。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 发起该操作的管理器。如果开关服务采用同步转换，此值可以为空。 |
| `cli` | 传给操作发起函数的客户端结构体。 |
| `state` | 完成时的状态机状态，仅包含 [`ONOFF_STATE_MASK`](#ga0e06eafdf5021ce970027f20fc001acc) 范围内的位。不论 `res` 是否为负，都必须单独检查 [`ONOFF_FLAG_ERROR`](#ga9ae0c3528254b10f5e1a9743aea234dd)，因为状态机错误可能表示以后除 [`onoff_reset`](#gaf7b46a5f2e43d1bab193c18b8f6c8ba8)() 外的所有操作都将失败。 |
| `res` | 操作结果。预期值由具体服务规定，但成功时必须为非负数，失败时必须为负数。`res` 为负时，`state` 中会设置 [`ONOFF_FLAG_ERROR`](#ga9ae0c3528254b10f5e1a9743aea234dd)；即使 `res` 非负，`state` 中仍可能设置 [`ONOFF_FLAG_ERROR`](#ga9ae0c3528254b10f5e1a9743aea234dd)。 |

## 16.14\_onoff\_monitor\_callback

<a id="gaee41b38d408cf5f5efc9cd007f377545"></a>
<a id="r_gaee41b38d408cf5f5efc9cd007f377545"></a>

```c
typedef void(* onoff_monitor_callback) (struct onoff_manager *mgr, struct onoff_monitor *mon, uint32_t state, int res)
```

```c
#include <zephyr/sys/onoff.h>
```

用于通知开关服务监视器（Monitor）发生错误或状态转换完成的函数签名。

与 [`onoff_client_callback`](#ga41b94526182c5772d7adebb1d1745068) 类似，但它提供所有转换的信息，而不局限于某个客户端相关的转换。监视器回调先于该状态变化关联的任何完成通知执行。

这些函数可能在任何上下文中调用，包括内核初始化前（Pre-kernel）、中断服务例程（Interrupt Service Routine，ISR）、协作式线程（Cooperative Thread）或可抢占线程（Preemptible Thread）。兼容的函数必须满足可在中断中调用（isr-ok）的要求，而且不能休眠。

回调允许从管理器注销自身，但不得注册或注销其他监视器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 转换已完成的管理器。 |
| `mon` | 接收本次通知的监视器实例。 |
| `state` | 完成时的状态机状态，仅包含 [`ONOFF_STATE_MASK`](#ga0e06eafdf5021ce970027f20fc001acc) 范围内的位。所有有效状态都可能被观测到。 |
| `res` | 操作结果。预期值取决于具体服务和状态，但成功时必须为非负数，失败时必须为负数。 |

## 16.15\_onoff\_notify\_fn

<a id="gac05f7946a14fa23ef67212eba30c98ac"></a>
<a id="r_gac05f7946a14fa23ef67212eba30c98ac"></a>

```c
typedef void(* onoff_notify_fn) (struct onoff_manager *mgr, int res)
```

```c
#include <zephyr/sys/onoff.h>
```

用于通知开关管理器（On-Off Manager）状态转换已经完成的函数签名。

这种类型的函数传给服务专用的转换函数，用于报告操作完成。它们可以在任何上下文中调用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 请求执行转换的管理器。 |
| `res` | 转换结果。成功时必须为非负数，失败时为负错误码。如果结果表示错误，服务将进入错误状态。 |

## 16.16\_onoff\_transition\_fn

<a id="ga51fdf83642c5fa16112ce143382ec5d1"></a>
<a id="r_ga51fdf83642c5fa16112ce143382ec5d1"></a>

```c
typedef void(* onoff_transition_fn) (struct onoff_manager *mgr, onoff_notify_fn notify)
```

```c
#include <zephyr/sys/onoff.h>
```

服务实现用于执行状态转换的函数签名。

服务定义必须提供两个此类型的函数指针，以接收需要执行转换的通知；还可选提供第三个函数，在服务处于错误状态时执行复位。

仅在关闭状态下调用 `start` 函数。

仅在开启状态下调用 `stop` 函数。

如果支持 `reset` 函数，仅在 [`onoff_has_error`](#ga347efda0aa0305c134224c59677fa6cb)() 返回 `true` 时调用它。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 请求执行转换的管理器。 |
| `notify` | 转换完成时应调用的函数。如果转换同步完成，实现必须在转换函数返回前调用 `notify`；否则必须保存此参数，并在转换完成时调用它。 |

**原文注意（Note）**：所有转换函数都必须满足可在中断中调用（isr-ok）的要求。

## 16.17\_onoff\_cancel()

<a id="gad05d32f1548e56b508628e84ba101554"></a>
<a id="r_gad05d32f1548e56b508628e84ba101554"></a>

```c
int onoff_cancel ( struct onoff_manager * mgr, struct onoff_client * cli )
```

```c
#include <zephyr/sys/onoff.h>
```

尝试取消进行中的客户端操作。

客户端可能已经发起操作，却需要在操作完成前停止使用它，例如发起请求后，原有需求已经消失。

只支持取消 [`onoff_request`](#ga20dcb358e405deb87b7fbb7846ef9d68)() 和 [`onoff_reset`](#gaf7b46a5f2e43d1bab193c18b8f6c8ba8)() 操作，取消本身同步完成。须注意：为该客户端发起的任何转换仍会继续直到完成，可能被消除的仅是转换完成通知。若开启转换完成时已没有活动请求，管理器将发起关闭转换。

已取消的操作不会再发出客户端通知。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 需要取消操作的管理器。 |
| `cli` | 指向发起待取消操作时所提供的同一个客户端状态对象。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 取消成功时，返回取消时观测到的状态机状态；成功取消后，*`cli` 的所有权（Ownership）归还客户端。 |
| `-EINVAL` | 参数无效。 |
| `-EALREADY` | 处理取消时，`cli` 已不对应尚未完成的通知记录。这通常表示操作及客户端通知已经完成。 |

## 16.18\_onoff\_cancel\_or\_release()

<a id="ga7aac2aeb66907ec920557f0ef67d6795"></a>
<a id="r_ga7aac2aeb66907ec920557f0ef67d6795"></a>

```c
static inline int onoff_cancel_or_release ( struct onoff_manager * mgr, struct onoff_client * cli )
```

```c
#include <zephyr/sys/onoff.h>
```

用于安全取消请求的辅助函数。

一些应用希望在异步事件发生时请求资源，例如连接 USB 总线，并在成对事件发生时释放资源，例如断开 USB 总线。如果不使用 [`onoff_monitor`](P021_开关监视器结构.md) 并谨慎避免竞态条件（Race Condition），应用就无法准确判断进行中的请求是否仍在等待。

此辅助函数先尝试取消操作；若因请求已完成而取消失败，则发起释放。这以同步方式确保客户端数据的所有权归还客户端，以供以后再次请求。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 需要取消操作的管理器。 |
| `cli` | 指向调用 [`onoff_request`](#ga20dcb358e405deb87b7fbb7846ef9d68)() 时提供的同一个客户端状态对象。若指向与 [`onoff_reset`](#gaf7b46a5f2e43d1bab193c18b8f6c8ba8)() 请求关联的客户端数据，行为未定义。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `ONOFF_STATE_TO_ON` | 取消发生在转换完成之前。 |
| `ONOFF_STATE_ON` | 取消发生在转换完成之后。 |
| `-EINVAL` | 参数无效。 |
| `<0` | [`onoff_release`](#ga19da5359f10fa2e2eb034d1e72235ea6)() 产生的其他错误。 |

## 16.19\_onoff\_has\_error()

<a id="ga347efda0aa0305c134224c59677fa6cb"></a>
<a id="r_ga347efda0aa0305c134224c59677fa6cb"></a>

```c
static inline bool onoff_has_error ( const struct onoff_manager * mgr)
```

```c
#include <zephyr/sys/onoff.h>
```

检查开关服务是否记录了错误。

此函数可判断服务是否记录了错误。可以调用 [`onoff_reset`](#gaf7b46a5f2e43d1bab193c18b8f6c8ba8)() 清除错误。

这是不加锁的便捷函数。只有确定其他执行流程不会调用导致服务在错误和非错误状态之间转换的操作时，才适合使用。

**返回（Returns）**：当且仅当服务存在尚未清除的错误时返回 `true`。

## 16.20\_onoff\_manager\_init()

<a id="ga73d52272baab03d1df2f267429390978"></a>
<a id="r_ga73d52272baab03d1df2f267429390978"></a>

```c
int onoff_manager_init ( struct onoff_manager * mgr, const struct onoff_transitions * transitions )
```

```c
#include <zephyr/sys/onoff.h>
```

将开关服务初始化为关闭状态。

对每个服务实例，必须由提供服务的基础设施恰好调用一次此函数，并且须在对该服务调用任何其他开关服务 API 之前完成。

开关服务的客户端不应调用此函数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 要初始化的管理器定义对象。 |
| `transitions` | 指向提供转换函数的结构体。只要管理器仍可能被引用，该结构体就必须保持有效。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-EINVAL` | 原文说明：`start`、`stop` 或 `flags` 无效。 |

> 译注：原返回说明中的 flags 是遗留措辞。本轮官方[实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/onoff.c)检查 mgr、transitions 以及 transitions 的 start、stop 是否为空；当前签名没有 flags 参数，转换函数结构也没有 flags 字段。初始化属于服务提供者职责，不能用来替代客户端的错误复位。

## 16.21\_onoff\_monitor\_register()

<a id="ga9897d93359fe58359c0204da46b4c01e"></a>
<a id="r_ga9897d93359fe58359c0204da46b4c01e"></a>

```c
int onoff_monitor_register ( struct onoff_manager * mgr, struct onoff_monitor * mon )
```

```c
#include <zephyr/sys/onoff.h>
```

为管理器添加状态变化监视器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 要监视其状态变化的管理器。 |
| `mon` | 可链接的节点，提供状态变化时应调用的非空回调。 |

**返回（Returns）**：添加成功时返回非负数，否则返回负错误码。

## 16.23\_onoff\_release()

<a id="ga19da5359f10fa2e2eb034d1e72235ea6"></a>
<a id="r_ga19da5359f10fa2e2eb034d1e72235ea6"></a>

```c
int onoff_release ( struct onoff_manager * mgr)
```

```c
#include <zephyr/sys/onoff.h>
```

释放先前保留的开关服务使用权。

此函数同步释放调用者先前的请求。若释放的是最后一个请求，管理器将发起关闭转换；可以注册 [`onoff_monitor`](P021_开关监视器结构.md) 来观察这一过程。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 先前请求成功的管理器。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 释放成功时，返回释放时观测到的状态机状态 [`ONOFF_STATE_ON`](#ga7cd0fba52afba2e337ab7c830d3058d7)。 |
| `-EIO` | 服务已记录错误。 |
| `-ENOTSUP` | 状态机所处状态不允许释放。 |

**原文注意（Note）**：若未与先前成功完成的 [`onoff_request`](#ga20dcb358e405deb87b7fbb7846ef9d68)() 调用配对，行为未定义。

> 译注：“同步释放”指释放使用请求；若引发关闭转换，硬件关闭本身仍可能异步完成。观察关闭过程应使用监视器。

## 16.24\_onoff\_request()

<a id="ga20dcb358e405deb87b7fbb7846ef9d68"></a>
<a id="r_ga20dcb358e405deb87b7fbb7846ef9d68"></a>

```c
int onoff_request ( struct onoff_manager * mgr, struct onoff_client * cli )
```

```c
#include <zephyr/sys/onoff.h>
```

请求保留开关服务的使用权。

返回值表示发起“请求资源可用”操作的尝试是否成功。若成功发起，请求操作的最终结果通过配置好的客户端通知方式提供，而且可能在本次调用返回前就已提供。

注意，即使实际请求最终失败，本函数调用本身也可能成功。始终检查操作完成结果。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 要使用的管理器。 |
| `cli` | 指向客户端状态的非空指针，其中指定同步方面的要求以及请求完成时如何通知客户端。若客户端传入与尚未完成的服务操作关联的对象指针，行为未定义。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 成功时，返回处理请求时观测到的状态机状态。 |
| `-EIO` | 服务已记录错误。 |
| `-EINVAL` | 参数无效。 |
| `-EAGAIN` | 引用计数（Reference Count）将发生溢出。 |

## 16.25\_onoff\_reset()

<a id="gaf7b46a5f2e43d1bab193c18b8f6c8ba8"></a>
<a id="r_gaf7b46a5f2e43d1bab193c18b8f6c8ba8"></a>

```c
int onoff_reset ( struct onoff_manager * mgr, struct onoff_client * cli )
```

```c
#include <zephyr/sys/onoff.h>
```

清除开关服务错误，并将其复位到关闭状态。

只有当 [`onoff_has_error`](#ga347efda0aa0305c134224c59677fa6cb)() 指示服务处于错误状态时，才可以复位服务。

返回值表示发起资源复位操作的尝试是否成功。若成功发起，复位操作本身的结果通过配置好的客户端通知方式提供，可能在本次调用返回前就已提供。多个客户端可以请求复位，完成时会通知所有这些客户端。

注意，即使实际复位最终失败，本函数调用本身也可能成功。始终检查操作完成结果。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mgr` | 要复位的管理器。 |
| `cli` | 指向客户端状态，其中包含复位完成时如何通知客户端的设置。如果 `cli` 引用与尚未完成的服务操作关联的对象，行为未定义。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 复位成功时，返回复位时观测到的状态机状态。 |
| `-ENOTSUP` | 服务不支持复位。 |
| `-EINVAL` | 参数无效。 |
| `-EALREADY` | 服务没有已记录的错误。 |

**原文注意（Note）**：根据状态转换条件，所有尚未完成的异步操作都会在错误发生时收到错误通知。因此，不必担心复位完成后仍残留悬而未决的请求。

## 16.26\_onoff\_sync\_finalize()

<a id="gae3331bdad9d03309ee78e86c487b7f26"></a>
<a id="r_gae3331bdad9d03309ee78e86c487b7f26"></a>

```c
int onoff_sync_finalize ( struct onoff_sync_service * srv, k_spinlock_key_t key, struct onoff_client * cli, int res, bool on )
```

```c
#include <zephyr/sys/onoff.h>
```

处理同步服务的转换完成，并释放锁。

此函数依据 `res` 和 `on` 参数更新服务状态，然后释放锁。如果 `cli` 不为空，则使用 `res` 完成客户端通知。

若加锁时服务处于错误状态，而完成处理时 `res` 非负，则在完成处理前先将计数复位为零。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `srv` | 指向同步服务状态。 |
| `key` | 先前调用 [`onoff_sync_lock`](#ga174cadf7dfa5d3c4dc5c8185994f3825)() 返回的锁键（Lock Key）。 |
| `cli` | 指向接收完成信息的开关客户端。传入空指针时，只更新服务状态。为了与管理器 API 的回调行为兼容，当 `on` 为 `false` 时 `cli` 必须为空，因为管理器不支持在关闭设备时使用客户端回调。 |
| `res` | 转换结果。负数使服务进入错误状态；非负数则按照 `on` 的指定增加或减少引用计数。 |
| `on` | 仅当 `res` 非负时才调整服务引用计数：`on` 为 `true` 时递增，`on` 为 `false` 时递减。 |

**返回（Returns）**：若服务保持或进入错误状态，返回负数；否则返回释放锁时的活动请求数。

## 16.27\_onoff\_sync\_lock()

<a id="ga174cadf7dfa5d3c4dc5c8185994f3825"></a>
<a id="r_ga174cadf7dfa5d3c4dc5c8185994f3825"></a>

```c
int onoff_sync_lock ( struct onoff_sync_service * srv, k_spinlock_key_t * keyp )
```

```c
#include <zephyr/sys/onoff.h>
```

锁定同步开关服务，并提供其状态。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `srv` | 指向同步服务状态。 |
| `keyp` | 指向保存锁键的位置。 |

**原文注意（Note）**：若返回错误状态，由调用者决定保留该错误，使用同一错误状态完成处理；还是清除错误，使用非错误结果完成处理。

**返回（Returns）**：服务处于错误状态时返回负数，否则返回取得锁时的活动请求数。无论是否返回负状态，返回时都仍持有锁。

> 译注：返回负错误状态也仍持有锁，不能直接遗漏后续完成处理；应按原约定通过 onoff_sync_finalize() 保留或清除错误并释放锁。
