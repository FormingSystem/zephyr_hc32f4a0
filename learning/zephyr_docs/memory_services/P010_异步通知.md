# 第10章\_异步通知

原文：[官方页面](https://docs.zephyrproject.org/latest/services/notify.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 10.1\_异步通知

Zephyr API 经常包含[异步（Async）](../api_guides/P003_API术语.md)函数：发起操作后，应用需要得知何时完成以及是否成功。[`k_poll()`](../eventpoll_reference/P003_轮询公共接口.md#gac550dc93662ce164fb22a5a91d6830db) 往往是合适的方式；但一些应用架构更适合回调通知（Callback Notification）。而开启时钟、电源轨等操作，可能需要在内核函数尚不可用时发起，因此也可能需要忙等待（Busy-wait）完成。

本 API 用于嵌入[开关管理器（On-Off Manager）](P002_资源管理.md#on-off-manager)等具体子系统，以及其他支持异步事务（Asynchronous Transaction）的 API。子系统封装层（Subsystem Wrapper）负责从带有通知元素的请求中提取操作专用数据，并使用 API 所要求的参数调用回调。

此 API 的限制是它不适用于[系统调用（System Calls）](../kernel/P044_系统调用.md)，原因如下：

- [`sys_notify`](P014_异步通知结构.md) 不是内核对象（Kernel Object）。
- 从用户空间（Userspace）复制通知内容，会破坏实现函数对 [`CONTAINER_OF`](../util_reference/P001_通用工具公共接口.md#gac5bc561d1bfd1bf68877fe577779bd2f) 的使用。
- 不接受用户空间调用者使用自旋等待（Spin-wait）或回调通知方式。

当用户模式线程（User Mode Thread）发起的异步操作需要通知时，子系统或驱动应提供一个系统调用 API，使用 [`k_poll_signal`](../eventpoll_reference/P005_轮询信号结构.md) 进行通知。
