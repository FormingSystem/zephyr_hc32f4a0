# 第14章\_异步通知结构

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structsys__notify.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 14.1\_概述

异步操作通知所关联的状态（State Associated with Notification for an Asynchronous Operation）。

```c
#include <zephyr/sys/notify.h>
```

## 14.2\_对象控制权与生命周期

此类对象由客户端分配，必须使用初始化函数，例如 [`sys_notify_init_signal()`](P011_异步通知接口.md)，完成配置。通常，它是服务专用客户端结构体的成员，例如 `onoff_client`。

将对象指针传给明确声明会接管对象的服务函数，例如原文所写的 `onoff_service_request()`，便会把外层对象的控制权（Control）移交给服务提供者（Service Provider）。在服务提供者持有控制权期间，客户端不得修改对象的任何字段。以下情况下，控制权归还客户端：

- 服务 API 调用返回错误。
- 操作完成被发布。此事可能发生在服务 API 调用返回之前。

从技术上说，完成发布发生在 `flags` 字段被更新、使 [`sys_notify_fetch_result()`](P011_异步通知接口.md) 返回成功之时；此时尚未发出信号或调用回调。虽然管理器此后不再引用 `sys_notify` 对象，但外层对象可能包含回调仍会访问的状态。采用回调时，外层对象的控制权要到回调被调用时才归还客户端；**明确允许在回调内部重新使用对象**。

控制权归还客户端后，通知对象必须重新初始化，才能用于下一次操作。

结构体内容不属于向客户端公开的 API。所有配置和检查都应通过 `sys_notify_init_callback()`、`sys_notify_fetch_result()` 等函数完成。不过，使用此结构体的服务可以直接访问某些字段。

> 译注：原文的 `onoff_service_request()` 名称保留供对照，当前[开关管理公开API](P016_开关服务接口.md)中请求函数名为 `onoff_request()`。这里要理解的是接口规定的对象控制权转移，不应照着旧名称编写调用。也不要把完成标志已更新理解为外层对象在回调被调用前就可自由复用。


## 14.3\_结构声明

```c
struct sys_notify {
        union method {
                /* Pointer to signal used to notify client.
                 *
                 * The signal value corresponds to the res parameter
                 * of sys_notify_callback.
                 */
                struct k_poll_signal *signal;

                /* Generic callback function for callback notification. */
                sys_notify_generic_callback callback;
        } method;

        /*
         * Flags recording information about the operation.
         *
         * Bits below SYS_NOTIFY_EXTENSION_POS are initialized by
         * async notify API init functions like
         * sys_notify_init_callback(), and must not by modified by
         * extensions or client code.
         *
         * Bits at and above SYS_NOTIFY_EXTENSION_POS are available
         * for use by service extensions while the containing object
         * is managed by the service.  They are not for client use,
         * are zeroed by the async notify API init functions, and will
         * be zeroed by sys_notify_finalize().
         */
        uint32_t volatile flags;

        /*
         * The result of the operation.
         *
         * This is the value that was (or would be) passed to the
         * async infrastructure.  This field is the sole record of
         * success or failure for spin-wait synchronous operations.
         */
        int volatile result;
};
```

通知方式成员的字段参考见[通知方式联合体](P015_通知方式联合体.md)。
