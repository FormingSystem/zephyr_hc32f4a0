# 第22章\_同步开关服务结构

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structonoff__sync__service.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 22.1\_概述

驱动使用开关服务 API 执行同步操作时的状态。

```c
#include <zephyr/sys/onoff.h>
```

## 22.2\_使用约定

当子系统 API 使用开关 API 支持异步操作，而某个具体驱动所需的转换可以在中断中调用（isr-ok）且不会休眠时，此结构很有用。它可代替 `onoff_manager`，通过 `onoff_sync_lock()` 和 `onoff_sync_finalize()` 提供加锁及服务状态的持续保存与更新。

译注：这里的状态保存在服务对象中；原文的 persisted state updates 不表示写入 Flash 或断电后保留。

## 22.3\_结构声明

```c
struct onoff_sync_service {
        struct k_spinlock lock;

        int32_t count;
};
```

## 22.4\_count

<a id="adff029426035dffb57fda0de44f2abae"></a>
<a id="r_adff029426035dffb57fda0de44f2abae"></a>

```c
int32_t onoff_sync_service::count
```

负数表示错误，非负数表示引用计数。

## 22.5\_lock

<a id="ac08d780a80fed2d89c1334cc3c65eeed"></a>
<a id="r_ac08d780a80fed2d89c1334cc3c65eeed"></a>

```c
struct k_spinlock onoff_sync_service::lock
```

为其他字段提供互斥保护（Mutex Protection）。

> 译注：原文称 Mutex protection，但字段实际类型为 k_spinlock，即自旋锁（Spinlock），不是内核互斥量 k_mutex。此处表达对其他字段的互斥访问保护。
