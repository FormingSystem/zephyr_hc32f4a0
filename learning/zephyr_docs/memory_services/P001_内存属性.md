# 第1章\_内存属性

原文：[官方页面](https://docs.zephyrproject.org/latest/services/mem_mgmt/index.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 1.1\_内存属性

可以在设备树（Devicetree）中通过 `zephyr,memory-attr` 属性，为内存区域（Memory Region）标注属性。借助提供的辅助库（Helper Library），可以在运行时取得这一属性及对应内存区域。

可用于该属性的通用属性集合，定义和说明见官方头文件 [memory-attr.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/memory-attr/memory-attr.h)。

例如，将设备树中的某个内存区域标为非易失（Non-volatile）、可缓存（Cacheable）以及允许乱序访问（Out-of-order）：

```dts
mem: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_NON_VOLATILE | DT_MEM_CACHEABLE | DT_MEM_OOO)>;
};
```

**原文注意（Note）**：使用 `zephyr,memory-attr` 不会实际创建任何内存区域。如果需要根据设备树定义的区域创建实际的节（Section），可以使用兼容标识符（Compatible）[`zephyr,memory-region`](https://docs.zephyrproject.org/latest/build/dts/api/bindings/base/zephyr%2Cmemory-region.html#std-dtcompatible-zephyr-memory-region)。仅当体系结构支持时，它才会生成新的链接器节（Linker Section）和区域。

`zephyr,memory-attr` 也可设置体系结构专用和软件专用的自定义属性，供运行时解释。其中一种用途是根据设备树定义的内存区域创建内存保护单元（Memory Protection Unit，MPU）区域。例如：

```dts
mem: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-region = "NOCACHE_REGION";
    zephyr,memory-attr = <DT_MEM_ARM_MPU_RAM_NOCACHE>;
};
```

MPU 用法详见官方 [memory-attr-arm.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/memory-attr/memory-attr-arm.h)，以及 [Arm Cortex-M 开发者指南](https://docs.zephyrproject.org/latest/hardware/arch/arm_cortex_m.html#arm-cortex-m-developer-guide)中的[内存映射与MPU注意事项](https://docs.zephyrproject.org/latest/hardware/arch/arm_cortex_m.html#arm-cortex-m-mpu-considerations)。Zephyr 如何处理缓存（Cache），另见[缓存基础](https://docs.zephyrproject.org/latest/hardware/cache/guide.html#cache-guide)。

处理和管理带属性内存区域的常规推荐方式，是启用 [`CONFIG_MEM_ATTR`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MEM_ATTR)，使用提供的 `mem-attr` 辅助库。启用后，区域及其属性列表会编译为用户可访问的数组，并提供查询、探测和操作这些区域与属性的函数；接口见后文。

**原文注意（Note）**：`zephyr,memory-attr` 只是对相应区域能力的描述，不会直接设置内存。要使用这些信息完成工作，例如创建 MPU 区域，用户代码或子系统必须通过 `mem-attr` 库或常规设备树辅助接口执行所需操作／设置。不过，在 ARM 和 ARM64 等部分体系结构上，MPU 驱动会使用这些信息，在启动时正确初始化缓存。参见 [`CONFIG_ARM_MPU`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ARM_MPU)、[`CONFIG_RISCV_PMP`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RISCV_PMP) 等选项。

`mem-attr` 库及其使用方式的测试位于 `tests/subsys/mem_mgmt/mem_attr/`。

## 1.2\_内存属性堆分配器

可以利用 `zephyr,memory-attr` 定义并创建一组内存堆（Memory Heap），使用户能够分配具有特定属性／能力的内存。

启用 [`CONFIG_MEM_ATTR_HEAP`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_MEM_ATTR_HEAP) 后，所有标有官方 [memory-attr-sw.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/memory-attr/memory-attr-sw.h) 中所列内存属性之一的区域，都会加入内存堆池（Pool of Memory Heaps），用于动态分配具有相应属性的缓冲区。以下是部分可用属性：

```c
DT_MEM_SW_ALLOC_CACHE
DT_MEM_SW_ALLOC_NON_CACHE
DT_MEM_SW_ALLOC_DMA
```

例如，可以定义多个具有不同属性的区域，并以适当属性表示允许从这些区域动态分配内存：

```dts
mem_cacheable: memory@10000000 {
    compatible = "mmio-sram";
    reg = <0x10000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE | DT_MEM_SW_ALLOC_CACHE)>;
};

mem_non_cacheable: memory@20000000 {
    compatible = "mmio-sram";
    reg = <0x20000000 0x1000>;
    zephyr,memory-attr = <(DT_MEM_NON_CACHEABLE | ATTR_SW_ALLOC_NON_CACHE)>;
};

mem_cacheable_big: memory@30000000 {
    compatible = "mmio-sram";
    reg = <0x30000000 0x10000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE | DT_MEM_OOO | DT_MEM_SW_ALLOC_CACHE)>;
};

mem_cacheable_dma: memory@40000000 {
    compatible = "mmio-sram";
    reg = <0x40000000 0x10000>;
    zephyr,memory-attr = <(DT_MEM_CACHEABLE      | DT_MEM_DMA |
                           DT_MEM_SW_ALLOC_CACHE | DT_MEM_SW_ALLOC_DMA)>;
};
```

> 译注——宏名与属性位域：以上保留官方原例。核对本轮取得的官方通用属性头文件，未找到 `DT_MEM_NON_CACHEABLE` 定义；软件属性头文件中的 `ATTR_SW_ALLOC_NON_CACHE` 是尚未移位的内部值，不能直接代替设备树属性所需的 `DT_MEM_SW_ALLOC_NON_CACHE`。若仅表达此堆的软件分配类别，应使用 `DT_MEM_SW_ALLOC_NON_CACHE`。实际不可缓存设置仍需平台的 MPU／MMU 配置，不能靠软件分类标记自动生效。原例中的十六进制值是目标设备内存地址示意，不是作者电脑目录。

之后即可使用提供的函数动态分配这些区域中的内存；库根据传入的属性和大小，选择合适的堆：

```c
// Init the pool
mem_attr_heap_pool_init();

// Allocate 0x100 bytes of cacheable memory from `mem_cacheable`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE, 0x100);

// Allocate 0x200 bytes of non-cacheable memory aligned to 32 bytes
// from `mem_non_cacheable`
block = mem_attr_heap_aligned_alloc(ATTR_SW_ALLOC_NON_CACHE, 0x100, 32);

// Allocate 0x100 bytes of cacheable and dma-able memory from `mem_cacheable_dma`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE | DT_MEM_SW_ALLOC_DMA, 0x100);
```

代码注释译文：初始化内存池；从 `mem_cacheable` 分配 `0x100` 字节可缓存内存；从 `mem_non_cacheable` 分配按32字节对齐的 `0x200` 字节不可缓存内存；从 `mem_cacheable_dma` 分配 `0x100` 字节可缓存且可直接存储器访问（Direct Memory Access，DMA）的内存。

> 译注——对齐参数：原例注释与调用不一致。API 的参数顺序是 `attr, align, bytes`，原调用实际传入对齐值 `0x100`、大小32，而且使用了未移位的属性值。若要表达原注释的意图，应写成下面这样；这是修正示意，区域配置仍须先满足平台要求。

```c
block = mem_attr_heap_aligned_alloc(DT_MEM_SW_ALLOC_NON_CACHE, 32, 0x200);
```

原文说明：当多个区域具有相同属性时，内存按以下方式分配：

1. 从 `zephyr,memory-attr` 具有所请求属性的区域中选择。
2. 在这些区域中，如果最小区域仍有足以满足请求大小的未分配空间，就从该区域分配。
3. 若空间不足，则改从能够容纳请求大小的下一个更大区域分配。

> 译注——当前实现的选择规则：本轮核对的官方 [mem_attr_heap.c](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/mem_mgmt/mem_attr_heap.c) 中，`mah_choice()` 对请求值和堆的软件属性使用 `h->attr != attr` 作精确比较，随后按 `ma_heaps` 注册顺序尝试分配，取得第一块成功结果即停止；池初始化沿区域列表追加，并没有先按区域大小排序。因此不能依赖原文的“最小区域优先”保证，也不能认为只请求 CACHE 就会自动选中 CACHE 与 DMA 组合属性的堆。此处与 [`mem_attr_check_buf()`](P003_内存属性接口.md#gac599eafdb0be231c0105b05eb76b657b) 的属性子集检查是不同规则。本文保留原说明并标出差异；使用其他版本时须核对该版本实现，来源摘要见来源记录。

下面是原文用于说明第3点的例子：

```c
// This memory is allocated from `mem_non_cacheable`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_NON_CACHE, 0x100);

// This memory is allocated from `mem_cacheable_big`
block = mem_attr_heap_alloc(DT_MEM_SW_ALLOC_CACHE, 0x5000);
```

代码注释译文：第一次分配来自 `mem_non_cacheable`；第二次分配来自 `mem_cacheable_big`。

**原文注意（Note）**：框架假定用于建堆的内存区域在初始化时已可用，且代码能够访问。用户必须在调用 [`mem_attr_heap_pool_init()`](P004_内存属性堆接口.md#ga85301dfc19493a84e89f965ed793d576) 之前完成区域初始化和设置。这意味着应正确配置 MPU／内存管理单元（Memory Management Unit，MMU），并确保确实能够从区域创建堆。例如，可以利用 `zephyr,memory-region` 属性创建容纳该堆的适当链接器节。
