# 第11章\_异步通知接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__sys__notify__apis.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 11.1\_概述

异步通知接口（Asynchronous Notification APIs）供支持异步事务的服务嵌入使用。

```c
#include <zephyr/sys/notify.h>
```

## 11.3\_sys\_notify\_generic\_callback

<a id="ga2a9ffe35a5ad44fb7c5b00bb5c5c0499"></a>
<a id="r_ga2a9ffe35a5ad44fb7c5b00bb5c5c0499"></a>

```c
typedef void(* sys_notify_generic_callback) ()
```

```c
#include <zephyr/sys/notify.h>
```

用于通过回调（Callback）通知操作完成结果的通用函数签名（Generic Signature）。

承担这一角色的函数可能在任何上下文中调用，包括内核初始化前（Pre-kernel）、中断服务例程（Interrupt Service Routine，ISR）、协作式线程（Cooperative Thread）或可抢占线程（Preemptible Thread）。兼容的函数必须满足可在中断中调用（isr-ok）的要求，而且不能休眠。

通常应向此类函数传入以下参数：

- 指向具体客户端请求结构体的指针，即包含 [`sys_notify`](P014_异步通知结构.md) 的外层结构体指针。
- 操作结果，即传给 [`sys_notify_finalize`](#ga424b1c94c1010bdc4170cf06c7f2ec72)() 的值，或随后通过 [`sys_notify_fetch_result`](#ga823397b1917e10593d606daf3ec06a65)() 取得的值。预期值由具体服务规定，但成功时必须为非负数，失败时必须为负数。

> 译注：这是服务适配所用的通用函数指针类型，不表示每种服务回调都没有参数。实际调用参数由服务规定，finalize 的调用者应按其专用签名立即调用返回的回调。

## 11.4\_sys\_notify\_fetch\_result()

<a id="ga823397b1917e10593d606daf3ec06a65"></a>
<a id="r_ga823397b1917e10593d606daf3ec06a65"></a>

```c
static inline int sys_notify_fetch_result ( const struct sys_notify * notify, int * result )
```

```c
#include <zephyr/sys/notify.h>
```

检查异步操作（Asynchronous Operation）是否完成，并读取结果。


**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `notify` | 指向用于指定异步函数行为、保存完成信息的对象。 |
| `result` | 指向保存操作结果的存储位置。仅在操作已完成时才写入结果。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 操作已经完成。 |
| `-EAGAIN` | 操作尚未完成。 |

> 译注：函数返回 0 仅表示操作已经完成；操作本身的成功／失败须查看写入 result 的值。-EAGAIN 表示尚未完成，此时不会写入结果。

## 11.5\_sys\_notify\_finalize()

<a id="ga424b1c94c1010bdc4170cf06c7f2ec72"></a>
<a id="r_ga424b1c94c1010bdc4170cf06c7f2ec72"></a>

```c
sys_notify_generic_callback sys_notify_finalize ( struct sys_notify * notify, int res )
```

```c
#include <zephyr/sys/notify.h>
```

记录操作完成，并发出完成通知。


**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `notify` | 指向通知状态结构体。 |
| `res` | 操作结果。预期值由具体服务规定，但成功时必须为非负数，失败时必须为负数。 |

**返回（Returns）**：若采用回调通知，则返回待调用函数的通用版本；调用者必须立即使用该回调所要求的参数调用它。若采用自旋等待或信号通知，则在本函数返回时通知已完成，并返回空指针。

## 11.7\_sys\_notify\_init\_callback()

<a id="gaa9f31f78c03f48a3c649bbac15cc3a6c"></a>
<a id="r_gaa9f31f78c03f48a3c649bbac15cc3a6c"></a>

```c
static inline void sys_notify_init_callback ( struct sys_notify * notify, sys_notify_generic_callback handler )
```

```c
#include <zephyr/sys/notify.h>
```

将通知对象初始化为回调通知方式。

采用此初始化方式的客户端通过给定回调获知操作完成。根据具体服务，回调可能在不同上下文中调用；参见 [`sys_notify_generic_callback`](#ga2a9ffe35a5ad44fb7c5b00bb5c5c0499)。

操作完成后，客户端对象必须重新初始化才能再次使用。


**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `notify` | 指向通知配置对象。 |
| `handler` | 用于通知的函数指针。 |

## 11.8\_sys\_notify\_init\_signal()

<a id="ga30f9eff4b20b7d637a3a1df5f4cb38f8"></a>
<a id="r_ga30f9eff4b20b7d637a3a1df5f4cb38f8"></a>

```c
static inline void sys_notify_init_signal ( struct sys_notify * notify, struct k_poll_signal * sigp )
```

```c
#include <zephyr/sys/notify.h>
```

将通知对象初始化为基于 `k_poll` 的信号通知（Signal Notification）方式。

采用此初始化方式的客户端通过给定信号获知操作完成。

操作完成后，客户端对象必须重新初始化才能再次使用。


**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `notify` | 指向通知配置对象。 |
| `sigp` | 指向用于通知的信号，不能为 `NULL`。在把客户端对象传给开关服务（On-Off Service）API 之前，必须先复位该信号。 |

**原文注意（Note）**：仅在选中 [`CONFIG_POLL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_POLL) 时才提供此能力。

## 11.9\_sys\_notify\_init\_spinwait()

<a id="gad1a5c3e58ff962ab3cac743dde8c6c1e"></a>
<a id="r_gad1a5c3e58ff962ab3cac743dde8c6c1e"></a>

```c
static inline void sys_notify_init_spinwait ( struct sys_notify * notify)
```

```c
#include <zephyr/sys/notify.h>
```

将通知对象初始化为自旋等待（Spin-wait）通知方式。

采用此初始化方式的客户端不会收到异步通知，必须定期调用 [`sys_notify_fetch_result`](#ga823397b1917e10593d606daf3ec06a65)() 检查操作是否完成。

操作完成后，客户端对象必须重新初始化才能再次使用。


**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `notify` | 指向通知配置对象。 |

## 11.10\_sys\_notify\_uses\_callback()

<a id="ga9772f8b356685acd707bd905860a2ca7"></a>
<a id="r_ga9772f8b356685acd707bd905860a2ca7"></a>

```c
static inline bool sys_notify_uses_callback ( const struct sys_notify * notify)
```

```c
#include <zephyr/sys/notify.h>
```

检测指定通知是否使用回调。

通用处理函数类型不包含具体回调所需的函数签名，服务必须负责转换为其专用回调。当服务没有提供转换函数时，可通过此检查拒绝回调通知请求。


**返回（Returns）**：当且仅当将使用回调通知时返回 `true`。

## 11.11\_sys\_notify\_validate()

<a id="ga71a9ccb690151020a6abea2ec9ffc667"></a>
<a id="r_ga71a9ccb690151020a6abea2ec9ffc667"></a>

```c
int sys_notify_validate ( struct sys_notify * notify)
```

```c
#include <zephyr/sys/notify.h>
```

校验并初始化通知结构体。

应在开始校验任何服务专用配置时调用此函数。它确保基本异步通知配置一致，并清除结果。

注意，此函数不校验扩展位（Extension Bits）；这些位由 [`sys_notify_init_callback`](#gaa9f31f78c03f48a3c649bbac15cc3a6c)() 等异步通知初始化函数清零。由于仅将 `flags` 中的通知方式位与对应设置核对，它可能无法识别传入的未初始化结构体。为降低接受未初始化操作的可能性，服务校验包含 [`sys_notify`](P014_异步通知结构.md) 实例的结构体时，还应确认扩展位是否按预期置位或清零。


**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 校验及重新初始化成功。 |
| `-EINVAL` | 配置无效。 |

> 译注：本轮官方实现成功时清除 result，但不会清除扩展标志位；头文件宏说明中的相反说法见[扩展位译注](P012_异步通知头文件.md)。
