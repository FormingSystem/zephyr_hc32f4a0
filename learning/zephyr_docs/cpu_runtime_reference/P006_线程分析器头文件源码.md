## 6.4\_源码跟踪译注

> 译注——线程分析器（Thread Analyzer）把栈扫描、可选运行统计和回调输出组合起来；thread_analyzer_info的utilization、usage、stack_safety、特权栈和优先级字段受不同配置控制。不要把某次Doxygen展示的成员表当作所有配置下的固定内存布局。

> 译注——本次实现的info和无名称线程使用的hexname均为分析回调中的局部对象；业务回调同步收到指针，不能在返回后继续保存并解引用这些临时地址。需要后续处理时应复制所需值和名称内容。

> 译注——cpu参数只在CONFIG_THREAD_ANALYZER_AUTO_SEPARATE_CORES下用于按CPU过滤以及选择统计分母；未启用该配置时遍历所有线程，并使用全CPU累计统计。RUN_UNLOCKED选择解锁遍历分支，不意味着获得线程列表快照或对象生命周期保证。

> 译注——默认栈安全处理函数区分阈值跨越与空间耗尽，官方实现注释明确它不能检测栈溢出（Stack Overflow）；定义了OVERFLOW状态码不代表默认处理函数会产生它。传入NULL恢复默认处理函数，此实现仅在STACK_SAFETY配置下提供。

> 译注——栈空间查询失败时当前实现打印错误并将unused设为0，随后仍调用业务回调；这时stack_used等于stack_size，不能仅凭该数字断言真实栈已耗尽。运行统计查询失败时utilization也没有有效赋值保证，读取结果须结合错误输出与实际配置。

> 译注——LONG_FRAME_PER_INTERVAL启用时，最长执行片段（Longest Frame）统计在业务回调之后重置；这不是清零全部线程累计运行时间。开启ISR_STACK_USAGE还会回调中断栈结果，不能把每条结果都当作普通线程。
