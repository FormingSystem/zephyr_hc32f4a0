## 8.1\_源码定位与版本边界

相对源码定位：[CPU负载头文件](../../../include/zephyr/sys/cpu_load.h)、[CPU负载实现](../../../lib/os/cpu_load/cpu_load.c)、[测量后端配置](../../../lib/os/cpu_load/Kconfig)、[线程分析器](../../../subsys/debug/thread_analyzer/thread_analyzer.c)、[线程类型头文件](../../../include/zephyr/kernel/thread.h)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注依据本批保存摘要的官方 main 文件，独立于官方正文。源码使用相对路径定位；本地源码版本若不同，应以来源记录中的版本边界核对。

> 译注——源码核对：本次官方k_thread_runtime_stats结构体页面只显示头文件引用，没有成员表。这里如实保留该页面范围，下面的字段解释属于明确标注的官方源码跟踪译注，不冒充网页遗漏的译文。

> 译注——源码核对：原始thread.h在CONFIG_SCHED_THREAD_USAGE下声明execution_cycles与total_cycles。对CPU统计，前者包含非空闲与空闲周期，后者为非空闲周期；对单线程统计，execution_cycles等于total_cycles。这些是周期计数（Cycle Counts），不是百分比或纳秒值。

> 译注——源码核对：CONFIG_SCHED_THREAD_USAGE_ANALYSIS增加current_cycles、peak_cycles、average_cycles：对线程，执行片段由调入与调出界定；对CPU，由进入／离开空闲线程界定非空闲片段。CONFIG_SCHED_THREAD_USAGE_ALL增加idle_cycles，单线程统计中此字段始终为0，只用于CPU空闲统计。

> 译注——源码核对：以上字段都未启用且使用C++时，头文件增加一个字节dummy以避免空结构体在C与C++中的大小差异。应使用对应配置编译出的类型，不能依据网页未列成员而把它当作固定大小的空类型。
