### `bindesc_callback_t`

```c

```

```c
#include <zephyr/bindesc.h>
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `entry` | 当前描述符。 |
| `user_data` | 传给 `bindesc_foreach` 的 `user_data`。 |

**返回（Returns）**：任何非零值都会停止遍历。

### `bindesc_find_bytes()`

```c
int bindesc_find_bytes ( struct bindesc_handle * handle, uint16_t id, const uint8_t ** result, size_t * result_size )
```

```c
#include <zephyr/bindesc.h>
```

查找指定的字节数组类型描述符。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `handle` | 已初始化的 bindesc 句柄。 |
| `id` | 要搜索的标识符（ID）。 |
| `result` | 指向找到的字节数据的指针。 |
| `result_size` | 找到的字节数据的大小。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 找到描述符时返回。 |
| `-ENOENT` | 未找到描述符时返回。 |

**警告（Warning）**：使用闪存后端（Flash Backend）时，下一次调用任意 bindesc API 都会使 `result` 失效。应立即使用该值，或将其复制到其他位置。

### `bindesc_foreach()`

```c
int bindesc_foreach ( struct bindesc_handle * handle, bindesc_callback_t callback, void * user_data )
```

```c
#include <zephyr/bindesc.h>
```

遍历二进制描述符，并对每个描述符运行用户定义的回调。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `handle` | 已初始化的 bindesc 句柄。 |
| `callback` | 对每个描述符调用的用户定义回调。 |
| `user_data` | 传给回调的用户定义数据。 |

**注意（Note）**：如果回调返回非零值，遍历就会停止。

**返回（Returns）**：如果遍历由回调提前终止，则返回回调的返回值；否则返回零。

> 译注（源码核对）：当前源码在检查结束标签之前调用回调，因此结束条目也会传给回调。闪存读取失败可返回 `-EIO`；若单个条目的数据超过闪存内部缓冲区容量，该条目会被跳过。原返回说明中的“否则零”不是说后端错误无法发生。

<a id="ga7df52ef12aa9572d3a2ff4245529d8fd"></a>

### `bindesc_get_size()`

```c
int bindesc_get_size ( struct bindesc_handle * handle, size_t * result )
```

```c
#include <zephyr/bindesc.h>
```

获取映像内二进制描述符的大小。

遍历二进制描述符结构，计算该结构的总字节数。例如，需要将整个结构复制到 RAM 时，这个功能很有用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `handle` | 已初始化的 bindesc 句柄。 |
| `result` | 用于写入结果的指针。 |

**返回（Returns）**：成功时返回 `0`，否则返回负的 `errno` 错误码。

> 译注（源码核对）：这里统计的是整个描述符区域：魔数、条目头部、数据、对齐填充和结束条目；`BINDESC_GET_SIZE(name)` 宏只返回单个条目的数据长度。二者不等价。

<a id="ga724d940fecd648523c3d3bd840785498"></a>

### `bindesc_open_flash()`

```c
int bindesc_open_flash ( struct bindesc_handle * handle, size_t offset, const struct device * flash_device )
```

```c
#include <zephyr/bindesc.h>
```

打开闪存（Flash）中的映像二进制描述符，以供读取。

初始化 bindesc 句柄，供后续 bindesc API 调用使用。与从 RAM 或内存映射闪存读取描述符不同，此后端需要通过闪存 API 将数据从闪存读入内部缓冲区（Internal Buffer）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[out] handle` | 供后续调用使用的 bindesc 句柄。 |
| ` offset` | bindesc 魔数相对于闪存起始位置的偏移量（Offset）。 |
| ` flash_device` | 用于读取描述符的闪存设备。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时返回。 |
| `-ENOENT` | 给定偏移量处未找到 bindesc 魔数时返回。 |

**注意（Attention）**：仅在启用 Kconfig 选项 `CONFIG_BINDESC_READ_FLASH` 时可用。

> 译注（源码核对）：当前实现还会在底层 `flash_read()` 失败时返回 `-EIO`，原返回值表未列出此项。该 API 要求显式给出闪存设备及设备内偏移；内存映射后端则按 `CONFIG_FLASH_BASE_ADDRESS + offset` 访问，两种参数不能混作任意 CPU 地址。

### `bindesc_open_ram()`

```c
int bindesc_open_ram ( struct bindesc_handle * handle, const uint8_t * address, size_t max_size )
```

```c
#include <zephyr/bindesc.h>
```

打开 RAM 中的映像二进制描述符，以供读取。

初始化 bindesc 句柄，供后续 bindesc API 调用使用。假定在调用此函数之前，用户或引导加载程序（Bootloader）已将整个 bindesc 上下文复制到 RAM。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[out] handle` | 供后续调用使用的 bindesc 句柄。 |
| ` address` | bindesc 魔数所在的地址。 |
| ` max_size` | 给定缓冲区的最大大小。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时返回。 |
| `-ENOENT` | 给定地址处未找到 bindesc 魔数时返回。 |
| `-EINVAL` | 给定地址未对齐时返回。 |

**注意（Note）**：给定地址必须按 `BINDESC_ALIGNMENT` 对齐。

> 译注（源码核对）：当前签名包含 `max_size`，它应是从 `address` 开始实际可访问的缓冲区大小。实现会先读取魔数，再在遍历循环中使用大小限制；该参数不能替代调用者对缓冲区及描述符布局的有效性检查，也不能把此 API 当作任意损坏映像的完整校验器。

## 18.6\_相关源码与使用边界

声明来自 `<zephyr/bindesc.h>`。可通过本仓库[对应头文件](../../../include/zephyr/bindesc.h)追踪源码；本仓库版本可能与官网 `latest` 不同。译注核对使用保存的[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/bindesc.h)与[官方读取实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/bindesc/bindesc_read.c)，摘要见[来源记录](../SOURCES.md)。

> 译注——句柄并非空结构：官方 Doxygen 隐藏了 `INTERNAL_HIDDEN` 成员。当前头文件实际包含 `address`、后端枚举 `type` 和 `size_limit`；启用 `CONFIG_BINDESC_READ_FLASH` 时还包含 `flash_device` 与对齐的内部 `buffer`。应用应通过 `bindesc_open_*` 初始化句柄，不依赖隐藏布局自行填充。闪存查找结果指向内部缓冲区，应遵守[读取接口](P018_二进制描述符读取接口.md)的结果生存期约定；RAM／内存映射结果则依赖原数据存储持续有效。

> 译注——当前实现的错误传播限制：本批保存的 `bindesc_find_str`、`bindesc_find_uint` 和 `bindesc_find_bytes` 使用 `if (!bindesc_foreach(...))` 判定未找到，未区分查找回调的成功停止值 `1` 与后端返回的负错误码。若遍历返回 `-EIO`，这些函数可能仍返回 `0`，同时给出空结果指针。使用当前版本时应同时核对返回码和结果指针，不能仅凭返回 `0` 直接解引用；这是源码核对结论，不是原 API 文档作出的保证。
