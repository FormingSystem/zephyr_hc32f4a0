# 第15章\_CVE\_2021

原文：[官方页面](https://docs.zephyrproject.org/latest/security/vulnerabilities/2021.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

> 译注——历史记录与版本：本页按官方年份归档翻译通用漏洞与披露（Common Vulnerabilities and Exposures，CVE）记录。下文“已修复”“尚未修复”“将纳入”等均为原页记载；版本号、PR、提交和公告链接照原文保留，不代表本仓库已验证修复或当前产品一定受影响。拉取请求（pull request，PR）与 GitHub 安全公告（GitHub Security Advisory，GHSA）用于追溯修复和披露。

> 译注——协议名称：L2CAP 为逻辑链路控制与适配协议（Logical Link Control and Adaptation Protocol），ATT 为属性协议（Attribute Protocol），HCI 为主机控制器接口。6LoWPAN 指低功耗无线个域网上的 IPv6 适配技术。

## 15.1 漏洞记录（CVE 2021-3319）

官方编号：[CVE 2021-3319](https://www.cve.org/CVERecord?id=CVE-2021-3319)。

拒绝服务（DoS）：IEEE 802.15.4 帧省略源地址／目标地址时，帧验证不正确。

IEEE 802.15.4 帧验证函数 `ieee802154_validate_frame` 未正确处理源地址和目标地址被省略的情况。

此问题已在 main 分支中修复，面向 v2.5.0。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-94jg-2p6q-5364](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-94jg-2p6q-5364)。

[PR31908：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/31908)。

## 15.2 漏洞记录（CVE 2021-3320）

官方编号：[CVE 2021-3320](https://www.cve.org/CVERecord?id=CVE-2021-3320)。

IEEE 802.15.4 确认帧（ACK frame）的验证与处理不一致：验证时考虑了 ACK 帧，实际处理时却没有，导致类型混淆（type confusion）。

## 15.11 漏洞记录（CVE 2021-3436）

官方编号：[CVE 2021-3436](https://www.cve.org/CVERecord?id=CVE-2021-3436)。

蓝牙：已知现有绑定（bond）的身份地址（identity address）时，可能在密钥分发（key distribution）阶段覆盖该绑定。

分发身份地址信息时，没有检查是否已存在具有相同身份地址的绑定。这意味着 RAM 中会创建重复条目，而持久存储（persistent storage）中的现有条目会被最新条目覆盖。

此问题已在 main 分支中修复，面向 v2.6.0。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-j76f-35mc-4h63](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-j76f-35mc-4h63)。

[PR 33266：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/33266)。

[PR 33432：针对 2.5 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/33432)。

## 15.13 漏洞记录（CVE 2021-3455）

官方编号：[CVE 2021-3455](https://www.cve.org/CVERecord?id=CVE-2021-3455)。

在无效 ATT 请求之后立即断开 L2CAP 通道，会导致系统卡死（freeze）。

中心设备（Central）连接外设（peripheral），并为增强属性协议（Enhanced ATT）创建 L2CAP 连接后，发送某些无效 ATT 请求并立即断开连接，会造成卡死。

此问题已在 main 分支中修复，面向 v2.6.0。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-7g38-3x9v-v7vp](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-7g38-3x9v-v7vp)。

## 15.14 漏洞记录（CVE 2021-3510）

官方编号：[CVE 2021-3510](https://www.cve.org/CVERecord?id=CVE-2021-3510)。

Zephyr JSON 解码器错误解码嵌套数组（array of array）。

使用 `JSON_OBJ_DESCR_ARRAY_ARRAY` 时，子数组的 token 类型为 `JSON_TOK_LIST_START`，却向联合体（union）的 object 部分赋值。随后 `arr_parse` 取出 array-object 的偏移量，该值与 list 无关，却被当作相对于父对象的偏移，并在该处保存子数组长度。

此问题已在 main 分支中修复，面向 v2.7.0。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-289f-7mw3-2qf4](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-289f-7mw3-2qf4)。

[PR 36340：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/36340)。

[PR 37816：针对 2.6 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/37816)。

## 15.15 漏洞记录（CVE 2021-3581）

官方编号：[CVE 2021-3581](https://www.cve.org/CVERecord?id=CVE-2021-3581)。

HCI 数据未被正确检查，导致蓝牙协议栈内存溢出。

通过 HCI 命令设置 `SCAN_RSP` 时，Zephyr 蓝牙协议栈没有有效检查传入 HCI 数据的长度，导致内存溢出；内存中的数据随后被覆盖，甚至可能造成任意代码执行。

此问题已在 main 分支中修复，面向 v2.6.0。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-8q65-5gqf-fmw5](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-8q65-5gqf-fmw5)。

[PR 35935：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/35935)。

[PR 35984：针对 2.5 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/35984)。
