# 第19章\_CVE\_2025

原文：[官方页面](https://docs.zephyrproject.org/latest/security/vulnerabilities/2025.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

> 译注——历史记录与版本：本页按官方年份归档翻译通用漏洞与披露（Common Vulnerabilities and Exposures，CVE）记录。下文“已修复”“尚未修复”“将纳入”等均为原页记载；版本号、PR、提交和公告链接照原文保留，不代表本仓库已验证修复或当前产品一定受影响。拉取请求（pull request，PR）与 GitHub 安全公告（GitHub Security Advisory，GHSA）用于追溯修复和披露。

> 译注——参数缩写：CID 为信道标识符（Channel Identifier），MTU 为最大传输单元（Maximum Transmission Unit），MPS 为最大协议数据单元载荷大小（Maximum PDU Payload Size）。本页保留原记录的触发条件和影响程度，没有补充利用步骤。

## 19.1 漏洞记录（CVE 2025-1673）

官方编号：[CVE 2025-1673](https://www.cve.org/CVERecord?id=CVE-2025-1673)。

`dns_validate_msg` 调用 `crc16_ansi` 和 `strlen` 时发生越界读取（out-of-bounds read）。

没有载荷（payload）的恶意或畸形 DNS 数据包可能造成越界读取，导致崩溃，即拒绝服务，或产生错误计算结果。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-jjhx-rrh4-j8mx](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-jjhx-rrh4-j8mx)。

此问题已在 main 分支中修复，面向 v4.1.0。

[PR 82072：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/82072)。

[PR 82289：针对 4.0 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/82289)。

[PR 82288：针对 3.7 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/82288)。

## 19.2 漏洞记录（CVE 2025-1674）

官方编号：[CVE 2025-1674](https://www.cve.org/CVERecord?id=CVE-2025-1674)。

解包 DNS 应答（DNS answer）时发生越界读取。

## 19.3 漏洞记录（CVE 2025-1675）

官方编号：[CVE 2025-1675](https://www.cve.org/CVERecord?id=CVE-2025-1675)。

`dns_copy_qname` 中存在越界读取。

`dns_pack.c` 中的 `dns_copy_qname` 使用不可信字段执行 `memcpy`，却不检查源缓冲区是否足够大、能够容纳被复制的数据。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-2m84-5hfw-m8v4](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-2m84-5hfw-m8v4)。

此问题已在 main 分支中修复，面向 v4.1.0。

[PR 82072：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/82072)。

## 19.5 漏洞记录（CVE 2025-7403）

官方编号：[CVE 2025-7403](https://www.cve.org/CVERecord?id=CVE-2025-7403)。

蓝牙：`bt_conn_tx_processor` 的处理不安全。

`bt_conn_tx_processor` 中的不安全处理导致释放后使用（use-after-free），进而造成向零地址之前的内存写入（write-before-zero）。被写入的 4 字节由攻击者控制，能够实现精确的内存破坏。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-9r46-cqqw-6j2j](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-9r46-cqqw-6j2j)。

此问题已在 main 分支中修复，面向 v4.2.0。

[PR 90975：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/90975)。

## 19.6 漏洞记录（CVE 2025-10456）

官方编号：[CVE 2025-10456](https://www.cve.org/CVERecord?id=CVE-2025-10456)。

蓝牙：能够在一定程度上任意使蓝牙低功耗目标设备发送断开请求。

蓝牙低功耗（Bluetooth Low Energy，BLE）固定通道（fixed channel），例如安全管理协议（SMP）或属性协议（ATT）的处理存在漏洞。攻击者可以利用该缺陷，使 BLE 目标，即受攻击设备，尝试断开固定通道，而蓝牙规范不允许这样做。这会导致未定义行为（undefined behavior），包括可能发生的断言失败、崩溃或内存破坏。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-hcc8-3qr7-c9m8](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-hcc8-3qr7-c9m8)。

此问题已在 main 分支中修复，面向 v4.2.0。

[PR 93576：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/93576)。

[PR 100474：针对 3.7 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/100474)。

## 19.7 漏洞记录（CVE 2025-10457）

官方编号：[CVE 2025-10457](https://www.cve.org/CVERecord?id=CVE-2025-10457)。

蓝牙：在不匹配的上下文中处理 `le_conn_rsp`。

负责处理 BLE 连接响应的函数没有验证该响应是否符合预期，也就是没有验证设备是否已发起连接请求，而仅依赖标识符（identifier）匹配。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-xqj6-vh76-2vv8](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-xqj6-vh76-2vv8)。

## 19.9 漏洞记录（CVE 2025-9408）

官方编号：[CVE 2025-9408](https://www.cve.org/CVERecord?id=CVE-2025-9408)。

Cortex-M 上的用户空间权限提升（privilege escalation）漏洞。

Cortex-M 的系统调用入口存在竞态（race），使恶意用户空间进程能够以实际可行的方式提升权限。原文另有保留性说明：“也可能涉及 R 和 A，但我认为不会”，未将其写成确定受影响范围。

## 19.10 漏洞记录（CVE 2025-9557）

官方编号：[CVE 2025-9557](https://www.cve.org/CVERecord?id=CVE-2025-9557)。

蓝牙 Mesh：`gen_prov_cont` 中存在越界写入（out-of-bounds write）。

越界写入可能导致任意代码执行；即使设备具备某种内存保护，仍可能导致崩溃，并造成拒绝服务。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-r3j3-c5v7-2ppf](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-r3j3-c5v7-2ppf)。

## 19.11 漏洞记录（CVE 2025-9558）

官方编号：[CVE 2025-9558](https://www.cve.org/CVERecord?id=CVE-2025-9558)。

蓝牙 Mesh：`gen_prov_start` 中存在越界写入。

`pb_adv.c` 的 `gen_prov_start` 函数中存在潜在越界写入（OOB Write）漏洞。收到的数据按完整长度复制到 `link.rx.buf` 接收缓冲区，却没有对数据大小进行任何验证。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-8wvr-688x-68vr](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-8wvr-688x-68vr)。

## 19.12 漏洞记录（CVE 2025-12035）

官方编号：[CVE 2025-12035](https://www.cve.org/CVERecord?id=CVE-2025-12035)。

经典蓝牙（Bluetooth Classic，BR/EDR）的 L2CAP 中存在整数溢出（integer overflow）。

蓝牙主机协议栈的 `bt_br_acl_recv` 例程中存在整数溢出；该例程位于处理传入 BR/EDR L2CAP 流量的关键路径上。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-p793-3456-h7w3](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-p793-3456-h7w3)。

## 19.13 漏洞记录（CVE 2025-12890）

官方编号：[CVE 2025-12890](https://www.cve.org/CVERecord?id=CVE-2025-12890)。

蓝牙外设（peripheral）：对畸形连接请求的处理无效。

畸形连接请求（Connection Request）的间隔被设为 1，这本应是非法值，同时 `chM` 为 `0x7CFFFFFFFF`；对这种请求的处理不当会触发崩溃，此后该外设将无法被连接。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-8hrf-pfww-83v9](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-8hrf-pfww-83v9)。

此问题已在 main 分支中修复，面向 v4.2.0。

[PR 89955：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/89955)。

## 19.14 漏洞记录（CVE 2025-12899）

官方编号：[CVE 2025-12899](https://www.cve.org/CVERecord?id=CVE-2025-12899)。

网络 ICMP：越界内存读取。

Zephyr 网络协议栈的缺陷会将包含 ICMP 类型 128 的 IPv4 数据包误判为 ICMPv6 回显请求（Echo Request）。这会导致越界内存读取，并在网络子系统中形成潜在信息泄露漏洞。

[Zephyr 项目缺陷跟踪（bug tracker）：GHSA-c2vg-hj83-c2vg](https://github.com/zephyrproject-rtos/zephyr/security/advisories/GHSA-c2vg-hj83-c2vg)。

此问题已在 main 分支中修复，面向 v4.3.0。

[PR 98780：针对 main 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/98780)。
