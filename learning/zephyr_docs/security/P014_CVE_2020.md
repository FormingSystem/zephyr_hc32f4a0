# 第14章\_CVE\_2020

原文：[官方页面](https://docs.zephyrproject.org/latest/security/vulnerabilities/2020.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

> 译注——历史记录与版本：本页按官方年份归档翻译通用漏洞与披露（Common Vulnerabilities and Exposures，CVE）记录。下文“已修复”“尚未修复”“将纳入”等均为原页记载；版本号、PR、提交和公告链接照原文保留，不代表本仓库已验证修复或当前产品一定受影响。拉取请求（pull request，PR）与 GitHub 安全公告（GitHub Security Advisory，GHSA）用于追溯修复和披露。

> 译注——协议名称：MQTT 为消息传输协议；CoAP 为受限应用协议（Constrained Application Protocol）；HCI 为主机控制器接口（Host Controller Interface），SPI 为串行外设接口（Serial Peripheral Interface），ACL 为异步面向连接链路。相关标识符和源代码表达式保持原样。

## 14.1 漏洞记录（CVE 2020-10019）

官方编号：[CVE 2020-10019](https://www.cve.org/CVERecord?id=CVE-2020-10019)。

Zephyr 的 USB 设备固件升级（Device Firmware Upgrade，DFU）中存在缓冲区溢出漏洞，通过 USB 连接的主机可能据此造成远程代码执行。

此问题已在发行版 v1.14.2、v2.2.0 和 v2.1.1 中修复。

## 14.3 漏洞记录（CVE 2020-10022）

官方编号：[CVE 2020-10022](https://www.cve.org/CVERecord?id=CVE-2020-10022)。

UpdateHub 模块将可变长度的散列字符串（hash string）复制到固定大小的数组。

从 UpdateHub 服务器收到的畸形 JSON 载荷（payload）可能触发 Zephyr 操作系统内存破坏（memory corruption）。轻则导致拒绝服务，重则导致代码执行。

参见 NCC-ZEP-016。

## 14.9 漏洞记录（CVE 2020-10059）

官方编号：[CVE 2020-10059](https://www.cve.org/CVERecord?id=CVE-2020-10059)。

UpdateHub 模块显式禁用了传输层安全（Transport Layer Security，TLS）验证。

UpdateHub 模块禁用了数据报传输层安全（Datagram TLS，DTLS）的对端检查，因而允许中间人攻击（man-in-the-middle attack）。固件镜像需要有效签名，这会缓解影响；但不进行对端检查时，使用 DTLS 也无法带来应有收益。

参见 NCC-ZEP-018。

此问题已通过针对 Zephyr main 分支的 PR 修复。

[Zephyr 项目缺陷跟踪（bug tracker）：ZEPSEC-36](https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-36)。

## 14.10 漏洞记录（CVE 2020-10060）

官方编号：[CVE 2020-10060](https://www.cve.org/CVERecord?id=CVE-2020-10060)。

UpdateHub 可能解引用未初始化指针（uninitialized pointer）。

在 `updatehub_probe` 中，JSON 解析刚完成后，就在两处访问输出结构的 `objects[1]`。如果 JSON 包含的元素少于两个，这些访问就会引用未初始化的栈内存，可能造成崩溃、拒绝服务或信息泄露（information leak）。

原文建议：在修复可用之前禁用 updatehub。

参见 NCC-ZEP-030。

此问题已通过针对 Zephyr main 分支的 PR 修复。

## 14.12 漏洞记录（CVE 2020-10062）

官方编号：[CVE 2020-10062](https://www.cve.org/CVERecord?id=CVE-2020-10062)。

MQTT 中的数据包长度解码错误。

CVE 描述：Zephyr 项目 MQTT 数据包长度解码器中的差一错误（off-by-one error）可能造成内存破坏，并可能导致远程代码执行。对应 NCC-ZEP-031。

MQTT 数据包头部的长度字段可以占 1 至 4 字节。代码中的差一错误可能将其解释为 5 字节，引发整数溢出（integer overflow），进而造成内存破坏。

此问题已在 main 分支中修复，面向 v2.3。

[Zephyr 项目缺陷跟踪（bug tracker）：ZEPSEC-84](https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-84)。

[用于 v2.3 的提交（commit）11b7a37d](https://github.com/zephyrproject-rtos/zephyr/pull/23821/commits/11b7a37d9a0b438270421b224221d91929843de4)。

[NCC-ZEP 报告（report）](https://research.nccgroup.com/2020/05/26/research-report-zephyr-and-mcuboot-security-assessment)，对应 NCC-ZEP-031。

## 14.29 漏洞记录（CVE 2020-13603）

官方编号：[CVE 2020-13603](https://www.cve.org/CVERecord?id=CVE-2020-13603)。

内存池（mempool）中可能发生溢出。

Zephyr 提供预先实现的 `malloc` 包装函数（wrapper function）作为替代。

`malloc` 函数是 `sys_mem_pool_alloc` 的包装函数。

`sys_mem_pool_alloc` 以不安全的方式分配 `size + WB_UP(sizeof(struct sys_mem_pool_block))` 大小的内存。

请求非常大的 size 值会导致内部整数回绕（integer wrap-around）。

整数回绕会使很小的一块内存被成功分配。

例如，调用 `malloc(0xffffffff)` 会成功分配 7 字节。

这会导致堆溢出（heap overflow）。

[Zephyr 项目缺陷跟踪（bug tracker）：ZEPSEC-111](https://zephyrprojectsec.atlassian.net/browse/ZEPSEC-111)。

[PR31796：针对 v2.4 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/31796)。

[PR32808：针对 v1.4 的修复](https://github.com/zephyrproject-rtos/zephyr/pull/26571)。
