## 2.1\_概述

Zephyr 提供 `nrf52_bsim` 目标开发板，用于模拟 nRF52833 片上系统（SoC）。它使用 [BabbleSim](https://BabbleSim.github.io) 模拟无线电活动，通过 [POSIX 架构](../native_reference/P002_POSIX架构.md#posix-arch)和[本机模拟器（Native Simulator）](https://github.com/BabbleSim/native_simulator/blob/main/docs/README.md)，在开发系统上本机执行应用。这样既有本机代码的执行性能，也便于使用本机工具调试，但同时继承[对应限制](../native_reference/P002_POSIX架构.md#posix-arch-limitations)。

此开发板包含下列 nRF52 外设模型，并使用与 `nrf52 dk` 目标相同的驱动。

- 无线电（Radio）。
- 定时器（Timers）。
- 加速地址解析器（Accelerated Address Resolver，AAR）。
- 高级加密标准（AES）的CCM与电子密码本（Electronic Codebook，ECB）模式加密硬件；CCM为计数器模式结合CBC-MAC的认证加密模式。
- 时钟控制（Clock Control，CLOCK）。
- 事件生成单元（Event Generator Unit，EGU）。
- 工厂信息配置寄存器（Factory Information Configuration Registers，FICR）。
- 通用输入输出（General-purpose Input/Output，GPIO）及其任务与事件（GPIO Tasks and Events，GPIOTE）。
- 非易失性存储控制器／闪存（Non-Volatile Memory Controller / Flash，NVMC）。
- 可编程外设互连（Programmable Peripheral Interconnect，PPI）。
- 随机数发生器（Random Number Generator，RNG）。
- 实时计数器（Real Time Counter，RTC）。
- 温度传感器（Temperature Sensor，TEMP）。
- 通用异步收发器（UART）与带EasyDMA直接存储器访问的UART（UARTE）。
- 用户信息配置寄存器（User Information Configuration Registers，UICR）。

各外设建模到什么程度，见[硬件模型实现状态](https://github.com/BabbleSim/ext_nRF_hw_models/blob/main/docs/README_impl_status.md)。

与真实 nRF52 器件不同，`nrf52_bsim` 的随机存取存储器（RAM）以及用于代码的闪存（Flash）容量不受限制。

## 2.2\_构建与运行

此开发板要求宿主提供32位 C 库，见 [POSIX 架构依赖](../native_reference/P002_POSIX架构.md#posix-arch-deps)。

要构建此目标，还需要在系统中编译好 BabbleSim。若尚未准备，最简单的办法是在本地 west 配置中启用 `babblesim` 组，执行 `west update`，再构建模拟器：

```shell
west config manifest.group-filter -- +babblesim
west update
cd ${ZEPHYR_BASE}/../tools/bsim
make everything -j 8
```

> 原文注意：需要更多 BabbleSim 组件或更新版本时，可查看 [BabbleSim 网站](https://BabbleSim.github.io)上的[获取源码](https://babblesim.github.io/fetching.html)和[构建说明](https://babblesim.github.io/building.html)。

接下来，用 `BSIM_OUT_PATH` 与 `BSIM_COMPONENTS_PATH` 两个环境变量指定 BabbleSim 安装位置。按前述步骤准备时可设置为：

```shell
export BSIM_OUT_PATH=${ZEPHYR_BASE}/../tools/bsim
export BSIM_COMPONENTS_PATH=${BSIM_OUT_PATH}/components/
```

> 原文注意：可把这两行加入 `~/.zephyrrc` 或 Shell 初始化脚本 `~/.bashrc`，避免每次新开 Shell 都手动设置。这里的 `~` 是读者自己的用户主目录，变量路径随其工作区位置解析。

现在可以构建此开发板上的应用，例如：

```shell
west build -b nrf52_bsim samples/hello_world
```

随后执行应用：

```shell
$ ./build/zephyr/zephyr.exe -nosim
# Press Ctrl+C to exit
```

代码中的 `$` 表示命令提示符，注释 `Press Ctrl+C to exit` 表示按 `Ctrl+C` 退出。

生成的是 BabbleSim 可执行程序。命令行参数 `-nosim` 表示脱离 BabbleSim 模拟单独运行，仅在没有无线电活动时可行，但适用于大多数 Zephyr 示例和测试。

需要无线电活动时，还必须运行 BabbleSim 的 2G4（2.4 GHz）物理层模拟器（PHY）。例如，让一个[低功耗蓝牙心率监测中心设备（BLE Central）](../bluetooth_samples/P008_心率中心设备.md#ble_central_hr)连接一个[心率监测外围设备（BLE Peripheral）](../bluetooth_samples/P007_心率服务外设.md#ble_peripheral_hr)：先构建中心设备应用，再以合适名称把生成文件复制到模拟器的 `bin` 目录。

```shell
west build -b nrf52_bsim samples/bluetooth/central_hr
```

```shell
$ cp build/zephyr/zephyr.exe \
  ${BSIM_OUT_PATH}/bin/bs_nrf52_bsim_samples_bluetooth_central_hr
```

对外围设备应用执行同样操作：

```shell
west build -b nrf52_bsim samples/bluetooth/peripheral_hr
```

```shell
$ cp build/zephyr/zephyr.exe \
  ${BSIM_OUT_PATH}/bin/bs_nrf52_bsim_samples_bluetooth_peripheral_hr
```

再将它们与 BabbleSim 2G4 物理层模拟器一起启动：

```shell
cd ${BSIM_OUT_PATH}/bin/
./bs_nrf52_bsim_samples_bluetooth_peripheral_hr -s=trial_sim -d=0 &
./bs_nrf52_bsim_samples_bluetooth_central_hr -s=trial_sim -d=1 &
./bs_2G4_phy_v1 -s=trial_sim -D=2 -sim_length=10e6 &
```

参数含义如下。

| 参数 | 含义 |
| --- | --- |
| `-s` | 唯一标识本次模拟的字符串 |
| `-D` | 告诉 PHY 本次模拟包含多少设备 |
| `-d` | 指定设备在模拟中的编号 |
| `-sim_length` | 模拟持续时间，单位为微秒（Microsecond） |

BabbleSim 设备与 PHY 还支持许多参数，运行时加 `-help` 可查看帮助。更多运行说明见[BabbleSim 示例](https://babblesim.github.io/example_2g4.html)。

## 2.3\_运行需要控制台交互的应用

某些应用需要通过控制台（Console）与用户交互，通常启用 [`CONFIG_CONSOLE_SUBSYS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_CONSOLE_SUBSYS) 和 [`CONFIG_CONSOLE_GETCHAR`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_CONSOLE_GETCHAR)。BabbleSim 开发板默认禁用 UART 控制台；启用时加入 [UART 控制台配置片段（UART Console Snippet）](../snippets/P008_UART控制台配置片段.md#snippet-uart-console)：

```shell
west build -S serial-console [...]
```

> 译注：官方链接标题写 `uart-console`，原始命令使用 `serial-console`；两者按原文保留。

用户需把终端连接到伪终端（Pseudoterminal），才能查看输出并与应用交互：

```shell
# Automatically attach to the terminal
./build/zephyr/zephyr.exe --uart<uart_id>_pty_attach
# Use a custom command to attach to the terminal, for example 'xterm -e screen %s &'
./build/zephyr/zephyr.exe --uart<uart_id>_attach_cmd=<cmd>
# Use a custom way to connect to the pseudoterminal
./build/zephyr/zephyr.exe --uart<uart_id>_pty --uart_pty_wait
minicom -D /dev/pts/<pts_id>
```

以上三段代码注释依次表示：自动连接终端；使用自定义命令连接，例如 `xterm -e screen %s &`；采用自定义方法连接伪终端。`/dev/pts/<pts_id>` 是 Linux 伪终端设备路径，编号需按实际分配填写。

`--uart_list` 会打印 `uart_id` 与 UART 外设之间的对应关系。设备树覆盖文件（Overlay）描述使用哪个 UART 外设作为控制台输出。连接 UART 输出的更多细节见可执行程序的 `-help` 输出。

## 2.5\_调试、覆盖率与地址检查

与 [native_sim](../native_reference/P004_Native_Simulator本机模拟器.md#native-sim-debug) 一样，生成文件是 Linux 本机应用，可使用调试器 GDB、分析工具 Valgrind 等本机工具调试或插桩（Instrumentation）。

此开发板继承 [POSIX 架构的代码覆盖率分析方法](https://docs.zephyrproject.org/latest/develop/test/coverage.html#coverage-posix)；也能像 native_sim 一样使用[地址检查器（Address Sanitizer，ASan）与未定义行为检查器（Undefined Behavior Sanitizer，UBSan）](../native_reference/P004_Native_Simulator本机模拟器.md#native-sim-asan)。

一个或多个组件在调试器中运行或被插桩时，BabbleSim 仍可正常工作。例如，一个设备在断点处暂停，会暂停整个模拟。

BabbleSim 按设计完全确定，其结果不受宿主计算速度影响。所有随机性均由随机种子（Random Seed）控制，种子可以通过命令行参数指定。

<a id="about-time-in-babblesim"></a>

## 2.6\_BabbleSim中的时间

BabbleSim 的时间是模拟时间，与真实时间解耦。通常模拟时间能比真实时间快几个数量级，仅受工作站计算能力限制。如果要把模拟速度限制为实时或实时的某个比例，可将[handbrake 限速设备](https://github.com/BabbleSim/base/tree/master/device_handbrake)连接到 BabbleSim PHY。
