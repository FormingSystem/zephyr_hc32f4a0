## 3.1\_概述

为了模拟 nRF5340 片上系统（SoC），Zephyr 提供两个目标开发板：`nrf5340bsim/nrf5340/cpuapp` 和 `nrf5340bsim/nrf5340/cpunet`。

它们使用 [BabbleSim](https://BabbleSim.github.io) 模拟无线电活动，通过 [POSIX 架构](../native_reference/P002_POSIX架构.md#posix-arch)和[本机模拟器（Native Simulator）](https://github.com/BabbleSim/native_simulator/blob/main/docs/README.md)在开发系统上本机执行应用。这样既有本机代码的执行性能，也便于用本机工具调试，但同时继承[对应限制](../native_reference/P002_POSIX架构.md#posix-arch-limitations)。

与 `nrf5340dk` 目标一样，`nrf5340bsim/nrf5340/cpuapp` 支持模拟 SoC 的应用核（Application Core），`nrf5340bsim/nrf5340/cpunet` 支持网络核（Network Core）。

这些开发板包含下列 nRF5340 外设模型，并使用与 `nrf5340dk` 目标相同的驱动。

- 加速地址解析器（Accelerated Address Resolver，AAR）。
- 高级加密标准（AES）的CCM与电子密码本（Electronic Codebook，ECB）模式加密硬件；CCM为计数器模式结合CBC-MAC的认证加密模式。
- 时钟控制（Clock Control，CLOCK）。
- 分布式可编程外设互连（Distributed Programmable Peripheral Interconnect，DPPI）。
- 事件生成单元（Event Generator Unit，EGU）。
- 工厂信息配置寄存器（Factory Information Configuration Registers，FICR）。
- 通用输入输出（General-purpose Input/Output，GPIO）及其任务与事件（GPIO Tasks and Events，GPIOTE）。
- 处理器间通信（Interprocessor Communication，IPC）。
- 互斥外设（Mutual Exclusive Peripheral，MUTEX）。
- 非易失性存储控制器／闪存（Non-Volatile Memory Controller / Flash，NVMC）。
- 无线电（RADIO）。
- 随机数发生器（Random Number Generator，RNG）。
- 实时计数器（Real Time Counter，RTC）。
- 温度传感器（Temperature Sensor，TEMP）。
- 定时器（TIMER）。
- 带EasyDMA直接存储器访问的通用异步收发器（UART with Easy DMA，UARTE）。
- 用户信息配置寄存器（User Information Configuration Registers，UICR）。

各外设建模到什么程度，见[硬件模型实现状态](https://github.com/BabbleSim/ext_nRF_hw_models/blob/main/docs/README_impl_status.md)。

与真实 nRF5340 器件不同，这些开发板的随机存取存储器（RAM）以及用于代码的闪存（Flash）容量不受限制。

<a id="building-for-and-using-these-boards"></a>

## 3.2\_构建与使用

若只关注 SoC 中某一个微控制器（MCU），可以按 [nrf52_bsim 的说明](P002_NRF52模拟开发板.md#nrf52bsim-build-and-run)使用对应目标 `nrf5340bsim/nrf5340/cpuapp` 或 `nrf5340bsim/nrf5340/cpunet`，只需在构建时替换开发板／目标。

> 原文注意：与真实硬件不同，为便于在没有应用核镜像（Image）的情况下开发，网络核 MCU 默认在启动时自动引导。可以用 [`CONFIG_NATIVE_SIMULATOR_AUTOSTART_MCU`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NATIVE_SIMULATOR_AUTOSTART_MCU) 或命令行参数 `--cpu1_autostart` 控制。如果某个 MCU 启动时没有任何镜像，它会自动进入休眠。

## 3.3\_将两个MCU镜像组装为单个可执行程序

默认情况下，针对上述任一目标构建，会生成对应 MCU 代码镜像的库 `zephyr/zephyr.elf`，以及可执行程序 `zephyr/zephyr.exe`。后者包含本机模拟器运行器（Runner）、SoC 硬件模型、该 MCU 镜像，以及另一个 MCU 的空镜像。

如果想把另一个 MCU 已构建好的镜像加入可执行程序，可在构建第二个镜像时，通过 [`CONFIG_NATIVE_SIMULATOR_EXTRA_IMAGE_PATHS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NATIVE_SIMULATOR_EXTRA_IMAGE_PATHS) 指定前一个镜像。前一个镜像可以由 Zephyr 构建系统或其他兼容本机模拟器的构建系统生成。

也可使用[系统构建（sysbuild）](../sysbuild/P001_系统构建.md#sysbuild)构建双 MCU 可执行程序。理解方法的一种直接途径，是查看仓库中的现有示例，例如 [nrf53_sync_rtc 示例](https://docs.zephyrproject.org/latest/samples/boards/nordic/nrf53_sync_rtc/README.html#nrf53-sync-rtc-sample-build-bsim)及其 [sysbuild.cmake 源码](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/boards/nordic/nrf53_sync_rtc/sysbuild.cmake)。

> 原文注意：这些库／镜像不是可供实际嵌入式器件使用的镜像。不能将它们用于嵌入式器件，也不能拿嵌入式镜像组装本机可执行程序。

<a id="trustzone-tf-m-and-other-security-considerations"></a>

## 3.4\_TrustZone、TF-M与其他安全注意事项

这些开发板没有建模 Arm TrustZone 安全隔离技术，因而：

- 不区分安全／非安全（Secure/Non-secure）执行状态或总线访问。
- 所有软件原则上都能访问全部 RAM、闪存和外设。拥有自己互连主端口（Interconnect Master Port）的外设，原则上能访问任何其他外设或 RAM 区域。
- 不提供 `nrf5340bsim/nrf5340/cpuapp/ns` 开发板／构建目标，也不能混合安全与非安全镜像。
- 当前没有安全保护单元（System Protection Unit，SPU）模型，因此不能将闪存、RAM 区域或外设标记为仅限安全或非安全访问。
- 不能使用可信固件 M（Trusted Firmware-M，TF-M）。

另外，也没有建模 Arm CryptoCell-312 外设。仍可使用 Mbed TLS 密码库，但须使用软件密码后端（Software Crypto Backend），不能使用 CryptoCell 硬件加速。
