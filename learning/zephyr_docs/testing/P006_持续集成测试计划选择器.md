# 第6章\_持续集成测试计划选择器

原文：[CI Test Plan Selector (test_plan_v2)](https://docs.zephyrproject.org/latest/develop/test/ci_test_plan.html)。读取日期：2026-10-12，`latest`。

**持续集成（Continuous Integration，CI）测试计划选择器（Test Plan Selector）**是官方 `scripts/ci/test_plan_v2.py` 中的模块化 Python 脚本。它分析**拉取请求（Pull Request，PR）**改动的文件，生成有针对性的 Twister 计划，选择可能受影响的测试，避免每个提交都无条件运行全树测试。

它生成两份产物：

- `testplan.json`：通过 `twister --load-tests` 交给运行器。
- `.testplan`：纯文本 `KEY=value` 环境文件，供 CI 调度脚本读取，其中包含 `TWISTER_TESTS`、`TWISTER_NODES`、`TWISTER_FULL`。

> 译注：这些是官方脚本的输入输出约定，不是本次已生成的计划。本文翻译 `latest` 的设计与用法，当前仓库较早的参照源码未必有同样接口，使用前核对目标版本。

## 6.1\_策略处理链

选择器由**策略处理链（Strategy Pipeline）**组成。每个**选择策略（Selection Strategy）**独立分析：接收改动文件列表或尚未被前序策略接收的子集，按自己的逻辑检查，返回 `TwisterCall` 调用描述列表，以及已处理文件集合。

**编排器（Orchestrator）**驱动策略链，把结果合并到 **计划累积器（PlanAccumulator）**，去重套件，最后写输出文件。`TwisterCall` 是描述应如何调用 Twister 的对象，不等于策略本身立即启动了测试。

顺序遵循两个原则。首先，具体策略先于宽泛策略，例如 `tests/kernel/sched/` 中的改动先交给 `DirectTestStrategy`，避免直接扩大为整个内核区域。其次，能独占处理文件的策略先于只追加覆盖的策略，避免板定义同时触发驱动兼容性扫描、Kconfig 扫描等重复工作。

## 6.2\_固定策略顺序

表中“移出文件池”对应 **消费式处理（Consuming）**：已处理文件不再交给后续策略；“否”表示通常采用**追加式处理（Additive）**，保留文件供其他策略继续补充覆盖。

| 顺序 | 策略类名 | 移出文件池 | 原因与职责 |
| --- | --- | --- | --- |
| 0 | `ComplexityStrategy` | 否 | 用 pydriller、lizard 分析补丁复杂度，必须先运行，让 `RiskClassifierStrategy` 可读取分数；自身不生成 Twister 调用。 |
| 1 | `IgnoreStrategy` | 是 | 提前忽略其规则判定不参与测试选择的文档、CI 工作流、工具等路径，避免后续无效分析。 |
| 1b | `BoilerplateFilter` | 是 | 去掉差异完全由空白、空行、许可证、版权或单独注释界定符组成的文件；要求 Git 提交范围，没有范围则不处理。 |
| 2 | `DirectTestStrategy` | 是 | 测试或示例文件变化只触发直接对应测试，避免维护区域策略另加整个区域。 |
| 3 | `SnippetStrategy` | 是 | 配置片段变化只选声明相应 `required_snippets` 的测试，避免把片段 YAML 当未知配置。 |
| 4 | `BoardStrategy` | 是 | 板专属变化对每个变体执行定向集成测试，避免板 YAML 又被 Kconfig 或头文件策略匹配。 |
| 5 | `SoCStrategy` | 是 | **片上系统（System on Chip，SoC）**级变化覆盖该家族上的板，不再把相同 `soc/` 路径交给 Kconfig 扫描。 |
| 6 | `ManifestStrategy` | 是 | `west.yml` 清单变化选择带模块标签的集成测试，避免通用维护区域扫描加入无关测试。 |
| 7 | `DriverCompatStrategy` | 否 | 按驱动兼容关系增加测试，同时允许 Kconfig 和维护区域策略补充覆盖。 |
| 8 | `DtsBindingStrategy` | 否 | **设备树绑定（Devicetree Binding）**变化结合覆盖文件相关测试和指定板的维护区域调用。 |
| 9 | `KconfigImpactStrategy` | 否 | Kconfig 可能影响多个无直接关系的文件；原文说明非广泛使用符号有条件地处理文件，广泛符号留给后续兜底。 |
| 10 | `HeaderImpactStrategy` | 否 | 根据头文件包含者追溯维护区域；被包含次数超过阈值的广泛使用头文件跳过该定向处理。 |
| 11 | `MaintainerAreaStrategy` | 否 | 兜底匹配 `MAINTAINERS.yml` 区域模式，对 `tests:` 非空的匹配区域生成 `--test-pattern` 调用。 |

> 译注：pydriller 是 Git 仓库分析库，lizard 是代码复杂度分析工具。原文提到 `RiskClassifierStrategy`，但本页固定顺序表没有列出它的位置；这里不补造执行顺序。表中 Kconfig 策略虽标“不消费”，描述又使用“消费”一词，实际是否从文件池移除仍应以相应版本的策略属性和编排器为准，不能仅根据概述推断。

## 6.3\_非实质性差异过滤

`BoilerplateFilter` 在忽略策略之后、所有测试选择策略之前，通过 Git 差异逐文件判断修改是否全属以下类别：

1. 空白和空行：执行 `git diff -w --ignore-blank-lines`，若该文件没有输出，判为仅有这类差异。
2. 许可证和版权头：行以 `SPDX-License-Identifier:`、`SPDX-FileCopyrightText:` 或 `Copyright` 开始。**软件包数据交换标识（Software Package Data Exchange，SPDX）**在此用于许可证与版权元数据。
3. 只有注释界定符的行：非空白内容仅由 `/*`、`*/`、`//`、`#`、`*` 等构成，例如块注释边框重新排版。

只有全部新增、删除行都属于上述类别，文件才移出池；任意一行实质性语句、宏或声明变化，都会使文件继续交给后续策略。

未提供 `--commits`，例如只用 `--modified-files` 时，没有提交范围供比较，该过滤器不执行，文件保留。

> 译注：这是原文描述的过滤启发式，不是“空白在所有语言中都不影响运行”的普遍保证；Python 缩进、构建语法等可能具有空白语义。审核过滤规则时仍应考虑文件类型和实际变化，不把过滤结果等同于行为已验证。

## 6.4\_消费式与追加式处理

每个策略子类有 `consumes: bool` 类属性。

- `consumes=True`：返回的已处理集合从剩余池移除。适用于对某种文件具有明确、独占解释权的策略；若后续再次处理会冗余或错误，就应消费它。
- `consumes=False`：默认值。无论返回什么已处理集合，文件都留在池中，下游仍能看到；适合补充覆盖而不独占文件的策略。

原文同时提示：当剩余池为空，编排器不再调用策略。追加式策略不会缩小池，只有消费式策略能减少剩余文件。这里“仍留在池中”与“完全没有任何策略处理过”是两个不同概念。

## 6.5\_全量回退与节点数量

以下任一情况使 `.testplan` 的 `TWISTER_FULL=True`：

- 所有策略结束后，仍存在从未被任何策略处理的改动文件。脚本请求全量运行，避免未知路径被静默漏掉。
- 某策略返回 `full_run=True` 的 `TwisterCall`。编排器立即设置全量标志，清空剩余池，停止继续执行后续调用，例如核心公共头文件变化不适合定向选择时。

此时 CI 脚本应丢弃定向 `testplan.json`，不带 `--load-tests` 运行 Twister。

`TWISTER_NODES` 是需要的 CI **构建节点（Builder Node）**数量：没有选中测试时为 0；测试数少于每节点容量时为 1；否则为总数除以容量后**向上取整（Ceiling）**。容量由 `--tests-per-builder` 指定，默认 900，向上取整避免不能整除时节点超容量。

> 译注：全量回退表示请求更大的测试范围，不保证因此捕获所有回归；最终覆盖仍取决于测试实现、平台和 CI 执行条件。

## 6.6\_添加新策略

先继承策略基类 `SelectionStrategy`，实现名字属性与分析方法。示例变量 `calls` 保存调用描述列表，变量 `handled` 保存已处理的输入文件子集：

```python
class MyStrategy(SelectionStrategy):

    consumes: bool = False  # or True if authoritative

    @property
    def name(self):
        return "MyStrategy"

    def analyze(self, changed_files):
        # inspect changed_files
        calls = [...]       # list of TwisterCall
        handled = {...}     # subset of changed_files this strategy owns
        return calls, handled
```

随后完成以下步骤：

1. 判断后续策略看到同一文件，能否提供有用覆盖；若只会冗余或产生错误，设置 `consumes=True`。
2. 在 `build_strategies()` 中安排位置：消费式先于追加式，具体先于一般；不改变池的追加式策略可按分析成本由低到高排列。
3. 可选依赖在 `analyze()` 内延迟导入。缺失依赖时平稳返回 `[], set()`，并用 `# noqa: PLC0415` 抑制延迟导入检查提示。
4. 在 `scripts/tests/ci/test_test_plan_v2.py` 增加正常匹配、不相关文件不处理、以及文件不存在、YAML 损坏、空输入等边界用例。

**YAML（YAML Ain't Markup Language，配置数据格式）**用于上述配置解析；`noqa` 注释是代码检查工具的抑制标记，不会替代实际异常处理。

## 6.7\_策略共享上下文

`PipelineContext` 是通过 `build_strategies()` 传给所有策略的 **数据类（Dataclass）**，当前包含：

| 字段 | 用途 |
| --- | --- |
| `complexity_score` | 补丁整体复杂度分数，由 `ComplexityStrategy` 写入，供 `RiskClassifierStrategy` 读取。 |
| `file_metrics` | 逐文件 `ComplexityMetrics` 映射，用于详细日志与下游决策。 |

新增跨策略状态应作为带类型的字段加入 `PipelineContext`，不要藏在某个策略实例私有变量中。

## 6.8\_验证选择行为

测试位于 `scripts/tests/ci/test_test_plan_v2.py`，在具备相应 pytest 依赖的 Zephyr 源码根执行：

```sh
pytest scripts/tests/ci/test_test_plan_v2.py -v
```

每个策略或共享组件对应一个测试类。下面的 `tmp_path` 是 pytest 临时目录夹具，`TwisterExecutor` 是执行 Twister 调用的类，测试中可用模拟对象替换它。新增策略应覆盖以下类别：

| 类别 | 要求 |
| --- | --- |
| **单元测试（Unit Test）** | 不要求完整 Zephyr 源码树，用 `tmp_path` 夹具建立最小 `board.yml`、`snippet.yml`、`testcase.yaml` 等结构；执行快且不依赖外部状态。 |
| 辅助方法测试 | 独立验证路径遍历、YAML 解析和正则提取，用人工构造内容替代仓库真实文件依赖。 |
| 编排器集成测试 | 用**模拟对象（Mock）**策略及 `TwisterExecutor` 模拟对象验证消费/追加、全量信号及 `.testplan` 输出，不调用真正 Twister。 |
| 真实源码树集成测试 | 可选，只在完整检出上有意义，使用 `@pytest.mark.integration` 标记以供默认运行排除。 |

> 译注：pytest 标记本身不会自动排除测试，默认排除还依赖项目的 pytest 配置或调用参数；原文描述的是测试套件应采用的分组约定。

最低检查点包括：不相关输入返回空调用、空处理集合；有效输入产生预期 `TwisterCall`；缺少磁盘文件时不崩溃；消费式策略的已处理集合只含匹配文件；追加式策略的集合为空，或只含它确实能判断的文件。

## 6.9\_命令行参考

以下完整保留原文帮助形式。大写占位 `FILE` 是文件，`PATH` 是路径，`DIR` 是目录，`PLATFORM` 是平台，`NAME` 是策略名称；`HEAD` 是 Git 当前检出提交的引用，JSON 即**JavaScript对象表示法（JavaScript Object Notation）**数据格式：

```text
usage: test_plan_v2.py [-c A..B] [-m FILE] [-f PATH]
                       [-o FILE] [-p PLATFORM] [--maintainers-file FILE]
                       [-T DIR] [--quarantine-list FILE]
                       [--tests-per-builder N] [--disable-strategy NAME]
                       [--detailed-test-id]

-c A..B              Git commit range (e.g. ``main..HEAD``).  Changed files
                     are derived from ``git diff --name-only A..B``.
-m FILE              JSON file containing a list of changed file paths.
-f PATH              Treat PATH as a changed file (repeatable).
-o FILE              Output JSON file (default: ``testplan.json``).
-p PLATFORM          Restrict all selections to this platform (repeatable).
--maintainers-file   Path to ``MAINTAINERS.yml``.
-T DIR               Extra testsuite root forwarded to every twister call.
--quarantine-list    Quarantine YAML forwarded to twister.
--tests-per-builder  Tests per CI builder node (default: 900).
--disable-strategy   Skip a strategy by name (repeatable).
--detailed-test-id   Pass ``--detailed-test-id`` to twister.
```

逐项中文说明如下，大写名字是参数占位：

| 参数 | 含义 |
| --- | --- |
| `-c A..B` | Git 提交范围，例如 `main..HEAD`；改动文件来自 `git diff --name-only A..B`。 |
| `-m FILE` | 保存改动文件路径列表的 **JavaScript对象表示法（JavaScript Object Notation，JSON）**文件。 |
| `-f PATH` | 把某路径视为改动文件，可重复。 |
| `-o FILE` | 输出 JSON，默认 `testplan.json`。 |
| `-p PLATFORM` | 将所有选择限制到指定平台，可重复。 |
| `--maintainers-file FILE` | `MAINTAINERS.yml` 路径。 |
| `-T DIR` | 向每次 Twister 调用转发的额外测试根目录。 |
| `--quarantine-list FILE` | 转发给 Twister 的隔离 YAML。 |
| `--tests-per-builder N` | 每个 CI 构建节点的测试容量，默认 900。 |
| `--disable-strategy NAME` | 按策略名禁用，可重复。 |
| `--detailed-test-id` | 向 Twister 转发同名选项，生成带配置路径的详细测试标识。 |
