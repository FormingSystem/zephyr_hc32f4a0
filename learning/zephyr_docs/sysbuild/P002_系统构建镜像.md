# 第2章\_系统构建镜像

原文：[Sysbuild images](https://docs.zephyrproject.org/latest/build/sysbuild/images.html)。读取日期：2026-10-12，`latest`。

**系统构建（System Build，Sysbuild）**允许向一次构建添加额外的**固件镜像（Firmware Image）**。项目或开发板可以声明这些镜像。本页介绍的 Sysbuild 镜像接入机制当前要求它们是 Zephyr 应用。

> 译注：这不否定上一章通过 CMake `ExternalProject` 构建非 Zephyr 项目的方式；两者的管理能力不同。本页的**构建域（Domain）**、镜像配置与 west 集成针对 Zephyr 应用。下面是供应用、开发板和模块维护者编写的配置示例，`<app>`、`<image>` 等需替换，未经实际构建验证。

## 2.1\_镜像可以从哪里加入

以下途径可以同时使用：

| 接入方 | 文件与作用 |
| --- | --- |
| 应用（Application） | 应用目录中的 `sysbuild.cmake` 添加镜像，`Kconfig.sysbuild` 控制是否加入。 |
| 开发板（Board） | 开发板目录中的 `sysbuild.cmake` 添加镜像，`Kconfig.sysbuild` 控制是否加入。 |
| 片上系统（System on Chip，SoC） | SoC 目录中的 `sysbuild.cmake` 添加镜像。 |
| 模块（Module） | 在 `module.yml` 中使用 `sysbuild-cmake` 与 `sysbuild-kconfig` 选项，详见[Sysbuild模块接入](https://docs.zephyrproject.org/latest/develop/modules.html#sysbuild-module-integration)。 |

这里的文件由相应接入方维护；Sysbuild 读取它们，决定创建哪些应用构建系统。

## 2.2\_两种镜像选择方式

附加镜像既可固定为某个应用，也可设计为由 Kconfig 选择、允许模块继续扩展的应用类型。

### 2.2.1\_固定的单一镜像

这种方式把附加镜像固定为某个应用，不能选择另一种应用。但若该应用位于独立仓库，仍可通过 west 清单选择不同版本或其他来源，因此“固定应用”不等于“版本永远不变”。

> 原文注意：仅当镜像固定于某个特定接口、无需扩展时，才应采用此方式。

假定已按[应用开发说明](../application/大纲.md)创建 Zephyr 应用。在 `Kconfig.sysbuild` 中声明布尔选项 `MY_IMAGE`，其 Sysbuild 配置形式为 `SB_CONFIG_MY_IMAGE`：

```kconfig
config MY_IMAGE
        bool "Include my amazing image"
        help
          If enabled, will include my amazing image in the build which does...
```

> 原文注意：若这是应用自己的 `Kconfig.sysbuild`，别忘记包含 `source "share/sysbuild/Kconfig"`。

在 `sysbuild.cmake` 中根据该选项调用 `ExternalZephyrProject_Add()`：

```cmake
if(SB_CONFIG_MY_IMAGE)
  ExternalZephyrProject_Add(
    APPLICATION my_image
    SOURCE_DIR ${ZEPHYR_MY_IMAGE_MODULE_DIR}/path/to/my_image
  )
endif()
```

> 译注：`APPLICATION my_image` 声明构建域名称，`SOURCE_DIR` 指向已有应用源码。CMake 变量 `ZEPHYR_MY_IMAGE_MODULE_DIR` 应由已发现的同名模块提供；它不是这里新建的应用目录。路径中的 `path/to/my_image` 需改为该模块内真实位置。Kconfig 的 `source` 以其加载环境的源根解析；显式带 `$(ZEPHYR_BASE)` 的写法见下一小节。

可在此继续设置[应用依赖顺序](P001_系统构建.md)或本章后述镜像配置。west 启用示例：

```sh
west build -b nrf52840dk/nrf52840 --sysbuild <app> -- -DSB_CONFIG_MY_IMAGE=y
```

### 2.2.2\_可扩展、可替换的镜像

这种方式允许用户从多个应用中选择附加镜像。下游项目还可继续扩展选择项，加入上游 Zephyr 未提供的树外应用。虽然实现更复杂，但这是为上游 Zephyr 添加镜像时优先采用的方式。

`Kconfig.sysbuild` 原例通过 `SUPPORT_OTHER_APP` 和 `SUPPORT_OTHER_APP_MY_IMAGE` 表达能力条件，通过 `choice OTHER_APP` 提供互斥选择；其中 choice 成员 `OTHER_APP_IMAGE_NONE` 表示不添加，`OTHER_APP_IMAGE_MY_IMAGE` 表示选择 `my_image`；原例默认成员名 `OTHER_APP_NONE` 与定义不一致，见后面译注。字符串选项 `OTHER_APP_IMAGE_NAME` 与 `OTHER_APP_IMAGE_PATH` 分别给出所选镜像名称和源码位置：

```kconfig
config SUPPORT_OTHER_APP
        bool
        # Conditions can be placed here if this application type is only usable on certain platforms
        default y

config SUPPORT_OTHER_APP_MY_IMAGE
        bool
        # Conditions can be placed here if this image is only usable on certain platforms
        default y

choice OTHER_APP
        prompt "Other app image"
        # Defaults can be specified here if a default image should be loaded if e.g. it is supported
        default OTHER_APP_NONE
        depends on SUPPORT_OTHER_APP

config OTHER_APP_IMAGE_NONE
        bool "None"
        help
          Do not Include an other app image in the build.

config OTHER_APP_IMAGE_MY_IMAGE
        bool "my_image"
        depends on SUPPORT_OTHER_APP_MY_IMAGE
        help
          Include my amazing image as the other app image to use, which does...

endchoice

config OTHER_APP_IMAGE_NAME
        string
        default "my_image" if OTHER_APP_IMAGE_MY_IMAGE
        help
          Name of other app image.

config OTHER_APP_IMAGE_PATH
        string
        default "$(ZEPHYR_MY_IMAGE_MODULE_DIR)/path/to/my_image" if OTHER_APP_IMAGE_MY_IMAGE
        help
          Source directory of other app image.
```

> 原文注意：若这是应用自己的 `Kconfig.sysbuild`，别忘记包含 `source "$(ZEPHYR_BASE)/share/sysbuild/Kconfig"`。

> 译注：原例写了 `default OTHER_APP_NONE`，但随后定义的“无附加镜像”选项是 `OTHER_APP_IMAGE_NONE`，两者名称不一致。实际配置时应让默认项指向已定义的 choice 成员。代码保留原文，避免把修订误认为官方原例。

`sysbuild.cmake` 根据所选名称与路径添加应用：

```cmake
if(SB_CONFIG_OTHER_APP_IMAGE_PATH)
  ExternalZephyrProject_Add(
    APPLICATION ${SB_CONFIG_OTHER_APP_IMAGE_NAME}
    SOURCE_DIR ${SB_CONFIG_OTHER_APP_IMAGE_PATH}
  )
endif()
```

同样可以在此设置依赖顺序和镜像配置。原文给出的启用命令为：

```sh
west build -b nrf52840dk/nrf52840 --sysbuild <app> -- -DSB_CONFIG_MY_IMAGE=y
```

> 译注：这个命令仍使用上一种固定镜像方案的 `SB_CONFIG_MY_IMAGE`，而本小节的 choice 成员名是 `OTHER_APP_IMAGE_MY_IMAGE`。按本段定义选择该镜像时，应设置 `-DSB_CONFIG_OTHER_APP_IMAGE_MY_IMAGE=y`，并满足其能力依赖，不能假定示例中未定义的选项自动存在。

其他[外部模块](https://docs.zephyrproject.org/latest/develop/modules.html#modules)可用下面的 `Kconfig.sysbuild` 片段增加第二个选择项。它重新打开同名 choice，并为名称、路径选项追加与新选择相关的默认值。新增成员 `OTHER_APP_IMAGE_MY_SECOND_IMAGE` 表示选择第二个镜像，模块目录变量 `ZEPHYR_MY_SECOND_IMAGE_MODULE_DIR` 提供其源码根：

```kconfig
config SUPPORT_OTHER_APP_MY_SECOND_IMAGE
        bool
        default y

choice OTHER_APP

config OTHER_APP_IMAGE_MY_SECOND_IMAGE
        bool "my_second_image"
        depends on SUPPORT_OTHER_APP_MY_SECOND_IMAGE
        help
          Include my other amazing image as the other app image to use, which does...

endchoice

config OTHER_APP_IMAGE_NAME
        default "my_second_image" if OTHER_APP_IMAGE_MY_SECOND_IMAGE

config OTHER_APP_IMAGE_PATH
        default "$(ZEPHYR_MY_SECOND_IMAGE_MODULE_DIR)/path/to/my_second_image" if OTHER_APP_IMAGE_MY_SECOND_IMAGE
```

不需额外修改 CMake：已有 CMake 代码读取所选名称和路径，用户选择替代镜像后，就会添加该镜像而不是原镜像。原文启用第二个镜像的命令为：

```sh
west build -b nrf52840dk/nrf52840 --sysbuild <app> -- -DSB_CONFIG_MY_SECOND_IMAGE=y
```

> 译注：这一原例也存在配置项名称不一致。按上面的定义，应选择 `-DSB_CONFIG_OTHER_APP_IMAGE_MY_SECOND_IMAGE=y`；`ZEPHYR_MY_SECOND_IMAGE_MODULE_DIR` 则需要由实际接入的第二个模块提供。修改 west 清单版本与选择另一个应用是不同动作。

## 2.3\_镜像配置的读写

Sysbuild 既能为镜像设置 Kconfig 选项，也能读取镜像完成配置后的 Kconfig 结果。因此可把一个设置集中到 Sysbuild，再向全部或选定镜像分发；也可以根据镜像最终结果调整后续顶层任务。

### 2.3.1\_配置之前写入Kconfig值

Sysbuild 可以在各镜像的 CMake 配置之前设置它们的 Kconfig 选项。这些设置会持续生效，不能由镜像自己改写。对应 CMake 函数为：

```cmake
set_config_bool(<image> CONFIG_<setting> <value>)
set_config_string(<image> CONFIG_<setting> <value>)
set_config_int(<image> CONFIG_<setting> <value>)
```

> 译注：`set_config_bool()`、`set_config_string()` 和 `set_config_int()` 分别设置布尔、字符串和整数配置。它们针对指定镜像，不是修改当前终端的环境变量；这里的“持续生效”描述 Sysbuild 对该镜像构建配置的约束，不表示写入操作系统全局配置。

例如，为默认镜像启用 Kconfig 选项 `CONFIG_BUILD_OUTPUT_HEX`，使其生成 **Intel十六进制文件（Intel HEX）**。CMake 变量 `DEFAULT_IMAGE` 保存默认镜像名称：

```cmake
set_config_bool(${DEFAULT_IMAGE} CONFIG_BUILD_OUTPUT_HEX y)
```

可在应用、开发板或 SoC 的 `sysbuild.cmake` 中安全使用这些函数，因为这些文件在镜像的 CMake 进程启动之前加载。若通过模块扩展 Sysbuild，则应使用 **CMake配置前钩子（Pre-CMake Hook）**：

```cmake
function(${SYSBUILD_CURRENT_MODULE_NAME}_pre_cmake)
  cmake_parse_arguments(PRE_CMAKE "" "" "IMAGES" ${ARGN})

  foreach(image ${PRE_CMAKE_IMAGES})
    set_config_bool(${image} CONFIG_BUILD_OUTPUT_HEX y)
  endforeach()
endfunction()
```

> 译注：钩子名由 `SYSBUILD_CURRENT_MODULE_NAME` 加 `_pre_cmake` 组成；该变量表示当前模块名。`cmake_parse_arguments()` 解析回调参数，`IMAGES` 列表中的镜像被逐个设置为输出 HEX。必须在配置之前写入，不能等镜像已完成配置后再用这一阶段的逻辑。

### 2.3.2\_镜像配置脚本

**镜像配置脚本（Image Configuration Script）**是可为镜像提供共用设置的 CMake 文件。每个镜像可使用多个脚本；脚本应能应用于不同镜像，并依据 Sysbuild 选项为它们设置一致的配置。

MCUboot 的相关配置同时作用于应用和引导加载器镜像，就是通过这种方式实现的。由 Sysbuild 集中管理签名密钥等设置，可使主应用与引导加载器保持同步。密钥文件定位规则见[签名密钥文件](https://docs.zephyrproject.org/latest/build/signing/index.html#build-signing-keys)，可使用 `${APP_DIR}` 等 CMake 变量构造位置，不在本译文中固定某台机器的安装路径。

在镜像配置脚本中，CMake 变量 `ZCMAKE_APPLICATION` 是正在配置的应用名称；脚本可以调用 `set_config_*` 函数，也可以读取 Sysbuild Kconfig。

例如，若启用了 `SB_CONFIG_BOOTLOADER_MCUBOOT`，并将 `SB_CONFIG_SIGNATURE_TYPE` 设为 `NONE`，则为当前镜像设置 `CONFIG_MCUBOOT_GENERATE_UNSIGNED_IMAGE`：

```cmake
if(SB_CONFIG_BOOTLOADER_MCUBOOT AND "${SB_CONFIG_SIGNATURE_TYPE}" STREQUAL "NONE")
  set_config_bool(${ZCMAKE_APPLICATION} CONFIG_MCUBOOT_GENERATE_UNSIGNED_IMAGE y)
endif()
```

> 译注：此例体现 Sysbuild 选项如何映射到镜像选项，结果是生成未签名镜像；它不是推荐生产固件关闭签名。具体签名策略由项目配置决定。

### 2.3.3\_应用或模块添加配置脚本

应用可在 `sysbuild.cmake` 中添加镜像配置脚本。以下示例先读取目标属性 `IMAGE_CONF_SCRIPT`，再追加路径，最后写回，只作用于默认镜像：

```cmake
# This applies the image configuration script to the default image only
get_property(tmp_conf_scripts TARGET ${DEFAULT_IMAGE} PROPERTY IMAGE_CONF_SCRIPT)
list(APPEND tmp_conf_scripts "${CMAKE_SOURCE_DIR}/image_configurations/MY_CUSTOM_TYPE_image_default.cmake")
set_target_properties(${DEFAULT_IMAGE} PROPERTIES IMAGE_CONF_SCRIPT "${tmp_conf_scripts}")
```

模块代码通过配置前钩子，为所有镜像追加：

```cmake
function(${SYSBUILD_CURRENT_MODULE_NAME}_pre_cmake)
  cmake_parse_arguments(PRE_CMAKE "" "" "IMAGES" ${ARGN})

  # This applies the image configuration script to all images
  foreach(image ${PRE_CMAKE_IMAGES})
    get_property(tmp_conf_scripts TARGET ${image} PROPERTY IMAGE_CONF_SCRIPT)
    list(APPEND tmp_conf_scripts "${CMAKE_SOURCE_DIR}/image_configurations/MY_CUSTOM_TYPE_image_default.cmake")
    set_target_properties(${image} PROPERTIES IMAGE_CONF_SCRIPT "${tmp_conf_scripts}")
  endforeach()
endfunction(${SYSBUILD_CURRENT_MODULE_NAME}_pre_cmake)
```

> 译注：`IMAGE_CONF_SCRIPT` 是保存配置脚本列表的 CMake 目标属性；`tmp_conf_scripts` 是原例的临时变量。原例用 `${CMAKE_SOURCE_DIR}` 拼接路径，这个变量表示顶层 CMake 项目源目录，在 Sysbuild 中通常不是附加模块目录。应确认 `image_configurations/MY_CUSTOM_TYPE_image_default.cmake` 确实位于该变量所指位置；自定义脚本由项目维护者创建，不是执行示例后自动生成的文件。

### 2.3.4\_Zephyr全局镜像类型

由 Zephyr 全局提供的配置脚本，可以在 `ExternalZephyrProject_Add()` 中按类型选择，但需要修改 Zephyr 的 Sysbuild 代码。通常只有新增一种“任何项目都应能选择”的镜像类型时，才应扩展此机制；主要用于上游 Zephyr，派生版本也可自行增加类型。

允许的类型名称在 `share/sysbuild/cmake/modules/sysbuild_extensions.cmake` 的 `ExternalZephyrProject_Add()` 中定义。下面按原文保留三个文件片段，展示加入 `MY_CUSTOM_TYPE` 的过程。

接口参数 `BOARD` 与 `BOARD_REVISION` 表示板目标与修订号，`APP_TYPE` 表示应用类型；原有类型 `MAIN` 表示主应用，`BOOTLOADER` 表示引导加载器，新增 `MY_CUSTOM_TYPE` 表示自定义类型。原注释中的 `MAIN_APP` 也是在指主应用，`-DCONF_FILES` 的命名疑点见后面译注。

首先修改[官方扩展实现文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/share/sysbuild/cmake/modules/sysbuild_extensions.cmake)中的允许列表，并同步相关接口注释：

```cmake
# ...
# Usage:
#   ExternalZephyrProject_Add(APPLICATION <name>
#                             SOURCE_DIR <dir>
#                             [BOARD <board> [BOARD_REVISION <revision>]]
#                             [APP_TYPE <MAIN|BOOTLOADER|MY_CUSTOM_TYPE>]
#   )
# ...
# APP_TYPE <MAIN|BOOTLOADER|MY_CUSTOM_TYPE>: Application type.
#                                            MAIN indicates this application is the main application
#                                            and where user defined settings should be passed on as-is
#                                            except for multi image build flags.
#                                            For example, -DCONF_FILES=<files> will be passed on to the
#                                            MAIN_APP unmodified.
#                                            BOOTLOADER indicates this app is a bootloader
#                                            MY_CUSTOM_TYPE indicates this app is...
# ...
function(ExternalZephyrProject_Add)
  set(app_types MAIN BOOTLOADER MY_CUSTOM_TYPE)
# ...
```

然后在 `sysbuild.cmake` 中，通过参数 `APP_TYPE MY_CUSTOM_TYPE` 添加所选镜像：

```cmake
if(SB_CONFIG_OTHER_APP_IMAGE_PATH)
  ExternalZephyrProject_Add(
    APPLICATION ${SB_CONFIG_OTHER_APP_IMAGE_NAME}
    SOURCE_DIR ${SB_CONFIG_OTHER_APP_IMAGE_PATH}
    APP_TYPE MY_CUSTOM_TYPE
  )
endif()
```

最后创建 `share/sysbuild/image_configurations/MY_CUSTOM_TYPE_image_default.cmake`，其中 `ZCMAKE_APPLICATION` 会指向当前正在配置的镜像：

```cmake
# Here, the ZCMAKE_APPLICATION variable will be replaced with the image being configured
set_config_bool(${ZCMAKE_APPLICATION} CONFIG_BUILD_OUTPUT_HEX y)
```

> 译注：第一段中的 `# ...` 表示原文件中省略的其他实现，不能用此短片段覆盖整个函数。注释提到 `-DCONF_FILES`，但通常应用配置参数是 `CONF_FILE`；应按实际源码接口核对，不能只根据示意注释新增变量。若只是某个应用或模块需要共用设置，上一小节追加脚本即可，不必修改全局类型允许列表。

## 2.4\_配置完成后读取结果

镜像完成 CMake 配置之后，Sysbuild 可读取它们的 Kconfig 值，用于检查配置或调整额外任务。函数格式为：

```cmake
sysbuild_get(<variable> IMAGE <image> [VAR <image-variable>] KCONFIG)
```

这里 `<variable>` 是接收结果的 CMake 变量，`IMAGE` 指定镜像，`VAR` 可指定要读取的镜像变量，`KCONFIG` 表示读取 Kconfig 结果。

只能在模块扩展的合适阶段，或 `sysbuild/CMakeLists.txt` 已执行 `find_package(Sysbuild)` 之后调用它。

模块的 **CMake配置后钩子（Post-CMake Hook）**示例：参数解析前缀 `POST_CMAKE` 生成镜像列表变量 `POST_CMAKE_IMAGES`；`message()` 的 `STATUS` 参数把读取结果作为配置状态消息输出。

```cmake
function(${SYSBUILD_CURRENT_MODULE_NAME}_post_cmake)
  cmake_parse_arguments(POST_CMAKE "" "" "IMAGES" ${ARGN})

  foreach(image ${POST_CMAKE_IMAGES})
    # Note that the variable to read in to must not be set before using the sysbuild_get() function
    set(tmp_val)
    sysbuild_get(tmp_val IMAGE ${image} VAR CONFIG_BUILD_OUTPUT_HEX KCONFIG)
    message(STATUS "Image ${image} build hex: ${tmp_val}")
  endforeach()
endfunction()
```

> 原文注意：调用 `sysbuild_get()` 前，接收变量不能已有设置。这里每次循环执行无值的 `set(tmp_val)`，清除临时变量，然后读取当前镜像的 `CONFIG_BUILD_OUTPUT_HEX`，输出其结果。

也可在应用的 `sysbuild/CMakeLists.txt` 中读取默认镜像：

```cmake
find_package(Sysbuild REQUIRED HINTS $ENV{ZEPHYR_BASE})

project(sysbuild LANGUAGES)

sysbuild_get(tmp_val IMAGE ${DEFAULT_IMAGE} VAR CONFIG_BUILD_OUTPUT_HEX KCONFIG)
message(STATUS "Image ${DEFAULT_IMAGE} build hex: ${tmp_val}")
```

> 译注：`ZEPHYR_BASE` 是当前 Zephyr 源码根环境变量；`find_package(Sysbuild)` 建立并配置 Sysbuild 项目及相关镜像后，才能读取结果。`message(STATUS ...)` 是 CMake 配置时的输出，不是设备运行日志。设置阶段与读取阶段不能互换：前者影响镜像配置，后者观察已经形成的配置。
