# 第8章\_Zephyr系统需求规格

原文：[Zephyr System Requirements](https://docs.zephyrproject.org/latest/build/requirements/zephyr_system_requirements.html)。本次读取日期：2026-10-14；基线为保存的 `latest` 页面，HTML 摘要见[来源记录](../SOURCES.md)。

<a id="zephyr-system-requirements"></a>

> 译注：本页是系统需求规格（System Requirements），不是开发主机的安装条件。原文各条需求状态均为草稿（Draft），`shall`在此译为“应”，表示规范要求，不等于该项功能已通过验证。编号、分类、父需求关系和原文顺序均保留；原文将条件变量条目标为非功能性，译文不擅自改类。条目中的定时器等用户故事也按原文保留，不作为具体API已支持某项操作的证明。

<a id="zep-syrs-1-architecture-layer-interface"></a>
<a id="zep-syrs-1"></a>

## 8.1\_ZEP-SYRS-1：架构层接口（Architecture Layer Interface）

Zephyr实时操作系统（Real-time Operating System，RTOS）应提供一个框架，与一组硬件架构服务通信。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | 硬件架构接口（Hardware Architecture Interface） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望能轻松把应用切换到不同的微控制器（Microcontroller Unit，MCU）架构，例如x86、ARM Cortex-M/A、RISCV等。

<a id="zep-syrs-2-support-multiprocessor-management"></a>
<a id="zep-syrs-2"></a>

## 8.2\_ZEP-SYRS-2：支持多处理器管理（Support multiprocessor management）

Zephyr RTOS应支持在多个内核上进行对称多处理（Symmetric Multiprocessing，SMP）。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | 硬件架构接口（Hardware Architecture Interface） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望在多核、支持SMP的MCU／微处理器（Microprocessor Unit，MPU）上使用Zephyr操作系统。

**父需求（Parents）：**[ZEP-SYRS-1](#zep-syrs-1)。

<a id="zep-syrs-3-support-subset-of-standard-c-library"></a>
<a id="zep-syrs-3"></a>

## 8.3\_ZEP-SYRS-3：支持标准C库的子集（Support Subset of Standard C Library）

Zephyr RTOS应支持标准C库（Standard C Library）的一个子集。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | C库（C Library） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望能选择不同的标准C库实现，例如功能完整的实现、占用更小的最小实现，或执行速度特别快的实现。

## 8.4\_ZEP-SYRS-4：设备驱动抽象（Device Driver Abstraction）

Zephyr RTOS应提供管理设备驱动（Device Driver）和外设（Peripheral）的框架。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | 设备驱动（Device Drivers） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望应用能在不同MCU架构（ARM Cortex-M/A、Intel x86、RISCV等）与不同MCU厂商（STM、NXP、Intel等）之间移植，而无须修改对MCU外设的访问。

## 8.7\_ZEP-SYRS-7：中断管理（Interrupt Management）

Zephyr RTOS应提供管理中断（Interrupt）和中断服务程序（Interrupt Service Routine，ISR）的框架。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | 中断（Interrupts） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望内核提供抽象的平台接口，使我无须详细了解平台架构和编程模型，就能实现标准中断的中断服务程序。

<a id="zep-syrs-20-direct-isr-platform-specific-helpers"></a>
<a id="zep-syrs-20"></a>

## 8.8\_ZEP-SYRS-20：直接ISR与平台专用辅助功能（Direct ISR, Platform Specific helpers.）

Zephyr RTOS应通过平台专用代码片段和工厂函数（Factory Function）支持直接ISR（Direct ISR）的开发，包括最小入口指令、最小出口指令、退出低功耗状态以及ISR构造。

| 字段 | 值 |
| --- | --- |
| 状态（Status） | 草稿（Draft） |
| 类型（Type） | 功能性（Functional） |
| 组件（Component） | 中断（Interrupts） |

**用户故事（User Story）：**作为Zephyr RTOS用户，我希望内核支持标准低延迟、低功耗中断服务程序的实现，而无须详细了解平台架构和编程模型。

**父需求（Parents）：**[ZEP-SYRS-7](#zep-syrs-7)。
