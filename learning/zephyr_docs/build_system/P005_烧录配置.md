# 第5章\_烧录配置

原文：[官方页面](https://docs.zephyrproject.org/latest/build/flashing/configuration.html)。本次读取日期：2026-10-14；基线为所保存的 `latest` 页面，HTML摘要见[来源记录](../SOURCES.md)。

Zephyr 支持为**烧录运行器（Flash Runner）**设置配置，以定制编程开发板时各条命令的使用方式。运行器由 [west flash](../west/P007_构建烧录与调试.md)调用。这套配置用于[系统构建（System Build，sysbuild）](../sysbuild/P001_系统构建.md)工程，能够针对一组开发板目标安排命令执行时机。

例如，某个多核**片上系统（System on Chip，SoC）**可能要求所有核心合计只执行一次 `--erase`，防止一次 `west flash` 调用重复擦除，从而错误清除其他待烧录镜像使用的存储区。

## 5.1\_优先级

烧录配置是单一配置，只从一个位置读取。可以存放在以下文件中，按优先级从高到低排列：

1. SoC 目录中的 `soc.yml`。
2. 开发板目录中的 `board.yml`。

> 译注：这不是将两份配置合并；选用高优先级来源后，不应假定低优先级文件仍会补充规则。

## 5.2\_配置

在 YAML 文件中添加 `runners` 映射，并在其下设置一个 `run_once` 子项。子项中再以传给烧录运行器的命令为键，例如 `--reset`；各键的值为设置列表，按运行器和限定符／开发板分组。

每条命令使用 `runners` 列表指定适用的运行器：若适用于全部运行器，可列出 `all`；否则列出各运行器专用名称。`groups` 键的值是开发板目标集合的列表。

开发板目标通过**正则表达式（Regular Expression）**匹配：

- 在 `soc.yml` 中，各组使用 `qualifiers` 键，只能匹配**开发板限定符（Board Qualifier）**，条目中必须省略开发板名称。
- 在 `board.yml` 中，各组使用 `boards` 键，其列表中的匹配项共同构成一组。

最后，`run` 可以设置为 `first` 或 `last`：前者表示每组目标在首个镜像的烧录过程中执行该命令一次；后者表示在该组最后一个镜像的烧录过程中执行一次。

以下 `soc.yml` 示例使使用 nRF5340 应用核或网络核的目标只执行一次 `--recover`；对于网络核和应用核，则分别在各自全部镜像烧录完成后才复位：

```yaml
runners:
  run_once:
    '--recover':
      - run: first
        runners:
          - nrfjprog
        groups:
          - qualifiers:
              - nrf5340/cpunet
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns
    '--reset':
      - run: last
        runners:
          - nrfjprog
          - jlink
        groups:
          - qualifiers:
              - nrf5340/cpunet
          - qualifiers:
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns
      # Made up non-real world example to show how to specify different options for different
      # flash runners
      - run: first
        runners:
          - some_other_runner
        groups:
          - qualifiers:
              - nrf5340/cpunet
          - qualifiers:
              - nrf5340/cpuapp
              - nrf5340/cpuapp/ns
```

> 译注：`--recover` 的一个 `qualifiers` 列表把三个限定符归为一组；`--reset` 的两个列表把网络核与应用核分组，应用核安全／非安全目标属于同组。`some_other_runner` 及其英文注释明确表示虚构示例，只展示不同运行器可选不同执行时机，不是可安装的真实运行器。

## 5.3\_使用方法

烧录非 sysbuild 应用时，运行器支持的命令照常使用，不应用 `run_once` 配置。烧录包含多个镜像的 sysbuild 工程时，才应用运行器的单次执行配置。

例如，为 nrf5340dk 构建 [SMP服务器示例](../firmware_update/P022_SMP服务器示例.md)，其中 MCUboot 作为附加镜像：

```shell
cmake -GNinja -Sshare/sysbuild/ -Bbuild -DBOARD=nrf5340dk/nrf5340/cpuapp -DAPP_DIR=samples/subsys/mgmt/mcumgr/smp_svr
cmake --build build
```

> 译注：这两条命令相对于 Zephyr 源码根目录解析，要求对应工具链与模块已准备好。`-S` 指定 sysbuild 源目录，`-B` 指定构建目录；它们没有指向作者机器上的固定位置。

构建完成并连接 nrf5340dk 后，可用下面的命令烧录两份应用镜像。在烧录首个镜像时，只执行一次设备恢复操作：

```shell
west flash --recover
```

若上述过程没有烧录配置，恢复操作就会执行两次，导致设备无法启动。

> 译注：`--recover` 是原例的设备恢复操作，会影响目标存储内容。本页保留官方操作说明；本次未执行构建、恢复或烧录。
