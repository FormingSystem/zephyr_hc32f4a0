## 2.1\_构建方式的选择

LLEXT子系统允许创建可加载到正在运行的Zephyr应用中的扩展。构建这些扩展时，通常需要取得主Zephyr应用使用的头文件（Headers）和编译器选项（Compiler Flags）。

最简单的方式是使用Zephyr原生CMake功能，将扩展作为Zephyr应用的一部分进行构建。一次构建同时生成主程序和扩展，二者自动使用相同参数。

有些情况下，接入完整Zephyr构建系统不可行或不方便，例如扩展使用另一套编译器，或属于完全不同的项目。此时，扩展开发者需要导出主应用使用的头文件和编译器选项，可以使用LLEXT扩展开发套件（Extension Development Kit，EDK）完成。

<a id="using-the-zephyr-cmake-features"></a>

## 2.2\_使用Zephyr CMake功能

Zephyr构建系统提供一组功能，将扩展纳入应用构建。该方式只需对应用构建系统作少量补充，是构建扩展最简单的方式。

<a id="building-the-extension"></a>

### 构建扩展（Building the Extension）

在应用的`CMakeLists.txt`中调用[`add_llext_target()`](../cmake_reference/P008_extensions.md#command:add-llext-target-target-name-output)，指定目标名称、输出文件和源文件，即可定义扩展。用法类似标准CMake函数[`add_custom_target`](https://cmake.org/cmake/help/latest/command/add_custom_target.html#command:add_custom_target)：

```cmake
add_llext_target(
    <target_name>
    OUTPUT <ext_file.llext>
    SOURCES <src1> [<src2>...]
)
```

参数含义如下：

- `<target_name>`：最终CMake目标（Target）的名称，构建该目标会生成LLEXT二进制文件。
- `<ext_file.llext>`：包含已打包扩展的输出文件名称。
- `<src1> [<src2>...]`：用于编译生成扩展的源文件列表。

扩展构建的具体步骤取决于当前选择的[ELF对象格式](P003_配置扩展.md#elf-object-type)。

`<target_name>`定义以下自定义属性（Custom Properties），可以使用CMake的`get_target_property()`查询：

| 属性 | 含义 |
| --- | --- |
| `lib_target` | 源码编译和／或链接步骤对应的目标名称。 |
| `lib_output` | 编译和／或链接步骤产生的二进制文件。 |
| `pkg_input` | 打包步骤（Packaging Step）的输入文件。 |
| `pkg_output` | 最终扩展文件名称。 |

<a id="tweaking-the-build-process"></a>

### 调整构建过程（Tweaking the Build Process）

以下CMake函数可用于细调扩展构建行为。每个函数的第一个参数都是LLEXT目标名称，其余功能与常用的Zephyr `target_*`版本等价：

- [`llext_compile_definitions()`](../cmake_reference/P008_extensions.md#command:llext-compile-definitions-target-name)。
- [`llext_compile_features()`](../cmake_reference/P008_extensions.md#command:llext-compile-features-target-name)。
- [`llext_compile_options()`](../cmake_reference/P008_extensions.md#command:llext-compile-options-target-name)。
- [`llext_include_directories()`](../cmake_reference/P008_extensions.md#command:llext-include-directories-target-name)。
- [`llext_link_options()`](../cmake_reference/P008_extensions.md#command:llext-link-options-target-name)。

<a id="custom-build-steps"></a>

### 自定义构建步骤（Custom Build Steps）

使用CMake函数`add_llext_command`可以向扩展构建过程添加自定义步骤。命令在指定阶段运行，并可引用目标属性，取得该次构建的具体信息。

函数形式如下：

```cmake
add_llext_command(
    TARGET <target_name>
    [PRE_BUILD | POST_BUILD | POST_PKG]
    COMMAND <command> [args...]
)
```

各阶段含义如下：

| 阶段 | 执行时机与可用信息 |
| --- | --- |
| `PRE_BUILD` | 若架构使用动态库（Dynamic Libraries），在扩展代码链接之前执行。可访问`lib_target`及其属性。 |
| `POST_BUILD` | 扩展代码构建后、打包为`.llext`文件之前执行。此步骤应读取`lib_output`内容，生成`pkg_input`文件。 |
| `POST_PKG` | 扩展输出文件创建后执行。命令可以操作最终扩展文件`pkg_output`。 |

`COMMAND`之后的其他内容会原样传给`add_custom_command()`，包括多条命令和其他选项。

<a id="llext-extension-development-kit-edk"></a>

## 2.3\_LLEXT扩展开发套件（EDK）

在主Zephyr构建系统之外，将扩展作为独立项目构建时，必须取得与主程序相同的一组生成头文件（Generated Headers）和编译器选项。它们直接影响Zephyr头文件的解释方式，以及扩展的整体编译结果。

可以要求Zephyr根据主应用的构建产物生成EDK。通过`llext-edk`目标执行：

译注：下列命令在已配置Zephyr环境的Bash中执行，当前位置应能访问已经配置、构建过的主应用构建目录。

```sh
west build -t llext-edk
```

生成的EDK位于构建目录下的`zephyr`目录中，是一个tar归档包（Tarball），包含构建扩展所需的头文件与编译选项。扩展开发者随后将这些头文件和选项接入自己的构建系统。

<a id="edk-definition-files"></a>

### EDK定义文件（EDK Definition Files）

EDK包含便于使用的定义文件，其中的变量保存项目所需编译选项，以及启用时的其他构建信息。目前提供以下格式：

- `Makefile.cflags`：供基于Makefile的项目使用。
- `cmake.cflags`：供基于CMake的项目使用。

头文件与选项中的路径以EDK根目录为前缀。CMake项目通过`CMAKE_CURRENT_LIST_DIR`自动取得该根目录；其他格式使用`LLEXT_EDK_INSTALL_DIR`变量，用户必须在包含生成文件之前，将它设置为EDK实际安装位置。

> 注意：变量名中的`LLEXT_EDK`前缀可以通过[`CONFIG_LLEXT_EDK_NAME`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_EDK_NAME)更改。

<a id="compile-flags"></a>

### 编译选项（Compile Flags）

`LLEXT_CFLAGS`提供构建扩展所需的完整选项。此外，也提供细分选项集合，以支持其他用途，例如构建单元测试中的模拟实现（Mocks）。

| 变量 | 内容 |
| --- | --- |
| `LLEXT_INCLUDE_CFLAGS` | 将非自动生成头文件所在目录加入编译器包含搜索路径的选项。 |
| `LLEXT_GENERATED_INCLUDE_CFLAGS` | 将自动生成头文件所在目录加入包含搜索路径的选项。 |
| `LLEXT_ALL_INCLUDE_CFLAGS` | 构建所用全部头文件目录的包含选项，由前两组组合而成。 |
| `LLEXT_GENERATED_IMACROS_CFLAGS` | 通过`-imacros`包含必须参与构建的自动生成头文件的选项。 |
| `LLEXT_BASE_CFLAGS` | 控制目标CPU代码生成的其他编译器选项；这些选项不包含在上述集合中。 |
| `LLEXT_CFLAGS` | 构建扩展所需的全部选项，由`LLEXT_ALL_INCLUDE_CFLAGS`、`LLEXT_GENERATED_IMACROS_CFLAGS`和`LLEXT_BASE_CFLAGS`组合而成。 |

<a id="target-information"></a>

### 目标信息（Target Information）

EDK包含用于标识当前Zephyr构建目标的信息。当前定义的变量与Zephyr构建系统中的信息对应：

| 变量 | 内容 |
| --- | --- |
| `LLEXT_EDK_BOARD_NAME` | 构建使用的开发板名称（Board Name）。 |
| `LLEXT_EDK_BOARD_QUALIFIERS` | 构建使用的开发板限定符（Board Qualifiers），如果已提供。 |
| `LLEXT_EDK_BOARD_REVISION` | 构建使用的开发板修订版（Board Revision），如果已提供。 |
| `LLEXT_EDK_BOARD_TARGET` | 构建使用的完整限定开发板目标（Fully Qualified Board Target）。 |

> 注意：这些变量名中的`LLEXT_EDK`前缀也可以通过[`CONFIG_LLEXT_EDK_NAME`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_EDK_NAME)更改。

<a id="llext-edk-kconfig-options"></a>

### LLEXT EDK的Kconfig选项

| 配置项 | 含义 |
| --- | --- |
| [`CONFIG_LLEXT_EDK_NAME`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_EDK_NAME) | 生成的EDK归档包名称，也用于EDK文件中若干变量的前缀。 |
| [`CONFIG_LLEXT_EDK_USERSPACE_ONLY`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_EDK_USERSPACE_ONLY) | 启用时，EDK包含的头文件不含将系统调用（System Calls）路由到内核的代码。适用于完全在用户态（User Mode）运行的扩展。 |
