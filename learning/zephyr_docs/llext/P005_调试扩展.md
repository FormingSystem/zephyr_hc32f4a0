## 5.1\_调试扩展的前提

调试扩展比较复杂。扩展代码没有构建进主Zephyr程序，因此最终Zephyr ELF文件不包含扩展代码的符号（Symbols）。此外，[`llext_load()`](P011_扩展管理API.md#ga0a4c3db30bc3ec7aa8a9b0e076af7157)会在运行时动态重定位（Relocate）扩展；即使已有符号，调试器也无法自行知道这些符号最终位于什么地址。

因此，正确建立调试会话需要一些手动步骤。下面介绍使用Zephyr SDK和west调试功能的方法，也可以将这些说明用于其他基于GDB的调试环境。

<a id="extension-debugging-process"></a>

## 5.2\_扩展调试流程（Extension Debugging Process）

1. 配置项目以显示详细LLEXT调试输出，即启用[`CONFIG_LOG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LOG)和[`CONFIG_LLEXT_LOG_LEVEL_DBG`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_LOG_LEVEL_DBG)。
2. 构建Zephyr应用与扩展。对于本次构建中的每个目标`name`，构建根目录的`llext`子目录会生成两个文件：`name_ext_debug.elf`是带完整调试信息的中间ELF文件；`name.llext`是最终扩展二进制文件，已裁剪为加载到Zephyr应用所需的必要数据。根据目标架构和构建配置，还可能有其他文件。
3. 启动主Zephyr应用的调试会话，方法见官方调试文档。在支持的开发板上，通常运行`west debug`即可，必要时增加参数。
4. 在应用代码中紧接[`llext_load()`](P011_扩展管理API.md#ga0a4c3db30bc3ec7aa8a9b0e076af7157)之后设置断点（Breakpoint），让程序运行到此处。这会完成扩展加载与重定位。日志中会出现`gdb add-symbol-file flags:`，后面跟随若干以`-s`开头的行。
5. 在GDB控制台输入下面的命令，加载该扩展的符号：

```text
add-symbol-file <path-to-debug.elf> <load-addresses>
```

其中`<path-to-debug.elf>`是第2步中带调试信息的ELF文件的完整路径；`<load-addresses>`是上一步日志中全部`-s`行组成的、以空格分隔的列表。

6. 调试器现在可以使用扩展符号，可正常设置断点、检查变量以及单步执行（Single Stepping）。

应用加载多个扩展时，可以对每个扩展重复第4～6步。

> 译注：原文用“完整路径”描述文件参数。GDB也接受相对于其工作目录的文件名，下文示例使用的就是`build/llext/...`。本译文不写入作者机器路径；按自己的工作目录定位文件即可。参见[GDB文件与符号表命令](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Files.html)。

<a id="symbol-lookup-issues"></a>

## 5.3\_符号查找问题（Symbol Lookup Issues）

> 警告：加载的扩展符号很可能被主应用中的符号遮蔽（Shadowing），例如扩展代码位于ELF缓冲区或LLEXT堆占用的内存区域。GDB选择最先知道的符号，因此可能把地址关联到`elf_buffer+0x123`，而不是预期的`ext_fn`。源码单步或局部变量检查等高层操作也会受到影响，因为在错误上下文中这些操作没有意义。

下面讨论两种解决方法。

<a id="discard-all-zephyr-symbols"></a>

### 丢弃全部Zephyr符号（Discard All Zephyr Symbols）

最简单的方式是在上述第5步之前清除GDB中的全部Zephyr应用符号。原文此处写作“不带参数调用`add-symbol-file`”。这样会使调试会话仅聚焦扩展，所有Zephyr应用信息都会丢失，例如调试器可能无法正确追踪扩展代码以外的调用栈。

> 译注：原文命令名写错了。无参数清除符号表的命令是`symbol-file`，不是`add-symbol-file`；下文官方会话记录也实际使用`symbol-file`。该行为已按[GDB官方手册](https://sourceware.org/gdb/current/onlinedocs/gdb.html/Files.html)核对。

可以在同一会话中多次使用这一方法，在主程序与扩展符号表之间切换，但操作很快会变得繁琐。

<a id="edit-the-elf-file"></a>

### 编辑ELF文件（Edit the ELF File）

另一种方式较复杂，但调试体验更连贯：编辑主Zephyr ELF文件，移除与待调试扩展内存区域重叠的符号信息。此后加载扩展符号时，GDB便不会产生歧义。可使用`objcopy`的`-N <symbol>`选项完成。

定位这些符号需要反复尝试，因为可能存在多个层次。例如，ELF缓冲区本身还可能包含在表示数据段（Data Segment）的符号中。对于同一项目，重叠符号列表通常不会频繁变化，因此查明后可重复使用。

<a id="example-debugging-session"></a>

## 5.4\_调试会话示例（Example Debugging Session）

本例在基于ARM Cortex-M3的仿真开发板`mps2/an385`上，调试`tests/subsys/llext`项目中`writable`测试情形的`detached_fn`扩展。

> 注意：下列日志来自Zephyr 4.1和Zephyr SDK 0.17.0。即使版本相同，不同运行中的地址也可能变化，必须根据自己的会话结果调整命令。

以下命令构建项目，并以调试模式启动仿真器。

译注：以下保留官方Linux Bash、QEMU和GDB会话。`zephyr$`与`(gdb)`是提示符，复制命令时不输入提示符或输出日志；各主机终端起点为Zephyr源码根目录。地址、版本、SDK安装示意位置均来自官方历史示例，不是本仓库的固定位置或本次执行结果。

**终端1：构建、QEMU仿真器、GDB服务器。**

```text
zephyr$ west build -p -b mps2/an385 tests/subsys/llext/ -T llext.writable -t debugserver_qemu
-- west build: generating a build system
[...]
-- west build: running target debugserver_qemu
[...]

```

另开终端，将`ZEPHYR_SDK_INSTALL_DIR`设置为实际Zephyr SDK安装目录，然后启动目标对应的GDB客户端。

**终端2：GDB客户端。**

```text
zephyr$ export LLEXT_SDK_INSTALL_DIR=/opt/zephyr-sdk-0.17.0
zephyr$ ${LLEXT_SDK_INSTALL_DIR}/arm-zephyr-eabi/bin/arm-zephyr-eabi-gdb build/zephyr/zephyr.elf
GNU gdb (Zephyr SDK 0.17.0) 12.1
[...]

(gdb)
```

> 译注：原文正文说设置`ZEPHYR_SDK_INSTALL_DIR`，命令却定义和使用`LLEXT_SDK_INSTALL_DIR`。后一变量在此只是示例中的Shell路径变量；`/opt/zephyr-sdk-0.17.0`也是官方安装位置示意，应替换为实际SDK目录。不要要求仓库位于任何固定绝对路径。

连接服务器，在`llext_load`处设置断点，并运行到该函数返回。

### 丢弃符号（Discarding Symbols）

丢弃Zephyr符号、仅保留扩展符号后，可以恢复扩展的完整调试功能，代价是失去全局上下文。注意，下面的调用栈回溯会在扩展之外停止。

**终端2：GDB客户端。**

<a id="editing-the-elf-file"></a>

### 编辑ELF文件（Editing the ELF File）

采用另一种方法时，必须先构建Zephyr二进制文件并在终端1启动仿真器，再修改ELF文件，最后才在终端2启动GDB客户端。

前面的会话已经识别出一个冲突符号：保存ELF文件的字符数组`test_detached_ext`。先移除该符号。多次重复同样步骤后，还能发现`__data_start`和`__data_region_start`也与目标内存区域重叠。

以下命令从Zephyr ELF中移除这些符号，将结果写入另一个ELF文件，再用修改后的文件启动调试会话。

**终端2：GDB客户端。**

```text
zephyr$ export LLEXT_SDK_INSTALL_DIR=/opt/zephyr-sdk-0.17.0
zephyr$ ${LLEXT_SDK_INSTALL_DIR}/arm-zephyr-eabi/bin/arm-zephyr-eabi-objcopy -N test_detached_ext -N __data_start -N __data_region_start build/zephyr/zephyr.elf build/zephyr/zephyr-edit.elf
zephyr$ ${LLEXT_SDK_INSTALL_DIR}/arm-zephyr-eabi/bin/arm-zephyr-eabi-gdb build/zephyr/zephyr-edit.elf
GNU gdb (Zephyr SDK 0.17.0) 12.1
[...]
Reading symbols from build/zephyr/zephyr-edit.elf...
(gdb)
```

可以重复前一次会话中的步骤，连接GDB服务器并加载扩展及调试符号。这次结果有所不同：

- `break`命令输出包含源码行号。
- `backtrace`同时包含扩展和Zephyr应用中的函数。
- 可以正确检查局部变量（Local Variables）。

**终端2：GDB客户端。**
