# 第9章\_模块式扩展示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/subsys/llext/modules/README.html)。本次读取日期：2026-10-14；基线为保存的`latest`页面，HTML摘要见[来源记录](../SOURCES.md)。

<a id="llext-modules"></a>

<a id="overview"></a>

## 9.1\_概述（Overview）

本例演示Zephyr可链接加载扩展（Linkable Loadable Extensions，LLEXT）子系统。LLEXT可以在运行时加载可重定位ELF文件（Relocatable ELF Files），访问其中的符号并调用函数。

具体来说，本例调用[`samples/subsys/llext/modules/src/hello_world_ext.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/subsys/llext/modules/src/hello_world_ext.c)中实现的简单“hello world”函数。根据Kconfig符号`CONFIG_HELLO_WORLD_MODE`的值，采用两种方式：

- 值为`y`时，由Zephyr应用直接编译并调用该函数，调用方代码位于[`samples/subsys/llext/modules/src/main_builtin.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/subsys/llext/modules/src/main_builtin.c)。
- 值为`m`时，将函数编译为LLEXT，以二进制数据块（Binary Blob）包含在应用中。运行时通过LLEXT加载扩展并调用函数，调用方代码位于[`samples/subsys/llext/modules/src/main_module.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/subsys/llext/modules/src/main_module.c)。

<a id="requirements"></a>

## 9.2\_要求（Requirements）

需要架构受LLEXT支持、并带控制台（Console）的开发板。也可以在QEMU仿真的[`qemu_xtensa`](../qemu_catalog_reference/P006_QEMU_Xtensa.md#qemu_xtensa)或[`qemu_cortex_r5`](../qemu_arm_reference/P005_QEMU_Cortex_R5仿真开发板.md#qemu_cortex_r5)虚拟开发板上运行。

<a id="building-and-running"></a>

## 9.3\_构建与运行（Building and Running）

默认情况下，示例将该函数与Zephyr其他代码一起编译进同一二进制文件，可通过以下命令验证。

译注：命令在已配置Zephyr与相应QEMU工具的Bash中执行，当前位置为Zephyr源码根目录。以下保留官方目标与构建选择。

```sh
west build -b qemu_xtensa/dc233c samples/subsys/llext/modules
west build -t run
```

以下命令将扩展代码单独编译，以二进制数据块包含在Zephyr镜像中，然后运行示例：

```sh
west build -b qemu_xtensa/dc233c -T sample.llext.modules.module_build samples/subsys/llext/modules
west build -t run
```

> 重要：此方式需要额外的架构专用配置，见[`samples/subsys/llext/modules/tests.yaml`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/subsys/llext/modules/tests.yaml)。

若要面向其他开发板构建，将上述命令中的[`qemu_xtensa`](../qemu_catalog_reference/P006_QEMU_Xtensa.md#qemu_xtensa)替换为目标开发板名称。

> 译注：命令实际使用完整目标`qemu_xtensa/dc233c`；更换开发板时，应使用新目标的完整名称与限定符，不机械保留`/dc233c`。两种构建模式或目标之间切换时，也应按自己的构建目录状态处理已有CMake缓存。
