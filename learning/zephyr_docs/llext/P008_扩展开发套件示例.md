<a id="index-0"></a>

<a id="overview"></a>

## 8.1\_概述（Overview）

本例演示Zephyr LLEXT扩展开发套件（Extension Development Kit，EDK）的用法。它包含一个Zephyr应用，由应用向加载的扩展提供API。该API是基于Zbus的简单发布／订阅系统（Publish/Subscribe System），供扩展之间通信。

应用包含一个订阅线程（Subscriber Thread），监听发布的事件，再通过Zbus转发给作为订阅者的扩展。应用加载四个扩展，分别在不同上下文中运行。`ext1`、`ext2`和`ext3`在用户空间（Userspace）运行，各自演示不同的应用与Zephyr API用法，例如信号量（Semaphores）、创建线程监听事件，以及发布或订阅事件。`kext1`与`ext3`类似，但运行于内核线程（Kernel Thread）。

应用还为每个扩展创建不同内存域（Memory Domains），提供一定程度的隔离；但内核扩展仍可访问整个Zephyr内核。

只有构建EDK时禁用[`CONFIG_LLEXT_EDK_USERSPACE_ONLY`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_LLEXT_EDK_USERSPACE_ONLY)，内核扩展才可用。

应用通过Zephyr构建系统构建，EDK也通过该系统的`llext-edk`目标生成。随后解压EDK，使用CMake构建各扩展。

最后，应用采用在构建时包含扩展的方式加载它们。这种方式并不十分实用；本例的重点是展示EDK可以让扩展独立于应用构建。扩展可以在与Zephyr应用无关的目录，甚至另一台机器上，仅依靠EDK构建。进一步可以设想，由应用开发者提供EDK，其他团队分别构建扩展。

<a id="building-the-edk"></a>

## 8.2\_构建EDK（Building the EDK）

使用`llext-edk`目标构建EDK，例如：

译注：下列原例使用Linux Bash、`qemu_cortex_r5`目标及已配置的Zephyr环境。第一组命令从Zephyr源码根目录执行；后续`cd`会改变当前目录，执行扩展和应用构建前应分别回到所说明的目录。`/tmp/edk`是官方临时目录示例，不是仓库固定地址，可以改用读者选择的目录并同步后续引用。

```sh
west build -b qemu_cortex_r5 -p=always samples/subsys/llext/edk/app
west build -t llext-edk
```

将EDK复制到一个位置并解压：

```sh
mkdir /tmp/edk
cp build/zephyr/llext-edk.tar.xz /tmp/edk
cd /tmp/edk
tar -xf llext-edk.tar.xz
```

将`LLEXT_EDK_INSTALL_DIR`设置为解压后的目录：

```sh
export LLEXT_EDK_INSTALL_DIR=/tmp/edk/llext-edk
```

扩展使用该变量查找EDK。

<a id="building-the-extensions"></a>

## 8.3\_构建扩展（Building the Extensions）

扩展通过环境变量[`ZEPHYR_SDK_INSTALL_DIR`](../toolchains/P003_环境变量.md)查找Zephyr SDK，必须确认其设置正确：

```sh
export ZEPHYR_SDK_INSTALL_DIR=</path/to/zephyr-sdk>
```

> 译注：`</path/to/zephyr-sdk>`是原文占位符，执行时必须替换为实际SDK安装路径，并去掉尖括号；不可将尖括号形式直接粘贴到Shell中作为命令执行。

分别进入`ext1`、`ext2`、`ext3`和`kext1`目录，构建扩展：

```sh
cmake -B build
make -C build
```

也可以直接在CMake调用中设置`LLEXT_EDK_INSTALL_DIR`：

```sh
cmake -B build -DLLEXT_EDK_INSTALL_DIR=/tmp/edk/llext-edk
make -C build
```

译注：这些目录位于本例源码中。每个扩展在自己的目录内执行命令并生成自己的`build`子目录；`kext1`还受前述EDK用户态选项限制。

<a id="building-the-application"></a>

## 8.4\_构建应用（Building the Application）

现在构建包含这些扩展的应用并运行。执行前回到Zephyr源码根目录：

```sh
west build -b qemu_cortex_r5 -p=always samples/subsys/llext/edk/app
west build -t run
```

应看到类似以下输出：

```text
[app]Subscriber thread [0x20b28] started.
[app]Loading extension [kext1].
[app]Thread 0x20840 created to run extension [kext1], at privileged mode.
[k-ext1]Waiting sem
[app]Thread [0x222a0] registered event [0x223c0]
[k-ext1]Waiting event
[app]Loading extension [ext1].
[app]Thread 0x20a30 created to run extension [ext1], at userspace.
[app]Thread [0x20a30] registered event [0x26060]
[ext1]Waiting event
[app]Loading extension [ext2].
[app]Thread 0x20938 created to run extension [ext2], at userspace.
[ext2]Publishing tick
[app][subscriber_thread]Got channel tick_chan
[ext1]Got event, reading channel
[ext1]Read val: 0
[ext1]Waiting event
[k-ext1]Got event, giving sem
[k-ext1]Got sem, reading channel
[k-ext1]Read val: 0
[k-ext1]Waiting sem
(...)
```

译注：`Subscriber thread started`表示订阅线程启动；`Loading extension`表示加载扩展；`privileged mode`为特权模式；`Waiting sem`和`Waiting event`分别表示等待信号量和事件；`Publishing tick`表示发布tick事件；`Read val`显示读到的值。地址与日志保留官方原样，不要求读者运行结果中的地址完全一致。
