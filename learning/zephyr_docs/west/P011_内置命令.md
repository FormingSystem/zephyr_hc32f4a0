# 第11章\_内置命令

原文：[官方页面](https://docs.zephyrproject.org/latest/develop/west/built-in.html)。本次读取日期：2026-10-14；依据保存的 `latest` 页面，HTML摘要见[来源记录](../SOURCES.md)。

本页详细说明 west 的**内置命令（Built-in Command）**；其中部分已在[基本概念](P002_基本概念.md)介绍。有些命令与同名 Git 命令有关，但作用于整个工作区，例如 `west diff` 显示多个 Git 仓库的本地修改。

部分命令接受项目参数。参数优先按清单中的项目名称解释，也可退而使用本地文件系统中的项目路径。`west list`、`west forall` 等命令接受项目参数；省略时，通常对清单中全部项目以及清单仓库本身操作。详细帮助使用 `west <command> -h`，例如 `west init -h`。

## 11.1\_west init

此命令创建 **west工作区（West Workspace）**，有两种方式：从远端 URL 克隆新清单仓库，或围绕已有本地清单仓库建立工作区。

### 11.1.1\_从远端克隆清单仓库

```shell
west init [-m URL] [--mr REVISION] [--mf FILE] [directory]
```

新工作区位于 `directory`，该目录中创建 `.west`。`-m` 指定清单仓库 URL，`--mr` 指定初次检出的修订，`--mf` 指定仓库内清单文件的位置。例如：

```shell
west init -m https://github.com/zephyrproject-rtos/zephyr --mr v1.14.0 zp
```

该命令将官方上游仓库克隆到 `zp/zephyr`，检出 `v1.14.0`，创建 `zp/.west`，并将[配置项](P003_配置.md) `manifest.path` 设为 `zephyr`，记录清单仓库在工作区中的位置。这里使用默认清单文件位置。

`-m` 默认值为 `https://github.com/zephyrproject-rtos/zephyr`，`--mf` 默认值为 `west.yml`。从 west v0.10.1 起，未用 `--mr` 指定时采用清单仓库的默认分支；更早版本的 `--mr` 默认值为 `master`。省略 `directory` 时使用当前工作目录。

> 译注：版本号是原文历史示例，不是本译文建议的新工程版本。方括号表示可选参数，实际调用时不输入括号。

### 11.1.2\_使用已有本地清单仓库

```shell
west init -l [--mf FILE] directory
```

此方式在 `directory` 的旁边创建 `.west`，并将 `manifest.path` 设置为该清单仓库目录。`--mf` 同样默认为 `west.yml`。

> 译注：这里 `.west` 与已有清单仓库目录是同级关系；该层构成工作区顶层，不是在清单仓库内部再建 `.west`。

### 11.1.3\_重新配置工作区

初始化后可以用 [west config](P003_配置.md) 修改 `manifest.path` 和 `manifest.file`。之后务必运行 `west update`，使工作区与新的清单文件一致。

## 11.2\_west update

```shell
west update [-f {always,smart}] [-k] [-r]
            [--group-filter FILTER] [--stats] [PROJECT ...]
```

### 11.2.1\_哪些项目会更新

默认解析清单文件（通常为 `west.yml`），更新其中列出的项目。使用[项目组](P013_west清单文件.md)时，只更新**活动项目（Active Project）**。

若只更新部分项目，传入一个或多个 `PROJECT`：可以是清单项目名，也可以是指向工作区内项目的路径。明确指定的项目无论是否活动都会更新。

### 11.2.2\_项目更新过程

对每个需更新的项目，依次执行：

1. 如果工作区中没有该项目的本地 Git 仓库，先初始化仓库。
2. 检查清单 `revision`；需要的修订本地不可用时，从远端获取。
3. 将项目的 `manifest-rev` 分支设为该修订指定的提交。
4. 在工作副本中以**分离头指针（Detached HEAD）**检出 `manifest-rev`；设计原因见[工作区](P004_工作区.md)。
5. 若项目声明 `submodules`，按后文规则递归更新 Git 子模块。

为减少不必要的获取，默认 `-f/--fetch smart` 不会重新获取本地已有的提交 SHA 或标签。需要强制获取时，使用 `-f always`，或把 `update.fetch` 设为 `always`。SHA 可用 Git 能接受的唯一前缀表示。

如果 `revision` 是既非标签也非 SHA 的 Git 引用，也就是跟踪分支，则始终执行获取，不受 `-f` 或 `update.fetch` 影响。`deadbeef` 这类分支名可能被当作短 SHA；可写成 `revision: refs/heads/deadbeef` 消除歧义。

为避免改变本地分支，默认通过 `git checkout --detach` 检出清单修订，原先检出的分支会留在原处。这通常不会修改任何本地分支。但如果在此前由 west 检出的分离 HEAD 上添加本地提交，Git 会警告这些提交已不被任何分支引用，今后可能被**垃圾回收（Garbage Collection）**并丢失。因此，有本地提交时，应在 `west update` 前确保它们位于已检出的本地分支上。

需要对已检出的本地分支执行**变基（Rebase）**，使用 `-r/--rebase`。希望当本地分支提交是新 `manifest-rev` 的后代时仍保持检出该分支，使用 `-k/--keep-descendants`。

**原文注意：**`--rebase` 遇到本地分支与清单新提交之间的 Git 冲突会失败，应按通常 Git 流程立即解决；也可用 `git -C <project_path> rebase --abort` 暂时取消这次变基。对干净工作树，普通 `west update` 不试图保留正在检出的本地提交，而是将其留在一旁，因此原文称它“不会失败”。`--keep-descendants` 是中间方案，原文也称其“不会失败”：分支已分叉的项目不尝试变基，像普通更新一样留下原分支；不需要变基或合并的项目则保留当前分支。

> 译注：“不会失败”仅描述这里的分支处理策略，不排除网络、权限、磁盘或仓库损坏等错误。`<project_path>` 是实际项目路径占位符。此处没有执行更新或变基。

### 11.2.3\_单次项目组调整

`--group-filter` 只在本次 `west update` 中调整项目组启用／禁用状态，其效果相当于将参数值追加到配置项 `manifest.group-filter` 后。

例如，`west update --group-filter=+foo,-bar` 等价于暂时把 `+foo,-bar` 追加到该配置，运行更新，再恢复原配置。只禁用单组时，采用 `--group-filter=-bar` 这样的等号形式，而不是将值拆成独立参数，可避免以短横线开头的值被误解析为选项。

### 11.2.4\_Git子模块更新过程

若项目配置 `submodules: true`，先在该项目中同步子模块配置：

```shell
git submodule sync --recursive
```

然后根据 `west update` 是否指定 `--rebase`，选择对应命令：

```shell
# without --rebase, e.g. "west update":
git submodule update --init --checkout --recursive

# with --rebase, e.g. "west update --rebase":
git submodule update --init --rebase --recursive
```

若配置为 `submodules: <list-of-submodules>`，则针对清单列出的子模块同步：

```shell
git submodule sync --recursive -- <submodule-path>
```

再根据是否使用 `--rebase`，更新列表中的每个子模块：

```shell
# without --rebase, e.g. "west update":
git submodule update --init --checkout --recursive <submodule-path>

# with --rebase, e.g. "west update --rebase":
git submodule update --init --rebase --recursive <submodule-path>
```

当 `update.sync-submodules` 为 `false` 时，跳过上述 `git submodule sync` 命令。

## 11.3\_其他项目命令

以下命令管理工作区内项目；详情见 `west <command> -h`。

| 命令 | 作用 |
| --- | --- |
| `west compare` | 比较工作区状态与清单。 |
| `west diff` | 在本地项目仓库运行 `git diff`。 |
| `west forall` | 在本地项目仓库执行任意命令。 |
| `west grep` | 在本地项目仓库搜索模式。 |
| `west list` | 按格式字符串为清单中每个项目打印一行信息。 |
| `west manifest` | 管理清单文件，详见[west清单文件](P013_west清单文件.md)。 |
| `west status` | 在本地项目仓库运行 `git status`。 |

## 11.4\_其他内置命令

| 命令 | 作用 |
| --- | --- |
| `west config` | 读取或设置[配置选项](P003_配置.md)。 |
| `west topdir` | 打印工作区顶层目录。 |
| `west help` | 获取某个命令帮助，或打印工作区全部命令的信息，包括[扩展命令](P012_扩展命令机制.md)。 |

**原文脚注：**以 SHA 指定修订时，west 可能从 Git 服务器获取全部引用，因为历史上部分服务器不允许直接按 SHA 获取。
