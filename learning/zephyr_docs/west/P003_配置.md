# 第3章\_west配置

原文：[Configuration](https://docs.zephyrproject.org/latest/develop/west/config.html)。读取日期：2026-10-12，`latest`。

本页说明 west 配置文件系统、`west config` 命令和内置命令的配置项。`west.configuration` Python 模块的接口说明见 [West APIs](https://docs.zephyrproject.org/latest/develop/west/west-apis.html)。

## 3.1\_配置文件

west 配置文件采用类似 INI 的语法：

```ini
[manifest]
path = zephyr

[zephyr]
base = zephyr
```

上例的 `manifest` 节中，`path` 选项为 `zephyr`，也可以表述为 `manifest.path` 的值是 `zephyr`。

配置文件分为三类：

| 层级 | 作用范围 | 位置 |
| --- | --- | --- |
| System，系统级 | 计算机上所有用户 | Linux：`/etc/westconfig`；macOS：`/usr/local/etc/westconfig`；Windows：`%PROGRAMDATA%\west\config` |
| Global，用户级 | 当前用户运行的 west | 默认是用户主目录中的 `.westconfig` |
| Local，工作区级 | 当前工作区 | 相对于工作区根目录的 `.west/config` |

Linux 上，如果设置了 `XDG_CONFIG_HOME`，用户级配置改用 `$XDG_CONFIG_HOME/west/config`。Windows 确定用户主目录时，依次检查 `%HOME%`、`%USERPROFILE%`，再检查 `%HOMEDRIVE%` 与 `%HOMEPATH%` 的组合。

后面的层级覆盖前面的层级。例如系统级 `color.ui=true`，工作区级 `color.ui=false`，最终值为 `false`；用户级同样覆盖系统级。

## 3.2\_west config命令

内置 `config` 命令用于读取和设置值。`--system`、`--global`、`--local` 分别选择配置文件，一次只能指定一个。不指定时，写操作默认写入工作区本地配置；读操作返回应用覆盖规则后的最终值。

详细帮助运行 `west config -h`。以下示例在已有 west 工作区内、能运行 west 的终端执行，彼此是独立操作。

将 `manifest.path` 改为 `some-other-manifest`：

```text
west config manifest.path some-other-manifest
```

这会让 `west update` 等命令从工作区根目录下的 `some-other-manifest` 查找清单，而不是原来传给 `west init` 的仓库目录，因此需谨慎。

读取 `zephyr.base`：

```text
west config zephyr.base
```

该值同样相对于工作区根目录；如果调用环境没有设置 `ZEPHYR_BASE`，west 将使用它作为该环境变量的值。

可以保持 `manifest.path` 不变，仅切换供构建使用的 Zephyr 仓库：

```text
west config zephyr.base some-other-zephyr
```

例如使用 `git worktree` 创建了其他 Zephyr 目录，想让 `west build` 使用它，同时保留 `west update` 原有行为时，这很有用。运行 `west config zephyr.base zephyr` 可切回上游清单中的通常路径。

在用户级配置关闭所有工作区的彩色输出：

```text
west config --global color.ui false
```

要撤销这一效果，原文给出：

```text
west config --global color.ui true
```

> 译注：最后一条是显式设置为 true，不是删除用户级选项。前面的 `some-other-manifest`、`some-other-zephyr` 都是示例目录名，必须对应实际存在且有效的仓库；这些不是本项目要求新增的目录。

## 3.3\_内置配置选项

下表覆盖原文列出的全部内置选项。Zephyr 扩展的配置项在相应扩展命令页面中说明。

| 选项 | 类型、默认值及作用 |
| --- | --- |
| `alias.ALIAS` | 字符串；非空时，可把 `<ALIAS>` 作为 west 命令使用，见 [West aliases](https://docs.zephyrproject.org/latest/develop/west/alias.html) |
| `color.ui` | 布尔值，默认 true；标准输出连接终端时显示彩色输出 |
| `commands.allow_extensions` | 布尔值，默认 true；false 时禁用扩展 |
| `grep.color` | 字符串，默认空；设为 `never` 可禁用 `west grep` 彩色输出，非空时传给底层 grep 工具的 `--color` |
| `grep.tool` | `git-grep`（默认）、`ripgrep` 或 `grep`，指定搜索工具 |
| `grep.<TOOL>-args` | 字符串，默认空；`<TOOL>` 可为任一种 grep.tool 值，如 `grep.ripgrep-args`，指定传给该工具的参数；详见 `west help grep` |
| `grep.<TOOL>-path` | 字符串，默认空；指定对应工具路径，不再通过命令搜索查找；例如 `grep.ripgrep-path` |
| `manifest.file` | 字符串，默认 `west.yml`；清单文件相对于清单仓库根的路径，供 init 及其他解析清单的命令使用 |
| `manifest.group-filter` | 字符串，默认空；逗号分隔的项目组列表，`+` 启用、`-` 禁用，例如 `+foo,-bar`；见[项目组](https://docs.zephyrproject.org/latest/develop/west/manifest.html#project-groups) |
| `manifest.path` | 字符串；清单仓库相对于工作区根的路径，由 `west init` 在本地设置，供 update 等命令使用 |
| `manifest.project-filter` | 逗号分隔的带正负前缀的正则表达式，按项目名称控制启用状态；规则详见下节 |
| `update.auto-cache` | 非空字符串在命令行没有 `--auto-cache` 时作为该参数的默认值 |
| `update.fetch` | `smart` 或 `always`；从 v0.6.1 起默认 smart。smart 对本地已有的 SHA 或标签跳过远程获取，always 无条件获取 |
| `update.name-cache` | 非空字符串在命令行没有 `--name-cache` 时作为该参数的默认值 |
| `update.narrow` | 布尔值，默认 false；true 时相当于给 update 指定 `--narrow` |
| `update.path-cache` | 非空字符串在命令行没有 `--path-cache` 时作为该参数的默认值 |
| `update.sync-submodules` | 布尔值，默认 true；更新 Git 子模块之前先同步子模块配置 |
| `zephyr.base` | 字符串；west 运行时设置 `ZEPHYR_BASE` 的默认值。init 通常把它设为路径为 zephyr 的清单项目位置；已有同名环境变量时忽略该设置，除非 base-prefer 为 configfile |
| `zephyr.base-prefer` | `env`（默认）或 `configfile`；env 让调用环境中的 ZEPHYR_BASE 优先，configfile 让配置值优先 |

## 3.4\_按项目名称过滤

`manifest.project-filter` 的值是逗号分隔的正则表达式，每项以 `+` 或 `-` 开头，例如：

```text
+re1,-re2,-re3
```

按列表顺序，用完整项目名匹配每个表达式。匹配项以 `-` 开头则禁用，以 `+` 开头则启用；同时匹配多个表达式时，最后一个决定结果。

使用此选项时，项目名称不能包含逗号，因此表达式无须匹配字面逗号。例如：

```text
-hal_.*,+hal_foo
```

会禁用 `hal_bar`，但启用 `hal_foo`。

如果项目已经由本列表明确启用或禁用，其结果不受所属项目组是否禁用影响。这也是当前禁用“没有所属组的项目”的唯一方式。没有匹配任何表达式时，继续按通常的项目组规则判断，见[项目组示例](https://docs.zephyrproject.org/latest/develop/west/manifest.html)。

每一项的首尾空白会被忽略，所以以下等价：

```text
+foo,-bar
+foo , -bar
```

空项也会被忽略，所以以下等价：

```text
+foo,,-bar
+foo,-bar
```
