# 第5章\_west故障排查

原文：[Troubleshooting West](https://docs.zephyrproject.org/latest/develop/west/troubleshooting.html)。读取日期：2026-10-12，`latest`。本页介绍常见问题及其解决方法。

## 5.1\_west update获取失败

一种有效的排查方法是启用详细输出。在已确认的工作区内执行：

```text
west -v update
```

输出会包含 west 调用的 Git 命令及其结果。寻找类似日志：

```text
=== updating your_project (path/to/your/project):
west.manifest: your_project: checking if cloned
[...other west.manifest logs...]
--- your_project: fetching, need revision SOME_SHA
west.manifest: running 'git fetch ... https://github.com/your-username/your_project ...' in <项目目录>
```

最后一行的 `git fetch` 是需要成功的实际操作。可以进入对应项目目录，复制完整的 fetch 命令单独运行，再依据凭据助手的文档继续定位问题。

如果处于企业防火墙之后，可能涉及代理等问题；对 HTTPS URL 使用 `curl -v FETCH_URL`，或对 SSH 场景使用 `ssh -v FETCH_URL`，可能有帮助。

同一 shell 中，若 Git fetch 单独执行时可以成功且无须再次输入密码，则 west update 也应能在不重复输入的情况下工作。

> 译注：日志中的省略号和 FETCH_URL 是说明占位符，`<项目目录>` 代替原文的机器路径示例；排错时使用真实日志中的完整参数。SSH 诊断须按照实际 SSH 主机地址和参数形式调用，不能把一个 HTTPS URL 原样交给 ssh。

## 5.2\_Windows提示无法识别west命令

错误形如：

```text
'west' is not recognized as an internal or external command, operable program or batch file.
```

这表示 west 未安装，或者 `PATH` 不包含 pip 安装 `west.exe` 的目录。

先确认完成[安装 west](P001_安装west.md)，再打开新的 cmd.exe 尝试。仍失败时，查找 `west.exe` 所在目录并加入 `PATH`。通常 Python 与 pip 安装过程已处理路径，所以一般无须手动执行以下修复。

在 cmd.exe 执行：

```bat
pip3 show west
```

1. 在输出中寻找 `Location:` 行，确定该 Python 安装中的 `lib\site-packages` 目录。
2. 从同一个 Python 安装根目录进入相对路径 `scripts`，寻找 `west.exe`。注意，是把结果末尾的 `lib\site-packages` 换成 `scripts`。
3. 如果确实存在，把实际 scripts 路径加入 PATH。以下将原文的机器路径参数化为 `WEST_SCRIPTS_DIR` 环境变量；先依据上一步结果设置此变量，再对照命令：

```bat
setx PATH "%PATH%;%WEST_SCRIPTS_DIR%"
```

不要直接复制此命令；实际 scripts 路径必须来自自己的安装结果。完成后关闭 cmd.exe，重新打开再运行 west。

> 译注：这里将原文固定盘符与 Python 版本目录改为按安装结果定位，`WEST_SCRIPTS_DIR` 是本页新增的路径变量。已采用虚拟环境时，首先检查是否激活了正确环境，而不是把其他环境的 scripts 永久加到全局路径。原文的 setx 命令会持久写 PATH，不能在未核对现有值时机械执行；变量未设置时不要执行。

## 5.3\_invalid choice: build或flash

执行 Zephyr 扩展时，可能出现：

```text
$ west build [...]
west: error: argument <command>: invalid choice: 'build' (choose from 'init', [...])

$ west flash [...]
west: error: argument <command>: invalid choice: 'flash' (choose from 'init', [...])
```

最可能的原因是在工作区外运行。west 需要先找到工作区，才能发现扩展命令。

有两种解决方式：

1. 在工作区内运行。例如把构建目录放入工作区，或者在工作区中执行 `west flash --build-dir YOUR_BUILD_DIR`。
2. 设置 `ZEPHYR_BASE` 环境变量，然后重新执行扩展命令。west 会使用它查找工作区。

不能确定一个命令是内置还是扩展时，在工作区中运行 `west help`。扩展会单独列出，上游 Zephyr 的输出类似：

```text
$ west help

built-in commands for managing git repositories:
  init:                 create a west workspace
  [...]

other built-in commands:
  help:                 get help for west or a command
  [...]

extension commands from project manifest (path: zephyr):
  build:                compile a Zephyr application
  flash:                flash and run a binary on a board
  [...]
```

## 5.4\_invalid choice: post-init

如果 `west init` 报错：

```text
west: error: argument <command>: invalid choice: 'post-init'
(choose from 'init', 'update', 'list', 'manifest', 'diff',
'status', 'forall', 'config', 'selfupdate', 'help')
```

说明安装的 west 很旧，而目标工作区需要较新版本。

原文给出的恢复步骤是：

1. 按安装说明，用 `pip3 install` 的 `-U` 选项更新 west。
2. 备份 `zephyrproject/.west/config` 中希望保留的配置；未设置任何配置时可跳过备份。
3. 完全移除 `zephyrproject/.west`，否则原文指出可能遇到“already in a workspace”。
4. 再次运行 `west init`。

> 译注：本节是针对旧版 west 的特定历史故障的原文恢复方案，不是一般初始化错误的通用处理方法。先核对 west 版本、工作区位置与配置，避免为绕过“already initialized”而删除仍在使用的 `.west`。
