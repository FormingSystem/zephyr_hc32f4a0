# 第2章\_west基本概念

原文：[Basics](https://docs.zephyrproject.org/latest/develop/west/basics.html)。读取日期：2026-10-12，`latest`。

本页介绍 west 的基本概念，并给出深入阅读入口。west 内置命令允许你在共同的工作区目录下管理多个项目，也就是多个 Git 仓库。

工作过程如下：`west init` 创建工作区并克隆清单仓库；`west update` 根据清单，首次克隆其余项目，并在后续更新它们。

## 2.1\_工作区示例

完成官方入门指南之后，本地工作区可能如下。这里的工作区包括 `zephyrproject` 目录及其所有子目录：

```text
zephyrproject/                 # 工作区顶层目录 topdir
├── .west/                     # 标识顶层目录的位置
│   └── config                 # 当前工作区的本地配置文件
│
│   # 清单仓库；west 创建它之后，不再修改其内容：
├── zephyr/                    # 包含 .git 的仓库
│   ├── west.yml               # 清单文件
│   └── [... other files ...]
│
│   # 由 west 管理的项目：
├── modules/
│   └── lib/
│       └── zcbor/             # 包含 .git 的项目仓库
├── tools/
│   └── net-tools/             # 包含 .git 的项目仓库
└── [ ... other projects ...]
```

> 译注：这是官方示例布局，目录由初始化和更新过程产生。已有工作区以实际 `.west/config` 为准，不必将工程重命名成 `zephyrproject`。

## 2.2\_工作区中的概念

**顶层目录（topdir）：** 示例中的 `zephyrproject` 是工作区顶层目录。名称可以任意选择，例如 `z` 或 `my-zephyr-workspace`。通常通过 `west init` 创建顶层目录及相关文件。

**`.west` 目录：** 顶层目录包含 `.west`。west 通过寻找它并取其父目录来确定 topdir；搜索从当前工作目录开始，如果失败，则以环境变量 `ZEPHYR_BASE` 指定的位置为后备起点重新搜索。

**配置文件：** `.west/config` 是当前工作区的本地配置文件。

**清单仓库（manifest repository）：** 每个工作区恰好有一个清单仓库，它是包含清单文件的 Git 仓库。位置由本地配置中的 `manifest.path` 指定。

上游 Zephyr 使用 `zephyr` 作为清单仓库，但工作区中的任何 Git 仓库都可以承担这一角色，只要包含有效清单文件。其他布局见[工作区拓扑](https://docs.zephyrproject.org/latest/develop/west/workspaces.html)，格式见 [West Manifests](https://docs.zephyrproject.org/latest/develop/west/manifest.html)。

**清单文件（manifest file）：** YAML 文件，用于定义由 west 管理的其他 Git 仓库。默认文件名为 `west.yml`，可以通过本地选项 `manifest.file` 覆盖。执行 `west update` 时，west 按文件内容更新工作区项目。

**项目（projects）：** 由 west 管理的 Git 仓库，在清单中定义，可以放在工作区内部任何位置。示例中的 `zcbor`、`net-tools` 都是项目。

Zephyr 构建系统默认通过 west 查询各项目的位置，使其中的代码能够作为模块使用。但 west 项目与 Zephyr 模块是不同概念，不能混同。

**扩展（extensions）：** west 已知的任何仓库，包括清单仓库和项目仓库，都可以定义附加 west 命令。Zephyr 仓库用这一机制提供 `west build` 等命令，从而使 west 核心不必了解各工作区使用的 Zephyr 版本细节。

**被忽略的文件：** 工作区还可放入不受 west 管理的 Git 仓库、文件和目录。除 `.west`、清单仓库和清单列出的项目外，west 基本上忽略其他内容。

## 2.3\_west init与west update

这是与工作区有关的两个最重要命令。

### 2.3.1\_west init的基本行为

`west init` 创建工作区。初始化之后，west 不修改清单仓库内容；需要拉取新版本等操作时，应使用普通 Git 命令。

通常只运行一次，例如：

```bash
# 新工作区的父目录；以下是官方旧版本演示，不用于重复初始化已有工作区。
west init -m https://github.com/zephyrproject-rtos/zephyr --mr v2.5.0 zephyrproject
```

它会：

1. 创建顶层目录 `zephyrproject`，以及其中的 `.west`、`.west/config`。
2. 从给定 URL 克隆清单仓库，放到 `zephyrproject/zephyr`。
3. 在该仓库检出 Git 标签 `v2.5.0`。
4. 在 `.west/config` 中设置 `manifest.path=zephyr`。
5. 将 `manifest.file` 设为 `west.yml`。

之后还需要运行 `west update` 克隆其余项目，工作区才完整。更多选项见[内置命令的 west init](https://docs.zephyrproject.org/latest/develop/west/built-in.html#west-init)。

> 译注：`v2.5.0` 是原文演示标签，不是本集对应的 latest 版本，也不是当前项目的版本选择建议。已有工作区时跳过初始化；不能因“already initialized”删除 `.west`。

### 2.3.2\_west update的基本行为

`west update` 确保工作区中的 Git 仓库与清单项目匹配。清单仓库切换到不同修订之后，应运行它，使项目仓库满足新修订的要求。

读取清单的过程是：

1. 找到顶层目录，在前例中即 `zephyrproject`。
2. 读取其中的 `.west/config`，取得 `manifest.path` 与 `manifest.file`，例如 `zephyr` 和 `west.yml`。
3. 打开两者共同确定的清单，例如 `zephyrproject/zephyr/west.yml`。

随后，west 根据清单决定缺失项目放在哪里、从哪个 URL 克隆、检出哪个 Git 修订。已经存在的项目在原位置获取并检出清单要求的修订。

详情见[内置命令的 west update](https://docs.zephyrproject.org/latest/develop/west/built-in.html#west-update)。
