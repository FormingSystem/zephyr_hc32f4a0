# 第12章\_扩展命令机制

原文：[官方页面](https://docs.zephyrproject.org/latest/develop/west/extensions.html)。本次读取日期：2026-10-14；依据保存的 `latest` 页面，HTML摘要见[来源记录](../SOURCES.md)。

West 具有**可插拔性（Pluggability）**：不修改 west 本身的源码，也能加入自定义命令。这类命令称为 **west扩展命令（West Extension Command）**，简称扩展。`west --help` 会按定义它们的项目分节显示。本页介绍扩展机制，并演示如何编写自己的扩展。

[构建、烧录与调试](P007_构建烧录与调试.md)命令及[其他Zephyr扩展命令](P008_其他Zephyr扩展命令.md)都属于此类，因此帮助输出类似：

```console
extension commands from project manifest (path: zephyr):
  completion:           display shell completion scripts
  boards:               display information about supported boards
  shields:              display list of supported shields
  build:                compile a Zephyr application
  twister:              west twister wrapper
  sign:                 sign a Zephyr binary for bootloader chain-loading
  flash:                flash and run a binary on a board
  debug:                flash and interactively debug a Zephyr application
  debugserver:          connect to board and launch a debug server
  attach:               interactively debug a board
  ...
```

上面的说明依次涉及补全脚本、开发板信息、扩展板列表、应用构建、Twister包装、引导链签名、烧录运行、交互调试、调试服务器以及连接已有目标调试。实现位于工作区的 `zephyr/scripts/west-commands.yml` 和 `zephyr/scripts/west_commands`；本仓库的相对源码入口为[命令声明](../../../scripts/west-commands.yml)与[命令实现目录](../../../scripts/west_commands)。

> 译注：这些源码链接便于跟踪实现；本仓库参照源码与所读取的官方 `latest` 不保证同版本。

## 12.1\_禁用扩展命令

将[配置项](P003_配置.md) `commands.allow_extensions` 设置为 `false` 可禁用扩展支持。若要对当前用户所有 west 调用设置，执行：

```shell
west config --global commands.allow_extensions false
```

此后可针对某个工作区重新启用：

```shell
west config --local commands.allow_extensions true
```

除非显式执行相应命令，否则 west 不会导入包含扩展实现的 Python 文件。后文说明具体原因。

## 12.2\_添加west扩展

添加扩展需要三步：编写实现代码；在 `west-commands.yml` 中声明信息；确保[west清单](P013_west清单文件.md)引用该声明文件。

**原文注意：**与内置命令同名的扩展会被忽略。

### 12.2.1\_第一步：实现命令

创建一个 Python 文件，实现扩展命令。当前支持的 Python 版本见 [west的PyPI元数据](https://pypi.org/project/west/)。文件可以放在清单跟踪的任意项目中，也可以放在清单仓库本身；其中必须定义 `west.commands.WestCommand` 的子类，运行扩展时会实例化并使用该类。

以下骨架包含子类及全部抽象方法的实现。更多可用接口见 [West APIs](https://docs.zephyrproject.org/latest/develop/west/west-apis.html)：

```python
'''my_west_extension.py

Basic example of a west extension.'''

from textwrap import dedent            # just for nicer code indentation

from west.commands import WestCommand  # your extension must subclass this

class MyCommand(WestCommand):

    def __init__(self):
        super().__init__(
            'my-command-name',  # gets stored as self.name
            '', # ignored self.help, will not be required by future west versions
            # self.description:
            description=dedent('''
            A multi-line description of my-command.

            You can split this up into multiple paragraphs and they'll get
            reflowed for you. You can also pass
            formatter_class=argparse.RawDescriptionHelpFormatter when calling
            parser_adder.add_parser() below if you want to keep your line
            endings.'''))

    def do_add_parser(self, parser_adder):
        # This is a bit of boilerplate, which allows you full control over the
        # type of argparse handling you want. The "parser_adder" argument is
        # the return value of an argparse.ArgumentParser.add_subparsers() call.
        parser = parser_adder.add_parser(self.name,
                                         description=self.description)

        # Add some example options using the standard argparse module API.
        parser.add_argument('-o', '--optional', help='an optional argument')
        parser.add_argument('required', help='a required argument')

        return parser           # gets stored as self.parser

    def do_run(self, args, unknown):
        # This gets called when the user runs the command, e.g.:
        #
        #   $ west my-command-name -o FOO BAR
        #   --optional is FOO
        #   required is BAR
        self.inf('--optional is', args.optional)
        self.inf('required is', args.required)
```

代码中的英文注释说明：`dedent` 用来改善多行字符串缩进；命令名称存入 `self.name`，当前 `help` 参数被忽略，后续版本将不再要求它；详细说明可含多个段落，默认重排换行，也可在创建解析器时传入 `argparse.RawDescriptionHelpFormatter` 保持原始换行。

`do_add_parser()` 的 `parser_adder` 是 `ArgumentParser.add_subparsers()` 的返回对象。通过标准 `argparse` 接口添加可选参数 `-o/--optional` 和必选位置参数 `required`，返回的解析器存入 `self.parser`。执行 `west my-command-name -o FOO BAR` 时，`do_run()` 输出两个解析结果。

通常可以忽略 `do_run()` 第二个参数 `unknown`，因为 `WestCommand` 默认拒绝未知参数。若希望接收未知参数列表，在 `super().__init__()` 中加入 `accepts_unknown_args=True`。

### 12.2.2\_第二步：添加或更新west-commands.yml

在项目中添加声明文件，向 west 描述扩展。假设上述类位于项目根目录 `my_west_extension.py`：

```yaml
west-commands:
  - file: my_west_extension.py
    commands:
      - name: my-command-name
        class: MyCommand
        help: one-line help for what my-command-name does
```

YAML 顶层是带 `west-commands` 键的**映射（Mapping）**；键值是**命令描述符（Command Descriptor）**序列。每项指定实现扩展的文件，以及扩展名称；实现类名可选，省略 `class` 时默认与 `name` 相同。

其中部分信息与 Python 定义重复，这是有意设计：west 直到用户运行 `west my-command-name` 才导入实现文件，原因有两个。

1. 用户可以用来自不可信来源的清单运行 `west update`，然后使用其他 west 命令，而不会途中导入该扩展代码。导入 Python 模块可能产生与执行 shell 同等的效果，因此延迟导入有助于控制代码执行时机。
2. 只有真正需要时才导入，也是一项小幅性能优化。

因此，未显式运行扩展时，west 只加载 YAML 声明，取得 `west --help` 等需要的基本信息。

若有多个扩展或分布在多个文件中，可写成：

```yaml
west-commands:
  - file: my_west_extension.py
    commands:
      - name: my-command-name
        class: MyCommand
        help: one-line help for what my-command-name does
  - file: another_file.py
    commands:
      - name: command2
        help: another cool west extension
      - name: a-third-command
        class: ThirdCommand
        help: a third command in the same file as command2
```

这里，`my_west_extension.py` 用类 `MyCommand` 实现 `my-command-name`；`another_file.py` 包含两个扩展：`command2` 的类名同为 `command2`，`a-third-command` 的类名为 `ThirdCommand`。

声明文件的**模式（Schema）**见 west 仓库中的 [west-commands-schema.yml](https://github.com/zephyrproject-rtos/west/blob/main/src/west/west-commands-schema.yml)。

### 12.2.3\_第三步：更新清单

最后，在清单中指出声明文件位置。若扩展位于普通项目中：

```yaml
manifest:
   # [... other contents ...]

   projects:
     - name: your-project
       west-commands: path/to/west-commands.yml
     # [... other projects ...]
```

`path/to/west-commands.yml` 相对于该项目根目录。`west-commands.yml` 是官方建议遵循的惯例名称，也可以按需要使用其他文件名。

若扩展在清单仓库中，则在 `self` 下声明：

```yaml
manifest:
  # [... other contents ...]

  self:
    west-commands: path/to/west-commands.yml
```

至此即可运行 `west my-command-name`。`west --help` 也会显示命令名、简短帮助和实现所在项目。将更新后的仓库分享给其他使用者，他们也能使用该命令。

> 译注：以上为官方扩展编写示例；本次翻译未修改用户级配置、安装依赖或执行扩展。源码和声明的相对位置由项目自身决定，不依赖作者的盘符。
