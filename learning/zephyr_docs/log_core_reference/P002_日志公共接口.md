## 2.4\_限速日志（Rate-limited Logging）

限速版本会丢弃重复消息，防止频繁执行的调用位置淹没日志。

每个调用位置独立限速，并使用原子操作保证线程安全；恢复日志输出时，会输出被跳过消息数量的摘要。普通限速版本使用默认间隔 `LOG_RATELIMIT_INTERVAL_MS`，后缀为 `_RATE` 的版本接受显式间隔。

<a id="r_gad3e63ad7a53287eb99a2bd2a1b58dc0e"></a>


相关声明：[LOG_RATELIMIT_INTERVAL_MS](#gad3e63ad7a53287eb99a2bd2a1b58dc0e)。

## 2.12\_详细说明（Detailed Documentation）

### `LOG_DBG`

```c
#define LOG_DBG ( ...)
```

```c
#include <zephyr/logging/log.h>
```

展开值（Value）：

```c
Z_LOG(LOG_LEVEL_DBG, __VA_ARGS__)
```

向日志写入一条 DEBUG 调试级别消息。

用于写入面向开发者的信息。

**参数（Parameters）**

### `LOG_MODULE_DECLARE`



声明日志模块的宏，不执行注册。

一个模块若拆分在多个文件中，必须恰好由其中一个文件使用 `LOG_MODULE_REGISTER()`，以创建模块专有状态并向日志核心注册模块。

- `LOG_MODULE_DECLARE(foo)`

说明（Note）：只有当前源文件的 `LOG_LEVEL` 非零，或者未定义 `LOG_LEVEL` 且 `CONFIG_LOG_DEFAULT_LEVEL` 非零时，才声明模块状态。其他情况下，此宏不产生作用。

另见（See Also）：`LOG_MODULE_REGISTER`。

### `LOG_MODULE_REGISTER`

```c
#define LOG_MODULE_REGISTER ( ...)
```

```c

```

展开值（Value）：

```c

        Z_DO_LOG_MODULE_REGISTER(__VA_ARGS__),                  \
        (_LOG_MODULE_DATA_CREATE(GET_ARG_N(1, __VA_ARGS__),     \
                              _LOG_LEVEL_RESOLVE(__VA_ARGS__))),\
        () \
)                                                                       \
```

宏接受一个或两个参数：

- 模块名称。

使用示例：

- `LOG_MODULE_REGISTER(foo, CONFIG_FOO_LOG_LEVEL)`
- `LOG_MODULE_REGISTER(foo)`

说明（Note）：只有当前源文件的 `LOG_LEVEL` 非零，或者未定义 `LOG_LEVEL` 且 `CONFIG_LOG_DEFAULT_LEVEL` 非零时，才定义模块状态并注册模块。其他情况下，此宏不产生作用。

## 2.13\_源码定位与版本边界

源码定位：[include/zephyr/logging/log.h](../../../include/zephyr/logging/log.h)、[include/zephyr/logging/log_core.h](../../../include/zephyr/logging/log_core.h)、[include/zephyr/logging/log_instance.h](../../../include/zephyr/logging/log_instance.h)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码与已译页面采用相对链接；未构建固件或验证串口、网络等日志输出后端。

> 译注——源码核对：模块（Module）、实例（Instance）、日志源（Source）、日志域（Domain）和输出后端（Backend）不是同一个对象。LOG_MODULE_REGISTER创建并注册模块状态，跨文件模块的其他文件用LOG_MODULE_DECLARE引用同一状态；实例日志通过自己的对象实现独立过滤，不能在每个文件中重复注册同一模块。

> 译注——源码核对：编译期过滤（Compile-time Filtering）可以使日志调用不进入产生日志的路径。运行时提高过滤级别不会恢复已经编译掉的调用，也不保证某个后端已经激活；模块级别与后端过滤需分别满足。

> 译注——源码核对：LOG_WRN_ONCE在每个宏展开位置保存静态原子状态，以比较交换控制首次执行；它不是按消息字符串全局去重，也不是每个线程各输出一次。首次执行经过该状态判断后，仍需经过日志自身过滤。

> 译注——源码核对：限速宏在各调用位置维护独立的上次时间和跳过计数，用原子操作协调并发调用。被限速的重复消息被丢弃，不会保存到一个以后逐条重放的队列；恢复输出时的Skipped %d messages表示“跳过了%d条消息”，代码中的原始格式串保留。

> 译注——源码核对：默认间隔以毫秒表示，CONFIG_LOG_RATELIMIT关闭时LOG_RATELIMIT_INTERVAL_MS为0。显式_RATE接口的参数也使用毫秒，不是每秒允许条数。限速策略与日志缓冲区容量、后端吞吐和线程调度是不同限制。

> 译注——源码核对：LOG_PRINTK与LOG_RAW仍经过日志基础设施，延后处理模式下不能据宏名推断已经同步输出到终端。LOG_RAW要求不额外添加颜色或换行，调用者若需要换行应在原字符串中明确提供。

> 译注——源码核对：十六进制转储接口的_str参数在官方说明中要求为persistent raw string，意为生命周期持续有效的原始说明字符串，不是要求写入持久存储。不要把临时栈上马上失效的字符串当作满足该契约。

> 译注——源码核对：实例指针字段在关闭日志时仍可能保留占位声明，以保持源代码可编译；这不代表运行时存在同样可用的日志实例。对象命名由模块名与实例名组合，声明、定义和结构初始化需使用对应宏。
