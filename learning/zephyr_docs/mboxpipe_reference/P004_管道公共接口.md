## 4.4\_详细说明（Detailed Documentation）

<a id="gac2256aa00c59e78199be9bdefd61aa52"></a>

### `K_PIPE_DEFINE`

```c
#define K_PIPE_DEFINE ( name, pipe_buffer_size, pipe_align )
```

```c
#include <zephyr/kernel.h>
```

展开值（Value）：

```c
static unsigned char __noinit __aligned(pipe_align)             \
        _k_pipe_buf_##name[pipe_buffer_size];                   \
STRUCT_SECTION_ITERABLE(k_pipe, name) =                         \
        Z_PIPE_INITIALIZER(name, _k_pipe_buf_##name, pipe_buffer_size)
```

静态定义并初始化一个管道。

可使用以下声明，在定义管道的模块之外访问它：

原始示例（Example）：

```c
extern struct k_pipe <name>;
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 管道名称。 |
| `pipe_buffer_size` | 管道环形缓冲区（Ring Buffer）的大小，以字节为单位；不使用环形缓冲区时为0。 |
| `pipe_align` | 管道环形缓冲区的对齐值，必须是2的幂。 |

> 译注——源码核对：宏同时定义环形缓冲区和管道对象，初始标志为打开（Open）。容量为0表示不缓存字节，不表示关闭；extern示例中的<name>是占位符。

<a id="ga83d4b5de8902845850d01b0c3db0702a"></a>

### `k_pipe_close()`

```c
void k_pipe_close ( struct k_pipe * pipe)
```

```c
#include <zephyr/kernel.h>
```

关闭管道。

本例程关闭管道。所有在该管道上阻塞的线程都会解除阻塞并收到错误码。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pipe` | 管道的地址。 |

> 译注——源码核对：当前实现清除标志并唤醒等待者，不释放或清空环形缓冲区。后续写入会遇到-EPIPE；读取会先消耗残留数据，已有读取进展时可以返回正数，因此原文所说“被解除阻塞的线程收到错误码”不能无条件套到每个读线程。这里没有单独open接口；重新初始化前必须先结束旧操作并协调对象生命周期。

<a id="gae2c8d97af1f7e9deb93e670859525cf3"></a>

### `k_pipe_init()`

```c
void k_pipe_init ( struct k_pipe * pipe, uint8_t * buffer, size_t buffer_size )
```

```c
#include <zephyr/kernel.h>
```

初始化管道。

本例程在管道对象首次使用之前初始化它。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pipe` | 管道的地址。 |
| `buffer` | 管道缓冲区的地址；不使用环形缓冲区时传NULL。 |
| `buffer_size` | 管道缓冲区大小；不使用环形缓冲区时为0。 |

> 译注——源码核对：当前实现初始化环形缓冲区、读写等待队列、计数和锁，并设置PIPE_FLAG_OPEN。非零容量时调用者负责提供足够的缓冲区并保持其生命周期；无缓冲区使用NULL与0。此函数不能用于并发活动尚未停止时的强制重置。

<a id="gaecb07412025d9e065ee7b99121522257"></a>

### `k_pipe_read()`

```c
int k_pipe_read ( struct k_pipe * pipe, uint8_t * data, size_t len, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

从管道读取数据。本例程从pipe读取最多len字节的数据。

管道为空时，本例程会阻塞，直到可以读取数据或等待超时。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pipe` | 管道的地址。 |
| `data` | 保存从管道读取的数据的地址。 |
| `len` | 请求读取的字节数。 |
| `timeout` | 等待读取数据的时间。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 成功时返回读取的字节数。 |
| `-EAGAIN` | 等待超时前未能读取任何数据。 |
| `-ECANCELED` | 读取被k_pipe_reset(..)中断。 |
| `-EPIPE` | 管道已关闭。 |
| `-EOVERFLOW` | len大于INT_MAX。 |

> 译注——源码核对：“最多len字节”不表示拿到第一个字节就一定返回。当前实现累计读取，未满len时继续等待到原截止时间；K_FOREVER可一直等到读满，或关闭／重置等事件发生。K_NO_WAIT或超时时已有进展则返回实际字节数，无进展才返回-EAGAIN。关闭后仍先读取环形缓冲区残留内容，有数据可返回正数，耗尽后才返回-EPIPE。重置可能在输出缓冲区已写入部分字节后返回-ECANCELED，应用不能把该错误等同于从未移动数据。

<a id="gaaedff72169127b8227c80bf8adf1f9dd"></a>

### `k_pipe_reset()`

```c
void k_pipe_reset ( struct k_pipe * pipe)
```

```c
#include <zephyr/kernel.h>
```

重置管道。本例程重置管道，丢弃所有未读数据，并解除等待写入或读取的线程的阻塞，使这些等待线程返回-ECANCELED。

管道正在重置但尚未完成时，调用k_pipe_read(..)或k_pipe_write(..)会返回-ECANCELED。重置后管道保持打开，可以正常使用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pipe` | 管道的地址。 |

> 译注——源码核对：当前实现先清空环形缓冲区；有等待者时设置PIPE_FLAG_RESET并唤醒读写等待队列，直到最后一个原等待者恢复并清除此标志。函数返回不等于所有等待者都已运行完；这段期间新读写仍可能返回-ECANCELED。原文“保持打开”适用于原本打开的管道：reset并未设置PIPE_FLAG_OPEN，已经close的管道不会因此重新打开。清空不会擦除底层字节，也不撤销之前已直接复制给接收者的数据。

<a id="ga514ab3d174dcada766ecbda138944ddc"></a>

### `k_pipe_write()`

```c
int k_pipe_write ( struct k_pipe * pipe, const uint8_t * data, size_t len, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

向管道写入数据。

本例程向pipe写入最多len字节的数据。管道已满时，本例程会阻塞，直到可以写入数据或等待超时。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `pipe` | 管道的地址。 |
| `data` | 待写入数据的地址。 |
| `len` | 数据大小，以字节为单位。 |
| `timeout` | 等待写入数据的时间。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `>=0` | 成功时返回写入的字节数。 |
| `-EAGAIN` | 等待超时前未能写入任何数据。 |
| `-ECANCELED` | 写入被k_pipe_reset(..)中断。 |
| `-EPIPE` | 管道已关闭。 |
| `-EOVERFLOW` | len大于INT_MAX。 |

> 译注——源码核对：当前实现尝试累计写满len，并以sys_timepoint_calc形成一次调用的截止时间；多轮等待不会每次重新获得完整timeout。K_NO_WAIT或超时时，已写入部分字节则返回该数量，完全无进展才返回-EAGAIN。重置会返回-ECANCELED；关闭后写入返回-EPIPE，这些错误可能发生在已有部分字节交付之后，不会回滚已交付内容。源数据须在调用完成前保持有效且不被并发改写。

## 4.5\_源码定位与版本边界

> 译注——阅读与源码边界：配合[管道指南](../kernel/P017_管道.md)阅读。管道是字节流（Byte Stream），一次读写不自动建立应用消息边界；当前接口返回实际字节数，不能与旧版put／get签名混用。关闭、重置、超时及部分进展的结果不同。

> 译注——直接复制的配置条件：当前pipe.c在管道为空、存在等待者且未启用CONFIG_KERNEL_COHERENCE时，可直接把写入数据复制到等待读线程的缓冲区；启用该配置则改为唤醒读者并走环形缓冲区路径。不能把无缓冲区的直接传递机制无条件推广到所有配置。直接复制不等于转交源指针所有权，读写缓冲区都应保持到调用完成。

仓库相对定位：[kernel.h](../../../include/zephyr/kernel.h)、[kernel/mailbox.c](../../../kernel/mailbox.c)与[kernel/pipe.c](../../../kernel/pipe.c)。本次依据为[官方内核头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/kernel.h)、[官方邮箱实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/mailbox.c)及[官方管道实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/pipe.c)，摘要见[来源记录](../SOURCES.md)。

仓库源码、滚动更新的main和latest网页不能自动视为同一版本。本批完成文档与源码核对，未构建或执行并发传输、超时、关闭及实板实验。
