### `sys_trace_named_event`

```c
#define sys_trace_named_event ( name, arg0, arg1 )
```

```c
#include <zephyr/tracing/tracing.h>
```

由用户调用以生成命名事件（Named Events）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 事件名称；跟踪子系统（Tracing Subsystems）可能限制此字符串的长度 |
| `arg0` | 用户为此事件提供的任意数据 |
| `arg1` | 用户为此事件提供的任意数据 |

> 译注——源码核对：本页保留官方跟踪接口约定，源码核对另列为译注。钩子声明不证明当前配置一定生成事件；实际输出取决于调用点、配置及后端。钩子通常在原上下文直接执行，不能假定由独立工作线程异步处理。

> 译注——源码核对：Enter、Exit及调度相关名称表示标记位置，不保证所有分支成对出现，也不自动证明应用处理或硬件传输已经完成。参数中的对象指针、整数标识和返回码需按实际签名与调用点区分。

> 译注——源码核对：命名事件（Named Events）是应用主动添加的事件，name标识事件名称，arg0和arg1是应用定义的数据。它们不会自动获得线程同步、数据结构序列化或业务成功判定的含义，数据解释应与采集端约定一致。

> 译注——源码核对：本页以宏形式展示接口；当前tracing.h在未选格式的分支提供空宏，而SystemView和CTF后端实际实现为函数。tracing_hooks.h特意不再用通用回退覆盖该函数式公共API。不要自行把这一接口改成sys_port_trace_*名称。

> 译注——源码核对：本次SystemView和CTF函数的两个数据参数类型均为uint32_t；“任意数据”不表示能无损传递任意大小的对象或64位指针。SystemView编码字符串时使用NAMED_EVENT_MAXSTR上限，CTF复制到有界字符串并保证末尾为零；名称可能被截短，不能假定任意长名称仍可唯一识别。

> 译注——源码核对：本次译注以来源记录中的官方源码摘要为界，仓库文件均采用相对路径定位；未配置跟踪设备、运行网络采集或测量事件时序。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
