> 译注——源码核对：本页保留官方跟踪接口约定，源码核对另列为译注。钩子声明不证明当前配置一定生成事件；实际输出取决于调用点、配置及后端。钩子通常在原上下文直接执行，不能假定由独立工作线程异步处理。

> 译注——源码核对：Enter、Exit及调度相关名称表示标记位置，不保证所有分支成对出现，也不自动证明应用处理或硬件传输已经完成。参数中的对象指针、整数标识和返回码需按实际签名与调用点区分。

> 译注——源码核对：这里的socket通常是整数文件描述符（File Descriptor），不是内核对象地址。sockets.c的多项失败路径向跟踪出口传入-errno，而应用API返回-1并设置errno；分析时不能把跟踪ret逐字当成应用实际得到的返回值。发送／接收成功时ret通常是字节数，不能统一当成0成功的状态码。

> 译注——源码核对：accept_enter记录监听描述符，accept_exit的socket参数在本次实现中传入new_sock，即新建连接描述符；成功时ret为0，失败时ret为-errno。不能要求入口和出口socket值相同，也不能把出口ret当作新描述符。socketpair出口分别记录两个描述符，失败分支传入-1、-1及-errno。

> 译注——源码核对：sendto入口带长度、标志和目标地址，但没有数据缓冲区指针；recvfrom入口的地址参数是输出位置，在操作成功前不能解释成已经确定的对端地址。getsockopt出口的optval及optlen也必须结合ret判断有效性。指针参数不等于跟踪后端已经复制其全部内容。

> 译注——源码核对：本次close钩子位置在本地INET套接字实现中，不能凭这一个实现推断所有卸载后端都产生相同事件。socket对象包装由CONFIG_TRACING_NET_SOCKETS控制，而socketpair使用普通函数包装；应检查实际调用方式与所选后端，不只检查某个配置符号。

> 译注——源码核对：本次译注以来源记录中的官方源码摘要为界，仓库文件均采用相对路径定位；未配置跟踪设备、运行网络采集或测量事件时序。
