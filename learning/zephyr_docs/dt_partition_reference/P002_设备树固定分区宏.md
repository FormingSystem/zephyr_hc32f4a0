## 2.2\_详细说明（Detailed Documentation）

<a id="gac8be7ec2cddde3f76f0f096bd3c63546"></a>

### `DT_FIXED_PARTITION_ADDR`

```c
#define DT_FIXED_PARTITION_ADDR ( node_id)
```

```c
#include <zephyr/devicetree/fixed-partitions.h>
```

展开值（Value）：

```c
(DT_REG_ADDR(node_id) + DT_REG_ADDR(DT_GPARENT(node_id)))
```

取得固定分区的绝对地址。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
&flash_controller {
        flash@1000000 {
                compatible = "soc-nv-flash";
                partitions {
                        compatible = "fixed-partitions";
                        storage_partition: partition@3a000 {
                                label = "storage";
                        };
                };
        };
};
```

这里，"storage"分区属于起始地址为0x1000000的闪存。分区的单元地址0x3a000表示该闪存内部的偏移（Offset）。

用法示例：

原始示例（Example）：

```c
DT_FIXED_PARTITION_ADDR(DT_NODELABEL(storage_partition)) // 0x103a000
```

此宏只能用于CPU能够寻址的内部存储器中的分区。否则可能产生编译期错误，例如：'__REG_IDX_0_VAL_ADDRESS' undeclared（未声明）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | fixed-partitions子节点的节点标识符。 |

返回（Returns）：分区偏移加上包含它的闪存节点基地址（Base Address）。

> 译注——源码核对：固定地址原例缺项：flash@1000000和partition@3a000的节点名不能替代reg属性，所列片段没有给出计算地址必需的reg及完整单元布局。若补齐对应基址与偏移，0x1000000 + 0x3a000才得到注释中的0x103a000；不能将原片段直接视为完整可编译DTS。

<a id="ga444fa975d314c342268a6d211627c3d1"></a>

### `DT_FIXED_SUBPARTITION_ADDR`

```c
#define DT_FIXED_SUBPARTITION_ADDR ( node_id)
```

```c
#include <zephyr/devicetree/fixed-partitions.h>
```

展开值（Value）：

```c
(DT_REG_ADDR(node_id) + DT_REG_ADDR(DT_GPARENT(DT_PARENT(node_id))))
```

取得固定子分区的绝对地址。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
&flash_controller {
        flash@1000000 {
                compatible = "soc-nv-flash";

                partitions {
                        compatible = "fixed-partitions";

                        slot0_partition: partition@10000 {
                                compatible = "fixed-subpartitions";
                                reg = <0x00010000 0x40000>;
                                ranges = <0x0 0x10000 0x40000>;
                                #address-cells = <1>;
                                #size-cells = <1>;

                                storage_partition: partition@0 {
                                        label = "storage";
                                        reg = <0x00000000 0x40000>;
                                };
                        };
                };
        };
};
```

这里，"storage"分区属于起始地址为0x1000000的闪存。分区的单元地址0x10000表示该闪存内部的偏移。

用法示例：

原始示例（Example）：

```c
DT_FIXED_SUBPARTITION_ADDR(DT_NODELABEL(storage_partition)) // 0x1010000
```

此宏只能用于CPU能够寻址的内部存储器中的子分区。否则可能产生编译期错误，例如：'__REG_IDX_0_VAL_ADDRESS' undeclared（未声明）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | fixed-subpartitions子节点的节点标识符。 |

返回（Returns）：子分区偏移加上包含它的闪存节点基地址。

> 译注——源码核对：子分区原例：storage节点实际是partition@0，0x10000是外层slot0_partition的偏移，原说明将其称作storage的单元地址不准确。slot0的ranges先把子分区地址0映射到闪存内偏移0x10000，SUBPARTITION_ADDR再加flash基址0x1000000；不是简单把子节点reg的原始0当作最终偏移。片段仍缺flash的reg及若干上下文，需要补齐。

## 2.3\_源码定位与版本边界

本册收录设备树分区宏及头文件，涵盖通用分区、固定分区、固定子分区和映射分区。相对源码定位：[通用分区头文件](../../../include/zephyr/devicetree/partitions.h)、[固定分区头文件](../../../include/zephyr/devicetree/fixed-partitions.h)、[映射分区头文件](../../../include/zephyr/devicetree/mapped-partition.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[地址解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：label属性与节点标签：这里的label指label = "image-0"这样的字符串属性，宏实参写作image_0；它不同于slot0_partition:这样的节点标签。原示例注释分别表示“boot_partition的节点标识符”和“slot0_partition的节点标识符”。查得节点不代表设备驱动已启用或分区可读写。

> 译注——源码核对：编号范围：生成器write_partition_data对三类分区使用同一个从0递增的flash_area_num，按生成时的节点遍历顺序赋值，也会为符合结构条件的禁用节点分配编号。ID不是闪存偏移、DTS单元地址、运行时设备索引或稳定存储格式；修改设备树后不应假定原编号保持不变。

> 译注——源码核对：固定分区层级：常见结构为flash节点→fixed-partitions容器→分区，宏用祖父节点定位flash。MEM版本只有在该节点兼容soc-nv-flash时才返回它，否则为DT_INVALID_NODE；MTD版本在内部flash情形返回flash的父控制器，在其他情形返回该祖父存储设备。子分区系列按再深一层的固定结构处理，不是任意祖先搜索。

> 译注——源码核对：版本边界：本次三个分区头文件、gen_defines.py与edtlib.py登记摘要；源码浏览页的非注释代码与对应原始头文件核对一致。滚动main和本仓库参照基线不自动视为同版本；本批未编译DTS、构建固件或执行擦写、分区修改及硬件实验。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
