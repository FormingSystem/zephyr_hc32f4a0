## 5.2\_详细说明（Detailed Documentation）

<a id="ga71223c8a3d42a59b07052a7a1043aeaa"></a>

### `DT_HAS_MAPPED_PARTITION_LABEL`

```c
#define DT_HAS_MAPPED_PARTITION_LABEL ( label)
```

```c
#include <zephyr/devicetree/mapped-partition.h>
```

展开值（Value）：

```c
IS_ENABLED(DT_CAT3(DT_COMPAT_zephyr_mapped_partition_LABEL_, label, _EXISTS))
```

检查是否存在具有给定label属性值的映射分区。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `label` | 以小写加下划线形式表示的label属性值。 |

返回（Returns）：若设备具有zephyr,mapped-partition兼容字符串，则为1，否则为0。

> 译注——源码核对：本宏的输入是label标记，实际检查生成的标签表_EXISTS。原返回说明只描述节点兼容性，没有准确表达按label查表的条件。

<a id="ga677f55ce5ad2e0519f699d8867f36aa1"></a>

### `DT_MAPPED_PARTITION_ADDR`

```c
#define DT_MAPPED_PARTITION_ADDR ( node_id)
```

```c
#include <zephyr/devicetree/mapped-partition.h>
```

展开值（Value）：

```c
DT_REG_ADDR(node_id)
```

取得映射分区的绝对地址。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
 flash@1000000 {
    compatible = "soc-nv-flash";
    reg = <0x1000000 0x30000>;
    ranges = <0x0 0x1000000 0x30000>;

    partitions {
            ranges;

            storage_partition: partition@3a000 {
                    compatible = "zephyr,mapped-partition";
                    label = "storage";
                    reg = <0x3a000 0x8000>;
            };
    };
 };
```

这里，"storage"分区属于起始地址为0x1000000的闪存。分区地址0x3a000表示该闪存内部的偏移。

用法示例：

原始示例（Example）：

```c
DT_MAPPED_PARTITION_ADDR(DT_NODELABEL(storage_partition)) // 0x103a000
```

此宏只能用于CPU能够寻址的内部存储器中的分区。否则可能产生编译期错误，例如：'__REG_IDX_0_VAL_ADDRESS' undeclared（未声明）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | zephyr,mapped-partition节点的节点标识符。 |

返回（Returns）：分区的单元地址（Unit Address）。

> 译注——源码核对：映射地址原例越界：flash的reg和ranges长度均为0x30000，而分区起点为0x3a000，已经不在该ranges覆盖区间内；分区长度0x8000还使末端达到0x42000。解析器_translate只翻译命中范围的地址，未命中则保留原值，因此所列范围不能推出注释中的0x103a000或预期偏移0x3a000。应依据真实容量修正存储器与映射长度或移动分区，保留原分区布局时至少要覆盖0x42000，并补齐#address-cells／#size-cells上下文。原代码保留，不声称此片段已通过构建。

### `DT_MAPPED_PARTITION_OFFSET`

```c

```

```c

```


设备树（Devicetree）片段示例：

原始示例（Example）：

```dts

    compatible = "soc-nv-flash";
    reg = <0x1000000 0x30000>;
    ranges = <0x0 0x1000000 0x30000>;

    partitions {
            ranges;

            storage_partition: partition@3a000 {
                    compatible = "zephyr,mapped-partition";
                    label = "storage";
                    reg = <0x3a000 0x8000>;
            };
    };
 };
```

这里，"storage"分区属于起始地址为0x1000000的闪存。分区地址0x3a000表示该闪存内部的偏移。

用法示例：

原始示例（Example）：

```c
DT_MAPPED_PARTITION_OFFSET(DT_NODELABEL(storage_partition)) // 0x3a000
```

此宏只能用于CPU能够寻址的内部存储器中的分区。否则可能产生编译期错误，例如：'__REG_IDX_0_VAL_ADDRESS' undeclared（未声明）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | zephyr,mapped-partition节点的节点标识符。 |

返回（Returns）：分区相对于存储设备的偏移。

> 译注——源码核对：映射地址原例越界：flash的reg和ranges长度均为0x30000，而分区起点为0x3a000，已经不在该ranges覆盖区间内；分区长度0x8000还使末端达到0x42000。解析器_translate只翻译命中范围的地址，未命中则保留原值，因此所列范围不能推出注释中的0x103a000或预期偏移0x3a000。应依据真实容量修正存储器与映射长度或移动分区，保留原分区布局时至少要覆盖0x42000，并补齐#address-cells／#size-cells上下文。原代码保留，不声称此片段已通过构建。

## 5.3\_源码定位与版本边界

本册收录设备树分区宏及头文件，涵盖通用分区、固定分区、固定子分区和映射分区。相对源码定位：[通用分区头文件](../../../include/zephyr/devicetree/partitions.h)、[固定分区头文件](../../../include/zephyr/devicetree/fixed-partitions.h)、[映射分区头文件](../../../include/zephyr/devicetree/mapped-partition.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[地址解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：label属性与节点标签：这里的label指label = "image-0"这样的字符串属性，宏实参写作image_0；它不同于slot0_partition:这样的节点标签。原示例注释分别表示“boot_partition的节点标识符”和“slot0_partition的节点标识符”。查得节点不代表设备驱动已启用或分区可读写。

> 译注——源码核对：编号范围：生成器write_partition_data对三类分区使用同一个从0递增的flash_area_num，按生成时的节点遍历顺序赋值，也会为符合结构条件的禁用节点分配编号。ID不是闪存偏移、DTS单元地址、运行时设备索引或稳定存储格式；修改设备树后不应假定原编号保持不变。

> 译注——源码核对：映射与偏移：MAPPED_PARTITION_ADDR直接读取DT_REG_ADDR，依赖ranges把分区地址翻译到CPU地址空间；MAPPED_PARTITION_OFFSET再减去所属NVM节点的地址。空ranges表示继续按同一地址空间向上翻译，缺少ranges则会停止该层翻译，二者不能互换。

> 译注——源码核对：NVM归属：生成器为zephyr,mapped-partition逐级向上寻找最近的soc-nv-flash祖先，并生成_NVM_DEVICE；找不到时生成器报错，不能把MEM宏的DT_INVALID_NODE分支当作整个生成过程都容忍缺少存储器。MTD宏返回该NVM节点的父节点，不额外查询某个已初始化的驱动对象。

> 译注——源码核对：版本边界：本次三个分区头文件、gen_defines.py与edtlib.py登记摘要；源码浏览页的非注释代码与对应原始头文件核对一致。滚动main和本仓库参照基线不自动视为同版本；本批未编译DTS、构建固件或执行擦写、分区修改及硬件实验。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
