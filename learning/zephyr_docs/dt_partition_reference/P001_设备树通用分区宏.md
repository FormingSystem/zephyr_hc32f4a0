## 1.2\_详细说明（Detailed Documentation）

<a id="ga4adb41991a8b796ea2f308673c51ff5f"></a>

### `DT_HAS_PARTITION_LABEL`

```c
#define DT_HAS_PARTITION_LABEL ( label)
```

```c
#include <zephyr/devicetree/partitions.h>
```

展开值（Value）：

```c
UTIL_OR(DT_HAS_MAPPED_PARTITION_LABEL(label), DT_HAS_FIXED_PARTITION_LABEL(label))
```

检查是否存在具有给定label属性值的分区。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `label` | 以小写加下划线形式表示的label属性值。 |

返回（Returns）：若设备具有"zephyr,mapped-partition"或"fixed-subpartitions"兼容字符串，或其父节点具有"fixed-partitions"兼容字符串，则为1，否则为0。

> 译注——源码核对：标签查找优先级：DT_NODE_BY_PARTITION_LABEL先查映射分区label，再回退到固定分区label；两种标签表都没有时不会自动返回一个可用节点。HAS_PARTITION_LABEL实际检查这两张label表，原返回说明却描述了节点兼容性，不能按该段文字把label参数换成节点标识。生成器只为fixed-partitions的直接子节点和zephyr,mapped-partition节点生成这些label表，不能推定普通fixed-subpartitions子节点也有相同查找项。

<a id="gac233d3cdead6e500937911460518d9d4"></a>

### `DT_MEM_FROM_PARTITION`

```c
#define DT_MEM_FROM_PARTITION ( node_id)
```

```c
#include <zephyr/devicetree/partitions.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_NODE_HAS_COMPAT(node_id, zephyr_mapped_partition),       \
            (DT_MEM_FROM_MAPPED_PARTITION(node_id)),                    \
            (DT_MEM_FROM_FIXED_PARTITION(node_id)))
```

取得分区所在非易失性存储器（Non-Volatile Memory，NVM）的节点标识符。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 分区节点的节点标识符。 |

返回（Returns）：包含该分区节点的内部存储器节点标识符；若不存在，则为DT_INVALID_NODE。

### `DT_PARTITION_ADDR`

```c
#define DT_PARTITION_ADDR ( node_id)
```

```c
#include <zephyr/devicetree/partitions.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_NODE_HAS_COMPAT(node_id, zephyr_mapped_partition),       \
            (DT_MAPPED_PARTITION_ADDR(node_id)),                        \
            (DT_FIXED_PARTITION_ADDR(node_id)))
```

取得分区的绝对地址（Absolute Address）。此宏只能用于CPU能够寻址的内部存储器中的分区。

否则可能产生编译期错误（Compile-time Error），例如：'__REG_IDX_0_VAL_ADDRESS' undeclared（未声明）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 分区节点的节点标识符。 |

返回（Returns）：分区的单元地址（Unit Address）。

> 译注——源码核对：地址含义：DT_PARTITION_ADDR返回对应实现计算的CPU地址。原返回段称“分区单元地址”过于简略；固定分区通常需要偏移加闪存基址，映射分区使用已经经ranges翻译的DT_REG_ADDR。这里的绝对地址属于CPU存储地址空间，与文档路径无关。

<a id="gaaa77bff50edd953502a952620b3568ed"></a>

### `DT_PARTITION_EXISTS`

```c
#define DT_PARTITION_EXISTS ( node_id)
```

```c
#include <zephyr/devicetree/partitions.h>
```

展开值（Value）：

```c
UTIL_OR(DT_MAPPED_PARTITION_EXISTS(node_id),            \
        UTIL_OR(DT_FIXED_PARTITION_EXISTS(node_id),     \
                DT_FIXED_SUBPARTITION_EXISTS(node_id)))
```

检查是否存在兼容字符串（Compatible）为"zephyr,mapped-partition"、"fixed-partitions"或"fixed-subpartitions"的节点。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 要检查的DTS节点。 |

返回（Returns）：若节点存在且具有"zephyr,mapped-partition"或"fixed-subpartitions"兼容字符串，或其父节点具有"fixed-partitions"兼容字符串，则为1，否则为0。

> 译注——源码核对：检查对象：DT_FIXED_PARTITION_EXISTS检查传入节点的父节点是否兼容fixed-partitions，DT_FIXED_SUBPARTITION_EXISTS检查父节点是否兼容fixed-subpartitions；不是检查传入节点本身具有这两个兼容字符串。映射分区版本才检查节点本身的zephyr,mapped-partition。通用EXISTS按这三种结果取或，不检查status或运行时设备就绪。原返回说明中的节点归属有歧义，以所列宏展开为准。

## 1.3\_源码定位与版本边界

本册收录设备树分区宏及头文件，涵盖通用分区、固定分区、固定子分区和映射分区。相对源码定位：[通用分区头文件](../../../include/zephyr/devicetree/partitions.h)、[固定分区头文件](../../../include/zephyr/devicetree/fixed-partitions.h)、[映射分区头文件](../../../include/zephyr/devicetree/mapped-partition.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[地址解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：label属性与节点标签：这里的label指label = "image-0"这样的字符串属性，宏实参写作image_0；它不同于slot0_partition:这样的节点标签。原示例注释分别表示“boot_partition的节点标识符”和“slot0_partition的节点标识符”。查得节点不代表设备驱动已启用或分区可读写。

> 译注——源码核对：编号范围：生成器write_partition_data对三类分区使用同一个从0递增的flash_area_num，按生成时的节点遍历顺序赋值，也会为符合结构条件的禁用节点分配编号。ID不是闪存偏移、DTS单元地址、运行时设备索引或稳定存储格式；修改设备树后不应假定原编号保持不变。

> 译注——源码核对：通用接口的子分区边界：DT_PARTITION_EXISTS包含子分区检查，DT_PARTITION_ID复用各节点的_PARTITION_ID；但本次DT_MEM_FROM_PARTITION、DT_MTD_FROM_PARTITION和DT_PARTITION_ADDR仅在映射分区与普通固定分区之间选择，没有单独转到FIXED_SUBPARTITION版本。对位于fixed-subpartitions之下的节点，应按实际层级使用相应子分区宏，不能因EXISTS为1就认定通用地址和存储器接口能处理任意嵌套。

> 译注——源码核对：版本边界：本次三个分区头文件、gen_defines.py与edtlib.py登记摘要；源码浏览页的非注释代码与对应原始头文件核对一致。滚动main和本仓库参照基线不自动视为同版本；本批未编译DTS、构建固件或执行擦写、分区修改及硬件实验。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
