## 1.3\_详细说明（Detailed Documentation）

<a id="ga9e84f3adc54120fb1f1ccffb1bac8c5c"></a>

### `base64_decode()`

```c
int base64_decode ( uint8_t * dst, size_t dlen, size_t * olen, const uint8_t * src, size_t slen )
```

```c
#include <zephyr/sys/base64.h>
```

解码Base64格式的缓冲区。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dst` | 目标缓冲区；检查所需大小时可以为NULL。 |
| `dlen` | 目标缓冲区大小。 |
| `olen` | 已写入的字节数。 |
| `src` | 源缓冲区。 |
| `slen` | 待解码的数据量。 |

**返回（Returns）**：成功返回0；空间不足返回-ENOMEM；输入数据不正确时返回-EINVAL。原说明规定总会更新*olen，以反映已经写入或本应写入的数据量。

**说明（Note）**：以*dst = NULL或dlen = 0调用此函数，可在*olen中取得所需缓冲区大小。此处保留原文写法，实际传参方式见源码译注。

> 译注——源码核对：原说明的*dst = NULL是指针写法错误：要只查询空间，应把dst参数本身设为NULL，而不是解引用dst赋值。非空有效输入的查询通常返回-ENOMEM，并在*olen中给出容量；空输入则返回0且长度为0。 解码结果是二进制字节，不自动追加NUL。先检查返回值，再读取实际输出长度；若要作为文本使用，需要额外空间并由调用者终止。原文称*olen总会更新，但当前第一遍检查遇到非法字符等情况直接返回-EINVAL，不更新*olen，因此错误时不能依赖其中仍保留的旧值。

<a id="gaaff09edf41470c26d5a54d18c4f91ba0"></a>

### `base64_encode()`

```c
int base64_encode ( uint8_t * dst, size_t dlen, size_t * olen, const uint8_t * src, size_t slen )
```

```c
#include <zephyr/sys/base64.h>
```

将缓冲区编码为Base64格式。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dst` | 目标缓冲区。 |
| `dlen` | 目标缓冲区大小。 |
| `olen` | 已写入的字节数。 |
| `src` | 源缓冲区。 |
| `slen` | 待编码的数据量。 |

**返回（Returns）**：成功返回0，缓冲区太小时返回-ENOMEM。总会更新*olen，以反映已经写入或本应写入的数据量。若该长度无法表示，则不向缓冲区写入数据，并将*olen设为size_t可表示的最大长度。

**说明（Note）**：以dlen = 0调用此函数，可在*olen中取得所需缓冲区大小。

> 译注——源码核对：非空输入的编码文本长度为4×ceil(slen/3)，目标还需要一个结尾NUL字节。长度查询或空间不足时，*olen包含这一个终止字节，返回-ENOMEM；成功时*olen只计文本字节，函数另外写入NUL。因此查询值和成功后的长度不是完全相同的计量口径。 slen为0时直接将*olen设为0并返回成功，不写目标缓冲区，也不会补NUL。需要空C字符串的调用者应自行保证目标起始字节为0。长度计算无法表示时，将*olen置size_t最大值并返回-ENOMEM，不能把这个哨兵直接用于分配后继续编码。

## 1.4\_源码定位与版本边界

对照[公共接口](P001_Base64编解码接口.md)、[头文件参考](P002_Base64头文件参考.md)与[源码浏览](P003_Base64头文件源码.md)。相对定位：[base64.h](../../../include/zephyr/sys/base64.h)、[base64.c](../../../lib/utils/base64.c)、[Kconfig](../../../lib/utils/Kconfig)与[构建规则](../../../lib/utils/CMakeLists.txt)。本次[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/base64.h)和[官方实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/base64.c)摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：用途与变体：当前映射表采用A–Z、a–z、0–9、+、/，并用=填充，是普通Base64编码；不直接支持以-、_替换末两字符的URL安全变体（URL-safe Base64）。Base64是表示转换，不提供加密、认证或完整性校验。

> 译注——源码核对：缓冲区归属：接口不分配存储，调用者提供源数据、目标空间和有效的olen指针。slen是源字节数，不依赖字符串终止符；非空输入不能把结尾NUL计入Base64解码长度。编码与解码输出的终止符规则不同，按各自的*olen处理。源与目标重叠没有公开保证，使用独立存储。

> 译注——源码核对：配置与版本：库构建由CONFIG_BASE64选择base64.c。本册核对本次官方main头文件、实现、Kconfig和构建文件；本仓库相对链接用于定位，不保证本地版本与滚动更新的latest一致。原文和代码保留，差异另列译注，未执行编解码或边界实验。

> 译注——源码核对：非空输入的编码文本长度为4×ceil(slen/3)，目标还需要一个结尾NUL字节。长度查询或空间不足时，*olen包含这一个终止字节，返回-ENOMEM；成功时*olen只计文本字节，函数另外写入NUL。因此查询值和成功后的长度不是完全相同的计量口径。

> 译注——源码核对：slen为0时直接将*olen设为0并返回成功，不写目标缓冲区，也不会补NUL。需要空C字符串的调用者应自行保证目标起始字节为0。长度计算无法表示时，将*olen置size_t最大值并返回-ENOMEM，不能把这个哨兵直接用于分配后继续编码。

> 译注——源码核对：原说明的*dst = NULL是指针写法错误：要只查询空间，应把dst参数本身设为NULL，而不是解引用dst赋值。非空有效输入的查询通常返回-ENOMEM，并在*olen中给出容量；空输入则返回0且长度为0。

> 译注——源码核对：解码结果是二进制字节，不自动追加NUL。先检查返回值，再读取实际输出长度；若要作为文本使用，需要额外空间并由调用者终止。原文称*olen总会更新，但当前第一遍检查遇到非法字符等情况直接返回-EINVAL，不更新*olen，因此错误时不能依赖其中仍保留的旧值。

> 译注——源码核对：当前解码器接受LF以及CRLF；允许行末或整个缓冲区末尾的普通空格，拒绝数据行内部空格、制表符、孤立CR及非ASCII字符。输入只包含可跳过的空白时可得到零长度输出，不能把返回0理解成一定解出了数据。

> 译注——源码核对：当前第一遍检查字符表、至多两个=以及填充后不能再出现普通编码字符，但没有完整验证非空字符数是否为4的倍数，也未验证末组未使用位为零。第二遍只在凑齐四个字符时输出，末尾不足一组可能被忽略。因此它不是严格的规范化Base64验证器，返回0不等于输入满足所有规范约束；协议需要严格校验时须另行检查。

本次验证范围为文档与源码对照，未编译或执行Base64编解码、边界及实板实验。
