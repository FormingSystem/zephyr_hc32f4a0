## 1.5\_详细说明（Detailed Documentation）

<a id="ga803e45abf48ee207fc0ab4028726a82b"></a>

### `RING_BUF_DECLARE`

```c
#define RING_BUF_DECLARE ( name, size8 )
```

```c
#include <zephyr/sys/ring_buffer.h>
```

展开值（Value）：

```c
BUILD_ASSERT((size8) <= RING_BUFFER_MAX_SIZE, RING_BUFFER_SIZE_ASSERT_MSG);     \
static uint8_t __noinit _ring_buffer_data_##name[(size8)];                      \
struct ring_buf name = RING_BUF_INIT(_ring_buffer_data_##name, (size8))
```

定义并初始化用于字节数据的环形缓冲区。

用户可见容量等于请求的size8。后备存储（Backing Storage）分配为大小等于size8的静态uint8_t数组；环形缓冲区结构初始化时指向这块后备存储，并设置相应容量。

其他模块可以通过以下声明引用此环形缓冲区：

原始示例（Example）：

```c
extern struct ring_buf <name>;
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 环形缓冲区名称。 |
| `size8` | 缓冲区容量，单位为字节。 |

> 译注——源码核对：宏声明静态__noinit后备数组并初始化对象，不把数据字节清零。初始逻辑为空，不能读取未提交区域。size8是字节数，只有旧item宏按32位字数计量。

<a id="gaa9373d083ab02a0aa0b6155004676838"></a>

### `RING_BUF_INIT`

```c
#define RING_BUF_INIT ( buf, sz )
```

```c
#include <zephyr/sys/ring_buffer.h>
```

展开值（Value）：

```c
{                                               \
        .buffer = (buf),                        \
        .size = (ring_buf_size_t)(sz),          \
}
```

静态初始化环形缓冲区。

size表示以字节为单位的缓冲区容量，它等于用户可见容量；内部不额外保留一个槽位。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `buf` | 指向后备字节存储的指针。 |
| `sz` | 缓冲区容量，单位为字节，等于用户可见容量。 |

> 译注——源码核对：这是结构初始化器（Initializer），保存现有后备字节存储的指针及容量，不另外分配存储；没有RING_BUF_DECLARE中的BUILD_ASSERT。调用者须保证容量上限、后备区域长度及生命周期，不能依赖窄化强制转换修复过大容量。

### `ring_buf_commit()`

```c

```

声明属性：`inline`、`static`。

```c

```

指明已写入环形缓冲区的字节数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `rb` | 环形缓冲区的地址。 |
| `size` | 已写入的字节数。 |

> 译注——源码核对：原文要求size不超过最近一次put_ptr的返回量，照译保留。实现的断言检查总空闲量，内置ring_buf_put则可能用offset访问多个片段后一次提交累计量，存在说明与内部用法的边界差异。应用逐连续片段写完后提交最直观；不能把断言未失败当作未写区域可以发布的依据，提交量从原写索引计算。

<a id="gad3990b5a2ae63166b76c6d1db179a215"></a>

### `ring_buf_get_ptr()`

```c
uint32_t ring_buf_get_ptr ( struct ring_buf * rb, uint8_t ** data, size_t offset )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/ring_buffer.h>
```

获取环形缓冲区内有效数据的地址。

用户可以直接使用环形缓冲区的内部存储，从而减少内存复制。处理数据后，必须通过ring_buf_consume释放相应区域。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[in] rb` | 环形缓冲区的地址。 |
| `[out] data` | 设为缓冲区内可读区域的起始地址。 |
| `[in] offset` | 相对于当前读取索引，调用者已经暂时消费的字节数；首次查看时为0。不得超过有效数据量。 |

**返回（Returns）**：可读取的字节数。如果数据在缓冲区末尾回绕（Wraparound），该值可能小于全部有效数据量。

> 译注——源码核对：取得读取指针不会消费数据。返回长度受当前连续片段限制，不能直接把总有效数据量用于一次越过缓冲区末尾的读取；offset由调用者跟踪，其他同侧访问者仍需串行化。

### `ring_buf_init()`

```c
void ring_buf_init ( struct ring_buf * rb, uint32_t size, uint8_t * data )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/ring_buffer.h>
```

初始化用于字节数据的环形缓冲区。

用于初始化未通过RING_BUF_DECLARE定义的环形缓冲区。size表示以字节为单位的缓冲区容量，等于用户可见容量；内部不额外保留一个槽位。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `rb` | 环形缓冲区的地址。 |
| `size` | 缓冲区容量，单位为字节。size为0时生成容量为0的退化缓冲区（Degenerate Buffer）。 |
| `data` | 环形缓冲区的数据区域，即uint8_t data[size]。 |

> 译注——源码核对：函数断言容量不超过当前上限，再保存指针、容量并复位索引。size=0在文档中明确允许，但不是允许任意空指针参与后续指针运算；有效对象和后备指针前提仍由调用者负责。初始化和复位不应与正在使用该对象的读写方并发进行。

| `rb` | 环形缓冲区的地址。 |

**返回（Returns）**：环形缓冲区已满时返回true，否则返回false。

> 译注——源码核对：根据有效数据量等于容量判断；容量0时也为true。查询结果不替代多访问者同步，也不保证随后的操作仍看到同一状态。

### `ring_buf_peek()`

```

声明属性：`inline`、`static`。

```

查看环形缓冲区内的数据但不消费它（Peek）。

**参数（Parameters）**

### `ring_buf_put_ptr()`

```c
uint32_t ring_buf_put_ptr ( struct ring_buf * rb, uint8_t ** data, size_t offset )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/ring_buffer.h>
```

获取环形缓冲区内可写区域的地址。

用户可以直接使用环形缓冲区的内部存储，从而减少内存复制。向所获区域写入数据后，必须通过ring_buf_commit确认写入的字节数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[in] rb` | 环形缓冲区的地址。 |
| `[out] data` | 设为缓冲区内可写区域的起始地址。 |
| `[in] offset` | 相对于当前写入索引，调用者已经暂时预留的字节数；首次获取区域时为0。不得超过空闲空间。 |

**返回（Returns）**：可写入的字节数。如果空闲区域在缓冲区末尾回绕，该值可能小于全部空闲空间。

> 译注——源码核对：返回一个物理连续片段，长度可能小于总空闲量；此调用不推进写索引。offset表示从当前索引起累计跳过的暂定写入量，不是一次新的独立分配，也不会替调用者锁住区域。只有返回长度内的数据可写。

## 1.6\_源码定位与版本边界

对照[公共API](P001_环形缓冲区公共接口.md)、[结构说明](P002_环形缓冲区结构.md)、[头文件参考](P003_环形缓冲区头文件参考.md)和[源码浏览译文](P004_环形缓冲区头文件源码.md)。

相对源码定位：[include/zephyr/sys/ring_buffer.h](../../../include/zephyr/sys/ring_buffer.h)；本次说明依据为[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/ring_buffer.h)、[官方Kconfig](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/Kconfig)与[官方CMakeLists.txt](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/CMakeLists.txt)，摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：版本与编译入口：本次官方main采用仅需头文件（Header-only）的实现，lib/utils/CMakeLists.txt不再编译ring_buffer.c；CONFIG_RING_BUFFER恢复旧claim/finish与item接口，并选择DEPRECATED。仓库当前实现仍有独立ring_buffer.c，不能把本页新版布局、配置含义和性能直接套用到本地版本。

> 译注——源码核对：单生产者／单消费者（Single Producer Single Consumer，SPSC）：当前官方头文件在CONFIG_SMP且CONFIG_MP_MAX_NUM_CPUS大于1时使用获取／释放（Acquire/Release）原子访问发布索引，其他配置使用相应编译器屏障（Compiler Barrier）。这不提供多生产者或多消费者的互斥，也不自动解决DMA缓存一致性；等待与唤醒仍由应用安排。指南中要求同步原语提供内存屏障的文字与此处实现细节分别保留，目标版本须以实际源码为准。

> 译注——源码核对：容量边界：当前默认RING_BUFFER_MAX_SIZE为UINT16_MAX/2U，即32767字节；CONFIG_RING_BUFFER_LARGE启用后为UINT32_MAX/4U，即1073741823字节，索引与容量字段由16位增为32位。Kconfig的32KB／1GB是概括表述，不能当作可原样传入的精确上限。容量不要求为2的幂，用户可见容量无需再减一个槽位。

> 译注——源码核对：零复制（Zero-copy）指针接口不改变索引，也不保存一次独占预留。offset相对尚未提交／消费的当前索引，由调用者跟踪；在同一侧没有推进索引时重复以offset=0获取指针，会指向同一逻辑区域。commit／consume发布实际处理的字节数，不是分配或释放后备内存。

> 译注——源码核对：配置与文档范围：本次公开API页只列新版接口；源码浏览页还保留CONFIG_RING_BUFFER条件下的兼容实现及关闭时的编译错误宏。原网页隐藏的Doxygen注释不作为可见源码注释计数，不把这四页登记解释为所有其他历史版本API已完成翻译。
