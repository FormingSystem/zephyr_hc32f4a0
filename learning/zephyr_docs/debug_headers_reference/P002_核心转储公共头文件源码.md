## 2.2\_可见注释译文（Comments）

3. 需要为核心转储字符串加前缀以便解析，因为日志模块还会添加它自己的前缀。

4. 目标代码（Target Code）。

5. 核心转储头（Coredump Header）。

6. 字符Z和E。

7. 头部版本（Header Version）。

8. 目标代码。

9. 指针大小以2为底的对数（Log2）。

10. 传入的核心转储原因（Coredump Reason）。

11. 架构专有块头（Architecture-specific Block Header）。

12. COREDUMP_ARCH_HDR_ID。

13. 头部版本。

14. 此块的字节数，不包括头部。

15. 线程元数据头（Threads Metadata Header）。

16. THREADS_META_HDR_ID。

17. 头部版本。

18. 此块的字节数，不包括头部。

19. 内存块头（Memory Block Header）。

20. COREDUMP_MEM_HDR_ID。

21. 头部版本。

22. 内存区域的起始地址。

23. 内存区域的结束地址。

24. 实时的每CPU寄存器快照头（Per-CPU Register Snapshot Header），由CONFIG_DEBUG_COREDUMP_SMP_FREEZE_CPUS使用。每个被冻结CPU的寄存器块之前都有一个这样的头；其架构专有载荷布局与故障线程的COREDUMP_ARCH_HDR_ID块相同，例如ARM64上的arm64_arch_block。这样，工具能够为故障发生时正在另一个CPU上运行的线程显示正确回溯（Backtrace），而不必退回使用该线程上次换出时保存的过时上下文。

25. COREDUMP_CPU_SNAPSHOT_HDR_ID。

26. 头部版本。

27. 后续架构专有载荷的字节数。

28. 产生此快照的CPU索引，范围为0至CONFIG_MP_MAX_NUM_CPUS-1。

29. 该CPU被冻结时，其.current所指向的k_thread。

30. 向后端通知核心转储开始。

31. 向后端通知核心转储结束。

## 2.4\_源码跟踪译注

> 译注——核心转储（Core Dump）公共头文件定义数据格式、目标代码、查询及命令编号，并声明转储入口；具体保存位置由后端决定。输出到日志、内存或其他后端不等同于已经生成可持久保存的文件。

> 译注——转储格式中的ptr_size是指针大小以2为底的对数，不是直接存放的字节数；架构块和线程元数据块的长度注释明确排除头部。解析器必须按各块格式与版本处理，不能用主机结构布局随意解释目标数据。

> 译注——每CPU快照头记录CPU索引和冻结时的当前线程，目的是保存故障时另一个CPU上正在运行线程的寄存器状态，而不是沿用该线程上次换出的旧上下文。这与普通内存块或故障线程的架构块用途不同。

> 译注——CONFIG_DEBUG_COREDUMP关闭时，几个void转储函数为空实现，查询与命令返回-ENOTSUP；开启功能后，如果后端没有query或cmd回调，通用代码仍返回-ENOTSUP。返回值的具体含义必须结合查询／命令编号和后端阅读。

> 译注——当前coredump使用原子所有者变量避免同时进入转储后端。启用CONFIG_DEBUG_COREDUMP_SMP_FREEZE_CPUS时，在转储主体前冻结其他CPU，在读取内存区域之后解冻；不能把所有配置下的转储都描述为完整的跨核瞬时快照。

> 译注——官方源码页有一项名为cmd的符号提示，说明为由协处理器执行显示列表命令，这是原网页交叉索引指向了同名图形接口。本页保留该原始提示及链接，不能将其理解为核心转储命令的语义。另有提示仅显示Returns:，按原页保留为空的返回标签，不补造返回值。

> 译注——原始头文件文档注释的@fn把coredump_buffer_output写为int，但真实声明和实现返回void；本页按原始可见代码保留void。不要据这处注释差异读取一个不存在的返回值。
