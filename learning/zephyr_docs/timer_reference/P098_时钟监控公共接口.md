# 第98章\_时钟监控公共接口

原文：[group__clock__monitor__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__clock__monitor__interface.html)。读取日期：2026-10-13，`latest`。

## 98.2\_事件回调

回调（Callback）可能在中断服务程序（Interrupt Service Routine，ISR）上下文执行。**应保持简短，把繁重工作延后到线程（Thread）或工作队列（Work Queue）处理。**

```c
typedef void (*clock_monitor_callback_t)(const struct device *dev,
                                         const struct clock_monitor_event_data *evt,
                                         void *user_data);
```

`user_data`为用户数据（User Data）。参数表中的`—`表示原页未标注方向，`[out]`表示输出。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 时钟监控设备 |
| `evt` | — | 事件载荷；**生命周期在回调返回时结束** |
| `user_data` | — | 从`clock_monitor_config`复制的不透明指针 |


## 98.3\_事件标志

匿名枚举（Anonymous Enumeration）定义事件标志（Event Flag），可以按位或（Bitwise OR）组合成32位无符号整数类型`uint32_t`的位掩码（Bitmask）。宏`BIT(n)`表示第 n 位的掩码。

```c
enum {
        CLOCK_MONITOR_EVT_FREQ_HIGH    = BIT(0),
        CLOCK_MONITOR_EVT_FREQ_LOW     = BIT(1),
        CLOCK_MONITOR_EVT_CLOCK_LOST   = BIT(2),
        CLOCK_MONITOR_EVT_MEASURE_DONE = BIT(3),
};
```

| 标志 | 数值定义 | 含义 |
| --- | --- | --- |
| `CLOCK_MONITOR_EVT_FREQ_HIGH` | `BIT(0)` | 被监控频率超过上限阈值（Upper Threshold） |
| `CLOCK_MONITOR_EVT_FREQ_LOW` | `BIT(1)` | 被监控频率低于下限阈值（Lower Threshold） |
| `CLOCK_MONITOR_EVT_CLOCK_LOST` | `BIT(2)` | 被监控时钟停止或停滞（Stopped or Stuck） |
| `CLOCK_MONITOR_EVT_MEASURE_DONE` | `BIT(3)` | 频率测量完成（Measurement Completed） |

## 98.4\_运行模式

```c
enum clock_monitor_mode {
        CLOCK_MONITOR_MODE_WINDOW = 1,
        CLOCK_MONITOR_MODE_MEASURE,
};
```

`clock_monitor_mode`表示监控实例的运行模式（Operating Mode）。

值0刻意没有对应名称：**全零初始化的配置会被`clock_monitor_configure`以`-ENOTSUP`拒绝**。

`CLOCK_MONITOR_MODE_WINDOW = 1`是连续高／低阈值窗口检查模式。持续将被监控时钟的频率与可编程的上、下界比较，频率离开窗口时产生事件。

`CLOCK_MONITOR_MODE_MEASURE`在每次`clock_monitor_start`时执行一次频率测量，通过配置时安装的回调，以赫兹（Hertz，Hz）报告结果。完成回调执行前，设备自动返回已配置的停止状态；正常成功路径不需要调用`clock_monitor_stop`。要重复测量，可以直接在回调中再次调用`clock_monitor_start`。

## 98.5\_应用监控配置

```c
__syscall int clock_monitor_configure(const struct device *dev,
                                      const struct clock_monitor_config *cfg);
```

必须在监控器停止时调用。将`cfg->callback`（可以为`NULL`）与其余配置**原子地安装（Atomically Install）**。

需要重新配置（Reconfiguration）时，用新的模式和参数再次调用此函数；没有单独的拆除（Teardown）操作。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 时钟监控设备 |
| `cfg` | — | 要应用的配置 |


**返回值：**

| 返回值 | 条件 |
| --- | --- |
| `0` | 成功 |
| `-EINVAL` | 配置格式不正确 |
| `-ENOTSUP` | 后端不支持请求的模式 |
| `-EBUSY` | 监控器正在运行，或另一次`configure()`正在进行 |
| `-EIO` | 参考时钟查询失败，或硬件初始化失败 |


## 98.6\_轮询最近一次已完成测量

```c
__syscall int clock_monitor_get_rate(const struct device *dev,
                                     uint32_t *rate_hz);
```

返回自最近一次`clock_monitor_configure`以来，最近一次已完成测量的结果。该值会保留：**读取不会清除它，也没有硬件副作用**。

这是配置时安装回调之外的轮询（Polling）方式，也可用于可能不允许安装回调的用户模式（User Mode）。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 已经配置为 MEASURE 测量模式的设备 |
| `rate_hz` | [out] | 以赫兹（Hertz，Hz）表示的测量频率，**仅在成功时写入** |


**返回值：**

| 返回值 | 条件 |
| --- | --- |
| `0` | `*rate_hz`保存最近一次测量值 |
| `-EAGAIN` | 测量正在进行，或尚无已完成的测量 |
| `-EIO` | 自`configure()`以来，被监控时钟丢失（停滞） |
| `-ENOSYS` | 后端没有测量硬件 |


## 98.7\_运行时切换参考与目标时钟

```c
__syscall int clock_monitor_set_source(const struct device *dev,
                                       uint32_t reference, uint32_t target);
```

在运行时（Runtime）切换参考时钟（Reference Clock）和目标时钟（Target Clock）输入。

`reference`和`target`是后端专用的不透明标识（Opaque Cookie）。每个后端通过设备树绑定头文件（Devicetree Bindings Header）公布可接受的编码，例如`<zephyr/dt-bindings/clock_monitor/<vendor>-<ip>.h>`，以便设备树属性和运行时调用使用同一套常量。原页没有给出通用哨兵数值，应查相应后端。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 时钟监控设备 |
| `reference` | — | 参考时钟的不透明标识（Cookie），或哨兵值（Sentinel） |
| `target` | — | 目标时钟的不透明标识（Cookie），或哨兵值（Sentinel） |


**返回值：**

| 返回值 | 条件 |
| --- | --- |
| `0` | 成功 |
| `-ENOTSUP` | 后端硬件不能在运行时切换时钟源 |
| `-EINVAL` | 一个或两个不透明标识不被此后端识别 |
| `-EBUSY` | 监控器正在运行，或测量正在进行 |
| `-ENOSYS` | 后端未实现`set_source()` |


## 98.8\_启动所配置的模式

```c
__syscall int clock_monitor_start(const struct device *dev);
```

设备必须已经通过`clock_monitor_configure`完成配置，随后行为由当前模式决定。

- `CLOCK_MONITOR_MODE_WINDOW`开始连续阈值检查。越过阈值时通过配置阶段安装的回调通知，直到调用`clock_monitor_stop`。
- `CLOCK_MONITOR_MODE_MEASURE`开始一次测量。完成时以`CLOCK_MONITOR_EVT_MEASURE_DONE`事件调用回调，测量值位于`evt->measured_hz`；若被测时钟停滞，则报告`CLOCK_MONITOR_EVT_CLOCK_LOST`，测量值为0。**回调执行前，设备自动回到已配置的停止状态。**

此函数可安全地在中断服务程序（Interrupt Service Routine，ISR）中调用，也可以从事件回调调用。要重复采样，可在回调中再次调用它，方式类似在计数器告警回调中重新设置告警。

**测量等待与超时：** 此 API 不提供阻塞等待（Blocking Wait）或测量超时。应用应等待回调，例如等待回调释放的信号量（Semaphore），并自行选定超时时间；超时时调用`clock_monitor_stop`中止仍在进行的测量。也可以改为轮询`clock_monitor_get_rate`。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 时钟监控设备 |


**返回值：**

| 返回值 | 条件 |
| --- | --- |
| `0` | 成功 |
| `-EINVAL` | 设备尚未配置 |
| `-EBUSY` | 已经在运行 |


## 98.9\_停止监控器

```c
__syscall int clock_monitor_stop(const struct device *dev);
```

使设备回到已配置的停止状态，并中止任何仍在进行的测量。此操作是幂等的（Idempotent）：**停止一个已经停止的设备仍返回0**。

此函数可安全地在 ISR 中调用，也可从事件回调调用。在 MEASURE 模式的回调中，自动停止已经完成，因此这时调用它是无害的空操作（No-op）。

**参数：**

| 参数 | 方向 | 说明 |
| --- | --- | --- |
| `dev` | — | 时钟监控设备 |


**返回值：**

| 返回值 | 条件 |
| --- | --- |
| `0` | 成功 |
