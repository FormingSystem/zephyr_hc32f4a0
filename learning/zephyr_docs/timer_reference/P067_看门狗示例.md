# 第67章\_看门狗示例

原文：[Watchdog](https://docs.zephyrproject.org/latest/samples/drivers/watchdog/README.html)。读取日期：2026-10-13，`latest`。

本示例演示看门狗（Watchdog）驱动应用程序接口（Application Programming Interface，API）的用法。典型场景是某段代码一直陷入无限循环（Infinite Loop）时，让开发板重新启动。[示例源码](https://github.com/zephyrproject-rtos/zephyr/tree/main/samples/drivers/watchdog)位于`samples/drivers/watchdog`。

## 67.1\_超时回调与开发板配置

本例用看门狗回调（Callback）处理一次超时事件（Timeout Event），使应用可以在看门狗超时导致开发板重启之前，请求执行一个动作。

看门狗外设在开发板的`.dts`设备树源文件（Devicetree Source）中配置。应使用`boards`目录中的配置文件确保看门狗已启用。

## 67.2\_为ST Nucleo F091RC构建

针对[Nucleo F091RC](https://docs.zephyrproject.org/latest/boards/st/nucleo_f091rc/doc/index.html#nucleo_f091rc)，构建和烧录命令为：

```sh
west build -b nucleo_f091rc samples/drivers/watchdog
west flash
```

要为其他开发板构建，将`nucleo_f091rc`改成目标板名称，并提供相应的设备树覆盖文件（Devicetree Overlay）。

## 67.3\_预期输出与重启

应看到类似以下输出：

```text
Watchdog sample application
Attempting to test pre-reset callback
Feeding watchdog 5 times
Feeding watchdog...
Feeding watchdog...
Feeding watchdog...
Feeding watchdog...
Feeding watchdog...
Waiting for reset...
Handled things..ready to reset
```

日志依次表示：启动看门狗示例应用、尝试测试复位前回调（Pre-reset Callback）、喂狗（Feed the Watchdog）5次、等待复位（Reset），以及回调已经处理完所需事项、准备复位。

**最后一条消息之后，开发板将复位，随后再次开始同一流程。** 相关接口见[看门狗公共接口](P001_看门狗公共接口.md)。
