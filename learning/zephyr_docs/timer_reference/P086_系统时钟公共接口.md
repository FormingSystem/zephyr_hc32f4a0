# 第86章\_系统时钟公共接口

原文：[group__clock__apis](https://docs.zephyrproject.org/latest/doxygen/html/group__clock__apis.html)。读取日期：2026-10-13，`latest`。

本页完整翻译系统时钟（System Clock）应用程序接口（Application Programming Interface，API）分组，包括超时构造、启动后运行时间、硬件周期、时间点和定时器驱动与内核之间的约定。原分组的子主题见[系统时钟低功耗交接接口](P089_系统时钟低功耗交接接口.md)。

## 86.1\_超时与时间点类型

`k_timeout_t`为内核超时（Kernel Timeout）的不透明类型（Opaque Type），`k_timepoint_t`为内核绝对时间点（Absolute Timepoint）的不透明类型。结构与使用约定见[超时类型](P087_内核超时类型.md)和[时间点类型](P088_内核时间点类型.md)。

`k_ticks_t`规定超时API中刻度（Tick）值的字长，因而限制最大超时时长，或等价地限制可采用的最短tick时长。它不改变系统运行时间计数器的大小：后者始终是64位tick计数。原API页面展示：

<a id="ga9832cb0adc2d1866420e5c370a0863e2"></a>

```c
typedef uint32_t k_ticks_t;
```

> 译注：对应[头文件源码](P091_系统时钟头文件源码.md)在`CONFIG_TIMEOUT_64BIT`启用时定义为`int64_t`，否则为`uint32_t`。原参考页展示的是32位分支，不能据此认为所有配置都使用32位超时。

## 86.2\_从不同单位构造超时

以下宏由`zephyr/kernel.h`提供，返回超时延迟值（Timeout Delay Value），告诉内核API最多等待指定时长来执行请求的操作。

<a id="ga0bb4b83f0222193b21a8910311bab0ca"></a>

<a id="ga3d9541cfe2e8395af66d186efa77362f"></a>

`K_NO_WAIT`展开为`Z_TIMEOUT_NO_WAIT`：如果操作不能立即完成，就不要等待。`K_FOREVER`展开为`Z_FOREVER`：为完成操作，等待所需的任意长时间。

`K_CYC(t)`：参数`t`是周期（Cycle）数，返回最多等待`t`个周期的超时值。原展开式：

```c
Z_TIMEOUT_CYC(t)
```

`K_HOURS(h)`：参数`h`为小时（Hour）数，返回最多等待`h`小时的超时值：

```c
K_MINUTES((h) * 60)
```

`K_MINUTES(m)`：参数`m`为分钟（Minute）数，返回最多等待`m`分钟的超时值：

```c
K_SECONDS((m) * 60)
```

<a id="ga302af954e87b10a9b731f1ad07775e9f"></a>

`K_MSEC(ms)`：参数`ms`为毫秒（Millisecond）数，返回最多等待`ms`毫秒的超时值：

```c
Z_TIMEOUT_MS(ms)
```

`K_NSEC(t)`：参数`t`为纳秒（Nanosecond）数，返回最多等待`t`纳秒的超时值。**定时器精度受tick频率限制，不取决于请求值写了多细的单位。**

```c
Z_TIMEOUT_NS(t)
```

`K_SECONDS(s)`：参数`s`为秒（Second）数，返回最多等待`s`秒的超时值：

```c
K_MSEC((s) * MSEC_PER_SEC)
```

`K_TICKS(t)`：参数`t`为系统tick数，返回最多等待`t`个tick的超时值：

```c
Z_TIMEOUT_TICKS(t)
```

## 86.3\_超时比较、相加及永久刻度值

<a id="ga66e180b3d8940c30786a1d972cbd6d8d"></a>

`K_TICKS_FOREVER`由`zephyr/sys/clock.h`定义，原值为`((k_ticks_t)(-1))`。

<a id="ga9abf00b34e16ab7ad0883603b6778b1b"></a>

`K_TIMEOUT_EQ(a, b)`比较两个超时对象是否相等，来自`zephyr/sys/clock.h`，对象相同返回真（True）。应用不应直接检查`k_timeout_t`内部成员；使用该宏，可在基于Zephyr超时常量实现自己的API时，与`K_NO_WAIT`、`K_FOREVER`等已知值比较。原展开式：

```c
((a).ticks == (b).ticks)
```

`K_TIMEOUT_SUM(timeout1, timeout2)`由`zephyr/kernel.h`提供，把两个`k_timeout_t`值相加。`timeout1`和`timeout2`分别为第一、第二个超时值。只有一个是绝对超时（Absolute Timeout）时，结果为绝对超时；两个都是相对超时（Relative Timeout）时，结果为相对超时。发生上溢（Overflow）、下溢（Underflow），或两个都是绝对超时时，返回`K_FOREVER`。返回值是超时之和，无法计算时为`K_FOREVER`。原展开式：

```c
K_TICKS(z_timeout_sum(timeout1, timeout2))
```

## 86.4\_微秒超时

`K_USEC(t)`由`zephyr/kernel.h`提供；参数`t`为微秒（Microsecond）数，返回最多等待`t`微秒的超时值。与纳秒形式一样，**实际定时精度仍受tick频率限制**。

```c
Z_TIMEOUT_US(t)
```

## 86.5\_时间单位常量与平均周期换算

<a id="ga0501e82515b2bdf36453c4cc80f5e0cc"></a>

下表宏均定义于`zephyr/sys/clock.h`。

| 宏 | 原值 | 含义 |
| --- | --- | --- |
| `NSEC_PER_USEC` | `1000U` | 每微秒的纳秒数。 |
| `NSEC_PER_MSEC` | `1000000U` | 每毫秒的纳秒数。 |
| `USEC_PER_MSEC` | `1000U` | 每毫秒的微秒数。 |
| `MSEC_PER_SEC` | `1000U` | 每秒的毫秒数。 |
| `SEC_PER_MIN` | `60U` | 每分钟的秒数。 |
| `SEC_PER_HOUR` | `3600U` | 每小时的秒数。 |
| `SEC_PER_DAY` | `86400U` | 每天的秒数。 |
| `MIN_PER_HOUR` | `60U` | 每小时的分钟数。 |
| `HOUR_PER_DAY` | `24U` | 每天的小时数。 |
| <a id="ga6a69d6cbdab5f24c2e66959293f210c1"></a>`USEC_PER_SEC` | `((USEC_PER_MSEC) * (MSEC_PER_SEC))` | 每秒的微秒数。 |
| `NSEC_PER_SEC` | `((NSEC_PER_USEC) * (USEC_PER_MSEC) * (MSEC_PER_SEC))` | 每秒的纳秒数。 |

`SYS_CLOCK_HW_CYCLES_TO_NS_AVG(X, NCYCLES)`将中央处理器（Central Processing Unit，CPU）的时钟周期换算成纳秒，并计算平均周期时间（Average Cycle Time）。原展开式保留64位向下取整换算和最终32位转换：

```c
(uint32_t)(k_cyc_to_ns_floor64(X) / NCYCLES)
```

## 86.6\_时钟标识与绝对睡眠标志

下列常量由`zephyr/sys/clock.h`提供：

| 宏 | 原值 | 含义 |
| --- | --- | --- |
| `SYS_CLOCK_REALTIME` | `1` | 实时时钟（Real-time Clock），也称墙上时钟（Wall Clock）。 |
| `SYS_CLOCK_MONOTONIC` | `4` | 单调时钟（Monotonic Clock）。 |
| `SYS_TIMER_ABSTIME` | `4` | 绝对超时标志（Absolute Timeout Flag）。 |

`SYS_CLOCK_REALTIME`测量自纪元（Epoch）`1970-01-01 00:00:00 UTC`起的时间，UTC为协调世界时（Coordinated Universal Time）。它不是稳定不变的时钟：硬件RTC初始化、网络时间同步或应用手动设置都可能调整它。

`SYS_CLOCK_MONOTONIC`用于测量系统启动以来的时间，是稳定时钟（Steady Clock），时间始终单调递增。

将`SYS_TIMER_ABSTIME`传给`sys_clock_nanosleep`，表示请求超时是相对于所选时钟的绝对时间。

## 86.7\_系统时钟锁与中断示例

自旋锁及键值的通用契约见[自旋锁公共接口](../kernel/P065_自旋锁公共接口.md)。

以下驱动函数由`zephyr/drivers/timer/system_timer.h`声明。`sys_clock_lock`取得内核定时器锁，保护tick记账（Tick Accounting）和超时队列（Timeout Queue）。

```c
k_spinlock_key_t sys_clock_lock(void);
```

定时器驱动应在中断服务程序（Interrupt Service Routine，ISR）开始时调用它，并把返回的锁键（Lock Key）交给`sys_clock_announce_locked`。后者接管该键，并在返回时释放锁。返回键也可交给`sys_clock_unlock`。

内核调用驱动实现的`sys_clock_set_timeout`和`sys_clock_elapsed`时，**已经持有此锁**。原例中的`CYC_PER_TICK`表示每个tick对应的周期数，`last_cycle`保存周期基线，`read_hw_counter()`代表硬件计数读取。官方ISR示例如下：

```c
static void timer_isr(const void *arg)
{
    k_spinlock_key_t key = sys_clock_lock();

    // Update driver-private state (e.g. cycle counter baseline)
    uint64_t now = read_hw_counter();
    uint32_t dticks = (now - last_cycle) / CYC_PER_TICK;
    last_cycle += (uint64_t)dticks * CYC_PER_TICK;

    // Reprogram comparator if needed ...

    // Announce ticks — key ownership transfers to announce.
    sys_clock_announce_locked(dticks, key);
}
```

示例注释依次表示：更新驱动私有状态，例如周期计数基线（Cycle Counter Baseline）；必要时重新设置比较器（Comparator）；通告tick，此时锁键的所有权转交给通告函数。

`sys_clock_unlock`释放此前由`sys_clock_lock`取得的锁：

```c
void sys_clock_unlock(k_spinlock_key_t key);
```

参数`key`为锁定函数返回的键。该函数供有特殊需求的驱动使用；多数驱动应使用会自动解锁的`sys_clock_announce_locked`。

## 86.8\_向内核通告时间进展

`sys_clock_announce_locked`通知内核：自上次`sys_clock_announce`调用以来已经过去`ticks`个tick；第一次调用则从系统启动时算起。

```c
void sys_clock_announce_locked(uint32_t ticks, k_spinlock_key_t key);
```

驱动应在硬件和延迟限制允许的范围内，尽量贴近tick边界通告。调用方必须已经通过`sys_clock_lock`持锁。`key`参数被本函数接管，函数返回时锁已释放。

对于需要把驱动内部状态更新，例如周期计数器基线更新，与内核tick记账作为一个原子操作（Atomic Operation）完成的定时器ISR，这是推荐入口。`ticks`为经过的tick数，`key`为锁定函数取得的键。

`sys_clock_announce`是旧接口包装（Legacy Wrapper），在内部取得系统时钟锁后转调：

```c
static inline void sys_clock_announce(uint32_t ticks);
```

参数`ticks`为经过的tick数。新驱动应优先使用`sys_clock_lock`加`sys_clock_announce_locked`，让驱动状态和tick记账受同一把锁保护。

## 86.9\_设置下一次超时

`sys_clock_set_timeout`通知驱动：下一次需要调用`sys_clock_announce`的时刻，是从当前时刻经过指定的`ticks`之后。

```c
void sys_clock_set_timeout(uint32_t ticks, bool idle);
```

允许额外通告，例如每个tick都通告，而本函数实现为空操作（No-op）。要求是在指定到期时刻**之前的一个tick区间内**有一次tick通告。`ticks == 1`表示“通告下一个tick”；选择这种约定是为了兼容旧用法。`ticks == 0`也合法，表示内核希望尽快收到下一次通告。

tick数值本身不携带其他特殊语义。驱动按请求设置计时，将时长限制在自身硬件能容纳的范围，并通告实际经过的tick数。过去从tick数值推断的两种情形已有专门入口：`sys_clock_no_timeout`表示没有待处理超时，`sys_clock_idle_enter`表示CPU将睡眠。

在对称多处理（Symmetric Multiprocessing，SMP）系统中，任意CPU都可能调用本函数，请求反映全系统期望的下一次超时。驱动必须串行化（Serialize）随后产生的通告，确保每一个tick在全系统**恰好通告一次**。内核不会把超时“分配”给指定CPU来替驱动完成串行化。

内核调用本函数时已持有系统时钟锁。`ticks`的单位是tick。`idle`参数已弃用（Deprecated）：内核直接调用时始终为`false`，空闲进入通知改走`sys_clock_idle_enter`，该钩子的兼容回退才会在此传入`true`。该参数计划在未来版本删除，**新代码必须忽略它**。

## 86.10\_没有待处理超时

`sys_clock_no_timeout`通知驱动当前没有待处理超时：

```c
void sys_clock_no_timeout(void);
```

当超时队列为空且启用了`CONFIG_SYSTEM_CLOCK_SLOPPY_IDLE`时，内核用该函数代替`sys_clock_set_timeout`。此时没有即将到来的tick通告，系统也不要求精确维持运行时间；驱动可以屏蔽唤醒、设置硬件允许的最长间隔，或同时采取两种措施。下一次`sys_clock_set_timeout`恢复正常工作。

CPU此时仍在运行，所以`sys_clock_cycle_get_32`和`sys_clock_cycle_get_64`必须继续计数：线程仍可能调用`k_cycle_get_32`或`k_busy_wait`。如果周期计数器由准备停止的同一定时器驱动，就只能屏蔽中断。若周期计数器位于不同的时钟域或电源域（Clock or Power Domain），则可能停止更多部件。停止时间基准（Time Base）的处理属于`sys_clock_idle_enter`。

这与`sys_clock_disable`不同，不是拆除或关闭整个驱动的过程（Teardown）。

该钩子（Hook）为可选；没有实现时，回退为请求`sys_clock_set_timeout`等待其能表达的最长值`UINT32_MAX`个tick。这在数值上就是此处旧有`K_TICKS_FOREVER`的值，所以尚未迁移、仍按这个值判断的驱动，会像过去一样停止时钟。

## 86.11\_进入与退出低功耗空闲

`sys_clock_idle_enter`由电源管理（Power Management）的空闲路径调用，表示CPU即将睡眠：

```c
void sys_clock_idle_enter(uint32_t ticks);
```

需要将计时交给低功耗唤醒定时器（Low-power Wakeup Timer），或为睡眠重新配置自身的驱动，在这里操作；`sys_clock_idle_exit`在退出时撤销这些操作。无需低功耗处理的驱动不必实现本钩子。

该钩子可选。缺省回退调用`sys_clock_set_timeout`，把已弃用的`idle`参数设为`true`，使依赖旧参数的驱动仍能工作。该回退将随参数移除；届时使用电源管理设施的平台应自行实现`sys_clock_idle_enter`。

参数`ticks`表示距下次预期唤醒的tick数。没有事情需要唤醒CPU、且允许运行时间记账漂移（Drift）时，传入`SYS_CLOCK_IDLE_FOREVER`，驱动可以停止时间基准。**只有调用CPU正在进入空闲**：多个CPU共享时间基准的驱动必须确保只有最后一个进入空闲的CPU才能停止时钟。

退出通知为：

```c
void sys_clock_idle_exit(void);
```

它通知驱动系统正在离开空闲，允许驱动进行恢复定时器和计算已流逝tick所需的记账。旧驱动也会借此回调`sys_clock_announce`通告过期tick；为兼容允许这样做，但不推荐，因为内核会自行确定经过的时间。

## 86.12\_已流逝刻度与禁用支持

`sys_clock_elapsed`查询从上次`sys_clock_announce`调用以来经过的tick数：

```c
uint32_t sys_clock_elapsed(void);
```

内核在已持有系统时钟锁时调用，驱动只需给出瞬时结果（Instantaneous Answer），不必再次负责该锁的获取。

`sys_clock_disable`禁用系统定时器：

```c
void sys_clock_disable(void);
```

并非所有系统定时器驱动都能禁用。可通过配置`CONFIG_SYSTEM_TIMER_HAS_DISABLE_SUPPORT`判断是否具备此能力。

## 86.13\_驱动提供的硬件周期计数

定时器驱动通常同时负责周期计数器（Cycle Counter）和tick通告。`sys_clock_cycle_get_32`通常由架构层（Architecture Layer）的`arch_k_cycle_get_32`调用；面向用户的接口归架构层所有，而非驱动。

<a id="ga42dcd1878309a82246dbfa26510f868a"></a>

```c
uint32_t sys_clock_cycle_get_32(void);
uint64_t sys_clock_cycle_get_64(void);
```

计数速率必须符合`CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC`。32位接口返回当前周期计数，应在整个32位空间单调递增，在`0xffffffff`处回绕（Wrap）。硬件定时器不足32位时，应合成一个32位计数。

64位接口与之类似，但返回`uint64_t`。并非所有硬件都具备64位计数器；仅在`CONFIG_TIMER_HAS_64BIT_CYCLE_COUNTER`启用时需要实现。它应在整个64位空间单调递增，在`2^64-1`处回绕；位数不足的硬件通常不要求实现该接口。

原文建议：如果计数时钟足够高，导致32位计数在“几秒内”回绕，应同时实现64位接口；原文给出的判断阈值为`CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC`**大于50 MHz**。

> 译注：这里保留原文的建议阈值及“几秒内”的措辞。严格的32位回绕周期为`2^32 / f`秒，其中`f`是每秒周期数；50 MHz时约为85.9秒。因此原文的阈值不是对所有超过该频率的计数器都“几秒回绕”的数学保证。

## 86.14\_应用读取硬件时钟

<a id="ga208687de625e0036558343b4e66143d3"></a>

以下两个静态内联接口来自`zephyr/kernel.h`，返回系统硬件时钟的当前递增计数，单位为周期：

```c
static inline uint32_t k_cycle_get_32(void);
static inline uint64_t k_cycle_get_64(void);
```

`k_cycle_get_64`需要`CONFIG_TIMER_HAS_64BIT_CYCLE_COUNTER`。未启用该选项时，此函数触发断言（Assert）并返回0。32位接口返回`uint32_t`，64位接口在可用时返回`uint64_t`。

## 86.15\_启动后运行时间

以下五个接口来自`zephyr/kernel.h`：

<a id="gae3e992cd3257c23d5b26d765fcbb2b69"></a>

<a id="ga9253cfb7b46af4d8994349323ce9872b"></a>

```c
int64_t k_uptime_ticks(void);
static inline int64_t k_uptime_get(void);
static inline uint32_t k_uptime_get_32(void);
static inline uint32_t k_uptime_seconds(void);
static inline int64_t k_uptime_delta(int64_t *reftime);
```

`k_uptime_ticks`返回系统启动至今的tick数，返回类型`int64_t`。tick是内核计时的基本精度单位，其频率参照`CONFIG_SYS_CLOCK_TICKS_PER_SEC`。

`k_uptime_get`返回启动至今的毫秒数。返回单位为毫秒不代表具有毫秒分辨率（Resolution），实际分辨率取决于`CONFIG_SYS_CLOCK_TICKS_PER_SEC`。

`k_uptime_get_32`返回毫秒运行时间的低32位。正确换算仍需要系统时钟的完整精度，除非能确定应用绝不会运行到系统时钟接近`2^32`个tick，否则相较`k_uptime_get`没有收益。调用可能涉及中断屏蔽（Interrupt Blocking）与64位运算。它同样不保证毫秒分辨率。

`k_uptime_seconds`返回启动至今的秒数，类型为`uint32_t`。

`k_uptime_delta`计算当前运行时间与较早参考时间之差，单位为毫秒；`reftime`指向参考时间，函数返回时把它更新为当前运行时间。返回值为经过的毫秒数。

## 86.16\_读取系统刻度

以下接口来自`zephyr/sys/clock.h`：

```c
uint32_t sys_clock_tick_get_32(void);
int64_t sys_clock_tick_get(void);
```

`sys_clock_tick_get_32`返回当前系统tick计数的低位部分，类型为`uint32_t`；`sys_clock_tick_get`返回当前系统tick计数，类型为`int64_t`。

## 86.17\_时间点与剩余超时

以下四个函数由`zephyr/sys/clock.h`提供：

```c
k_timepoint_t sys_timepoint_calc(k_timeout_t timeout);
k_timeout_t sys_timepoint_timeout(k_timepoint_t timepoint);
static inline int sys_timepoint_cmp(k_timepoint_t a, k_timepoint_t b);
static inline bool sys_timepoint_expired(k_timepoint_t timepoint);
```

<a id="ga509cf4599c1f162c97540743e8c21d33"></a>

`sys_timepoint_calc(timeout)`计算超时对象到期时对应的时间点，所依据的“现在”是**未加锁的当前时刻（Unlocked Now）**。正确用法是在用户传入一个新超时值时同步调用一次，不应反复调用它来调整超时。参数`timeout`相对于当前时间，也可以为`K_FOREVER`或`K_NO_WAIT`；返回对应时间点。相关函数为`sys_timepoint_timeout`与`sys_timepoint_expired`。

`sys_timepoint_timeout(timepoint)`返回从当前时间到所给时间点的剩余超时。时间点已经过去，或由`K_NO_WAIT`创建时，返回`K_NO_WAIT`；由`K_FOREVER`创建时，返回`K_FOREVER`。参数`timepoint`为所需剩余超时对应的时间点。需要反复更新剩余等待时应使用此函数。

`sys_timepoint_cmp(a, b)`比较两个时间点。`a`为待比较值，`b`为比较基准；相同返回0，a早于b返回负值，否则返回正值。

<a id="ga87d0d7a0f7bcdcc8c4909962eac12985"></a>

`sys_timepoint_expired(timepoint)`判断时间点是否已经过去：已过期返回`true`，否则为`false`。参数为待判断时间点，相关创建函数为`sys_timepoint_calc`。

## 86.18\_墙上时钟偏移及时间读写

以下三个函数来自`zephyr/sys/clock.h`：

```c
void sys_clock_getrtoffset(struct timespec *tp);
int sys_clock_gettime(int clock_id, struct timespec *tp);
int sys_clock_settime(int clock_id, const struct timespec *tp);
```

`sys_clock_getrtoffset(tp)`读取`SYS_CLOCK_REALTIME`相对于`SYS_CLOCK_MONOTONIC`的当前偏移，以`struct timespec`写入`tp`指向的内存。墙上时钟依赖系统设置的基准时间，可能因硬件RTC初始化、网络时间协议（Network Time Protocol，NTP）同步或应用手动调整而更新。`tp`为`NULL`时，此函数可能触发断言。

`sys_clock_gettime(clock_id, tp)`读取指定时钟的当前时间；`clock_id`为查询对象，`tp`指向结果内存。成功返回0，时钟标识无效返回`-EINVAL`。

`sys_clock_settime(clock_id, tp)`设置指定时钟时间；`clock_id`指定目标时钟，`tp`指向期望时间。成功返回0；时钟标识无效，或`tp`中的纳秒部分不在闭区间`[0, 999999999]`内，返回`-EINVAL`。

## 86.19\_基于指定时钟睡眠

`sys_clock_nanosleep`由`zephyr/sys/clock.h`提供：

```c
int sys_clock_nanosleep(int clock_id, int flags, const struct timespec *rqtp, struct timespec *rmtp);
```

调用线程以所选时钟为基准睡眠。`flags`包含`SYS_TIMER_ABSTIME`时，等待到`rqtp`给出的绝对时间；不包含该标志时，按`rqtp`给出的相对时长等待。接受的`clock_id`是`SYS_CLOCK_REALTIME`或`SYS_CLOCK_MONOTONIC`。

`rqtp`指向请求的睡眠时间；`rmtp`用于接收剩余时间。如果`rmtp`非`NULL`，且线程提前被唤醒，剩余时间写入该对象；若实际睡眠已达到请求时长，则将其置为零。`flags`是调整睡眠行为的标志。

成功返回0。时钟标识无效、请求纳秒部分不在`[0, 999999999]`内，或`rqtp`包含负值时，返回`-EINVAL`。原文没有在此列出其他错误返回。
