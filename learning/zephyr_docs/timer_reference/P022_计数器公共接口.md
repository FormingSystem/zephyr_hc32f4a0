# 第22章\_计数器公共接口

原文：[group__counter__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__counter__interface.html)。读取日期：2026-10-13，`latest`。

本页说明计数器（Counter）应用程序接口（Application Programming Interface，API），自Zephyr 1.14引入，接口版本为1.1.0。计数器可统计时钟驱动的刻度（Tick），也可统计异步事件（Asynchronous Events）。主头文件为：

```c
#include <zephyr/drivers/counter.h>
```

捕获边沿标志另定义于`zephyr/dt-bindings/counter/counter-capture.h`。设备概览见[计数器](../hardware/P017_计数器.md)，驱动实现见[后端接口](P023_计数器驱动后端接口.md)。本页下面所有函数参数`dev`均指向驱动实例的设备结构；`chan_id`表示通道ID（Channel ID），`user_data`表示用户数据。

## 22.1\_能力、告警、顶值与捕获标志

顶值（Top Value）决定回绕（Turnaround）位置，保护周期（Guard Period）用于识别绝对告警是否设置过晚。告警（Alarm）的相对值以函数调用期间读取的当前计数值为基准。
| 宏 | 原值 | 含义 |
| --- | --- | --- |
| `COUNTER_CONFIG_INFO_COUNT_UP` | `BIT(0)` | 向上计数（Count Up）能力标志。 |
| `COUNTER_TOP_CFG_DONT_RESET` | `BIT(0)` | 更新顶值时禁止复位（Do Not Reset），让计数器继续自由运行。 |
| `COUNTER_TOP_CFG_RESET_WHEN_LATE` | `BIT(1)` | 改变顶值后越过新边界时，要求计数器复位。 |
| `COUNTER_ALARM_CFG_ABSOLUTE` | `BIT(0)` | 告警刻度为绝对值（Absolute Value）；未设时相对调用期间读取的计数值。 |
| `COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE` | `BIT(1)` | 驱动发现绝对告警设置过晚时立即到期（Expire When Late），回调上下文必须与准时设置时相同。 |
| `COUNTER_GUARD_PERIOD_LATE_TO_SET` | `BIT(0)` | 标识用于检测绝对告警设置过晚的保护周期。 |
| `COUNTER_CAPTURE_CONTINUOUS` | `0` | 连续捕获（Continuous Capture），直到停止。 |
| `COUNTER_CAPTURE_SINGLE_SHOT` | `BIT(2)` | 单次捕获（Single-Shot Capture）。 |

`COUNTER_TOP_CFG_DONT_RESET`未设置时，更新顶值会复位计数器；设置时则保持自由运行。若新顶值使当前值超出边界，可用`COUNTER_TOP_CFG_RESET_WHEN_LATE`要求复位。

捕获（Capture）边沿标志位如下，供`counter_capture_configure`使用。标准标志位位于32位`counter_capture_flags_t`的低8位，高24位保留给片上系统（System on Chip，SoC）专用标志。

| 宏 | 原值 | 含义 |
| --- | --- | --- |
| `COUNTER_CAPTURE_RISING_EDGE` | `(1U << 0)` | 上升沿（Rising Edge）捕获。 |
| `COUNTER_CAPTURE_FALLING_EDGE` | `(1U << 1)` | 下降沿（Falling Edge）捕获。 |
| `COUNTER_CAPTURE_BOTH_EDGES` | `(COUNTER_CAPTURE_RISING_EDGE \| COUNTER_CAPTURE_FALLING_EDGE)` | 双边沿（Both Edges）捕获。 |

## 22.2\_配置结构与回调类型

告警参数分别见[32位告警配置](P024_计数器32位告警配置.md)和[64位告警配置](P025_计数器64位告警配置.md)，顶值参数分别见[32位顶值配置](P026_计数器32位顶值配置.md)和[64位顶值配置](P027_计数器64位顶值配置.md)。通用能力见[配置信息](P028_计数器只读配置信息.md)；`counter_capture_dt_spec`容纳设备树（Devicetree）指定的捕获信息，见[官方结构页](P033_计数器捕获设备树规格.md)。

五种回调（Callback）及捕获标志类型如下。告警回调中的`ticks`是触发告警的计数值；捕获回调中的`ticks`是触发捕获的计数值，`flags`为捕获配置标志。64位版本分别将`ticks`改为`uint64_t`。顶值回调在计数器回绕时调用，其用户数据来自`counter_set_top_value`。

```c
typedef uint32_t counter_capture_flags_t;
typedef void (*counter_capture_cb_t)(const struct device *dev, uint8_t chan_id,
                                     counter_capture_flags_t flags, uint32_t ticks,
                                     void *user_data);
typedef void (*counter_alarm_callback_t)(const struct device *dev, uint8_t chan_id, uint32_t ticks,
                                         void *user_data);
typedef void (*counter_top_callback_t)(const struct device *dev, void *user_data);
typedef void (*counter_alarm_callback_64_t)(const struct device *dev, uint8_t chan_id,
                                            uint64_t ticks, void *user_data);
typedef void (*counter_capture_cb_64_t)(const struct device *dev, uint8_t chan_id,
                                        counter_capture_flags_t flags, uint64_t ticks,
                                        void *user_data);
```

## 22.3\_按索引取得设备树捕获规格

设备树构造宏返回`struct counter_capture_dt_spec`的静态初始化器（Static Initializer）。通用参数含义如下，适用于后面所有12个构造宏。

| 参数 | 含义 |
| --- | --- |
| `node_id` | 设备树节点标识。 |
| `prop` | 小写字母与下划线形式的属性名，例如`counter_captures`。 |
| `idx` | `counter-captures`属性中的逻辑索引（Logical Index）。 |
| `name` | 节点`counter-capture-names`属性定义的元素名称，使用小写字母与下划线形式。 |
| `inst` | `DT_DRV_COMPAT`对应的实例编号（Instance Number）。 |
| `default_value` | 缺失时展开的回退值（Fallback Value）。 |

`COUNTER_CAPTURE_DT_SPEC_GET(node_id, prop)`选择属性的索引0，真实展开式为：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX(node_id, prop, 0)
```

`COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX(node_id, prop, idx)`根据节点与索引生成捕获规格：

```c
{                                                                                          \
        .dev = DEVICE_DT_GET(DT_COUNTER_CAPTURES_CTLR_BY_IDX(node_id, prop, idx)),         \
        .chan_id = (uint8_t)DT_COUNTER_CAPTURES_CHANNEL_BY_IDX(node_id, prop, idx),        \
        .flags = DT_COUNTER_CAPTURES_FLAGS_BY_IDX(node_id, prop, idx),                     \
}
```

官方设备树示例：

```dts
n: node {
    counter-captures = <&counter1 1 COUNTER_CAPTURE_RISING_EDGE>,
                       <&counter2 3 COUNTER_CAPTURE_BOTH_EDGES>;
};
```

官方用法及初始化结果：

```c
const struct counter_capture_dt_spec spec =
    COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX(DT_NODELABEL(n), counter_captures, 1);

// Initializes 'spec' to:
// {
//         .dev = DEVICE_DT_GET(DT_NODELABEL(counter2)),
//         .chan_id = 3,
//         .flags = COUNTER_CAPTURE_BOTH_EDGES,
// }
```

原示例注释的含义是：将`spec`初始化为`counter2`设备、通道3和双边沿捕获标志。**设备`dev`仍须检查就绪状态（Readiness）**，例如调用`device_is_ready()`。节点必须存在，具有`counter-captures`属性，且该属性指定计数器控制器、通道以及可选的标志；不满足这些前提却使用此宏是错误。

`COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX_OR(node_id, prop, idx, default_value)`提供默认值回退：

```c
COND_CODE_1(DT_NODE_HAS_PROP(node_id, prop),                                               \
                (COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX(node_id, prop, idx)),                  \
                (default_value))
```

节点具有相应属性时，展开为按索引获取的初始化器，此时不展开`default_value`；否则展开为默认值。返回值是对应属性的静态初始化器，或节点／属性不存在时的默认值。宏实际检查节点属性，不额外保证所给索引有效。

## 22.4\_按名称取得捕获规格

`COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME(node_id, prop, name)`根据节点标识和名称生成捕获规格：

```c
{                                                                                          \
        .dev = DEVICE_DT_GET(DT_COUNTER_CAPTURES_CTLR_BY_NAME(node_id, prop, name)),       \
        .chan_id = (uint8_t)DT_COUNTER_CAPTURES_CHANNEL_BY_NAME(node_id, prop, name),      \
        .flags = DT_COUNTER_CAPTURES_FLAGS_BY_NAME(node_id, prop, name),                   \
}
```

官方设备树示例定义`alpha`与`beta`两个名称：

```dts
n: node {
    counter-captures = <&counter1 1 COUNTER_CAPTURE_RISING_EDGE>,
                       <&counter2 3 COUNTER_CAPTURE_BOTH_EDGES>;
    counter-capture-names = "alpha", "beta";
};
```

官方用法：

```c
const struct counter_capture_dt_spec spec =
    COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME(DT_NODELABEL(n), counter_captures, alpha);

// Initializes 'spec' to:
// {
//         .dev = DEVICE_DT_GET(DT_NODELABEL(counter1)),
//         .chan_id = 1,
//         .flags = COUNTER_CAPTURE_RISING_EDGE,
// }
```

原示例注释表示：将`spec`初始化为`counter1`设备、通道1和上升沿捕获标志。与按索引形式一样，节点和属性必须存在，并指定控制器、通道及可选标志；仍需用`device_is_ready()`之类的方法检查设备就绪状态。

`COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME_OR(node_id, prop, name, default_value)`在节点具有属性时展开为按名称获取的初始化器，不展开默认值；否则使用默认值：

```c
COND_CODE_1(DT_NODE_HAS_PROP(node_id, prop),                                               \
                (COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME(node_id, prop, name)),                \
                (default_value))
```

返回值为该属性的静态初始化器，或节点／属性不存在时的默认值。名称参数应来自`counter-capture-names`；回退判断不是名称存在性检查。

## 22.5\_默认索引与驱动实例形式

以下七个入口复用前两节的参数规则与返回语义，实例形式通过`DT_DRV_INST(inst)`取得节点。

`COUNTER_CAPTURE_DT_SPEC_GET_OR(node_id, prop, default_value)`选择索引0并提供回退值：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX_OR(node_id, prop, 0, default_value)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET(inst, prop)`从驱动实例选择索引0：

```c
COUNTER_CAPTURE_DT_SPEC_GET(DT_DRV_INST(inst), prop)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET_BY_IDX(inst, prop, idx)`从驱动实例按索引获取：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX(DT_DRV_INST(inst), prop, idx)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET_BY_IDX_OR(inst, prop, idx, default_value)`从实例按索引获取，缺失节点／属性时返回默认值：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_IDX_OR(DT_DRV_INST(inst), prop, idx, default_value)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET_BY_NAME(inst, prop, name)`从实例按名称获取：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME(DT_DRV_INST(inst), prop, name)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET_BY_NAME_OR(inst, prop, name, default_value)`从实例按名称获取，缺失节点／属性时返回默认值：

```c
COUNTER_CAPTURE_DT_SPEC_GET_BY_NAME_OR(DT_DRV_INST(inst), prop, name, default_value)
```

`COUNTER_CAPTURE_DT_SPEC_INST_GET_OR(inst, prop, default_value)`从实例选索引0，缺失时使用默认值：

```c
COUNTER_CAPTURE_DT_SPEC_GET_OR(DT_DRV_INST(inst), prop, default_value)
```

这些入口的返回值同样是捕获规格的静态初始化器；带OR的入口可返回指定回退值。非OR形式仍要求属性和选择的元素有效。

> 译注：原文对`GET`、`GET_OR`、`INST_GET`、`INST_GET_OR`的“等价于”简介省略了`prop`参数；`GET_BY_IDX_OR`的部分文字展开式也遗漏`prop`。本页完整保留上面的实际展开式，并在说明中使用完整参数，避免复制出参数数量不符的调用。

## 22.6\_方向、通道数和频率

以下函数分别查询计数方向、告警通道数量及32／64位频率：

```c
bool counter_is_counting_up(const struct device *dev);
uint8_t counter_get_num_of_channels(const struct device *dev);
uint32_t counter_get_frequency(const struct device *dev);
uint64_t counter_get_frequency_64(const struct device *dev);
```

`counter_is_counting_up`向上计数时返回`true`，向下计数时返回`false`。`counter_get_num_of_channels`返回告警通道数量。

`counter_get_frequency`在原页只有签名、没有独立说明；对应后端类型说明其单位为赫兹（Hertz，Hz）。`counter_get_frequency_64`返回以Hz为单位的64位频率，若没有固定频率则返回0；关闭`CONFIG_COUNTER_64BITS_FREQ`时回退到`counter_get_frequency`。

## 22.7\_微秒、纳秒与刻度换算

输入`us`为微秒（Microsecond），`ns`为纳秒（Nanosecond）。32位结果超过可表示范围时进行饱和处理（Saturation）；64位版本返回`uint64_t`刻度。

```c
uint32_t counter_us_to_ticks(const struct device *dev, uint64_t us);
uint64_t counter_us_to_ticks_64(const struct device *dev, uint64_t us);
uint32_t counter_ns_to_ticks(const struct device *dev, uint64_t ns);
uint64_t counter_ns_to_ticks_64(const struct device *dev, uint64_t ns);
```

下面四个函数将输入刻度换算为微秒或纳秒，结果均为`uint64_t`；不带`_64`的版本接收32位刻度，带`_64`的版本接收64位刻度。

```c
uint64_t counter_ticks_to_us(const struct device *dev, uint32_t ticks);
uint64_t counter_ticks_to_us_64(const struct device *dev, uint64_t ticks);
uint64_t counter_ticks_to_ns(const struct device *dev, uint32_t ticks);
uint64_t counter_ticks_to_ns_64(const struct device *dev, uint64_t ticks);
```

## 22.8\_运行控制与当前值

`counter_start`以自由运行模式（Free-Running Mode）启动设备；`counter_stop`停止设备；`counter_reset`将计数器复位到初始值。

```c
int counter_start(const struct device *dev);
int counter_stop(const struct device *dev);
int counter_reset(const struct device *dev);
```

启动和复位成功返回0，失败返回负错误码（Negative errno）。停止成功返回0，不支持停止时返回`-ENOTSUP`。

读写当前值分别提供32位和64位形式：

```c
int counter_get_value(const struct device *dev, uint32_t *ticks);
int counter_get_value_64(const struct device *dev, uint64_t *ticks);
int counter_set_value(const struct device *dev, uint32_t ticks);
int counter_set_value_64(const struct device *dev, uint64_t ticks);
```

取得值时，`ticks`是保存当前计数值的输出指针；设置值时，`ticks`是要写入的计数值。四个函数成功均返回0，失败返回负错误码。

## 22.9\_设置和取消通道告警

下列两个函数设置单次告警（Single-Shot Alarm），`alarm_cfg`分别指向32位或64位告警配置：

```c
int counter_set_channel_alarm(const struct device *dev, uint8_t chan_id, const struct counter_alarm_cfg *alarm_cfg);
int counter_set_channel_alarm_64(const struct device *dev, uint8_t chan_id, const struct counter_alarm_cfg_64 *alarm_cfg);
```

告警到期后可再次设置，无须先禁用。调用到期处理函数时，通道已被视为可用，可在该处理上下文中再次设置。**这两个API不是线程安全的（Not Thread Safe）。**

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功。 |
| `-ENOTSUP` | 请求不受支持，例如设备不支持中断或所请求通道。 |
| `-EINVAL` | 告警设置无效。 |
| `-ETIME` | 绝对告警设置过晚。 |
| `-EBUSY` | 已有活动告警。 |

取消指定通道上的告警使用：

```c
int counter_cancel_channel_alarm(const struct device *dev, uint8_t chan_id);
```

取消接口也不是线程安全的。成功返回0；请求不受支持或计数器尚未启动时返回`-ENOTSUP`。

## 22.10\_最大顶值、当前顶值与更新

最大可设置顶值和当前顶值的查询分别提供32位与64位版本：

```c
uint32_t counter_get_max_top_value(const struct device *dev);
uint64_t counter_get_max_top_value_64(const struct device *dev);
uint32_t counter_get_top_value(const struct device *dev);
uint64_t counter_get_top_value_64(const struct device *dev);
```

前两个函数返回最大顶值，后两个返回当前顶值。启用`CONFIG_COUNTER_64BITS_TICKS`时，`counter_get_max_top_value`只返回最大顶值的低32位；若预计超出32位，必须使用`counter_get_max_top_value_64`。关闭该配置时，最大顶值64位查询回退到32位查询。

设置顶值使用：

```c
int counter_set_top_value(const struct device *dev, const struct counter_top_cfg *cfg);
int counter_set_top_value_64(const struct device *dev, const struct counter_top_cfg_64 *cfg);
```

`cfg`为配置指针，不能为`NULL`。函数设置顶值，并可根据计数方向将计数器复位到0或顶值；回绕时可复位计数器并周期性调用可选回调。**只有没有活动通道告警时才能改变顶值。**

`COUNTER_TOP_CFG_DONT_RESET`禁止复位。若计数器继续运行，更新过程中可能已越过新顶值边界；此时返回错误，并可通过`COUNTER_TOP_CFG_RESET_WHEN_LATE`要求驱动复位。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功。 |
| `-ENOTSUP` | 不支持请求，例如顶值不能改变，或更新顶值时计数器不能／必须复位而请求不相容。 |
| `-EBUSY` | 任一告警处于活动状态。 |
| `-ETIME` | 设置了`COUNTER_TOP_CFG_DONT_RESET`，且向上计数时新顶值小于当前计数值。 |

> 译注：原文在32位设置函数的警告中使用“最大顶值的低32位”和“get”措辞。这里保留其32位限制：完整64位顶值应通过`counter_set_top_value_64`设置，不能把32位设置接口当成完整64位操作。完整源码另外在顶值超过能力上限时返回`-EINVAL`，见[源码页](P031_计数器公共头文件源码.md)。

## 22.11\_保护周期与过晚判定

设置保护周期使用32位或64位刻度：

```c
int counter_set_guard_period(const struct device *dev, uint32_t ticks, uint32_t flags);
int counter_set_guard_period_64(const struct device *dev, uint64_t ticks, uint32_t flags);
```

`ticks`为保护周期长度，`flags`选择保护周期用途，当前标志为`COUNTER_GUARD_PERIOD_LATE_TO_SET`。当绝对告警值接近当前计数值，驱动激活告警之前，计数器可能已经越过目标。若未发现这一点，告警要等计数器经过一个完整周期并再次达到目标后才触发；32位计时器可能因此等待很久。

保护周期应覆盖从调用驱动API到实际激活告警所需的最大刻度数。若当前值刚越过目标且仍落在保护周期内，驱动认为设置过晚；根据`COUNTER_ALARM_CFG_EXPIRE_WHEN_LATE`，可忽略该告警或使其立即到期。若已越过目标但超出了保护周期，则视为有意等待回绕，允许计数器跨越0后再到期。

原文给出的精确判定和例子如下，比较为严格小于。公式中的 `now` 是当前计数值，`target` 是告警目标值，`top_value` 是顶值，`guard_period` 是保护周期：

| 方向 | 过晚判定 |
| --- | --- |
| 向上计数 | `(now - target) % top_value < guard_period` |
| 向下计数 | `(target - now) % top_value < guard_period` |

其余情况接受告警：目标仍在未来，或已过去足够久、被解释为有意等待下一次回绕。

| 示例 | 过晚的目标区间 | 接受的目标区间 |
| --- | --- | --- |
| 向上计数，now=4950，顶值5000，保护周期100 | [4851, 4950] | [0, 4850]或[4951, 4999] |
| 向下计数，now=50，顶值5000，保护周期100 | [50, 149] | [0, 49]或[150, 4999] |

若仅需要短告警周期，可把保护周期设得很大，例如顶值的一半，从而大幅降低无意等待完整回绕的可能。**初始化时保护周期为0，即不提供保护。** 32位和64位设置函数共享以上逻辑与例子。

设置成功返回0；功能或标志不受支持返回`-ENOSYS`；刻度值无效返回`-EINVAL`。读取保护周期使用：

```c
uint32_t counter_get_guard_period(const struct device *dev, uint32_t flags);
uint64_t counter_get_guard_period_64(const struct device *dev, uint32_t flags);
```

`flags`含义相同。返回值单位为计数刻度；不支持该函数或标志时返回0。关闭`CONFIG_COUNTER_64BITS_TICKS`时，64位保护周期读取回退到32位版本。

## 22.12\_待处理中断

下面的函数取得待处理中断（Pending Interrupt）状态，其目的是读取设备的中断状态寄存器，特别适合从低功耗状态唤醒后检查唤醒源（Wake-up Source）。

```c
uint32_t counter_get_pending_int(const struct device *dev);
```

原文规定：有任意计数器中断待处理返回1，没有则返回0。

## 22.13\_计数器校准

下列函数仅在启用Kconfig选项`CONFIG_COUNTER_CALIBRATION`时可用：

```c
int counter_set_calibration(const struct device *dev, int32_t calibration);
int counter_get_calibration(const struct device *dev, int32_t *calibration);
```

校准（Calibration）以十亿分率（Parts Per Billion，ppb）表示：正值加快计数器，负值减慢计数器。设置时`calibration`是输入值；读取时是保存结果的输出指针。

两者成功返回0，驱动不支持时返回`-ENOSYS`。设置函数在校准值超出范围时还返回`-EINVAL`。
