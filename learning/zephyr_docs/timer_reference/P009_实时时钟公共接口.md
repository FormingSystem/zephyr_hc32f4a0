# 第9章\_实时时钟公共接口

原文：[group__rtc__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__rtc__interface.html)。读取日期：2026-10-13，`latest`。

本页说明实时时钟（Real-Time Clock，RTC）的应用程序接口（Application Programming Interface，API），自Zephyr 3.4引入，接口版本为0.1.0。日期和时间由支持亚秒精度（Sub-second Precision）的`rtc_time`结构存储，见[时间结构](P011_实时时钟时间结构.md)。头文件为：

```c
#include <zephyr/drivers/rtc.h>
```

## 9.1\_设置与读取时间

两个函数的`dev`均为设备实例。`rtc_set_time`从`timeptr`读取待设置的时间；`rtc_get_time`向`timeptr`写入读取结果。

```c
int rtc_set_time(const struct device *dev, const struct rtc_time *timeptr);
int rtc_get_time(const struct device *dev, struct rtc_time *timeptr);
```

成功均返回0，其他失败返回负错误码（Negative errno）。设置时`-EINVAL`表示时间无效或超出硬件能力；读取时`-ENODATA`表示RTC时间尚未设置。

## 9.2\_闹钟时间掩码

闹钟（Alarm）的字段掩码（Field Mask）选择设置闹钟时启用哪些时间字段。九个位的定义如下：
| 掩码宏 | 原值 | 匹配字段 |
| --- | --- | --- |
| `RTC_ALARM_TIME_MASK_SECOND` | `BIT(0)` | 秒（Second） |
| `RTC_ALARM_TIME_MASK_MINUTE` | `BIT(1)` | 分（Minute） |
| `RTC_ALARM_TIME_MASK_HOUR` | `BIT(2)` | 小时（Hour） |
| `RTC_ALARM_TIME_MASK_MONTHDAY` | `BIT(3)` | 月内日期（Day of Month） |
| `RTC_ALARM_TIME_MASK_MONTH` | `BIT(4)` | 月（Month） |
| `RTC_ALARM_TIME_MASK_YEAR` | `BIT(5)` | 年（Year） |
| `RTC_ALARM_TIME_MASK_WEEKDAY` | `BIT(6)` | 星期（Day of Week） |
| `RTC_ALARM_TIME_MASK_YEARDAY` | `BIT(7)` | 年内日序（Day of Year） |
| `RTC_ALARM_TIME_MASK_NSEC` | `BIT(8)` | 纳秒（Nanosecond） |

要启用闹钟，至少应启用一个字段。只有所有已启用字段均与RTC当前时间匹配时，闹钟才触发。

## 9.3\_查询闹钟支持的字段

此函数查询指定闹钟支持哪些时间字段：

```c
int rtc_alarm_get_supported_fields(const struct device *dev, uint16_t id, uint16_t *mask);
```

`dev`为设备实例，`id`为闹钟ID，`mask`接收所支持字段的位掩码，各位由上一节宏定义。成功返回0；硬件不支持此API时返回`-ENOTSUP`，其他失败返回负错误码。

原文还将`-EINVAL`描述为“ID超出范围或时间无效”。本函数没有时间输入参数，译文保留这一原始描述，不擅自删改返回说明。

## 9.4\_设置与读取闹钟时间

下列两个函数分别设置和取得闹钟时间：

```c
int rtc_alarm_set_time(const struct device *dev, uint16_t id, uint16_t mask, const struct rtc_time *timeptr);
int rtc_alarm_get_time(const struct device *dev, uint16_t id, uint16_t *mask, struct rtc_time *timeptr);
```

设置函数中，`dev`为设备实例，`id`选择闹钟，`mask`指定启用字段，`timeptr`指向要设置的闹钟时间。只需要配置掩码启用的字段。**`mask`为0时禁用闹钟，此时`timeptr`可以为`NULL`。**

读取函数中，`mask`是接收已启用字段掩码的输出指针，`timeptr`是接收闹钟时间的输出指针，`dev`与`id`含义相同。

两者成功返回0，硬件不支持该API返回`-ENOTSUP`，其他失败返回负错误码。设置函数的`-EINVAL`表示ID超出范围或时间无效；读取函数的`-EINVAL`表示ID超出范围。

## 9.5\_回调类型

RTC定义更新事件回调（Update Event Callback）与闹钟触发回调（Alarm Triggered Callback）：

```c
typedef void (*rtc_update_callback)(const struct device *dev, void *user_data);
typedef void (*rtc_alarm_callback)(const struct device *dev, uint16_t id, void *user_data);
```

两者的`dev`均为调用处理函数的设备实例。`rtc_update_callback`接收设置更新中断回调时提供的可选用户数据`user_data`；`rtc_alarm_callback`还接收闹钟ID`id`，其可选用户数据来自闹钟回调配置。

## 9.6\_闹钟回调与待处理状态

设置闹钟回调使用：

```c
static inline int rtc_alarm_set_callback(const struct device *dev, uint16_t id, rtc_alarm_callback callback, void *user_data);
```

`dev`为设备实例，`id`指定闹钟，`callback`为触发时调用的函数，`user_data`为可选用户数据。设置回调会启用回调；此后闹钟触发时调用回调，随后自动清除待处理状态（Pending Status）。**闹钟本身保持启用，直到用`rtc_alarm_set_time`手动禁用。**

要禁用闹钟回调，必须同时将`callback`与`user_data`设置为`NULL`。禁用回调后，闹钟触发会把状态置为待处理；可用下面的函数检查：

```c
int rtc_alarm_is_pending(const struct device *dev, uint16_t id);
```

`dev`是设备实例，`id`指定待检查的闹钟。如果闹钟处于待处理状态，本次检查会清除该状态。原先待处理返回1，原先不待处理返回0。

这两个函数均在ID超出范围时返回`-EINVAL`，硬件不支持API时返回`-ENOTSUP`，其他失败返回负错误码；设置回调成功返回0。轮询函数的1表示检测到了事件，不是失败。

## 9.7\_每秒更新回调

下列函数设置RTC更新回调：

```c
static inline int rtc_update_set_callback(const struct device *dev, rtc_update_callback callback, void *user_data);
```

`dev`为设备实例，`callback`在更新事件发生时调用，`user_data`是可选用户数据。设置后启用回调，RTC时钟每更新1秒便调用一次，可用于将RTC与其他时钟源同步。

禁用更新回调时，必须同时将`callback`和`user_data`设为`NULL`。成功返回0，硬件不支持API返回`-ENOTSUP`，其他失败返回负错误码。

## 9.8\_设置与读取校准

校准（Calibration）作用于RTC时钟输入：正校准值提高时钟频率，负校准值降低时钟频率。校准值单位是十亿分率（Parts Per Billion，ppb）。

```c
int rtc_set_calibration(const struct device *dev, int32_t calibration);
int rtc_get_calibration(const struct device *dev, int32_t *calibration);
```

`dev`为设备实例。设置函数接收待设置值`calibration`，读取函数通过同名指针输出校准值。成功均返回0，不受硬件支持返回`-ENOTSUP`，其他失败返回负错误码。设置函数还在校准值超出范围时返回`-EINVAL`。

以下辅助函数根据频率计算将RTC校准到1赫兹（Hertz，Hz）所需的校准量：

```c
static inline int32_t rtc_calibration_from_frequency(uint32_t frequency);
```

输入`frequency`的单位是**纳赫兹（Nanohertz，nHz）**，返回值单位是ppb；不能把输入当作普通Hz数值。原源码还对输入大于0进行断言，见[完整源码](P014_实时时钟公共头文件源码.md)。

## 9.9\_标准时间库辅助函数与相关接口

辅助函数`rtc_time_to_tm`可安全地将`rtc_time`指针转换为标准时间结构`tm`指针：

```c
static inline struct tm *rtc_time_to_tm(struct rtc_time *timeptr);
```

结构布局说明见[时间结构](P011_实时时钟时间结构.md)。驱动实现者参见[后端接口](P010_实时时钟驱动后端接口.md)与[驱动操作结构](P012_实时时钟驱动操作结构.md)。原文的其他主题为[器件专用扩展](P015_实时时钟器件扩展入口.md)与[伪RTC驱动（Fake RTC）](../hardware/P497_RTC伪设备接口.md)。
