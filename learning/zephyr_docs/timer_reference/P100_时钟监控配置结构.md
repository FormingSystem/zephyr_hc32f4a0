# 第100章\_时钟监控配置结构

原文：[structclock__monitor__config](https://docs.zephyrproject.org/latest/doxygen/html/structclock__monitor__config.html)。读取日期：2026-10-13，`latest`。

结构体`clock_monitor_config`是交给`clock_monitor_configure`的顶层配置（Top-level Configuration），头文件为`zephyr/drivers/clock_monitor.h`。

## 100.1\_结构声明

```c
struct clock_monitor_config {
        enum clock_monitor_mode mode;
        union {
                struct clock_monitor_window_cfg window;
                struct clock_monitor_measure_cfg measure;
        };
        clock_monitor_callback_t callback;
        void *user_data;
};
```

## 100.2\_模式参数与回调成员

| 成员 | 类型 | 含义 |
| --- | --- | --- |
| `mode` | `enum clock_monitor_mode` | 要激活的运行模式（Operating Mode） |
| `window` | `struct clock_monitor_window_cfg` | 匿名联合体（Anonymous Union）成员；仅在 WINDOW 窗口模式下采用 |
| `measure` | `struct clock_monitor_measure_cfg` | 匿名联合体成员；仅在 MEASURE 测量模式下采用 |
| `callback` | `clock_monitor_callback_t` | 异步事件投递（Asynchronous Event Delivery）的可选回调 |
| `user_data` | `void *` | 传给回调的用户不透明指针（Opaque Pointer） |

匿名联合体中的参数由`mode`选择。窗口配置见[时钟监控频率窗口结构](P102_时钟监控频率窗口结构.md)，测量配置见[时钟频率测量配置结构](P101_时钟频率测量配置结构.md)。

## 100.3\_事件投递与轮询

回调（Callback）及其`user_data`与其他配置一起原子地安装（Atomically Install）。回调是**唯一的事件投递路径**。

传入`callback = NULL`会禁用事件投递；在 MEASURE 模式下，最近结果仍可通过`clock_monitor_get_rate`轮询（Polling）取得。回调类型和事件载荷生命周期见[时钟监控公共接口](P098_时钟监控公共接口.md)；完整原始声明见[时钟监控完整头文件](P106_时钟监控完整头文件.md)。
