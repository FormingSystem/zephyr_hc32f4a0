# 第25章\_计数器64位告警配置

原文：[structcounter__alarm__cfg__64](https://docs.zephyrproject.org/latest/doxygen/html/structcounter__alarm__cfg__64.html)。读取日期：2026-10-13，`latest`。

结构体`counter_alarm_cfg_64`配置计数器（Counter）的64位告警（Alarm）回调，定义于：

```c
#include <zephyr/drivers/counter.h>
```

## 25.1\_完整字段

字段顺序和类型按原页保留。

| 类型 | 字段 | 含义 |
| --- | --- | --- |
| `uint64_t` | `ticks` | 触发告警的计数刻度（Tick）值。 |
| `counter_alarm_callback_64_t` | `callback` | 告警发生时调用的回调（Callback），**不能为NULL**。 |
| `void *` | `user_data` | 通过回调返回的用户数据。 |
| `uint32_t` | `flags` | 告警标志（Alarm Flags），见公共接口的COUNTER_ALARM_CFG_*。 |

## 25.2\_刻度范围与设置过晚的风险

`ticks`既可为相对当前读数的值（Relative Value），也可为绝对值（Absolute Value），由`COUNTER_ALARM_CFG_ABSOLUTE`选择。相对与绝对告警值都可以位于0到当前顶值（Top Value）之间。

如果绝对告警值接近当前值，驱动真正激活告警前，计数器可能已经越过该值。可以定义保护周期（Guard Period），让驱动明确判断是否设置过晚，详见[公共接口的保护周期](P022_计数器公共接口.md)。

若计数器由时钟驱动，刻度可转换为微秒（Microsecond）；计数器实现也可能统计异步事件（Asynchronous Events），不能默认每个计数器都有固定时间频率。原页交叉引用`counter_get_top_value`、`counter_set_guard_period`和`counter_ticks_to_us`。

> 译注：原64位结构页的交叉引用仍使用上述不带`_64`的名称；完整64位值应对照[公共接口](P022_计数器公共接口.md)中的相应64位版本，不能因此截断64位刻度。
