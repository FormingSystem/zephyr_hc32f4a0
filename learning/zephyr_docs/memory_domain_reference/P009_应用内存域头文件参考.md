## 9.2\_源码定位与版本边界

源码定位：[include/zephyr/app_memory/app_memdomain.h](../../../include/zephyr/app_memory/app_memdomain.h)、[scripts/build/gen_app_partitions.py](../../../scripts/build/gen_app_partitions.py)、[include/zephyr/linker/app_smem.ld](../../../include/zephyr/linker/app_smem.ld)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位采用相对链接；未把源码对照视为目标板已启用用户模式或完成MPU／MMU隔离测试。

> 译注——源码核对：K_APPMEM_PARTITION_DEFINE定义分区描述和链接元数据，K_APP_DMEM／BMEM将全局变量放入指定段；这些宏不会自动调用k_mem_domain_add_partition，也不会把线程自动加入某个域。定义、链接布局和运行时授权是三个步骤。

> 译注——源码核对：本次宏使用K_MEM_PARTITION_P_RW_U_RW作为分区属性。Z_APP_SIZE和Z_APP_BSS_SIZE对应链接器符号的数值，宏通过取地址取得长度，不是在解引用某个char数组来读取大小；不要把这些符号改写为普通运行时数组。

> 译注——源码核对：gen_app_partitions.py扫描目标文件或库中的分区段并生成链接内容；链接器把分区的数据与BSS区域及其边界符号组织起来。内核用户空间初始化随后按z_app_region记录清零BSS，带初值的数据段与零初始化段不能混为同一种初始化。

> 译注——源码核对：官方正文把类型拼为k_mem_paritition，实际C类型为k_mem_partition。原文还说占位char变量；当前Z_APPMEM_PLACEHOLDER实现使用内联汇编生成无数据符号，目的是让空分区也能被扫描器发现。两处原始措辞保留，并在此说明源码差异。

> 译注——源码核对：未启用CONFIG_USERSPACE时，本次K_APP_DMEM与K_APP_BMEM为空标记、段名称退回.data／.bss、K_APPMEM_PARTITION_DEFINE为空展开。这使代码可按配置编译，不意味着非用户模式配置仍提供同样的内存域隔离。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
