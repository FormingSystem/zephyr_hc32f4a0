### `k_mem_domain_add_partition()`

```c
int k_mem_domain_add_partition ( struct k_mem_domain * domain, struct k_mem_partition * part )
```

```c
#include <zephyr/app_memory/mem_domain.h>
```

向内存域添加内存分区。

向内存域添加内存分区。分区必须满足以下约束：

- 同一内存域中的分区不得互相重叠。
- 不得定义会暴露内核私有数据结构或内核对象的分区。
- 起始地址对齐与分区大小必须符合底层内存管理硬件的约束，这些约束随架构而异。
- 内存域分区只用于控制用户模式线程对内存的访问。
- 若启用 `CONFIG_EXECUTE_XOR_WRITE`，分区不得同时允许写入和执行。

违反这些约束可能导致 CPU 异常或未定义行为（Undefined Behavior）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `domain` | 要添加分区的内存域。 |
| `part` | 待添加的内存分区。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时。 |
| `-EINVAL` | 提供的参数无效时。 |
| `-ENOSPC` | 没有可用分区槽位（Partition Slot）时。 |

<a id="ga8a987bc85c02925685fe87213fe26c5a"></a>

### `k_mem_domain_init()`

```c
int k_mem_domain_init ( struct k_mem_domain * domain, uint8_t num_parts, struct k_mem_partition * parts[] )
```

```c
#include <zephyr/app_memory/mem_domain.h>
```

初始化内存域。

使用给定名称和内存分区初始化内存域。

有关分区约束的详细说明，参阅 `k_mem_domain_add_partition()` 文档。

不得对同一内存域多次调用 `k_mem_domain_init()`，否则属于未定义行为。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `domain` | 要初始化的内存域。 |
| `num_parts` | `parts` 参数中的数组元素数量。 |
| `parts` | 指向各内存分区的指针数组。`num_parts` 为零时可以为 `NULL`。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功时。 |
| `-EINVAL` | 提供的参数无效时。 |
| `-ENOMEM` | 内存不足时。 |

<a id="ga3613abdb546a66059fa3f621a2ebd41a"></a>

### `k_mem_domain_default`

```c
struct k_mem_domain k_mem_domain_default
```

声明属性：`extern`。

```c
#include <zephyr/app_memory/mem_domain.h>
```

默认内存域（Default Memory Domain）。

所有线程都属于某个内存域，即使线程运行在监督模式（Supervisor Mode）。若线程没有被加入其他域，也没有继承其他域的成员关系，则属于此默认内存域。

若 C 库的 `z_libc_partition` 分区存在，则会将它加入此内存域。

## 1.8\_源码定位与版本边界

源码定位：[include/zephyr/app_memory/mem_domain.h](../../../include/zephyr/app_memory/mem_domain.h)、[kernel/userspace/mem_domain.c](../../../kernel/userspace/mem_domain.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位采用相对链接；未把源码对照视为目标板已启用用户模式或完成MPU／MMU隔离测试。

> 译注——源码核对：内存域（Memory Domain）描述用户线程可访问的内存区域，不等于进程地址空间或动态内存分配器。把线程加入域不分配RAM，也不自动授予内核对象权限；内存访问策略与对象权限是不同机制。监督模式线程的域成员关系仍会被子线程继承。

> 译注——源码核对：当前实现添加分区时复制start、size和attr到域内部数组，而不是长期保存传入的分区描述指针。之后修改原描述结构不会自动更新域内副本；移除操作按起始地址和大小匹配分区，不按描述结构指针身份匹配。内存区本体的生命周期仍须覆盖线程使用期。

> 译注——源码核对：配置中的CONFIG_MAX_DOMAIN_PARTITIONS规定结构数组容量，运行时还从架构取得max_partitions。实际可用槽位可能更少，不能仅按数组长度判断硬件映射资源充足。初始化或添加前仍必须满足不重叠、对齐、大小和权限约束，不能依赖所有配置都以相同运行时检查拒绝错误参数。

> 译注——源码核对：当前通用代码拒绝零长度和地址加长度回绕的分区；CONFIG_EXECUTE_XOR_WRITE启用时会检查可写且可执行属性。该检查不能代替架构对齐或MPU粒度要求，也不是自动识别内核私有数据的扫描器；暴露哪些内容仍是调用者必须满足的约束。

> 译注——源码核对：k_mem_domain_deinit仅在CONFIG_ARCH_MEM_DOMAIN_SUPPORTS_DEINIT支持时执行，否则返回-ENOTSUP；默认域不能反初始化，仍有关联线程时返回-EBUSY。它不会替调用者把线程自动迁移到默认域。架构反初始化失败在当前通用包装中映射为-ENOMEM。

> 译注——源码核对：k_mem_domain_init原文提到“给定名称”，但函数实际参数只有域指针、分区数量和分区指针数组，没有名称字符串。正文按原文保留；不要据这句描述额外添加参数。重复初始化同一域的禁止约束仍需遵守。

> 译注——源码核对：部分操作先更新域的软件描述再调用架构钩子，失败时不能笼统假定所有状态已经自动回滚。当前接口不是对多个线程和分区批量变更提供事务保证；需要按实际返回码和所选架构处理失败。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
