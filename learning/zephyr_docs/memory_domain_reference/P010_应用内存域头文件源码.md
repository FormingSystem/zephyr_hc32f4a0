## 10.2\_可见注释译文（Comments）

1. 版权与许可证：Copyright (c) 2019 Intel Corporation；SPDX-License-Identifier: Apache-2.0。原始法律声明保留。

2. 若使用K_APPMEM_PARTITION声明分区但从未向其中分配数据，则符号表中不会出现带该前缀的符号，gen_app_partitions.py无法检测该分区，分区边界链接器符号也不会生成，从而导致构建错误。此内联汇编定义一个不占数据的符号，应适用于产生ELF二进制的各架构，相关依据见原注释中的GNU汇编器段文档。由于不知道被压入段原先的标志和类型，因此明确指定：aw表示可分配且可写，@progbits表示段含有数据。

3. ARM将@解释为注释起始，因此必须向汇编器传入%progbits。

4. CONFIG_USERSPACE条件分支结束。

5. ZEPHYR_INCLUDE_APP_MEMORY_APP_MEMDOMAIN_H_头文件包含保护结束。

## 10.4\_源码跟踪译注

> 译注——K_APPMEM_PARTITION_DEFINE定义分区描述和链接元数据，K_APP_DMEM／BMEM将全局变量放入指定段；这些宏不会自动调用k_mem_domain_add_partition，也不会把线程自动加入某个域。定义、链接布局和运行时授权是三个步骤。

> 译注——本次宏使用K_MEM_PARTITION_P_RW_U_RW作为分区属性。Z_APP_SIZE和Z_APP_BSS_SIZE对应链接器符号的数值，宏通过取地址取得长度，不是在解引用某个char数组来读取大小；不要把这些符号改写为普通运行时数组。

> 译注——gen_app_partitions.py扫描目标文件或库中的分区段并生成链接内容；链接器把分区的数据与BSS区域及其边界符号组织起来。内核用户空间初始化随后按z_app_region记录清零BSS，带初值的数据段与零初始化段不能混为同一种初始化。

> 译注——官方正文把类型拼为k_mem_paritition，实际C类型为k_mem_partition。原文还说占位char变量；当前Z_APPMEM_PLACEHOLDER实现使用内联汇编生成无数据符号，目的是让空分区也能被扫描器发现。两处原始措辞保留，并在此说明源码差异。

> 译注——未启用CONFIG_USERSPACE时，本次K_APP_DMEM与K_APP_BMEM为空标记、段名称退回.data／.bss、K_APPMEM_PARTITION_DEFINE为空展开。这使代码可按配置编译，不意味着非用户模式配置仍提供同样的内存域隔离。

头文件定位：[include/zephyr/app_memory/app_memdomain.h](../../../include/zephyr/app_memory/app_memdomain.h)，关联实现／接口：[scripts/build/gen_app_partitions.py](../../../scripts/build/gen_app_partitions.py)；[官方原始头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/app_memory/app_memdomain.h)与[官方关联文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/scripts/build/gen_app_partitions.py)的摘要见来源记录。去掉注释和展示空白后，本页代码与本次读取的原始头文件一致，不能推广到以后滚动更新的main或任意本地版本。
