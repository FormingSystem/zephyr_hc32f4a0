# 第4章\_内存域结构

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structk__mem__domain.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：从[本册大纲](大纲.md)进入内存域、内存分区与应用分区接口参考，再通过接口链接进入完整说明。源码跟踪译注与官方原文分开标示。

内存域（Memory Domain）。

```c
#include <zephyr/app_memory/mem_domain.h>
```

<a id="details"></a>

内存域是内存分区的集合，用于表示用户线程对线性地址空间（Linear Address Space）的访问策略。一个线程只能属于一个内存域，而一个内存域可以包含多个线程。监督模式线程也可以属于内存域；这不影响其内存访问，但具有实际用途，因为子线程会继承父线程的内存域成员关系。用户线程所属内存域即使没有活动分区，仍保证可以访问自身栈缓冲区、程序代码和只读数据。

源码定位：[include/zephyr/app_memory/mem_domain.h](../../../include/zephyr/app_memory/mem_domain.h)、[kernel/userspace/mem_domain.c](../../../kernel/userspace/mem_domain.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码定位采用相对链接；未把源码对照视为目标板已启用用户模式或完成MPU／MMU隔离测试。

> 译注——源码核对：k_mem_domain中的num_partitions是活动分区数量，不是整个结构的字节大小。移除操作把槽位size置零，数组中可能有空槽；应用不应绕过API直接修改这些字段或仅凭数量自行重建硬件配置。arch和线程链表成员由配置控制，不能假定结构布局在不同构建中固定。

> 译注——源码核对：内存域（Memory Domain）描述用户线程可访问的内存区域，不等于进程地址空间或动态内存分配器。把线程加入域不分配RAM，也不自动授予内核对象权限；内存访问策略与对象权限是不同机制。监督模式线程的域成员关系仍会被子线程继承。
