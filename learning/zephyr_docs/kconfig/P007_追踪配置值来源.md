# 第7章\_追踪配置值来源

原文：[Tracing values to their source](https://docs.zephyrproject.org/latest/build/kconfig/tracing.html)。读取日期：2026-10-12，`latest`。

构建目录中的 `zephyr/.config` 保存把用户配置应用到整棵 Kconfig 定义树后的合并结果。当某些不可见符号被其他位置的规则隐式选中时，最终值的来源很难直接从配置文件看清。

`traceconfig` **构建目标（Build Target）**会生成说明每个符号最终值如何产生的报告，用于追踪赋值、默认值与选择关系。

## 7.1\_生成来源追踪报告

按常规方法构建 Zephyr 应用后，可执行：

```sh
west build -t traceconfig
```

或者直接调用 Ninja：

```sh
ninja traceconfig
```

> 译注：第一条在能够定位该应用构建目录的 Bash 环境执行，非默认目录时给 west 指定已有构建目录；第二条需先进入那个含 `build.ninja` 的构建目录。两者是替代方式，不是必须顺序执行。这里调用报告目标，不会替读者安装工具或初始化工作区。

**原文注意：**来源信息只有在干净构建上才有意义。否则既有 `.config` 会把配置固定在特定值，参见[配置符号卡住](https://docs.zephyrproject.org/latest/build/kconfig/tips.html#stuck-symbols)。因此，建议生成追踪前进行一次[干净构建（Pristine Build）](https://docs.zephyrproject.org/latest/develop/west/build-flash-debug.html#west-building-pristine)。

报告生成在构建目录的 `zephyr/kconfig-trace.md`。它使用 Markdown 表格、突出显示和可点击链接，在**集成开发环境（Integrated Development Environment，IDE）**中较方便阅读，也可以直接用文本编辑器查看。

## 7.2\_区分三类符号

报告分为：

1. **可见符号（Visible Symbols）**。
2. **不可见符号（Invisible Symbols）**。
3. **未设置符号（Unset Symbols）**。

前两节用表格展示符号类型、名字和当前值；第四列说明是哪类语句产生了该值，第五列给出来源位置或表达式。

## 7.3\_理解值的来源

| 来源标签 | 产生方式 | 位置列内容 |
| --- | --- | --- |
| `assigned`，显式赋值 | 从配置文件读取 `CONFIG_xxx=y` 等明确设置。 | 文件名及行号。 |
| `default`，默认值 | 没有用户赋值，使用 Kconfig 定义树中适用的默认值。 | 原文说明为相应默认语句的位置。 |
| `selected`，被选择 | 另一个符号的 `select` 使当前符号被设置。 | 导致设置的表达式。 |
| `implied`，被建议启用 | 另一个符号的 `imply` 使当前符号被设置。 | 导致设置的表达式。 |

最后一节仅列出未通过上述方式获得设置的符号，因此没有额外来源信息。

> 译注：原文最后使用“undefined”描述这组内容，但报告标题是 `Unset symbols`，不应据此理解为符号在 Kconfig 文件中根本没有定义。源码 `scripts/kconfig/traceconfig.py` 还会将没有具体位置的隐式默认标为 `(implicit)`，并不保证每个默认都能显示一个显式语句行号。报告帮助定位配置来源，实际依赖语义仍需结合[技巧与最佳实践](P004_Kconfig技巧与最佳实践.md)判断。本次没有执行干净构建或生成应用追踪报告。
