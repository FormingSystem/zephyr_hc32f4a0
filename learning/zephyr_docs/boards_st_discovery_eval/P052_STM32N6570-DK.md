## 概述（Overview）

STM32N6570_DK Discovery套件是基于Arm Cortex-M55的STM32N657X0H3Q完整演示及开发平台。

STM32N6570_DK提供丰富硬件，可评估USB Type-C、Octo-SPI Flash、十六线SPI PSRAM、以太网、摄像头模块、LCD、microSD、音频编解码器、数字麦克风、ADC、灵活扩展接口及用户按键。4个灵活扩展连接器便于针对无线连接、模拟应用及传感器等场景扩展。

STM32N657X0H3Q具有1路USB 2.0高速／全速设备、主机及OTG控制器，另有1路带UCPD的同类USB控制器；1路支持TSN的以太网；4路I2C、2路I3C、6路SPI，其中4路支持I2S；2路SAI，支持4个数字麦克风DMIC；5路USART、5路UART，支持原文所写ISO78916、LIN、IrDA及最高12.5 Mbit/s；1路LPUART；2路SDMMC，支持MMC 4.0、CE-ATA 1.0及SD 1.0.1；3路支持TTCAN的CAN FD；JTAG、SWD及嵌入式跟踪宏单元ETM。

STM32N6570_DK集成STLINK-V3EC在线调试器／编程器及USB虚拟COM桥接，并配套完整MCU软件包。

## 硬件（Hardware）


- VFBGA264封装STM32N657X0H3Q，采用Arm Cortex-M55，具有ST Neural-ART加速器、H.264编码器、NeoChrom 2.5D GPU及4.2 Mbytes连续SRAM
- 5英寸LCD模块，带电容触摸面板
- USB Type-C带USB 2.0高速接口，支持双电源角色DRP
- USB Type-A带USB 2.0高速主机接口，最大0.5 A
- 符合IEEE-802.3-2002的1 Gbit以太网，支持时间敏感网络TSN
- SAI音频编解码器（Codec）
- 1个MEMS数字麦克风
- 1 Gbit Octo-SPI Flash
- 256 Mbit十六线SPI PSRAM
- 两个用户LED
- 用户、防篡改及复位按键
- 开发板连接器（Board Connectors）：


  - USB Type-C®接口
  - USB Type-A接口
  - 以太网RJ45接口
  - 摄像头模块
  - MicroSD卡
  - 液晶显示屏（LCD）
  - 立体声耳机插孔，带模拟麦克风输入
  - 音频MEMS子板扩展连接器
  - Arduino Uno R3扩展连接器
  - STMod+扩展连接器
- 板载STLINK-V3EC调试器／编程器，支持USB重新枚举为虚拟COM端口及调试端口

STM32N6570-DK内置ST Neural-ART神经处理单元（NPU），面向节能的边缘AI应用，例如以独立Zephyr应用形式提供的[Zephyr计算机视觉应用](https://github.com/stm32-hotspot/zephyr-stm32n6-ai-people-detection)。

<a id="ethernet"></a>

### 以太网（Ethernet）

STM32N6570-DK具有1 Gbit以太网接口，通过RGMII连接外部PHY。

片上一次性可编程存储器（OTP）中有一块区域用于以太网MAC地址。制造时该区域未编程，读取值全为0，须在现场用[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)编程。

若要在应用中使用OTP的MAC_ADDR1地址，添加以下设备树覆盖（Overlay）：

```text
&mac {
    nvmem-cells = <&mac_address0>;
    nvmem-cell-names = "mac-address";
};
```

警告（Warning）

若片上OTP尚未编程，则使用该覆盖后以太网无法工作，因为会将全0的OTP值作为MAC地址，而00:00:00:00:00:00不是有效MAC地址。

为便于运行Zephyr网络示例且无需对器件进行不可逆编程，STM32以太网驱动默认根据器件唯一ID生成本地管理MAC地址（Locally Administered MAC Address）。

<a id="board-variants"></a>

## 开发板变体（Board Variants）

STM32N6570_DK提供3种变体：


- 主应用为默认变体，由启动加载器链式加载，可访问全部AXISRAM1及AXISRAM2区域；要求使用--sysbuild构建。
- fsbl：第一阶段启动加载器（First Stage Boot Loader，FSBL），由Boot ROM加载，通过ST-Link烧录，通常是启动加载器镜像。它以RAM LOAD模式在AXISRAM2后半部分运行，整个镜像可用511K空间。
- sb：第一阶段启动加载器的串行启动（Serial Boot）变体。与FSBL镜像等效，但可通过USB加载且无需切换启动引脚，因此更便于开发。

<a id="flashing-or-loading"></a>

### 烧录或加载（Flashing or Loading）

开发板配置为使用west的[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)运行工具（Runner）编程，须安装[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html) 2.18.0或更高版本。（[installation](https://docs.zephyrproject.org/latest/develop/flash_debug/host-tools.html#stm32cubeprog-flash-host-tools)）

注意（Note）

固件在安全执行模式（Secure Mode）下运行，需要签名。构建结束后，构建系统会自动使用[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)的STM32_SigningTool_CLI工具生成签名二进制文件。该工具随[STM32CubeProgrammer](https://www.st.com/en/development-tools/stm32cubeprog.html)安装，但必须确认它已加入PATH。

开发板编程有两种选择：


- 将固件写入外部Flash；启动时再加载到RAM并从RAM执行。
- 也可使用启动ROM提供的串行启动接口（Serial Boot Interface），直接将固件加载到RAM执行；该方式不会将固件保留在非易失存储器中。
