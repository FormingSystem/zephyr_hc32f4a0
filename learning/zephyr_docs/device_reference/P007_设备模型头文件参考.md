```c
const STRUCT_SECTION_ITERABLE(Z_DEVICE_API_TYPE(_class), _name)
```

用于在可遍历段（Iterable Section）中声明设备API结构的包装宏。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_class` | 设备API类别。 |
| `_name` | API实例名称。 |

> 译注——源码核对：_class会拼接成_class_driver_api结构类型。该宏定义可遍历段中的const API操作表实例，设备对象需要通过其api成员引用此表；它不创建设备对象、不调用初始化函数，也不自动把普通任意地址变成合法接口表。

<a id="a2b0530c13706c66229d35977c6553db9"></a>

### `DEVICE_API_EXTENDS`

```c
#define DEVICE_API_EXTENDS ( _child, _parent, _member )
```

展开值（Value）：

```c
CONTAINER_OF_VALIDATE((struct Z_DEVICE_API_TYPE(_parent) *)0,                              \
                      struct Z_DEVICE_API_TYPE(_child), _member)                           \
BUILD_ASSERT(offsetof(struct Z_DEVICE_API_TYPE(_child), _member) == 0,                     \
             "Parent API struct must be the first member of child API struct")
```

声明API类_child是设备API类_parent的扩展（Extension）。

登记父子关系（Parent–Child Relationship），使DEVICE_API_IS(_parent, dev)对API属于_child类别的设备返回true。父API结构必须是子API结构的第一个成员。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_child` | 子API类别（扩展类别）的名称。 |
| `_parent` | 父API类别（基类）的名称。 |
| `_member` | _child API类别结构的第一个成员名称。此成员的类型必须与_parent API类别结构相同。 |

> 译注——源码核对：当前宏借助CONTAINER_OF_VALIDATE验证父成员的类型，并用BUILD_ASSERT要求其偏移为0。官方源码说明，构建脚本还将该宏作为识别API类别继承关系的标记，用来形成类别层次；不能只给一个普通结构添加首成员，就假定链接区间中已经登记父子关系。原始断言字符串中的“Parent API struct must be the first member of child API struct”意为父API结构必须是子API结构的首成员。

<a id="a9907e8ee5e7be8c3b5d52b13bd33970a"></a>

### `DEVICE_API_GET`

```c
#define DEVICE_API_GET ( _class, _dev )
```

展开值（Value）：

```c
({                                                                                         \
        IF_ENABLED(CONFIG_DEVICE_API_ASSERT, (                                             \
        __ASSERT(_dev != NULL, "device is NULL");                                          \
        __ASSERT(DEVICE_API_IS(_class, _dev), "device API is not %s", STRINGIFY(_class));  \
        ));                                                                                \
        Z_DEVICE_API_GET(_class, _dev);                                                    \
})
```

展开为指定类别的设备API指针。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_class` | 设备API类别。 |
| `_dev` | 设备实例指针。 |

**返回（Returns）**：返回指向设备API的指针。

> 译注——源码核对：在CONFIG_DEVICE_API_ASSERT条件下展开非空和类别断言，随后按给定类别转换api指针。实际断言行为还受断言机制配置控制；这里不是提供错误码或NULL回退的运行时容错接口。应先确保设备对象和类别正确，再按需要检查设备就绪。原始断言字符串“device is NULL”指设备指针为空，“device API is not %s”指设备API不属于指定类别。

<a id="a48c6030c2e7d1d05ace7c708dda11949"></a>

### `DEVICE_API_IS`

```c
#define DEVICE_API_IS ( _class, _dev )
```

展开值（Value）：

```c
({                                                                                         \
        STRUCT_SECTION_START_EXTERN(Z_DEVICE_API_TYPE(_class));                            \
        extern const uint8_t Z_DEVICE_API_EXT_END(Z_DEVICE_API_TYPE(_class))[];            \
                                                                                           \
        ((const uint8_t *)Z_DEVICE_API_GET(_class, _dev) <                                 \
                 Z_DEVICE_API_EXT_END(Z_DEVICE_API_TYPE(_class)) &&                        \
         (const uint8_t *)Z_DEVICE_API_GET(_class, _dev) >=                                \
                 (const uint8_t *)STRUCT_SECTION_START(Z_DEVICE_API_TYPE(_class)));        \
})
```

结果为布尔值的宏，可用于检查设备是否属于指定类别（Class）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_class` | 设备API类别。 |
| `_dev` | 设备实例指针。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `true` | 设备属于给定类别。 |
| `false` | 设备不属于给定类别。 |

> 译注——源码核对：当前实现检查_dev->api地址是否位于该类别起始位置与扩展结束位置之间，以涵盖按构建流程登记的子类别。它不检查device_is_ready，不探测硬件，也不验证任意非空指针的内存合法性。必须传入有效设备对象；宏展开多次引用_dev，避免传入带副作用的表达式。
