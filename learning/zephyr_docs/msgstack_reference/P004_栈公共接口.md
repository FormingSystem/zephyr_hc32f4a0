# 第4章\_栈公共接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__stack__apis.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：本册覆盖消息队列（Message Queue）、消息队列属性及整数数据栈（Stack）的公共接口。消息队列按固定字节数复制消息，整数数据栈保存stack_data_t值；均须区别于以链接节点传递对象的通用队列。原始声明、宏展开、参数和返回值完整保留，源码说明另作译注。

## 4.3\_详细说明（Detailed Documentation）

<a id="ga8c9ca77e5de3c9757dcd4ecb55797835"></a>

### `K_STACK_DEFINE`

```c
#define K_STACK_DEFINE ( name, stack_num_entries )
```

```c
#include <zephyr/kernel.h>
```

展开值（Value）：

```c
stack_data_t __noinit                                  \
        _k_stack_buf_##name[stack_num_entries];        \
STRUCT_SECTION_ITERABLE(k_stack, name) =               \
        Z_STACK_INITIALIZER(name, _k_stack_buf_##name, \
                            stack_num_entries)
```

静态定义并初始化一个栈（Stack）。

可使用以下声明，在定义栈的模块之外访问它：

原始示例（Example）：

```c
extern struct k_stack <name>;
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 栈名称。 |
| `stack_num_entries` | 栈最多可容纳的值的数量。 |

> 译注——源码核对：这里的栈是线程间传递整数值的内核对象，不是线程执行所需的调用栈（Call Stack）。宏定义stack_data_t数组及可遍历段中的k_stack对象；extern示例中的<name>须替换为实际变量名。

<a id="gab97d924db1aef3f6adade156a107d45c"></a>

### `k_stack_alloc_init()`

```c
int32_t k_stack_alloc_init ( struct k_stack * stack, uint32_t num_entries )
```

```c
#include <zephyr/kernel.h>
```

初始化栈。

本例程在栈对象首次使用之前初始化它。内部缓冲区从调用线程的资源池分配。调用k_stack_cleanup()时会释放这部分内存；启用用户空间（Userspace）时，栈对象失去全部引用后也会释放这部分内存。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `stack` | 栈的地址。 |
| `num_entries` | 栈最多可容纳的值的数量。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-ENOMEM` | 无法分配内存。 |

> 译注——源码核对：当前实现检查num_entries乘sizeof(stack_data_t)的大小溢出，溢出与分配失败均返回-ENOMEM。用户模式验证层另要求num_entries大于0且乘法不溢出；违反验证约束不能当作普通返回错误码处理。

<a id="ga819f4e7b2cf11cf2e1b80933fdcb67ea"></a>

### `k_stack_cleanup()`

```c
int k_stack_cleanup ( struct k_stack * stack)
```

```c
#include <zephyr/kernel.h>
```

释放为栈分配的缓冲区。

如果栈对象通过k_stack_alloc_init()获得了动态分配的缓冲区，本函数会释放它。若缓冲区不是动态分配的，则本函数不执行任何释放操作。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `stack` | 栈的地址。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-EAGAIN` | 对象仍在使用中。 |

> 译注——源码核对：当前检查针对等待栈数据的线程，发现等待者时返回-EAGAIN；不要将其与消息队列cleanup的-EBUSY混用。缓冲区含未弹出值本身不阻止释放。动态缓冲区释放后base被置NULL，但next和top不重建，不能继续push／pop；值若表示对象地址，所指对象不会随缓冲区释放。

<a id="ga4400a39ef48289305cf66a092d5c6c7d"></a>

### `k_stack_init()`

```c
void k_stack_init ( struct k_stack * stack, stack_data_t * buffer, uint32_t num_entries )
```

```c
#include <zephyr/kernel.h>
```

初始化栈。

本例程在栈对象首次使用之前初始化它。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `stack` | 栈的地址。 |
| `buffer` | 用于存放栈中各值的数组地址。 |
| `num_entries` | 栈最多可容纳的值的数量。 |

> 译注——源码核对：buffer应为至少含num_entries个stack_data_t元素的数组，元素数不是字节数；调用者需保证其生命周期。此初始化函数不能代替已有对象的释放操作；当前源码也没有在此重置flags，不应把它当成任意旧状态均可直接重置的接口。

<a id="ga36ce6ceb9ea3d5c36d22b10430789480"></a>

### `k_stack_pop()`

```c
int k_stack_pop ( struct k_stack * stack, stack_data_t * data, k_timeout_t timeout )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

从栈弹出一个元素。

本例程按后进先出（Last In, First Out，LIFO）顺序，从stack移除一个stack_data_t值，并将该值存入data。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `stack` | 栈的地址。 |
| `data` | 用于保存出栈值的区域地址。 |
| `timeout` | 等待取得一个值的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 元素已出栈。 |
| `-EBUSY` | 未等待即返回。 |
| `-EAGAIN` | 等待超时。 |

**说明（Note）**：从中断服务程序（Interrupt Service Routine，ISR）调用时，timeout必须设为K_NO_WAIT。

> 译注——源码核对：缓存值按后进先出顺序弹出；空栈不等待返回-EBUSY，等待超时返回-EAGAIN。失败路径不提供有效新值，不应未经返回值判断就使用输出。ISR只能使用K_NO_WAIT；栈中若存的是指针值，该接口不管理其所指对象的寿命。

<a id="gaa6180f4db6ec93ee84149cba054d3e53"></a>

### `k_stack_push()`

```c
int k_stack_push ( struct k_stack * stack, stack_data_t data )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

将一个元素压入栈。

本例程将stack_data_t类型的值data加入stack。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `stack` | 栈的地址。 |
| `data` | 要压入栈的值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-ENOMEM` | 栈已满。 |

> 译注——源码核对：本次头文件定义stack_data_t为uintptr_t，宽度跟随目标指针宽度，不应固定理解为32位。此接口没有timeout，不等待空位；已满的检查路径返回-ENOMEM。若有pop等待者可直接把值交付给它，只有无等待者时才写入栈数组。

## 4.4\_源码定位与版本边界

> 译注——阅读与源码边界：配合[整数数据栈指南](../kernel/P029_整数数据栈.md)阅读。这里的Stack不是线程调用栈；已缓存数据按后进先出（Last In, First Out，LIFO）取出，但有等待者时可直接交付。类型stack_data_t当前为uintptr_t，不能无条件假定所有目标都是32位。

仓库相对定位：[kernel.h](../../../include/zephyr/kernel.h)、[kernel/msg_q.c](../../../kernel/msg_q.c)与[kernel/stack.c](../../../kernel/stack.c)。本次依据为[官方内核头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/kernel.h)、[官方消息队列实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/msg_q.c)及[官方栈实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/stack.c)，摘要见[来源记录](../SOURCES.md)。

> 译注——可配置错误检查：清理接口的等待者检查与k_stack_push的满栈检查使用CHECKIF。默认配置执行错误返回分支；CONFIG_ASSERT_ON_ERRORS改为断言且不执行该错误返回块，CONFIG_NO_RUNTIME_CHECKS则省略检查。因此不能在所有配置下依赖这些错误码防止误用。依据[官方check.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/check.h)，仓库相对定位见[check.h](../../../include/zephyr/sys/check.h)。

仓库源码、滚动更新的main和latest网页不能自动视为同一版本。本批完成文档与源码核对，未构建或执行并发、内存分配及实板实验。
