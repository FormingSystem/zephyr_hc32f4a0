## 8.3\_详细说明（Detailed Documentation）

<a id="ga8d3604770d7735d229e7d2fef4ff590a"></a>

### `ARCH_EXCEPT`

```c
#define ARCH_EXCEPT ( reason_p)
```

```c
#include <zephyr/arch/arch_interface.h>
```

触发由软件引起的致命错误（Software-induced Fatal Error）。

若调用者运行在用户模式（User Mode），只能触发 `K_ERR_KERNEL_OOPS` 或 `K_ERR_STACK_CHK_FAIL`。

理想情况下，此操作应产生软件陷阱（Software Trap），异常上下文反映调用时的状态。陷阱发生时的通用寄存器状态不应被调用过程扰乱。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `reason_p` | 以 `K_ERR_` 命名的致命错误原因代码。 |

<a id="gab3ab80b9bcef30a3109d6c7cecf941f6"></a>

### `ARCH_IRQ_CONNECT`

```c
#define ARCH_IRQ_CONNECT ( irq, pri, isr, arg, flags )
```

```c
#include <zephyr/arch/arch_interface.h>
```

静态连接中断的架构专有钩子（Architecture-specific Hook）。

在构建时静态填充中断表：中断 `irq` 触发时，以 `arg` 为参数调用 `isr`，采用优先级 `pri` 和架构专有配置标志。所有参数都必须可用于常量表达式（Constant Expression）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `irq` | 中断线路编号。 |
| `pri` | 中断优先级。 |
| `isr` | 中断服务例程（ISR）。 |
| `arg` | 传给 ISR 的参数。 |
| `flags` | 架构专有的 IRQ 配置标志。 |

另见（See Also）：`IRQ_CONNECT()`。

<a id="ga875f2b1ca924721fe3854796bd96c2db"></a>

### `ARCH_IRQ_DIRECT_CONNECT`

```c
#define ARCH_IRQ_DIRECT_CONNECT ( irq_p, priority_p, isr_p, flags_p )
```

```c
#include <zephyr/arch/arch_interface.h>
```

静态连接直接中断的架构专有钩子。

与 `ARCH_IRQ_CONNECT()` 类似，但用于通过 `ARCH_ISR_DIRECT_DECLARE()` 声明的 ISR；安装后绕过公共的软件 ISR 分派，以尽量降低延迟。直接 ISR 不接收参数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `irq_p` | 中断线路编号。 |
| `priority_p` | 中断优先级。 |
| `isr_p` | 直接中断服务例程（Direct ISR）。 |
| `flags_p` | 架构专有的 IRQ 配置标志。 |

另见（See Also）：`IRQ_DIRECT_CONNECT()`。

<a id="ga5279598e93dd914614a2ae52557be1a5"></a>

### `ARCH_ISR_DIRECT_DECLARE`

```c
#define ARCH_ISR_DIRECT_DECLARE ( name)
```

```c
#include <zephyr/arch/arch_interface.h>
```

声明直接中断服务例程的架构专有钩子。

声明一个可由 `ARCH_IRQ_DIRECT_CONNECT()` 安装的函数 `name`。它包装随后提供的函数体，使 `ARCH_ISR_DIRECT_HEADER()` 与 `ARCH_ISR_DIRECT_FOOTER()` 分别在前后执行，并应用架构专有的 ISR 入口／退出处理，例如中断属性。如果退出中断时允许发生上下文切换，被包装的函数体返回非零值。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 要声明的直接 ISR 名称。 |

另见（See Also）：`ISR_DIRECT_DECLARE()`。

<a id="gaa7c471213fa28b3685f153ea2a72cf9d"></a>

### `ARCH_ISR_DIRECT_FOOTER`

```c
#define ARCH_ISR_DIRECT_FOOTER ( swap)
```

```c
#include <zephyr/arch/arch_interface.h>
```

退出直接中断时的架构专有状态维护。

与 `ARCH_ISR_DIRECT_HEADER()` 配对：撤销中断入口的状态维护；若 `swap` 非零，则检查退出中断时是否需要上下文切换，并安排该切换。每个直接 ISR 都通过 `ISR_DIRECT_FOOTER()` 在末尾调用它。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `swap` | 非零表示退出时允许发生上下文切换。 |

另见（See Also）：`ISR_DIRECT_FOOTER()`。

<a id="ga6c6d57983c066fe8ab21a78f86f7adb3"></a>

### `ARCH_ISR_DIRECT_HEADER`

```c
#define ARCH_ISR_DIRECT_HEADER ( )
```


执行通常由公共中断分派路径完成的入口状态维护，例如跟踪中断嵌套和发出跟踪事件。每个直接 ISR 都通过 `ISR_DIRECT_HEADER()` 在开头调用它。

另见（See Also）：`ISR_DIRECT_HEADER()`。

### `ARCH_PCIE_IRQ_CONNECT`

```c
#define ARCH_PCIE_IRQ_CONNECT ( bdf, irq, pri, isr, arg, flags )
```

```c
#include <zephyr/arch/arch_interface.h>
```

连接 PCIe 端点中断的架构专有钩子。

与 `ARCH_IRQ_CONNECT()` 类似，但用于 `bdf` 所标识的 PCIe 端点中断，以便架构在构建时或运行时从该端点解析最终中断向量。

**参数（Parameters）**

| --- | --- |

| `irq` | 中断线路编号。 |
| `pri` | 中断优先级。 |
| `isr` | 中断服务例程（ISR）。 |
| `arg` | 传给 ISR 的参数。 |
| `flags` | 架构专有的 IRQ 配置标志。 |

另见（See Also）：`PCIE_IRQ_CONNECT()`。

<a id="gab7c91d90ed8ccfce15c8bd040496f9ac"></a>

### `arch_cpu_irqs_are_enabled()`

```c
bool arch_cpu_irqs_are_enabled ( void )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

查询当前 CPU 中断控制器的整体锁定状态，不修改该状态。

`arch_irq_unlocked()` 检查的是保存的键；与它不同，此函数报告调用 CPU 整体中断使能的即时状态。

返回（Returns）：调用 CPU 的中断当前已使能时为 true。

<a id="gaac8f60e7dfc5ce3222372798e96316ae"></a>

### `arch_irq_allocate()`

```c
unsigned int arch_irq_allocate ( void )
```

```c
#include <zephyr/arch/arch_interface.h>
```

分配 IRQ 的架构专有钩子。

说明：此类函数的实现应适当禁用／使能 IRQ，以避免并发问题。另外，已分配的 IRQ 被视为已使用，因此后续的相关检查应反映这一状态。

此 API 仅在未启用 PCIe 控制器驱动（`CONFIG_PCIE_CONTROLLER`）时使用；存在控制器驱动时，IRQ 分配由控制器处理。

另见（See Also）：后续调用 `arch_irq_is_used()` 应返回 true。

返回（Returns）：新分配的 IRQ；发生错误时返回 `UINT_MAX`。



## 8.4\_源码定位与版本边界

相对源码定位：[include/zephyr/arch/arch_interface.h](../../../include/zephyr/arch/arch_interface.h)、[include/zephyr/irq.h](../../../include/zephyr/irq.h)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把源码对照视为目标开发板已经实测。

> 译注——源码核对：arch_irq_*是架构端的实现契约，应用通常使用irq_*公共接口。架构中断编号、分配、优先级、动态连接和保留状态的能力并非所有平台都相同；本页保留官方约束，不把一种架构的硬件编号范围套用到另一种架构。

> 译注——源码核对：arch_irq_lock/arch_irq_unlock保存并恢复本地处理器中断状态。公共irq_lock可能在SMP配置下添加全局协调，二者不能因名字相似而互换。k_is_in_isr判断当前上下文；可抢占（Preemptible）还要求位于可抢占线程、调度器未锁定等条件。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
