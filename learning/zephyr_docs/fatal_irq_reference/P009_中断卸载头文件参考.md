### `irq_offload()`

```c
void irq_offload ( irq_offload_routine_t routine, const void * parameter )
```

在中断上下文中运行函数。

此函数在中断上下文中同步运行指定函数，并传入所提供的设备。它适合需要验证内核对象在中断上下文中也能正确工作的测试代码。

另外，若架构设置了 `CONFIG_IRQ_OFFLOAD_NESTED`，从 ISR 上下文调用此例程时（即 `k_is_in_isr()` 为 true），它可同步触发一个嵌套中断（Nested Interrupt）。并非所有平台的硬件都支持此能力；即使支持，某些中断也可能运行在不可抢占的优先级上。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `routine` | 要运行的函数。 |
| `parameter` | 该函数作为中断运行时传给它的参数。 |

## 9.4\_源码定位与版本边界

相对源码定位：[include/zephyr/irq_offload.h](../../../include/zephyr/irq_offload.h)、[kernel/irq_offload.c](../../../kernel/irq_offload.c)、[arch/arm/core/irq_offload.c](../../../arch/arm/core/irq_offload.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把源码对照视为目标开发板已经实测。

> 译注——源码核对：中断卸载（IRQ Offload）同步地在中断上下文执行回调，不是把工作提交给工作队列（Workqueue）。原文参数说明提到“所提供的设备”，但声明的实际参数类型是const void *，用于传递调用方上下文，并不限定为设备对象。

> 译注——源码核对：通用实现只在CONFIG_IRQ_OFFLOAD_NESTED分支直接调用架构卸载接口；其他配置先取得信号量，再调用并释放。是否允许从ISR嵌套卸载仍取决于架构能力、硬件优先级和配置，不可由同步调用性质推断任意ISR都能调用。

> 译注——源码核对：本次ARM实现通过SVC进入中断上下文，在进入前后锁定／解锁调度器，并临时保存回调与参数。部分基线架构对PRIMASK状态另有断言。本页跟踪官方架构实现，未验证某块板的SVC优先级或嵌套行为。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
