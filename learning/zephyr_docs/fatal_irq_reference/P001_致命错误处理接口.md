## 1.3\_详细说明（Detailed Documentation）

<a id="gaa8c0b43a2360e5319d7910e8e0ceb951"></a>

### `k_fatal_halt()`

```c
FUNC_NORETURN void k_fatal_halt ( unsigned int reason)
```

```c
#include <zephyr/fatal.h>
```

发生致命错误（Fatal Error）时停止系统。

调用架构专有代码关闭系统，或使系统停在低功耗状态。若没有此类支持，则锁定中断并停留在空闲循环中。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `reason` | 致命异常原因代码（Fatal Exception Reason Code）。 |

<a id="ga255cc816d227f0a5c0e80e61bfba11fa"></a>

### `k_sys_fatal_error_handler()`

```c
void k_sys_fatal_error_handler ( unsigned int reason, const struct arch_esf * esf )
```

```c
#include <zephyr/fatal.h>
```

致命错误策略处理函数（Fatal Error Policy Handler）。

应用代码不直接调用此函数；它被声明为弱符号（Weak Symbol），以便应用提供自己的处理策略。

此函数的默认实现会无条件停止系统。根据架构支持，可能表现为简单的无限循环、关闭硬件电源，或退出模拟器。

如果此函数返回，当前正在执行的线程将被终止（Aborted）。

自定义实现需要注意以下几点：

- 若确定错误不可恢复，应调用 `LOG_PANIC()` 以刷新所有待处理的日志缓冲区。
- `K_ERR_KERNEL_PANIC` 表示内核自身发生严重且不可恢复的错误，不应把它视为可恢复错误。`z_fatal_error()` 中有断言来强制这一要求。
- 即使不是内核恐慌（Kernel Panic），只要故障并非发生于用户模式，内核自身也可能已处于不一致状态；此时调用内核对象 API 可能出现未定义行为或再次触发异常。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `reason` | 致命错误的原因。 |
| `esf` | 异常上下文（Exception Context），包含错误发生时的详细信息和部分或全部寄存器状态。在某些情况下可以为 `NULL`。 |

## 1.4\_源码定位与版本边界

相对源码定位：[include/zephyr/fatal.h](../../../include/zephyr/fatal.h)、[kernel/fatal.c](../../../kernel/fatal.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把源码对照视为目标开发板已经实测。

> 译注——源码核对：官方接口说明将默认策略描述为停止系统（Halt）。本次kernel/fatal.c中的弱定义k_sys_fatal_error_handler先调用LOG_PANIC；启用CONFIG_RESET_ON_FATAL_ERROR时请求热复位（Warm Reboot），否则调用arch_system_halt。应区分官方接口文字与当前源码的配置分支，不能断言所有配置都停在原地。k_fatal_halt则直接进入架构停止接口。

> 译注——源码核对：替换错误策略处理器后返回，不等于任何致命错误都可以安全恢复。z_fatal_error对内核恐慌（Kernel Panic）、中断上下文、测试配置和多线程配置另有约束；普通非测试路径禁止从内核恐慌返回，支持多线程时正常返回路径会终止出错线程。异常栈帧（Exception Stack Frame）指针esf可能为空，不可无条件解引用。

> 译注——源码核对：头文件同时声明z_fatal_error供内核错误分派使用。源码可见不代表它与供应用覆盖的k_sys_fatal_error_handler具有相同用途或稳定性承诺。通用弱定义的arch_system_halt锁定本地架构中断后循环；不能据此推断每个平台都已经停止其他CPU核心。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
