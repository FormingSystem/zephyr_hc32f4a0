## 12.2\_详细说明（Detailed Documentation）

<a id="ga2df4b2550ace30512cddebd36b6a54a1"></a>

### `k_float_disable()`

```c
int k_float_disable ( struct k_thread * thread)
```

```c
#include <zephyr/kernel.h>
```

禁用浮点上下文信息的保存（Floating-point Context Preservation）。

此例程通知内核，指定线程不再使用浮点寄存器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 线程标识（Thread ID）。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 操作成功。 |
| `-ENOTSUP` | 尚未实现禁用浮点上下文保存的操作。 |
| `-EINVAL` | 无法完成禁用浮点上下文保存的操作。 |

**警告（Warning）**：警告（Warning）：某些架构对请求禁用浮点上下文保存的方式有约束，参见 `arch_float_disable`。仅应对当前已启用浮点支持的线程使用此例程来禁用该支持。

<a id="ga81fb955ddd41658a9aad5c083f173f77"></a>

### `k_float_enable()`

```c
int k_float_enable ( struct k_thread * thread, unsigned int options )
```

```c
#include <zephyr/kernel.h>
```

启用浮点上下文信息的保存。

此例程通知内核，指定线程将使用浮点寄存器。

调用此例程会把线程的浮点上下文信息初始化为浮点单元（Floating-point Unit，FPU）复位后的状态。下次 `z_swap()` 调度此线程时，如果上一个 FPU 使用者以协作方式换出，线程将接手一个保证处于正常状态的 FPU；如果上一个使用者被抢占，或者当前线程是首个 FPU 使用者，则加载当前线程自己的浮点上下文。此后，内核会保护该线程的浮点上下文，避免它在抢占式上下文切换中被改变。

`options` 参数指明指定线程将使用哪些浮点寄存器组。

对于 x86，选项为：

- `K_FP_REGS` 表示只使用 x87 FPU 和 MMX 寄存器。
- `K_SSE_REGS` 表示使用 SSE 寄存器，也包括 x87 FPU 和 MMX 寄存器。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `thread` | 线程标识（Thread ID）。 |
| `options` | 架构相关的选项。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 操作成功。 |
| `-ENOTSUP` | 尚未实现启用浮点上下文保存的操作。 |
| `-EINVAL` | 无法完成启用浮点上下文保存的操作。 |

**警告（Warning）**：警告（Warning）：某些架构对请求启用浮点上下文保存的方式有约束，参见 `arch_float_enable`。仅应对当前尚未启用浮点支持的线程使用此例程。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把源码对照视为目标开发板已经实测。

> 译注——源码核对：浮点上下文（Floating-point Context）接口控制线程的浮点状态使用与保存，不等于直接开关硬件FPU电源。本次通用实现仅在CONFIG_FPU与CONFIG_FPU_SHARING同时启用时委托架构实现，否则返回-ENOTSUP。

> 译注——源码核对：原文关于x87、MMX与SSE的选项针对相应架构，不能把K_FP_REGS或K_SSE_REGS对x86寄存器集合的说明当作Cortex-M的寄存器布局。浮点支持、上下文共享与具体线程选项应一起核对。用户态验证路径还检查传入对象是否为线程对象。
