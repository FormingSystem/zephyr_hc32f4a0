## 7.3\_详细说明（Detailed Documentation）

### `IRQ_CONNECT`


### `IRQ_DIRECT_CONNECT`

```c
#define IRQ_DIRECT_CONNECT ( irq_p, priority_p, isr_p, flags_p )
```

```c
#include <zephyr/irq.h>
```

展开值（Value）：

```c
ARCH_IRQ_DIRECT_CONNECT(irq_p, priority_p, isr_p, flags_p)
```

初始化直接中断处理函数（Direct Interrupt Handler）。

此例程为一个 IRQ 初始化中断处理函数。随后必须通过 `irq_enable()` 使能该 IRQ，处理函数才会开始服务中断。

这些 ISR 面向性能敏感的中断处理，不经过公共中断处理代码。其实现必须能够安全地直接放入向量表（Vector Table）。用 C 编写 ISR 时，`ISR_DIRECT_DECLARE()` 宏会自动完成这些处理；用汇编编写时，开发者须自行保证执行正确步骤。

与普通 Zephyr 中断相比，这类中断目前有以下限制：

- 不向 ISR 传递参数。
- 不切换栈，ISR 使用被打断上下文的栈运行，除非架构通过硬件自动切换栈。
- 中断锁定状态保持为 ISR 开始运行时硬件设置的状态。在以锁定中断状态进入 ISR 的架构上，中断仍保持锁定。
- 调度决策变为可选，由通过 `ISR_DIRECT_DECLARE()` 宏实现的 ISR 返回值控制。
- 调用操作系统退出电源管理空闲状态也变为可选。普通中断始终在 ISR 运行前完成此操作；直接中断则由 `ISR_DIRECT_PM()` 的放置位置控制时机，也可以完全省略。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `irq_p` | IRQ 线路编号。 |
| `priority_p` | 中断优先级（Interrupt Priority）。 |
| `isr_p` | 中断服务例程的地址。 |
| `flags_p` | 架构专有的 IRQ 配置标志。 |

**警告（Warning）**：警告（Warning）：虽然此例程在运行时调用，但其所有参数都必须能由编译器在构建时计算出来。

说明（Note）：所有配置了 `IRQ_ZERO_LATENCY` 标志的 IRQ 都必须声明为直接中断。

### `irq_lock`

```c
#define irq_lock ( )
```

```c
#include <zephyr/irq.h>
```

展开值（Value）：

```c
z_smp_global_lock()
```

锁定中断（Lock Interrupts）。

此例程禁用 CPU 上的所有中断。返回的无符号整数是锁定键（Lock-out Key），以架构相关的方式表示调用前中断是否已锁定。重新使能中断时，必须把该键传给 `irq_unlock()`。

只要调用者保存每次生成的锁定键，就可以递归调用此例程。解除锁定时，必须按获取键的相反顺序逐个传给 `irq_unlock()`，才能重新使能中断。也就是说，每次 `irq_lock()` 都必须有对应的 `irq_unlock()`。

此例程只能从监督模式（Supervisor Mode）调用。某些架构（例如 ARM）在用户模式调用时会静默失败，而不会产生异常。

ISR 和线程均可调用此例程。

说明（Note）：此例程还必须充当内存屏障（Memory Barrier），以保证单处理器自旋锁实现正确。

**警告（Warning）**：警告（Warning）：只要递归的 `irq_lock()` 调用尚未全部与对应的 `irq_unlock()` 配平，调用者就仍“持有中断锁”。发生上下文切换时持有中断锁是非法的。不得使用锁定键手工重新使能中断，也不得用它检查或修改 CPU 中断位的内容。

返回（Returns）：架构相关的锁定键，表示调用之前的中断禁用状态。

<a id="ga646045943b3b2a130738bcc48867bf57"></a>

### `irq_unlock`

```c
#define irq_unlock ( key)
```

```c
#include <zephyr/irq.h>
```

展开值（Value）：

```c
z_smp_global_unlock(key)
```

解除中断锁定（Unlock Interrupts）。

此例程使用关联的锁定键撤销先前 `irq_lock()` 的效果。对每次锁定调用，调用者都必须调用一次本例程，并以获取键的相反顺序提供这些键，之后中断才会恢复使能。

此例程只能从监督模式（Supervisor Mode）调用。某些架构（例如 ARM）在用户模式调用时会静默失败，而不会产生异常。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `key` | 由 `irq_lock()` 生成的锁定键。 |

说明（Note）：此例程还必须充当内存屏障（Memory Barrier），以保证单处理器自旋锁实现正确。

说明（Note）：可由 ISR 调用。

### `ISR_DIRECT_DECLARE`

```c
#define ISR_DIRECT_DECLARE ( name)
```

```c
#include <zephyr/irq.h>
```

展开值（Value）：

```c
ARCH_ISR_DIRECT_DECLARE(name)
```

声明直接中断服务例程的辅助宏。

此宏以正确方式声明函数，并自动包含 `ISR_DIRECT_FOOTER()` 与 `ISR_DIRECT_HEADER()`。如果退出时可能需要作出调度决策，函数应返回非零值。调度决策的更多细节见 `ISR_DIRECT_FOOTER()`。

有些架构支持普通（Regular）与快速（Fast）两类中断，两者要求 ISR 使用不同的汇编寄存器处理方式；在这些架构上，此宏始终生成快速中断类型的代码。

用法示例：

原始示例（Example）：

```c
ISR_DIRECT_DECLARE(my_isr)
{
        bool done = do_stuff();
        ISR_DIRECT_PM(); // done after do_stuff() due to latency concerns
        if (!done) {
            return 0; // don't bother checking if we have to z_swap()
        }

        k_sem_give(some_sem);
        return 1;
 }
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | ISR 的符号名称。 |

**警告（Warning）**：警告（Warning）：为配置了 `IRQ_ZERO_LATENCY` 标志的 IRQ 服务的 ISR，在此宏中必须始终返回 0。

## 7.4\_源码定位与版本边界

相对源码定位：[include/zephyr/irq.h](../../../include/zephyr/irq.h)、[include/zephyr/arch/arm/asm_inline_gcc.h](../../../include/zephyr/arch/arm/asm_inline_gcc.h)、[include/zephyr/arch/arm/irq.h](../../../include/zephyr/arch/arm/irq.h)、[arch/arm/core/cortex_m/irq_manage.c](../../../arch/arm/core/cortex_m/irq_manage.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。仓库源码使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把源码对照视为目标开发板已经实测。

> 译注——源码核对：普通中断服务例程（Interrupt Service Routine，ISR）、直接中断（Direct Interrupt）和零延迟中断（Zero-latency Interrupt）有不同的入口与约束。IRQ_CONNECT和IRQ_DIRECT_CONNECT的连接参数须在构建时可确定；动态连接（Dynamic Connection）另有架构和配置前提，连接动作不等于已经使能中断源。

> 译注——源码核对：irq_lock返回先前中断状态的键（Key），嵌套锁定须按相反次序用各自键解锁。irq.h在对称多处理（SMP）配置下选择z_smp_global_lock，否则调用arch_irq_lock。架构层本地屏蔽与公共接口的SMP包装不同；不可把任意arch_irq_lock调用解释为已经阻止其他核心执行。

> 译注——源码核对：本次Cortex-M主线架构的锁定实现读取BASEPRI，再以BASEPRI_MAX设置阈值；解锁恢复保存值。因此配置允许的零延迟中断可不受常规中断锁约束。不能依靠irq_lock保护也会被零延迟ISR访问的数据，更不能把零延迟ISR当作可任意调用内核服务的普通ISR。

> 译注——源码核对：原文ISR_DIRECT_PM段落使用IRQ_DIRECT_HEADER和IRQ_DIRECT_FOOTER名称；本次头文件的实际宏名为ISR_DIRECT_HEADER和ISR_DIRECT_FOOTER。正文保留原文名称，此处指出源码差异。直接ISR返回值用于请求退出时的调度检查；ARM头文件明确限制零延迟ISR不得调用ISR_DIRECT_PM且须返回0。

> 译注——源码核对：挂起（Pending）操作需要CONFIG_ARCH_HAS_IRQ_PENDING_OPS；读取活动中断需要CONFIG_ARCH_HAS_IRQ_GET_ACTIVE。Cortex-M实现操作NVIC状态，清除NVIC挂起位不等于清除了外设中断状态，仍有效的电平源可能重新挂起。无活动硬件IRQ的返回哨兵是UINT_MAX，不是0；中断卸载与CPU异常不计入该接口所称硬件IRQ。

> 译注——源码核对：k_irq_*便捷包装在头文件中为内联函数，并不因带k_前缀就自动成为允许用户态调用的系统调用（System Call）。调用权限与ISR适用性仍须依据具体接口契约。
