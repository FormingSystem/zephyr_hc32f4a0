# 第11章\_TSC 工作组（TSC Working Groups）

原文：[官方页面](https://docs.zephyrproject.org/latest/project/working_groups.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

<a id="overview"></a>

## 11.1 概述（Overview）

TSC 可酌情设立工作组（Working Group，WG）或小组委员会，专门负责特定技术领域、倡议或任务。

<a id="membership"></a>

## 11.2 成员资格（Membership）

<a id="working-group-membership-eligibility"></a>

### 11.2.1 工作组成员资格（Working Group Membership Eligibility）

- 每个工作组应与 TSC 协商，确定自身成员资格要求。

- 每个工作组应有一支积极参与其活动和决策的成员团队。

- 原则上，工作组成员资格应向所有 Zephyr 协作者开放；但工作组可以设置限制，例如来自同一家公司的参与人数。 相关链接：[协作者（Collaborators）](P010_TSC项目角色.md#collaborator)。

- 所有 TSC 成员均有资格成为工作组成员，这是 TSC 成员职责的一部分。

- 最少成员人数可根据任务复杂程度、有效处理任务所需的专业能力广度而变化。

- 工作组应以至少五至七名成员为目标，保证观点多样性、协作及连续性。

- Zephyr 项目各工作组的结构应有利于有效工作、生产力及包容性；最优规模可能随具体背景和活动范围而变化。

- 工作组会议和讨论向全部项目[贡献者](P010_TSC项目角色.md#contributor)开放。

<a id="working-group-chair-co-chair"></a>

### 11.2.2 工作组主席与联合主席（Working Group Chair / Co-chair）

各工作组可以选出主席，并可选设联合主席，负责主持会议并代表工作组与 TSC 沟通。

<a id="working-group-chair-co-chair-elections"></a>

### 11.2.3 工作组主席／联合主席选举（Working Group Chair / Co-Chair Elections）

- 主席和联合主席由工作组成员选举产生。

- 任何工作组成员都有权自荐担任主席或联合主席。

- 主席和联合主席任期为一年。

- 若主席或联合主席在任期结束前辞职，应投票选出新的主席或联合主席。

<a id="working-group-voter-eligibility"></a>

### 11.2.4 工作组投票资格（Working Group Voter Eligibility）

- 工作组成员可以参加主席或联合主席选举投票。

- 每家公司只有一名工作组成员可以在选举中投票。

> 译注——投票范围：这一限制专指工作组主席／联合主席选举，不能扩大解释为所有工作组会议都只允许一人参加。前文分别说明成员资格、开放讨论和 TSC 成员参与规则。

- 主席和联合主席须为工作组成员。

<a id="working-group-election-confirmation"></a>

### 11.2.5 工作组选举确认（Working Group Election Confirmation）

- 当选主席及／或联合主席提交 TSC 确认。

- TSC 决定接受选举结果，或要求重新投票。

<a id="advisory-role"></a>

## 11.3 顾问角色（Advisory role）

- 工作组具有咨询性质，为项目和 TSC 提供建议。

- 工作组按大致共识（Rough consensus）运作。若无法就建议达成共识，主席应将问题提交 TSC 或相关委员会（功能安全和信息安全），由其正式投票；也可以告知项目，工作组无法达成共识。

- 工作组须跟踪讨论，记录所作的投票、决定和建议，并向社区及 TSC 分享结果。

- 工作组会议及线下讨论须记录于独立文档，包含出席情况、法定人数、待执行事项和后续步骤等支持细节。

- 工作组内部决定不具约束力，只有将决定及结果传达给 TSC 后，才可能视为获得批准。

- 结果传达或报告后一周内，若 TSC 未提出异议，工作组决定视为已确认并获批准。

<a id="tsc-working-group-lifecycle"></a>

## 11.4 TSC 工作组生命周期（TSC Working Group Lifecycle）

<a id="creation-of-a-tsc-working-group"></a>

### 11.4.1 创建 TSC 工作组（Creation of a TSC working group）

为创建工作组，一名 TSC 成员须通过 TSC 邮件列表提出提案，至少包含：

- TSC 工作组名称。

- TSC 工作组目的。

- TSC 工作组预期交付物。

- TSC 工作组初始参与者，其中至少一名 TSC 成员担任发起人（Sponsor）。

- 可选的 TSC 工作组完成条件（Definition of done）。

<a id="update-of-a-tsc-working-group"></a>

### 11.4.2 更新 TSC 工作组（Update of a TSC working group）

TSC 可通过决议修改工作组；申请此类变更时，向 TSC 邮件列表提交请求。

<a id="conclusion-of-a-tsc-working-group"></a>

### 11.4.3 结束 TSC 工作组（Conclusion of a TSC working group）

TSC 按自身决策程序决定终止工作组。终止请求应包含：

- TSC 工作组名称。

- TSC 工作组已交付成果。

- 终止 TSC 工作组的理由。
