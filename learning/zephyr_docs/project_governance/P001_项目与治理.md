Zephyr 的开发工作流使用 GitHub 问题（Issue）跟踪功能、改进和缺陷报告，使用拉取请求（Pull Request，PR）提交并评审变更。社区成员协作评审这些 Issue 和 PR，通过定期发布推进功能增强与质量改进，具体见[发布流程（Release Process）](P008_发布流程.md#release-process)。

要处理大量 Issue 和 PR，社区与贡献者必须及时完成评审、反馈和响应，既包括初次提交，也包括后续问题与澄清。[开发流程与工具](P003_开发环境与工具.md#dev-environment-and-tools)以及[评审时间](P003_开发环境与工具.md#review-time)说明介绍了项目面向活跃开发社区的目标和准则。

[TSC 项目角色（TSC Project Roles）](P010_TSC项目角色.md#project-roles)详细介绍开发工作流中的角色及其权限。

<a id="terminology"></a>

## 1.1 术语（Terminology）

- 主线（mainline）：开发核心功能与核心特性的主代码树。

- 子系统／功能分支（subsystem/feature branch）：同一仓库中的分支。本文也用“分支”指不在同一仓库、但与原仓库共享历史的副本中的分支。

- 上游（upstream）：当前源码所基于的父分支，即拉取和推送变更所面向的上游分支。

- 长期支持（Long-Term Support，LTS）。

对应官方文档源码：[doc/project/index.rst](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/doc/project/index.rst)。
