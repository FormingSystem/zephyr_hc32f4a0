# 第5章\_缺陷报告（Bug Reporting）

原文：[官方页面](https://docs.zephyrproject.org/latest/project/issues.html)。快照读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

为保留提案、变更、功能和 Issue 之间的追溯关系，建议源码提交与相关 GitHub Issue 双向交叉引用。源于已跟踪功能或问题的变更，应在提交中提及相应 Issue 或 PR 标识。

应随时能沿代码中的引用，找到变更来源及其原因。

<a id="reporting-a-regression-issue"></a>

## 5.1 报告回归问题（Reporting a regression issue）

如果某用例在较早提交或版本中能正常运行，而当前出现问题，就可能是回归。提交报告时直接给出引入问题的提交，可显著节省后续修复时间。

定位引入回归的提交有多种方法。代码树二分定位（Bisect）效率较高，不要求深入理解代码，任何人都可使用。

推荐工具是 git bisect。 相关链接：[`git bisect`](https://git-scm.com/docs/git-bisect)。

操作建议如下：

- 每个二分步骤都运行 `west update`。

> 译注——回归定位前提：二分查找（Bisection）用于定位引入回归的提交。应在读者用于复现问题的 west 工作区内，使用 UCRT64 Bash 或 Linux Bash，先确保相关修改已妥善保存并能够稳定复现问题。`west update` 按每一步检出的清单同步模块版本；它会改变依赖仓库状态，不能仅为阅读本文就在中文文档目录执行。每步应检查同步结果后再复现；失败时先解决版本或依赖问题，避免将环境故障误判成回归结果。

- 二分结束并定位到可疑提交后，手动验证结果。

对应官方文档源码：[doc/project/issues.rst](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/doc/project/issues.rst)。

> 译注——源码跟踪：本仓库[对应源码](../../../doc/project/issues.rst)可用于对照，版本可能与网页不同。本批仅翻译和核对文档，未执行Git工作流、构建、发布或连接设备。
