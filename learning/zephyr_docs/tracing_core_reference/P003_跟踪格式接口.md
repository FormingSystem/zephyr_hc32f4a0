## 3.6\_详细说明（Detailed Documentation）

<a id="ga1b9265a15c577024edd687edc368ca82"></a>

### `TRACING_DATA`

```c
#define TRACING_DATA ( ...)
```

```c
#include <zephyr/tracing/tracing_format.h>
```

展开值（Value）：

```c
do {                                                                   \
        struct tracing_data arg[] = {__VA_ARGS__};                     \
                                                                       \
        tracing_format_data(arg, sizeof(arg) /                         \
                            sizeof(struct tracing_data));              \
} while (false)
```

以跟踪数据格式（Tracing Data Format）跟踪消息的宏。

所有参数都应为struct tracing_data。

<a id="ga5cf7507b0040325a4c04600fcdeb3b21"></a>

### `TRACING_FORMAT_DATA`

```c
#define TRACING_FORMAT_DATA ( x)
```

```c
#include <zephyr/tracing/tracing_format.h>
```

展开值（Value）：

```c
((struct tracing_data){.data = (uint8_t *)&(x), .length = sizeof((x))})
```

将数据转换为跟踪数据格式（Tracing Data Format）的宏。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `x` | 数据字段（Data Field）。 |

### `tracing_data_t`

```c
typedef struct tracing_data tracing_data_t
```

```c
#include <zephyr/tracing/tracing_format.h>
```

用于表示跟踪数据格式（Tracing Data Format）的结构体。

此结构体表示要通过跟踪子系统输出的一段数据。它通常与TRACING_FORMAT_DATA和TRACING_DATA配合使用，将原始值或内存区域包装成后端可使用的统一格式。

相对源码定位：[跟踪入口](../../../include/zephyr/tracing/tracing.h)、[钩子声明](../../../include/zephyr/tracing/tracing_hooks.h)、[包装宏](../../../include/zephyr/tracing/tracing_macros.h)、[格式接口](../../../include/zephyr/tracing/tracing_format.h)、[默认底层钩子](../../../include/zephyr/tracing/tracing_default_hooks.h)、[跟踪配置](../../../subsys/tracing/Kconfig)、[构建选择](../../../subsys/tracing/CMakeLists.txt)、[公共格式处理](../../../subsys/tracing/tracing_format_common.c)、[同步格式处理](../../../subsys/tracing/tracing_format_sync.c)、[异步格式处理](../../../subsys/tracing/tracing_format_async.c)、[跟踪核心](../../../subsys/tracing/tracing_core.c)、[跟踪缓冲区](../../../subsys/tracing/tracing_buffer.c)、[默认弱钩子](../../../subsys/tracing/tracing_none.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：官方接口正文、原始宏展开与源码译注分别保留。来源记录固定本次官方页面及源码的摘要；仓库文件通过相对链接定位，读者使用的源码版本可能不同。

> 译注——源码核对：TRACING_FORMAT_DATA(x)仅构造含地址与长度的描述符（Descriptor），展开式使用&(x)和sizeof(x)，因此x必须能取地址。若x是指针变量，描述的是指针变量本身的字节，并不会自动获得其指向缓冲区的长度；若x是真正的数组对象，sizeof(x)才是该数组大小。宏本身不复制数据。

> 译注——源码核对：TRACING_DATA接受一组struct tracing_data，建立局部描述符数组，再调用tracing_format_data；count是描述符数量，length是各段的字节数。公共实现依次复制各段数据，不自动插入类型、字段名、字节序转换或段长编码。结构体的__packed属性也不等于输出流已具备跨平台序列化协议。

> 译注——源码核对：当前同步实现立即调用tracing_buffer_handle：字符串和分段数据先经环形缓冲区，raw_data直接将给定缓冲区交给处理函数。异步实现先复制或格式化进环形缓冲区，再触发输出线程；它不会只保留调用者的描述符数组等待以后处理。源数据在读取／复制期间仍须有效，后端的进一步缓冲行为以其实现为准。

> 译注——源码核对：格式接口均返回void。运行时跟踪关闭时直接返回，异步实现还跳过跟踪线程自身；缓冲区不足时可增加丢包计数。函数返回不证明主机已收到数据，也不能作为无丢失的确认。同步／异步实现和输出后端由CONFIG_TRACING_CORE下的配置及CMake选择。

> 译注——源码核对：本次验证限于官方文档与源码对照，未配置采集后端、运行事件采集或测量时序。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
