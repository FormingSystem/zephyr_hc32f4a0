## 4.2\_详细说明（Detailed Documentation）

<a id="ga5b96dccfd349dd0ddba1812aa942c1bd"></a>

### `DT_DEP_ORD`

```c
#define DT_DEP_ORD ( node_id)
```

```c
#include <zephyr/devicetree/ordinals.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _ORD)
```

取得节点的依赖序号（Dependency Ordinal）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符。 |

返回（Returns）：以整数字面量（Integer Literal）表示的节点依赖序号。

<a id="ga6c31d58b47d826f1a1de1e5d0044e2f7"></a>

### `DT_DEP_ORD_STR_SORTABLE`

```c
#define DT_DEP_ORD_STR_SORTABLE ( node_id)
```

```c
#include <zephyr/devicetree/ordinals.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _ORD_STR_SORTABLE)
```

取得适于按字符串排序（String Sortable）的节点依赖序号。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符。 |

返回（Returns）：前导补零的整数字面量形式的节点依赖序号。

> 译注——源码核对：可排序形式：本次生成器以至少五位、左侧补零的形式输出ORD_STR_SORTABLE，例如序号12写成00012，目的在于文本排序；宏本身不产生带双引号的C字符串。不要直接把它当十进制整数参与C运算，前导0可能被解释为八进制，含8或9时还可能不合法。需要普通数值时使用DT_DEP_ORD，需文本时按使用场景展开并字符串化。

<a id="ga9c5e6f36c6e7a250368177a9f0713f86"></a>

<a id="ga027cc1361d1e059dde039926980e26fa"></a>

### `DT_INST_SUPPORTS_DEP_ORDS`

```c
#define DT_INST_SUPPORTS_DEP_ORDS ( inst)
```

```c
#include <zephyr/devicetree/ordinals.h>
```

展开值（Value）：

```c
DT_SUPPORTS_DEP_ORDS(DT_DRV_INST(inst))
```

取得直接依赖某个DT_DRV_COMPAT实例的节点的依赖序号列表。

等价于DT_SUPPORTS_DEP_ORDS(DT_DRV_INST(inst))。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `inst` | 实例编号（Instance Number）。 |

返回（Returns）：直接依赖该实例的节点的节点标识符列表。

> 译注——源码核对：序号与节点：依赖序号是生成头文件中的整数标记，不是节点标识符、结构指针或稳定硬件ID。DT_INST_SUPPORTS_DEP_ORDS的原返回说明写成节点标识符列表，但它转发DT_SUPPORTS_DEP_ORDS，实际仍是依赖序号列表；保留原文并在此纠正。

<a id="ga22dd1b0c89eb5ddfbfdd1e723d44f509"></a>

### `DT_REQUIRES_DEP_ORDS`

```c
#define DT_REQUIRES_DEP_ORDS ( node_id)
```

```c
#include <zephyr/devicetree/ordinals.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _REQUIRES_ORDS)
```

取得节点直接依赖项（Direct Dependencies）的依赖序号列表。

展开结果中的每个序号后都有一个逗号，包括最后一个序号：

原始示例（Example）：

```c
DT_REQUIRES_DEP_ORDS(my_node) // required_ord_1, ..., required_ord_n,
```

只有将根节点标识符DT_ROOT作为参数时，DT_REQUIRES_DEP_ORDS()才展开为空。根节点没有直接依赖项；其他每个节点至少依赖其父节点。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符。 |

返回（Returns）：依赖序号列表，每个序号后都带逗号（,）；也可能展开为空。

<a id="ga3f559e9a787792685ed08be124b374ae"></a>

### `DT_SUPPORTS_DEP_ORDS`

```c
#define DT_SUPPORTS_DEP_ORDS ( node_id)
```

```c
#include <zephyr/devicetree/ordinals.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _SUPPORTS_ORDS)
```

取得直接依赖该节点的节点的依赖序号列表。

展开结果中的每个序号后都有一个逗号，包括最后一个序号：

原始示例（Example）：

```c
DT_SUPPORTS_DEP_ORDS(my_node) // supported_ord_1, ..., supported_ord_n,
```

DT_SUPPORTS_DEP_ORDS()可能展开为空：当node_id指向没有其他节点依赖的叶节点（Leaf Node）时，就会出现这种情况。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符。 |

返回（Returns）：依赖序号列表，每个序号后都带逗号（,）；也可能展开为空。

## 4.3\_源码定位与版本边界

本册收录总线、chosen、CPU和依赖顺序四组宏，以及CPU／依赖顺序头文件参考与源码。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[cpu.h](../../../include/zephyr/devicetree/cpu.h)、[ordinals.h](../../../include/zephyr/devicetree/ordinals.h)和[生成脚本](../../../scripts/dts/gen_defines.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：两个方向：REQUIRES列出本节点直接依赖的节点，SUPPORTS列出直接依赖本节点的节点。生成器分别使用depends_on和required_by，并按依赖序号排序；两者均不是完整的传递闭包，不应把它们当作所有祖先或所有下游设备列表。

> 译注——源码核对：列表形态：每项后都有逗号，包含末项；没有依赖时生成器输出仅含注释的空展开。适合嵌入允许尾随逗号的初始化器，不是带长度的运行时数组。普通节点至少依赖父节点，根节点的REQUIRES为空；叶节点还须没有其他引用依赖，SUPPORTS才为空。

> 译注——源码核对：构建与初始化：序号依赖当前设备树生成结果，不应写死到持久存储或跨构建接口中。它可以用于跟踪依赖关系，但单独取得序号不会创建设备、完成驱动初始化或替代初始化级别与优先级的配置。

> 译注——源码核对：版本与范围：本册仅翻译所列官方页面。CPU和依赖顺序源码去掉注释与展示空白后与本次官方头文件一致；总线和chosen展开式结合本次devicetree.h及生成脚本核对。相对源码定位用于跟踪，不把任意本地基线视为与滚动main相同。本次未编译展开示例或进行CPU、总线、初始化及实板实验。

本次验证范围为文档与源码对照，未编译或执行CPU、总线、初始化、宏边界及实板实验。
