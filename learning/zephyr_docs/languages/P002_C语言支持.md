# 第2章\_C语言支持

原文：[C Language Support](https://docs.zephyrproject.org/latest/develop/languages/c/index.html)。读取日期：2026-10-12，`latest`。

C 是广泛用于嵌入式系统的通用底层编程语言。Zephyr 主要以 C 编写，原生支持 C 应用。Zephyr 的 **应用程序编程接口（Application Programming Interface，API）**函数与宏以 C 实现，并通过 `include` 目录下的 C 头文件提供；用 C 编写应用可直接使用最广泛的功能。

原文规定 Zephyr 应用运行在 C 标准所称的**宿主环境（Hosted Environment）**中，因此 `main()` 返回类型必须为 `int`。应用必须从 `main` 返回 `0`，非零返回值均保留。

## 2.1\_语言标准

Zephyr 不把目标限定为某一个 C 标准版本，但源码大量使用 **C99（ISO/IEC 9899:1999）**引入的功能，因此实际要求工具链至少支持 C99。原文列出的功能包括：

| 功能 | 英文名称与含义 |
| --- | --- |
| 内联函数 | Inline Function，用 `inline` 声明的函数。 |
| 标准布尔类型 | Boolean Type，`<stdbool.h>` 中的 `bool`。 |
| 定宽整数类型 | Fixed-width Integer Type，`<stdint.h>` 中的 `[u]intN_t`。 |
| 指定初始化器 | Designated Initializer，按成员名或相应指定方式初始化。 |
| 可变参数宏 | Variadic Macro，接受可变数量实参的宏。 |
| restrict限定 | Restrict Qualification，向编译器表达指针访问约束。 |

部分组件或组件内部还使用 C11、C17 标准阶段的功能，例如 `_Generic` 和 `_Static_assert`。对应标准为 ISO/IEC 9899:2011 与 ISO/IEC 9899:2018。

> 译注：**泛型选择（Generic Selection）**关键字 `_Generic` 与**静态断言（Static Assertion）**关键字 `_Static_assert` 都在 C11 引入；原文将其放在 C11/C17 一组，不表示后者到 C17 才出现。

因此原文建议开发 Zephyr 时使用至少支持 C17 的编译器。部分可选组件和外部模块可能使用更新标准中的特性，这时需要支持相应标准的更新工具链。

## 2.2\_标准库

**C标准库（C Standard Library，libc）**提供程序常用的标准函数。Zephyr 支持多种实现，具体选择取决于构建应用所用工具链与应用需求：

| 文档 | 涵盖内容 |
| --- | --- |
| [C库公共代码](P003_C库公共代码.md) | 时间函数与动态内存管理。 |
| [最小C库](P004_最小C库.md) | 基本函数、格式化输出、动态内存和错误编号。 |
| [Newlib](P005_Newlib_C库.md) | 完整版与精简版、格式化输入输出、动态内存。 |
| [Picolibc](P006_Picolibc_C库.md) | 模块构建与工具链预编译版本，以及相应功能。 |

## 2.3\_格式化输出

C 定义了 `printf`、`sprintf` 等**格式化输出（Formatted Output）**函数，由 C 标准库实现。不同库对输出模式、支持能力有各自的要求与配置，具体见对应运行库文档。

## 2.4\_动态内存管理

C 的**动态内存管理（Dynamic Memory Management）**接口，例如 [malloc()](https://docs.zephyrproject.org/latest/doxygen/html/stdlib_8h.html#a9c36d0fe3ec4675cbffdc9b52f5fb399) 和 [free()](https://docs.zephyrproject.org/latest/doxygen/html/stdlib_8h.html#afbedc913aa4651b3c3b4b3aecd9b4711)，也由标准库实现。

各库实现细节不同，但 Zephyr 支持的库都必须遵守以下约定：

1. 自己管理**内存堆（Memory Heap）**，可以完全内部管理，也可调用 `libc-hooks.c` 实现的 `sbrk()` 等**钩子函数（Hook Function）**。
2. 通过标准分配接口得到的内存块，必须满足架构及相应内存区域的对齐要求。
3. 启用**用户空间（Userspace）**时，在 `z_malloc_partition` 内存分区中分配内存，详见[预定义内存分区](https://docs.zephyrproject.org/latest/kernel/usermode/memory_domain.html#memory-domain-predefined-partitions)。

具体堆管理机制见各运行库章节。

> 原文注意：原生 Zephyr 应用应使用[内核内存管理接口](https://docs.zephyrproject.org/latest/kernel/memory_management/index.html#memory-management-api)，例如 [k_malloc()](../heap_reference/P001_内核堆公共接口.md#gaa8edf1e63e5d5dd78d7adcfd787394ee)，以利用其高级功能。`malloc()` 等标准接口主要供面向多个操作系统的可移植应用和库使用。
