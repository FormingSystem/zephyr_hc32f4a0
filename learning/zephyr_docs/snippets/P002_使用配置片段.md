# 第2章\_使用配置片段

原文：[Using Snippets](https://docs.zephyrproject.org/latest/build/snippets/using.html)。读取日期：2026-10-12，`latest`。

**配置片段（Snippet）**具有名称。构建应用时，将名称交给构建系统即可使用对应设置。Zephyr 已提供的片段见[内置配置片段列表](P007_内置配置片段目录.md#built-in-snippets)。

> 译注：以下为原文命令格式，假定主机工具、工具链与板目标已准备好，当前位置能找到应用目录 `app`，并且构建系统能发现指定片段。`foo`、`snippet1` 等是示例名称，不是要求新建的文件。`[...]` 表示可补充其他参数，实际输入时删除方括号和省略号。

## 2.1\_通过west使用

构建应用 `app` 时使用名为 `foo` 的片段：

```sh
west build -S foo app
```

使用多个片段时，重复提供 `-S`：

```sh
west build -S snippet1 -S snippet2 [...] app
```

> 译注：这里 `west build` 的 `-S` 表示选择 Snippet；不要与下一节 CMake 的同名选项混淆。片段按给定顺序处理，覆盖规则见[编写配置片段](P003_编写配置片段.md)。

## 2.2\_直接使用CMake

不通过 west 而直接运行 CMake 时，使用 CMake 变量 `SNIPPET`，其值为以空格或分号分隔的片段名称列表。例如：

```sh
cmake -Sapp -Bbuild -DSNIPPET="snippet1;snippet2" [...]
cmake --build build
```

> 译注：`cmake -Sapp` 指定源码目录为 `app`，`-Bbuild` 指定构建目录为 `build`；真正选择片段的是 `-DSNIPPET=...`。分号列表保留引号，避免被 shell 当成命令分隔符。原例未列板目标、生成器等参数，应根据已有构建配置或追加参数提供它们。若提示片段不存在，先核对片段名称及搜索根目录，不要创建同名空文件绕过错误。
