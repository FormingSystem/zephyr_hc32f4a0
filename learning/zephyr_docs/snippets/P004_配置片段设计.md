# 第4章\_配置片段设计

原文：[Snippets Design](https://docs.zephyrproject.org/latest/build/snippets/design.html)。读取日期：2026-10-12，`latest`。

本页记录**配置片段（Snippet）**机制的设计目标。进一步讨论见官方 [Issue #51834](https://github.com/zephyrproject-rtos/zephyr/issues/51834)。

## 4.1\_设计目标

**可扩展性（Extensible）：**例如，无需修改 Zephyr 仓库，就能为一个既有内置片段增加开发板支持。

**可组合性（Composable）：**可同时使用多个片段，例如：

```sh
west build -S <snippet1> -S <snippet2> ...
```

**组合多类配置（Combine Multiple Types of Configuration）：**可把不同类型的构建系统设置保存在同一处，并一同应用。

**可特化性（Specializable）：**例如，为特定开发板或开发板修订版本定制片段行为。

**面向未来且向后兼容（Future-proof and Backwards-compatible）：**设计上希望未来能够扩展或改变片段机制，同时不破坏旧片段的兼容性。

**适用于纯软件改动（Applicable to Purely Software Changes）：**与 **扩展板（Shield）**功能不同，片段不假定主板上连接了子板（Daughterboard）、Shield、HAT 或其他外部硬件组件。

**避免重复（Don’t Repeat Yourself，DRY）：**片段减少不必要的重复。例如可用正则表达式 `/(foo|bar)/` 为板 `foo` 与 `bar` 一起指定同一组板级配置。

> 译注：这里的向后兼容是原文陈述的设计目标，不是对任意版本组合已经验证的承诺。`<snippet1>`、`<snippet2>` 与省略号是命令格式占位；实际使用方法与处理顺序见前两章。
