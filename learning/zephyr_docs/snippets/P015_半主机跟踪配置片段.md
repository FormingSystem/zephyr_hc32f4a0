# 第15章\_半主机跟踪配置片段

原文：[官方页面](https://docs.zephyrproject.org/latest/snippets/semihost-tracing/README.html)。读取日期：2026-10-14；保存的latest页面及HTML摘要见[来源记录](../SOURCES.md)。

原构建格式：

```sh
west build -S semihost-tracing [...]
```

<a id="overview"></a>

## 15.1 概述（Overview）

本片段在支持半主机机制（Semihosting）的目标上，使用半主机机制启用通用跟踪格式（Common Trace Format，CTF）跟踪。

使用QEMU运行示例应用时，可以通过半主机机制生成CTF跟踪文件，然后使用[Babeltrace](https://babeltrace.org/) <a id="id2"></a>[1](#id1)查看。

原页面在这里列出以下命令：

```gdb
(gdb) dump binary memory ram_tracing.bin ram_tracing ram_tracing+8192
```

> 译注——原命令不匹配后端：上方是从`ram_tracing`符号导出RAM缓冲区的GDB命令，与本文选择的半主机后端并不对应。为便于核对原文，命令原样保留。当前官方[半主机后端](https://raw.githubusercontent.com/zephyrproject-rtos/zephyr/main/subsys/tracing/tracing_backend_semihosting.c)通过`semihost_open()`以追加二进制模式打开`./tracing.bin`，随后调用`semihost_write()`写入事件；实际主机文件位置取决于运行半主机服务的环境，不是固定的文档仓库路径。CTF数据还需与对应元数据一起解析，参见[跟踪子系统](../observability/P015_跟踪子系统.md)。
