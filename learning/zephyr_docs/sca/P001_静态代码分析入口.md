# 第1章\_静态代码分析入口

原文：[Static Code Analysis (SCA)](https://docs.zephyrproject.org/latest/develop/sca/index.html)。读取日期：2026-10-12，`latest`。

Zephyr 通过 CMake 接入**静态代码分析（Static Code Analysis，SCA）**工具。这类工具分析源码或构建信息，帮助发现缺陷；它们不以实际运行固件作为分析前提。

构建设置 `ZEPHYR_SCA_VARIANT` 选择分析工具，也可以作为环境变量设置。例如 `-DZEPHYR_SCA_VARIANT=sparse` 启用 Sparse，通用形式为 `-DZEPHYR_SCA_VARIANT=<tool>`。

## 1.1\_工具接入文件与搜索根

每种工具由 `sca.cmake` 实现接入，文件位于 `SCA_ROOT/cmake/sca/<tool>/sca.cmake`。`SCA_ROOT` 是可包含多个目录的搜索根设置；Zephyr 自身始终加入该列表，用户还可以添加其他根。

若要支持**树外（Out-of-Tree）**工具，即接入文件放在 Zephyr 源码树之外，创建以下结构：

```text
<sca_root>/                 # Custom SCA root
└── cmake/
    └── sca/
        └── <tool>/         # Name of SCA tool, this is the value given to ZEPHYR_SCA_VARIANT
            └── sca.cmake   # CMake code that configures the tool to be used with Zephyr
```

例如在自建 `my_tools` 根目录中增加名为 `foo` 的工具：

```text
my_tools
         └── cmake/
             └── sca/
                 └── foo/
                     └── sca.cmake
```

> 译注：第二棵目录树把原文主机绝对路径占位改为相对目录名，实际文件布局不变。`foo` 是工具标识，不是预装程序名。

使用时设置 `-DZEPHYR_SCA_VARIANT=foo`，并将 `my_tools` 加入 `SCA_ROOT`。可在 CMake 命令行用 `-DSCA_ROOT=<sca_root>`，也可通过模块的 `module.yml` 提供，见[模块构建设置](https://docs.zephyrproject.org/latest/develop/modules.html#modules-build-settings)。环境设置方式见[环境变量](https://docs.zephyrproject.org/latest/develop/env_vars.html#env-vars)。

> 译注：原文此处一句误写为设置 `SCA_TOOL`，但其命令示例及搜索根机制实际使用 `SCA_ROOT`。另外模块概览页将工具子目录简写为 `sca/<tool>`；本页详细布局以及仓库 `cmake/modules/FindScaTools.cmake` 的读取路径都包含 `cmake/sca/<tool>`，不能漏掉中间的 `cmake` 目录。创建文件只是提供接入实现，还需要本次配置选择该工具并找到相应根。

## 1.2\_编译器与链接器启动器

需要观察或包装编译、链接命令的工具，应在自己的 `sca.cmake` 设置 `CMAKE_<LANG>_COMPILER_LAUNCHER` 与 `CMAKE_<LANG>_LINKER_LAUNCHER`。这些 **启动器（Launcher）**变量指定实际编译器或链接器之前运行的程序；`<LANG>` 表示 C 等语言。

必须设置为普通 CMake 变量，不要写成缓存项。新设置会替换此前的启动器，包括编译缓存工具 ccache。

若分析工具是**透明包装器（Transparent Wrapper）**，即不修改收到的原命令而直接执行它，也可以把原启动器追加到调用链中：

```cmake
set(CMAKE_C_COMPILER_LAUNCHER ${my_wrapper} ${CMAKE_C_COMPILER_LAUNCHER})
```

`my_wrapper` 是例子中已定义的包装程序变量；先执行它，再保留旧的 C 编译启动器。
