## 1.4\_详细说明（Detailed Documentation）

<a id="gab49fdcd86522d318051ca6a6ddf41c7c"></a>

### `SYS_MEM_BLOCKS_DEFINE`

```c
#define SYS_MEM_BLOCKS_DEFINE ( name, blk_sz, num_blks, buf_align )
```

```c
#include <zephyr/sys/mem_blocks.h>
```

展开值（Value）：

```c
_SYS_MEM_BLOCKS_DEFINE(name, blk_sz, num_blks, buf_align,)
```

创建内存块对象（Memory Block Object），并新建后备缓冲区（Backing Buffer）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 内存块对象的名称。 |
| `blk_sz` | 每个内存块的字节数，必须是 2 的幂。 |
| `num_blks` | 内存块总数。 |
| `buf_align` | 内存块缓冲区的对齐值（Alignment），必须是 2 的幂。 |

> 译注——源码核对：当前宏检查blk_sz和buf_align为2的幂，并为缓冲区使用WB_UP后的容量与对齐；位图按num_blks独立分配。分配地址仍以原blk_sz的ilog2作为步长，不应把缓冲区预留量与块步长混为一谈。元数据位于数据缓冲区之外；分配不清零内容。每块都满足所需对齐还要求块大小与对齐关系正确。

<a id="ga2e58484681d0d9629af9a8c7c14453d9"></a>

### `sys_multi_mem_blocks_choice_fn_t`

```c
typedef sys_mem_blocks_t *(* sys_multi_mem_blocks_choice_fn_t) (struct sys_multi_mem_blocks *group, void *cfg)
```

```c
#include <zephyr/sys/mem_blocks.h>
```

多内存块分配器选择函数（Choice Function）。

这是使用者提供的函数，负责根据不透明配置值（Opaque Configuration）cfg 选择具体的内存块分配器。cfg 是使用者传给 sys_multi_mem_blocks_alloc() 的参数。回调返回选定分配器的指针，之后在该分配器上执行分配。

可以返回 NULL；此时分配失败，调用代码收到 -EINVAL。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `group` | 多内存块分配器结构。 |
| `cfg` | 使用者提供的不透明值，应用可按任意方式解释它。 |

**返回（Returns）**：返回指向选定分配器的指针；未选定时返回 NULL。

> 译注——源码核对：此回调只返回分配器指针，随后由包装调用sys_mem_blocks_alloc；与sys_multi_heap的choice需要自己完成分配不同。应返回已经加入组、生命周期有效的分配器；当前分配包装不核验成员关系，返回未登记对象会使后续按组释放无法找到它。

### `sys_mem_blocks_alloc()`

```c
int sys_mem_blocks_alloc ( sys_mem_blocks_t * mem_block, size_t count, void ** out_blocks )
```

```c
#include <zephyr/sys/mem_blocks.h>
```

分配多个内存块。

分配多个内存块，并将其指针放入输出数组。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `[in] mem_block` | 指向内存块对象的指针。 |
| `[in] count` | 要分配的块数。 |
| `[out] out_blocks` | 用于接收各内存块指针的输出数组，至少必须具有 count 个元素。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 成功。 |
| `-EINVAL` | 传入的参数无效。 |
| `-ENOMEM` | 可分配内存块不足。 |

> 译注——源码核对：当前逐块调用位图分配；失败时释放本次已经取得的块并返回-ENOMEM，但out_blocks已写入的地址不会清空，不能在失败后继续使用。各块不保证连续，整个count请求也不是单次不可分割的位图事务。count=0返回0而不写数组，空对象或空数组在此前仍受断言约束。

| `0` | 成功。 |
| `-EINVAL` | 传入的参数无效。 |
| `-ENOMEM` | 可分配的连续内存块不足。 |

> 译注——源码核对：原文“把各指针放入输出数组”是重复自普通分配的描述；此接口只写一个*out_block，表示count个连续块的起点。当前count=0成功并写NULL；普通失败不保证清空输出。一次底层位图分配查找整段连续空闲位，总空闲块足够也可能因碎片而失败。

## 1.5\_源码定位与版本边界

先读[内存块分配器指南](../kernel/P025_内存块分配器.md)，再与[固定块内存池Slab接口](../heap_reference/P003_固定块内存池公共接口.md)对照。块数、字节数、连续性及位图状态是不同概念。

源码定位：[mem_blocks.h](../../../include/zephyr/sys/mem_blocks.h)、[mem_blocks.c](../../../lib/mem_blocks/mem_blocks.c)、[bitarray.h](../../../include/zephyr/sys/bitarray.h)、[bitarray.c](../../../lib/utils/bitarray.c)及[util.h](../../../include/zephyr/sys/util.h)；官方依据为[内存块头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/mem_blocks.h)、[内存块实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/mem_blocks/mem_blocks.c)、[位图头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/bitarray.h)、[位图实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/bitarray.c)和[取整工具](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/util.h)。

CONFIG_SYS_MEM_BLOCKS启用实现，运行时统计和通知分别受CONFIG_SYS_MEM_BLOCKS_RUNTIME_STATS、CONFIG_SYS_MEM_BLOCKS_LISTENER控制。配置及编译依据见[仓库Kconfig](../../../lib/mem_blocks/Kconfig)、[CMakeLists.txt](../../../lib/mem_blocks/CMakeLists.txt)和[官方Kconfig](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/mem_blocks/Kconfig)、[官方构建文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/mem_blocks/CMakeLists.txt)。

> 译注——同步与事件边界：底层位图的分配、释放和测试设置在自身自旋锁内进行；启用统计时，内存块层还有统计更新锁。这不把普通多块循环变成一个不可分割的事务，也不保护分配器组的任意并发重配置。分配失败回滚可能产生配对通知，事件不能直接等同于成功的应用请求。监听规则见[堆事件监听接口](../lowheap_reference/P003_堆事件监听接口.md)。
