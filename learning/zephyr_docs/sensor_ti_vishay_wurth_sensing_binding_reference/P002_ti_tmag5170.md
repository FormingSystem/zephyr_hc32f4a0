# 第2章\_ti_tmag5170

原文：[官方页面](https://docs.zephyrproject.org/latest/build/dts/api/bindings/sensor/ti,tmag5170.html)。读取日期：2026-10-16；来源摘要见[来源记录](../SOURCES.md)。

<a id="ti-tmag5170-on-spi-bus"></a>
<a id="dtbinding-ti-tmag5170"></a>
<a id="std-dtcompatible-ti-tmag5170"></a>

兼容字符串（Compatible String）：`ti,tmag5170`。厂商：[ Texas Instruments ](https://docs.zephyrproject.org/latest/build/dts/api/bindings.html#dt-vendor-ti)。

采用此设备树绑定（Devicetree Binding）的开发板见[官方筛选目录](https://docs.zephyrproject.org/latest/boards/index.html#compatibles=ti,tmag5170)。

驱动源码（Driver Source）：[drivers/sensor/ti/tmag5170/tmag5170.c](https://github.com/zephyrproject-rtos/zephyr/blob/main/drivers/sensor/ti/tmag5170/tmag5170.c)。

<a id="description"></a>

Texas Instruments TMAG5170 高精度线性三维霍尔效应传感器（High-Precision Linear 3D Hall-Effect Sensor）。

<a id="properties"></a>

属性类型：`int` 为整数，`boolean` 为布尔属性，`string` 为字符串，`string-array` 为字符串数组，`array` 为数值数组，`uint8-array` 为8位无符号整数数组，`compound` 为复合类型；`phandle` 为节点引用（Phandle），`phandles` 为节点引用列表，`phandle-array` 为节点引用与说明符单元数组。

## 2.1\_节点专用属性

这些属性不继承自基础绑定文件。

| 属性 | 类型 | 中文说明与约束 |
| --- | --- | --- |
| `int-gpios` | `phandle-array` | 传感器 ALERT 引脚连接，驱动用它向应用通知数据就绪事件（Data Ready Event）。必须在项目配置中启用 `TMAG5170_TRIGGER`，该属性才生效。 |
| `operating-mode` | `int` | **必需**。器件工作模式（Operating Mode）。1：待机（stand-by），等待应用触发测量；2：主动测量（active measure），以尽可能高的速度连续采样所有启用通道，适用于功耗要求不严格且需要频繁采样的设备；3：主动触发（active trigger），也等待应用触发，但转换完成时间比待机短，代价是功耗增加；4：周期工作（duty-cycled），每次采样后休眠，再自动唤醒采集下一次，休眠时间由 `sleep-time` 决定，适合不需要高频采样的低功耗设备。；合法值：`1, 2, 3, 4` |
| `magnetic-channels` | `string` | 启用磁场轴通道的数据采集（Data Acquisition）。同一轴重复启用时进行伪同时采样（Pseudo-Simultaneous Sampling），细节见数据手册。默认启用 XYZ 全部轴，以便检查传感器是否正常。允许值：None（芯片复位值）、X、Y、XY、Z、ZX、YZ、XYZ（默认）、XYX、YXY、YZY、ZYZ、ZXZ、XZX、XYZYX、XYZZYX。；默认值：`XYZ`；合法值：`None, X, Y, XY, Z, ZX, YZ, XYZ, XYX, YXY, YZY, ZYZ, ZXZ, XZX, XYZYX, XYZZYX` |
| `x-range` | `int` | X 轴可测量的最大与最小值，量程越宽，分辨率越低。0：TMAG5170A1 为 ±50 mT、TMAG5170A2 为 ±150 mT（默认，也是芯片复位值）；1：分别为 ±25 mT、±75 mT；2：分别为 ±100 mT、±300 mT。；默认值：`0`；合法值：`0, 1, 2` |
| `y-range` | `int` | Y 轴可测量的最大与最小值，量程越宽，分辨率越低。0：TMAG5170A1 为 ±50 mT、TMAG5170A2 为 ±150 mT（默认，也是芯片复位值）；1：分别为 ±25 mT、±75 mT；2：分别为 ±100 mT、±300 mT。；默认值：`0`；合法值：`0, 1, 2` |
| `z-range` | `int` | Z 轴可测量的最大与最小值，量程越宽，分辨率越低。0：TMAG5170A1 为 ±50 mT、TMAG5170A2 为 ±150 mT（默认，也是芯片复位值）；1：分别为 ±25 mT、±75 mT；2：分别为 ±100 mT、±300 mT。；默认值：`0`；合法值：`0, 1, 2` |
| `oversampling` | `int` | 通过额外采样降低噪声影响。启用温度通道时，温度也进行过采样（Oversampling），除非设置 `disable-temperature-oversampling`。允许值：1（默认及芯片复位值）、2、4、8、16、32。；默认值：`1`；合法值：`1, 2, 4, 8, 16, 32` |
| `enable-temperature-channel` | `boolean` | 启用温度测量（Temperature Measurement）。 |
| `magnet-type` | `string` | 根据磁体类型启用温度补偿（Temperature Compensation）。允许值：None，不补偿（默认及芯片复位值）；NdBFe = 0.12 %/°C；SmCo = 0.03 %/°C；Ceramic（陶瓷）= 0.2 %/°C。；默认值：`None`；合法值：`None, NdBFe, SmCo, Ceramic` |
| `angle-measurement` | `string` | 使用两个轴的数据计算角度（Angle Calculation）。允许值：None，不计算（默认及芯片复位值）；XY；YZ；XZ。；默认值：`None`；合法值：`None, XY, YZ, XZ` |
| `disable-temperature-oversampling` | `boolean` | 为 true 时，每组转换始终只采样一次温度；为 false 时，按 `oversampling` 属性对温度过采样。 |
| `sleep-time` | `int` | 两次转换之间传感器的休眠时间（Sleep Time），单位 ms，仅在 `duty-cycled` 模式下生效。计算转换间总时间还须计入转换本身的耗时；转换时间取决于 `oversampling`、`magnetic-channels`、`temperature-channel-enabled` 和 `disable-temperature-oversampling`。允许值为 1（默认及芯片复位值）、5、10、15、20、30、50、100、500、1000 ms。；默认值：`1`；合法值：`1, 5, 10, 15, 20, 30, 50, 100, 500, 1000` |
| `friendly-name` | `string` | 描述传感器的可读字符串，可帮助主机操作系统区分同型号的多个实例，例如笔记本电脑上盖与底座的加速度计。此属性定义于[HID Usage Tables规范](https://usb.org/sites/default/files/hut1_3_0.pdf)第22.5节“通用传感器属性用途”（Generic Sensor Property Usages）。 |
| `spi-max-frequency` | `int` | **必需**。设备SPI接口的最大时钟频率，单位Hz |
| `duplex` | `int` | 双工模式（Duplex Mode），可为全双工或半双工。默认全双工，对应0，这是最常见模式。应使用宏而非原始枚举值，`dt-bindings/spi/spi.h` 定义的对应关系为0对应SPI_FULL_DUPLEX，2048对应SPI_HALF_DUPLEX；原始对照表见下文；默认值：`0`；合法值：`0, 2048` |
| `frame-format` | `int` | Motorola或TI帧格式（Frame Format）。默认Motorola，对应0，这是最常见格式。应使用宏而非原始枚举值，`dt-bindings/spi/spi.h` 对应关系为0对应SPI_FRAME_FORMAT_MOTOROLA，32768对应SPI_FRAME_FORMAT_TI；原始对照表见下文；默认值：`0`；合法值：`0, 32768` |
| `spi-cpol` | `boolean` | SPI时钟极性（Clock Polarity），指示时钟空闲状态；设置时空闲为逻辑高电平，否则为低电平 |
| `spi-cpha` | `boolean` | SPI时钟相位（Clock Phase），决定采样边沿；设置时在第二个边沿采样，否则在第一个边沿采样 |
| `spi-lsb-first` | `boolean` | 设备要求最低有效位优先（Least Significant Bit First，LSB-first）的数据模式 |
| `spi-hold-cs` | `boolean` | 某些场景需由控制器通过软件管理SPI片选（Chip Select，CS），以连续执行多次SPI事务而不释放片选。典型情况为变长数据包：第一笔事务读取长度，第二笔读取该长度的字节数据 |
| `spi-cs-high` | `boolean` | 设备要求片选高电平有效（Active High） |
| `spi-interframe-delay-ns` | `int` | SPI字（Word）之间的延迟，单位纳秒。默认0是特殊值，表示SCK周期的一半；默认值：`0` |
| `spi-cs-setup-delay-ns` | `int` | 片选置有效之后，由控制器引入的延迟，单位纳秒，也称使能前置时间（Enable Lead Time） |
| `spi-cs-hold-delay-ns` | `int` | 片选释放之前，由控制器引入的延迟，单位纳秒，也称使能后置时间（Enable Lag Time） |
| `supply-gpios` | `phandle-array` | 控制设备供电的GPIO说明符（Specifier）。设备有专用供电开关时提供此属性，供电状态完全由设备驱动负责；与vin-supply的共享稳压器方式相区别 |
| `vin-supply` | `phandle` | 控制设备供电的稳压器引用，目标设备树节点必须使用稳压器兼容字符串。通过共享稳压器供电时应提供此属性，其供电状态取决于所有受电设备的请求状态。若同时提供supply-gpios，则必须先请求稳压器再将GPIO置为有效；释放稳压器前，必须先将GPIO置为无效 |

本页没有已弃用的节点专用属性。

## 2.2\_基础属性

以下属性继承自基础绑定（Base Binding），定义可用于许多节点的通用属性，**并非全部一定适用于本兼容字符串**。

涉及中断（Interrupt）、时钟（Clock）、直接存储器访问（Direct Memory Access，DMA）、输入输出（Input/Output，I/O）、邮箱（Mailbox，MBOX）、处理器间消息（Inter-Processor Messaging，IPM）、电源域（Power Domain）及硬件自旋锁（Hardware Spinlock）。

| 属性 | 类型 | 中文说明与约束 |
| --- | --- | --- |
| `status` | `string` | 节点代表的硬件或其他资源的运行状态（Operational Status）。`okay` 表示资源可运行，例如可供驱动使用；`disabled` 表示资源不可运行，系统应将其视为不存在。参见《设备树规范》（Devicetree Specification）v0.4第2.3.4节；合法值：`okay, disabled, reserved, fail, fail-sss` |
| `compatible` | `string-array` | **必需**。字符串列表定义节点代表的硬件或其他资源类型。设备驱动通过特定兼容字符串（Compatible String）寻找应由自身管理的设备。推荐格式为 `vendor,device`：前者是厂商简称，后者通常来自数据手册。多个值从最具体到最通用排列，让具体设备匹配当前可用的最具体驱动。参见规范v0.4第2.3.1节 |
| `reg` | `array` | **必需**。给出寻址设备所需的信息，具体含义随设备及 `compatible` 而变化。通常是一组地址与长度对，每对称为寄存器块（Register Block），数值通常写为十六进制。参见规范v0.4第2.3.6节及[重要属性](../devicetree/P003_语法与结构.md#dt-important-props) |
| `reg-names` | `string-array` | 为 `reg` 中每个寄存器块提供可选名称；原始例子及逐项说明见本层表后 |
| `ranges` | `compound` | 定义总线子地址空间与总线节点父地址空间之间的映射或转换。通常为空，或由子总线地址、父总线地址、长度三元组组成。**空属性表示两侧地址空间相同、不需要转换；总线节点没有此属性则认为子、父地址空间之间不存在映射**。参见规范v0.4第2.3.8节 |
| `interrupts` | `array` | 设备产生的中断，编码为一个或多个中断说明符；格式由设备在中断树中的位置决定，具有相同 `interrupt-parent` 的设备使用相同格式；中断（Interrupt）及中断映射见《设备树规范》v0.4第2.4节 |
| `interrupts-extended` | `compound` | 扩展中断说明符，可替代 `interrupts`；中断（Interrupt）及中断映射见《设备树规范》v0.4第2.4节 |
| `interrupt-names` | `string-array` | 设备各中断的可选名称；中断本身在 `interrupts` 或 `interrupts-extended` 中定义；中断（Interrupt）及中断映射见《设备树规范》v0.4第2.4节 |
| `interrupt-parent` | `phandle` | 若存在，引用负责处理此设备所产生中断的节点；中断（Interrupt）及中断映射见《设备树规范》v0.4第2.4节 |
| `label` | `string` | 描述设备的可读字符串；除逐案确有需要外，已不推荐使用此属性。参见规范 v0.4 第 4.1.2 节“其他属性” |
| `clocks` | `phandle-array` | 设备的时钟提供者（Clock Provider）信息，通常应遵守[dt-schema时钟绑定约定](https://github.com/devicetree-org/dt-schema/blob/main/dtschema/schemas/clock/clock.yaml) |
| `clock-names` | `string-array` | `clocks` 中各时钟提供者的名称；通用说明称其为可选名称，是否必须填写以本层的必需标记为准 |
| `#address-cells` | `int` | 子节点 `reg` 地址字段所用的 `<u32>` 单元数量；`<u32>` 为32位无符号单元，参见《设备树规范》v0.4第2.3.5节 |

| `dma-coherent` | `boolean` | 表示设备支持一致性 DMA 操作，见规范 v0.4 第 2.3.10 节 |

| `dma-ranges` | `compound` | 定义总线物理地址空间与其父总线物理地址空间之间的映射或转换，见规范 v0.4 第 2.3.9 节 |
| `io-channels` | `phandle-array` | 与设备相关的 I/O 通道说明符 |
| `io-channel-names` | `string-array` | `io-channels` 中各通道说明符的可选名称 |
| `mboxes` | `phandle-array` | 与设备相关的邮箱/IPM 通道说明符 |
| `mbox-names` | `string-array` | `mboxes` 中各邮箱说明符的可选名称 |
| `power-domains` | `phandle-array` | 与设备相关的电源域说明符 |
| `power-domain-names` | `string-array` | `power-domains` 中各电源域说明符的可选名称 |

## 参数编码原始对照 2

```text

the measurement.
2 - active measure mode - continuous sampling on all enabled channels

strict power requirements and need frequent sampling.
3 - active trigger mode - in this mode, similar to stand-by mode, the device
wait for application to trigger the measurement, but the time needed to finish
the conversion is shorter than in stand-by mode, on the cost of increased power
consumption.
4 - duty-cycled - after each sample the device goes to sleep and then
```

## 2.3\_寄存器块命名原例

以下设备树源码（Devicetree Source，DTS）演示 `reg-names` 命名；`uart` 指通用异步收发器（Universal Asynchronous Receiver/Transmitter，UART）。

```dts
  / {
       soc {
           #address-cells = <1>;
           #size-cells = <1>;

           uart@1000 {
               reg = <0x1000 0x2000>, <0x3000 0x4000>;
               reg-names = "foo", "bar";
           };
       };
  };
```

`uart@1000` 节点有两个寄存器块（Register Block）：一个基址为 `0x1000`、大小为 `0x2000`、名称为 `foo`；另一个基址为 `0x3000`、大小为 `0x4000`、名称为 `bar`。
