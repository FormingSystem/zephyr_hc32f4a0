# 第1章\_设备树遍历宏

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__devicetree-generic-foreach.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：按[本册大纲](大纲.md)区分遍历范围、回调参数、展开顺序与分隔符，再选择遍历宏。源码跟踪译注与官方原文分开标示。

重要（IMPORTANT）：不能在DT遍历宏（For-each Macro）自身的展开过程中再次使用同一个宏。

<a id="details"></a>

重要（IMPORTANT）：不能在DT遍历宏（For-each Macro）自身的展开过程中再次使用同一个宏。

例如，下面这种写法不会按你可能预想的方式工作：

原始示例（Example）：

```c
#define FOO(node_id) [...] DT_FOREACH_NODE(...) [...]
DT_FOREACH_NODE(FOO)
```

在此示例中，C预处理器（C Preprocessor）已经在文件顶层展开DT_FOREACH_NODE()时，不会再展开FOO()内部的DT_FOREACH_NODE()宏。

此规则适用于任何宏，并不限于DT_FOREACH_NODE()。C语言采用这种规则来避免宏展开中的无限递归（Infinite Recursion）。

如果需要“嵌套”调用这些宏之一，可以改用另一个相关宏来绕过这一预处理器限制，如下所示：

原始示例（Example）：

```c
#define BAR(node_id) [...] DT_FOREACH_NODE_VARGS(...) [...]
DT_FOREACH_NODE(BAR)
```

这里在DT_FOREACH_NODE()中的BAR()里使用DT_FOREACH_NODE_VARGS()。因此，预处理器会按预期展开DT_FOREACH_NODE_VARGS()和DT_FOREACH_NODE()。

### `DT_COMPAT_FOREACH_STATUS_OKAY_VARGS`

```c
#define DT_COMPAT_FOREACH_STATUS_OKAY_VARGS ( compat, fn, ... )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_HAS_COMPAT_STATUS_OKAY(compat),                  \
            (UTIL_CAT(DT_FOREACH_OKAY_INST_VARGS_,              \
                      compat)(fn, compat, __VA_ARGS__)),        \
            ())
```

对兼容字符串为compat且状态为okay的所有节点调用fn，并传入多个参数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `compat` | 以小写加下划线形式表示的设备树兼容字符串。 |
| `fn` | 为每个已启用节点调用的宏。必须能够接收设备树兼容字符串和实例编号（Instance Number）。 |
| `...` | 传给fn的附加参数。 |

另见（See Also）：DT_INST_FOREACH_STATUS_OKAY_VARGS。

> 译注——源码核对：回调参数顺序：DT_COMPAT_FOREACH_STATUS_OKAY_VARGS的生成展开实际调用fn(instance_number, compat, ...)，实例编号在前，兼容字符串在后，再接调用者的附加参数。它与DT_FOREACH_STATUS_OKAY_VARGS的fn(node_id, ...)不同；实例编号也不是硬件外设编号。

### `DT_FOREACH_ANCESTOR`

```c
#define DT_FOREACH_ANCESTOR ( node_id, fn )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _FOREACH_ANCESTOR)(fn)
```

对node_id的每个祖先节点（Ancestor Node）调用fn。

宏fn必须接收一个参数，该参数将是node_id的一个子节点的标识符，用于遍历所有祖先节点。

祖先节点将按它们在最终设备树中出现的顺序迭代。

设备树片段示例：

原始示例（Example）：

```dts
n: node1 {
        foobar = "foo1";

        n_2: node2 {
                   foobar = "foo2";

                   n_3: node3 {
                              foobar = "foo3";
                   };
        };
};
```

用法示例：

原始示例（Example）：

```c
#define GET_PROP(n) DT_PROP(n, foobar),

const char *ancestor_names[] = {
    DT_FOREACH_ANCESTOR(DT_NODELABEL(n_3), GET_PROP)
};
```

这会展开为：

原始示例（Example）：

```c
const char *ancestor_names[] = {
    "foo2", "foo1",
};
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `fn` | 要调用的宏。 |

> 译注——源码核对：原文把fn参数写成“子节点标识符”，此处应为祖先节点标识符。生成器write_parent从直接父节点开始逐级向上，直到根节点，排除当前节点；不是按DTS文本自上而下扫描。示例n_3的祖先还包括根节点，原文给出的数组只列foo2、foo1而遗漏根节点展开。若根节点没有foobar，直接对它调用DT_PROP会产生未定义的生成标记；需要为根节点补充该属性，或在回调中按属性存在性过滤。原示例照录，未将其当作可直接编译的完整程序。


| `fn` | 为每个已启用节点调用的宏。必须只接收一个node_id参数。 |
| `...` | 传给fn的附加参数。 |

> 译注——源码核对：原文fn参数表沿用了非VARGS版本的“只接收一个node_id参数”，此处实际调用fn(node_id, ...)，第一个参数是节点标识，随后是调用者传入的附加参数。示例MY_FN(node_id, operator)展示了这个顺序。

## 1.3\_源码定位与版本边界

本册收录设备树遍历宏（For-each Macros），涵盖全树、祖先、子节点、属性元素、兼容字符串、设备类别和节点标签。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)和[生成脚本](../../../scripts/dts/gen_defines.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：遍历与执行：fn是预处理宏，不是运行时函数指针。这些宏生成标记序列，不会自行访问硬件、创建就绪设备或执行循环。status为okay或绑定声明某设备类别，只是此处的节点筛选条件，不保证驱动已编译或设备已初始化。

> 译注——源码核对：筛选范围与顺序：CHILD系列只遍历直接子节点，不递归遍历全部后代；带STATUS_OKAY的版本只保留可用子节点。全树、兼容字符串和设备类别遍历不承诺访问顺序，不应依赖某次生成结果来安排设备初始化。节点标签保留最终设备树中的顺序与大小写。

> 译注——源码核对：分隔符规则：本页_SEP系列将分隔符放在相邻展开之间，不自动在末尾补一个。逗号须写为(,)使其作为一个宏实参传入；fn自身若已添加逗号，再使用逗号分隔符会造成重复。普通版本由fn自行提供所需标点，空白不能代替数组元素之间的逗号。

> 译注——源码核对：原例差异：GPIO属性示例中的GPIO_ACTICE_HIGH拼写应为GPIO_ACTIVE_HIGH。DT_NODE_PATH示例生成相邻字符串字面量，放在C表达式中会连接成一个字符串，并不会自动形成字符串数组。带[...]、...的片段是展开示意，使用前须补齐上下文；原文代码保留原样。

> 译注——源码核对：嵌套限制：改用不同的相关宏只能绕过当前宏被禁用重入这一层限制；如果更深层再次要求展开仍处于展开过程中的同名宏，仍会受预处理规则限制。VARGS并不意味着可以任意递归。

> 译注——源码核对：版本边界：本次官方devicetree.h和gen_defines.py登记摘要，源码跟踪采用相对链接。滚动main与本仓库参照基线不自动视为同版本；本批仅核对译文和源码，未编译宏／DTS示例、构建固件或操作硬件。
