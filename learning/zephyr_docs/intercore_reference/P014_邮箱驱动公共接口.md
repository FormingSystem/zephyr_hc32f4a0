# 第14章\_邮箱驱动公共接口

原文：[group__mbox__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__mbox__interface.html)。读取日期：2026-10-13，`latest`。

本页提供邮箱（Mailbox，MBOX）设备的应用程序接口（Application Programming Interface，API），主头文件为`zephyr/drivers/mbox.h`。官方标记为自版本 1.0 引入、接口版本 0.8.0。驱动实现者见[后端接口](P015_邮箱驱动后端接口.md)，设备树访问见[设备树宏](P021_邮箱设备树访问宏.md)，概念入口见[邮箱驱动](../hardware/P069_邮箱驱动.md)。

## 14.1\_设备、通道与通信方向

邮箱外设在系统的中央处理器（Central Processing Unit，CPU）和处理器簇（Cluster）之间传递信号；某些外设还可传递数据。每个邮箱实例提供一个或多个通道（Channel），每个通道面向另一个处理器簇；多个通道可以指向同一处理器簇。图中的 TX 表示发送（Transmit），RX 表示接收（Receive），数字表示通道编号。以下完整保留官方字符示意图：

```text
                     CPU #1        |
+----------+                       |        +----------+
|          +---TX9----+   +--------+--RX8---+          |
|  dev A   |          |   |        |        |  CPU #2  |
|          <---RX8--+ |   | +------+--TX9--->          |
+----------+        | |   | |      |        +----------+
                 +--+-v---v-+--+   |
                 |             |   |
                 |   MBOX dev  |   |
                 |             |   |
                 +--+-^---^--+-+   |
+----------+        | |   |  |     |        +----------+
|          <---RX2--+ |   |  +-----+--TX3--->          |
|  dev B   |          |   |        |        |  CPU #3  |
|          +---TX3----+   +--------+--RX2---+          |
+----------+                       |        +----------+
                                   |
```

图中设备`dev A`通过发送（Transmit，TX）通道 9 向 CPU #2 发送信号或数据，并从接收（Receive，RX）通道 8 接收。因此，它可以在通道 9 发送消息，并为邮箱设备的通道 8 注册回调（Callback）。图中的`dev B`同理使用 TX3 与 RX2。

## 14.2\_信号通知和数据传输模式

接口支持信号通知模式（Signalling Mode）与数据传输模式（Data Transfer Mode）：

| 约束 | 信号通知模式 | 数据传输模式 |
| --- | --- | --- |
| `mbox_mtu_get()` | 必须返回`0` | 必须返回非零值 |
| `mbox_send()`的`msg` | 必须为`NULL` | 必须非`NULL` |
| 接收回调的`data` | 必须为`NULL` | 必须非`NULL` |
| 消息内容 | 不通过消息结构传送数据 | 发送端和接收端的`msg`内容必须一致 |

最大传输单元（Maximum Transmission Unit，MTU）表示出站消息能容纳的最大字节数。消息结构见[`struct mbox_msg`](P018_邮箱消息结构.md)。

## 14.3\_设备树规格与通道类型

设备树（Devicetree，DT）规格由[`struct mbox_dt_spec`](P017_邮箱设备树规格结构.md)保存。`MBOX_DT_SPEC_GET(node_id, name)`读取控制器和通道编号，返回该结构的静态初始化器。`node_id`为邮箱设备的节点标识，`name`为`mboxes`元素的小写字母与下划线形式名称。

```c
{                                                                      \
        .dev = DEVICE_DT_GET(DT_MBOX_CTLR_BY_NAME(node_id, name)),     \
        .channel_id = DT_MBOX_CHANNEL_BY_NAME(node_id, name),          \
}
```

`DEVICE_DT_GET`宏取得设备对象；控制器与通道由[邮箱设备树宏](P021_邮箱设备树访问宏.md)取得。官方设备树片段：

```dts
n: node {
        mboxes = <&mbox1 8>,
                 <&mbox1 9>;
        mbox-names = "tx", "rx";
};
```

下例用`DT_NODELABEL`从标签取得节点标识，并选择发送通道：

```c
const struct mbox_dt_spec spec = MBOX_DT_SPEC_GET(DT_NODELABEL(n), tx);
```

`MBOX_DT_SPEC_INST_GET(inst, name)`是实例版本。`inst`为`DT_DRV_COMPAT`实例编号，`name`含义同上，返回同一结构的静态初始化器：

```c
MBOX_DT_SPEC_GET(DT_DRV_INST(inst), name)
```

通道标识类型为：


```c
typedef uint32_t mbox_channel_id_t;
```

`mbox_channel_id_t`以`uint32_t`表示邮箱通道编号。

## 14.4\_检查设备就绪


```c
static inline bool mbox_is_ready_dt(const struct mbox_dt_spec *spec);
```

参数`spec`指向邮箱设备树规格，用于检查其设备实例是否就绪（Ready）。

原返回值说明写为“参见`mbox_send()`的返回值”。**译注：**这与函数的`bool`返回类型不一致；[可见源码](P020_邮箱驱动头文件源码.md)直接返回`device_is_ready(spec->dev)`，应按设备就绪的布尔结果判断，不能把它解释为发送函数的错误码。

## 14.5\_尝试发送消息


```c
__syscall int mbox_send(const struct device *dev, mbox_channel_id_t channel_id,
                        const struct mbox_msg *msg);
```

通过邮箱通道发送消息。`dev`为设备实例，`channel_id`为通道标识，`msg`为消息结构。信号通知模式必须令`msg == NULL`；`msg`非空时，接收端应通过接收回调的`data`参数获得相应数据。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-EBUSY` | 远端尚未读取上次发送的数据 |
| `-EMSGSIZE` | 驱动不支持所给数据大小 |
| `-EINVAL` | 参数有误，例如通道描述值过大，或设备不是出站（Outbound）邮箱通道 |

**译注：**原说明使用`struct mbox_channel`称呼通道，但此函数的实际声明使用`dev`和`channel_id`，原头文件的公开结构为消息、设备树规格及驱动操作表；调用时以这里保留的原签名为准。


```c
static inline int mbox_send_dt(const struct mbox_dt_spec *spec,
                               const struct mbox_msg *msg);
```

设备树版本从`spec`取得设备与通道，`msg`仍为消息结构，返回值同`mbox_send()`。

## 14.6\_注册接收回调


```c
static inline int mbox_register_callback(const struct device *dev,
                                         mbox_channel_id_t channel_id,
                                         mbox_callback_t cb,
                                         void *user_data);
```

在`dev`设备的`channel_id`通道上注册处理入站（Inbound）消息的回调。`cb`在收到消息中断时执行；`user_data`为应用专用数据指针，执行回调时原样传入。成功返回`0`，错误时返回负错误码`-errno`。

此函数不对当前中断（Interrupt）状态作任何假设；需要改变中断使能状态时，应使用`mbox_set_enabled()`。回调在中断上下文（Interrupt Context）执行，只能调用中断安全（Interrupt-safe）的接口，完整回调契约见[驱动后端](P015_邮箱驱动后端接口.md)。


```c
static inline int mbox_register_callback_dt(const struct mbox_dt_spec *spec,
                                            mbox_callback_t cb, void *user_data);
```

设备树版本中`spec`指定设备和通道，`cb`是收到消息中断时执行的函数，`user_data`是传给回调的应用专用指针，返回值同普通版本。

## 14.7\_查询消息最大长度


```c
__syscall int mbox_mtu_get(const struct device *dev);
```

`dev`为邮箱设备实例。返回经出站通道实际可以发送的最大字节数。若驱动只支持信号通知，或接收侧必须通过间接方式取得内容和大小，例如探测其他外设、读取内存区域，此值可以为`0`。返回`0`时，`mbox_send()`的`msg`应为`NULL`。

| 返回值 | 含义 |
| --- | --- |
| `>0` | 消息最大字节数 |
| `0` | 信号通知模式 |
| `-errno` | 错误时的负错误码 |


```c
static inline int mbox_mtu_get_dt(const struct mbox_dt_spec *spec);
```

从`spec`指定的设备树规格查询最大消息字节数，返回值同`mbox_mtu_get()`。

## 14.8\_使能入站通道


```c
__syscall int mbox_set_enabled(const struct device *dev,
                               mbox_channel_id_t channel_id, bool enabled);
```

使能或禁用`dev`设备上`channel_id`入站通道的中断与回调。`enabled == true`使能，`false`禁用。

调用使能后，通道立即被视为已启用，可以接收信号和消息，**包括已挂起的信号或消息**。因此，需要回调时，应先用`mbox_register_callback()`安装合适回调，再使能通道。基于此，原文建议驱动探测（Probe）时先禁用所有通道。

使能没有安装回调的通道属于未定义行为（Undefined Behavior）；通常，驱动仍应妥善处理无回调时出现的伪中断（Spurious Interrupt）。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-EINVAL` | 指定通道不是入站通道 |
| `-EALREADY` | 通道已经使能 |


```c
static inline int mbox_set_enabled_dt(const struct mbox_dt_spec *spec,
                                      bool enabled);
```

从`spec`取得设备和通道；`enabled`为`true`时使能，为`false`时禁用，返回值同普通版本。

## 14.9\_查询最大通道数


```c
__syscall uint32_t mbox_max_channels_get(const struct device *dev);
```

参数`dev`指定邮箱设备，查询硬件支持的最大通道数。原返回值说明：成功返回大于`0`的最大通道数，出错返回负错误码`-errno`。


```c
static inline int mbox_max_channels_get_dt(const struct mbox_dt_spec *spec);
```

设备树版本从`spec`取得设备，原文返回值说明引用普通版本。

**译注：**普通版本及后端回调的实际返回类型是无符号的`uint32_t`，设备树包装函数却返回`int`。源码还在缺少对应操作时直接返回`-ENOSYS`，该值经过无符号返回类型转换，不能用普通版本结果直接做`< 0`来检测错误。这里保留原声明与原错误描述，并明确两者不一致；不要把转换后的大正整数误当成有效通道数量。完整实现见[头文件源码](P020_邮箱驱动头文件源码.md)。
