# 第1章\_硬件自旋锁公共接口

原文：[group__hwspinlock__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__hwspinlock__interface.html)。读取日期：2026-10-13，`latest`。

本页介绍硬件自旋锁（Hardware Spinlock）的应用程序接口（Application Programming Interface，API），主头文件为`zephyr/drivers/hwspinlock.h`。官方标记：自 Zephyr 3.5 引入，本接口版本为 0.8.0。概念说明见[硬件自旋锁](../hardware/P101_硬件自旋锁.md)，驱动实现者另见[后端接口](P002_硬件自旋锁驱动后端.md)。

## 1.1\_从设备树构造公共配置

设备树（Devicetree，DT）节点标识`node_id`表示硬件自旋锁设备；`inst`是`DT_DRV_COMPAT`对应的实例编号。`HWSPINLOCK_COMMON_CONFIG_FROM_DT_INST(inst)`返回[`struct hwspinlock_driver_config`](P004_硬件自旋锁驱动配置结构.md)初始化器，调用前必须先使用`HWSPINLOCK_SPINLOCK_ARRAY_DT_INST_DEFINE()`。原展开式为：

```c
HWSPINLOCK_COMMON_CONFIG_FROM_DT_NODE(DT_DRV_INST(inst))
```

`HWSPINLOCK_COMMON_CONFIG_FROM_DT_NODE(node_id)`从节点标识构造同一配置结构的初始化器。调用前必须先用`HWSPINLOCK_SPINLOCK_ARRAY_DT_DEFINE()`定义关联的锁数组：

```c
{                                                                                          \
        .num_locks = __HWSPINLOCK_NUM_LOCKS_FROM_DT_NODE(node_id),                         \
        .locks = __HWSPINLOCK_SPINLOCK_ARRAY_NAME_FROM_DT_NODE(node_id),                   \
}
```

## 1.2\_按索引和名称取得设备树规格

`HWSPINLOCK_DT_SPEC_GET(node_id)`构造[`struct hwspinlock_dt_spec`](P005_硬件自旋锁设备树规格结构.md)静态初始化器，等价于取得`hwlocks`属性索引 0 的元素：

```c
HWSPINLOCK_DT_SPEC_GET_BY_IDX(node_id, 0)
```

`HWSPINLOCK_DT_SPEC_GET_BY_IDX(node_id, idx)`从设备树读取对应的设备控制器与锁编号。`idx`是`hwlocks`中的元素索引，返回值为规格结构的静态初始化器：

```c
{                                                                                          \
        .dev = DEVICE_DT_GET(DT_HWSPINLOCK_CTRL_BY_IDX(node_id, idx)),                     \
        .id = DT_HWSPINLOCK_ID_BY_IDX(node_id, idx),                                       \
}
```

以下示例中，`DT_NODELABEL` 宏由节点标签取得节点标识；`DEVICE_DT_GET` 宏取得设备对象指针；控制器与编号由[硬件自旋锁设备树宏](P008_硬件自旋锁设备树宏.md)读取。官方设备树片段：

```dts
n: node {
        hwlocks = <&hwlock 8>,
                  <&hwlock 9>;
};
```

对应的使用方式：

```c
const struct hwspinlock_dt_spec spec = HWSPINLOCK_DT_SPEC_GET_BY_IDX(DT_NODELABEL(n), 0);
```

`HWSPINLOCK_DT_SPEC_GET_BY_NAME(node_id, name)`按名称读取控制器和编号，返回相同类型的静态初始化器。`name`是`hwlocks`元素的小写字母与下划线形式名称：

```c
{                                                                                          \
        .dev = DEVICE_DT_GET(DT_HWSPINLOCK_CTRL_BY_NAME(node_id, name)),                   \
        .id = DT_HWSPINLOCK_ID_BY_NAME(node_id, name),                                     \
}
```

以下片段为两个锁指定读取和写入名称：

```dts
n: node {
        hwlocks = <&hwlock 8>,
                  <&hwlock 9>;
        hwlock-names = "rd", "wr";
};
```

按写入名称取得规格：

```c
const struct hwspinlock_dt_spec spec = HWSPINLOCK_DT_SPEC_GET_BY_NAME(DT_NODELABEL(n), wr);
```

## 1.3\_实例形式的规格宏

下列宏中的`inst`都是`DT_DRV_COMPAT`实例编号；`idx`为`hwlocks`元素索引，`name`为小写字母与下划线形式的元素名称。

`HWSPINLOCK_DT_SPEC_INST_GET(inst)`是`HWSPINLOCK_DT_SPEC_GET()`的实例版本：

```c
HWSPINLOCK_DT_SPEC_GET(DT_DRV_INST(inst))
```

`HWSPINLOCK_DT_SPEC_INST_GET_BY_IDX(inst, idx)`是按索引取得规格的实例版本：

```c
HWSPINLOCK_DT_SPEC_GET_BY_IDX(DT_DRV_INST(inst), idx)
```

`HWSPINLOCK_DT_SPEC_INST_GET_BY_NAME(inst, name)`是按名称取得规格的实例版本：

```c
HWSPINLOCK_DT_SPEC_GET_BY_NAME(DT_DRV_INST(inst), name)
```

## 1.4\_为各硬件锁定义本地自旋锁数组

`HWSPINLOCK_SPINLOCK_ARRAY_DT_DEFINE(node_id)`为每个硬件自旋锁定义关联的软件自旋锁（Spinlock）。它利用标准属性`num-locks`确定数组大小；所得数组由`HWSPINLOCK_COMMON_CONFIG_FROM_DT_NODE()`使用。结果是含`num-locks`把锁的数组定义：

```c
static struct k_spinlock __HWSPINLOCK_SPINLOCK_ARRAY_NAME_FROM_DT_NODE(                    \
        node_id)[__HWSPINLOCK_NUM_LOCKS_FROM_DT_NODE(node_id)]
```

`HWSPINLOCK_SPINLOCK_ARRAY_DT_INST_DEFINE(inst)`是对应实例版本；数组由`HWSPINLOCK_COMMON_CONFIG_FROM_DT_INST()`使用：

```c
HWSPINLOCK_SPINLOCK_ARRAY_DT_DEFINE(DT_DRV_INST(inst))
```

## 1.5\_加锁并保存锁键


```c
static inline k_spinlock_key_t hw_spin_lock(const struct device *dev, uint32_t id);
```

`dev`是硬件自旋锁设备实例，`id`是锁标识符。若锁已被另一方占用，调用会等待其释放。返回的锁键（Lock Key）必须在释放时传给`hw_spin_unlock()`。

本接口用于保护多个处理器簇（Cluster）间共享的资源。其目标不是替代普通自旋锁；但为了防止另一个线程再次获取同一把硬件锁，加锁机制也表现为普通自旋锁。由于它同时使用 Zephyr 软件自旋锁与硬件锁，因此遵循[`k_spin_lock`的规则](../kernel/P065_自旋锁公共接口.md)：不同硬件锁可以嵌套，持锁时可以获取另一把尚未锁定的锁；中央处理器（Central Processing Unit，CPU）再次尝试获取自己已持有的同一把锁会造成死锁（Deadlock）。

## 1.6\_单次尝试加锁


```c
static inline int hw_spin_trylock(const struct device *dev, uint32_t id, k_spinlock_key_t *key);
```

`dev`和`id`分别指定设备及锁；输出参数`key`指向锁键。若硬件锁被另一个处理器簇持有，立即返回`-EBUSY`。本函数关联的加锁规则见上一节。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-ENOSYS` | 未实现此操作 |
| `-EINVAL` | 硬件锁编号无效 |
| `-EBUSY` | 锁已被其他使用者持有 |

**译注：**上表保留官方接口契约。对应[可见源码](P007_硬件自旋锁驱动头文件源码.md)会在调用驱动前用`id`索引本地锁数组，并未在包装函数中先做边界检查。不可据此认为传入任意无效编号都能安全返回`-EINVAL`；应遵守下一节的最大编号查询要求。

## 1.7\_解锁与查询编号范围


```c
static inline void hw_spin_unlock(const struct device *dev, uint32_t id, k_spinlock_key_t key);
```

解锁`dev`设备上`id`指定的硬件锁。`key`为取得此锁时`hw_spin_lock()`返回的值。


```c
static inline uint32_t hw_spinlock_get_max_id(const struct device *dev);
```

返回`dev`设备的最大硬件锁编号。尝试对某一编号加锁或解锁前，应先调用此函数查询最大编号。

## 1.8\_设备树规格版本的函数

以下四个函数以`spec`指向的硬件自旋锁设备树规格代替独立设备和编号；行为与返回值分别等同于对应普通版本。


```c
static inline int hw_spin_trylock_dt(struct hwspinlock_dt_spec *spec, k_spinlock_key_t *key);
```

尝试加锁；`key`是指向输出锁键的指针，返回值见`hw_spin_trylock()`。


```c
static inline k_spinlock_key_t hw_spin_lock_dt(struct hwspinlock_dt_spec *spec);
```

等待并获取锁；返回值见`hw_spin_lock()`。


```c
static inline void hw_spin_unlock_dt(struct hwspinlock_dt_spec *spec, k_spinlock_key_t key);
```

释放锁；`key`是获取此锁时返回的键值。


```c
static inline uint32_t hw_spinlock_get_max_id_dt(struct hwspinlock_dt_spec *spec);
```

查询设备的最大锁编号；返回值见`hw_spinlock_get_max_id()`。
