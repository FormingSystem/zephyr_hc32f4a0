# 第58章\_处理器间消息公共接口

原文：[group__ipm__interface](https://docs.zephyrproject.org/latest/doxygen/html/group__ipm__interface.html)。读取日期：2026-10-13，`latest`。

本页描述处理器间邮箱（Inter-Processor Mailbox，IPM）控制器的应用程序编程接口（Application Programming Interface，API）。接口自版本1.0提供，接口版本为1.0.0；主头文件为`zephyr/drivers/ipm.h`。驱动实现所需的类型见[驱动后端](P059_处理器间消息驱动后端.md)，完整可见实现见[头文件源码](P062_处理器间消息完整头文件.md)。

## 58.1\_接收回调类型


```c
typedef void (*ipm_callback_t)(const struct device *ipmdev, void *user_data,
                               uint32_t id, volatile void *data);
```

`ipm_callback_t`是收到消息时使用的回调（Callback）函数指针类型，通过`ipm_register_callback()`注册。回调在中断上下文（Interrupt Context）执行，因此只能调用中断安全（Interrupt-safe）的接口。

| 参数 | 含义 |
| --- | --- |
| `ipmdev` | 驱动实例 |
| `user_data` | 注册时提供的私有数据指针 |
| `id` | 消息类型标识符（Message Type Identifier） |
| `data` | 消息数据指针；应读取多少数据必须根据消息标识符／上层协议推断 |

## 58.2\_发送消息


```c
int ipm_send(const struct device *ipmdev, int wait, uint32_t id,
                       const void *data, int size);
```

尝试通过 IPM 设备发送消息。远端中断处理程序（Interrupt Handler）结束时，消息就被视为已消费（Consumed）。若远端需要延后处理，或希望把待发送消息排入队列并等待事件／信号量（Event / Semaphore），可以在上层驱动中实现。

发送数据量和`id`最大值均有限制，分别使用`ipm_max_data_size_get()`和`ipm_max_id_val_get()`查询。`size`仅供发送方确定要写入消息寄存器的数据量，**不会传给接收方**；接收方读取多少数据由上层协议规定。

| 参数 | 含义 |
| --- | --- |
| `ipmdev` | 驱动实例 |
| `wait` | 非零时无限期忙等（Busy-wait），直到远端消费消息，即远端中断处理程序结束。远端延后处理、发送排队或事件／信号量等待可由上层驱动实现 |
| `id` | 消息标识符。原文称其值受`ipm_max_data_size_get`限制，因为许多开发板只允许用32位寄存器的一部分位存储标识符；此处引用问题见下方译注 |
| `data` | 待发送消息数据的指针 |
| `size` | 数据大小 |

**译注：**原文`id`参数的说明把上限查询写为`ipm_max_data_size_get`。本页前文和各查询函数的返回值说明表明，消息标识符上限应由`ipm_max_id_val_get()`获取；数据字节数上限由`ipm_max_data_size_get()`获取。两者不可混用。

下表中的`-EBUSY``-EMSGSIZE``-EINVAL`是错误返回码，分别对应远端仍忙、消息大小不受支持和参数无效；具体触发条件按原文列出。

| 返回值 | 含义 |
| --- | --- |
| `-EBUSY` | 远端尚未读取上次发送的数据 |
| `-EMSGSIZE` | 给定的数据大小不受驱动支持 |
| `-EINVAL` | 参数错误，例如`id`过大，或设备不是出站（Outbound）IPM通道 |
| `0` | 成功 |

## 58.3\_注册接收回调


```c
static inline void ipm_register_callback(const struct device *ipmdev,
                                         ipm_callback_t cb, void *user_data);
```

注册传入消息的回调函数。`ipmdev`是驱动实例指针；`cb`是在消息接收中断中执行的回调；`user_data`是应用专用数据指针，会在执行回调时传入。此函数返回类型为`void`。

## 58.4\_查询最大数据量


```c
int ipm_max_data_size_get(const struct device *ipmdev);
```

返回单条出站消息最多能够携带的字节数。消息载荷（Payload）通常存储在寄存器中，因此不同 IPM 实现允许的单条消息数据量不同。`ipmdev`为驱动实例指针；返回值是消息大小上限，单位为字节。

## 58.5\_查询消息标识符上限


```c
uint32_t ipm_max_id_val_get(const struct device *ipmdev);
```

返回出站消息标识符的最大可能值。许多 IPM 实现把消息标识符存放在寄存器中，而寄存器的部分位保留作其他用途。`ipmdev`为驱动实例指针；返回值为消息标识符的最大值，类型为`uint32_t`。

## 58.6\_使能入站中断与回调


```c
int ipm_set_enabled(const struct device *ipmdev, int enable);
```

使能入站（Inbound）通道的中断和回调。`ipmdev`为驱动实例指针；`enable`为0时禁用，非零时启用。成功返回`0`；设备不是入站通道时返回`-EINVAL`。

## 58.7\_通知异步命令完成


```c
void ipm_complete(const struct device *ipmdev);
```

通知异步（Asynchronous）命令完成。某些 IPM 后端能够异步交付命令：回调仍在中断上下文调用，但消息及提供的数据指针会持续处于“活动”（Active）且未确认（Unacknowledged）状态，直到后续代码调用`ipm_complete()`。原文指出后续调用预计发生在线程模式（Thread Mode）。

对于不支持异步方式的驱动，此函数为空操作（No-op）。`ipmdev`是驱动实例指针。

**实现译注：**[可见源码](P062_处理器间消息完整头文件.md)中，完成回调受异步回调配置选项`CONFIG_IPM_CALLBACK_ASYNC`控制，并且只有驱动的`complete`函数指针非`NULL`时才调用。上面关于一般发送完成时机的描述与这里的异步完成机制均为原文规定；使用异步后端时应同时遵守其完成通知要求。
