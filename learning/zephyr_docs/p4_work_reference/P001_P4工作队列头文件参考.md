<a id="a409785d1aeaa3e6bd874bc8db1ef08e7"></a>

### `K_P4WQ_ARRAY_DEFINE_WITH_DONE_HANDLER`

```c
#define K_P4WQ_ARRAY_DEFINE_WITH_DONE_HANDLER ( name, n_threads, stack_sz, flg, dn_handler )
```

展开值（Value）：

```c
static K_THREAD_STACK_ARRAY_DEFINE(_p4stacks_##name,            \
                                   n_threads, stack_sz);        \
static struct k_thread _p4threads_##name[n_threads];            \
static struct k_p4wq name[n_threads];                           \
static const STRUCT_SECTION_ITERABLE(k_p4wq_initparam,          \
                                     _init_##name) = {          \
        .num = n_threads,                                       \
        .stack_size = stack_sz,                                 \
        .threads = _p4threads_##name,                           \
        .stacks = &(_p4stacks_##name[0][0]),                    \
        .queue = name,                                          \
        .flags = K_P4WQ_QUEUE_PER_THREAD | flg,                 \
        .done_handler = dn_handler,                                                     \
}
```

静态初始化一个P4工作队列数组。

静态定义一个`struct k_p4wq`对象数组，配置指定数量的线程；它们将在启动时初始化，在进入`main()`时即可使用。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 要定义的`struct k_p4wq`数组的符号名称。 |
| `n_threads` | 线程与工作队列的数量。 |
| `stack_sz` | 每个线程请求的栈大小，单位为字节。 |
| `flg` | 标志（Flags）。 |
| `dn_handler` | 类型为`k_p4wq_done_handler_t`的处理函数指针。 |

### `k_p4wq_add_thread()`

| `stack_size` | 线程栈大小。 |

<a id="aede724dfe684f0a4e93845dee342f830"></a>

### `k_p4wq_cancel()`

```c
bool k_p4wq_cancel ( struct k_p4wq * queue, struct k_p4wq_work * item )
```

取消已提交的P4工作项。

取消先前提交的工作项，并将其从队列中移除。如果在队列中找到并移除了该条目，则返回`true`。如果返回`false`，则该条目可能从未提交、已经执行，或仍在运行。

返回（Returns）：成功移除条目时返回`true`，否则返回`false`。

### `k_p4wq_submit()`

```c
void k_p4wq_submit ( struct k_p4wq * queue, struct k_p4wq_work * item )
```

向P4队列提交工作项。

向队列提交指定工作项。调用者必须已经初始化结构体中的相关字段。当有CPU时间可用且没有更高优先级工作项可执行时，队列会执行该处理函数。处理函数可能在任意CPU上调用。

结构体存放在队列中期间，调用者不得修改它。在调用`k_p4wq_cancel()`或进入处理函数之前，这块内存应保持不变。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `queue` | 要提交到的P4队列。 |
| `item` | 要提交的P4工作项。 |

说明（Note）：此调用是一个调度点（Scheduling Point）。如果提交的工作项或其他任何就绪线程的优先级高于当前线程，且当前线程的优先级允许抢占，那么调用者会让出CPU。

## 1.6\_源码定位与版本边界

相对源码定位：[P4工作队列头文件](../../../include/zephyr/sys/p4wq.h)、[队列实现](../../../lib/os/p4wq.c)、[配置选项](../../../lib/os/Kconfig)及[构建条件](../../../lib/os/CMakeLists.txt)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：P4展开为Pooled Parallel Preemptible Priority-based，即池化、并行、可抢占、按优先级调度。它维护自己的工作线程池、等待队列和待执行红黑树。此前[RTIO工作队列](../rtio_work_reference/P005_RTIO工作队列头文件参考.md)虽然公开结构包含k_p4wq_work，本次RTIO实现却使用k_queue和专用线程；两者不能按成员名称混同。

> 译注——源码核对：本次构建条件在lib/os/CMakeLists.txt中以CONFIG_SCHED_DEADLINE选择p4wq.c。静态初始化通常位于APPLICATION阶段、优先级99；启用CONFIG_P4WQ_INIT_STAGE_EARLY时改为POST_KERNEL阶段、优先级1。源码中提到SMP初始化级别的旧注释不替代实际SYS_INIT参数。

> 译注——源码核对：K_P4WQ_DEFINE系列创建一个队列共享多个线程；ARRAY系列创建n_threads个队列，并通过QUEUE_PER_THREAD让每个队列对应一个线程。静态宏还创建线程栈、线程对象和可迭代初始化记录。动态k_p4wq_add_thread需要调用者提供未使用或已中止的线程对象及有效栈内存，不是自动分配所有资源。

> 译注——源码核对：k_p4wq_init()先清零整个队列再初始化内部结构，因此预先写入的flags和done_handler会被清除。添加线程前应先完成队列初始化，再按所用入口设置相关配置；不能对仍在使用的队列重新调用init。

> 译注——源码核对：工作项priority采用线程调度语义；deadline在提交时会加上k_cycle_get_32()，从相对周期数转换为内部绝对周期计数，不能当作毫秒值。若处理函数再次提交同一工作项，应重新准备所需的相对deadline，不能盲目复用已被转换的值。同优先级、同deadline时，本次红黑树用节点地址打破平局，不保证先进先出。

> 译注——源码核对：本次提交逻辑会检查正在执行的高优先级工作，并尝试唤醒合适的空闲工作线程。线程池不足时仅记录优先级保证被违反的警告，提交函数仍返回void，条目仍留在队列中；不能把可配置优先级解释成任意负载下都满足执行时限的保证。

> 译注——源码核对：取消只在待执行红黑树中查找并移除条目，不中止正在运行的处理函数。原文说内存在调用cancel前不得改变，但不能把“调用过cancel”理解成已安全收回所有权：必须结合true返回或已完成通知判断，false也可能意味着工作仍在运行。

> 译注——源码核对：没有done_handler时，正常完成及成功取消都会give工作项的done_sem；同步work的k_p4wq_wait会按timeout获取该信号量，非同步work只检查计数，未完成时返回-EBUSY。超时或-EBUSY不能证明队列已不再使用工作项；等待成功后再按生命周期重用或释放。

> 译注——源码核对：设置队列done_handler后，正常完成或成功取消调用该回调，执行的是与give done_sem互斥的分支。因此不能在该配置下假定k_p4wq_wait仍会收到常规完成信号量。原注释描述成功执行后的回调，但本次成功取消路径也调用它，应用不能据回调发生就认定handler已经执行过。

> 译注——源码核对：原文允许处理函数入口后访问工作项，但处理函数返回后队列仍要处理活动链表、线程字段和完成通知；不能在普通handler中提前释放整个工作项内存。回调完成通知或适当等待用于确认所有权。当前代码支持handler内部重新提交的特殊路径，不等于外部线程可随时重复提交仍在排队或运行的同一对象。

> 译注——源码核对：DELAYED_START会让工作线程创建后暂不启动；静态初始化遇到USER_CPU_MASK也会附加延迟启动。k_p4wq_enable_static_thread按构建配置处理CPU掩码并启动延迟线程；PIN_ONLY配置要求掩码恰好一个位。CPU亲和性（CPU Affinity）受CONFIG_SCHED_CPU_MASK等选项控制，不能把原文“任意CPU”理解成无视已配置的亲和性限制。

> 译注——源码核对：本次译注以来源记录中的官方源码摘要为界。本仓库同名文件通过相对链接定位，不将任意本地版本或作者环境当作读者前提。
