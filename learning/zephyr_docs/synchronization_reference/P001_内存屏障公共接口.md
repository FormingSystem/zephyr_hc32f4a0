## 1.3\_详细说明（Detailed Documentation）

<a id="gab0dd6769236babde7cf48c32007edf31"></a>

### `barrier_dmem_fence_full()`

```c
ALWAYS_INLINE void barrier_dmem_fence_full ( void )
```

声明属性：`static`。

```c
#include <zephyr/sys/barrier.h>
```

完整／顺序一致数据内存屏障（Full / Sequentially Consistent Data Memory Barrier）。

此例程在线程之间充当同步栅栏（Synchronization Fence），防止数据访问指令跨越屏障指令发生重排序（Reordering）。

> 译注——源码核对：公共头文件只有在选择CONFIG_BARRIER_OPERATIONS_ARCH或CONFIG_BARRIER_OPERATIONS_BUILTIN时才调用后端；两者均未启用时包装函数体为空。内建后端调用顺序一致栅栏，Arm架构后端调用__DMB。不能只根据函数名判断当前构建一定发出了哪条指令。

<a id="gaaa6909c1410bc371f59ad3eec21ee5ef"></a>

### `barrier_dsync_fence_full()`

```c
ALWAYS_INLINE void barrier_dsync_fence_full ( void )
```

声明属性：`static`。

```c
#include <zephyr/sys/barrier.h>
```

完整／顺序一致数据同步屏障（Full / Sequentially Consistent Data Synchronization Barrier）。

与barrier_dmem_fence_full()一样，此例程在线程之间充当同步栅栏，防止数据访问指令跨越屏障指令发生重排序。此外，在同步完成之前，它还会阻止后续任何指令执行，而不仅是加载（Load）或存储（Store）指令。

**说明（Note）**：如果硬件或架构不支持，此指令退化为完整／顺序一致数据内存屏障。

> 译注——源码核对：内建后端的此函数与dmem使用相同的顺序一致栅栏；这对应原文说明的回退情形，不保证额外的硬件数据同步效果。Arm架构后端则调用__DSB，须结合实际选择的后端判断。

<a id="gaa916454a2ff58e50b2f51845447177ec"></a>

### `barrier_isync_fence_full()`

```c
ALWAYS_INLINE void barrier_isync_fence_full ( void )
```

声明属性：`static`。

```c
#include <zephyr/sys/barrier.h>
```

完整／顺序一致指令同步屏障（Full / Sequentially Consistent Instruction Synchronization Barrier）。

此例程用于保证后续指令被取入，并保证之前执行的上下文改变操作，例如写入系统控制寄存器，在此例程完成时已经完成。从硬件角度看，这可能意味着清空指令流水线（Instruction Pipeline）。

**说明（Note）**：如果硬件或架构不支持，此指令退化为编译器屏障（Compiler Barrier）。

> 译注——源码核对：内建后端当前是带memory破坏描述的空volatile汇编，属于编译器屏障，不会因此自动生成清空处理器指令流水线的指令。Arm架构后端调用__ISB。两种实现分别对应架构支持与回退情形。

<a id="ga4c456ba144bf4b7cf5c5b58312bda29a"></a>

### `barrier_sync_synchronize()`

```c
ALWAYS_INLINE void barrier_sync_synchronize ( void )
```

声明属性：`static`。

```c
#include <zephyr/sys/barrier.h>
```

跨核心的完整／顺序一致数据内存屏障（Full / Sequentially Consistent Data Memory Barrier）。

此例程在线程／核心之间充当同步栅栏，防止数据访问指令跨越屏障指令发生重排序。

> 译注——源码核对：本次内建后端与Arm架构后端均调用__sync_synchronize。屏障约束访问顺序，不会自动执行缓存写回／失效，也不是等待若干线程全部到达的集合式同步屏障。
