在定义此条件变量的模块之外，可通过以下声明访问它：

原始示例（Example）：

```c

```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 条件变量的名称。 |

> 译注——源码核对：此宏初始化条件变量的等待队列，不存放应用条件表达式或通知计数。原始extern示例中的<name>须替换为实际变量标识符。

<a id="gad2e46a7b9e1bc934fd1f5cb38dde40d8"></a>

### `k_condvar_broadcast()`

```c
int k_condvar_broadcast ( struct k_condvar * condvar)
```

```c
#include <zephyr/kernel.h>
```

解除所有正在等待该条件变量的线程的阻塞状态。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `condvar` | 指向k_condvar结构的指针。 |

**返回（Returns）**：成功时返回一个整数，表示唤醒的线程数。

> 译注——源码核对：返回的是本次从等待队列唤醒的线程数，可以为0。被唤醒者还需重新取得互斥量，再检查应用条件，不能把广播理解为所有线程已同时完成等待函数。

<a id="gac9b497c56cc4642965afa6c0c6d7ecfc"></a>

### `k_condvar_init()`

```c
int k_condvar_init ( struct k_condvar * condvar)
```

```c
#include <zephyr/kernel.h>
```

初始化条件变量。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `condvar` | 指向k_condvar结构的指针。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 条件变量创建成功。 |

> 译注——源码核对：应在第一次等待／通知前初始化。条件变量保存等待队列，实际条件仍由应用在互斥量保护下管理；不应在仍有等待者时重新初始化。

<a id="ga0376a8f7dc6e4f1e1eed55940f43015b"></a>

### `k_condvar_signal()`

```c
int k_condvar_signal ( struct k_condvar * condvar)
```

```c
#include <zephyr/kernel.h>
```

通知一个正在等待该条件变量的线程。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `condvar` | 指向k_condvar结构的指针。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 操作成功。 |

> 译注——源码核对：当前实现没有等待者时也返回0，且不保存一次供未来wait消费的通知。返回0不是“已唤醒一个线程”的数量证明；应用仍需在持锁状态下维护真实条件。

<a id="gab2e1d05db4f954755f430ca894e44dbc"></a>

### `k_condvar_wait()`

```c
int k_condvar_wait ( struct k_condvar * condvar, struct k_mutex * mutex, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

等待条件变量，并释放互斥量锁。

以原子方式释放当前持有的互斥量，阻塞当前线程以等待condvar指定的条件变量，最后再次取得该互斥量。

只有当另一个线程针对同一个条件变量调用k_condvar_signal或k_condvar_broadcast后，等待线程才会解除阻塞。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `condvar` | 指向k_condvar结构的指针。 |
| `mutex` | 互斥量的地址。 |
| `timeout` | 等待条件变量的时长，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 操作成功。 |
| `-EAGAIN` | 等待时间已到，发生超时。 |

> 译注——源码核对：原文“只有通知才解除阻塞”的措辞不包含后文列出的超时路径。当前实现中K_NO_WAIT直接返回-EAGAIN且不解锁；其他等待返回后，无论收到通知还是超时，都以K_FOREVER重新取得mutex，因此timeout不是整个调用的严格耗时上限。当前实现只调用一次unlock，不会清空递归加锁计数；调用前应确保该互斥量由当前线程持有且只加锁一次。被唤醒后仍须在持锁状态下重新检查应用条件。
