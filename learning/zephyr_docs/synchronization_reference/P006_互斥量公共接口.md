STRUCT_SECTION_ITERABLE(k_mutex, name) = \

在定义此互斥量的模块之外，可通过以下声明访问它：

原始示例（Example）：

```c

```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `name` | 互斥量的名称。 |

> 译注——源码核对：原始extern示例中的<name>是名称占位符，应替换为实际互斥量标识符，不能连同尖括号直接编译。该宏用STRUCT_SECTION_ITERABLE定义并初始化对象，不是在堆上动态分配锁。

<a id="ga56b64952fb8b78b00268a21c28b41480"></a>

### `k_mutex_init()`

```c
int k_mutex_init ( struct k_mutex * mutex)
```

```c
#include <zephyr/kernel.h>
```

初始化互斥量。

此例程在互斥量对象第一次使用前初始化它。

完成后，互斥量可用，且没有拥有者（Owner）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mutex` | 互斥量的地址。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 已创建互斥量对象。 |

> 译注——源码核对：这是首次使用前的初始化，不是用于强制释放已持有互斥量的重置操作。当前实现清空拥有者、计数和等待队列；在仍被线程持有或等待时重初始化会破坏对象状态。

<a id="ga850549358645249c285669baa49c33b0"></a>

### `k_mutex_lock()`

```c
int k_mutex_lock ( struct k_mutex * mutex, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

锁定互斥量。

此例程锁定mutex。如果互斥量已被另一个线程锁定，调用线程会等待，直到互斥量可用或发生超时。

允许线程再次锁定自己已经持有的互斥量。该操作立即完成，并将加锁计数（Lock Count）增加1。

不得在中断服务程序（Interrupt Service Routine，ISR）中锁定互斥量。

互斥量处于锁定状态或仍有线程等待它时，不得释放它或复用它所在的内存。如果互斥量嵌入动态分配的对象中，必须在释放该对象前解锁；否则，拥有者线程仍会追踪位于已不属于该对象的内存中的互斥量。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mutex` | 互斥量的地址。 |
| `timeout` | 等待锁定互斥量的时长，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 互斥量已锁定。 |
| `-EBUSY` | 未等待便返回。 |
| `-EAGAIN` | 等待时间已到，发生超时。 |

> 译注——源码核对：K_NO_WAIT失败对应-EBUSY，等待超时对应-EAGAIN；当前线程再次加锁成功会增加递归计数。即使指定K_NO_WAIT，也不能在ISR中使用互斥量。优先级继承的链遍历和延后恢复存在实现边界，见本页源码跟踪说明。

<a id="ga360f4c0e7258b0d7030cdb1f452b2c31"></a>

### `k_mutex_unlock()`

```c
int k_mutex_unlock ( struct k_mutex * mutex)
```

```c
#include <zephyr/kernel.h>
```

解锁互斥量。

此例程解锁mutex。调用线程必须已经锁定该互斥量。

只有当调用线程解锁的次数与此前加锁的次数相等后，其他线程才能取得该互斥量。

不得在ISR中解锁互斥量；由于拥有者和优先级继承（Priority Inheritance）的语义，互斥量只能在线程上下文（Thread Context）中操作。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `mutex` | 互斥量的地址。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 互斥量已解锁。 |
| `-EPERM` | 当前线程不是该互斥量的拥有者。 |
| `-EINVAL` | 互斥量未处于锁定状态。 |

> 译注——源码核对：成功返回0不一定表示锁已完全释放：递归计数大于1时仅减1，拥有者仍不变。计数降至最后一层时，当前实现可直接把拥有权交给等待者；不得由其他线程代为解锁或提前释放存储。

## 6.5\_源码定位与版本边界

> 译注——阅读与源码边界：先读[互斥量指南](../kernel/P011_互斥量.md)。本次mutex.c在Z_MUTEX_PI_ENABLED条件下跟踪线程持有的互斥量列表，释放锁后按其余等待者重新计算优先级；继承链遍历的MUTEX_CHAIN_WALK_MAX_HOPS为16，这是一次遍历的工作量上限，不是允许形成的链长度上限。超时后的优先级降低在等待者恢复执行后处理，且不会沿更深的拥有链完整传播；不要将优先级继承理解为消除所有死锁或即时恢复全部线程优先级的保证。

仓库相对定位：[kernel.h](../../../include/zephyr/kernel.h)与[kernel/mutex.c](../../../kernel/mutex.c)。本次依据为[官方内核头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/kernel.h)与[官方实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/mutex.c)。
