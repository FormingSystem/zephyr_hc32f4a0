# 第4章\_宏工具头文件参考

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/util__macro_8h.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：按[本册大纲](大纲.md)查公共接口、宏展开和内部查找表；使用前先核对参数范围、类型及求值次数。源码跟踪译注与官方原文分开标示。

宏工具（Macro Utilities）。

<a id="details"></a>

```c
#include <zephyr/sys/util_internal.h>
```

查看此文件的源码。

宏工具。为 C/C++ 代码和设备树（Devicetree）相关实现提供公共接口。一般情况下，C/C++ 应包含 <sys/util.h>，而不直接包含此文件；设备树实现应包含此文件，而不是 <sys/util_internal.h>。

## 4.1\_宏定义（Macros）

<a id="r_ga3a8ea58898cb58fc96013383d39f482c"></a>

```c
#define BIT(n)
```

相关声明：[BIT](P001_通用工具公共接口.md#ga3a8ea58898cb58fc96013383d39f482c)。

仅位位置 n 置位的无符号整数；在汇编语言中为有符号整数。

<a id="r_gacfdade52af3ced2d87472cec47d14a76"></a>

```c
#define BIT64(_n)
```

相关声明：[BIT64](P001_通用工具公共接口.md#gacfdade52af3ced2d87472cec47d14a76)。

仅位位置 _n 置位的 64 位无符号整数。

<a id="r_ga23a900e882ecb48455e70f01fd45b246"></a>

```c
#define WRITE_BIT(var, bit, set)
```

相关声明：[WRITE_BIT](P001_通用工具公共接口.md#ga23a900e882ecb48455e70f01fd45b246)。

根据布尔值设置或清除无符号整数中的一位。

<a id="r_ga3c12c6d36ad0aa481a3436923d21f4f8"></a>

```c
#define BIT_MASK(n)
```

相关声明：[BIT_MASK](P001_通用工具公共接口.md#ga3c12c6d36ad0aa481a3436923d21f4f8)。

将第 0 至第 n-1 位全部置位的位掩码；n 为 0 时结果为 0。

<a id="r_ga1a138896caafcb2429a6483ea7412d12"></a>

```c
#define BIT64_MASK(n)
```

相关声明：[BIT64_MASK](P001_通用工具公共接口.md#ga1a138896caafcb2429a6483ea7412d12)。

将第 0 至第 n-1 位全部置位的 64 位掩码；n 为 0 时结果为 0。

<a id="r_ga52d277cbf33f76350b2fcb21c24640ee"></a>

```c
#define IS_POWER_OF_TWO(x)
```

相关声明：[IS_POWER_OF_TWO](P001_通用工具公共接口.md#ga52d277cbf33f76350b2fcb21c24640ee)。

检查 x 是否为 2 的幂。

<a id="r_ga406b5955c2803cdd9d9f19c90f242662"></a>

```c
#define IS_SHIFTED_BIT_MASK(m, s)
```

相关声明：[IS_SHIFTED_BIT_MASK](P001_通用工具公共接口.md#ga406b5955c2803cdd9d9f19c90f242662)。

检查从指定位开始是否连续置位。

<a id="r_ga6d4b02e5da10bf93c4697dd6bf239ffd"></a>

```c
#define IS_BIT_MASK(m)
```

相关声明：[IS_BIT_MASK](P001_通用工具公共接口.md#ga6d4b02e5da10bf93c4697dd6bf239ffd)。

检查从最低有效位（Least Significant Bit，LSB）开始是否连续置位。

<a id="r_ga93abc3834bcb58b15c819e68d694ed20"></a>

```c
#define IS_BIT_SET(value, bit)
```

相关声明：[IS_BIT_SET](P001_通用工具公共接口.md#ga93abc3834bcb58b15c819e68d694ed20)。

检查数值中的指定位是否已经置位。

<a id="r_ga92235ab2e350fbdc01ddf0f894e5e4c0"></a>

```c
#define LSB_GET(value)
```

相关声明：[LSB_GET](P001_通用工具公共接口.md#ga92235ab2e350fbdc01ddf0f894e5e4c0)。

从 value 中提取最低的已置位位。

<a id="r_gaa49a456f06f7bdbedfcf3517e461947e"></a>

```c
#define FIELD_GET(mask, value)
```

相关声明：[FIELD_GET](P001_通用工具公共接口.md#gaa49a456f06f7bdbedfcf3517e461947e)。

从 value 中提取由字段掩码 mask 指定的位字段（Bit Field）。

<a id="r_gaa03c8b31bf67a097dd9f8153a04ef86b"></a>

```c
#define FIELD_PREP(mask, value)
```

相关声明：[FIELD_PREP](P001_通用工具公共接口.md#gaa03c8b31bf67a097dd9f8153a04ef86b)。

使用 value 生成位字段值，mask 指定字段的位置和宽度。

相关声明：[IS_ENABLED](P001_通用工具公共接口.md#ga111fe4e9d63758262fc6810a782cb32a)。

## 4.2\_源码定位与版本边界

本册提供[公共接口](P001_通用工具公共接口.md)，以及util.h、util_macro.h、util_internal.h和四份预处理查找表的独立参考与完整源码。相对源码定位：[util.h](../../../include/zephyr/sys/util.h)、[util_macro.h](../../../include/zephyr/sys/util_macro.h)、[util_internal.h](../../../include/zephyr/sys/util_internal.h)。

关联实现：[十六进制转换](../../../lib/utils/hex.c)、[十进制转换](../../../lib/utils/dec.c)、[位掩码空闲区间](../../../lib/utils/bitmask.c)、[UTF-8处理](../../../lib/utils/utf8.c)、[配置](../../../lib/utils/Kconfig)及[构建规则](../../../lib/utils/CMakeLists.txt)。UTF-8实现由CONFIG_UTF8控制。对应[官方源码目录](https://github.com/zephyrproject-rtos/zephyr/tree/main/lib/utils)和[官方头文件目录](https://github.com/zephyrproject-rtos/zephyr/tree/main/include/zephyr/sys)的本次摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：公共入口与内部实现：C/C++通常包含<zephyr/sys/util.h>；只需要预处理宏的代码可按官方要求包含<zephyr/sys/util_macro.h>。原文中省略zephyr/的历史包含路径照实保留，实际头文件位置以本册相对定位为准。util_internal及其查找表用于实现公共宏，不应作为应用稳定接口直接调用。

> 译注——源码核对：原文首段称“非空返回真”，而实际语义是展开为空返回1、非空返回0。原文又把三个示例结果写成真、假、真；按当前Z_IS_EMPTY_实现，UNDEFINED保持为非空标识符，第三项也应为假。即EMPTY得到1、NON_EMPTY得到0、UNDEFINED得到0。原句与示例原样保留，此处明确纠正两处描述，未定义与空宏不能混同。

> 译注——源码核对：原文把0至4095全部描述为x-1；当前查找表实际定义Z_UTIL_DEC_0为0，所以UTIL_DEC(0)得到0，不是-1。表中还包含4096，但公共说明范围仍为0至4095，不把内部额外条目推广为稳定契约。

> 译注——源码核对：版本与验证范围：本册保留官方声明、原始示例及全部可见源码，不以概述替代重复生成的定义。七份源码页去除注释和展示空白后与本次官方原始头文件核对一致；本仓库相对链接用于源码跟踪，不保证本地基线与滚动main完全相同。这里的边界说明来自源码阅读，未编译运行宏展开、缓冲区或硬件轮询实验。
