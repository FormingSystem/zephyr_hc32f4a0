### `COND_CODE_1`

```c

```

```c

```

展开值（Value）：

```c

```

根据 _flag 是否展开为 1 插入代码。

原始示例（Example）：

### `FOR_EACH_NONEMPTY_TERM`

```c
#define FOR_EACH_NONEMPTY_TERM ( F, term, ... )
```

```c
#include <zephyr/sys/util_macro.h>
```

展开值（Value）：

```c
COND_CODE_0(                                                    \
        /* are there zero non-empty arguments ? */              \
        NUM_VA_ARGS_LESS_1(LIST_DROP_EMPTY(__VA_ARGS__, _)),    \
        /* if so, expand to nothing */                          \
        (),                                                     \
        /* otherwise, expand to: */                             \
        (/* FOR_EACH() on nonempty elements, */         \
                FOR_EACH(F, term, LIST_DROP_EMPTY(__VA_ARGS__)) \
                /* plus a final terminator */                   \
                __DEBRACKET term                                \
        ))
```

类似 FOR_EACH()，但使用终止符（Terminator）而非分隔符，并移除实参列表中的空元素。

FOR_EACH(F, (sep), a, b) 中的 sep 是分隔符，放在对 F 的各次调用之间，如下：

原始示例（Example）：

```c
FOR_EACH(F, (sep), a, b) // F(a) sep F(b)
                         //               ^^^ no sep here!
```

相对地，FOR_EACH_NONEMPTY_TERM(F, (term), a, b) 中的 term 会添加在展开结果中每次出现的 F 之后：

原始示例（Example）：

```c
FOR_EACH_NONEMPTY_TERM(F, (term), a, b) // F(a) term F(b) term
                                        //                ^^^^
```

此外，还会删除所有空元素：

原始示例（Example）：

```c
FOR_EACH_NONEMPTY_TERM(F, (term), a, EMPTY, b) // F(a) term F(b) term
```

在某些场景下，这种方式更方便：FOR_EACH_NONEMPTY_TERM() 接受空实参列表时展开为空，而要编写一个即使收到空实参也能正确工作的宏 F，往往较麻烦。

例如，__VA_ARGS__ 可能为空，也可能不为空，而结果需要嵌入更大的初始化器（Initializer）：

原始示例（Example）：

```c
#define SQUARE(x) ((x)*(x))

int my_array[] = {
        FOR_EACH_NONEMPTY_TERM(SQUARE, (,), FOO(...))
        FOR_EACH_NONEMPTY_TERM(SQUARE, (,), BAR(...))
        FOR_EACH_NONEMPTY_TERM(SQUARE, (,), BAZ(...))
};
```

这比以下方式更方便：

- 先判断 FOO、BAR 和 BAZ 的展开结果是否为空，再手动决定是否在 FOR_EACH() 调用之间添加逗号；
- 或者改写 SQUARE，使它能在 "x" 为空时正确处理，例如 FOO 展开为空时就需要这样做。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `F` | 对可变实参中的每个非空元素调用的宏。 |
| `term` | 放在每次 F 调用之后的终止符，例如逗号或分号。必须用圆括号包围，以便允许使用逗号。 |
| `...` | 可变实参列表；对列表中的每个非空元素，以 F(element) 形式调用宏 F。 |

### `IS_ENABLED`

```c

```

```c

```

在编译器可见的表达式中检查宏定义。

这种技巧最早出现在 Linux 的 config_enabled() 宏中。它将可能定义为 "1"、也可能完全未定义的宏值，转换为 C 编译器能够处理的字面表达式，而不仅限于预处理器处理。它常与 CONFIG_FOO 宏一起使用；该宏可以由 Kconfig 定义为 1，也可以保持未定义。

这种写法更清晰，因为即使 CONFIG_FOO 未定义，编译器仍然能够针对 do_something_with_foo 生成错误和警告。

注意：不建议在 #if 语句中使用 IS_ENABLED，因为相对于直接使用 #if defined()，它没有额外好处。
