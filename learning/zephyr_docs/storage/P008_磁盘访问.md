# 第8章\_磁盘访问

原文：[Disk Access](https://docs.zephyrproject.org/latest/services/storage/disk/access.html)。读取日期：2026-10-12，`latest`。

**磁盘访问（Disk Access）**的**应用程序编程接口（Application Programming Interface，API）**提供对存储设备的访问。

## 8.1\_初始化与反初始化

SD 卡等磁盘设备支持热插拔，因此 API 提供初始化和反初始化控制命令（IOCTL）：

| 命令 | 作用 |
| --- | --- |
| `DISK_IOCTL_CTRL_INIT` | 初始化磁盘。进一步 I/O 前必须调用，等价于旧接口 `disk_access_init()` |
| `DISK_IOCTL_CTRL_DEINIT` | 反初始化磁盘。此后必须重新初始化才能继续 I/O |

初始化与反初始化调用需要配对：只有反初始化次数追平初始化次数后，才真正反初始化磁盘。

也可以给 `DISK_IOCTL_CTRL_DEINIT` 传入一个指向值为 `true` 的布尔变量的指针，强制反初始化。这是不安全的操作，各驱动处理方式可能不同，但它总是返回表示成功的值。

反初始化属于底层操作，通常应由文件系统实现处理。应用一般不需要手动调用磁盘反初始化，而应使用 `fs_unmount()` 卸载文件系统。

## 8.2\_SD卡支持

Zephyr 支持部分 SD 卡控制器，也支持通过 **串行外设接口（Serial Peripheral Interface，SPI）** 连接 SD 卡。这些驱动采用磁盘驱动接口，文件系统可通过 Disk Access API 访问标准容量和高容量 SD 卡。

> 原文注意：FAT 文件系统不具备掉电安全性。突然断电，或未卸载就拔卡，可能损坏文件系统。

### 8.2.1\_SD存储卡子系统

可通过磁盘驱动 API 或 SDMMC 子系统访问 SD 存储卡。SDMMC 可以透明地服务于磁盘驱动 API，也允许直接进行块级访问，并通过 [SD 主机控制器 API](https://docs.zephyrproject.org/latest/hardware/peripherals/sdhc.html#sdhc-api)与卡通信。

### 8.2.2\_通过SPI连接SD卡

下面设备树片段将 SD 卡节点加入 `spi1`，使用 PA27 作片选，初始化后以 24 MHz 运行 SPI：

```dts
&spi1 {
        status = "okay";
        cs-gpios = <&porta 27 GPIO_ACTIVE_LOW>;

        sdhc0: sdhc@0 {
                compatible = "zephyr,sdhc-spi-slot";
                reg = <0>;
                status = "okay";
                mmc {
                    compatible = "zephyr,sdmmc-disk";
                    disk-name = "SD";
                    status = "okay";
                };
                spi-max-frequency = <24000000>;
        };
};
```

原文说明，开发板启动时文件系统驱动会自动检测和初始化 SD 卡。文件与目录操作使用 [include/zephyr/fs/fs.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/fs/fs.h) 中的文件系统接口，例如 `fs_open()`、`fs_read()`、`fs_write()`，详见[文件系统](P007_文件系统.md)。

> 译注：自动访问依赖相应驱动和文件系统挂载配置，单独加入节点并不代表应用已经挂载了文件系统。PA27、`porta` 和 24 MHz 均为原例参数，实际接线、引脚复用及可用频率需要按目标板确定。

## 8.3\_eMMC支持

Zephyr 也通过 Disk Access API 支持 eMMC。由于 MMC 总线与 SD 总线非常相似，MMC 基于 SD 子系统实现，MMC 控制器也使用 SDHC 设备驱动 API。

## 8.4\_把Flash分区模拟为块设备

`flashdisk` 驱动可将 Flash 分区作为块设备，实例通过设备树定义：

```dts
/ {
    msc_disk0 {
        compatible = "zephyr,flash-disk";
        partition = <&storage_partition>;
        disk-name = "NAND";
        cache-size = <4096>;
    };
};
```

原文要求 [zephyr,flash-disk](../misc_nxp_renesas_zephyr_binding_reference/P041_zephyr_flash-disk.md#std-dtcompatible-zephyr-flash-disk) 节点中的缓存大小等于底层分区的最小可擦除块大小。

> 译注：`disk-name = "NAND"` 只是此例选用的逻辑磁盘名，并不表示底层必然是 NAND 器件；也不能据此把所有 Flash 的擦除块大小都设为 4096。实际驱动对擦除布局和缓存大小的要求应结合目标介质核对。

## 8.5\_其他块设备

Zephyr 还支持 [NVMe 磁盘](P028_NVMe磁盘驱动.md)和 [VirtIO 块设备](P029_VirtIO块设备驱动.md)，各自文档说明其配置与行为。

## 8.6\_配置与API

Disk Access 相关 Kconfig 配置为 `CONFIG_DISK_ACCESS`，磁盘驱动相关配置为 `CONFIG_DISK_DRIVERS`。

应用接口见[磁盘访问 API](https://docs.zephyrproject.org/latest/doxygen/html/group__disk__access__interface.html)，驱动接口见[磁盘驱动 API](https://docs.zephyrproject.org/latest/doxygen/html/group__disk__driver__interface.html)。关联的[文件系统操作示例](P084_文件系统操作示例.md)展示不同文件系统和存储设备的使用。
