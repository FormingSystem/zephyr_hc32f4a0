# 第11章\_引导加载器信息

原文：[Bootloader Information](https://docs.zephyrproject.org/latest/services/storage/retention/blinfo.html)。读取日期：2026-10-13，`latest`。

**引导加载器信息（Bootloader Information，blinfo）**子系统是[数据保留系统](P010_数据保留服务.md)的扩展。它读取引导加载器共享的数据，并允许应用查询。还可选择把取得的信息组织起来，放入[设置子系统（Settings）](P005_设置子系统.md)，使用 `blinfo/` 前缀。

## 11.1\_设备树设置

需要创建一个数据保留区域，其父节点是保留数据区域，通常用**未初始化随机存取存储器（Non-Initialized Random Access Memory，Non-Init RAM）**实现。以下官方示例基于 [nRF52840 DK](https://docs.zephyrproject.org/latest/boards/nordic/nrf52840dk/doc/index.html#nrf52840dk) 开发板及其内存布局：

译注：示例中的 `DT_SIZE_K()` 是按 1024 倍换算字节数的设备树宏。**静态随机存取存储器（Static Random Access Memory，SRAM）**的第一块区域以 `sram0` 节点引用，原注释记为 SRAM0。

```dts
/ {
        sram@2003FC00 {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FC00 DT_SIZE_K(1)>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        boot_info0: boot_info@0 {
                                compatible = "zephyr,retention";
                                status = "okay";
                                reg = <0x0 0x100>;
                        };
                };
        };

        chosen {
                zephyr,bootloader-info = &boot_info0;
        };
};


/* Reduce SRAM0 usage by 1KB to account for non-init area */
&sram0 {
        reg = <0x20000000 DT_SIZE_K(255)>;
};
```

必须在引导加载器 MCUboot 和应用两侧都应用此配置，才能正常使用。它可以与其他数据保留接口结合，例如[启动模式](P010_数据保留服务.md#boot-mode)。

译注：示例为未初始化区域预留 1 KiB，其中 `boot_info0` 使用 256 字节；末尾相应缩减普通 SRAM。该布局仅用于说明，不能把示例地址直接套用到另一块开发板。

## 11.2\_MCUboot配置

应用上述设备树配置后，需要让 MCUboot 把共享数据存入该区域。原文要求设置以下 Kconfig 配置项：

| 配置项 | 作用 |
| --- | --- |
| [`CONFIG_RETAINED_MEM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM) | 启用保留内存驱动 |
| [`CONFIG_RETENTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION) | 启用数据保留系统 |
| `CONFIG_BOOT_SHARE_DATA` | 启用共享数据 |
| `CONFIG_BOOT_SHARE_DATA_BOOTINFO` | 启用启动信息共享数据类型 |
| `CONFIG_BOOT_SHARE_BACKEND_RETENTION` | 通过 retention/blinfo 子系统存储共享数据 |

## 11.3\_应用基础配置与查询函数

应用侧需启用 [`CONFIG_RETAINED_MEM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM)、[`CONFIG_RETENTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION)、[`CONFIG_RETENTION_BOOTLOADER_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_BOOTLOADER_INFO) 和 [`CONFIG_RETENTION_BOOTLOADER_INFO_TYPE_MCUBOOT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_BOOTLOADER_INFO_TYPE_MCUBOOT)，分别提供保留内存驱动、数据保留系统、引导加载器信息子系统和 MCUboot 信息类型支持。

使用此子系统需要包含以下头文件：

```c
#include <zephyr/retention/blinfo.h>
```

默认只提供查询函数 [`blinfo_lookup()`](P016_引导加载器信息接口.md)，应用可用它查询来自引导加载器的信息。此函数由默认启用的 Kconfig 配置项 [`CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_FUNCTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_FUNCTION) 提供；应用也可改为选择设置存储功能。

## 11.4\_通过设置键查询

使用设置存储方式时，通过设置键查询引导加载器信息。需要启用 [`CONFIG_SETTINGS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SETTINGS)、[`CONFIG_SETTINGS_RUNTIME`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SETTINGS_RUNTIME) 与 [`CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_SETTINGS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_BOOTLOADER_INFO_OUTPUT_SETTINGS)，分别提供设置子系统、运行时访问和 blinfo 设置输出。

随后可用 [`settings_runtime_get()`](P017_设置运行时接口.md) 函数读取以下键。这里的 `enum` 表示枚举类型，`struct` 表示结构体类型；类型名按原文保留。

| 设置键 | 数据含义与类型 |
| --- | --- |
| `blinfo/mode` | MCUboot 配置的运行模式，值为 `enum mcuboot_mode` |
| `blinfo/signature_type` | MCUboot 配置的签名类型（Signature Type），值为 `enum mcuboot_signature_type` |
| `blinfo/recovery` | MCUboot 启用的恢复类型（Recovery Type），值为 `enum mcuboot_recovery_mode` |
| `blinfo/running_slot` | 当前运行的槽位；在直接原位执行模式中，可用来判断更新应写入哪个槽位 |
| `blinfo/bootloader_version` | 引导加载器版本，数据为 `struct image_version` 对象 |
| `blinfo/max_application_size` | 能够加载的应用最大大小，单位字节 |

**直接原位执行（Direct Execute In Place，Direct-XIP）**是表中运行槽位用途对应的模式名称。

除了前面的 blinfo 头文件，此模式还需包含以下头文件：

```c
#include <bootutil/boot_status.h>
#include <bootutil/image.h>
#include <zephyr/mcuboot_version.h>
#include <zephyr/settings/settings.h>
```
