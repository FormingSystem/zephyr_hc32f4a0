# 第10章\_数据保留服务

原文：[Retention System](https://docs.zephyrproject.org/latest/services/storage/retention/index.html)。读取日期：2026-10-13，`latest`。

**数据保留系统（Retention System）**提供应用程序编程接口（Application Programming Interface，API），供应用读写在设备保持供电时能够保存内容的内存区域或设备。它让不同应用之间、或同一应用内部能够共享信息，在设备重启时不丢失状态。

这里的数据不应在掉电后继续保留；某些设备进入部分低功耗模式时也会丢失这些数据。它不应保存到 Flash、EEPROM 或电池备份 RAM 等非易失性存储中。对应名称分别为**闪存（Flash Memory）**、**电可擦可编程只读存储器（Electrically Erasable Programmable Read-Only Memory，EEPROM）**及**电池备份随机存取存储器（Battery-Backed Random Access Memory）**。

## 10.1\_在驱动之上验证与划分数据

数据保留系统建立在**保留数据驱动（Retained Data Driver）**之上，并增加用于确保数据有效性的软件功能。可以选择使用**魔数头（Magic Header）**，检查保留内存区域的开头是否包含指定值；也可以在数据末尾附加一个 1、2 或 4 字节的**校验和（Checksum）**。

API 还支持把保留区域分成多个独立区域。例如，64 字节可分为 4 字节的启动模式、16 字节的时间戳和 44 字节的上一条日志。各区域可独立访问或更新；前缀（Prefix）与校验和可在设备树中按实例设置。

## 10.2\_设备树设置

使用此系统前，需要为开发板配置保留数据驱动。Zephyr 提供一个驱动，可使用一部分**随机存取存储器（Random Access Memory，RAM）**作为未初始化区域（Non-Init Area）。随后把一个或多个保留系统实例定义为该设备的子节点。必须相应缩减普通内存区域，扣除预留的 RAM。

下面的官方示例基于 [nRF52840 DK](https://docs.zephyrproject.org/latest/boards/nordic/nrf52840dk/doc/index.html#nrf52840dk) 开发板及其内存布局：

译注：示例中的 `DT_SIZE_K()` 是按 1024 倍换算字节数的设备树宏。**静态随机存取存储器（Static Random Access Memory，SRAM）**的第一块区域以 `sram0` 节点引用，原注释记为 SRAM0。

```dts
/ {
        sram@2003FC00 {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FC00 DT_SIZE_K(1)>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        /* This creates a 256-byte partition */
                        retention0: retention@0 {
                                compatible = "zephyr,retention";
                                status = "okay";

                                /* The total size of this area is 256
                                 * bytes which includes the prefix and
                                 * checksum, this means that the usable
                                 * data storage area is 256 - 3 = 253
                                 * bytes
                                 */
                                reg = <0x0 0x100>;

                                /* This is the prefix which must appear
                                 * at the front of the data
                                 */
                                prefix = [08 04];

                                /* This uses a 1-byte checksum */
                                checksum = <1>;
                        };

                        /* This creates a 768-byte partition */
                        retention1: retention@100 {
                                compatible = "zephyr,retention";
                                status = "okay";

                                /* Start position must be after the end
                                 * of the previous partition. The total
                                 * size of this area is 768 bytes which
                                 * includes the prefix and checksum,
                                 * this means that the usable data
                                 * storage area is 768 - 6 = 762 bytes
                                 */
                                reg = <0x100 0x300>;

                                /* This is the prefix which must appear
                                 * at the front of the data
                                 */
                                prefix = [00 11 55 88 fa bc];

                                /* If omitted, there will be no
                                 * checksum
                                 */
                        };
                };
        };
};

/* Reduce SRAM0 usage by 1KB to account for non-init area */
&sram0 {
        reg = <0x20000000 DT_SIZE_K(255)>;
};
```

译注：示例预留 1 KiB，分成 256 字节和 768 字节两块。第一块含 2 字节前缀、1 字节校验，用户可用 253 字节；第二块含 6 字节前缀、没有校验，用户可用 762 字节。末尾配置把普通 SRAM 区域缩减为 255 KiB。这些地址属于示例板，不能直接视为本项目开发板的内存分配。

启用 [`CONFIG_RETENTION`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION) 后即可使用数据保留 API；它要求同时启用 [`CONFIG_RETAINED_MEM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM) 保留内存驱动支持。通过以下代码取得设备对象：

```c
#include <zephyr/device.h>
#include <zephyr/retention/retention.h>

const struct device *retention0 = DEVICE_DT_GET(DT_NODELABEL(retention0));
const struct device *retention1 = DEVICE_DT_GET(DT_NODELABEL(retention1));
```

调用写入函数时，区域中的魔数头和校验和（如果启用）会被设置；从这时起，区域被标记为有效。

## 10.3\_互斥保护与中断限制

应用启用多线程支持时，保留区域默认启用**互斥保护（Mutex Protection）**。不同线程可以安全调用保留函数，避免与其他线程的并发调用冲突；相应地，不能在**中断服务程序（Interrupt Service Routine，ISR）**中使用这些函数。

可启用 Kconfig 配置项 [`CONFIG_RETENTION_MUTEX_FORCE_DISABLE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_MUTEX_FORCE_DISABLE)，对全部保留区域全局禁用互斥保护，此时调用者负责确保各函数调用不发生冲突。使用这一方式时，还必须启用 [`CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETAINED_MEM_MUTEX_FORCE_DISABLE)，禁用底层保留内存驱动的互斥支持。

## 10.4\_启动模式

数据保留子系统还提供**启动模式（Boot Mode）**接口，使用少量函数就能在设备重启后动态改变应用状态，或运行另一个应用。例如，主应用可以不依赖物理按钮，直接请求进入 MCUboot 的**串口恢复（Serial Recovery）**功能。MCUboot 是引导加载器（Bootloader）项目名称。

使用启动模式功能，需要在设备树中创建一个专门用于模式选择的数据保留条目，用户数据区只需一个字节；再把它指定给 `chosen` 节点中的 `zephyr,boot-mode` 属性。官方示例如下：

```dts
/ {
        sram@2003FFFF {
                compatible = "zephyr,memory-region", "mmio-sram";
                reg = <0x2003FFFF 0x1>;
                zephyr,memory-region = "RetainedMem";
                status = "okay";

                retainedmem {
                        compatible = "zephyr,retained-ram";
                        status = "okay";
                        #address-cells = <1>;
                        #size-cells = <1>;

                        retention0: retention@0 {
                                compatible = "zephyr,retention";
                                status = "okay";
                                reg = <0x0 0x1>;
                        };
                };
        };

        chosen {
                zephyr,boot-mode = &retention0;
        };
};

/* Reduce SRAM0 usage by 1 byte to account for non-init area */
&sram0 {
        reg = <0x20000000 0x3FFFF>;
};
```

用 Kconfig 配置项 [`CONFIG_RETENTION_BOOT_MODE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_RETENTION_BOOT_MODE) 启用此接口，然后调用启动模式函数。如果使用 MCUboot 串口恢复，在构建 MCUboot 时启用 `CONFIG_MCUBOOT_SERIAL` 与 `CONFIG_BOOT_SERIAL_BOOT_MODE`，即可通过以下代码重启并直接进入串口恢复模式：

```c
#include <zephyr/retention/bootmode.h>
#include <zephyr/sys/reboot.h>

bootmode_set(BOOT_MODE_TYPE_BOOTLOADER);
sys_reboot(0);
```

## 10.5\_扩展模块

模块可以把数据保留系统作为传输途径，例如在引导加载器与应用之间传递信息，从而扩展其功能。对应模块见[引导加载器信息](P011_引导加载器信息.md)。
