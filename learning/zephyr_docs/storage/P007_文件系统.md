# 第7章\_文件系统

原文：[File Systems](https://docs.zephyrproject.org/latest/services/storage/file_system/index.html)。读取日期：2026-10-12，`latest`。

Zephyr **实时操作系统（Real-Time Operating System，RTOS）** 的**虚拟文件系统切换层（Virtual Filesystem Switch，VFS）**允许应用在不同挂载点同时挂载多个文件系统，例如 `/fatfs` 和 `/lfs`。挂载点结构保存实例化、挂载和操作文件系统所需的信息。VFS 通过文件系统注册机制，使应用无须直接调用某个文件系统特有的 **应用程序编程接口（Application Programming Interface，API）** 或内部函数。

## 7.1\_注册文件系统

文件系统实现或库可以通过注册 API 接入或移除。每种实现必须使用全局唯一的整数标识符；树外实现应使用 `FS_TYPE_EXTERNAL_BASE` 作为编号基础，以免与树内标识冲突。

```c
int fs_register(int type, const struct fs_file_system_t *fs);

int fs_unregister(int type, const struct fs_file_system_t *fs);
```

Zephyr 用挂载点作为磁盘卷名称，使同一文件系统支持多个实例；文件系统库在格式化或挂载时使用该名称。

## 7.2\_声明挂载点

声明示例：

```c
static struct fs_mount_t mp = {
.type = FS_FATFS,
.mnt_point = FATFS_MNTP,
.fs_data = &fat_fs,
};
```

这里 `.type` 指定文件系统类型，原例的 `FS_FATFS` 表示 FATFS；`.mnt_point` 的 `FATFS_MNTP` 为挂载路径，`.fs_data` 指向 `fs_mount()` 所需的文件系统专有数据 `fat_fs`。

> 译注：原文把 `FS_FATFS` 概括为“如 FATFS 或 LittleFS 的文件系统类型”。该枚举值实际特指 FATFS，使用 LittleFS 时需要选择相应类型和配套数据结构，不能只改变挂载路径。

## 7.3\_示例

VFS 示例主要位于 `samples/subsys/fs`；其他子系统示例也会把文件系统作为重要功能使用。原文特别推荐：

- [文件系统操作](P084_文件系统操作示例.md)：在 SDHC 介质上使用 FAT 文件系统。
- [文件系统 shell](https://docs.zephyrproject.org/latest/samples/subsys/shell/fs/README.html#shell-fs)：通过 shell 的 `fs` 子系统访问内部 Flash 中格式化为 LittleFS 的分区。
- [USB 大容量存储](../usb/P060_USB大容量存储示例.md#usb-mass)：按配置在 **随机存取存储器（Random Access Memory，RAM）** 或 **串行外设接口（Serial Peripheral Interface，SPI）** Flash 上使用 FAT，或在 Flash 上使用 LittleFS。
