# 第65章\_设置键名处理接口

原文：[group__settings__name__proc](https://docs.zephyrproject.org/latest/doxygen/html/group__settings__name__proc.html)。读取日期：2026-10-13，`latest`。

## 65.1\_只读名称处理

本页为**设置子系统（Settings Subsystem）键名（Key Name）**的只读处理接口，参数使用 `const char *`，声明位于 `zephyr/settings/settings.h`。

## 65.2\_定位下一个名称片段

[`settings_name_next()`](https://docs.zephyrproject.org/latest/doxygen/html/group__settings__name__proc.html#gacf259320845ae83c46df634f93c6d3e5) 确定第一个**分隔符（Separator）**之前的字符数。

```c
int settings_name_next(const char *name, const char **next);
```

输入 `name` 是名称字符串；输出 `next` 指向剩余名称，不包含分隔符。返回第一个分隔符的索引；若没有分隔符，则返回整个名称长度。

## 65.3\_比较名称起始部分

[`settings_name_steq()`](https://docs.zephyrproject.org/latest/doxygen/html/group__settings__name__proc.html#ga6d9d36d54a1bfd59bf7729621653edd9) 比较 `name` 的起始部分与 `key`。

```c
int settings_name_steq(const char *name, const char *key, const char **next);
```

输入 `name` 为名称字符串，`key` 为比较字符串；输出 `next` 指向剩余名称。若剩余部分以分隔符开始，`next` 会跳过该分隔符。返回 **0** 表示不匹配，返回 **1** 表示匹配；可用 `next` 检查是否完整匹配。

下表忠实保留原页列出的示例；所有调用的 `name` 都是 `"bt/btmesh/iv"`：

| `key` | 原文返回值 | 原文 `next` |
| --- | --- | --- |
| `"b"` | `1` | `"t/btmesh/iv"` |
| `"bt"` | `1` | `"btmesh/iv"` |
| `"bt/"` | `0` | `NULL` |
| `"bta"` | `0` | `NULL` |

译注：第一行与此次读取的[官方 `settings.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/settings/src/settings.c) 实现不同。该实现要求 `key` 匹配结束后，`name` 到达 `/`、`=` 或字符串结尾；`"b"` 后剩余首字符为 `t`，所以该例按实现返回 **0**，且 `next == NULL`。第二至第四行与此实现相符。以上是源码分支核对，未执行运行测试。

原文备注：如果 [`settings_handler`](P066_设置动态处理器结构.md) 的名称在末尾包含分隔符，该函数的实现可以简化。
