# 第21章\_安全存储服务

原文：[Secure Storage](https://docs.zephyrproject.org/latest/services/storage/secure_storage/index.html)。读取日期：2026-10-13，`latest`。

**安全存储子系统（Secure Storage Subsystem）**实现了**平台安全架构（Platform Security Architecture，PSA）**[安全存储应用程序编程接口（Secure Storage API）](https://arm-software.github.io/psa-api/storage/)所定义的函数。可以在尚未提供该 API 实现的[开发板目标（Board Target）](../getting_started/P006_术语表.md#term-board-target)上启用它。

## 21.1\_功能范围与安全环境

此子系统使所有支持非易失性存储的开发板目标都能使用 PSA Secure Storage API，为原先没有实现的目标补充功能支持。例如，启用 **可信固件M（Trusted Firmware-M，TF-M）**、目标名以 `/ns` 结尾的目标不能再启用此子系统，因为 TF-M 已经提供该 API 的实现。

除了提供功能支持，此子系统还可能保护通过 PSA Secure Storage API 保存的**静态数据（Data at Rest）**，实际效果取决于设备专属安全特性和配置。不过，条件允许时仍优先使用 [TF-M](../tfm/P001_TFM可信固件入口.md#tfm) 这样的**安全处理环境（Secure Processing Environment）**，因为其隔离保证可以提供更强的安全性。

## 21.2\_总体限制

官方明确列出以下限制：

- 此实现不以完全符合规范为目标，首要目标是在所有开发板目标上提供 API 功能支持。后文列出与规范的重要差异，但并非穷尽清单。
- 不保证在所有情况下都能保护所存储的静态数据；效果取决于设备安全特性和配置。
- 截至原文编写时，尚未提供独立的**受保护存储（Protected Storage，PS）**API 实现。除非使用自定义 PS 实现，否则 PS API 直接调用**内部可信存储（Internal Trusted Storage，ITS）**API。

## 21.3\_标识符宽度

**唯一标识符（Unique Identifier，UID）**类型默认只有 30 位，与规范[第 2.5 节 UIDs](https://arm-software.github.io/psa-api/storage/1.0/overview/architecture.html#uids)不同。

这是一项优化，方便直接把 UID 用作存储条目标识。例如，启用 [`CONFIG_SECURE_STORAGE_ITS_STORE_IMPLEMENTATION_ZMS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SECURE_STORAGE_ITS_STORE_IMPLEMENTATION_ZMS) 时，可直接用于 [Zephyr内存存储（Zephyr Memory Storage，ZMS）](P006_Zephyr内存存储ZMS.md)。

Zephyr 为不同 API 使用者定义了各自的数值范围，保证彼此不冲突，并且全部能容纳在 30 位内。详情见官方 [`include/zephyr/psa`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/psa) 目录中的头文件。

## 21.4\_加密、认证与重放保护

ITS 中的数据默认会被**加密（Encryption）**和**认证（Authentication）**，这与规范[第 3.2 节“内部可信存储要求”的第 1 项](https://arm-software.github.io/psa-api/storage/1.0/overview/requirements.html#internal-trusted-storage-requirements)不同。

规范[第 2.4 节“内部可信存储 API”](https://arm-software.github.io/psa-api/storage/1.0/overview/architecture.html#the-internal-trusted-storage-api)认为 ITS 底层存储天然具有保密性并能防止重放，因为多数嵌入式**微控制器（Microcontroller Unit，MCU）**具有片内 Flash，可以使其只能被 MCU 上运行的软件访问，参见规范[第 2.2 节“技术背景”](https://arm-software.github.io/psa-api/storage/1.0/overview/architecture.html#technical-background)。

并非所有 MCU 都符合这一前提，因此本实现为存储数据提供额外保护。但这仍不能保证所有设备与配置下的静态数据安全；它需要**随机熵源（Random Entropy Source）**，尤其需要安全的**加密密钥提供者（Encryption Key Provider）**，由 [`CONFIG_SECURE_STORAGE_ITS_TRANSFORM_AEAD_KEY_PROVIDER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SECURE_STORAGE_ITS_TRANSFORM_AEAD_KEY_PROVIDER) 配置。

上述配置名中的 AEAD 表示**带关联数据的认证加密（Authenticated Encryption with Associated Data）**。此外，ITS 存储的数据不具备**重放攻击（Replay Attack）**防护，因为这需要硬件保护的存储支持。

## 21.5\_运行时访问与只写一次的边界

通过 PSA Secure Storage API 保存的数据，不能防止软件或调试手段直接读写，这与规范[第 3.2 节的第 2 项和第 10 项](https://arm-software.github.io/psa-api/storage/1.0/overview/requirements.html#internal-trusted-storage-requirements)不同。本实现只在静态存储层面提供保护；若还要保护运行时数据，需要相应硬件机制。

`PSA_STORAGE_FLAG_WRITE_ONCE` 的**只写一次（Write Once）**标志，只能阻止通过 API 修改条目，不能阻止直接修改存储介质。要持续保证这一标志，系统必须记住某条目曾经创建过；这种状态必须能在存储介质被重写后仍然存在，与重放保护一样，需要硬件保护的存储。

能够写入存储介质的攻击者，因此仍能让只写一次的条目被覆盖或移除：可以先篡改条目，使子系统把它视为损坏并允许替换；也可以直接擦除，使它看起来从未存在。单纯对条目加密和认证，无法阻止这两种情况。

## 21.6\_读取接口的额外错误

`psa_its_get*()` 函数可能返回 `PSA_ERROR_INVALID_SIGNATURE`（签名/认证无效）和 `PSA_ERROR_DATA_CORRUPT`（数据损坏）。

规范没有为 ITS API 定义这些错误，因为它假定底层存储受到硬件保护，读取的数据总是完整的。这里不满足该假定，所以会把这些错误码传递给调用者，使其能够区分条目被篡改和内部故障。

## 21.7\_配置与替换实现

Zephyr 提供的 PSA Secure Storage API 实现可通过[安全存储 Kconfig 配置项](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_SECURE_STORAGE_.*)设置，定义位于 [`subsys/secure_storage/`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/secure_storage/) 下的各个 Kconfig 文件。

如果现有实现的功能不足，可在不同层次以自定义实现替换。已有完整 ITS 或 PS API 实现时，启用相应配置项，并实现对应函数：

| 配置项 | 替换范围 |
| --- | --- |
| [`CONFIG_SECURE_STORAGE_ITS_IMPLEMENTATION_CUSTOM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SECURE_STORAGE_ITS_IMPLEMENTATION_CUSTOM) | 整套 ITS API |
| [`CONFIG_SECURE_STORAGE_PS_IMPLEMENTATION_CUSTOM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SECURE_STORAGE_PS_IMPLEMENTATION_CUSTOM) | 整套 PS API |

Zephyr 的 ITS 实现由 [`CONFIG_SECURE_STORAGE_ITS_IMPLEMENTATION_ZEPHYR`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_SECURE_STORAGE_ITS_IMPLEMENTATION_ZEPHYR) 选择，内部使用 ITS **变换模块（Transform Module）**和**存储模块（Store Module）**，两者可以独立配置和定制。不同可能性见 [ITS变换与存储配置项](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_SECURE_STORAGE_ITS_%28TRANSFORM%7CSTORE%29_.*)。

原文特别建议使用或实现安全的[加密密钥提供者](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_SECURE_STORAGE_ITS_TRANSFORM_AEAD_KEY_PROVIDER_.*)。
