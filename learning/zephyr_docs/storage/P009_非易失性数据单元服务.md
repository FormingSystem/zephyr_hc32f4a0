# 第9章\_非易失性数据单元服务

原文：[Non-Volatile Memory (NVMEM)](https://docs.zephyrproject.org/latest/services/storage/nvmem/index.html)。读取日期：2026-10-13，`latest`。

**非易失性存储器（Non-Volatile Memory，NVMEM）**子系统提供访问非易失性存储设备的通用接口。它抽象底层硬件，为读写数据提供统一的**应用程序编程接口（Application Programming Interface，API）**。

## 9.1\_提供者、数据单元与使用者

**NVMEM 提供者（NVMEM Provider）**是向外提供 NVMEM 数据单元的驱动，例如一个**电可擦可编程只读存储器（Electrically Erasable Programmable Read-Only Memory，EEPROM）**驱动。提供者负责在底层硬件上执行实际读写。

**NVMEM 数据单元（NVMEM Cell）**是非易失性存储器中的一个区域，在设备树中定义，具有偏移、大小、只读状态等属性。

**NVMEM 使用者（NVMEM Consumer）**是使用这些数据单元保存或读取数据的驱动或应用。

## 9.2\_配置子系统与后端

以下 Kconfig 配置项启用子系统及相应设备支持。**电池备份随机存取存储器（Battery-Backed Random Access Memory，BBRAM）**、**闪存（Flash Memory）**和**一次性可编程存储器（One-Time Programmable Memory，OTP）**是这里列出的其他存储类型。

| 配置项 | 作用 |
| --- | --- |
| [`CONFIG_NVMEM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NVMEM) | 启用 NVMEM 子系统 |
| [`CONFIG_NVMEM_BBRAM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NVMEM_BBRAM) | 启用 BBRAM 的 NVMEM 支持 |
| [`CONFIG_NVMEM_EEPROM`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NVMEM_EEPROM) | 启用 EEPROM 设备的 NVMEM 支持 |
| [`CONFIG_NVMEM_FLASH.*`](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_NVMEM_FLASH.*) | 配置 Flash 设备的 NVMEM 支持；此处为配置项族的匹配表达式 |
| [`CONFIG_NVMEM_OTP.*`](https://docs.zephyrproject.org/latest/kconfig.html#!CONFIG_NVMEM_OTP.*) | 配置 OTP 设备的 NVMEM 支持；同样为配置项族 |

## 9.3\_在设备树中定义和引用数据单元

NVMEM 依赖设备树绑定描述数据单元。下面的官方示例在 EEPROM 提供者下定义布局：一段保存**介质访问控制地址（Media Access Control Address，MAC Address）**，另一段保存校准数据（Calibration Data）。

```dts
&eeprom0 {
	nvmem-layout {
		compatible = "fixed-layout";
		#address-cells = <1>;
		#size-cells = <1>;

		mac_address: mac_address@0 {
			reg = <0x0 6>;
			#nvmem-cell-cells = <0>;
			read-only;
		};

		calibration_data: calibration_data@6 {
			reg = <0x6 100>;
			#nvmem-cell-cells = <0>;
		};
	};
};
```

属性 `reg` 是包含两项的数组：第一项为数据单元在所属存储器中的偏移，第二项为数据单元的字节大小。`#nvmem-cell-cells` 描述节点引用（Phandle）中附带的属性参数个数，通常设为零，参见[说明单元名称（Specifier Cell Names，*-cells）](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-cells)。

使用者随后可以这样引用这些数据单元：

```dts
my_consumer: my-consumer {
	compatible = "my,consumer";
	nvmem-cells = <&mac_address>, <&calibration_data>;
	nvmem-cell-names = "mac-address", "calibration-data";
};
```

## 9.4\_读取数据的使用示例

下面的官方示例使用 NVMEM API 读取数据单元。译注：`DT_NODELABEL` 宏按节点标签选择设备树节点，`NVMEM_CELL_GET_BY_NAME` 宏按名称取得数据单元；未就绪时示例返回 `-ENODEV`，表示设备不可用。

```c
#include <zephyr/nvmem.h>

static const struct nvmem_cell mac_address =
	NVMEM_CELL_GET_BY_NAME(DT_NODELABEL(my_consumer), mac_address);

int main(void)
{
	uint8_t mac[6];
	int ret;

	if (!nvmem_cell_is_ready(&mac_address)) {
		printk("NVMEM cell is not ready\n");
		return -ENODEV;
	}

	ret = nvmem_cell_read(&mac_address, mac, 0, sizeof(mac));
	if (ret < 0) {
		printk("Failed to read MAC address: %d\n", ret);
		return ret;
	}

	/* ... */
}
```

译注：示例用 `NVMEM_CELL_GET_BY_NAME` 从使用者节点取得名为 `mac_address` 的数据单元，再用 `nvmem_cell_is_ready()` 检查其就绪状态，最后调用 `nvmem_cell_read()` 从单元内偏移零处读取六个字节。失败路径保留原示例的错误检查和输出。
