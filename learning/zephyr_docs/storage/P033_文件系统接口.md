# 第33章\_文件系统接口

原文：[group__file__system__api](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html)。读取日期：2026-10-13，`latest`。


## 33.2\_挂载标志

`BIT(n)` 表示第 `n` 位的位掩码。以下标志写入 `fs_mount_t.flags`：

| 宏 | 定义值 | 含义 |
| --- | --- | --- |
| [`FS_MOUNT_FLAG_NO_FORMAT`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga37b6ee15dc50499516fc51e9cb6287d5) | `BIT(0)` | 找不到请求的文件系统时，禁止格式化设备 |
| [`FS_MOUNT_FLAG_READ_ONLY`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga789e7f0fbbbb1c751f9dee9d9ca9693d) | `BIT(1)` | 以**只读（Read Only）**方式挂载 |
| [`FS_MOUNT_FLAG_AUTOMOUNT`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gac11f7ecef01b7758b6f8f70fdcd7089d) | `BIT(2)` | 标记应在启动时挂载的预定义挂载结构；对用户自行定义的挂载结构没有影响 |
| [`FS_MOUNT_FLAG_USE_DISK_ACCESS`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gadb6c0761d7d537f73b23b1056d12686e) | `BIT(3)` | 要求文件系统驱动使用**磁盘访问接口（Disk Access API）** |

在调用 [`fs_mount()`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga46d59d84a1da3ce1d90478397826d793) 前设置 [`FS_MOUNT_FLAG_USE_DISK_ACCESS`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gadb6c0761d7d537f73b23b1056d12686e)，意味着文件系统必须使用磁盘访问接口；否则驱动的挂载回调应返回 `-ENOTSUP`（不支持）。未设置时，驱动默认应使用**闪存接口（Flash API）**，除非它只支持磁盘访问接口。若实际使用磁盘访问接口，但标志原先未设置，挂载回调应在成功时设置该标志。

## 33.3\_设备树文件系统表宏

**文件系统表（File System Table，fstab）**用于描述挂载条目。以下 `node_id` 是 `zephyr,fstab` 节点中某个子条目的**设备树节点标识符（Devicetree Node Identifier）**。

`FS_FSTAB_DECLARE_ENTRY(node_id)` 为外部定义的 fstab 条目生成声明，定义体为：

```c
extern struct fs_mount_t FS_FSTAB_ENTRY(node_id)
```

原文同时称其求值结果为某个 `struct fs_mount_t` 对象的名称。译注：从定义体可以看到，此宏生成的是包含该对象名的 `extern` 声明；单独获取对象名称应使用下一项宏。

`FS_FSTAB_ENTRY(node_id)` 给出定义 `zephyr,fstab` 条目挂载结构时使用的名称。`_CONCAT` 在这里连接名称前缀与节点标识符：

```c
_CONCAT(z_fsmp_, node_id)
```

`FSTAB_ENTRY_DT_INST_MOUNT_POINT(inst)` 获取指定实例的**挂载点（Mount Point）**路径；`inst` 为实例编号，[`DT_INST_PROP`](../dt_instance_reference/P001_设备树驱动实例宏.md#ga9dce2e631b2a94804e8f2bcc76c6eff8) 读取该实例的属性：

```c
DT_INST_PROP(inst, mount_point)
```

`FSTAB_ENTRY_DT_MOUNT_FLAGS(node_id)` 读取 fstab 条目的通用挂载标志，返回适合初始化 `fs_mount_t.flags` 的值。[`DT_PROP`](../dt_property_reference/P001_设备树属性读取宏.md#ga8e1fd9ebacd85d2013df027d041d506b) 在这里读取节点属性：

```c
((DT_PROP(node_id, automount) ? FS_MOUNT_FLAG_AUTOMOUNT : 0)    \
 | (DT_PROP(node_id, read_only) ? FS_MOUNT_FLAG_READ_ONLY : 0)  \
 | (DT_PROP(node_id, no_format) ? FS_MOUNT_FLAG_NO_FORMAT : 0)  \
 | (DT_PROP(node_id, disk_access) ? FS_MOUNT_FLAG_USE_DISK_ACCESS : 0))
```

`FSTAB_ENTRY_DT_MOUNT_POINT(node_id)` 获取指定 fstab 条目的挂载点路径：

```c
DT_PROP(node_id, mount_point)
```

## 33.5\_目录项与文件系统类型

`enum fs_dir_entry_type` 区分目录项类型：

```c
enum fs_dir_entry_type {
    FS_DIR_ENTRY_FILE = 0,
    FS_DIR_ENTRY_DIR
};
```

[`FS_DIR_ENTRY_FILE`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gga79f37397a1590284fae2c4b456f26afbae84f63edd56b9a797a219b5382f85e3b) 表示文件条目，[`FS_DIR_ENTRY_DIR`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gga79f37397a1590284fae2c4b456f26afba443eeda19fcb1164475c2ffd8276e937) 表示目录条目。

Zephyr 支持源码树内和外部文件系统。每种实现都需要唯一类型标识符，用于注册实现，并将挂载点与类型关联。以下匿名枚举给出源码树内文件系统的全局标识符：

```c
enum {
    FS_FATFS = 0,
    FS_LITTLEFS,
    FS_EXT2,
    FS_VIRTIOFS,
    FS_RPMSGFS,
    FS_NATIVE_MOUNT,
    FS_TYPE_EXTERNAL_BASE
};
```

前五项分别表示 FatFS、LittleFS、Ext2、Virtiofs 和 RpMsgFS；[`FS_NATIVE_MOUNT`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gga342d09da6adbf7d1576ce7f933c1b4ffa6720b5692bb7f5bf0f42facece372954) 表示**原生模拟器（Native Simulator）**挂载文件系统。外部文件系统的唯一标识符从 [`FS_TYPE_EXTERNAL_BASE`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gga342d09da6adbf7d1576ce7f933c1b4ffa37c6c9e64a57fee8c51884e18facf25f) 开始分配；应用同时使用多种外部实现时，由应用负责保证标识符不重复。

## 33.6\_函数参数与错误约定

下文 `zfp` 指向文件对象，`zdp` 指向目录对象，`mp` 指向挂载结构。返回值为负数通常表示负错误码；但读取、写入和位置查询成功时返回的并非统一的 0，具体约定分别列出。

**虚拟文件系统（Virtual File System，VFS）**负责统一文件系统接口。文中 **可移植操作系统接口（Portable Operating System Interface，POSIX）**用于描述路径及目录条目的相关惯例。

| 参数 | 含义 |

## 33.9\_打开或创建文件

```c
int fs_open (struct fs_file_t *zfp, const char *file_name, fs_mode_t flags);
```

打开文件，必要时创建文件，并为其关联文件流。成功打开的文件不再使用时，应调用 [`fs_close()`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga4811679c25021e9f763824e06292e043) 关闭。

[`flags`](https://docs.zephyrproject.org/latest/doxygen/html/parser_8h.html#ab6b306ef981f5e21bb41ea2c2dbe8cd9) 可为 0，也可为 [`FS_O_READ`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gafd1228407bcf929a175cc18802cda4b2)、[`FS_O_WRITE`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga0e86c5413b46133e824deaa89b16ee8d)、`FS_O_RDWR`、`FS_O_CREATE`、`FS_O_APPEND`、`FS_O_TRUNC` 中一个或多个标志的按位组合。**当 [`flags`](https://docs.zephyrproject.org/latest/doxygen/html/parser_8h.html#ab6b306ef981f5e21bb41ea2c2dbe8cd9) 为 0 时，可以打开已存在且可访问的文件，但没有读写权限。**

| 参数 | 含义 |
| --- | --- |
| `zfp` | 指向已初始化的文件对象 |
| `file_name` | 要打开的文件名 |
| [`flags`](https://docs.zephyrproject.org/latest/doxygen/html/parser_8h.html#ab6b306ef981f5e21bb41ea2c2dbe8cd9) | 模式标志 |

返回值：0：成功。`-EBUSY`：文件对象已被使用。`-EINVAL`：文件名无效。`-EROFS`：以写方式打开只读文件，或在使用 [`FS_MOUNT_FLAG_READ_ONLY`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga789e7f0fbbbb1c751f9dee9d9ca9693d) 挂载的文件系统中创建文件。`-ENOENT`：指定路径的文件不存在。`-ENOTSUP`：底层文件系统驱动未实现此操作。`-EACCES`：未以写方式打开文件却请求截断。其他负错误码由文件系统后端决定。

## 33.10\_关闭文件

```c
int fs_close (struct fs_file_t *zfp);
```

刷新相关文件流并关闭文件。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |

返回值：0：成功。`-ENOTSUP`：底层文件系统驱动未实现。其他错误返回负错误码。

## 33.11\_读取文件

```c
ssize_t fs_read (struct fs_file_t *zfp, void *ptr, size_t size);
```

最多读取 `size` 字节到 `ptr` 指向的缓冲区，返回实际读取字节数。可用数据少于请求量时，返回值可能小于 `size`。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |
| `ptr` | 数据缓冲区指针 |
| `size` | 要读取的字节数 |

返回值：大于或等于 0：成功读取的字节数。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.12\_写入文件

```c
ssize_t fs_write (struct fs_file_t *zfp, const void *ptr, size_t size);
```

尝试写入 `size` 字节。若返回负值，文件指针没有向前移动。若返回非负值但小于 `size`，应检查全局 `errno` 变量中的错误码，因为设备可能已没有可用数据空间。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |
| `ptr` | 待写数据缓冲区指针 |
| `size` | 要写入的字节数 |

返回值：大于或等于 0：成功写入的字节数。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.13\_调整文件位置

```c
int fs_seek (struct fs_file_t *zfp, off_t offset, int whence);
```

把文件位置移动到新位置；以 `whence` 指定的位置为基准加上 `offset`。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |
| `offset` | 要移动到的相对位置 |
| `whence` | 偏移计算基准：`FS_SEEK_SET` 为文件开头，`FS_SEEK_CUR` 为当前位置，`FS_SEEK_END` 为文件末尾 |

返回值：0：成功。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动不支持。其他错误返回负错误码。

## 33.14\_查询文件位置

```c
off_t fs_tell (struct fs_file_t *zfp);
```

获取并返回文件流中的当前位置。原文特别说明：当前修订版不验证文件对象。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |

返回值：大于或等于 0：当前文件位置。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动不支持。其他错误返回负错误码。

## 33.15\_截断或扩展文件

```c
int fs_truncate (struct fs_file_t *zfp, off_t length);
```

将已打开文件调整到给定大小。新长度小于当前长度时截断，大于当前长度时扩展，扩展区域填零。

**扩展过程中若卷空间耗尽，函数会扩展到能达到的最大长度，并仍返回成功。调用者应检查实际大小是否等于请求长度。**

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |
| `length` | 新文件大小，单位为字节 |

返回值：0：成功。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.16\_刷新文件缓存

```c
int fs_sync (struct fs_file_t *zfp);
```

将已打开文件的缓存写数据刷新到存储介质，可用于要求立即写入数据，例如减少意外断电造成的数据丢失。关闭文件时会正确刷新缓存，因此关闭文件时无需额外调用此函数。

| 参数 | 含义 |
| --- | --- |
| `zfp` | 文件对象指针 |

返回值：0：成功。`-EBADF`：对象代表未打开或已关闭的文件。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.17\_删除文件或目录

```c
int fs_unlink (const char *path);
```

删除指定文件或目录。

| 参数 | 含义 |
| --- | --- |
| `path` | 待删除文件或目录的路径 |

返回值：0：成功。`-EINVAL`：文件名无效。`-EROFS`：文件只读，或文件系统以 [`FS_MOUNT_FLAG_READ_ONLY`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#ga789e7f0fbbbb1c751f9dee9d9ca9693d) 挂载。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.18\_重命名或移动

```c
int fs_rename (const char *from, const char *to);
```

将源路径重命名或移动到目标路径。源可以是文件或目录；目标路径中的所有中间目录必须已经存在。源为文件时，目标必须包含完整的目标文件名，不能只给新父目录。若目标对象已存在，会在重命名前被删除，即目标被覆盖。

当前实现不允许在不同挂载点之间移动文件。

| 参数 | 含义 |
| --- | --- |
| `from` | 源路径 |
| `to` | 目标路径 |

返回值：0：成功。`-EINVAL`：文件名无效，或操作会跨挂载点移动。`-EROFS`：文件只读，或文件系统以 `FS_MOUNT_FLAG_READ_ONLY` 挂载。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.19\_创建目录

```c
int fs_mkdir (const char *path);
```

根据指定路径创建新目录。

| 参数 | 含义 |
| --- | --- |
| `path` | 待创建目录的路径 |

返回值：0：成功。`-EEXIST`：同名条目已存在。`-EROFS`：路径位于只读目录中，或文件系统以 `FS_MOUNT_FLAG_READ_ONLY` 挂载。`-ENOTSUP`：底层驱动未实现。其他错误返回负错误码。

## 33.23\_挂载文件系统

```c
int fs_mount (struct fs_mount_t *mp);
```

完成挂载所需步骤，包括调用具体文件系统的挂载函数，并将挂载点加入已挂载文件系统列表。

原文指出，当前 ELM **文件分配表（File Allocation Table，FAT）**驱动只允许挂载点 `/RAM:`、`/NAND:`、`/CF:`、`/SD:`、`/SD2:`、`/USB:`、`/USB2:`、`/USB3:`，或只含一个数字的挂载点，如 `/0:`、`/1:` 等。这些是文件系统命名空间中的挂载路径。

挂载失败时，不改变 `mp` 引用的对象。挂载成功时，文件系统基础设施保留对该对象的引用；在对同一指针成功执行 [`fs_unmount()`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gabc20c3ce66340c4c207aba3c88448fbf) 之前，应用不得修改该结构的内容。

| 参数 | 含义 |
| --- | --- |
| `mp` | 指向 `struct fs_mount_t` 挂载信息结构 |

返回值：0：成功。`-ENOENT`：文件系统类型尚未注册。`-ENOTSUP`：底层驱动不支持，或设置了 [`FS_MOUNT_FLAG_USE_DISK_ACCESS`](https://docs.zephyrproject.org/latest/doxygen/html/group__file__system__api.html#gadb6c0761d7d537f73b23b1056d12686e) 而驱动不支持磁盘访问接口。`-EROFS`：需要格式化，但设置了只读挂载标志。其他错误返回负错误码。

## 33.28\_规范化路径

```c
int fs_normalize_path (const char *path, char *buf, size_t len);
```

生成路径的**规范化形式（Normalized Form）**：合并重复与末尾路径分隔符，并按文本处理 `.` 和 `..` 分量。它不查询挂载表，因此路径无需指向已挂载文件系统；Zephyr 不支持**符号链接（Symbolic Link）**，所以也不解析链接。

`..` 消去前一个分量；若试图越过开头的 `/`，结果仍为 `/`，与 POSIX 系统一致。若调用者必须把路径限制在某个子树中，应检查规范化后的结果是否仍位于该子树内。

`path` 与 `buf` 可以是同一个缓冲区，以便**原地（In Place）**规范化；若为不同缓冲区，则不得重叠。出错时，`buf` 内容未定义；原地处理时，即使路径被拒绝，调用者自己的缓冲区也可能已被修改。

| 参数 | 含义 |
| --- | --- |
| `path` | 待规范化的绝对路径 |
| `buf` | 接收规范化路径的缓冲区，结果以空字符结束 |
| `len` | `buf` 的大小，单位为字节 |

返回值：0：成功。`-EINVAL`：路径不是绝对路径、`buf` 为 `NULL`，或 `len` 为 0。`-ENAMETOOLONG`：缓冲区不足以容纳规范化路径，或者不足以容纳解析 `..` 前产生的任何路径前缀。其他错误返回负错误码。
