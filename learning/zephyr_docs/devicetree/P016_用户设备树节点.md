# 第16章\_用户设备树节点

原文：[The /zephyr,user node](https://docs.zephyrproject.org/latest/build/dts/zephyr-user-node.html)。读取日期：2026-10-12，`latest`。

Zephyr 设备树脚本对 `/zephyr,user` 节点做了特殊处理：基本上可以在其中放入任意属性并读取其值，而不需要另写**绑定（Binding）**。属性类型由赋值推导，适合仅需要少量简单属性的场景。

**原文注意：**这个节点用于示例代码和用户应用，不应在 Zephyr 上游驱动、子系统等源码中使用。

> 译注：`/zephyr,user` 是设备树内部节点路径，不是主机文件绝对路径。这里的便利机制不替代正式硬件绑定和设备模型。

## 16.1\_存放简单值

若希望通过设备树在构建时配置数值或数组，可使用如下**覆盖文件（Overlay）**内容：

```dts
/ {
     zephyr,user {
             boolean;
             bytes = [81 82 83];
             number = <23>;
             numbers = <1>, <2>, <3>;
             string = "text";
             strings = "a", "b", "c";
     };
};
```

在 C/C++ 中，通过宏 `DT_PATH` 取得节点标识，使用宏 `DT_PROP` 读取属性。例子把当前节点标识保存到自行定义的宏 `ZEPHYR_USER_NODE`：

```c
#define ZEPHYR_USER_NODE DT_PATH(zephyr_user)

DT_PROP(ZEPHYR_USER_NODE, boolean) // 1
DT_PROP(ZEPHYR_USER_NODE, bytes)   // {0x81, 0x82, 0x83}
DT_PROP(ZEPHYR_USER_NODE, number)  // 23
DT_PROP(ZEPHYR_USER_NODE, numbers) // {1, 2, 3}
DT_PROP(ZEPHYR_USER_NODE, string)  // "text"
DT_PROP(ZEPHYR_USER_NODE, strings) // {"a", "b", "c"}
```

注释显示各属性展开结果：布尔值为 `1`，字节数组按十六进制读取，数值数组和字符串数组按对应初始化形式生成。

> 译注：上述 C 片段展示宏展开，不是完整可执行函数；使用相关宏需要设备树头文件。节点名中的逗号转换为 C 标识符中的下划线，因此写 `zephyr_user`。覆盖文件须接入实际应用构建，单独保存文件不会自动改变已有镜像。

## 16.2\_选择应用使用的设备

简单场景下，可在 `/zephyr,user` 保存 **节点句柄（phandle）**，通过覆盖文件切换应用使用的设备：

```dts
/ {
     zephyr,user {
             handle = <&gpio0>;
             handles = <&gpio0>, <&gpio1>;
     };
};
```

把属性 `handle` 和 `handles` 中的引用转换为设备指针。宏 `DEVICE_DT_GET` 根据节点取得设备对象，宏 `DT_NODELABEL` 根据标签取得节点标识；代码注释展示两种等价写法：

```c
/*
 * Same thing as:
 *
 * ... my_dev = DEVICE_DT_GET(DT_NODELABEL(gpio0));
 */
const struct device *my_device =
     DEVICE_DT_GET(DT_PROP(ZEPHYR_USER_NODE, handle));

/*
 * Same thing as:
 *
 * ... *my_devices[] = {
 *         DEVICE_DT_GET(DT_NODELABEL(gpio0)),
 *         DEVICE_DT_GET(DT_NODELABEL(gpio1))
 * };
 */
const struct device *my_devices[] = {
     DT_FOREACH_PROP_ELEM_SEP(ZEPHYR_USER_NODE, handles, DEVICE_DT_GET_BY_IDX, (,))
};
```

宏 `DT_FOREACH_PROP_ELEM_SEP` 对 `handles` 每个元素展开按索引取设备对象的宏 `DEVICE_DT_GET_BY_IDX`，并用逗号分隔，以构成指针数组。节点引用机制见[上一章](P015_设备树节点引用.md)。

> 译注：该片段沿用前节 `ZEPHYR_USER_NODE` 定义。引用节点及其驱动必须在当前构建中形成设备对象；取得指针不保证设备初始化已成功，实际使用前仍应按[设备树操作指南](P006_设备树操作指南.md)检查设备就绪状态。

## 16.3\_保存应用GPIO选择

`/zephyr,user` 也适合放需要通过覆盖文件改变的应用 **通用输入输出（General-Purpose Input/Output，GPIO）**。

**原文注意：**属性值只要包含至少一个 phandle 和一个数值，就会推导为 `phandle-array`，例如 `<&adc0 1>`。

下面示例使用宏 `GPIO_ACTIVE_HIGH` 表示高电平有效，`gpio0` 是已有控制器的节点标签：

```dts
#include <zephyr/dt-bindings/gpio/gpio.h>

/ {
     zephyr,user {
             signal-gpios = <&gpio0 1 GPIO_ACTIVE_HIGH>;
     };
};
```

这里 `signal-gpios` 选择 `gpio0` 控制器的 1 号引脚，`GPIO_ACTIVE_HIGH` 表示高电平有效。源码中可把它转为 `struct gpio_dt_spec`，即包含控制器、引脚号和标志的描述结构；宏 `GPIO_DT_SPEC_GET` 生成初始化内容，宏 `GPIO_OUTPUT_INACTIVE` 表示输出且初始为逻辑无效：

```c
#include <zephyr/drivers/gpio.h>

#define ZEPHYR_USER_NODE DT_PATH(zephyr_user)

const struct gpio_dt_spec signal =
        GPIO_DT_SPEC_GET(ZEPHYR_USER_NODE, signal_gpios);

/* Configure the pin */
gpio_pin_configure_dt(&signal, GPIO_OUTPUT_INACTIVE);

/* Set the pin to its active level */
gpio_pin_set_dt(&signal, 1);
```

`gpio_dt_spec` 把控制器、引脚号和设备树标志组合成一个描述对象。`GPIO_DT_SPEC_GET` 从属性建立该对象，`gpio_pin_configure_dt()` 以输出且初始无效的状态配置引脚，`gpio_pin_set_dt(&signal, 1)` 再设置逻辑有效电平。

接口详情见 [`gpio_dt_spec`](https://docs.zephyrproject.org/latest/doxygen/html/structgpio__dt__spec.html)、[`GPIO_DT_SPEC_GET`](https://docs.zephyrproject.org/latest/doxygen/html/group__gpio__interface.html#ga2fa6bb5880f46984f9fc29c70f7d503e)和 [`gpio_pin_configure_dt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__gpio__interface.html#ga423db4f985098ddcaa504ec430e91913)。

> 译注：原例省略就绪与返回值检查，实际应用应补齐。两条函数调用应放在函数体内，不是直接放在文件作用域；GPIO 接线与有效电平以实际板为准。本次没有执行构建或改变硬件引脚状态。
