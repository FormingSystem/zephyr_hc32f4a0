# 第11章\_提交上游的设备树绑定规则

原文：[Rules for upstream bindings](https://docs.zephyrproject.org/latest/build/dts/bindings-upstream.html)。读取日期：2026-10-12，`latest`。

本页规定准备提交 Zephyr 上游的绑定应遵循的规则。不打算提交上游的绑定可以不受这些规则约束，但仍建议遵循。设备树维护者的决定优先于本页；如有冲突，应告知维护者更新文档，或提交修正文档的补丁。

> 译注：这是官方贡献规则的翻译，本次不执行上游提交或发送消息。

## 11.1\_先检查已有绑定

Zephyr 希望设备树源码与其他操作系统兼容。如果权威来源已有该硬件绑定，编写 Zephyr 绑定时应尽量复用属性，任何 Zephyr 专用差异都必须说明理由。

尤其要检查 Linux 主线的 `Documentation/devicetree/bindings`，以及厂商在 Linux 内核以外提供的正式绑定。编写时尽可能遵循 [Linux 设备树绑定设计指南](https://docs.kernel.org/devicetree/bindings/writing-bindings.html)。

## 11.2\_通用规则

通用规则涵盖绑定文件名、默认值要求、说明文字的格式和属性命名，提交前应逐项核对。

### 11.2.1\_文件名与强制要求

匹配 compatible 的绑定文件名必须基于该 compatible。例如 `vnd,foo` 对应 `vnd,foo.yaml`。专用于某总线时可加总线后缀，例如 `on-bus: bar` 的文件可命名为 `vnd,foo-bar.yaml`。

[绑定语法](P010_绑定语法.md)中 default 部分的建议，在提交上游时都是要求。尤其是使用默认值时，属性 description 必须说明为何选择该值。

### 11.2.2\_描述格式

属性 description 只接受两种写法。短描述可直接写：

```yaml
description: my short string
```

长描述或跨行内容必须使用保留换行的 `|` 格式：

```yaml
title: I'm sure you need a short title.
description: |
  My very long string
  goes here.
  Look at all these lines!
```

这样 YAML 解析器不会移除换行，绑定索引才会正确显示长文字。属性用法复杂时可添加最小节点示例：

```yaml
description: ...
properties:
 ...

examples:
  - |
    leds {
      compatible = "gpio-leds";
      uled: led {
      gpios = <&gpioe 12 GPIO_ACTIVE_HIGH>;
      };
    };
```

### 11.2.3\_命名

属性名不要使用大写 A–Z 或下划线，应使用小写字母和连字符。唯一例外是复用 Linux 等来源已有且被广泛采用的绑定。

## 11.3\_厂商前缀

具体厂商生产的设备，compatible 应带厂商前缀。若厂商已在 `dts/bindings/vendor-prefixes.txt` 中，必须使用现有前缀。

不是某个硬件厂商生产的通用设备，不应凭空发明厂商前缀。前缀不是 compatible 必选部分；虽然存在少量例外，仍强烈不建议没有真实厂商却添加前缀。

不要只向上游添加 vendor-prefixes 条目，却没有使用者。至少应同时提交使用该前缀的绑定和设备树，最好还有处理该 compatible 的驱动。

自定义绑定可以在任一 `DTS_ROOT` 下放自己的 `dts/bindings/vendor-prefixes.txt`；工具会认可这些前缀，不会因在自有绑定或设备树中使用它们而警告或报错。Zephyr 有时从 Linux 同步前缀表，这个同步过程不受上一条“必须同时有使用者”的限制。

如果绑定描述一种抽象硬件类，由 Zephyr 专用驱动处理，通常优先用 `zephyr` 前缀。例子可在[官方绑定索引](https://docs.zephyrproject.org/latest/build/dts/api/bindings.html)的 Zephyr Project 分类查找。

## 11.4\_默认值规则

凡是使用 default，description 必须解释选择依据，以及哪些条件会要求使用不同值。若修改一个属性必须同时修改另一个属性才能保持配置一致，则应把这些属性设为必填。

不必在 description 重复默认值本身，绑定索引已经自动显示。默认值可能因板或硬件组合而不同，例如充电芯片所接电池容量，随意默认很容易错；这类属性适合 `required: true`，要求使用者明确选择。

驱动作者应判断是否能安全默认，适合的候选包括：只有插入额外硬件等异常条件才变化的延迟；有标准初始配置的设备，例如 **通用串行总线（Universal Serial Bus，USB）** 音频耳机；与厂商上电复位值一致且不依赖其他属性的值。

`status`、`#address-cells`、`#size-cells` 不能在绑定中设置 default，它们的默认行为已由设备树规范第 2.3.4、2.3.5 节规定。

合格描述示例：

```yaml
properties:
  cs-interval:
    type: int
    default: 0
    description: |
      Minimum interval between chip select deassertion and assertion.
      The default corresponds to the reset value of the register field.
  hold-time-ms:
    type: int
    default: 20
    description: |
      Amount of time to hold the power enable GPIO asserted before
      initiating communication. The default was recommended in the
      manufacturer datasheet, and would only change under very
      cold temperatures.
```

第一项说明片选释放到重新有效的最小间隔，默认值来自寄存器复位值；第二项说明通信前电源使能保持时间，默认由厂商手册推荐，仅在极低温时可能需要改变。它们都解释了依据，而不是重复数值。

不合格示例：

```yaml
properties:
  # Description doesn't mention anything about the default
  foo:
    type: int
    default: 1
    description: number of foos

  # Description mentions the default value instead of why it
  # was chosen
  bar:
    type: int
    default: 2
    description: bar size; default is 2

  # Explanation of the default value is in a comment instead
  # of the description. This won't be shown in the bindings index.
  baz:
    type: int
    # This is the recommended value chosen by the manufacturer.
    default: 2
    description: baz time in milliseconds
```

`foo` 没解释默认值依据；`bar` 只重复“默认是 2”；`baz` 把厂商推荐依据放在注释而非 description，绑定索引不会显示这条注释。

## 11.5\_zephyr逗号前缀

以下两类属性名必须加 `zephyr,`：

- 对与上游 Linux 共享的绑定增加 Zephyr 专用扩展。例如 `dts/bindings/adc/adc-controller.yaml` 中通用 **模数转换器（Analog-to-Digital Converter，ADC）** 通道的 `zephyr,vref-mv`；基础通道绑定部分共享，专用扩展用前缀标识。
- 专用于 Zephyr 驱动的软件配置。例如 `ti,bq274xx` 的 `zephyr,lazy-load`。设备树总体用于硬件描述和配置，但它也是 Zephyr 对单个 `struct device` 配置驱动行为的机制，因此允许部分软件设置，前提是此前缀明确其专用性质。

Zephyr 专用 compatible 也可以加 `zephyr,`，例如 `zephyr,ipc-openamp-static-vrings`。这种情况下，绑定中各属性再加该前缀是允许的，但不是强制要求。
