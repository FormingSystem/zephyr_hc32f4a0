# 第15章\_设备树节点引用

原文：[Phandles](https://docs.zephyrproject.org/latest/build/dts/phandles.html)。读取日期：2026-10-12，`latest`。

设备树的 **节点句柄（phandle）**与 C 指针有相似用途：C 指针可引用结构体，phandle 可引用设备树节点。本页从怎样取得引用开始，再说明一个引用后为何有时还需要引脚号、标志等额外数据。

> 译注：这是一种用途类比。设备树引用不是可在固件运行时任意解引用的 C 指针；C/C++ 代码访问时还要使用 Zephyr 生成的节点标识和宏。

## 15.1\_由节点标签取得引用

通常通过**节点标签（Node Label）**取得 phandle。例如：

```dts
/ {
        lbl_a: node-1 {};
        lbl_b: lbl_c: node-2 {};
};
```

`/node-1` 可用 `&lbl_a` 引用；`/node-2` 可用 `&lbl_b` 或 `&lbl_c`，因为两个标签属于同一节点。`&nodelabel` 的写法类似 C 的取地址运算，但所属语言与语义仍是设备树。

## 15.2\_三种引用属性类型

这里的“类型”指[设备树绑定中的属性类型](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-properties)。

### 15.2.1\_phandle：引用一个节点

某节点可用单个引用描述它与另一个节点的关系。常见例子是中断产生设备与接收中断的控制器：

```dts
node_b: node-b {
        interrupt-controller;
};

node-a {
        interrupt-parent = <&node_b>;
};
```

`interrupt-parent` 是设备树规范的标准属性，表示中断父控制器。此类属性的绑定类型是 `phandle`。

### 15.2.2\_phandles：引用零个或多个节点

`phandles` 是节点引用数组。**引脚控制（Pin Control，pinctrl）**中的 `pinctrl-0`、`pinctrl-1` 等属性就可以包含多个引用，每个引用指向外设的一组引脚配置信息。下面一个属性含六个引用：

```dts
pinctrl-0 = <&quadspi_clk_pe10 &quadspi_ncs_pe11
             &quadspi_bk1_io0_pe12 &quadspi_bk1_io1_pe13
             &quadspi_bk1_io2_pe14 &quadspi_bk1_io3_pe15>;
```

### 15.2.3\_phandle-array：引用并描述资源

如果需要引用另一个节点拥有的资源，并附带该资源的配置或元数据，就用 `phandle-array`。它不只是没有附加值的 `phandles` 引用列表；接下来说明其分组方式。

## 15.3\_引用数组中的说明符

典型 `phandle-array` 写成若干用逗号分隔的尖括号组：

```dts
node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>, <&baz 4 5>;
};
```

每组从 phandle 开始。跟在它后面的值组成**说明符（Specifier）**，用于描述所需资源及必要元数据。上例三个说明符分别是 `1 2`、`3`、`4 5`；对应引用分别指向控制这些资源的 `foo`、`bar`、`baz` 节点。

### 15.3.1\_GPIO为什么需要附加值

常见用途是描述外部芯片连接到**片上系统（System on Chip，SoC）**的 **通用输入输出（General-Purpose Input/Output，GPIO）**。例如外部芯片的中断引脚接到某个 GPIO，驱动需要知道控制器、引脚号，以及有效电平、上下拉等信息。

设备树中的控制器节点通常描述一组引脚，而不是每个引脚各有一个节点。因此，单个控制器 phandle 不能独自表示某一根引脚，需要：

```dts
my-external-ic {
        irq-gpios = <&gpioX pin flags>;
};
```

`irq-gpios` 只有一组值。`&gpioX` 指控制器，`pin` 是引脚编号，`flags` 是描述该引脚元数据的**位掩码（Bit Mask）**，例如 `(GPIO_ACTIVE_LOW | GPIO_PULL_UP)` 表示低有效与上拉。具体标志见 [`gpio.h`设备树定义](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/gpio/gpio.h)。

驱动读到这些信息即可按当前板的连接配置中断处理，不必为了接线变化改动驱动源码。

### 15.3.2\_一个属性描述多个引脚

属性也可包含多组资源：

```dts
my-other-external-ic {
        handshake-gpios = <&gpioX pinX flagsX>, <&gpioY pinY flagsY>;
};
```

第一组表示 `gpioX` 控制器的 `pinX`，使用 `flagsX`；第二组表示 `gpioY` 的 `pinY`，使用 `flagsY`。这些名称是示意占位，实际文件需替换为已有节点标签、引脚编号及合法标志。

“引脚号加标志”并非从数值本身猜出来的约定，它由下面的说明符空间及绑定规则建立。

## 15.4\_说明符空间决定单元含义

**说明符空间（Specifier Space）**让节点描述：其他节点通过引用数组使用其资源时，必须附带哪些数据。说明符中的各个数值称为**单元（Cell）**。

例如：

```dts
node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>;
};
```

`1 2` 是含两个单元的说明符，`3` 含一个单元。每个 `phandle-array` 属性关联一个有名称的说明符空间，按具体硬件为这些单元赋予含义。常见硬件有约定名称，也可以定义新名称。

### 15.4.1\_控制器规定需要几个单元

节点用 `#SPACE_NAME-cells` 按空间名声明所需单元数，`SPACE_NAME` 是实际空间名的占位。假设上例属性的空间名是 `baz`，被引用节点应有：

```dts
foo: node@1000 {
        #baz-cells = <2>;
};

bar: node@2000 {
        #baz-cells = <1>;
};
```

因此引用 `foo` 后需要两个单元，引用 `bar` 后需要一个。没有 `#baz-cells`，工具就无法校验每组说明符的长度。这使一个属性能够列出多种资源，即使不同控制器需要的元数据长度不同。

### 15.4.2\_一个节点支持多个空间

同一节点可对不同类型资源规定不同长度：

```dts
foo: node@1000 {
        #baz-cells = <2>;
        #bob-cells = <1>;
};
```

如果 `phandle-array-prop-2` 关联 `bob` 空间，就可写：

```dts
node {
        phandle-array-prop = <&foo 1 2>, <&bar 3>;
        phandle-array-prop-2 = <&foo 4>;
};
```

第一种资源引用 `foo` 时附带两个单元，第二种只附带一个。节点通过不同的 `#SPACE_NAME-cells` 属性分别描述各资源类型。

### 15.4.3\_gpio空间

GPIO 的说明符几乎总是两个单元：引脚号和引脚标志位掩码。因此常见 GPIO 控制器形如：

```dts
gpioX: gpio-controller@deadbeef {
        gpio-controller;
        #gpio-cells = <2>;
};
```

> 译注：`deadbeef` 是原文示例单元地址，不能作为真实芯片寄存器地址使用。`#gpio-cells = <2>` 表示引用后需要两个说明符单元，不是控制器只有两根 GPIO。

## 15.5\_属性怎样关联说明符空间

前面给出了空间名与单元数；还需确定某个 `phandle-array` 属性使用哪个空间。通常名为 `foos` 的属性隐含关联 `foo` 空间。例如绑定：

```yaml
properties:
  dmas:
    type: phandle-array
  pwms:
    type: phandle-array
```

`dmas` 对应 `dma`，`pwms` 对应 `pwm`，分别表示**直接存储器访问（Direct Memory Access，DMA）**资源和**脉宽调制（Pulse-Width Modulation，PWM）**资源。

存在两个专门规则：`*-gpios` 统一使用 `gpio` 空间，`*-io-channels` 统一使用 `io-channel` 空间。也就是说，`foo-gpios` 查 `#gpio-cells`，而非 `#foo-gpio-cells`；`bar-io-channels` 查 `#io-channel-cells`，而非 `#bar-io-channel-cells`。

若不使用默认推导，可在绑定中通过 [`specifier-space`](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-specifier-space)手工指定任意引用数组属性的空间。

## 15.6\_为单元命名并在C代码中读取

编写绑定时，应为硬件支持的每个说明符空间内的单元命名，语法见 [说明符单元名（*-cells）](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-cells)。这样 C 代码可以按名称查询并取值：

| 通用宏 | 用法方向 |
| --- | --- |
| [`DT_PHA_BY_IDX`](../dt_property_reference/P001_设备树属性读取宏.md#ga118b63fd22c20ef940ac2fa073c126ed) | 按属性元素索引读取命名单元。 |
| [`DT_PHA_BY_NAME`](../dt_property_reference/P001_设备树属性读取宏.md#gae469615356a867c49416da15bdc44a26) | 按属性元素名称读取命名单元。 |

许多硬件专用接口内部使用这些机制。下面每项都是设备树访问宏，后面说明它所取出的信息：

- [`DT_GPIO_PIN_BY_IDX`](https://docs.zephyrproject.org/latest/doxygen/html/group__devicetree-gpio.html#ga8f7d82567056266bab1603865f8b27af)：按索引取得 GPIO 引脚号。
- [`DT_PWMS_CHANNEL_BY_IDX`](https://docs.zephyrproject.org/latest/doxygen/html/group__devicetree-pwms.html#ga10a372e44c7e3feb551ca996c6ca5a8f)：按索引取得 PWM 通道。
- [`DT_DMAS_CELL_BY_NAME`](../dma_reference/P008_DMA设备树宏.md#ga1b80ae7fee6bcc9aa2ad03435e70dd14)：按 DMA 元素名取得单元。
- [`DT_IO_CHANNELS_INPUT_BY_IDX`](../dt_connection_reference/P001_设备树I_O通道宏.md#ga290c912d0a96ba65bb44341a783fac19)：按索引取得输入输出通道的输入标识。
- [`DT_CLOCKS_CELL_BY_NAME`](../timer_reference/P107_设备树时钟获取宏.md)：按时钟元素名取得单元。

进一步可查[属性值写法](https://docs.zephyrproject.org/latest/build/dts/intro-syntax-structure.html#dt-writing-property-values)、[引用属性绑定](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-properties)及 [`dependency-mode`节点依赖控制](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#dt-bindings-dependency-mode)。
