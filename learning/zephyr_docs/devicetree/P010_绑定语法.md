# 第10章\_设备树绑定语法

原文：[Devicetree bindings syntax](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html)。读取日期：2026-10-12，`latest`。

本页说明 Zephyr YAML 绑定格式，简单例子见[绑定入门](P009_绑定入门.md)。所有代码块保留原文内容和注释，周围正文翻译其规则与示例含义；占位符、对照示例和省略号不应当作可直接使用的完整绑定。

## 10.1\_顶层键

绑定顶层是键到值的映射，整体形态如下。`title` 是可选简短标题，`description` 描述硬件；`include` 复用其他绑定，`compatible` 用于节点匹配；`properties` 约束当前节点，`child-binding` 约束子节点；`bus` 声明当前节点提供的总线，`on-bus` 声明自身挂接的总线；`examples` 给出用法，`foo-cells` 为相应说明项中的 cell 命名。

```yaml
# When the description text is too long, this field can
# be used to improve readability, e.g.:
#
# title: Binding the device's hardware model.
#
# description |
#   A piece of content with 20 lines.
#   ...
title: Concise title for the long description [optional]

# A high level description of the device the binding applies to:
description: |
   This is the Vendomatic company's foo-device.

   Descriptions which span multiple lines (like this) are OK,
   and are encouraged for complex bindings.

   See https://yaml-multiline.info/ for formatting help.

# You can include definitions from other bindings using this syntax:
include: other.yaml

# Used to match nodes to this binding:
compatible: "manufacturer,foo-device"

properties:
  # Requirements for and descriptions of the properties that this
  # binding's nodes need to satisfy go here.

child-binding:
  # You can constrain the children of the nodes matching this binding
  # using this key.

# If the node describes bus hardware, like an SPI bus controller
# on an SoC, use 'bus:' to say which one, like this:
bus: spi

# If the node instead appears as a device on a bus, like an external
# SPI memory chip, use 'on-bus:' to say what type of bus, like this.
# Like 'compatible', this key also influences the way nodes match
# bindings.
on-bus: spi

examples:
  # You can put a sample node here showing how to use the binding.
  # - |
  #  ...
  # or
  # - ...

foo-cells:
  # "Specifier" cell names for the 'foo' domain go here; example 'foo'
  # values are 'gpio', 'pwm', and 'dma'. See below for more information.
```

### 10.1.1\_title和description

标题是可选的短描述，通常采用“Vendor Family Model”形式，尽量接近厂商数据手册；缩写后用括号展开。标题不超过 100 个字符，长内容放入 description；不要在标题使用 binding、schema 或 driver，因为这里本来都是绑定。例如：

```yaml
title: Acme Foo UART (Universal Asynchronous Receiver/Transmitter)
```

description 是自由格式的硬件说明，也可以包含数据手册链接或示例节点、属性。多行格式可参考 [YAML 多行字符串](https://yaml-multiline.info/)。

### 10.1.2\_compatible匹配

键值通常采用逗号分隔的厂商前缀和设备名：

```yaml
# Note the comma-separated vendor prefix and device name
compatible: "manufacturer,device"
```

下面的节点与它匹配：

```dts
device {
     compatible = "manufacturer,device";
};
```

如果不存在 `manufacturer,device-v2` 的绑定，下面节点也会回退匹配它：

```dts
device-2 {
    compatible = "manufacturer,device-v2", "manufacturer,device";
};
```

绑定由 `(compatible, on-bus)` 对唯一标识，on-bus 可以不指定。对节点的每个 compatible 按顺序尝试；指定且匹配总线的绑定优先于未指定总线的绑定。使用首个匹配项。

假设有如下 **串行外设接口（Serial Peripheral Interface，SPI）** 总线设备：

```dts
spi-bus {
        device-3 {
                compatible = "manufacturer,device";
        };
};
```

`manufacturer,device-spi.yaml` 与 `manufacturer,device.yaml` 可以共存，依次按以下顺序匹配：

```yaml
compatible: "manufacturer,device"
on-bus: spi
```

```yaml
compatible: "manufacturer,device"
```

以下 `manufacturer,device-i2c.yaml` 也可共存，但不匹配该 SPI 设备：

```yaml
compatible: "manufacturer,device"
on-bus: i2c
```

同一 compatible 若找到多个相同条件的匹配绑定，则报错。厂商前缀见 `dts/bindings/vendor-prefixes.txt`，设备名通常来自数据手册。通用设备类没有特定厂商时可以省略前缀，例如用于 **通用输入输出（General-Purpose Input/Output，GPIO）** 连接的板载 **发光二极管（Light-Emitting Diode，LED）** 的 `gpio-leds`。

## 10.2\_properties和属性条目

`properties` 描述匹配节点包含的属性。例如 **通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）**：

```yaml
compatible: "manufacturer,serial"

properties:
  reg:
    type: array
    description: UART peripheral MMIO register space
    required: true
  current-speed:
    type: int
    description: current baud rate
    required: true
```

节点必须包含整数 `current-speed`（当前波特率）以及 `reg`（UART 外设 **内存映射输入输出（Memory-Mapped Input/Output，MMIO）** 寄存器空间）。构建系统通常只为匹配绑定 `properties` 中列出的 **设备树源文件（Devicetree Source，DTS）** 属性生成 C 宏，其他属性一般被忽略；例外是规范已定义含义的标准属性，如 `reg`，即使没有匹配绑定，也会生成对应宏。

属性条目的格式为：

```yaml
<property name>:
  required: <true | false>
  type: <string | int | boolean | array | uint8-array | string-array |
         phandle | phandles | phandle-array | path | compound>
  deprecated: <true | false>
  default: <default>
  description: <description of the property>
  enum:
    - <item1>
    - <item2>
    ...
    - <itemN>
  const: <string | int | array | uint8-array | string-array>
  min: <int>
  max: <int>
  min-len: <int>
  max-len: <int>
  specifier-space: <space-name>
  dependency-mode: <normal | reverse | ignore | child-ignore>
```

以下完整示例分别展示必需波特率、可选字符串数组、**通用串行总线（Universal Serial Bus，USB）** 速度枚举、整数分辨率枚举、固定地址 cell 数，以及各种默认值：

```yaml
properties:
    # Describes a property like 'current-speed = <115200>;'. We pretend that
    # it's obligatory for the example node and set 'required: true'.
    current-speed:
        type: int
        required: true
        description: Initial baud rate for bar-device

    # Describes an optional property like 'keys = "foo", "bar";'
    keys:
        type: string-array
        description: Keys for bar-device

    # Describes an optional property like 'maximum-speed = "full-speed";'
    # the enum specifies known values that the string property may take
    maximum-speed:
        type: string
        description: Configures USB controllers to work up to a specific speed.
        enum:
           - "low-speed"
           - "full-speed"
           - "high-speed"
           - "super-speed"

    # Describes an optional property like 'resolution = <16>;'
    # the enum specifies known values that the int property may take
    resolution:
      type: int
      enum:
       - 8
       - 16
       - 24
       - 32

    # Describes a required property '#address-cells = <1>';  the const
    # specifies that the value for the property is expected to be the value 1
    "#address-cells":
        type: int
        required: true
        const: 1

    int-with-default:
        type: int
        default: 123
        description: Value for int register, default is power-up configuration.

    array-with-default:
        type: array
        default: [1, 2, 3] # Same as 'array-with-default = <1 2 3>'

    string-with-default:
        type: string
        default: "foo"

    string-array-with-default:
        type: string-array
        default: ["foo", "bar"] # Same as 'string-array-with-default = "foo", "bar"'

    uint8-array-with-default:
        type: uint8-array
        default: [0x12, 0x34] # Same as 'uint8-array-with-default = [12 34]'
```

这里 `current-speed` 必填；`keys` 可选；`maximum-speed` 限定为列出的四种速度字符串；`resolution` 为 8、16、24、32 之一；`#address-cells` 必须为 1。其余条目依次展示整数、整数数组、字符串、字符串数组和字节数组默认值。

### 10.2.1\_required与type

`required: true` 要求节点必须存在该属性，否则构建失败。默认是 false，即可选；显式写 `required: false` 多余且不推荐。

类型约束属性值，DTS 写法详见[语法与结构](P003_语法与结构.md)，phandle 细节见[句柄说明](https://docs.zephyrproject.org/latest/build/dts/phandles.html)。

| 类型 | 含义 | DTS 示例 |
| --- | --- | --- |
| `string` | 一个字符串 | `status = "disabled";` |
| `int` | 一个 32 位 cell | `current-speed = <115200>;` |
| `boolean` | 真值为无赋值的标志，假值为属性不存在 | `hw-flow-control;` |
| `array` | 零个或多个 32 位 cell | `offsets = <0x100 0x200 0x300>;` |
| `uint8-array` | 零个或多个十六进制字节，规范称 bytestring | `local-mac-address = [de ad be ef 12 34];` |
| `string-array` | 零个或多个字符串 | `dma-names = "tx", "rx";` |
| `phandle` | 一个 phandle | `interrupt-parent = <&gic>;` |
| `phandles` | 零个或多个 phandle | `pinctrl-0 = <&usart2_tx_pd5 &usart2_rx_pd6>;` |
| `phandle-array` | phandle 及其 32 位 cell（通常为说明项）的列表 | `dmas = <&dma0 2>, <&dma0 3>;` |
| `path` | phandle 路径引用或节点路径字符串 | `zephyr,bt-c2h-uart = &uart0;` 或 `foo = "/path/to/some/node";` |
| `compound` | 更复杂的组合类型，不生成宏 | `foo = <&label>, [01 02];` |

### 10.2.2\_deprecated和default

`deprecated: true` 表示该属性计划逐步淘汰。设备树使用它时工具会警告，上游 PR 的 Twister 会把此警告视为错误。默认为 false，显式写 `deprecated: false` 多余且不推荐。

可选的 `default` 提供节点缺少属性时采用的值：

```yaml
properties:
  foo:
    type: int
    default: 3
```

匹配节点缺少 `foo` 时，结果相当于 DTS 写了 `foo = <3>;`，但绑定中的默认值使用 YAML 数据类型。

同一个属性同时直接声明 `default` 和 `required: true` 会警告：必填属性缺失已导致失败，默认值永远不会用到。但是，当前绑定用 `required: true` 覆盖继承来的默认值、强制显式填写是有定义的行为，不产生这个警告。仅通过 include 引用的绑定不会独立加载，相关警告可能在文档生成而非应用构建时才出现。

默认值只支持前面示例出现的类型，其他类型设置 default 会报错。上游使用要求见[上游绑定规则](https://docs.zephyrproject.org/latest/build/dts/bindings-upstream.html)。

### 10.2.3\_enum、范围和长度

`enum` 列出允许值，DTS 值不在列表中就报错。

`min`、`max` 限制 `int` 或 `array` 的闭区间范围，可以只设一个，也可以同时设置，但不能与同一属性的 enum 混用。数组每个元素都要满足范围：

```yaml
properties:
  # A brightness percentage between 0 and 100
  brightness:
    type: int
    min: 0
    max: 100
    description: LED brightness as a percentage

  # A timeout in milliseconds, with a minimum of 1 ms (no upper bound)
  timeout-ms:
    type: int
    min: 1
    description: Timeout in milliseconds
```

上例亮度限定 0–100，超时至少 1 ms，没有上限。

`min-len`、`max-len` 限制数组类属性的元素数，适用于 array、uint8-array、string-array、phandles、phandle-array。二者可分别设置，长度超界报错：

```yaml
properties:
  # An array of exactly 3 integers
  coordinates:
    type: array
    min-len: 3
    max-len: 3
    description: 3D coordinates

  # A list of up to 4 GPIO phandles
  gpios:
    type: phandle-array
    max-len: 4
    description: Up to 4 GPIOs
```

上例坐标必须恰好 3 个整数，GPIO 列表最多 4 项。

### 10.2.4\_const与specifier-space

`const` 规定属性必须采用的常量，常用于限制某种具体硬件的标准属性。

`specifier-space` 为 `phandle-array` 显式指定说明项空间。通常从属性名隐式推导：`foos` 对应 `foo`；特别地，`*-gpios` 都对应 `gpio`，例如 `foo-gpios` 不会变成 `foo-gpio`。

只有惯例导致别扭或不合理名称时才应手动指定；不能滥用来把 GPIO 属性叫作 `my-pin` 再硬指定 gpio 空间，GPIO 属性应遵循以 `-gpios` 或 `-gpio` 结尾的名称。

例如把 `bar` 的说明项空间指定为 `my-custom-space`：

```yaml
compatible: ...
properties:
  bar:
    type: phandle-array
    specifier-space: my-custom-space
```

随后 DTS 可按被引用控制器各自的 cell 数提供参数：

```dts
controller1: custom-controller@1000 {
        #my-custom-space-cells = <2>;
};

controller2: custom-controller@2000 {
        #my-custom-space-cells = <1>;
};

my-node {
        bar = <&controller1 10 20>, <&controller2 30>;
};
```

第一个控制器要求 2 个 cell，第二个要求 1 个。合理的实际用例是 `mboxes` 对应空间 `mbox`，而非机械去掉末尾 s 得到的 `mboxe`：

```yaml
properties:
  mboxes:
    type: phandle-array
    specifier-space: mbox
```

### 10.2.5\_dependency-mode

默认情况下，包含 phandle 属性的节点依赖它引用的节点。`dependency-mode` 改变 Zephyr 依赖图计算时对该引用的处理：

| 值 | 规则 |
| --- | --- |
| `normal` 或省略 | 引用者依赖被引用者 |
| `reverse` | 反向，被引用者依赖引用者 |
| `ignore` | 此属性不形成依赖 |
| `child-ignore` | 被引用节点是引用者的子节点时忽略，否则建立普通依赖；适用于引用既可能指向内部子节点，也可能指向外部设备的情况 |

在绑定的属性定义中设置。例如不让 PHY 句柄形成依赖：

```yaml
compatible: "vendor,ethernet-controller"

properties:
  phy-handle:
    type: phandle
    description: |
      Specifies a reference to a node representing a PHY device.
    dependency-mode: ignore
```

允许内部/外部两类引用时：

```yaml
compatible: "vendor,node-with-optional-phandle"

properties:
  optional-ref:
    type: phandle
    description: |
      References either a child node or an external device.
      Child node references create no dependency, but external
      device references do.
    dependency-mode: child-ignore
```

对应 DTS 示例：

```dts
root {
        external_dev: external-device@2000 {
                compatible = "vendor,external-device";
                reg = <0x2000 0x100>;
        };

        parent_dev: parent-device@1000 {
                compatible = "vendor,node-with-optional-phandle";
                reg = <0x1000 0x100>;
                optional-ref = <&internal_child>; /* child: ignored dependency */

                internal_child: internal-device {
                        compatible = "vendor,internal-device";
                };
        };

        peer_dev: peer-device@3000 {
                compatible = "vendor,node-with-optional-phandle";
                reg = <0x3000 0x100>;
                optional-ref = <&external_dev>; /* external: normal dependency */
        };
};
```

`parent_dev` 指向自己的 `internal_child`，因此不形成该引用依赖；`peer_dev` 指向外部 `external_dev`，因此形成正常依赖。未指定此键时始终采用 normal。

## 10.3\_child-binding

节点所有子节点具有相同属性结构时，可使用 `child-binding`，每个子节点得到它作为绑定。如果子节点有显式 compatible 且能找到绑定，则显式绑定优先。

例如 **脉宽调制（Pulse Width Modulation，PWM）** LED 的每个子节点都需要 `pwms`：

```dts
pwmleds {
        compatible = "pwm-leds";

        red_pwm_led {
                pwms = <&pwm3 4 15625000>;
        };
        green_pwm_led {
                pwms = <&pwm3 0 15625000>;
        };
        /* ... */
};
```

绑定为：

```yaml
compatible: "pwm-leds"

child-binding:
  description: LED that uses PWM

  properties:
    pwms:
      type: phandle-array
      required: true
```

子绑定还可以递归。下面的绑定要求孙节点有整数 `my-property`：

```yaml
compatible: foo

child-binding:
  child-binding:
    properties:
      my-property:
        type: int
        required: true
```

它应用于下例的 `grandchild`：

```dts
parent {
        compatible = "foo";
        child {
                grandchild {
                        my-property = <123>;
                };
        };
};
```

## 10.4\_bus与on-bus

当前节点是总线控制器时，用 bus 声明类型，例如 **片上系统（System on Chip，SoC）** 的 SPI 控制器：

```yaml
compatible: "manufacturer,spi-peripheral"
bus: spi
# ...
```

它告诉构建系统，匹配节点的子节点位于这种总线上，进而影响子节点的 on-bus 匹配。单一总线支持多种协议时也可以用列表，例如 I3C 和 **集成电路间总线（Inter-Integrated Circuit，I2C）**：

```yaml
compatible: "manufacturer,i3c-controller"
bus: [i3c, i2c]
# ...
```

当前节点是总线上的设备时，用 on-bus。例如外部 SPI 存储器：

```yaml
on-bus: spi
```

I2C 温度传感器则为：

```yaml
on-bus: i2c
```

查找绑定时，构建系统检查父节点绑定的 bus。指定了总线类型时，只考虑匹配 on-bus 的绑定和未显式指定 on-bus 的绑定，前者优先；对 compatible 的每个值依次重复搜索。

因此同一种传感器在不同总线上可以匹配不同绑定，即使 compatible 相同：

```dts
spi-bus@0 {
   /* ... some compatible with 'bus: spi', etc. ... */

   sensor@0 {
       compatible = "manufacturer,sensor";
       reg = <0>;
       /* ... */
   };
};

i2c-bus@0 {
   /* ... some compatible with 'bus: i2c', etc. ... */

   sensor@79 {
       compatible = "manufacturer,sensor";
       reg = <79>;
       /* ... */
   };
};
```

两份绑定分别为：

```yaml
# manufacturer,sensor-spi.yaml, which matches sensor@0 on the SPI bus:
compatible: "manufacturer,sensor"
on-bus: spi

# manufacturer,sensor-i2c.yaml, which matches sensor@79 on the I2C bus:
compatible: "manufacturer,sensor"
properties:
  uses-clock-stretching:
    type: boolean
on-bus: i2c
```

只有 I2C 节点的匹配绑定声明 `uses-clock-stretching`；搜索 SPI 节点时会忽略 I2C 绑定。

> 译注：原页说明句漏写成 `use-clock-stretching`，此处按 YAML 的 `uses-clock-stretching`。原 I2C 示例的 `sensor@79` 与十进制 `reg = <79>` 也不一致；地址若为 `0x79` 应改成 `<0x79>`，若为十进制 79 则单元地址应为 `@4f`。代码按原文保留供对照。

## 10.5\_class设备类

匹配节点可以作为某个 Zephyr 设备类使用时，用 class 声明：

```yaml
compatible: "manufacturer,adc"
class: adc
```

值为设备类名或名字列表，允许小写字母、数字、`-`、`_`，格式错误或重复名字会被拒绝。名称应匹配通过 `DEVICE_API` 注册的 **应用程序编程接口（Application Programming Interface，API）** 类，如 adc；连字符在生成 C token 时转换为下划线。

此键声明驱动能够实现哪些 API 类，实际编译哪个驱动和 API 仍由 Kconfig 决定。硬件可按配置实现多个 API 时使用列表：

```yaml
compatible: "manufacturer,rtc"
class: [rtc, counter]
```

class 通常在设备类基础绑定中只声明一次，例如 `dts/bindings/adc/adc-controller.yaml`，包含它的绑定自动继承。当前绑定及包含文件的 class 集合取并集。

构建时可用 `DT_NODE_HAS_CLASS` 查询成员关系，`DT_FOREACH_CLASS_STATUS_OKAY` 遍历，`DT_NUM_CLASS_STATUS_OKAY` 计数；Kconfig 中可用 `$(dt_class_enabled,<class name>)`。

如果不能改动原绑定，例如下游模块要给上游设备补类，可创建更具体 compatible，其绑定包含原绑定并声明 class：

```yaml
# vnd,foo-classed.yaml
compatible: "vnd,foo-classed"
include: vnd,foo.yaml
class: xyz
```

节点同时列出新旧 compatible：

```dts
compatible = "vnd,foo-classed", "vnd,foo";
```

节点采用第一个有匹配绑定的 compatible，因此类也来自它；驱动可以匹配节点任一 compatible，原驱动仍可匹配。同一 compatible 的重复绑定会报错，不能用新增同名绑定遮蔽旧绑定。

## 10.6\_examples与说明项cell名称

需要展示最小用法时，可在 examples 给出 DTS，例如 LED：

```yaml
description: ...

properties:
 ...

examples:
  - |
    leds {
      compatible = "gpio-leds";

      uled: led {
      gpios = <&gpioe 12 GPIO_ACTIVE_HIGH>;
      };
    };
```

`*-cells` 给说明项中的每个 cell 命名，概念详见[phandle-array](https://docs.zephyrproject.org/latest/build/dts/phandles.html)。例如两个 PWM 控制器分别需要 2 个和 1 个参数：

```dts
pwm1: pwm@deadbeef {
    compatible = "foo,pwm";
    #pwm-cells = <2>;
};

pwm2: pwm@deadbeef {
    compatible = "bar,pwm";
    #pwm-cells = <1>;
};

my-node {
    pwms = <&pwm1 1 2000>, <&pwm2 3000>;
};
```

相应绑定通过 `pwm-cells` 命名，第一个为 channel、period，第二个仅为 period：

```yaml
# foo,pwm.yaml
compatible: "foo,pwm"
...
pwm-cells:
  - channel
  - period

# bar,pwm.yaml
compatible: "bar,pwm"
...
pwm-cells:
  - period
```

> 译注：原文两个控制器都写成 `pwm@deadbeef`，这里作为分开的说明片段保留；若放到同一父节点下形成真实树，必须按硬件使用不冲突的节点名/地址。

引用方还可用 `*-names`（例如 pwm-names）给每一项命名，从而通过 `DT_PWMS_CHANNEL_BY_NAME` 等 API 按名字取 cell。如果说明项为空，例如 `#clock-cells = <0>`，绑定中的 `*-cells` 推荐省略，也可显式空数组，如 `clock-cells: []`。

## 10.7\_include复用与合并

include 的值可以是字符串或列表，用于复用公共属性定义。最简单的方式是给文件名：

```yaml
include: foo.yaml
```

只要在[绑定搜索位置](P009_绑定入门.md)找到名为 `foo.yaml` 的文件，就包含它。内容通过递归字典合并加入当前绑定，合并结果会被检查是否合法。任意层都可包含，包括子绑定：

```yaml
# foo.yaml will be merged with content at this level
include: foo.yaml

child-binding:
  # bar.yaml will be merged with content at this level
  include: bar.yaml
```

同一键在当前绑定和被包含文件中值不同，通常会报错，有两个例外：当前绑定可以把继承的 `required: false` 加强为 `required: true`；class 值按前述规则取并集。反过来把必填弱化为可选是错误，避免破坏结构约束。

`base.yaml` 定义许多公共属性，编写新绑定时应先检查是否可以复用。例如让其中的 reg 必填：

```yaml
reg:
  required: true
```

type 等其余键通过字典合并补齐。包含多个文件时用字符串列表，也可写成一行 `include: [foo.yaml, bar.yaml]`：

```yaml
include:
  - foo.yaml
  - bar.yaml
```

多个包含文件对同一属性的 required 做逻辑或，确保任一 `true` 都不会丢失。

只想复用部分属性时，include 用列表，在条目映射中设置允许或排除列表：

```yaml
include:
  - name: foo.yaml
    property-allowlist:
      - i-want-this-one
      - and-this-one
  - name: bar.yaml
    property-blocklist:
      - do-not-include-this-one
      - or-this-one
```

每个映射必须有文件名 `name`，可有 `property-allowlist` 或 `property-blocklist`，两者不能同时出现在同一条目中；二者都没有也合法，表示不筛选。列表可以混用字符串和映射：

```yaml
include:
  - foo.yaml
  - name: bar.yaml
    property-blocklist:
      - do-not-include-this-one
      - or-this-one
```

还可筛选子绑定：

```yaml
include:
  - name: bar.yaml
    child-binding:
      property-allowlist:
        - child-prop-to-allow
```

## 10.8\_nexus节点与映射

所有 phandle-array 类型属性支持通过 `*-map` 属性映射，例如规范定义的 `gpio-map`。这可用于描述通用扩展连接器；带 Arduino 兼容排针的板惯例上会定义 `arduino_header` 节点。
