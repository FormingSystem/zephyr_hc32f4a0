# 第9章\_设备树绑定入门

原文：[Introduction to Devicetree Bindings](https://docs.zephyrproject.org/latest/build/dts/bindings-intro.html)。读取日期：2026-10-12，`latest`。详细格式见[绑定语法](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html)。

节点通常通过 `compatible` 属性匹配绑定。构建系统在配置阶段尝试为每个节点找到绑定文件；匹配成功后，用绑定信息验证节点内容，并生成节点的 C 宏。

## 9.1\_简单示例

一个设备树节点：

```dts
/* Node in a DTS file */
bar-device {
     compatible = "foo-company,bar-device";
     num-foos = <3>;
};
```

匹配它的最小 YAML 绑定：

```yaml
# A YAML binding matching the node
compatible: "foo-company,bar-device"

properties:
  num-foos:
    type: int
    required: true
```

节点和绑定的 compatible 相同，因此匹配。

## 9.2\_验证与生成宏

构建系统用绑定验证节点，并转换成 `devicetree_generated.h`。上例要求节点必须有 `num-foos`，且 `<3>` 的类型正确；随后生成展开为整数常量 3 的宏，供[设备树 C/C++ API](https://docs.zephyrproject.org/latest/build/dts/api-usage.html)读取。

下列节点缺少绑定要求的属性，会引起构建错误：

```dts
bad-node {
     compatible = "foo-company,bar-device";
};
```

## 9.3\_其他匹配方式

compatible 有多个字符串时，按列出顺序尝试，使用第一个匹配绑定。例如：

```dts
baz-device {
     compatible = "foo-company,baz-device", "generic-baz-device";
};
```

找不到 `foo-company,baz-device` 时，才使用 `generic-baz-device` 的绑定。没有 compatible 的节点还可通过父节点关联的 child-binding（子绑定）匹配。

节点处在 **集成电路间总线（Inter-Integrated Circuit，I2C）**、**串行外设接口（Serial Peripheral Interface，SPI）** 等总线上时，匹配也考虑总线类型，详见[on-bus](https://docs.zephyrproject.org/latest/build/dts/bindings-syntax.html#on-bus)。特殊的 [`/zephyr,user`](https://docs.zephyrproject.org/latest/build/dts/zephyr-user-node.html) 节点不需要绑定。

## 9.4\_绑定查找位置

文件名通常与 compatible 对应，例如前例惯例上名为 `foo-company,bar-device.yaml`。构建系统在以下位置的 **`dts/bindings` 子目录**递归查找：

- Zephyr 仓库。
- 应用源码目录。
- 开发板目录。
- 所用扩展板目录。
- CMake 变量 `DTS_ROOT` 显式加入的目录。
- 模块[构建设置](https://docs.zephyrproject.org/latest/develop/modules.html#build-settings)中声明 `dts_root` 的位置。

扩展名 `.yaml` 或 `.yml` 的文件都会考虑，包括更深子目录。绑定必须放在上述根目录的 `dts/bindings` 之下，不能随意放在根目录本身。

例如应用目录为 `my-app`，`my-app/dts/bindings/serial/my-company,my-serial-port.yaml` 会被找到，但 `my-app/my-company,my-serial-port.yaml` 会被忽略。
