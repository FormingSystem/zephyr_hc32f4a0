## 21.4\_源码跟踪译注

> 译注——输入与用途：str是长度为n的原始字节序列，不必是以NUL结尾的字符串；哈希映射的C后端对64位键的字节表示进行哈希，再比较键值判断相等。32位哈希可能碰撞，不是唯一ID，也不是密码学摘要或认证机制。

> 译注——恒等哈希（Identity Hash）：实际仅接受1、2、4、8字节，并按相应无符号整数类型读取；8字节只返回低32位。名称不意味着任意长度数据原样返回。长度不支持时触发断言，之后返回0；调用者仍须保证有效对象、对齐及相应C语言访问规则。

> 译注——DJB2变体：从5381开始，对每字节先乘33再异或，而不是常见的加字符形式；严格处理n字节，包括中间的零字节，不自行扫描字符串终止符。通过CONFIG_SYS_HASH_FUNC32_DJB2加入实现。

> 译注——Murmur3与默认选择：此实现种子为0，按本机32位读取或UNALIGNED_GET处理分组，再混合尾部和长度。不能仅凭名称假定不同平台或外部库生成完全相同的数值。sys_hash32通过CONFIG_SYS_HASH_FUNC32_CHOICE_*选派；若没有选择，会断言并返回0，不是自动探测可用算法。

头文件相对定位：[include/zephyr/sys/hash_function.h](../../../include/zephyr/sys/hash_function.h)，关联实现／接口：[lib/hash/hash_func32_murmur3.c](../../../lib/hash/hash_func32_murmur3.c)；[官方原始头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/hash_function.h)与[官方关联文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/hash/hash_func32_murmur3.c)的摘要见来源记录。去掉注释和展示空白后，本页代码与本次读取的原始头文件一致，不能推广到以后滚动更新的main或任意本地版本。
