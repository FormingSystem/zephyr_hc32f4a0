哈希映射（Hashmap，又称哈希表／Hash Table）API。哈希映射以空间换取速度；插入、删除和查找操作的平均复杂度均为O(1)。

## 1.6\_详细说明（Detailed Documentation）

<a id="ga9cabdd6d7577372220065db79983f006"></a>

### `SYS_HASHMAP_CONFIG`

```c
#define SYS_HASHMAP_CONFIG ( _max_size, _load_factor )
```

```c
#include <zephyr/sys/hash_map_api.h>
```

展开值（Value）：

```c
{                                                                                          \
        .max_size = (size_t)_max_size, .load_factor = (uint8_t)_load_factor,               \
        .initial_n_buckets = NHPOT(DIV_ROUND_UP(100, _load_factor)),                   \
}
```

sys_hashmap_config的初始化器（Initializer）。

此宏用于初始化sys_hashmap_config类型的结构。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_max_size` | 最大条目数量。 |
| `_load_factor` | 最大负载因子，以百分之一为单位。 |

> 译注——源码核对：默认负载因子75表示0.75，初始桶数为NHPOT(DIV_ROUND_UP(100, _load_factor))。_load_factor必须非零；字段会转为uint8_t，不能依赖宏检查溢出或替调用者选择适合后端的范围。配置上限与后端实际执行检查的位置另见实现译注。

### `SYS_HASHMAP_DEFINE_ADVANCED`

```c
#define SYS_HASHMAP_DEFINE_ADVANCED ( _name, _api, _config_type, _data_type, _hash_func, _alloc_func, ... )
```

```c
#include <zephyr/sys/hash_map.h>
```

展开值（Value）：

```c
const struct _config_type _name##_config = __VA_ARGS__;                                    \
struct _data_type _name##_data;                                                            \
struct sys_hashmap _name = {                                                               \
        .api = (const struct sys_hashmap_api *)(_api),                                     \
        .config = (const struct sys_hashmap_config *)&_name##_config,                      \
        .data = (struct sys_hashmap_data *)&_name##_data,                                  \
        .hash_func = (_hash_func),                                                         \
        .alloc_func = (_alloc_func),                                                       \
}
```

声明哈希映射（高级形式）。

声明哈希映射，并控制高级参数。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_name` | 哈希映射的名称。 |
| `_api` | sys_hashmap_api类型的API指针。 |
| `_config_type` | sys_hashmap_config的变体。 |

### `sys_hashmap_should_rehash()`

```c

```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/hash_map.h>
```

判断是否应调整哈希映射的大小。

这是供各实现选择使用的简单适时调整方法。当插入／移除导致负载因子超过／落入指定范围时，以两倍／一半的倍率扩大或缩小哈希映射。

| 名称／方向 | 说明 |
| --- | --- |
| ` map` | 要检查的哈希映射。 |
| ` grow` | 将要增加条目时为true；已经移除条目时为false。 |
| ` num_reserved` | 保留条目的数量。 |
| `[out] new_num_buckets` | 用于接收哈希映射大小的变量。 |

**说明（Note）**：用户应在插入新键值对之前，以及移除键值对之后调用此函数。保留条目数量由具体实现定义，只有扩大哈希表时才将其计入负载因子。

**返回（Returns）**：哈希映射应重新散列（Rehash）时返回true，否则返回false。

> 译注——源码核对：should_rehash只计算候选桶数并返回判断，不执行分配。grow=true按即将多一项计算，应在新增之前调用；grow=false使用删除后的size。即使返回false，new_num_buckets仍被写入候选值，调用者应以布尔结果决定是否采用；输出指针不能为NULL或指向现有n_buckets。num_reserved只影响扩容负载判断，查询负载因子的函数不计它。

## 1.7\_源码定位与版本边界

本册依次提供[通用接口](P001_哈希映射公共接口.md)、[实现概览](P011_哈希映射实现概览.md)和[哈希函数](P019_哈希函数公共接口.md)，六份头文件各有独立参考与源码页。相对源码定位：[hash_map.h](../../../include/zephyr/sys/hash_map.h)、[hash_map_api.h](../../../include/zephyr/sys/hash_map_api.h)、[hash_function.h](../../../include/zephyr/sys/hash_function.h)。

后端与配置依据：[C++实现](../../../lib/hash/hash_map_cxx.cpp)、[开放寻址实现](../../../lib/hash/hash_map_oa_lp.c)、[分离链接实现](../../../lib/hash/hash_map_sc.c)、[映射Kconfig](../../../lib/hash/Kconfig.hash_map)、[哈希函数Kconfig](../../../lib/hash/Kconfig.hash_func)和[构建规则](../../../lib/hash/CMakeLists.txt)。对应[官方源码目录](https://github.com/zephyrproject-rtos/zephyr/tree/main/lib/hash)及[官方头文件目录](https://github.com/zephyrproject-rtos/zephyr/tree/main/include/zephyr/sys)的本次文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：接口与所有权：键和值均以uint64_t传递并保存，API不理解字符串内容、对象析构或指针所指资源。分配器管理映射内部存储，调用者仍负责键值所代表的外部对象；clear回调可用于应用自己的清理，不能把“释放所有资源”理解为自动释放任意用户对象。

> 译注——源码核对：复杂度与同步：平均O(1)描述以合理哈希分布为前提，不保证每次操作恒定耗时；碰撞、重新散列（Rehash）和内存分配会改变代价。接口不自行加锁，迭代顺序不是排序顺序，也不是稳定的插入顺序。遍历及其回调期间应保持映射结构稳定。

> 译注——源码核对：声明与存储期：DEFINE系列建立配置、运行数据和映射对象，并不预先分配全部桶或保证后续操作无堆分配。STATIC版本为这些对象添加static；非STATIC宏的data没有显式初始化器，宜放在文件作用域以获得零初始化，不能把函数内未初始化的自动对象当作空表。

> 译注——源码核对：配置选择：哈希映射实现与哈希函数是两组独立选择。SYS_HASH_MAP_CHOICE默认选分离链接，SYS_HASH_FUNC32_CHOICE默认选Murmur3；各自还需启用相应功能配置。C++实现会选择CPP、完整C++库及异常支持，官方定位主要是基准测试。

> 译注——源码核对：版本与实现差异：通用内联函数大多直接转发操作表，不统一验证max_size或修正后端行为。以下源码跟踪依据本次下载的官方文件；实现异常单独标注，不能将接口文档的返回契约当作所有分支已被运行验证。

本次验证范围为文档与源码对照，未编译或执行哈希映射、异常注入、性能及实板实验。
