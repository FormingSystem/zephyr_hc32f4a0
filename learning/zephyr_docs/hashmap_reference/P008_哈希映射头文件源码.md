<a id="l00316"></a>static inline bool sys_hashmap_should_rehash(const struct sys_hashmap *map, bool grow,
<a id="l00317"></a>                                             size_t num_reserved, size_t *new_num_buckets)
<a id="l00318"></a>{
<a id="l00319"></a>        size_t size;
<a id="l00320"></a>        bool should_grow;
<a id="l00321"></a>        size_t n_buckets;
<a id="l00322"></a>        bool should_shrink;
<a id="l00323"></a>        const bool shrink = !grow;
<a id="l00324"></a>        struct sys_hashmap_oa_lp_data *const data = (struct sys_hashmap_oa_lp_data *)map-&gt;data;
<a id="l00325"></a>        const struct sys_hashmap_config *const config = map-&gt;config;
<a id="l00326"></a>
<a id="l00327"></a>        /* All branchless calculations, so very cache-friendly */
<a id="l00328"></a>
<a id="l00329"></a>        /* calculate new size */
<a id="l00330"></a>        size = data-&gt;size;
<a id="l00331"></a>        size += grow;
<a id="l00332"></a>        /* maximum size imposed by the implementation */
<a id="l00333"></a>        __ASSERT_NO_MSG(size &lt; SIZE_MAX / 100);
<a id="l00334"></a>
<a id="l00335"></a>        /* calculate new number of buckets */
<a id="l00336"></a>        n_buckets = data-&gt;n_buckets;
<a id="l00337"></a>        /* initial number of buckets */
<a id="l00338"></a>        n_buckets += grow * (size == 1) * config-&gt;initial_n_buckets;
<a id="l00339"></a>        /* grow at a rate of 2x */
<a id="l00340"></a>        n_buckets &lt;&lt;= grow * (size != 1);
<a id="l00341"></a>        /* shrink at a rate of 2x */
<a id="l00342"></a>        n_buckets &gt;&gt;= shrink;
<a id="l00343"></a>
<a id="l00344"></a>        /* shrink to zero if empty */
<a id="l00345"></a>        n_buckets *= (size != 0);
<a id="l00346"></a>
<a id="l00347"></a>        __ASSERT_NO_MSG(new_num_buckets != NULL);
<a id="l00348"></a>        __ASSERT_NO_MSG(new_num_buckets != &amp;data-&gt;n_buckets);
<a id="l00349"></a>        *new_num_buckets = n_buckets;
<a id="l00350"></a>
<a id="l00351"></a>        should_grow =
<a id="l00352"></a>                grow &amp;&amp; (data-&gt;n_buckets == 0 ||
<a id="l00353"></a>                         (size + num_reserved) * 100 / data-&gt;n_buckets &gt; map-&gt;config-&gt;load_factor);
<a id="l00354"></a>        should_shrink =
<a id="l00355"></a>                shrink &amp;&amp; (n_buckets == 0 || (size * 100) / n_buckets &lt;= map-&gt;config-&gt;load_factor);
<a id="l00356"></a>
<a id="l00357"></a>        return should_grow || should_shrink;
<a id="l00358"></a>}

## 8.2\_可见注释译文（Comments）

1. 版权声明：Copyright (c) 2022 Meta；许可证为Apache-2.0，原法律文本完整保留。

2. 对realloc()的安全包装，不依赖由哪一种libc提供它。

3. 以下计算均不使用分支，因此有利于缓存（Cache）。

4. 计算新的大小。

5. 实现施加的最大大小限制。

6. 计算新的桶数量。

7. 初始桶数量。

8. 以两倍倍率增长。

9. 以二分之一倍率收缩。

10. 为空时收缩到零。

11. 头文件包含保护（Include Guard）结束：ZEPHYR_INCLUDE_SYS_HASH_MAP_H_。

## 8.4\_源码跟踪译注

> 译注——接口与所有权：键和值均以uint64_t传递并保存，API不理解字符串内容、对象析构或指针所指资源。分配器管理映射内部存储，调用者仍负责键值所代表的外部对象；clear回调可用于应用自己的清理，不能把“释放所有资源”理解为自动释放任意用户对象。

> 译注——复杂度与同步：平均O(1)描述以合理哈希分布为前提，不保证每次操作恒定耗时；碰撞、重新散列（Rehash）和内存分配会改变代价。接口不自行加锁，迭代顺序不是排序顺序，也不是稳定的插入顺序。遍历及其回调期间应保持映射结构稳定。

> 译注——声明与存储期：DEFINE系列建立配置、运行数据和映射对象，并不预先分配全部桶或保证后续操作无堆分配。STATIC版本为这些对象添加static；非STATIC宏的data没有显式初始化器，宜放在文件作用域以获得零初始化，不能把函数内未初始化的自动对象当作空表。

> 译注——配置选择：哈希映射实现与哈希函数是两组独立选择。SYS_HASH_MAP_CHOICE默认选分离链接，SYS_HASH_FUNC32_CHOICE默认选Murmur3；各自还需启用相应功能配置。C++实现会选择CPP、完整C++库及异常支持，官方定位主要是基准测试。

> 译注——版本与实现差异：通用内联函数大多直接转发操作表，不统一验证max_size或修正后端行为。以下源码跟踪依据本次下载的官方文件；实现异常单独标注，不能将接口文档的返回契约当作所有分支已被运行验证。

> 译注——迭代器size是构造时的条目数快照，pos为已访问数量；has_next只比较pos<size，不检查当前映射是否变化。先用api->iter构造，再循环检查has_next、调用next、读取key/value。各后端的尺寸断言不是锁，也不能检测条目数不变的替换或删后再加；不要在迭代中修改映射。

> 译注——should_rehash只计算候选桶数并返回判断，不执行分配。grow=true按即将多一项计算，应在新增之前调用；grow=false使用删除后的size。即使返回false，new_num_buckets仍被写入候选值，调用者应以布尔结果决定是否采用；输出指针不能为NULL或指向现有n_buckets。num_reserved只影响扩容负载判断，查询负载因子的函数不计它。
