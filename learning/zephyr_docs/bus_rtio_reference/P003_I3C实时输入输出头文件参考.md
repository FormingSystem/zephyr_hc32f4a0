## 3.4\_详细说明（Detailed Documentation）

### `I3C_RTIO_DEFINE`

```c
#define I3C_RTIO_DEFINE ( _name, _sq_sz, _cq_sz )
```

展开值（Value）：

```c
RTIO_DEFINE(CONCAT(_name, _r), _sq_sz, _cq_sz); \
static struct i3c_rtio _name = {                \
        .r = &CONCAT(_name, _r),                \
};
```

静态定义一个i3c_rtio上下文。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_name` | 上下文的符号名称。 |
| `_sq_sz` | 提交队列项（Submission Queue Entry，SQE）池大小。 |
| `_cq_sz` | 完成队列项（Completion Queue Entry，CQE）池大小。 |

### `i3c_rtio_complete()`

```c
bool i3c_rtio_complete ( struct i3c_rtio * ctx, int status )
```

通知当前提交项（ctx->txn_curr）已经完成。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `ctx` | I3C RTIO驱动上下文。 |
| `status` | 完成状态（Completion Status），负值表示错误。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `true` | 下一个提交项已经就绪，可以启动。 |
| `false` | 没有更多待处理的提交项。 |

## 3.5\_源码定位与版本边界

相对源码定位：[I2C RTIO头文件](../../../include/zephyr/drivers/i2c/rtio.h)、[I3C RTIO头文件](../../../include/zephyr/drivers/i3c/rtio.h)、[I2C实现](../../../drivers/i2c/i2c_rtio.c)、[I3C实现](../../../drivers/i3c/i3c_rtio.c)、[I2C公共接口](../../../include/zephyr/drivers/i2c.h)、[I3C公共接口](../../../include/zephyr/drivers/i3c.h)、[RTIO核心](../../../include/zephyr/rtio/rtio.h)、[SQE辅助函数](../../../include/zephyr/rtio/sqe.h)、[I2C配置](../../../drivers/i2c/Kconfig)和[I3C配置](../../../drivers/i3c/Kconfig)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：初始化与设备绑定：I3C_RTIO_DEFINE静态创建上下文并设置r；i3c_rtio_init初始化信号量、队列、事务指针及iodev.api，但当前实现没有设置iodev.data。transfer只更新ctx->i3c_desc，公共i3c_iodev_submit却从iodev.data取得i3c_iodev_data及bus。因此不能将DEFINE加init描述为已完成所有设备绑定；具体驱动集成还须提供公共提交路径要求的数据。这是源码边界提示，并未修改官方实现。

> 译注——源码核对：队列项不是数据副本：copy逐条申请SQE，根据READ标志准备读或写操作。普通prep_read／prep_write保存原缓冲区指针与长度，没有复制有效载荷；异步操作结束前，缓冲区、I/O设备描述及其引用对象须保持有效。copy返回最后一个SQE，不是事务头，也不执行硬件传输。num_msgs必须大于0；当前代码以断言表达该前提，不能把零消息当作受支持的空操作。

> 译注——源码核对：事务边界：copy为各项设置RTIO_SQE_TRANSACTION，最后一项清除此位，以连续提交项组成事务。消息的STOP／RESTART标志分别映射到总线I/O标志，并非copy自动替每个事务追加STOP。某个SQE申请失败时调用rtio_sqe_drop_all，后者清除该RTIO上下文提交队列中的全部待提交项，不仅是本次已经复制的消息；混用该队列的调用者必须考虑这一范围。

> 译注——源码核对：I3C标志与描述：copy映射STOP、RESTART、HDR、NBCH与NOACK_EXPECTED，并打包hdr_mode及hdr_cmd_code。配置包装保存type和config指针，CCC包装保存payload指针，均未深复制所指结构。HDR（高数据率，High Data Rate）或CCC操作是否受硬件支持仍由驱动决定，构造SQE并不能证明设备支持该操作。

> 译注——源码核对：提交与完成：submit先将I/O提交项放入MPSC队列，再在自旋锁保护下尝试选择当前事务。返回false可能表示已有事务正在进行，并不等于新提交被拒绝。complete遇到负状态时报告整个当前事务错误并选择下一事务；非负状态时先推进txn_curr，直到事务结束才报告成功。返回true表示有下一项可启动，不表示驱动已经自动启动硬件。只有当前操作确实完成后，驱动才应调用complete。

> 译注——源码核对：同步兼容包装：transfer、configure和recover用信号量以K_FOREVER串行访问内部上下文，并调用rtio_submit(r, 1)等待至少一个完成项；这些包装不是可随意在ISR里调用的非阻塞入口。transfer消费并释放当前可见的完成项，将最后消费到的result作为返回值；配置／恢复包装取单个完成项，没有取到时返回-EIO。实现没有检查rtio_submit的返回值，因此不能把这层包装描述为对所有提交失败都有独立校验。

> 译注——源码核对：CCC包装：i3c_rtio_ccc同样持有信号量、申请SQE并提交RTIO_OP_I3C_CCC，等待完成后释放CQE；无可用SQE返回-ENOMEM，没有完成项返回-EIO。该头文件没有提供I2C对应的run_sync_start_async循环辅助函数，不将两种头文件视为完全相同的接口集合。

> 译注——源码核对：配置与实际能力：I2C_RTIO和I3C_RTIO当前均标为实验性（Experimental），选择RTIO与RTIO_WORKQ。SQ_SIZE／CQ_SIZE控制提交及完成资源容量，不能据默认值推断任意长度消息数组都能提交。公共i2c_iodev_submit／i3c_iodev_submit在驱动未提供iodev_submit操作时报告-ENOSYS；存在回退辅助机制并不意味着这些公共包装自动替所有驱动安装回退。

> 译注——源码核对：原文命名：recover说明中的i3c_recover()按原页保留；当前公共驱动头文件的恢复入口为i3c_recover_bus()。源码结尾注释的DRVIERS拼写按原样保留。

> 译注——源码核对：版本边界：本批核对两种总线的RTIO头文件、实现与Kconfig，两个公共驱动头文件，以及RTIO核心和SQE头文件，共十份官方源码并记录摘要。两份源码页非注释代码分别与读取的官方头文件一致；latest、滚动main及仓库版本不自动相同。源码定位使用相对路径，本次未构建固件、连接总线、发送消息或操作硬件。

本次验证范围为文档与源码对照，未构建固件、连接总线、发送消息或操作硬件。
