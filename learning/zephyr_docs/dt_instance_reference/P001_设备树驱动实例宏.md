```c
            ())
```

对兼容字符串为DT_DRV_COMPAT且状态为okay的所有节点调用fn。

设备树（Devicetree）片段示例：

原始示例（Example）：

```dts
a {
        compatible = "vnd,device";
        status = "okay";
        foobar = "DEV_A";
};

b {
        compatible = "vnd,device";
        status = "okay";
        foobar = "DEV_B";
};

c {
        compatible = "vnd,device";
        status = "disabled";
        foobar = "DEV_C";
};
```

使用示例：

原始示例（Example）：

```c
#define DT_DRV_COMPAT vnd_device
#define MY_FN(inst) DT_INST_PROP(inst, foobar),

```

原始示例（Example）：

```c
MY_FN(0) MY_FN(1)
```

然后进一步展开为以下结果之一：

原始示例（Example）：

```c
"DEV_A", "DEV_B",
```

或以下结果：

原始示例（Example）：

```c
"DEV_B", "DEV_A",
```

不保证a和b在展开结果中的出现顺序。

注意，fn负责添加逗号、分号或其他分隔符、终止符。

设备驱动应尽可能使用此宏，为设备树中匹配驱动兼容字符串DT_DRV_COMPAT的每个已启用节点实例化一个struct device。

| --- | --- |
| `fn` | 为每个已启用节点调用的宏。必须只接收一个实例编号参数。 |

> 译注——源码核对：回调类型：DT_INST_FOREACH_STATUS_OKAY传入fn(inst)，VARGS版本为fn(inst, ...)，不会再附加compat。不要与DT_COMPAT_FOREACH_STATUS_OKAY_VARGS的fn(inst, compat, ...)或DT_FOREACH_STATUS_OKAY的fn(node_id)混淆。该宏本身只生成回调展开；由回调中的DEVICE_DT_INST_DEFINE等声明创建设备对象，不会自动执行设备初始化。

## 1.3\_源码定位与版本边界

本册收录基于实例的设备树API（Instance-based Devicetree APIs），涵盖节点关系、属性、寄存器、中断、总线和遍历。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)和[生成脚本](../../../scripts/dts/gen_defines.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：与通用接口的关系：多数DT_INST_*宏先用DT_DRV_INST(inst)得到节点标识，再调用通用宏。它们继承通用版本的类型、默认值与存在性边界，实例包装不会额外检查硬件就绪、补齐绑定或提供运行时异常恢复。通用说明见[节点标识](../dt_identity_reference/P001_设备树节点标识宏.md)、[属性读取](../dt_property_reference/P001_设备树属性读取宏.md)、[寄存器](../dt_reg_reference/P001_设备树寄存器属性宏.md)和[中断属性](../dt_irq_reference/P001_设备树中断属性宏.md)。

> 译注——源码核对：示例结果：sensor0与sensor1启用，sensor2禁用。ALL检查中foo满足全部启用节点，而bar与baz不满足；ANY检查中foo与bar至少满足一个启用节点，baz仅出现在禁用节点而不计入。代码中的// 1与// 0就是对应的真／假结果。示例需要匹配属性类型的绑定及有效i2c0上下文，不能仅复制覆盖片段就假定会生成所有属性宏。

> 译注——源码核对：遍历参数：实例的子节点回调接收子节点标识，标签回调接收保持大小写的标签标记，属性回调接收(node_id, prop, idx)，reg回调接收(node_id, idx)；VARGS版本将附加参数接在这些参数之后。原说明中的VA_ARGS表示可变实参，实际展开使用__VA_ARGS__。这与遍历设备实例时传入inst不同；_SEP仅在相邻展开之间放置分隔符，逗号写成(,)。详见[通用遍历宏](../dt_foreach_reference/P001_设备树遍历宏.md)。

> 译注——源码核对：子节点与总线：CHILD只涉及直接子节点。CHILD_BY_UNIT_ADDR_INT要求兄弟节点中的整数单元地址唯一；其addr用于拼接生成标记，应使用生成器所用十进制地址标记，而不是把0x前缀或算术表达式当作可自动求值的实参。DESCENDANT_NUM_ON_BUS在遇到声明bus的节点后停止向其下方继续统计，不是对整个子树无条件递归；bus实参用i2c、spi这样的标记，不带引号。

> 译注——源码核对：属性和回退：枚举idx先选择属性数组元素，返回值才是该值在enum列表中的位置。ENUM_IDX_OR只检查对应元素存在，不能补救缺少enum元数据。字符串逻辑长度为1；数组花括号展开是初始化器，PHANDLE得到节点标识，PHA得到描述符单元值。PROP_OR、字符串_OR与PHA_OR分别继承属性、索引或单元存在性条件；字符串类型不正确时不能指望_OR自动改走默认值。

> 译注——源码核对：寄存器与中断：没有BY_IDX／BY_NAME的基本读取宏通常固定索引0；原文的“唯一”不表示宏会验证仅有一项。REG_ADDR_RAW省略整数后缀包装，不表示跳过生成器地址翻译；U64增加64位后缀，在链接器／汇编上下文按原文退化为普通形式。IRQ_LEVEL是控制器层级，不是优先级；IRQ与IRQN分别用于描述符单元和中断号，启用多级中断时IRQN可能包含编码，不能直接等同于原始irq单元。
