# 第25章\_内存块分配器

原文：[Memory Blocks Allocator](https://docs.zephyrproject.org/latest/kernel/memory_management/sys_mem_blocks.html)。读取日期：2026-10-12，`latest`。

**内存块分配器（Memory Block Allocator）**从指定内存区域动态分配固定大小的块，可以一次分配或释放多个块。同次分配的一组块不一定连续，适合分散/聚集 **直接内存访问（Direct Memory Access，DMA）** 等操作。

与 slab 不同，其记账信息放在数据缓冲区之外。分配器不需要访问数据内容，因此缓冲区所在内存区域可以在适当时机断电节能。

## 25.1\_概念

分配器数量只受可用内存等资源限制，通过内存地址引用。其关键属性包括：块大小、可分配块数、承载所有块的缓冲区，以及记录分配状态的位图。

原文要求块大小按正的 `4N` 字节粒度考虑，块数必须大于 0，缓冲区至少容纳“块大小 × 块数”字节。缓冲区按大于 2 的某个 2 的幂对齐，例如 4、8、16 字节；块大小必须是该对齐值的整数倍，保证每块都对齐。

由于内部记账结构及创建方式，每个分配器必须在编译时声明并定义。

> 译注：本地 `include/zephyr/sys/mem_blocks.h` 的定义宏还明确断言块大小必须是 2 的幂，不能把原文的 `4N` 理解为允许任意 4 的倍数。应用应遵守目标版本宏的完整约束。

## 25.2\_内部工作方式

缓冲区由紧密排列的固定大小块组成，块间没有额外空隙。分配器通过 `sys_bitarray` 位图接口逐个查找空闲块，直到满足请求数量。

> 译注——位图的原子操作：普通空闲查询不占用资源；底层alloc和test_and_set_region才在位数组自旋锁内完成检查及状态修改。位索引和位数均不是字节地址，内存块层另按块大小换算。完整规则见[位数组公共接口](../bitarray_reference/P001_位数组公共接口.md)。

全部分配器元数据位于缓冲区之外，分配代码不会碰缓冲区内容，所以缓冲区区域可以断电而不破坏管理状态。

> 译注：是否可以断电仍取决于应用是否需要保存内容、是否有 DMA 或其他访问尚未完成；元数据外置只解决分配器本身不触碰数据区域的问题。

## 25.3\_多分配器组

多内存块分配器组提供统一管理若干分配器的辅助函数。应用可写选择回调，决定从哪个成员分配。

运行时先调用 `sys_multi_mem_blocks_init()` 初始化组，再用 `sys_multi_mem_blocks_add_allocator()` 加入各分配器。

`sys_multi_mem_blocks_alloc()` 接收一个不透明配置参数，直接传给选择回调。回调选出合适分配器后，通过 `sys_mem_blocks_alloc()` 完成分配。

`sys_multi_mem_blocks_free()` 释放时不需要配置参数。实现根据传入块地址找到所属分配器，再调用 `sys_mem_blocks_free()`。

## 25.4\_定义分配器

对象类型为 `sys_mem_blocks_t`，用 `SYS_MEM_BLOCKS_DEFINE` 在编译时定义和初始化。下例包含 4 个 64 字节块，按 4 字节对齐：

```c
SYS_MEM_BLOCKS_DEFINE(allocator, 64, 4, 4);
```

私有作用域可使用：

```c
SYS_MEM_BLOCKS_DEFINE_STATIC(static_allocator, 64, 4, 4);
```

也可提供预定义缓冲区，将数据区放在独立位置；缓冲区定义时必须显式保证对齐：

```c
uint8_t __aligned(4) backing_buffer[64 * 4];
SYS_MEM_BLOCKS_DEFINE_WITH_EXT_BUF(allocator, 64, 4, backing_buffer);
```

## 25.5\_分配与释放块

调用 `sys_mem_blocks_alloc()` 分配多个块：

```c
int ret;
uintptr_t blocks[2];

ret = sys_mem_blocks_alloc(allocator, 2, blocks);
```

返回 0 时，`blocks` 数组包含所分配各块的地址。使用完成后，通过 `sys_mem_blocks_free()` 归还：

```c
int ret;
uintptr_t blocks[2];

ret = sys_mem_blocks_alloc(allocator, 2, blocks);
... /* perform some operations on the allocated memory blocks */
ret = sys_mem_blocks_free(allocator, 2, blocks);
```

> 译注：原例将 `allocator` 当作指针传入，但前面宏定义的是对象；对应调用应传 `&allocator`。本地声明的输出/输入参数类型为 `void **`，应使用指针数组，如 `void *blocks[2]`，而不是把 `uintptr_t[]` 未经核对当作兼容参数。必须先确认分配成功，才可使用或释放所请求的块。

## 25.6\_使用分配器组

下面提供选择回调并加入两个分配器。回调根据 `cfg` 选择组成员，具体逻辑由应用填写：

```c
sys_mem_blocks_t *choice_fn(struct sys_multi_mem_blocks *group, void *cfg)
{
    ... /* choose which allocator in the group to use based on cfg */
}

SYS_MEM_BLOCKS_DEFINE(allocator0, 64, 4, 4);
SYS_MEM_BLOCKS_DEFINE(allocator1, 64, 4, 4);

static sys_multi_mem_blocks_t alloc_group;

sys_multi_mem_blocks_init(&alloc_group, choice_fn);
sys_multi_mem_blocks_add_allocator(&alloc_group, &allocator0);
sys_multi_mem_blocks_add_allocator(&alloc_group, &allocator1);
```

下面从组分配，再通过组释放：

```c
int ret;
uintptr_t blocks[1];
size_t blk_size;

ret = sys_multi_mem_blocks_alloc(&alloc_group, UINT_TO_POINTER(0),
                                 1, blocks, &blk_size);

ret = sys_multi_mem_blocks_free(&alloc_group, 1, blocks);
```

`blk_size` 用于接收所选分配器的块大小。该例中的地址数组类型也应按前述 **应用程序编程接口（Application Programming Interface，API）** 签名修正，并检查分配与释放返回值。

完整参考见[Memory Blocks APIs](../memblocks_reference/P001_内存块分配公共接口.md)。

> 译注——失败、连续性与释放：普通多块分配失败会回滚本次已分配块，但不会清空输出数组；连续分配仅输出一个起点。批量释放遇错仍继续处理后续项，可能部分成功，不能把返回错误理解为全部未释放。区域空闲查询不预留块；多分配器组的同次释放必须来自同一成员。接口和源码边界见[内存块分配公共接口](../memblocks_reference/P001_内存块分配公共接口.md)。
