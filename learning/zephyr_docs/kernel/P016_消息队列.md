# 第16章\_消息队列

原文：[Message Queues](https://docs.zephyrproject.org/latest/kernel/services/data_passing/message_queues.html)。读取日期：2026-10-12，`latest`。

**消息队列（Message Queue）**是实现简单消息队列的内核对象，允许线程与**中断服务例程（Interrupt Service Routine，ISR）**异步发送、接收固定大小的数据项。

## 16.1\_概念

可以定义任意数量的消息队列，仅受可用内存等资源限制，通过内存地址引用。对象有三个关键属性：保存已发送但未接收数据的环形缓冲区、以字节为单位的数据项大小，以及缓冲区最多容纳的数据项数量。使用前必须初始化，使缓冲区为空。

线程或 ISR 可以发送数据项。如果已有接收线程等待，就把发送者所指数据复制给该线程；否则在有空间时复制进环形缓冲区。两种路径都要求发送的数据区域大小与队列的数据项大小一致。

环形缓冲区已满时，发送线程可选择等待空间。多个发送线程可同时等待；空间出现后，优先交给最高优先级发送者，同优先级时选等待最久者。

线程可接收数据，内核将数据复制到其指定区域；接收区域大小必须与数据项大小相匹配。队列为空时，接收线程可等待。多个接收线程等待时，新项优先交给最高优先级者，同优先级时选等待最久者。

线程还可窥视（peek）队首消息：把内容复制到指定区域，但不从队列移除，同样要求匹配数据项大小。

ISR 也可以接收，但队列为空时不得等待。环形缓冲区没有特殊对齐要求，因为底层使用可处理未对齐地址的 `memcpy()`，也不暴露内部指针。

> 译注：ISR 发送时同样不能等待队列空间，应使用 `K_NO_WAIT` 并处理失败。接收缓冲区必须至少容纳完整数据项；队列每次复制固定的数据项字节数，而不会根据实际对象大小自动调整。

## 16.2\_定义消息队列

用 `struct k_msgq` 定义对象，并通过 `k_msgq_init()` 初始化。下例定义一个可保存 10 项、每项 12 字节的空队列：

```c
struct data_item_type {
    uint32_t field1;
    uint32_t field2;
    uint32_t field3;
};

char my_msgq_buffer[10 * sizeof(struct data_item_type)];
struct k_msgq my_msgq;

k_msgq_init(&my_msgq, my_msgq_buffer, sizeof(struct data_item_type), 10);
```

也可以用以下宏在编译时定义并初始化：

| 宏 | 用途 |
| --- | --- |
| `K_MSGQ_DEFINE` | 定义公开消息队列。 |
| `K_MSGQ_DEFINE_STATIC` | 定义具有静态作用域的私有消息队列。 |
| `K_MSGQ_DEFINE_TYPE` | 按指定数据项类型定义公开队列。 |
| `K_MSGQ_DEFINE_STATIC_TYPE` | 按指定类型定义私有队列。 |

下例效果与前面的运行时初始化相同，宏同时定义队列和缓冲区：

```c
K_MSGQ_DEFINE(my_msgq, sizeof(struct data_item_type), 10, 1);
```

若编译时已知数据项类型，可用 `K_MSGQ_DEFINE_TYPE` 自动配置数据项大小和对齐：

```c
K_MSGQ_DEFINE_TYPE(my_msgq, struct data_item_type, 10);
```

> 译注：这里保留官网当前列出的全部宏；旧版头文件不一定提供所有简写形式，应核对目标版本。

## 16.3\_写入消息队列

调用 `k_msgq_put()` 加入数据。下例从生产者向一个或多个消费者发送数据。如果消费者跟不上导致队列满，生产者丢弃所有旧消息，再保存新数据。该接口可能触发重新调度。

```c
void producer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* create data item to send (e.g. measurement, timestamp, ...) */
        data = ...

        /* send data to consumers */
        while (k_msgq_put(&my_msgq, &data, K_NO_WAIT) != 0) {
            /* message queue is full: purge old data & try again */
            k_msgq_purge(&my_msgq);
        }

        /* data item was successfully added to message queue */
    }
}
```

> 译注：这里“丢弃所有旧消息”是示例主动调用 `k_msgq_purge()` 的策略，不是消息队列满时的默认行为。需要保证每条数据不丢失的应用，不能照搬此策略。

## 16.4\_读取消息队列

`k_msgq_get()` 取出一条消息。下例处理一个或多个生产者生成的数据。原文特别提醒：必须检查返回值，因为 `k_msgq_purge()` 可能使调用返回 `-ENOMSG`。

```c
void consumer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* get a data item */
        k_msgq_get(&my_msgq, &data, K_FOREVER);

        /* process data item */
        ...
    }
}
```

> 译注：虽然正文强调检查返回值，原代码却忽略了它。实际程序应只在返回 0 后处理 `data`；`K_FOREVER` 也不能保证该调用一定成功，清空操作可能使等待提前失败。

## 16.5\_窥视队首消息

`k_msgq_peek()` 复制队首数据项但不移除。下例窥视生产者提交的队首项：

```c
void consumer_thread(void)
{
    struct data_item_type data;

    while (1) {
        /* read a data item by peeking into the queue */
        k_msgq_peek(&my_msgq, &data);

        /* process data item */
        ...
    }
}
```

> 译注：原例同样未检查返回值。队列为空时不能处理未取得的数据；成功 peek 也不会消费消息，重复循环可能反复处理同一项。需要消费时使用 get，并明确 peek 与其他消费者并发操作的关系。

## 16.6\_用途、成本与接口

消息队列适合在线程间异步传递小型数据项。也可以传递大数据，但读写会锁中断，且整项复制的时间随大小线性增加，可能增大中断延迟。因此，大对象通常更适合传递指向对象的指针，而不是复制整个对象。

> 译注：传指针后，消息队列只复制指针值；对象所有权、有效期和多线程访问必须由应用保证。

需要同步传输时，可采用内核[邮箱](https://docs.zephyrproject.org/latest/kernel/services/data_passing/mailboxes.html)对象。

原文相关配置选项列为“无”。完整接口见[Message Queue APIs](../msgstack_reference/P001_消息队列公共接口.md)。相关[消息队列示例](../basic_samples/P026_消息队列示例.md#msg_queue)实现基本的生产者/消费者线程对。

> 译注——复制与缓冲区寿命：当前实现中，阻塞的put会暂存源数据地址，直到有空间后完成复制；函数返回前应保持源消息有效且不被并发改写。put_front固定不等待，队列满时返回-ENOMSG。cleanup只负责按分配标志释放内部缓冲区，不能代替purge；具体条件见[消息队列公共接口](../msgstack_reference/P001_消息队列公共接口.md)。
