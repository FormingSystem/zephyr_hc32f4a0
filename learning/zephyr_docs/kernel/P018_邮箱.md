# 第18章\_邮箱

原文：[Mailboxes](https://docs.zephyrproject.org/latest/kernel/services/data_passing/mailboxes.html)。读取日期：2026-10-12，`latest`。

**邮箱（Mailbox）**是提供增强消息传递能力的内核对象，能力超出普通消息队列。线程可以同步或异步发送、接收任意大小的消息。

## 18.1\_概念

邮箱数量仅受可用内存等资源限制，每个对象通过内存地址引用。它包含两条队列：发送队列保存已发送但未接收的消息；接收队列保存等待消息的线程。使用前必须初始化，将两条队列置空。

邮箱只在线程之间交换消息，不用于中断服务例程。发送者称为发送线程，接收者称为接收线程。每条消息只能由一个线程接收，不支持一对多或广播消息。

邮箱消息不是匿名处理的：通信双方可以得知对方身份，也可以指定只与哪个线程通信。

## 18.2\_消息格式

消息描述符是描述数据位置及邮箱处理方式的结构。发送者和接收者访问邮箱时都提供描述符；邮箱据此判断双方是否兼容，并在交换过程中更新部分字段，使双方知道实际发生了什么。

消息数据可以是零个或多个字节，大小和格式由应用决定，不同消息可以不同。消息缓冲区是发送或接收线程提供的内存区域，通常可以使用数组或结构体变量。

没有消息数据存储的消息称为空消息。已有消息缓冲区、但其中实际数据长度为 0 的消息，不等同于没有缓冲区的空消息。

> 译注：原文沿用“没有任一形式的消息数据”的措辞，但当前页只具体说明消息缓冲区形式。这里按本页公开字段区分 `tx_data == NULL` 的空消息与缓冲区存在而 `size == 0` 的情况，不额外补造另一种数据载体。

## 18.3\_消息生命周期

发送线程把消息交给邮箱时，消息被创建。之后由邮箱持有，直到交给接收线程。接收线程既可以在接收消息时立即取走数据，也可以通过后续第二次邮箱操作再取数据。只有数据提取流程结束后，邮箱才删除这条消息。

## 18.4\_线程兼容性

发送线程可以指定接收线程地址，也可用 `K_ANY` 允许任意线程接收。接收线程同样可以指定发送者地址，或用 `K_ANY` 接收任意来源。只有双方限制都满足时才能交换消息，此时称为兼容。

例如 A 只向 B 发送：B 若等待 A 的消息或任意来源，就能接收；B 若只等 C，就不匹配。C 永远不能接收这条指定给 B 的消息，即使 C 正在等 A 或任意来源。

## 18.5\_消息流量控制

发送者决定交换采用同步还是异步方式。同步方式中，发送线程阻塞到接收方完成消息处理；异步方式中，发送者不等别人接收就继续工作，例如收集下一条消息的数据。

同步交换提供隐式流量控制：发送速度不能超过接收处理速度。异步交换则通过显式机制，让发送者在发下一条之前判断上一条是否仍存在。

> 译注：本页的“完成处理”是邮箱意义上的数据取走或丢弃、消息删除，并不自动表示接收线程已经完成所有后续业务运算。若应用需要业务级完成确认，还须定义额外应答协议。

## 18.6\_定义邮箱

用 `struct k_mbox` 定义，再调用 `k_mbox_init()` 初始化空邮箱：

```c
struct k_mbox my_mailbox;

k_mbox_init(&my_mailbox);
```

也可使用宏 `K_MBOX_DEFINE` 在编译时定义并初始化，效果相同：

```c
K_MBOX_DEFINE(my_mailbox);
```

## 18.7\_消息描述符字段

描述符类型为 `struct k_mbox_msg`。应用只应使用下列公开字段，其他字段留给邮箱内部实现。

| 字段 | 含义与设置方式 |
| --- | --- |
| `info` | 由应用定义的 32 位信息值。交换可双向进行：每次交换发送者都能传给接收者；同步交换中，接收者也能把信息传回发送者。 |
| `size` | 消息数据字节数。发送空消息或零长度缓冲区时设为 0；接收时设为最多愿意接收的大小，不要数据则设 0。接收后邮箱更新为实际交换字节数。 |
| `tx_data` | 发送缓冲区指针，空消息设 `NULL`。接收时无须初始化该字段。 |
| `tx_target_thread` | 期望接收线程的地址；`K_ANY` 允许任何线程接收。接收方不必初始化。消息接收后更新为实际接收线程地址。 |
| `rx_source_thread` | 期望发送线程的地址；`K_ANY` 允许任意来源。发送方不必初始化。消息放入邮箱时更新为实际发送线程地址。 |

## 18.8\_发送消息

发送线程先准备数据（若有），再按上述规则准备描述符，最后调用邮箱发送接口。若已有兼容接收者等待，立即交付；否则进入发送队列。

发送队列可同时有多条消息，按发送线程优先级排序，同优先级按先发送者优先。原文不在此规定队列固定容量；异步管理资源另受后述配置影响。

同步发送通常要等接收方既接收消息、又提取数据后才完成。如果指定等待时间内消息没有被接收，则从发送队列移除并报告失败。成功后，发送者可检查描述符，了解实际接收线程、交换字节数和接收者返回的 `info`。

即使指定最长等待时间，同步发送仍可能无限阻塞：超时只限制**等待消息被接收**的阶段。消息一旦被接收，就不限制接收者之后花多长时间提取数据、解除发送者阻塞。

异步发送按原文描述立即完成发送调用，不论当时是直接交付还是排入发送队列。发送者可选传一个信号量，邮箱在消息被删除时给出该信号量，例如接收者已接收并提取数据后。应用可据此限制某个发送者或一组发送者尚未完成的消息数量，形成显式流控。

异步发送者无法通过这种交换得知实际接收线程、实际交换量或接收方提供的 `info`。

> 译注：异步调用返回并不表示发送缓冲区已经可复用；应保持消息数据有效，直到完成通知或应用协议确认不再访问。异步管理资源有限，也应核对目标版本 **应用程序编程接口（Application Programming Interface，API）** 对资源耗尽的约定，不能把原文“立即完成”理解为无限容量保证。

### 18.8.1\_发送空消息

下面通过邮箱同步向任意愿意接收的消费者传递 4 字节随机值。`info` 已足以承载该值，所以不使用消息数据缓冲区：

```c
void producer_thread(void)
{
    struct k_mbox_msg send_msg;

    while (1) {

        /* generate random value to send */
        uint32_t random_value = sys_rand32_get();

        /* prepare to send empty message */
        send_msg.info = random_value;
        send_msg.size = 0;
        send_msg.tx_data = NULL;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);
    }
}
```

### 18.8.2\_通过消息缓冲区发送

下面同步发送变长请求。`info` 用于交换双方能够处理的数据长度信息；发送方提供待发送长度，接收方可返回自身缓冲区容量：

```c
void producer_thread(void)
{
    char buffer[100];
    int buffer_bytes_used;

    struct k_mbox_msg send_msg;

    while (1) {

        /* generate data to send */
        ...
        buffer_bytes_used = ... ;
        memcpy(buffer, source, buffer_bytes_used);

        /* prepare to send message */
        send_msg.info = buffer_bytes_used;
        send_msg.size = buffer_bytes_used;
        send_msg.tx_data = buffer;
        send_msg.tx_target_thread = K_ANY;

        /* send message and wait until a consumer receives it */
        k_mbox_put(&my_mailbox, &send_msg, K_FOREVER);

        /* info, size, and tx_target_thread fields have been updated */

        /* verify that message data was fully received */
        if (send_msg.size < buffer_bytes_used) {
            printf("some message data dropped during transfer!");
            printf("receiver only had room for %d bytes", send_msg.info);
        }
    }
}
```

> 译注：示例省略了数据来源与长度计算，应保证 `buffer_bytes_used` 不超过 `buffer` 容量，并检查发送返回值后再使用回填字段。`info` 的格式化输出也应与其实际整数类型匹配。

## 18.9\_接收消息

接收线程先准备描述符，声明希望接收的消息，再调用接收接口。邮箱搜索发送队列，选第一个兼容发送者的消息。没有兼容消息时可选择等待；指定等待时间内仍未出现则失败。成功后可检查描述符，得知发送者、实际交换量和发送方 `info`。

多个线程可以同时在接收队列等待，按优先级排序，同优先级时先等待者优先。不过兼容性限制意味着并非总按先进先出交付。例如 A 只等 X，稍后 B 只等 Y；此时 Y 向任意线程发送的消息会交给 B，A 继续等。

接收者控制取多少数据以及放在哪里：可以取全部、只取开头一部分，或完全不要；也可以选择自己的目标缓冲区。

### 18.9.1\_接收时立即取数据

最直接的方法是在接收时提供非 `NULL` 缓冲区地址及容量。邮箱在接收操作中复制数据；目标太小时，未复制部分丢失；消息较短时，缓冲区未填满部分保持原样。无论哪种情况，描述符都会记录实际复制字节数。

立即提取适合最大长度已知的小消息。下例处理任意生产者发送的变长请求，用 `info` 交换长度信息，并求接收到的消息字节之和：

```c
void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[100];

    int i;
    int total;

    while (1) {
        /* prepare to receive message */
        recv_msg.info = 100;
        recv_msg.size = 100;
        recv_msg.rx_source_thread = K_ANY;

        /* get a data item, waiting as long as needed */
        k_mbox_get(&my_mailbox, &recv_msg, buffer, K_FOREVER);

        /* info, size, and rx_source_thread fields have been updated */

        /* verify that message data was fully received */
        if (recv_msg.info != recv_msg.size) {
            printf("some message data dropped during transfer!");
            printf("sender tried to send %d bytes", recv_msg.info);
        }

        /* compute sum of all message bytes (from 0 to 100 of them) */
        total = 0;
        for (i = 0; i < recv_msg.size; i++) {
            total += buffer[i];
        }
    }
}
```

> 译注：原例用 `char` 缓冲区累加，若目标平台的 `char` 有符号，值大于 127 的字节可能按负数累加。若协议需要无符号字节和，应显式按无符号类型处理。示例还省略了接收返回值检查。

### 18.9.2\_稍后通过缓冲区提取

接收时把缓冲区地址设为 `NULL`，并把 `size` 设为之后最多愿意提取的字节数，就能推迟数据复制。邮箱不在本次接收中复制数据，但仍更新描述符，指明可提取多少字节。

随后必须按以下规则处理：

- 若回填 `size` 为 0，可能是发送者没有数据，也可能是接收者不要数据；邮箱已完成提取流程并删除消息，不需要后续操作。
- 若 `size` 非零且仍要数据，调用 `k_mbox_data_get()` 并提供足够大的缓冲区。邮箱复制数据后删除消息。
- 若 `size` 非零但决定不要数据，仍必须调用 `k_mbox_data_get()`，缓冲区传 `NULL`，让邮箱不复制而直接删除消息。

这种方式适合不宜立即复制的场合，例如内存受限、接收者无法始终准备容纳最大消息的缓冲区。

下例先用发送者 `info` 判断消息类型，只有符合条件才复制数据，以避免不必要的复制：

```c
void consumer_thread(void)
{
    struct k_mbox_msg recv_msg;
    char buffer[10000];

    while (1) {
        /* prepare to receive message */
        recv_msg.size = 10000;
        recv_msg.rx_source_thread = K_ANY;

        /* get message, but not its data */
        k_mbox_get(&my_mailbox, &recv_msg, NULL, K_FOREVER);

        /* get message data for only certain types of messages */
        if (is_message_type_ok(recv_msg.info)) {
            /* retrieve message data and delete the message */
            k_mbox_data_get(&recv_msg, buffer);

            /* process data in "buffer" */
            ...
        } else {
            /* ignore message data and delete the message */
            k_mbox_data_get(&recv_msg, NULL);
        }
    }
}
```

> 译注：这段示例仍预留了 10000 字节栈缓冲区，展示的是“按类型决定是否复制”，本身并未节省这块缓冲区。小栈嵌入式线程不能未经核算就照搬其大小。原文前述 `size == 0` 分支也应在完整应用中妥善处理。

## 18.10\_用途、配置与接口

当普通消息队列不能满足线程间传递需求时，可以使用邮箱。相关 Kconfig 选项为 `CONFIG_NUM_MBOX_ASYNC_MSGS`。完整接口见[Mailbox APIs](../mboxpipe_reference/P001_邮箱公共接口.md)。

> 译注——异步资源的具体实现：本次官方mailbox.c以K_FOREVER从共享栈取得异步描述符，池耗尽时调用仍会阻塞；它复制描述符而不复制源数据。配置、完成通知与原描述符更新边界见[邮箱公共接口](../mboxpipe_reference/P001_邮箱公共接口.md)。
