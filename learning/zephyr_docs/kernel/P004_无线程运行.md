# 第4章\_不启用线程的运行方式

原文：[Operation without Threads](https://docs.zephyrproject.org/latest/kernel/services/threads/nothread.html)。读取日期：2026-10-12，`latest`。

**引导加载器（Bootloader）**、简单事件驱动应用和展示核心能力的示例，可能不需要线程。将 `CONFIG_MULTITHREADING=n` 可关闭线程支持。这会显著改变 Zephyr 功能范围，而且原文说明测试覆盖有限，不能默认其他能力都照常工作。

## 4.1\_预期可用的核心能力

关闭多线程后，以下功能应正常工作：

- 构建系统，以及启动应用进入 `main()`。
- 中断管理。
- 系统时钟，包括 `k_uptime_get()`。
- 定时器，原文写作 `k_timer()`。
- 不休眠的延迟，例如 `k_busy_wait()`。
- 通过 `k_cpu_idle()` 进入 **中央处理器（Central Processing Unit，CPU）** 空闲睡眠。
- `main()` 之前的驱动和子系统初始化，例如 `SYS_INIT`。
- 内存管理。
- 后文明确列出的部分驱动。

这些要求也影响其他配置选择，例如 `CONFIG_SYS_CLOCK_EXISTS` 不能设为 `n`。

> 译注：这里的 `k_timer()` 是原文对定时器机制的概括，并非要求调用一个名为 `k_timer()` 的创建函数。CPU 空闲睡眠也不等于支持线程阻塞等待。

## 4.2\_不能预期可用的能力

大部分内核线程 **应用程序编程接口（Application Programming Interface，API）** 将不可用，包括线程、调度、工作队列、Polling API、信号量、互斥锁、条件变量，以及内核数据传递机制。

## 4.3\_子系统与驱动支持边界

以下子系统预期可在一定程度上工作。没有列出的子系统不应假设受支持。即使在已列出的子系统中，部分现有驱动仍可能依赖线程；项目会考虑为这些范围内的驱动增加支持，也会考虑在特定平台上影响较小的隔离实现。

### 4.3.1\_Flash

**片上系统（System on Chip，SoC）** 内部 Flash 外设驱动预期可用；通过总线访问的串行存储设备可能不受支持。

原文此处尚未提供具体受支持驱动列表，只有待补充列表/表格的说明，不能据此推断某一外部 Flash 已受支持。

### 4.3.2\_GPIO

SoC 内部 **通用输入输出（General-Purpose Input/Output，GPIO）** 外设驱动预期可用；GPIO 扩展器等总线设备可能不受支持。原文具体驱动列表同样尚未补齐。通用接口见[GPIO 译文](../hardware/P005_GPIO.md)。

### 4.3.3\_UART

SoC **通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）** 外设驱动的部分功能预期可用：

- 启用 `CONFIG_UART_INTERRUPT_DRIVEN` 的应用是否可用，取决于驱动实现。
- 启用 `CONFIG_UART_ASYNC_API` 的应用是否可用，也取决于驱动实现。
- 两者都不启用、采用基本轮询方式的应用预期可用。

原文尚未给出具体驱动及各 API 支持表。三种接口区别见[UART 译文](../hardware/P006_UART.md)。
