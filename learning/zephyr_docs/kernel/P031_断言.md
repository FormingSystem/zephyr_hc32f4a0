# 第31章\_断言

原文：[Assertions](https://docs.zephyrproject.org/latest/kernel/services/other/assert.html)。读取日期：2026-10-12，`latest`。

Zephyr 提供多种**断言（Assertion）**设施检测编程错误。运行时断言在程序运行期间检查条件，失败则触发致命错误；当前原文推荐支持模块配置的 `ZASSERT()`，旧 `__ASSERT()` 已成为其兼容层并标为弃用。构建断言 `BUILD_ASSERT()` 则完全在编译期求值，并且始终检查。

`ZASSERT()` 与 Ztest 测试框架中小写的 `zassert_true()`、`zassert_equal()` 等宏无关：后者报告测试失败，前者报告编程错误并触发致命错误。

> 译注：本页按读取时最新模块断言体系翻译。较旧 Zephyr 分支可能仍只有传统 `__ASSERT()`，应检查目标版本是否有 `zephyr/sys/zassert.h`，不要把当前官网的迁移状态当作所有版本都已完成的事实。

## 31.1\_运行时断言等级

模块接口声明在 [`include/zephyr/sys/zassert.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/zassert.h)。各源文件选择一个断言模块，其等级为编译期常量，编译器可据此裁剪断言体积。

| 等级常量 | 检查与失败输出 |
| --- | --- |
| `ZASSERT_LEVEL_OFF` | 完全移除断言。 |
| `ZASSERT_LEVEL_TERSE` | 检查条件；失败仅输出固定 `ASSERTION FAIL`，不编入位置、条件文本、消息及参数。 |
| `ZASSERT_LEVEL_NORMAL` | 检查条件；失败输出位置 `ASSERTION FAIL @ file:line`，不编入条件文本、消息及参数。 |
| `ZASSERT_LEVEL_VERBOSE` | 检查条件；失败输出字符串化的条件、位置及可选消息。 |

`CONFIG_ASSERT` 是总开关。关闭时，全部模块强制为 OFF，`ZASSERT()`、`ZASSERT_MODULE()` 均不生成相关代码，不受模块独立配置影响。

裁剪依赖编译优化来删除不使用的条件、参数和字符串常量。优化级别较低时，死代码消除可能不充分，即使模块等级较低，二进制中仍可能残留断言相关内容。

## 31.2\_选择模块并使用断言

在源文件作用域、任何 `ZASSERT` 使用之前，选择一次模块：

```c
#include <zephyr/sys/zassert.h>

ZASSERT_MODULE(MYMODULE);
```

模块名为大写标识符。默认等级来自 `CONFIG_ASSERT_MODULE_<module>_LEVEL`，本例为 `CONFIG_ASSERT_MODULE_MYMODULE_LEVEL`。也可传第二个参数覆盖文件等级，例如 `ZASSERT_MODULE(MYMODULE, ZASSERT_LEVEL_VERBOSE)`。

选定后，用 `ZASSERT` 检查条件，可带类似 `printf()` 的格式化消息：

```c
ZASSERT(x == 3, "x was %d, expected 3", x);
```

条件为假且等级至少 TERSE 时触发致命错误。位置只在 NORMAL 及以上编入并打印；条件文本、消息和参数只在 VERBOSE 时编入并打印。

头文件及内联函数不应在文件作用域放 `ZASSERT_MODULE()`，否则选择会泄漏到每个包含者。可以在函数体内选择模块，将作用域限定在代码块内：

```c
static inline void f(void *ptr)
{
        ZASSERT_MODULE(MYMODULE);

        ZASSERT(ptr != NULL, "ptr must not be NULL");
}
```

固定等级断言还可直接用 `ZASSERT_TERSE()`、`ZASSERT_NORMAL()`、`ZASSERT_VERBOSE()`；它们在调用处选择等级，不向当前作用域声明模块：

```c
ZASSERT_TERSE(ptr != NULL);
ZASSERT_NORMAL(ptr != NULL);
ZASSERT_VERBOSE(ptr != NULL, "ptr must not be NULL");
```

注意带 `_LEVEL_` 的名称是配置等级常量，不带它的上述宏才执行固定等级断言。

文件级模块必须在该翻译单元第一次 `ZASSERT()` 之前选定，每个文件只能选择一个文件级模块。作用域内没有模块却使用 `ZASSERT()` 会编译失败；可先选择模块，或改用固定等级形式。无论哪种形式，`CONFIG_ASSERT` 总开关仍有效。

## 31.3\_定义模块Kconfig等级

模块等级符号通过 [`subsys/debug/zassert/Kconfig.template.assert`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/debug/zassert/Kconfig.template.assert) 生成。先设置模块名和可读说明，再引入模板：

```text
module = MYMODULE
module-str = the MYMODULE assert module
source "subsys/debug/zassert/Kconfig.template.assert"
```

模板生成 Off、Terse、Normal、Verbose 四选一配置，以及由其推导、不可直接赋值的整数符号 `CONFIG_ASSERT_MODULE_MYMODULE_LEVEL`，供 `ZASSERT_MODULE(MYMODULE)` 使用。选项默认 Verbose，可在 `prj.conf` 中覆盖。

## 31.4\_示例

[断言示例](https://docs.zephyrproject.org/latest/samples/subsys/debug/asserts/README.html#assert)演示总开关启用时，为单个文件开启详细断言。简化版本如下：

```c
#include <zephyr/kernel.h>
#include <zephyr/sys/zassert.h>

ZASSERT_MODULE(MYMODULE);

int main(void)
{
        int x = 2;

        ZASSERT(x == 3, "x was %d, expected 3", x);

        return 0;
}
```

配置 `CONFIG_ASSERT_MODULE_MYMODULE_LEVEL_VERBOSE=y` 后，失败检查产生类似输出：

```text
ASSERTION FAIL [x == 3] @ .../src/main.c:...
x was 2, expected 3
```

## 31.5\_定制失败行为

断言失败路径集中在一组可覆盖的弱函数中，声明位于 `zassert.h`，实现位于 [`subsys/debug/zassert/zassert.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/debug/zassert/zassert.c)。

- `zassert_fail()` 报告断言失败，包括位置及存在时的消息、参数，然后调用 `zassert_post_action()`。覆盖它可截获或重定向整个断言报告流程。
- `zassert_post_action()` 执行最终动作。默认用户模式线程失败调用 `k_oops()`，其他情况调用 `k_panic()`。
- `zassert_vprint()` 是全部断言文字经过的输出原语，可在一处重定向文本。`zassert_print()` 是它的可变参数包装，供旧 `__ASSERT_PRINT()` 兼容层使用。
- 启用 `CONFIG_ASSERT_TEST` 后，后处理函数允许返回而非终止，以便测试通过自定义钩子验证断言行为。

## 31.6\_构建断言

`BUILD_ASSERT()` 全部在编译期求值，始终检查，与 C `_Static_assert`、C++ `static_assert` 语义相同。失败产生编译错误；编译器支持时还打印指定消息。

消息必须为静态字符串或静态字符串拼接，不支持运行时格式化或可变参数。下例假定条件不成立：

```c
BUILD_ASSERT(FOO == 2000, "Invalid value of FOO, expected 2000, got " STRINGIFY(FOO));
```

GCC 输出类似：

```text
     tests/kernel/fatal/src/main.c: In function 'test_main':
     include/zephyr/toolchain/gcc.h:28:37: error: static assertion failed:
"Invalid value of FOO, expected 2000, got 1000"
      #define BUILD_ASSERT(EXPR, MSG) _Static_assert(EXPR, "" MSG)
                                      ^~~~~~~~~~~~~~
     tests/kernel/fatal/src/main.c:370:2: note: in expansion of macro 'BUILD_ASSERT'
       BUILD_ASSERT(FOO == 2000,
       ^~~~~~~~~~~~~~~~
```

## 31.7\_旧版__ASSERT兼容层

[`include/zephyr/sys/__assert.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/__assert.h) 中的 `__ASSERT()` 家族早于 `ZASSERT()`，当前通过内建 DEFAULT 模块兼容。新代码推荐使用专属模块的 `ZASSERT()`。

原文将旧 `__ASSERT()` 及相关传统 `CONFIG_ASSERT*` 配置标为弃用，它们仍可经 DEFAULT 模块工作，但底层接口未来可能变化。

DEFAULT 模块由 `CONFIG_ASSERT` 启用，等级来自 `CONFIG_ASSERT_MODULE_DEFAULT_LEVEL`，通过以下选择项设置：`CONFIG_ASSERT_MODULE_DEFAULT_LEVEL_OFF`、`_TERSE`、`_NORMAL`、`_VERBOSE`。运行 Zephyr 测试时，`CONFIG_TEST` 默认启用断言。

旧配置仍用于推导 DEFAULT 等级：`CONFIG_ASSERT_VERBOSE` 对应 Verbose；`CONFIG_ASSERT_NO_COND_INFO`、`CONFIG_ASSERT_NO_MSG_INFO`、`CONFIG_ASSERT_NO_FILE_INFO` 对应 Terse；`CONFIG_ASSERT_LEVEL == 0` 使其为 Off。未设置这些旧配置时，DEFAULT 选择保持自身 Verbose 默认值，延续旧行为。要无条件关闭全部断言，设 `CONFIG_ASSERT=n`。

> 译注：原文“`CONFIG_ASSERT*` 弃用”的通配写法过宽；同页仍明确把 `CONFIG_ASSERT` 作为新体系总开关，并使用新的模块等级选项。应按具体旧兼容符号理解，不能因此删除所有以该前缀开头的当前配置。

完整参考见[模块化断言接口](https://docs.zephyrproject.org/latest/doxygen/html/group__zassert.html)。
