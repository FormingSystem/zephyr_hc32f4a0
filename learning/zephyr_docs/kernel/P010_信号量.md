# 第10章\_信号量

原文：[Semaphores](https://docs.zephyrproject.org/latest/kernel/services/synchronization/semaphores.html)。读取日期：2026-10-12，`latest`。

**信号量（Semaphore）**是实现传统计数信号量的内核对象。

## 10.1\_概念

可以定义任意数量的信号量，仅受可用内存等资源限制。每个信号量通过其内存地址引用，具有两个关键属性：计数 `count` 表示还能成功获取多少次，0 表示当前不可用；上限 `limit` 表示计数所能达到的最大值。

信号量使用前必须初始化。初始计数必须为非负数且不大于上限。

线程或**中断服务例程（Interrupt Service Routine，ISR）**可以给出信号量（give）。给出会增加计数；若已达到上限，则不再增加。

线程可以获取信号量（take）。获取成功会减少计数；若计数为 0，则不可获取，线程可以选择等待别人给出信号量。多个线程可以同时等待同一个不可用信号量。给出信号量时，优先交给优先级最高的等待线程；同优先级时，交给等待最久者。

把初始计数设为上限，也就是“满”信号量，可以限制同时进入临界区的线程数量。初始计数为 0、上限大于 0 的“空”信号量则形成一道门：在有人增加计数之前，等待线程都不能通过。常见计数信号量的标准用法均可支持。

内核也允许 ISR 获取信号量，但不可用时 ISR **不得等待**。

## 10.2\_定义信号量

用 `struct k_sem` 类型的变量定义对象，再调用 `k_sem_init()` 初始化。下面将初值设为 0、上限设为 1，得到一个初始不可用的二值信号量：

```c
struct k_sem my_sem;

k_sem_init(&my_sem, 0, 1);
```

也可以使用宏 `K_SEM_DEFINE` 在编译时定义并初始化。下面与上述代码效果相同：

```c
K_SEM_DEFINE(my_sem, 0, 1);
```

## 10.3\_给出信号量

调用 `k_sem_give()` 给出信号量。下面的代码沿用前例，通知消费者线程已有一份数据可供处理：

```c
void input_data_interrupt_handler(void *arg)
{
    /* notify thread that data is available */
    k_sem_give(&my_sem);

    ...
}
```

> 译注：上限为 1 时，消费者取走之前多次 give 会合并为同一个可用状态。若必须逐个记录输入项，应另外保存数据及数量，或采用合适容量的队列；这段原例只演示通知。

## 10.4\_获取信号量

调用 `k_sem_take()` 获取信号量。下面最多等 50 毫秒，未能及时取得时输出警告；成功后读取可用数据：

```c
void consumer_thread(void)
{
    ...

    if (k_sem_take(&my_sem, K_MSEC(50)) != 0) {
        printk("Input data not available!");
    } else {
        /* fetch available data */
        ...
    }
    ...
}
```

## 10.5\_用途、配置与接口

信号量可控制多个线程对一组资源的访问，也可同步生产者、消费者线程与 ISR 之间的处理。原页相关配置选项列为“无”。正式接口见[Semaphore APIs](../synchronization_reference/P008_信号量公共接口.md)。

- [基本同步](../basic_samples/P029_基本同步示例.md#synchronization)：操作基本内核同步原语。
- [哲学家就餐](../basic_samples/P030_哲学家就餐示例.md#dining-philosophers)：用 Zephyr 内核服务实现哲学家就餐问题的一种解法。

## 10.6\_用户模式信号量

启用用户模式时，`sys_sem` 对象位于用户内存，为用户模式线程提供计数信号量。未启用用户模式时，它的行为与 `k_sem` 相同。详见[用户模式信号量 API](../userspace_sync_reference/P007_用户模式信号量公共接口.md)。

> 译注——用户模式包装的返回值：本次源码中，用户模式sys_sem以Futex和原子操作维护计数；非用户模式版本转发k_sem，但将take的-EBUSY／-EAGAIN转换为-ETIMEDOUT。初始化检查和饱和give的返回值也存在后端差异，不能直接套用k_sem错误码，详见[用户模式信号量参考](../userspace_sync_reference/P007_用户模式信号量公共接口.md)。
