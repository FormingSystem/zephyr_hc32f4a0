# 第6章\_定时器

原文：[Timers](https://docs.zephyrproject.org/latest/kernel/services/timing/timers.html)。读取日期：2026-10-12，`latest`。

**定时器（Timer）**是使用内核系统时钟测量时间流逝的内核对象。到达时限后，它可以执行应用定义的动作，也可以只记录到期次数，等待应用查询。

## 6.1\_基本属性

可以定义任意数量的定时器，受可用 **随机存取存储器（Random Access Memory，RAM）** 限制，每个定时器通过内存地址引用。主要属性如下：

| 属性 | 含义 |
| --- | --- |
| duration | 从启动到首次到期的时长，类型 `k_timeout_t`，可通过不同单位的宏构造。 |
| period | 首次到期后各周期之间的间隔，同为 `k_timeout_t`，不得为负；`K_NO_WAIT`（零）或 `K_FOREVER` 表示只到期一次的单次定时器。 |
| 到期函数 | 每次到期时由系统时钟中断处理程序执行，可为 `NULL`。 |
| 停止函数 | 运行中的定时器被提前停止时执行，可为 `NULL`；原文描述为由停止它的线程执行。 |
| status | 自上次读取以来的到期次数。 |

例如首次延迟 200 ms、周期 75 ms，应使用相应超时值，第一次在 200 ms 后到期，以后每 75 ms 到期。

> 译注：描述中的数字是时间示意，调用接口时应写 `K_MSEC(200)`、`K_MSEC(75)` 等，不能把普通整数当成当前 **应用程序编程接口（Application Programming Interface，API）** 的 `k_timeout_t`。停止回调处于调用停止操作的上下文；若允许从 **中断服务例程（Interrupt Service Routine，ISR）** 停止，也不能在回调中假定一定可以阻塞。

## 6.2\_初始化、启动与周期基准

使用前必须初始化，指定到期和停止回调，清零状态并进入停止状态。启动时给定 duration、period，状态再次清零，然后开始倒计时。

duration 是相对启动时刻的最小延迟。period 则相对前一次**应当到期的时刻**计算，所以周期定时器不会相对系统时钟持续漂移；实际相邻回调间隔可能比 period 短，也可能更长，受中断处理延迟和前面回调执行时间等因素影响。

若要求每次动作之后至少再等指定时长，应在到期回调中或处理到期后重新启动定时器。

运行中到期时，状态计数增加，执行到期回调，并唤醒等待该定时器的线程。单次定时器随后停止；周期定时器按原有理论到期时间轴安排下一次，而不是简单从当前回调执行时刻重新起算。

## 6.3\_停止、重启与状态读取

可以在倒计时中提前停止。停止不改变已有状态计数，定时器进入停止状态并执行停止回调，等待线程被唤醒。停止已经停止的定时器允许，但没有效果。

也可以在运行中重启：清零状态，采用新的 duration 和 period 重新倒计时；原本等待该定时器的线程继续等待。

任何时刻都可直接读取状态，得到自上次读取以来的到期次数，**读取会把计数清零**。也可读取到期剩余时间；零表示定时器已经停止。

线程还可以与定时器同步：如果状态非零或定时器已停止，就立即继续；否则阻塞到至少一次到期或定时器停止。同步操作返回状态并清零它。

同一个定时器只应有一个状态读取者，因为直接或同步读取都会改变值；同时也只能有一个线程等待其状态同步。ISR 不允许执行这种可能阻塞的同步。

## 6.4\_定时器观察者

启用 `CONFIG_TIMER_OBSERVER` 后，可注册观察者，接收系统内所有定时器的初始化、启动、停止和到期事件。这样跟踪、性能分析或电源管理模块可以观察活动，无须修改内核或各定时器。

使用 `K_TIMER_OBSERVER_DEFINE` 静态定义观察者，提供 `on_init`、`on_start`、`on_stop`、`on_expiry` 回调，不需要的传 `NULL`。到期观察回调运行在中断上下文，必须短小且不阻塞。

## 6.5\_定义定时器

定义 `struct k_timer`，再调用 `k_timer_init()`：

```c
struct k_timer my_timer;
extern void my_expiry_function(struct k_timer *timer_id);

k_timer_init(&my_timer, my_expiry_function, NULL);
```

也可用 `K_TIMER_DEFINE` 在编译期定义并初始化，效果相同：

```c
K_TIMER_DEFINE(my_timer, my_expiry_function, NULL);
```

## 6.6\_由到期回调提交工作

如果周期任务不能在中断上下文完成，到期回调应把工作项交给系统工作队列，由线程处理：

```c
void my_work_handler(struct k_work *work)
{
    /* do the processing that needs to be done periodically */
    ...
}

K_WORK_DEFINE(my_work, my_work_handler);

void my_timer_handler(struct k_timer *dummy)
{
    k_work_submit(&my_work);
}

K_TIMER_DEFINE(my_timer, my_timer_handler, NULL);

...

/* start a periodic timer that expires once every second */
k_timer_start(&my_timer, K_SECONDS(1), K_SECONDS(1));
```

示例每秒到期一次，ISR 只提交工作，复杂操作留在 `my_work_handler()`。

## 6.7\_直接读取状态

下面启动 200 ms 单次定时器，做其他工作后检查状态：

```c
K_TIMER_DEFINE(my_status_timer, NULL, NULL);

...

/* start a one-shot timer that expires after 200 ms */
k_timer_start(&my_status_timer, K_MSEC(200), K_NO_WAIT);

/* do work */
...

/* check timer status */
if (k_timer_status_get(&my_status_timer) > 0) {
    /* timer has expired */
} else if (k_timer_remaining_get(&my_status_timer) == 0) {
    /* timer was stopped (by someone else) before expiring */
} else {
    /* timer is still running */
}
```

状态大于零表示已到期；状态为零且剩余时间也为零，示例解释为被其他代码提前停止；否则仍在运行。

> 译注：该判断依赖只有一个状态读取者等使用前提。如果其他代码已经读取并清零状态，就不能再用相同判断推断完整历史。

## 6.8\_同步等待状态

下面让两个协议操作至少隔开指定时间，同时利用中间时间完成其他工作：

```c
K_TIMER_DEFINE(my_sync_timer, NULL, NULL);

...

/* do first protocol operation */
...

/* start a one-shot timer that expires after 500 ms */
k_timer_start(&my_sync_timer, K_MSEC(500), K_NO_WAIT);

/* do other work */
...

/* ensure timer has expired (waiting for expiry, if necessary) */
k_timer_status_sync(&my_sync_timer);

/* do second protocol operation */
...
```

如果线程中间没有其他工作，可以直接 sleep，无须单独建立定时器。

> 译注：`k_timer_status_sync()` 也会因定时器被停止而返回。此例“确保时间已过”的前提是没有其他代码提前停止它；若存在取消路径，应检查返回状态并按协议要求处理。

## 6.9\_用途、配置与参考

定时器适合在指定时间后发起异步操作、判断时间是否已经流逝，以及在带时限操作期间继续做其他工作。原文还建议在需要比简单 `k_sleep()`、`k_usleep()` 更精细的控制时采用定时器。

若只需测量某操作耗时，直接读取系统时钟或硬件时钟即可，无须定时器。

原文末尾“相关配置选项”列为无；本页前面新增的观察者功能则明确使用 `CONFIG_TIMER_OBSERVER`，应按实际功能区分。完整接口见[官方 Timer APIs](https://docs.zephyrproject.org/latest/doxygen/html/group__timer__apis.html)。
