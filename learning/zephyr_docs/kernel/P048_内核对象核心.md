# 第48章\_内核对象核心

原文：[Object Cores](https://docs.zephyrproject.org/latest/kernel/object_cores/index.html)。读取日期：2026-10-12，`latest`。

**对象核心（Object Core）**是一种内核调试设施，可用于识别已登记的对象，并对其执行操作。

## 48.1\_对象核心的概念

每个对象实例嵌入名为 `obj_core` 的字段，把对象关联到其对象类型。每个对象类型使调试工具能够枚举该类型的实例，各对象类型又通过单链表连接，从而可以遍历系统中的对象。

每种类型从两个来源枚举对象：一是永久对象，例如 `K_SEM_DEFINE` 静态定义的实例，直接遍历其可迭代段，无须运行时登记；二是容量有上限的运行时对象登记表，例如驱动数据结构中经 `k_sem_init()` 初始化的信号量。登记表只引用对象，不把登记链表内容写入对象内部。

因此对象可以在任意存储中初始化、原地重新初始化，或在没有对象核心调用的情况下被丢弃；对象消失不会破坏登记表结构。但这个模型有以下规则：

- 位于当前运行线程栈或中断栈中的对象不登记，因为其寿命随栈帧结束；对象类型的 `skipped` 计数记录这类情况。其他栈不一定能被识别，例如用户线程系统调用使用的特权栈，或架构专用异常栈；其中对象仍可能登记，并持续被报告，直到存储被复用。
- 登记表已满时，新对象不再登记，由类型的 `dropped` 计数记录。容量通过 `CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS` 设置。
- 对象被丢弃但未注销时，仍可能被报告，直到存储复用。遍历通过类型标记消失识别存储已复用并删除条目。内核会在释放对象时主动注销，包括线程终止、`k_object_free()`、`k_timer_cleanup()`、`k_msgq_cleanup()`、`k_stack_cleanup()`；启用 `CONFIG_OBJ_CORE_EVICT_ON_FREE` 时，将内存归还给堆、固定块内存池或内存块分配器也会注销。
- 用其他方式结束对象寿命的代码可以调用 `k_obj_core_unlink()`，使其立即停止被报告。类型标记检查只是兜底，它仍会读取对象原存储，所以该存储必须保持有效映射。
- 某类型的 `dropped` 一旦非零，就存在任何遍历都不会报告的对象；只有它为零时，原文才将清单视为完整。

> 译注：这里的“完整”受前述主动跳过栈对象等规则约束，不能把 `dropped == 0` 当作所有曾经创建对象都在清单中的保证。当前登记表模型来自此版官方文档，也不等同于旧版对象核心链表实现。

已接入对象核心的内核对象包括条件变量、事件、**先进先出（First In, First Out，FIFO）**、**后进先出（Last In, First Out，LIFO）**、邮箱、固定块内存池、消息队列、互斥量、管道、通用队列、信号量、线程、定时器和系统内存块。开发者也可为自己项目中的其他对象接入。

[对象核心示例](../basic_samples/P027_对象核心示例.md)逐步展示该设施；[对象监视器示例](../basic_samples/P028_对象监视器示例.md)用于观察运行中应用的对象变化。

## 48.2\_对象统计

不同内核对象可以收集并报告统计信息。对象核心统计提供统一访问方式：启用后，对象类型保存一个统计描述符指针，描述可用操作；对象核心保存该对象“原始”统计数据指针。

原始数据是尚未加工的统计值。查询结果可能就是原始数据，也可能已经计算处理，例如求平均值。原文列出的支持情况如下：

| 对象类型 | 原始数据类型 | 查询数据类型 |
| --- | --- | --- |
| `struct mem_slab` | `struct mem_slab_info` | `struct sys_memory_stats` |
| `struct sys_mem_blocks` | `struct sys_mem_blocks_info` | `struct sys_memory_stats` |
| `struct k_thread` | `struct k_cycle_stats` | `struct k_thread_runtime_stats` |
| `struct _cpu` | `struct k_cycle_stats` | `struct k_thread_runtime_stats` |
| `struct z_kernel` | `struct k_cycle_stats[num CPUs]` | `struct k_thread_runtime_stats` |

> 译注：表中首行沿用原文拼写。本地核对的 `include/zephyr/kernel.h` 使用 `struct k_mem_slab` 和 `struct k_mem_slab_info`，具有 `k_` 前缀；实际代码应遵循目标版本声明。

## 48.3\_实现方式

下面依次说明对象类型定义、实例初始化、遍历和统计查询。代码为相互衔接的原文示例，其中占位定义及命名差异不能直接作为可编译程序。

### 48.3.1\_定义新对象类型

对象类型是 `struct k_obj_type` 类型的全局变量。如果对象结构的静态实例位于可迭代段，可通过 `K_OBJ_TYPE_DEFINE` 在构建时定义类型，这些实例就是永久对象。以下示例同时配置对象核心与统计描述符：

```c
/* Unique object type ID */

#define K_OBJ_TYPE_MY_NEW_TYPE  K_OBJ_TYPE_ID_GEN("UNIQ")

struct my_obj_type_raw_info {
    ...
};

struct my_obj_type_query_stats {
    ...
};

struct my_new_obj {
    ...
    struct k_obj_core obj_core;
    struct my_obj_type_raw_info  info;
};

struct k_obj_core_stats_desc my_obj_type_stats_desc = {
    .raw_size = sizeof(struct my_obj_type_raw_stats),
    .query_size = sizeof(struct my_obj_type_query_stats),
    .raw = my_obj_type_stats_raw,
    .query = my_obj_type_stats_query,
    .reset = my_obj_type_stats_reset,
    .disable = NULL,    /* Stats gathering is always on */
    .enable = NULL,     /* Stats gathering is always on */
};

K_OBJ_TYPE_DEFINE_STATS(my_obj_type, my_new_obj, K_OBJ_TYPE_MY_NEW_TYPE,
                        &my_obj_type_stats_desc, info);
```

`K_OBJ_TYPE_ID_GEN("UNIQ")` 用于生成本例的唯一类型标识；统计描述符中的 `raw`、`query`、`reset` 指定原始读取、查询及重置操作，`disable` / `enable` 为 `NULL` 表示本例统计始终开启。

> 译注：原例声明 `my_obj_type_raw_info`，却在 `.raw_size` 使用 `my_obj_type_raw_stats`，名称不一致。实际实现需统一为真实数据类型，并提供例中省略的统计函数。

对象不放在可迭代段时，应先在运行时初始化对象类型，再初始化实例。可以把永久对象数组登记为该类型的固定范围，这样这些对象不占动态登记项：

```c
struct k_obj_type  my_obj_type;
struct my_new_obj  my_objects[8];

void my_obj_type_init(void)
{
    z_obj_type_init(&my_obj_type, K_OBJ_TYPE_MY_NEW_TYPE,
                    offsetof(struct my_new_obj, obj_core));
    k_obj_type_init_range(&my_obj_type, my_objects,
                          &my_objects[ARRAY_SIZE(my_objects)],
                          sizeof(struct my_new_obj), false);
    k_obj_type_stats_init(&my_obj_type, &my_obj_type_stats_desc);
}
```

### 48.3.2\_初始化对象核心

已接入框架的内核对象，在初始化时自动初始化其对象核心。自定义对象则要显式初始化并登记。如果实例已属于类型的永久范围，登记操作无效果，因为遍历会从范围中报告它。

```c
void my_new_obj_init(struct my_new_obj *new_obj)
{
    ...
    k_obj_core_init(K_OBJ_CORE(new_obj), &my_obj_type);
    k_obj_core_link(K_OBJ_CORE(new_obj));
    k_obj_core_stats_register(K_OBJ_CORE(new_obj), &new_obj->raw_stats,
                              sizeof(struct my_obj_type_raw_info));
}
```

> 译注：前一例结构成员名为 `info`，此例却使用 `new_obj->raw_stats`；需要统一。`K_OBJ_CORE()` 取得实例中嵌入的对象核心地址，`k_obj_core_stats_register()` 登记原始统计区域。

### 48.3.3\_遍历对象

`k_obj_type_walk_locked()` 与 `k_obj_type_walk_unlocked()` 都先访问永久对象，再访问运行时登记对象。以下示例查找类型并打印全部对象地址：

```c
int walk_op(struct k_obj_core *obj_core, void *data)
{
    uint8_t *ptr;

    ptr = obj_core;
    ptr -= obj_core->type->obj_core_offset;

    printk("%p\n", ptr);

    return 0;
}

void print_object_addresses(void)
{
    struct k_obj_type *obj_type;

    /* Find the object type */

    obj_type = k_obj_type_find(K_OBJ_TYPE_MY_NEW_TYPE);

    /* Walk the list of objects */

    k_obj_type_walk_unlocked(obj_type, walk_op, NULL);
}
```

> 译注：回调从对象核心地址减去 `obj_core_offset`，恢复外层对象地址。原例 `ptr = obj_core` 在严格编译下涉及不同结构指针与字节指针的赋值，应显式转换为 `uint8_t *`；使用前也应处理类型查找失败。这里保留原代码以便对照。

### 48.3.4\_查询和重置统计

下面示例获取对象的查询统计，成功后重置统计值：

```c
struct my_new_obj my_obj;

...

void my_func(void)
{
    struct my_obj_type_query_stats  my_stats;
    int  status;

    my_obj_type_init(&my_obj);

    ...

    status = k_obj_core_stats_query(K_OBJ_CORE(&my_obj),
                                    &my_stats, sizeof(my_stats));
    if (status != 0) {
        /* Failed to get stats */
        ...
    } else {
        k_obj_core_stats_reset(K_OBJ_CORE(&my_obj));
    }

    ...
}
```

> 译注：原文此前 `my_obj_type_init(void)` 初始化类型，`my_new_obj_init(struct my_new_obj *)` 初始化实例；此处却调用 `my_obj_type_init(&my_obj)`。实际代码应先保证类型已初始化，再用实例初始化函数初始化 `my_obj`，不能照抄这个参数不匹配的调用。

## 48.4\_配置选项

基本配置为 `CONFIG_OBJ_CORE`、`CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS`、`CONFIG_OBJ_CORE_EVICT_ON_FREE`。

各对象接入配置包括 `CONFIG_OBJ_CORE_CONDVAR`、`CONFIG_OBJ_CORE_EVENT`、`CONFIG_OBJ_CORE_FIFO`、`CONFIG_OBJ_CORE_LIFO`、`CONFIG_OBJ_CORE_MAILBOX`、`CONFIG_OBJ_CORE_MEM_SLAB`、`CONFIG_OBJ_CORE_MSGQ`、`CONFIG_OBJ_CORE_MUTEX`、`CONFIG_OBJ_CORE_PIPE`、`CONFIG_OBJ_CORE_QUEUE`、`CONFIG_OBJ_CORE_SEM`、`CONFIG_OBJ_CORE_STACK`、`CONFIG_OBJ_CORE_THREAD`、`CONFIG_OBJ_CORE_TIMER`、`CONFIG_OBJ_CORE_SYS_MEM_BLOCKS`。

统计配置包括 `CONFIG_OBJ_CORE_STATS`、`CONFIG_OBJ_CORE_STATS_MEM_SLAB`、`CONFIG_OBJ_CORE_STATS_THREAD`、`CONFIG_OBJ_CORE_STATS_SYSTEM`、`CONFIG_OBJ_CORE_STATS_SYS_MEM_BLOCKS`。
