# 第63章\_内核服务入口

原文：[Kernel Services](https://docs.zephyrproject.org/latest/kernel/services/index.html)。读取日期：2026-10-12，`latest`。

Zephyr 内核是每个 Zephyr 应用的核心，提供占用小、性能高且功能丰富的多线程执行环境。设备驱动、网络协议栈和应用特定代码利用这些内核能力组成完整应用。

内核可配置，只纳入应用需要的功能，适合内存很少或多线程需求简单的系统。原文举例最低可至 2 KB，或仅需一组中断处理程序加一个后台任务；应用包括嵌入式传感器集线器、环境传感器、简单 **发光二极管（Light-Emitting Diode，LED）** 可穿戴设备和库存标签。

需要更多内存（原文举例 50 至 900 KB）、多个通信设备（例如 Wi-Fi 与低功耗蓝牙）以及复杂多线程的应用，也可以使用 Zephyr，如运动穿戴设备、智能手表和物联网无线网关。

> 译注：这些容量数字是原文的应用范围示例，不是当前任意架构、工具链或功能组合的已验证最小资源需求；实际镜像与运行内存需按工程配置测量。

## 63.2\_数据传递

这些内核对象用于在线程与**中断服务例程（Interrupt Service Routine，ISR）**之间传递数据。下面完整翻译原页高层特性表；原文与具体接口存在差异的条目在表后说明。

| 对象 | 双向？ | 数据结构 | 数据项大小 | 数据对齐 | ISR可接收？ | ISR可发送？ | 容量超限处理 |
| --- | --- | --- | --- | --- | --- | --- | --- |
| **先进先出（First In, First Out，FIFO）** | 否 | 队列 | 任意 [1] | 4 B [2] | 是 [3] | 是 | 不适用 |
| **后进先出（Last In, First Out，LIFO）** | 否 | 队列 | 任意 [1] | 4 B [2] | 是 [3] | 是 | 不适用 |
| 数据栈 | 否 | 数组 | 机器字 | 机器字 | 是 [3] | 是 | 未定义行为 |
| 消息队列 | 否 | 环形缓冲区 | 任意 [6] | 2 的幂 | 是 [3] | 是 | 线程等待或返回负错误码 |
| 邮箱 | 是 | 队列 | 任意 [1] | 任意 | 否 | 否 | 不适用 |
| 管道 | 否 | 环形缓冲区 [4] | 任意 | 任意 | 是 [5] | 是 [5] | 线程等待或返回负错误码 |

原文脚注：

1. 调用者在数据元素自身中为队列管理开销分配空间。
2. 通过 `k_fifo_alloc_put()` / `k_lifo_alloc_put()` 加入的对象没有此对齐限制，但会使用调用线程资源池中的临时内存。
3. ISR 接收时，超时参数只能是 `K_NO_WAIT`。
4. 管道的环形缓冲区可选。
5. ISR 发送或接收管道数据时，超时只能是 `K_NO_WAIT`。
6. 数据项大小必须是数据对齐值的整数倍。

> 译注：这张总表包含旧说明，不能替代具体接口。FIFO/LIFO 直接节点需要满足目标平台指针对齐，不能把“4 B”推广到所有架构；消息队列专页明确说明其底层按 `memcpy()` 复制，没有特殊对齐要求；本地 `k_stack_push()` 声明明确规定满栈返回 `-ENOMEM`，不是本表所写的“未定义行为”。脚注 [1] 也不应推广为邮箱用户负载必须嵌入队列节点；邮箱消息描述符与数据缓冲区规则见对应章节。ISR 发送消息同样不得等待。选型和实现请优先核对目标版本 **应用程序编程接口（Application Programming Interface，API）** 与专页。

具体章节为[通用队列](P028_通用队列与取消等待.md)、[FIFO](P014_FIFO先进先出队列.md)、[LIFO](P015_LIFO后进先出队列.md)、[数据栈](P029_整数数据栈.md)、[消息队列](P016_消息队列.md)、[邮箱](P018_邮箱.md)和[管道](P017_管道.md)。
