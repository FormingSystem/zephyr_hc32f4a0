# 第29章\_整数数据栈

原文：[Stacks](https://docs.zephyrproject.org/latest/kernel/services/data_passing/stacks.html)。读取日期：2026-10-12，`latest`。

这里的**栈（Stack）**是**后进先出（Last In, First Out，LIFO）**数据容器，允许线程与**中断服务例程（Interrupt Service Routine，ISR）**加入或取出有限数量的整数值。

> 译注：这是 `k_stack` 数据传递对象，不是线程执行时保存局部变量和返回地址的调用栈。

## 29.1\_概念

对象数量仅受可用内存等资源限制，通过内存地址引用。核心属性是存储尚未取出的整数值的数组，以及可存储的最大值数量。

数组元素类型为 `stack_data_t`，按本机机器字边界对齐。该类型宽度取决于处理器架构和编译模式，为 32 或 64 位。

使用前必须初始化，使栈为空。线程或 ISR 可压入一个值；有等待线程时直接交付，否则压入数组。

启用 `CONFIG_NO_RUNTIME_CHECKS` 时，内核不检测和阻止对已满栈继续压入。溢出会越过数组边界，导致不可预测行为。

线程可弹出数据。空栈时可选择等待，多个线程可同时等待。新值到来时先交给最高优先级线程，同优先级时交给等待最久者。ISR 也可弹出，但空栈时不得等待。

## 29.2\_定义数据栈

用 `struct k_stack` 定义对象，再调用 `k_stack_init()` 或 `k_stack_alloc_init()`。后者不由调用者提供数组，而从调用线程资源池分配缓冲区。

下面定义可容纳 10 个机器字值的空栈：

```c
#define MAX_ITEMS 10

stack_data_t my_stack_array[MAX_ITEMS];
struct k_stack my_stack;

k_stack_init(&my_stack, my_stack_array, MAX_ITEMS);
```

也可用宏 `K_STACK_DEFINE` 在编译时同时定义栈和数组，效果相同：

```c
K_STACK_DEFINE(my_stack, MAX_ITEMS);
```

## 29.3\_压栈

调用 `k_stack_push()` 加入一个值。下例通过保存若干数据结构的地址，把栈用作对象池的空闲地址集合：

```c
/* define array of data structures */
struct my_buffer_type {
    int field1;
    ...
    };
struct my_buffer_type my_buffers[MAX_ITEMS];

/* save address of each data structure in a stack */
for (int i = 0; i < MAX_ITEMS; i++) {
    k_stack_push(&my_stack, (stack_data_t)&my_buffers[i]);
}
```

## 29.4\_出栈

调用 `k_stack_pop()` 取出一个值。下例取出一个空闲结构地址以便使用。使用结束后，必须把地址再次压回栈，才能让该对象被复用：

```c
struct my_buffer_type *new_buffer;

k_stack_pop(&buffer_stack, (stack_data_t *)&new_buffer, K_FOREVER);
new_buffer->field1 = ...
```

> 译注：前面实例名为 `my_stack`，这里原例却用 `buffer_stack`，完整程序应统一。省略号不构成可编译语句，且实际使用前应检查 pop 返回值。把指针放进机器字容器时，应核对目标类型和转换规则，不要把同一空闲对象重复归还。

## 29.5\_用途、配置与接口

已知最大元素数量、需要按后进先出顺序保存整数值时，可使用该栈。原文末尾配置列表为“无”，但概念段另提到全局 `CONFIG_NO_RUNTIME_CHECKS` 对溢出检查的影响。

完整接口见[Stack APIs](../msgstack_reference/P004_栈公共接口.md)。相关[哲学家就餐示例](../basic_samples/P030_哲学家就餐示例.md#dining-philosophers)使用 Zephyr 内核服务实现经典同步问题。

> 译注——类型与清理边界：当前官方头文件以uintptr_t定义stack_data_t，其宽度跟随目标指针。动态缓冲区清理后的对象不能继续push／pop；cleanup的等待者检查和push的满栈检查受CHECKIF配置控制，默认错误返回与断言／省略检查模式不能混用。详见[栈公共接口](../msgstack_reference/P004_栈公共接口.md)。
