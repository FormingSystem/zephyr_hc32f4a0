# 第17章\_管道

原文：[Pipes](https://docs.zephyrproject.org/latest/kernel/services/data_passing/pipes.html)。读取日期：2026-10-12，`latest`。

**管道（Pipe）**是允许一个线程向另一个线程发送字节流的内核对象。它提供高效线程间通信，可同步传输整个或部分数据块。

## 17.1\_概念

管道数量只受可用内存等资源限制，通过内存地址引用。核心属性是大小，即内部环形缓冲区容量；大小为 0 表示不使用环形缓冲区。使用前必须初始化，初始化后为空。

线程可执行三类操作：

- 写入：同步提交全部或部分数据，已接纳数据直接复制给等待的读线程，或复制进环形缓冲区。缓冲区已满或不存在时，可阻塞到有足够空间或超时。
- 读取：同步取得全部或部分数据，从环形缓冲区复制，或直接从等待的发送线程复制。缓冲区为空或不存在时，可阻塞到有数据或超时。
- 重置：复位内部状态，并让全部未完成读写以错误码结束。

管道适合生产者/消费者模式及线程之间的连续流传输。

## 17.2\_定义管道

用 `struct k_pipe` 对象与字节缓冲区定义管道，再调用 `k_pipe_init()`。下例定义一个空管道，其环形缓冲区容纳 100 字节、按 4 字节边界对齐：

```c
uint8_t __aligned(4) my_ring_buffer[100];
struct k_pipe my_pipe;

k_pipe_init(&my_pipe, my_ring_buffer, sizeof(my_ring_buffer));
```

也可以用 `K_PIPE_DEFINE` 宏在编译时同时定义并初始化管道与缓冲区，效果相同：

```c
K_PIPE_DEFINE(my_pipe, 100, 4);
```

不需要环形缓冲区时，缓冲区指针传 `NULL`，大小传 0。

## 17.3\_写入管道

调用 `k_pipe_write()` 写入数据。下面演示生产者向一个或多个消费者发送数据，并通过累加实际写入字节数处理部分写入。原文描述为缓冲区满时等待指定时间：

```c
struct message_header {
    size_t num_data_bytes; /* Example field */
    ...
};

void producer_thread(void)
{
    int rc;
    uint8_t *data;
    size_t total_size;
    size_t bytes_written;

    while (1) {
        /* Craft message to send in the pipe */
        make_message(data, &total_size);
        bytes_written = 0;

        /* Write data to the pipe, handling partial writes */
        while (bytes_written < total_size) {
            rc = k_pipe_write(&my_pipe, &data[bytes_written], total_size - bytes_written, K_NO_WAIT);

            if (rc < 0) {
                /* Error occurred */
                ...
                break;
            } else {
                /* Partial or full write succeeded; adjust for next iteration */
                bytes_written += rc;
            }
        }

        /* Reset bytes_written for the next message */
        bytes_written = 0;
        ...
    }
}
```

> 译注：实际代码传 `K_NO_WAIT`，因此不会执行正文所说的定时等待。`data` 指针也未初始化，`make_message()` 和错误恢复逻辑尚未定义；这是一段展示调用结构的片段，不是可直接运行的完整程序。应用应提供有效缓冲区，检查错误及实际进度，按需求选择等待时间。

## 17.4\_读取管道

调用 `k_pipe_read()` 读取数据。下面与前例配合，先读消息头，再按头中的长度读取正文；每一步都循环处理部分读取：

```c
struct message_header {
    size_t num_data_bytes; /* Example field */
    ...
};

void consumer_thread(void)
{
    int rc;
    uint8_t buffer[128];
    size_t bytes_read = 0;
    struct message_header *header = (struct message_header *)buffer;

    while (1) {
        /* Step 1: Read the message header */
        bytes_read = 0;
   read_header:
        while (bytes_read < sizeof(*header)) {
            rc = k_pipe_read(&my_pipe, &buffer[bytes_read], sizeof(*header) - bytes_read, &bytes_read, K_NO_WAIT);

            if (rc < 0) {
                /* Error occurred */
                ...
                goto read_header;
            }

            /* Adjust for partial reads */
            bytes_read += rc;
        }

        /* Step 2: Read the message body */
        bytes_read = 0;
        while (bytes_read < header->num_data_bytes) {
            rc = k_pipe_read(&my_pipe, &buffer[sizeof(*header) + bytes_read], header->num_data_bytes - bytes_read, K_NO_WAIT);

            if (rc < 0) {
                /* Error occurred */
                ...
                goto read_header;
            }

            /* Adjust for partial reads */
            bytes_read += rc;
        }
        /* Successfully received the complete message */
    }
}
```

> 译注：原例第一次 `k_pipe_read()` 调用多传了 `&bytes_read`，而后一次使用四参数形式。当前接口为 `k_pipe_read(pipe, data, len, timeout)`，实际读取数量由返回值给出，不能把两种写法混用。
>
> 示例还省略了协议防护：应验证头部长度不超过 `buffer` 剩余容量，处理部分头部/正文失败后的重新同步，并保证把字节缓冲区解释为结构体时的对齐、布局与字节序正确。错误后直接跳回 `read_header` 不一定能恢复消息边界，且原代码在该标签处没有统一重新清零所有读取状态。

## 17.5\_重置管道

`k_pipe_reset()` 重置内部状态，让所有未完成操作以错误码结束。下面在检测到严重错误时复位整个管道：

```c
void monitor_thread(void)
{
    while (1) {
        ...
        /* Critical error detected: reset the entire pipe to reset it. */
        k_pipe_reset(&my_pipe);
        ...
    }
}
```

## 17.6\_用途与接口

管道常用于在线程间发送数据流，包括生产者/消费者、日志或数据包传输，以及实时系统中的变长消息传递。完整接口和错误约定见[Pipe APIs](../mboxpipe_reference/P004_管道公共接口.md)。

> 译注：管道传递的是字节流；消息头和边界由应用协议定义。本文保留当前 `read`/`write` **应用程序编程接口（Application Programming Interface，API）**，旧版 Zephyr 的管道接口可能不同，应按目标版本核对。

> 译注——关闭与重置的源码边界：当前close不清空缓冲区，read仍可返回残留字节；reset不会重新设置打开标志，因此不能用来重新打开已关闭管道。超时可以返回部分进展，重置／写入途中关闭也可能在已有数据交付后返回错误，不能假定负返回值表示没有移动任何数据。详见[管道公共接口](../mboxpipe_reference/P004_管道公共接口.md)。
