# 第60章\_多生产者单消费者包缓冲区

原文：[Multi Producer Single Consumer Packet Buffer](https://docs.zephyrproject.org/latest/kernel/data_structures/mpsc_pbuf.html)。读取日期：2026-10-12，`latest`。

多生产者单消费者包缓冲区（Multi Producer Single Consumer Packet Buffer，MPSC_PBUF）以环形缓冲区按先进先出顺序保存变长数据包。

正常情况下只允许一个上下文消费数据。原文还考虑恐慌情形：另一个上下文介入、冲刷数据后不再返回。

生产分两阶段：先分配所需空间，生产者填入数据后提交。消费也分两阶段：先认领包并取得数据指针与长度，处理完后释放包。这样可以减少内存复制。

## 60.1\_主要性质

生产采用“分配—提交”，消费采用“认领—释放”；分配器保证所需长度的内存连续，支持带超时的分配，并为短包提供优化接口。

空间不足有两种策略：允许覆盖时，逐个丢弃最旧条目，直到能提供所需空间，每丢弃一包调用用户回调；禁止覆盖时，无法提供所需空间便分配失败。

## 60.2\_内部包头与分配

每包带有 MPSC_PBUF 管理头，仅含两个标志位。可将 `MPSC_PBUF_HDR` 放在用户包头起始位置，使首个机器字剩余位继续用于应用字段，降低开销。

`valid` 表示这是有效用户包；`busy` 表示包已认领但尚未释放。

| valid | busy | 状态 |
| ---: | ---: | --- |
| 0 | 0 | 空闲空间。 |
| 1 | 0 | 有效包。 |
| 1 | 1 | 已认领的有效包。 |
| 0 | 1 | 内部跳过包。 |

缓冲区内同时存在空闲空间、有效用户包和内部跳过包。跳过包用于表示填充区域，例如缓冲区末尾不足以容纳一个完整包的空间。

分配器通过成对读写索引计算可用空间。可以分配时，推进临时写索引，返回缓冲区内地址，并复位包头；若写索引需要回绕，则在末尾插入跳过包。无法分配且禁止覆盖时，立即返回 `NULL`，或在指定超时的情况下阻塞等待。

### 60.2.1\_覆盖分配

启用覆盖后，逐个丢弃最旧包，直到空间足够。丢弃前检查 `busy`，保证不覆盖正在消费的包。

遇到忙包时，会在其前加入跳过包，并丢弃忙包之后的其他包。忙包释放时，代码识别这种情形，把该包转成跳过包，避免重复处理。

## 60.3\_使用方法

包头细节见 [include/zephyr/sys/mpsc_packet.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/mpsc_packet.h)，操作接口见 [include/zephyr/sys/mpsc_pbuf.h](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/mpsc_pbuf.h)。分开头文件可以避免仅声明包类型时引入过多依赖。

### 60.3.1\_包头和配置

用户包头必须以内部管理头开始：

```c
#include <zephyr/sys/mpsc_packet.h>

struct foo_header {
        MPSC_PBUF_HDR;
        uint32_t length: 32 - MPSC_PBUF_HDR_BITS;
};
```

配置结构保存底层缓冲区信息、配置标志和回调。丢包通知回调在因覆盖丢弃包时调用；长度回调用于确定包长度。

> 译注：本地 `mpsc_pbuf.h` 的 `get_wlen` 回调、配置的缓冲区大小和 `mpsc_pbuf_alloc()` 长度参数均以 32 位字为单位，不是字节。原文没有明确单位，应用必须与目标版本接口保持一致，并将管理头计入实际包存储需求。

### 60.3.2\_生产包

标准两阶段写入方式为：

```c
foo_packet *packet = mpsc_pbuf_alloc(buffer, len, K_NO_WAIT);

fill_data(packet);

mpsc_pbuf_commit(buffer, packet);
```

> 译注：例中的 `foo_packet`、`buffer` 和 `len` 需由应用定义；调用者必须检查分配返回值是否为 `NULL`，再填写和提交。这里的 `K_NO_WAIT` 表示不等待空间。

优化的短包形式有一个 32 位字，或一个 32 位字加指针。它们按值写入，传入包头必须已经设置 `valid` 位：

```c
mpsc_pbuf_put_word(buffer, data);
mpsc_pbuf_put_word_ext(buffer, data, ptr);
```

### 60.3.3\_消费包

消费同样分两阶段：认领，处理，然后释放：

```c
foo_packet *packet = mpsc_pbuf_claim(buffer);

process(packet);

mpsc_pbuf_free(buffer, packet);
```

> 译注：认领可能因没有可读包而返回 `NULL`，需先检查。认领到的包在释放前由消费者持有，释放后不能继续通过旧指针读取，因为空间可能被重新使用。
