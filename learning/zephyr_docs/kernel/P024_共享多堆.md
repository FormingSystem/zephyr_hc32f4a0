# 第24章\_共享多堆

原文：[Shared Multi Heap](https://docs.zephyrproject.org/latest/kernel/memory_management/shared_multi_heap.html)。读取日期：2026-10-12，`latest`。

**共享多堆内存池管理器（Shared Multi-Heap Manager）**使用多堆分配器，统一管理具有不同能力或属性的保留内存区域，例如可缓存与不可缓存内存。

各区域可在运行时加入共享池，并附带一个不透明属性值，例如整数或枚举。驱动或应用随后可按属性请求具有特定能力的内存。

## 24.1\_初始化并加入内存区域

通常启动时由平台代码调用 `shared_multi_heap_pool_init()` 初始化框架，再调用 `shared_multi_heap_add()` 加入内存区域。地址、大小等信息可从设备树取得。

每个区域由 `struct shared_multi_heap_region` 描述，包含地址、大小及应用定义的整数属性。属性可表达缓存能力、处理器亲和性等。

下面加入两个可缓存区域和一个不可缓存区域：

```c
// Init the shared multi-heap pool
shared_multi_heap_pool_init()

// Fill the struct with the data for cacheable memory
struct shared_multi_heap_region cacheable_r0 = {
     .addr = addr_r0,
     .size = size_r0,
     .attr = SMH_REG_ATTR_CACHEABLE,
};

// Add the region to the pool
shared_multi_heap_add(&cacheable_r0, NULL);

// Add another cacheable region
struct shared_multi_heap_region cacheable_r1 = {
     .addr = addr_r1,
     .size = size_r1,
     .attr = SMH_REG_ATTR_CACHEABLE,
};

shared_multi_heap_add(&cacheable_r1, NULL);

// Add a non-cacheable region
struct shared_multi_heap_region non_cacheable_r2 = {
     .addr = addr_r2,
     .size = size_r2,
     .attr = SMH_REG_ATTR_NON_CACHEABLE,
};

shared_multi_heap_add(&non_cacheable_r2, NULL);
```

> 译注：原例 `shared_multi_heap_pool_init()` 行缺少分号。各 `addr_r*`、`size_r*` 是应用提供的区域参数，不能把示例中的属性标记当作自动修改硬件缓存属性的操作；平台必须先保证实际内存映射与所声明属性一致。

## 24.2\_按属性分配

驱动或应用需要特定能力的动态内存时，调用 `shared_multi_heap_alloc()` 或其对齐版本，将属性作为选择参数。框架结合属性与各堆运行状态，例如可用容量、当前堆状态，选择实际内存区域。

下面分别从可缓存和不可缓存内存请求 4 KB：

```c
// Allocate 4K from cacheable memory
shared_multi_heap_alloc(SMH_REG_ATTR_CACHEABLE, 0x1000);

// Allocate 4K from non-cacheable memory
shared_multi_heap_alloc(SMH_REG_ATTR_NON_CACHEABLE, 0x1000);
```

> 译注：示例仅展示选择参数，实际程序应保存返回指针、检查失败，并按相应接口归还分配块。

## 24.3\_添加属性与接口

接口不强制限制属性集合，但预先定义了两种常见属性：`SMH_REG_ATTR_CACHEABLE`、`SMH_REG_ATTR_NON_CACHEABLE`。其他属性的意义由应用或平台约定。

> 译注——原文概述与当前实现：上述保留指南的概括。本次API和源码还列有外部内存SMH_REG_ATTR_EXTERNAL；当前实现以固定枚举索引数组，并按MAX_SHARED_MULTI_HEAP_ATTR检查上界，不能只传一个新的整数就扩展属性。共享分配、释放和重分配持有自旋锁；区域必须在单一初始化上下文中加入。总后端数仍受一个sys_multi_heap的MAX_MULTI_HEAPS限制，不是每种属性各有8个可同时登记的后端。详见[共享多堆公共接口](../lowheap_reference/P009_共享多堆公共接口.md)。

完整参考见[共享多堆接口](../lowheap_reference/P009_共享多堆公共接口.md)。

> 译注——基础多堆与共享策略：sys_multi_heap的choice回调负责真正分配，包装层不自动轮询后端或添加等待。已有块重分配会先尝试原后端，只有失败后才按cfg选择，因此修改cfg不保证迁移内存属性。基础规则见[多堆包装接口](../lowheap_reference/P002_多堆包装接口.md)；不要将本层行为直接扩大为所有共享多堆策略的保证。
