# 第36章\_精密计时

原文：[Precision Timing](https://docs.zephyrproject.org/latest/kernel/precision_timing.html)。读取日期：2026-10-12，`latest`。

**精密计时（Precision Timing）**子系统为**精确时间协议（Precision Time Protocol，PTP）**、**通用精确时间协议（generalized Precision Time Protocol，gPTP）**等需要控制高分辨率时钟的使用者提供一组可复用机制，通过 `CONFIG_PRECISION_TIMING` 启用。

> 译注：这两种协议用于让联网设备的时钟相互同步；本章子系统提供操作时钟和校正偏差的工具，不代替协议决定与谁同步、何时接受测量结果。

接口当前处于[实验阶段](https://docs.zephyrproject.org/latest/develop/api/api_lifecycle.html#api-lifecycle-experimental)，仍可能变化；一个协议不会仅因为使用该子系统就改变自身成熟度。

本子系统不实现同步策略。协议状态机、时钟选择、直接校时阈值、样本接受、锁定检测、时间源丢失处理及诊断，仍由 PTP、gPTP 自己负责。

## 36.1\_精密时间值

`precision_time_t` 是有符号 64 位纳秒值，带检查的加减辅助函数可报告溢出。该类型本身不标识时间域或时间尺度；国际原子时、协调世界时、PTP 硬件时钟、单调时间及协议之间关系的建模不属于该接口职责。

## 36.2\_精密时钟

`precision_clock` 分派四项必需操作：读取当前时间、设置绝对时间、应用相位调整，以及设置相对标称频率的速率偏移。速率偏移以百万分之一（ppm）为单位，并带 16 位二进制小数字段。

时钟适配器必须实现全部操作。调整范围等硬件限制由底层时钟实现负责。

`precision_clock_ptp_adapter` 将现有 Zephyr PTP 时钟设备接到此接口，并转换 `net_ptp_time` 与 `precision_time_t`。它不增加能力发现或同步状态管理。

## 36.3\_比例积分控制器

`precision_pi` 是按实例管理的比例积分（Proportional-Integral，PI）控制器，每个实例分别保存增益和积分项。每个误差样本的更新等价于：

```c
integral += ki * error;
output = kp * error + integral;
```

控制器不决定误差应被直接校正、拒绝还是用于调整速率，也不追踪同步、捕获、锁定、保持、时间源超时或时钟故障。调用者负责这些策略，并在需要时重置累计积分。

PTP、gPTP 集成通过 `CONFIG_PRECISION_TIMING_PI_KP`、`CONFIG_PRECISION_TIMING_PI_KI` 初始化增益；配置整数以千分之一为单位。直接调用 `precision_pi_init()` 时，可为各实例提供不同增益。

## 36.4\_协议集成与示例

PTP 与 gPTP 默认时钟更新路径保留原有策略，仅通过 `precision_pi` 共享计算。它们初始化一次 PTP 时钟适配器，再通过 `precision_clock` 操作访问硬件时钟。

[精密计时示例](../basic_samples/P043_精确定时示例.md#precision_timing)演示带溢出检查的时间运算、软件实现的精密时钟，以及 PI 驱动的速率调整。原页在时间、时钟和 PI 参考项下重复列出的是同一个示例。
