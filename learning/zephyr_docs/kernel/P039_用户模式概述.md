# 第39章\_用户模式概述

原文：[Overview](https://docs.zephyrproject.org/latest/kernel/usermode/overview.html)。读取日期：2026-10-12，`latest`。

## 39.1\_威胁模型

Zephyr 将**用户模式线程（User Mode Thread）**视为不可信，与其他用户线程及内核隔离。设计目标是让有缺陷或恶意的用户线程无法泄露、修改其他线程或内核的私有数据与资源，也不能干扰或控制它们。

典型用途包括：防止无意编程错误破坏系统；把解释器、网络协议和文件系统等复杂解析逻辑放入受限环境，减少恶意第三方代码或数据影响内核及其他线程；把系统划为多个逻辑应用，每个有自己的线程组与私有数据，一个应用崩溃或被攻破时与其他应用隔离。

### 39.1.1\_保护目标

对非特权处理器状态下运行的线程，系统力求防止访问未授权内存，或以不兼容方式访问，例如写只读区域。栈的访问规则部分取决于硬件：

- 用户线程默认可读写自己的栈。
- 默认不可访问其他内存域用户线程的栈。
- 默认不可访问监督模式线程栈、系统调用提权使用的栈，以及中断或处理器异常栈。
- 同一内存域中的其他用户线程栈是否可访问，取决于架构。原页概述为 **内存保护单元（Memory Protection Unit，MPU）** 上通常只可访问自身栈，**内存管理单元（Memory Management Unit，MMU）** 上可能访问同域用户栈；可移植代码不能依赖后者。

程序正文和只读数据默认对系统所有线程只读可见，这一策略可以调整。除上述默认范围外，用户线程不自动获得其他内存访问权。

内核还按对象或驱动实例控制授权，防止使用未授权内核对象与设备驱动。用户发起的内核/驱动调用须验证对象类型、参数范围及合理性、缓冲区读写权限，以及对象初始化状态，防止错误参数导致内核崩溃或私有结构损坏。

其他目标包括：检测并安全处理用户栈溢出；阻止调用被内核配置排除的系统调用；阻止关闭或篡改内核及硬件内存保护；只允许通过规定系统调用和中断处理入口从用户模式进入监督模式；除内核接口明确支持的方式外，不允许用户线程引入新的可执行代码。

> 译注：概述的栈隔离简写需与[内存保护与内存域](P041_内存保护与内存域.md)中的架构能力和 `CONFIG_MEM_DOMAIN_ISOLATED_STACKS` 配置一起理解，不能仅凭 MPU/MMU 名称推断所有目标行为。

### 39.1.2\_不在保护范围内的情况

内核本身与监督模式线程被视为可信。工具链及构建辅助程序也被信任；生成对象表、系统调用和中断配置等构建逻辑及其处理的 **可执行与可链接格式（Executable and Linkable Format，ELF）** 文件，同样属于可信基础。

内核模式代码若错误配置内存域，把私有内核数据暴露给用户线程，用户模式机制不能补救。内核对象所在 **随机存取存储器（Random Access Memory，RAM）** 应始终保持仅监督模式可直接访问。

顶层声明可以创建用户线程并分配对象权限，因此参与生成 `zephyr.elf` 的 C 源文件与头文件通常均视为可信。

系统不防止通过占用处理器造成拒绝服务：Zephyr 没有线程优先级老化，一个用户线程可使全部低优先级线程饥饿；未启用时间片时，同优先级线程也可能受影响。

同时活动线程数量存在构建期上限，达到后，新用户线程创建会失败。监督模式栈溢出即使被捕获，也不能保证系统完整性。

## 39.2\_高层策略

用户线程通常只能访问自己的栈、程序代码、只读数据以及所属内存域授予的分区。其他 RAM 要么通过系统调用由内核代为访问，要么由监督线程用内存域接口明确授予。新线程继承父线程内存域；线程可通过同域共享内存，或信号量、管道等内核对象通信。

用户线程不能直接访问内核对象内部内存。对象地址用作引用，真正操作经系统调用完成。设备驱动与线程栈也纳入内核对象管理，防止用户篡改对象中的内核私有状态。

默认用户线程只获得自身线程对象权限，其他对象或驱动须被授予。授权者要么处于监督模式，要么同时有目标线程对象和被授予对象的权限。创建线程还可选择继承父线程的对象权限，但不继承父线程对象本身。

Zephyr 为性能与体积，监督模式直接调用通常只做少量或不做参数检查。来自用户模式的系统调用则增加一层处理函数，严格验证对象身份与类型、权限、参数边界及相关内存缓冲区的读写权限。

线程栈按架构要求定义，超过指定栈空间会产生硬件故障，具体方式随架构而异。

## 39.3\_约束

原页写道：供用户模式使用的内核对象、线程栈和设备实例应在构建时定义；动态使用通过预定义对象池满足。

> 译注：这一段包含旧限制。[用户模式内核对象](P040_用户模式内核对象.md)明确说明 `CONFIG_DYNAMIC_OBJECTS` 与 `k_object_alloc()` 可在运行时创建受跟踪对象。因此不能把这里解释为当前版本全面禁止动态对象；未经跟踪的任意内存对象仍不会自动成为合法用户模式对象。

内核启动后再加载额外应用二进制时，还存在以下约束：加载代码中定义的对象不会自动进入内核已生成的对象表，需要使用对象分配接口；由于未参与原内核构建，不能靠其中的静态声明安装中断、实例化驱动或定义系统调用，无论它以哪种模式执行；来源未经验证的加载代码，应在处理器已经处于用户模式时进入。
