# 第65章\_自旋锁公共接口

原文：[group__spinlock__apis](https://docs.zephyrproject.org/latest/doxygen/html/group__spinlock__apis.html)。读取日期：2026-10-13，`latest`。

本页对应自旋锁（Spinlock）应用程序接口（Application Programming Interface，API）分组。声明位于`zephyr/spinlock.h`，锁对象是[`struct k_spinlock`](P066_自旋锁结构参考.md)。概念说明见[自旋锁](P027_自旋锁.md)。

## 65.1\_用宏保护代码块

`K_SPINLOCK(lck)`用给定自旋锁保护代码块，在执行代码块前自动加锁。`lck`是用于保护该代码块的锁。原宏展开式为：

```c
for (k_spinlock_key_t __i K_SPINLOCK_ONEXIT = {}, __key = k_spin_lock(lck); !__i.key;      \
     k_spin_unlock((lck), __key), __i.key = 1)
```

执行到代码块末尾，或通过`K_SPINLOCK_BREAK`离开时，锁都会释放。官方示例：

```c
K_SPINLOCK(&mylock) {

  ...execute statements with the lock held...

  if (some_condition) {
    ...release the lock and leave the guarded section prematurely:
    K_SPINLOCK_BREAK;
  }

  ...execute statements with the lock held...

}
```

示例中的占位文本分别表示“在持锁状态下执行语句”和“释放锁并提前离开受保护区域”。该模式实质上展开为一个循环体恰好执行一次的`for`循环：

```c
for (k_spinlock_key_t key = k_spin_lock(&mylock); ...; k_spin_unlock(&mylock, key)) {
    ...
}
```

**警告：代码块必须执行至末尾，或使用`K_SPINLOCK_BREAK`离开。若通过`break`、`goto`、`return`离开，退出时不会释放自旋锁。**

在用户模式（User Mode）下，自旋锁必须放在应用可访问的内存中；相关宏见原文引用的[`K_APP_DMEM`](../memory_domain_reference/P006_应用内存分区接口.md#ga8fd691f9c9007ec80432c19f7ce84881)和[`K_APP_BMEM`](../memory_domain_reference/P006_应用内存分区接口.md#gace571a7f6ee313a732976cc863b5d0e6)。

## 65.2\_释放后提前退出

`K_SPINLOCK_BREAK`在释放锁之后，离开`K_SPINLOCK`保护的代码块。其原值为：

```c
#define K_SPINLOCK_BREAK continue
```

这与直接写`break`不同；具体用法与限制见上一节。

## 65.3\_不透明的锁键类型

```c
typedef struct z_spinlock_key k_spinlock_key_t;
```

`k_spinlock_key_t`是自旋锁键类型（Spinlock Key Type），保存调用`k_spin_lock`时的系统中断状态（Interrupt State），应传给配对的`k_spin_unlock`。此类型是不透明（Opaque）的，应用不应检查其内部内容。

## 65.4\_加锁与互斥保证

`k_spin_lock`锁定指定自旋锁，可在中断服务程序（Interrupt Service Routine，ISR）中调用，原标记为`isr-ok`：

<a id="gaac60da4347f5b29ff8c4e5f24c99b3bf"></a>

```c
static ALWAYS_INLINE k_spinlock_key_t k_spin_lock(struct k_spinlock *l);
```

参数`l`指向要获取的锁。返回值为解锁时必须交回的键，表示需要恢复的中断状态。

函数返回后，直到调用`k_spin_unlock`之前，调用线程保证不会在当前中央处理器（Central Processing Unit，CPU）上被挂起或中断。实现保证互斥（Mutual Exclusion）：同一时刻只有一个CPU上的一个线程能持锁返回。其他CPU若尝试获取已被占有的锁，就进入由实现定义的忙循环（Busy Loop），即自旋（Spinning），直到锁释放。

不同的自旋锁可以嵌套（Nested）：持有一把锁时，再获取另一把尚未锁定的锁是合法的。但自旋锁**不可递归（Non-recursive）**；试图获取当前CPU已经持有的同一把锁会死锁（Deadlock）。

只有一个CPU时，上述行为保证仍成立，只是没有其他CPU可供自旋等待。单处理器（Uniprocessor）实现可以把锁操作优化为中断屏蔽（Interrupt Mask）操作。

**警告：发生上下文切换（Context Switch）时仍持有自旋锁是非法的。**

## 65.5\_尝试加锁

`k_spin_trylock`只尝试获取锁一次，可在ISR中使用：

```c
static ALWAYS_INLINE int k_spin_trylock(struct k_spinlock *l, k_spinlock_key_t *k);
```

输入参数`l`指向锁；输出参数`k`指向锁键。成功时把键保存到`k`中，返回0；如果另一线程持锁，返回`-EBUSY`。相关接口为`k_spin_lock`和`k_spin_unlock`。

## 65.6\_解锁与嵌套顺序

`k_spin_unlock`释放由`k_spin_lock`获得的锁，可在ISR中使用：

```c
static ALWAYS_INLINE void k_spin_unlock(struct k_spinlock *l,
                                        k_spinlock_key_t key);
```

参数`l`指向待释放锁；`key`必须是获取这把锁时返回的那个值。调用后，任意CPU都能获取该锁。若已有其他CPU正在`k_spin_lock`内自旋等待，则其中恰好一个会同步获得锁并返回。

锁的获取与释放必须正确嵌套。解锁的对象必须是**最近一次**由`k_spin_lock`获取的锁，且使用那次调用返回的键。以下行为均非法：按错误的嵌套顺序解锁、释放未持有的锁、传入非对应获取操作返回的键。

启用`CONFIG_SPIN_VALIDATE`时，校验框架可以检测其中部分错误。完整实现及校验条件见[源码页](P068_自旋锁头文件源码.md)。
