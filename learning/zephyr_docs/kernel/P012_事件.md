# 第12章\_事件

原文：[Events](https://docs.zephyrproject.org/latest/kernel/services/synchronization/events.html)。读取日期：2026-10-12，`latest`。

**事件对象（Event Object）**是实现传统事件机制的内核对象。

## 12.1\_概念

可以定义任意数量的事件对象，仅受可用内存等资源限制，通过内存地址引用。一个或多个线程可以等待同一个事件对象，直到所需事件集合到达。新事件到来时，所有等待条件满足的线程同时进入就绪状态。

事件对象的核心属性是一个 **32 位值**，记录已经到达的事件。使用前必须初始化对象。

线程或**中断服务例程（Interrupt Service Routine，ISR）**都可以交付事件。交付有两种方式：设置（setting）用新集合覆盖已有集合；投递（posting）按位把新事件加入已有集合。两者都可能使多个等待线程同时满足匹配条件，并使它们就绪。

线程可以等待一个或多个事件，既可以要求请求的所有事件都到达，也可以只要求其中任意一个到达。等待请求还可选择在开始等待前重置当前事件集合；多个线程共享同一事件对象时，必须谨慎使用该选项。

内核允许 ISR 查询事件对象，但 ISR 不得等待事件。

> 译注：“同时就绪”不等于在单核处理器上同时执行。实际执行顺序仍由调度器决定；下文带原子移除的等待方式还包含消费事件位的语义，不应仅凭通用概念段推断每个等待者都能独占消费同一事件。

## 12.2\_定义事件对象

用 `struct k_event` 类型定义变量，再调用 `k_event_init()` 初始化：

```c
struct k_event my_event;

k_event_init(&my_event);
```

也可用 `K_EVENT_DEFINE` 宏在编译时定义并初始化，效果相同：

```c
K_EVENT_DEFINE(my_event);
```

## 12.3\_设置与投递事件

调用 `k_event_set()` 设置事件。下面沿用前例，将对象跟踪的事件集合覆盖为 `0x001`，以通知线程数据可用：

```c
void input_available_interrupt_handler(void *arg)
{
    /* notify threads that data is available */

    k_event_set(&my_event, 0x001);

    ...
}
```

调用 `k_event_post()` 投递事件。下面把 `0x120` 所指的事件按位加入当前集合：

```c
void input_available_interrupt_handler(void *arg)
{
    ...

    /* notify threads that more data is available */

    k_event_post(&my_event, 0x120);

    ...
}
```

## 12.4\_等待事件而不移除

调用 `k_event_wait()` 等待任意指定事件。下面最多等待 50 毫秒；若 `0xFFF` 掩码内没有任何事件及时到达，就输出警告：

```c
void consumer_thread(void)
{
    uint32_t  events;

    events = k_event_wait(&my_event, 0xFFF, false, K_MSEC(50));
    if (events == 0) {
        printk("No input devices are available!");
    } else {
        /* Access the desired input device(s) */
        ...
    }
    ...
}
```

如果消费者必须等所有指定事件都到达才继续，则用 `k_event_wait_all()`。下面等待 `0x121` 掩码所指的全部事件：

```c
void consumer_thread(void)
{
    uint32_t  events;

    events = k_event_wait_all(&my_event, 0x121, false, K_MSEC(50));
    if (events == 0) {
        printk("At least one input device is not available!");
    } else {
        /* Access the desired input devices */
        ...
    }
    ...
}
```

上述调用中的 `false` 表示等待前不重置当前集合。成功返回本身也不移除事件位。

## 12.5\_等待并原子移除事件

`k_event_wait_safe()` 在取得事件的同时原子移除已取得的事件位。下面仍最多等待 50 毫秒，等待指定集合中的任意事件，未到达则警告。如果及时取得事件，这些位将从对象中消失，直到下一次 set 或 post 再次设置它们：

```c
void consumer_thread(void)
{
    uint32_t  events;

    events = k_event_wait_safe(&my_event, 0xFFF, false, K_MSEC(50));
    if (events == 0) {
        printk("No input devices are available!");
    } else {
        /* Access the desired input device(s) */
        ...
    }
    ...
}
```

若需要等待全部指定事件，并在收到时原子移除，则使用 `k_event_wait_all_safe()`。成功后，已取得事件同样要等下次 set 或 post 才重新出现：

```c
void consumer_thread(void)
{
    uint32_t  events;

    events = k_event_wait_all_safe(&my_event, 0x121, false, K_MSEC(50));
    if (events == 0) {
        printk("At least one input device is not available!");
    } else {
        /* Access the desired input devices */
        ...
    }
    ...
}
```

> 译注：事件位记录状态，不记录同一位发生了多少次。需要保留每次发生次数或每份数据时，应结合[信号量](P010_信号量.md)或数据队列设计，不能把重复 post 当作自动排队的多条消息。

## 12.6\_用途、配置与接口

事件可表示一组条件已经发生，也可用位集合同时向多个线程传递少量信息。相关 Kconfig 选项为 `CONFIG_EVENTS`。完整声明与返回值见[Event APIs](../eventpoll_reference/P001_事件公共接口.md)。

> 译注——safe与多等待者：当前events.c在一次发布中先用同一事件快照匹配全部等待线程，再统一清除safe等待者收到的位，因此safe不表示只有一个消费者能收到该位。reset=true则在等待前清除整个事件对象；匹配条件、原子消费和等待前复位应分开理解。详见[事件公共接口](../eventpoll_reference/P001_事件公共接口.md)。
