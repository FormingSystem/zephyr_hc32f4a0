# 第19章\_环形缓冲区

原文：[Ring Buffers](https://docs.zephyrproject.org/latest/kernel/data_structures/ring_buffers.html)。读取日期：2026-10-12，`latest`。

**环形缓冲区（Ring Buffer）**按先进先出顺序保存内容。需要异步流式复制数据时，Zephyr 提供 `struct ring_buf`，管理共享内存缓冲区的数据写入与取出。

> 译注：当前官网已经介绍新的 `_ptr`、`_commit`、`_consume` 接口，并将旧 claim/finish 接口列为弃用。旧版仓库的 **应用程序编程接口（Application Programming Interface，API）** 和 Kconfig 含义可能不同，下面按读取时原文完整翻译，不把迁移状态当成本地已实现事实。

## 19.1\_概念与初始化

环形缓冲区数量只受可用内存等资源限制，通过内存地址引用。它包含原始字节缓冲区和以字节为单位的容量；缓冲区存储已写入、尚未取走的数据。使用前初始化，使逻辑内容为空。

`struct ring_buf` 可放在用户可访问内存的任意位置。`ring_buf_init()` 初始化时，须提供应用控制的缓冲区内存。原文提醒：历史不同使用方式可能以字节或机器字表示容量，必须核对所用接口单位。`RING_BUF_DECLARE` 则按指定字节数一次完成静态定义与初始化。

> 译注：本页主体介绍字节流接口，容量按字节计算；不要因历史 item API 的“word”措辞，把本页示例容量自行乘除 4。

`ring_buf_put()` 接收数据指针及字节数，依次复制能容纳的字节，返回实际写入量，可能少于请求量。`ring_buf_get()` 按写入顺序复制到用户缓冲区，也返回实际传输量。

## 19.2\_直接访问与容量管理

为避免多次复制，零复制指针接口允许直接访问内部内存。`ring_buf_put_ptr()` 返回可写区域指针及连续可用大小。跨越缓冲区末尾时，连续大小可能小于总空闲空间。应用可直接写入，例如由**直接内存访问（Direct Memory Access，DMA）**接收；完成后用 `ring_buf_commit()` 提交实际写入量，再开始下一次传输。

相应地，`ring_buf_get_ptr()` 返回内部可读数据指针，无须先复制到另一块内存；处理完后用 `ring_buf_consume()` 告知已消费多少字节，再开始下一次传输。

旧的 `ring_buf_put_claim()` / `ring_buf_put_finish()`、`ring_buf_get_claim()` / `ring_buf_get_finish()` 提供类似功能，但会保留已 claim 的区域直到 finish，增加代码体积与运行成本。原文当前将它们标为弃用，计划在将来版本移除，新代码应使用上述新接口。

`ring_buf_space_get()` 查询空闲字节数，`ring_buf_is_empty()` 判断是否为空，均不修改内容。`ring_buf_reset()` 立即将逻辑缓冲区置空，丢弃已写入字节的跟踪状态，但不会改写实际内存。

## 19.3\_实例的使用步骤

用 `RING_BUF_DECLARE()` 声明实例后，可通过复制接口 `ring_buf_put()` / `ring_buf_get()`，或直接访问接口操作。

直接写入分为三步：

1. `ring_buf_put_ptr()` 获取下一个可写位置和连续空间大小。
2. 应用写入数据，例如启动 DMA。
3. `ring_buf_commit()` 提交实际有效字节数，数量不得超过第一步得到的空间，可以少于它。

直接读取也分为三步：

1. `ring_buf_get_ptr()` 获取下一个可读位置和连续数据大小。
2. 应用处理数据。
3. `ring_buf_consume()` 确认已消费字节数，数量不得超过第一步提供的大小，可以少于它。

## 19.4\_并发

环形缓冲区接口不提供内部并发控制。根据读写者数量，应用可能需要互斥量保护，并用信号量通知消费者已有数据。

单生产者与单消费者运行在不同执行上下文时，例如两个线程，或一个线程加一个中断服务例程，可在不增加锁的情况下并发使用同一环形缓冲区。生产者只更新 put 索引，消费者只更新 get 索引，双方不写同一字段。原文明确说明复制接口及旧的 claim/finish 接口均满足这一规则。

当双方运行在不同处理器，即**对称多处理（Symmetric Multiprocessing，SMP）**场景中，应用仍须保证数据写入在发布它的索引更新之前可见。通常用内核同步原语协调即可获得所需内存屏障，例如生产者 give 一个 `k_sem`，消费者 take 后读数据。

多个并发生产者或多个并发消费者的访问必须由应用串行化，例如通过互斥量或适当禁止抢占。

> 译注：禁止当前线程被抢占并不能阻止其他处理器或 **中断服务例程（Interrupt Service Routine，ISR）** 访问。同步方法必须覆盖实际并发参与者；DMA 的缓存一致性与设备访问顺序也不由环形缓冲区自动处理。新接口的跨核发布要求应结合目标版本头文件核对。

> 译注——2026-10-15源码对照：新增[环形缓冲区参考册](../ringbuffer_reference/大纲.md)，完整保留本次官方公共API、结构、头文件参考和源码浏览。当前官方头文件在SMP且配置最大CPU数大于1时，使用Acquire／Release原子访问发布索引；其他配置使用相应编译器屏障。这比上面指南原文的并发说明更具体，不因此删除原文，也不能推导出多生产者／多消费者互斥或DMA缓存一致性。实际使用以目标版本实现为准。

> 译注——配置与容量：本次官方默认实现全部位于头文件，CONFIG_RING_BUFFER恢复已弃用的claim/finish与item接口；默认最大容量为32767字节，LARGE配置下为1073741823字节。仓库当前仍编译独立ring_buffer.c，布局与配置含义存在版本差异。默认新版ring_buf_get不支持NULL目标来丢弃数据；直接访问的offset、提交／消费以及零容量边界见[API译注](../ringbuffer_reference/P001_环形缓冲区公共接口.md)。

## 19.5\_内部工作方式

数据总是写到下一个字节位置，到末尾后回绕到起点，因此形成“环”。`struct ring_buf` 保存缓冲区指针、大小，以及表示下一次读写位置的头尾索引。

普通 put/get 复制接口隐藏了末尾边界；直接返回连续内存的接口则不能返回跨越末尾的一整段。原文以 claim/finish 为例指出：跨边界传输可能需要两组调用，使应用观察到额外开销。应用应把“连续可用空间”与“总空闲空间”区分开。

## 19.6\_定义环形缓冲区

可定义 `struct ring_buf` 后调用 `ring_buf_init()`，也可在文件作用域用宏一次定义对象和数据缓冲区。下例容量为 93 字节：

```c
#define MY_RING_BUF_BYTES 93
RING_BUF_DECLARE(my_ring_buf, MY_RING_BUF_BYTES);
```

## 19.7\_写入数据

复制写入使用 `ring_buf_put()`，并检查是否只复制了部分数据：

```c
uint8_t my_data[MY_RING_BUF_BYTES];
uint32_t ret;

ret = ring_buf_put(&ring_buf, my_data, MY_RING_BUF_BYTES);
if (ret != MY_RING_BUF_BYTES) {
    /* not enough room, partial copy. */
    ...
}
```

也可直接访问内部空间写入，再提交实际数据量：

```c
uint32_t size;
uint32_t rx_size;
uint8_t *data;

/* Get pointer to writable area within the ring buffer memory. */
size = ring_buf_put_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
rx_size = uart_rx(data, size);

/* Indicate amount of valid data. rx_size must be equal or less than size. */
ring_buf_commit(&ring_buf, rx_size);
```

> 译注：定义段命名为 `my_ring_buf`，后续原例却使用 `ring_buf`，拼接为程序时需统一实例名。这里 `uart_rx(data, size)` 是省略设备与异步完成管理的示意，不是可直接替代 Zephyr **通用异步收发器（Universal Asynchronous Receiver-Transmitter，UART）** 异步 API 的完整调用；真正使用 DMA 或异步 UART 时，应在接收完成后提交实际有效字节，不能仅在启动接收后立即 commit。

## 19.8\_读取数据

`ring_buf_get()` 复制读出字节，返回值可能小于请求量：

```c
uint8_t my_data[MY_DATA_BYTES];
size_t  ret;

ret = ring_buf_get(&ring_buf, my_data, sizeof(my_data));
if (ret != sizeof(my_data)) {
    /* Fewer bytes copied. */
} else {
    /* Requested amount of bytes retrieved. */
    ...
}
```

直接读取则取得内部指针，处理后确认消费量：

```c
uint32_t size;
uint32_t proc_size;
uint8_t *data;

/* Get pointer to readable data within the ring buffer memory. */
size = ring_buf_get_ptr(&ring_buf, &data, 0);

/* Work directly on a ring buffer memory. */
proc_size = process(data, size);

/* Indicate amount of data that has been consumed. proc_size must be equal
 * or less than size.
 */
ring_buf_consume(&ring_buf, proc_size);
```

`process()` 和 `MY_DATA_BYTES` 等由应用提供。消费数量必须不超过本次取得的连续数据大小。

## 19.9\_配置与接口

当前原文列出两个 Kconfig 选项：

- `CONFIG_RING_BUFFER`：恢复已弃用的 claim/finish 和固定大小 item 等旧接口。当前环形缓冲区本体是始终可用的头文件实现，正常新接口使用不要求启用此项。
- `CONFIG_RING_BUFFER_LARGE`：将最大缓冲区大小从 32 KB 提高到 1 GB。

声明与实现位于[`include/zephyr/sys/ring_buffer.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/ring_buffer.h)，完整参考见[Ring Buffer APIs](../ringbuffer_reference/P001_环形缓冲区公共接口.md)。
