# 第47章\_按需分页

原文：[Demand Paging](https://docs.zephyrproject.org/latest/kernel/memory_management/demand_paging.html)。读取日期：2026-10-12，`latest`。

**按需分页（Demand Paging）**只在当前执行上下文需要时，把数据载入物理内存。物理内存从概念上分成页大小的页框，用来容纳数据页。

Zephyr 内核镜像本身始终驻留于物理内存，永远不作为换出候选。按需分页只适用于运行时通过 `k_mem_map()` 创建的匿名映射，以及启用 `CONFIG_LINKER_USE_ONDEMAND_SECTION` 后，通过 `__ondemand_func` / `__ondemand_rodata` 属性显式放进按需加载链接段的内容。

原文将这种安排类比主流操作系统：异常或中断分派路径不放在可分页页面，避免处理缺页本身又发生缺页。把代码或数据放进 `__ondemand_*` 段，是贡献者主动选择使其可分页，同时必须保证缺页处理路径不会访问它。

> 原文说明：旧版 Zephyr 曾使用 `__pinned_*` 属性，仅固定被标记的内核镜像部分，其余部分允许分页。该模型存在安全性和维护问题：**中央处理器（Central Processing Unit，CPU）** 异常分派可能访问已被换出的线程特权栈，在 x86 引起双重故障，或在 ARM64 引起嵌套异常；要求对调度器、驱动、libc、锁等全部缺页处理可达代码逐一标记，也难以建立和长期维护。原文称 `__pinned_*`、`LINKER_USE_PINNED_SECTION`、`LINKER_GENERIC_SECTIONS_PRESENT_AT_BOOT` 和 `K_*_PINNED_STACK_*` 在 Zephyr 4.4 移除，分析见 [GitHub #108773](https://github.com/zephyrproject-rtos/zephyr/issues/108773)。

> 译注：这里保留官网最新模型与版本说明，不据此推断本地不同来源的内核代码已经采用同样实现。

## 47.1\_换入、换出和固定

访问的数据页已经存在于页框中时，处理器继续执行，不发生缺页中断。若不在任何页框中，则产生缺页异常。

有空闲页框时，分页代码从后备存储读入对应数据页。没有空闲页框时，先由淘汰算法选出一个数据页：如果它自换入后被修改，就写回后备存储；未修改，或已完成写回后，原页可视为已换出，释放对应页框。后备存储再把所需数据复制到这个空闲页框，执行继续。

可以显式调用 `k_mem_page_in()` 提前换入预计很快要使用的数据，减少未来缺页次数及延迟；也可用 `k_mem_page_out()` 换出预计较长时间不用的数据，预先释放页框，让后续换入不必临时运行淘汰算法。

`k_mem_pin()` 进一步把区域固定在物理内存中：必要时先换入，再标记页框不可淘汰，保证区域持续驻留、访问不产生因换出导致的缺页。它比单纯换入更强，适用于必须始终可用、对延迟或安全关键的数据。

`k_mem_unpin()` 取消固定，使页框重新可以淘汰；取消固定本身不立即换出。若需要马上换出，可随后调用 `k_mem_page_out()`。

## 47.2\_术语与页框状态

数据页（Data Page）是页大小的数据区域，可以在页框内，也可以存放在后备存储。通过虚拟地址可在 CPU 页表或等效机制中查到其位置。代码类型一般为 `void *`，做指针算术时也使用 `uint8_t *`。

页框（Page Frame）是 **随机存取存储器（Random Access Memory，RAM）** 中页大小的物理内存容器，用物理地址表示。Zephyr 约定以 `uintptr_t` 表示物理地址，为每个页框创建 `struct k_mem_page_frame` 保存元数据。

| 标志 | 含义 |
| --- | --- |
| `K_MEM_PAGE_FRAME_FREE` | 页框未使用且在空闲列表上。此时其他标志都无意义，也不能修改。 |
| `K_MEM_PAGE_FRAME_PINNED` | 固定在内存中，绝不能换出。 |
| `K_MEM_PAGE_FRAME_RESERVED` | 硬件保留的物理页，不应使用。 |
| `K_MEM_PAGE_FRAME_MAPPED` | 已映射到虚拟地址。 |
| `K_MEM_PAGE_FRAME_BUSY` | 正参与换入或换出操作。 |
| `K_MEM_PAGE_FRAME_BACKED` | 后备存储中存在它的干净副本。 |

`K_MEM_SCRATCH_PAGE` 是提供给后备存储使用的特殊临时页虚拟地址：换出时从此页复制到指定后备位置，换入时从后备位置复制到此页。它必须可读写。

数据页本身可能只读；若直接把其原映射交给后备存储写入，就不得不把该映射改成可读写，让应用其他部分也看到可写页，带来安全问题。因此换页使用独立临时映射。

## 47.3\_分页统计

原文的统计入口段将启用条件写为 `CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM_NUM_BINS`，然后列出总体统计 `k_mem_paging_stats_get()`，以及启用 `CONFIG_DEMAND_PAGING_THREAD_STATS` 时的线程统计 `k_mem_paging_thread_stats_get()`。

> 译注：`NUM_BINS` 是直方图桶数整数配置，不是总体统计的布尔开关。读取的[官方 Kconfig.vm](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/Kconfig.vm)定义总体开关为 `CONFIG_DEMAND_PAGING_STATS`；线程统计和时间直方图都依赖它。原页这里的条件不准确。

启用 `CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM` 并定义 `CONFIG_DEMAND_PAGING_TIMING_HISTOGRAM_NUM_BINS` 后，可以取得执行时间直方图。时序高度依赖架构、**片上系统（System on Chip，SoC）** 和开发板，原文强烈建议为具体应用定义 `k_mem_paging_eviction_histogram_bounds[]` 与 `k_mem_paging_backing_store_histogram_bounds[]`，给出各桶边界。

- `k_mem_paging_histogram_eviction_get()`：淘汰算法执行时间直方图。
- `k_mem_paging_histogram_backing_store_page_in_get()`：后备存储换入时间直方图。
- `k_mem_paging_histogram_backing_store_page_out_get()`：后备存储换出时间直方图。

## 47.4\_淘汰算法

淘汰算法选择要换出的数据页及页框，为下次换入腾出空间。内核分页代码调用以下四个接口：

| 接口 | 职责 |
| --- | --- |
| `k_mem_paging_eviction_init()` | 在 `POST_KERNEL` 阶段初始化算法。 |
| `k_mem_paging_eviction_add()` | 数据页开始具有可淘汰资格时加入跟踪。 |
| `k_mem_paging_eviction_remove()` | 数据页失去可淘汰资格时移除，例如被固定、解除映射或即将换出。 |
| `k_mem_paging_eviction_select()` | 选择数据页，返回对应页框指针，并通过 `dirty` 参数说明自换入后是否被修改。若脏标志为真，分页代码要求后备存储写回内容。 |

还有由架构内存管理代码在页面触发访问异常时调用的 `k_mem_paging_eviction_accessed()`；LRU 算法用它把已访问页重新排队。

原文提供两种算法：NRU（Not-Recently-Used，最近未使用）示例算法很简单，依据页面是否被访问和修改进行分级并选择；LRU（Least-Recently-Used，最近最少使用）基于排序的数据页队列，代码更复杂，但原文评价其效率明显更高，并建议生产使用。

实现新算法时，必须提供 `k_mem_paging_eviction_init()` 与 `k_mem_paging_eviction_select()`。若启用 `CONFIG_EVICTION_TRACKING`，还必须实现 `add()`、`remove()`、`accessed()` 这三个对应完整名称的接口。

## 47.5\_后备存储

后备存储负责在页框与存储介质之间换入、换出数据页，必须实现以下接口：

| 接口 | 职责 |
| --- | --- |
| `k_mem_paging_backing_store_init()` | 在 `POST_KERNEL` 阶段初始化后备存储。 |
| `k_mem_paging_backing_store_location_get()` | 为待换出页保留一个存储位置，返回随后交给换出函数的位置令牌。 |
| `k_mem_paging_backing_store_location_free()` | 释放位置令牌，使该位置可供后续换出复用。 |
| `k_mem_paging_backing_store_location_query()` | 查找某段存储内容的位置令牌，用于建立虚拟映射并按需换入，尤其适用于 `CONFIG_DEMAND_MAPPING`。 |
| `k_mem_paging_backing_store_page_in()` | 从令牌对应的后备位置复制一页到 `K_MEM_SCRATCH_PAGE`。 |
| `k_mem_paging_backing_store_page_out()` | 从 `K_MEM_SCRATCH_PAGE` 复制一页到令牌对应的后备位置。 |
| `k_mem_paging_backing_store_page_finalize()` | 换入后更新页框结构中的内部记账信息；允许为空实现。 |
