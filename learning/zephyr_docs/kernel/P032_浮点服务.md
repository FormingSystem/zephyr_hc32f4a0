# 第32章\_浮点服务

原文：[Floating Point Services](https://docs.zephyrproject.org/latest/kernel/services/other/float.html)。读取日期：2026-10-12，`latest`。

在支持**浮点寄存器（Floating-Point Register）**的板级配置上，内核允许线程使用这些寄存器，具体服务随架构而异。

原文开头列出带浮点扩展的 Arm Cortex-M、Intel x86、SPARC、带浮点扩展的 ARCv2，并说明内核不支持 **中断服务例程（Interrupt Service Routine，ISR）** 使用浮点寄存器。

> 译注：这一开头列表及 ISR 总体限制未与后文同步更新：本页后面还说明 Arm64、RISC-V，并明确这两个架构有受限制的 ISR 浮点支持。应以各架构小节为准，不能把例外推广到 Cortex-M 或所有平台。

## 32.1\_模式与运行时管理

内核可按应用需要配置三种浮点模式，并选择是否包含 SSE 寄存器支持。浮点单元简称 FPU（Floating Point Unit），SSE 是 x86 的流式 SIMD 扩展寄存器集合。

线程是否参与浮点上下文保存也可运行时管理。`k_float_enable()` 为线程启用保存，参数可用 `K_FP_REGS`、`K_SSE_REGS` 选择寄存器集合；`k_float_disable()` 再次关闭。不支持此管理的目标返回 `-ENOTSUP`，其他无法执行的无效请求返回 `-EINVAL`。

不使用浮点寄存器模式适用于没有线程用浮点的应用。原文称它是一般默认模式；若线程仍访问浮点寄存器，会触发致命错误并终止线程。具体架构可能有后文说明的不同默认值。

非共享模式适用于只有一个线程使用浮点寄存器。x86 会初始化寄存器使线程可用，Cortex-M 与 ARCv2 跳过该初始化。上下文切换不保存或改变浮点寄存器。若两个以上线程使用，行为未定义；内核不会检测或阻止。

共享模式适用于多个线程使用浮点。架构可能支持三类线程：non-user（不使用浮点寄存器）、FPU user（使用标准浮点寄存器）、SSE user（同时使用标准浮点和 SSE 寄存器）。这里的 user 指浮点使用者，与用户态权限无关。内核在必要时初始化、允许访问并保存/恢复寄存器，使各线程计算互不干扰。

## 32.2\_带浮点扩展的Arm Cortex-M

Cortex-M 默认采用共享浮点寄存器模式。开启共享时，内核把所有线程视为潜在 FPU 使用者，允许访问，并在第一次使用时自动检测。

已知会使用浮点的线程可以提前标记：静态创建时向 `K_THREAD_DEFINE` 传 `K_FP_REGS`，动态创建时向 `k_thread_create()` 传该选项。预标记让基于 **内存保护单元（Memory Protection Unit，MPU）** 的栈保护正确配置保护区大小，以保证栈溢出检测，并在线程创建时启用延迟压栈。

切出曾使用浮点的线程时，内核保存被调用者保存寄存器，调用者保存的浮点寄存器也放到线程栈中。切入曾使用浮点的线程时，恢复相应寄存器和栈中的上下文；未使用浮点的线程不做这些保存恢复。

原文要求每个将使用浮点的线程额外提供 72 字节栈空间，并将其描述为浮点上下文保存空间。Zephyr 在 Cortex-M 上启用[延迟压栈（Lazy Stacking）](https://developer.arm.com/documentation/dai0298/a)，以降低浮点上下文活跃时的中断延迟。

未启用 MPU 栈保护时，延迟压栈始终有效。启用 MPU 栈保护时，预标记 `K_FP_REGS` 的线程默认开启；未预标记者在内核检测到使用浮点后动态开启。

线程不再需要浮点时，可调用 `k_float_disable()`，让内核不再在切换时保存恢复其浮点上下文。

> 译注：72 字节是该原文给出的特定上下文增量，不是整个线程所需栈大小。中断嵌套、函数调用和库函数等仍需另外计入；原文对 caller-saved/callee-saved 保存位置的简述也应与目标架构实现核对。

## 32.3\_Arm64

Arm64 默认采用共享模式。编译器可用浮点/SIMD 寄存器优化代码，`memcpy` 等库函数也可能使用它们，即使应用源码看起来没有浮点运算。

内核按线程实际使用情况处理，采用延迟保存：只在确有必要时更新上下文。例如从 FPU 使用者切到不使用者，再切回原线程，不必保存和恢复寄存器。

ISR 使用浮点或 SIMD 得到支持，但不推荐。访问会触发陷阱，当前 FPU 线程上下文保存到线程对象，然后 ISR 在中断关闭状态下继续，防止另一个中断嵌套使用 FPU。ISR 没有持久寄存器上下文，系统不为它保存单独 FPU 上下文，因此采用此限制。

共享模式使每个线程对象增加 512 字节。

## 32.4\_ARCv2

ARCv2 将线程分为不使用者和 FPU 使用者，必须标记。静态线程向 `K_THREAD_DEFINE` 传 `K_FP_REGS`，动态线程向 `k_thread_create()` 传该选项。

不再需要浮点时，可调用 `k_float_disable()`，停止后续切换中的保存恢复。切出使用者时保存被调用者保存的浮点寄存器，并在栈中保存调用者保存部分；切入使用者时恢复，未使用者不处理浮点上下文。

单精度硬件需额外 16 字节栈空间，双精度需 32 字节。

## 32.5\_RISC-V

RISC-V 按需授予 FPU 使用权，采用延迟保存，只在必要时更新寄存器。例如切出使用者，切到不使用者，或虽然有资格但本次调度期间未访问 FPU 的线程，再切回原使用者，无须保存原上下文。

ISR 浮点/SIMD 使用得到支持但不推荐。使用时触发陷阱，保存当前线程的 FPU 上下文，随后在关闭中断状态下继续 ISR，避免嵌套中断争用；不为 ISR 提供持久 FPU 上下文。

另有优化：若某线程最近一次被切出前修改了 FPU 状态（置脏），则被视为活跃 FPU 使用者。如果其上下文后来因其他线程使用而被保存，再次调入时会提前恢复，避免再次访问时产生陷阱。

若线程本次调度期间未修改 FPU，随后其他线程取得 FPU，则该线程下次仍按需恢复，直到实际访问。这样区分很可能继续使用浮点的线程与暂时不用的线程。

共享模式使每个线程对象增加 136 字节（单精度）或 264 字节（双精度）。

## 32.6\_SPARC

SPARC 分为不使用者和 FPU 使用者，静态或动态创建时分别通过 `K_THREAD_DEFINE`、`k_thread_create()` 的 `K_FP_REGS` 标记。

从中断处理程序退出而进行线程切换时，若切出线程启用了 FPU，则把全部浮点寄存器保存到其栈中。恢复线程时，仅在此前保存过的情况下恢复浮点寄存器。这是同步保存恢复，不采用延迟机制。

进入 ISR 时始终禁用 FPU，与 `CONFIG_FPU_SHARING` 无关。`k_float_disable()` 未实现。

启用 `CONFIG_FPU_SHARING` 时，每个 FPU 使用线程需要额外 136 字节栈；未启用共享时不需这项额外栈空间。

## 32.7\_x86

x86 按实际情况把线程视为不使用者、FPU 使用者或 SSE 使用者，并采用延迟保存；从 FPU 使用者切到不使用者再返回时，不必保存恢复。

原文给出以下额外栈需求：

| 线程类型 | 寄存器使用 | 额外栈空间 |
| --- | --- | ---: |
| 协作线程 | 任意 | 0 字节 |
| 可抢占线程 | 无 | 0 字节 |
| 可抢占线程 | FPU | 108 字节 |
| 可抢占线程 | SSE | 464 字节 |

内核在第一次访问时自动检测并标记。如果构建支持 SSE，就标为 SSE 使用者，否则标为 FPU 使用者。若不希望只用普通浮点的线程被自动标为 SSE，或要避免首次异常处理开销，可预先标记：

- 静态线程向 `K_THREAD_DEFINE` 传 `K_FP_REGS` 或 `K_SSE_REGS`。
- 动态线程向 `k_thread_create()` 传相应选项。
- 已创建线程启动后，可调用 `k_float_enable()` 为自己标记。

不频繁使用浮点的线程可通过 `k_float_disable()` 去掉标记，减少无必要的上下文维护；再次需要时用 `k_float_enable()` 恢复。

## 32.8\_执行浮点运算

内核正确配置后，线程使用浮点算术无需特殊编码。下面用浮点累加一组整数，避免普通整数累加时溢出，再计算平均值：

```c
int average(int *values, int num_values)
{
    double sum;
    int i;

    sum = 0.0;

    for (i = 0; i < num_values; i++) {
        sum += *values;
        values++;
    }

    return (int)((sum / num_values) + 0.5);
}
```

> 译注：示例未处理 `num_values == 0`，对负结果使用 `+0.5` 后截断也不是通用舍入规则。`double` 是否由硬件直接支持取决于目标；只有单精度 FPU 时，双精度运算可能走软件实现。不要把这段示例当作已覆盖所有输入范围的平均值函数。

## 32.9\_用途、配置与接口

应用需要浮点计算时可使用这些服务。非共享模式启用 `CONFIG_FPU`、关闭 `CONFIG_FPU_SHARING`；共享模式同时启用两项，并按架构为各线程留出足够上下文空间。

x86 通过 `CONFIG_X86_SSE` 支持 SSEx 指令。完整声明见[Floating Point APIs](../fatal_irq_reference/P012_浮点上下文接口.md)。
