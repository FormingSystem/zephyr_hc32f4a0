# 第37章\_时间工具

原文：[Time Utilities](https://docs.zephyrproject.org/latest/kernel/timeutil.html)。读取日期：2026-10-12，`latest`。

## 37.1\_概述

Zephyr 运行时间基于 tick 计数。采用默认 `CONFIG_TICKLESS_KERNEL` 时，该计数从系统启动时的 0 开始，按标称恒定速率前进。POSIX 中类似概念是 `CLOCK_MONOTONIC`，或 Linux 的 `CLOCK_MONOTONIC_RAW`。`k_uptime_get()` 将它表示为毫秒。

应用经常需要把内部时间关联到日常使用的外部时间尺度，例如本地时间或协调世界时。这些时间尺度的解释不同，还可能因闰秒、夏令时等本地偏移出现不连续变化。

这种不连续性，加上底层周期计数器时钟本身的误差，使 Zephyr 时钟估计与真实民用时间之间的偏移并非常数，可能随运行时间明显变化。

时间工具提供三类功能：时间表示转换、时间尺度同步与对齐，以及表示值的比较、加法和减法。下面先说明接口，再解释所需时间概念。

## 37.2\_时间表示转换

同一时刻可表示为相对纪元的秒数，例如 `time_t`、`struct timespec`，通常解释为 UNIX 时间；也可表示为年、月、日、时、分、秒组成的日历时间，例如 `struct tm`。UNIX 时间定义参见[RFC 8536 第2节](https://datatracker.ietf.org/doc/html/rfc8536.html#section-2)。

这些只是表示方式，必须结合时间尺度解释；尺度可以是本地时间、UTC，或其他连续/不连续尺度。

C 标准库已提供部分转换，例如 [`gmtime()`](https://pubs.opengroup.org/onlinepubs/9699919799/functions/gmtime.html) 将相对 POSIX 纪元的 `time_t` 秒数转为日历表示。带小数秒的 `timespec` 也可先转换整秒，再单独处理不足一秒部分。

对应的逆转换未以完全对称方式标准化，`mktime()` 等接口涉及时区。Zephyr 通过 `timeutil_timegm()`、`timeutil_timegm64()` 提供相应转换。

`timespec_to_timeout()`、`timespec_from_timeout()` 在 `struct timespec` 与 `k_timeout_t` 时长之间转换：

```c
k_timeout_t to;
struct timespec ts;

timespec_from_timeout(K_FOREVER, &ts);
to = timespec_to_timeout(&ts); /* to == K_FOREVER */

timespec_from_timeout(K_MSEC(100), &ts);
to = timespec_to_timeout(&ts); /* to == K_MSEC(100) */
```

> 译注：示例注释中的 `to == K_FOREVER` 表示语义相等，不是要求对所有版本的 `k_timeout_t` 直接用 C 的 `==`；该类型可能是不透明结构，应使用相应超时比较接口。

完整参考见[时间表示接口](../timeutil_reference/P002_时间表示接口.md)。

## 37.3\_时间尺度同步

同步要处理三类差异：

1. 离散计数的标称速率。例如 Zephyr tick 以 `CONFIG_SYS_CLOCK_TICKS_PER_SEC` Hz 推进，外部源可能给整秒或微秒。
2. 某一时刻两个尺度之间的绝对偏移。
3. 两个尺度实际速率之间的相对误差。用 GPS 每秒脉冲校准的参考时钟通常比误差可达 ±250 ppm 的 RC 振荡器系统时钟准确得多。

对齐过程分为以下步骤：用无符号 64 位整数表示按固定标称速率前进的时刻；`struct timeutil_sync_config` 保存参考尺度与本地尺度的标称速率，例如参考为 TAI、本地为 `k_uptime_ticks()`；`struct timeutil_sync_instant` 记录同一时刻在两种尺度中的表示。

`struct timeutil_sync_state` 保存初始观测、较新的第二次观测，以及修正相对速率误差的 skew。`timeutil_sync_estimate_skew()` 可从两次观测估算偏斜；`timeutil_sync_ref_from_local()`、`timeutil_sync_local_from_ref()` 据此将时刻从一个尺度转换到另一个。

> 译注——源码跟踪：采样更新与偏斜（Skew）估计、应用是不同步骤。当前实现建立首个base时把skew设为1；后续update只记录采样，estimate_skew返回估计值而不写状态，应用需由调用者设置，并受CONFIG_TIMEUTIL_APPLY_SKEW控制。详见[同步接口与版本边界](../timeutil_reference/P003_时间同步接口.md)。

完整参考见[时间同步接口](../timeutil_reference/P003_时间同步接口.md)。

## 37.4\_timespec操作

`timespec_is_valid()` 检查表示是否有效。下面的纳秒字段为负，超出合法范围：

```c
struct timespec ts = {
    .tv_sec = 0,
    .tv_nsec = -1, /* out of range! */
};

if (!timespec_is_valid(&ts)) {
    /* error-handing code */
}
```

部分无效表示可通过 `timespec_normalize()` 规范化：

```c
if (!timespec_normalize(&ts)) {
    /* error-handling code */
}

/* ts should be normalized */
__ASSERT(timespec_is_valid(&ts) == true, "expected normalized timespec");
```

`timespec_equal()` 检查两值是否相等：

```c
if (timespec_equal(then, now)) {
    /* time is up! */
}
```

`timespec_compare()` 对有效值进行全序比较，结果为 -1、0、+1：

```c
int cmp = timespec_compare(a, b);

switch (cmp) {
case 0:
    /* a == b */
    break;
case -1:
    /* a < b */
    break;
case +1:
    /* a > b */
    break;
}
```

`timespec_add()`、`timespec_sub()`、`timespec_negate()` 分别加、减、取负。与 normalize 一样，不溢出时输出规范化值并返回 `true`，发生溢出则返回 `false`：

```c
/* a += b */
if (!timespec_add(&a, &b)) {
    /* overflow */
}

/* a -= b */
if (!timespec_sub(&a, &b)) {
    /* overflow */
}

/* a = -a */
if (!timespec_negate(&a)) {
    /* overflow */
}
```

> 译注——源码跟踪：算术接口的false不统一保证目标对象未修改；需要失败后保留原值时，在临时副本上操作。timespec_to_timeout的rem为请求值减去转换后时长，向上取整后可能为负，且不可与req共用存储。完整前提见[timespec工具](../timeutil_reference/P008_timespec时间工具接口.md)与[时间表示接口](../timeutil_reference/P002_时间表示接口.md)。

完整参考见[timespec 工具接口](../timeutil_reference/P008_timespec时间工具接口.md)。

## 37.5\_时间支持的基本概念

原文参考 [ISO/TC 154/WG 5 N0038 草案](https://www.loc.gov/standards/datetime/iso-tc154-wg5_n0038_iso_wd_8601-1_2016-02-16.pdf)及其他资料使用以下术语：

| 术语 | 含义 |
| --- | --- |
| 时间轴（time axis） | 把时间表示为有序时刻序列。 |
| 时间尺度（time scale） | 相对作为纪元的原点表示时刻的方法。 |
| 单调递增（monotonic） | 后续时刻的表示值不小于此前值。 |
| 连续（continuous） | 相邻时刻间没有突然前跳或后跳。 |
| 民用时间（civil time） | 由民事主管机构规定的时间尺度，通常考虑让当地午夜接近太阳时间。 |

### 37.5.1\_相关时间尺度

国际原子时（International Atomic Time，TAI）基于按 SI 秒计数的原子钟平均结果，是单调、连续的时间尺度。

原文以世界时（Universal Time，UT）概括与地球自转有关的时间，并在同一段将闰秒调整、不连续性及 UTC 联系起来；因此它指出 TAI 与民用使用的世界时之间差值随时间变化，而非固定值。

> 译注：这段原文混用了 UT、UT1 与 UTC。UT1 反映地球自转；UTC 是以原子时为基础、通过闰秒保持接近 UT1 的协调世界时，不能把“靠闰秒调整”泛化为所有 UT 变体的定义。可对照[NIST 对 UTC 与 UT1 的说明](https://www.nist.gov/pml/time-and-frequency-division/time-realization/leap-seconds)。以下保留原文的工程重点：内部连续计时与民用时间转换必须考虑不连续调整。

世界时与地理位置无关。本地标准时间则根据位置和规定，在给定时刻相对世界时采用一定偏移，通常与经度有关，并可能因夏令时改变。因此，本地民用时间又增加一层不连续性。

POSIX 时间自 `1970-01-01T00:00:00Z` 的 POSIX 纪元计秒。UNIX 时间扩展为可用负数表示纪元之前。两者都假定每天恰好 86400 秒；平常映射到 UTC，因此涉及 UTC 调整时会出现不连续性。

原文将连续对应物称为 UNIX Leap Time，即 UNIX 时间加上 POSIX 纪元之后的闰秒修正，并以纪元时 TAI−UTC 为 8 秒的简化约定说明。

### 37.5.2\_不同时间尺度的例子

2016 年底加入一个正闰秒，使 TAI−UTC 从 36 秒变为 37 秒。1999 年底没有闰秒，当时差值为 32 秒。原文对照表如下：

| UTC 日期 | UNIX 时间 | TAI 日期 | TAI−UTC | UNIX Leap Time |
| --- | ---: | --- | ---: | ---: |
| `1970-01-01T00:00:00Z` | 0 | `1970-01-01T00:00:08` | +8 | 0 |
| `1999-12-31T23:59:28Z` | 946684768 | `2000-01-01T00:00:00` | +32 | 946684792 |
| `1999-12-31T23:59:59Z` | 946684799 | `2000-01-01T00:00:31` | +32 | 946684823 |
| `2000-01-01T00:00:00Z` | 946684800 | `2000-01-01T00:00:32` | +32 | 946684824 |
| `2016-12-31T23:59:59Z` | 1483228799 | `2017-01-01T00:00:35` | +36 | 1483228827 |
| `2016-12-31T23:59:60Z` | 未定义 | `2017-01-01T00:00:36` | +36 | 1483228828 |
| `2017-01-01T00:00:00Z` | 1483228800 | `2017-01-01T00:00:37` | +37 | 1483228829 |

> 译注：以上日期和数值是原页示例，尤其 1970 年的整数偏移为其说明约定，不应代替高精度历史时间转换表或外部时间源规范。

## 37.6\_功能需求

Zephyr tick 计数不理解闰秒或本地标准时间偏移，是连续尺度。但它可能不够准确，例如误差 5% 的 RC 定时器每小时可漂移约三分钟。

将它转为人类常用时间，需要两阶段：先把连续但不够准确的 Zephyr 尺度映射到准确稳定的外部尺度，再把稳定尺度映射到可能不连续的民用尺度。

围绕 `timeutil_sync_state_update()` 的接口支持第一阶段。第二阶段需要闰秒表、本地偏移变更计划等外部资料，适合由外部库提供，目前不属于这些时间工具接口。

## 37.7\_选择外部时间源与尺度

若只要求民用时间误差在数秒范围内，可用 UTC 作参考。但外部源调整闰秒时出现不连续：按 1 Hz 采集的相邻两次观测，实际间隔不一定等于其时间戳数值之差。

精密活动更适合不受地方时和太阳时调整影响的连续尺度。原文列出：

- GPS 时间：纪元为 `1980-01-06T00:00:00Z`，连续跟随 TAI，`TAI−GPS=19 s`。
- Bluetooth Mesh 时间：纪元为 `2000-01-01T00:00:00Z`，按原文约定相对 TAI 的偏移为 -32。
- UNIX Leap Time：纪元为 `1970-01-01T00:00:00Z`，按原文约定相对 TAI 的偏移为 -8。

由于 C 与 Zephyr 库支持使用 UNIX 纪元在整数与日历表示之间转换，原文建议把 UNIX Leap Time 作为便利的外部尺度选择。

同步点的采集机制不受此接口限制：可读取本地高精度**实时时钟（Real-Time Clock，RTC）**，通过 NTP/PTP 交换网络报文，或处理 GPS 的 NMEA 消息，可带每秒脉冲，也可不带。

## 37.8\_timespec的表示规则

`struct timespec` 起源于 POSIX，自 C11 起进入 C 标准，其形式为：

```c
struct timespec {
    time_t tv_sec;  /* seconds */
    long   tv_nsec; /* nanoseconds */
};
```

`tv_nsec` 合法范围为 `[0, 999999999]`；`tv_sec` 表示自纪元以来的秒数。若用 `timespec` 表达时间差，秒字段可以为负数。
