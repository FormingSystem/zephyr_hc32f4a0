# 第3章\_系统线程

原文：[System Threads](https://docs.zephyrproject.org/latest/kernel/services/threads/system_threads.html)。读取日期：2026-10-12，`latest`。

**系统线程（System Thread）**是内核在系统初始化时自动创建的线程，包括主线程、空闲线程，以及按配置增加的其他线程。

## 3.1\_主线程

主线程执行内核初始化，随后调用应用提供的 `main()`，如果定义了该函数。

默认采用已配置的最高可抢占优先级，即 `0`。若内核完全不支持可抢占线程，则使用最低协作优先级，即 `-1`。

执行初始化或应用 `main()` 时，主线程属于必要线程，中止它会引发致命系统错误。但若应用没有定义 `main()`，或 `main()` 正常返回，主线程会正常结束，不产生错误。

## 3.2\_空闲线程及其他系统线程

系统没有其他工作时运行空闲线程。如果可以，它会调用板的电源管理支持以节能；否则执行不做实际工作的循环。只要系统运行，它就一直存在，不会正常终止。

空闲线程始终使用配置中的最低线程优先级，也属于必要线程，中止会导致致命错误。

内核和板配置可能创建更多系统线程。例如启用系统工作队列后，会有专门的线程处理提交的工作项，见[官方工作队列说明](https://docs.zephyrproject.org/latest/kernel/services/threads/workqueue.html)。

## 3.3\_编写main函数

应用的 `main()` 在内核初始化完成后执行。默认没有参数；启用 `CONFIG_BOOTARGS` 时内核会传递启动参数，可使用 `main(int, char **)`。

原文给出简单骨架：先初始化信号量，再注册释放该信号量的 **中断服务例程（Interrupt Service Routine，ISR）**，主循环等待信号量并完成后续处理。实际应用可以更复杂。

```c
int main(void)
{
    /* initialize a semaphore */
    ...

    /* register an ISR that gives the semaphore */
    ...

    /* monitor the semaphore forever */
    while (1) {
        /* wait for the semaphore to be given by the ISR */
        ...
        /* do whatever processing is now needed */
        ...
    }
}
```

## 3.4\_推荐用法

应用只需要一个线程时，可直接在主线程执行线程态处理，无须另外创建应用专用线程。
