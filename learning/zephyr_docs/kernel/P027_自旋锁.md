# 第27章\_自旋锁

原文：[Spinlocks](https://docs.zephyrproject.org/latest/kernel/services/synchronization/spinlocks.html)。读取日期：2026-10-12，`latest`。

**自旋锁（Spinlock）**是 Zephyr 最底层的互斥原语，用来保护很短的临界区，保证同一时间只有一个执行上下文访问共享资源。锁已被占用时，请求者忙等，也就是“自旋”，而不是阻塞并让出处理器，因此只适合短临界区。

持锁期间还会屏蔽本地处理器中断，这使它能在线程与中断处理程序之间共享：本地**中断服务例程（Interrupt Service Routine，ISR）**不能抢占持锁者，其他处理器也不能取得同一锁，从而避免观察或破坏更新到一半的数据。`struct k_spinlock` 因此是 Zephyr 内核保护核心数据结构的主要同步原语。

应用也可以直接使用，但通常推荐优先考虑更高层的 `k_mutex`、`k_sem`。

> 译注：这里“屏蔽中断”的范围受架构影响，不能据此认为非屏蔽中断或 Zephyr 零延迟中断也受普通锁中断机制保护。那些上下文必须遵守自身的内核调用与共享数据限制。

## 27.1\_基本用法

每个独立共享资源可配一把 `struct k_spinlock`。`k_spin_lock()` 返回 `k_spinlock_key_t`，解锁时必须将该 key 传回 `k_spin_unlock()`：

```c
static struct k_spinlock lock;

void update_shared_state(void)
{
        k_spinlock_key_t key = k_spin_lock(&lock);

        /* critical section: exclusive access */

        k_spin_unlock(&lock, key);
}
```

`K_SPINLOCK` 辅助宏在代码块期间持锁，在正常离开块时自动释放：

```c
K_SPINLOCK(&lock) {
        /* critical section: exclusive access */
}
```

代码块必须执行到末尾，或用 `K_SPINLOCK_BREAK` 离开。直接使用普通 `break`、`goto`、`return` 会跳过释放，留下未解锁状态：

```c
K_SPINLOCK(&lock) {
        if (nothing_to_do) {
                K_SPINLOCK_BREAK;
        }

        /* critical section: exclusive access */
}
```

## 27.2\_不自旋的尝试加锁

`k_spin_trylock()` 只尝试一次，失败就返回而不忙等，适合调用者有其他工作可做或不能停顿的场合。成功时写出 key，解锁方式与普通加锁相同：

```c
k_spinlock_key_t key;

if (k_spin_trylock(&lock, &key) == 0) {
        /* critical section: exclusive access */
        k_spin_unlock(&lock, key);
} else {
        /* lock is held elsewhere, do something else */
}
```

## 27.3\_使用规则

临界区应尽可能短，因为本地中断被屏蔽，其他处理器可能正在忙等。持有自旋锁时，绝不能执行阻塞或休眠操作。

不得递归取得同一把自旋锁，持锁上下文再次申请会死锁。可以嵌套不同自旋锁，但必须遵循一致的锁顺序，避免互相等待。

## 27.4\_单处理器系统

关闭 `CONFIG_SMP` 时，自旋锁并不真正自旋，因为只有一个处理器，不存在其他处理器竞争。`k_spin_lock()` 简化为屏蔽本地中断，从而防止 ISR 和上下文切换在数据更新中途访问临界状态，满足普通单处理器场景的互斥需要。

## 27.5\_误用校验

`CONFIG_SPIN_VALIDATE` 启用校验层，可检测递归加锁、当前上下文释放自己未持有的锁、未按嵌套顺序解锁（内层仍持有却先释放外层），以及持锁或嵌套 `irq_lock()` 屏蔽中断期间发生上下文切换。

原文说明单处理器上仅递归加锁检查有意义，并以不存在跨处理器竞争、持锁期间屏蔽中断解释其余检查限制。

> 译注：此处是原文对校验实现覆盖范围的描述，不能反向理解为单核应用可以不按顺序解锁、随意使用旧 key，或在临界区调用阻塞函数。前述使用规则在单核上仍需遵守。

## 27.6\_公平自旋锁

默认实现基于一个 `atomic_t` 变量，不保证竞争处理器之间的公平性；某个处理器可能反复获胜，使其他处理器饥饿。

启用 `CONFIG_TICKET_SPINLOCKS` 可切换到票号实现，按请求的先进先出顺序授予锁，代价是锁对象稍大。

## 27.7\_用途与接口

自旋锁适合线程与 ISR 之间、或 **对称多处理（Symmetric Multiprocessing，SMP）** 不同处理器之间共享的短临界区。其他场景可以选择更合适的机制：

- [互斥量](P011_互斥量.md)：临界区较长，或可能阻塞、休眠；只有线程可取得。
- [信号量](P010_信号量.md)：上下文间通知或资源池访问计数。
- [原子操作](P026_原子操作.md)：共享状态是一个机器字且可通过单次原子操作更新，无须额外锁。

完整接口见[Spinlock APIs](P065_自旋锁公共接口.md)。
