# 第50章\_代码与数据重定位

原文：[Code And Data Relocation](https://docs.zephyrproject.org/latest/kernel/code-relocation.html)。读取日期：2026-10-12，`latest`。

**代码与数据重定位（Code and Data Relocation）**功能可把指定文件的 `.text`、`.rodata`、`.data`、`.bss` 段放到指定内存区域。内存区域与文件信息传给 `scripts/build/gen_relocate_app.py`，脚本始终由 CMake 调用。

它可以在不修改源代码的情况下重新安排内存内容，效果类似于批量对一组文件应用 `__attribute__((section("name")))`。还可以用正则表达式只选择需要搬移的段。

## 50.1\_生成过程与基本用法

脚本从输入文件读取规则，每行表示放入指定区域的一组文件。例如：

> 路径说明：原文示意中的用户目录前缀统一写为 `<zephyr-source>`，表示读者实际使用的 Zephyr 源码根目录。这里展示的是生成文件的格式；占位符不是可直接输入的路径，也不是该格式会自动展开的变量。实际生成器按当前工程位置写入所需路径。

```text
SRAM2:<zephyr-source>/samples/hello_world/src/main.c,
SRAM1:<zephyr-source>/samples/hello_world/src/main2.c,
```

原文给出的脚本调用参数为 `python3 gen_relocate_app.py -i input_file -o generated_linker -c generated_code`。在 `prj.conf` 中启用 `CONFIG_CODE_DATA_RELOCATION`，构建系统就会调用脚本完成相应重定位。

脚本生成 `linker_relocate.ld` 和 `code_relocation.c`。前者创建合适的链接段，把全部选中文件中的函数或变量链接到指定位置。

原文说明：主链接脚本中的 text 区域被拆成两部分，前部保存向量表等信息及部分调试相关内容，后部处理其余完整 text 内容。这是为了给生成链接脚本留出正确处理顺序；链接器对输入段只放置一次，必须让需要重定位的函数和数据先进入目标区域。

`code_relocation.c` 保存数据段初始化、XIP 情况下代码复制、BSS 清零以及数据从 **只读存储器（Read-Only Memory，ROM）** 复制到目标内存的代码。

启用步骤是先在 `prj.conf` 打开上述配置，再在工程 `CMakeLists.txt` 指定待重定位文件与目标区域：

```cmake
zephyr_code_relocate(FILES src/main.c LOCATION SRAM2)
```

`FILES` 后给文件列表，`LOCATION` 后给目标内存区域；可以按需要多次调用 `zephyr_code_relocate()`。

> 译注：这里的区域名必须由目标工程的链接布局提供。写上 `SRAM2` 并不会自动为任何开发板创建第二块 SRAM；修改 HC32 布局前还需核对实际地址、容量和启动顺序。

## 50.2\_附加配置

不指定段后缀时，将指定文件的相关内容整体放入所选区域。原文列举的区域名有 `SRAM1`、`SRAM2`、`CCD`、`AON`：

```cmake
zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2)
zephyr_code_relocate(FILES src/file2.c LOCATION SRAM1)
```

在区域名后添加 `_DATA`、`_TEXT`、`_RODATA`、`_BSS` 或 `_NOINIT`，只选择相应段：

```cmake
zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2_DATA)
zephyr_code_relocate(FILES src/file2.c LOCATION SRAM2_TEXT)
```

也可组合后缀，例如 `SRAM2_DATA_BSS_NOINIT`，把有初值数据、零初始化数据和不初始化数据全部放入 `SRAM2`。

`FILES` 支持多个文件，也支持 CMake 生成器表达式提供的文件列表：

```cmake
file(GLOB sources "file*.c")
zephyr_code_relocate(FILES ${sources} LOCATION SRAM2)
zephyr_code_relocate(FILES $<TARGET_PROPERTY:my_tgt,SOURCES> LOCATION SRAM2)
```

## 50.3\_按段筛选

默认重定位指定文件的全部适用段。用 `FILTER` 提供正则表达式，可以只选匹配的段。

正则匹配段名。默认编译选项包含 `-ffunction-sections` 与 `-fdata-sections`，函数和数据分别进入独立段，因此可以借段名选择文件中的具体符号：

```cmake
zephyr_code_relocate(FILES src/file1.c FILTER ".*\\.func1|.*\\.func2" LOCATION SRAM2_TEXT)
```

该例只重定位 `src/file1.c` 中的 `func1()` 与 `func2()`。

## 50.4\_NOKEEP与NOCOPY

默认生成的 `linker_relocate.ld` 用 `KEEP()` 保留全部重定位函数和变量。因此即使链接时使用 `--gc-sections`，输入文件中的未使用符号也不会被丢弃。

传入 `NOKEEP` 可以覆盖该行为，让未使用的段仍可被链接器垃圾回收：

```cmake
zephyr_code_relocate(FILES src/file1.c LOCATION SRAM2_TEXT NOKEEP)
```

上述例子避免 `file1.c` 中未使用的 `.text` 代码仍占据 `SRAM2`。

传入 `NOCOPY` 时，不为该次重定位在 `code_relocation.c` 中生成复制代码。这适合把文件内容放入可原地执行（Execute In Place，XIP）的区域。

下例把 `xip_external_flash.c` 的 `.text` 放到外部 Flash 的 `EXTFLASH` 区域并直接执行；其 `.data` 仍正常复制到 SRAM：

```cmake
zephyr_code_relocate(FILES src/xip_external_flash.c LOCATION EXTFLASH_TEXT NOCOPY)
zephyr_code_relocate(FILES src/xip_external_flash.c LOCATION SRAM_DATA)
```

## 50.5\_重定位库

可以使用 `LIBRARY` 参数和库名重定位整个库。原文示例把串口驱动库放到 SRAM2：

```cmake
zephyr_code_relocate(LIBRARY drivers__serial LOCATION SRAM2)
```

> 译注：原文此处说明句误写 `zephyr_code_relocation()`，示例和实际使用名称为 `zephyr_code_relocate()`。

## 50.6\_注意事项与测试示例

重定位内核或架构文件时要小心，其中可能包含早期初始化代码，在重定位复制发生前就已经执行。目标区域也可能需要额外的**内存保护单元（Memory Protection Unit，MPU）**或**内存管理单元（Memory Management Unit，MMU）**配置，才能允许执行代码。

演示测试位于 `$ZEPHYR_BASE/tests/application_development/code_relocation`。它采用由 `include/zephyr/arch/arm/cortex_m/scripts/linker.ld` 派生的自定义链接文件，把三个文件的 `.text`、`.data` 和 `.bss` 分别放入 SRAM 的不同部分。

`NOCOPY` 的使用见[代码重定位不复制示例](../basic_samples/P013_不复制代码重定位示例.md)。
