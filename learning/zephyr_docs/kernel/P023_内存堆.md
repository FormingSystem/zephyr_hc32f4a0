# 第23章\_内存堆

原文：[Memory Heaps](https://docs.zephyrproject.org/latest/kernel/memory_management/heap.html)。读取日期：2026-10-12，`latest`。

Zephyr 提供一组支持线程动态分配内存的工具，涵盖带同步的**堆（Heap）**、底层堆、多堆包装器与系统堆。

## 23.1\_带同步的堆分配器

`k_heap` 为内存分配提供内核同步，并支持在内存暂时不可用时等待。

### 23.1.1\_创建堆

最简单的方法是用 `K_HEAP_DEFINE` 静态定义。它创建给定名称的 `struct k_heap`，管理指定大小的内存区域。也可用 `k_heap_init()` 管理由应用提供的任意内存区域。

### 23.1.2\_分配内存

`k_heap_alloc()` 接收堆对象地址和所需字节数，类似 C 标准库 `malloc()`，失败返回 `NULL`。

堆支持阻塞分配：线程可休眠等待内存。最后一个 `k_timeout_t` 参数限定可等待的时间，或使用 `K_NO_WAIT` 不等待、`K_FOREVER` 无限等待。

`k_heap_aligned_alloc()` 按调用者指定的 2 的幂对齐值分配，返回地址为该对齐值的整数倍。`k_heap_calloc()` 分配数组并清零。

`k_heap_realloc()` 改变已有分配的大小，保留新旧大小较小者范围内的内容。与 C 标准库 `realloc()` 一样，返回地址可能改变。

### 23.1.3\_释放内存

由 `k_heap_alloc()` 分配的内存用 `k_heap_free()` 归还。传入指针必须是 `NULL` 或来自同一堆的有效分配。释放 `NULL` 没有效果。

> 译注：扩展分配函数返回的块同样须按对应堆 **应用程序编程接口（Application Programming Interface，API）** 释放，不能混用系统堆或其他堆的释放接口。realloc 成功后也不能继续使用被替换的旧地址。

### 23.1.4\_枚举静态堆

`K_HEAP_DEFINE` 定义的堆放在专用链接段中，可运行时枚举。`k_heap_array_get()` 返回静态堆数组地址及条目数，主要用于检查系统所有堆的诊断和测量工具。

## 23.2\_底层堆分配器

`k_heap` 底层由 `struct sys_heap` 实现。它提供相同的分配语义，但没有内核同步设施，适合由应用自行管理内存的场景，例如同步不可用或更复杂的用户空间。

与 `k_heap` 不同，对同一 `sys_heap` 的所有调用都必须由调用者串行化，不能由多个线程同时使用。任意时刻只允许一个执行上下文进入该堆的接口。

### 23.2.1\_内部实现

内部将堆划为 8 字节的 chunk，分配由连续 chunk 组成。每个分配块或空闲块前部有块头，记录长度、物理地址更低的左邻块长度、是否在用，以及空闲链表前后链接的 chunk 索引。

为减少碎片，空闲块按大小放入不同桶：例如 3—4 个 chunk 一桶、5—8 个一桶、9—16 个一桶。这样可从较小、较零碎的可用块中分配。块释放后还会自动与相邻空闲块合并。

管理元数据存放于受管理的连续堆内存中，堆起始处包含随容量变化的桶链表头；除 `sys_heap` 结构本身外，不要求额外外部管理内存。

实现追求高性能及可预测延迟。原文说明 `sys_heap` 接口在常量时间内完成，并给出典型架构上约 1—200 个周期的描述。为避免无限搜索，分配时对最小可能满足请求的桶设置编译时搜索次数上限；代价是稍微降低抵抗碎片的能力。`CONFIG_SYS_HEAP_ALLOC_LOOPS` 控制该上限，默认 3。

> 译注：原文周期数是实现性能描述，不是本项目 HC32 实测或所有操作的硬实时承诺。内存复制、清零、重新分配的搬移成本还与数据大小有关，不能仅凭分配元数据算法的有界搜索推断整个应用调用恒定耗时。

## 23.3\_多堆包装器

`sys_heap` 要求受管理内存是一块连续区域。复杂微控制器系统可能有多段不连续内存，或各区域的缓存、性能、功耗特征不同，外设 **直接内存访问（Direct Memory Access，DMA）** 也可能只能访问其中部分区域。

`sys_multi_heap` 对一个或多个 `sys_heap` 做简单包装。先初始化子堆，再调用 `sys_multi_heap_init()`，随后用 `sys_multi_heap_add_heap()` 加入各堆。没有专门销毁函数；与 `sys_heap` 一样，需要销毁时先确保所有块已释放或至少不会再被访问，再将底层内存改作他用。

`sys_multi_heap_alloc()`、`sys_multi_heap_aligned_alloc()` 与相应底层函数类似，但额外接收不透明配置参数。多堆代码本身不解释这个指针，只传给初始化时提供的应用回调。回调选择一个受管理堆并完成实际分配，可自行解释配置参数。

调整已有块大小时可用 `sys_multi_heap_realloc()` 或 `sys_multi_heap_aligned_realloc()`。如果原堆无法扩展，可转到配置参数允许的其他堆。

不再需要某个分配块时，调用 `sys_multi_heap_free()`，无须再传配置参数。来自任意受管理子堆的内存都用同样方式归还。

> 译注：原文该句写成“free a multi heap”，此处接口释放的是分配块，不是销毁整个多堆管理器；这一点与前面的“没有销毁函数”保持一致。

## 23.4\_系统堆

系统堆是预定义的公共内存分配器，允许线程像使用 `malloc()` 那样动态分配。系统只定义一个系统堆，应用不像普通堆那样通过对象内存地址直接引用它。大小可以配置，但受实际内存容量限制。

`k_malloc()` 返回按指针大小倍数对齐的地址，找不到合适块时返回 `NULL`。使用完成后用 `k_free()` 归还。

### 23.4.1\_设置系统堆容量

Kconfig 选项 `CONFIG_HEAP_MEM_POOL_SIZE` 指定容量。基础默认值为 0，表示不定义该堆池对象。最大值受可用内存限制，设置过大会在链接阶段失败。

板、驱动、库等子系统可以定义带 `HEAP_MEM_POOL_ADD_SIZE_` 前缀的 Kconfig 选项，提出以字节为单位的最低需求。多个需求求和，成为系统堆最小值。应用若设置得更小，会被忽略并采用该最低值。

需要强制使用小于最低需求的值时，可启用 `CONFIG_HEAP_MEM_POOL_IGNORE_MIN`。这适合针对具体应用已经更准确测算需求、正在优化堆容量的情况。

### 23.4.2\_分配内存

下面申请 200 字节，成功后清零，失败则输出警告：

```c
char *mem_ptr;

mem_ptr = k_malloc(200);
if (mem_ptr != NULL)) {
    memset(mem_ptr, 0, 200);
    ...
} else {
    printf("Memory not allocated");
}
```

> 译注：原例 `if (mem_ptr != NULL))` 多了一个右括号，应为 `if (mem_ptr != NULL)`。保留原片段便于对照，不能原样编译。

### 23.4.3\_释放内存

下面申请 75 字节，使用后释放：

```c
char *mem_ptr;

mem_ptr = k_malloc(75);
... /* use memory block */
k_free(mem_ptr);
```

> 译注：省略的使用代码之前应先确认分配成功；`k_free(NULL)` 可无操作，但不能因此跳过对空指针解引用的检查。

## 23.5\_用途、配置与完整接口

堆适合以类似 `malloc()` 的方式动态分配内存。原页末尾列出的相关配置为 `CONFIG_HEAP_MEM_POOL_SIZE`，前文另说明了子系统需求、忽略最低需求和底层搜索次数。

原页提供以下完整参考入口：

- [Heap APIs](../heap_reference/P001_内核堆公共接口.md)：带同步堆与系统堆。
- [Low Level Heap Allocator](../lowheap_reference/P001_底层堆分配接口.md)：底层分配器。
- [Multi-Heap Wrapper](../lowheap_reference/P002_多堆包装接口.md)：多堆包装器。
- [Heap Listener APIs](../lowheap_reference/P003_堆事件监听接口.md)：堆监听器。

> 译注——分配接口与边界：当前系统k_malloc系列在用户地址前附加所属堆记录，必须用k_free归还，不能与普通k_heap_alloc／k_heap_free混用。当前可等待k_heap_realloc对非NULL指针和零大小存在底层已释放而包装继续重试的路径，释放应明确调用k_heap_free。最小容量、额外对齐与NOCACHE配置说明见[内核堆公共接口](../heap_reference/P001_内核堆公共接口.md)。

> 译注——底层与监听边界：底层sys_heap的统计和完整性验证也需要外部同步；未启用CONFIG_SYS_HEAP_VALIDATE时，验证函数直接返回true。多堆地址查询不验证堆末尾边界，不能用来判断任意指针是否合法；监听回调在全局自旋锁内同步执行。详见[底层堆与多堆监听参考册](../lowheap_reference/大纲.md)。
