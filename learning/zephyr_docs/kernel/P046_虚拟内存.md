# 第46章\_虚拟内存

原文：[Virtual Memory](https://docs.zephyrproject.org/latest/kernel/memory_management/virtual_memory.html)。读取日期：2026-10-12，`latest`。

Zephyr 的虚拟内存（Virtual Memory，VM）让开发者细致控制内存访问。平台必须具有**内存管理单元（Memory Management Unit，MMU）**，并在构建中启用它。Zephyr 主要面向嵌入式系统，其虚拟内存支持与传统操作系统略有不同。

未启用按需分页时，内核镜像的代码和数据默认采用物理地址与虚拟地址一一对应的映射。改变这一安排，需要仔细调整链接脚本。

基础虚拟内存支持不使用二级存储扩展可用内存，可用内存上限仍等于物理内存容量。显式启用[按需分页](P047_按需分页.md)，才能把二级存储作为后备存储，使用超过物理内存容量的内存。即使虚拟地址空间比物理内存大，未启用按需分页时，每个有效虚拟映射也必须有物理内存支撑。

## 46.1\_Kconfig配置

内核支持虚拟内存需要启用或定义以下配置：

| 配置 | 含义 |
| --- | --- |
| `CONFIG_MMU` | 必须启用，以支持内核虚拟内存。 |
| `CONFIG_MMU_PAGE_SIZE` | 内存页大小，原文默认值为 4 KB。 |
| `CONFIG_KERNEL_VM_BASE` | 虚拟地址空间基地址。 |
| `CONFIG_KERNEL_VM_SIZE` | 虚拟地址空间大小，原文默认值为 8 MB。 |
| `CONFIG_KERNEL_VM_OFFSET` | 内核镜像相对 `CONFIG_KERNEL_VM_BASE` 的起始偏移。 |

可选的 `CONFIG_KERNEL_DIRECT_MAP` 允许指定物理地址与虚拟地址一一对应的直接映射，而非由内核在虚拟空间内选择地址。它适用于需要更精确访问控制的设备**内存映射输入输出（Memory-Mapped Input/Output，MMIO）**区域。

> 译注：上述默认值来自所读取文档；实际平台可能在 Kconfig 默认值、设备树和链接脚本中进一步约束它们，不能直接作为任意开发板的固定内存布局。

## 46.2\_地址空间布局

下面是虚拟地址空间示意。原文提示相关内部宏的具体含义可能随架构和配置变化：

```text
+--------------+ <- K_MEM_VIRT_RAM_START
| Undefined VM | <- architecture specific reserved area
+--------------+ <- K_MEM_KERNEL_VIRT_START
| Mapping for  |
| main kernel  |
| image        |
|              |
|              |
+--------------+ <- K_MEM_VM_FREE_START
|              |
| Unused,      |
| Available VM |
|              |
|..............| <- grows downward as more mappings are made
| Mapping      |
+--------------+
| Mapping      |
+--------------+
| ...          |
+--------------+
| Mapping      |
+--------------+ <- memory mappings start here
| Reserved     | <- special purpose virtual page(s) of size K_MEM_VM_RESERVED
+--------------+ <- K_MEM_VIRT_RAM_END
```

各边界含义如下：

- `K_MEM_VIRT_RAM_START`：虚拟地址空间起点，必须按页对齐，当前等于 `CONFIG_KERNEL_VM_BASE`。
- `K_MEM_VIRT_RAM_SIZE`：虚拟地址空间大小，必须为页大小的整数倍，当前等于 `CONFIG_KERNEL_VM_SIZE`。
- `K_MEM_VIRT_RAM_END`：`K_MEM_VIRT_RAM_START + K_MEM_VIRT_RAM_SIZE`。
- `K_MEM_KERNEL_VIRT_START`：链接脚本中的 `z_mapped_start`，表示启动时内核镜像的虚拟起始地址。
- `K_MEM_KERNEL_VIRT_END`：链接脚本中的 `z_mapped_end`，表示启动时内核镜像的虚拟结束地址。
- `K_MEM_VM_FREE_START`：可分配给新映射的虚拟空间起点。启用 `CONFIG_ARCH_MAPS_ALL_RAM` 时，全部物理内存已映射，它等于 `DT_CHOSEN_SRAM_ADDR + DT_CHOSEN_SRAM_SIZE`；未启用时，等于内核镜像末尾 `K_MEM_KERNEL_VIRT_END`。
- `K_MEM_VM_RESERVED`：为内核功能保留的区域大小，例如按需分页使用的特殊虚拟页。

图中 `Undefined VM` 是架构保留区，`Mapping for main kernel image` 是主内核镜像映射，`Unused, Available VM` 是尚可使用的虚拟空间。新增映射从保留区之前向图示上方、较低地址方向增长。

## 46.3\_虚拟内存映射

映射包括启动时内核镜像的布局，以及运行时为未使用物理内存建立的匿名映射。

### 46.3.1\_启动映射

多数受支持架构在启动时作以下设置：

- `.text` 只读、可执行，内核模式与用户模式均可访问。
- `.rodata` 只读、不可执行，两种模式均可访问。
- `.data`、`.bss`、`.noinit` 等其他内核段可读写、不可执行，仅内核模式可访问。
- 创建用户线程时，自动授予该线程对自己栈的读写权限。
- 全局变量默认不对用户线程开放；用户线程使用全局变量或相互共享数据的方法见[内存域与分区](P041_内存保护与内存域.md)。

缓存模式依架构而定，可能是不缓存、写回或直写。**片上系统（System on Chip，SoC）** 还可能通过自身配置提供启动必需的额外映射，通常包括硬件初始化所需设备 MMIO 区域。

### 46.3.2\_匿名内存映射

可以按需把未使用的物理内存映射到虚拟地址空间。这类似于从堆分配内存，但要求按页对齐，并提供更细的访问控制。

使用 `k_mem_map()` 时：请求大小必须是页大小的整数倍；返回地址位于 `K_MEM_VM_FREE_START` 与 `K_MEM_VIRT_RAM_END` 之间；映射在物理内存中不保证连续。内核自动在映射虚拟区域前后各安排保护页，用来捕捉缓冲区向前或向后越界访问。

通过 `k_mem_unmap()` 解除映射并释放资源。传给映射与解除映射函数的区域大小必须相同；原文明确警告，解除映射函数不会先检查该区域是不是一个有效映射。
