# 第13章\_条件变量

原文：[Condition Variables](https://docs.zephyrproject.org/latest/kernel/services/synchronization/condvar.html)。读取日期：2026-10-12，`latest`。

**条件变量（Condition Variable）**是一种同步原语，让线程等待某个特定条件出现。

## 13.1\_概念

条件变量数量仅受可用内存等资源限制，每个对象通过内存地址引用。线程可以用它等待条件变为真。

条件变量本质上提供一个等待线程队列。当执行状态，也就是某个条件，不满足要求时，线程把自己放到队列中等待。`k_condvar_wait()` 原子执行两个步骤：释放互斥量，把当前线程加入条件变量队列。

另一个线程改变相关状态后，可用 `k_condvar_signal()` 唤醒一个等待线程，或用 `k_condvar_broadcast()` 唤醒多个等待线程。被唤醒的线程会重新取得之前释放的互斥量，再从 `k_condvar_wait()` 返回。

不论等待因为收到通知、超时还是请求不阻塞而结束，`k_condvar_wait()` 返回时，相关互斥量都已经由调用线程重新锁定。条件变量本身也必须在使用前初始化。

> 译注：原文写“释放最后取得的互斥量”，实际接口显式接收 mutex 参数。应理解为释放传给本次等待调用、且调用线程已经持有的那个互斥量，不是由内核自动查找线程最近操作的任意锁。等待结束后的重新加锁也可能需要等拥有者释放，因此超时参数不应直接理解成整个函数调用的严格墙钟上限。

> 译注——当前源码的立即返回路径：本次官方`condvar.c`对`K_NO_WAIT`直接返回`-EAGAIN`，既不解锁也不重新加锁；它保持调用者原有的持锁状态。真正进入等待的路径返回后才会以`K_FOREVER`重新加锁，包括超时情况。该实现只调用一次解锁，不能用它自动释放递归取得多次的互斥量，详见[条件变量公共接口](../synchronization_reference/P010_条件变量公共接口.md)。

## 13.2\_定义条件变量

用 `struct k_condvar` 类型定义变量，再调用 `k_condvar_init()` 初始化：

```c
struct k_condvar my_condvar;

k_condvar_init(&my_condvar);
```

也可用 `K_CONDVAR_DEFINE` 宏在编译时定义并初始化，效果相同：

```c
K_CONDVAR_DEFINE(my_condvar);
```

## 13.3\_等待条件变量

线程通过 `k_condvar_wait()` 等待。原文示例先取得互斥量，再等待另一个线程发送通知；阻塞期间释放锁，返回前重新取得锁：

```c
K_MUTEX_DEFINE(mutex);
K_CONDVAR_DEFINE(condvar)

int main(void)
{
    k_mutex_lock(&mutex, K_FOREVER);

    /* block this thread until another thread signals cond. While
     * blocked, the mutex is released, then re-acquired before this
     * thread is woken up and the call returns.
     */
    k_condvar_wait(&condvar, &mutex, K_FOREVER);
    ...
    k_mutex_unlock(&mutex);
}
```

> 译注：原例 `K_CONDVAR_DEFINE(condvar)` 行缺少结尾分号，省略号也表示未补全的应用逻辑，不能直接视为完整程序。真实条件保存在应用共享状态中，应在持锁状态下用循环检查该条件，并在不满足时等待；被唤醒后仍要重新检查。条件变量通知本身不会替应用保存“条件为真”的事实。

## 13.4\_发送通知

`k_condvar_signal()` 通知一个线程，`k_condvar_broadcast()` 通知多个等待线程。下面沿用前例，在持锁状态下完成工作并满足条件，然后发出通知并解锁：

```c
void worker_thread(void)
{
    k_mutex_lock(&mutex, K_FOREVER);

    /*
     * Do some work and fulfill the condition
     */
    ...
    ...
    k_condvar_signal(&condvar);
    k_mutex_unlock(&mutex);
}
```

## 13.5\_用途、配置与接口

条件变量与互斥量配合，用于在线程间通知状态或条件变化。条件变量不是条件本身，也不是事件对象；实际条件由外围程序逻辑表达。

互斥量本身用于保证共享资源的互斥访问，不是专门的通知或同步信号机制。

原文相关配置选项列为“无”。完整接口见[Condition Variables APIs](../synchronization_reference/P010_条件变量公共接口.md)。相关[条件变量示例](../basic_samples/P024_条件变量协作示例.md#kernel-condvar)演示在多线程应用中使用条件变量。
