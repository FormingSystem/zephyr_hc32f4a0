## 8.3\_源码定位与版本边界

> 译注——源码核对：这些跟踪钩子（Tracing Hooks）用于记录原API的调用位置，不替代对象操作。tracing_hooks.h通过#ifndef为后端尚未定义的钩子提供空宏；启用对象功能并不自动产生可导出的记录。总跟踪开关、对象开关和所选后端共同决定实际输出。

> 译注——源码核对：入口（Enter）、阻塞（Blocking）和出口（Exit）是源码中的标记名称，不保证所有路径都有成对记录。钩子直接在调用点执行，可能处于自旋锁保护、中断或调度敏感上下文。timeout是请求参数；ret可能是指针、布尔值、字节数或错误码，应以对应API为准。

> 译注——源码核对：k_heap对象接口与系统堆（System Heap）k_malloc／k_free等使用不同钩子前缀。分配出口ret是内存指针，NULL表示未取得内存，不是整数errno。许多分配入口没有bytes或align参数，不能由这些钩子的签名单独重建完整请求。

> 译注——源码核对：alloc_helper_blocking的官方简述仍称“align alloc”，但本次公共辅助函数同时服务普通分配、对齐分配和calloc。它只在首次需要等待时发出blocking，后续重试不重复发出；事件数量不是内存分配重试次数。

> 译注——源码核对：系统堆k_malloc钩子的原简述沿用了“aligned alloc”，本页保留原描述并据宏名区分。mempool.c的系统分配直接进入底层sys_heap操作，不能要求它必然嵌套产生k_heap_alloc跟踪。

> 译注——源码核对：k_heap_free钩子只有堆对象参数，没有被释放的地址。系统k_free则在用户指针之前保存的堆引用处记录heap_ref，随后释放内部块；heap_ref与应用看到的内存指针并非同一地址。k_free(NULL)没有进入该记录分支。
