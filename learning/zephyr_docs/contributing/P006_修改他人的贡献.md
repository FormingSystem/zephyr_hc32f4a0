# 第6章\_修改他人的贡献

原文：[官方页面](https://docs.zephyrproject.org/latest/contribute/modifying_contributions.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

<a id="scenarios"></a>

## 6.1\_适用场景（Scenarios）

Zephyr 鼓励贡献者和协作者参与拉取请求（Pull Request，PR）的审查，使补丁尽可能在原 PR 中得到批准并合入主分支。PR 作者负责根据审查过程修订自己的原始提交。

不过，有时贡献者需要修改其他人提交的 PR 中的补丁。例如：

- 把其他贡献者的提交拣选（cherry-pick）到自己的 PR，以整合停滞 PR 中有用的内容，或把它作为更大补丁的一部分合入主分支。
- 向他人创建的分支或 PR 推送，以帮助更新 PR 并合入补丁，或推动停滞的 PR 完成并合入。

<a id="accepted-policies"></a>

## 6.2\_认可的做法（Accepted Policies）

准备拣选并可能修改他人补丁的开发者，必须在自己的 PR 中解释：为什么选择拣选，而不是帮助补丁通过原 PR 合入；同时邀请原作者参与新 PR 的审查。

准备向其他 Zephyr 贡献者的分支或 PR 强制推送（force-push）的开发者，必须在 PR 中说明推送和修改现有补丁的理由。例如，原作者无法继续时，为使 PR 完成审查而接续处理。

> 原文说明：应尽量把上述做法限制在已确认停滞（stale）的 PR。识别方法见[开发流程与工具](https://docs.zephyrproject.org/latest/project/dev_env_and_tools.html#dev-environment-and-tools)。

如果大幅修改了原补丁，可采用以下一种做法：

1. **优先做法**：联系原作者，请其确认修改后的补丁可以保留原签署行（sign-off line）和作者身份合入。
2. 以自己的工作提交修改后的补丁，使用自己的签署行和作者身份。此时必须在提交说明中指出工作依据的原始来源，例如原 PR 编号。

> 原文说明：如果贡献者不希望其他 Zephyr 开发者在自己的原始分支或 PR 中修订补丁，应取消勾选 “Allow Edits By Maintainers”（允许维护者编辑）。
