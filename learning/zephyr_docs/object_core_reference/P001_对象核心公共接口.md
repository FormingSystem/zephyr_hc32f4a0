### `k_obj_core_link()`

```c
void k_obj_core_link ( struct k_obj_core * obj_core)
```

```c
#include <zephyr/kernel/obj_core.h>
```

将内核对象登记到其对象类型中。

内核对象可以选择登记，以便由k_obj_type_walk_locked()和k_obj_type_walk_unlocked()报告。登记前必须已经用k_obj_core_init()初始化。重复登记已登记的对象，或登记属于该类型永久范围的对象，均无效果。位于当前线程栈或中断栈中的对象不会被登记，而会增加该类型的skipped计数。登记表（Registry）不在对象内部保存引用，因此对象可以不经注销便被丢弃；当其存储空间被复用或登记表已满时，失效登记项会被清除。登记表已满时，不会登记该对象，而会增加该类型的dropped计数。

| 名称／方向 | 说明 |
| --- | --- |
| `obj_core` | 指向内核对象的指针 |

### `k_obj_type_walk_locked()`

```c
int k_obj_type_walk_locked ( struct k_obj_type * type, int(* func )(struct k_obj_core *obj_core, void *data), void * data )
```

```c
#include <zephyr/kernel/obj_core.h>
```

遍历（Walk）一个对象类型的各对象核心。

本函数对该对象类型的每个对象核心调用回调（Callback）：先处理该类型的永久对象，再处理运行时登记的对象。读取每个登记项时获取登记表自旋锁（Spinlock），在调用回调前释放，因此回调可以使用任意内核函数或对象核心函数。若已登记对象的存储空间已被复用，该对象会从登记表中移除，而不被报告。

回调函数应返回非零值以停止后续遍历，或返回0以继续遍历。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `type` | 指向对象类型的指针 |
| `func` | 为该对象类型的每个对象核心调用的回调函数 |
| `data` | 传递给回调的自定义数据 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `non-zero` | 如果遍历被回调终止，则为非零值；否则为0 |

<a id="ga539bed22f047bff5786599bd16187414"></a>

### `k_obj_type_walk_unlocked()`

```c
int k_obj_type_walk_unlocked ( struct k_obj_type * type, int(* func )(struct k_obj_core *obj_core, void *data), void * data )
```

```c
#include <zephyr/kernel/obj_core.h>
```

遍历（Walk）一个对象类型的各对象核心。

本函数类似于k_obj_type_walk_locked()，但读取登记表时不获取自旋锁，因此可用于无法使用该锁的场合。遍历期间登记或注销的对象可能被报告，也可能不被报告；存储空间已被复用的登记对象会被跳过，而不是从登记表移除。

回调函数应返回非零值以停止后续遍历，或返回0以继续遍历。

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |

## 1.5\_源码定位与版本边界

相对源码定位：[对象核心头文件](../../../include/zephyr/kernel/obj_core.h)、[对象核心实现](../../../kernel/obj_core.c)、[内核配置入口](../../../kernel/Kconfig)、[内核构建入口](../../../kernel/CMakeLists.txt)、[对象核心配置](../../../kernel/Kconfig.obj_core)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：对象核心（Object Core）用于按对象类型组织、枚举内核对象并接入统计，不等同于跟踪事件输出。以下源码译注以来源记录中的官方版本摘要为界，与官方正文分开；仓库定位使用相对路径。

> 译注——源码核对：本次实现把永久对象（Permanent Objects）按连续范围原位枚举，把运行时对象存入独立登记表（Registry）；并非在每个对象内部串成对象链表。k_obj_core_init仅关联类型，link才尝试运行时登记，init_and_link组合两步。原文的“链接到列表”应结合当前登记表实现理解。

> 译注——源码核对：运行时登记表容量受CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS控制，本次默认128。当前线程栈及当前CPU中断栈范围内的对象被跳过并增加skipped；表满无法登记时增加dropped。link返回void，调用返回不证明登记成功；这两个计数也不是已登记对象总数。

> 译注——源码核对：walk_locked先走永久范围，再逐项读取动态登记表。锁只覆盖动态项读取与失效项清理，调用业务回调前已释放；unlocked遍历不取该锁，只跳过失效项。两者都不是一份固定时点快照，类型标记检查也不是对象引用计数或内存生命周期保护。

> 译注——源码核对：k_obj_type_init_range当前直接写statics[0]，不自动把每次调用追加为新范围。K_OBJ_TYPE_MAX_RANGES为3，各范围以stride为0终止；需要多范围时应结合源码中的类型初始化方式，不应重复调用此函数并假定前三次分别填入三个槽。

> 译注——源码核对：evict_range按对象核心地址是否落入[addr, addr + len)来删除动态登记项，使用原子比较交换，不取得登记表自旋锁；不是按整个对象与范围有无重叠来判定，也不负责释放对象内存。CONFIG_OBJ_CORE_EVICT_ON_FREE控制释放时主动注销的关联机制。

> 译注——源码核对：K_OBJ_TYPE_ID_GEN把字符串前四个字符移位组合为类型ID，不自动申请唯一编号或检查冲突。K_OBJ_CORE取对象的obj_core成员地址，并不动态验证对象类型；必须使用具有该成员的正确对象。

> 译注——源码核对：本次验证限于官方文档及源码对照，未运行对象并发测试、统计采集或实板验证。
