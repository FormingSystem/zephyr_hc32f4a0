## 4.4\_源码跟踪译注

> 译注——本次实现把永久对象（Permanent Objects）按连续范围原位枚举，把运行时对象存入独立登记表（Registry）；并非在每个对象内部串成对象链表。k_obj_core_init仅关联类型，link才尝试运行时登记，init_and_link组合两步。原文的“链接到列表”应结合当前登记表实现理解。

> 译注——运行时登记表容量受CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS控制，本次默认128。当前线程栈及当前CPU中断栈范围内的对象被跳过并增加skipped；表满无法登记时增加dropped。link返回void，调用返回不证明登记成功；这两个计数也不是已登记对象总数。

> 译注——walk_locked先走永久范围，再逐项读取动态登记表。锁只覆盖动态项读取与失效项清理，调用业务回调前已释放；unlocked遍历不取该锁，只跳过失效项。两者都不是一份固定时点快照，类型标记检查也不是对象引用计数或内存生命周期保护。

> 译注——k_obj_type_init_range当前直接写statics[0]，不自动把每次调用追加为新范围。K_OBJ_TYPE_MAX_RANGES为3，各范围以stride为0终止；需要多范围时应结合源码中的类型初始化方式，不应重复调用此函数并假定前三次分别填入三个槽。

> 译注——evict_range按对象核心地址是否落入[addr, addr + len)来删除动态登记项，使用原子比较交换，不取得登记表自旋锁；不是按整个对象与范围有无重叠来判定，也不负责释放对象内存。CONFIG_OBJ_CORE_EVICT_ON_FREE控制释放时主动注销的关联机制。

> 译注——对象登记与统计登记是两件事。stats_register检查类型的统计描述符及raw_size后保存stats指针，不分配或复制统计缓冲区；deregister清除该指针，不释放调用者内存。官方“自动启用”是接口语义，本次register实现没有调用描述符的enable回调，不能推断注册会执行与显式enable完全相同的后端动作。

> 译注——raw按raw_size检查缓冲区长度，query按query_size检查，要求相等而不是至少足够大；query可由回调生成平均值等报告数据。描述符或对应回调缺失时返回-ENOTSUP，大小错误或对象尚未登记统计时可返回-EINVAL，其余结果由回调返回。

> 译注——统计raw、query、reset、disable、enable在obj_core_lock持锁期间调用对应回调，这与对象walk_locked在回调前解锁不同。统计回调应遵守自旋锁上下文，不能阻塞或递归进入再次获取同一锁的对象核心操作。

> 译注——原文disable说明中包含损坏的:c:func标记，本译文保留其目标k_obj_core_stats_enable并正常呈现函数名称。disable与reset、deregister各有独立职责；停止收集不等于清零或释放统计存储。

> 译注——源码页中部分辅助宏属于官方隐藏文档区，但仍在源码浏览页可见，所以原样保留；接口说明以本册公共与统计参考页为准，不将内部辅助声明自动推广为稳定公共API。
