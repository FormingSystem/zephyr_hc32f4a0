## 7.3\_源码定位与版本边界

相对源码定位：[对象核心头文件](../../../include/zephyr/kernel/obj_core.h)、[对象核心实现](../../../kernel/obj_core.c)、[内核配置入口](../../../kernel/Kconfig)、[内核构建入口](../../../kernel/CMakeLists.txt)、[对象核心配置](../../../kernel/Kconfig.obj_core)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：对象核心（Object Core）用于按对象类型组织、枚举内核对象并接入统计，不等同于跟踪事件输出。以下源码译注以来源记录中的官方版本摘要为界，与官方正文分开；仓库定位使用相对路径。

> 译注——源码核对：运行时登记表容量受CONFIG_OBJ_CORE_MAX_DYNAMIC_OBJECTS控制，本次默认128。当前线程栈及当前CPU中断栈范围内的对象被跳过并增加skipped；表满无法登记时增加dropped。link返回void，调用返回不证明登记成功；这两个计数也不是已登记对象总数。

> 译注——源码核对：walk_locked先走永久范围，再逐项读取动态登记表。锁只覆盖动态项读取与失效项清理，调用业务回调前已释放；unlocked遍历不取该锁，只跳过失效项。两者都不是一份固定时点快照，类型标记检查也不是对象引用计数或内存生命周期保护。

> 译注——源码核对：k_obj_type_init_range当前直接写statics[0]，不自动把每次调用追加为新范围。K_OBJ_TYPE_MAX_RANGES为3，各范围以stride为0终止；需要多范围时应结合源码中的类型初始化方式，不应重复调用此函数并假定前三次分别填入三个槽。

> 译注——源码核对：node串联的是对象类型列表，不是同类型每个对象；obj_core_offset是从对象起始地址到其obj_core成员的字节偏移。统计启用时的额外字段保留在源码条件分支中，不能依照当前网页成员列表硬编码结构体大小。

> 译注——源码核对：本次验证限于官方文档及源码对照，未运行对象并发测试、统计采集或实板验证。
