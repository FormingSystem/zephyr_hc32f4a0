## 1.2\_详细说明（Detailed Documentation）

<a id="gaa49e19bbc39dc0d6f16b78a5d02482c9"></a>

### `DT_ALIAS`

```c
#define DT_ALIAS ( alias)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT(DT_N_ALIAS_, alias)
```

从 `/aliases` 获取节点标识符。

此宏的参数是 `/aliases` 节点的一个属性，返回该别名所引用节点的标识符。将别名属性中的非字母数字字符转换为下划线，并将所有字母转换为小写，以形成有效的 C 标记。

设备树片段示例：

原始示例（Example）：

```dts
/ {
        aliases {
                my-serial = &serial1;
        };

        soc {
                serial1: serial@40001000 {
                        status = "okay";
                        current-speed = <115200>;
                        ...
                };
        };
};
```

可使用 `DT_ALIAS(my_serial)` 获取 `serial@40001000` 节点的标识符。注意，设备树中的 `my-serial` 在 `DT_ALIAS()` 参数中变为 `my_serial`。以下示例结合 `DT_PROP()` 获取 `current-speed` 属性：

原始示例（Example）：

```c
DT_PROP(DT_ALIAS(my_serial), current_speed) // 115200
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `alias` | 使用小写字母和下划线形式的别名。 |

返回（Returns）：具有该别名的节点标识符。

<a id="ga88259608f4e9083ccc2e9ca5ec2c212e"></a>

### `DT_CHILD`

```c
#define DT_CHILD ( node_id, child )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
UTIL_CAT(node_id, DT_S_PREFIX(child))
```

获取子节点的节点标识符。

设备树片段示例：

原始示例（Example）：

```dts
/ {
        soc-label: soc {
                serial1: serial@40001000 {
                        status = "okay";
                        current-speed = <115200>;
                        ...
                };
        };
};
```

以下示例结合 `DT_PROP()` 获取 `serial@40001000` 节点的状态：

原始示例（Example）：

```c
#define SOC_NODE DT_NODELABEL(soc_label)
DT_PROP(DT_CHILD(SOC_NODE, serial_40001000), status) // "okay"
```

不能将 `serial1` 这样的节点标签用作此宏的 `child` 参数；应改用 `DT_NODELABEL()`。

也可使用 `DT_FOREACH_CHILD()` 遍历某节点全部子节点的标识符。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `child` | 使用小写字母和下划线形式的子节点名称。 |

返回（Returns）：名称由 `child` 指定的节点标识符。

<a id="ga3ebb396be1ef1bc6d6ab1414efbf8001"></a>

### `DT_CHILD_BY_UNIT_ADDR_INT`

```c
#define DT_CHILD_BY_UNIT_ADDR_INT ( node_id, addr )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT3(node_id, _CHILD_UNIT_ADDR_INT_, addr)
```

获取单元地址（Unit Address）匹配的子节点标识符。

设备树片段示例：

原始示例（Example）：

```dts
/ {
        soc-label: soc {
                serial1: serial@40001000 {
                        status = "okay";
                        current-speed = <115200>;
                        ...
                };
        };
};
```

以下示例结合 `DT_PROP()` 获取 `serial@40001000` 节点的状态：

原始示例（Example）：

```c
#define SOC_NODE DT_NODELABEL(soc_label)
DT_PROP(DT_CHILD_BY_UNIT_ADDR_INT(SOC_NODE, 1073745920), status) // "okay"
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `addr` | 子节点的整数单元地址。 |

说明（Note）：仅适用于具有唯一整数单元地址的子节点。

返回（Returns）：具有指定单元地址的子节点标识符。

> 译注——源码核对：整数单元地址：生成器将child.unit_addr的整数值写入宏名，示例0x40001000以十进制标记1073745920传入；宏拼接不执行算术，也不会把0x40001000或表达式自动转换为该十进制标记。重复单元地址的子节点不会生成此查询别名。原例soc-label应使用合法节点标签soc_label；节点名和标签的语法不能混用。

### `DT_COMPAT_GET_ANY_STATUS_OKAY`

```c
#define DT_COMPAT_GET_ANY_STATUS_OKAY ( compat)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_HAS_COMPAT_STATUS_OKAY(compat),  \
            (DT_INST(0, compat)),               \
            (DT_INVALID_NODE))
```

获取具有指定兼容字符串且状态为 `okay` 的节点标识符。

当需要任意一个具有指定兼容字符串的已启用节点，且不关心具体选择哪个时，可使用此宏。如果存在这样的节点，则返回其中一个的标识符；否则返回 `DT_INVALID_NODE`。

设备树片段示例：

原始示例（Example）：

```dts
node-a {
   compatible = "vnd,device";
   status = "okay";
};

node-b {
   compatible = "vnd,device";
   status = "okay";
};

node-c {
   compatible = "vnd,device";
   status = "disabled";
};
```

用法示例：

原始示例（Example）：

```c
DT_COMPAT_GET_ANY_STATUS_OKAY(vnd_device)
```

此宏展开为 `node-a` 或 `node-b` 的节点标识符，不会展开为 `node-c`，因为后者状态不是 `okay`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `compat` | 使用小写字母和下划线形式的兼容字符串，不加引号。 |

返回（Returns）：具有该兼容字符串的节点标识符，或 `DT_INVALID_NODE`。

```c
UTIL_CAT(DT_N_INST, DT_DASH(inst, compat))
```

获取某个兼容字符串（Compatible）实例的节点标识符。

具有某一特定 `compatible` 属性值的所有节点都会被分配实例编号（Instance Number）。编号从 0 开始，且针对该兼容字符串独立计算。将实例编号 `inst` 和转换为小写加下划线形式的兼容字符串 `compat` 传给 `DT_INST()`，即可取得这些节点的标识符。

实例编号具有以下性质：

- 对每个兼容字符串，实例编号从 0 开始且连续。
- 具有某兼容字符串的每个节点都会恰好分配一个对应实例编号，包括被禁用的节点。
- 已启用节点，即 `status` 为 `okay` 或缺省的节点，从 0 开始分配编号；禁用节点的编号大于所有已启用节点的编号。

除此之外不作其他保证，特别是：

- 实例编号与 SoC 文档、节点标签、单元地址或 `/aliases` 节点属性中的任何编号方式都没有对应关系；需要按节点标签或别名查找时，应使用 `DT_NODELABEL()` 或 `DT_ALIAS()`。
- 通常不保证同一节点在不同构建中具有相同实例编号，即使是在同一构建目录中再次构建同一应用。

设备树片段示例：

原始示例（Example）：

```dts
serial1: serial@40001000 {
        compatible = "vnd,soc-serial";
        status = "disabled";
        current-speed = <9600>;
        ...
};

serial2: serial@40002000 {
        compatible = "vnd,soc-serial";
        status = "okay";
        current-speed = <57600>;
        ...
};

serial3: serial@40003000 {
        compatible = "vnd,soc-serial";
        current-speed = <115200>;
        ...
};
```

假设设备树中没有其他节点具有 `compatible = "vnd,soc-serial"`，则该兼容字符串对应的节点实例编号为 0、1、2。

`serial@40002000` 和 `serial@40003000` 均已启用，因此实例编号为 0 和 1，但不保证具体哪个节点获得哪个编号。

`serial@40001000` 是唯一被禁用的节点，因此实例编号为 2；禁用节点会获得最大的实例编号。所以：

原始示例（Example）：

```c
// Could be 57600 or 115200. There is no way to be sure:
// either serial@40002000 or serial@40003000 could
// have instance number 0, so this could be the current-speed
// property of either of those nodes.
DT_PROP(DT_INST(0, vnd_soc_serial), current_speed)

// Could be 57600 or 115200, for the same reason.
// If the above expression expands to 57600, then
// this expands to 115200, and vice-versa.
DT_PROP(DT_INST(1, vnd_soc_serial), current_speed)

// 9600, because there is only one disabled node, and
// disabled nodes are "at the end" of the instance
// number "list".
DT_PROP(DT_INST(2, vnd_soc_serial), current_speed)
```

注意，设备树中的 `"vnd,soc-serial"` 在 `DT_INST()` 参数中变为不带引号的 `vnd_soc_serial`。同样，`current-speed` 也变为 `current_speed`。

若节点的 `compatible` 属性包含多个值，则针对每个兼容字符串分别分配独立的实例编号。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `inst` | 兼容字符串 `compat` 对应的实例编号。 |
| `compat` | 使用小写字母和下划线形式的兼容字符串，不加引号。 |

返回（Returns）：具有该实例编号和兼容字符串的节点标识符。

> 译注——源码核对：实例编号与原例注释：DT_INST包含所有匹配节点，已启用节点排在前面，禁用节点在后。原例的三组英文注释依次说明：实例0可能取得57600或115200，无法确定是哪一个已启用串口；实例1也可能为两者之一，但与实例0对应另一个串口；实例2为9600，因为唯一禁用节点排在最后。实例号不能固定解释为硬件UART编号，DT_COMPAT_GET_ANY_STATUS_OKAY也只保证取得任意一个已启用匹配节点。

说明（Note）：此宏根据路径分量返回节点标识符。若要根据节点标识符取得路径字符串，应改用 `DT_NODE_PATH()`。

返回（Returns）：具有该路径的节点标识符。

<a id="gad65aa36621281687b22fa5d72db33e86"></a>

### `DT_ROOT`

```c
#define DT_ROOT DT_N
```

```c
#include <zephyr/devicetree.h>
```

设备树（Devicetree）根节点的节点标识符。

<a id="ga977d0ad58626e3ab906064fdcdace5e6"></a>

### `DT_SAME_NODE`

```c
#define DT_SAME_NODE ( node_id1, node_id2 )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
IS_EQ(DT_DEP_ORD(node_id1), DT_DEP_ORD(node_id2))
```

判断 `node_id1` 和 `node_id2` 是否指向同一节点。

`node_id1` 和 `node_id2` 都必须是设备树中实际存在节点的标识符；不确定时可用 `DT_NODE_EXISTS()` 检查。

展开结果求值为 0 或 1，但不一定是字面整数 0 或 1。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id1` | 第一个节点标识符。 |
| `node_id2` | 第二个节点标识符。 |

返回（Returns）：若两个节点标识符指向同一节点，则表达式求值为 1，否则为 0。

## 1.3\_源码定位与版本边界

本册收录节点标识、存在性／状态和厂商／型号三组宏。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：四种名称：节点标识是预处理器标记，不是运行时指针。DT_PATH按路径节点名逐级查找，DT_NODELABEL按冒号前标签查找，DT_ALIAS按/aliases属性查找，label属性只是普通属性值。DT_NODE_PATH返回设备树内部路径字符串，其中/soc等不是宿主文件系统绝对地址。DT_INVALID_NODE是无效标识哨兵，不是NULL，也不能拿它任意读取属性。

> 译注——源码核对：名称输出形态：FULL_NAME返回字符串，TOKEN将特殊字符转为下划线，UNQUOTED保留名称中的标点形成标记序列，不保证是单个合法C标识符。C_TOKEN_BY_IDX返回指定节点的第idx个标签原始拼写；该idx不是phandles属性索引，也不是节点实例编号。原文参数简写“node_id中的索引”应按标签列表理解。

> 译注——源码核对：子节点与后代：CHILD_NUM统计直接子节点；DESCENDANT_NUM_ON_BUS跨过普通容器向下遍历，但在自身提供总线的子节点处停止继续递归，避免统计子总线后面的设备。生成值依据解析后的on_bus，bus参数实际传i2c、spi等标记，不是带引号的字符串。生成器只为已识别的相关总线控制器／总线类型输出这些计数，不能假设任意节点与bus组合都有默认0。

> 译注——源码核对：哈希与相等：本次edtlib对完整节点路径进行SHA-256计算，再用调整字符表的Base64编码并去掉填充，输出预处理标记；它不是C整数或自动加引号的字符串，也不是芯片唯一ID。改路径会改哈希。DT_SAME_NODE比较当前生成结果中的依赖序号，两边须是存在的节点；不能拿该比较替代节点存在性检查。

> 译注——源码核对：启用与运行状态：节点存在、status为okay和运行时设备初始化成功是不同条件。查询标签、别名或实例不会使能外设；状态缺省按okay处理，不能从宏查询成功推断硬件连线、驱动构建和设备就绪均已确认。

> 译注——源码核对：版本与验证：本次官方devicetree.h、gen_defines.py和edtlib.py分别登记摘要，源码对照不代表滚动main与本仓库参照基线完全相同。原始代码、字符串和许可证保留；本批未编译宏／DTS示例、构建固件或操作硬件。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
