## 3.2\_详细说明（Detailed Documentation）

<a id="gae4bbd66726d930d878588f9bb9f4d500"></a>

### `DT_NODE_MODEL_BY_IDX`

```c
#define DT_NODE_MODEL_BY_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT3(node_id, _COMPAT_MODEL_IDX_, idx)
```

以字符串字面量形式获取索引 `idx` 处的型号（Model）。

型号是从兼容字符串的厂商前缀之后提取的字符串。

`vendor-prefixes.txt` 示例：

原始示例（Example）：

```text
 vnd        A stand-in for a real vendor
 zephyr     Zephyr-specific binding
```

设备树片段示例：

原始示例（Example）：

```dts
 n1: node-1 {
    compatible = "vnd,model1", "gpio", "zephyr,model2";
 };
```

用法示例：

原始示例（Example）：

```c
 DT_NODE_MODEL_BY_IDX(DT_NODELABEL(n1), 0) // "model1"
 DT_NODE_MODEL_BY_IDX(DT_NODELABEL(n1), 2) // "model2"
```

注意，索引 1 处的兼容字符串不匹配厂商前缀文件中的任何条目，因此索引 1 不是有效的型号索引。可用 `DT_NODE_MODEL_HAS_IDX(node_id, idx)` 判断索引是否有效。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | 要获取型号的索引。 |

返回（Returns）：第 `idx` 个型号的字符串字面量。

<a id="ga98a2ff981359088e2e995017791176b1"></a>

### `DT_NODE_MODEL_BY_IDX_OR`

```c
#define DT_NODE_MODEL_BY_IDX_OR ( node_id, idx, default_value )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_NODE_MODEL_HAS_IDX(node_id, idx), \
            (DT_NODE_MODEL_BY_IDX(node_id, idx)), (default_value))
```

类似于 `DT_NODE_MODEL_BY_IDX()`，但提供回退到 `default_value` 的能力。

若值存在，则展开为 `DT_NODE_MODEL_BY_IDX(node_id, idx)`，此时不会展开 `default_value` 参数。

否则，展开为 `default_value`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | 要获取型号的索引。 |

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `default_value` | 要展开成的回退值。 |

返回（Returns）：第 `idx` 个型号的字符串字面量。

返回（Returns）：第 `idx` 个型号的字符串字面量，或 `default_value`。

<a id="ga2ff3c91b22fae081d00d96964f465aa2"></a>

### `DT_NODE_MODEL_HAS_IDX`

```c
#define DT_NODE_MODEL_HAS_IDX ( node_id, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
IS_ENABLED(DT_CAT4(node_id, _COMPAT_MODEL_IDX_, idx, _EXISTS))
```

判断节点的 `compatible` 属性在指定索引处是否具有型号信息。

若返回 1，则 `DT_NODE_MODEL_BY_IDX(node_id, idx)` 有效。若返回 0，则用索引 `idx` 调用 `DT_NODE_MODEL_BY_IDX(node_id, idx)` 会出错。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `idx` | 要检查的型号索引。 |

返回（Returns）：若 `idx` 是有效的型号索引则为 1，否则为 0。

## 3.3\_源码定位与版本边界

本册收录节点标识、存在性／状态和厂商／型号三组宏。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：来源与索引：厂商值来自vendor-prefixes.txt中匹配前缀的说明文字，型号值来自compatible逗号后的部分。索引对应原compatible列表位置，不会跳过无厂商项后重新编号；示例索引1为gpio，没有有效厂商／型号字段。它们是构建时元数据，不读取芯片ID寄存器，也不保证与产品宣传型号一致。

> 译注——源码核对：原始前缀表译文：vnd对应的A stand-in for a real vendor意为“实际厂商的占位名称”；zephyr对应的Zephyr-specific binding意为“Zephyr专用绑定”。这些原字符串作为代码输出保留英文，中文含义在此对照，不修改宏实际返回值。

> 译注——源码核对：默认值：_OR通过COND_CODE_1在预处理期选择分支；default_value是调用者提供的标记，不会自动加双引号。需要字符串时应传字符串字面量或能展开成字符串的宏。原返回说明把default_value放在引号内，只是指参数，不意味着宏返回字面文本default_value。

> 译注——源码核对：第0项约定：DT_NODE_VENDOR_OR和DT_NODE_MODEL_OR固定选择索引0并提供回退，不要求compatible列表只有一项，也不自动搜索后续第一个有效厂商或型号。调用不带_OR的BY_IDX前先使用相应HAS_IDX核对。

> 译注——源码核对：版本与验证：本次官方devicetree.h、gen_defines.py和edtlib.py分别登记摘要，源码对照不代表滚动main与本仓库参照基线完全相同。原始代码、字符串和许可证保留；本批未编译宏／DTS示例、构建固件或操作硬件。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
