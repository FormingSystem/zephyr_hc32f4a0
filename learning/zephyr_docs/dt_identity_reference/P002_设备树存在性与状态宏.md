## 2.2\_详细说明（Detailed Documentation）

### `DT_BINDING_COMPAT_TOKEN`

```c
#define DT_BINDING_COMPAT_TOKEN ( node_id)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT(node_id, _BINDING_COMPAT_TOKEN)
```

以标记形式获取节点所匹配绑定的兼容字符串。

展开为与节点绑定匹配的兼容字符串的标记形式，特殊字符替换为下划线。可用于在编译期通过标记拼接（Token Pasting）分派到按兼容字符串命名的符号。

例如，假设 GPIO 控制器节点匹配 `"atmel,sam0-gpio"`：

原始示例（Example）：

```c
DT_BINDING_COMPAT_TOKEN(DT_NODELABEL(gpio0))  // expands to: atmel_sam0_gpio
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |

返回（Returns）：绑定的兼容字符串，形式为 C 标记。

### `DT_FOREACH_PHA_CELL_BY_IDX`

```c
#define DT_FOREACH_PHA_CELL_BY_IDX ( node_id, pha, idx, fn )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT6(node_id, _P_, pha, _IDX_, idx, _FOREACH_CELL)(fn)
```

按索引遍历句柄数组元素中的全部单元。

此宏对索引 `idx` 处句柄数组元素中的每个单元值调用 `fn(cell_value)`。

一般情况下，此宏展开为：

原始示例（Example）：

```c
fn(node_id, pha, idx, cell[0]) fn(node_id, pha, idx, cell[1]) [...]
fn(node_id, pha, idx, cell[n-1])
```

其中，`n` 是 `pha` 中的单元数量，即 `DT_PHA_NUM_CELLS_BY_IDX(node_id, pha, idx)` 的返回值；`cell[x]` 是描述符中的单元名称。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `pha` | 类型为 `phandle-array` 的属性名，使用小写字母和下划线形式。 |
| `idx` | 句柄数组元素的索引。 |
| `fn` | 对每个单元值调用的宏。 |

> 译注——源码核对：遍历回调实参：原文写fn(cell_value)，但同页展开式和生成器实际传四个参数。BY_IDX为fn(node_id, pha, idx, cell_name)，BY_NAME为fn(node_id, pha, name, cell_name)，传入的是单元名称，不是单元数值。需要数值时，在辅助宏内调用DT_PHA_BY_IDX或DT_PHA_BY_NAME。原文按名称展开示意的后两处idx也应按name理解；保留原示意并就地说明。

### `DT_HAS_CLASS_STATUS_OKAY`

```c
#define DT_HAS_CLASS_STATUS_OKAY ( _class)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：


判断设备树是否具有属于某设备类别（Device Class）且状态为 `okay` 的节点。

若节点的绑定或其包含的绑定通过 `class:` 键声明某设备类别，则节点属于该类别。当且仅当至少一个已启用节点属于该类别时，此判断为真。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_class` | 使用小写字母和下划线形式的设备类别名称。 |

返回（Returns）：若有已启用节点属于该设备类别则为 1，否则为 0。

### `DT_HAS_COMPAT_STATUS_OKAY`

```c
#define DT_HAS_COMPAT_STATUS_OKAY ( compat)
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
IS_ENABLED(DT_CAT(DT_COMPAT_HAS_OKAY_, compat))
```

判断设备树是否具有指定兼容字符串且状态为 `okay` 的节点。

检查设备树中是否存在状态为 `okay` 且具有指定兼容字符串的节点。也就是说，当且仅当至少存在一个 `node_id`，使以下两个表达式都返回 1 时，返回 1：

原始示例（Example）：

```c
DT_NODE_HAS_STATUS(node_id, okay)
DT_NODE_HAS_COMPAT(node_id, compat)
```

与通常规则一样，缺省 `status` 或状态值为 `ok` 都视为 `okay`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `compat` | 使用小写字母和下划线形式的兼容字符串，不加引号。 |

返回（Returns）：若上述两个条件均满足则为 1，否则为 0。

## 2.3\_源码定位与版本边界

本册收录节点标识、存在性／状态和厂商／型号三组宏。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：检查层次：NODE_EXISTS只判断节点是否存在；HAS_COMPAT检查compatible列表；HAS_CLASS检查绑定声明的设备类别；HAS_STATUS检查设备树状态。这些结果不能代替驱动是否编译或设备运行时就绪。带STATUS_OKAY的全局查询与计数才筛选已启用节点，缺省status与ok按okay处理。

> 译注——源码核对：绑定兼容字符串：DT_BINDING_COMPAT系列输出实际匹配绑定的那个兼容字符串，区别于compatible列表中的全部值，也不保证是列表第一个值。生成器仅在matching_compat存在时输出这组宏；先确认绑定匹配。TOKEN和UPPER_TOKEN用于标记拼接，UNQUOTED保留逗号等字符，嵌入其他宏时仍须考虑参数解析规则。原例expands to意为“展开为”。

> 译注——源码核对：单元计数与分隔符：NUM_CELLS是指定一个句柄数组元素携带的数据单元数量，不包括控制器phandle，也不是整个属性的元素数。SEP通过生成器在相邻调用之间插入分隔符，末尾不额外添加；逗号或分号须按实现传成(,)或(;)以供DT_DEBRACKET_INTERNAL解包。

> 译注——源码核对：按名查询前提：BY_NAME使用对应*-names条目转换后的名称标记；NAME_BY_IDX最后生成的是原始名称的字符串字面量，而IDX_BY_NAME返回数字索引。未命名元素不会生成名称查询宏，不能把NAME_BY_IDX的字符串直接当作BY_NAME参数使用。HAS_CELL只检查第0个元素，其他索引使用HAS_CELL_AT_IDX。

> 译注——源码核对：片段语法：HAS_COMPAT原例n: node的结尾只有右花括号，完整DTS节点定义还需要分号。片段保留用于说明两个compatible值都匹配，不将其记为已经编译通过。

> 译注——源码核对：版本与验证：本次官方devicetree.h、gen_defines.py和edtlib.py分别登记摘要，源码对照不代表滚动main与本仓库参照基线完全相同。原始代码、字符串和许可证保留；本批未编译宏／DTS示例、构建固件或操作硬件。

本次验证范围为文档与源码对照，未编译宏／DTS示例、构建固件或操作硬件。
