# 第157章\_运行协议一致性测试

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/conformance/usage.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 1. 运行流程（Running the Conformance Suites）

一次运行的流程是：Twister 构建并启动被测系统（System Under Test，SUT），测试控制层（Harness）用 Titan 构建 TTCN-3 套件，套件通过 TAP 接口与运行中的应用通信，最后将 Titan 判定（Verdict）转换成测试结果。

> 译注——运行环境：以下是官方 Linux 主机流程，使用原生 Bash、TAP、`sudo`、Linux 包套接字及相关工具；不能仅把终端换成 Windows PowerShell 或 UCRT64 就视为已具备同等条件。原文 `/usr` 是发行版 Titan 的安装前缀，`/opt/titan` 是官方容器配方的前缀，不是作者仓库位置。`ZEPHYR_BASE` 应由读者自己的 Zephyr 环境提供；`NET_TOOLS_BASE` 若设置，应指向 net-tools 仓库根，而不是其 `ttcn3` 子目录。所有构建和网络操作均未在本次翻译中执行。

## 2. 一次运行需要什么（What a Run Needs）

- Titan 安装，以及指向其安装位置的 `TTCN3_DIR`，见 [安装 Titan](#installing-titan)。
- 第三方 TTCN-3 模块，先运行一次 `ttcn3/fetch-modules.sh` 获取；模块按固定提交克隆，不包含在 net-tools 仓库内。
- net-tools 源码检出。官方 west 工作区已包含它：`west.yml` 将它放在未被过滤掉的 `tools` 分组中。
- `make`，Titan 通过它构建套件。
- `zeth` 接口，或供 IP 层以下套件使用的 `zethL2`，见 [设置网络接口](#setting-up-the-network-interfaces)。
- 对无法避开特权端口或包套接字的套件，需要 root。
- 对通过 Titan 主控制器（Main Controller）运行的套件，需要 `expect`。

[套件列表](P155_TTCN3协议一致性测试.md#ttcn3-suites)列出各套件的要求；`scripts/net/run-conformance-tests.sh --list` 也可打印这些信息。

控制层优先从 `NET_TOOLS_BASE` 查找 net-tools；未设置时，从相对于 `ZEPHYR_BASE` 的 `../tools/net-tools/ttcn3` 查找，再向上多查一层。套件构建前检查这些条件；缺少某项时给出原因并跳过，而不是判失败。

> 译注：官方 `west.yml` 的默认分组状态不保证任意已有工作区已经下载 net-tools；用户的活动清单、分组过滤或固定修订可能不同。先核对自己的清单及实际 `ttcn3` 目录，不能为了阅读本页覆盖已有工作区配置。

## 3. 安装 Titan（Installing Titan）

多数发行版提供 Titan 软件包，官方持续集成（Continuous Integration，CI）也采用包安装。以下原文命令在支持 `apt` 的 Linux 主机 Bash 中执行；安装与环境变量设置是两个动作，成功安装后为当前终端导出安装前缀。

```sh
sudo apt install --no-install-recommends eclipse-titan expect
export TTCN3_DIR=/usr
```

发行版包可能落后于套件所依赖的协议模块；如果因此编译失败，改为从源码构建当前 Titan。

### 3.1 从源码构建 Titan（Building Titan from Source）

`net-tools/docker/Dockerfile.ttcn3` 把 Titan 构建安装到 `/opt/titan`，可作为手动操作的依据，既可用于构建容器，也可作为逐步参考。它是本地可选路线，不是当前 CI 采用的路线。

手动构建有两个关键点。Titan 通过其源码目录中的 `Makefile.personal` 配置，而不是 `configure` 脚本；该文件中的 `TTCN3_DIR` 是安装前缀。`make install` 必须串行执行，因为部分运行库包含的头文件由另一部分生成，并行执行可能发生竞争。

## 4. 使用脚本运行（Running the Suites with the Script）

[scripts/net/run-conformance-tests.sh](https://github.com/zephyrproject-rtos/zephyr/blob/main/scripts/net/run-conformance-tests.sh) 将后两节操作合并成一条命令，是最简单的运行方式。它查找 net-tools，必要时获取缺失模块，创建所选套件需要的接口；所选套件需要 root 时，使用 `sudo` 重新启动自身；随后运行一次 Twister，并在结束后拆除接口。

在已准备好前述依赖的 Zephyr 源码根目录、Linux Bash 终端中执行：

```sh
export TTCN3_DIR=/usr
./scripts/net/run-conformance-tests.sh
```

命名套件后只运行指定套件，便于在开发单个套件时保持非特权模式，例如：

```sh
./scripts/net/run-conformance-tests.sh mdns dns
```

`--list` 显示套件与各自要求；`--keep` 保留接口供下次使用；`--start` 和 `--stop` 只完成创建或拆除接口的相应一半操作。`--help` 列出其他选项及自动探测到的目录。

特权运行会创建 root 所有的文件，因此脚本退出前会把 Twister 输出目录和套件构建目录的所有权交还调用用户。

## 5. 设置网络接口（Setting Up the Network Interfaces）

需要两个 TAP 接口，因为工作在 IP 层以下的套件，不能与会替自己应答的主机协议栈共享同一测试链路。

### 5.1 共享接口 zeth（Shared Interface）

套接字套件使用此接口，测试器（Tester）相当于链路上的另一个主机。以下原命令先从 Zephyr 环境定位官方默认布局的 net-tools 目录，再创建接口：

```sh
cd $ZEPHYR_BASE/../tools/net-tools
sudo ./net-setup.sh --config zeth.conf start
```

主机持有 `192.0.2.2/24` 和 `2001:db8::2`，Zephyr 在 `192.0.2.1`、`2001:db8::1` 应答。把命令中的 `start` 改成 `stop` 即可拆除接口。

### 5.2 无地址接口 zethL2（Address-Less Interface）

工作在 IP 层以下的套件使用此接口。仍在 net-tools 根目录、同一 Linux Bash 环境执行：

```sh
sudo ./net-setup.sh --config zeth-l2.conf --iface zethL2 start
```

此接口刻意不分配 IP 地址。如果不加限制，Linux 会为主机在其他接口上持有的地址参与地址解析和邻居发现（Neighbor Discovery），来自主机的应答就可能与来自 Zephyr 的应答混淆。测试器发送原始帧（Raw Frame），自身无需在接口上配置地址。

配置设置三项 `sysctl`，阻止主机参与：`arp_ignore=8` 使它不为任何本地地址应答 ARP；原文将 `arp_announce=2` 描述为“不用本接口未持有的地址应答”；`disable_ipv6=1` 禁用该接口 IPv6，以免出现邻居通告（Neighbor Advertisement）或路由器请求（Router Solicitation）。

> 译注——ARP 参数含义修正：[Linux 官方 IP Sysctl 文档](https://docs.kernel.org/networking/ip-sysctl.html)说明，`arp_announce` 控制**发出的 ARP 请求**使用哪个本地源地址，不是 ARP 应答开关；值 2 尽量选择适合目标的地址，找不到时仍有回退路径。这里拒绝本地地址 ARP 应答的关键设置是 `arp_ignore=8`。原命令与官方 `zeth-l2.conf` 保留不变，原文对 `arp_announce` 的描述不能当成严格的“不从其他接口选地址”保证。

`zethL2` 名称不能任意单独更改，相关三处配置的一致性要求见 [测试网络](P156_一致性测试架构.md#ttcn3-test-network)。

> 译注——目录可移植性：原文 `cd $ZEPHYR_BASE/...` 未加引号；工作区路径含空格时应使用带引号的形式，例如 `cd "$ZEPHYR_BASE/../tools/net-tools"`、`cd "$ZEPHYR_BASE"`。默认相邻目录布局不适用时，进入自己的 net-tools 检出目录，并通过 `NET_TOOLS_BASE` 告诉控制层其位置，不必迁移或改名仓库。

## 6. 使用 Twister 运行（Running the Suites with Twister）

先获取一次第三方模块；此脚本允许重复运行。在 Linux Bash 中执行以下原文命令：

```sh
cd $ZEPHYR_BASE/../tools/net-tools
./ttcn3/fetch-modules.sh
```

然后设置 Titan 前缀，回到 Zephyr 源码根并运行测试：

```sh
export TTCN3_DIR=/usr
cd $ZEPHYR_BASE
./scripts/twister -p native_sim --enable-slow -T tests/net/conformance
```

`--enable-slow` 必须指定，因为套件都标记为慢速测试，完整运行需要数十分钟；只允许 `native_sim` 平台。

通过 `net.conformance.<suite>` 测试标识选择单个套件，例如在 Zephyr 源码根执行：

```sh
./scripts/twister -p native_sim --enable-slow -T tests/net/conformance \
    -s net.conformance.mdns
```

套件还带有 `net` 和 `conformance` 标签，使用 `--tag conformance` 可选择全部一致性测试。

### 6.1 以 root 运行（Running as Root）

部分套件必须以 root 运行。DHCP 固定使用 67、68 端口，无法改用其他端口，因此测试器必须绑定特权端口；直接读取链路帧又需要包套接字。权限不足时，这些测试会自行跳过。

使用 `sudo -E` 保留 `TTCN3_DIR` 和其他环境。整次运行要么全部特权、要么全部非特权，不能把两种运行同时混在一起；原因见 [测试控制层](P156_一致性测试架构.md#ttcn3-runner)。

### 6.2 为什么串行运行（Why a Run Is Serial）

所有被测系统都在同一接口、同一地址应答，因此同一时间只能运行一项一致性测试。测试独占接口锁并相互等待，无论给 Twister 分配多少并行任务，整个目录的一致性测试仍会串行运行。

## 7. 手动运行套件（Running a Suite by Hand）

Twister 方便，但调试迭代较慢；编写或调试套件时，可以分别运行两侧。

先在第一个 Linux Bash 终端的 Zephyr 环境构建并启动被测系统，保持它运行。网络接口、Titan 与模块均须已经准备好；`-p` 会要求原始构建目录使用干净构建，不应指向需要保留其他用途数据的目录。

```sh
cd $ZEPHYR_BASE
west build -p -b native_sim -d ../build/mdns tests/net/conformance/mdns
../build/mdns/zephyr/zephyr.exe
```

在第二个具备相同环境变量的终端，构建并运行套件：

```sh
cd $ZEPHYR_BASE/../tools/net-tools/ttcn3
./build.sh mdns
cd suites/mdns/build
./mdns ../mdns.cfg
```

如果用例会创建并行测试组件，应改由主控制器启动。原文以 `coap` 为例，以下命令需要在已构建的 CoAP 套件 `suites/coap/build` 目录执行，而不是接在 mDNS 的构建目录中直接运行：

```sh
ttcn3_start ./coap ../coap.cfg
```

指定用例名可以只运行一个用例，例如在 mDNS 套件的 `suites/mdns/build` 目录执行：

```sh
./mdns ../mdns.cfg MDNS_Suite.tc_a_query
```

地址、接口和超时来自套件配置文件的 `[MODULE_PARAMETERS]` 段，因此只需修改配置文件，不需修改套件源码，即可改变测试链路。

手动执行还必须自行完成控制层自动处理的一件事：把 Titan 库目录加入 `LD_LIBRARY_PATH`。

> 译注——手动库路径：发行版布局通常为 `$TTCN3_DIR/lib/titan`，源码安装通常为 `$TTCN3_DIR/lib`，以实际存在的目录为准；执行 `ttcn3_start` 时也需能从 `PATH` 找到 `$TTCN3_DIR/bin`。这只配置当前终端的程序／动态库查找，不替代 Titan 安装。构建失败时不要继续运行旧产物；等待应用的就绪行后再启动套件。

## 8. 读取结果（Reading the Result）

Titan 结束时打印每类判定的数量，以及本次运行的总体判定。下面为原文预期输出，不是本次翻译的执行结果：

```text
Verdict statistics: 0 none (0.00 %), 7 pass (100.00 %), 0 inconc (0.00 %), 0 fail (0.00 %), 0 error (0.00 %).
Test execution summary: 7 test cases were executed. Overall verdict: pass
```

`inconc` 表示无法得出结论（Inconclusive），通常是依赖的事件没有发生，不能算通过。`error` 表示套件自身发生错误，而不是被测系统的协议断言失败。

证据保存在两处。Titan 按配置文件的 `LogFile` 设置，在套件构建目录写日志；Twister 在输出目录写 `twister_harness.log`，以 INFO 级别记录套件的全部输出。

## 9. 套件何时被跳过（When a Suite Is Skipped）

套件构建前检查所需条件；缺少前提时，默认跳过而不是失败。检查原因按顺序如下。

| 原始原因（Reason） | 处理方法（What to Do） |
| --- | --- |
| `TTCN3_DIR is unset` | 安装 Titan 并导出 `TTCN3_DIR`，见安装一节。 |
| `make is not installed` | 安装 `make`；Titan 使用生成的 Makefile 构建套件。 |
| `no TTCN-3 suites under ...` | 未找到 net-tools，设置 `NET_TOOLS_BASE`。 |
| `... has no <suite> suite` | net-tools 检出版本早于该套件，更新到包含它的版本。 |
| `third party modules are missing` | 运行 `ttcn3/fetch-modules.sh`。 |
| `the <iface> interface does not exist` | 用 `net-setup.sh` 创建接口，见网络接口一节。 |
| `ttcn3_start is not in TTCN3_DIR/bin` | 安装 `expect` 以及提供主控制器的 Titan。 |
| `has to be run as root` | 通过 `sudo -E` 重跑，或使用统一运行脚本。 |

设置环境变量 `NET_CONFORMANCE_REQUIRED`，可把这些情况改为失败。它适用于运行目的就是验证这些套件的场景，例如每夜 CI，避免没有运行的测试冒充已经验证。

> 译注——变量判定：当前官方 `build_suite()` 使用 `os.environ.get('NET_CONFORMANCE_REQUIRED')` 判断，因此值为非空字符串 `0` 也会启用强制失败。需要恢复默认跳过策略时，应从相应运行环境取消该变量。当前前提检查仅确认模块目录等入口存在，并不证明每个模块、工具或版本都完整可用；后续真实构建仍可能失败。

## 10. 故障排查（Troubleshooting）

### 10.1 套件无法编译（The Suite Does Not Compile）

原文指出，常见原因是发行版 Titan 落后于套件使用的协议模块；可从源码构建 Titan。

### 10.2 收不到任何内容并超时（The Suite Sees Nothing and Times Out）

检查应用与套件是否位于同一接口。IP 层以下的套件使用 `zethL2`，应用构建时的 `host-interface` 也必须指向它；测试通过 `boards/native_sim.overlay` 设置此属性。如果主机代替 Zephyr 应答，说明 `zethL2` 的 sysctl 配置未生效，可检查 `sysctl net.ipv4.conf.zethL2.arp_ignore` 的结果。

### 10.3 挂起或中途终止（A Run Hangs or Is Cut Off）

四层超时围绕整次运行：等待应用就绪行 30 秒、构建套件 1800 秒、运行套件 600 秒、Twister 整项测试 900 秒。是哪一层触发，有助于定位问题。套件运行超时会与其整个进程组（Process Group）一并终止，避免遗留主控制器。

> 译注：1800 秒是内部构建调用的上限，不能据此认为外层 Twister 会允许单项测试运行超过 900 秒；构建与运行共用外层预算。手动运行时也应检查各命令实际结果，不能套用原示意日志作为成功证明。

### 10.4 遗留状态（Leftover State）

使用 `net-setup.sh` 的 `stop` 操作拆除接口。测试锁文件名为 `zephyr-net-conformance-<euid>.lock`，位于临时目录；进程退出时锁自动释放，因此遗留空锁文件本身无害。
