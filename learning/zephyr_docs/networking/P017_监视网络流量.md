# 第17章\_监视网络流量

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/network_monitoring.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 17.1\_监视目的与配置入口

排查连接问题或为 Zephyr 开发新协议支持时，监视网络流量（Network Traffic Monitoring）很有用。本页说明如何捕获网络流量，使远程主机上的 Wireshark 等工具能够查看 Zephyr 设备发送和接收的网络分组（Network Packet）。

需要启用的配置选项也可参见 Zephyr 源码中的[网络分组捕获（Network Packet Capture）示例](P201_网络数据包捕获示例.md#net-capture)。

## 17.2\_主机配置（Host Configuration）

以下步骤使用 Linux 主机捕获 Zephyr 的接收（RX）与发送（TX）流量；原文指出，其他操作系统可采用类似配置方法。

先找到官方 [net-tools](https://github.com/zephyrproject-rtos/net-tools) 项目。标准 Zephyr 工作区通常包含 `tools/net-tools`，也可以在读者选择的目录独立克隆：

```sh
git clone https://github.com/zephyrproject-rtos/net-tools
```

[`net-tools`](https://github.com/zephyrproject-rtos/net-tools) 提供用于建立 IP 内封装 IP 隧道（IP-to-IP Tunnel）的配置，将监视数据从 Zephyr 传给主机。在终端 1 中进入 [`net-tools`](https://github.com/zephyrproject-rtos/net-tools) 目录，执行：

```sh
./net-setup.sh -c zeth-tunnel.conf
```

脚本创建以下 IPIP 隧道接口：

| 接口名 | 说明 |
| --- | --- |
| `zeth-ip6ip` | IPv6 封装于 IPv4（IPv6-over-IPv4）隧道 |
| `zeth-ipip` | IPv4 封装于 IPv4（IPv4-over-IPv4）隧道 |
| `zeth-ipip6` | IPv4 封装于 IPv6（IPv4-over-IPv6）隧道 |
| `zeth-ip6ip6` | IPv6 封装于 IPv6（IPv6-over-IPv6）隧道 |

Zephyr 会将捕获的网络分组发送给其中一个接口，具体取决于捕获配置。随后可以使用 Wireshark 监视对应接口。

创建隧道后，可使用 [`net-tools`](https://github.com/zephyrproject-rtos/net-tools) 中的 `net-capture.py` 打印或保存捕获的数据。该脚本提供 UDP 监听器（UDP Listener），将分组信息输出到屏幕，也可以保存为 PCAP 文件。另开一个主机终端，进入工具目录，执行下面示例的首行命令；后续各行是原文输出：

```text
$ ./net-capture.py -i zeth-ip6ip -w capture.pcap
[20210408Z14:33:08.959589] Ether / IP / ICMP 192.0.2.1 > 192.0.2.2 echo-request 0 / Raw
[20210408Z14:33:08.976178] Ether / IP / ICMP 192.0.2.2 > 192.0.2.1 echo-reply 0 / Raw
[20210408Z14:33:16.176303] Ether / IPv6 / ICMPv6 Echo Request (id: 0x9feb seq: 0x0)
[20210408Z14:33:16.195326] Ether / IPv6 / ICMPv6 Echo Reply (id: 0x9feb seq: 0x0)
[20210408Z14:33:21.194979] Ether / IPv6 / ICMPv6ND_NS / ICMPv6 Neighbor Discovery Option - Source Link-Layer Address 02:00:5e:00:53:3b
[20210408Z14:33:21.217528] Ether / IPv6 / ICMPv6ND_NA / ICMPv6 Neighbor Discovery Option - Destination Link-Layer Address 00:00:5e:00:53:ff
[20210408Z14:34:10.245408] Ether / IPv6 / UDP 2001:db8::2:47319 > 2001:db8::1:4242 / Raw
[20210408Z14:34:10.266542] Ether / IPv6 / UDP 2001:db8::1:4242 > 2001:db8::2:47319 / Raw
```

脚本命令行帮助如下。其用途是监听来自 Zephyr 的捕获数据，并按需保存为 PCAP 文件：

```text
Listen captured network data from Zephyr and save it optionally to pcap file.
./net-capture.py \
     -i | --interface <network interface>
             Listen this interface for the data
     [-p | --port <UDP port>]
             UDP port (default is 4242) where the capture data is received
     [-q | --quiet]
             Do not print packet information
     [-t | --type <L2 type of the data>]
             Scapy L2 type name of the UDP payload, default is Ether
     [-w | --write <pcap file name>]
             Write the received data to file in PCAP format
```

| 参数 | 中文说明 |
| --- | --- |
| `-i` / `--interface` | 接收数据的网络接口。 |
| `-p` / `--port` | 接收捕获数据的 UDP 端口，默认 `4242`。 |
| `-q` / `--quiet` | 不打印分组信息。 |
| `-t` / `--type` | UDP 载荷（Payload）的 Scapy 二层类型名称，默认 `Ether`。 |
| `-w` / `--write` | 以 PCAP 格式将收到的数据写入指定文件。 |

也可以不用 `net-capture.py`，改用 `netcat` 提供 UDP 监听器，避免主机向 Zephyr 返回端口不可达（Port Unreachable）消息：

```sh
nc -l -u 2001:db8:200::2 4242 > /dev/null
```

上面的 IP 地址是隧道内层端点（Inner Tunnel Endpoint），应与 Zephyr 配置一致，可以按实际配置改变。Zephyr 将包含被捕获分组的 UDP 数据包送入配置好的 IP 隧道，因此主机需要这样的接收端。`/dev/null` 是 Linux 的空设备，表示丢弃接收数据，不是仓库路径。

## 17.3\_构建并启动 Zephyr（Zephyr Configuration）

示例采用 `native_sim`，也可换用任何支持联网的开发板。在终端 3 的 Zephyr 源码根目录执行：

```sh
west build -b native_sim samples/net/capture -- -DCONFIG_UART_NATIVE_PTY_AUTOATTACH_DEFAULT_CMD=\""gnome-terminal -- screen %s"\"
```

为显示 Zephyr 控制台与 shell，按下面方式启动实例：

```sh
build/zephyr/zephyr.exe -attach_uart
```

其他应用同样可以使用捕获功能，只要启用合适的选项；可参考 [`samples/net/capture/prj.conf`](../../../samples/net/capture/prj.conf)。原文自动打开串口终端的配置使用 `gnome-terminal` 和 `screen`；上述程序来自构建生成的 `build` 目录。

网络捕获可以按需自动配置，但当前捕获示例本身不执行这一步。读者需要在网络 shell（net-shell）中设置并启用监视。

## 17.4\_建立捕获隧道

先使用 `net capture setup` 设置监视。命令语法与原始帮助如下：

```text
net capture setup <remote-ip-addr> <local-ip-addr> <peer-ip-addr>
     <remote> is the (outer) endpoint IP address
     <local> is the (inner) local IP address
     <peer> is the (inner) peer IP address
     Local and Peer IP addresses can have UDP port number in them (optional)
     like 198.0.51.2:9000 or [2001:db8:100::2]:4242
```

`<remote-ip-addr>` 是外层远端 IP 地址，`<local-ip-addr>` 是内层本地 IP 地址，`<peer-ip-addr>` 是内层对端 IP 地址。本地与对端地址可附加 UDP 端口，例如原帮助中的 `198.0.51.2:9000` 或 `[2001:db8:100::2]:4242`。

在 **Zephyr 控制台**中执行：

```text
net capture setup 192.0.2.2 2001:db8:200::1 2001:db8:200::2
```

该命令创建隧道接口。`192.0.2.2` 是隧道终止的远程主机地址，也用于选择隧道所附着的本地网络接口；`2001:db8:200::1` 是隧道内层本地地址，`2001:db8:200::2` 是接收捕获数据的内层对端地址。

可以在设置命令中指定 UDP 端口。IPv6-over-IPv4 隧道示例如下：

```text
net capture setup 192.0.2.2 [2001:db8:200::1]:9999 [2001:db8:200::2]:9998
```

IPv4-over-IPv4 隧道示例如下：

```text
net capture setup 192.0.2.2 198.51.100.1:9999 198.51.100.2:9998
```

若省略端口，默认使用 UDP `4242`。用下面命令检查当前监视配置：

```text
uart:~$ net capture
Network packet capture disabled
                Capture  Tunnel
Device          iface    iface   Local                  Peer
NET_CAPTURE0    -        1      [2001:db8:200::1]:4242  [2001:db8:200::2]:4242
```

输出显示网络分组捕获尚未启用（disabled）。因此 `Capture iface`，即被捕获的接口，仍未设置；`Tunnel iface` 表示承载捕获数据的隧道接口。

## 17.5\_启用、停止与清理捕获

在 Zephyr shell 启用分组监视：

```text
net capture enable 2
```

`2` 指定要捕获流量的网络接口，本例为 `native_sim` 的以太网接口。可使用 `net iface` 查看当前可用接口与编号。

本例发送捕获数据的接口与被监视的接口相同。监视系统会避免再次捕获已经封装的捕获流量，否则将产生递归（Recursion）。不能捕获隧道接口本身的流量，因为这会形成递归循环。

捕获数据也可以通过其他网络接口发送：在 `net capture setup` 中设置合适的 `<remote-ip-addr>`，使 IP 隧道附着到所需接口即可。再次查看捕获状态：

```text
uart:~$ net capture
Network packet capture enabled
                Capture  Tunnel
Device          iface    iface   Local                  Peer
NET_CAPTURE0    2        1      [2001:db8:200::1]:4242  [2001:db8:200::2]:4242
```

输出显示捕获已启用（enabled），被捕获接口为 `2`。启用后，系统将捕获的接收或发送分组交给隧道接口进一步处理。

使用下面命令停止当前监视：

```text
net capture disable
```

再使用下面命令清除监视配置：

```text
net capture cleanup
```

不一定要通过 net-shell 配置；应用也可以直接调用[网络捕获 API（Network Capture API）](P029_网络分组捕获.md#net-capture-interface)完成设置。

## 17.6\_Wireshark 配置（Wireshark Configuration）

[Wireshark](https://www.wireshark.org/) 可用于查看捕获的网络流量。既可以监视隧道接口，也可以监视 `zeth` 接口。要查看 UDP 数据包中实际封装的原始数据，请参见[Wireshark UDP 解封装（Decapsulation）说明](https://osqa-ask.wireshark.org/questions/28138/decoding-ethernet-encapsulated-in-tcp-or-udp/)。
