# 第22章\_网络管理

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/api/net_mgmt.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 22.1\_概览（Overview）

网络管理（Network Management）API 允许应用或网络层代码调用 IP 协议栈任意层中已经定义的管理过程（Management Procedure），以及接收相关网络事件通知。例如，应用可以请求 Wi-Fi 或 Bluetooth 网络接口扫描，也可以在接口 IP 地址变化时接收通知。

实现通过在构建时排除未使用的管理过程来节约内存。它没有为每个过程设计独立的静态 API，而是用 [`NET_MGMT_REGISTER_REQUEST_HANDLER`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#gab67d09d1e65b806ec1957451cbf60501) 注册处理函数，再通过统一的 [`net_mgmt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#ga40e0f9fc86812ad9f6fe174b4c3804e6) 请求入口调用对应处理函数。

原文将当前实现标为实验性（Experimental），后续版本可能调整和改进。

## 22.2\_请求已定义的过程（Requesting a Defined Procedure）

管理请求均采用 `net_mgmt(mgmt_request, ...)` 形式。`mgmt_request` 是位掩码（Bit Mask），表明目标协议层、是否涉及 `net_if` 对象，以及具体请求的管理过程。可用请求取决于协议栈实际实现了哪些功能。

为避免额外开销，当前 [`net_mgmt()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#ga40e0f9fc86812ad9f6fe174b4c3804e6) 均采用直接调用（Direct Call）。原文指出，未来即使改变内部方式，也不会影响此接口的使用者。

## 22.3\_监听网络事件（Listening to Network Events）

注册回调并指定事件集合，即可筛选所关心的网络事件。对层（Layer）与层代码（Layer Code）的每个组合，需要独立的回调注册对象；命令字段（Command）则使用事件掩码。

运行时用 [`net_mgmt_add_event_callback()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#gae53f5bbc973b0f414107eca75ac0c26f) 注册，用 [`net_mgmt_del_event_callback()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#ga4960bfb01ecd891da72c57f17587f946) 注销，辅助函数 [`net_mgmt_init_event_callback()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#ga4e42b6d16b863ca374d032682e8c11fb) 用于初始化回调结构。也可以用 [`NET_MGMT_REGISTER_EVENT_HANDLER`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#ga3a6ca8a72ab12afd4f9b0461253eaa12) 在编译时注册处理函数。

事件与回调的事件集合匹配时，处理函数收到实际事件代码，因此一个处理函数可以处理不同事件。

**原文警告（Warning）**：同层且同层代码的事件可能出现筛选误命中（False Positive）。无论初始化时指定了多少事件，处理函数都必须检查实际传入的事件代码，只处理明确支持的事件。要监听多个层，必须为每层分别注册监听器（Listener），但处理函数本身可以共享。

运行时注册的原例：

```c
/*
 * Set of events to handle.
 * See e.g. include/zephyr/net/net_event.h for some NET_EVENT_xxx values.
 */
#define EVENT_IFACE_SET (NET_EVENT_IF_xxx | NET_EVENT_IF_yyy)
#define EVENT_IPV4_SET (NET_EVENT_IPV4_xxx | NET_EVENT_IPV4_yyy)

struct net_mgmt_event_callback iface_callback;
struct net_mgmt_event_callback ipv4_callback;

void callback_handler(struct net_mgmt_event_callback *cb,
                      uint64_t mgmt_event,
                      struct net_if *iface)
{
        if (mgmt_event == NET_EVENT_IF_xxx) {
                /* Handle NET_EVENT_IF_xxx */
        } else if (mgmt_event == NET_EVENT_IF_yyy) {
                /* Handle NET_EVENT_IF_yyy */
        } else if (mgmt_event == NET_EVENT_IPV4_xxx) {
                /* Handle NET_EVENT_IPV4_xxx */
        } else if (mgmt_event == NET_EVENT_IPV4_yyy) {
                /* Handle NET_EVENT_IPV4_yyy */
        } else {
                /* Spurious (false positive) invocation. */
        }
}

void register_cb(void)
{
        net_mgmt_init_event_callback(&iface_callback, callback_handler,
                                     EVENT_IFACE_SET);
        net_mgmt_init_event_callback(&ipv4_callback, callback_handler,
                                     EVENT_IPV4_SET);
        net_mgmt_add_event_callback(&iface_callback);
        net_mgmt_add_event_callback(&ipv4_callback);
}
```

代码注释译文：分别定义接口事件与 IPv4 事件集合，事件值参照 [`include/zephyr/net/net_event.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/net_event.h)；根据收到的实际代码处理对应事件，最后的 `else` 表示忽略误命中的调用。两个回调结构分别初始化和注册，但共享同一个处理函数。

编译时注册也可采用同样的组织方式。**原文注意（Note）**：只有启用 [`CONFIG_NET_MGMT_EVENT_INFO`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_MGMT_EVENT_INFO) 后，`info` 与 `info_length` 参数才可使用，否则分别为 `NULL` 和 `0`。

```c
/*
 * Set of events to handle.
 */
#define EVENT_IFACE_SET (NET_EVENT_IF_xxx | NET_EVENT_IF_yyy)
#define EVENT_IPV4_SET (NET_EVENT_IPV4_xxx | NET_EVENT_IPV4_yyy)

static void event_handler(uint64_t mgmt_event, struct net_if *iface,
                          void *info, size_t info_length,
                          void *user_data)
{
        if (mgmt_event == NET_EVENT_IF_xxx) {
                /* Handle NET_EVENT_IF_xxx */
        } else if (mgmt_event == NET_EVENT_IF_yyy) {
                /* Handle NET_EVENT_IF_yyy */
        } else if (mgmt_event == NET_EVENT_IPV4_xxx) {
                /* Handle NET_EVENT_IPV4_xxx */
        } else if (mgmt_event == NET_EVENT_IPV4_yyy) {
                /* Handle NET_EVENT_IPV4_yyy */
        } else {
                /* Spurious (false positive) invocation. */
        }
}

NET_MGMT_REGISTER_EVENT_HANDLER(iface_event_handler, EVENT_IFACE_SET,
                                event_handler, NULL);
NET_MGMT_REGISTER_EVENT_HANDLER(ipv4_event_handler, EVENT_IPV4_SET,
                                event_handler, NULL);
```

代码注释含义与上例一致：先定义事件集合，处理时逐项比较真实事件编号，忽略无关调用；两个静态注册分别使用接口和 IPv4 事件集合。

可监听的通用核心事件见 [`include/zephyr/net/net_event.h`](../../../include/zephyr/net/net_event.h)。原例的 `NET_EVENT_IF_xxx` 等是待替换的示意标识，不是能直接构建的完整应用。

## 22.4\_定义网络管理过程（Defining a Network Management Procedure）

可以为自己的协议栈实现增加管理过程：定义处理函数，再用相关的 `mgmt_request` 代码注册。

请求代码的位置取决于目标层；对于二层（L2），还取决于具体技术。原文举例称 IP 层代码在 [`include/zephyr/net/net_event.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/net_event.h)，以太网相关内容在 [`include/zephyr/net/ethernet.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/ethernet.h)。对应源码入口分别为[网络事件头文件](../../../include/zephyr/net/net_event.h)和[以太网头文件](../../../include/zephyr/net/ethernet.h)。

处理函数使用下面的签名（Signature）：

```c
static int your_handler(uint64_t mgmt_event, struct net_if *iface,
                        void *data, size_t len);
```

随后以管理请求代码注册：

```c
NET_MGMT_REGISTER_REQUEST_HANDLER(<mgmt_request code>, your_handler);
```

新的管理过程即可通过以下方式调用：

```c
net_mgmt(<mgmt_request code>, ...);
```

其中 `<mgmt_request code>` 和省略号表示需要填入的实际请求代码及参数，并非原样可编译的 C 语句。

## 22.5\_发出网络事件（Signaling a Network Event）

通过 [`net_mgmt_event_notify()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html#gabf710692e596a2d98f37b82da884a82a) 并传入网络事件代码，即可发出指定事件，细节见 [`include/zephyr/net/net_mgmt.h`](../../../include/zephyr/net/net_mgmt.h)。

与管理请求代码类似，事件代码也可能定义在各 L2 技术的管理头文件中。例如，若关注 IEEE 802.15.4 L2 的事件，应查看 [`include/zephyr/net/ieee802154_mgmt.h`](../../../include/zephyr/net/ieee802154_mgmt.h)。

## 22.6\_API 参考与相关示例

详细接口见[网络管理 API](https://docs.zephyrproject.org/latest/doxygen/html/group__net__mgmt.html)。

- [DHCPv4 客户端（DHCPv4 Client）](P035_DHCPv4客户端示例.md#dhcpv4-client)：启动客户端，从 DHCPv4 服务器取得 IPv4 地址。
- [DNS 解析（DNS Resolve）](P037_DNS解析示例.md#dns-resolve)：解析给定主机名的 IP 地址。
- [IPv4 自动配置客户端（Autoconfiguration Client）](P199_IPv4自动配置客户端示例.md#ipv4-autoconf)：执行 IPv4 自动配置，自行分配随机 IPv4 地址。
- [Telnet 控制台（Telnet Console）](P209_Telnet控制台示例.md#telnet-console)：通过 Telnet 访问 Zephyr shell。
