# 第48章\_高级回显客户端示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/net/sockets/echo_client/README.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 48.1 概览（Overview）

Zephyr 的 `echo-client` 示例实现 UDP/TCP 回显客户端（Echo Client）：发送 IPv4 或 IPv6 分组，等待数据返回，再检查返回内容是否与发出的数据一致。UDP 是用户数据报协议（User Datagram Protocol），TCP 是传输控制协议（Transmission Control Protocol）。

源码位于[samples/net/sockets/echo_client](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/sockets/echo_client)，也可[在 GitHub 浏览官方源码](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/net/sockets/echo_client/README.rst/..)。

## 48.2 前置要求与配置（Requirements and Configuration）

准备[与主机系统联网](P007_与主机系统联网.md#networking-with-host)的环境。应用有多种用法，常见方式是在 QEMU 模拟器中运行，详见[QEMU 联网](P009_QEMU联网概览.md#networking-with-qemu)。

客户端目录提供适用于不同开发板和设置的配置文件：

| 文件 | 作用 |
| --- | --- |
| `prj.conf` | 通用配置，通常应使用此文件 |
| `overlay-ot.conf` | 启用 OpenThread 支持，即 Thread 协议的开源实现 |
| `overlay-802154.conf` | 启用原生 IEEE 802.15.4 联网。默认第二层（L2）通信不使用确认；可通过 `ieee802154 ack set` 启用确认（Acknowledgment），提高连接可靠性 |
| `overlay-qemu_802154.conf` | 用两个相互连接的 QEMU 实例模拟 IEEE 802.15.4 网络 |
| `overlay-tls.conf` | 启用传输层安全（Transport Layer Security，TLS） |
| `overlay-vlan.conf` | 启用虚拟局域网（Virtual Local Area Network，VLAN），见[网络示例通用说明](P198_网络示例通用配置.md#networking-samples-common) |

## 48.3 构建与运行（Building and Running）

构建命令的通用形式为：

```shell
west build -b <board to use> samples/net/sockets/echo_client -- -DCONF_FILE=<config file to use>
```

`<board to use>` 和 `<config file to use>` 是需替换的开发板目标、配置文件占位符；它们不是可直接输入的参数。示例路径均相对于 Zephyr 源码根目录。

为 `nrf52840dk/nrf52840` 构建 OpenThread 版本：

```shell
west build -b nrf52840dk/nrf52840 samples/net/sockets/echo_client -- -DCONF_FILE="prj.conf overlay-ot.conf"
west build -t run
```

> 译注：原文保留的 `west build -t run` 是运行构建目标，不等于将固件烧录到物理板。官方 [`board.cmake`](https://github.com/zephyrproject-rtos/zephyr/blob/main/boards/nordic/nrf52840dk/board.cmake) 配置的是相应烧录／调试执行器（Runner）。实板操作依其板卡说明执行，本轮未验证该 `run` 目标。

为 IEEE 802.15.4 RF2XX 收发器（Transceiver）构建：

```shell
west build -b [samr21_xpro | sam4s_xplained | sam_v71_xult/samv71q21] samples/net/sockets/echo_client -- -DEXTRA_CONF_FILE=overlay-802154.conf
west flash
```

方括号中的 `samr21_xpro`、`sam4s_xplained` 和 `sam_v71_xult/samv71q21` 是三个备选目标，应选择一个实际目标；不要把方括号和竖线照抄为 Shell 命令。通过终端观察通信：

```shell
$ minicom -D /dev/ttyACM1
```

`/dev/ttyACM1` 是 Linux 示例的串口设备节点（Device Node），需替换为实际枚举结果；`$` 是提示符。

### 启用 TLS（Enabling TLS Support）

构建时加入 `overlay-tls.conf`：

```shell
west build -b qemu_x86 samples/net/sockets/echo_client -- -DCONF_FILE="prj.conf overlay-tls.conf"
```

另一种方式是在 `west build` 或 `cmake` 中指定 `-DEXTRA_CONF_FILE=overlay-tls.conf`。

示例使用的证书与私钥（Private Key）位于 `src` 目录。客户端与[高级回显服务器](P047_高级回显服务器示例.md#sockets-echo-server)的默认证书可用于在两个示例之间建立安全连接。

### SOCKS5 代理（SOCKS5 Proxy）

也可以通过 SOCKS5 代理连接回显服务器。运行 `west build` 或 `cmake` 时，加入 `-DEXTRA_CONF_FILE=overlay-socks5.conf`。

为简化测试，默认假定代理与 Linux 主机上的回显服务器运行在同一台主机。可以利用安全 Shell（Secure Shell，SSH）的 `-D` 选项启动内置 SOCKS 代理。

IPv4 代理：

```shell
$ ssh -N -D 0.0.0.0:1080 localhost
```

IPv6 代理：

```shell
$ ssh -N -D [::]:1080 localhost
```

同时测试 IPv4 与 IPv6 时，原文要求分别运行两条命令。若代理地址与回显服务器不同，或端口不同，则修改 `echo_client/src/tcp.c` 中的以下定义：

```c
#define SOCKS5_PROXY_V4_ADDR IPV4_ADDR
#define SOCKS5_PROXY_V6_ADDR IPV6_ADDR
#define SOCKS5_PROXY_PORT    1080
```

> 源码核对译注：当前官方 [`tcp.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/sockets/echo_client/src/tcp.c) 中，默认代理地址分别取自 `CONFIG_NET_CONFIG_PEER_IPV4_ADDR` 和 `CONFIG_NET_CONFIG_PEER_IPV6_ADDR`，不再使用上方片段中的 `IPV4_ADDR`／`IPV6_ADDR` 宏名；默认端口仍为 `1080`。`0.0.0.0` 和 `[::]` 表示监听所有对应地址，不是仅回环监听。本轮没有启动代理或改动主机端口。

### Wi-Fi

通过[Wi-Fi 配置片段（Snippet）](../snippets/P027_WiFi_IPv4配置片段.md#snippet-wifi-ipv4)启用 IPv4 Wi-Fi 支持。

## 48.4 在 Linux 主机运行服务器（Running echo-server in Linux Host）

一种测试布局是在 QEMU 中运行客户端，在 Linux 主机运行服务器。先按[QEMU 联网](P009_QEMU联网概览.md#networking-with-qemu)准备环境。

在主机终端启动服务器：

```shell
$ sudo ./echo-server -i tap0
```

再构建并在 QEMU 中启动客户端：

```shell
west build -b qemu_x86 samples/net/sockets/echo_client -- -DCONF_FILE="prj.conf overlay-linux.conf"
west build -t run
```

必须先启动主机服务器，再启动 QEMU 客户端。按 `CTRL`+`A`，再按 `x` 可退出 QEMU。

也可以与 Linux 主机验证 TLS 通信，方法见[net-tools 官方说明](https://github.com/zephyrproject-rtos/net-tools)；其中也提供这里的主机 `echo-server` 工具。相反的布局，即主机运行客户端、QEMU 运行服务器，见[高级回显服务器](P047_高级回显服务器示例.md#sockets-echo-server)。

## 48.5 OpenThread RCP 与 Zephyr 主机（SPINEL over UART）

本节完整保留官方原页的硬件组合：OpenThread 无线协处理器（Radio Co-Processor，RCP）通过通用异步收发器（Universal Asynchronous Receiver/Transmitter，UART）与 Zephyr 主机（HOST）连接，使用 Spinel 协议。PC 主机与运行 Zephyr 的嵌入式主机是两个不同角色。

> 译注：本节是官方提供的 nRF／i.MX RT 示例，不是为本仓库新增的芯片移植流程。原文固定的 SDK 版本、镜像标签、探针标识和设备节点在下方原样保留，并就地说明需要按实际环境替换的项目。

### 前置准备（Prerequisites）

在 x86_64 PC 主机上构建[net-tools](https://github.com/zephyrproject-rtos/net-tools) 的 `echo-server`；原文使用 SHA1 短标识 `1c4fdba`：

```shell
$ make echo-server
```

使用 Nordic nRF SDK `v2.7.0` 为 nRF RCP 准备固件：

```shell
(v2.7.0) ~/ncs$ west build -p always -b nrf21540dk/nrf52840 -S logging nrf/samples/openthread/coprocessor
```

> 译注：原文 `(v2.7.0) ~/ncs$` 是 SDK 环境和工作目录提示，不是命令的一部分，也不要求读者使用作者的目录。实际输入从 `west build` 开始，并在自己的相应 SDK 工作区执行。该行只显示构建动作，RCP 固件烧录仍须按对应开发板流程完成。

为 `mimxrt1020_evk` 构建 Zephyr 主机固件：

```shell
west build -b mimxrt1020_evk samples/net/sockets/echo_client -- -DCONF_FILE="prj.conf overlay-ot-rcp-host-uart.conf"
```

然后烧录：

```shell
$ west flash -r pyocd -i 0226000047784e4500439004d9170013e56100009796990
```

> 译注：原文 `-i` 后的长字符串是示例探针标识（Probe ID），不是通用值，应替换为实际连接的探针。开发板目标名同样依所用源码版本核对。本轮没有连接探针或执行烧录。

通过 UART 连接 nRF RCP 与 IMXRT1020 主机，原文接线说明如下：

```c
/*
 * imxrt1020_evk -> HOST
 * nRF21540-DK   -> RCP (nrf/samples/openthread/coprocessor)
 * LPUART2 used for communication:
 *  nRF21540 (P6) P0.08 RXD -> IMXRT1020-EVK (J17) D1 (GPIO B1 08) (TXD)
 *  nRF21540 (P6) P0.07 CTS -> IMXRT1020-EVK (J19) D8 (GPIO B1 07) (RTS)
 *  nRF21540 (P6) P0.06 TXD -> IMXRT1020-EVK (J17) D0 (GPIO B1 09) (RXD)
 *  nRF21540 (P6) P0.05 RTS -> IMXRT1020-EVK (J17) D7 (GPIO B1 06) (CTS)
 */
```

| nRF21540-DK（RCP） | IMXRT1020-EVK（HOST） | 信号关系 |
| --- | --- | --- |
| P6 P0.08 RXD | J17 D1，GPIO B1 08，TXD | RCP 接收数据（Receive Data）接主机发送数据（Transmit Data） |
| P6 P0.07 CTS | J19 D8，GPIO B1 07，RTS | RCP 允许发送（Clear to Send，CTS）接主机请求发送（Request to Send，RTS） |
| P6 P0.06 TXD | J17 D0，GPIO B1 09，RXD | RCP 发送接主机接收 |
| P6 P0.05 RTS | J17 D7，GPIO B1 06，CTS | RCP 请求发送接主机允许发送 |

原文指定主机使用 LPUART2，nRF 运行 `nrf/samples/openthread/coprocessor`。

### 准备 OpenThread 边界路由器（OpenThread Border Router，OTBR）

在 x86_64 PC 主机安装 OTBR Docker 容器，原文引用[Nordic 的 Docker OTBR 步骤](https://docs.nordicsemi.com/bundle/ncs-2.5.1/page/nrf/protocols/thread/tools.html#running_otbr_using_docker)，并特别列出以下操作。该链接对应 `ncs-2.5.1` 文档，前面的 RCP 构建示例标记为 `v2.7.0`；它们是原页给出的版本组合，不表示已用最新 SDK 复测。

先建立 `otbr0` 网桥（Network Bridge），让 Linux PC 可以访问 OpenThread 网络：

```shell
sudo docker network create --ipv6 --subnet fd11:db8:1::/64 -o com.docker.network.bridge.name=otbr0 otbr
```

拉取原文指定的 OTBR 镜像：

```shell
docker pull nrfconnect/otbr:84c6aff
```

加载模块并启动容器：

```shell
sudo modprobe ip6table_filter
sudo docker run -it --rm --privileged --name otbr --network otbr -p 8080:80 --sysctl "net.ipv6.conf.all.disable_ipv6=0 net.ipv4.conf.all.forwarding=1 net.ipv6.conf.all.forwarding=1" --volume /dev/ttyACM5:/dev/radio nrfconnect/otbr:84c6aff --radio-url spinel+hdlc+uart:///dev/radio?uart-baudrate=1000000
```

> 译注：`/dev/ttyACM5:/dev/radio` 将主机实际串口映射到容器设备节点；前者应按实际硬件替换，后者必须与 `--radio-url` 一致。这些是 Linux 设备路径，不是读者的 Git 仓库位置。命令保留原文的特权容器、网络转发与串口速率配置，本轮没有执行它们。

在 PC 主机添加路由。`fd11:22::/64` 是访问 Thread 设备的网内前缀（On-Mesh Prefix）：

```shell
sudo ip -6 route add fd11:22::/64 dev otbr0 via fd11:db8:1::2
```

原文给出的 Thread 网络地址路由查询及输出为：

```text
ip route get fd11:22:0:0:5188:1678:d0c0:6893
fd11:22::5188:1678:d0c0:6893 from :: via fd11:db8:1::2 dev otbr0 src fd11:db8:1::1 metric 1024 pref medium
```

这里的地址和输出是官方示例结果，不是本轮执行记录。接着打开容器控制台：

```shell
sudo docker exec -it otbr /bin/bash
```

可用以下命令检查路由器表和 IP 地址：

```shell
ot-ctl router table
ot-ctl ipaddr
```

### 配置 OTBR（Configure OTBR）

在 PC 浏览器打开 `http://localhost:8080/`，进入 **Form** 页面，保留原文列出的默认值，然后选择 **FORM** 创建 OpenThread 网络：

| 项目 | 原文示例值 |
| --- | --- |
| 网络密钥（Network Key） | `00112233445566778899aabbccddeeff` |
| 网内前缀（On-Mesh Prefix） | `fd11:22::` |
| 信道（Channel） | `15` |

网内前缀必须与 `otbr0` 路由设置一致。这里的 `localhost` 指运行容器并映射 Web 端口的 PC 主机。

### 配置 RCP 与 OpenThread 主机（Configure RCP and OT HOST）

对 nRF21540-DK RCP 与 `mimxrt1020` 主机执行原文的 OpenThread 命令：

```text
ot factoryreset
ot dataset networkkey 00112233445566778899aabbccddeeff
ot ifconfig up
```

> 译注：`ot factoryreset` 会重置设备的 OpenThread 配置，属于官方示例初始化步骤；本轮没有执行设备重置。

在 PC 的 Web 界面进入 **Commission**，将 **Joiner PSKd*** 设置为 `J01NME`，点击 **START COMMISSION** 开始入网授权（Commissioning）。PSKd 是入网设备的预共享密钥（Pre-Shared Key for the Device）。然后在设备侧执行：

```text
ot joiner start J01NME
ot thread start
```

`ot ipaddr` 应显示以 `fd11:22:0:0:` 开头的 IPv6 地址。PC 主机可以通过网络访问该地址，例如原文给出的 `ping -6 fd11:22:0:0:e8bf:266b:63ca:eff4`。实际测试须使用设备实际显示的地址。

最后，在 x86-64 PC 主机启动回显服务器：

```shell
./echo-server -i otbr0
```

> 译注：本节原文含版本、设备及网络相关参数，保留它们是为了忠实翻译官方场景。本轮仅核对文档和相关源码，没有安装 SDK／Docker、建立网桥或路由、操作设备、启动代理或测试 OpenThread 通信。
