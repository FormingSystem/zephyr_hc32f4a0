# 第6章\_网络分组处理统计

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/net_pkt_processing_stats.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 6.1\_启用处理时间统计

本页说明如何获得协议栈内部的网络分组处理统计（Network Packet Processing Statistics）。协议栈具有测量发送或接收路径处理耗时的基础设施，由两个 Kconfig 选项控制：发送（TX）使用 [`CONFIG_NET_PKT_TXTIME_STATS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_TXTIME_STATS)，接收（RX）使用 [`CONFIG_NET_PKT_RXTIME_STATS`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_RXTIME_STATS)。TX 收集所有类型网络分组的统计；RX 只收集 UDP、TCP 和原始分组（Raw Packet）类型的统计。

启用后，网络 Shell 命令 [`net stats`](P092_网络Shell.md#net-shell) 会显示：

```text
Avg TX net_pkt (11484) time 67 us
Avg RX net_pkt (11474) time 43 us
```

**原文注意（Note）**：上面和下面的数值均来自仿真的 `qemu_x86` 开发板与 UDP 流量。

TX 时间表示从网络分组创建到发往网络的耗时；RX 时间表示从分组创建到交给应用的耗时，单位为微秒。如果系统定义了多个发送或接收队列，会分别按流量类别（Traffic Class）收集统计；队列数量由 [`CONFIG_NET_TC_TX_COUNT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_TC_TX_COUNT) 和 [`CONFIG_NET_TC_RX_COUNT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_TC_RX_COUNT) 控制。

## 6.2\_分阶段统计

启用 [`CONFIG_NET_PKT_TXTIME_STATS_DETAIL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_TXTIME_STATS_DETAIL) 或 [`CONFIG_NET_PKT_RXTIME_STATS_DETAIL`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_RXTIME_STATS_DETAIL) 后，还会在分组经过 IP 协议栈时收集额外的发送或接收信息。此时 [`net stats`](P092_网络Shell.md#net-shell) 显示：

```text
Avg TX net_pkt (18902) time 63 us    [0->22->15->23=60 us]
Avg RX net_pkt (18892) time 42 us    [0->9->6->11->13=39 us]
```

方括号中的数字表示分组从上一状态到下一状态耗费多少微秒。

### 6.2.1\_发送示例

上述 TX 数值是18902个分组的平均值：

1. 应用创建分组，以此为起点，时间为0。
2. 分组即将进入发送队列。从创建到这一状态，本例平均耗时22微秒。
3. 对应 TX 线程运行，从发送队列取出分组；距上一状态15微秒。
4. 分组刚刚发送完成，协议栈即将释放它；距上一状态23微秒。
5. 总体平均发送耗时60微秒。前面的63表示同一种总耗时，但计算方法不同，因此因舍入误差而略有差异。

### 6.2.2\_接收示例

上述 RX 数值是18892个分组的平均值：

1. 网络设备驱动创建分组，以此为起点，时间为0。
2. 分组即将进入接收队列。从创建到这一状态，本例平均耗时9微秒。
3. 对应 RX 线程运行，从接收队列取出分组；距上一状态6微秒。
4. 分组处理后放入正确的套接字队列；距上一状态11微秒。
5. 最后一个值表示此后到应用收到数据的耗时，本例为13微秒。
6. 原文称平均“发送”耗时39微秒。前面的42表示同一种总耗时，但计算方式不同，因此因舍入误差而略有差异。

> 译注：接收示例末句的 sent 是原文笔误；结合 RX 数据路径，此处指分组从驱动创建到交给应用的接收处理时间。保留原统计值，不把它当作本仓库或 HC32 硬件的实测性能。本轮没有运行 QEMU 流量测试。
