# 第29章\_网络分组捕获

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/api/capture.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 29.1\_概览（Overview）

`net_capture` API 用于监视 Zephyr 某个网络接口的流量，并把数据发送到外部系统分析。可以通过网络 shell（net-shell）手工设置，也可以通过 API 自动设置。

## 29.2\_Cooked 模式捕获（Cooked Mode Capture）

配置并启用捕获后，系统会自动捕获指定接口的网络流量。如果要捕获的网络数据没有对应接口，则使用 Cooked 模式捕获 API。

Cooked 模式可以捕获任意网络分组，不要求数据原本经过网络接口。例如 PPP 中底层高级数据链路控制（High-level Data Link Control，HDLC）分组：普通接口捕获时，HDLC 二层数据已被剥离，此模式则可保留这类低层数据。CANBUS 或 Bluetooth 数据也可采用这种方式，但原文指出，当前协议栈尚未提供这两类捕获支持。

工作流程如下：

1. 创建 `any` 网络接口，作为数据汇入点（Sink），Cooked 捕获 API 向它写入分组。
2. 在 `any` 上附加名为 `cooked` 的虚拟接口（Virtual Network Interface）。
3. 通过接口配置 API 指定 `cooked` 要捕获的 L2 分组类型。
4. 调用 Cooked 捕获 API 时，调用者必须指明数据的二层协议类型，捕获逻辑才能判断是否接收这一类分组。
5. 在捕获设施中把 `cooked` 标为被捕获接口。数据经 `any` 到达 `cooked` 后，自动进入捕获 IP 隧道（Capture IP Tunnel），送往远程主机分析。

官方捕获示例创建的接口如下：

```text
Interface any (0x808ab3c) (Dummy) [1]
================================
Virtual interfaces attached to this : 2
Device    : NET_ANY (0x80849a4)

Interface cooked (0x808ac94) (Virtual) [2]
==================================
Virtual name : Cooked mode capture
Attached  : 1 (Dummy / 0x808ab3c)
Device    : NET_COOKED (0x808497c)

Interface eth0 (0x808adec) (Ethernet) [3]
===================================
Virtual interfaces attached to this : 4
Device    : zeth0 (0x80849b8)
IPv6 unicast addresses (max 4):
     fe80::5eff:fe00:53e6 autoconf preferred infinite
     2001:db8::1 manual preferred infinite
IPv4 unicast addresses (max 2):
     192.0.2.1/255.255.255.0 overridable preferred infinite

Interface net0 (0x808af44) (Virtual) [4]
==================================
Virtual name : Capture tunnel
Attached  : 3 (Ethernet / 0x808adec)
Device    : IP_TUNNEL0 (0x8084990)
IPv6 unicast addresses (max 4):
     2001:db8:200::1 manual preferred infinite
     fe80::efed:6dff:fef2:b1df autoconf preferred infinite
     fe80::56da:1eff:fe5e:bc02 autoconf preferred infinite
```

该例主机隧道外层端点地址为 `192.0.2.2`。Zephyr 根据此地址选择承载隧道的本地接口，此例中为接口 `3`。

接口 `2` 是附加在接口 `1` 上的虚拟接口。捕获 API 先将 Cooked 数据写入作为汇入点的接口 `1`，数据因附加关系传播到接口 `2`。

在 Zephyr 的 net-shell 执行 `net capture enable 2` 后，发送给接口 `2` 的分组被写入捕获接口 `4`。接口 `4` 封装分组，再经以太网接口 `3` 通过隧道发给对端。

若修改 [`samples/net/capture/overlay-tunnel.conf`](../../../samples/net/capture/overlay-tunnel.conf) 中的地址，上述 IP 地址也会随之变化。

> 译注：这里的接口编号、IP 和日志内存地址均为官方例子。接口编号应通过实际运行时的 `net iface` 输出确认；日志不是本仓库执行结果。文中的 `any` 和 `cooked` 是网络接口名，不是需要读者创建的目录。
