# 第28章\_网络分组过滤

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/api/net_pkt_filter.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 28.1\_概览（Overview）

网络分组过滤（Network Packet Filtering）用于构造自定义规则，决定是否接收或发送分组，也可修改入站分组优先级，适用于简单防火墙（Firewall）、流量控制等。启用相关 API 需要设置 [`CONFIG_NET_PKT_FILTER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_FILTER)。

发送与接收路径都可有过滤规则列表（Rule List）。每条规则包括一组条件（Condition）和处理结果（Outcome）。分组按顺序接受规则检查：某规则的全部条件为真时，按该规则确定结果；任一条件为假，则检查下一条规则。

结果有三种：`NET_OK` 接受分组，`NET_DROP` 丢弃分组，`NET_CONTINUE` 即时修改优先级并继续检查。前两者直接结束本次规则列表处理；`NET_CONTINUE` 只更新优先级，不决定最终接受／丢弃。多个优先级规则都匹配时，分组保留最后一个匹配规则赋予的优先级。

规则由 [`npf_rule`](https://docs.zephyrproject.org/latest/doxygen/html/structnpf__rule.html) 表示，规则列表由 [`npf_rule_list`](https://docs.zephyrproject.org/latest/doxygen/html/structnpf__rule__list.html) 保存；使用 [`npf_insert_rule()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt__filter.html#ga3b2a85558b6756e76760d9a40c780e28) 插入、[`npf_append_rule()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt__filter.html#gadfa956e4af3c45460846fc22f863e697) 追加、[`npf_remove_rule()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt__filter.html#ga4d7426db901debff35e1de5805e06c71) 移除。

### 28.1.1\_各层规则列表

不同协议层使用不同列表。L2 处理以太网等链路层；L3 处理 IPv4、IPv6；`local_in` 匹配运行在 IP 之上的 UDP、TCP 等入站协议类型。

| 列表 | 作用与配置 |
| --- | --- |
| `npf_send_rules` | L2 出站分组规则。 |
| `npf_recv_rules` | L2 入站分组规则。 |
| `npf_ipv4_recv_rules` | 入站 IPv4 规则，通过 [`CONFIG_NET_PKT_FILTER_IPV4_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_FILTER_IPV4_HOOK) 启用或关闭。 |
| `npf_ipv6_recv_rules` | 入站 IPv6 规则，通过 [`CONFIG_NET_PKT_FILTER_IPV6_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_FILTER_IPV6_HOOK) 启用或关闭。 |
| `npf_local_in_recv_rules` | 入站 UDP／TCP 规则，通过 [`CONFIG_NET_PKT_FILTER_LOCAL_IN_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_PKT_FILTER_LOCAL_IN_HOOK) 启用或关闭。 |

空规则列表默认接受，即 `NET_OK`；非空列表执行到末尾仍未确定接受结果时，默认丢弃，即 `NET_DROP`。建议非空列表始终以显式默认终止规则结束：`npf_default_ok` 或 `npf_default_drop`。

### 28.1.2\_条件与规则定义

条件由 [`npf_test`](https://docs.zephyrproject.org/latest/doxygen/html/structnpf__test.html) 表示。需要额外测试数据时，可将其嵌入更大的结构；条件测试函数负责从传入的 [`npf_test`](https://docs.zephyrproject.org/latest/doxygen/html/structnpf__test.html) 指针取回外层结构。

[`include/zephyr/net/net_pkt_filter.h`](../../../include/zephyr/net/net_pkt_filter.h) 提供静态定义各种条件的便利宏，另有 `NPF_RULE()` 创建立即给出结果的规则，`NPF_PRIORITY()` 创建修改优先级的规则。

创建与管理过滤器的例子见[网络分组过滤示例](P202_网络数据包过滤示例.md#net-pkt-filter)。网络 shell 的 `net filter` 命令可在运行时查看已安装规则。

## 28.2\_使用示例（Examples）

下面的规则接受不超过 `200` 字节的 IP 分组，其他分组丢弃：

```c
static NPF_SIZE_MAX(maxsize_200, 200);
static NPF_ETH_TYPE_MATCH(ip_packet, NET_ETH_PTYPE_IP);

static NPF_RULE(small_ip_pkt, NET_OK, ip_packet, maxsize_200);

void install_my_filter(void)
{
    npf_insert_recv_rule(&npf_default_drop);
    npf_insert_recv_rule(&small_ip_pkt);
}
```

> 译注：这里的 IP 类型条件使用 `NET_ETH_PTYPE_IP`，即以太网中的 IPv4 类型；它不同时代表 IPv6。`npf_insert_recv_rule()` 插到列表开头，因此先插入默认丢弃，再插入放行规则，得到“先检查小 IPv4 分组，最后默认丢弃”的顺序。

另一种效率较低但实现相同筛选结果的方式是：

```c
static NPF_SIZE_MIN(minsize_201, 201);
static NPF_ETH_TYPE_UNMATCH(not_ip_packet, NET_ETH_PTYPE_IP);

static NPF_RULE(reject_big_pkts, NET_DROP, minsize_201);
static NPF_RULE(reject_non_ip, NET_DROP, not_ip_packet);

void install_my_filter(void) {
    npf_append_recv_rule(&reject_big_pkts);
    npf_append_recv_rule(&reject_non_ip);
    npf_append_recv_rule(&npf_default_ok);
}
```

先丢弃至少 `201` 字节的分组，再丢弃不是该 IP 类型的分组，最后默认接受。

下面的优先级示例，原文意图为：PTP 使用网络控制优先级（Network Control，`NET_PRIORITY_NC`），IPv6 使用关键应用优先级（Critical Applications，`NET_PRIORITY_CA`），IPv4 使用增强尽力优先级（Excellent Effort，`NET_PRIORITY_EE`），LLDP 和 ARP 使用最低的后台优先级（Background，`NET_PRIORITY_BK`）。

只有通过 [`CONFIG_NET_TC_RX_COUNT`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_TC_RX_COUNT) 启用多个接收流量类别队列时，优先级规则才具有实际调度意义。分组优先级到队列的映射遵循 IEEE 802.1Q，并取决于该队列数量。

```c
static NPF_ETH_TYPE_MATCH(is_arp, NET_ETH_PTYPE_ARP);
static NPF_ETH_TYPE_MATCH(is_lldp, NET_ETH_PTYPE_LLDP);
static NPF_ETH_TYPE_MATCH(is_ptp, NET_ETH_PTYPE_PTP);
static NPF_ETH_TYPE_MATCH(is_ipv4, NET_ETH_PTYPE_IP);
static NPF_ETH_TYPE_MATCH(is_ipv6, NET_ETH_PTYPE_IPV6);

static NPF_PRIORITY(priority_bk, NET_PRIORITY_BK, is_arp, is_lldp);
static NPF_PRIORITY(priority_ee, NET_PRIORITY_EE, is_ipv4);
static NPF_PRIORITY(priority_ca, NET_PRIORITY_CA, is_ipv6);
static NPF_PRIORITY(priority_nc, NET_PRIORITY_NC, is_ptp);

void install_my_filter(void) {
    npf_append_recv_rule(&priority_bk);
    npf_append_recv_rule(&priority_ee);
    npf_append_recv_rule(&priority_ca);
    npf_append_recv_rule(&priority_nc);
    npf_append_recv_rule(&npf_default_ok);
}
```

> 源码跟踪译注：原例的 `NPF_PRIORITY(priority_bk, NET_PRIORITY_BK, is_arp, is_lldp)` 要求 `is_arp` 和 `is_lldp` **同时成立**，不是“ARP 或 LLDP”。同一以太网类型字段不能同时匹配这两种类型，因此该规则不能实现原文意图。实际使用时可拆成两条规则，分别为 ARP 和 LLDP 设置 `NET_PRIORITY_BK`，依次加入列表；其他规则及最后的默认接受规则保持原逻辑。条件求值依据为 [`subsys/net/pkt_filter/base.c`](../../../subsys/net/pkt_filter/base.c) 的 `apply_tests()`，类型匹配依据为 [`ethernet.c`](../../../subsys/net/pkt_filter/ethernet.c)，读取摘要见[来源记录](../SOURCES.md)。原代码仍完整保留，本轮未执行过滤实验。
