# 第24章\_二层管理

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/api/net_l2.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 24.1\_概览（Overview）

二层协议栈（Layer 2，L2）向上层隐藏整个网络链路层（Link Layer）及相关设备驱动，其连接点是 [`include/zephyr/net/net_if.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/net_if.h) 中声明的 [`net_if`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__if.html)。

上层只需要了解接口对象，以及 [`include/zephyr/net/net_l2.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/net_l2.h) 中以 [`net_l2`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__l2.html) 提供的通用 API，不需要了解更下层的实现。只有 L2 与连接到接口的设备驱动交互；L2 决定该类驱动应提供的专用 API，使二者配合工作。

当前已有 Ethernet、IEEE 802.15.4 Soft-MAC、CANBUS、OpenThread、Wi-Fi 的 L2，以及可作为新实现模板的虚拟空层（Dummy Layer）。源码跟踪入口为 [`net_if.h`](../../../include/zephyr/net/net_if.h) 与 [`net_l2.h`](../../../include/zephyr/net/net_l2.h)。

## 24.2\_L2 层 API（L2 Layer API）

编写 L2 或对应驱动前，需要理解三层（L3）怎样与其交互，以及 L2 应如何响应；参见[网络协议栈架构](P003_网络协议栈架构.md#network-stack-architecture)。通用 L2 API 包括：

- **`recv()`**：驱动将收到的分组放入 [`net_pkt`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__pkt.html)，调用 [`net_recv_data()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__core.html#ga3421119d2b1797ee5d70f736a61f93b7) 交给协议栈。协议栈此时还不知道如何处理，将其转交 L2 的 `recv()`，由 L2 解析链路头、处理仅属于链路层的分组等。错误分组返回 `NET_DROP`；L2 已完整处理分组返回 `NET_OK`；需要上层继续处理则返回 `NET_CONTINUE`。
- **`send()`**：协议栈调用它实际发送分组，相关链路层内容由此函数生成并加入。成功返回发送的字节数，失败返回负错误码。
- **`enable()`**：启用或禁用接口上的流量。返回值 `<0` 表示错误，`>=0` 表示成功。
- **`get_flags()`**：返回 L2 驱动能力，例如是否支持多播（Multicast）或混杂模式（Promiscuous Mode）。

## 24.3\_网络设备驱动（Network Device Drivers）

网络驱动以 Zephyr 的[设备驱动模型（Device Driver Model）](https://docs.zephyrproject.org/latest/kernel/drivers/index.html#device-model-api)为基础，但有两点区别：

1. `driver_api` 必须指向有效的 `net_if_api`。
2. 使用 [`NET_DEVICE_INIT_INSTANCE()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__if.html#gacc7edecdd9de9920cc155977d8fec2a2)；以太网设备则使用 [`ETH_NET_DEVICE_INIT()`](https://docs.zephyrproject.org/latest/doxygen/html/group__ethernet.html#ga197e02748be8eaf410f7deb57c984642)。这些宏调用 [`DEVICE_DEFINE()`](../device_reference/P001_设备模型公共接口.md#gac12521f4d900e8947aac45c1b228366d)，并为创建的设备驱动实例建立关联的独立 [`net_if`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__if.html)。

驱动具体实现取决于所属 L2，例如 Ethernet 或 IEEE 802.15.4。以下只描述分组收发行为，其他硬件相关细节不在本页展开。

### 24.3.1\_以太网驱动（Ethernet Device Driver）

接收时，驱动根据数据量为分组准备所需缓冲区。分组本体为 [`net_pkt`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__pkt.html)，应通过 `net_pkt_rx_alloc_with_buffer()` 分配；配套的数据缓冲区由该分配流程准备，再用 [`net_pkt_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt.html#gae99eadd977b7f66ecc91d2ccba34c6fa) 写入收到的数据。

全部网络数据收到后，驱动调用 [`net_recv_data()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__core.html#ga3421119d2b1797ee5d70f736a61f93b7)。若调用失败，驱动负责通过 [`net_pkt_unref()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt.html#ga893d1660fd18ad5842224fda78466099) 释放分组引用。

发送时，驱动的发送函数被调用，驱动必须把整个分组及其全部缓冲区作为完整分组发送。每个以太网驱动最终都需要如下调用：

```c
ETH_NET_DEVICE_INIT(..., CONFIG_ETH_INIT_PRIORITY,
                    &the_valid_net_if_api_instance, 1500);
```

> 译注：原文把缓冲区自动分配和 [`net_pkt_write()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__pkt.html#gae99eadd977b7f66ecc91d2ccba34c6fa) 写入连在一起描述；写入 API 本身不能代替分配步骤，无法满足请求长度时会报错。宏中的省略号也是原文占位，并非可原样编译的完整驱动。

### 24.3.2\_IEEE 802.15.4 驱动

这类驱动与以太网基本相同，尤其前述接收规则同样适用，但有两个主要差异。

首先，使用扩展 `net_if_api` 的专用 [`ieee802154_radio_api`](https://docs.zephyrproject.org/latest/doxygen/html/structieee802154__radio__api.html)。IEEE 802.15.4 L2 所需能力超过普通 `send()`、`recv()`，因此每个驱动必须提供正确填写的专用 API 结构指针，定义见 [`include/zephyr/net/ieee802154_radio.h`](../../../include/zephyr/net/ieee802154_radio.h)。

其次，发送方式不同。多数 IEEE 802.15.4 PHY 只支持较小的帧：包含帧头、载荷（Payload）与帧校验在内共 `127` 字节。IPv6 等分组往往超过限制，需要先分片（Fragmentation），并通过 6LoWPAN 等协议压缩分组头及相关片段，再交给无线驱动。

标准还规定载波侦听多路访问／冲突避免（CSMA/CA）、帧重传、加密及添加信息元素等预处理，独立无线驱动不应各自重复这些工作。因此 [`ieee802154_radio_api`](https://docs.zephyrproject.org/latest/doxygen/html/structieee802154__radio__api.html) 的 `tx` 回调不同于 `net_if_api` 的 `send` 回调。

Zephyr 原生 L2 提供通用 `ieee802154_send()` 作为 [`net_if`](https://docs.zephyrproject.org/latest/doxygen/html/structnet__if.html) 的发送函数。它完成标准规定的分组准备，将分组拆成可能已压缩、加密或经过其他处理的片段缓冲区，经 [`ieee802154_radio_api`](https://docs.zephyrproject.org/latest/doxygen/html/structieee802154__radio__api.html) 的 `tx` 一次发送一个；只有整个发送过程成功或失败后，才释放分组引用。

### 24.3.3\_IEEE 802.15.4 L1 与 L2 的双向交互

**L2 → L1**：`ieee802154_send()` 和 IEEE 802.15.4 网络管理操作调用驱动，例如发送无线分组或在运行时重新配置驱动。驱动通过 [`ieee802154_radio_api`](https://docs.zephyrproject.org/latest/doxygen/html/structieee802154__radio__api.html) 中的方法处理这些调用。

**L1 → L2**：驱动也可能主动调用 MAC 层。适配 API 采用控制反转（Inversion of Control）模式，在需要反向传递信息或与硬件紧密配合时，避免各驱动重复复杂逻辑，并保持媒体访问控制层（MAC，L2）与物理层（PHY，L1）之间的松散耦合和职责分离。

例如初始化时，驱动调用 [`ieee802154_init()`](https://docs.zephyrproject.org/latest/doxygen/html/group__ieee802154__driver.html#gad2a4cb5df84ffe20b83fc54dc9bcfc91)，把接口 MAC 地址及其他硬件配置传给 L2；也可通过 [`ieee802154_handle_ack()`](https://docs.zephyrproject.org/latest/doxygen/html/group__ieee802154__driver.html#ga68e1f89571ccbefef61a5496577337fc) 等向 L2 报告对性能或时序敏感的事件。

这些 L1 → L2 调用不是 [`ieee802154_radio_api`](https://docs.zephyrproject.org/latest/doxygen/html/structieee802154__radio__api.html) 的方法，而是在 [`include/zephyr/net/ieee802154_radio.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/ieee802154_radio.h) 中声明、说明的独立函数。API 文档会明确指出哪些函数属于控制反转适配 API，必须由全部 L2 实现提供。

**原文注意**：该头文件中未明确标为回调的独立函数，应理解为与具体 L2 无关的 PHY 层辅助函数，例如 [`ieee802154_is_ar_flag_set()`](https://docs.zephyrproject.org/latest/doxygen/html/group__ieee802154__driver.html#gaf5d7bdde2a9774f9d90604a6e203bb07)。

与其他网络接口一样，IEEE 802.15.4 驱动最后需要调用 [`NET_DEVICE_INIT_INSTANCE()`](https://docs.zephyrproject.org/latest/doxygen/html/group__net__if.html#gacc7edecdd9de9920cc155977d8fec2a2)：

```c
NET_DEVICE_INIT_INSTANCE(...,
                         the_device_init_prio,
                         &the_valid_ieee802154_radio_api_instance,
                         IEEE802154_L2,
                         NET_L2_GET_CTX_TYPE(IEEE802154_L2), 125);
```
