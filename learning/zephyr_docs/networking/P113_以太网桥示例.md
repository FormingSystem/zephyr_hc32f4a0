# 第113章\_以太网桥示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/net/ethernet/bridge/README.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 1. 概述（Overview）

本示例用于测试和调试以太网桥（Ethernet Bridge）。源码位于 [`samples/net/ethernet/bridge`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/ethernet/bridge)，可[在 GitHub 查看官方源码](https://github.com/zephyrproject-rtos/zephyr/blob/main//samples/net/ethernet/bridge/README.rst/..)。

## 2. 构建和运行（Building and Running）

按下面的命令构建网桥示例应用：

```sh
west build -b <board to use> samples/net/ethernet/bridge -- -DCONF_FILE=prj.conf
```

> 译注——构建位置：从 Zephyr 源码根目录，在已准备好的构建终端中执行。`<board to use>` 是原文保留的板目标占位符，需要换成实际目标。示例目录和配置文件均为官方源码已有内容；编译完成后，仍需按所选目标的运行方式启动程序。

没有硬件开发板时，可以使用 `native_sim` 应用快速验证网桥。官方源码中的 [`samples/net/ethernet/bridge/bridge-test-setup.sh`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/ethernet/bridge/bridge-test-setup.sh) 提供主机设置脚本。步骤如下。

### 2.1 执行前置设置（Pre-setup）

运行脚本的前置设置阶段，创建 `zeth0` 和 `zeth1` 两个 TAP 接口：

```sh
bridge-test-setup.sh pre-setup
```

> 译注——脚本位置与权限：主机网络命令在 Linux Bash 中执行，需要创建 TAP 和网络命名空间的权限，通常以 root 身份运行。原文的裸脚本名要求该脚本位于命令搜索路径中；若从官方 [`samples/net/ethernet/bridge`](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/ethernet/bridge) 目录执行，应使用 `./bridge-test-setup.sh`，并保留原有子命令。后面的 `post-setup`、`clean` 同理。脚本来源见 [bridge-test-setup.sh](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/ethernet/bridge/bridge-test-setup.sh)。

### 2.2 启动模拟程序（Run native_sim）

运行已构建的 `native_sim` 应用。

### 2.3 执行后置设置（Post-setup）

运行脚本的后置设置阶段，把 `zeth1` 移入另一个网络命名空间（Network Namespace）。原文说明：不能在启动 `native_sim` 之前完成这一步，因为 Zephyr 接口似乎无法连接已经位于另一个网络命名空间中的接口。

```sh
bridge-test-setup.sh post-setup
```

> 译注——源码跟踪：当前脚本先在默认网络命名空间创建两块 TAP，再创建 `ns0` 并把 `zeth1` 移入其中。应保留“前置设置 → 启动应用 → 后置设置”的顺序。

### 2.4 测试网桥（Test Bridging）

测试 `zeth0` 与 `zeth1` 之间的桥接。IP 地址配置如下：

| 接口 | IPv4 | IPv6 |
| --- | --- | --- |
| `zeth0` | `192.0.2.2` | `2001:db8::2` |
| `zeth1` | `192.0.2.3` | `2001:db8::3` |

用 ping 探测另一个网络命名空间中的 `zeth1`：

```sh
ping 192.0.2.3
ping 2001:db8::3
```

> 译注——执行位置与结果：上述 ping 在 Linux 主机默认网络命名空间的 Bash 中执行，目标位于 `ns0`。收到响应表示测试流量已通过网桥到达目标；若失败，回查两个设置阶段、TAP 连接以及模拟程序运行状态。

### 2.5 清理（Clean up）

测试后执行清理：

```sh
bridge-test-setup.sh clean
```

> 译注——源码跟踪：当前脚本的清理分支删除 `zeth0` 和 `ns0`，命名空间内的 `zeth1` 随之移除。这些名称由示例固定使用；清理针对的是本次示例所创建的对象。
