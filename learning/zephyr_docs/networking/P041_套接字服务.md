# 第41章\_套接字服务

原文：[官方页面](https://docs.zephyrproject.org/latest/services/connectivity/networking/api/socket_service.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 41.1 概览（Overview）

套接字服务（Socket Service）API 可以安装一个处理函数（Handler），在套接字收到数据时调用。应用无需为每一种 TCP 或 UDP 服务单独创建专用线程；一个服务线程即可处理多个被监听的套接字，减少线程带来的内存占用。TCP 是传输控制协议（Transmission Control Protocol），UDP 是用户数据报协议（User Datagram Protocol）。

如何用该 API 创建基于 BSD 套接字（BSD Sockets）的简单服务器，见[套接字服务回显服务器示例](P043_套接字服务回显示例.md#sockets-service-echo)。源码位于[samples/net/sockets/echo_service](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/sockets/echo_service)。

## 41.2 接口说明（API Description）

通过 [`CONFIG_NET_SOCKETS_SERVICE`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_NET_SOCKETS_SERVICE) 启用套接字服务 API。主要操作如下：

| 接口 | 作用 |
| --- | --- |
| [`NET_SOCKET_SERVICE_SYNC_DEFINE`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#ga424f319f9ccc675f8eeca23cb2c91bc4) | 定义一个网络套接字服务，具有外部链接范围（Extern Scope），可由多个 C 源文件使用 |
| [`NET_SOCKET_SERVICE_SYNC_DEFINE_STATIC`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#gadee4c786ebf89706a6b0151244b55cc3) | 定义具有静态范围（Static Scope）的服务，只能在当前 C 源文件中使用 |
| [`net_socket_service_register()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#gaa72bb82aa413b711e61eda092504b091) | 将可轮询（Pollable）的套接字注册到服务；调用前必须先创建套接字 |
| [`net_socket_service_unregister()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#gae2d4eea01c9ea4e6a48315681e05afd6) | 从服务中移除可轮询套接字；调用后才可关闭这些套接字 |
| [`net_socket_service_handler_t`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#ga5d9495470c1ade51791df56c59cfb1f5) | 用户指定的回调函数（Callback），在被监听的套接字收到数据时调用 |

> 源码核对译注：上述 `SYNC` 宏定义同步服务（Synchronous Service）。服务线程调用回调后要等它返回，不能把它理解为每个套接字各有一个并行执行的回调线程。避免在回调中长时间阻塞其他套接字的处理。定义见官方 [`socket_service.h`](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/net/socket_service.h)，调用过程见 [`sockets_service.c`](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/net/lib/sockets/sockets_service.c)。

## 41.3 应用流程（Application Overview）

启用套接字服务 API 后，应用先创建服务。以下保留官方示例代码：

```c
#define MAX_BUF_LEN 1500
#define MAX_SERVICES 1

static void udp_service_handler(struct net_socket_service_event *pev)
{
     struct pollfd *pfd = &pev->event;
     int client = pfd->fd;
     struct sockaddr_in6 addr;
     socklen_t addrlen = sizeof(addr);

     /* In this example we use one static buffer in order to avoid
      * having a large stack.
      */
     static char buf[MAX_BUF_LEN];

     len = recvfrom(client, buf, sizeof(buf), 0,
                    (struct sockaddr *)&addr, &addrlen);
     if (len <= 0) {
             /* Error */
             ...
             return;
     }

     /* Do something with the received data. The pev variable contains
      * user data that was stored in the socket service when it was
      * registered.
      */
}

NET_SOCKET_SERVICE_SYNC_DEFINE_STATIC(service_udp, udp_service_handler, MAX_SERVICES);
```

该处理函数从事件的 `pollfd` 中获取套接字，用 `recvfrom()` 接收数据。示例使用一个静态缓冲区（Static Buffer），避免为 1500 字节缓冲区占用较大的线程栈。`pev` 还包含注册服务时保存的用户数据（User Data）。

> 译注：这是说明片段，原文的 `len` 未声明，省略号也不是完整 C 实现。实际应用须声明接收长度并补齐处理逻辑。UDP 接收到合法的零长度数据报时，接收长度可以为零；原文 `len <= 0` 分支不能直接当成通用 UDP 错误判定，也不能像 TCP 一样把零解释为对端关闭连接。

应用创建套接字并注册到服务后，服务线程会在有数据到达时调用回调：

```c
/* Create one or multiple sockets */

struct pollfd sockfd_udp[1] = { 0 };
int sock, ret;

sock = socket(AF_INET6, SOCK_DGRAM, IPPROTO_UDP);
if (sock < 0) {
     LOG_ERR("socket: %d", -errno);
     return -errno;
}

/* Set possible socket options after creation */
...

/* Then bind the socket to local address */
if (bind(sock, (struct sockaddr *)addr, sizeof(*addr)) < 0) {
     LOG_ERR("bind: %d", -errno);
     return -errno;
}

/* Set the polled sockets */
sockfd_udp[0].fd = sock;
sockfd_udp[0].events = POLLIN;

/* Register UDP socket to service handler */
ret = net_socket_service_register(&service_udp, sockfd_udp,
                                  ARRAY_SIZE(sockfd_udp), NULL);
if (ret < 0) {
     LOG_ERR("Cannot register socket service handler (%d)", ret);
     return ret;
}

/* Application logic happens here. When application is ready to
 * quit, one should unregister the socket service and close the
 * socket.
 */

(void)net_socket_service_unregister(&service_udp);
close(sock);
```

流程是创建 UDP 套接字、设置所需选项、绑定本地地址（Bind），再把描述符和 `POLLIN` 事件放进 `pollfd` 数组，调用 [`net_socket_service_register()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#gaa72bb82aa413b711e61eda092504b091)。退出时先注销服务，再关闭套接字。

> 译注：这里的地址 `addr` 及部分应用逻辑由上下文提供。原文简略的错误分支也未展示全部资源清理；不能直接拼接这些片段作为已验证的完整程序。

TCP 的逻辑略有不同：接收连接（Accept）后，需要通过 [`net_socket_service_register()`](https://docs.zephyrproject.org/latest/doxygen/html/group__bsd__socket__service.html#gaa72bb82aa413b711e61eda092504b091) 把已接受的客户端套接字纳入服务监听的集合：

```c
struct sockaddr_in6 client_addr;
socklen_t client_addr_len = sizeof(client_addr);
struct pollfd sockfd_tcp[1] = { 0 };
int client;

/* TCP socket service is created similar way as the UDP one */
sock = socket(AF_INET6, SOCK_STREAM, IPPROTO_TCP);
if (sock < 0) {
     LOG_ERR("socket: %d", -errno);
     return -errno;
}

if (bind(sock, (struct sockaddr *)addr, sizeof(*addr)) < 0) {
     LOG_ERR("bind: %d", -errno);
     return -errno;
}

if (listen(sock, 5) < 0) {
     LOG_ERR("listen: %d", -errno);
     return -errno;
}

while (1) {
     client = accept(tcp_sock, (struct sockaddr *)&client_addr,
                     &client_addr_len);
     if (client < 0) {
             LOG_ERR("accept: %d", -errno);
             continue;
     }

     inet_ntop(client_addr.sin6_family, &client_addr.sin6_addr,
               addr_str, sizeof(addr_str));
     LOG_INF("Connection from %s (%d)", addr_str, client);

     sockfd_tcp[0].fd = client;
     sockfd_tcp[0].events = POLLIN;

     /* Register all the sockets to service handler */
     ret = net_socket_service_register(&service_tcp, sockfd_tcp,
                                       ARRAY_SIZE(sockfd_tcp), NULL);
     if (ret < 0) {
             LOG_ERR("Cannot register socket service handler (%d)", ret);
             break;
     }
}
```

> 源码核对译注：原文先把监听套接字保存到 `sock`，后面却调用 `accept(tcp_sock, ...)`，名称不一致；应用应使用实际的监听描述符。注册函数先清理服务现有事件，再复制传入数组，效果是替换监听集合，并非自动追加连接。原文 `sockfd_tcp[1]` 只有一个位置，每次写入新的 `client` 会替换之前的描述符。需要同时保留多个客户端时，必须自行维护足够容量的数组，注册完整的当前集合，并使服务声明的容量与之匹配。依据为官方 [`net_socket_service_register()` 实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/net/lib/sockets/sockets_service.c)。

TCP 客户端连接关闭后，需要将其套接字从轮询列表中移除：

```c
/* If the TCP socket is closed while reading the data in the handler,
 * mark it as non pollable.
 */
if (sockfd_tcp[0].fd == client) {
     sockfd_tcp[0].fd = -1;

     /* Update the handler so that client connection is
      * not monitored any more.
      */
      (void)net_socket_service_register(&service_tcp, sockfd_tcp,
                                        ARRAY_SIZE(sockfd_tcp), NULL);
      close(client);

      LOG_INF("Connection from %s closed", addr_str);
}
```

该片段将相应文件描述符设置为 `-1`，重新注册更新后的数组，使服务不再监视该连接，最后关闭客户端套接字。

更完整的实现见[echo_service 示例的 src/main.c](https://github.com/zephyrproject-rtos/zephyr/blob/main/samples/net/sockets/echo_service/src/main.c)。以上是官方说明片段及明确标注的源码核对译注，本轮未执行构建或实际 TCP/UDP 通信。
