# 第33章\_系统电源管理钩子

原文：[group__subsys__pm__sys__hooks](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__hooks.html)。读取日期：2026-10-13，`latest`。

系统电源管理（Power Management，PM）通过以下钩子（Hook）执行片上系统（System on Chip，SoC）专用的进入低功耗和恢复操作。使用头文件 `zephyr/pm/pm.h`。

## 33.1\_进入电源状态

<a id="gaa5c707f5c9c14494a388c6c2144e8f61"></a>

```c
void pm_state_set(enum pm_state state, uint8_t substate_id);
```

实现将处理器置入可用电源状态所需的 SoC 专用细节。参数 [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是电源状态，`substate_id` 是电源子状态标识。

选择 Kconfig 配置选项 `CONFIG_PM_STATE_SET_IRQ_UNLOCKED` 的实现，可以继续采用在本钩子中解除中断屏蔽的旧行为。其他实现不得在本钩子中解除中断屏蔽，也不得以其他方式分派挂起的唤醒源中断服务程序（Interrupt Service Routine，ISR）。架构辅助函数可以紧邻低功耗指令调整中断状态；内核空闲路径在 PM 恢复收尾工作完成后恢复原始中断状态。

当系统 PM 在恢复期间保持中断锁定时，恢复顺序保证只涵盖 [`arch_irq_lock()`](../fatal_irq_reference/P008_架构中断接口.md#ga25bca3069cb999b6d4f924b87bf7de38) 能屏蔽的中断。零延迟中断（Zero-Latency Interrupt，`IRQ_ZERO_LATENCY`）不在此顺序保证之内，必须能在 PM 唤醒期间安全执行；否则，在系统状态不允许其 ISR 执行的期间，必须屏蔽或禁用对应中断源。

## 33.2\_退出睡眠后的操作

```c
void pm_state_exit_post_ops(enum pm_state state, uint8_t substate_id);
```

在退出睡眠状态之后执行所需的 SoC 或架构专用后续操作。参数 [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是电源状态，`substate_id` 是电源子状态标识。

默认调用顺序是：系统管理的设备已经恢复，但 PM 退出通知与系统时钟的空闲退出记账（Idle-Exit Accounting）尚未执行，且中断仍被锁定。

启用 Kconfig 选项 `CONFIG_PM_EARLY_SYSTEM_TIMER_RESUME` 时，本钩子在系统时钟空闲退出记账和系统管理设备恢复之前执行。采用这一实验性顺序的平台必须保证本钩子不依赖设备已经恢复，例如在释放输入输出（Input/Output，I/O）保持或隔离时。

未选择 `CONFIG_PM_STATE_SET_IRQ_UNLOCKED` 的实现只能利用本钩子做硬件恢复操作，不得解除中断屏蔽或分派挂起的唤醒源 ISR；内核空闲路径在 PM 恢复收尾工作结束后恢复原始中断状态。

**无论哪一种调用顺序，本钩子执行时系统定时器都尚未重新启动。**如果低功耗状态停止了该定时器，依赖它等待的代码，例如基于定时器的 [`k_busy_wait()`](../thread_core_reference/P001_线程公共接口.md#ga550b642e071480323e589866abb99c22)，可能永远无法返回。

与 [`pm_state_set()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__hooks.html#gaa5c707f5c9c14494a388c6c2144e8f61) 一样，恢复期间保持中断锁定的顺序保证仅覆盖 [`arch_irq_lock()`](../fatal_irq_reference/P008_架构中断接口.md#ga25bca3069cb999b6d4f924b87bf7de38) 能屏蔽的中断。`IRQ_ZERO_LATENCY` 零延迟中断可能在恢复窗口中、本钩子完成之前运行，因此必须满足上节所述的 PM 唤醒安全要求。
