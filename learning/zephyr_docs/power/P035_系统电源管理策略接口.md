# 第35章\_系统电源管理策略接口

原文：[group__subsys__pm__sys__policy](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html)。读取日期：2026-10-13，`latest`。

系统电源管理（Power Management，PM）策略应用程序编程接口（Application Programming Interface，API）自 Zephyr 2.7 提供，版本1.0.0，使用头文件 `zephyr/pm/policy.h`。涉及延迟变化订阅结构 [`pm_policy_latency_subscription`](P044_电源策略延迟订阅结构.md)、延迟请求结构 [`pm_policy_latency_request`](P043_电源策略延迟请求结构.md) 和事件结构 [`pm_policy_event`](P042_电源策略事件结构.md)。

## 35.1\_所有子状态与延迟回调

宏 [`PM_ALL_SUBSTATES`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gab241e40f9282a1c8ebc602997fbb3190) 是表示“全部子状态”的特殊值：

```c
#define PM_ALL_SUBSTATES (UINT8_MAX)
```

最大延迟变化时使用以下回调（Callback）类型通知：

```c
typedef void (*pm_policy_latency_changed_cb_t)(int32_t latency);
```

`latency` 是新的最大延迟。正值表示微秒数；`SYS_FOREVER_US` 表示解除延迟约束；禁止其他值。

## 35.2\_单个电源状态锁

```c
void pm_policy_state_lock_get(enum pm_state state, uint8_t substate_id);
void pm_policy_state_lock_put(enum pm_state state, uint8_t substate_id);
bool pm_policy_state_lock_is_active(enum pm_state state, uint8_t substate_id);
bool pm_policy_state_is_available(enum pm_state state, uint8_t substate_id);
```

这四个函数的 [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 都表示电源状态，`substate_id` 表示子状态标识；传入 `PM_ALL_SUBSTATES` 可作用于该状态的全部子状态。

[`pm_policy_state_lock_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gabbb379f8572f164addafe93ad3468f3d) 增加状态锁计数。第一次调用后不再允许使用该状态，后续调用继续增加引用计数（Reference Count），因此接口可安全并发使用。只有 [`pm_policy_state_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga12f4d121aa8be0eb66381713b481a8b1) 调用次数与 `get()` 相等后，才重新允许使用该状态。活动状态 `PM_STATE_ACTIVE` 始终允许使用，对它调用本接口没有效果。

[`pm_policy_state_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga12f4d121aa8be0eb66381713b481a8b1) 减少锁计数。

[`pm_policy_state_lock_is_active()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga39f14c8509dee55ed084b4111584b766) 检查锁是否生效，即该状态是否被禁止；生效返回 [`true`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a41f9c5fb8b08eb5dc3edce4dcb37fee7)，否则返回 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727)。

[`pm_policy_state_is_available()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga1c8634f68224aa64f05a373dfad5cb09) 检查状态是否可用。状态被锁定，或无法满足延迟要求时，都不可用；可用返回 [`true`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a41f9c5fb8b08eb5dc3edce4dcb37fee7)，不可用返回 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727)。

## 35.3\_全部状态锁与快速检查

```c
void pm_policy_state_all_lock_get(void);
void pm_policy_state_all_lock_put(void);
bool pm_policy_state_any_active(void);
```

[`pm_policy_state_all_lock_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gae81343e186bcef8732c700bc1e3e207b) 请求锁定所有电源状态，请求使用引用计数；[`pm_policy_state_all_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gadd21b48a4cadb7c05e74ff7fdd335386) 释放对所有状态的锁定。

[`pm_policy_state_any_active()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga0c4fee04c7434e2ba741be8d5b1036c6) 快速检查是否还有可用电源状态，使挂起操作可以提前退出。存在任一可用状态返回 [`true`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a41f9c5fb8b08eb5dc3edce4dcb37fee7)，所有状态均不可用返回 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727)。

## 35.4\_应用与移除约束集合

```c
void pm_policy_state_constraints_get(struct pm_state_constraints *constraints);
void pm_policy_state_constraints_put(struct pm_state_constraints *constraints);
```

`constraints` 指向要应用或移除的电源状态约束集合。

[`pm_policy_state_constraints_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga43ad016f054543cf96c2362ccf12d29a) 锁定列表中所有约束的并集涉及的状态。每项约束都通过增加引用计数参与锁定，就像分别对各约束状态调用 [`pm_policy_state_lock_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gabbb379f8572f164addafe93ad3468f3d)。

[`pm_policy_state_constraints_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga7965f17a8a82ea107f0cdd1afdc93afa) 解除先前以相同约束集合调用 `get()` 时建立的锁定，对约束并集中的每个受影响状态减少锁计数。译注：原文将其对应的单状态释放函数写为 `pm_policy_state_put`，本页实际声明的函数是 [`pm_policy_state_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga12f4d121aa8be0eb66381713b481a8b1)。

## 35.5\_按设备锁定电源状态

```c
void pm_policy_device_power_lock_get(const struct device *dev);
void pm_policy_device_power_lock_put(const struct device *dev);
bool pm_policy_device_is_disabling_state(const struct device *dev,
                                         enum pm_state state, uint8_t substate_id);
```

`dev` 是设备引用。[`pm_policy_device_power_lock_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga708b7d2f8cb5f09738e3c6e5937c475e) 对所有会关闭该设备供电的电源状态增加锁；[`pm_policy_device_power_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gafb90036c42bce2cc44466427b2907a81) 移除这些锁，分别对应单状态的 [`pm_policy_state_lock_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gabbb379f8572f164addafe93ad3468f3d) 与 [`pm_policy_state_lock_put()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga12f4d121aa8be0eb66381713b481a8b1)。

[`pm_policy_device_is_disabling_state()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga4cfc3c450387663b6e1bf9bb966baad8) 让调用方检查 [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90)、`substate_id` 所指定的状态是否禁用 `dev`。会禁用返回 [`true`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a41f9c5fb8b08eb5dc3edce4dcb37fee7)，否则返回 [`false`](https://docs.zephyrproject.org/latest/doxygen/html/stdbool_8h.html#a65e9886d74aaee76545e83dd09011727)。

## 35.6\_登记、更新和注销事件

```c
void pm_policy_event_register(struct pm_policy_event *evt, int64_t uptime_ticks);
void pm_policy_event_update(struct pm_policy_event *evt, int64_t uptime_ticks);
void pm_policy_event_unregister(struct pm_policy_event *evt);
```

策略中的事件（Event）指将在未来已知时刻唤醒系统的任何来源。登记事件后，策略管理器可以判断是否值得进入某种电源状态。事件按系统运行时间节拍（Uptime Tick）跟踪，计算下次唤醒时间时取最早事件。

`evt` 为事件对象，`uptime_ticks` 为事件发生的运行时间节拍值。一个对象在任一时刻最多登记一次；重复登记已注册对象的行为等同于 [`pm_policy_event_update()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga059074d867befbe9c6b7afc170ee09b3)。

唤醒后，中央处理器（Central Processing Unit，CPU）应保持唤醒，直到事件已处理。处理完成通过注销事件，或调用 [`pm_policy_event_update()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga059074d867befbe9c6b7afc170ee09b3) 将事件移至未来来表示。

[`pm_policy_event_update()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga059074d867befbe9c6b7afc170ee09b3) 直接移动事件时间，不必先注销再登记；对象当前未登记时无效果。[`pm_policy_event_unregister()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga9448e31e1bd1a8b02defe6d1427197ff) 注销事件；对象当前未登记时同样无效果。

## 35.7\_距下一个事件的节拍数

```c
int64_t pm_policy_next_event_ticks(void);
int64_t pm_policy_next_custom_ticks(void);
```

[`pm_policy_next_event_ticks()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gae2680fcc323e161362e4a5aa5339ac12) 返回到最早已登记事件的相对超时，单位为运行时间节拍。事件在未来时返回正节拍数，已到期或时间已过时返回 `0`，没有登记事件时返回 `-1`。

返回节拍数不受睡眠决策所用32位时间范围限制。`pm_system_suspend()` 在传给 `pm_policy_next_state()` 之前，将值饱和限制到 `SYS_CLOCK_MAX_WAIT`。因此，更远的事件与恰好位于此上限的事件选择相同状态，不会发生截位。

[`pm_policy_next_custom_ticks()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga66ec68b1873f7e694a55608e9ad6ee5d) 是可选钩子（Hook），提供来自专有或硬件特定来源、未通过普通事件机制建模的额外“下一个事件”节拍值。仅启用 Kconfig 配置选项 [`CONFIG_PM_CUSTOM_TICKS_HOOK`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_PM_CUSTOM_TICKS_HOOK) 时可用。

自定义事件在未来返回正节拍数，到期或已过返回 `0`，没有待处理自定义事件返回 `-1`。返回值同样在睡眠决策前饱和限制到 `SYS_CLOCK_MAX_WAIT`，因此钩子可以报告任意遥远事件，无须单独处理32位范围边界。

## 35.8\_最大延迟请求

```c
void pm_policy_latency_request_add(struct pm_policy_latency_request *req, uint32_t value_us);
void pm_policy_latency_request_update(struct pm_policy_latency_request *req, uint32_t value_us);
void pm_policy_latency_request_remove(struct pm_policy_latency_request *req);
```

`req` 是延迟请求对象，`value_us` 是最大允许延迟，单位为微秒。

[`pm_policy_latency_request_add()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga848627f6d143ece582711a16cab5442a) 增加新的延迟要求；系统不会进入会使系统超过该延迟值的状态。[`pm_policy_latency_request_update()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga6483bd320881d697de27493b4f2d92d1) 更新为新的微秒上限。[`pm_policy_latency_request_remove()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gaadcb851b1bfb312ea0960918dc9f869e) 移除该延迟要求。

## 35.9\_订阅最大延迟变化

```c
void pm_policy_latency_changed_subscribe(struct pm_policy_latency_subscription *req,
                                         pm_policy_latency_changed_cb_t cb);
void pm_policy_latency_changed_unsubscribe(struct pm_policy_latency_subscription *req);
```

`req` 是订阅请求对象。[`pm_policy_latency_changed_subscribe()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gacf77adf6eaf5258e03ce1923d685ed3b) 订阅最大延迟变化，`cb` 为回调函数，传 `NULL` 表示禁用；[`pm_policy_latency_changed_unsubscribe()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga8ca62cfeef8d4ebb58800e3ac6b645ee) 取消订阅。
