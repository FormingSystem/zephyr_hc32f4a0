# 第34章\_电源状态接口

原文：[group__subsys__pm__states](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html)。读取日期：2026-10-13，`latest`。

系统电源管理（Power Management，PM）状态接口使用头文件 `zephyr/pm/state.h`。结构 [`pm_state_info`](P047_电源状态信息结构.md) 保存状态信息；[`pm_state_constraint`](P045_电源状态约束结构.md) 保存将电源状态用于设备或系统功能约束所需的信息；[`pm_state_constraints`](P046_电源状态约束集合.md) 表示多个状态约束的集合。

## 34.1\_受支持且启用的状态数量

译注：下方原始宏值中的 `DT_*` 标识属于设备树辅助宏：例如 `DT_ENUM_IDX` 读取枚举属性的索引，`DT_PROP` 读取属性，`DT_PROP_LEN_OR` 读取属性长度或采用默认值，`DT_NODELABEL` 由节点标签取得标识。`LISTIFY` 是按数量重复展开的工具宏，`Z_PM_*` 是本接口实现所用的内部辅助宏；保留原名便于对照头文件。

宏 `DT_NUM_CPU_POWER_STATES(node_id)` 接收中央处理器（Central Processing Unit，CPU）的设备树（Devicetree，DT）节点标识，返回该节点支持且启用的电源状态数量。原页宏值：

```c
COND_CODE_1(DT_NODE_HAS_PROP(node_id, cpu_power_states),                                   \
            (DT_FOREACH_PROP_ELEM_SEP(node_id, cpu_power_states, Z_DT_PHANDLE_01, (+))),   \
            (0))
```

## 34.2\_初始化单项约束

宏 `PM_STATE_CONSTRAINT_INIT(node_id)` 使用设备树信息初始化设备 PM 约束，`node_id` 为节点标识。宏值：

```c
{                                                                     \
        .state = PM_STATE_DT_INIT(node_id),                           \
        .substate_id = DT_PROP_OR(node_id, substate_id, 0),           \
}
```

## 34.3\_取得约束集合

宏 `PM_STATE_CONSTRAINTS_GET(node_id, prop)` 生成包含约束列表指针及约束数量的结构初始化值，适合初始化 [`pm_state_constraints`](P046_电源状态约束集合.md)。必须先对相同属性调用 [`PM_STATE_CONSTRAINTS_LIST_DEFINE()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#ga0d2e6b304792a15ddb8736e04664ffa6)，才能引用对应约束数组。`node_id` 为设备树节点标识，`prop` 为包含电源状态节点引用（Phandle）列表的属性名。

```c
{                                                                                  \
        .list = Z_PM_STATE_CONSTRAINTS_LIST_NAME(node_id, prop),                   \
        .count = DT_PROP_LEN(node_id, prop),                                       \
}
```

## 34.4\_定义约束列表

宏 `PM_STATE_CONSTRAINTS_LIST_DEFINE(node_id, prop)` 创建 [`pm_state_constraint`](P045_电源状态约束结构.md) 结构数组，使用指定设备树属性中的电源状态信息初始化。`node_id` 是设备树节点标识，`prop` 是包含电源状态节点引用列表的属性名。

```c
struct pm_state_constraint Z_PM_STATE_CONSTRAINTS_LIST_NAME(node_id, prop)[] =     \
{                                                                                  \
        DT_FOREACH_PROP_ELEM_SEP(node_id, prop, Z_PM_STATE_CONSTRAINT_REF, (,))    \
}
```

## 34.5\_初始化状态枚举与信息结构

`PM_STATE_DT_INIT(node_id)` 为 `enum pm_state` 生成初始化值。`node_id` 必须标识兼容属性为 `zephyr,power-state` 的节点。

```c
DT_ENUM_IDX(node_id, power_state_name)
```

`PM_STATE_INFO_DT_INIT(node_id)` 为 `struct pm_state_info` 生成初始化值，要求同样的节点兼容属性。

```c
{                                                                      \
        .state = PM_STATE_DT_INIT(node_id),                            \
        .substate_id = DT_PROP_OR(node_id, substate_id, 0),            \
        .min_residency_us = DT_PROP_OR(node_id, min_residency_us, 0),  \
        .exit_latency_us = DT_PROP_OR(node_id, exit_latency_us, 0),    \
        .pm_device_disabled = DT_PROP(node_id, zephyr_pm_device_disabled),    \
}
```

## 34.6\_从CPU节点生成状态信息数组

宏 `PM_STATE_INFO_LIST_FROM_DT_CPU(node_id)` 根据 CPU 节点中全部存在且启用的状态，初始化 `struct pm_state_info` 数组。参数 `node_id` 是 CPU 节点标识。

```c
{                                                                      \
        LISTIFY(DT_PROP_LEN_OR(node_id, cpu_power_states, 0),          \
                Z_PM_STATE_INFO_FROM_DT_CPU, (), node_id)              \
}
```

设备树片段示例：

```devicetree
cpus {
   ...
   cpu0: cpu@0 {
           device_type = "cpu";
           ...
           cpu-power-states = <&state0 &state1>;
   };

   power-states {
           state0: state0 {
                   compatible = "zephyr,power-state";
                   power-state-name = "suspend-to-idle";
                   min-residency-us = <10000>;
                   exit-latency-us = <100>;
           };

           state1: state1 {
                   compatible = "zephyr,power-state";
                   power-state-name = "suspend-to-ram";
                   min-residency-us = <50000>;
                   exit-latency-us = <500>;
                   zephyr,pm-device-disabled;
           };
   };
};
```

用法示例：

```c
const struct pm_state_info states[] =
     PM_STATE_INFO_LIST_FROM_DT_CPU(DT_NODELABEL(cpu0));
```

## 34.7\_从CPU节点生成状态枚举数组

宏 `PM_STATE_LIST_FROM_DT_CPU(node_id)` 根据 CPU 节点中全部存在且启用的状态初始化状态数组，参数为 CPU 节点标识。译注：原文描述误写为 `struct pm_state`，但其下方用法明确声明为 `enum pm_state` 数组；这里按实际示例说明。

```c
{                                                                      \
        LISTIFY(DT_PROP_LEN_OR(node_id, cpu_power_states, 0),          \
                Z_PM_STATE_FROM_DT_CPU, (), node_id)                   \
}
```

设备树片段示例：

```devicetree
cpus {
   ...
   cpu0: cpu@0 {
           device_type = "cpu";
           ...
           cpu-power-states = <&state0 &state1>;
   };

   power-states {
           state0: state0 {
                   compatible = "zephyr,power-state";
                   power-state-name = "suspend-to-idle";
                   min-residency-us = <10000>;
                   exit-latency-us = <100>;
           };

           state1: state1 {
                   compatible = "zephyr,power-state";
                   power-state-name = "suspend-to-ram";
                   min-residency-us = <50000>;
                   exit-latency-us = <500>;
           };
   };
};
```

用法示例：

```c
const enum pm_state states[] = PM_STATE_LIST_FROM_DT_CPU(DT_NODELABEL(cpu0));
```

## 34.8\_电源状态枚举

枚举 `enum pm_state` 定义以下状态。高级配置与电源接口（Advanced Configuration and Power Interface，ACPI）对应关系按原文保留。

| 枚举值 | 状态与行为 | ACPI对应状态 |
| --- | --- | --- |
| [`PM_STATE_ACTIVE`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a383b8ef562f50d7a3d18914d3c950743) | 运行时活动（Runtime Active）：系统完全上电并处于活动状态 | G0/S0 |
| [`PM_STATE_RUNTIME_IDLE`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a73c76572bc04e999d22a3bded9c54b19) | 运行时空闲（Runtime Idle）：所有核心进入尽可能深的空闲状态并等待中断，不要求设备改变状态，设备保持原状态 | S0ix |
| [`PM_STATE_SUSPEND_TO_IDLE`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a781f940d30738d746eb2523155950fc0) | 挂起到空闲（Suspend to Idle）：执行正常的平台挂起，所有核心进入尽可能深的空闲状态，并可能将外设置为低功耗；不丢失工作状态，即 CPU 核不丢失执行上下文，因此能较容易地从先前停下的位置恢复 | S1 |
| [`PM_STATE_STANDBY`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a19a09872876d4732d0aebb82e52f2429) | 待机（Standby）：除外设进入低功耗外，还关闭所有非启动 CPU；通常比挂起到空闲更省电，但恢复延迟更大。在单处理器系统中，应与挂起到空闲为相同状态 | S2 |
| [`PM_STATE_SUSPEND_TO_RAM`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a363669b6a6db4bee5b8196442e9f2a00) | 挂起到随机存取存储器（Suspend to RAM）：尽可能关闭系统各部分以显著节能；内存应进入自刷新（Self-Refresh）以保留内容，设备和 CPU 状态保存在内存中，恢复可能需要只读存储器（Read-Only Memory，ROM）中的引导代码 | S3 |
| [`PM_STATE_SUSPEND_TO_DISK`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5acc7f38698db1ae08365115f8407c9695) | 挂起到磁盘（Suspend to Disk）：尽可能关闭系统，包括内存；内存内容写入磁盘或其他非易失存储，恢复时借助引导代码读回内存，使系统回到挂起时的执行位置 | S4 |
| [`PM_STATE_SOFT_OFF`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a18d180711616cd9ed59fbe27dd0dbf01) | 软关机（Soft Off）：功耗极低，但恢复到活动状态延迟很大；CPU和内存内容不保留，系统如初次上电及内核启动一样重新启动 | G2/S5 |
| [`PM_STATE_COUNT`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gga20e2f5ea9027a3653e5b9cc5aa1e21d5a97c44ed1a8b6873243d6bbd76a382737) | 电源管理状态数量，内部使用 | 不适用 |

## 34.9\_查询CPU状态

```c
uint8_t pm_state_cpu_get_all(uint8_t cpu, const struct pm_state_info **states);
const struct pm_state_info *pm_state_get(uint8_t cpu, enum pm_state state, uint8_t substate_id);
```

[`pm_state_cpu_get_all()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#ga682f75eb5324455ce95a5c7d4c2d6242) 获取 CPU 支持的所有状态信息，`cpu` 为 CPU 索引，`states` 接收受支持状态列表，返回受支持状态数量。

[`pm_state_get()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#ga7ae95c361448060420843c2ae6342f9c) 在分配给该 CPU 的全部状态及禁用状态中查找；`cpu` 是 CPU 索引，[`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 是电源状态，`substate_id` 是子状态。找到时返回状态结构指针，否则返回 `NULL`。

## 34.10\_状态与字符串转换

```c
const char *pm_state_to_str(enum pm_state state);
int pm_state_from_str(const char *name, enum pm_state *out);
```

[`pm_state_to_str()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gac3b058822bd4f9e73c8ef053fd66bdba) 将参数 [`state`](https://docs.zephyrproject.org/latest/doxygen/html/parser__state_8h.html#adc6e5733fc3c22f0a7b2914188c49c90) 转换为对应的常量字符串并返回。

[`pm_state_from_str()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__states.html#gaa8b05b5453f956f424f439ff12b4e3f4) 解析输入字符串 `name`，例如 `"suspend-to-ram"`，通过 `out` 存储解析后的枚举值。成功返回 `0`，字符串无效或为 `NULL` 时返回无效参数错误 `-EINVAL`（Invalid Argument）。

## 34.11\_约束匹配

```c
bool pm_state_in_constraints(const struct pm_state_constraints *constraints,
                             const struct pm_state_constraint match);
```

检查约束 `match` 是否匹配 `constraints` 指向的约束集合中的任意一项。匹配返回 `true`，否则返回 `false`。
