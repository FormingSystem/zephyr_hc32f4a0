# 第50章\_电源策略延迟示例

原文：[PM policy latency](https://docs.zephyrproject.org/latest/samples/subsys/pm/latency/README.html)。读取日期：2026-10-13，`latest`。

## 50.1\_概述

设备树（Devicetree）中定义的每个电源状态都有退出延迟（Exit Latency），即硬件从该状态恢复所需的时间。本示例模拟以下电源状态：

| 状态 | 含义 | 退出延迟 |
| --- | --- | --- |
| `RUNTIME_IDLE` | 运行时空闲（Runtime Idle） | 10 ms |
| `SUSPEND_TO_IDLE` | 挂起到空闲（Suspend to Idle） | 20 ms |
| `STANDBY` | 待机（Standby） | 30 ms |

应用或驱动通过 [`pm_policy_latency_request_add()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga848627f6d143ece582711a16cab5442a) 登记能容忍的最大退出延迟。电源管理（Power Management，PM）策略随后禁止进入退出延迟超过该约束的状态。示例还展示如何用 [`pm_policy_latency_changed_subscribe()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gacf77adf6eaf5258e03ce1923d685ed3b) 订阅约束变化。

应用执行以下过程：

1. 没有延迟约束时依次睡眠，系统进入 `RUNTIME_IDLE`、`SUSPEND_TO_IDLE` 和 `STANDBY`。
2. 增加应用级30 ms约束，重复睡眠。`STANDBY` 的退出延迟恰好为30 ms，仍可进入。
3. 打开测试设备，设备登记自己的20 ms约束。合并后的最小值为20 ms，`STANDBY` 被禁止。
4. 使用 [`pm_policy_latency_request_update()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#ga6483bd320881d697de27493b4f2d92d1) 将应用约束更新为10 ms，此时只能进入 `RUNTIME_IDLE`。
5. 将应用约束恢复为30 ms并关闭测试设备；设备通过 [`pm_policy_latency_request_remove()`](https://docs.zephyrproject.org/latest/doxygen/html/group__subsys__pm__sys__policy.html#gaadcb851b1bfb312ea0960918dc9f869e) 移除自身20 ms约束。
6. 移除全部约束，系统进入 `STANDBY`。

## 50.2\_要求、构建与运行

示例运行于主机原生模拟目标 `native_sim`，要求 Linux 主机。

```shell
west build -b native_sim samples/subsys/pm/latency
west build -t run
```
