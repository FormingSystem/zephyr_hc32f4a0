# 第9章\_任务看门狗接口

原文：[group__task__wdt__api](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html)。读取日期：2026-10-13，`latest`。

任务看门狗（Task Watchdog）应用程序编程接口（Application Programming Interface，API）自 Zephyr 2.5 提供，本页接口版本为 0.8.0。使用头文件 `zephyr/task_wdt/task_wdt.h`。机制说明见[任务看门狗](P007_任务看门狗.md)。

## 9.1\_超时回调

```c
typedef void (*task_wdt_callback_t)(int channel_id, void *user_data);
```

任务看门狗回调（Callback）接收通道标识 `channel_id` 和关联的用户数据 `user_data`。

## 9.2\_初始化

```c
int task_wdt_init(const struct device *hw_wdt);
```

建立所需的内核定时器，并在需要后备保护（Fallback）时设置硬件看门狗。必须先调用本函数，再调用 [`task_wdt_add()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga26484bd148a9e2910d9989a1d9598230) 和 [`task_wdt_feed()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga00fc594cace06d6308efa1ded45a22fc)。

`hw_wdt` 指向作为后备保护的硬件看门狗设备；传入 `NULL` 表示不需要硬件后备看门狗。

| 返回值 | 含义 |
| --- | --- |
| `0` | 成功 |
| `-ENOTSUP` | 不支持指定硬件看门狗 |
| 负错误码 | 使用后备 `hw_wdt` 时，安装超时接口失败；具体值见 [`wdt_install_timeout()`](https://docs.zephyrproject.org/latest/doxygen/html/group__watchdog__interface.html#ga5be7aa7f1987be0e69c74b62d1c126a5) |

## 9.3\_添加超时通道

```c
int task_wdt_add(uint32_t reload_period, task_wdt_callback_t callback, void *user_data);
```

向任务看门狗通道列表添加新的超时项。

| 参数 | 含义 |
| --- | --- |
| `reload_period` | 用于重置超时的周期，单位为毫秒 |
| `callback` | 看门狗定时器到期时调用的函数；传入 `NULL` 使用系统复位处理函数 |
| `user_data` | 与该看门狗通道关联的用户数据 |

成功时返回非负的通道索引 `channel_id`，表示该超时项分配到的通道；后续调用 [`task_wdt_feed()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga00fc594cace06d6308efa1ded45a22fc) 时使用此标识。`reload_period` 无效时返回 `-EINVAL`；无法再安装超时项时返回 `-ENOMEM`。

## 9.4\_删除与喂狗

译注：本页的 `-EINVAL`、`-ENOMEM`、`-ENOTSUP` 是错误码标识，分别对应无效参数（Invalid Argument）、内存不足（Not Enough Memory）和不支持（Not Supported）。

```c
int task_wdt_delete(int channel_id);
int task_wdt_feed(int channel_id);
```

[`task_wdt_delete()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga631c1243b5a00a304687cc54e2632c0d) 从任务看门狗列表中删除指定通道；该通道随后可由其他任务通过 [`task_wdt_add()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga26484bd148a9e2910d9989a1d9598230) 再次使用。

[`task_wdt_feed()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga00fc594cace06d6308efa1ded45a22fc) 对指定通道喂狗（Feed）。它遍历所有已安装的任务看门狗，以接下来最早到期的超时时刻更新用于软件看门狗的内部内核定时器。

两者的 `channel_id` 都是 [`task_wdt_add()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga26484bd148a9e2910d9989a1d9598230) 返回的通道索引；成功返回 `0`，指定通道没有已安装的超时项时返回 `-EINVAL`。

## 9.5\_低功耗前暂停与恢复

```c
void task_wdt_suspend(void);
void task_wdt_resume(void);
```

[`task_wdt_suspend()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga53647130091f938ab22227e5ffd3649d) 在改变系统电源模式之前暂停所有通道：停止内部定时器，并在启用硬件看门狗时最后喂狗一次。调用后，系统应很快进入低功耗模式（Low-Power Mode）。若硬件支持在睡眠时暂停看门狗，需要启用 Kconfig 配置选项 [`CONFIG_TASK_WDT_HW_FALLBACK_PAUSE_IN_SLEEP`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_TASK_WDT_HW_FALLBACK_PAUSE_IN_SLEEP)。

[`task_wdt_resume()`](https://docs.zephyrproject.org/latest/doxygen/html/group__task__wdt__api.html#ga9beef1872ae55d7ab65295a70058c394) 恢复内部定时器并给所有通道喂狗。若启用了硬件看门狗，也给它喂狗，为应用恢复自行喂狗留出足够时间。
