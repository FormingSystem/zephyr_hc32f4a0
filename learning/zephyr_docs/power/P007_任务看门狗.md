# 第7章\_任务看门狗

原文：[Task Watchdog](https://docs.zephyrproject.org/latest/services/task_wdt/index.html)。读取日期：2026-10-12，`latest`。

许多微控制器带**硬件看门狗（Hardware Watchdog）**，用于在严重软件故障时触发恢复动作，通常是系统复位。初始化后，软件需定期重启计时，即“喂狗”；程序卡住、不再喂狗时，看门狗超时并触发恢复。

## 7.1\_多任务监控

实时操作系统中多个任务并行运行，单一看门狗实例未必足以分别监视每个任务。任务看门狗是基于内核定时器的软件看门狗，通过多个通道监控线程或任务。还可用已有硬件看门狗作为后备，在任务看门狗自身或调度器失效时提供保护。

后端使用内核定时器。如果配置正确，正常运行中喂狗调用会不断更新定时器，其超时 **中断服务例程（Interrupt Service Routine，ISR）** 实际不会触发。

目前不支持多个任务看门狗实例；**应用程序编程接口（Application Programming Interface，API）** 全局可用，增加或删除通道无须到处传递上下文或设备指针。最大通道数通过 Kconfig 预设，建议恰好匹配应用需要的数量。

> 译注：原文把单个硬件看门狗表述为“只能用于一个任务”，这里强调的是无法仅凭任意线程持续喂一个计时器，就独立证明所有线程都健康；多通道软件层用于补充这种监控粒度。

## 7.2\_配置与API

配置定义见 [subsys/task_wdt/Kconfig](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/task_wdt/Kconfig)，相关选项为：

- `CONFIG_TASK_WDT`。
- `CONFIG_TASK_WDT_CHANNELS`。
- `CONFIG_TASK_WDT_HW_FALLBACK`。
- `CONFIG_TASK_WDT_MIN_TIMEOUT`。
- `CONFIG_TASK_WDT_HW_FALLBACK_DELAY`。

接口见[任务看门狗 API](P009_任务看门狗接口.md)，[任务看门狗示例](P011_任务看门狗示例.md)演示监控线程。
