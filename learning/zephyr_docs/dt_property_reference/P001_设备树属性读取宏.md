### `DT_ENUM_IDX_BY_IDX`

```c
#define DT_ENUM_IDX_BY_IDX ( node_id, prop, idx )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
DT_CAT6(node_id, _P_, prop, _IDX_, idx, _ENUM_IDX)
```

获取属性数组值在其枚举（Enumeration）值列表中的索引。

返回值从 0 开始。

设备树片段示例：

原始示例（Example）：

```dts
some_node: some-node {
    compat = "vend,enum-string-array";
    foos =
        <&phandle val1>,
        <&phandle val2>,
        <&phandle val3>;
    foo-names = "default", "option3", "option1";
};
```

绑定（Binding）片段示例：

原始示例（Example）：

```yaml
compatible: vend,enum-string-array
properties:
  foos:
    type: phandle-array
    description: |
      Explanation about what this phandle-array exactly is for.

  foo-names:
    type: string-array
    description: |
      Some explanation about the available options
      default: explain default
      option1: explain option1
      option2: explain option2
      option3: explain option3
    enum:
      - default
      - option1
      - option2
      - option3
```

用法示例：

原始示例（Example）：

```c
DT_ENUM_IDX_BY_IDX(DT_NODELABEL(some_node), foo_names, 0) // 0
DT_ENUM_IDX_BY_IDX(DT_NODELABEL(some_node), foo_names, 2) // 1
```

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `prop` | 使用小写字母和下划线形式的属性名。 |
| `idx` | 要获取的索引。 |

返回（Returns）：属性值在其 `enum:` 列表中从 0 开始的索引。

> 译注——源码核对：两种索引：idx先选择属性数组中的元素，返回值再表示该元素在绑定enum列表中的位置。示例foo-names索引2处为option1，因此枚举索引是1；不能把返回值当作原数组下标。ENUM_HAS_VALUE检查实际属性取值是否包含该值，不是检查enum允许列表是否包含该值；BY_IDX限定某一元素。 枚举原例：DTS中compat应为compatible，才能按所示兼容字符串匹配绑定；phandle、val1等仍是待补定义的示意。YAML的两段description依次为“说明此句柄数组的具体用途”和“说明可用选项”；default、option1、option2、option3各行分别提示解释该选项。原代码与描述文本保留，未将占位片段记作可编译完整示例。

### `DT_ENUM_IDX_BY_IDX_OR`

```c
#define DT_ENUM_IDX_BY_IDX_OR ( node_id, prop, idx, default_idx_value )
```

```c
#include <zephyr/devicetree.h>
```

展开值（Value）：

```c
COND_CODE_1(DT_PROP_HAS_IDX(node_id, prop, idx), \
            (DT_ENUM_IDX_BY_IDX(node_id, prop, idx)), (default_idx_value))
```

类似于 `DT_ENUM_IDX_BY_IDX()`，但提供回退到默认枚举索引的能力。

若值存在，则通过 `DT_ENUM_IDX_BY_IDX(node_id, prop, idx)` 展开为其从 0 开始的索引值。

否则，展开为提供的默认枚举索引值。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `node_id` | 节点标识符（Node Identifier）。 |
| `prop` | 使用小写字母和下划线形式的属性名。 |
| `idx` | 要获取的索引。 |
| `default_idx_value` | 要展开成的回退索引值。 |

返回（Returns）：若对应值存在，返回该值在枚举中从 0 开始的索引；否则返回 `default_idx_value`。

> 译注——源码核对：枚举回退边界：ENUM_IDX_BY_IDX_OR仅用DT_PROP_HAS_IDX判断元素索引是否存在，不检查绑定是否声明enum、是否生成_ENUM_IDX。若元素存在但没有枚举元数据，仍会选择枚举读取分支，不能依靠default_idx_value补救类型或绑定错误。无_BY_IDX版本固定索引0。

### `DT_STRING_UPPER_TOKEN_BY_IDX`

展开值（Value）：

类似于 `DT_STRING_TOKEN_BY_IDX()`，但转换为大写。

去掉数组某元素外侧的引号，将其转换为大写，并将非字母数字字符转换为下划线。例如，需要通过程序将值组合成 C 变量名或代码时，此宏可能有用。

在其他情况下使用 `DT_STRING_UPPER_TOKEN_BY_IDX()` 会出错。

```dts
n1: node-1 {

};
```

```yaml
properties:
  prop:
    type: string-array
```

用法示例：

## 1.3\_源码定位与版本边界

本册收录设备树属性读取宏，涵盖普通值、逻辑长度、枚举索引、字符串标记和句柄数组。相对源码定位：[devicetree.h](../../../include/zephyr/devicetree.h)、[生成脚本](../../../scripts/dts/gen_defines.py)和[设备树解析器](../../../scripts/dts/python-devicetree/src/devicetree/edtlib.py)。本次官方文件摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：回退检查对象：PROP_OR与PROP_LEN_OR检查属性_EXISTS，PHA_BY_IDX_OR／BY_NAME_OR检查合成的指定单元_EXISTS，STRING_TOKEN_BY_IDX_OR检查元素索引存在。它们都是预处理期分支，不进行运行时类型转换、数据校验或硬件访问。属性存在但类型不支持长度／字符串标记时，_OR不会改走默认值；default_value须适合最终使用位置，也不会自动添加引号。

> 译注——源码核对：返回形式：DT_PROP的结果由绑定类型决定。花括号数组初始化器不是已经创建的C数组对象，phandle得到的是节点标识，不是数字句柄或struct device指针；phandle-array的单元和控制器引用分别由PHA与PHANDLE系列访问。生成器prop2value不会为phandles／phandle-array提供同类整属性数组表达式。

> 译注——源码核对：逻辑长度：字符串长度为1，表示一个字符串元素，不是strlen结果；phandle-array长度按“控制器句柄加其描述符”计数，不是32位单元数。PROP_LAST依赖有效长度与最后一个索引，只适用于非空且支持BY_IDX的属性；空数组没有最后元素，不应把宏当作自动提供默认值。

> 译注——源码核对：存在性与默认属性：绑定默认值以及缺省布尔属性False可能仍生成_EXISTS。PROP_OR因此可能取得默认值或0，而不使用调用者回退值；HAS_IDX也只检查元素，读取某个PHA单元前仍需核对该单元存在及绑定名称。句柄数组中的未指定占位元素仍占逻辑索引，但生成器将其_IDX_EXISTS置0，所以不能仅凭idx小于LEN就认定该元素可读取。

> 译注——源码核对：字符串形态：STRING_TOKEN保留原大小写，只替换特殊字符；UPPER_TOKEN另转大写；UNQUOTED保留内容形成标记序列，并不是运行时字符串解析函数。12.7这样的展开可用于浮点初始化，但A B C不因此变成一个合法C表达式，123_foo也不是合法的C标识符。属性必须具有所要求的string或string-array类型，不能靠_OR绕过类型要求。

> 译注——源码核对：示例语法与注释：STRING_TOKEN、STRING_UNQUOTED及其部分数组片段中的n2节点结尾缺少分号，原片段照录并注明。DT_PHANDLE_BY_IDX示例中的英文注释分别为“node-2的节点标识符”和“node-3的节点标识符”。其他含...、xx、yy、zz及未定义句柄的片段属于示意，须补齐绑定与DTS上下文。

> 译注——源码核对：版本边界：本次官方devicetree.h、gen_defines.py和edtlib.py登记摘要，源码跟踪采用相对链接。滚动main与本仓库参照基线不自动视为同版本；本批仅核对译文和源码，未编译宏／DTS示例、构建固件或操作硬件。
