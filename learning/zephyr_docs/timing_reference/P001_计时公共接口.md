<a id="details"></a>

计时测量接口（Timing Measurement APIs）。

**引入版本（Since）**：2.4。**接口版本（Version）**：1.0.0。

计时测量接口可用于获得一段代码的执行时间，以辅助分析和优化。

请注意，计时函数可能使用与内核默认定时器不同的定时器；具体使用哪个定时器，由架构（Architecture）、片上系统（System on Chip，SoC）或开发板（Board）配置指定。

### `timing_cycles_get()`

```c

```


| --- | --- |
| `start` | 指向被测执行过程开始时计数器读数的指针。 |
| `end` | 指向被测执行过程停止时计数器读数的指针。 |

返回（Returns）：开始与结束之间的周期数。

<a id="ga82ab007cd5864f2aa598461eec95085f"></a>

### `timing_ns_get()`

```c
uint64_t timing_ns_get ( void )
```

```c
#include <zephyr/timing/timing.h>
```

返回以纳秒（Nanoseconds）为单位的单调时间戳（Monotonic Timestamp）。

`timing_counter_get()` 的底层计数器可能不足 64 位并发生回绕（Wrap）；与它不同，此函数返回 64 位纳秒值，即使计数器回绕也保持单调递增。它面向需要绝对时间参考（Absolute Time Reference）的使用方，例如跟踪事件时间戳，而不是仅需两次明确读数之间时长的使用方。

返回值始终保持单调。只要在底层计数器的每个回绕周期内至少调用一次，该值也能保持准确；如果调用间隔更长，返回值仍只会增加，但可能少计实际经过的时间。

返回（Returns）：以纳秒为单位的单调时间戳。

## 1.4\_源码定位与版本边界

相对源码定位：[计时头文件](../../../include/zephyr/timing/timing.h)、[公共计时实现](../../../subsys/timing/timing.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把任意本地构建视为已经验证。

> 译注——源码核对：公共timing接口按开发板（Board）优先、其次片上系统（SoC）、最后架构（Architecture）的次序选择实现；读取、频率和换算必须使用同一组选定接口。它可能使用不同于内核系统定时器的计数器，不能把timing_counter_get结果无条件交给k_cyc_to_ns等系统时钟换算宏。

> 译注——源码核对：timing_t是uint64_t别名，只规定存储类型，不保证硬件计数器宽度为64位。计数器回绕（Wrap）应由对应timing_cycles_get处理；通用32位实现及本次Cortex-M实现通过uint32_t相减处理模运算，无法恢复两次读数间已丢失的多个完整回绕周期。

> 译注——源码核对：timing_ns_get在自旋锁下累加相邻计数器读数的间隔，再换算成纳秒。其起点不保证为0，也不是UTC或日历时间；“绝对时间参考”是该计数时间域内的时间戳。官方要求至少每个回绕周期读取一次以保持准确，单调性不能代替经过时间的准确性。

> 译注——源码核对：timing_start使用共享原子引用计数（Reference Count），仅从0增加时调用底层start；stop减少引用，旧值大于1时不停止底层。当前stop在旧值为0时也会调用底层stop，所以应配对使用，不能把重复stop当作有明确无副作用保证的操作。init的has_inited只避免重复初始化，不重置纳秒累加器，也不是并发初始化锁。

> 译注——源码核对：平均换算的count表示累计测量次数，应大于0。本次通用与Cortex-M实现直接相除，没有为0提供错误返回；公共包装也未额外校验。MHz结果为整数，在涉及非整数MHz频率、低频计数器或动态频率时，须核对所选后端的实际换算精度与限制。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
