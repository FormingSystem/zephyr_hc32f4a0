## 9.2\_详细说明（Detailed Documentation）

<a id="gaffc9f3013d53e72c25243ce4f972549f"></a>

### `arch_busy_wait()`

```c
void arch_busy_wait ( uint32_t usec_to_wait)
```

```c
#include <kernel_arch_interface.h>
```

架构专有的忙等待（Busy-waiting）实现。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `usec_to_wait` | 等待时长，以微秒（Microseconds）为单位。 |

<a id="ga9ee9f897ec750957de45bf8d43349d5e"></a>

### `arch_k_cycle_get_32()`

```c
uint32_t arch_k_cycle_get_32 ( void )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

取得当前周期计数，计数单位由 `CONFIG_SYS_CLOCK_HW_CYCLES_PER_SEC` 指定。

虽然此接口历来被归入架构 API，但实际上几乎所有平台都会将其转交给定时器驱动提供的 `sys_clock_cycle_get_32()` 接口。

另见（See Also）：`k_cycle_get_32()`。

返回（Returns）：当前周期时间值。它应在完整的 32 位数值范围内单调递增，到达 `0xffffffff` 后回绕。若硬件定时器的精度位数更少，应合成一个 32 位计数值。

<a id="gacc1ed8d949f694a1d39e389334caf971"></a>

### `arch_k_cycle_get_64()`

```c
uint64_t arch_k_cycle_get_64 ( void )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/arch/arch_interface.h>
```

与 `arch_k_cycle_get_32()` 相同，但返回值为 64 位。

并非所有定时器硬件都具有 64 位定时器；只有设置了 `CONFIG_TIMER_HAS_64BIT_CYCLE_COUNTER` 时才需要实现此接口。

另见（See Also）：`arch_k_cycle_get_32()`。

返回（Returns）：当前周期时间值。它应在完整的 64 位数值范围内单调递增，到达 `2^64-1` 后回绕。精度位数更少的定时器硬件通常不需要实现此接口。

相对源码定位：[架构接口](../../../include/zephyr/arch/arch_interface.h)、[内核架构接口](../../../kernel/include/kernel_arch_interface.h)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把任意本地构建视为已经验证。

> 译注——源码核对：arch_k_cycle_get_32与64对应系统硬件周期计数，单位由系统时钟配置决定；这不是每个CPU任意计数器的通用换算接口，也不保证与代码段计时接口timing_*同源。

> 译注——源码核对：arch_busy_wait的等待参数以微秒计。它属于架构层忙等待（Busy-waiting）实现，不应把等待接口与允许线程睡眠、重新调度的睡眠接口混用。此页只翻译架构契约，未运行等待精度测试。
