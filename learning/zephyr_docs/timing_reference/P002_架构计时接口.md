## 2.2\_详细说明（Detailed Documentation）

<a id="gad7a709477650c8596a96fe080f583fdd"></a>

### `arch_timing_counter_get()`

```c
timing_t arch_timing_counter_get ( void )
```

```c
#include <zephyr/arch/arch_interface.h>
```

返回计时计数器（Timing Counter）的值。





说明（Note）：每次调用 `arch_timing_counter_get()` 都必须发生在 `arch_timing_start()` 与 `arch_timing_stop()` 的调用之间，并且位于同一个 CPU 核心。

说明（Note）：并非所有架构的计时计数器都具有 64 位精度。内部回绕（Rollover）可能使读数看起来“倒退”。计时代码必须处理回绕，例如采用平台相关代码，在相减前先转换为 `uint32_t`；也可以使用必须正确处理这种差异的 `arch_timing_cycles_get()`。

返回（Returns）：计时计数器的值。

另见（See Also）：`timing_counter_get()`。

<a id="ga44d3a7bd8b7008c9cd6c0524e97f128c"></a>

### `arch_timing_cycles_get()`

```c
uint64_t arch_timing_cycles_get ( volatile timing_t *const start, volatile timing_t *const end )
```

```c
#include <zephyr/arch/arch_interface.h>
```

获取 `start` 与 `end` 之间的周期数（Cycles）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `start` | 指向被测执行过程开始时计数器读数的指针。 |
| `end` | 指向被测执行过程停止时计数器读数的指针。 |

说明（Note）：对于某些架构，计数器原始数值需要换算才能得到实际周期数，也可能在内部回绕。此函数根据两次返回的周期值计算正向的时间间隔。

返回（Returns）：开始与结束之间的周期数。

另见（See Also）：`timing_cycles_get()`。

## 2.3\_源码定位与版本边界

相对源码定位：[架构接口](../../../include/zephyr/arch/arch_interface.h)、[通用计时实现](../../../arch/common/timing.c)、[Cortex-M计时实现](../../../arch/arm/core/cortex_m/timing.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。源码定位使用相对链接；本地版本如有差异，应核对源码与来源摘要，不能把任意本地构建视为已经验证。

> 译注——源码核对：arch_timing_*属于架构实现契约，arch_k_cycle_get_*属于内核硬件周期计数接口；两组名称相似但不能假定使用同一计数源。应用通常通过timing_*公共包装选择实现，架构移植者则按本页契约提供底层操作。

> 译注——源码核对：官方明确要求arch_timing_counter_get位于同一CPU核心上的start与stop之间。接口中的64位类型不会自动使不同核心的计数器同步，也不会替调用者固定线程亲和性（CPU Affinity）。

> 译注——源码核对：本次Cortex-M实现读取DWT周期计数器（Data Watchpoint and Trace Cycle Counter），用32位差值处理回绕。其频率来自SystemCoreClock、SysTick相关系统时钟，或一次校准缓存，取决于配置；这里是官方架构源码对照，不声称任何具体芯片或开发板已完成计时实测。

> 译注——源码核对：timing_t是uint64_t别名，只规定存储类型，不保证硬件计数器宽度为64位。计数器回绕（Wrap）应由对应timing_cycles_get处理；通用32位实现及本次Cortex-M实现通过uint32_t相减处理模运算，无法恢复两次读数间已丢失的多个完整回绕周期。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
