# 第3章\_轮询公共接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__poll__apis.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：本册覆盖事件（Event）与轮询（Polling）接口、对象和字段。k_event保存32位事件集合；k_poll通过事件描述符观察受支持对象的就绪状态。两者的等待、消费与复位规则不同，原始声明和说明保留，源码对照另作明确译注。

## 3.7\_详细说明（Detailed Documentation）

<a id="ga8e3889f2bac281a6e65e31068e58047e"></a>

### `K_POLL_EVENT_INITIALIZER`

```c
#define K_POLL_EVENT_INITIALIZER ( _event_type, _event_mode, _event_obj )
```

```c
#include <zephyr/kernel.h>
```

展开值（Value）：

```c
{ \
.poller = NULL, \
.type = _event_type, \
.state = K_POLL_STATE_NOT_READY, \
.mode = _event_mode, \
.unused = 0, \
{ \
        ._typed_##_event_type = _event_obj, \
}, \
}
```

静态初始化轮询事件。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_event_type` | 事件类型，为K_POLL_TYPE_xxx中的一个值。 |
| `_event_mode` | 操作模式，为enum k_poll_modes中的一个值。 |
| `_event_obj` | 被轮询的内核对象或轮询信号的地址，必须与事件类型匹配。 |

> 译注——源码核对：当前宏通过._typed_##_event_type选择与对象类型匹配的联合体成员，用来检查对象指针类型。因此_event_type应采用相应的公开K_POLL_TYPE名称，不能把任意按位或表达式直接当作这个宏参数使用。它初始化事件描述符，不轮询、不取得被监视对象。

### `K_POLL_EVENT_STATIC_INITIALIZER`

```c
#define K_POLL_EVENT_STATIC_INITIALIZER ( _event_type, _event_mode, _event_obj, event_tag )
```

```c

```

展开值（Value）：

```c
{ \
.tag = event_tag, \
.type = _event_type, \
.state = K_POLL_STATE_NOT_READY, \
.mode = _event_mode, \
.unused = 0, \
{ \
        ._typed_##_event_type = _event_obj, \
}, \
}
```

静态初始化轮询事件，并附带用户标签（User Tag）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `_event_type` | 事件类型，为K_POLL_TYPE_xxx中的一个值。 |
| `_event_mode` | 操作模式，为enum k_poll_modes中的一个值。 |
| `_event_obj` | 被轮询的内核对象或轮询信号的地址，必须与事件类型匹配。 |
| `event_tag` | 用户指定的不透明标签，即API不解释其含义。 |

> 译注——源码核对：此版本另设置event_tag；实际tag只有8位，不是可保存任意32位值的用户字段。当前宏同样用类型名称拼接联合体成员，并不支持任意组合表达式。

### `k_poll()`

```c
int k_poll ( struct k_poll_event * events, int num_events, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

等待多个轮询事件中的一个或多个发生。

本例程允许线程同时等待多个轮询事件中的一个或多个发生。这些事件可以是内核对象变为可用，例如信号量可用，也可以是轮询信号事件。

事件通知内核对象可用时，并不会把该对象“交给”调用k_poll()的线程，只表示在本次k_poll()调用有效期间该对象曾经可用。此外，通过常规方式获取对象、即在对象上挂起等待的线程，优先于轮询该对象的线程。因此，只有对象已经可用且其挂起等待队列为空时，轮询线程才会收到该对象的轮询事件。基于这一点，被轮询对象只有一个线程尝试获取，且该线程正是轮询线程时，k_poll()更为有效。

k_poll()返回0后，调用者应遍历传入的所有事件，检查state字段是否包含预期值，并执行相应操作。

再次将事件用于k_poll()之前，用户必须把state字段复位为K_POLL_STATE_NOT_READY。

从用户模式（User Mode）调用时，需要从调用者的资源池临时分配内存。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `events` | 待轮询的事件数组。 |
| `num_events` | 数组中的事件数量。 |
| `timeout` | 等待事件就绪的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 一个或多个事件已就绪。 |
| `-EAGAIN` | 等待时间已到期。 |
| `-EINTR` | 轮询被中断，例如由k_queue_cancel_wait()中断。所有输出事件仍已设置且有效，被取消的事件会设置K_POLL_STATE_CANCELLED。换言之，-EINTR状态表示至少一个输出事件具有K_POLL_STATE_CANCELLED状态。 |
| `-ENOMEM` | 线程资源池内存不足，仅用户模式适用。 |
| `-EINVAL` | 参数错误，仅用户模式适用。 |

> 译注——源码核对：当前实现要求线程上下文，即使K_NO_WAIT也不能从ISR调用。返回0后逐项检查state，再用相应对象的非等待获取接口尝试消费；轮询成功不保证随后获取仍成功。-EINTR时取消事件状态仍有效；-EAGAIN可能与清理注册期间的新通知竞态相遇，不应把残留state当作本次成功结果。用户模式会分配并复制事件数组；不合法模式／类型等返回-EINVAL，但对象权限或内存访问验证失败走K_OOPS，不能把所有坏参数都当作可恢复的-EINVAL。

### `k_poll_signal_raise()`

```c
int k_poll_signal_raise ( struct k_poll_signal * sig, int result )
```

```c
#include <zephyr/kernel.h>
```

触发轮询信号对象。

本例程使轮询信号就绪，它本质上对应类型为K_POLL_TYPE_SIGNAL的轮询事件。若有线程正在轮询该事件，该线程会变为可运行状态。可以指定一个结果值。

轮询信号包含signaled字段；k_poll_signal_raise()将其置位后，该字段会一直保持置位，直到用户用k_poll_signal_reset()将其清零。因此，再次将信号用于k_poll()之前，必须由用户复位；否则k_poll()会认为该信号仍已触发并立即返回。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `sig` | 轮询信号。 |
| `result` | 要保存到信号result字段中的值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 信号已成功交付。 |

**说明（Note）**：即使轮询线程的超时已开始到期、因此未直接通知该次轮询，仍会保存result并设置signaled字段。下一次k_poll()会检测到这次未及时通知的触发。

> 译注——源码核对：当前实现先保存result并把signaled置1，再取出一个已注册轮询事件通知；没有已注册者也返回0，状态留待后续轮询发现。重复raise不累计次数，而会覆盖result；它不是消息队列或计数信号量，也不是向所有当前轮询者广播。迟到通知保留状态的前提是应用未将其再次复位。
