### `k_event_clear()`

```c
uint32_t k_event_clear ( struct k_event * event, uint32_t events )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

清除事件对象中的事件。

本例程清除（复位）事件对象中保存的指定事件。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 要在event中清除的事件集合。 |

**返回（Returns）**：events所选事件此前的状态；未被events选中的事件不包含在返回值中。

> 译注——源码核对：清除选中的事件位并返回这些位的旧状态，不清除等待队列，也不是取消等待接口。其他线程是否继续等待仍由其匹配条件决定。

### `k_event_post()`

```c
uint32_t k_event_post ( struct k_event * event, uint32_t events )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

向事件对象发布一个或多个事件。

本例程向事件对象发布一个或多个事件。等待该event对象且等待条件因此次发布而满足的全部任务，会立即解除等待状态。

发布（Post）与设置（Set）不同：发布的事件会与事件对象当前记录的事件集合合并。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 要发布到event的事件集合。 |

**返回（Returns）**：正在发布的这些事件此前的值，即本次调用前event中已经置位且由events选中的位。

> 译注——源码核对：当前底层按old与events按位或合并，返回old & events，即本次选中位的旧值；返回0不表示发布失败。匹配线程解除等待后仍由调度器决定实际运行时间。“发布一次”不等于向每位附加一次计数。

<a id="gac22e9d768d003246e68b4b0b64e60f49"></a>

### `k_event_set()`

```c
uint32_t k_event_set ( struct k_event * event, uint32_t events )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

设置事件对象中的事件。

本例程把事件对象中保存的事件设置为指定值。等待该event对象且等待条件因此满足的全部任务，会立即解除等待状态。

设置（Set）与发布（Post）不同：新设置的事件会替换事件对象当前记录的事件集合。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 要设置到event中的事件集合。 |

**返回（Returns）**：event中事件此前的值。

> 译注——源码核对：设置会替换全部32位；未出现在events中的旧位也会清除。返回值为修改前的完整位集合，随后满足条件的safe等待者还可能消费匹配位，因此不能把传入值当作返回时对象仍保存的状态。

### `k_event_set_masked()`

```c
uint32_t k_event_set_masked ( struct k_event * event, uint32_t events, uint32_t events_mask )
```

声明属性：`isr-ok`（允许从中断服务程序ISR调用）。

```c
#include <zephyr/kernel.h>
```

设置或清除事件对象中的事件。

本例程把事件对象中保存的事件设置为指定值。等待该event对象且等待条件因此满足的全部任务，会立即解除等待状态。与k_event_set不同，本例程允许根据掩码（Mask）设置或清除特定事件位。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 要在event中设置／清除的事件集合。 |
| `events_mask` | 应用于events的掩码。 |

**返回（Returns）**：events_mask所选事件此前的值。

> 译注——源码核对：当前计算式为(old & ~events_mask) | (events & events_mask)，只更新掩码内的位，掩码外保持原值。返回old & events_mask；这是旧值查询与位更新，不是返回操作后的全体事件。

<a id="ga0f83f5f034e13bab65149fb90b87a753"></a>

### `k_event_wait()`

```c
uint32_t k_event_wait ( struct k_event * event, uint32_t events, bool reset, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

等待指定事件中的任意一个。

本例程在事件对象event上等待，直到任一指定事件已交付给该对象，或最长等待时间timeout到期。一个线程最多可等待32个不同编号的事件，它们用一个32位字中的各个位表示。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 希望等待的事件集合。 |
| `reset` | 为true时，在等待之前清除事件对象当前记录的事件集合；为false时不清除。 |
| `timeout` | 等待所需事件集合的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `non-zero` | 成功时返回匹配的事件集合。 |
| `0` | 指定时间内未收到匹配事件。 |

**说明（Note）**：多个线程等待同一event对象时，调用者必须谨慎使用复位。只有timeout为K_NO_WAIT时，才能从中断服务程序（Interrupt Service Routine，ISR）上下文调用本函数。

**说明（Note）**：events为0时，本函数立即返回0。如果reset为true，则返回前会复位事件对象当前记录的事件。

> 译注——源码核对：返回的是与请求掩码相交的全部已匹配位，并非只返回某一个位。普通版本成功后不清除事件；reset=true是在开始检查之前清除整个对象的全部事件位，不仅是本次请求掩码。events=0立即返回0，若同时reset=true仍先清空对象；0也可表示不等待未匹配或超时，不能只凭0区分这些情况。

| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 希望等待的事件集合。 |
| `reset` | 为true时，在等待之前清除事件对象当前记录的事件集合；为false时不清除。 |
| `timeout` | 等待所需事件集合的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `non-zero` | 成功时返回匹配的事件集合。 |
| `0` | 指定时间内未收到匹配事件。 |

**说明（Note）**：多个线程等待同一event对象时，调用者必须谨慎使用复位。只有timeout为K_NO_WAIT时，才能从中断服务程序（Interrupt Service Routine，ISR）上下文调用本函数。

**说明（Note）**：events为0时，本函数立即返回0。如果reset为true，则返回前会复位事件对象当前记录的事件。

> 译注——源码核对：成功要求全部请求位同时存在，返回请求位集合；额外存在的非请求位不在返回值中。reset=true仍先清除整个事件对象；普通wait_all成功不消费位。中断上下文只能指定K_NO_WAIT。

<a id="ga505ddf074c4903fca7e2d355b0caddac"></a>

### `k_event_wait_all_safe()`

```c
uint32_t k_event_wait_all_safe ( struct k_event * event, uint32_t events, bool reset, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

等待全部指定事件，使用安全版本（Safe Version）。

本调用与k_event_wait_all几乎相同，主要区别是安全版本会以原子方式从事件对象中清除已接收的事件。这样可以减少另行调用k_event_clear或传入“reset”参数的需要，因为这两种做法可能导致事件信息丢失。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 希望等待的事件集合。 |
| `reset` | 为true时，在等待之前清除事件对象当前记录的事件集合；为false时不清除。 |
| `timeout` | 等待所需事件集合的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `non-zero` | 成功时返回匹配的事件集合。 |
| `0` | 指定时间内未收到全部匹配事件。 |

**说明（Note）**：events为0时，本函数立即返回0。如果reset为true，则返回前会复位事件对象当前记录的事件。

> 译注——源码核对：与wait_all使用相同的全位匹配条件，并原子清除本次收到的位；其他未匹配位保留。当前发布阶段会先匹配全部等待者再统一清除，不能借此保证只有一个等待者获得事件。共享对象通常还需明确各位的发布、消费与复位协议。

<a id="gab31c5012e1ae3740c3bde23b245a077e"></a>

### `k_event_wait_safe()`

```c
uint32_t k_event_wait_safe ( struct k_event * event, uint32_t events, bool reset, k_timeout_t timeout )
```

```c
#include <zephyr/kernel.h>
```

等待指定事件中的任意一个，使用安全版本（Safe Version）。

本调用与k_event_wait几乎相同，主要区别是安全版本会以原子方式从事件对象中清除已接收的事件。这样可以减少另行调用k_event_clear或传入“reset”参数的需要，因为这两种做法可能导致事件信息丢失。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `event` | 事件对象的地址。 |
| `events` | 希望等待的事件集合。 |
| `reset` | 为true时，在等待之前清除事件对象当前记录的事件集合；为false时不清除。 |
| `timeout` | 等待所需事件集合的时间，或特殊值K_NO_WAIT、K_FOREVER之一。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `non-zero` | 成功时返回匹配的事件集合。 |
| `0` | 指定时间内没有收到任何匹配事件。 |

**说明（Note）**：events为0时，本函数立即返回0。如果reset为true，则返回前会复位事件对象当前记录的事件。

> 译注——源码核对：safe版本在同一锁保护下清除成功匹配的位，避免“先返回再另行clear”的竞争窗口。但它不是单消费者令牌：当前发布实现先用同一事件快照匹配全部已等待线程，累计需要清除的位，最后统一清除，所以多个已等待线程仍可同时收到相同位。reset=true依然会先清空整个对象；safe不把事件位变成计数。

## 1.5\_源码定位与版本边界

> 译注——阅读与源码边界：配合[事件指南](../kernel/P012_事件.md)阅读。any／all描述匹配条件，普通／safe描述是否原子清除收到的位，reset参数描述等待前是否清空全部位；这是三个不同维度。事件不累计重复发布次数，safe也不等于独占消费。
