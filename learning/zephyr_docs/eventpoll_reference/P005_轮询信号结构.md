# 第5章\_轮询信号结构

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structk__poll__signal.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：本册覆盖事件（Event）与轮询（Polling）接口、对象和字段。k_event保存32位事件集合；k_poll通过事件描述符观察受支持对象的就绪状态。两者的等待、消费与复位规则不同，原始声明和说明保留，源码对照另作明确译注。

轮询信号对象（Poll Signal Object）。

```c
#include <zephyr/kernel.h>
```

<a id="details"></a>

轮询信号对象（Poll Signal Object）。轮询信号是一种内核对象，线程或ISR可以通过k_poll_signal_raise()触发它，再以K_POLL_TYPE_SIGNAL类型调用k_poll()进行轮询。

## 5.2\_详细说明（Detailed Documentation）

<a id="ab438c1e36cecda66fe2c4642518a1db1"></a>

### `result`

```c
int k_poll_signal::result
```

按需保存传给k_poll_signal_raise()的自定义结果值。

> 译注——源码核对：仅在信号已触发且应用已协调并发访问时，才作为当前通知结果解释。动态初始化不设置result，reset也不清除旧结果；重复raise可覆盖先前结果。

<a id="ae9fe6751d75f7d2b2800cb723603c0fe"></a>

### `signaled`

```c
unsigned int k_poll_signal::signaled
```

事件已触发时为1，否则为0。

保持为1，直到用户将其复位为0。

> 译注——源码核对：这是持续保持的状态位，不是触发次数。k_poll读取它不会自动清零，应用应使用k_poll_signal_reset按协议复位；还需单独清除相应k_poll_event.state。

## 5.3\_源码定位与版本边界

> 译注——阅读与源码边界：轮询信号（Poll Signal）保存一个保持置位的标志及一个结果值。触发、轮询观察、信号复位和事件描述符状态复位是不同操作；需要累计每一次通知或传输多条结果时，应选择适合的队列／计数协议。

仓库相对定位：[kernel.h](../../../include/zephyr/kernel.h)、[kernel/events.c](../../../kernel/events.c)与[kernel/poll.c](../../../kernel/poll.c)。本次依据为[官方内核头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/kernel.h)、[官方事件实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/events.c)及[官方轮询实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/kernel/poll.c)，摘要见[来源记录](../SOURCES.md)。

仓库源码、滚动更新的main和latest网页不能自动视为同一版本。本批完成文档与源码核对，未构建或执行事件并发、轮询竞争、用户模式及实板实验。
