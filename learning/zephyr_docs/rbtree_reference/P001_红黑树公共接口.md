# 第1章\_红黑树公共接口

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/group__rbtree__apis.html)。读取日期：2026-10-15；来源摘要见[来源记录](../SOURCES.md)。

> 译注——阅读位置：先读[红黑树指南](../kernel/P056_红黑树.md)，再查公共API、节点／树结构和头文件源码。源码跟踪译注说明比较顺序、遍历与配置边界。

平衡红黑树（Balanced Red/Black Tree）实现。

<a id="details"></a>

平衡红黑树实现。这里实现了一种侵入式平衡树（Intrusive Balanced Tree），保证所有操作的运行时间为O(log2(N))，整棵树创建与销毁的摊销行为为O(1)。算法与命名沿用已有学术和教学实现的惯例，可参阅[红黑树说明](https://en.wikipedia.org/wiki/Red%E2%80%93black_tree)。

该实现以减小尺寸为目标，优先考虑运行时内存占用。所谓侵入式，是指rbnode句柄应放入另一个结构中，与其他此类结构（例如Zephyr的双向链表）相同，因此节点内无须保存数据指针。颜色位（Color Bit）与一个指针共用存储，这在同类库中很常见。

尤其值得注意的是，节点不保存父指针（Parent Pointer）；沿树递进时，通过栈动态建立上层结构。因此每个节点的总内存开销仅为两个指针，与双向链表相同。

## 1.6\_详细说明（Detailed Documentation）

<a id="gaa0a518139442a69865881f6b460b03df"></a>

### `RB_FOR_EACH`

```c
#define RB_FOR_EACH ( tree, node )
```

```c
#include <zephyr/sys/rb.h>
```

展开值（Value）：

```c
for (struct _rb_foreach __f = _RB_FOREACH_INIT(tree, node);     \
     ((node) = z_rb_foreach_next((tree), &__f));                \
     )
```

不使用递归，按中序（In-order）遍历树。

rb_walk()虽然非常简单，但在某些用途下，使用C调用栈递归并不方便，而且某些体系结构的栈帧会浪费较多内存。此宏以适度增加代码大小为代价，实现非递归的foreach循环，直接遍历树。

注意，生成的循环无法安全应对树的修改。循环期间改变树结构会导致错误结果，例如跳过节点或重复访问节点。与链表不同，这里没有_SAFE变体。

还需注意，宏参数会展开多次，因此参数不应是带副作用（Side Effects）的表达式。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `tree` | 指向待遍历struct rbtree的指针。 |
| `node` | 用作迭代器（Iterator）的局部struct rbnode*变量名称。 |

> 译注——源码核对：默认_RB_FOREACH_INIT按tree->max_depth调用alloca；这些辅助存储在包含它的函数返回时释放，而非循环结束立即归还。反复在同一函数内创建遍历需考虑累计栈占用。参数多次展开，应传稳定变量；宏只隐藏遍历状态，不保护树修改。

<a id="gab03a8af066d5110cda6b7522f342b168"></a>

### `RB_FOR_EACH_CONTAINER`

```c
#define RB_FOR_EACH_CONTAINER ( tree, node, field )
```

```c
#include <zephyr/sys/rb.h>
```

展开值（Value）：

```c
for (struct _rb_foreach __f = _RB_FOREACH_INIT(tree, node);        \
                ({struct rbnode *n = z_rb_foreach_next(tree, &__f); \
                 (node) = n ? CONTAINER_OF(n, __typeof__(*(node)),   \
                                 field) : NULL; (node); }) != NULL;        \
                 )
```

遍历rbtree，并隐式处理容器字段的转换逻辑。

与RB_FOR_EACH()相同，但node可以使用包含struct rbnode的任意类型。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `tree` | 指向待遍历struct rbtree的指针。 |
| `node` | 局部迭代器变量的名称。 |
| `field` | node所指容器中struct rbnode字段的名称。 |

> 译注——源码核对：node是已经声明的容器指针变量，不是类型名称；通过__typeof__(*(node))和field执行CONTAINER_OF。继承普通遍历对副作用、结构稳定与辅助栈的全部限制。

<a id="ga6c22a3d4a917b0a2e4328eb9df8e8615"></a>

### `rb_lessthan_t`

```c
typedef bool(* rb_lessthan_t) (struct rbnode *a, struct rbnode *b)
```

```c
#include <zephyr/sys/rb.h>
```

红黑树比较谓词（Comparison Predicate）。

比较两个节点；根据树的排序规则，节点A严格小于节点B时返回true，否则返回false。

注意，插入期间，新插入的节点始终作为A，B则是树中参与比较的已有节点。可以谨慎利用这一特性，为原本比较为相等的节点实现“最近／最早加入”的排序语义。

> 译注——源码核对：比较器应在树保持非空期间维持固定顺序；不能直接返回整数差值当作bool，否则小于与大于都可能被当作true。业务键相同的对象仍需可重复、无歧义的次级顺序。

<a id="ga918cb502c4b636f49a73906735612b91"></a>

### `rb_contains()`

```c
bool rb_contains ( struct rbtree * tree, struct rbnode * node )
```

```c
#include <zephyr/sys/rb.h>
```

给定节点属于该树时返回true。

注意，函数内部不会解引用node指针，尽管树的lessthan回调可能会这样做；它只检查该指针与树内节点的指针是否相等。因此可以仅比较指针值，用此函数实现集合（Set）结构。

> 译注——源码核对：只沿比较关系查找并以指针身份判定，不是按业务键相等判断。实现最终返回n==node，空树传NULL会得到true；这不表示NULL是有效节点。应传有效非NULL候选，且比较器必须能够处理该候选；不要将此函数视作任意指针安全检查器。

<a id="ga6b2c6d796f333fb03e316afc42336ecf"></a>

### `rb_insert()`

```c
void rb_insert ( struct rbtree * tree, struct rbnode * node )
```

```c
#include <zephyr/sys/rb.h>
```

将节点插入树中。

> 译注——源码核对：先重置待插入节点的左右链接，再查找和再平衡，不检查节点是否已入树。重复插入会破坏已有结构；第一次插入把根设为黑色，max_depth设为1。节点及容器应在使用期间保持有效。

<a id="ga8de6504411a0dbd8f4a43e9e18c53919"></a>

### `rb_remove()`

```c
void rb_remove ( struct rbtree * tree, struct rbnode * node )
```

```c
#include <zephyr/sys/rb.h>
```

从树中移除节点。

> 译注——源码核对：当前实现调用find_and_stack，前提是树非空。对非空树，沿比较路径找不到目标指针时直接返回；没有状态返回值。不要据此推断空树调用也安全。成功删除不释放容器，也不保证将移除节点的全部字段清零，因此不能凭旧子指针判断成员资格。

<a id="ga79e7c341ee876f1e6f6adaf8b1162995"></a>

### `rb_walk()`

```c
void rb_walk ( struct rbtree * tree, rb_visit_t visit_fn, void * cookie )
```

声明属性：`inline`、`static`。

```c
#include <zephyr/sys/rb.h>
```

遍历／枚举红黑树。

非常简单的递归枚举实现。代码量小，但要求单独提供函数，对使用者可能不够方便，而且无法提前退出循环。迭代实现参见RB_FOR_EACH。

> 译注——源码核对：以左子树、当前节点、右子树的顺序递归，空树不调用回调。接口仅在未启用CONFIG_MISRA_SANE时提供；每个节点都会访问，完整遍历为O(N)，并使用随树高变化的C调用栈。

## 1.7\_源码定位与版本边界

从[本册大纲](大纲.md)对应到公共API、结构及源码。相对定位：[rb.h](../../../include/zephyr/sys/rb.h)、[rb.c](../../../lib/utils/rb.c)和[库构建规则](../../../lib/utils/CMakeLists.txt)。

本次依据为[官方头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/sys/rb.h)、[官方实现](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/utils/rb.c)与[官方指南](https://github.com/zephyrproject-rtos/zephyr/blob/main/doc/kernel/data_structures/rbtree.rst)，摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：初始化与所有权：按官方指南先将rbtree结构清零，再设置lessthan_fn，没有专门初始化API。应用拥有节点及其外层容器，树只修改链接和颜色位，不分配、复制或释放容器；同一rbnode不能重复插入或同时属于两棵树，已入树节点地址和排序键须保持稳定。

> 译注——源码核对：比较关系：rb_lessthan_t是布尔“小于”谓词（Less-than Predicate），不是最小堆使用的负／零／正三路比较器。不同节点需要唯一且固定的顺序；业务键相同应有稳定的次级排序规则。API原文关于最近／最早插入语义的提示不等于允许任意等价节点，contains与remove仍依赖一致的比较路径。

> 译注——源码核对：时间与内存：原API总述称所有操作O(log2(N))，完整遍历实际须访问全部N个节点，因此为O(N)，回调自身的代价另计。两指针开销指每个节点的持久字段，不包含rbtree管理结构和辅助栈。整树销毁的O(1)表述不包含逐节点释放应用对象。

> 译注——源码核对：同步与遍历：接口不自行加锁。RB_FOR_EACH及容器版本不支持遍历期间改树，也没有_SAFE版本；普通C循环可用break结束。递归rb_walk的回调返回void，没有请求提前结束的返回协议；回调同样应保持树结构与对象生命周期有效。

> 译注——源码核对：配置边界：默认插入／移除用局部可变长栈（Variable-length Array，VLA），foreach用alloca分配辅助栈。CONFIG_MISRA_SANE改用rbtree中的固定数组，同时不声明rb_walk／z_rb_walk。固定数组由同一棵树的操作共用，因此嵌套或并发操作也需避免覆盖正在使用的遍历栈。

> 译注——源码核对：内部表示：rbnode的children[0]最低位编码颜色，取左子节点时需屏蔽该位。节点布局及z_rb_*辅助入口不应当作应用手工修改拓扑的契约；源码中的内部CHECK默认展开为空，不提供全面的运行时合法性验证。

本次验证范围为文档与源码对照，未构建或运行红黑树及实板实验。
