# 第27章\_散列数据包结构

原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structhash__pkt.html)。读取日期：2026-10-14；基线为保存的 `latest` 页面，HTML 摘要见[来源记录](../SOURCES.md)。

## 27.1\_阅读说明与来源

译注：本组补齐密码散列（Cryptographic Hash）的会话、分段处理（Multipart Operation）、上下文与数据包参考。SHA 表示安全散列算法（Secure Hash Algorithm）。配合[通用密码能力](P008_密码驱动通用接口.md)与[驱动后端接口](P009_密码驱动后端接口.md)阅读；这里不是键值容器中的普通哈希映射（Hash Map）。

本组：[密码散列会话接口](P023_密码散列会话接口.md) · [密码散列头文件](P024_密码散列头文件.md) · [密码散列头文件源码](P025_密码散列头文件源码.md) · [散列会话上下文结构](P026_散列会话上下文结构.md) · [散列数据包结构](P027_散列数据包结构.md)。

用于表示散列操作输入输出参数的结构。

```c
#include <zephyr/crypto/hash.h>
```

用于表示散列操作输入输出参数的结构。除明确说明的字段外，其余字段必须由应用在调用 `hash_compute()` 前填写。

## 27.3\_详细说明（Detailed Documentation）

<a id="ab5b3ffd87a11ce3838178b2e652d49b9"></a>

### `ctx`

```c
struct hash_ctx* hash_pkt::ctx
```

此数据包关联的上下文。

可用于获取会话详细信息，尤其适用于异步操作。由 `hash_compute()` 或 `hash_update()` 填写。

<a id="ae61b4e2101c820f89ddb6fba547dcc7a"></a>

### `in_buf`

```c
const uint8_t* hash_pkt::in_buf
```

输入缓冲区的起始地址。

缓冲区由应用分配，必须在整个操作期间保持有效。

<a id="a06c516ec59f233a2090fb37eb0476652"></a>

### `in_len`

```c
size_t hash_pkt::in_len
```

要处理的输入字节数。

<a id="ac86c2221c6ebe7c3e568c6d72b91ff43"></a>

### `out_buf`

```c
uint8_t* hash_pkt::out_buf
```

输出缓冲区的起始地址。

缓冲区由应用分配，必须在整个操作期间保持有效。原地操作（In-place Operation）时可为 `NULL`，此时驱动将结果写入 `in_buf`。

> 译注（源码核对）：当前结构没有输出容量字段，调用方必须根据选定算法预留足够的摘要空间。原地输出仅适用于实际支持该能力的驱动和会话；虽然输入指针类型为 `const uint8_t *`，需要原地写入时底层存储仍必须可写，且容量足以容纳完整摘要，不能指向只读字面量或过小的消息缓冲区。

## 27.4\_相关源码与使用边界

本仓库的[散列头文件](../../../include/zephyr/crypto/hash.h)与[公共接口头文件](../../../include/zephyr/crypto/crypto.h)可用于追踪，版本可能与官网 `latest` 不同。源码译注核对依据为保存的[官方散列头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/crypto/hash.h)和[官方公共头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/crypto/crypto.h)，摘要见[来源记录](../SOURCES.md)。

> 译注——摘要容量：SHA-224／SHA3-224 需要 28 字节，SHA-256／SHA3-256 需要 32 字节，SHA-384／SHA3-384 需要 48 字节，SHA-512／SHA3-512 需要 64 字节。这是二进制摘要大小，不含文本编码或空字符终止符；输出十六进制字符串时还需另行编码和分配容量。枚举中的算法名称不表示每个设备都实现了全部算法。
