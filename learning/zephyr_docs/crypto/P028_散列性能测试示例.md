# 第28章\_散列性能测试示例

原文：[官方页面](https://docs.zephyrproject.org/latest/samples/drivers/hash_bench/README.html)。读取日期：2026-10-14；保存的 latest 页面及 HTML 摘要见[来源记录](../SOURCES.md)。

## 28.1\_概述（Overview）

本示例测量[密码散列 API（Crypto Hash API）](P002_密码学接口指南.md#crypto-api) 的吞吐量（Throughput，以每字节周期数 cycles/byte 和 MB/s 表示）及 CPU 负载（CPU Load）。它基于开发板当前启用的散列驱动，对不同消息大小执行 SHA-256 和 SHA-3-512 测试，用于展示硬件散列加速器相对于纯软件实现的作用，以及比较轮询（Polling）与中断驱动（Interrupt-driven）实现。

## 28.2\_构建与运行（Building and Running）

本工程向控制台输出信息。把 `<board>` 替换为已启用密码散列驱动的开发板（例如 `stm32mp135f_dk`），然后构建和运行：

```shell
west build -b <board> samples/drivers/hash_bench
west flash
```

若要测量纯软件 Mbed TLS 实现，可使用 `prj_mtls_shim.conf` 叠加配置（Overlay）。这也适用于 `native_sim`，以便与带硬件加速器的开发板比较：

```shell
west build -b native_sim samples/drivers/hash_bench -- -DEXTRA_CONF_FILE=prj_mtls_shim.conf
west build -t run
```

控制台标题说明实际运行的实现：硬件加速器显示 `Hash HW benchmark`，Mbed TLS 适配层（Shim）显示 `Hash SW benchmark`。

## 28.3\_示例输出（Sample Output）

```console
Hash HW benchmark
BENCH SHA256 len=64 loops=2000 cycles=... cpb=... MBps=...
...
BENCH SHA3-512 len=65536 loops=40 cycles=... cpb=... MBps=...
```

译注（源码核对）：当前程序还输出 `CPU=...%`；上述省略号是原文占位符，不是本次测量结果。程序先预热，再对 64、256、1024、4096、16384、65536 字节消息分别循环 2000、1000、500、200、100、40 次。不支持的算法在会话建立返回 `-ENOTSUP` 时跳过，因此只看到成功退出不能证明两种算法均运行。

译注：`cpb` 使用整数除法，`MBps` 按每百万字节计算，不能与 MiB/s 混用。模拟目标若在一个计数器刻度内完成，源码把零耗时夹为 1 以避免除零；这种情况下吞吐量没有实际比较意义。比较不同平台还应结合时钟、CPU负载和驱动实现条件。本示例没有逐次对照已知摘要测试向量，性能测试不代替算法正确性测试。

译注：输入缓冲区为 64 KiB，部分驱动还要求缓存行对齐。`CONFIG_HASH_BENCH_IO_ALIGNMENT_BYTES` 默认 4，应按具体驱动要求配置；软件叠加配置将主线程栈设为 4096 字节以满足 SHA-3 调用需要。本仓库当前参照版本没有该示例目录，源码追踪请使用本页列出的官方来源，不能把示例文件缺失视为翻译文件丢失。
