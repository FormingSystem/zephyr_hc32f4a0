## 23.7\_详细说明（Detailed Documentation）

### `hash_completion_cb`

```c
typedef void(* hash_completion_cb) (struct hash_pkt *completed, int status)
```

```c
#include <zephyr/crypto/hash.h>
```

处理异步散列请求的完成事件。

应用可以从已完成数据包的 `ctx` 字段获取会话上下文（Session Context）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `completed` | 已完成的散列数据包。 |
| `status` | 完成状态。`0` 表示成功，负的 `errno` 错误码表示失败。 |

<a id="ga955369c6da6aa70ded229d8861292070"></a>

### `hash_begin_session()`

```c
int hash_begin_session ( const struct device * dev, struct hash_ctx * ctx, enum hash_algo algo ) inlinestatic
```

```c
#include <zephyr/crypto/crypto.h>
```

建立散列会话（Hash Session）。

初始化算法等一次性参数；这些参数可以在会话的全部操作中保持不变。状态可以缓存在硬件中，也可以保存在驱动的数据状态变量中。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 指向驱动实例的设备结构的指针。 |
| `ctx` | 指向上下文结构的指针。会话能力和算法等一次性参数通过此结构提供。结构文档说明了应用在本次调用前必须填写哪些字段。 |
| `algo` | 本会话使用的散列算法，例如 sha256。 |

**返回（Returns）**：成功时为 `0`，失败时为负的 `errno` 错误码。

> 译注（源码核对）：当前 `struct hash_ctx` 不含独立的算法字段，算法通过本函数的 `algo` 实参提供。应用主要负责设置 `flags`；包装层设置 `device`，驱动建立会话并填写处理函数和状态。输入输出形式与同步／异步各组能力应分别选取一种；能力位掩码本身不枚举可用的 SHA 算法，仍需检查会话建立结果。

<a id="gaa69bbf41cc150dae0d97b215862729cf"></a>

### `hash_callback_set()`

```c
int hash_callback_set ( const struct device * dev, hash_completion_cb cb ) inlinestatic
```

```c
#include <zephyr/crypto/crypto.h>
```

向驱动注册异步散列完成回调（Asynchronous Completion Callback）。

应用可以注册异步散列完成回调，驱动会在先前通过 `hash_compute()` 提交的请求完成时调用它。根据密码设备的硬件语义，该回调很可能从中断服务例程（Interrupt Service Routine，ISR）上下文执行。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 指向驱动实例的设备结构的指针。 |
| `cb` | 指向供驱动调用的应用回调函数的指针。 |

**返回（Returns）**：成功时为 `0`；驱动不支持异步操作时为 `-ENOTSUP`；其他错误为负的 `errno` 错误码。

> 译注（源码核对）：注册入口接收设备和回调，不接收单个会话指针。当前包装层在驱动没有提供回调注册函数时返回 `-ENOTSUP`；不能仅因头文件声明了该 API 就认定设备支持异步操作。

<a id="ga761e5d0bda9937d7fa4550c876a1c387"></a>

### `hash_compute()`

```c
int hash_compute ( struct hash_ctx * ctx, struct hash_pkt * pkt ) inlinestatic
```

```c
#include <zephyr/crypto/crypto.h>
```

执行密码散列函数（Cryptographic Hash Function）。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `ctx` | 指向本次操作散列上下文的指针。 |
| `pkt` | 保存输入／输出的结构。 |

**返回（Returns）**：成功时为 `0`，失败时为负的 `errno` 错误码。

> 译注（源码核对）：这里的完成操作由底层驱动执行，包装层不会复制输入缓冲区，也不自行分配摘要存储。异步模式下要以完成通知为准再使用结果或释放相关对象。

### `hash_free_session()`

```c
int hash_free_session ( const struct device * dev, struct hash_ctx * ctx ) inlinestatic
```

```c
#include <zephyr/crypto/crypto.h>
```

清理散列会话。

清除会话的硬件状态和／或驱动状态。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `dev` | 指向驱动实例的设备结构的指针。 |
| `ctx` | 指向待释放会话的密码散列上下文结构的指针。 |

**参阅（See Also）**：另请参阅 `hash_begin_session`。

**返回（Returns）**：成功时为 `0`，失败时为负的 `errno` 错误码。

<a id="gaf54ee20fb1ca58764f6f301739c3ba93"></a>

### `hash_update()`

```c
int hash_update ( struct hash_ctx * ctx, struct hash_pkt * pkt ) inlinestatic
```

```c
#include <zephyr/crypto/crypto.h>
```

执行分段密码散列操作（Multipart Hash Operation）。

此函数可调用零次或多次，每次传入一段数据。最终散列根据传入的全部数据段计算。要计算最终散列，请调用 `hash_compute()`。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `ctx` | 指向本次操作散列上下文的指针。 |
| `pkt` | 保存输入的结构。 |

**返回（Returns）**：成功时为 `0`，失败时为负的 `errno` 错误码。

> 译注（源码核对）：当前包装层将 `pkt->ctx` 设为会话上下文，然后以 `finish = false` 调用驱动；`hash_compute()` 则使用 `finish = true`。分段输入应按原消息顺序提交，最后一次调用可携带剩余数据并完成摘要，不能把每一段独立计算的摘要拼起来当作整条消息的摘要。

## 23.8\_相关源码与使用边界

本仓库的[散列头文件](../../../include/zephyr/crypto/hash.h)与[公共接口头文件](../../../include/zephyr/crypto/crypto.h)可用于追踪，版本可能与官网 `latest` 不同。源码译注核对依据为保存的[官方散列头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/crypto/hash.h)和[官方公共头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/crypto/crypto.h)，摘要见[来源记录](../SOURCES.md)。

> 译注——摘要容量：SHA-224／SHA3-224 需要 28 字节，SHA-256／SHA3-256 需要 32 字节，SHA-384／SHA3-384 需要 48 字节，SHA-512／SHA3-512 需要 64 字节。这是二进制摘要大小，不含文本编码或空字符终止符；输出十六进制字符串时还需另行编码和分配容量。枚举中的算法名称不表示每个设备都实现了全部算法。
