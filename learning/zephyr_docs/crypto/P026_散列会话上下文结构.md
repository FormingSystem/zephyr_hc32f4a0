原文：[官方页面](https://docs.zephyrproject.org/latest/doxygen/html/structhash__ctx.html)。读取日期：2026-10-14；基线为保存的 `latest` 页面，HTML 摘要见[来源记录](../SOURCES.md)。

## 26.1\_阅读说明与来源

译注：本组补齐密码散列（Cryptographic Hash）的会话、分段处理（Multipart Operation）、上下文与数据包参考。SHA 表示安全散列算法（Secure Hash Algorithm）。配合[通用密码能力](P008_密码驱动通用接口.md)与[驱动后端接口](P009_密码驱动后端接口.md)阅读；这里不是键值容器中的普通哈希映射（Hash Map）。

本组：[密码散列会话接口](P023_密码散列会话接口.md) · [密码散列头文件](P024_密码散列头文件.md) · [密码散列头文件源码](P025_密码散列头文件源码.md) · [散列会话上下文结构](P026_散列会话上下文结构.md) · [散列数据包结构](P027_散列数据包结构.md)。

用于表示会话参数的结构。

```c
#include <zephyr/crypto/hash.h>
```

用于表示会话参数的结构。各字段注释说明谁负责填写字段，以及相对于 `begin_session()` 调用应在何时填写。

## 26.3\_详细说明（Detailed Documentation）

<a id="abe1e70bd23305296e54564b5966ff310"></a>

### `device`

```c
const struct device* hash_ctx::device
```

此密码上下文所属的设备驱动实例。

由 `hash_begin_session()` 填写。

<a id="ad9c9bb4472975ba6999986bb6c01b501"></a>

### `drv_sessn_state`

```c
void* hash_ctx::drv_sessn_state
```

由驱动持有的会话状态。

如果驱动支持多个并行密码会话，此字段标识当前会话对应的特定驱动状态。由于不能进行动态内存分配，驱动应在构建时为所支持的最大并行会话数分配空间。该字段由驱动在 `hash_begin_session()` 期间填写。

> 译注（源码核对）：原注释讨论的是此驱动接口建议的会话状态管理方式，不能扩大理解为 Zephyr 整个系统不支持动态内存分配。

<a id="ab550711912423a0eb03c410aef491854"></a>

### `flags`

```c
uint16_t hash_ctx::flags
```

用于说明本会话如何解释某些字段的标志（Flags）。

这是下列 `CAP_*` 的位掩码（Bitmask），由应用在调用 `hash_begin_session()` 前填写。应用可通过 `crypto_query_hwcaps()` 获取硬件／驱动支持的能力标志。

<a id="a72a2e7af667bed1ee1dabb8411b01e40"></a>

### `hash_hndlr`

```c
hash_op_t hash_ctx::hash_hndlr
```

为本会话选定的散列操作处理函数（Hash Operation Handler）。

由驱动在 `hash_begin_session()` 期间填写。

<a id="a33dbeb54cd8663f1f5391988d8ee642e"></a>

### `started`

```c
bool hash_ctx::started
```

分段散列操作状态。

分段散列操作开始后，此值为 `true`。

> 译注（源码核对）：此字段表示驱动维护的分段操作状态。公共 `hash_update()`／`hash_compute()` 包装层只传递 `finish` 参数，不直接更新该标志；应用不应自行翻转它来模拟开始或结束操作。
