# 第2章\_应用版本管理

原文：[Application version management](https://docs.zephyrproject.org/latest/build/version/index.html)。读取日期：2026-10-12，`latest`。

Zephyr 的**应用版本管理（Application Version Management）**建立在其自身版本管理机制之上。应用可以提供版本文件，由构建系统生成相应头文件，应用或模块代码像读取内核版本一样读取应用版本。

这些信息可供 C/C++ 代码、Kconfig、CMake 和 Shell 使用，便于管理应用生命周期。针对 MCUboot 等受支持引导加载器构建时，也可以自动把正确应用版本用于镜像签名，无需为填写版本额外执行手工签名步骤。

> 译注：应用版本与 Zephyr 内核版本是两个对象。本章只翻译版本信息的来源和使用方式；签名仍要求项目已经正确配置引导加载器与签名流程，不表示只创建版本文件就会自动具备完整升级能力。

## 2.1\_VERSION文件

每个应用通过自己的 `VERSION` 文本文件提供版本信息。将它放在应用根目录，与应用的 `CMakeLists.txt` 同级。每个字段单独一行，基本结构如下：

```text
VERSION_MAJOR =
VERSION_MINOR =
PATCHLEVEL =
VERSION_TWEAK =
EXTRAVERSION =
```

**主版本（Major Version）**、**次版本（Minor Version）**、**补丁级别（Patch Level）**与**微调版本（Tweak Version）**都是数值字段。Zephyr 将每个数值字段限制为一个字节；实际使用方还可能施加额外限制，例如引导加载器只支持其中部分字段，或要求更低的最大值。

| 字段 | 类型与允许值 | 是否必填 |
| --- | --- | --- |
| `VERSION_MAJOR` | 数值，0–255 | 是 |
| `VERSION_MINOR` | 数值，0–255 | 是 |
| `PATCHLEVEL` | 数值，0–255 | 是 |
| `VERSION_TWEAK` | 数值，0–255 | 是 |
| `EXTRAVERSION` | 额外版本标识：小写 `a-z`、数字 `0-9`、`.` 和 `-` | 否 |

应用执行 CMake 配置时，版本文件会自动处理。版本文件改变后，构建系统会自动检查变化，无需仅为更新该文件再手工运行一次 CMake。

> 译注：第一个代码块是字段模板，不是已填好的有效版本。`VERSION` 由应用作者创建，版本头文件由构建系统生成；不要手工修改生成的头文件。

以下各节使用这个完整 `VERSION` 文件举例：

```text
VERSION_MAJOR = 1
VERSION_MINOR = 2
PATCHLEVEL = 3
VERSION_TWEAK = 4
EXTRAVERSION = unstable.5
```

## 2.2\_应用构建版本

**应用构建版本（Application Build Version）**与 `VERSION` 文件定义的版本不同，它更动态，旨在表达构建时应用源码的状态，来自源码版本管理元数据。

默认情况下，若应用位于 Git 仓库中，其内容来自在应用目录执行 `git describe --abbrev=12 --always` 的输出。这通常包含最近的标签、该标签之后的提交数量及缩短后的提交哈希。

> 译注：若没有可用标签，`--always` 允许退回到提交哈希；恰好位于被选择的标签时，输出也可能只有标签。该命令没有 `--dirty`，因此不能据此认定输出一定反映未提交修改。

直接设置 [APP_BUILD_VERSION](https://docs.zephyrproject.org/latest/build/cmake-ref/variable/APP_BUILD_VERSION.html#variable:APP_BUILD_VERSION) 可覆盖默认行为。可在应用 `CMakeLists.txt` 中设置，或在调用 CMake 时传入，例如 `cmake -DAPP_BUILD_VERSION="v3.3.0-18-g2c85d92" ...`；这里省略号表示其他构建参数。

## 2.3\_在C/C++代码中使用

在应用代码中加入 `#include <zephyr/app_version.h>`，即可使用生成的版本宏。下表完整保留原文的宏名、类型、组成字段与示例。

| 宏定义 | 类型 | 来源或组合方式 | 示例 |
| --- | --- | --- | --- |
| `APPVERSION` | 数值 | 主版本左移24位、次版本左移16位、补丁级别左移8位，再加入微调版本 | `0x1020304` |
| `APP_VERSION_NUMBER` | 数值 | 主版本左移16位、次版本左移8位，再加入补丁级别 | `0x10203` |
| `APP_VERSION_MAJOR` | 数值 | `VERSION_MAJOR` | `1` |
| `APP_VERSION_MINOR` | 数值 | `VERSION_MINOR` | `2` |
| `APP_PATCHLEVEL` | 数值 | `PATCHLEVEL` | `3` |
| `APP_TWEAK` | 数值 | `VERSION_TWEAK` | `4` |
| `APP_EXTRAVERSION` | 不带引号的文本 | `EXTRAVERSION` | `unstable.5` |
| `APP_VERSION_STRING` | 带引号字符串 | 主版本、次版本、补丁级别、额外版本 | `"1.2.3-unstable.5"` |
| `APP_VERSION_EXTENDED_STRING` | 带引号字符串 | 主版本、次版本、补丁级别、额外版本、微调版本 | `"1.2.3-unstable.5+4"` |
| `APP_VERSION_TWEAK_STRING` | 带引号字符串 | 主版本、次版本、补丁级别、微调版本 | `"1.2.3+4"` |
| `APP_BUILD_VERSION` | 不带引号的文本 | 来自构建版本，不取自 `VERSION` 字段 | `v3.3.0-18-g2c85d92` |

> 译注：原表把未加引号的内容称为 String，但宏展开结果不等于 C 字符串字面量。例如不能直接将 `APP_EXTRAVERSION` 当作 `%s` 的字符串参数；需要通过适当的字符串化宏转换，或使用已经带引号的版本字符串宏。本仓库 Shell 版本服务对 `APP_BUILD_VERSION` 使用 `STRINGIFY()`，正是为了这一转换。

## 2.4\_在Kconfig中使用

Kconfig 文件可使用下列变量展开。这里 `$(...)` 是 Kconfig 变量语法，不是 shell 命令替换。

| Kconfig变量 | 类型 | 来源字段 | 示例 |
| --- | --- | --- | --- |
| `$(VERSION_MAJOR)` | 数值 | `VERSION_MAJOR` | `1` |
| `$(VERSION_MINOR)` | 数值 | `VERSION_MINOR` | `2` |
| `$(PATCHLEVEL)` | 数值 | `PATCHLEVEL` | `3` |
| `$(VERSION_TWEAK)` | 数值 | `VERSION_TWEAK` | `4` |
| `$(EXTRAVERSION)` | 字符串 | `EXTRAVERSION` | `unstable.5` |
| `$(APPVERSION)` | 字符串 | 主版本、次版本、补丁级别、额外版本 | `1.2.3-unstable.5` |
| `$(APP_VERSION_EXTENDED_STRING)` | 字符串 | 主版本、次版本、补丁级别、额外版本、微调版本 | `1.2.3-unstable.5+4` |
| `$(APP_VERSION_TWEAK_STRING)` | 字符串 | 主版本、次版本、补丁级别、微调版本 | `1.2.3+4` |

> 译注：Kconfig 的 `APPVERSION` 是字符串，C/C++ 和下一节 CMake 的同名对象是打包数值，不能只凭同名就认为类型相同。本仓库 `Kconfig.zephyr` 会读取应用的 `VERSION`，CMake 的 Kconfig 接入则传入组合字符串；这是不同环境各自取得版本信息的方式。

## 2.5\_在CMake中使用

CMake 文件中可使用以下变量：

| CMake变量 | 类型 | 来源或组合方式 | 示例 |
| --- | --- | --- | --- |
| `APPVERSION` | 十六进制数值 | 主版本左移24位、次版本左移16位、补丁级别左移8位，再加入微调版本 | `0x1020304` |
| `APP_VERSION_NUMBER` | 十六进制数值 | 主版本左移16位、次版本左移8位，再加入补丁级别 | `0x10203` |
| `APP_VERSION_MAJOR` | 数值 | `VERSION_MAJOR` | `1` |
| `APP_VERSION_MINOR` | 数值 | `VERSION_MINOR` | `2` |
| `APP_PATCHLEVEL` | 数值 | `PATCHLEVEL` | `3` |
| `APP_VERSION_TWEAK` | 数值 | `VERSION_TWEAK` | `4` |
| `APP_VERSION_EXTRA` | 字符串 | `EXTRAVERSION` | `unstable.5` |
| `APP_VERSION_STRING` | 字符串 | 主版本、次版本、补丁级别、额外版本 | `1.2.3-unstable.5` |
| `APP_VERSION_EXTENDED_STRING` | 字符串 | 主版本、次版本、补丁级别、额外版本、微调版本 | `1.2.3-unstable.5+4` |
| `APP_VERSION_TWEAK_STRING` | 字符串 | 主版本、次版本、补丁级别、微调版本 | `1.2.3+4` |
| `APP_BUILD_VERSION` | 字符串 | 来自构建版本，不取自 `VERSION` 字段 | `v3.3.0-18-g2c85d92` |

> 译注：CMake 的 `APP_VERSION_TWEAK` 对应 C 宏 `APP_TWEAK`，CMake 的 `APP_VERSION_EXTRA` 对应 C 宏 `APP_EXTRAVERSION`。查找某个使用位置时，要按它所属的语言环境选择名称。

## 2.6\_用于支持MCUboot的应用

只要目标应用已配置为支持 **MCUboot（微控制器引导加载器项目）**，并且构建生成了签名镜像，版本信息就会自动加入镜像数据，无需为版本再添加额外配置。

## 2.7\_在Shell中查询

配置了 **Shell（交互式命令行）**接口后，可通过以下命令取得应用版本：

| 命令 | 对应版本值 | 示例输出 |
| --- | --- | --- |
| `app version` | `APP_VERSION_STRING` | `1.2.3-unstable.5` |
| `app version-extended` | `APP_VERSION_EXTENDED_STRING` | `1.2.3-unstable.5+4` |
| `app build-version` | `APP_BUILD_VERSION` | `v3.3.0-18-g2c85d92` |

> 译注：本仓库通过 Kconfig 选项 `CONFIG_APP_VERSION_SHELL` 控制这些命令，且要求应用版本信息存在；最小 Shell 配置下不一定默认启用。因此有 Shell 提示符不代表这些子命令必然已编译进去。上述输出是原文示例，不是本次实板运行结果。
