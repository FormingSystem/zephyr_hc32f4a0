# 第9章\_控制台支撑程序

原文：[Console](https://docs.zephyrproject.org/latest/develop/twister/harness/console.html)。读取日期：2026-10-12，`latest`。

**控制台测试支撑程序（Console Harness）**使 Twister 按测试 YAML 中定义的**正则表达式（Regular Expression）**解析文本输出，判断测试是否按预期运行。以下选项位于 `harness_config`。

## 9.1\_匹配测试输出

| 字段 | 要求及含义 |
| --- | --- |
| `type` | 必填，可选 `one_line` 或 `multi_line`，按要匹配的单行或多行模式选择。 |
| `regex` | 必填，正则表达式字符串列表，与测试输出匹配以确认预期行为。 |
| `ordered` | 默认 `False`；为 `True` 时按规定顺序匹配，为 `False` 时不要求顺序。 |

## 9.2\_从日志记录数据字段

可选 `record` 配置用于提取供后续分析的数据。其 `regex` 必填，使用**命名捕获组（Named Capturing Group）**从输出行提取字段。记录同时写入实例构建目录的 `recording.csv`，以及 `twister.json` 套件对象的 `recording` 属性。

指定多个表达式时，每个表达式都会应用于每行输出，因此同一行可产生不同记录，不同行也可产生相同或不同结构的记录。**逗号分隔值（Comma-Separated Values，CSV）**文件包含所有记录出现过的字段列，缺失值填空字符串。

例如提取指标名 `metric`、周期数 `cycles` 和纳秒数 `nanoseconds`：

```yaml
record:
  regex:
    - "(?P<metric>.*):(?P<cycles>.*) cycles, (?P<nanoseconds>.*) ns"
```

`record.merge` 默认 `False`；设为 `True` 时，一个实例只保存一条汇总记录，包含所有提取字段。同名字段按出现顺序形成列表；不同字段因匹配规则或输出不同，列表长度可以不同。

## 9.3\_把字段解析为结构化数据

`record.as_json` 可列出需要进一步按 **JavaScript对象表示法（JavaScript Object Notation，JSON）**解析的命名捕获组。解析后，在 `twister.json` 中成为嵌套属性；对应 CSV 列仍保留原 JSON 字符串。

这样测试镜像可以通过日志传递分层的结果、轨迹、统计等结构。例如配置，其中 `RECORD`、`DATA` 是日志格式中的固定分隔标记：

```yaml
record:
  regex: "RECORD:(?P<type>.*):DATA:(?P<metrics>.*)"
  as_json: [metrics]
```

匹配到以下日志：

```text
RECORD:jitter_drift:DATA:{"rollovers":0, "mean_us":1000.0}
```

在报告中形成：

```json
"recording":[
    {
          "type":"jitter_drift",
          "metrics":{
              "rollovers":0,
              "mean_us":1000.0
          }
    }
]
```

此例中 `type` 是记录类型，`metrics` 被解析为嵌套对象，其中包括 `rollovers` 和 `mean_us` 两个由测试自行定义的数据字段。后面的块是报告片段，不是独立完整 JSON 文件。
