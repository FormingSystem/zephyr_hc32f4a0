## 199.1 `CONFIG_SYS_HEAP_CALLER_LEVEL`

**提示（Prompt）**：捕获调用者指针时的栈帧深度（Stack-frame depth for caller pointer capture）

**说明（Help）**

通过 `__builtin_return_address(N)` 捕获分配调用位置（allocation call site）时跳过的栈帧数。`0` 表示 `sys_heap_alloc()`／`sys_heap_aligned_alloc()` 的直接调用者，始终安全并适用于所有架构。`N > 0` 表示栈中更上层的调用者；当分配经过包装函数、直接调用者只是分配适配层（allocator shim），而真正的调用位置在上面一层或多层时很有用。调用链中的每个栈帧都必须保留帧指针（frame pointer），因此设置 `CONFIG_OMIT_FRAME_POINTER` 时会强制为 `0`。

警告：`N > 0` 依赖于 `__builtin_return_address(N)` 的非零参数用法，GCC 文档将其列为不安全。启用之前请在所用工具链和架构上验证。

**类型（Type）**：整数（Integer），`int`。

**依赖条件（Dependencies）**

```text
CONFIG_SYS_HEAP_CALLER_POINTER
```

**默认值（Defaults）**

```text
0
```

**取值范围（Ranges）**

```text
[0, 0] if CONFIG_OMIT_FRAME_POINTER
[0, 4]
```

**定义位置（Location）**：[`lib/heap/Kconfig:461`](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/heap/Kconfig#L461)。

**菜单路径（Menu Path）**：顶层（Top） → 附加库（Additional libraries） → 堆与内存分配（Heap and Memory Allocation） → 堆统计日志框架（Heap statistics logging framework） → 捕获分配调用者指针（allocation caller pointer）

**配置项引用（Symbol References）**：[`CONFIG_SYS_HEAP_CALLER_POINTER`](P199_lib_配置项参考_3.md#CONFIG_SYS_HEAP_CALLER_POINTER)、[`CONFIG_OMIT_FRAME_POINTER`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_OMIT_FRAME_POINTER)。

## 199.11 `CONFIG_SYS_HEAP_KASAN`

**提示（Prompt）**：轻量堆写入检查器（Lightweight heap write sanitizer）

**说明（Help）**

`sys_heap` 的轻量写入检查器（write sanitizer）。它结合 `-fsanitize=kernel-address` 编译器插桩（compiler instrumentation）和每堆影子位数组（shadow bitarray，每个粒度单元一位），检测写访问中的缓冲区上溢、下溢（overflows／underflows）及释放后使用（use-after-free）。自带轻量运行时（`__asan_store*` 回调），不依赖外部 ASAN 库，并支持在真实嵌入式目标上调试。目前仅支持内核模式堆（kernel-mode heaps），要求 GCC 或 Clang 支持 `-fsanitize=kernel-address`，不能与 `CONFIG_ASAN` 同时使用。

此选项不会启用全系统插桩（system-wide instrumentation）。必须显式选择源文件：使用 `zephyr_target_enable_heap_kasan()` 为某个 CMake 目标的全部源文件插桩，或使用 `zephyr_heap_kasan_enable_directory()` 为指定目录下的源文件插桩。

堆跟踪也必须显式启用，每个堆都需注册才能检测。对于公共 libc malloc 堆和内核系统堆，分别启用 `CONFIG_SYS_HEAP_KASAN_MALLOC` 和 `CONFIG_SYS_HEAP_KASAN_SYSTEM`。自定义 `k_heap` 或 `sys_heap` 实例必须通过 `K_HEAP_KASAN_ENABLE()` 或 `SYS_HEAP_KASAN_ENABLE()` 显式注册。

**类型（Type）**：布尔值（Boolean），`bool`。

**依赖条件（Dependencies）**

```text
!CONFIG_ASAN
```

**主动选择（Selects）**

```text
CONFIG_SYS_HEAP_SANITIZER_HOOKS
```

**定义位置（Location）**：[`lib/heap/Kconfig:219`](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/heap/Kconfig#L219)。

**菜单路径（Menu Path）**：顶层（Top） → 附加库（Additional libraries） → 堆与内存分配（Heap and Memory Allocation）

**配置项引用（Symbol References）**：[`CONFIG_ASAN`](https://docs.zephyrproject.org/latest/kconfig.html#CONFIG_ASAN)、[`CONFIG_SYS_HEAP_SANITIZER_HOOKS`](P199_lib_配置项参考_3.md#CONFIG_SYS_HEAP_SANITIZER_HOOKS)。

## 199.14 `CONFIG_SYS_HEAP_KASAN_GRANULE_4`

**提示（Prompt）**：4 字节，影子内存比例（shadow ratio）为 1:32

**说明（Help）**

每个 4 字节粒度单元（granule）对应一个影子位（shadow bit）。小于粒度的尾部越界写入不会被检测到，例如执行 `alloc(1)` 后写入 `p[1]`～`p[3]`；它们仍位于同一粒度单元内，不会触及 `sys_heap` 元数据或相邻内存块。影子内存大小为 `heap_size / 32`。

**类型（Type）**：布尔值（Boolean），`bool`。

**依赖条件（Dependencies）**

## 199.23 `CONFIG_SYS_HEAP_SANITIZER_ASAN`

**提示（Prompt）**：完整地址检查器（Address Sanitizer，ASAN）的堆毒化（heap poisoning），用于 native_sim

**说明（Help）**

与工具链的地址检查器（Address Sanitizer，ASAN）运行时集成，为 `sys_heap` 分配器实现内存毒化（memory poisoning）。初始化时，将整个堆缓冲区标记为不可访问（poison）；分配时，对返回的用户区域解除该标记（unpoison）；释放时再次标记。这样，ASAN 就能报告对已释放、从未分配及越界堆内存的访问，并提供完整回溯（backtrace）和影子内存转储（shadow dump）。启用后可检测：

- 释放后使用（Use-after-free）：访问已经释放的内存。
- 未分配访问（Unallocated access）：访问从未分配的内存。
- 缓冲区越界（Buffer overruns）：写入超过请求分配大小的区域。

此功能仅适用于支持 ASAN 的原生仿真器平台（native simulator platforms）。支持任何提供 ASAN 运行时及手动毒化 API（manual poisoning API）的工具链，例如 GCC 的 `libasan`，或 Clang／LLVM 的 `compiler-rt`。要求使用大堆内存块格式（big-heap chunk format），使用户指针及可用区域末端均按 8 字节对齐，与 ASAN 的影子粒度一致。64 位平台隐式满足此要求；32 位平台必须显式选择 `SYS_HEAP_BIG_ONLY`，因此此配置下不会测试小堆内存块格式。仅用于调试和验证。

**类型（Type）**：布尔值（Boolean），`bool`。

**依赖条件（Dependencies）**

```text

```

**主动选择（Selects）**

<a id="CONFIG_SYS_HEAP_THREAD_STATS"></a>

## 199.30 `CONFIG_SYS_HEAP_THREAD_STATS`

**提示（Prompt）**：每线程堆分配跟踪（Per-thread heap allocation tracking）

**说明（Help）**

为每个堆按线程跟踪尚未释放的分配字节数（outstanding allocation bytes）。每个分配到统计槽位（statistics slot）的堆，都维护一个固定大小的表，保存线程及其总字节数。无法归属到被跟踪线程的分配，计入每个堆的三个汇总计数器之一：

- `isr_alloc_bytes`：在中断服务程序（ISR）上下文中分配，即 `k_is_in_isr()`。
- `boot_alloc_bytes`：调度器启动前分配，即 `k_is_pre_kernel()`。
- `overflow_alloc_bytes`：超出 `SYS_HEAP_STATS_MAX_TRACKED_THREADS` 限制的线程所做的分配。

这些计数器与 `sys_heap` 本身使用相同的调用者侧锁（caller-side lock）进行串行化访问；没有外部加锁的并发访问会产生未定义结果。注意事项：

- `k_thread` 线程控制块（TCB）被回收供新线程使用时，统计表无法区分前后两个线程，原线程仍存活的分配会被归到新线程。
- 线程名称在首次分配时捕获。如果当时尚未调用 `k_thread_name_set()`，则名称可用后，会在下一次分配时刷新。
- 每个不同的 `sys_heap` 指针占用大小为 `SYS_HEAP_STATS_TRACKED_HEAPS` 的池中的一个槽位；重新初始化相同指针时自动复用已有槽位。

**类型（Type）**：布尔值（Boolean），`bool`。

**依赖条件（Dependencies）**

```text
CONFIG_SYS_HEAP_STATS_LOGGING
```

**定义位置（Location）**：[`lib/heap/Kconfig:401`](https://github.com/zephyrproject-rtos/zephyr/blob/main/lib/heap/Kconfig#L401)。

**菜单路径（Menu Path）**：顶层（Top） → 附加库（Additional libraries） → 堆与内存分配（Heap and Memory Allocation） → 堆统计日志框架（Heap statistics logging framework）

**配置项引用（Symbol References）**：[`CONFIG_SYS_HEAP_STATS_LOGGING`](P199_lib_配置项参考_3.md#CONFIG_SYS_HEAP_STATS_LOGGING)。
