## 8.4\_源码跟踪译注

> 译注——三类字段：zephyr,memory-attr使用32位属性值，通用字段为位15:0，软件字段为位19:16，架构字段为位31:20。通用、软件及架构的UNKNOWN分别占位15、19、31；UNKNOWN是一个显式标志，不能把0或未设置某一位一概解释为UNKNOWN。各字段的掩码（Mask）和移位量（Shift）见通用头文件源码。

> 译注——提取后仍在原位：本册各GET宏均执行按位与，没有右移。例如DT_MEM_SW_GET(DT_MEM_SW_ALLOC_DMA)仍为BIT(18)，不是原始低位常量ATTR_SW_ALLOC_DMA的BIT(2)。DT_MEM_ARM、DT_MEM_ARM64、DT_MEM_RISCV和DT_MEM_XTENSA等内部编码宏将低位属性移入架构字段；不要把已经编码的DT_MEM_*常量再次移位。

> 译注——声明与消费：这些绑定头文件定义属性编码，实际处理取决于启用的子系统和架构代码。subsys/mem_mgmt/mem_attr.c从状态为okay且具有zephyr,memory-attr的节点生成区域表，记录名称、第0个reg的地址与大小及完整属性值。属性声明本身不会分配内存、启用缓存、建立内存管理单元（Memory Management Unit，MMU）映射或赋予硬件原本不具备的DMA能力。

> 译注——原文掩码差异：软件属性概述误写为DT_MEM_ARCH_ATTR_MASK；实际DT_MEM_SW_ATTR_MASK为GENMASK(19,16)，与架构字段GENMASK(31,20)分开。原说明保留并指出差异，调用应依据真实软件字段掩码。

> 译注——两种缓存描述：DT_MEM_CACHEABLE是通用能力标志，DT_MEM_SW_ALLOC_CACHE是供软件堆选择的标志，位于不同字段，不可互换。软件CACHE、NON_CACHE和DMA标签分别编码为位16、17和18；是否可组合及组合的含义需要结合消费方，不应仅因它们都是位标志就任意组合。

> 译注——堆选择是完整匹配：mem_attr_heap_pool_init提取每个区域的软件字段，跳过结果为0的区域并为其余区域建立堆；分配路径mah_choice使用h->attr != attr作精确比较，而不是包含位测试。若区域带CACHE|DMA，请求仅DMA并不会自动选中它；属性也不会把不可缓存区域切换为可缓存区域。初始化、内存所有权和实际区域配置仍须由使用方保证。

> 译注——版本边界：本批记录六份绑定头文件及内存属性／属性堆的两个公共头文件、两份实现文件，共十份官方源码摘要。六个源码浏览页的非注释代码与本次读取的对应原始头文件一致；滚动main、latest和本仓库参照源码不自动视为同版本。本次未编译示例、配置MPU／MMU、建立内存堆或执行硬件实验。

头文件相对定位：[include/zephyr/dt-bindings/memory-attr/memory-attr-sw.h](../../../include/zephyr/dt-bindings/memory-attr/memory-attr-sw.h)，关联实现／接口：[subsys/mem_mgmt/mem_attr_heap.c](../../../subsys/mem_mgmt/mem_attr_heap.c)；[官方原始头文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/include/zephyr/dt-bindings/memory-attr/memory-attr-sw.h)与[官方关联文件](https://github.com/zephyrproject-rtos/zephyr/blob/main/subsys/mem_mgmt/mem_attr_heap.c)的摘要见来源记录。去掉注释和展示空白后，本页代码与本次读取的原始头文件一致，不能推广到以后滚动更新的main或任意本地版本。
