## 概述（Overview）

i.MX93评估套件（MCIMX93-EVK）以小尺寸、低成本展示i.MX 93应用处理器的常用功能。这块入门开发板帮助开发者先熟悉处理器，再为更具体的设计投入大量资源。

i.MX93 MPU由两个Cortex-A55核组成的集群及单个Cortex-M33核构成，Zephyr OS已移植到Cortex-A55和Cortex-M33。


- 开发板特性（Board Features）：


  - RAM：2 GB LPDDR4
  - 存储（Storage）：


    - SanDisk 16 GB eMMC 5.1
    - microSD卡插槽（Socket）
  - 无线（Wireless）：


    - Murata Type-2EL模块，接口为SDIO、UART及SPI；基于NXP IW612 SoC，支持2.4 GHz／5 GHz双频1×1 Wi-Fi 6、蓝牙5.2及802.15.4
  - 通用串行总线（USB）：


    - 两个USB 2.0 Type-C连接器
  - 以太网（Ethernet）
  - PCI-E M.2
  - 接插件（Connectors）：


    - 40引脚双排排针
  - 发光二极管（LED）：


    - 1个电源状态LED
    - 两个UART LED
  - 调试（Debug）


    - 20引脚JTAG连接器
    - Micro-USB用于UART调试，提供分别用于A55和M33的两个COM端口

<a id="pwm-tpm"></a>

#### PWM，使用TPM

M33核启用TPM2，可用示波器或逻辑分析仪观察信号，将仪器连接J1005-3与J1005-7（GND）。

A55核为[PWM Blinky](../basic_samples/P004_PWM闪烁LED.md#pwm-blinky)应用启用TPM3，板上RGB LED D1001的绿色通道会以不同频率闪烁。

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/basic/blinky_pwm
```

#### 模数转换器（ADC）

M33核启用sar_adc1，ADC_IN0／1／2／3分别连接J1003-1／3／5／7。

<a id="devices"></a>

### 设备（Devices）

<a id="system-clock"></a>

#### 系统时钟（System Clock）

此板配置使用24 MHz系统时钟。Cortex-A55最高运行频率1.7 GHz，Cortex-M33最高200 MHz，SYSTICK与M33同频。

<a id="serial-port"></a>

#### 串口（Serial Port）

原文说明，此板为A55及M33使用单一串行通信通道，即CPU的UART2。

<a id="usdhc-sd-or-emmc-interface-on-a55"></a>

#### uSDHC：A55上的SD或eMMC接口

i.MX 93提供3个uSDHC主控制器模块，支持SD／eMMC接口。MCIMX93-EVK的uSDHC2连接MicroSD卡槽J1002，uSDHC1连接SoM板上的eMMC。提供usdhc1.overlay及usdhc2.overlay设备树覆盖文件，以启用指定控制器。

当前依靠U-Boot或Linux在Cortex-A核上启动Zephyr，因此Zephyr须使用与U-Boot或Linux不同的uSDHC控制器，避免资源冲突。例如，EVK从使用uSDHC2的SD卡启动时，Zephyr可使用uSDHC1上的MMC测试：

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 tests/subsys/sd/mmc -- -DEXTRA_DTC_OVERLAY_FILE=usdhc1.overlay
```

若EVK从使用uSDHC1的MMC启动，Zephyr可使用uSDHC2上的SD卡测试：

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 tests/subsys/sd/sdmmc -- -DEXTRA_DTC_OVERLAY_FILE=usdhc2.overlay
```

<a id="board-mux-control"></a>

#### 板上多路复用器控制（Board MUX Control）

此板使用一组数字多路复用器切换不同功能，由板载ADP5585 GPIO扩展器的EXP_SEL信号控制。启用板级控制模块后，可通过DTS选择功能组A或B。定义的DTS节点如下：

```text
board_exp_sel: board-exp-sel {
    compatible = "imx93evk-exp-sel";
    mux-gpios = <&gpio_exp0 4 GPIO_ACTIVE_HIGH>;
    mux = "A";
};
```

配置EXP_SEL信号需要以下步骤：


1. 启用Kconfig选项CONFIG_BOARD_MIMX93_EVK_EXP_SEL_INIT。
2. 在&board_exp_sel设备树节点中选择mux="A";或mux="B";。

启用需要配置多路复用器的板级功能时，会启用CONFIG_BOARD_MIMX93_EVK_EXP_SEL_INIT。某些板级功能还会自动选择MUX，其优先级高于DTS配置。例如启用CONFIG_CAN时，即使DTS设置mux="B";，也会选择MUX A，并在日志中发出警告。

<a id="user-button-gpio-option"></a>

#### 用户按键GPIO选项（User Button GPIO Option）

用户按键RFU_BTN1和RFU_BTN2默认连接i.MX 93 GPIO，可通过板上拨码开关改接PCAL6524 GPIO扩展器：先将SW1006设为0000，再将SW1005设为0101。文档附带支持此配置的设备树覆盖文件。

使用以下命令测试PCAL6524上的用户按键：

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/basic/button -- -DEXTRA_DTC_OVERLAY_FILE=imx93_evk_mimx9352_exp_btn.overlay
```

运行应用，按下RFU_BTN1时，红色LED相应点亮。

注意：覆盖文件仅支持mimx9352/a55；启用I2C及PCAL6524后，可扩展至mimx9352/m33。此条件按原文保留。

<a id="option-1-boot-zephyr-by-using-jlink-runner"></a>

### 选项1：使用J-Link运行工具（Runner）启动Zephyr

默认运行工具为J-Link。使用J-Link调试器将EVK的JTAG连接器接至主机，给开发板上电并停在U-Boot命令行，执行以下命令停用数据缓存（D-Cache）：


随后使用west flash或west debug，从主机加载zephyr.bin，在A55 core0上启动Zephyr应用。

<a id="flash-and-run"></a>

#### 烧录与运行（Flash and Run）

以下以基本同步（[Basic Synchronization](../basic_samples/P029_基本同步示例.md#synchronization)）应用为例。

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization
west flash
```

<a id="debug"></a>

#### 调试（Debug）

下面以[Hello World](../getting_started/P005_HelloWorld示例.md#hello_world)应用为例。

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/hello_world
west debug
```

<a id="option-2-boot-zephyr-by-using-u-boot-command"></a>

### 选项2：使用U-Boot命令启动Zephyr

U-Boot的go命令可在A55 core0上启动Zephyr；cpu命令则用于加载Zephyr并启动其他A55次级核。原文指定[Real-Time Edge U-Boot](https://github.com/nxp-real-time-edge-sw/real-time-edge-uboot)支持cpu命令，分支格式为uboot_vxxxx.xx-y.y.y，其中xxxx.xx为U-Boot版本，y.y.y为[Real-Time Edge软件](https://www.nxp.com/rtedge)版本。例如uboot_v2023.04-2.9.0表示Real-Time Edge Software v2.9.0采用的U-Boot v2023.04。预构建镜像及用户指南见Real-Time Edge Software。

<a id="step-1-download-zephyr-image-into-ddr-memory"></a>

#### 步骤1：将Zephyr镜像下载到DDR存储器

首先将Zephyr二进制镜像下载到DDR，可使用TFTP：

```text
tftp 0xd0000000 zephyr.bin
```

也可将zephyr.bin复制到SD卡，并插入开发板。例如，镜像在SD卡FAT分区中时，用以下U-Boot命令加载到DDR。示例假定SD卡设备编号为1、FAT分区编号为1，应按实际配置调整：

```text
fatload mmc 1:1 0xd0000000 zephyr.bin;
```

<a id="step-2-boot-zephyr"></a>

#### 步骤2：启动Zephyr

使用以下命令在core0上启动Zephyr：

```text
dcache off; icache flush; go 0xd0000000;
```

也可用cpu命令从次级核启动，例如Core1：

```text
dcache flush; icache flush; cpu 1 release 0xd0000000
```

注意（Note）

i.MX 93只有两个Cortex-A55核，因此为imx93_evk/mimx9352/a55/smp目标构建时，应使用U-Boot的go命令启动Zephyr。

<a id="option-3-boot-zephyr-by-using-remoteproc-under-linux"></a>

### 选项3：在Linux下使用remoteproc启动Zephyr

A55核运行Linux时，可通过remoteproc框架加载并启动Zephyr，细节见Real-Time Edge用户指南。预构建镜像及用户指南见[Real-Time Edge Software](https://www.nxp.com/rtedge)。

此配置可运行基础Zephyr应用及内核测试，例如[基础同步（Basic Synchronization）](../basic_samples/P029_基本同步示例.md#synchronization)示例：

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization
```

这将构建包含同步（Synchronization）示例的镜像，启动后控制台输出如下：


<a id="option-4-boot-zephyr-by-using-spsdk-runner"></a>

### 选项4：使用SPSDK运行工具启动Zephyr

SPSDK运行工具使用[https://spsdk.readthedocs.io](https://spsdk.readthedocs.io)提供的工具集，构建包含全部所需固件组件的可启动镜像flash.bin。west flash可将其下载到DDR、SD卡或eMMC。镜像不包含U-Boot，因此由TF-A直接启动第一个Cortex-A55核上的Zephyr。

使用SPSDK运行工具前需要获取二进制组件（Binary Blobs），命令如下：

```text
west blobs fetch hal_nxp
```

注意（Note）

建议在 `west update` 之后运行上述命令。

SPSDK运行工具通过CONFIG_BOARD_NXP_SPSDK_IMAGE启用，i.MX93 EVK默认未启用。以下以基本同步示例说明如何启用：（[基础同步（Basic Synchronization）](../basic_samples/P029_基本同步示例.md#synchronization)）

```text
# From the root of the zephyr repository
west build -b imx93_evk/mimx9352/a55 samples/synchronization -- -DCONFIG_BOARD_NXP_SPSDK_IMAGE=y
```

若板卡变体提供并启用CONFIG_BOARD_NXP_SPSDK_IMAGE，将自动生成flash.bin。执行以下编程命令前，将SW1301[3:0]设为0b0011，以USB下载模式启动，并将USB1及DBG连接Linux主机。系统枚举4个115200、8N1串口，第4个用于Cortex-A55 Zephyr控制台。spsdk烧录工具已通过scripts/requirements.txt安装；Linux下需按[https://spsdk.readthedocs.io](https://spsdk.readthedocs.io)安装指南设置USB设备权限。

```text
# load and run without programming. for next flashing, need to reset the board firstly
$ west flash -r spsdk

# program to SD card, then set SW1301[3:0]=0b0010 to reboot from SD
$ west flash -r spsdk --bootdevice sd

# program to emmc card, then set SW1301[3:0]=0b0000 to reboot from EMMC
$ west flash -r spsdk --bootdevice=emmc
```

Zephyr日志随后显示在第4个串口控制台。

## 使用SOF专用变体（SOF-specific Variant）

<a id="purpose"></a>

### 用途（Purpose）

此板没有DSP，因此为希望在板上运行Sound Open Firmware（[SOF](https://github.com/thesofproject/sof)）的用户提供另一种方案：通过Jailhouse从Linux划出一个A55核，将其分配给运行SOF的Zephyr。

<a id="what-is-jailhouse"></a>

### 什么是Jailhouse？

Jailhouse是用于划分硬件资源的轻量级虚拟机监控器（Hypervisor）。资源划分方式及其他信息见参考资料[1](https://lwn.net/Articles/578295/)、[2](https://lwn.net/Articles/578852/)及[3](http://events17.linuxfoundation.org/sites/events/files/slides/ELCE2016-Jailhouse-Tutorial.pdf)；此处还提供其GitHub仓库链接。（[here](https://github.com/siemens/jailhouse)）

<a id="how-does-it-work"></a>

### 它如何工作？

首先说明后文会使用的几个Jailhouse概念：


- 单元（Cell）：分配给该单元的操作系统能够使用的一组硬件资源。
- 根单元（Root Cell）：Linux所在的主单元，包含Linux使用的全部硬件资源，也用于向客体分配资源。客体不能使用未分配给根单元的CPU等资源。
- 客体（Inmate）：与Linux并行运行的其他操作系统。客体所用资源从Linux所在的根单元划出。

SOF和Zephyr作为客体，与Linux并行运行在板卡的core 1上。因此，该核会从Linux划出，专供Zephyr使用。

虚拟机监控器根据配置文件描述的内存区域建立第二阶段地址转换表（Second-stage Translation Table），以此限制根单元及客体对硬件资源的访问。考虑以下场景：

> 假设根单元需要使用UART，其寄存器映射到[0x0—0x42000000]区域。若客体也要使用该UART，须在客体配置文件中加入同一区域及JAILHOUSE_MEM_ROOTSHARED标志，允许客体与根单元共享它。若未添加此区域，而作为客体运行的Zephyr尝试访问，将产生第二阶段地址转换故障（Second-stage Translation Fault）。

备注（Notes）：


- Linux与Zephyr并不知道彼此同时运行，只能看到各自配置文件分配的内核；根单元有一个配置文件，每个客体也分别有配置文件。
