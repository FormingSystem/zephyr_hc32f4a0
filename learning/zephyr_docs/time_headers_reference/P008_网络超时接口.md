## 8.4\_详细说明（Detailed Documentation）

<a id="gab59bff1cb36902a27ee8e887ef39a4ce"></a>

### `NET_TIMEOUT_MAX_VALUE`

```c
#define NET_TIMEOUT_MAX_VALUE ((uint32_t)INT32_MAX)
```

```c
#include <zephyr/net/net_timeout.h>
```

用于支持毫秒分辨率超时的除数（Divisor）。

延迟由工作队列（Work Queues）处理，而工作队列不会随时钟变化同步执行。因此，必须能够在超时实际发生之后检测到它：比较“截止时间”（Deadline）与“当前时间”（Now）时，需要留出足够的容差，以处理当前时间已越过截止时间而产生的可观测延迟。

最简单的办法是利用原生转换，将定义明确的 32 位无符号差值转换为 32 位有符号差值，这会把最大延迟限制为 `INT32_MAX`。这种方式与判断未超出其表示范围的截止时间是否完成的标准机制兼容。

<a id="ga3d9804474050d070fc4224e834f8cefc"></a>

### `net_timeout_deadline()`

```c
int64_t net_timeout_deadline ( const struct net_timeout * timeout, int64_t now )
```

```c
#include <zephyr/net/net_timeout.h>
```

返回超时结束时对应的 64 位系统时间。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `timeout` | 指向超时状态的指针；该状态由 `net_timeout_set()` 初始化，并由 `net_timeout_evaluate()` 维护。 |
| `now` | 完整精度的 `k_uptime_get()` 值，将相对于此值计算截止时间。 |

说明（Note）：必须按规定间隔调用 `net_timeout_evaluate()`，才能保证行为正确。

返回（Returns）：超时到期时对应的 `k_uptime_get()` 值。

<a id="ga07b07966dd10929f6d3774467614f006"></a>

### `net_timeout_evaluate()`

```c
uint32_t net_timeout_evaluate ( struct net_timeout * timeout, uint32_t now )
```

```c
#include <zephyr/net/net_timeout.h>
```

更新状态以反映已经过的时间，并取得新的延迟值。

必须周期性调用此函数，以完成两项工作：第一，对于超过最大可表示延迟的总时长，根据已经过的时间更新剩余部分；第二，判断超时是否已经结束，或基础设施应再等待多长时间后重新检查是否结束。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `timeout` | 指向超时状态的指针。 |
| `now` | 用于估算剩余时间的参照时刻；应使用最近取得的 `k_uptime_get_32()` 值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 超时已经结束。 |
| `>0` | 在重新评估此超时状态之前，最多可等待的时间，单位为毫秒（Milliseconds）。 |

<a id="ga34e39484b19c39b3e37a4799848ad502"></a>

### `net_timeout_remaining()`

```c
uint32_t net_timeout_remaining ( const struct net_timeout * timeout, uint32_t now )
```

```c
#include <zephyr/net/net_timeout.h>
```

计算距离超时的剩余时间，以整数秒表示。

**参数（Parameters）**

| 名称／方向 | 说明 |
| --- | --- |
| `timeout` | 指向超时状态的指针。 |
| `now` | 用于估算剩余时间的参照时刻；应使用最近取得的 `k_uptime_get_32()` 值。 |

**返回值（Return Values）**

| 名称／方向 | 说明 |
| --- | --- |
| `0` | 超时已经结束。 |
| `>0` | 超时的剩余时长，单位为秒（Seconds）。 |

说明（Note）：此函数将剩余时间向下取整。例如，如果将在 3500 毫秒后超时，则返回值为 3。必须按规定间隔调用 `net_timeout_evaluate()`，才能保证行为正确。

## 8.5\_源码定位与版本边界

相对源码定位：[网络超时头文件](../../../include/zephyr/net/net_timeout.h)、[实现](../../../subsys/net/ip/net_timeout.c)。官方源码摘要见[来源记录](../SOURCES.md)。

> 译注——源码核对：以下源码跟踪译注独立于官方正文，依据来源记录中保存摘要的官方main文件。译文与仓库内已有源码采用相对链接，不依赖作者机器位置；不同C库和构建配置须分别核对。

> 译注——源码核对：net_timeout_set的lifetime单位是秒，now单位是毫秒；evaluate返回毫秒延迟，remaining返回向下取整的秒数，deadline返回64位uptime毫秒时刻。不同接口的单位不能互换，deadline不是日历或UTC时间。

> 译注——源码核对：NET_TIMEOUT_MAX_VALUE为INT32_MAX毫秒，即约24.86天；32位毫秒计数完整回绕周期才约49.71天。原文头文件的“约49天”描述计数器回绕背景，不等于可以无条件等49天才评估。wrap_counter累计的是INT32_MAX毫秒的整段数量，不是UINT32_MAX毫秒的完整硬件回绕次数。

> 译注——源码核对：set只初始化状态，不创建定时器、工作项或线程，也不操作node链表链接。调用方应按evaluate给出的最大等待时间安排下一次评估；超过约定间隔后，截断差值无法保证恢复真实经过时间。不要把该结构当作无需维护即可永久计时的64位定时器。

> 译注——源码核对：remaining对正的剩余毫秒数除以1000，因此还剩1～999毫秒时也返回0。官方返回值表保留“超时结束时返回0”，但反向推断“0必然已到期”不成立；需要准确判断时应按契约使用evaluate或在有效状态下比较deadline。

> 译注——源码核对：deadline用完整64位now和timer_start低32位重建最近起点，实现假设该起点距离now不足2^32毫秒。函数不会自动调用evaluate维护状态，必须遵守原文的周期评估要求；不能用任意历史截断时间重新构造无限久以前的起点。

> 译注——源码核对：lifetime为0时set直接把剩余片段与计数清零。一般情况下，若总毫秒数恰好为NET_TIMEOUT_MAX_VALUE的整数倍，实现会把一个整段移入timer_timeout，保持未到期时剩余片段为正。除node外，应通过API访问与维护状态；本实现不提供内部锁。

> 译注——源码核对：wrap_counter的官方字段说明末句再次列出了wrap_counter自身；译文保留这一原文信息。源码实际在evaluate中配套维护timer_start、timer_timeout与wrap_counter，不能把文案中的重复字段理解为额外状态。

本次验证范围为文档与源码对照，未构建固件、配置实板引脚或操作硬件。
