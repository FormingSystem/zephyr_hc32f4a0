# 板卡配置、PCB 适配与验证

面向熟悉嵌入式硬件、尚未掌握 Zephyr 配置工具的读者，不重讲 C 语法。

先区分新增与配置：从原生源码起步，先完成[已有板编译](../P01_zephyr_make_project/P007_编译示例与新增开发板_Windows.md)，再读[新增板实验](../P01_zephyr_make_project/P007_编译示例与新增开发板_Windows.md)，其中包含 AN386 练习板与所选 UYUP HC32 实板两个新增示例。下面 P001/P002 是树内 HC32 移植完成后的配置专题；模块接入与树内迁移的边界见新增板章末。

1. [选择目标板与软件配置](P001_选择目标板与软件配置.md)：board/SoC、Kconfig、实际文件地图。
2. [按 PCB 连接修改设备树](P002_按PCB连接修改设备树.md)：overlay、binding、引脚与驱动支持边界。
3. [用 Twister 和 QEMU 验证配置](P003_用Twister和QEMU验证配置.md)：场景选择、运行证据和实板边界。

各章实验与完整配置放在正文，材料目录只保存原件。P001 只改软件选项，P002 才改设备树，P003 才运行测试；P003 还承接 CMake 模块章已建立的应用。

```mermaid
flowchart LR
    A["P001：选板与软件能力"] --> B["比较两个构建的最终配置"]
    B --> C["P002：改变 LED 别名"]
    C --> D["检查合并树与非法属性拒绝"]
    D --> E["P003：运行模拟器场景"]
    E --> F["故意失败、解释原因并恢复"]
```

这条路线先让输入、生成文件、实际运行各有明确的位置。章内操作图持续标出当前步骤；每次修改只针对当前练习副本，并说明哪些结果能证明配置生效，哪些仍需实板电平或收发观察。

前提：[原生实验准备](../P000_实验准备.md)。实验固定已核实的硬件映射，不杜撰新板接线。清理范围和失败恢复随章给出。

HC32 的 P001/P002 要求先在 G 盘实验源码树完成对应移植；P003 的 MPS2 模拟实验只依赖原生工具与 CMake P002，不以 HC32 移植成功为前提。
