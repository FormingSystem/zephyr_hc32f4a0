# 第3章\_复位与中断向量表：案例与推演

先读[关系与模型](P001_关系与模型.md)与[原理与实现](P002_原理与实现.md)。下面把已建立的对象放进具体输入，先预测再核对；纸面结果与真实芯片观察分别说明。

## 3.1\_检查三个容易混淆的地址

仍以 IRQ40 为例，填写下表后再对照：

| 对象 | 数值 | 用途 |
| --- | --- | --- |
| 表基址 | 0x08000000 | 所有槽位地址的计算起点 |
| IRQ40表项地址 | 0x080000E0 | 从这里读取入口值 |
| 表项内容 | 0x08001235 | 表示Thumb处理入口 |
| 代码位置 | 0x08001234 | 开始取处理函数指令的位置 |

将表搬到 RAM 基址 `0x24000000`，但处理代码仍留在 Flash，IRQ40 表项地址变成 `0x240000E0`，表项内容可以仍为 `0x08001235`。移动表并不等于复制每个处理函数。

## 3.2\_从链接结果发现默认处理函数

在后续启动镜像实验生成 ELF 后，查看向量段内容与符号表，比较所需处理函数是否有独立地址。弱定义允许应用提供强定义覆盖默认入口，但拼错函数名可能让默认入口继续有效。核对三个证据：器件定义的 IRQ、启动文件中的槽位符号、最终 ELF 中该符号的地址。源码中“存在一个类似名称的函数”不构成绑定成功。

本节数值只供手算；不要向真实 VTOR 写入示例地址。实际切换前要先建立整表及符合要求的内存区域，失败时恢复已验证的启动映像。
