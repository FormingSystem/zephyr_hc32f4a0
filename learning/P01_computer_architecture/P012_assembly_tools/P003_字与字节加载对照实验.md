让两个函数都返回 32 位结果，只改变指针指向的元素类型，检查加载指令是否随之改变。

目标文件里已经有机器指令。反汇编工具能逐条显示它们，因而只编译一个函数，也能检查 CPU 将从指针指向的位置读多少位。

<a id="section-1"></a>

## 3.1\_生成第一份可对照的对象

完成本专题原理篇的工具准备后，在自己的 `mcu_arch_lab` 目录保存 `probe.c`：

```c
#include <stdint.h>
uint32_t probe(const volatile uint32_t *p)
{
    return *p + 1u;
}
```

```bash
# UCRT64 或 Linux Bash；在保存本节源文件的练习目录执行。
(
set -e
cd "${MCU_ARCH_LAB:-$HOME/mcu_arch_lab}"
mkdir -p build/probe
arm-none-eabi-gcc -mcpu=cortex-m7 -mthumb -mfloat-abi=soft -O1 -c probe.c -o build/probe/probe.o
arm-none-eabi-objdump -dr build/probe/probe.o > build/probe/probe.dis
)
```

`-c` 只生成对象，尚未链接；`-dr` 同时显示反汇编和重定位；输出明确保存到 `build/probe/probe.dis`。打开该文件找到 probe，预期看到一次32位读取、加一与返回，具体编码和寄存器安排以本次工具为准。

<a id="section-2"></a>

## 3.2\_构造一次可解释的变化

把源文件另存为 `probe_byte.c`，只将参数改为 `const volatile uint8_t *p`，返回类型保持不变。编译第二个对象，保留第一份以便比较：

```bash
# UCRT64 或 Linux Bash；在保存本节源文件的练习目录执行。
(
set -e
cd "${MCU_ARCH_LAB:-$HOME/mcu_arch_lab}"
mkdir -p build/probe
arm-none-eabi-gcc -mcpu=cortex-m7 -mthumb -mfloat-abi=soft -O1 -c probe_byte.c -o build/probe/probe_byte.o
arm-none-eabi-objdump -dr build/probe/probe_byte.o > build/probe/probe_byte.dis
)
```

并排打开两份 `.dis`，找到 `<probe>` 中从指针读取数据的指令。第一份预期用 `ldr` 取一个字，第二份用 `ldrb` 取一个字节并零扩展。返回类型相同，读取宽度由被指对象的类型决定。若仍看到旧结果，先检查打开的反汇编是否来自新对象，以及命令是否成功结束。

完成后只清理自己练习目录的 `build/probe` 即可，保留两份源码与命令记录；不删工具包和教材原件。两份对象都不能直接烧录，因为尚无向量表、入口与完整链接布局。
