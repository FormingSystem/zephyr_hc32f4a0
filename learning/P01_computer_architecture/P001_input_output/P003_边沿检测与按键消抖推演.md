## 3.1\_亲手追踪一个边沿检测器

不需要板卡，先在纸上运行下面的 C 逻辑。输入已经被解释为按下状态，且暂时假设没有抖动。`previous` 和 `lamp` 都从 0 开始，每收到一个输入就执行一次。

```c
/* 逻辑模型：pressed 为本轮输入，状态保留到下一轮。 */
if (pressed && !previous) {
    lamp = !lamp;
}
previous = pressed;
```

给定输入 `0, 1, 1, 0, 1`，先填写每一步执行前的 previous，再计算 lamp。检查结果应为 `0, 1, 1, 1, 0`：第三次输入仍为按下，但 previous 已经是 1，所以不重复动作。这里保存一个位就改变了整个控制规律。

把输入改为 `0, 1, 0, 1, 1`，最后灯会回到灭。这既可能代表两次真实按键，也可能只是一次按键抖动；仅凭这五个位无法区分。要区别二者，还需要采样时间和持续时间约束，不能把边沿检测直接叫作消抖。

## 3.2\_从计算结果向外查证

| 观察点 | 应确认的事实 | 不符合时先看哪里 |
| --- | --- | --- |
| 输入引脚 | 松开高、按下低 | 接线、上拉、电平兼容 |
| 输入状态 | 与引脚电压解释一致 | 引脚复用、输入配置 |
| previous 与 lamp | 符合上述状态表 | 更新顺序和初始化 |
| 输出引脚与灯 | 输出电压产生预期灯电流 | 输出模式、限流电阻、灯极性 |

实板检查前依据板卡原理图选择引脚，不直接假定本教材的教学引脚已经连接了按钮。完成后恢复输出为安全状态，再撤除临时接线。这个从信号到软件再到信号的排查顺序，也适用于传感器开关和继电器控制。
