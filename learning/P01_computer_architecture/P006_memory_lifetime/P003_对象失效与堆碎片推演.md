一个地址值可以被复制，所指对象却有自己的存续时间。先按创建与释放的时刻跟踪对象，再按地址画出已分配和空闲的区域。

<a id="section-1"></a>

## 3.1\_给每个对象画一条寿命线

阅读下面代码，不在实板运行错误返回值：

```c
static unsigned total;
unsigned *wrong_result(void)
{
    unsigned sample = 42;
    ++total;
    return &sample; /* 错误示例：返回后sample的寿命已经结束。 */
}
```

调用前 total 存在；进入函数后 sample 的寿命开始；退出后 total 仍存在，sample 已结束。返回指针只是带走一个地址值，不能延长 sample 的寿命。正确接口可以返回数值，或由调用者提供输出对象；不是把指针加上 volatile 就能修复。

<a id="section-2"></a>

## 3.2\_用块图识别碎片

假设一块教学堆共 64 字节，暂不计管理头和对齐。连续分配 A=16、B=16、C=16，余下 16；释放 A 和 C 后，A 所在的 16 字节与尾部可合并的 32 字节分开，中间 B 仍占用。总空闲 48 字节，但请求一个 40 字节连续块仍可能失败。

在纸上按地址顺序画 `空16 | B16 | 空32`，再释放 B，支持相邻合并的分配器才能形成 64 字节空闲块。这个练习说明分配成功取决于布局，不只取决于总数。真实分配器还需扣除管理信息并满足对齐；恢复方式是明确所有权、及时释放与选择适当的固定块或分配策略，而不是盲目加大数组。
