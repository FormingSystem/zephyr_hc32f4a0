给 DMA1 选一块发送缓冲区。先查主机能否访问这段地址，再考虑 CPU 怎样把准备好的像素交给 DMA。

CPU 和直接存储器访问控制器（DMA）都能发起内存访问，但它们在芯片上接入的位置不同。一块缓冲区要能用于传输，必须从指定 DMA 控制器走得到，还必须让它读到 CPU 最后写入的内容。

<a id="section-1"></a>

## 3.1\_为显示发送缓冲选择位置

场景是 CPU 填充一段像素，DMA1 从内存读出并送给串行外设。先比较 DTCM 与 AXI SRAM 两个候选，而不是直接写 DMA 寄存器。

| 问题 | DTCM候选 | AXI SRAM候选 |
| --- | --- | --- |
| CPU能否按该工程布局访问 | 查链接区间与初始化 | 查链接区间与初始化 |
| DMA1路径是否存在 | 不能照搬CPU的TCM路径 | 继续按互连图核对可达性 |
| CPU可能只改了缓存副本吗 | 与AXI缓存路径不同 | 若可缓存则要处理一致性 |
| 链接结果是否真的放在这里 | 查map中的符号地址 | 同样查map，不能只看声明名字 |

在 STM32H743 上，DMA1 无法沿 Cortex-M7 的专用 TCM 通路访问 DTCM。若 map 文件把像素数组放在 `0x20000000` 开始的 DTCM，CPU 写入成功，仍不能用该地址让 DMA1 发送。改放到 `0x24000000` 开始的 AXI SRAM 后，DMA1 有可达路径；如果 CPU 通过回写缓存修改了像素，最新字节还可能只在缓存中。交给 DMA 读取之前，需要把相应脏缓存行写回内存。于是查地址、查通路和查可见性各解决一次具体失败。

<a id="section-2"></a>

## 3.2\_换芯片时重做哪些判断

拿到另一型号，先记录完整料号、封装与修订；再从存储器地图找容量和地址，从互连图找发起者到目标，从时钟树找各模块时钟。保留上述问题，重新填写答案。H743 的域划分不是所有 STM32 的共同结构，不能靠同属 Cortex-M7 就复制所有地址和 DMA 路由。
