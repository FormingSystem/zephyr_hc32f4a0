## 3.1\_模拟一次跨文件调用

先读两个源文件，不需要立即安装工具：main.c 声明并调用 `unsigned adjust(unsigned);`，adjust.c 定义该函数并返回参数加一。预处理各自独立展开，编译得到两份对象，链接时 adjust 的引用才与定义配对。

预测三种故障：只给链接器 main.o 会缺少定义；把函数定义为 static 会限制其外部可见性；让两份普通对象都定义同名强符号通常会报重复定义。这三种错误对应输入缺失、链接可见性与身份冲突，补头文件并不能都解决。

<a id="section-2"></a>

## 3.2\_按问题选择证据

| 当前问题 | 首先观察 | 能证明什么 |
| --- | --- | --- |
| 宏是否选择了正确分支 | 预处理后的.i | 实际进入编译的文本 |
| 访问用了字节还是字 | .s或反汇编 | 指令的访问宽度 |
| 函数是否进入最终程序 | ELF符号与map | 链接保留及地址安排 |
| 初始化数据在哪里 | 段与加载地址 | 镜像来源及运行目的地 |
| 复位后是否到main | 实板复位调试 | 启动链的实际运行 |

在汇编观察专题准备工具后，用同一源文件分别保留 `.i/.s/.o`，不要拿旧构建目录的 map 对照新源码。改变目标或 ABI 后使用新的输出目录重新生成全部相关对象；混用旧对象可能产生链接失败，也可能产生更隐蔽的调用错误。
