两个源文件分开编译时，调用方怎样留下对另一个函数的引用？用同一个名字追踪声明、重定位项与定义。

每个 C 源文件各自编译。调用方即使只见到声明，也能按函数类型准备参数；被调用函数的定义随后由链接器按符号名配对。

<a id="section-1"></a>

## 3.1\_模拟一次跨文件调用

为这次跨文件调用单独建立 `cross-file` 子目录，两个源文件都保存在这里。这样本例的 `main.c` 可以与后面启动实验的同名文件分别保留。

```bash
# UCRT64 或 Linux Bash；从任意目录创建实验子目录。
mkdir -p "${MCU_ARCH_LAB:-$HOME/mcu_arch_lab}/cross-file"
```

先用纸笔预测：编译 `main.c` 时，看得见函数声明，能知道 `adjust` 的地址吗？

```c
/* main.c */
unsigned adjust(unsigned);

int main(void)
{
    return (int)adjust(7);
}
```

```c
/* adjust.c */
unsigned adjust(unsigned value)
{
    return value + 1;
}
```

声明已经足够让编译器安排传参和接收返回值，调用点的目标仍要留给链接器。已经[准备好 Arm GNU 工具](../P012_assembly_tools/P002_安装工具并保留各阶段产物.md#section-2)的读者可在这两个文件所在目录验证；第一次顺读也可以先推演，待工具就绪再回来核对。

```bash
# UCRT64 或 Linux Bash；在保存 main.c 和 adjust.c 的子目录编译。
(
set -e
cd "${MCU_ARCH_LAB:-$HOME/mcu_arch_lab}/cross-file"
arm-none-eabi-gcc -mcpu=cortex-m7 -mthumb -O1 -c main.c adjust.c
arm-none-eabi-nm main.o adjust.o
arm-none-eabi-objdump -dr main.o
arm-none-eabi-ld -r main.o adjust.o -o combined.o
arm-none-eabi-nm combined.o
)
```

第一次 `nm` 在 `main.o` 显示 `U adjust`（待解析），在 `adjust.o` 显示 `T adjust`（定义在代码段）。在 `objdump -dr` 的调用指令旁找指向 `adjust` 的重定位项。最后的 `ld -r` 把两份对象合成一个可重定位对象；第二次 `nm` 可以在同一个文件里找到两个函数定义。实际 Flash 地址还要等最终链接布局确定。[从对象到完整镜像的实验](../P015_reset_startup/P003_链接脚本启动汇编与镜像验证.md#section-3)

预测三种故障：只给链接器 main.o 会缺少定义；把函数定义为 static 会限制其外部可见性；让两份普通对象都定义同名强符号通常会报重复定义。这三种错误对应输入缺失、链接可见性与身份冲突，补头文件并不能都解决。

<a id="section-2"></a>

## 3.2\_按问题选择证据

| 当前问题 | 首先观察 | 能证明什么 |
| --- | --- | --- |
| 宏是否选择了正确分支 | 预处理后的.i | 实际进入编译的文本 |
| 访问用了字节还是字 | .s或反汇编 | 指令的访问宽度 |
| 函数是否进入最终程序 | ELF符号与map | 链接保留及地址安排 |
| 初始化数据在哪里 | 段与加载地址 | 镜像来源及运行目的地 |
| 复位后是否到main | 实板复位调试 | 启动链的实际运行 |

在汇编观察专题准备工具后，用同一源文件分别保留 `.i/.s/.o`，不要拿旧构建目录的 map 对照新源码。改变目标或 ABI 后使用新的输出目录重新生成全部相关对象；混用旧对象可能产生链接失败，也可能产生更隐蔽的调用错误。
