先排出高中断抢占低中断的执行顺序，再用同一条时间线判断到达的事件能否全部保留。

CPU 同一时刻只执行一条指令流。抢占会暂存下层处理的返回现场，待上层返回后继续；外设在这段时间到达的数据则要有单独的位置保存。

<a id="section-1"></a>

## 3.1\_手推一次抢占与继续

假设低紧迫中断 L 已运行，高紧迫中断 H 到来且未被屏蔽。执行顺序为 L 前半段、H、L 后半段，主循环要等 L 完成才恢复。为每段只画一个 CPU 色块，不能把 H 与 L 画成同时执行。

现在只改变一个条件：H 的优先级不再允许抢占 L。H 保持挂起，先完成 L 再处理 H。事件到来的时间相同，响应时间却因仲裁条件不同而改变；这就是中断延迟不能只用“硬件入口需要几拍”描述的原因。

<a id="section-2"></a>

## 3.2\_把丢事件变成容量问题

假设 ISR 每1 ms产生一个按键报告，主循环连续忙于显示5 ms。布尔标志只能告诉主循环有事发生，不能恢复五条报告。容量为4的空队列也装不下五条，仍需选择丢新、丢旧、计数或流控策略。

先在纸上画五次入队和一次批量消费，标记每个槽位的所有者。单生产者单消费者也必须保证数据写完后再发布可读状态，并考虑实际编译器与硬件同步要求。此处不把未受保护的普通 C 数组冒充完整并发队列；在 RTOS 中优先使用其提供的中断安全队列接口。
