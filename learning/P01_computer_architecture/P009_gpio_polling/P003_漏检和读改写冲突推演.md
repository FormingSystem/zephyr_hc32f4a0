# 第3章\_漏检和读改写冲突推演

本篇路线：

- [3.1_画出一次漏检](#section-1)
- [3.2_手推一次读改写冲突](#section-2)


把按钮脉冲放到两次读取之间，再让两个写入者修改同一输出寄存器，分别找出输入和输出在哪一步丢失。

轮询程序只在执行输入读取时取得一个样本；修改输出寄存器还可能分成读取、计算、写回三步。这两条路径各有一个能被时间线暴露的问题。

<a id="section-1"></a>

## 3.1\_画出一次漏检

在纸上画采样点 `0、5、10 ms`，把按钮短脉冲放在 `1—2 ms`。三个采样点都看见未按下，程序无法重建该脉冲。把脉冲改成 `1—8 ms`，5 ms 时才能首次发现，检测延迟为 4 ms。这里测量的是电平发生到软件读出的时间，不包含消抖与后续输出。

如果把显示计算分成每次 0.5 ms 的小步，其他工作也保证及时返回，采样间隔就可以下降。但必须检查所有最坏分支；平均循环很快并不能证明最大间隔很短。

<a id="section-2"></a>

## 3.2\_手推一次读改写冲突

初始 ODR=0。主循环读出0，打算把 bit0 置一；中断先把 bit1 置一，硬件输出状态变为2；主循环随后写回自己算出的1，bit1 被意外清掉。把主循环改为向 BSRR 写 bit0 置位命令，中断对 bit1 也使用相应命令，最终两个位均可为1。

练习只推演数据竞争，不提供可直接操作未知接线的地址代码。实板时先核对端口、引脚、访问宽度及负载，再在调试器或逻辑分析仪中观察；实验结束恢复安全输出与原配置。
