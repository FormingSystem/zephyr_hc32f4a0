# 第3章\_帧时间与计数周期计算

同一次发送会占用串口多久、占用 CPU 多久？先计算位在线上的时间，再计算软件提交字节所花的时间。

UART 把一个字符拆成依次在线路上传送的位。CPU 可以在把字节交给外设后去做别的工作，所以要分别累计线路时间和处理器执行时间。

<a id="section-1"></a>

## 3.1\_先算硬件时间，再算CPU时间

发送 100 字节，波特率取 115200。这里的 8N1 表示 8 个数据位、无校验、1 个停止位；加上 1 个起始位，每个字节在线路上占 10 个位周期。忽略帧间空隙时，线路时间约为 `100×10/115200=8.68 ms`。教学假设 CPU 每字节提交需要 1 μs，则 CPU 提交总量为 0.1 ms，剩余线路时间并不必须由 CPU 陪着等待。实际驱动还会有中断、复制与调度开销，1 μs 只是本题假设。

若接收端变慢，或者发送 FIFO 不够，CPU 还需等待容量。优化应先确定瓶颈在计算、提交还是线路；提高 CPU 频率并不会自动提高固定波特率线路的吞吐率。

<a id="section-2"></a>

## 3.2\_用计数关系反推定时器设置

假设已经从时钟树确认定时器输入为100 MHz，采用普通向上计数，PSC=99，ARR=999，则计数频率是1 MHz，1000次计数产生一次更新，周期1 ms。这里寄存器存的是“除数减一”，所以必须分别加一再计算。

把 ARR 改为499，预期周期变为0.5 ms；如果实测仍为1 ms，先检查预装载值何时生效、更新事件和当前使用的时钟，不直接怀疑 CPU 算错。中心对齐、重复计数器及其他模式需要另一套周期推导，不把这条公式当成所有模式通用结论。
