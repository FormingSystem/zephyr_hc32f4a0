阈值的初值保存在 Flash，运行时却从 RAM 读取。用四个字节追踪复位代码什么时候完成交接。

链接器能为变量安排地址，上电时 RAM 里的字节却还没有因此变成 C 程序要求的初值。启动代码要在进入 main 前复制有初值的数据，并把需要零初始化的区域清零。

<a id="section-1"></a>

## 4.1\_逐字复制一份初始值

教学布局：Flash 的 `0x08001000` 保存 `19 00 00 00`，RAM 的 `0x24000000` 是 threshold 的运行位置。按小端解释，启动复制四字节后 threshold 才成为25。另设 bss 区间为 `[0x24000004,0x2400000C)`，应清零8字节。

先在纸上画复制前后的两块 RAM，故意把清零终点写为 `<= 0x2400000C`，观察会多写一个地址或一个字。链接脚本中的结束符号通常表示半开区间边界，循环应按所用步长与对齐正确处理。初始化错误会在 main 之前破坏邻接对象，不能只在 main 内排查。

<a id="section-2"></a>

## 4.2\_让镜像证据与运行证据分别成立

从 ELF 验证这次初始化，可在自己的最小镜像上用 `arm-none-eabi-objdump -h build/minimal.elf` 找 `.data` 一行。LMA 是初值随镜像存放的地址，VMA 是程序访问变量的运行地址；启动代码从前者复制到后者。再用 `arm-none-eabi-nm -n build/minimal.elf` 查复位入口和段边界，对照向量段前两项是否给出了初始栈顶与复位入口。前一节的数值是手算输入，实际地址以该 ELF 为准。[生成并检查最小镜像的完整实验](P003_链接脚本启动汇编与镜像验证.md#section-3)

实板前先备份原固件和必要配置，按板卡支持的调试方法验证。若复位后没有到 main，依次查看入口是否有效、MSP 是否位于可用 RAM、早期函数是否使用尚未初始化的数据、复制清零区间是否正确。不要为追踪启动随意改写不可逆的保护或选项字节。
