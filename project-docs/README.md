# 工程文档与 Zephyr 学习资料

首次学习请先看[从哪里开始学习 Zephyr](learning/开始学习.md)：选择第一篇、完成首次实验，再按问题进入后续专题。

如果你刚打开工程，先从下面四篇介绍开始。它们围绕现有的心跳和指示灯示例，解释工程由什么组成、
程序怎样运行、源码怎样成为固件，以及芯片移植需要补齐哪些部分。阅读只要求能看懂简单的 C 函数，
不预设你已经熟悉 Zephyr；Zephyr 是本工程采用的嵌入式操作系统项目名称。

`project-docs/` 维护工程介绍、开发说明、移植记录和 Zephyr 学习资料；`doc/` 保存 Zephyr 上游文档源码。
项目环境所需的通用工具教学与独立实验统一放在根目录 [learning/](../learning/README.md)，
面向已有嵌入式经验、尚未接触这些工具的读者；这里保留项目采用方式和工程事实。
当前入口为 [Python venv 的项目用法](python/venv/README.md)与 [west 的项目边界](west/README.md)。
本目录下已有的 `learning/` 是结合本项目源码的 Zephyr 课程，与根目录的工具补充教学分工不同。
介绍依据本仓库固定的 Zephyr 4.4.99 源码与当前实现，准确节点见[源码基线](source-baseline.md)。

## 从认识工程到理解移植

建议按顺序阅读。每一篇先解决一个问题，再把剩下的问题交给下一篇；需要操作命令或核对板卡时，使用下方参考文档。

| 顺序 | 本篇解决的问题 | 读完后能做什么 |
| --- | --- | --- |
| [01 认识这个工程](P01_认识这个工程.md) | 芯片、板卡、Zephyr 和我们的代码是什么关系？ | 解释完整源码与主机工具的边界，找到准备修改的层 |
| [02 Zephyr 如何组织程序运行](P02_Zephyr如何组织程序运行.md) | 心跳程序等待时，其他工作怎样继续？ | 区分睡眠、忙等和中断，解释到期与实际执行的差别 |
| [03 从源码到固件](P03_从源码到固件.md) | 软件选项和硬件描述怎样进入最终程序？ | 查看生效配置与已有产物，按构建阶段定位问题 |
| [04 HC32 移植由哪些部分组成](P04_HC32移植由哪些部分组成.md) | 从复位到灯和串口动作，分别由谁负责？ | 划定下一项外设的修改范围，并选择对应的验证证据 |

## 系统学习与实验

四篇介绍之后，进入[Zephyr 学习与实验路线](learning/README.md)。
课程以可诊断数据采集节点为贯穿场景，从基础、构建、内核运行走到 HC32 驱动、存储、通信、安全与完整工程。

- [完整专题蓝图](learning/专题蓝图.md)：14 组、88 个规划专题，各有前置依赖、讲解范围、最小实验与验收目标。
- [实验编写与验收约定](learning/实验规范.md)：源码组织、失败案例、运行记录及模拟器与实板的验证边界。
- [官方资料与源码查询索引](learning/资料索引.md)：按问题查固定版本的本地文档、实现和样例。

当前详细专题进度为 **6/88**：第一组 T01—T06 已交付，覆盖版本证据、C 对象、编译链接、硬件层次、环境隔离和首个软件实验。
从 [T01 版本与证据](learning/evidence/README.md)开始；模拟用例、编译反例和主机检查分别见[第一组验收记录](learning/第一组验收记录.md)。
T07—T88 尚待逐篇实现，实板验证仍单独登记。
