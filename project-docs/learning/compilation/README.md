# 从程序文字追到链接产物

在 C 语言里写出一个函数以后，编译成功为什么仍可能找不到定义？改一个宏为什么能改变机器指令？
本组用三个短源文件追踪这一过程，补齐阅读 Zephyr 构建日志所需的基础。

| 已有章节 | 阅读以后能做什么 | 实验状态 |
| --- | --- | --- |
| [第 1 章：从 C 到链接对象](P01_从C到链接对象.md) | 分清预处理、编译、汇编和链接；定位缺少定义；读取符号、段和反汇编；解释端序、对齐和整数转换的边界 | ARM 交叉编译与产物检查通过；4 次预期链接失败后恢复；没有运行目标程序 |

对应蓝图 **T03**，前置 **T02：嵌入式 C 的对象与生命期**。正文独立回收函数、对象与声明的必要含义，
更完整的先修顺序见[总阅读路线](../README.md)。本组是对象文件实验，不要求开发板，也不使用 Zephyr 运行内核。

实验输入在 [object_probe](../../../samples/learning/compilation/object_probe/)，
执行入口为 [inspect_objects.py](../../../scripts/learning/inspect_objects.py)。
二者都在当前克隆内；产物只写入被忽略的 `build/learning/compilation/`。
该目录会被重复使用，入口没有并发锁；按顺序运行，需要保留的旧结果应在重跑前自行归档。
先读正文再运行，不把生成的教学链接文件当作 HC32 固件。

2026-09-11 已复核入口修复：准备失败会更新本轮失败记录，工具超时会尝试清理本轮进程树并保存清理结果。
7 项主机回归通过，重新执行四个编译变体共 54 条子命令，其中 4 条为受控的缺定义链接失败；整体检查通过。
本次没有执行目标程序或测试硬件，具体状态与历史实验身份见正文。
