# Zephyr 学习与实验资料索引

本页是后续逐篇编写专题时使用的查询导航：先确定要解释的问题，再查当前版本的官方文档、
实现和实验入口。它不表示这些专题已经写完，也不表示列出的上游示例已经在本工程运行。
下列链接指向本仓库现有文件或目录，核对日期为 **2026-09-10**。

阅读前先核对[源码基线](../source-baseline.md)和[移植状态](../porting-status.md)。
本仓库使用 Zephyr **4.4.99** 的固定源码快照；网上其他版本的 API、目录和命令需要重新比对。
上游文档源码在 `doc/`，一般为 reStructuredText 格式的 `.rst` 文件；它们包含文档生成器指令，
直接阅读源文件时不要求先生成整个文档网站。

## 如何使用这些入口

每篇专题按“文档约定 → 公共接口 → 当前实现 → 最小实验 → 观察与反例”的顺序取证。
表中的“要回答的问题”是写作起点，不应只把对应 API 列表翻译成中文。
遇到芯片规格、时钟、引脚和厂商示例，通过 [AGENTS.md](../../AGENTS.md) 中明确标注的
“私人环境配置”入口查找本机资料。私人文件和缓存不作为公共学习文档或构建的必需依赖。

实验准备分为以下几种情形，同一专题可能同时需要多项准备：

| 情形 | 在本项目中的含义 |
| --- | --- |
| 已有回归入口 | 项目脚本已有对应命令；历史执行范围与结果仍以移植状态为准，不能扩大解释 |
| 需要新建实验 | 可先围绕内核、算法或框架做软件实验，但还需新增应用、配置、断言和运行入口并实际验证 |
| 需要 HC32 驱动 | 公共接口或其他芯片示例已有源码；当前 HC32 适配尚未提供所需能力 |
| 需要主机或外部依赖 | 需要其他运行环境、第三方模块、主机网络配置或配套工具，不能仅凭上游源码存在判断可用 |
| 需要外设和实板测量 | 需要确认装配、连接、仪器与时序；模拟器的输出无法代替物理电气结果 |

## 写作和实验时必须重新核对的内容

上游示例的 README 提供预期使用方式；同目录的测试元数据决定测试目标、过滤条件、夹具和检查方法。
实际文件名以当前目录为准，例如本项目启动示例使用 `tests.yaml`。看到 `build_only` 只能解释为构建场景，
不能记作运行通过；测试被过滤或跳过也不是通过。

当前 `project.py test` 运行的 QEMU 场景只匹配启动文字。后续专题若要证明消息次序、超时处理、内存释放
或错误恢复，应新增对应断言，再记录平台、命令、源码节点、配置与输出。现有 `tests/` 下的上游测试是
实验设计依据，需要筛选平台和依赖后运行，不能把整个目录列为本项目已通过的回归。

新增外部模块时，同时检查来源节点、许可证、构建发现方式与实际库文件。仓库中的 `west.yml`、
`modules/` 适配代码和配置开关各有用途，任何一项单独存在都不能证明依赖齐全。
板级实验继续遵守[硬件记录](../hardware.md)，将实际完成的构建、模拟、测量分别写入
[移植状态](../porting-status.md)，以便后续窗口区分阅读依据、实现进度和验证结果。
