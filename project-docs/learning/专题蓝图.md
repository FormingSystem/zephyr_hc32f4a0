# Zephyr 学习与实验专题蓝图

这是一份分批建设课程的工作蓝图：先确定要解决哪些问题、需要哪些前置知识，以及每个专题应拿出什么实验结果，
再逐篇写成完整说明。Zephyr 是本工程使用的嵌入式操作系统项目名称；本计划以 HC32F4A0PITB 移植为长期实践对象。
目标是让读者最终能自己解释、实现、测量和维护一个系统，而不只是查到一个函数的用法。
HC32F4A0PITB 是芯片型号，HC32 是系列简称，UYUP 是板卡品牌名称；它们不作为英文缩写展开。

本版规划 **14 组、88 个专题**，更新日期为 2026-09-10。专题可以包含数篇文章和数个实验，
不是 88 篇固定长度的文章。篇数由概念依赖和实验边界决定；遇到证据推翻原设计时修订蓝图。
当前已有四篇入门介绍，**下面 T01—T88 均处于规划状态，尚未交付对应详细正文或新增实验**。
已有可点击内容统一见[阅读路线](README.md)，实验完成标准见[实验规范](实验规范.md)。

## 1. 读者起点与最终结果

默认读者会写简单 C 函数，但未必熟悉指针生命期、编译链接、处理器异常或操作系统术语。
基础足够时可以用诊断练习跳过补课；跳过的依据是能够解释练习，不是已经见过相关名词。

完成主线以后，应当能够从一次外部事件出发，追踪到引脚或输入数据、驱动、中断、线程、队列、应用处理与结果输出；
也能够从一条错误现象反向找到配置、运行状态或源码层的问题。每个结论都应有适用版本、运行条件和验证方法。

全课程复用一个“可诊断数据采集节点”的场景：先由软件生成数据，再接按键与真实传感器，
随后加入消息传递、存储和远程通信。采集者拥有待发送数据，消费者取得数据后处理，状态管理者决定启动、暂停与恢复。
当消费者变慢、设备断开、队列满、线程退出或电源中断时，逐步引入必要的新机制。
每个专题仍保留独立小实验，综合应用用于检验组合后的行为。

## 2. 怎样读这份目录

T 编号是稳定的专题标识。表内“前置”列表示开始该专题前需要的结论，**不是要求机械按编号顺序全部学完**。
例如 HC32 移植可以在掌握构建、启动和异常基础后展开，不必等待全部内存专题结束。
更深入的测试与调试放在后面，但基本观察、断言和运行记录在 T06 就开始使用。

表内的缩写、框架名和源码符号用于确定将来文章的研究范围，不假定读者已经认识它们；
它们要在对应正文首次使用前完成中文含义、正式名称或名称性质、所属层次和边界的说明。
每组开头给出的“新语言”是作者准备正文时的术语依赖顺序，不能直接用名词列表代替讲解。

实验环境采用下面的简写。它们表示计划中的执行条件，不是通过记录。
QEMU 是模拟器专名；`mps2/an386` 是本工程的模拟目标标识，模拟另一种板卡，不能验证 HC32 外设。

| 简写 | 含义 | 使用方式 |
| --- | --- | --- |
| 主机 | 在电脑上读源码、检查构建产物或执行辅助测试 | 优先采用当前工程支持的环境，额外工具另行注明 |
| 模拟 | 在 QEMU 的 `mps2/an386` 目标上运行软件 | 逐实验确认功能和配置；不能验证 HC32 外设 |
| 本板 | 在 HC32F4A0PITB / UYUP 实物上运行 | 必须经过具体驱动与实板前置验收 |
| 扩展 | 需要其他目标、主机环境、外部器件或额外模块 | 先列缺项，不视为当前工程开箱可运行 |

当前工程只有启动例程的模拟回归记录，
并非本目录实验都已具备。[移植状态](../porting-status.md)是已有证据的唯一进度依据。

## 4. 应用、构建与配置（T07—T13）

## 6. 共享数据与异步任务（T21—T28）

让采集者与消费者同时访问记录，先观察竞争，再选择保护或交接机制。

| T25 消息队列与邮箱 | 数据复制、消息所有权、容量、等待/丢弃策略、发送完成与处理完成 | 让消费者变慢，核对生成数、接收数、丢弃数与队列高水位之间的守恒关系 | T02、T17、T22；模拟 |

| T28 消息发布与应用状态机 | zbus 发布订阅与 SMF 状态机分别负责数据传播和状态迁移；订阅者、通知方式、生命周期 | 让采集节点在启动/运行/故障/恢复之间切换，慢订阅者下核对传播与状态一致性 | T24—T27；模拟 |

公共语义只解释一次，然后在同一模块中比较轮询/阻塞、线程/中断、同步/异步的差量。
不要把每种配置重新写成一套完整内核教程。取消请求、停止新工作、已有工作完成与最终释放必须分别观察。

## 7. 内存与执行边界（T29—T33）

数据通路建立后，需要回答缓冲区在哪、能活多久、谁能访问和何时可以重用。
新语言依次是栈边界、分配策略、权限、内存域以及处理器与设备之间的数据可见性。

| 编号与专题 | 要讲透的问题与范围 | 最小实验与验收结果 | 前置；环境 |
| --- | --- | --- | --- |
| T29 线程栈、异常栈与容量估算 | 栈布局、调用深度、局部对象、栈水位、哨兵、保护和异常路径余量 | 改变局部缓冲和调用深度，记录占用；受控触发保护并解释检测与预防的区别 | T03、T15、T19；模拟，本板另验 |
| T30 固定内存块、堆与资源池 | slab、heap、分配失败、碎片、对齐、确定性成本和退出回收 | 同一负载比较固定块与变长分配，注入耗尽并检查失败路径与回收计数 | T02、T25、T29；模拟 |
| T31 用户态、系统调用与对象权限 | 特权、用户线程、系统调用、内核对象权限、内存域和访问验证 | 在支持的目标上构造授权与未授权访问，记录被拒绝的入口与实际保护条件 | T11、T19、T29；扩展 |
| T32 HC32 内存布局与保护设计 | 主存分区、备份内存、MPU 区域对齐、栈保护和链接约束的组合 | 先做区域覆盖/重叠/权限模型检查，再在驱动与架构前置完成后测访问边界 | T12、T29、T31；主机，本板待实现 |
| T33 浮点、对齐、缓存与设备缓冲 | 浮点上下文、结构体布局、端序、内存属性、设备可访问区和缓存维护条件 | 检查数据布局及浮点切换成本；在有相应缓存的目标验证可见性，本板按实际硬件裁剪 | T03、T19、T21、T30；模拟、本板、扩展分别验证 |

本板当前未启用 MPU，不能把用户态实验标为已有能力。跨平台的缓存或地址转换机制应说明目标支持情况；
不因 Zephyr 提供某接口就推定本板具备相应硬件。

## 8. HC32 最小移植（T34—T39）

## 12. 低功耗、安全与升级（T61—T65）

这组包含三条可分别推进的路线：减少耗电、保护信任边界、可恢复地更换固件。
它们会共享启动和存储知识，但不互相冒充。新语言先从设备暂停/恢复进入电源状态，
再从“如何判断输入和镜像可信”进入密码原语、签名、密钥与升级状态机。

## 17. 实际推进路线与依赖

默认先建立软件实验能力，然后让内核与移植两条线并行。下面是依赖摘要，完整前置以各表为准。
箭头表示后一步消费前一步的结论，不表示复制前一步教程。

```text
四篇介绍 → T01—T06 → T07—T12 → T14—T19
                                      ├─ 线程线：T20 → T21—T30 → T85 软件数据源版本
                                      └─ 移植线：补 T13 → T34—T39 → T40 → 按外设前置展开
T31—T33：在支持目标研究内存边界，供本板保护与设备缓冲方案使用
已学机制 + 实际问题 → T55—T60 深化调试（基础记录从 T06 已开始）
已有采集/驱动 + T50—T54 → T86 持久化版本
电源路线 T61—T62 / 安全升级路线 T63—T65 / 通信路线 T66—T73 按项目需要展开
每批实验从 T06 起验证 → T79—T84 统一回归与维护 → T87 / T88
```

建议第一轮逐个实现 **T01、T02、T03、T04、T05、T06**；完成后再进入构建配置组。
如果读者已有 C 与硬件基础，可先做 T02—T04 的诊断练习，再跳到 T05/T06。
第一轮的交付目标是一个真实可运行、能识别失败的软件实验和一份完整记录，不以新增标题数量验收。

之后每一轮选择一个专题，必要时将长专题分成连续几篇。正文与实验按独立状态交付：
文档可以先完成，但硬件前置缺失时必须记录缺项；不能为了标成完成而把实验目标替换成不相关的打印程序。

## 18. 每个专题写作前的契约

表中的“问题/范围、实验/验收、前置/环境”构成最小专题契约。正式写正文前，进一步完成以下工作账本，
并把与读者相关的结果写进开篇和实验说明；不要求每篇文章展示整套作者表格。

| 设计项 | 需要先确定什么 |
| --- | --- |
| 为什么现在讲 | 前一专题已经能解释什么，当前新增哪个不能解释的现场 |
| 术语依赖 | 原始写法、正式全称或专名性质、中文名、类型、朴素定义、前置词、首次位置与精确依据 |
| 最小机制 | 参与者、对象、初始状态、状态写入者/读取者、通知方式和完成条件 |
| 错误模型 | 一个看似合理的判断如何被明确交错或输入击穿，修正需增加什么约束 |
| 接口契约 | 调用上下文、阻塞、超时、所有权、返回码、取消和资源回收 |
| 源码证据 | 对应固定提交的接口、实现、配置与调用链；只有存在文件不能证明该配置会使用它 |
| 实验对照 | 改哪个变量、观察哪项量、哪种结果会推翻预测，如何恢复基线 |
| 下一问题 | 当前完成后仍没有解决的具体条件，以及应进入的后续专题 |

对有不同配置或执行模型的专题，先建立共同职责，再按模块比较真实差量。例如：

| 模块 | 共同问题 | 比较轴 | 在对应专题验证什么 |
| --- | --- | --- | --- |
| 调度 | 哪个就绪线程获得执行机会 | 协作/抢占、单核/多核 | T16 先核单核规则；T83 再核真正增加的并行条件 |
| 数据交接 | 消费者何时能读，何时归还存储 | 拷贝/借用、有界/动态、等待/丢弃 | T25/T26/T30 分别验证完成与容量约束 |
| 外设传输 | 请求何时结束，错误怎样报告 | 轮询/中断/DMA、同步/异步 | T39/T42/T43 复用同一数据输入，对比占用与所有权 |
| 数据保存 | 什么时刻的数据可在重启后恢复 | 参数记录/文件、介质/后端 | T50—T54 验证不同层的完成与恢复边界 |

深入源码时先有模块阅读导图，再逐个解释确实影响结论的实现簇。
同一版本同一实现保持一个权威讲解位置，其他章节回链它；不复制多套会随版本漂移的源码注释。
图表要解决具体关系或时间顺序问题；并发专题需要角色关系与端到端时序说明，不能只列结构体字段。

## 19. 来源、状态与后续维护

本计划依据本地官方文档目录、工程脚本、现有移植记录及源码模块分布制定；
具体查询入口在[资料索引](资料索引.md)。对应上游提交与内置模块见[源码基线](../source-baseline.md)。
官方[文档入口](https://docs.zephyrproject.org/latest/index.html)用于检查领域覆盖，
其在线内容随主线变化，后续文章中的具体接口与行为必须重新对照本仓库固定提交。

本仓库包含完整 Zephyr 自身源码和当前 HC32 所需模块，但不包含上游清单列出的所有外部库。
通信、安全、文件系统、图形、升级等专题需要逐项核对依赖，不把适配目录当成第三方库本体。
本机厂商资料与示例通过[AGENTS.md](../../AGENTS.md)明确标注的私人环境配置入口查找，公共文章不依赖私人路径。

每落地一个专题，同步其真实阅读入口、实验状态、受影响的前后关系与[项目状态](../porting-status.md)。
T 编号保持稳定；拆分后的正文按专题目录内 P01、P02 等编号，不挤占已有四篇工程介绍的文件身份。
本版只完成全课程设计与交付约定，未修改固件、运行新增实验或操作硬件。
